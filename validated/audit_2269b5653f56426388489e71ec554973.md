### Title
Webhook signature verification authenticates against `repository.owner.login`/`organization.login` while the mutated repository is resolved independently from `repository.full_name`, letting a signed payload from one org create a review stack under a different org's repository with an attacker-controlled branch - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb], [File: app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App/webhook secret to verify against using `repository_owner`, which is read from the attacker-controlled JSON body (`repository.owner.login`, falling back to `organization.login`), while `OpenedHandler#repository` independently resolves the actual `Shipit::Repository` to mutate from `params.repository.full_name`. Nothing binds these two fields together, so an attacker who legitimately controls one org onboarded to a shared, multi-tenant Shipit instance can sign a payload with their own org's webhook secret while setting `repository.full_name` to a victim org's repo, causing `ReviewStackAdapter#create!` to persist a `ReviewStack` under the victim's `Repository` with `branch: params.pull_request.head.ref` pointing at the attacker's own fork.

### Finding Description
The claimed binding, stated as an equality that must hold and is in fact broken:

`organization_used_to_verify_signature (params.repository.owner.login) == owner_of(Repository_actually_mutated) (derived from params.repository.full_name)`

Trace:
- `WebhooksController#verify_signature` selects the GitHub App config via `repository_owner`: `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0) [2](#0-1) . This value comes straight from the JSON body the attacker submits to `POST /webhooks`; it is not cross-checked against `repository.full_name`.
- `OpenedHandler#repository` resolves the `Shipit::Repository` to act on solely from `params.repository.full_name`, independent of the org used above: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [3](#0-2) .
- `OpenedHandler#process` passes this repository's `review_stacks` scope into `ReviewStackAdapter`: `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` [4](#0-3) .
- `ReviewStackAdapter#create!` persists a stack in that scope with `branch: params.pull_request.head.ref` (attacker's fork branch) and `environment: "pr#{params.number}"` [5](#0-4) .

Attacker request: open a PR in their own fork/org, then `POST /webhooks` with header `X-Github-Event: pull_request` and a signature computed with their own org's `webhook_secret`, setting:
- `repository.owner.login`: attacker's org (so `verify_signature` resolves `Shipit.github(organization: 'attacker-org')`, whose secret the attacker knows and used to compute a valid HMAC),
- `repository.full_name`: `"victim-org/victim-repo"` (used by `OpenedHandler#repository` to find the real, victim-owned `Repository`),
- `pull_request.head.ref`: any branch name in the attacker's fork,
- `number`: `N` matching an existing PR number in the victim repo without a provisioned review stack yet.

Because `verify_signature` succeeds (HMAC checked against the attacker's own secret, which the attacker legitimately possesses) and `repository_owner` is never required to match `repository.full_name`'s owner, the request passes authentication as a legitimately-signed webhook, yet it is authorized to mutate the victim's `Repository#review_stacks`. `find_or_create!` then calls `create!` since no stack exists for `pr#{N}` yet, writing a `ReviewStack` scoped to the victim's `Repository` whose `branch` is the attacker's fork ref [6](#0-5) .

None of the listed guards prevent this: `verify_signature` only checks the HMAC against whichever org secret the payload's `repository.owner.login`/`organization.login` selects — it has no notion of "the org that is allowed to mutate `repository.full_name`" [7](#0-6) . `drop_unhandled_event` only checks the event type is handled [8](#0-7) . The `ExplicitParameters` schema in `OpenedHandler` only validates types/presence of fields, not cross-field consistency between `repository.full_name` and `repository.owner.login` [9](#0-8) . `provisioning_behavior_allow_all?` only gates whether stacks get auto-provisioned for the victim repo, it does not validate the request's origin [10](#0-9) .

### Impact Explanation
This is a payload nominally authenticated for one org ("attacker-org") mutating another org's ("victim-org") `Repository#review_stacks`, matching the Critical category "a payload for one repository mutating another's stack ... an unauthorized deploy". A `ReviewStack` is created under the victim's `Repository` whose deploy `branch` is fully attacker-controlled (their fork's ref), and it is immediately queued via `Shipit::ReviewStackProvisioningQueue.add(stack)` [11](#0-10) , leading to provisioning/deployment of attacker-chosen code using the victim repository's deployment credentials and infrastructure. This is repeatable against any victim repository/organization hosted on the same multi-tenant Shipit instance, for every PR number not yet claimed by a stack, as long as `provisioning_behavior_allow_all?` is enabled for the victim repo.

### Likelihood Explanation
Requires: (1) a multi-tenant Shipit deployment configured with per-organization GitHub Apps/webhook secrets (as documented and supported, e.g. `config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`); (2) attacker legitimately controls at least one onboarded org (and thus its webhook secret) — a realistic scenario for shared/internal Shipit instances serving many teams; (3) victim repo has `provisioning_behavior_allow_all?` enabled and no existing stack for `pr#{N}`. Attacker cost is low: no Shipit session, no `github_access_token`, no victim secrets needed — only their own org's webhook secret to sign an arbitrary JSON body they fully control, then a direct HTTP POST to `/webhooks`. This is fully repeatable across arbitrary victim repos/PR numbers on the same instance.

### Recommendation
Bind the organization used for signature verification to the organization that will actually be mutated: derive the target `Repository` first from `repository.full_name`, then verify the webhook signature using that repository's owning GitHub App secret (or explicitly assert `repository.owner.login == full_name.split('/').first` and reject mismatches before any handler processes the payload).

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` or a new test in `test/models/shipit/webhooks/handlers/pull_request/opened_handler_test.rb`):

```ruby
test "cross-org signed webhook must not create a review stack for a different org's repository" do
  victim_repo = shipit_repositories(:shipit) # owner login e.g. "shopify", review_stacks_enabled, provisioning_behavior_allow_all
  Shipit.stubs(:github_teams).returns([])

  attacker_org = 'attacker-org'
  attacker_secret = 'attacker-secret'
  Shipit.stubs(:github).with(organization: attacker_org).returns(
    Shipit::GithubApp::Default.new(attacker_org, webhook_secret: attacker_secret)
  )

  payload = {
    action: 'opened',
    number: 999,
    pull_request: {
      id: 1, number: 999, url: 'x', title: 'x', state: 'open',
      additions: 1, deletions: 0,
      head: { sha: 'abc', ref: 'attacker/evil-branch' },
      user: { login: 'attacker' },
      assignees: [], labels: []
    },
    repository: { full_name: victim_repo.github_repo_name, owner: { login: attacker_org } },
    sender: { login: 'attacker' }
  }.to_json

  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', attacker_secret, payload)

  @request.headers['X-Github-Event'] = 'pull_request'
  @request.headers['X-Hub-Signature'] = signature

  assert_no_difference -> { victim_repo.review_stacks.count } do
    post :create, body: payload, as: :json
  end
  # Binding check: attacker org used for signing must not equal victim repo owner
  refute_equal attacker_org, victim_repo.github_repo_owner_name
  # Assert no ReviewStack got branch == attacker's ref under victim repository
  assert_nil victim_repo.review_stacks.find_by(environment: 'pr999')
end
```

This test currently fails (the stack is created) because `verify_signature` accepts the attacker-signed payload and `OpenedHandler#repository` resolves the victim's `Repository` independently of the signing org, demonstrating the broken binding between authentication and authorization scope.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))

      ].join(' '))
    end
