### Title
Unbounded zip-entry decompression in `extractZipFile` allows disk exhaustion via a small attacker-published zip bomb - (File: internal/zip/zip.go)

### Summary
`extractZipFile` copies decompressed data from a `zip.File` entry to disk with `io.Copy(df, f)` with no size cap and no check against the entry's declared `UncompressedSize64`, so a small malicious artifact/log zip can expand to an arbitrarily large file on extraction. This is reachable from `gh run download` and `gh run view --log`, both of which extract zip archives whose contents are fully attacker-controlled (artifact/run-log payload).

### Finding Description
`extractZipFile` opens a per-entry reader via `zf.Open()` (a decompressing reader over the zip's DEFLATE/stored stream) and writes it out with an unbounded `io.Copy(df, f)`: [1](#0-0) 

There is no check of `zf.UncompressedSize64` before or during the copy, and no `io.LimitReader`/quota is applied anywhere in the call chain. `ExtractZip` iterates every entry in the archive and calls `extractZipFile` for each, so every entry independently can be a decompression bomb: [2](#0-1) 

Reachable entrypoints:
- `gh run download` streams the artifact HTTP response to a temp file, builds a `zip.Reader` over it, then calls `ghzip.ExtractZip`, ultimately invoking `extractZipFile` for each entry: [3](#0-2) 
- `gh run view --log` fetches run logs into memory (`io.ReadAll`), wraps them in a `zip.Reader`, caches to disk, and later opens/extracts entries via the same `zip.Reader`/`archive/zip` path: [4](#0-3) 

The attacker fully controls the zip contents (it's the artifact/run-log payload published by the workflow run they trigger), so they can craft a small zip whose entries decompress to gigabytes/terabytes of data. Neither `ExtractZip` nor `extractZipFile` nor the callers apply any decompressed-size limit, entry-count limit, or ratio check; `safepaths` only guards against path traversal, not size: [5](#0-4) 

A `grep` across the repo for size-limiting patterns (`UncompressedSize`, `MaxBytes`, `LimitReader`, "bomb") found no decompression-bomb protection anywhere in the zip/download/view code paths.

### Impact Explanation
An attacker who can get a victim to run `gh run download` or `gh run view --log` against a repo/run they control (e.g., their own fork, a PR-triggered workflow, or any repo the victim has access to) can cause the CLI to write an unbounded amount of decompressed data to the victim's disk from a tiny downloaded artifact/log, exhausting disk space (denial of service) and/or causing the process to hang. This matches "High - Unbounded resource consumption on the victim's machine from a single attacker-published object."

### Likelihood Explanation
No special privileges are required beyond publishing a workflow run/artifact or log content, which any contributor or someone with a PR/fork can trigger. `gh run download`/`gh run view --log` are ordinary, commonly used commands, making this readily reachable and repeatable.

### Recommendation
- Enforce a maximum decompressed size per entry and/or in total, using `io.CopyN`/`io.LimitReader` bounded by a sane cap (and comparing to `zf.UncompressedSize64`, rejecting mismatches).
- Enforce a maximum compression ratio per entry to catch bombs where the declared uncompressed size itself is falsified.
- Apply the same bound to the run-log path (`getRunLog`'s `io.ReadAll(resp)` in `view.go`) which also reads the entire HTTP body unbounded into memory before any zip validation.
- Fail extraction/download with a clear error when limits are exceeded rather than silently continuing.

### Proof of Concept
Go unit test extending `internal/zip/zip_test.go`:
```go
func Test_extractZip_DecompressionBomb(t *testing.T) {
    tmpDir := t.TempDir()
    zipPath := filepath.Join(tmpDir, "bomb.zip")

    // Build a zip with one entry of a few KB compressed that expands to >1GB.
    f, _ := os.Create(zipPath)
    zw := zip.NewWriter(f)
    w, _ := zw.CreateHeader(&zip.FileHeader{Name: "bomb.bin", Method: zip.Deflate})
    zeroChunk := make([]byte, 1<<20) // 1MB of zeros, compresses extremely well
    for i := 0; i < 2000; i++ {      // ~2GB decompressed
        w.Write(zeroChunk)
    }
    zw.Close()
    f.Close()

    extractPath, _ := safepaths.ParseAbsolute(filepath.Join(tmpDir, "out"))
    zr, _ := zip.OpenReader(zipPath)
    defer zr.Close()

    err := ExtractZip(&zr.Reader, extractPath)
    // Expected (fixed) behavior: err should be non-nil, e.g. "decompressed size exceeds limit"
    // Actual (current) behavior: err is nil and a ~2GB file is written from a few-KB zip.
    require.Error(t, err, "expected extraction to be rejected due to decompression size limit")
}
```
Expected assertion after fix: extraction aborts with a bounded-size error instead of writing multi-GB output from a small (KB-scale) attacker-supplied zip. [6](#0-5)

func ExtractZip(zr *zip.Reader, destDir safepaths.Absolute) error {
	for _, zf := range zr.File {
		fpath, err := destDir.Join(zf.Name)

			var pathTraversalError safepaths.PathTraversalError
			if errors.As(err, &pathTraversalError) {
				continue
			}
			return err
		}

		if err := extractZipFile(zf, fpath); err != nil {
			return fmt.Errorf("error extracting %q: %w", zf.Name, err)
		}
	}
	return nil
}

func getRunLog(cache RunLogCache, httpClient *http.Client, repo ghrepo.Interface, run *shared.Run, attempt uint64) (*zip.ReadCloser, error) {
	cacheKey := fmt.Sprintf("%d-%d", run.ID, run.StartedTime().Unix())
	isCached, err := cache.Exists(cacheKey)
	if err != nil {
		return nil, err
	}

	if !isCached {
		// Run log does not exist in cache so retrieve and store it
		logURL, err := safeurl.JoinPathWithHostPrefix(ghinstance.RESTPrefix(repo.RepoHost()), "repos", repo.RepoOwner(), repo.RepoName(), "actions", "runs", strconv.FormatInt(run.ID, 10), "logs")
		if err != nil {
			return nil, err
		}

		if attempt > 0 {
			logURL, err = safeurl.JoinPathWithHostPrefix(ghinstance.RESTPrefix(repo.RepoHost()), "repos", repo.RepoOwner(), repo.RepoName(), "actions", "runs", strconv.FormatInt(run.ID, 10), "attempts", strconv.FormatUint(attempt, 10), "logs")
			if err != nil {
				return nil, err
			}
		}

		resp, err := getLog(httpClient, logURL)
		if err != nil {
			return nil, err
		}
		defer resp.Close()

		data, err := io.ReadAll(resp)
		if err != nil {
			return nil, err
		}
		respReader := bytes.NewReader(data)

		// Check if the response is a valid zip format
		_, err = zip.NewReader(respReader, respReader.Size())
		if err != nil {
			return nil, err
		}

		err = cache.Create(cacheKey, respReader)
		if err != nil {
			return nil, err
		}
	}

	return cache.Open(cacheKey)
}
