### Title
`ProxyType::NonTransfer` claims `is_superset` over `ProxyType::Auction` while its `filter` denies `Registrar::swap`, letting a NonTransfer proxy escalate to registrar-swap access - ([File: polkadot/runtime/westend/src/lib.rs], also [File: polkadot/runtime/rococo/src/lib.rs])

### Summary
On the Westend and Rococo relay-chain runtimes, `ProxyType::NonTransfer` unconditionally declares itself a superset of every other proxy type (`(ProxyType::NonTransfer, _) => true`), including `ProxyType::Auction`. But `NonTransfer`'s own `filter` deliberately *excludes* `Registrar::swap` (comment: `// Specifically omitting Registrar 'swap'`), while `Auction`'s `filter` admits the entire `Registrar` call family, including `swap`. Because `pallet_proxy` gates `add_proxy`/`remove_proxy` solely on `is_superset`, a delegate holding only a `NonTransfer` proxy can add itself an `Auction` sub-proxy and then use it to call `Registrar::swap` on the delegator's behalf — a call the `NonTransfer` type was explicitly designed to deny. This is structurally identical to the already-identified and fixed `NonTransfer`/`Governance` superset bug on Asset Hub Westend (`GHSA`-style fix, PR referenced in `prdoc/pr_12769.prdoc`, regression test `non_transfer_proxy_is_not_a_superset_of_governance`), but the equivalent `NonTransfer`/`Auction` pair on the relay-chain runtimes was left unpatched.

### Finding Description
`InstanceFilter::is_superset` is the sole gate `pallet_proxy::do_proxy` uses before allowing a delegate to add or remove a sub-proxy of another type: [1](#0-0) 

The invariant this depends on is: if `X.is_superset(Y) == true`, then `X.filter(c) == true` for every call `c` that `Y.filter(c)` admits. On Westend/Rococo:

- `ProxyType::NonTransfer` is an allow-list filter that explicitly omits `Registrar::swap`: [2](#0-1) 

- `ProxyType::Auction` admits the entire `Registrar` call family (including `swap`), as seen in the sibling Rococo runtime (structurally the same family of runtimes): [3](#0-2) 

- Yet `is_superset` unconditionally claims `NonTransfer` is a superset of everything, including `Auction`: [4](#0-3) [5](#0-4) 

This is the exact "double exception" mismatch pattern from the Kyverno advisory: two independently-declared authorization statements (`NonTransfer`'s claimed superset relation vs. `Auction`'s actual admitted-call set) disagree, and the more permissive one wins once composed, bypassing the restriction the first was designed to enforce.

`Registrar::swap` itself is gated only by `ensure_root_para_or_owner`, which accepts `Root`, the para's own origin, or the *signed account* that is `Paras::<T>::get(id).manager` while unlocked: [6](#0-5) [7](#0-6) 

The dispatch always runs as `Signed(real)` (the delegator), so `who == real` and the manager check is satisfied whenever the *delegator* (not the delegate) is a para manager — exactly the population of accounts that would legitimately want to grant a restrictive `NonTransfer` proxy to an operational key.

Attack chain, with no privileged role, governance, or stolen keys required:
1. `R` (a para manager of `id`) grants delegate `D` a `NonTransfer` proxy via normal `pallet_proxy::add_proxy`.
2. `D` calls `Proxy::proxy(R, Some(NonTransfer), Proxy::add_proxy{ delegate: D, proxy_type: Auction, delay: 0 })`.
   - The `add_proxy`/`remove_proxy` guard in `do_proxy` only denies when `!def.proxy_type.is_superset(proxy_type)`. Since `NonTransfer.is_superset(Auction) == true`, the guard does **not** fire.
   - Falling through to `_ => def.proxy_type.filter(c)`, `NonTransfer`'s allow-list includes `RuntimeCall::Proxy(..)` wholesale, so the `add_proxy` call itself is admitted.
   - `D` is now also an `Auction` proxy for `R`.
3. `D` calls `Proxy::proxy(R, Some(Auction), Registrar::swap{ id, other })`.
   - `Auction`'s filter admits all `Registrar` calls, so this passes the proxy filter.
   - Dispatch runs as `Signed(R)`; `ensure_root_para_or_owner` succeeds because `R` is `id`'s manager.
   - `Registrar::swap` executes, even though `D`'s originally-granted `NonTransfer` proxy was explicitly designed to deny this exact call.

### Impact Explanation
A delegate restricted to a `NonTransfer` proxy (explicitly intended to exclude parachain-registrar `swap`) can silently escalate, via a two-step self-authorized proxy addition, to executing `Registrar::swap` on behalf of the delegator whenever that delegator is a parachain manager. `swap` mutates on-chain parachain/parathread lifecycle state, auction/lease/deposit bookkeeping (`T::OnSwap::on_swap`), and can be used to swap slot/lease positions between paras — a state-changing, integrity-relevant action that the delegator never intended to authorize when granting only a `NonTransfer` proxy. This is unauthorized dispatch of a call outside the intended permission boundary of an explicitly-scoped proxy type, matching CWE-284 (Improper Access Control), and mirrors a bug class Parity has already classified as security-relevant and fixed for the `NonTransfer`/`Governance` pair on Asset Hub Westend (`prdoc/pr_12769.prdoc`).

### Likelihood Explanation
The precondition — a proxy delegator who is also a registered/unlocked parachain manager granting a `NonTransfer` proxy to an operational account — is a realistic, non-privileged scenario (para managers commonly delegate day-to-day operational keys). No governance, root, validator, or forged-message capability is needed; both steps of the attack are ordinary signed `Proxy::proxy` calls dispatched by the attacker-controlled delegate account. The bug is deterministic and requires no race condition or timing — it is a static logic inconsistency between `is_superset` and `filter`.

### Recommendation
Apply the same fix used for Asset Hub Westend's `NonTransfer`/`Governance` pair (PR referenced in `prdoc/pr_12769.prdoc`): remove `Auction` (and any other type whose filter is not fully dominated by `NonTransfer`'s filter) from the unconditional `(ProxyType::NonTransfer, _) => true` superset claim in `polkadot/runtime/westend/src/lib.rs` and `polkadot/runtime/rococo/src/lib.rs`, or enumerate `is_superset` explicitly per pair the way the fixed Asset Hub runtime now does. Add a lattice-consistency regression test (as already exists for Asset Hub Westend, `proxy_type_superset_relation_matches_call_filters`) to these relay-chain runtimes to prevent recurrence.

### Proof of Concept
Not executed against a live network. Reasoning is based on static code tracing through `pallet_proxy::do_proxy`, `ProxyType::is_superset`/`filter` for Westend/Rococo, and `paras_registrar::swap`'s origin check, as cited above. A concrete FRAME integration-test reproduction would:
1. Register `R` as manager of a test para `id` via `Registrar::register`/`reserve` in the existing `paras_registrar` mock, and make it an on-demand parachain.
2. `Proxy::add_proxy(R, D, ProxyType::NonTransfer, 0)`.
3. `Proxy::proxy(D, R, None, Box::new(Proxy::add_proxy{ delegate: D, proxy_type: ProxyType::Auction, delay: 0 }))` — assert `Ok`.
4. `Proxy::proxy(D, R, Some(ProxyType::Auction), Box::new(Registrar::swap{ id, other }))` — assert `Ok`, and assert the `Registrar::Swapped`/pending-swap state changed, demonstrating `D` executed a call its original `NonTransfer` grant explicitly denied.
This test was not run in this session; it is provided as the exact reproduction a maintainer/agent should execute using the existing `paras_registrar` and `pallet_proxy` mock harnesses (analogous to the existing `proxy_type_superset_relation_matches_call_filters` / `non_transfer_proxy_is_not_a_superset_of_governance` tests already present for Asset Hub Westend at [8](#0-7) ).

impl<T: Config> Pallet<T> {
	/// Ensure the origin is one of Root, the `para` owner, or the `para` itself.
	/// If the origin is the `para` owner, the `para` must be unlocked.
	fn ensure_root_para_or_owner(
		origin: <T as frame_system::Config>::RuntimeOrigin,
		id: ParaId,
	) -> DispatchResult {
		if let Ok(who) = ensure_signed(origin.clone()) {
			let para_info = Paras::<T>::get(id).ok_or(Error::<T>::NotRegistered)?;

			if para_info.manager == who {
				ensure!(!para_info.is_locked(), Error::<T>::ParaLocked);
				return Ok(());
			}
		}

		Self::ensure_root_or_para(origin, id)
	}

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}
