### Title
Recalculation of pending partitioned stake rewards re-derives delegation state from the live `stakes_cache` instead of the calculation-time snapshot, allowing a stake owner to desynchronize `all_stake_rewards` between restarted and non-restarted validators - (File: runtime/src/bank/partitioned_epoch_rewards/calculation.rs)

### Summary
`recalculate_stake_rewards` (invoked via `recalculate_partitioned_rewards_if_active` on snapshot restore) rebuilds the entire pending `PartitionedStakeReward` list by reading `stake_delegations` from the bank's **live** `stakes_cache`, whereas the vote-account side of the same calculation deliberately uses a **frozen** `epoch_stakes()` snapshot "to match the vote-account admission policy used for distribution". A stake owner who submits a legitimate `Withdraw` (reducing excess lamports/`delegation.stake`) or `Merge` (changing `delegation.stake`/`credits_observed`) after the epoch-boundary calculation but before a validator restarts from snapshot can cause that validator's recalculated reward for their own stake account to differ from the value already frozen in memory on validators that never restarted.

### Finding Description
`calculate_validator_rewards`/`calculate_stake_rewards_and_commissions` is run once at the epoch boundary and its result (`all_stake_rewards`) is kept in `Bank::epoch_reward_status` for the rest of the epoch on validators that keep running, per `set_epoch_reward_status_calculation`/`set_epoch_reward_status_distribution` [1](#0-0) .

When a validator restarts mid-distribution, `initialize_after_snapshot_restore` calls `recalculate_partitioned_rewards_if_active` [2](#0-1) , which calls `recalculate_stake_rewards` to rebuild `all_stake_rewards` from scratch [3](#0-2) .

`recalculate_stake_rewards` pulls stake delegation data via `get_epoch_params_for_recalculation`, which explicitly documents that vote-account data is taken from a *frozen* `epoch_stakes()` snapshot "to match the vote-account admission policy used for distribution", but the stake-side data (`stakes.stake_delegations_vec()`) is taken from the **current, live** `self.stakes_cache.stakes()`: [4](#0-3) [5](#0-4) 

The recomputed `PartitionedStakeReward` (containing `inflation.stake_reward`, the new `delegation.stake`, and `credits_observed`) is later used verbatim to build the actual stored stake account during distribution, in `build_updated_stake_reward`/`store_stake_accounts_in_partition` — the current on-chain state's `meta`/`flags` are reused, but the reward amount and resulting `new_stake.delegation`/`credits_observed` come straight from whichever `all_stake_rewards` the local Bank instance is holding: [6](#0-5) 

Since `stakes_cache` reflects whatever transactions have already landed against the attacker's own stake account (e.g. `Withdraw` of excess lamports, changing `delegation.stake`, or `Merge`, changing both `delegation.stake` and `credits_observed`), a stake account mutation submitted after the epoch-boundary calculation block but before a node's restart will be picked up by `recalculate_stake_rewards` on the restarting node, but NOT reflected in the frozen in-memory `all_stake_rewards` still held by validators that never restarted (`store_stake_accounts_in_partition` and the test at `test_rewards_period_system_transfer` confirm ordinary transfers/instructions are permitted during the active reward interval - there is no gate blocking stake mutation while `EpochRewardStatus::Active`) [7](#0-6) .

The existing regression test `test_recalculate_alpenglow_rewards_after_partial_distribution_uses_original_denominator` demonstrates the project is aware of a version of this problem for the *vote-credit denominator* (and mitigates it because per-epoch vote credits are immutable historical records once the epoch closes) [8](#0-7) , but there is no equivalent protection for the STAKE account's own `delegation.stake`/`credits_observed`, which remain live and mutable by the stake owner throughout the active reward interval.

### Impact Explanation
If two validators reach the same distribution slot with different `all_stake_rewards` for the same stake pubkey (one using the calculation-time value, one using a restart-time recalculated value), `store_stake_accounts_in_partition` will write different lamport balances / `delegation.stake` / `credits_observed` for the identical stake account at the identical slot. This produces different bank hashes for the same block across validators — cross-node state divergence and a consensus halt/fork, matching the "stake/epoch-stakes/reward state identical on all honest nodes" invariant violation described in the prompt. This falls into Agave's highest-severity bounty category (consensus/safety violation causing network halt or fork), reachable purely through an unprivileged stake-owner transaction combined with the standard, supported validator restart-from-snapshot code path.

### Likelihood Explanation
- Preconditions: attacker owns a stake account earning rewards during the active `EpochRewardStatus` interval, and submits a normal, signer-authorized `Withdraw` (of any excess above rent-exempt + effective stake) or `Merge` instruction against their own stake account before some (but not necessarily all) validators restart from snapshot mid-distribution.
- Feasibility: node restarts happen routinely in production fleets (process crash/OOM, upgrades, hardware failure) and are an explicitly supported code path (`initialize_after_snapshot_restore`), not something requiring privileged control. The stake mutation itself requires zero special permissions and is a single ordinary transaction.
- Repeatability: any stake owner active during a reward interval that spans multiple blocks (the norm for validators with many delegators, since rewards distribute over multiple partitions/blocks) can attempt this every epoch.

### Recommendation
Freeze the stake delegation state used for recalculation, mirroring the treatment already given to `cached_vote_accounts`. Concretely, capture the calculation-time `stake_delegations` (or the resulting `all_stake_rewards`) into a value that survives snapshot restore (e.g., persist enough of the calculation-phase snapshot, or derive `stake_delegations` in `get_epoch_params_for_recalculation` from an epoch-boundary-frozen source instead of `self.stakes_cache.stakes()`), so that `recalculate_stake_rewards` is guaranteed to reproduce byte-identical `PartitionedStakeReward`s regardless of any subsequent, legitimate mutation to the underlying stake accounts during the active reward interval.

### Proof of Concept
Extend `test_recalculate_alpenglow_rewards_after_partial_distribution_uses_original_denominator`'s pattern in `runtime/src/bank/partitioned_epoch_rewards/calculation.rs`, but instead of mutating the vote account, mutate the **stake** account of the un-distributed reward recipient between calculation and recalculation:

1. Build a `RewardBank` with at least two stake delegations distributed over ≥2 partitions (as in `test_recalculate_stake_rewards`).
2. Advance to the epoch boundary; capture `EpochRewardPhase::Calculation.all_stake_rewards` (`original_stake_rewards`).
3. Before any distribution occurs, submit a legitimate stake-owner-signed `Withdraw` instruction (or construct/store an equivalent post-Merge state directly via `bank.store_account`, mirroring how `store_stake_accounts_in_partition`/tests already manipulate stake accounts) against the *unpaid* stake account, reducing `delegation.stake` by some amount within the withdrawable excess.
4. Call `bank.recalculate_stake_rewards(&bank.get_epoch_rewards_sysvar(), &thread_pool)`.
5. Assert: `recalculated_stake_rewards` for that pubkey's `inflation.stake_reward` / `inflation.stake.delegation.stake` differs from `original_stake_rewards`'s entry for the same pubkey — proving that a node which restarts after the withdrawal will store a different final stake-account state for that slot than a node that never restarted (which would still be using `original_stake_rewards`), i.e., the two nodes disagree on the committed bank state for the identical distribution slot.

    /// Retrieves stake history and delegations for stake reward recalculation

    fn get_epoch_params_for_recalculation<'a>(
        &'a self,
        rewarded_epoch: Epoch,
        stakes: &'a Stakes<StakeAccount<Delegation>>,
    ) -> EpochRewardCalculateParamInfo<'a> {
        // Use `stakes` for stake-related info
        let stake_history = stakes.history().clone();
        let stake_delegations = stakes.stake_delegations_vec();

        // Use the VAT-filtered vote-account snapshot from epoch_stakes.
        // Recalculation should match the vote-account admission policy used for
        // distribution.
        let leader_schedule_epoch = self.epoch_schedule().get_leader_schedule_epoch(self.slot());
        let distribution_epoch_vote_accounts = self
            .epoch_stakes(leader_schedule_epoch)
            .expect("calculation should always run after Bank::update_epoch_stakes()")
            .stakes()
            .vote_accounts();
        let cached_vote_accounts =
            self.get_cached_vote_accounts(rewarded_epoch, distribution_epoch_vote_accounts);

        EpochRewardCalculateParamInfo {
            stake_history,
            stake_delegations,
            cached_vote_accounts,
        }
    }

    /// If rewards are still active, recalculates partitioned stake rewards and
    /// updates Bank::epoch_reward_status. This method assumes that reward
    /// commissions have already been calculated and delivered, and *only*
    /// recalculates stake rewards
    pub(in crate::bank) fn recalculate_partitioned_rewards_if_active<F, TP>(
        &mut self,
        thread_pool_builder: F,
    ) where
        F: FnOnce() -> TP,
        TP: std::borrow::Borrow<ThreadPool>,
    {
        let epoch_rewards_sysvar = self.get_epoch_rewards_sysvar();
        if epoch_rewards_sysvar.active {
            let thread_pool = thread_pool_builder();
            let (stake_rewards, partition_indices) =
                self.recalculate_stake_rewards(&epoch_rewards_sysvar, thread_pool.borrow());
            self.set_epoch_reward_status_distribution(
                epoch_rewards_sysvar.distribution_starting_block_height,
                stake_rewards,
                partition_indices,
            );
        }
    }

    fn build_updated_stake_reward(
        distribution_epoch: u64,
        stake_history: &StakeHistory,
        new_warmup_cooldown_rate_epoch: Option<Epoch>,
        stakes_cache_accounts: &imbl::HashMap<Pubkey, StakeAccount<Delegation>>,
        partitioned_stake_reward: &PartitionedStakeReward,
        rent: &Rent,
        adjust_delegations_for_rent: bool,
        use_fixed_point_stake_math: bool,
    ) -> Result<StakeReward, DistributionError> {
        let stake_account = stakes_cache_accounts
            .get(&partitioned_stake_reward.stake_pubkey)
            .ok_or(DistributionError::AccountNotFound)?
            .clone();

        let (mut account, stake_state): (AccountSharedData, StakeStateV2) = stake_account.into();
        let StakeStateV2::Stake(meta, stake, flags) = stake_state else {
            // StakesCache only stores accounts where StakeStateV2::delegation().is_some()
            unreachable!(
                "StakesCache entry {:?} failed StakeStateV2 deserialization",
                partitioned_stake_reward.stake_pubkey
            )
        };
        account
            .checked_add_lamports(partitioned_stake_reward.inflation.stake_reward)
            .map_err(|_| DistributionError::ArithmeticOverflow)?;
        account
            .checked_add_lamports(partitioned_stake_reward.block_reward)
            .map_err(|_| DistributionError::ArithmeticOverflow)?;

        let mut new_stake = partitioned_stake_reward.inflation.stake;
        if adjust_delegations_for_rent {
            let minimum_balance = rent.minimum_balance(account.data().len());
            // The rewarded epoch is right before the distribution epoch
            let rewarded_epoch = distribution_epoch.saturating_sub(1);
            // The entry in `partitioned_stake_reward` contains the rewards,
            // calculated during the calculation phase
            let delegation_with_rewards = new_stake.delegation.stake;
            adjust_delegation_for_rent(
                &mut new_stake.delegation,
                rewarded_epoch,
                delegation_with_rewards,
                account.lamports(),
                minimum_balance,
            );
        } else {
            let expected_delegation = stake
                .delegation
                .stake
                .saturating_add(partitioned_stake_reward.inflation.stake_reward);
            assert_eq!(
                expected_delegation, new_stake.delegation.stake,
                "stake reward delegation must be consistent with the updated stake account \
                 lamport balance"
            );
        }
        account
            .set_state(&StakeStateV2::Stake(meta, new_stake, flags))
            .map_err(|_| DistributionError::UnableToSetState)?;
