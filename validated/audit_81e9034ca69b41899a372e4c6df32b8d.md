### Title
RAY-scaled debt overflow permanently freezes an overgrown market - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
`accrue_step` converts the market's scaled debt back to an unscaled RAY value before it updates or caps the borrow index. That conversion uses non-saturating `i128` arithmetic, so a sufficiently large borrowed scaled balance multiplied by a still-legal borrow index panics with `GenericError::MathOverflow` before `update_borrow_index` can clamp the index. Because withdrawal, repayment, liquidation seizure, and direct index accrual all synchronize the market first, an unprivileged caller can make the market permanently unusable by opening a very large debt position and then waiting for enough index growth.

### Finding Description
The accrual path first evaluates `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)` to compute utilization. [1](#0-0)  `scaled_to_original` is implemented as `scaled.mul(env, index)`. [2](#0-1)  `Ray::mul` delegates to `mul_div_half_up`, which panics with `GenericError::MathOverflow` when the fixed-point result cannot fit in `i128`. [3](#0-2) [4](#0-3) 

The borrow-index cap is applied only after this value conversion. `accrue_step` calls `update_borrow_index` after computing `borrowed_original`, while `update_borrow_index` itself multiplies the old index by the interest factor and clamps the resulting index to `MAX_BORROW_INDEX_RAY`. [5](#0-4) [6](#0-5)  Thus, `borrowed_scaled * borrow_index` can exceed `i128::MAX` even though `borrow_index < MAX_BORROW_INDEX_RAY`.

The pool executes this accrual for each elapsed chunk before changing or committing market state. [7](#0-6) [8](#0-7)  Withdraw and repay are documented and implemented to accrue interest before burning shares or processing payment. [9](#0-8) [10](#0-9)  Liquidation seizure likewise calls `ops::synced_market` before socializing debt. [11](#0-10) 

An attacker reaches this through the normal unprivileged controller surface: `supply`, `borrow`, and `update_indexes` with a `HubAssetKey { hub_id, asset }`. The exploit does not require privileged parameters, oracle manipulation, malformed tokens, or a swap venue; it only needs an admitted high-decimals market, enough collateral to pass `borrow`, and time-driven interest accrual.

### Impact Explanation
Once `scaled debt × borrow index` crosses the `i128` value ceiling, every operation that must first synchronize the market reverts with `MathOverflow`. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot seize or clean bad debt, and `update_indexes` cannot advance the market.

This is a permanent freezing of user funds, not a fail-closed rejection of an invalid input. The stored scaled debt remains valid, and the borrow index remains below the protocol cap, but subsequent accrual can never get past the pre-cap value multiplication. The repository's own regression test demonstrates that a market at 98% utilization eventually fails `update_indexes` and then rejects both withdrawal and repayment while the stored borrow index is still below `MAX_BORROW_INDEX_RAY`. [12](#0-11) 

### Likelihood Explanation
The trigger requires a very large market: the regression fixture uses a billion whole units of an 18-decimal asset and sustained 98% utilization. [13](#0-12)  Those balances are economically substantial, so ordinary markets may never approach the threshold.

However, the condition is reachable entirely through normal protocol actions and deterministic elapsed-time accrual. After the threshold is reached, no attacker action is needed to maintain the denial of service; every market operation deterministically panics. The issue is therefore High rather than Critical: it can permanently freeze all funds in one affected market, but it requires an unusually large debt book and collateral-backed borrowing rather than allowing direct theft.

### Recommendation
Saturate or bound market-value conversions before index growth makes them unrepresentable. In `accrue_step`, use a saturating `scaled_to_original` calculation for utilization and reward calculations, or explicitly cap total debt/supply value at the maximum representable RAY value before calling `Ray::mul`.

Preferably enforce a scaled-exposure ceiling that guarantees `scaled_amount * MAX_BORROW_INDEX_RAY` and `scaled_supply * MAX_SUPPLY_INDEX_RAY` fit in `i128` at borrow/supply admission time. If that is not possible, handle the accrual overflow by clamping the index first or by recording a terminal saturated state that still permits repayment, withdrawal, liquidation, and bad-debt processing using saturating value math.

### Proof of Concept
1. Governance creates a market for an 18-decimal token and an ordinary collateral market, with caps high enough to admit the position.
2. Attacker supplies `1_000_000_000 * 10^18` base units of the debt asset to create liquidity.
3. Attacker supplies sufficient collateral and calls `borrow(account_id, leg(debt_asset, 980_000_000 * 10^18), receiver)` so utilization is approximately 98%.
4. After enough elapsed ledger time, call `update_indexes(vec![HubAssetKey { hub_id, asset: debt_asset }])`.
5. `accrue_step` computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` before applying the index cap. The product exceeds `i128::MAX`, so `Ray::mul` panics with `GenericError::MathOverflow`.
6. Repeat `withdraw`, `repay`, `liquidate`, or `clean_bad_debt`; each path attempts market synchronization first and hits the same overflow.

The repository already encodes this exact scenario in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`: it supplies the large asset, borrows 98%, advances time until `try_update_indexes` returns `MATH_OVERFLOW`, verifies `borrow_index < MAX_BORROW_INDEX_RAY`, and confirms both withdrawal and repayment fail with the same error. /// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
