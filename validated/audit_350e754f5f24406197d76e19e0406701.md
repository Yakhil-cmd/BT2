### Title
Webhook signature authenticates an organization but the payload's `repository.full_name` (unbound to that organization) is used to select the target repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which organization's `webhook_secret` to validate the HMAC signature against by reading `repository.owner.login` (or `organization.login`) straight out of the untrusted, not-yet-verified request body [1](#0-0) . That field is used only to select the secret; the field that handlers actually act on to locate and mutate a stack — `repository.full_name` — is a completely separate, independently-controlled field of the same JSON body [2](#0-1) . The signature only proves "this body was signed with organization X's secret"; it proves nothing about which repository the body's `full_name` field refers to. This breaks the intended binding `organization authenticated == organization owning the repository written to`.

### Finding Description
`Shipit.github(organization: repository_owner)` selects a `GitHubApp` instance (and its `webhook_secret`) keyed by the organization named in the payload [3](#0-2) , resolved via `github_app_config(organization)` from the multi-tenant `secrets.github` config [4](#0-3) . `GitHubApp#verify_webhook_signature` then HMAC-validates the raw body against that organization's own secret [5](#0-4) .

Once verified, `WebhooksController#create` re-parses the same raw body and dispatches it, unmodified, to the registered handlers for the event type [6](#0-5) . For a `push` event, `PushHandler` resolves the target `Repository`/stacks purely from `payload.dig('repository', 'full_name')` [2](#0-1) , and `Repository.from_github_repo_name` does a global lookup by owner/name with no relation to which organization's secret validated the signature [7](#0-6) . It then calls `stack.sync_github(expected_head_sha: params.after)` on every matching, non-archived stack on the named branch [8](#0-7) .

Because `repository.owner.login` (used for secret selection) and `repository.full_name` (used for the actual database lookup/action) are two independent JSON fields, and Shipit supports hosting multiple organizations each with their own configured `webhook_secret` [9](#0-8) , an attacker who legitimately controls (or knows the webhook secret of) organization "A" configured in this Shipit instance can craft an arbitrary raw JSON body where `repository.owner.login = "A"` (so it validates against A's known secret) but `repository.full_name = "victim-org/victim-repo"`. The signature check passes — it was never meant to, and never does, bind the org used for verification to the repository field the handler subsequently trusts.

### Impact Explanation
This crosses a tenant/organization trust boundary without any repository write access, ApiClient token, GitHub team membership, or Shipit session for the victim's repo/organization: knowledge of organization A's `webhook_secret` (an org the attacker legitimately administers as a Shipit tenant) is sufficient to make Shipit believe a forged push notification about a repository belonging to a completely different tenant/org is authentic. This lets the attacker force `stack.sync_github` (and, depending on stack configuration, downstream continuous-deployment triggers) on any stack in the instance, an unauthorized action against a repository/stack the attacker has no legitimate authority over — matching the "organization authenticated versus the repository that is written" binding break called out as in-scope.

### Likelihood Explanation
Requires a multi-organization Shipit deployment where more than one org is configured under `secrets.github` (a documented, supported configuration) and requires the attacker to know a valid `webhook_secret` for at least one configured org — realistic if the attacker is themselves the administrator of one tenant org in a shared/managed Shipit instance, which is a normal, unprivileged position relative to other tenants' repositories.

### Recommendation
After signature verification, re-derive the organization from the same trusted field used for verification and require `repository.full_name`'s owner segment to match that verified organization before any handler acts on it (or verify the signature keyed by the repository actually referenced in `full_name`, not by a separately-read `owner.login`/`organization.login` field). Reject the webhook if the two do not match.

### Proof of Concept
1. Shipit is configured for two tenant organizations, `org-a` and `org-b`, each with its own `webhook_secret` under `secrets.github` [10](#0-9) . `org-b` owns repository `org-b/victim-repo`, which has a Shipit stack tracking branch `main`.
2. Attacker administers `org-a` and knows `org-a`'s `webhook_secret` (their own tenant's secret).
3. Attacker computes `sha1=HMAC(org-a_webhook_secret, body)` over a crafted raw JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": { "full_name": "org-b/victim-repo", "owner": { "login": "org-a" } }
}
```
4. POST this body with header `X-Hub-Signature: sha1=<computed>` and `X-Github-Event: push` to `/webhooks`.
5. `verify_signature` reads `repository_owner` = `"org-a"` [11](#0-10) , loads `org-a`'s `GitHubApp`, and the signature validates successfully because it was computed with `org-a`'s real secret.
6. `create` dispatches the parsed body to `PushHandler`, which looks up `org-b/victim-repo`'s stacks via `Repository.from_github_repo_name("org-b/victim-repo")` [2](#0-1)  and invokes `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on `org-b`'s stack — despite the attacker having no relationship to `org-b` or `victim-repo`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
