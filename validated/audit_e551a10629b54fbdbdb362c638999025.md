### Title
`MembershipHandler#process` mutates any `Team`'s members using an org identity that `verify_signature` never binds to that Team - ([File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App config to validate the HMAC signature purely from `params.dig('organization', 'login')` when no `repository` key is present in the payload, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org's `webhook_secret` is unset. `MembershipHandler` never re-checks `params.organization.login` against the organization that actually owns the `Team` row it mutates - it looks the team up solely by the attacker-supplied `params.team.id` (`github_id`), so an attacker who can satisfy signature verification for any org (e.g., one with no configured `webhook_secret`) can add/remove members on a `Team` belonging to a completely different organization.

### Finding Description
The claimed binding is: `organization authenticated by verify_signature (params.organization.login used to pick the GitHub App / webhook_secret)` == `organization owning the Team row mutated by MembershipHandler#process`.

- `MembershipHandler`'s params schema requires only `team` and `organization`/`member`, with **no `repository` key at all**: [1](#0-0) 
- Because `repository` is absent, `WebhooksController#repository_owner` falls back to `params.dig('organization', 'login')` - a value taken straight from the unauthenticated JSON body: [2](#0-1) 
- `verify_signature` uses that same attacker-controlled value to pick which GitHub App config (and thus which `webhook_secret`) to validate against: [3](#0-2) 
- `GitHubApp#verify_webhook_signature` returns `true` with no further check when the resolved org's `webhook_secret` is blank: [4](#0-3) 
- `MembershipHandler#process` then resolves the mutated record purely via `find_or_create_by!(github_id: params.team.id)`, which for an **existing** record returns the stored row untouched (the block only runs on creation, so `team.organization` is not re-validated against `params.organization.login` for existing teams), and directly mutates `team.members`: [5](#0-4) 

Exploit flow: attacker sends a `POST /webhooks` request with header `X-Github-Event: membership` and a JSON body where `organization.login` is set to any org whose Shipit-side config has no `webhook_secret` (a value the attacker can freely choose from the body itself, and which is exactly the org used to pick the signature-verification config), `team.id` set to the numeric `github_id` of a target `Team` belonging to an unrelated organization (team IDs are visible in public GitHub UI/API responses and are low-entropy integers), and `member.login`/`action` set to add or remove an arbitrary GitHub user. `verify_signature` passes (secret-less org), `drop_unhandled_event` passes because `membership` is a handled event, and `MembershipHandler#process` finds the existing target `Team` by `github_id` and calls `team.add_member(member)` or `team.members.delete(member)` with no cross-check that `params.organization.login` corresponds to the org that actually owns that `Team`.

No other guard intercepts this: `ExplicitParameters` only validates types/presence, not cross-object ownership; `force_github_authentication`, `User#authorized?`, and `require_permission!` are session/API-token controls not invoked on the public `/webhooks` endpoint; `Repository`/`Stack` validators are irrelevant since no `Repository`/`Stack` is touched by this handler.

### Impact Explanation
An attacker can unauthenticated-ly add or remove members on any `Team` record in the Shipit instance, provided they can get `verify_signature` to pass for the organization name they place in the payload (trivial if any configured org has no `webhook_secret`). Since `Shipit.github_teams` authorization (`User#authorized?`) is driven by `Team` membership, this is an escalation vector into `Shipit.github_teams` authorization by adding an attacker-controlled GitHub login to a privileged team, or a denial of access by removing legitimate members - a cross-tenant mutation of a `Team` record that the requesting "identity" never legitimately owns, matching the Critical category "a payload for one repository/org mutating another's ... team." This is fully repeatable against any `Team` whose `github_id` the attacker can observe or guess, for as long as any org in the deployment lacks a `webhook_secret`.

### Likelihood Explanation
Requires one precondition outside pure attacker control: some organization configured in the Shipit deployment's GitHub App config has a blank/missing `webhook_secret` (an operator misconfiguration, not a secret the attacker must possess). Given that precondition — which the question stipulates ("attacker whose own org has no webhook_secret configured") — the rest of the attack requires zero credentials: no session, no API token, no GitHub secret, just an HTTP POST with a guessed/observed numeric `team.id`. This is a low-cost, fully repeatable, unauthenticated attack once the misconfiguration exists.

### Recommendation
- In `MembershipHandler#process` (and any other handler that mutates a pre-existing record by an attacker-suppliable numeric ID), verify that `params.organization.login` matches the `organization` already stored on the found `Team` before allowing member mutation, and reject if they differ.
- More generally, `WebhooksController#repository_owner`/`verify_signature` should not use unauthenticated payload fields to select the verification secret without also confirming, post-verification, that the resource identifiers in the payload structurally belong to that same organization.
- Do not allow `verify_webhook_signature` to silently return `true` for orgs with no `webhook_secret`; require a secret to be configured for every org accepted by the webhook endpoint, or reject payloads for orgs with no secret configured.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`-style, no live GitHub):
1. Configure two orgs in the test `Shipit.github` config: `victim-org` (has a `webhook_secret`) and `attacker-org` (no `webhook_secret`).
2. Create a `Team` fixture with `organization: 'victim-org'`, `github_id: 4242`, and one existing `Membership`.
3. POST to `/webhooks` with header `X-Github-Event: membership`, no signature header value that matches `victim-org`'s secret, and JSON body:
   ```json
   { "action": "added",
     "team": {"id": 4242, "name": "Victim Team", "slug": "victim-team", "url": "https://api.github.com/teams/4242"},
     "organization": {"login": "attacker-org"},
     "member": {"login": "attacker-controlled-user"} }
   ```
4. Assert response is `200 OK` (signature accepted because `attacker-org` has no secret) — this is the "authenticated org" side of the binding: `attacker-org`.
5. Reload the `Team` fixture (`github_id: 4242`, `organization: 'victim-org'`) — this is the "mutated org" side of the binding: `victim-org`.
6. Assert `team.members.include?(User.find_by(login: 'attacker-controlled-user'))` is `true`, proving the org authenticated (`attacker-org`) is not the org whose `Team` was mutated (`victim-org`), breaking the claimed equality and demonstrating unauthenticated cross-org membership mutation.

        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
