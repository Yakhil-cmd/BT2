## Analog Found: Proxy `is_superset` claims full coverage of `Auction` while `NonTransfer`'s own filter explicitly denies `Registrar::swap`

### Title
`NonTransfer` proxy privilege escalation via chained `add_proxy`→`Auction` hop reaches explicitly-denied `Registrar::swap` - ([File: polkadot/runtime/rococo/src/lib.rs])

### Summary
The wger bug is a session-flag reuse: a permission state set for one narrow purpose (`trainer.identity`) is silently reused to authorize a second, broader hop the checker never re-validates. The exact analog exists in `pallet-proxy`'s `InstanceFilter` implementations for `ProxyType::NonTransfer` in `polkadot/runtime/rococo/src/lib.rs`, `polkadot/runtime/westend/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`. `is_superset()` unconditionally declares `NonTransfer` a superset of every other `ProxyType`, including `Auction`, even though `NonTransfer`'s own `filter()` deliberately excludes `Registrar::swap` (explicitly commented "Specifically omitting Registrar `swap`") while `Auction`'s `filter()` admits the entire `Registrar` call family, including `swap`. [1](#0-0) [2](#0-1) [3](#0-2) 

The same exact pattern repeats in Westend and the `rc` staking-async runtime: [4](#0-3) [5](#0-4) 

Note that a *nearly identical* class of bug was already found and fixed on Asset Hub Westend (`NonTransfer` falsely claiming `Governance` as a subset), documented in `prdoc/pr_12769.prdoc` and guarded by a regression test — but the fix did not address the `NonTransfer`/`Auction` mismatch that remains in the relay-chain runtimes. [6](#0-5) [7](#0-6) 

### Finding Description
`pallet-proxy`'s `do_proxy` enforces that a proxy call adding/removing another proxy cannot grant more permission than the acting proxy already has, via `def.proxy_type.is_superset(proxy_type)`: [8](#0-7) 

For a chained/generic (non-proxy-pallet) call, the guard simply falls back to `def.proxy_type.filter(c)` — i.e. the filter attached to whichever `ProxyType` was used to find the proxy definition for that specific dispatch: [9](#0-8) 

In Rococo (and Westend, and staking-async `rc`), the runtime declares:
- `NonTransfer.filter()` admits `RuntimeCall::Proxy(..)` (the whole proxy pallet) and `RuntimeCall::Registrar(register|deregister|reserve)` only — explicitly **not** `swap`.
- `Auction.filter()` admits `RuntimeCall::Registrar { .. }` unconditionally — **including** `swap`.
- `is_superset()` states `(ProxyType::NonTransfer, _) => true` for **any** other `ProxyType`, i.e. it claims `NonTransfer ⊇ Auction` without verifying that `NonTransfer`'s filter actually covers every call `Auction`'s filter admits.

This is the same root-cause shape as the wger bug: a check (`is_superset`) is treated as authoritative for whether a "session" (proxy type) may escalate into another, but the two independent state machines (`filter()` allow-list and `is_superset()` claim) have silently drifted apart, so the "AND"/subset invariant the caller relies on (do_proxy) no longer holds for the specific denied call (`Registrar::swap`).

### Impact Explanation
An account holding only a `NonTransfer` proxy for a delegator — explicitly meant to exclude `Registrar::swap` — can chain two ordinary, individually-permitted proxy calls to grant itself an `Auction` proxy over the same delegator, then invoke `Registrar::swap` through that new proxy record, on behalf of the delegator. This defeats the delegator's intended narrowing of authority (the very purpose of `ProxyType` differentiation) and lets a lower-privileged proxy reach a call class it was never meant to reach — an authorization/privilege-management defect (CWE-269), matching the `NonTransfer`/`Governance` class that Parity itself already patched on Asset Hub Westend but left open here for `Auction`.

### Likelihood Explanation
High reachability: both `add_proxy` and `proxy` are ordinary signed extrinsics reachable by any account that has already been granted a `NonTransfer` proxy by a delegator (a normal, common grant — `NonTransfer` is meant to be a broad, low-risk default). No governance, no stolen keys, no privileged role is required — only possession of an ordinary `NonTransfer` delegation, which the delegator believes intentionally excludes `swap`.

### Recommendation
Make `is_superset()` structurally derived from (or verified against) `filter()` so that a `ProxyType` can only claim superset status over another type if it is provably a strict superset of that type's allowed call set — the same fix pattern already applied for `NonTransfer`/`Governance` in `asset-hub-westend` (`prdoc/pr_12769.prdoc`) should be extended to remove `NonTransfer ⊇ Auction` in `polkadot/runtime/rococo/src/lib.rs`, `polkadot/runtime/westend/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, or explicitly special-case `Registrar::swap` out of `Auction`'s filter reachability via `NonTransfer` chaining.

### Proof of Concept
Traced (not executed against a live network, per instructions) through exact code paths:
1. Delegator `A` grants proxy `D` a `NonTransfer` proxy (ordinary `add_proxy` call).
2. `D` calls `Proxy::proxy(origin=D, real=A, force_proxy_type=Some(NonTransfer), call=Proxy::add_proxy{delegate: D, proxy_type: Auction, delay: 0})`.
   - `do_proxy`'s guard for `add_proxy`: `!def.proxy_type.is_superset(&Auction)` = `!NonTransfer.is_superset(&Auction)` = `!true` = `false` → guard doesn't block.
   - Falls through to `def.proxy_type.filter(c)` = `NonTransfer.filter(add_proxy call)` = `true` (whole `Proxy` pallet admitted). **`D` is now also registered as an `Auction` proxy for `A`.**
3. `D` calls `Proxy::proxy(origin=D, real=A, force_proxy_type=Some(Auction), call=Registrar::swap{..})`.
   - `find_proxy` resolves the newly created `Auction` `ProxyDefinition`.
   - `do_proxy`'s guard falls to `_ => def.proxy_type.filter(c)` = `Auction.filter(Registrar::swap)` = `true`.
   - `Registrar::swap` dispatches under `A`'s signed origin — a call class the `NonTransfer` grant's own source comment states is deliberately excluded.

I was unable to execute this against a running node/test harness in this environment (no filesystem/terminal access here); this is a traced code-path proof through the exact `is_superset`/`filter` mismatch, matching the already-fixed sibling bug's shape (`prdoc/pr_12769.prdoc`), which itself confirms Parity treats this exact class of "false superset claim → escalation via proxy chaining" as a valid, fixable vulnerability class.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));
