### Title
Bad-debt socialization in `liquidate` is unreachable because the trigger condition checks the wrong variable, leaving uncollateralized debt permanently unsocialized - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`liquidate()` is supposed to automatically socialize (write off) any debt that remains after a borrower's collateral of a given asset is fully exhausted. The trigger for this is the `no-collateral-left` flag, which checks `(is-eq coll-removed u0)`. However, `coll-removed` is the return value of the `collateral-remove` vault call using `coll-final`, and the function already asserts `(> coll-final u0)` earlier in the same call before any collateral is removed. Consequently `coll-removed` can never be `0` in a successful liquidation, so `no-collateral-left` can never be `true`, and `socialize-debt-asset` is effectively dead code. Any position whose entire collateral balance for an asset is drained in a single `liquidate` call, while debt remains outstanding, is left with permanently un-socialized bad debt.

### Finding Description
In `liquidate`, the "dust sweep" logic computes `coll-final` (the collateral amount actually seized), and this value is asserted to be greater than zero before any state mutation occurs: [1](#0-0) 

Later, the same non-zero `coll-final` is passed to the vault's `collateral-remove`, and its return value is stored as `coll-removed`, which is then used as the sole indicator that "no collateral is left" for socialization purposes: [2](#0-1) 

Because `coll-final` was already required to be `> 0` at line 1492, and the vault removes exactly that requested (already-capped) amount, `coll-removed` is always non-zero in a successful call. Therefore `(is-eq coll-removed u0)` is always `false`, `no-collateral-left` is always `false`, and the block that calls `socialize-debt-asset` to write off the borrower's remaining debt is never executed: [3](#0-2) 

This is structurally the same class of issue as the referenced Tapioca finding: a liquidator's ordinary liquidation call causes a position to end up with collateral fully exhausted and debt still outstanding, but the code path meant to formally recognize/socialize that bad debt is bypassed - here not through parameter manipulation but through a broken condition, making the bypass unconditional and automatic rather than something the liquidator must engineer.

### Impact Explanation
When a position's collateral for an asset is fully drained (e.g. via a severe price crash, exactly the scenario exercised in the repo's own test `ATK-LG-05: Bad debt cannot be artificially created`), the leftover, now fully uncollateralized debt is never removed from the borrower's obligations nor written down via `vault-socialize-debt`. That debt remains recorded as outstanding in the vault's accounting indefinitely. This:
- Understates the protocol's real losses and distorts total-debt/utilization/interest-rate calculations that assume all recorded debt is real.
- Leaves depositors of that debt asset unaware their claims are partially unbacked, since the loss is never formally recognized and reserves are never adjusted.
- Ultimately risks depositors being unable to fully withdraw once the shortfall surfaces, i.e., protocol insolvency / freezing of depositor funds - impacting an unprivileged set of victims (all suppliers of that asset) distinct from the liquidator (caller) or the borrower.

### Likelihood Explanation
This does not require any special manipulation by the liquidator - it triggers on the natural, intended "collateral fully exhausted" liquidation path that the protocol's own security test suite explicitly exercises. Any liquidation that fully drains a borrower's collateral for an asset while debt remains (a routine and expected event during market downturns) will hit this dead code path every single time.

### Recommendation
Change the trigger condition to reflect whether the borrower's remaining balance of that collateral asset is zero after the liquidation, e.g. compare `user-coll-balance` to `coll-final` (`(is-eq coll-final user-coll-balance)`) rather than checking `coll-removed` for zero, so that `socialize-debt-asset` actually fires whenever a position's collateral for the liquidated asset is fully depleted while debt remains.

### Proof of Concept
1. Borrower deposits collateral and borrows heavily against it (as in `ATK-LG-05`): `collateralAdd(sBTC, 1 BTC)`, `borrow(USDC, $42k)`. [4](#0-3) 
2. Collateral price crashes so that 1 BTC is worth far less than the debt (e.g. $10k), making the position deeply underwater.
3. A liquidator calls `liquidate` requesting to repay more than the position can support; `coll-final` is capped at `user-coll-balance` (the full 1 BTC), `coll-final` is asserted `> 0` and passed to `collateral-remove`, returning `coll-removed = 1 BTC` (non-zero).
4. `debt-final` (and thus `scaled-to-remove`) only covers the portion the seized collateral can pay for (`coll-actual-usd / (1+penalty)`), leaving a large remainder of `debt_updated` still recorded against the borrower.
5. `no-collateral-left` evaluates to `false` because `coll-removed ≠ 0`, so `socialize-debt-asset` never runs even though the borrower now has 0 collateral of that asset and outstanding, un-collateralized debt.
6. The un-socialized debt remains permanently on the books; no further call can trigger socialization for this asset, because any subsequent `liquidate` attempt against 0 remaining collateral will fail the earlier `(> coll-final u0)` assertion.
