### Title
KIP-71 Bound Inversion via Independent Per-Vote Consistency Checks Allows Corrupted Base-Fee State — (`File: kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` validates each governance vote for `kip71.lowerboundbasefee` and `kip71.upperboundbasefee` independently against the **currently effective** parameter set, without considering other pending votes in the same epoch. Two votes cast in the same epoch — one raising `LowerBoundBaseFee` above the current upper bound, one lowering `UpperBoundBaseFee` below the current lower bound — each pass their individual check, but when both are ratified together at the epoch boundary they produce an inverted state (`LowerBound > UpperBound`). This corrupts `NextMagmaBlockBaseFee`, causing the fee market to behave in reverse and producing a deterministic but economically invalid base-fee sequence that all nodes accept.

---

### Finding Description

`VerifyVote` in `kaiax/gov/headergov/impl/header.go` calls `checkConsistency` for every vote as it arrives:

```go
// kaiax/gov/headergov/impl/header.go:179-192
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    } else {
        return nil
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    } else {
        return nil
    }
```

`h.GetParamSet(blockNum)` returns the parameter set ratified in the **previous** epoch — it is blind to any other votes already accumulated in the **current** epoch. [1](#0-0) 

Suppose the current effective values are `LowerBound = 25 gwei`, `UpperBound = 750 gwei`:

| Block | Vote | Check performed | Result |
|-------|------|-----------------|--------|
| X (epoch k) | `LowerBoundBaseFee = 500 gwei` | `500 <= 750` (current upper) | ✓ accepted |
| Y (epoch k, Y > X) | `UpperBoundBaseFee = 100 gwei` | `100 >= 25` (current lower) | ✓ accepted |

At the epoch-k boundary both votes are ratified together into `header.Governance`. The ratification logic in `getExpectedGovernance` simply collects the last vote per parameter name in the epoch — it performs no cross-parameter consistency check: [2](#0-1) 

After the epoch boundary: `LowerBound = 500 gwei`, `UpperBound = 100 gwei` — inverted.

---

### Impact Explanation

`NextMagmaBlockBaseFee` in `params/kip71_config.go` clamps `parentBaseFee` to `[lowerBound, upperBound]` before computing the next fee. With inverted bounds the clamping logic is: [3](#0-2) 

```go
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {   // >= 100 gwei → clamp DOWN to 100
    parentBaseFee = upperBoundBaseFee
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 { // <= 500 gwei → clamp UP to 500
    parentBaseFee = lowerBoundBaseFee
}
```

Because `upperBound (100) < lowerBound (500)`, every `parentBaseFee` satisfies the first branch and is clamped to 100 gwei. The subsequent decrease path then tries to go below 100 gwei and is floored at `lowerBoundBaseFee = 500 gwei`, producing a fee that is **above** the supposed upper bound. The fee market is inverted: low gas usage drives the base fee up to 500 gwei; high gas usage caps it at 100 gwei.

`VerifyMagmaHeader` enforces that every block's `BaseFee` equals `NextMagmaBlockBaseFee(...)` computed from the governance parameter set: [4](#0-3) 

Because all honest nodes share the same (inverted) governance state, they all compute the same wrong expected base fee and accept blocks with that fee. The chain continues, but every transaction's effective gas cost is computed against a corrupted base fee, permanently distorting fee revenue, burnt-fee accounting, and miner/staker reward distribution until a corrective governance vote is ratified one full epoch later.

---

### Likelihood Explanation

Exploitable in any network configured with `governance.governancemode = "none"`. In `none` mode any council member (validator) may cast a vote; two validators independently voting for conflicting bounds in the same epoch is sufficient. No coordination or privileged access beyond normal validator participation is required. Mainnet and Kairos use `single` mode (only the governing node votes), so on those networks the governing node would have to cast both conflicting votes intentionally — a privileged action. However, the code path is fully reachable on any `none`-mode deployment, and the consistency check gap exists unconditionally in the shared codebase.

---

### Recommendation

Replace the independent per-vote bound checks with a joint check that also considers any pending vote for the **counterpart** bound already accumulated in the current epoch. Concretely, inside `checkConsistency`:

- For `Kip71LowerBoundBaseFee`: resolve the effective upper bound as `min(params.UpperBoundBaseFee, pendingUpperBoundVoteIfAny)` before comparing.
- For `Kip71UpperBoundBaseFee`: resolve the effective lower bound as `max(params.LowerBoundBaseFee, pendingLowerBoundVoteIfAny)` before comparing.

Alternatively, add a cross-parameter consistency check at ratification time inside `getExpectedGovernance` / `VerifyGov` that rejects any epoch-boundary `header.Governance` payload where the ratified `LowerBoundBaseFee ≥ UpperBoundBaseFee`.

---

### Proof of Concept

**Setup:** network with `governance.governancemode = "none"`, `epoch = 1000`, current effective `LowerBound = 25 gwei`, `UpperBound = 750 gwei`.

1. **Block 1200** — Validator A is proposer, calls `governance_vote("kip71.lowerboundbasefee", 500_000_000_000)`.
   - `checkConsistency`: `500e9 <= 750e9` (current upper) → accepted. [5](#0-4) 

2. **Block 1800** — Validator B is proposer, calls `governance_vote("kip71.upperboundbasefee", 100_000_000_000)`.
   - `checkConsistency`: `100e9 >= 25e9` (current lower) → accepted. [6](#0-5) 

3. **Block 2000** (epoch boundary) — `getExpectedGovernance` collects both votes; `VerifyGov` confirms the `header.Governance` payload matches. Both parameters are ratified. [2](#0-1) 

4. **Block 2001 onward** — `GetParamSet` returns `LowerBound = 500 gwei`, `UpperBound = 100 gwei`. `NextMagmaBlockBaseFee` clamps every `parentBaseFee ≥ 100 gwei` down to 100 gwei, then floors the result at 500 gwei, producing a base fee of 500 gwei regardless of actual gas usage. [7](#0-6) 

5. `VerifyMagmaHeader` accepts every block with `BaseFee = 500 gwei` because all nodes compute the same inverted expected value. The corrupted fee state persists for the entire next epoch (1000 blocks) until a corrective vote can be ratified. [4](#0-3)

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}
