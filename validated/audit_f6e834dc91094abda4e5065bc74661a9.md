## Title
Unauthorized Shared-Address Injection via Unauthenticated `new_shared_address` Wallet Message - ([File: wallet_defined_by_addresses.js])

### Summary
The `new_shared_address` device-message handler accepts and permanently stores an attacker-supplied multi-signature address definition from *any* paired correspondent device without verifying that the local wallet ever initiated or approved creation of that shared address. This mirrors the mem0 OpenMemory bug class: an endpoint that performs a sensitive write (creating/associating account data) while skipping the authorization step that should gate it, letting an unprivileged caller (here, any paired device) plant attacker-controlled state.

### Finding Description
Any device paired with the victim (a "paired device" per the reachable-actor scope) can send a `new_shared_address` message directly, without going through the intended `create_new_shared_address` → `approve_new_shared_address` handshake. The handler in `wallet.js` dispatches it straight to `wallet_defined_by_addresses.js`: [1](#0-0) 

`handleNewSharedAddress` only performs structural checks — that the definition hashes to the claimed address, that signer addresses referenced in the definition are syntactically valid addresses, and that every path in the definition has a corresponding signer entry: [2](#0-1) 

The only "ownership" check is `determineIfIncludesMeAndRewriteDeviceAddress`, which merely requires that *some* address referenced in the definition already exists in the local `my_addresses` or `shared_addresses` tables — it does not require that the sender's own device/address is genuinely a cosigner, nor that the local wallet ever agreed to this specific shared address: [3](#0-2) 

`validateAddressDefinition` then only checks that the oscript definition is syntactically well-formed (e.g., "each branch must have a signature", complexity limits) via `Definition.validateDefinition` — it never validates that cooperation between the parties is actually required: [4](#0-3) [5](#0-4) 

If all checks pass, `addNewSharedAddress` unconditionally inserts the row into `shared_addresses`/`shared_address_signing_paths`, and for light wallets registers it as a watched address: [6](#0-5) 

Because an attacker fully controls `body.definition`, they can submit something like `["or", [["address","VICTIM_OWNED_ADDR"], ["address","ATTACKER_ADDR"]]]`. `determineIfIncludesMeAndRewriteDeviceAddress` passes because `VICTIM_OWNED_ADDR` is already known locally, and `validateAddressDefinition` passes because an `or` of two signature branches is syntactically valid. The wallet then silently records this address as a legitimate "shared address" the user is associated with — despite the victim never having initiated or approved any multisig arrangement with the attacker.

### Impact Explanation
Once planted, the address is exposed through the wallet's normal shared/control-address bookkeping (e.g. `readAllControlAddresses`, `forwardPrivateChainsToOtherMembersOfAddresses`) and, for light clients, is watched via `network.addLightWatchedAddress`. A victim who is later led to believe this is a genuine cosigned/protected address (e.g., shown in UI as a shared address they participate in) and sends or receives funds to it can have those funds unilaterally swept by the attacker, since the injected definition's `or` branch lets the attacker sign alone — bypassing the multisig protection the victim believes exists. This is an unauthorized-spending / fund-loss vector achievable purely by sending an unsolicited device message, without ever completing the legitimate creation/approval protocol.

### Likelihood Explanation
Likelihood is high for any already-paired correspondent (a normal, low-privilege relationship — e.g., a bot, merchant, or contact the user paired with for an unrelated purpose). No cryptographic break is needed; the message only needs a valid signature from the sender's own device key (standard for any paired device) and a definition that hashes to the claimed address — both trivially satisfiable by the attacker.

### Recommendation
`handleNewSharedAddress` should refuse to add a shared address unless the local device previously agreed to participate in this exact address's creation (e.g., match against a `pending_shared_addresses`/`pending_shared_address_signing_paths` entry created via the `create_new_shared_address`/`approve_new_shared_address` flow, as `approvePendingSharedAddress` does) rather than accepting arbitrary unsolicited definitions from any correspondent. At minimum, warn/require explicit user confirmation before persisting an unsolicited shared address definition, and verify that the sender's own address/device is actually one of the required cosigners along every path that must sign, not merely that some unrelated address is already known locally.

### Proof of Concept
1. Attacker pairs with the victim's wallet (normal pairing flow, no elevated privilege required).
2. Attacker learns one of the victim's real addresses `V` (many wallets share addresses in chat for payment requests).
3. Attacker crafts `arrDefinition = ["or", [["address", V], ["address", A]]]` where `A` is an address they control, computes `address = getChash160(arrDefinition)`, and sends a `new_shared_address` device message: `{address, definition: arrDefinition, signers: {"r.0": {address: V}, "r.1": {address: A}}}`.
4. Victim's `handleNewSharedAddress` passes all checks (`determineIfIncludesMeAndRewriteDeviceAddress` succeeds because `V` is known; `validateAddressDefinition` succeeds because `or` of two signed branches is valid) and stores the shared address.
5. If the victim (or anyone) later funds `address` believing it requires both parties' cooperation, the attacker alone can spend it via the `or` branch, resulting in unauthorized fund loss.

// It is possible that my device address is not mentioned in the definition if I'm a member of multisig address, one of my cosigners is mentioned instead
function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
