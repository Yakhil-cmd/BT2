Confirmed multi-organization support: `Shipit.github(organization:)` resolves credentials per-organization via `github_app_config(organization)`, keyed by the `organization` string itself [1](#0-0) . `WebhooksController#verify_signature` derives that `organization` argument directly from attacker-controlled JSON body fields (`repository.owner.login` or `organization.login`), then verifies `X-Hub-Signature` against the secret configured for that same string [2](#0-1) . However, the downstream handlers (`PushHandler`, `Handler#repository_name`, `ClosedHandler`, `LabeledHandler`, etc.) resolve the target `Repository`/`Stack` purely from `payload.dig('repository', 'full_name')` — a separate, independently attacker-controlled field that is never cross-checked against `repository.owner.login` used for signature verification [3](#0-2) [4](#0-3) [5](#0-4) .

This is analogous to the DYAD bug class: the field that is cryptographically bound/checked (`repository.owner.login`, used to select the webhook secret) is not the same field that is actually acted upon (`repository.full_name`, used to select which `Stack`/`Repository` gets synced, archived, unarchived, or has commit statuses/deployments written). In a Shipit deployment configured with multiple organizations (`secrets.github` keyed by org, each with its own `webhook_secret`), an attacker who controls (or compromises) one onboarded organization's webhook secret — e.g., by owning a repo in "org-a" that has this Shipit instance installed as a GitHub App — can craft a raw JSON body where `repository.owner.login = "org-a"` (satisfies signature check, since that's the string used to look up the HMAC secret) but `repository.full_name = "org-b/victim-repo"` (a different organization's repository tracked by the same Shipit instance). The `X-Hub-Signature` is computed over the full raw body using org-a's secret, so it validates. The handler then acts on `org-b/victim-repo`'s `Stack`, e.g. triggering `GithubSyncJob`/`sync_github` for arbitrary commits, or archiving/unarchiving pull-request-driven review stacks, or writing commit statuses, for a repository the attacker does not control.

### Title
Webhook signature verification keys off `repository.owner.login` while handlers act on the independently-controlled `repository.full_name`, enabling cross-organization stack manipulation - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which organization's HMAC `webhook_secret` to validate against using `repository.owner.login` (or `organization.login`) from the unauthenticated JSON body, then verifies `X-Hub-Signature` over the whole raw body with that secret. Every webhook handler that determines *what* to modify (push syncs, PR-driven stack archive/unarchive, commit statuses) instead reads `repository.full_name`, a separate JSON field that is not tied to the field used for secret selection.

### Finding Description
- Verification: `github_app = Shipit.github(organization: repository_owner)` where `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')`, then `github_app.verify_webhook_signature(header, raw_body)` [6](#0-5) .
- Credential selection: `Shipit.github(organization:)` looks up `github_app_config(organization)` from `secrets.github`, keyed by organization name, and instantiates/returns a `GitHubApp` scoped to that org's `webhook_secret` [1](#0-0) .
- Signature check: `verify_webhook_signature` HMACs the *entire raw body* with that org's secret and compares to the header — it does not bind the signature to any specific field being "authorized," it only proves "whoever sent this knows org X's secret" [7](#0-6) .
- Action target: `Shipit::Webhooks::Handlers::Handler#stacks`/`#repository_name` reads `payload.dig('repository','full_name')` to find the `Repository` and its `Stack`s to act on [3](#0-2) ; `PushHandler#process` calls `stack.sync_github` for the matched stacks [8](#0-7) ; PR handlers (`ClosedHandler`, `LabeledHandler`, `UnlabeledHandler`, `ReopenedHandler`) similarly resolve `Repository.from_github_repo_name(params.repository.full_name)` and call `archive!`/`unarchive!` on review stacks [5](#0-4) [9](#0-8) .

The binding that should hold is: `organization used to select/verify the HMAC secret == organization owning the repository actually acted upon`. Nothing in the controller or handlers enforces `repository.owner.login == repository.full_name.split('/').first`, so these two independently-attacker-supplied fields can diverge.

Before the attack: an attacker with legitimate access to only "org-a" (a repo installed on this Shipit instance, giving them knowledge of `github.org-a.webhook_secret` via, e.g., a compromised or malicious member of org-a with app-install rights) can only affect org-a's stacks.

After the attack: by setting `repository.owner.login = "org-a"` (used solely for `verify_signature`) and `repository.full_name = "org-b/victim-repo"` (used solely by the handler), the attacker forges a signature that passes verification yet drives sync/archive/status actions against org-b's stacks, which the attacker never had trust over.

### Impact Explanation
This crosses the "organization authenticated versus repository written" trust boundary explicitly called out in scope. Concretely it allows unauthorized cross-repository/cross-organization writes: forcing `GithubSyncJob` to run against an arbitrary victim stack with an attacker-chosen `expected_head_sha`, or archiving/unarchiving review-stack deployments for a repository the attacker does not own, on any multi-organization Shipit deployment. This maps to the "Critical - cross-repository writes / unauthorized deploy" impact bucket, since `sync_github` and stack archive/unarchive actions influence what gets considered deployable and can affect deploy behavior for a repository outside the attacker's own organization.

### Likelihood Explanation
Requires the Shipit instance to be configured with the multi-organization `secrets.github` schema (keyed by organization, each with its own `webhook_secret`) — this is a supported, documented configuration, not a hypothetical one (`github_app_config`/`github_default_organization` exist specifically for it) [10](#0-9) . It further requires the attacker to know one onboarded organization's webhook secret, which is the normal precondition for any org integrated with this instance to send authenticated webhooks — no special privilege beyond being a legitimate webhook sender for their own org is needed to attempt cross-org spoofing.

### Recommendation
After verifying the signature, re-derive the acting organization strictly from `repository.owner.login` (the value already used for signature verification) and pass it explicitly into every handler; reject or ignore any webhook where `repository.full_name.split('/').first` (case-insensitively) does not match the verified `repository_owner`. Equivalently, scope `Repository.from_github_repo_name` / `stacks` lookups to only repositories belonging to the verified organization.

### Proof of Concept
1. Configure `secrets.github` with two orgs, `org-a` and `org-b`, each with a distinct `webhook_secret`, both integrated with the same Shipit instance (org-b has a tracked `Stack` for `org-b/victim-repo`).
2. As an actor who knows `org-a`'s `webhook_secret` (e.g., a malicious org-a admin with access to the GitHub App's webhook config), craft a `push` event JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": { "full_name": "org-b/victim-repo", "owner": { "login": "org-a" } }
}
```
3. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(org-a secret, raw_body)>` and POST to `/github/webhooks`.
4. `verify_signature` resolves `repository_owner = "org-a"`, fetches org-a's `GitHubApp`, and the HMAC matches — request passes [11](#0-10) .
5. `PushHandler#process` resolves stacks via `repository.full_name = "org-b/victim-repo"` and enqueues `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` for org-b's stack [8](#0-7) , despite the signing organization being org-a.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
