### Title
`ProxyType::NonTransfer` fail-open deny-list lets a value-restricted proxy move funds via `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive` and `Indices::transfer` on Asset Hub Rococo - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
On `asset-hub-rococo`, `pallet_proxy::Config::ProxyType::NonTransfer` is documented/intended (matching the sibling `asset-hub-westend` runtime) as a proxy that "cannot move the delegator's funds or assets." It is implemented as a deny-list (`!matches!(c, Balances|Assets|NftFractionalization|Nfts|Uniques)`) rather than an allow-list, so any pallet call not explicitly named is permitted by default (fail-open). [1](#0-0)  The identical bug class was found and fixed in the sibling `asset-hub-westend` runtime (`prdoc/pr_12771.prdoc`, referencing upstream issue #12466) and in `staking-async` parachain (`prdoc/pr_12922.prdoc`), both of which added `ForeignAssets`, `PoolAssets`, and (for westend) `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, `Indices::transfer/force_transfer` to the deny list. [2](#0-1) [3](#0-2)  No equivalent `prdoc` fix exists for `asset-hub-rococo`, and its `NonTransfer` filter remains unchanged, while its runtime is confirmed to include `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Revive`, and `Psm` pallets (101 references found in the file).

### Finding Description
`pallet_proxy` gates every call dispatched through a delegate account with `InstanceFilter::filter` (via `Config::ProxyType`). [4](#0-3)  A delegator who grants a `NonTransfer` proxy is relying on the filter to block any call that could move their funds or assets to another account, exactly analogous to how the Red-DiscordBot Mod module relied on a hierarchy check to block privilege-escalating actions.

The `asset-hub-rococo` implementation only denies five call families:
```
ProxyType::NonTransfer => !matches!(
    c,
    RuntimeCall::Balances { .. } |
        RuntimeCall::Assets { .. } |
        RuntimeCall::NftFractionalization { .. } |
        RuntimeCall::Nfts { .. } |
        RuntimeCall::Uniques { .. }
),
``` [5](#0-4) 

Because this is a deny-list rather than an allow-list, `filter` returns `true` (permit) for every other pallet call by default — including `ForeignAssets::transfer`, `PoolAssets::transfer`, `AssetConversion::swap_exact_tokens_for_tokens`, `PolkadotXcm::transfer_assets`/`teleport_assets`, `Revive::call` (which carries a `value`), and `Indices::transfer`/`force_transfer` (which repatriates the reserved deposit). These are precisely the call families the `asset-hub-westend` fix (`pr_12771`) had to explicitly add to its deny-list after discovering the same fail-open condition, per its own commit message: "any pallet added to the runtime is reachable by a NonTransfer proxy unless it is listed explicitly." [6](#0-5) 

### Impact Explanation
A `NonTransfer` proxy delegate on `asset-hub-rococo` — a real, permitted, user-controlled entry point (`pallet_proxy::Call::proxy`, dispatched as a normal signed extrinsic) — can call `ForeignAssets::transfer`, `PoolAssets::transfer`, `AssetConversion` swaps, `PolkadotXcm::transfer_assets`/`teleport_assets`, `Revive::call` with a nonzero `value`, or `Indices::transfer`, all executed with the real account's origin (`do_proxy` re-dispatches as `RawOrigin::Signed(real)`). This lets an account the delegator explicitly restricted from moving funds/assets nonetheless move the delegator's foreign assets, pool assets, or send funds off-chain via XCM/contract calls — a direct violation of the proxy's documented invariant, i.e., unauthorized privilege escalation matching CWE-285 (Improper Authorization), the same bug class as the referenced advisory.

### Likelihood Explanation
High likelihood of exploitation whenever a delegator has granted a `NonTransfer` proxy and holds `ForeignAssets`/`PoolAssets` balances, has assets in liquidity pools, or holds funds that can be sent via XCM/contracts — all standard use cases on Asset Hub. No privileged role, governance action, or stolen keys are required; the delegate only needs the `NonTransfer` proxy the delegator legitimately granted them, and dispatches ordinary signed extrinsics through `pallet_proxy::proxy`.

### Recommendation
Apply the same fix already merged for `asset-hub-westend` (`pr_12771.prdoc`) and `staking-async` parachain (`pr_12922.prdoc`) to `asset-hub-rococo`: extend the `ProxyType::NonTransfer` deny-list in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs` to explicitly deny `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Revive`, `Psm` (if present), `PolkadotXcm`, and `Indices::transfer`/`force_transfer`, mirroring the westend fix, and add a lattice/regression test (as was added in `asset-hub-westend/tests/tests.rs::non_transfer_proxy_rejects_value_moving_calls`) to prevent recurrence when new value-moving pallets are added.
