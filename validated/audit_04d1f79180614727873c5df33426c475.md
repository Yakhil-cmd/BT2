### Title
Unbounded synchronous recursion in `extractAddressPathsFromDefinition` allows a paired device to crash the node with a stack overflow - ([File: wallet_defined_by_addresses.js])

### Summary
`handleNewSharedAddress()` in `wallet_defined_by_addresses.js` processes an incoming `new_shared_address` device-chat message and passes the attacker-controlled `body.definition` array into `extractAddressPathsFromDefinition()`, which recurses synchronously and unboundedly over the definition tree with no depth or complexity limit, unlike every other definition-walker in the codebase. [1](#0-0) 

### Finding Description
`extractAddressPathsFromDefinition` walks the address-definition tree (`or`/`and`/`r of set`/`weighted and`) via a plain recursive `traverse()` function, purely synchronous, with no `MAX_DEPTH`, complexity counter, or `setImmediate` stack-unwinding trick: [1](#0-0) 

Compare this to every production-grade definition evaluator in the codebase, which all defend against exactly this class of bug: `definition.js`'s `evaluate()` enforces `MAX_COMPLEXITY`/`MAX_OPS` and drives recursion through `async.eachSeries` callbacks (never native call-stack recursion for depth) [2](#0-1) , and `formula/validation.js`/`formula/evaluation.js` both explicitly cap recursion `depth > 100`/`MAX_DEPTH` and periodically `setImmediate` to avoid "Maximum call stack size exceeded" [3](#0-2) [4](#0-3) . `extractAddressPathsFromDefinition` has none of these protections.

This function is reached directly from `handleNewSharedAddress`, which is invoked from the `new_shared_address` message case in the wallet chat-protocol handler — reachable by any paired device/correspondent without any prior validation of definition depth: [5](#0-4) [6](#0-5) 

Critically, at the point `extractAddressPathsFromDefinition` is called (line 396), only `isArrayOfLength(body.definition, 2)` and a `getChash160` hash computation have executed — no depth/complexity check has run yet. The protected, complexity-limited `Definition.validateDefinition` call only happens afterward (`validateAddressDefinition`, line 409), by which point the unguarded recursive traversal has already executed. A deeply nested definition such as thousands of nested `['and', [X]]` wrappers will cause `traverse()` to recurse until it exhausts the V8 call stack, throwing an uncaught `RangeError: Maximum call stack size exceeded`. This call is not wrapped in a `try/catch` (unlike the `getChash160` call two lines above it, which is explicitly guarded), so the exception propagates out of the chat-message handler and crashes the Node.js process.

The same unguarded synchronous-recursion pattern exists in the sibling functions `getMemberDeviceAddressesBySigningPaths`'s inner `evaluate()` (reachable via the `create_new_shared_address` message through `validateAddressDefinitionTemplate`) [7](#0-6)  and `getDeviceAddressesBySigningPaths`'s inner `evaluate()` in `wallet_defined_by_keys.js`, both reachable from paired-device wallet messages [8](#0-7) .

### Impact Explanation
An unhandled `RangeError` thrown synchronously inside a network/device-message callback is not caught anywhere in the call chain shown, so it becomes an uncaught exception in the Node.js process, crashing the node. Any correspondent/paired device (a routine, low-privilege relationship established for shared-wallet or multi-sig cosigning) can send a single crafted `new_shared_address` (or `create_new_shared_address`) chat message to remotely crash the recipient's wallet/node process — a network-wide denial of service against any node that has ever paired with the attacker's device, without needing to control a hub or peer at the P2P layer.

### Likelihood Explanation
High. No signature or unit inclusion is required — only an existing device pairing/correspondent relationship, which is a normal, low-trust interaction for setting up shared addresses. Constructing a deeply nested array (`['and', [...]]` repeated thousands of times) is trivial and requires no special access.

### Recommendation
Add a depth/complexity guard to `extractAddressPathsFromDefinition`, `getMemberDeviceAddressesBySigningPaths`, and `getDeviceAddressesBySigningPaths`, matching the `MAX_DEPTH`/`MAX_COMPLEXITY` checks already used in `definition.js` and `formula/validation.js`, and reject definitions whose depth or node count exceeds the limit before any recursive traversal begins. Additionally, wrap these traversal calls in `try/catch` so a stack-overflow exception cannot escape the message handler and crash the process, and perform a structural depth check (similar to `isTooDeeplyNestedOrHasTooManyNodes` used elsewhere for device messages) on `body.definition`/`body.address_definition_template` before any processing.

### Proof of Concept
1. As a paired correspondent device, send a `new_shared_address` message (handled by `wallet.js` case `"new_shared_address"` → `walletDefinedByAddresses.handleNewSharedAddress`) with `body.definition` built as a deeply nested structure, e.g. `depth = 100000` repetitions of `['and', [ ... ]]` (analogous to the `formula.test.js` `deeply nested if/array` stress tests that already probe this class of issue for the formula engine, e.g. `test.cb('deeply nested if', ...)`) [9](#0-8) , but targeting `definition.js`'s `or`/`and` ops instead.
2. `handleNewSharedAddress` passes this into `extractAddressPathsFromDefinition(body.definition)` at line 396, which recurses synchronously via `traverse()` with no depth cap.
3. The recursion exhausts the V8 stack, throwing `RangeError: Maximum call stack size exceeded`, uncaught, crashing the victim node process.

function extractAddressPathsFromDefinition(arrDefinition) {
	var result = {};
	function traverse(arr, path) {
		if (!Array.isArray(arr) || arr.length < 2) return;
		var op = arr[0];
		var args = arr[1];
		switch (op) {
			case 'or':
			case 'and':
				if (Array.isArray(args))
					for (var i = 0; i < args.length; i++)
						traverse(args[i], path + '.' + i);
				break;
			case 'r of set':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i], path + '.' + i);
				break;
			case 'weighted and':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i].value, path + '.' + i);
				break;
			case 'address':
				result[path] = args;
				break;
			case 'hash':
				result[path] = 'secret';
				break;
			case 'in merkle':
				result[path] = ''; // empty address
				break;
		}
	}
	traverse(arrDefinition, 'r');
	return result;
}

		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));

	function evaluate(arr, path){
		var op = arr[0];
		var args = arr[1];
		if (!args)
			return;

			case 'or':
			case 'and':
				for (var i=0; i<args.length; i++)
					evaluate(args[i], path + '.' + i);
				break;
			case 'r of set':
				if (!ValidationUtils.isNonemptyArray(args.set))
					return;
				for (var i=0; i<args.set.length; i++)
					evaluate(args.set[i], path + '.' + i);
				break;
			case 'weighted and':
				if (!ValidationUtils.isNonemptyArray(args.set))
					return;
				for (var i=0; i<args.set.length; i++)
					evaluate(args.set[i].value, path + '.' + i);
				break;
			case 'address':
				var address = args;
				var prefix = '$address@';
				if (!ValidationUtils.isNonemptyString(address) || address.substr(0, prefix.length) !== prefix)
					return;

				break;
			case 'definition template':
				throw Error(op+" not supported yet");
			// all other ops cannot reference device address
		}
	}

	evaluate(arrAddressDefinitionTemplate, 'r');

	function evaluate(arr, path){
		var op = arr[0];
		var args = arr[1];
		if (!args)
			return;
		var prefix = '$pubkey@';
		switch (op){
			case 'sig':
				// ignore static keys. We do not assume all keys are pubkey@device_address
				if (!args.pubkey || args.pubkey.substr(0, prefix.length) !== prefix)
					return;
				var device_address = args.pubkey.substr(prefix.length);

				break;
			case 'or':
			case 'and':
				for (var i=0; i<args.length; i++)
					evaluate(args[i], path + '.' + i);
				break;
			case 'r of set':
				if (!ValidationUtils.isNonemptyArray(args.set))
					return;
