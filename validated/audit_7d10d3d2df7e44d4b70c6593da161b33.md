I checked the only SQL-adjacent code path in this repo, the `eth-rpc`/`pallet-revive` off-chain indexer in `receipt_provider.rs`, which is the closest analog to the reported Cacti SQL-injection class (a web app building `tree.php` queries from unsanitized `parent_id`). All dynamic query construction there uses `sqlx::QueryBuilder`/`query!` with `push_bind`/parameter placeholders for every attacker-influenced value (block hash, address, topic hashes, block numbers) in `logs()` and `logs_by_block_number()`, and the only raw string interpolation (`format_args!(" AND topic_{i} IN (")` and the `remove()` placeholder generation) uses internally-controlled loop indices, never attacker-supplied strings, so there is no unsanitized-input-to-SQL-string concatenation matching the CVE's root cause.

Even setting injection feasibility aside, this component is off-chain RPC/indexing infrastructure for `pallet-revive`'s Ethereum-compatibility layer, not consensus-validated runtime state; any theoretical DB corruption here would be local to a single RPC node's SQLite cache and would not produce unauthorized dispatch, unbacked issuance, asset theft, or a deterministic chain failure as required by the reporting criteria. No other SQL/database query-construction code from attacker-controlled extrinsic, XCM, or contract input exists elsewhere in the scoped production code.

			let placeholders = vec!["?"; chunk.len()].join(", ");

				format!("DELETE FROM transaction_hashes WHERE block_hash in ({placeholders})");
			let sql_logs = format!("DELETE FROM logs WHERE block_hash in ({placeholders})");

				"DELETE FROM eth_to_substrate_blocks WHERE substrate_block_hash in ({placeholders})"
			);

			let mut delete_tx_query = sqlx::query(&sql_tx);
			let mut delete_logs_query = sqlx::query(&sql_logs);
			let mut delete_mappings_query = sqlx::query(&sql_mappings);

			for block_map in chunk {
				delete_tx_query = delete_tx_query.bind(block_map.substrate_hash.as_ref());
				delete_logs_query = delete_logs_query.bind(block_map.ethereum_hash.as_ref());

			delete_logs_query.execute(&mut *db_tx).await?;
			delete_mappings_query.execute(&mut *db_tx).await?;
		}

		db_tx.commit().await?;
