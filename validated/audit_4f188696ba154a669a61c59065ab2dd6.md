### Title
Bad-debt wipeout clamps `supply_index` to the floor instead of zeroing shares, leaving wiped suppliers with "dangling" scaled positions that can withdraw future deposits - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` socializes bad debt by scaling `supply_index` down pro-rata, but clamps the result at `SUPPLY_INDEX_FLOOR_RAW` (RAY/1000) instead of allowing it to reach zero. When the write-down equals or exceeds total supplied value, every supply position keeps its scaled share count while the index is artificially held at the floor — the on-chain equivalent of a use-after-free: the shares were economically "freed" (their backing was written off) but remain referenced and still resolve to a nonzero claim. Any fresh deposit into the emptied market can then be fully drained by the wiped-out holders via an ordinary `withdraw`.

### Finding Description
In `contracts/pool/src/interest.rs`, `apply_bad_debt_to_supply_index` computes `new_supply_index = supply_index * (1 - capped_bad_debt / total_supplied_value)` and then applies `new_supply_index.max(SUPPLY_INDEX_FLOOR_RAW)` [1](#0-0) . When `bad_debt >= total_supplied_value`, `remaining` is 0, so the correct index is 0 — but the floor pushes it back up to RAY/1000. Crucially, **no supply shares are burned**: `cache.supplied` is unchanged and per-account `scaled_amount` entries persist.

Withdrawals resolve claims with `unscale_supply_floor` / `resolve_withdrawal` [2](#0-1) , so each retained scaled share still maps to `scaled * floor_index > 0` underlying. The pool's own tests prove the drain: `test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard` and `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` show a wiped holder ("userA"/Alice) withdrawing exactly a fresh depositor's ("userB"/Bob) entire deposit, leaving `cash` unable to cover the honest claim [3](#0-2) .

The trigger is reachable permissionlessly: `clean_bad_debt` is a keeper-open controller entrypoint that seizes an insolvent/dust account and calls this same function through the pool seize path, and the harness test `test_bad_debt_index_floored_at_safety_floor` confirms a single `liquidate` call can push the index to the floor when supplied value is small relative to the unrecoverable debt [4](#0-3) . A thin or newly created market — or one emptied by the documented "exit ahead of write-down" behavior — makes the wipeout condition `bad_debt >= total_supplied_value` easy to reach.

### Impact Explanation
Theft of user funds / protocol insolvency. After a wipeout write-down, the first new supplier's deposit becomes withdrawable by legacy wiped positions at 1:1 up to their phantom claim. The market reports solvent (shares still exist, index is positive) while its books are permanently insolvent: `total_owed > cash` the moment anyone deposits [5](#0-4) .

### Likelihood Explanation
Requires a full socialization event where bad debt ≥ total supplied value in one market — not a routine liquidation, but achievable on thin markets or after other suppliers exit pre-write-down (which the code permits). Any unprivileged address can trigger the write-down via `liquidate` or `clean_bad_debt`, and the subsequent theft is an ordinary `withdraw`. Medium.

### Recommendation
When the write-down would zero the index, zero it and burn/zero all outstanding scaled supply claims (or migrate them to an explicit loss ledger), rather than resurrecting value via `SUPPLY_INDEX_FLOOR_RAW`. Alternatively, gate withdrawals on a "wiped" market flag until recapitalization, so `scaled_amount` cannot resolve to a claim against unrelated fresh cash.

### Proof of Concept
The in-repo tests already demonstrate the exploit at the cache level (`contracts/pool/tests/interest.rs` `test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard`, `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard`): after `apply_bad_debt_to_supply_index` clamps the index to the floor, `resolve_withdrawal(i128::MAX, old_scaled)` returns `gross == fresh_deposit`, `require_reserves` passes, and the wiped holder drains the pool to empty. End-to-end: (1) attacker creates thin market exposure and an insolvent account via price movement, (2) calls `clean_bad_debt`/`liquidate` so `bad_debt >= supplied * supply_index`, clamping the index to the floor, (3) a victim supplies into the market, (4) the attacker (or any wiped holder) calls `withdraw` with `i128::MAX` and receives the victim's deposit.

fn test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let scaled_a_raw = 1_000_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: scaled_a_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let scaled_a = Ray::from(scaled_a_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout must clamp supply index UP to the floor, not reset the base"
        );

        let stranded = cache.unscale_supply_floor(scaled_a);
        assert!(stranded > 0, "floor clamp leaves userA a phantom claim");
        assert_eq!(cache.cash(), 0, "empty market: no cash to extract yet");

        let c = stranded;
        let scaled_b = cache.calculate_scaled_supply(c);
        cache.mint_supply(scaled_b);
        cache.credit_cash(c);

        let b_claim = cache.unscale_supply_floor(scaled_b);
        assert_eq!(b_claim, c, "userB's honest claim equals their deposit");

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, scaled_a);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded position pays out non-zero");
        assert_eq!(
            gross, c,
            "userA drains exactly userB's fresh deposit out of the pool"
        );

        assert!(
            cache.cash() < b_claim,
            "pool cash ({}) can no longer cover userB's claim ({}): honest supplier lost funds",
            cache.cash(),
            b_claim
        );
        assert_eq!(cache.cash(), 0, "userA drained the pool to empty");
    });
}

fn test_bad_debt_index_floored_at_safety_floor() {
