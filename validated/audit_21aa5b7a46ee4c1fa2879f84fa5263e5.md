### Title
Cross-organization commit-status forgery bypasses deploy safety checks via unscoped `StatusHandler` webhook processing - ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`WebhooksController#verify_signature` authenticates an incoming webhook against the GitHub App/organization derived from the payload's `repository.owner.login` (or `organization.login`) field [1](#0-0) , but the `status` event handler that actually performs the write never re-checks that binding: `StatusHandler#process` looks up commits globally by `sha` across the entire installation with no repository/stack scoping at all [2](#0-1) . This breaks the "organization that authenticated versus the repository that is written" binding: a webhook validly signed for one configured GitHub organization can create/replace a commit status for a commit belonging to a completely different organization's stack.

### Finding Description
Shipit explicitly supports multiple, independently configured GitHub Apps/organizations in a single installation (`docs/setup.md` "Using Multiple Github Applications", `test/dummy/config/secrets_double_github_app.yml`) [3](#0-2) . Each organization has its own `webhook_secret`, and that secret is explicitly documented/allowed to be left blank ("Webhook secret (optional)") [4](#0-3) .

`WebhooksController#verify_signature` picks the `GitHubApp` (and thus the secret used for HMAC verification) using `repository_owner`, taken from the payload itself:
```
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [5](#0-4) 

Once the signature is accepted for that organization, the entire raw JSON body — including any other field, such as `sha` in a `status` payload — is handed unmodified to the event handler:
```
Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
``` [6](#0-5) 

`StatusHandler#process`, unlike `PushHandler` and `CheckSuiteHandler` which scope through `Handler#stacks` (itself scoped by `repository.full_name`) [7](#0-6) , performs no such scoping:
```
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [2](#0-1) 

`Commit.where(sha: ...)` searches across **all** stacks/repositories tracked by the Shipit instance, regardless of which organization the webhook signature was verified against. `create_status_from_github!` then creates a `Status`, which feeds directly into deploy-safety logic: `Commit#deployable?`/`#blocked?` and the "blocking statuses" feature that gate whether a commit can be deployed or merged [8](#0-7) , and it also triggers `stack.schedule_merges` when the resulting status is `success` [9](#0-8) .

### Impact Explanation
In a multi-tenant Shipit deployment (multiple GitHub organizations configured, as documented), a party who legitimately controls the webhook signing secret for **their own, lower-trust organization** (e.g., because they administer that GitHub App, or that organization's `webhook_secret` was left blank per the documented optional setting) can pass `verify_signature` and then supply a forged `status` payload whose `sha` matches a known commit hash in a **different** organization's tracked repository. Because `StatusHandler` performs no cross-check between the authenticated organization and the target commit's stack/repository, the forged status is applied to the victim commit. This can:
- Satisfy CI/blocking-status requirements needed for `deployable?`, enabling an **unauthorized deploy** of a commit that never actually passed CI in the victim repository.
- Trigger `stack.schedule_merges`, potentially advancing the victim stack's merge queue.

This matches the Critical impact category "cross-repository writes ... or an unauthorized deploy, rollback or merge."

### Likelihood Explanation
Requires only a valid webhook signature for **some** organization already configured on the Shipit instance — not for the victim organization. This is realistic in the documented multi-org deployment model, and is trivially satisfied for any org whose admin leaves `webhook_secret` blank (an explicitly supported, non-error configuration). The attacker additionally needs to know a target commit `sha`, which is often public (public repos, PR pages, CI logs). No privileged Shipit account, `ApiClient` token, or the victim organization's secret is required.

### Recommendation
Scope `StatusHandler#process` (and any other handler that doesn't already scope through `Handler#stacks`) to only commits belonging to repositories associated with the organization/repository identified and verified in `WebhooksController#verify_signature`, e.g. restrict `Commit.where(sha: params.sha)` to `stacks.joins(:commits).where(...)` similar to `CheckSuiteHandler`, and/or pass the verified organization down to handlers so they can assert it matches the commit's stack/repository owner before mutating state.

### Proof of Concept
1. Shipit is configured with two organizations, `OrgA` (attacker-administered, `webhook_secret` blank/known to attacker) and `OrgB` (victim, unrelated, tracked stack with a commit of sha `abc123...` currently pending/unknown status and subject to a blocking status check).
2. Attacker sends:
```
POST /webhooks
X-Github-Event: status
X-Hub-Signature: sha1=<valid-for-OrgA-or-absent-if-secret-nil>
{
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgA/whatever" },
  "sha": "abc123...",           // commit belonging to OrgB's stack
  "state": "success",
  "context": "ci/required-check",
  "created_at": "..."
}
```
3. `verify_signature` resolves `Shipit.github(organization: "OrgA")` and accepts the signature (valid for OrgA, or trivially valid if OrgA has no `webhook_secret`).
4. `StatusHandler#process` runs `Commit.where(sha: "abc123...")`, finds the commit in OrgB's stack (no ownership check performed), and creates a `success` status for it.
5. OrgB's stack now treats the commit as passing CI, potentially unblocking deploy/merge despite the actual CI in OrgB's GitHub repository never reporting success.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",

      ].join(' '))
    end
