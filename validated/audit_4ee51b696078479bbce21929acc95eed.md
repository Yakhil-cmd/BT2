Based on my investigation, I found a genuine local admission-boundary defect in the orderless-transaction (nonce-based) replay-protection path, distinct from the Olympus accounting bug but sharing its root cause pattern: **a stateful side-effect ("consumption") is applied during a code path that is also reachable from a non-committing/advisory context, without being gated the same way other checks are gated for that context.**

### Title
Nonce replay-protection consumption in `prologue_common` is not gated by `is_simulation`, unlike auth-key and gas checks - ([File: aptos-move/framework/aptos-framework/sources/transaction_validation.move])

### Summary
`prologue_common` explicitly skips the authentication-key check and the gas-balance check when `is_simulation` is true, via `skip_auth_key_check` and `skip_gas_payment`. However, the replay-protection dispatch for orderless (nonce-based) transactions is **not** gated by `is_simulation` at all, and unconditionally calls `check_and_insert_nonce`, which mutates the on-chain `NonceHistory` resource as a side effect of "checking" replay protection.

### Finding Description [1](#0-0) 

The auth-key check is explicitly skipped for simulation: [2](#0-1) 

The gas balance check is also explicitly skipped for simulation: [3](#0-2) [4](#0-3) 

But the replay-protection dispatch runs unconditionally for both sequence-number and nonce transactions, regardless of `is_simulation`: [5](#0-4) 

For nonce-based (orderless) transactions this calls `check_for_replay_protection_orderless_txn`, which calls `nonce_validation::check_and_insert_nonce`: [6](#0-5) 

`check_and_insert_nonce` is a **write** operation: it inserts the `(sender_address, nonce)` pair into the persistent `NonceHistory` table and returns `false` only if that pair already exists and is unexpired: [7](#0-6) 

`AptosSimulationVM::create_vm_and_simulate_signed_transaction` sets `vm.is_simulation = true` and then calls `execute_user_transaction`, which runs the full prologue (including `check_and_insert_nonce`) inside the simulated VM session: [8](#0-7) 

Because the write is produced inside a Move session as part of the transaction's write set for that simulated execution, whether it persists depends entirely on whether the simulation's output/write-set is committed. The API's `/transactions/simulate` path explicitly discards state hashes and does not apply the write set to the real state (only returns it to the caller): [9](#0-8) 

This means the immediate simulate-endpoint path appears safe because outputs are never committed. However, the inconsistency remains a structural admission-boundary defect: `prologue_common` treats nonce-replay-protection as *always real* regardless of `is_simulation`, in contrast to every other simulation-sensitive check in the same function. Any other caller of the "is_simulation=true" prologue variants that **does** commit output (e.g., a debugger/session tool that persists its state store, or a future code path built on top of `execute_user_transaction` with `is_simulation=true` that commits results) would silently burn a user's nonce without ever executing their real, signed transaction — a legitimate transaction submitted afterward with that same nonce would then be permanently rejected as a replay, even though it was never actually executed. This is exactly analogous to the Olympus bug: a bookkeeping mutation (`lastBalance` update / nonce insertion) is performed unconditionally in a control path meant to be non-committing/read-only in some contexts, silently discarding value/availability that legitimate users are entitled to.

### Impact Explanation
If exploited (i.e., if any simulation/dry-run caller that sets `is_simulation=true` persists the resulting write set — which the CLI's `Session`-based local simulation flow at `simulate_using_session` explicitly does via `sess.execute_transaction`, which calls `AptosVM::execute_user_transaction` without special-casing nonce consumption) this constitutes a real transaction (submitted with a specific nonce) being permanently unable to gain admission afterward, i.e., a legitimate transaction that should execute is rejected at the mempool/VM-validation boundary as a replay. This matches the "Replay, expiry, sequence... binding failure" admission-gate criterion. I could not fully verify whether `aptos-transaction-simulation-session`'s `Session::execute_transaction` persists to a store that is later reused for real submission versus being a throwaway local dev tool state — this needs further confirmation in a live session before treating it as commit-impacting in production.

### Likelihood Explanation
Low-to-moderate. The primary REST `/transactions/simulate` path is safe because its output is never persisted. The risk is concentrated in the `aptos-transaction-simulation-session`/CLI tooling path (`Session::execute_transaction` / `simulate_using_session`), which explicitly maintains a persistent local `state_store` across calls and could accumulate consumed nonces that block subsequent legitimate signed submissions using the same session state as a base. This requires a specific deployment/tooling pattern where a "simulation" session's state store is reused as a source of truth for later real submissions, which needs additional confirmation to be a full unprivileged network-level threat.

### Recommendation
Gate `check_for_replay_protection_orderless_txn`'s state mutation by `is_simulation`, symmetric to `skip_auth_key_check`/`skip_gas_payment`, e.g., skip the `check_and_insert_nonce` write (or use a read-only existence check) when `is_simulation` is true, in `prologue_common`: [5](#0-4) 

### Proof of Concept
1. Build a `Session`-based local simulation environment via `aptos-transaction-simulation-session` (as used by `simulate_using_session` in `crates/aptos/src/aptos_context.rs`).
2. Construct a signed orderless transaction using nonce `N` for sender `S`, with `is_simulation` implicitly true through the simulate/session flow.
3. Call `sess.execute_transaction(transaction, ...)`, which runs `AptosVM::execute_user_transaction` and internally calls `nonce_validation::check_and_insert_nonce(S, N, expiration)`, inserting `(S, N)` into `NonceHistory` in the session's persistent `state_store`.
4. Submit the real signed transaction with the same nonce `N` from `S` to a node whose state is derived from (or later synced with) that session store.
5. Observe `PROLOGUE_ENONCE_ALREADY_USED` (nonce-already-used) rejection at prologue/admission time, even though the original transaction with nonce `N` was never actually keeper-committed on the canonical chain — demonstrating an admission mismatch between "simulated" and "real" execution caused by the ungated `check_and_insert_nonce` write.

**Caveat**: I was not able to fully trace whether `aptos-transaction-simulation-session`'s state store is ever used as the basis for subsequently submitting a *real* transaction to a live network node (vs. being a fully isolated CLI/debugger sandbox with no interaction with mempool/vm-validator admission). This distinction determines whether the impact is a genuine unprivileged admission-boundary bypass/DoS or merely a self-contained tooling inconsistency. I recommend a Devin session with file-system/terminal access to trace `Session::state_store` origin and lifecycle to fully confirm exploitability before treating this as a confirmed high/critical finding.

    // Returns true if the input (address, nonce) pair doesn't exist in the nonce history, and inserted into nonce history successfully.
    // Returns false if the input (address, nonce) pair already exists in the nonce history.
    public(friend) fun check_and_insert_nonce(
        sender_address: address,
        nonce: u64,
        txn_expiration_time: u64,
    ): bool acquires NonceHistory {
        assert!(exists<NonceHistory>(@aptos_framework), error::invalid_state(E_NONCE_HISTORY_DOES_NOT_EXIST));
        // Check if the transaction expiration time is too far in the future.
        assert!(txn_expiration_time <= timestamp::now_seconds() + NONCE_REPLAY_PROTECTION_OVERLAP_INTERVAL_SECONDS, error::invalid_argument(ETRANSACTION_EXPIRATION_TOO_FAR_IN_FUTURE));
        let nonce_history = &mut NonceHistory[@aptos_framework];
        let nonce_key = NonceKey {
            sender_address,
            nonce,
        };
        let bucket_index = sip_hash_from_value(&nonce_key) % NUM_BUCKETS;
        let current_time = timestamp::now_seconds();
        if (!nonce_history.nonce_table.contains(bucket_index)) {
            nonce_history.nonce_table.add(
                bucket_index,
                empty_bucket(false)
            );
        };
        let bucket = nonce_history.nonce_table.borrow_mut(bucket_index);

        let existing_exp_time = bucket.nonce_to_exp_time_map.get(&nonce_key);
        if (existing_exp_time.is_some()) {
            let existing_exp_time = existing_exp_time.extract();

            // If the existing (address, nonce) pair has not expired, return false.
            if (existing_exp_time >= current_time) {
                return false;
            };

            // We maintain an invariant that two transaction with the same (address, nonce) pair cannot be stored
            // in the nonce history if their transaction expiration times are less than `NONCE_REPLAY_PROTECTION_OVERLAP_INTERVAL_SECONDS`
            // seconds apart.
            if (txn_expiration_time <= existing_exp_time + NONCE_REPLAY_PROTECTION_OVERLAP_INTERVAL_SECONDS) {
                return false;
            };

            // If the existing (address, nonce) pair has expired, garbage collect it.
            bucket.nonce_to_exp_time_map.remove(&nonce_key);
            bucket.nonces_ordered_by_exp_time.remove(&NonceKeyWithExpTime {
                txn_expiration_time: existing_exp_time,
                sender_address,
                nonce,
            });
        };

        // Garbage collect upto MAX_ENTRIES_GARBAGE_COLLECTED_PER_CALL expired nonces in the bucket.
        let i = 0;
        while (i < MAX_ENTRIES_GARBAGE_COLLECTED_PER_CALL && !bucket.nonces_ordered_by_exp_time.is_empty()) {
            let (front_k, _) = bucket.nonces_ordered_by_exp_time.borrow_front();
            // We garbage collect a nonce after it has expired and the NONCE_REPLAY_PROTECTION_OVERLAP_INTERVAL_SECONDS
            // seconds have passed.
            if (front_k.txn_expiration_time + NONCE_REPLAY_PROTECTION_OVERLAP_INTERVAL_SECONDS < current_time) {
                bucket.nonces_ordered_by_exp_time.pop_front();
                bucket.nonce_to_exp_time_map.remove(&NonceKey {
                    sender_address: front_k.sender_address,
                    nonce: front_k.nonce,
                });
            } else {
                break;
            };
            i += 1;
        };

        // Insert the (address, nonce) pair in the bucket.
        let nonce_key_with_exp_time = NonceKeyWithExpTime {
            txn_expiration_time,
            sender_address,
            nonce,
        };
        bucket.nonces_ordered_by_exp_time.add(nonce_key_with_exp_time, true);
        bucket.nonce_to_exp_time_map.add(nonce_key, txn_expiration_time);

    /// Simulates a signed transaction (i.e., executes it without performing
    /// signature verification) on a newly created VM instance.
    /// *Precondition:* the transaction must **not** have a valid signature.
    pub fn create_vm_and_simulate_signed_transaction(
        transaction: &SignedTransaction,
        state_view: &impl StateView,
    ) -> (VMStatus, TransactionOutput) {
        assert_err!(
            transaction.verify_signature(),
            "Simulated transaction should not have a valid signature"
        );

        let env = AptosEnvironment::new(state_view);
        let mut vm = AptosVM::new(&env);
        vm.is_simulation = true;

        let log_context = AdapterLogSchema::new(state_view.id(), 0);
        let original_view = state_view.as_move_resolver();
        let patched_view = Self::patch_randomness_seed(&original_view);
        let resolver = vm.as_move_resolver(&patched_view);
        let code_storage = state_view.as_aptos_code_storage(&env);

        let (vm_status, vm_output) = vm.execute_user_transaction(
            &resolver,
            &code_storage,
            transaction,
            &log_context,
            &AuxiliaryInfo::new_timestamp_not_yet_assigned(0),
        );
        let txn_output = vm_output
            .into_transaction_output()
            .expect("Converting to transaction output should never fail");
        (vm_status, txn_output)
    }
