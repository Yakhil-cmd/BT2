## Finding

### Title
Unauthenticated Injection of Phantom Multisig-Wallet Cosigner Records Freezes Wallet Setup - ([File: wallet_defined_by_keys.js])

### Summary
The CVE describes an "unverified" state-changing operation (password change) performed without checking that the requester is entitled to modify the target account. The closest reachable analog in `ocore` is the `my_xpubkey` device-message handler, which is explicitly whitelisted for **non-correspondent** senders and updates the `extended_pubkeys` table for an arbitrary `wallet` id without ever checking that the sending device is actually one of the cosigners named in that wallet's `definition_template`.

### Finding Description
`wallet.js` explicitly allows the `my_xpubkey` subject from devices that are not even paired correspondents: [1](#0-0) 

The handler for this subject performs only basic type/length checks on the body and then calls straight into `walletDefinedByKeys.addDeviceXPubKey` using the sender's own `from_address` (derived from the verified device-message signature), with no check that `from_address` belongs to the set of device addresses encoded in the wallet's `definition_template`: [2](#0-1) 

`addDeviceXPubKey` itself unconditionally inserts a new `extended_pubkeys` row (`INSERT IGNORE`) keyed by `(wallet, device_address)` and then sets `approval_date`, without verifying that `wallet` exists or that `device_address` is one of the addresses produced by `getDeviceAddressesBySigningPaths()` for that wallet's stored definition template: [3](#0-2) 

That contrasts with `addNewAddress`, which does validate that the target `wallet` exists before proceeding: [4](#0-3) 

Because the wallet-completion logic in `checkAndFullyApproveWallet` / `checkAndFinalizeWallet` joins `wallets` to `extended_pubkeys` **without restricting to legitimate cosigner device addresses**, any extraneous row inserted for that `wallet` id participates in the "are all cosigners ready" checks: [5](#0-4) 

An attacker who learns (or guesses/observes) a target wallet's id — which is simply `sha256(initiator_xPubKey)` and is transmitted in plaintext-adjacent wallet-setup messages such as `create_new_wallet`/`my_xpubkey` to any device the initiator is paired with — can send a crafted `my_xpubkey` message to any of the intended cosigner devices for that same wallet id. This inserts a phantom `extended_pubkeys` row with `approval_date` set (via `addDeviceXPubKey`) but `member_ready_date` left `NULL` (since the attacker never subsequently sends `wallet_fully_approved`). From then on, `checkAndFinalizeWallet`'s `rows.some(row => !row.member_ready_date)` guard is permanently true for every legitimate device polling that wallet, so the wallet's `ready_date` can never be set, and `wallet_completed` is never emitted.

### Impact Explanation
This is a targeted, network-reachable freezing primitive: a multisig wallet that legitimate cosigners have already agreed to (all real cosigners approved) can be prevented from ever completing setup/derivation of shared addresses, because the finalization SQL treats every row under that `wallet` id as an authoritative cosigner without validating membership against the definition template. This matches the "AA fund loss or freezing" / node-disagreement class of impact called out in the validation rules — funds destined for the not-yet-finalized shared address cannot be safely spent from that wallet because address derivation and full multisig completion never occur.

### Likelihood Explanation
The `my_xpubkey` subject is intentionally whitelisted for non-correspondents (to bootstrap wallet creation before pairing completes), so no pairing or prior relationship with the victim device is required, only knowledge of the wallet id and the pubkey/hub of one participant device — both of which are exchanged in the same wallet-setup message flow the attacker is abusing. This makes the vector realistically reachable by any device address able to route a `hub/message` to one of the cosigner devices.

### Recommendation
In `addDeviceXPubKey` (and generally in `handleOfferToCreateNewWallet`/`my_xpubkey` processing), verify that:
1. The target `wallet` exists (`SELECT 1 FROM wallets WHERE wallet=?`), and
2. `device_address` is a member of `getDeviceAddressesBySigningPaths(JSON.parse(definition_template))` for that wallet,
before inserting/updating an `extended_pubkeys` row. Reject the message otherwise.

### Proof of Concept
1. Learn `wallet_id = W` for a target multisig wallet in the process of being set up between devices A and B (e.g., by observing pairing/gossip metadata or via a previously-removed/blackholed correspondent that still knows `W`).
2. As attacker device C (not a cosigner of `W`, not even paired with A or B), send a `hub/message` to A's hub containing `{subject: "my_xpubkey", body: {wallet: W, my_xpubkey: "<attacker-derived-xpub>"}}`, signed with C's own device key.
3. Because `my_xpubkey` is in `arrSubjectsAllowedFromNoncorrespondents`, A processes it via `addDeviceXPubKey(W, C_device_address, xpub, ...)`, inserting a new `extended_pubkeys` row for `(W, C_device_address)` with `approval_date` set.
4. C never sends `wallet_fully_approved`, so `member_ready_date` for C's row stays `NULL` forever.
5. `checkAndFinalizeWallet(W, ...)` on device A will now always find a row with `member_ready_date IS NULL` and will never set `wallets.ready_date`, permanently blocking completion of wallet `W` even though the legitimate cosigners have fully approved it.

// check that all members agree that the wallet is fully approved now
function checkAndFinalizeWallet(wallet, onDone){
	db.query("SELECT member_ready_date FROM wallets LEFT JOIN extended_pubkeys USING(wallet) WHERE wallets.wallet=?", [wallet], function(rows){
		if (rows.length === 0){ // wallet not created yet or already deleted
		//	throw Error("no wallet in checkAndFinalizeWallet");
			console.log("no wallet in checkAndFinalizeWallet");
			return onDone ? onDone() : null;
		}
		if (rows.some(function(row){ return !row.member_ready_date; }))
			return onDone ? onDone() : null;
		db.query("UPDATE wallets SET ready_date="+db.getNow()+" WHERE wallet=? AND ready_date IS NULL", [wallet], function(){
			if (onDone)
				onDone();
			eventBus.emit('wallet_completed', wallet);
		});
	});
}

function checkAndFullyApproveWallet(wallet, onDone){
	db.query("SELECT approval_date FROM wallets LEFT JOIN extended_pubkeys USING(wallet) WHERE wallets.wallet=?", [wallet], function(rows){
		if (rows.length === 0) // wallet not created yet
			return onDone ? onDone() : null;
		if (rows.some(function(row){ return !row.approval_date; }))
			return onDone ? onDone() : null;
		db.query("UPDATE wallets SET full_approval_date="+db.getNow()+" WHERE wallet=? AND full_approval_date IS NULL", [wallet], function(){
			db.query(
				"UPDATE extended_pubkeys SET member_ready_date="+db.getNow()+" WHERE wallet=? AND device_address=?", 
				[wallet, device.getMyDeviceAddress()], 
				function(){
					db.query(
						"SELECT device_address FROM extended_pubkeys WHERE wallet=? AND device_address!=?", 
						[wallet, device.getMyDeviceAddress()], 
						function(rows){
							// let other members know that I've collected all necessary xpubkeys and ready to use this wallet
							rows.forEach(function(row){
								sendNotificationThatWalletFullyApproved(row.device_address, wallet);
							});
							checkAndFinalizeWallet(wallet, onDone);
						}
					);
				}
			);
		});
	});
}

// called from network, without user interaction
function addDeviceXPubKey(wallet, device_address, xPubKey, onDone){
	db.query(
		"INSERT "+db.getIgnore()+" INTO extended_pubkeys (wallet, device_address) VALUES(?,?)",
		[wallet, device_address],
		function(){
			db.query(
				"UPDATE extended_pubkeys SET extended_pubkey=?, approval_date="+db.getNow()+" WHERE wallet=? AND device_address=?", 
				[xPubKey, wallet, device_address],
				function(){
					eventBus.emit('wallet_approved', wallet, device_address);
					checkAndFullyApproveWallet(wallet, onDone);
				}
			);
		}
	);
}

// silently adds new address upon receiving a network message
function addNewAddress(wallet, is_change, address_index, address, handleError){
	breadcrumbs.add('addNewAddress is_change='+is_change+', index='+address_index+', address='+address);
	db.query("SELECT 1 FROM wallets WHERE wallet=?", [wallet], function(rows){
		if (rows.length === 0)
			return handleError("wallet "+wallet+" does not exist");
		deriveAddress(wallet, is_change, address_index, function(new_address, arrDefinition){
			if (new_address !== address)
				return handleError("I derived address "+new_address+", your address "+address);
			recordAddress(wallet, is_change, address_index, address, arrDefinition, function(){
				eventBus.emit("new_wallet_address", address);
				handleError();
			});
		});
	});
}
