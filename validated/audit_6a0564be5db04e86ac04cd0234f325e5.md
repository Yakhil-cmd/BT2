### Title
Unconstrained `reward.mintingamount` Governance Parameter Allows Arbitrary KAIA Minting Per Block — (`kaiax/gov/param.go`)

### Summary

The `reward.mintingamount` governance parameter has a `noopFormatChecker` (always returns `true`) with no upper-bound validation. A malicious or compromised governing node (in `single` mode) or any GC member (in `none` mode) can vote to set `reward.mintingamount` to an arbitrarily large `*big.Int` value. Once ratified, every subsequent block's `FinalizeState` mints that amount of KAIA and distributes it to validators and funds, causing unbounded inflation of the native token supply.

### Finding Description

In `kaiax/gov/param.go`, the `RewardMintingAmount` parameter entry uses `noopFormatChecker`, which unconditionally returns `true` for any canonicalized value:

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: noopFormatChecker,   // ← accepts any *big.Int, no upper bound
    ...
    DefaultValue: big.NewInt(0),
},
``` [1](#0-0) 

Compare this with `RewardMinimumStake`, which has an explicit non-negative guard:

```go
RewardMinimumStake: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok { return false }
        return v.Sign() >= 0
    },
``` [2](#0-1) 

The `checkConsistency` function in `VerifyVote` explicitly returns `nil` for `RewardMintingAmount` with no additional checks:

```go
case gov.RewardDeferredTxFee, gov.RewardKip82Ratio, gov.RewardMintingAmount, gov.RewardMinimumStake,
    gov.RewardProposerUpdateInterval, gov.RewardRatio, ...
    return nil
``` [3](#0-2) 

The ratified value flows directly into `NewRewardConfig` and then into every block's reward calculation:

```go
rc.MintingAmount = new(big.Int).Set(paramset.MintingAmount)
``` [4](#0-3) 

In `getDeferredRewardFullKore` and `getDeferredRewardFullFlex`, `config.MintingAmount` is used directly as the minted amount distributed to proposer, stakers, KIF, KEF, and KPF every block:

```go
minted = new(big.Int).Set(config.MintingAmount)
validators, kif, kef := config.RewardRatio.Split(minted)
proposer, stakers := config.Kip82Ratio.Split(validators)
``` [5](#0-4) 

### Impact Explanation

Setting `reward.mintingamount` to an astronomically large value (e.g., `2^255 - 1` kei) causes every block's `FinalizeState` to mint and distribute that amount of KAIA tokens to validators and ecosystem funds. This is an unauthorized minting of KAIA — the native token — affecting the entire token supply. The corrupted value is `spec.Minted` and the recipient balances in `spec.Rewards`, which are applied to the state in `FinalizeState`. This falls squarely within the allowed impact gate: "Unauthorized mint … affecting KAIA … or system-managed funds."

### Likelihood Explanation

Low. In `single` governance mode (Mainnet), only the governing node can cast votes, requiring it to be malicious or compromised. In `none` governance mode, any GC member casting the last vote in an epoch can ratify the change unilaterally. This mirrors the external report's "low likelihood, requires malicious or compromised owner" profile. The parameter is explicitly listed as mutable: [6](#0-5) 

### Recommendation

Add an upper-bound `FormatChecker` for `RewardMintingAmount` in `kaiax/gov/param.go`, analogous to how `RewardRatio` and `RewardKip82Ratio` enforce their sum-to-100 invariant. A reasonable upper bound (e.g., the current mainnet minting amount of `9.6e18` kei multiplied by a safety factor, or a hard cap such as `1e27` kei) should be enforced. Additionally, `checkConsistency` in `kaiax/gov/headergov/impl/header.go` should validate that the proposed minting amount does not exceed the bound.

### Proof of Concept

1. In `none` governance mode, a GC member calls `governance_vote("reward.mintingamount", "115792089237316195423570985008687907853269984665640564039457584007913129639935")` (i.e., `2^256 - 1` as a decimal string).
2. The vote passes `bigIntCanonicalizer` (valid `*big.Int`) and `noopFormatChecker` (always `true`).
3. `PartialParamSet.Add` stores the value without rejection.
4. At the next epoch block, the vote is ratified and written to `header.Governance`.
5. From the next epoch onward, `GetParamSet(blockNum).MintingAmount` returns `2^256 - 1`.
6. Every call to `GetDeferredReward` → `getDeferredRewardFullKore` sets `minted = 2^256 - 1` and distributes it to all reward recipients via `FinalizeState`, minting unbounded KAIA per block. [7](#0-6) [8](#0-7)

func (p PartialParamSet) Add(name string, value any) error {
	param, ok := Params[ParamName(name)]
	if !ok {
		return ErrInvalidParamName
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		return err
	}

	if !param.FormatChecker(cv) {
		return ErrInvalidParamValue
	}

	p[ParamName(name)] = cv
	return nil
