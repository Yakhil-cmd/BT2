### Title
Webhook signature authenticates the organization named in `repository.owner.login`, but stack processing writes to the repository named in `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to authenticate a webhook against using `repository.owner.login` (or `organization.login`), while the downstream handler resolves which tracked repository/stack actually gets processed using the separate field `repository.full_name`. When any configured organization has no `webhook_secret` set (a documented, valid/optional configuration), signature verification for that organization is skipped entirely, letting an attacker forge a payload that "authenticates" as the unprotected organization while acting on a different, protected repository.

### Finding Description
`verify_signature` derives the authenticating organization purely from attacker-controlled JSON before any cryptographic check occurs: [1](#0-0) [2](#0-1) 

The GitHub App resolved for that organization performs the HMAC check, but only if a `webhook_secret` is configured for it — otherwise verification is bypassed unconditionally: [3](#0-2) 

`webhook_secret` is explicitly documented/templated as optional (`nil`) per organization, so a multi-organization deployment can legitimately have one org configured without a secret: [4](#0-3) 

Once `verify_signature` passes (trivially, for the org with no secret), the actual work performed by `Handler` subclasses is scoped using a *different* payload field, `repository.full_name`, not the `repository.owner.login`/`organization.login` used for authentication: [5](#0-4) [6](#0-5) 

`PushHandler` then triggers a sync for whatever stack `Repository.from_github_repo_name` resolves: [7](#0-6) 

**Broken binding (equality):**
`authenticated_org = payload.dig('repository','owner','login')` (used to pick the `GithubApp`/secret in `verify_signature`) is assumed to equal `written_repo_owner = payload.dig('repository','full_name').split('/').first` (used in `Handler#repository_name` to pick the `Stack` that gets acted on). Nothing enforces this equality; they are read from independent parts of the same JSON body that the attacker fully controls.

- **Before the attack:** GitHub always sends a consistent `repository` object, so `owner.login` and the owner portion of `full_name` always match, and the signature is checked against the secret of the actual repository's org.
- **After the attack:** an attacker crafts a POST to the single shared `/github/webhooks` endpoint with `repository.owner.login` (and/or `organization.login`) set to an org that has no `webhook_secret` configured (verification short-circuits to `true`), while `repository.full_name` is set to `victim-org/tracked-repo` — a completely different, secret-protected repository with an active `Stack`. `verify_signature` passes without ever computing an HMAC, and `PushHandler`/other handlers proceed to operate on `victim-org/tracked-repo`'s stack (e.g., invoking `stack.sync_github`, forging commit `status` events used to gate deploys, etc.) using a request that was never authenticated for that org at all.

### Impact Explanation
This is an authentication bypass of the GitHub webhook trust boundary for any protected repository, as long as at least one other organization in the same Shipit instance is configured without a `webhook_secret` (a supported configuration). An unauthenticated attacker can inject arbitrary GitHub events (push, status, check_suite, pull_request, membership, etc.) attributed to a protected repository without ever knowing or forging that repository's real webhook secret. Depending on which handler is invoked, this can be used to force sync jobs, forge commit CI status ("success") on arbitrary commits to influence deploy-gating logic, or manipulate team/membership records tied to `Shipit.github_teams` authorization — i.e., authentication bypass and escalation into repository/authorization state, satisfying the Critical/High impact bar.

### Likelihood Explanation
Requires only network access to the single `/github/webhooks` endpoint (no credentials, no repository access, no session) plus the pre-existing condition that some organization on the instance has no `webhook_secret` configured — an explicitly supported, documented state, not a misconfiguration outside the engine's design. No privileged access of any kind is needed to send the crafted request.

### Recommendation
Bind signature verification to the same field used for authorization of the write. Concretely, `verify_signature` should resolve the app/secret from the same `repository.full_name` (or its owner segment) that `Handler#repository_name` uses, not from a field parsed independently, and reject requests where `repository.owner.login`/`organization.login` disagrees with the owner encoded in `repository.full_name`. Additionally, consider requiring `webhook_secret` to be present for every configured organization (removing the "no secret configured" bypass path) so that a single unprotected org cannot be leveraged to skip verification for the whole shared endpoint.

### Proof of Concept
1. Configure two orgs in `secrets.yml`: `safe-org` (no `webhook_secret`) and `victim-org` (with `webhook_secret` set, owning a tracked `Stack` for `victim-org/tracked-repo`).
2. POST to `/github/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "safe-org" }, "full_name": "victim-org/tracked-repo" }
}
```
No `X-Hub-Signature` needed to match anything real, since `Shipit.github(organization: "safe-org")` resolves an app whose `verify_webhook_signature` returns `true` unconditionally.
3. `WebhooksController#verify_signature` passes; `PushHandler` resolves `victim-org/tracked-repo` via `repository.full_name` and enqueues `GithubSyncJob` for that stack, despite the request never having been authenticated for `victim-org`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
