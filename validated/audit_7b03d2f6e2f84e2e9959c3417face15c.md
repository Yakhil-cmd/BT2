### Title
Asset Hub Kusama nomination-pools `PostUnbondingPoolsWindow` still fixed at 4, reproducing bugbounty report #90's `TotalUnbondingPools` shrink-and-corrupt bug fixed on Asset Hub Polkadot — (`system-parachains/asset-hubs/asset-hub-kusama/src/staking/nom_pools.rs`)

### Summary
This is a structural analog of the reported `StakedlvlUSD` cooldown bug: a bounded storage size is derived from a "duration" parameter at one point in time, but that duration can later be shortened by governance, and the bound is not adjusted to match — corrupting/undecodable stored state instead of merely blocking user withdrawal. Asset Hub Polkadot already identified and patched exactly this class of bug (documented as "bugbounty report #90"), but Asset Hub Kusama's nomination-pools config still uses the old, unpatched fixed constant.

### Finding Description
`pallet_nomination_pools` bounds its `SubPools::with_era` map (`TotalUnbondingPools`) as `StakeAdapter::bonding_duration() + PostUnbondingPoolsWindow`. `bonding_duration()` resolves to `StakingInterface::nominator_bonding_duration()`, which is `BondingDuration` (28) while `pallet_staking_async::AreNominatorsSlashable` is `true`, but drops to `NominatorFastUnbondDuration` the moment that flag is flipped to `false`.

On Asset Hub Polkadot, this exact scenario was already found to be exploitable and fixed: a fixed `PostUnbondingPoolsWindow` constant would let `TotalUnbondingPools` shrink from 32 to 6 when the flag flips, making any oversized historical `with_era` map undecodable, and the next `unbond` call then overwrites it with an empty `Default`, silently destroying per-era unbonding accounting: [1](#0-0) 

The fix computes `PostUnbondingPoolsWindow` dynamically so the total bound stays pinned at its historical maximum regardless of the flag state: [2](#0-1) 

Asset Hub Kusama's equivalent file, however, still uses the legacy fixed constant that the Polkadot fix was written specifically to replace: [3](#0-2) 

Asset Hub Kusama's staking config does wire up `NominatorFastUnbondDuration` and inherits the same `AreNominatorsSlashable`-gated `nominator_bonding_duration()` behavior from `pallet_staking_async`: [4](#0-3) 

The only thing preventing the flag flip on Kusama today is a code comment stating intent ("is intended to remain set to true and should not be modified via governance"), not an enforced invariant: [5](#0-4) 

`AreNominatorsSlashable` is a plain pallet storage item settable at will (as demonstrated by the Polkadot regression test doing exactly this via `pallet_staking_async::AreNominatorsSlashable::<Runtime>::put(false)`): [6](#0-5) 

Nothing in the Kusama runtime's `AdminOrigin` configuration or elsewhere technically blocks governance (`EnsureRoot` or `StakingAdmin`) from toggling this flag on Kusama, so the "intended to remain true" comment is not a security guarantee.

### Impact Explanation
If Kusama governance ever flips `AreNominatorsSlashable` to `false` (e.g., to mirror Polkadot's fast-unbond policy, or via a governance mistake/malicious proposal that passes OpenGov), `nominator_bonding_duration()` drops from 28 to `NominatorFastUnbondDuration`, and the fixed `PostUnbondingPoolsWindow::get() = 4` no longer pins `TotalUnbondingPools` at 32. This shrinks the pallet's `SubPools::with_era` BoundedBTreeMap bound below its historical maximum, so any nomination pool whose `with_era` map has more than the new (smaller) number of entries becomes undecodable. Per the documented pallet behavior, a subsequent `unbond` call on such a pool silently replaces the undecodable map with an empty default, permanently destroying per-era unbonding accounting and effectively burning/losing users' unbonding pool shares — a real solvency/accounting corruption, not just an inconvenience.

### Likelihood Explanation
This requires a governance action (flipping `AreNominatorsSlashable`) rather than an unprivileged transaction, so it is not directly triggerable by an ordinary user today. However, likelihood is non-trivial because: (1) the flag is a legitimate, intentionally-exposed governance lever (it exists specifically to allow toggling fast-unbond behavior, as proven by the fact Polkadot already flipped/uses it), (2) Polkadot's own codebase and comments show this exact flip was anticipated and exploited-in-principle for Polkadot, and (3) Kusama typically mirrors Polkadot's parameter changes over time, so this is a realistic future governance action rather than a purely theoretical scenario. The current mitigating factor is only a comment, not code enforcement.

### Recommendation
Apply the same fix used on Asset Hub Polkadot to Asset Hub Kusama's `system-parachains/asset-hubs/asset-hub-kusama/src/staking/nom_pools.rs`: replace `type PostUnbondingPoolsWindow = frame_support::traits::ConstU32<4>` with a dynamic `PostUnbondingPoolsWindow` implementation (identical to Polkadot's) that computes the window as `BondingDuration::get().saturating_add(4).saturating_sub(nominator_bonding_duration())`, so `TotalUnbondingPools` remains pinned at its historical maximum regardless of the `AreNominatorsSlashable` state. Alternatively/additionally, add a runtime-level guard preventing `AreNominatorsSlashable` from being set to `false` on Kusama until the dynamic window fix lands, or add a migration/invariant check that rejects unbonds when it would shrink the effective bound below any pool's existing `with_era` map size.

### Proof of Concept
Adapting the existing Polkadot regression test to Kusama's runtime (same mechanics, since both runtimes share `pallet_staking_async`/`pallet_nomination_pools`):
```rust
// asset-hub-kusama, hypothetical test mirroring the Polkadot one at
// system-parachains/asset-hubs/asset-hub-polkadot/src/lib.rs:3175-3209
sp_io::TestExternalities::new(Default::default()).execute_with(|| {
    use frame_support::traits::Get;
    use sp_staking::StakingInterface;

    let total_unbonding_pools = || {
        <Staking as StakingInterface>::nominator_bonding_duration() +
            <Runtime as pallet_nomination_pools::Config>::PostUnbondingPoolsWindow::get()
    };

    pallet_staking_async::AreNominatorsSlashable::<Runtime>::put(true);
    assert_eq!(<Staking as StakingInterface>::nominator_bonding_duration(), 28);
    assert_eq!(total_unbonding_pools(), 32); // BondingDuration(28) + fixed window(4)

    // Governance flips the flag (or a future policy change / erroneous referendum).
    pallet_staking_async::AreNominatorsSlashable::<Runtime>::put(false);
    assert_eq!(
        <Staking as StakingInterface>::nominator_bonding_duration(),
        NominatorFastUnbondDuration::get() // 28 on current KSM constant, but any future lower value reproduces the bug
    );
    // Because PostUnbondingPoolsWindow is FIXED at 4 (unlike PAH's dynamic version),
    // total_unbonding_pools() now shrinks whenever NominatorFastUnbondDuration < 28,
    // exactly reproducing bugbounty report #90's corruption path on the next `unbond`.
});
```
Note: with Kusama's *current* constant value `NominatorFastUnbondDuration = BondingDuration::get()` (28), the bound coincidentally does not shrink today. The vulnerability is latent: it activates the instant Kusama governance sets `NominatorFastUnbondDuration` to any value below 28 (mirroring Polkadot's `2`) while keeping the fixed `PostUnbondingPoolsWindow = ConstU32<4>`, since no code enforces the "should not be modified" comment.

```rust
/// Bound for `pallet_nomination_pools::SubPools::with_era`, frozen at its historical maximum so it
/// does not shrink when the nominator bonding duration drops.
///
/// The pallet derives its `TotalUnbondingPools` bound as `StakeAdapter::bonding_duration() +
/// PostUnbondingPoolsWindow`, and `StakeAdapter::bonding_duration()` resolves to
/// `StakingInterface::nominator_bonding_duration()`, which drops from `BondingDuration` (28) to
/// `NominatorFastUnbondDuration` (2) the moment `AreNominatorsSlashable` is set from `true` to
/// `false`. With a fixed window the bound would shrink 32 -> 6, making any oversized historical
/// `with_era` map undecodable; the next `unbond` then overwrites it with an empty `Default`,
/// destroying per-era unbonding accounting (bugbounty report #90).
///
/// We pin the bound at `BondingDuration + 4 = 32` by computing the window as `MAX -
/// nominator_bonding_duration()`. Subtracting the same value the pallet adds keeps
/// `TotalUnbondingPools == MAX` by construction, regardless of the flag. Post-flip this also widens
/// the effective merge window to `32 - 2 = 30` eras, keeping each per-era pool on its correct
/// points-to-balance ratio long enough for deferred pre-flip slashes (`SlashDeferDuration = 27`) to
/// still be applied.
///
/// TODO: this is an interim runtime fix, meant to be superseded by the in-pallet decoupling in
/// polkadot-sdk.
pub struct PostUnbondingPoolsWindow;
impl Get<u32> for PostUnbondingPoolsWindow {
	fn get() -> u32 {
		// Historical maximum number of unbonding sub-pools: the validator bonding duration plus the
		// legacy 4-era post-unbonding window. `BondingDuration` is the upper bound of
		// `nominator_bonding_duration()`, so the subtraction below never saturates.
		let max_unbonding_pools = BondingDuration::get().saturating_add(4);
		max_unbonding_pools
			.saturating_sub(<Staking as sp_staking::StakingInterface>::nominator_bonding_duration())
	}
```
