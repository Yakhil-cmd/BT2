### Title
Unauthenticated Bridge P2P Peer Can Inject Arbitrary JSON-RPC Calls Into MainBridge Internal RPC Server — (`node/sc/main_bridge_handler.go`, `node/sc/mainbridge.go`)

### Summary

Any peer that can reach the MainBridge P2P listening port and pass the trivial bridge handshake (only `NetworkId` and `ProtocolVersion` are checked) can send a `ServiceChainCall` P2P message whose RLP-decoded payload is forwarded verbatim to the internal `rpc.Server` pipe. That server has the full public `kaia`/`klay` namespace registered, including `kaia_sendTransaction`. When the bridge operator account is unlocked (a required operational state for bridge operation), an attacker can drain the operator's KAIA balance or manipulate bridge contract state by calling `kaia_sendTransaction` as the operator.

### Finding Description

In `NewMainBridge()`, an internal `rpc.Server` is created and connected to `mb.rpcConn` via `net.Pipe()`: [1](#0-0) 

In `SetComponents()`, all public `kaia`/`klay` namespace APIs from the CN node (including `KaiaTransactionAPI` with `SendTransaction` and `SendRawTransaction`) are registered on this internal server: [2](#0-1) 

In `handleCallMsg()`, the raw bytes from any bridge peer's `ServiceChainCall` message are decoded and written directly to `mb.rpcConn` with no validation, no method filtering, and no authentication: [3](#0-2) 

The bridge peer handshake only validates `NetworkId` and `ProtocolVersion` — no peer identity allowlist: [4](#0-3) 

The `ServiceChainCall` message code is `0x06`: [5](#0-4) 

### Impact Explanation

An attacker who can reach the MainBridge P2P port can:
1. Connect with any ECDSA key pair (RLPx accepts any key)
2. Pass the handshake by sending the correct `NetworkId` and `ProtocolVersion`
3. Send a `ServiceChainCall` message whose RLP payload is a valid JSON-RPC request, e.g.:
   ```json
   {"jsonrpc":"2.0","method":"kaia_sendTransaction","params":[{"from":"<operator_addr>","to":"<attacker_addr>","value":"0x..."}],"id":1}
   ```
4. The internal RPC server executes the call. If the bridge operator account is unlocked (required for bridge operation), the transaction is signed and submitted, draining the operator's KAIA balance.

The `kaia_sendRawTransaction` path allows submitting pre-signed transactions — same as the public RPC, so limited additional impact. The `kaia_sendTransaction` path is the critical one: it uses the CN node's account manager to sign, and bridge operators must keep their account unlocked. [6](#0-5) 

### Likelihood Explanation

The MainBridge P2P port listens for inbound connections (`NoDiscovery = true`, `NoDial = true`, but `ListenAddr = mb.config.MainBridgePort`). If this port is reachable from outside the operator's private network (common in cloud deployments without strict firewall rules), any attacker can exploit this. The handshake requires only public chain parameters (networkId, protocol version), which are publicly known. [7](#0-6) 

### Recommendation

1. **Authenticate bridge peers**: Maintain an allowlist of authorized peer node IDs (ECDSA public keys) and reject connections from unlisted peers after the RLPx handshake.
2. **Validate `ServiceChainCall` payloads**: Parse the JSON-RPC method name and restrict it to a whitelist of methods that bridge peers are permitted to invoke (e.g., only `kaia_getTransactionReceipt`, `kaia_getBlockByNumber`).
3. **Do not register transaction-sending APIs on the internal bridge RPC server**: The internal server should only expose read-only methods needed for bridge operation, not `kaia_sendTransaction` or `kaia_sendRawTransaction`.

	}

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}
