### Title
Blank `webhook_secret` for a configured GitHub organization lets an unauthenticated attacker forge `pull_request`/`unlabeled` events that archive or unarchive another party's review stack - (File: `lib/shipit/github_app.rb`, `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/unlabeled_handler.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` authenticates a webhook only against the organization named in the payload's own `repository.owner.login`/`organization.login` field, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that organization's config has no `webhook_secret`. If such a no-secret organization is configured in Shipit, an attacker who owns no repository under that org can forge a `pull_request` `action=unlabeled` payload naming any real repository/review stack that belongs to that org, and `UnlabeledHandler` will archive or unarchive that victim's `ReviewStack` without any authentication. This is a genuine unauthenticated cross-tenant state mutation, but the specific `blocking_statuses`/`blocked?` amplification described in the prompt is not supported by the code: `UnlabeledHandler` and `ReviewStackAdapter` never read or write commit statuses, so no forced-status/`blocked?` interaction exists on this path.

### Finding Description
The broken binding is: **the organization used to select the `webhook_secret` for HMAC verification must equal the organization that owns the stack being mutated, and that organization must actually be able to prove authenticity via a secret.** In practice `repository_owner` (`params.dig('repository','owner','login')`) is read once in `verify_signature` [1](#0-0) [2](#0-1)  and `Shipit.github(organization: repository_owner)` returns a `GitHubApp` instance whose `verify_webhook_signature` short-circuits to `true` when `@webhook_secret` is blank: `return true unless webhook_secret` [3](#0-2) . Because the attacker fully controls the raw JSON body, they can set `repository.owner.login` to the no-secret organization's login and `repository.full_name` to `"<org>/<victim-repo>"` for any repository they do not own under that org.

Downstream, `UnlabeledHandler#repository` resolves `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [4](#0-3) , and `#stack` builds a `ReviewStackAdapter` scoped to `repository.review_stacks` and looks the stack up by the forged `environment` (`"pr#{params.number}"`) [5](#0-4) [6](#0-5) . `#handle` then calls `stack.archive!` or `stack.unarchive!` based on the (also attacker-controlled) `labels` array and the repository's `provisioning_behavior` [7](#0-6) [8](#0-7) . `ReviewStackAdapter#archive!`/`#unarchive!` perform real writes — `stack.remove_from_provisioning_queue`, `stack.deprovision`, `stack.archive!(user, ...)`, or adding the stack back to `ReviewStackProvisioningQueue` and calling `stack.unarchive!` [9](#0-8)  — against a stack the attacker never authenticated as owning.

None of the existing guards stop this: `drop_unhandled_event` only checks the event type is handled at all, `verify_signature` accepts the request because the target org's `@webhook_secret` is blank, and `ExplicitParameters` (the `params do ... end` block) only validates the shape of the JSON, not who sent it. There is no `current_user`/session/API-client check anywhere in this pipeline — `WebhooksController` is fully unauthenticated by design, relying entirely on HMAC verification, which this organization's configuration disables.

However, the specific claim that "a forced status can set/clear `blocked?` and gate deploys" as an amplifier for `UnlabeledHandler` is not supported: neither `UnlabeledHandler` nor `ReviewStackAdapter` touch commit statuses, `blocking_statuses`, or `blocked?` at any point. The archive/unarchive mutation is self-contained and does not require or interact with `blocking_statuses` configuration.

### Impact Explanation
An unprivileged attacker can, by naming a real victim repository/review-stack under a Shipit-configured organization that has a blank `webhook_secret`, cause `UnlabeledHandler` to archive (deprovision) or unarchive (re-queue for provisioning) that victim's `ReviewStack` — a write to a repository's/stack's records that the attacker never authenticated for. This is repeatable against any review-stack-enabled repository under that org and matches the Critical category "a payload for one repository mutating another's stack." The `blocking_statuses`/`blocked?` deploy-gating angle described in the question is not actually exercised by this handler, so it adds no additional impact beyond the archive/unarchive write itself.

### Likelihood Explanation
The only precondition is that a Shipit operator has configured at least one GitHub organization without a `webhook_secret` (e.g. during initial setup, or an org intentionally left without one) — the code path `return true unless webhook_secret` in `GitHubApp#verify_webhook_signature` makes this a zero-cost bypass for any such org, requiring no secrets, tokens, or sessions from the attacker, only knowledge of the org login and a target repo/PR-number under it. Given that precondition, exploitation is trivial and fully repeatable via `POST /webhooks`.

### Recommendation
Do not allow `verify_webhook_signature` to return `true` when `webhook_secret` is blank; instead reject (`head 422`) webhooks for organizations that have no configured secret, and require every configured GitHub organization to have a non-blank `webhook_secret` at boot/config-validation time.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual)
test "unlabeled event for no-secret org archives victim review stack without a valid signature" do
  # Arrange: configure org "no-secret-org" with a github config lacking `webhook_secret`
  # and a real Repository/ReviewStack "no-secret-org/victim-repo" with provisioning_behavior_prevent_with_label
  # and an existing open ReviewStack with environment "pr42".
  before = ReviewStack.find_by(environment: "pr42").archived?

  payload = {
    action: "unlabeled",
    number: 42,
    pull_request: {
      id: 1, number: 42, url: "...", title: "x", state: "open",
      additions: 1, deletions: 1,
      head: { sha: "abc", ref: "feature" },
      user: { login: "attacker" },
      assignees: [],
      labels: [{ name: "provisioning-label" }] # attacker-chosen, no "keep-open" label present
    },
    repository: { owner: { login: "no-secret-org" }, full_name: "no-secret-org/victim-repo" },
    sender: { login: "attacker" }
  }.to_json

  post "/webhooks", params: payload, headers: {
    "X-Github-Event" => "pull_request",
    "X-Hub-Signature" => "sha1=deadbeef", # invalid/forged, irrelevant since secret is blank
    "Content-Type" => "application/json"
  }

  assert_response :ok
  after = ReviewStack.find_by(environment: "pr42").reload.archived?
  refute_equal before, after # victim stack mutated by an unauthenticated, non-owning attacker
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end
