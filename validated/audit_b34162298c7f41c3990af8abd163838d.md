Rationale: The external report's root cause is EVM `CREATE`-based deterministic contract addressing (`address = f(deployer, nonce)`), which allows two different chains sharing the same deployer address/nonce sequence to collide and let a DAO deployed on one chain overwrite another chain's DAO state via a cross-chain factory message. Sui's analogous address-derivation mechanisms do not share this weakness:

- Sui object IDs are derived via `ObjectID::derive_id(digest, creation_num)`, where `digest` is the full transaction digest (covering sender, gas payment objects, commands, epoch, etc.), not a simple incrementing per-account nonce plus a fixed deployer address. This makes cross-chain collisions computationally infeasible and unrelated to any reusable "deployer" concept. [1](#0-0) [2](#0-1) 

- Sui's intentionally deterministic address scheme, `sui::derived_object`, derives addresses from a parent object's UID plus a key, and explicitly guards against double-claiming the same `(parent, key)` pair via an on-chain `Claimed` marker and an `assert!` that aborts if the derived ID was already claimed — the same protective invariant that was missing in the reported DAO bug. [3](#0-2) 

- The Sui-Ethereum bridge (the closest "cross-chain deployment/message" analog) enforces message type, per-message-type nonce, and explicit target/source chain ID checks before processing any cross-chain message, and marks messages processed to prevent replay — guarding against the "same address, different chain" replay/override pattern described in the report. [4](#0-3) [5](#0-4) 

No reachable analog with a matching root cause (address collision across chains from a reusable deployer-nonce-style scheme causing unauthorized state overwrite) exists in this repository's in-scope production code.

    /// Create an ObjectID from `TransactionDigest` and `creation_num`.
    /// Caller is responsible for ensuring that `creation_num` is fresh
    pub fn derive_id(digest: TransactionDigest, creation_num: u64) -> Self {
        let mut hasher = DefaultHash::default();
        hasher.update([HashingIntentScope::RegularObjectId as u8]);
        hasher.update(digest);
        hasher.update(creation_num.to_le_bytes());
        let hash = hasher.finalize();

        // truncate into an ObjectID.
        // OK to access slice because digest should never be shorter than ObjectID::LENGTH.
        ObjectID::try_from(&hash.as_ref()[0..ObjectID::LENGTH]).unwrap()
    }

/// Claim a deterministic UID, using the parent's UID & any key.
public fun claim<K: copy + drop + store>(parent: &mut UID, key: K): UID {
    let addr = derive_address(parent.to_inner(), key);
    let id = addr.to_id();
    assert!(!df::exists(parent, Claimed(id)), EObjectAlreadyExists);
    df::add(parent, Claimed(id), ClaimedStatus::Reserved);
    object::new_uid_from_hash(addr)
