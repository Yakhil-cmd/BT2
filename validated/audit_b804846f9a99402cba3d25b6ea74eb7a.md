### Title
Unbounded `reward.stakingrewardthreshold` governance parameter allows governing node to redirect all staker KAIA rewards to the block proposer — (`kaiax/gov/param.go`, `kaiax/reward/impl/getter.go`)

### Summary

The `RewardStakingRewardThreshold` governance parameter has no maximum bound in its `FormatChecker`. A governing node operating in `"single"` governance mode can vote to set this parameter to an arbitrarily large value (e.g., `math.MaxUint64`). Because `assignStakingRewardsFlex` truncates the stored `*big.Int` to `uint64` and compares each validator's staking amount against it, no validator will ever exceed the threshold, causing the entire staking reward budget to be returned as a remainder and credited to the block proposer instead of the stakers.

### Finding Description

**Root cause — no maximum bound on `RewardStakingRewardThreshold`:**

`kaiax/gov/param.go` defines the parameter's `FormatChecker` as:

```go
RewardStakingRewardThreshold: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok {
            return false
        }
        return v.Sign() >= 0   // only lower-bound; no upper-bound
    },
    ...
    DefaultValue: big.NewInt(5_000_000),
},
``` [1](#0-0) 

Any non-negative `*big.Int` is accepted — including `math.MaxUint64` (18,446,744,073,709,551,615 KAIA).

**No consistency check blocks the vote:**

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` explicitly lists `RewardStakingRewardThreshold` in the "no further checks needed" branch and returns `nil`:

```go
case gov.RewardStakingRewardThreshold,
    gov.RewardStakingUpdateInterval, ...:
    return nil
``` [2](#0-1) 

**Consumption path — `uint64` truncation and threshold comparison:**

`assignStakingRewardsFlex` in `kaiax/reward/impl/getter.go` reads the parameter as:

```go
threshold = config.StakingRewardThreshold.Uint64()
```

and then only credits a validator if `amount > threshold`:

```go
if amount > threshold {
    excessInt[cn.RewardAddr] = amount - threshold
    totalExcessInt += excessInt[cn.RewardAddr]
}
``` [3](#0-2) 

When `threshold = math.MaxUint64`, no validator's staking amount (realistically in the low millions of KAIA) can exceed it. `totalExcessInt` stays `0`, the allocation map is empty, and the entire `budget` is returned as `remaining`.

**Remainder credited to proposer:**

Back in `getDeferredRewardFullFlex`:

```go
stakersAlloc, kip82Remainder := assignStakingRewardsFlex(config, stakers, si)
proposer.Add(proposer, kip82Remainder)
stakers.Sub(stakers, kip82Remainder)
``` [4](#0-3) 

`kip82Remainder` equals the full staking budget, so the proposer receives the stakers' entire KAIA allocation.

**Dispatch condition:**

This path is reached whenever `config.Rules.IsOsaka && config.UseFlexReward` (the Osaka/Flex reward rule):

```go
if config.Rules.IsOsaka && config.UseFlexReward {
    return getDeferredRewardFullFlex(config, execFee, burntFee, blobFee, si)
``` [5](#0-4) 

### Impact Explanation

Every block mined under the Osaka + `UseFlexReward` configuration distributes the staking portion of the minting reward (the `s` fraction of `g × MintingAmount`) entirely to the proposer instead of the stakers. The existing test case at line 1082 of `getter_test.go` explicitly confirms this outcome:

```go
{"flex, all below threshold, no staking reward", true, big.NewInt(9_000_000), kpfAddr, &reward.RewardSpec{
    Proposer: big.NewInt(3.84e18 + 3.5e16), // fee/2 + stakers (entire staking budget)
    Stakers:  big.NewInt(0),                // no stakers were eligible
    ...
}},
``` [6](#0-5) 

With a default `MintingAmount` of 9.6 KAIA/block and a typical `g × s` ratio of ~40%, this represents roughly 3.84 KAIA per block silently redirected from stakers to the proposer — an unauthorized KAIA transfer affecting all staking reward recipients every block for as long as the parameter remains set.

### Likelihood Explanation

The governing node in `"single"` governance mode is a single address that can unilaterally cast a winning vote on any mutable governance parameter. This is the direct analog of the "management" role in the original bug report. The vote requires no external preconditions: the governing node submits a header governance vote for `reward.stakingrewardthreshold` with value `math.MaxUint64`, it passes both the `FormatChecker` and `checkConsistency`, and takes effect after the next epoch boundary. No majority-validator collusion is required.

### Recommendation

Add an upper-bound check to the `FormatChecker` for `RewardStakingRewardThreshold` in `kaiax/gov/param.go`. The bound should be at most the realistic maximum total staking amount (e.g., capped at `reward.minimumstake` or a fixed protocol constant). Additionally, add a cross-parameter consistency check in `checkConsistency` (analogous to the existing `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` cross-check) to reject any `StakingRewardThreshold` value that would make all current validators ineligible.

```go
RewardStakingRewardThreshold: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok { return false }
        // Must be non-negative and within uint64 range to avoid silent truncation
        return v.Sign() >= 0 && v.IsUint64()
    },
    ...
},
```

### Proof of Concept

1. Network is running post-Osaka with `reward.useflexreward = true` and `governance.governancemode = "single"`.
2. The governing node submits a header governance vote: `reward.stakingrewardthreshold = 18446744073709551615` (`math.MaxUint64`).
3. The vote passes `FormatChecker` (`v.Sign() >= 0` ✓) and `checkConsistency` (returns `nil` ✓).
4. After the epoch boundary, `GetParamSet` returns `StakingRewardThreshold = math.MaxUint64`.
5. `NewRewardConfig` copies it: `rc.StakingRewardThreshold = new(big.Int).Set(paramset.StakingRewardThreshold)`.
6. `assignStakingRewardsFlex` computes `threshold = config.StakingRewardThreshold.Uint64()` = `18446744073709551615`.
7. All validators have staking amounts in the millions of KAIA — none satisfy `amount > 18446744073709551615`.
8. `totalExcessInt = 0`; the function returns `(empty_alloc, budget)`.
9. `getDeferredRewardFullFlex` executes `proposer.Add(proposer, kip82Remainder)` where `kip82Remainder = budget`.
10. Every subsequent block: stakers receive 0 KAIA; the proposer receives the full staking allocation in addition to its own minting reward.

		// Excess is the amount over the threshold (not over minStake).

			excessInt[cn.RewardAddr] = amount - threshold
