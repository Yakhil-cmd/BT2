### Title
`ProxyType::NonTransfer` fails open on Asset Hub Rococo, letting a delegate move the delegator's `ForeignAssets`, `PoolAssets`, `AssetConversion`, XCM and other value-bearing calls - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`ProxyType::NonTransfer` on Asset Hub Rococo is documented as "Can execute any call that does not transfer funds or assets" [1](#0-0) , but it is implemented as a deny-list that only excludes `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques` [2](#0-1) . Any other pallet capable of moving the delegator's value — most notably `ForeignAssets`, `PoolAssets` (the other `pallet-assets` instances), `AssetConversion`, `PolkadotXcm`, and `Revive` — is not named in the deny-list and therefore remains reachable by a `NonTransfer` proxy. This is the exact same class of bug that was found and fixed on Asset Hub Westend (`prdoc/pr_12771.prdoc`) and on the `staking-async` parachain runtime (`prdoc/pr_12922.prdoc`), but the equivalent fix was never applied to Asset Hub Rococo.

### Finding Description
`pallet-proxy`'s `InstanceFilter` implementation governs which calls a delegate acting through a `Proxy::proxy` call may execute on behalf of a delegator. The delegator grants the `NonTransfer` proxy type expecting the security guarantee stated in its doc comment: the delegate cannot move funds or assets. The filter, however, is written as `!matches!(c, <deny-list>)` — a blocklist — so by construction any `RuntimeCall` variant that is not explicitly named in the match arm passes the filter and is authorized [3](#0-2) .

Comparing to the Asset Hub Westend runtime, which received an explicit fix for this exact issue, the corrected deny-list additionally denies `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, `Vesting::vested_transfer`, and `Indices::transfer`/`force_transfer` [4](#0-3) . The `staking-async` parachain runtime received an analogous partial fix denying `ForeignAssets` and `PoolAssets` [5](#0-4) . Asset Hub Rococo's `NonTransfer` filter still only lists the original, incomplete deny-list [6](#0-5) , with no corresponding `prdoc` entry or code fix for asset-hub-rococo.

This mirrors the Tomcat `ResourceLinkFactory` vulnerability's core defect class (CWE-863, incorrect authorization): the security boundary is meant to be an explicit allow-list of "safe" operations, but the actual mechanism is a fail-open deny-list, so any resource/call not explicitly enumerated is implicitly reachable rather than denied by default.

### Impact Explanation
A delegator who grants a `NonTransfer` proxy — trusting the documented invariant that the delegate cannot move funds/assets — is exposed to the delegate transferring the delegator's `ForeignAssets` and `PoolAssets` holdings, performing `AssetConversion` swaps/liquidity withdrawals that move the delegator's assets, sending `PolkadotXcm` `transfer_assets`/`teleport_assets`/`send`/`execute` (which can express arbitrary asset movement off-chain), and invoking `Revive` contract calls carrying a `value` transfer. This is an authorization bypass leading to direct, irreversible theft of the delegator's funds by a delegate who was only meant to hold restricted, non-value-moving authority.

### Likelihood Explanation
Any account that has granted (or is later persuaded/tricked into granting) a `NonTransfer` proxy is affected; no privileged role or governance action is required by the attacker — only possession of a `NonTransfer` proxy relationship, which is a normal, commonly used and low-trust proxy type by design. Given that the identical defect was already discovered and patched on sibling runtimes (Asset Hub Westend, staking-async parachain), it is a real, previously-confirmed bug class, just unpatched on this particular runtime instance.

### Recommendation
Apply the same fix already applied to Asset Hub Westend (`prdoc/pr_12771.prdoc`) to `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs`: extend the `ProxyType::NonTransfer` deny-list to also cover `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, `Vesting::vested_transfer`, and `Indices::transfer`/`force_transfer` (adjusted for whichever of these pallets are actually configured on Asset Hub Rococo). More robustly, consider converting `NonTransfer` to an explicit allow-list so that newly added pallets default to denied rather than allowed.

### Proof of Concept
I was not able to execute a live integration test against this repository snapshot (no filesystem/terminal access in this session). The finding is evidenced statically:
- Asset Hub Rococo's `NonTransfer` filter only names `Balances`, `Assets`, `NftFractionalization`, `Nfts`, `Uniques` in its deny-list [3](#0-2) .
- The identical bug on Asset Hub Westend was confirmed and fixed via a regression test asserting that `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, etc. calls were previously permitted through `NonTransfer` [7](#0-6)  and the fix commit `prdoc/pr_12771.prdoc` [8](#0-7) .
- A minimal reproduction on Asset Hub Rococo would mirror the Westend regression test: construct `RuntimeCall::ForeignAssets(pallet_assets::Call::<Runtime, ForeignAssetsInstance>::transfer{..})` (and analogous `PoolAssets`/`AssetConversion`/`PolkadotXcm` calls) and assert `ProxyType::NonTransfer.filter(&call)` returns `true` on the unpatched code — demonstrating the bypass — the same pattern used in `substrate/frame/staking-async/runtimes/parachain/src/lib.rs:2350-2379`'s `non_transfer_proxy_denies_other_asset_instances` test for its sibling runtime [9](#0-8) . I did not run this test against asset-hub-rococo in this session and could not confirm whether `ForeignAssets`/`PoolAssets`/`AssetConversion`/`PolkadotXcm`/`Revive` pallets are all present and reachable in the exact currently-deployed Asset Hub Rococo runtime configuration (construct_runtime! pallet list) — that final wiring confirmation should be done before filing, since bounty eligibility also depends on the matching live program/version.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}

#[test]
fn non_transfer_proxy_denies_other_asset_instances() {
	use frame_support::traits::InstanceFilter;

	// `ForeignAssets` (Instance2) and `PoolAssets` (Instance3) move fungibles just like
	// `Assets` (Instance1) does, so a `NonTransfer` proxy must not be able to call them.
	let foreign_assets_transfer = RuntimeCall::ForeignAssets(pallet_assets::Call::<
		Runtime,
		ForeignAssetsInstance,
	>::transfer {
		id: xcm::v5::Location::parent(),
		target: sp_runtime::MultiAddress::Id(AccountId::from([0u8; 32])),
		amount: 1,
	});
	assert!(
		!ProxyType::NonTransfer.filter(&foreign_assets_transfer),
		"NonTransfer must deny ForeignAssets transfers",
	);

	let pool_assets_transfer =
		RuntimeCall::PoolAssets(pallet_assets::Call::<Runtime, PoolAssetsInstance>::transfer {
			id: 1,
			target: sp_runtime::MultiAddress::Id(AccountId::from([0u8; 32])),
			amount: 1,
		});
	assert!(
		!ProxyType::NonTransfer.filter(&pool_assets_transfer),
		"NonTransfer must deny PoolAssets transfers",
	);
}
