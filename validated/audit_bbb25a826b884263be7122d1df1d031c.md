### Title
Webhook signature verification org differs from the stack-owning org used to trigger sync, allowing an unsigned push webhook to trigger `Stack#sync_github` on an unrelated repository - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/push_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` used to check the webhook HMAC by reading `repository.owner.login` (or `organization.login`) from the untrusted JSON body, while `PushHandler` (via `Handler#stacks`/`#repository_name`) locates the `Stack` to act on by reading the independent `repository.full_name` field from the same body. Because these two lookups are never cross-checked, an attacker can send an unsigned request whose `repository.owner.login` names an org that has no `webhook_secret` configured, while `repository.full_name` names an unrelated victim repository, causing the victim's `Stack#sync_github` to run with an attacker-chosen `after` sha.

### Finding Description
The broken binding: `verifying_org = payload.dig('repository','owner','login')` (used in `verify_signature`) is assumed to equal `owning_org_of(stack whose sync_github is invoked) = org part of payload.dig('repository','full_name')` (used in `PushHandler`/`Handler#stacks`). Both values are attacker-controlled and independent, so this equality does not hold.

- `WebhooksController#verify_signature` computes `repository_owner` purely from the payload and uses it to pick the `GitHubApp` config: [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` unconditionally returns `true` when that org's `webhook_secret` is blank: [3](#0-2) 
- `Shipit#github` resolves the per-organization config for whatever `organization:` string is passed, raising only if the org name is entirely unknown, not if it mismatches the target repo: [4](#0-3) 
- `Handler#stacks`/`#repository_name` (used by `PushHandler#process`) resolve the actual `Stack` from `payload.dig('repository','full_name')`, a completely different field of the same body: [5](#0-4) 
- `PushHandler#process` then invokes `stack.sync_github(expected_head_sha: params.after)` on whatever stacks match that `full_name` and branch: [6](#0-5) 
- Multi-org configuration where an org legitimately has no `webhook_secret` set is an explicitly documented and supported setup ("Webhook secret (optional)"), so `org-no-secret` is a realistic configuration, not a contrived edge case: [7](#0-6) [8](#0-7) 

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: push` and body:
```json
{"repository":{"owner":{"login":"org-no-secret"},"full_name":"victim-org/victim-repo"},"ref":"refs/heads/main","after":"<attacker sha>"}
```
`verify_signature` resolves `Shipit.github(organization: "org-no-secret")`, which has no `webhook_secret`, so `verify_webhook_signature` returns `true` regardless of (or absent) `X-Hub-Signature`. The request proceeds to `PushHandler#process`, which looks up stacks by `repository.full_name == "victim-org/victim-repo"` and branch `main`, and calls `sync_github(expected_head_sha: <attacker sha>)` on the real victim stack — a job proven to be enqueued by existing tests: [9](#0-8) .

None of the existing guards prevent this: `drop_unhandled_event` and `check_if_ping` are unrelated to org binding; `verify_signature` only checks the signature against the org named in the payload itself, never against the org actually owning the target repository; there is no model validation anywhere in the request path enforcing `repository.owner.login`'s org equals the org segment of `repository.full_name`.

### Impact Explanation
This lets an unprivileged attacker cause `Stack#sync_github` (and the `GithubSyncJob` it enqueues) to run against an arbitrary victim tenant's stack with an attacker-supplied `expected_head_sha`, without ever presenting a valid signature for the victim's org — i.e., a payload nominally "verified" for one org mutates another org's stack/commit state. This is repeatable against any repository/stack on a multi-tenant Shipit instance as long as one configured org lacks a `webhook_secret`, and matches the Critical category "a payload for one repository mutating another's stack ... or an unauthorized deploy/rollback."

### Likelihood Explanation
Requires the Shipit instance to use the multi-org GitHub App config schema with at least one org configured without a `webhook_secret` (explicitly documented as optional, and shown with `webhook_secret: # nil` in the shipped sample config). The attacker needs no credentials, no valid signature, and no relationship to the victim org — only knowledge of the victim's `repository.full_name` and target branch, both public information. This is trivially and repeatably exploitable via a single unauthenticated HTTP POST per target stack.

### Recommendation
Bind webhook signature verification to the same repository identity used for stack resolution: resolve `repository_owner` from the org segment of `repository.full_name` (not from a separately-supplied `owner.login`/`organization.login` field), or explicitly verify that `repository.owner.login` matches the owner segment parsed out of `repository.full_name` before proceeding, rejecting the request (422) on mismatch.

### Proof of Concept
Minitest plan (extends `test/controllers/webhooks_controller_test.rb`):
```ruby
test "push webhook verified against unrelated org triggers victim stack sync" do
  victim_stack = shipit_stacks(:shipit) # owns e.g. "shopify/shipit-engine", tracking "master"
  Shipit.stubs(:github).with(organization: "org-no-secret").returns(
    Shipit::GitHubApp.new("org-no-secret", { webhook_secret: nil })
  )

  request.headers['X-Github-Event'] = 'push'
  body = {
    "repository" => { "owner" => { "login" => "org-no-secret" }, "full_name" => victim_stack.repo_name },
    "ref" => "refs/heads/#{victim_stack.branch}",
    "after" => "a" * 40
  }.to_json

  Shipit::Stack.any_instance.expects(:sync_github).with(expected_head_sha: "a" * 40)

  post :create, body:, as: :json
  assert_response :ok
end
```
Assertions on both sides of the binding: (1) `repository_owner` used for `verify_signature` == `"org-no-secret"` (attacker-chosen, unrelated org, no secret ⇒ verification passes unconditionally); (2) the `Stack` on which `sync_github` is invoked belongs to `repository.full_name` == victim's real repo — proving the two are independent and the equality assumed by the binding does not hold.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
