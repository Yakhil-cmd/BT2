### Title
Wrong Address Checked in `GovernanceGoverningNode` Vote Consistency Validation Allows Non-Council Governing Node to Be Ratified — (`File: kaiax/gov/headergov/impl/header.go`)

### Summary

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` validates a `governance.governingnode` vote by checking whether the **current** governing node is in the council, instead of checking whether the **proposed new** governing node is in the council. This is the direct Kaia analog of the external bug: the wrong value is compared against the state guard, making the guard a no-op in normal operation and allowing an invalid governance state to be ratified.

### Finding Description

In `checkConsistency`, the `GovernanceGoverningNode` case reads:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if slices.Contains(council, params.GoverningNode) {  // ← checks CURRENT node
        return nil
    }
    return ErrGovNodeNotInValSetList
``` [1](#0-0) 

The vote payload carries `vote.Value().(common.Address)` — the **new** address the governing node is being changed to. The guard is supposed to enforce that the new governing node is a council member (so it can propose blocks and exercise governance authority). Instead, it checks `params.GoverningNode`, the **current** governing node.

In normal chain operation the current governing node is always in the council (that invariant is maintained by the `AddValidator`/`RemoveValidator` guard at line 200 which correctly uses `vote.Value()`). Therefore `slices.Contains(council, params.GoverningNode)` is always `true`, the guard always returns `nil`, and the consistency check for `GovernanceGoverningNode` is completely bypassed. [2](#0-1) 

Compare with the correctly-written `AddValidator`/`RemoveValidator` case, which checks `vote.Value()` (the proposed addresses):

```go
if slices.Contains(vote.Value().([]common.Address), params.GoverningNode) {
    return ErrGovNodeInValSetVoteValue
}
``` [3](#0-2) 

The same broken check is reached from two call sites: the `governance_vote` API (`Vote()`) and block header verification (`VerifyVote()`), both of which call `checkConsistency`. [4](#0-3) [5](#0-4) 

The test suite confirms the gap: the only `GovernanceGoverningNode` test case votes to keep the governing node as `validVoter` (same as the current governing node), so the wrong-address check happens to pass and the bug is never exercised. [6](#0-5) 

### Impact Explanation

After the vote is cast and ratified at the next epoch block, `GetParamSet` returns the new (non-council) address as `GoverningNode`. Two consequences follow immediately:

1. **Governance lock.** In `single` mode (Mainnet and Kairos), only the governing node may cast votes. The new governing node is not in the council, so it can never become a block proposer, and therefore can never inscribe a vote in `header.Vote`. No further governance parameter changes are possible — the chain's governance is permanently frozen.

2. **Validator-set invariant broken.** `applyVote` in `kaiax/valset` skips the governing node when processing `RemoveValidator` votes, using `GetParamSet(num).GoverningNode` as the protected address. With a non-council governing node recorded, that protection applies to the wrong address, corrupting future validator-set transitions. [7](#0-6) 

The corrupted `GoverningNode` value is persisted in the `header.Governance` field at the epoch block and replicated to every syncing node, making the state change canonical and irreversible without a hard fork.

### Likelihood Explanation

The trigger is the governing node calling `governance_vote("governance.governingnode", <newAddr>)` where `<newAddr>` is not yet in the council — a realistic operational mistake (e.g., voting to hand off governance to a new node before that node has been added via `AddValidator`). The broken guard accepts the vote silently. The governing node is a semi-trusted actor (not a majority of validators), and the bug requires no external attacker: an accidental mis-ordering of two legitimate governance operations is sufficient.

### Recommendation

Replace `params.GoverningNode` with `vote.Value().(common.Address)` in the council membership check:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    newGovNode := vote.Value().(common.Address)   // ← proposed value
    if slices.Contains(council, newGovNode) {
        return nil
    }
    return ErrGovNodeNotInValSetList
```

Add a test case that votes to change the governing node to an address **not** in the council and asserts `ErrGovNodeNotInValSetList` is returned.

### Proof of Concept

1. Chain is in `single` governance mode. Current governing node is `GovNode` (in council). Council = `{GovNode, V1, V2}`.
2. `GovNode` calls `governance_vote("governance.governingnode", "0xDeAdBeEf...")` where `0xDeAdBeEf` is not in the council.
3. `checkConsistency` is called. It fetches `params.GoverningNode == GovNode`, checks `slices.Contains(council, GovNode)` → `true` → returns `nil`. The vote is accepted.
4. At the next epoch block, `VerifyGov` confirms the ratified governance matches the locally computed result (it does, because `getExpectedGovernance` simply replays the accepted votes). `header.Governance` is written with `{"governance.governingnode": "0xDeAdBeEf..."}`.
5. From `(k+1)*epoch` onward, `GetParamSet` returns `GoverningNode = 0xDeAdBeEf`. `0xDeAdBeEf` is not in the council, cannot propose blocks, and cannot cast votes. Governance is permanently locked. [8](#0-7) [9](#0-8)

// checkConsistency checks if vote values are consistent with chain states such as other parameters and validator set.
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}
