### Title
Cross-organization webhook forgery via mismatched `repository.owner.login` vs `repository.full_name` in multi-org GitHub App configuration - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In multi-organization deployments, `WebhooksController#verify_signature` selects *which* organization's `webhook_secret` to verify the inbound signature against using `repository_owner`, a value read straight out of the untrusted JSON body (`params.dig('repository', 'owner', 'login')` or `organization.login`). The event handlers, however, resolve the actual `Repository`/`Stack` to act on using a *different* field from the very same body: `payload.dig('repository', 'full_name')`. Nothing binds these two fields together, so the signature-verification target and the write-target are independent, attacker-controlled values inside one unauthenticated payload.

### Finding Description
`Shipit.github(organization:)` looks up per-organization config (including `webhook_secret`) from `secrets.github` when the multi-org schema is used [1](#0-0) . Critically, `GitHubApp#verify_webhook_signature` short-circuits to `true` when no `webhook_secret` is configured for that organization: `return true unless webhook_secret` [2](#0-1) . The example configuration files ship with `webhook_secret: # nil` for one or more orgs, showing this is a realistic, documented state [3](#0-2) .

`WebhooksController#verify_signature` picks the org whose secret is checked based on `repository_owner`, which is read from the raw, unauthenticated body before any signature check occurs: [4](#0-3) [5](#0-4) 

Once `verify_signature` passes (trivially, for an org with no secret), `create` dispatches the entire raw JSON body to the registered handlers [6](#0-5) . Every handler determines the target `Repository`/`Stack` from `payload.dig('repository', 'full_name')` — a sibling field of `repository.owner.login`, but never checked for consistency with it: [7](#0-6) [8](#0-7) 

Because `repository.owner.login` (used to choose the verifying secret) and `repository.full_name` (used to choose the acted-upon repository/stack) live in the same attacker-supplied JSON object and are never cross-validated, an attacker can set `owner.login` to an organization configured with no `webhook_secret` (verification vacuously succeeds) while setting `full_name` to point at a completely different, actively-managed repository/stack belonging to another configured organization. The binding broken is exactly the "organization that authenticated vs. the repository that is written" class: `authenticated_org == payload.repository.owner.login`, but `acted_upon_repo == payload.repository.full_name`, and the code never enforces `authenticated_org == owner_of(acted_upon_repo)`.

### Impact Explanation
This allows an unauthenticated attacker (no webhook secret, no GitHub App key, no session) to forge `push`, `pull_request`, `status`, `check_suite`, and `membership` events against any repository/stack managed by the Shipit instance, as long as the instance is configured for multiple GitHub organizations and at least one configured organization lacks a `webhook_secret`. Concretely this can trigger `stack.sync_github` deploy-triggering pulls [9](#0-8) , archive/unarchive review stacks, or manipulate PR-driven provisioning for a target repository the attacker does not control — all without any credential tied to that target repository's organization. This crosses the "unauthorized deploy/rollback" and "cross-repository writes" impact bar because the acted-upon repository is decoupled from the verified identity.

### Likelihood Explanation
Requires: (1) a Shipit deployment using the documented multi-organization GitHub config schema, and (2) at least one configured organization with an empty/absent `webhook_secret`. This is not a hypothetical edge case — the shipped example configs (`config/secrets.development.shopify.yml`, `config/secrets.development.example.yml`) explicitly show `webhook_secret: # nil` as a valid, documented per-org value, and `docs/setup.md` describes `webhook_secret` as optional ("If you've set a webhook secret..."). No attacker credentials, session, or write access are needed — only knowledge that such an organization exists (organization logins/slugs are public on GitHub).

### Recommendation
Bind the signature-verification identity to the repository actually acted upon: derive the verifying organization strictly from `repository.full_name`'s owner segment (not a separate `owner.login`/`organization.login` field), and reject payloads where `repository.owner.login` disagrees with the owner segment of `repository.full_name`. Additionally, do not allow `verify_webhook_signature` to vacuously pass when `webhook_secret` is blank for organizations that also manage repositories referenced by other, secret-bearing organizations — instead treat a missing `webhook_secret` as "reject all webhooks for this org" rather than "accept unsigned webhooks."

### Proof of Concept
1. Configure Shipit with two GitHub orgs: `attacker-org` (no `webhook_secret` configured) and `victim-org` (has a `webhook_secret`, owns a tracked stack `victim-org/app`).
2. POST to `/webhooks` with header `X-Github-Event: push` and no valid `X-Hub-Signature`, body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/app"
  }
}
```
3. `verify_signature` calls `Shipit.github(organization: "attacker-org")` → `verify_webhook_signature` returns `true` immediately because `attacker-org` has no `webhook_secret` [10](#0-9) .
4. `PushHandler` resolves `stacks` via `Repository.from_github_repo_name("victim-org/app")` [11](#0-10)  and calls `stack.sync_github(expected_head_sha: "deadbeef")` on the real victim stack [9](#0-8)  — a forged, unauthenticated event acting on a repository the attacker never authenticated for.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
