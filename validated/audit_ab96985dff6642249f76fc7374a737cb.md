### Title
`repository.owner.login` vs `repository.full_name` mismatch in webhook payload lets an attacker use a no-secret org to bypass signature verification while mutating another repository's `ReviewStack` - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/reopened_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App / webhook secret to verify against using `params.dig('repository', 'owner', 'login')`, while `ReopenedHandler` (and sibling PR handlers) resolve the target `Repository` using `params.repository.full_name`. Because both fields come from the same attacker-controlled JSON body and are never checked against each other, an attacker can set `repository.owner.login` to an organization with no `webhook_secret` configured (which trivially passes verification via `return true unless webhook_secret`) while setting `repository.full_name` to a victim org/repo that does have review stacks configured, letting the forged payload unarchive/mutate the victim's `ReviewStack`.

### Finding Description
The broken binding is: *the organization whose webhook_secret verified the request* (`repository_owner` in `verify_signature`, derived from `params.dig('repository','owner','login')`) *must equal* the organization that owns the repository the handler actually writes to (`params.repository.full_name`'s owner, used by `Shipit::Repository.from_github_repo_name` in the handler). These are read from two different JSON keys in the same attacker-supplied body, and nothing enforces they agree.

Code path:
- `Shipit::WebhooksController#verify_signature` [1](#0-0)  resolves `github_app = Shipit.github(organization: repository_owner)` using `repository_owner` [2](#0-1) .
- `GitHubApp#verify_webhook_signature` short-circuits to `true` when no `webhook_secret` is configured for that organization: `return true unless webhook_secret` [3](#0-2) .
- On success, `create` parses the *same raw body* and dispatches it unmodified to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
- `ReopenedHandler#repository` resolves the target repository from a *different* JSON field, `params.repository.full_name`, via `Shipit::Repository.from_github_repo_name` [5](#0-4) , and `from_github_repo_name` simply splits the string on `/` and does a DB lookup with no relation back to `repository.owner.login` [6](#0-5) .
- If the resolved repository's review-stack provisioning rules allow it, `process` calls `stack.unarchive!` [7](#0-6) , mutating a `ReviewStack` that belongs to whatever org `full_name` names — not the org used for signature verification.

Attacker's exact request: `POST /webhooks` with `X-Github-Event: pull_request`, `X-Hub-Signature: sha1=<anything>` (or omitted — it's irrelevant once `webhook_secret` is nil for the chosen org), and JSON body containing `repository.owner.login = "no-secret-org"` (any Shipit-configured org lacking `webhook_secret`) but `repository.full_name = "victim-org/victim-repo"`, plus a valid `pull_request` sub-object (`action: "reopened"`, PR `head.sha`/`ref`, `labels`, etc.) satisfying the handler's `ExplicitParameters` schema.

Why existing guards fail: `drop_unhandled_event` only checks the event name exists in the handler registry; `verify_signature` only ever inspects `repository.owner.login`, never `repository.full_name`; `ExplicitParameters` validates shape/types but not cross-field organization consistency; there is no model validation tying `repository.owner.login` to `repository.full_name`'s owner segment.

### Impact Explanation
A single forged POST causes the engine to unarchive/recreate a `ReviewStack` belonging to a repository/org the attacker does not control and never proved ownership of, purely because some *other*, unrelated org in the Shipit deployment happens to have no `webhook_secret` set. This is a cross-tenant state-mutation bug: one org's ("no-secret-org") lack of a secret is leveraged to forge writes against a completely different org's stack. It is repeatable against any repository with review stacks enabled, as long as one no-secret org exists anywhere in the Shipit config, matching the "Critical: payload for one repository mutating another's stack" category.

### Likelihood Explanation
This requires: (1) at least one organization configured in Shipit (`Shipit.github(organization:)`) with no `webhook_secret` set — a realistic and undocumented-as-dangerous configuration state, since the code explicitly treats "no secret configured" as "skip verification" rather than "reject"; (2) a target victim repository with review stacks enabled and a provisioning behavior (`allow_all`, or `allow_with_label`/`prevent_with_label` satisfied by attacker-supplied labels in the same forged JSON) — both attacker-controllable within the payload itself since these are the handler's own DB-driven config, not verified against the payload's org. No secrets, sessions, or tokens are needed by the attacker; only knowledge that some org in the fleet has no configured secret (which may be discoverable from public config/docs or trial-and-error, since the response codes for verified vs. unverified differ: 200 vs 422).

### Recommendation
Cross-check that the organization derived from `repository.full_name` (or `organization.login`) matches `repository.owner.login` before dispatching to handlers, or better: always derive the verifying organization and the routed repository from the *same single field*. Additionally, treat a missing `webhook_secret` as a hard misconfiguration and refuse to accept unsigned/no-secret webhooks in production rather than silently returning `true`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (minitest, ActionDispatch::IntegrationTest style)
test "forged pull_request reopened payload using a no-secret org unarchives a stack in a different org" do
  # Arrange: "no-secret-org" has no webhook_secret configured; "victim-org" does and owns the review stack.
  no_secret_org_app = Shipit::GitHubApp.new('no-secret-org', {}) # no :webhook_secret key
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(no_secret_org_app)

  victim_repo = shipit_repositories(:victim) # owner: 'victim-org', review_stacks_enabled: true, provisioning_behavior_allow_all
  review_stack = shipit_review_stacks(:victim_pr_42) # archived: true

  payload = {
    action: 'reopened',
    number: 42,
    pull_request: {
      id: 1, number: 42, url: 'https://api.github.com/x', title: 't', state: 'open',
      additions: 1, deletions: 1,
      head: { sha: 'abc123', ref: 'feature' },
      user: { login: 'attacker' },
      assignees: [], labels: []
    },
    # verification uses this org (no secret => auto-verified)
    repository: { owner: { login: 'no-secret-org' }, full_name: victim_repo.full_name },
    sender: { login: 'attacker' }
  }.to_json

  post '/webhooks', params: payload,
    headers: { 'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => 'sha1=deadbeef', 'Content-Type' => 'application/json' }

  assert_response :ok
  # Equality violated: verifying org ('no-secret-org') != owning org of mutated stack ('victim-org')
  assert_equal 'no-secret-org', 'no-secret-org'          # org verify_signature trusted
  refute_equal 'no-secret-org', victim_repo.owner          # actual owner of mutated stack
  assert review_stack.reload.archived? == false, "victim-org's ReviewStack was unarchived by no-secret-org's forged payload"
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
