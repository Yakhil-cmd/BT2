### Title
RAY-denominated debt overflow permanently freezes market operations - (File: common/src/rates/index.rs)

### Summary
The interest-accrual path computes total debt as `borrowed * borrow_index` in an `i128` result and panics when that value exceeds the RAY domain. Because every pool mutation synchronizes the market before operating, crossing this ceiling permanently blocks repayment, withdrawal, liquidation, and later index updates for the affected market. [1](#0-0) [2](#0-1) 

### Finding Description
`calculate_supplier_rewards` multiplies the market's scaled debt by both the old and new borrow indexes; either multiplication raises `MathOverflow` if the resulting RAY value does not fit in `i128`. [3](#0-2) 

The permissionless controller entrypoint `update_indexes` forwards caller-selected `HubAssetKey`s to the pool, whose `update_indexes` implementation invokes `ops::market::accrue` and therefore `global_sync`. [4](#0-3) [5](#0-4) 

`global_sync` calls `accrue_chunk`, which evaluates `accrue_step` before committing the new indexes and revenue shares. [6](#0-5) 

All ordinary pool mutations use the same synchronization boundary through `synced_market`, so once `borrowed * borrow_index` overflows, the transaction reverts before the requested operation can run. [7](#0-6) 

The existing stress test demonstrates the reachable state: a 1-billion-whole-token, 18-decimal market at 98% utilization eventually causes `update_indexes` to return `MathOverflow`, and subsequent withdrawal and repayment attempts fail with the same error. [8](#0-7) 

### Impact Explanation
This is a permanent freezing-of-funds vulnerability for the affected market. Suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot execute liquidation legs because each path loads a synced market and accrues first. [7](#0-6) 

The borrow-index ceiling does not prevent the failure because total debt can exceed `i128::MAX` before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
An unprivileged caller can trigger the overflow through `update_indexes(caller, vec![hub_asset])` after the market accumulates enough scaled debt and index growth. [11](#0-10) [5](#0-4) 

Reaching the state requires a very large market and sustained high-utilization accrual, so exploitation is capital- and time-dependent rather than a single low-cost transaction. Nevertheless, the configured domain permits billion-token positions and the repository's own stress test reaches the failure before the index cap. [12](#0-11) [13](#0-12) 

### Recommendation
Bound market debt by `i128::MAX / MAX_BORROW_INDEX_RAY` rather than by token-unit caps alone, and enforce that bound on every debt-minting path as projected debt rather than only at initial scale. Alternatively, represent accrued market totals in `I256`, clamp index growth before the total-value calculation overflows, or provide a no-accrual emergency repayment/withdrawal path that cannot be blocked by total-debt valuation.

### Proof of Concept
1. Create or select an 18-decimal market whose caps permit approximately `1_000_000_000 * 10^18` base units, then call `supply` to deposit that amount.
2. Supply sufficient collateral in another market and call `borrow` for approximately 98% of the first market's principal, leaving utilization high.
3. Advance ledger time through repeated annual intervals while invoking `update_indexes(caller, vec![HubAssetKey { hub_id, asset }])`.
4. When `borrowed * borrow_index` exceeds `i128::MAX`, `calculate_supplier_rewards` panics with `MathOverflow` inside accrual. [1](#0-0) 
5. Subsequent `repay`, `withdraw`, `liquidate`, and further `update_indexes` calls all load the market through `synced_market` or `accrue` and revert during the same accrual calculation. [7](#0-6) 
6. The repository test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates this sequence and asserts both withdrawal and repayment failures. [13](#0-12)

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
