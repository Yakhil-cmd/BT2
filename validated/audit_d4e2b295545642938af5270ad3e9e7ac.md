## Title
CCMenu token authorizes `read:stack` on a specific stack but the controller uses it to read any stack - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::CCMenuController` authenticates requests with a bearer `token` param that is bound to a specific `ApiClient`, but the action that renders stack build status ignores the client/stack binding and instead resolves the target stack directly from the attacker-controlled `stack_id` URL parameter.

### Finding Description
`CCMenuUrlController#client` mints a per-user, per-stack CCMenu URL by creating (or reusing) an `ApiClient` scoped with `permissions: %w[read:stack]` and embeds `client.authentication_token` plus the originating `stack_id` in the returned URL: [1](#0-0) 

The token itself only encodes the `ApiClient` id (via a `SimpleMessageVerifier` HMAC) and carries no reference to which stack it was generated for: [2](#0-1) 

`Shipit::Api::BaseController` is designed to scope stack access to the client's own `stack_id` when the client is stack-bound (`current_api_client.stack_id?` gates whether `Stack.all` or `Stack.where(id: current_api_client.stack_id)` is used): [3](#0-2) 

However, `CCMenuController` overrides `#stack` and bypasses that scoping entirely, resolving the stack purely from the request's `stack_id` parameter with no relation to the authenticated `ApiClient`: [4](#0-3) 

Only the `read:stack` permission bit is checked via `require_permission :read, :stack`, which calls `ApiClient#check_permissions!` — a check that only inspects the `permissions` array, never the `stack_id` association: [5](#0-4) 

This breaks the intended binding: `ApiClient.stack_id (authorized stack) == stack the token can read`. In practice, any valid CCMenu token (which is a bare, unscoped GET query-string secret designed to be embedded in third-party CI dashboard tools) can be replayed against `/api/stacks/:other_stack_id/cc_menu.xml` to read another stack's deploy/build status, deploy timestamps, and running-task state — data the token was never meant to unlock.

### Impact Explanation
This is an unauthenticated-read escalation: possession of a single CCMenu token (which is routinely shared with third-party CI status monitors, embedded in URLs, and is not treated as a high-value secret by users) grants read access to the deploy/task status of every stack in the Shipit instance, not just the one it was issued for. This matches the "High" impact class: unauthenticated read of stack state / task output beyond the token's authorized scope.

### Likelihood Explanation
Likelihood is high once a token is obtained: no additional guessing is required beyond varying the `stack_id` path parameter, which is visible/predictable (numeric or `owner/name/env` slug). Any party who legitimately has one CCMenu URL (e.g., a build-status widget shared across a team, or leaked via a dashboard/log) can pivot to read every other stack's status.

### Recommendation
In `CCMenuController#stack`, resolve the stack through the same client-scoped lookup used elsewhere (`current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all).from_param!(params[:stack_id])`, mirroring `BaseController#stacks`/`#stack`, so a stack-scoped `ApiClient` cannot be used to read a different stack's status.

### Proof of Concept
1. As user A, visit stack `shipit` and trigger `GET /stacks/shipit-engine/production/cc_menu_url` — `CCMenuUrlController#client` creates/reuses an `ApiClient` (`permissions: ["read:stack"]`) and returns a URL containing `token=<T>` and `stack_id=shopify/shipit-engine/production`. [6](#0-5) 
2. Take token `T` and replay it against a different, unrelated stack: `GET /api/stacks/other-org/other-repo/staging/cc_menu.xml?token=T`.
3. `authenticate_api_client` succeeds (token `T` verifies to a real `ApiClient`), `require_permission :read, :stack` passes (client has `read:stack`), and `#stack` resolves `Stack.from_param!('other-org/other-repo/staging')` directly from the request param, returning that unrelated stack's XML status — confirming the token is not actually confined to the stack it was issued for. [7](#0-6)

```ruby
# frozen_string_literal: true

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
```
