## Finding

### Title
Git history rewrite (`commit --amend`/rebase) during a Stop-hook retry window collapses the v2 review set to empty, permanently skipping review of a dangerous change - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`restore_unreviewed_stop_state` preserves `touched_paths` and (conditionally) `baseline_sha` across a retried Stop hook fire, but it never re-validates or restores `head_at_capture`'s relationship to the *current* HEAD. If the dangerous edit gets folded into a rewritten commit (`git commit --amend`, interactive rebase) during the window between a transient Stop failure and its retry, the mid-session-commit detection in `compute_v2_review_set` silently fails, `dirty_now` becomes empty, and the whole review set collapses to empty, causing the Stop hook to skip review entirely.

### Finding Description
The Stop hook (`handle_stop_hook`) snapshots session state via `consume_stop_state`, which returns `baseline_sha` and `head_at_capture` unchanged and only clears `touched_paths` [1](#0-0) . On a transient failure (API unreachable, or an HTTP error after the LLM call), the hook calls `restore_unreviewed_stop_state(session_id, touched_paths, snap_baseline)` to re-arm the guard for the next retry [2](#0-1) [3](#0-2) . That restore function only merges `touched_paths` back and conditionally sets `baseline_sha` — it does **not** touch or re-derive `head_at_capture`: [4](#0-3) .

`compute_v2_review_set` relies on `head_at_capture` to catch files changed by mid-session **commits**, via `_is_ancestor(repo, head_at_capture, current_head)` — this only returns true when the current HEAD is a fast-forward descendant of `head_at_capture` [5](#0-4) , backed by `git merge-base --is-ancestor` [6](#0-5) .

A normal, unprivileged git operation — `git commit --amend` (or an interactive rebase) — replaces HEAD with a **sibling** commit rather than a descendant, so `head_at_capture` is no longer reachable from the new HEAD and `_is_ancestor` returns `False`. If the dangerous edit is folded into that amended commit, the working tree becomes clean, so `git status --porcelain` reports no dirty files. `dirty_now` (tracked_dirty ∪ new_untracked) is then empty, and since `review_set = dirty_now & changed_since` (or `dirty_now` alone on missing baseline), an empty `dirty_now` forces an empty `review_set` regardless of `changed_since` [7](#0-6) . `handle_stop_hook` treats an empty `review_paths` as "nothing to review" and exits cleanly via `_skip(9, ...)` with `sys.exit(0)` — no code-2 continuation, no LLM review, no warning: [8](#0-7) .

The retry window created by `restore_unreviewed_stop_state` (API-unreachable or LLM-error paths) is exactly the interval during which this amend can happen: the guard keeps `touched_paths`/`baseline_sha` alive across the retry, but provides no protection for `head_at_capture`, so the invariant "the review set must stay bound to the right repo, baseline, and touched paths" is broken — the review set becomes decoupled from the actual dangerous file once history is rewritten.

### Impact Explanation
This is a logic-level bypass of the security-guidance Stop hook's mandatory review gate. A dangerous change (e.g., a hardcoded secret, command injection, SQLi) that would normally be flagged and force `exit(2)`/continuation is silently skipped, with the review pipeline reporting "empty review set" and exiting 0 as if there were nothing to review. This matches "Logic-level service disruption caused by bypassing a required guard or misbinding security state" — the guard is bypassed and the baseline/touched-path binding to the actual dangerous content is lost.

### Likelihood Explanation
The precondition is a transient Stop failure (API unreachable or an HTTP error from the LLM call — both are routine, not attacker-controlled network conditions that occur in normal operation) followed by an ordinary `git commit --amend` (or rebase) during the retry window, run either by the user/agent as part of normal workflow or induced via prompt-injected instructions telling Claude to "clean up the commit message" or "squash the last commit." No elevated privileges, no exploitation of the plugin's execution environment, and no unusual git commands are required — this is well within "normal git operations in a cloned repo." The failure/retry window is a routine occurrence given `ENABLE_STOP_REVIEW`/API dependency, making this readily repeatable.

### Recommendation
- Update `restore_unreviewed_stop_state` to also validate/refresh `head_at_capture` on restore (or drop the ancestor-based commit-detection shortcut when a retry has occurred), so that non-fast-forward history changes during a retry can't zero out `dirty_now`.
- In `compute_v2_review_set`, when `_is_ancestor` returns `False` but `head_at_capture != current_head`, don't just skip the ancestor union — detect the rewrite (e.g., via `git merge-base` on old/new HEAD) and diff against the merge-base or `head_at_capture` directly so committed changes from a rewritten commit are still surfaced.
- Treat an empty `review_paths` combined with a non-empty preserved `touched_paths` list as suspicious (e.g., re-check `git show <touched_path>` against `baseline_sha` before skipping) rather than unconditionally trusting `git status --porcelain`.

### Proof of Concept
Integration test plan (pytest-style, using a temp git repo fixture already used elsewhere in the plugin's test suite):
1. Init a repo, commit an initial file, capture `baseline_sha`/`head_at_capture` via `capture_git_baseline` + `_git_rev_parse_head` (simulating UPS).
2. Simulate PostToolUse: write `dangerous_file.py` with an obviously vulnerable pattern (e.g., `os.system(user_input)`), call `record_touched_path`.
3. Simulate a Stop hook fire: call `consume_stop_state`, then simulate a transient failure by directly invoking `restore_unreviewed_stop_state(session_id, touched_paths, snap_baseline)`.
4. Between the failed fire and the retry, run `git add dangerous_file.py && git commit --amend --no-edit` in the repo (folding the dangerous file into the amended HEAD commit, rewriting it as a sibling, not descendant, of `head_at_capture`).
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline)` and assert:
   - Expected (pre-fix, demonstrating the bug): `review_paths == []` even though `dangerous_file.py` differs from `baseline_sha`.
   - Desired (post-fix): `review_paths` still contains `dangerous_file.py`.
6. Additionally assert `_is_ancestor(repo, head_at_capture, new_head)` is `False` after the amend, confirming the root cause of the missed detection.

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```

```python
def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```
