### Title
Silent enforcement bypass via missing `field` key in explicit `conditions` frontmatter causes block rules to never match - (File: `plugins/hookify/core/config_loader.py`)

### Summary
`Condition.from_dict` silently defaults a missing `field` key to the empty string `''` instead of failing or applying the same event-based inference used by the legacy `pattern` path. Because `RuleEngine._extract_field` never recognizes `field=''` as a known field name, any condition built this way permanently returns `None`, causing `_check_condition` to fail and the enclosing rule (including `action: block` rules) to never match, silently disarming the rule while its frontmatter still looks like an active security control.

### Finding Description
`Rule.from_dict` supports two parsing paths for rule frontmatter [1](#0-0) :
- **Legacy `pattern` style**: `field` is always correctly inferred from `event` (`bash`→`command`, `file`→`new_text`, else→`content`) [2](#0-1) .
- **Explicit `conditions` style**: each list item is passed to `Condition.from_dict`, which does `field=data.get('field', '')` [3](#0-2) . If a condition dict is missing the `field` key (e.g. because of a hand-authored/generated rule that only specifies `operator` and `pattern`), `field` silently becomes `''`.

At evaluation time, `RuleEngine._extract_field` only recognizes a fixed set of literal field names (`command`, `new_text`/`new_string`, `old_text`/`old_string`, `file_path`, `content`, `reason`, `transcript`, `user_prompt`) [4](#0-3) . `field=''` matches none of them, so `_extract_field` returns `None`, `_check_condition` returns `False` immediately [5](#0-4) , and `_rule_matches` requires *all* conditions to match, so the whole rule never fires [6](#0-5) .

Attacker-reachable paths for such malformed frontmatter:
1. **Repo-shipped rule file**: a rule file such as `.claude/hookify.block-curl-pipe.local.md` committed with `action: block` and a `conditions:` entry that omits `field` (e.g. only `operator`/`pattern` present) looks like an active blocking control to a reviewer, but is a permanent no-op. The plugin's own `SKILL.md` guidance recommends gitignoring `.local.md` files, but nothing in `load_rule_file`/`extract_frontmatter` enforces that or validates required condition fields, so a malicious or careless contributor can still ship one [7](#0-6) .
2. **`/hookify` generation**: if the generation prompt/content that drives rule authoring (potentially influenced by untrusted repository content) produces a `conditions` block missing `field`, the resulting rule silently fails to enforce, with no error surfaced beyond a print in verbose failure paths — the loader treats a syntactically valid-but-semantically-empty condition as a normal, healthy rule (no exception is raised; `load_rule_file` returns a `Rule` object normally).

This directly violates the stated invariant "default field inference must not broaden rule scope or weaken enforcement": the explicit-conditions default (`field=''`) weakens enforcement to zero, whereas the legacy path's inference is always correct and non-empty.

### Impact Explanation
Hookify's `action: block` rules are meant to be an operator-authored enforcement layer (e.g., blocking dangerous `rm -rf`, `curl | sh`, or committing secrets) enforced via `PreToolUse`/`Stop` hook responses with `permissionDecision: deny` [8](#0-7) . A rule silently defanged by this bug gives operators/reviewers false confidence that a specific class of dangerous command or file edit is blocked when in fact it is never evaluated as matching, allowing the underlying dangerous command to execute unblocked by this control. This is a defense-in-depth mechanism layered on top of Claude Code's core approval system, not a replacement for it — so the impact is scoped to "hookify's own advertised guarantee is defeated," which can translate into unauthorized command execution in setups that rely on hookify block rules as their enforcement mechanism.

### Likelihood Explanation
The bug is deterministic and trivially reproducible: any rule using the `conditions:` list form without a `field` key on one or more entries becomes a permanent no-op, regardless of `action`. No privilege beyond the ability to introduce/modify a `.claude/hookify.*.local.md` file (via repo content or by influencing `/hookify` output) is required, and the failure is silent — `load_rule_file` returns a normal `Rule` object with no warning that the condition is semantically empty [9](#0-8) .

### Recommendation
- In `Condition.from_dict`, do not default `field` to `''`; require it explicitly, and raise/skip the rule (with a loud warning) if missing, mirroring how `load_rule_file` already treats malformed files as errors.
- Alternatively, reuse the same event-based field inference used for the legacy `pattern` path when `field` is absent in an explicit condition, so both parsing styles have identical default-safety behavior.
- Add a validation pass in `Rule.from_dict`/`load_rule_file` that rejects (fails closed, not silently drops) any `action: block` rule whose conditions list contains a condition with an unrecognized/empty `field`.

### Proof of Concept
```python
from hookify.core.config_loader import Rule
from hookify.core.rule_engine import RuleEngine

frontmatter = {
    "name": "block-dangerous-rm",
    "enabled": True,
    "event": "bash",
    "action": "block",
    "conditions": [
        # Missing 'field' — e.g. produced by generation or careless authoring
        {"operator": "regex_match", "pattern": r"rm\s+-rf"}
    ],
}
rule = Rule.from_dict(frontmatter, "Dangerous rm command blocked!")

engine = RuleEngine()
result = engine.evaluate_rules([rule], {
    "hook_event_name": "PreToolUse",
    "tool_name": "Bash",
    "tool_input": {"command": "rm -rf /"},
})

# Expected (intended policy): result contains permissionDecision "deny"
# Actual: result == {}  -> command is NOT blocked
assert result == {}, "Block rule silently failed to fire due to missing 'field' default"
```
Compare against the equivalent legacy-`pattern` rule (`pattern: rm\s+-rf`, no `conditions`), which correctly infers `field=command` and blocks the same input — demonstrating the parsing differential and confirming the invariant violation.

    @classmethod
    def from_dict(cls, frontmatter: Dict[str, Any], message: str) -> 'Rule':
        """Create Rule from frontmatter dict and message body."""
        # Handle both simple pattern and complex conditions
        conditions = []

        # New style: explicit conditions list
        if 'conditions' in frontmatter:
            cond_list = frontmatter['conditions']
            if isinstance(cond_list, list):
                conditions = [Condition.from_dict(c) for c in cond_list]

        # Legacy style: simple pattern field
        simple_pattern = frontmatter.get('pattern')
        if simple_pattern and not conditions:
            # Convert simple pattern to condition
            # Infer field from event
            event = frontmatter.get('event', 'all')
            if event == 'bash':
                field = 'command'
            elif event == 'file':
                field = 'new_text'
            else:
                field = 'content'

            conditions = [Condition(
                field=field,
                operator='regex_match',
                pattern=simple_pattern
            )]

        return cls(
            name=frontmatter.get('name', 'unnamed'),
            enabled=frontmatter.get('enabled', True),
            event=frontmatter.get('event', 'all'),
            pattern=simple_pattern,
            conditions=conditions,
            action=frontmatter.get('action', 'warn'),
            tool_matcher=frontmatter.get('tool_matcher'),
            message=message.strip()
        )

def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule

    except (IOError, OSError, PermissionError) as e:
        print(f"Error: Cannot read {file_path}: {e}", file=sys.stderr)
        return None
    except (ValueError, KeyError, AttributeError, TypeError) as e:
        print(f"Error: Malformed rule file {file_path}: {e}", file=sys.stderr)
        return None
    except UnicodeDecodeError as e:
        print(f"Error: Invalid encoding in {file_path}: {e}", file=sys.stderr)
        return None
    except Exception as e:
        print(f"Error: Unexpected error parsing {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
        return None

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
