### Title
Not a vulnerability — documented and bounded staleness window is an accepted design trade-off - ([File: pallets/remote-proxy/src/lib.rs])

### Summary
The `do_remote_proxy` function [1](#0-0)  validates proofs against any root still present in `BlockToRoot`, which retains up to `MaxStorageRootsToKeep` entries [2](#0-1) . This means an old proof remains valid until its root is pruned, but this is explicitly documented as expected behavior in the module-level security considerations doc comment, and is bounded/finite rather than an open-ended exploit.

### Finding Description
The pallet's doc comment explicitly warns operators about this exact scenario: "when deleting a proxy at the remote location at X, it will take `MaxStorageRootsToKeep` time until the proxy can not be used anymore. The reason for this is that the caller will be able to provide an old `proof` at which the proxy was still available." [3](#0-2)  The pruning logic in `on_validation_data` removes roots older than `block - MaxStorageRootsToKeep`, keeping the window strictly bounded [4](#0-3) , and this bounded pruning/rejection behavior is directly tested in `clean_up_works_and_old_blocks_are_rejected` [5](#0-4) , which confirms proofs referencing blocks outside the retained window are rejected with `UnknownProofAnchorBlock`. The consuming runtime configures a concrete, finite window (`RC_MINUTES`, i.e. relay-chain minutes) for `MaxStorageRootsToKeep` [6](#0-5) , so the staleness window is a short, known, finite duration rather than indefinite.

### Impact Explanation
There is no unbounded or unauthorized replay: the exploit window matches exactly the documented and configured `MaxStorageRootsToKeep` duration, which is a known and accepted risk parameter that operators are told to size accordingly. This is analogous to standard nonce/session-expiry windows in other systems and is not a logic error, missing check, or accounting bug — it is the intended behavior explicitly called out by the pallet authors.

### Likelihood Explanation
N/A — this is not treated as a bug because the behavior is intentional and documented, not an oversight.

### Recommendation
No fix required; this is expected behavior. Runtime integrators should size `MaxStorageRootsToKeep` conservatively (as already done, e.g. `ConstU32<{ RC_MINUTES }>` for asset-hub-kusama) per the module's own documented guidance.

### Proof of Concept
Not applicable; the existing test `clean_up_works_and_old_blocks_are_rejected` already demonstrates the bounded window's enforcement [5](#0-4) .

	impl<T: Config<I>, I: 'static> OnSystemEvent for Pallet<T, I> {
		fn on_validation_data(validation_data: &PersistedValidationData) {
			let Some((block, hash)) = T::RemoteProxy::block_to_storage_root(validation_data) else {
				return;
			};

			// Update the block to root mappings.
			BlockToRoot::<T, I>::mutate(|roots| {
				let delete_up_to =
					block.clone().saturating_sub(T::MaxStorageRootsToKeep::get().into());

				while roots.first().is_some_and(|f| f.0 <= delete_up_to) {
					roots.remove(0);
				}

				// We always remove all the old items before, thus there should always be space in
				// the vector.
				let _res = roots.try_push((block, hash));
				debug_assert!(_res.is_ok());
			});
		}

		fn do_remote_proxy(
			who: T::AccountId,
			real: T::AccountId,
			force_proxy_type: Option<T::ProxyType>,
			call: <T as pallet_proxy::Config>::RuntimeCall,
			proof: RemoteProxyProof<RemoteBlockNumberOf<T, I>>,
		) -> DispatchResult {
			let Some(real_remote) = T::RemoteProxy::local_to_remote_account_id(&real) else {
				return Err(Error::<T, I>::CouldNotConvertLocalToRemoteAccountId.into());
			};

			let def = match proof {
				RemoteProxyProof::RelayChain { proof, block } => {
					let roots = BlockToRoot::<T, I>::get();

					let Ok(storage_root) = roots
						.binary_search_by(|(b, _)| b.cmp(&block))
						.map(|pos| roots[pos].1.clone())
					else {
						return Err(Error::<T, I>::UnknownProofAnchorBlock.into());
					};

					let key = T::RemoteProxy::proxy_definition_storage_key(&real_remote);

					let db =
						sp_trie::StorageProof::new(proof).into_memory_db::<RemoteHasherOf<T, I>>();
					let value = sp_trie::read_trie_value::<sp_trie::LayoutV1<_>, _>(
						&db,
						&storage_root,
						&key,
						None,
						None,
					)
					.ok()
					.flatten()
					.ok_or(Error::<T, I>::InvalidProof)?;

					let proxy_definitions = alloc::vec::Vec::<
						ProxyDefinition<
							RemoteAccountIdOf<T, I>,
							RemoteProxyTypeOf<T, I>,
							RemoteBlockNumberOf<T, I>,
						>,
					>::decode(&mut &value[..])
					.map_err(|_| Error::<T, I>::ProxyDefinitionDecodingFailed)?;

					let f = |x: &ProxyDefinition<
						T::AccountId,
						T::ProxyType,
						BlockNumberFor<T>,
					>|
					 -> bool {
						x.delegate == who &&
							force_proxy_type.as_ref().is_none_or(|y| &x.proxy_type == y)
					};

					proxy_definitions
						.into_iter()
						.filter_map(T::RemoteProxy::remote_to_local_proxy_defintion)
						.find(f)
						.ok_or(Error::<T, I>::DidNotFindMatchingProxyDefinition)?
				},
			};

			ensure!(def.delay.is_zero(), Error::<T, I>::Unannounced);

			Self::do_proxy(def, real, call);

			Ok(())
		}
