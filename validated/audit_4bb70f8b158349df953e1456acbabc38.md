### Title
Position-NFT transfer does not transfer controller spending authority - ([File: contracts/controller/src/account.rs])

### Summary
The position NFT’s transferable owner is not the authority used by the controller’s position-management paths. `transfer` can move the NFT to a new holder, but `Account.owner` remains the original minter. All owner/delegate-gated controller calls still trust the stale `account.owner` field, so the old holder retains control after selling or transferring the position while the current NFT owner is rejected. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`create_account_with` mints the NFT to `owner` and stores that address in `Account.owner`; no subsequent NFT transfer updates the account record. [4](#0-3) 

The NFT exposes the normal enumerable NFT interface, so its `transfer`/`transfer_from` implementation can change `owner_of(token_id)` independently of controller storage. [5](#0-4) [6](#0-5) 

The controller’s main spending paths do not authenticate against the NFT’s current owner. `is_owner_or_delegate` compares `caller` with the stale `account.owner`; `require_owner_or_delegate` returns early for that stale owner and otherwise requires that caller to be an active listed delegate. [7](#0-6) 

`process_borrow`, `process_withdraw`, and liquidation share-credit receiver resolution all load `Account` and then enforce that stale owner. [8](#0-7) [9](#0-8) [10](#0-9) 

This creates two inconsistent credential issuers: the NFT says the transferee owns the account, while controller storage continues to treat the transferor as owner. The mismatch is the XOXNO analogue of accepting a credential under the wrong issuer/authority result.

### Impact Explanation
An old owner can transfer or sell a position NFT and then retain practical control over the collateral and debt represented by that NFT. The old owner can call `withdraw` or `borrow` because `caller == account.owner` still succeeds. [11](#0-10) [9](#0-8) 

The new NFT owner cannot call those endpoints because the same stale-owner check does not recognize them. This enables theft from a purchaser or recipient of the position NFT and can freeze the new owner out of their collateral indefinitely unless the former owner cooperates. [12](#0-11) 

### Likelihood Explanation
The vulnerable path is reachable by an unprivileged NFT holder through the ordinary `transfer` or approved `transfer_from` interface. After the transfer:

1. The transferee’s controller calls fail `require_owner_or_delegate`.
2. The transferor’s calls continue to pass it.
3. The transferor can drain withdrawable collateral or create debt against the transferred position.

No privileged role, leaked key, oracle manipulation, or contract upgrade is required. The only precondition is an existing funded account NFT changing hands.

### Recommendation
Make the NFT owner the single source of truth on every account-authority decision, or make ownership transfer impossible.

Preferred fix:
- Replace uses of persisted `Account.owner` in `is_owner_or_delegate` / `require_owner_or_delegate` with `storage::account_owner(env, account_id)` or equivalent live `owner_of(account_id)` lookup.
- Ensure delegate grants follow the current NFT owner and are invalidated or rebound safely when ownership changes.
- Apply the same rule to `supply`, `borrow`, `withdraw`, strategy endpoints, liquidation `SeizeMode::Credit(id)`, delegate management, and account renewal.
- Add an enforced-auth test proving that after NFT transfer the former owner cannot withdraw/borrow and the new owner can.

If NFT transfers are intended to be unsupported, disable `transfer` and `transfer_from` rather than retaining inconsistent accounting.

### Proof of Concept
1. Alice calls `controller.supply(alice, 0, spoke_id, [(USDC, 1_000)])`, creating `account_id = N` and minting NFT `N` to Alice.
2. Alice calls `position_nft.transfer(alice, bob, N)`.
3. The NFT now reports Bob as owner, but controller storage still stores `Account.owner = alice`. [2](#0-1) 
4. Bob calls `controller.withdraw(bob, N, [(USDC, 1)], None)`. The call reaches `require_owner_or_delegate(N, bob, alice)`, fails ownership, and Bob cannot withdraw. [9](#0-8) [12](#0-11) 
5. Alice calls `controller.withdraw(alice, N, [(USDC, 1)], Some(attacker_or_alice))`. The stale `alice == account.owner` comparison passes, and the pool pays the recipient according to normal withdrawal logic. [11](#0-10) [13](#0-12) 

Expected result after the fix: step 4 succeeds for Bob, and step 5 fails for Alice.

#[contractimpl(contracttrait)]
impl NonFungibleToken for PositionNft {
    type ContractType = Enumerable;

    /// `{stored base_uri}{token_id}?isStatic=true&chain=STELLAR`
    ///
    /// Panics with the OZ `NonExistentToken` error for burned or never-minted
    /// ids, matching the stock behavior.
    fn token_uri(e: &Env, token_id: u32) -> String {
        let _owner = Base::owner_of(e, token_id);

        let base = Base::base_uri(e);
        let base_len = base.len() as usize;
        // OZ `set_metadata` caps the base at `MAX_BASE_URI_LEN` (200 bytes):
        // 200 + 10 digits (u32 max) + 28-byte suffix fits in 256.
        let mut buf = [0u8; 256];
        base.copy_into_slice(&mut buf[..base_len]);
        let mut len = base_len;
        // Decimal digits, most significant first. token_id >= 1 always
        // (id 0 is consumed at construction), so no zero special-case.
        let mut digits = [0u8; 10];
        let mut n = token_id;
        let mut count = 0usize;
        while n > 0 {
            digits[count] = b'0' + (n % 10) as u8;
            n /= 10;
            count += 1;
        }
        while count > 0 {
            count -= 1;
            buf[len] = digits[count];
            len += 1;
        }
        for b in TOKEN_URI_SUFFIX.bytes() {
            buf[len] = b;
            len += 1;
        }
        String::from_bytes(e, &buf[..len])
    }
}

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}
