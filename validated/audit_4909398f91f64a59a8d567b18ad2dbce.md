Based on my investigation, I found no demonstrable Polkadot SDK analog to this Jenkins CVE.

The Jenkins vulnerability (CVE-2018-1999043) involves `BasicAuthenticationFilter` and `BasicHeaderApiTokenAuthenticator` creating ephemeral in-memory `User` objects for every failed login attempt with an unrecognized username, allowing unauthenticated attackers to exhaust JVM memory through repeated invalid-credential requests — a pure resource-exhaustion/DoS bug tied to a specific in-process object cache with no bound.

Searching the codebase for comparable patterns — extrinsic/XCM/validation paths that allocate or persist ephemeral records upon *failed* or *invalid* authentication/signature checks — did not surface a genuine analog:

- Substrate's transaction validation path (`validate_unsigned`, `Checkable::check`, `Applyable::validate`) rejects invalid signatures/proofs early via `InvalidTransaction::BadProof` etc. **before** any state mutation or persistent allocation occurs, e.g. in `UncheckedExtrinsic::check` [1](#0-0)  and in the mixnet, paras PVF-check, and meta-tx unsigned-validation flows, all of which return early on bad signatures without creating any records [2](#0-1) [3](#0-2) [4](#0-3) .
- `frame_system`/`Executive::apply_extrinsic` only calls `note_extrinsic` (persisting the encoded extrinsic) *after* the signature/extension `check` succeeds, so a bad signature never reaches that point [5](#0-4) .
- Any place that does create records regardless of an inner failure (e.g. `pallet-recovery`'s v1 migration inserting an `Attempt` entry even when the security-deposit hold fails) is a one-time storage migration under root/governance control, not a repeatable attacker-triggered path, and does not match the "no privileged prerequisite" scope of this task [6](#0-5) .

More importantly, even a theoretical analog matching this CVE's bug class would be explicitly out of scope per the task's own exclusion rules, which reject "unbounded-loop or memory/storage-growth scenarios" and "generic resource-exhaustion claims" — precisely the nature of CVE-2018-1999043 (unbounded ephemeral-object creation causing memory exhaustion).

No vulnerability found for this question.
