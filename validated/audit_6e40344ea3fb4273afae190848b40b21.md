### Title
Cross-organization webhook confusion lets an attacker forge a `pull_request` `opened` event that provisions a `ReviewStack` on any repository, when the attacker's chosen org has no `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/org config used to verify the HMAC signature solely from `repository_owner` (`params.dig('repository','owner','login')`), while the actual repository/stack that the event handler acts on is resolved independently from `params.repository.full_name` in `OpenedHandler#repository` [1](#0-0) [2](#0-1) . If the org named in `owner.login` has no `webhook_secret` configured, `GitHubApp#verify_webhook_signature` returns `true` unconditionally (`return true unless webhook_secret`) [3](#0-2) , so an attacker can pick any no-secret org for `owner.login` while pointing `full_name` at a *different*, secret-protected repository, and the forged payload will pass signature verification and still act on that other repository's `ReviewStack`.

### Finding Description
The broken binding: the code implicitly assumes
`org_used_for_signature_verification(params.repository.owner.login) == org_that_owns_the_mutated_repository(params.repository.full_name)`.
This is never enforced anywhere in the request pipeline.

Trace:
1. `WebhooksController#create` runs `before_action :verify_signature`, which calls `Shipit.github(organization: repository_owner)` and then `github_app.verify_webhook_signature(signature, raw_post)` [4](#0-3) .
2. `repository_owner` is taken from `params.dig('repository', 'owner', 'login')`, fully attacker-controlled JSON in the raw POST body [1](#0-0) .
3. `Shipit.github(organization:)` looks up per-org config via `github_app_config(organization)` and instantiates a `GitHubApp` for that org and its `webhook_secret` [5](#0-4) [6](#0-5) .
4. If that org's config has no `webhook_secret` set (`@webhook_secret = @config[:webhook_secret].presence`), `verify_webhook_signature` returns `true` for *any* signature/body, i.e., unauthenticated [7](#0-6) .
5. After passing `verify_signature`, `create` dispatches the whole raw payload to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [8](#0-7) .
6. `OpenedHandler#repository` resolves the acted-upon repository from `params.repository.full_name` via `Shipit::Repository.from_github_repo_name`, completely independent of `owner.login` used for signature verification [2](#0-1) .
7. If `respond_to_pull_request_opened?`/provisioning rules pass, `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` runs, creating a `ReviewStack` with `branch: params.pull_request.head.ref` and `environment: "pr#{params.number}"`, and a `User.find_or_create_by_login!(params.sender.login)` acting as actor [9](#0-8) .

Attacker's exact request: `POST /webhooks` with header `X-Github-Event: pull_request`, any/garbage `X-Hub-Signature`, and a JSON body where `repository.owner.login` = an org with no `webhook_secret` configured in `Rails.application.credentials.github`, but `repository.full_name` = `"victim-org/victim-repo"` (a repo belonging to an org that *does* have a `webhook_secret`), `action: "opened"`, plus a valid-looking `pull_request` object and `sender.login`.

Why guards fail: `verify_signature` never checks that the org resolved for signature verification is the same org that owns `full_name`; `drop_unhandled_event` only checks the event type exists a handler for, not payload consistency; `ExplicitParameters` schema in `OpenedHandler` only validates field *types/presence*, not that `repository.full_name`'s org matches `repository.owner.login`; there is no `force_github_authentication`/session check on this unauthenticated webhook endpoint by design. This precisely matches the "org selected to verify the signature is not the org that owns the repository the handler mutates" exploit idea.

### Impact Explanation
An unprivileged attacker who merely controls a no-secret-configured org's webhook delivery (or can simply POST an HTTP request with a forged owner name — no GitHub secret needed since the check is bypassed entirely for that org) can cause `Shipit::Stack`/`Shipit::ReviewStack` records to be created for *any* victim repository configured in the multi-org Shipit instance, as long as that repo's `full_name` and provisioning settings (`review_stacks_enabled`, `provisioning_behavior_allow_all?`, etc.) permit it. This is a payload for one org mutating another org's stack — a write for a repository that did not authenticate the request — matching the "Critical: payload for one repository mutating another's stack" impact category. It is repeatable against every repository whose owning org happens to have `webhook_secret` unset relative to the org selected in `owner.login` (or, more precisely, wherever an org with no secret exists in the same Shipit deployment, that org's identity can be used to forge events resolved against any other org's `full_name`).

### Likelihood Explanation
Preconditions: the multi-org GitHub App config schema must be active (`github_default_organization` non-nil) and at least one configured org must have no `webhook_secret` set; the target repository must have review-stack provisioning enabled and configured to allow PR-triggered provisioning. Attacker cost is trivial — a single unauthenticated HTTP POST with attacker-chosen JSON body; no GitHub secrets, sessions, or API tokens are required. This is fully repeatable and requires no privileged access, matching the "unprivileged attacker, unauthenticated POST /webhooks" threat model in the question.

### Recommendation
Enforce that the org used to select/verify the webhook signature is the same org that owns the repository referenced by `full_name` before dispatching to handlers — e.g., derive `repository_owner` from `full_name.split('/').first` (or cross-check it against `owner.login`) rather than trusting `owner.login` alone, and reject the request if the two diverge. Additionally, consider treating "no `webhook_secret` configured for an org" as a hard misconfiguration error (reject unsigned webhooks) rather than silently authenticating any payload (`return true unless webhook_secret` in `GitHubApp#verify_webhook_signature`).

### Proof of Concept
Under `test/controllers/webhooks_controller_test.rb` (existing suite mocks multi-org `Shipit.github`):
```ruby
test "pull_request opened forged via mismatched owner/full_name org with no webhook_secret creates ReviewStack for a different org's repo" do
  # Setup: configure two orgs in credentials.github:
  #   :attacker_org  -> no webhook_secret
  #   :victim_org    -> webhook_secret: "s3cr3t"
  # victim_org owns repository "victim-org/victim-repo" with review_stacks_enabled + allow_all provisioning

  payload = payload_parsed(:pull_request_opened)
  payload["repository"]["owner"]["login"] = "attacker_org"   # selects no-secret org for verification
  payload["repository"]["full_name"]      = "victim-org/victim-repo" # handler resolves THIS repo
  payload["action"] = "opened"

  assert_difference -> { Shipit::ReviewStack.count } do
    post "/webhooks",
      params: payload.to_json,
      headers: {
        "X-Github-Event" => "pull_request",
        "X-Hub-Signature" => "sha1=deadbeef", # garbage/forged, never validated for attacker_org
        "Content-Type" => "application/json"
      }
  end

  assert_response :ok
  stack = Shipit::Repository.from_github_repo_name("victim-org/victim-repo").review_stacks.last
  assert_equal "pr#{payload['number']}", stack.environment
  # Assert the binding equality is violated:
  # org_used_for_verification("attacker_org") != org_owning_mutated_repo("victim-org")
end
```
This demonstrates that the org authenticating the signature (`attacker_org`, no secret) is not equal to the org owning the mutated repository (`victim-org`), and the write still succeeds.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
