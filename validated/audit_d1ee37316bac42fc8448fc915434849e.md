### Title
Markdown body/comment content for `pr view`, `issue view`, and `discussion view` is never routed through the `Untrusted` sanitizer, allowing raw ANSI/OSC-8 escapes embedded in code fences to reach the terminal - (File: pkg/cmd/pr/view/view.go, pkg/cmd/issue/view/view.go, pkg/cmd/discussion/view/view.go, pkg/cmd/pr/shared/comments.go)

### Summary
`NewUntrustedBytes`/`Untrusted.String()` in `pkg/iostreams/untrusted.go` correctly neutralizes ANSI escape sequences, but this sanitizer is opt-in and is only invoked by a subset of callers (`gist view`, `skills preview`, `internal/skills/discovery.FetchBlob`). The `gh pr view`, `gh issue view`, `gh discussion view`, and PR comment-rendering code paths never wrap `pr.Body`/`issue.Body`/`d.Body`/`comment.Content()` in `iostreams.Untrusted`; they pass the raw attacker-controlled string straight into `markdown.Render` (glamour) and then `fmt.Fprintf` the rendered output directly to `opts.IO.Out`. Glamour does not strip literal control bytes from code-fence content, so any raw ANSI/OSC-8 escape sequence an attacker places inside a code block of an issue/PR body or comment survives rendering and is written unfiltered to the victim's terminal.

### Finding Description
The `Untrusted` sanitizer's protection depends entirely on callers choosing to construct an `Untrusted` value with `NewUntrusted`/`NewUntrustedBytes` and calling `.String()` before printing: [1](#0-0) 

That opt-in pattern is followed by `gist view` (`content := iostreams.NewUntrusted(gf.Content)` then `content.String()` before `markdown.Render`) and by `internal/skills/discovery.FetchBlob`, which explicitly returns `iostreams.NewUntrustedBytes(decoded)`: [2](#0-1) [3](#0-2) 

However, `gh pr view`'s human-readable body rendering takes `pr.Body` — a plain `string` field from the API response, never wrapped in `Untrusted` — feeds it directly into `markdown.Render`, and writes the resulting rendered markdown straight to `opts.IO.Out` with `fmt.Fprintf`: [4](#0-3) 

The same unsanitized pattern exists for `gh issue view`: [5](#0-4) 

for `gh discussion view`: [6](#0-5) 

and for PR/issue comment bodies rendered via `formatComment`: [7](#0-6) 

Glamour's job is to convert markdown to styled terminal output; it does not strip or escape literal control bytes embedded in code-fence content (code blocks are rendered close to verbatim so the user sees the exact code). Because these view paths bypass `Untrusted` entirely, there is no equivalent of the `asciisanitizer.Sanitizer` transform applied anywhere on this path — not before rendering, not after. An attacker who authors an issue/PR body, comment, or discussion body containing a fenced code block with raw ESC/OSC-8 bytes can have those bytes emitted unmodified to the victim's terminal the moment the victim runs `gh pr view`, `gh issue view`, `gh pr view --comments`, or `gh discussion view` in a TTY.

### Impact Explanation
This enables terminal escape sequence injection (ANSI/OSC-8) from fully untrusted, remotely-published content (a PR/issue body or comment) into a victim's terminal via a routine `gh pr view` invocation. Depending on the terminal emulator, this can be used for output/prompt spoofing (e.g., forging fake `gh` confirmation prompts, overwriting prior terminal lines, or crafting deceptive clickable hyperlinks via OSC-8 with a malicious target) that could trick a victim into an unintended destructive confirmation or visiting a malicious/credential-harvesting URL. This matches the "High - Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" impact class cited in the question.

### Likelihood Explanation
Fully feasible with only unprivileged capabilities: anyone can open an issue/PR or leave a comment on a public repository containing a markdown code fence with embedded escape bytes, and any maintainer/viewer who runs `gh pr view`, `gh issue view`, or `gh discussion view` against that content on a real TTY is affected. No token, admin, or MITM access is required, and the attack is fully repeatable.

### Recommendation
Route `pr.Body`, `issue.Body`, discussion `Body`, and comment `Content()` through `iostreams.Untrusted` (or sanitize the fully rendered markdown output) before it reaches `markdown.Render`/`fmt.Fprintf(out, ...)`, consistent with the pattern already used in `gist view` and `skills preview`. Concretely: wrap the body/comment string in `iostreams.NewUntrusted(...)` and call `.String()` either before calling `markdown.Render`, or — since glamour output can itself carry legitimate ANSI styling codes that must not be stripped — sanitize the raw markdown source before rendering (stripping non-whitespace C0/C1 control bytes and OSC/CSI sequences from the source) rather than the final glamour output, so genuine styling codes glamour emits are preserved but attacker-supplied escapes in the source text are neutralized.

```go
// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
```

```go
// FetchBlob retrieves the content of a blob by SHA. The blob is base64-encoded
// inside the JSON response and decoded here, so it is returned as
// iostreams.Untrusted and callers must choose sanitized display or raw
// round-tripping.
func FetchBlob(client *api.Client, host, owner, repo, sha string) (iostreams.Untrusted, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "blobs", sha)
	if err != nil {
		return iostreams.Untrusted{}, err
	}
	var resp struct {
		SHA      string `json:"sha"`
		Content  string `json:"content"`
		Encoding string `json:"encoding"`
	}
	if err := client.REST(host, "GET", apiPath.String(), nil, &resp); err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not fetch blob: %w", err)
	}

	if resp.Encoding != "base64" {
		return iostreams.Untrusted{}, fmt.Errorf("unexpected blob encoding: %s", resp.Encoding)
	}

	// GitHub API returns base64 with embedded newlines; use the StdEncoding
	// decoder via a reader to handle them transparently.
	decoded, err := io.ReadAll(base64.NewDecoder(base64.StdEncoding, strings.NewReader(resp.Content)))
	if err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not decode blob content: %w", err)
	}

	return iostreams.NewUntrustedBytes(decoded), nil
}
```
