### Title
Stale `transitionResultCache` After Reorg Corrupts ABv2 Node-State Writes — (`kaiax/valset/impl/transition.go`, `kaiax/valset/impl/execution.go`)

### Summary

`transitionResultCache` is keyed by block number (`uint64`) only. `RewindTo` does not purge it. After a reorg that replaces canonical block N at height H with block N', the cache still holds the `TransitionResult` for height H+1 computed from N's state root. When the next block at H+1 is processed on top of N', `writeTransitionToABv2` calls `getTransitionResult(H+1, …)`, gets the stale entry, and writes ABv2 node-state transitions derived from the orphaned block's state — not the new canonical chain's state.

### Finding Description

**Cache is keyed by number only:** [1](#0-0) 

**`getTransitionResult` returns on cache hit without any hash or root check:** [2](#0-1) 

**`postInsertBlockPermissionless` eagerly pre-populates the cache for height H+1 using the just-inserted block N's state root:** [3](#0-2) 

**`RewindTo` only trims the permissioned vote-block list; `transitionResultCache` is never touched:** [4](#0-3) 

**`writeTransitionToABv2` calls `getTransitionResult` and blindly uses whatever the cache returns:** [5](#0-4) 

**`InitializeState` (called during both block import and block production) drives the write:** [6](#0-5) 

The only place `transitionResultCache` is ever purged is `Start()`, which runs at node startup — not during reorgs: [7](#0-6) 

### Impact Explanation

`applyTransition` reads ABv2 state from `statedb` (the parent's state root) and uses the parent block's header to compute node-state transitions: [8](#0-7) 

After a reorg, N and N' have different state roots and different headers. The cached result for H+1 was computed from N's root/header. When H+1 is processed on top of N':

- **Block import path:** `InitializeState` writes stale ABv2 transitions into the in-progress statedb. The resulting state root diverges from the block's committed state root, so the node rejects a valid canonical block and falls off the canonical chain.
- **Block production path:** The proposer writes stale ABv2 transitions into the produced block. Nodes without the stale cache compute a different state root and reject the block, preventing the proposer from advancing the chain.

Either path produces **consensus divergence between honest nodes** depending on whether they experienced the reorg before or after the cache was populated.

### Likelihood Explanation

Reorgs are uncommon in Kaia's BFT consensus but are not impossible — they occur during network partitions, delayed block propagation, or when a node syncs a longer fork. `postInsertBlockPermissionless` always pre-populates the cache immediately after every block insert, so the stale entry is guaranteed to exist whenever a reorg follows a successful block insert. No attacker privilege is required; a natural network partition suffices.

### Recommendation

Key `transitionResultCache` by `(blockNumber, parentHash)` instead of `blockNumber` alone, **or** purge the cache in `RewindTo`:

```go
func (v *ValsetModule) RewindTo(block *types.Block) {
    trimValidatorVoteBlockNums(v.ChainKv, block.Header().Number.Uint64())
    v.validatorVoteBlockNumsCache = nil
    v.transitionResultCache.Purge() // add this
}
```

A keyed approach is preferable because it avoids a full purge on soft rewinds and preserves valid entries for side-chain queries.

### Proof of Concept

1. Enable the permissionless fork.
2. Insert canonical block N at height H. `postInsertBlockPermissionless` caches `transitionResult[H+1]` from N's state root.
3. Trigger a reorg: deliver a competing block N' at height H with a different state root (e.g., different validator performance data). `RewindTo(N')` is called — cache is **not** purged.
4. Attempt to import or produce block H+1 on top of N'. `InitializeState` → `writeTransitionToABv2` → `getTransitionResult(H+1, statedb_N')` returns the stale entry from step 2.
5. Assert: the ABv2 transitions written into the statedb are derived from N's state root, not N'. The resulting state root for H+1 diverges from what a node that never saw N would compute, demonstrating consensus divergence.
