### Title
Bad-debt write-down clamps `supply_index` at `SUPPLY_INDEX_FLOOR_RAW`, leaving wiped suppliers an unbacked residual claim that drains later deposits - (File: contracts/pool/src/interest.rs)

### Summary
The external report's class — a loss event that fails to update the liquidity/share ratio, leaving claims that later cause a deficit of funds during withdrawals — maps directly onto `interest::apply_bad_debt_to_supply_index`. When seized debt exceeds the loss the index can express, the write-down is clamped up to `RAY/1000` instead of fully zeroing supplier claims. The residual claim is unbacked, yet it remains withdrawable through the normal `withdraw` path and pays out real tokens once any fresh cash enters the market.

### Finding Description
`apply_bad_debt_to_supply_index` (contracts/pool/src/interest.rs:73-89) computes the surviving supply value, derives a `reduction_factor`, multiplies the `supply_index` by it, and then applies `new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))`. On a near-total or total wipeout the mathematically correct index is `0` (or below the floor), but the clamp forces it back up to `RAY/1000`. Every pre-existing scaled supply position therefore keeps a strictly positive value: `unscale_supply_floor(position) = position * RAY/1000 / RAY`, i.e. roughly 0.1% of the original deposit, despite the market having absorbed a loss that consumed 100% of supplier value.

The debt side is burned correctly in `seize::apply` (contracts/pool/src/ops/seize.rs:24-28), so the market ends with `borrowed = 0`, `cash = 0`, and a residual supplied claim. Nothing zeroes or escrows that claim. A later `supply` call credits `cash` and mints shares for the new depositor at the floored index. When the wiped supplier calls controller `withdraw`, `withdraw::accounting` resolves the gross amount via `resolve_withdrawal`, and `gate_and_debit` (contracts/pool/src/ops/withdraw.rs:111-119) only checks `require_reserves(net_transfer)` — the fresh cash covers the phantom claim — plus utilization and `require_supply_for_debt`, both of which pass because `borrowed = 0`. The wiped supplier is paid out of the new depositor's principal.

The codebase's own raw-cache tests demonstrate exactly this drain: `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` and `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` (contracts/pool/tests/interest.rs:372-495) show a wiped position paying out a fresh deposit in full, leaving `cash < fresh_claim`. The production withdraw path adds no guard that fixes this — it only checks reserves against current cash, which is precisely the broken check the tests flag.

### Impact Explanation
Theft of user funds. After a severe bad-debt event clamps `supply_index` to the floor, the first new deposit(s) into that market are immediately exfiltrable by any holder of pre-wipeout supply shares, via an ordinary unprivileged `withdraw`. The honest new depositor's claim becomes unbacked (`cash < unscale_supply_floor(their_shares)`), so they permanently lose funds. This is the same "deficit of funds during withdrawals" consequence as the source report: the loss was not fully distributed across existing LPs, so the share price does not reflect the loss, and the residual is paid out of unrelated later liquidity.

### Likelihood Explanation
Triggering requires a bad-debt event large enough that the correct post-write-down index falls below `RAY/1000` — i.e. bad debt ≥ ~99.9% of total supplied value (a near-total wipeout through `liquidate`/`clean_bad_debt` → `seize_positions`). That is an extreme but reachable condition via ordinary unprivileged entrypoints (borrow defaults, liquidations), and once reached the attack needs only a `withdraw` call. Because the residual scales with the pre-wipeout position, an attacker can amplify the payoff by holding a large supply position in a thin market before the wipeout. Rated Medium.

### Recommendation
Do not resurrect wiped claims via the index floor. When `capped == total_supplied_value`, either set `supply_index` to an explicit zeroed state and gate all subsequent share-value reads/withdrawals on it, or burn/flag the residual scaled positions (e.g. track a `wiped` market flag that forces `resolve_withdrawal` to zero for positions predating the wipe). Alternatively, apply the floor only to *new* share-minting math while paying wiped positions their true `0` value — e.g. record a per-market `pre_floor_supply` and exclude it from withdrawals. At minimum, `gate_and_debit` should reject withdrawals whose value derives solely from the floor clamp rather than from real remaining supply value.

### Proof of Concept
1. Attacker A supplies `S` into market `(hub, X)`; borrower B borrows nearly all of it.
2. B defaults. A liquidator calls `liquidate`/`clean_bad_debt`; `seize::apply` burns B's debt and calls `apply_bad_debt_to_supply_index` with `bad_debt ≥ total_supplied_value`. `reduction_factor` floors at 0, `new_supply_index` computes below `RAY/1000`, and the `max(SUPPLY_INDEX_FLOOR_RAW)` clamp restores it. A's scaled position now values at ~`S/1000` instead of `0`.
3. Victim C calls `supply(amount = S/1000)`; pool credits `cash` and mints C's shares at the floored index.
4. A calls `withdraw(amount = i128::MAX)` through the controller. `resolve_withdrawal` pays A's residual claim `S/1000`; `require_reserves` passes against C's deposit; `require_supply_for_debt` passes since `borrowed = 0`. A receives C's entire deposit.
5. C's `unscale_supply_floor` claim now exceeds `cash`; C cannot withdraw — permanent loss.

This mirrors contracts/pool/tests/interest.rs:431-495, which asserts the drained amount equals the fresh deposit and that `cash` cannot cover the honest claim.
