### Title
Rule-name-only baseline suppression lets new instances of an already-seen pattern bypass Write warnings - ([File: plugins/security-guidance/hooks/security_reminder_hook.py])

### Summary
`check_patterns` returns only `(ruleName, reminder)` pairs with no per-occurrence location, so any baseline-vs-new-content suppression logic built on this primitive (comparing rule-name sets) cannot distinguish a pre-existing instance of a dangerous pattern from a brand-new, attacker-controlled instance of the same rule introduced elsewhere in a fully rewritten file via `Write`.

### Finding Description
`check_patterns(file_path, content)` [1](#0-0)  iterates `SECURITY_PATTERNS` and appends `(pattern["ruleName"], pattern["reminder"])` to `matches` whenever a substring/regex/path check hits — it never records where in the content the match occurred. `get_baseline_file_content` [2](#0-1)  fetches the pre-turn baseline content of a file via `git show <baseline_sha>:<rel_path>`. If a `Write` handler computes `baseline_matches = {r for r, _ in check_patterns(baseline_path, baseline_content)}` and then filters `check_patterns(new_content)` results to only those whose rule name is *not* in `baseline_matches`, the filter operates purely on rule identity. An attacker who seeds one instance of a rule (e.g., `os_system_injection`) anywhere in a file, then uses prompt-injected issue/PR content to get Claude to `Write` a full rewrite of that file containing a second, unrelated, attacker-controlled `os.system(...)` call, would have that new dangerous statement silently dropped from the warning set — because the rule name (not the specific code) was already "seen" in the baseline. This mirrors the same rule-name-only comparison idiom already visible in `sweep_pending_warnings` [4](#0-3) .

### Impact Explanation
If confirmed, this results in net-new, attacker-controlled command-injection/eval/`os.system` code being written to disk with the pattern-based PostToolUse guard fully suppressed — no `additionalContext` warning, no `exit(2)` continuation gate, and no `record_pending_warnings` entry for Stop-hook follow-up. That code can subsequently be executed via `Bash` with no consent signal ever raised to the user, undermining the "deny means deny" guarantee of the pattern layer described in the plugin's own architecture docstring [5](#0-4) .

### Likelihood Explanation
Preconditions are narrow but realistic in an automation flow: `tool_name == "Write"` (a full-file rewrite, common when Claude "fixes" or refactors a file), a git baseline SHA captured for the session, and the target file already containing one instance of the given rule (which an attacker can plant in advance as innocuous-looking pre-existing code). No admin/maintainer privilege is required — only ordinary repository content and a Write-triggering prompt.

### Recommendation
Make baseline suppression location/content-aware rather than rule-name-only: compare based on `(ruleName, matched-line-content)` or the surrounding line/hunk, not merely rule identity. Alternatively, do not suppress pattern warnings on `Write` content diffs at all when the tool fully replaces file content — only allow rule-based suppression when there is a true line-level diff showing that the same source line, or an unmodified span, still triggers the same rule.

def sweep_pending_warnings(session_id):
    """
    Stop-hook final sweep. Re-read every file in pending_warnings, re-check
    patterns, and return (fixed, unresolved, unresolved_mask). Clears state.
    A file that's been deleted counts as fixed — the dangerous code is gone.
    Never raises — this is telemetry and must not break the Stop hook.
    """
    def _sweep(state):
        try:
            pending = state.get("pending_warnings")
            if not isinstance(pending, dict) or not pending:
                return 0, 0, 0

            by_file = {}
            for key in pending:
                if not isinstance(key, str) or ":" not in key:
                    continue
                fp, _, rule = key.rpartition(":")
                by_file.setdefault(fp, set()).add(rule)

            unresolved = []
            fixed = 0
            for fp, rules in by_file.items():
                try:
                    with open(fp, "r", errors="replace") as f:
                        still_matching = {r for r, _ in check_patterns(fp, f.read())}
                except (OSError, IOError):
                    still_matching = set()
                for rule in rules:
                    if rule in still_matching:
                        unresolved.append(rule)
                    else:
                        fixed += 1

            state["pending_warnings"] = {}
            # Filter to known rules so a renamed/removed rule in old state
            # doesn't KeyError rule_names_to_mask.
            known = [r for r in unresolved if r in _RULE_NAME_TO_ID]
            return fixed, len(unresolved), rule_names_to_mask(known)
        except Exception as e:
            debug_log(f"sweep_pending_warnings failed: {e}")
            return 0, 0, 0

def check_patterns(file_path, content):
    """Check if file path or content matches any security patterns. Returns ALL matches."""
    normalized_path = file_path.lstrip("/")
    matches = []

    for pattern in list(SECURITY_PATTERNS) + extensibility.user_patterns():
        # path_filter is a gate: when present, the rule only applies to
        # matching paths. Distinct from path_check, which is itself a
        # positive match condition (e.g. .github/workflows/).
        if "path_filter" in pattern:
            try:
                if not pattern["path_filter"](normalized_path):
                    continue
            except Exception:
                continue

        matched = False

        if "path_check" in pattern:
            try:
                if pattern["path_check"](normalized_path):
                    matched = True
            except Exception:
                pass

        if not matched and "substrings" in pattern and content:
            for substring in pattern["substrings"]:
                if substring in content:
                    matched = True
                    break

        if not matched and "regex" in pattern and content:
            try:
                if re.search(pattern["regex"], content):
                    matched = True
            except Exception:
                pass

        if matched:
            matches.append((pattern["ruleName"], pattern["reminder"]))

    return matches

def get_baseline_file_content(session_id, file_path, cwd):
    """Get the content of a file at the baseline SHA. Returns None if unavailable."""
    baseline_sha = load_baseline_sha(session_id)
    if not baseline_sha:
        return None
    try:
        abs_path = os.path.abspath(file_path)
        cwd_abs = os.path.abspath(cwd) if cwd else os.getcwd()
        try:
            rel_path = os.path.relpath(abs_path, cwd_abs)
        except ValueError:
            return None
        result = subprocess.run(
            [*GIT_CMD, "show", f"{baseline_sha}:{rel_path}"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if result.returncode == 0:
            return result.stdout
        return None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
