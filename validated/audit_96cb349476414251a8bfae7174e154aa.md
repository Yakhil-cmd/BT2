## Title
Uncaught exception via unvalidated `earned_headers_commission_recipients` field crashes node during unit validation - (File: `validation.js`, `object_length.js`)

### Summary
`validation.validate()` calls `objectLength.getHeadersSize(objUnit)` synchronously and unconditionally (no `try/catch`), unlike its sibling call to `getTotalPayloadSize()` a few lines later, which *is* wrapped in `try/catch`. `getHeadersSize()` serializes the entire unit header — including the attacker-controlled `earned_headers_commission_recipients` array — through `object_length.js`'s `getLength()`, which throws a plain `Error` for any non-finite `number` value (`Infinity`/`NaN`) or unexpected type encountered anywhere inside the object graph. Because `earned_headers_commission_recipients`'s internal structure is not validated before this call (only `hasFieldsExcept` on the top-level unit is checked, and `validateHeadersCommissionRecipients` runs later, inside the `async.series` after the header-size check), a single crafted field value can trigger this throw.

### Finding Description
In `validation.js`, `validate(objJoint, callbacks, external_conn)`: [1](#0-0) 

- Line 257 calls `objectLength.getHeadersSize(objUnit)` with no surrounding `try { } catch`.
- Line 259-266 calls `objectLength.getTotalPayloadSize(objUnit)` wrapped in `try/catch`, explicitly acknowledging that payload/header-size computation can throw and must be defended against.

`getHeadersSize()` deep-clones the unit and computes length over remaining header fields (including `earned_headers_commission_recipients`, which is *not* stripped): [2](#0-1) 

`getLength()`'s recursive `_getLength` throws `Error("invalid number: " + value)` for any non-finite number anywhere in the object graph, and similarly throws for objects with non-own properties, `undefined` values, or unrecognized types: [3](#0-2) 

At the point `getHeadersSize` is invoked (`validation.js:257`), the only check performed on `objUnit` so far is `hasFieldsExcept` (line 190), which only verifies the *top-level* field names are allowed — it does not validate the internal shape or numeric values inside `earned_headers_commission_recipients`. The dedicated structural/numeric validation for that field, `validateHeadersCommissionRecipients`, only runs later inside the `mutex.lock` → `async.series` pipeline (after `checkDuplicate`), i.e. strictly after the unguarded `getHeadersSize` call has already executed: [4](#0-3) 

Because `earned_headers_commission_recipients` is attacker-supplied (any element with a numeric sub-field set to `Infinity`, `NaN`, or a value of an unsupported JS type such as `undefined`/`function` inside the cloned object) reaches `getLength()` before it is ever type/range checked, the thrown `Error` is not caught anywhere in `validate()`'s synchronous body (the only local `try/catch` in `validate()` covers the unit-hash calculation at lines 131-138, not this call).

### Impact Explanation
`validation.validate()` is invoked synchronously from `network.js`'s `handleJoint()` for every unit posted by any peer or wallet client to a hub/full node — no privilege required beyond being able to send a joint. If the thrown `Error` is not intercepted by the caller (network.js wraps validation results via callbacks, but a *synchronous throw* from `validate()` itself, rather than a callback-based `ifUnitError`, bypasses that error-handling contract entirely) it becomes an uncaught exception. `network.js` explicitly registers a global handler that treats any uncaught exception as fatal and re-throws to crash the process: [5](#0-4) 

This matches the bug class in the reference CVE (a specially crafted message causing denial of service): an unprivileged unit poster can craft a unit with a malformed `earned_headers_commission_recipients` value and cause any node/hub that receives and validates it to crash, disrupting the ability of the network to confirm new units — a network-wide denial-of-service impact reachable purely through crafted unit content.

### Likelihood Explanation
The attack requires only the ability to compose and broadcast a syntactically valid unit with a crafted `earned_headers_commission_recipients` array — a capability available to any unprivileged unit poster. No cryptographic break, no privileged access, and no race condition are needed; the only open question (which I could not fully verify with the tools/iterations available) is whether `mutex.lock` in `mutex.js` invokes its callback synchronously or via `process.nextTick`/`setImmediate`, which determines whether the resulting exception surfaces as a same-tick throw inside `network.js`'s call to `validation.validate` or as a deferred uncaught exception caught by the `process.on('uncaughtException')` handler. Either path plausibly reaches the fatal, process-crashing branch, but I was not able to trace `mutex.js`'s exact scheduling semantics before running out of investigation budget.

### Recommendation
Wrap the `objectLength.getHeadersSize(objUnit)` call at `validation.js:257` in the same `try/catch` pattern already used for `getTotalPayloadSize`, converting any thrown error into `callbacks.ifJointError(...)`. Additionally, move structural/type validation of `earned_headers_commission_recipients` (and any other header field that flows into `getHeadersSize`) ahead of the `getHeadersSize`/`getLength` call, so malformed values are rejected via the normal validation-error callback path before reaching code that can throw synchronously.

### Proof of Concept
1. Craft a unit whose header includes `earned_headers_commission_recipients` set to a value containing a non-finite number in a nested field expected to be numeric (e.g., an element whose numeric field is serialized as `Infinity` — reachable since JSON itself cannot literally encode `Infinity`, but if the wire deserializer/any internal helper coerces a value to `NaN`/`Infinity` before this stage, e.g., via `parseFloat` on an oversized/malformed numeric string elsewhere in the unit that ends up embedded in this field), or more directly an object containing a key whose value is `undefined` after `_.cloneDeep`, triggering `getLength`'s `throw Error("undefined at " + key ...)` branch.
2. Post/broadcast this joint to a target hub/full node.
3. The node's call to `validation.validate()` executes `objectLength.getHeadersSize(objUnit)` unguarded; the thrown `Error` is not caught within `validate()`, propagates out of the synchronous call chain, and — depending on `mutex.lock`'s scheduling — either throws synchronously in `network.js`'s `handleJoint` or is caught by the global `uncaughtException` handler, which re-throws and crashes the process.

*(Note: I was unable to fully confirm within the available tool budget the precise value/type that gets past `hasFieldsExcept` while still causing `Infinity`/`undefined` to appear inside `earned_headers_commission_recipients` at the point `getHeadersSize` runs, nor `mutex.lock`'s exact synchronous/async callback semantics. These would need to be confirmed with direct code execution/testing in a full Devin session before treating this as a fully proven exploit.)*

function getLength(value, bWithKeys) {
	let cache = new WeakMap();  // object to length
	function _getLength(value) {
		if (value === null)
			return 0;
		switch (typeof value) {
			case "string":
				return value.length;
			case "number":
				if (!isFinite(value))
					throw Error("invalid number: " + value);
				return 8;
				//return value.toString().length;
			case "object":
				// return cached result if already processed
				if (cache.has(value))
					return cache.get(value);
				var len = 0;
				if (Array.isArray(value))
					value.forEach(function (element) {
						len += _getLength(element);
					});
				else
					for (var key in value) {
						if (!Object.prototype.hasOwnProperty.call(value, key))
							throw Error("object has non-own property " + key + " in " + JSON.stringify(value));
						if (typeof value[key] === "undefined")
							throw Error("undefined at " + key + " of " + JSON.stringify(value));
						if (bWithKeys)
							len += key.length;
						len += _getLength(value[key]);
					}
				cache.set(value, len);  // memoize for future references
				return len;
			case "boolean":
				return 1;
			default:
				throw Error("unknown type=" + (typeof value) + " of " + value);
		}
	}
	return _getLength(value);
}
