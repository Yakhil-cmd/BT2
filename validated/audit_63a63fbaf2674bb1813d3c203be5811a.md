### Title
Debt socialization skips interest accrual, causing an unfair loss write-down to be socialized onto vault depositors - (File: `mainnet/contracts/vault/v0-vault-stx.clar`)

### Summary
Every state-mutating vault entry point that changes `index`/`lindex`/`assets` (`deposit`, `redeem`, `system-borrow`, `system-repay`) calls `(try! (accrue))` as its first action, so pending interest since `last-update` is folded into the vault state before any other calculation runs. `socialize-debt` is the one exception: it computes `old-total-assets`, `debt-reduction`, and the new `lindex` write-down directly from the stale `index`/`lindex`/`assets` without ever calling `accrue()` first.

### Finding Description
`socialize-debt` reads `idx` and `current-lindex` straight from storage and computes: [1](#0-0) 

Compare this to every other mutating function, which begins with an explicit `accrue()` call before touching state: [2](#0-1) [3](#0-2) [4](#0-3) 

`accrue()` is what advances `index`, advances `lindex` from the interest actually earned since `last-update`, and mints the `treasury-lp` fee share to the DAO before any other accounting happens: [5](#0-4) 

Because `socialize-debt` never calls `accrue()`, `old-total-assets = total-assets()` is built from the *old* `index`, i.e. it omits the interest that has silently accrued between `last-update` and the block in which the liquidation/socialization transaction executes: [6](#0-5) 

The write-down ratio applied to `lindex` is `(old-total-assets - debt-reduction) / old-total-assets`: [7](#0-6) 

Since `old-total-assets` is understated (it is missing the yet-unaccrued interest that would otherwise have been folded into `lindex` and partially minted to the DAO treasury as `treasury-lp`), the ratio applied to `lindex` is more punishing than it should be, and the interest that accrued in that window is dropped entirely rather than being credited to depositors (via `lindex` growth) and to the DAO (via `treasury-lp` minting). This is the same bug class as the reported issue: a rate/index used to compute a value shared between two unprivileged parties (here, all vault LPs as a group, versus the liquidator whose liquidation transaction triggers the write-down) is stale/wrong at the moment it matters, so one side's entitlement (LPs' owed yield, DAO's owed fee) silently disappears while the other side's outcome (the liquidator's execution, and the harsher loss borne by remaining depositors) is computed on the wrong base.

This is a socialization mechanism, so its miscalculation is charged to *all* suppliers of that vault uniformly — an explicitly in-scope analog class ("a socialization charged to all suppliers").

### Impact Explanation
Whenever a liquidation results in bad debt and the elapsed time since the vault's last `accrue()` call is non-trivial, the interest that should have accrued to LPs (and the DAO's `fee-reserve` cut of it) between `last-update` and the socialization block is permanently lost: it is neither reflected in `lindex` growth nor minted as `treasury-lp`, and it is not available to offset the write-down ratio. This is a **permanent loss of unclaimed yield for vault depositors and the DAO treasury**, since the base (`old-total-assets`) used to size the loss write-down is smaller than the true economic total assets at that moment, making the resulting `lindex` cut steeper than it should be. This maps to the in-scope High impact bucket: theft/permanent freezing of unclaimed yield.

### Likelihood Explanation
This triggers on ordinary protocol operation — any liquidation that produces bad debt (`socialize-debt` call from `market.clar`) after a period without any deposit/redeem/borrow/repay activity (which are the only other things that call `accrue()`) will exhibit the missed-interest write-down. No privileged access or DAO compromise is required; it is a direct consequence of `socialize-debt` being the only mutating vault entrypoint missing the `accrue()` guard.

### Recommendation
Add `(try! (accrue))` as the first action of `socialize-debt` (mirroring `deposit`, `redeem`, `system-borrow`, and `system-repay`), so that all interest owed to LPs and the DAO treasury up to the current block is settled into `index`/`lindex`/`assets` before the bad-debt write-down ratio is computed against `total-assets()`.

### Proof of Concept
1. Vault has active borrowers; time passes without any `deposit`/`redeem`/`system-borrow`/`system-repay` call, so `last-update` stays stale while real utilization/interest accrues.
2. A borrower's position becomes liquidatable and ends up leaving bad debt. `market.clar`'s liquidation flow calls the vault's `socialize-debt(scaled-amount)`. [8](#0-7) 
3. Because `socialize-debt` does not call `accrue()`, `old-total-assets` is computed from the stale `index` via `total-assets()`/`total-debt()`, omitting the interest that has accrued since `last-update`.
4. `new-lindex` is derived from this understated `old-total-assets`, producing a steeper cut to `lindex` than warranted, and the omitted interest (and its DAO fee-reserve share) is never minted or credited — it disappears rather than being distributed to LPs/DAO before the loss is socialized.
5. All existing zToken holders of that vault redeem at the reduced `lindex`, permanently losing the yield that should have accrued in the missed window, on top of their proportional share of the actual bad debt.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
