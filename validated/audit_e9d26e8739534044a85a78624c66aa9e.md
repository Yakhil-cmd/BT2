### Title
Organization identity used for webhook signature verification is decoupled from the repository written by the handler - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp`/webhook secret to validate a signature using `repository_owner`, which is read from `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`). But the handler that actually performs the write — looking up the `Stack`/`Repository` to sync — uses a different field entirely: `payload.dig('repository', 'full_name')` in `Handler#repository_name`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
In the multi-organization configuration (`Shipit.github(organization:)`, documented in `docs/setup.md`), each GitHub App/org has its own `webhook_secret`. `verify_signature` derives which secret to check against solely from `repository.owner.login` (or `organization.login`) inside the JSON body: [4](#0-3) 

Signature verification (`verify_webhook_signature`) checks the HMAC over the entire raw POST body against the secret configured for that one organization: [5](#0-4) 

Because the whole raw body is signed, any field inside it — including `repository.full_name` — is technically "covered" by the signature. However, the two fields (`repository.owner.login` used to pick the *verifying* secret, and `repository.full_name` used to pick the *target* Stack in `PushHandler`/`Handler#stacks`) are independent, attacker-controlled JSON fields within a single payload that only needs to be valid JSON signed by whichever organization's secret the attacker possesses: [6](#0-5) 

An attacker who legitimately controls (or has been granted) one organization's GitHub App webhook secret (e.g., an org admin of Org B who can view/rotate it under Org B's App settings) can therefore craft an arbitrary payload with `repository.owner.login = "orgB"` but `repository.full_name = "orgA/private-repo"`, sign it with Org B's secret, and have it accepted by `verify_signature` (since Org B's secret does match). The equality the engine implicitly assumes — organization whose credential authenticated the request == organization whose repository is mutated — does not hold: `repository_owner` (used for auth) and `repository_name`/`full_name` (used for the write) are read from two unrelated leaves of the same untrusted JSON tree, with no cross-check that `repository.owner.login` matches the owner segment of `repository.full_name`.

### Impact Explanation
This lets a party who is entitled to trigger webhooks for one configured organization forge `push`, `status`, `check_suite`, `pull_request`, or `membership` events against a Stack belonging to a *different* organization mounted on the same Shipit instance. For `push`, this triggers `stack.sync_github(expected_head_sha:)`, causing Shipit to fetch and record commits/refs for a foreign repository using attacker-supplied `after` SHAs, and for `status`/`check_suite` it can inject fabricated CI status/check state for arbitrary commits in the victim stack, which can influence merge-queue and deploy gating logic. This crosses the "an organization authenticated versus the repository written" boundary and can enable unauthorized state changes on a different tenant's deploy pipeline — matching the escalation-into-authorization / unauthorized-deploy class of impact.

### Likelihood Explanation
Exploitability depends entirely on the deployment running the documented multi-organization configuration (`docs/setup.md`, "Using Multiple Github Applications") with more than one org's webhook secret configured, and on the attacker holding one legitimate (but not the target's) webhook secret — a precondition, not a privileged Shipit credential. I could not verify from the indexed code whether any additional cross-check exists elsewhere (e.g., in `Repository.from_github_repo_name` or `Stack.sync_github`) that ties the resolved repository back to the authenticating organization; none was found in `Handler`, `PushHandler`, or `WebhooksController`. Given the index size limits, I recommend a full session to confirm no such check exists in `app/models/shipit/repository.rb` or `Stack#sync_github` before treating this as fully confirmed.

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler`), after verifying the signature, assert that `repository.owner.login` (the org whose secret validated the request) matches the owner segment parsed from `repository.full_name` (and from `organization.login` for org-scoped events like `membership`) before dispatching to any handler that resolves a `Stack`/`Repository`. Reject the request (422) on mismatch.

### Proof of Concept
1. Configure Shipit with two organizations, `orgA` and `orgB`, each with its own `webhook_secret` (per `docs/setup.md`'s multi-org schema).
2. As a holder of `orgB`'s webhook secret, construct a `push` payload:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": { "owner": { "login": "orgB" }, "full_name": "orgA/private-repo" }
}
```
3. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(orgB_webhook_secret, raw_body)>` and POST to `/webhooks` with `X-Github-Event: push`.
4. `verify_signature` resolves `repository_owner` = `"orgB"`, fetches `Shipit.github(organization: "orgB")`, and the HMAC matches → request passes with 200. `PushHandler#process` then resolves stacks via `Repository.from_github_repo_name("orgA/private-repo")` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on Org A's stack, despite the request never being authenticated by Org A's secret.     def verify_signature
```ruby
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
