### Title
Missing zero-address validation on `creator` in `initialize_with_permission` permanently freezes creator fees - ([File: programs/cp-swap/src/instructions/initialize_with_permission.rs])

### Summary
`initialize_with_permission` accepts an arbitrary, unvalidated `creator` account and stores its key as `pool_creator` in `PoolState`. Unlike `setVibesFee`'s missing `vibeTreasury_ != address(0)` check, there is no check here that `creator` is non-default/meaningful, allowing the pool's creator-fee beneficiary to be set to an address nobody controls, permanently locking any accrued creator fees.

### Finding Description
In `InitializeWithPermission`, `creator` is declared as an `UncheckedAccount<'info>` with no `Signer` requirement and no constraint on its value: [1](#0-0) . The instruction handler passes this unchecked key straight into `pool_state.initialize(...)`, which stores it as `self.pool_creator`, and hard-codes `enable_creator_fee = true`: [2](#0-1) . `PoolState::initialize` unconditionally assigns `self.pool_creator = pool_creator.key()` with no validation: [3](#0-2) .

Because `creator` need not be a `Signer` and is not checked against `Pubkey::default()` (or any other unusable/burn address), a caller can set `pool_creator` to the system-program ID (the "zero pubkey") or any other key with no known private key.

This is directly reachable via `collect_creator_fee_permissionless`, which fetches creator fees for whatever address is recorded as `pool_creator` without requiring that address to sign: the `creator` account is only constrained by `address = pool_state.load()?.pool_creator` and is an `UncheckedAccount`, while `creator_token_0`/`creator_token_1` ATAs are created with `associated_token::authority = creator`: [4](#0-3) [5](#0-4) . Any unprivileged `payer` can invoke this instruction and push the accumulated `creator_fees_token_0/1` into an ATA owned by the zero/default address: [6](#0-5) . `collect_creator_fee` (the signer-gated variant) would also become permanently uncallable since no keypair can ever sign for the default pubkey: [7](#0-6) .

By contrast, `initialize` (the standard, non-permissioned entrypoint) is safe against this because its `creator` field is a `Signer<'info>` [8](#0-7) , so `pool_creator` can never be a keyless default address there — the bug is specific to `initialize_with_permission`.

### Impact Explanation
Creator fees accrued in the pool's token vaults (`creator_fees_token_0` / `creator_fees_token_1`) become permanently unrecoverable: they can be moved out of the vault into an associated token account whose authority is a key with no private key, and nothing in the codebase can ever move tokens out of that ATA again. This is a permanent freezing of LP/creator funds, satisfying the "concrete... permanent freezing of user or LP funds" bar in the validation criteria.

### Likelihood Explanation
Likelihood depends on how `Permission` PDAs (gating who may call `initialize_with_permission`) are granted — I was not able to fully verify the access-control model for obtaining a `Permission` account within the remaining investigation budget (file `programs/cp-swap/src/instructions/admin/create_permission_pda.rs` was located but not read in full). If permission to call `initialize_with_permission` is broadly obtainable (e.g., self-registerable) or if a legitimate permissioned pool creator simply passes the wrong/default `creator` account by mistake or malice, the freezing occurs unconditionally and requires no special privilege beyond calling this one instruction with attacker-chosen accounts, matching the report's DoS bug class.

### Recommendation
Add an explicit validation in `InitializeWithPermission` (and defensively in `PoolState::initialize`) that `creator.key() != Pubkey::default()`, mirroring the recommended `require(vibeTreasury_ != address(0))` pattern from the reference report, e.g.:
```rust
require_keys_neq!(ctx.accounts.creator.key(), Pubkey::default(), ErrorCode::InvalidInput);
```
placed before `pool_state.initialize(...)` is called.

### Proof of Concept
1. Obtain (or be granted) a `Permission` PDA for `payer`.
2. Call `initialize_with_permission` supplying the `creator` account as the System Program ID (`11111111111111111111111111111111111111111`, Solana's canonical zero/default pubkey) instead of a real keypair — this is accepted because `creator` is only an `UncheckedAccount`, not a `Signer` [1](#0-0) .
3. The pool initializes with `pool_creator = <default pubkey>` and `enable_creator_fee = true` [2](#0-1) .
4. Perform swaps that accrue `creator_fees_token_0/1` in `PoolState`.
5. Call `collect_creator_fee_permissionless` with `creator` set to the default pubkey; the instruction succeeds, creating an ATA owned by the default pubkey and transferring the fees into it [6](#0-5) .
6. No account can ever sign to move funds out of that ATA — the creator fees are permanently frozen.

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
```
