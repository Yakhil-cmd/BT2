### Title
Webhook signature is verified against a GitHub App keyed on `repository.owner.login`, but every handler resolves its target repository from the unvalidated `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` selects *which* GitHub App/organization secret to check the HMAC signature against using `repository_owner`, derived from `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`). [1](#0-0)  Once the signature check passes, every webhook `Handler` subclass independently resolves the repository/stack to act on from a *different* payload field, `repository.full_name`, via `Repository.from_github_repo_name(repository_name)`. [2](#0-1)  Nothing in the controller or `Handler` base class cross-checks that the organization used to select/verify the signing secret is the same organization that owns the repository the handler is about to mutate. This mirrors the reported bug class: a lookup/index (`_getIndex`) that is used without confirming the looked-up value actually corresponds to what is expected, so a value that should be treated as "not verified for this pool/org" is silently treated as valid.

### Finding Description
- `verify_signature` picks the app config via `Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(signature, raw_post)`, where `webhook_secret` is optional per the setup docs ("Webhook secret (optional)"). [3](#0-2)  If `webhook_secret` is blank for the organization resolved from `repository.owner.login`, `verify_webhook_signature` unconditionally returns `true`: [4](#0-3) 
- The multi-org configuration format documented in `docs/setup.md` explicitly allows each organization to have its own (optionally empty) `webhook_secret`. [5](#0-4) 
- After `verify_signature` passes, `Handler#stacks` looks up the target `Repository` using `payload.dig('repository', 'full_name')`, a field completely independent of the one used to pick the signing secret. [2](#0-1) 
- This same disjoint pattern is repeated in every pull-request handler (`ClosedHandler`, `OpenedHandler`, `EditedHandler`, `LabeledHandler`, etc.), each of which independently re-derives `repository` from `params.repository.full_name` to find or mutate a `Stack`/`ReviewStack`: [6](#0-5) [7](#0-6) 
- `PushHandler` also inherits `stacks` from `Handler` and drives a `GithubSyncJob`-equivalent sync using attacker-controlled `after`: [8](#0-7) 
- `ReviewStackAdapter#archive!` will call `stack.remove_from_provisioning_queue`, `stack.deprovision`, and `stack.archive!(user, ...)` on whatever `Stack` matches, without any org-ownership re-check: [9](#0-8) 

**Broken binding (equality that should hold but doesn't):**
`organization used to select/verify the webhook signature (repository.owner.login / organization.login)` == `organization that owns the repository the handler mutates (repository.full_name)`

Before an attacker's request: for genuine GitHub-originated webhooks, GitHub itself always keeps these two fields consistent, so the equality trivially holds and the missing check is latent.

After an attacker's request: since `/webhooks` is a public, unauthenticated Rails endpoint (`ActionController::Base`, `skip_before_action :verify_authenticity_token`) that only requires a valid `X-Hub-Signature` for *some* configured organization, an attacker who can produce a valid signature for **any** organization configured in `secrets.github` with a blank/absent `webhook_secret` (an option explicitly supported and documented) can submit a completely handcrafted JSON body. In that body they set `repository.owner.login` (or `organization.login`) to the secret-less organization to pass `verify_signature`, while setting `repository.full_name` to any **other** repository/stack hosted on the same Shipit instance (e.g., belonging to a fully protected organization with a real secret). The handler layer never re-validates that the two fields agree, so it acts on the victim organization's stack.

### Impact Explanation
This breaks the "organization authenticated versus repository written" trust boundary explicitly called out as in-scope. Concretely, with a single secret-less organization anywhere in the deployment's `secrets.github` map, an unprivileged external attacker (no Shipit session, no `ApiClient` token, no GitHub write access to the victim repo) can force actions on any other stack/review-stack tracked by the instance:
- Force `Stack#sync_github` on an arbitrary victim stack with an attacker-chosen `expected_head_sha`, feeding false "at head" state into deploy/rollback decisions. [8](#0-7) 
- Archive/unarchive/deprovision an arbitrary review stack belonging to a different, fully-secured organization via `PullRequest::ClosedHandler`/`LabeledHandler` + `ReviewStackAdapter#archive!`. [9](#0-8) 
- Rewrite stored `PullRequest` metadata for a victim stack via `EditedHandler#pull_request.update`. [10](#0-9) 

Since `Stack#sync_github` is the mechanism that feeds continuous-deployment scheduling (`Stack.schedule_continuous_delivery` deploys any stack with `continuous_deployment: true` once new commits are observed via sync), [11](#0-10)  forcing a sync with an attacker-chosen `expected_head_sha` on a stack the attacker doesn't otherwise control can influence which commit is deployed next, i.e. an unauthorized deploy trigger — a Critical-tier impact per the scope's own definition.

### Likelihood Explanation
The prerequisite (an organization with an empty `webhook_secret`) is directly enabled and documented by the engine itself ("Webhook secret (optional)"), so any multi-org deployment that leaves even one organization's secret blank — e.g., during setup/testing, or for an org that doesn't expect malicious traffic — exposes every other organization's stacks on the same instance. No GitHub App private key, `ApiClient` token, or Shipit session is required; the only requirement is knowledge/guessing of one organization's login string that lacks a secret, and the ability to POST directly to `/webhooks`.

### Recommendation
In `WebhooksController#verify_signature` and/or `Shipit::Webhooks::Handlers::Handler`, require that the organization resolved for signature verification match the owner of the repository the handler is about to act on before dispatching (e.g., compare `repository_owner` against `Repository.from_github_repo_name(repository_name).owner`, or scope `Shipit.github_organizations` lookups strictly and reject mismatches). Additionally, consider making `webhook_secret` mandatory (removing the `return true unless webhook_secret` bypass in `GitHubApp#verify_webhook_signature`) so a misconfigured/empty secret cannot silently authorize arbitrary payloads.

### Proof of Concept
1. Deploy Shipit configured for two organizations in `secrets.github`: `victim-org` (has a real `webhook_secret`, and owns a stack tracking `victim-org/app`) and `attacker-org` (deliberately left with no `webhook_secret`, per the documented optional setting).
2. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "full_name": "victim-org/app",
    "owner": { "login": "attacker-org" }
  }
}
```
No `X-Hub-Signature` header, or any arbitrary value, is required, since `Shipit.github(organization: "attacker-org")` resolves to a `GitHubApp` whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally.
3. `WebhooksController#create` dispatches to `PushHandler`, whose `stacks` method resolves `Repository.from_github_repo_name("victim-org/app")` — the victim's real repository — and calls `stack.sync_github(expected_head_sha: "deadbeef...")` on the victim's stack, despite the request having been "authenticated" only against `attacker-org`.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
