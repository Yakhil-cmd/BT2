Based on my research, the vulnerability described in the report is specific to the `SurplusGuildMinter` contract's flawed pattern of comparing a gauge's `lastGaugeLoss` against a freshly zero-initialized `UserStake` struct (rather than the stored value), causing a new staker to be immediately flagged as `slashed` if the gauge had any loss anywhere in its history.

I searched for an analogous pattern in Polkadot SDK's staking/slashing subsystems (`pallet-staking`, `pallet-staking-async`, `pallet-nomination-pools`, `pallet-delegated-staking`), since these are the closest FRAME equivalents to a "stake into a pool/gauge, get slashed based on historical events" model. The architecture differs fundamentally from the ECG bug pattern:

- Nomination pools slash the pool's bonded balance/points ratio directly, not via a per-user "last-loss-applied" timestamp compared against a zero-initialized struct [1](#0-0) .
- New joiners are explicitly protected from slashes that happened before they joined, verified both by dedicated tests (`apply_slash_fail`, `join_works`) and by pool-level `pending_slash` bookkeeping scoped to actual slash events applied via `on_slash` [2](#0-1) [3](#0-2) .
- `pallet-delegated-staking`'s `AgentLedger.pending_slash` is only accrued via `on_slash` callbacks tied to actual slash amounts, never inferred by comparing a user's stored state against a default/zero value [4](#0-3) .
- `pallet-staking`/`pallet-staking-async` ledger slashing (`StakingLedger::slash`) operates on era-bounded unlocking chunks and active balance directly, with no per-user "last applied" timestamp comparison against zero-initialized defaults [5](#0-4) .

None of these mechanisms rely on comparing a stored "last loss/slash" marker against an uninitialized/default value for a newly staking user, which is the exact root cause in the ECG report. No genuine, demonstrable analog of this bug class exists in the reachable FRAME staking/pooling code paths inspected.

	pub(crate) fn slash(
		&mut self,
		slash_amount: BalanceOf<T>,
		minimum_balance: BalanceOf<T>,
		offence_era: EraIndex,
	) -> BalanceOf<T> {
		if slash_amount.is_zero() {
			return Zero::zero();
		}

		use sp_runtime::PerThing as _;
		let mut remaining_slash = slash_amount;
		let pre_slash_total = self.total;

		// for an `offence_era = x`, any chunk that is scheduled to be unlocked at era `x + 28`
		// (assuming 28 is the bonding duration) onwards should be slashed.
		let slashable_chunks_start = offence_era.saturating_add(T::BondingDuration::get());

		// `Some(ratio)` if this is proportional, with `ratio`, `None` otherwise. In both cases, we
		// slash first the active chunk, and then `slash_chunks_priority`.
		let (maybe_proportional, slash_chunks_priority) = {
			if let Some(first_slashable_index) =
				self.unlocking.iter().position(|c| c.era >= slashable_chunks_start)
			{
				// If there exists a chunk who's after the first_slashable_start, then this is a
				// proportional slash, because we want to slash active and these chunks
				// proportionally.

				// The indices of the first chunk after the slash up through the most recent chunk.
				// (The most recent chunk is at greatest from this era)
				let affected_indices = first_slashable_index..self.unlocking.len();
				let unbonding_affected_balance =
					affected_indices.clone().fold(BalanceOf::<T>::zero(), |sum, i| {
						if let Some(chunk) = self.unlocking.get(i).defensive() {
							sum.saturating_add(chunk.value)
						} else {
							sum
						}
					});
				let affected_balance = self.active.saturating_add(unbonding_affected_balance);
				let ratio = Perquintill::from_rational_with_rounding(
					slash_amount,
					affected_balance,
					Rounding::Up,
				)
				.unwrap_or_else(|_| Perquintill::one());
				(
					Some(ratio),
					affected_indices.chain((0..first_slashable_index).rev()).collect::<Vec<_>>(),
				)
			} else {
				// We just slash from the last chunk to the most recent one, if need be.
				(None, (0..self.unlocking.len()).rev().collect::<Vec<_>>())
			}
		};
