### Title
ANSI/OSC escape sequence passthrough via attacker-controlled issue metadata (title, labels, milestone, linked-issue titles) - ([File: pkg/cmd/issue/view/view.go])

### Summary
`printHumanIssuePreview` writes several attacker-controlled fields — issue title, labels, milestone title, issue-type name, and linked issue/sub-issue titles — directly to `opts.IO.Out` via `fmt.Fprintf`/`fmt.Fprintln`, bypassing the codebase's established sanitizing writer (`opts.IO.ContentOut`). Unlike `pkg/cmd/gist/view/view.go` and `pkg/cmd/run/view/view.go`, which explicitly route untrusted remote content through `iostreams.NewUntrusted`/`ContentOut` (which wraps writes with an `asciisanitizer.Sanitizer` transform), this function uses the plain, non-sanitizing `Out` stream for these fields.

### Finding Description
`printHumanIssuePreview` ( [1](#0-0) ) sets `out := opts.IO.Out` and then prints `issue.Title` directly: [1](#0-0) 

Later it prints labels, milestone title, issue-type name, and linked issue titles the same way: [2](#0-1) 

These are plain Go `string` fields on `api.Issue` (title, labels, milestone, issue type, linked/sub-issue titles) populated straight from the GraphQL API response, not wrapped in the codebase's `iostreams.Untrusted` type, which is the mechanism used elsewhere to guarantee sanitization on print: [3](#0-2) 

The codebase's sanitization pattern is `opts.IO.ContentOut`, a writer that wraps `Out` with an `asciisanitizer.Sanitizer` transform when content sanitization is enabled: [4](#0-3) 

This pattern is applied consistently by `gist view` (via `iostreams.NewUntrusted`) and by `pr diff`/`repo read-file` (via `ContentOut`/`CopyGuardedContent`/`ContainsEscapeSequence`) for remote text: [5](#0-4) [6](#0-5) 

`printHumanIssuePreview`, however, never routes the title/labels/milestone/linked-issue-title fields through `ContentOut` or `Untrusted` — it uses `opts.IO.Out` directly, so any C0/C1 control bytes or ANSI/OSC/DCS sequences embedded in an issue title, label name, milestone title, issue type name, or a linked/sub-issue title are written to the terminal unmodified.

Note: the issue *body* is passed through `markdown.Render` (glamour) at line 306, and comments through `prShared.CommentList`; whether those specific paths sanitize escape sequences could not be confirmed from the available index, but the title/labels/milestone/linked-issue-title fields are demonstrably unsanitized based on the code shown.

### Impact Explanation
An attacker who authors an issue/PR (title, label name — if creatable by the attacker, milestone title, or a linked issue title they control in a fork) can embed OSC 52 (clipboard write), OSC 7 (working-directory/title spoof), or DCS sequences. When a victim runs `gh issue view <n>` on a TTY, `printHumanIssuePreview` is invoked and these bytes reach the terminal raw, potentially spoofing terminal prompts/titles or writing to the clipboard — matching the "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" bounty class.

### Likelihood Explanation
Feasible and repeatable: creating an issue/PR with a malicious title, or creating a milestone/label with an embedded ANSI/OSC payload, requires only ordinary write access to a repository the attacker controls (their own repo/fork), and the victim simply runs `gh issue view` against it on an interactive terminal. No special privileges beyond normal unauthenticated/low-privileged GitHub usage are needed.

### Recommendation
Wrap all remotely-sourced string fields printed in `printHumanIssuePreview` (title, author display name, labels, milestone title, issue type name, parent/sub-issue/blocked-by/blocking titles) in `iostreams.NewUntrusted(...)` before formatting, or route the writer through `opts.IO.ContentOut` for these fields, consistent with the pattern already used in `gist view` and `pr diff`. Apply the same treatment to any comment/body rendering paths not already covered by `markdown.Render`'s own sanitization.

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}

// SetContentSanitization toggles ANSI escape sanitization on ContentOut.
// Commands should call this with false when an explicit opt-out flag (e.g.
// --allow-escape-sequences) is set, so subsequent writes of external content
// pass through unmodified.
func (s *IOStreams) SetContentSanitization(enabled bool) {
	s.sanitizeContent = enabled
	s.ContentOut = newContentWriter(s.Out, enabled)
}

// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})
}
