### Title
Terminal escape-sequence passthrough via unsanitized repository entry names - (File: pkg/cmd/repo/read-dir/read_dir.go)

### Summary
`writeTSV` in `pkg/cmd/repo/read-dir/read_dir.go` writes the `Type`, `Name`, `modeOctal()`, and `Size` of each directory entry directly to `io.Out` with no sanitization of the `Name` field, which originates from the GraphQL `Tree.Entries[].Name` value returned by the target repository. `writeTable` has the same issue for TTY output. Because git tree entry names are attacker-controlled (any repository owner/collaborator can create a file/blob with an arbitrary UTF-8 name, including valid UTF-8 sequences containing ESC `0x1B`), a malicious repository can embed ANSI/OSC/DCS escape sequences in a file name that is faithfully reproduced in `gh repo read-dir` output.

### Finding Description
- `fetchTree` in `pkg/cmd/repo/read-dir/http.go` populates `dirEntry.Name` directly from the GraphQL response field `Name` with no filtering: [1](#0-0) .
- `writeTSV` then formats and writes this value straight to `io.Out` for non-TTY consumers: [2](#0-1) .
- `writeTable` similarly passes `e.Name` unmodified into the table printer for TTY rendering: [3](#0-2) .
- No call to any ANSI/OSC-stripping helper was found in this package, and no wrapping writer in `pkg/iostreams` was found to sanitize control sequences from arbitrary text written via `IOStreams.Out`/`ErrOut` in this code path.
- Git tree entry names can contain arbitrary bytes; GitHub's GraphQL `name` field decodes them as UTF-8 (invalid byte sequences are replaced, but valid UTF-8 control characters such as `ESC` (`0x1B`) pass through unchanged). This lets an attacker create a blob/tree entry whose name is, e.g., `\x1b]52;c;<base64-payload>\x07innocuous.txt` (OSC 52 clipboard write) or an OSC 7/DCS sequence for prompt/path spoofing.
- When a victim runs `gh repo read-dir` (either piping output, e.g. in a script, or interactively) against the attacker's repository/fork/PR branch, the escape sequence is written verbatim to the victim's terminal, which will interpret it according to the terminal emulator's OSC/DCS handling.

### Impact Explanation
This enables terminal escape-sequence injection: a remote, unprivileged attacker (repository owner or a PR/fork author whose tree the victim inspects) can inject OSC 52 (clipboard write/read on supporting terminals), OSC 7 (fake CWD reporting used for prompt spoofing), or other control sequences into the victim's terminal via a crafted file name in their repository. This matches the "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" impact class, since a spoofed prompt or clipboard write could trick a victim into copying/pasting attacker-controlled text or misinterpreting subsequent output (including possibly influencing manual "y/N" confirmations later in the terminal session, depending on terminal/shell integration features).

### Likelihood Explanation
Feasibility is high and requires no special privileges: an attacker only needs to publish a public repository (or push a branch/PR to a repo the victim will inspect) containing a file whose name includes escape bytes; git and GitHub's tree API do not restrict which UTF-8 bytes are legal in a file name. The victim need only run the ordinary `gh repo read-dir <path> --repo <attacker-repo>` command, which is exactly the documented use case for exploring an untrusted repository without cloning it, making exploitation realistic and repeatable.

### Recommendation
Sanitize `dirEntry.Name` (and any other server-supplied text fields rendered to the terminal, e.g. `Path`) before writing to `io.Out`/`io.ErrOut` in both `writeTSV` and `writeTable`: strip or escape C0/C1 control characters and ANSI/OSC/DCS sequences (e.g., via a shared `text.SanitizeControlSequences` helper) prior to formatting, while leaving `NameRaw`/`PathRaw` (used for JSON export) untouched for programmatic consumers.

### Proof of Concept
```go
func TestWriteTSV_StripsEscapeSequences(t *testing.T) {
    ios, _, out, _ := iostreams.Test()
    dir := &repoDir{
        Entries: []dirEntry{
            {
                Type: "file",
                Name: "\x1b]52;c;ZXZpbA==\x07innocuous.txt", // OSC 52 clipboard write payload
                Mode: 0o100644,
                Size: 10,
            },
        },
    }
    err := writeTSV(ios, dir)
    require.NoError(t, err)
    // Golden assertion: raw escape byte must not reach the writer.
    require.NotContains(t, out.String(), "\x1b]52;")
}
```
Expected (current) result: the assertion fails, since `writeTSV` writes `e.Name` unmodified, including the `\x1b]52;...\x07` sequence, confirming the passthrough.

func writeTSV(io *iostreams.IOStreams, dir *repoDir) error {
	var sb strings.Builder

	_, err := io.Out.Write([]byte(sb.String()))
	return err
}
