### Title
Unbounded GraphQL pagination loop in `preloadIssueComments` allows a malicious API host to cause client-side memory/CPU exhaustion (DoS) - ([File: pkg/cmd/issue/view/http.go])

### Summary
`preloadIssueComments` pages through `CommentsForIssue` results with a `for {}` loop that only terminates when the server reports `PageInfo.HasNextPage == false`. A malicious or attacker-controlled GraphQL endpoint (e.g. a custom `GH_HOST`) can return `HasNextPage=true` with a fresh `EndCursor` and non-empty `comments.Nodes` on every response, causing the loop to run forever while unboundedly appending to `issue.Comments.Nodes` in memory.

### Finding Description
The loop at [1](#0-0)  has no bound on iteration count, elapsed time, or total nodes fetched. Termination is entirely controlled by the remote server's response: `comments.PageInfo.HasNextPage` and `comments.PageInfo.EndCursor` are read directly from the GraphQL response and fed back as the next query's `endCursor` variable with no server/host validation beyond `repo.RepoHost()` being reached at all. `gh issue view <n> --comments` calls this via `viewRun`, so any user who configures `gh` to talk to a malicious host (via `GH_HOST` or `--repo` pointing at an alternate host with `gh config set` / enterprise host setup) — or whose configured host is compromised/spoofed at the application layer — controls every field of the response used to decide loop continuation. There is no cap analogous to a max-page or max-item limit, and no timeout/context cancellation on the loop, so the client will keep issuing requests and accumulating comment nodes in `issue.Comments.Nodes` indefinitely, growing unbounded memory and eventually causing an OOM crash or effectively hanging the `gh` process (self-inflicted resource exhaustion, not remote code execution or credential leakage). The identical unbounded pattern also exists in `preloadClosedByPullRequestsReferences` in the same file at [2](#0-1) .

### Impact Explanation
This is a client-side denial-of-service: `gh issue view --comments` against a malicious/compromised host can hang indefinitely and exhaust memory, degrading availability of the CLI process on the victim's machine. It does not lead to code execution, credential exfiltration, file write, or authorization bypass, so it falls into a low-severity availability/DoS class rather than a high-impact GitHub bounty category.

### Likelihood Explanation
Exploitation requires the victim to actually be interacting with an attacker-controlled or compromised host (e.g. custom `GH_HOST`/enterprise host under attacker's control) — this is an explicit precondition already called out in the question and permitted by the rules. Given that precondition, the exploit is deterministic and trivially repeatable: the malicious server just always returns `hasNextPage: true` with a new cursor and some payload nodes.

### Recommendation
Bound the pagination loop with a maximum iteration/page count (or maximum total nodes) and/or a context with a timeout, aborting and surfacing an error if exceeded, rather than trusting the server's `HasNextPage`/`EndCursor` indefinitely. Apply the same fix to `preloadClosedByPullRequestsReferences`.

### Proof of Concept
Using `httpmock.Registry`, register a `CommentsForIssue` GraphQL responder that always returns `data.node.issue.comments.pageInfo.hasNextPage = true` with a monotonically-changing `endCursor` and a small `nodes` array. Call `preloadIssueComments` with an `api.Issue` whose `Comments.PageInfo.HasNextPage = true`, and assert that after N (e.g. 100,000) iterations the function has not returned — demonstrating the loop never terminates and `issue.Comments.Nodes` grows unbounded (test should be run with a hard iteration/time budget and expected-to-fail-to-terminate assertion, e.g. via `context` deadline or goroutine + `select` timeout wrapping the call).

	for {
		var query response
		err := gql.Query(repo.RepoHost(), "CommentsForIssue", &query, variables)
		if err != nil {
			return err
		}

		comments := query.Node.Issue.Comments
		if comments == nil {
			comments = query.Node.PullRequest.Comments
		}

		issue.Comments.Nodes = append(issue.Comments.Nodes, comments.Nodes...)
		if !comments.PageInfo.HasNextPage {
			break
		}
		variables["endCursor"] = githubv4.String(comments.PageInfo.EndCursor)
	}
