## Title
`pull_request` webhook signature is verified against `repository.owner.login`'s GitHub org config while the affected repository/stack is selected by the independent `repository.full_name` field, allowing an attacker who controls a no-secret org to forge PRs against any victim review-stack - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` used to authenticate the webhook solely from `params.dig('repository','owner','login')`, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org's configured `webhook_secret` is blank. Because the handlers (e.g. `OpenedHandler`, `LabelCapturingHandler`) resolve the actual `Shipit::Repository`/stack from the completely independent `params.repository.full_name` field of the same forged JSON body, an attacker can pick a configured-but-secretless org for `owner.login` to pass verification while pointing `full_name` at any victim repository, including one with `review_stacks_enabled: true` and `allow_all`.

### Finding Description
The broken binding, stated as an equality that should hold but doesn't:

`organization_that_authenticated_request (params.repository.owner.login)` MUST equal `organization_that_owns_the_affected_repository (Repository.from_github_repo_name(params.repository.full_name).owner)`.

Trace:
1. `Shipit::WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository','owner','login')` [1](#0-0)  and uses it to fetch `Shipit.github(organization: repository_owner)` [2](#0-1) .
2. `GitHubApp#verify_webhook_signature` short-circuits `return true unless webhook_secret` [3](#0-2) , so any org configured in `secrets.github` without a `webhook_secret` accepts an unsigned/forged payload.
3. `Shipit.github(organization:)` only requires the organization key to exist in `secrets.github` (raising `GithubOrganizationUnknown` otherwise) [4](#0-3)  - it never checks the org against the repository actually referenced in the payload.
4. The handler then processes the same JSON body but derives the target repository from a *different* field: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` in `OpenedHandler#repository` [5](#0-4)  and identically in `LabelCapturingHandler#repository` [6](#0-5) . `Repository.from_github_repo_name` simply splits the string on `/` and does a DB lookup, with no cross-check against `owner.login` [7](#0-6) .

Exploit: attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature`, and body:
```json
{
  "action": "opened",
  "repository": { "owner": { "login": "attacker-controlled-no-secret-org" }, "full_name": "victim-org/victim-repo" },
  "pull_request": { ... "labels": [{"name": "..."}] ... },
  "sender": { "login": "attacker" }
}
```
`repository.owner.login` selects the no-secret org's `GitHubApp`, so `verify_webhook_signature` returns `true` with no HMAC. `full_name` selects the real `victim-org/victim-repo` `Repository`. If that repository has `review_stacks_enabled: true` and `provisioning_behavior: allow_all`, `OpenedHandler#process` calls `ReviewStackAdapter#find_or_create!`, auto-provisioning a new `ReviewStack` on the attacker's chosen branch/PR, which later executes `shipit.yml` from the (attacker-controlled fork) branch, and `LabelCapturingHandler` persists `params.pull_request.labels.map(&:name)` onto the stack's `PullRequest`, feeding attacker-chosen strings into `ReviewStack#env` as uppercased environment keys.

Existing guards fail because: `verify_signature`'s only check is on `repository_owner`, never on `full_name`; `ExplicitParameters` schema only validates types/presence, not that `owner.login` matches the owner half of `full_name`; and `Repository.from_github_repo_name` performs no authentication/ownership check, it's a pure DB lookup.

### Impact Explanation
An unauthenticated, unprivileged attacker can force Shipit to treat an arbitrary forged `pull_request` payload as authentic for **any** repository configured in Shipit, as long as *any one* configured GitHub organization in the deployment lacks a `webhook_secret`. This lets the attacker: auto-provision review stacks for a victim repository (`OpenedHandler`), inject arbitrary label names as environment variables via `LabelCapturingHandler`/`ReviewStack#env`, and drive downstream execution of the victim repo's `shipit.yml` on stack provisioning - a payload targeting one repository (the no-secret org) mutating another repository's stack. This matches the Critical class ("a payload for one repository mutating another's stack" / RCE via provisioning execution).

### Likelihood Explanation
Preconditions: (1) Shipit must be configured with at least one GitHub organization that has no `webhook_secret` set (multi-org config, `secrets.github[org]` without `webhook_secret`) - this is an operator misconfiguration, not something the attacker controls; (2) the victim repository must have `review_stacks_enabled: true` and `provisioning_behavior: allow_all` (or matching label rules) to auto-provision. Given those two preconditions, the attack is trivial and free: a single unauthenticated HTTP POST, repeatable against any repository/organization known to the attacker, regardless of which org's secretless config is (ab)used for verification. The severity is gated entirely on the "no-secret organization" misconfiguration; if every configured org has a proper `webhook_secret`, `verify_webhook_signature` requires a valid HMAC and the attack fails.

### Recommendation
Bind the authenticated organization to the repository actually acted upon: after `verify_signature` succeeds, re-derive `repository_owner` from `params.repository.full_name`'s owner segment (or require `params.repository.owner.login` to equal the owner parsed from `full_name`) and reject the request (`head 422`) on mismatch. Additionally, do not allow `verify_webhook_signature` to return `true` for organizations lacking a `webhook_secret` in production; require every configured GitHub org to have a `webhook_secret`, or fail closed (deny) instead of failing open when it's blank.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "pull_request forged via no-secret organization can target a different, victim repository's review stack" do
  # Setup: two orgs configured — "no-secret-org" (no webhook_secret) and the victim's real org
  Rails.application.credentials.github["no-secret-org"] = { app_id: 1, installation_id: 1, private_key: "..." } # no webhook_secret key
  victim_repo = shipit_repositories(:shipit) # owner "shopify", name "shipit-engine" in fixtures
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :allow_all)

  payload = payload_parsed(:pull_request_opened)
  payload["repository"]["owner"]["login"] = "no-secret-org"          # binding LHS: used for signature verification
  payload["repository"]["full_name"]      = victim_repo.github_repo_name # binding RHS: used to select the affected stack

  assert_difference -> { Shipit::Stack.where(type: "Shipit::ReviewStack").count }, 1 do
    post shipit.webhooks_url,
      params: payload.to_json,
      headers: { "X-Github-Event" => "pull_request", "Content-Type" => "application/json" } # no X-Hub-Signature
  end

  assert_response :ok
  # Both sides of the equality diverge: attacker authenticated as "no-secret-org" but mutated "shopify/shipit-engine"
  created_stack = victim_repo.review_stacks.last
  assert_not_nil created_stack, "victim repository's review stack was created/mutated by a request that never authenticated against it"
end
```
This demonstrates the divergence: `params.repository.owner.login` ("no-secret-org", used by `verify_signature`) ≠ owner of `params.repository.full_name` ("shopify", used by `Repository.from_github_repo_name` to pick the mutated stack), and the request is nonetheless accepted and acted upon.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
