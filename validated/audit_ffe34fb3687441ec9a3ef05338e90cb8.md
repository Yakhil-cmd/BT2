I've identified a strong analog to the NFTX bug class in `gh release verify` / `gh release verify-asset`.

### Title
`FilterAttestationsByTag`/`FilterAttestationsByFileDigest` abort the entire release-verification scan on one malformed attestation, allowing a single attacker-published attestation to hide a valid one - ([File: pkg/cmd/release/shared/attestation.go])

### Summary
`gh release verify` and `gh release verify-asset` fetch *all* attestations attached to a release's tag SHA from the GitHub API (via `config.AttClient.GetByDigest`, limit 100) and then loop over them in `FilterAttestationsByTag`/`FilterAttestationsByFileDigest` to find the one that matches the tag/asset digest. Just like the NFTX `distribute` loop that reverts entirely when one `feeReceiver` returns malformed data, these filter functions abort the *whole* filtering pass and return an error the instant a single attestation's DSSE payload fails to unmarshal, discarding every attestation already collected — including a legitimate, correctly signed one.

### Finding Description [1](#0-0)  and [2](#0-1)  iterate over the `attestations` slice and, for each entry, run `protojson.Unmarshal([]byte(statement), &statementData)` on `att.Bundle.Bundle.GetDsseEnvelope().Payload`. If any single entry's payload is not valid protojson (e.g., truncated, malformed, or intentionally garbled JSON in the `dsseEnvelope.payload` field of a Sigstore bundle), the function immediately `return`s the error, discarding `filtered` entirely — even though other, legitimate attestations were already successfully parsed and appended.

These attestations are not privileged, admin-only, or self-authored data: they come from `GetByDigest`, a call to the public GitHub attestations API scoped by digest for a specific `owner/repo`, as shown in the callers [3](#0-2)  and [4](#0-3) . Any actor able to attach/publish an attestation associated with that digest (e.g., anyone with write access to attestations for a public repo, or an attacker who can get a malformed attestation indexed against the same subject digest) can inject one bad entry into the returned set. Because the API is queried by digest, not solely by a single verified provenance chain, an attacker-controlled attestation entry reaching this digest is the "single poorly implemented feeReceiver" analog.

### Impact Explanation
The impact mirrors the NFTX finding directly: a single malformed/attacker-crafted attestation entry causes the entire batch operation to fail, denying legitimate users (`gh release verify`, `gh release verify-asset`) the ability to see or use valid, trustworthy attestations that were already present in the same response. This is a availability/DoS-style bug in the trust-verification pipeline — the command that is supposed to establish supply-chain trust for a release can be made to always fail (`error parsing attestations for tag ...`) as long as the attacker can get one bad record associated with the queried digest, even though a good attestation is also present.

### Likelihood Explanation
Reaching this code path requires only running `gh release verify [tag]` or `gh release verify-asset [tag] <file>` against a repository whose attestations are attacker-influenceable (public repos where attestation records for a digest are fetched broadly by digest, not restricted to a single trusted source per call). No special privileges, MITM, or local access are needed — this executes during the normal remote-attacker-reachable flow of fetching content from GitHub's API by digest.

### Recommendation
Change `FilterAttestationsByTag` and `FilterAttestationsByFileDigest` to skip (continue) on individual unmarshal failures rather than aborting the whole loop, consistent with how `FilterAttestations` in `pkg/cmd/attestation/api/attestation.go` already handles malformed entries defensively: [5](#0-4) 
That function explicitly comments "Don't fail just because a single entry can't be unmarshalled" and uses `continue` instead of returning an error — the two functions in `pkg/cmd/release/shared/attestation.go` should adopt the same pattern so one bad attestation cannot mask/deny the presence of an otherwise-valid one.

### Proof of Concept
1. Have `gh release verify v1.2.3` (or `verify-asset`) call `config.AttClient.GetByDigest(...)`, which returns two attestations for the same digest: one well-formed, valid attestation for the tag, and one with a `dsseEnvelope.payload` that is not valid protojson (e.g. base64 of `"{not json"`).
2. `FilterAttestationsByTag` iterates the slice; on the malformed entry `protojson.Unmarshal` returns an error, and the function immediately returns `nil, err` — discarding the previously appended valid attestation.
3. `verifyRun` surfaces this as `error parsing attestations for tag v1.2.3: failed to unmarshal statement: ...`, and the command fails entirely, even though a valid attestation for that release exists in the very same API response.

func FilterAttestationsByTag(attestations []*api.Attestation, tagName string) ([]*api.Attestation, error) {
	var filtered []*api.Attestation
	for _, att := range attestations {
		statement := att.Bundle.Bundle.GetDsseEnvelope().Payload
		var statementData v1.Statement
		err := protojson.Unmarshal([]byte(statement), &statementData)
		if err != nil {
			return nil, fmt.Errorf("failed to unmarshal statement: %w", err)
		}
		tagValue := statementData.Predicate.GetFields()["tag"].GetStringValue()

		if tagValue == tagName {
			filtered = append(filtered, att)
		}
	}
	return filtered, nil
}

func FilterAttestationsByFileDigest(attestations []*api.Attestation, fileDigest string) ([]*api.Attestation, error) {
	var filtered []*api.Attestation
	for _, att := range attestations {
		statement := att.Bundle.Bundle.GetDsseEnvelope().Payload
		var statementData v1.Statement
		err := protojson.Unmarshal([]byte(statement), &statementData)

		if err != nil {
			return nil, fmt.Errorf("failed to unmarshal statement: %w", err)
		}
		subjects := statementData.Subject
		for _, subject := range subjects {
			digestMap := subject.GetDigest()
			alg := "sha256"

			digest := digestMap[alg]
			if digest == fileDigest {
				filtered = append(filtered, att)
			}
		}

	}
	return filtered, nil
}

func FilterAttestations(predicateType string, attestations []*Attestation) ([]*Attestation, error) {
	filteredAttestations := []*Attestation{}

	for _, each := range attestations {
		dsseEnvelope := each.Bundle.GetDsseEnvelope()
		if dsseEnvelope != nil {
			if dsseEnvelope.PayloadType != "application/vnd.in-toto+json" {
				// Don't fail just because an entry isn't intoto
				continue
			}
			var intotoStatement IntotoStatement
			if err := json.Unmarshal([]byte(dsseEnvelope.Payload), &intotoStatement); err != nil {
				// Don't fail just because a single entry can't be unmarshalled
				continue
			}
			if intotoStatement.PredicateType == predicateType {
				filteredAttestations = append(filteredAttestations, each)
			}
		}
	}
