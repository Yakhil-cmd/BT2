### Title
Ralph-loop Stop hook activation relies solely on file existence, allowing a checked-in repo to spoof a `/ralph-loop` session and hijack session exit - ([File: plugins/ralph-wiggum/hooks/stop-hook.sh])

### Summary
The Stop hook's only activation check is `[[ -f "$RALPH_STATE_FILE" ]]` on `.claude/ralph-loop.local.md`, with no binding to an actual `/ralph-loop` invocation, session ID, or any provenance marker. A repository that ships this file pre-populated can cause the hook to block session exit and feed attacker-chosen `PROMPT_TEXT` back into the conversation as soon as a Stop event fires, without the victim ever running `/ralph-loop`.

### Finding Description
`plugins/ralph-wiggum/hooks/hooks.json` registers `stop-hook.sh` for the `Stop` event [1](#0-0) . The script's sole gate is file presence: `RALPH_STATE_FILE=".claude/ralph-loop.local.md"` followed by `if [[ ! -f "$RALPH_STATE_FILE" ]]; then exit 0; fi` [2](#0-1) . There is no cryptographic nonce, session token, or timestamp binding the file to a `/ralph-loop` command actually executed in the current session — the normal flow is that `/ralph-loop.md` runs `setup-ralph-loop.sh` to create this file [3](#0-2) , but the hook cannot distinguish a file created that way from one simply checked into the repository. If present, the hook parses frontmatter (`iteration`, `max_iterations`, `completion_promise`) and, absent a matching completion promise or exhausted iteration count, emits `{"decision":"block","reason": $PROMPT_TEXT, ...}` [4](#0-3) , where `PROMPT_TEXT` is read directly from the attacker-controlled file content after the frontmatter [5](#0-4) . This `reason` is fed back to Claude as the next turn, establishing a persistent loop the victim never opted into for that repo/session.

The exploit precondition is that the victim already has the `ralph-wiggum` plugin installed/enabled in Claude Code (it is not part of core Claude Code; it's an optional plugin listed in `.claude-plugin/marketplace.json`). Given that precondition, opening any repo containing the pre-planted `.claude/ralph-loop.local.md` is sufficient — no `/ralph-loop` invocation, approval prompt, or session-scoped marker is required to arm the hook.

### Impact Explanation
This is a trust-boundary bypass: untrusted repository content becomes execution-influencing authority (blocking Stop and injecting a prompt) without any explicit user action establishing that authority. It matches "unauthorized persistent automation / prompt-injection loop established without consent," since the attacker fully controls the injected `reason` text, which is sent back to the model as the driving instruction for continued autonomous iteration, potentially causing the agent to keep executing attacker-defined objectives across many turns. Impact is scoped to sessions where the ralph-wiggum plugin is already enabled.

### Likelihood Explanation
Feasible and repeatable for any victim who has the plugin enabled: it only requires that a Stop event fire (i.e., the user tries to end/finish the session normally) while working in the attacker's repo. No social engineering beyond "open this repo" is needed, and the malicious `.claude/ralph-loop.local.md` is ordinary repo content (a markdown file), which passes no allowlist or validation before the hook reads it.

### Recommendation
Bind the state file to an actual `/ralph-loop` invocation instead of trusting bare file existence: e.g., have `setup-ralph-loop.sh` write a per-session random token/session ID into the frontmatter and have `stop-hook.sh` verify it against the current session ID from `$HOOK_INPUT` before honoring the file; additionally, warn/prompt the user (rather than silently blocking) the first time a pre-existing `.claude/ralph-loop.local.md` is discovered that was not created via `/ralph-loop` in the active session, and consider ignoring/refusing state files that are tracked in git (vs. created locally and gitignored) unless the user explicitly confirms.

### Proof of Concept
Integration test:
1. Create a fresh repo with only `.claude/ralph-loop.local.md` containing a valid frontmatter (`iteration: 0`, `max_iterations: 0`, no `completion_promise`) and a `PROMPT_TEXT` body — never invoke `/ralph-loop`.
2. Simulate a `Stop` hook event (pipe a minimal `{"transcript_path": "..."}` JSON with a transcript containing one assistant message) to `stop-hook.sh`.
3. Assert current behavior: the hook outputs `{"decision":"block","reason":"<attacker PROMPT_TEXT>", ...}` and does not exit 0, i.e., the Stop is blocked purely due to file presence.
4. Expected (fixed) behavior: absent a valid session-binding token proving `/ralph-loop` was invoked in this session, the hook should `exit 0` (allow normal stop) or require explicit user confirmation before blocking.

```shellscript
# Not complete - continue loop with SAME PROMPT
NEXT_ITERATION=$((ITERATION + 1))

# Extract prompt (everything after the closing ---)
# Skip first --- line, skip until second --- line, then print everything after
# Use i>=2 instead of i==2 to handle --- in prompt content
PROMPT_TEXT=$(awk '/^---$/{i++; next} i>=2' "$RALPH_STATE_FILE")

if [[ -z "$PROMPT_TEXT" ]]; then
  echo "⚠️  Ralph loop: State file corrupted or incomplete" >&2
  echo "   File: $RALPH_STATE_FILE" >&2
  echo "   Problem: No prompt text found" >&2
  echo "" >&2
  echo "   This usually means:" >&2
  echo "     • State file was manually edited" >&2
  echo "     • File was corrupted during writing" >&2
  echo "" >&2
  echo "   Ralph loop is stopping. Run /ralph-loop again to start fresh." >&2
  rm "$RALPH_STATE_FILE"
  exit 0
fi

# Update iteration in frontmatter (portable across macOS and Linux)
# Create temp file, then atomically replace
TEMP_FILE="${RALPH_STATE_FILE}.tmp.$$"
sed "s/^iteration: .*/iteration: $NEXT_ITERATION/" "$RALPH_STATE_FILE" > "$TEMP_FILE"
mv "$TEMP_FILE" "$RALPH_STATE_FILE"

# Build system message with iteration count and completion promise info
if [[ "$COMPLETION_PROMISE" != "null" ]] && [[ -n "$COMPLETION_PROMISE" ]]; then
  SYSTEM_MSG="🔄 Ralph iteration $NEXT_ITERATION | To stop: output <promise>$COMPLETION_PROMISE</promise> (ONLY when statement is TRUE - do not lie to exit!)"
else
  SYSTEM_MSG="🔄 Ralph iteration $NEXT_ITERATION | No completion promise set - loop runs infinitely"
fi

# Output JSON to block the stop and feed prompt back
# The "reason" field contains the prompt that will be sent back to Claude
jq -n \
  --arg prompt "$PROMPT_TEXT" \
  --arg msg "$SYSTEM_MSG" \
  '{
    "decision": "block",
    "reason": $prompt,
    "systemMessage": $msg
  }'
```
