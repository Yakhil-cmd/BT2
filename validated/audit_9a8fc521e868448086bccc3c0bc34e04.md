### Title
Stack-scoped API tokens can read CCMenu status of any stack, bypassing the token's `stack_id` binding - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::BaseController` restricts which stacks a request can touch to the set authorized by the authenticated `ApiClient` (`current_api_client.stack_id`). `Shipit::Api::CCMenuController` overrides the `stack` accessor and bypasses that restriction, resolving the target stack directly from the global `Stack` table using only the URL parameter. This breaks the binding between "the stack a token authorizes" and "the stack it touches," mirroring the reported bug class where a value used for one purpose (authorization) is not reconciled with the value actually acted upon (data disclosure).

### Finding Description
`Shipit::Api::BaseController` defines stack resolution as: [1](#0-0) 

```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

This is the mechanism that enforces the "stack a token authorizes" binding: when an `ApiClient` record has a non-nil `stack_id` (i.e. it was created scoped to one stack, as in the `here_come_the_walrus` fixture [2](#0-1) ), `stacks` is restricted to that single stack, and any `stack_id` param pointing elsewhere raises `RecordNotFound` via `from_param!`.

`CCMenuController` however overrides `stack` to bypass `stacks` entirely: [3](#0-2) 

```ruby
class CCMenuController < BaseController
  require_permission :read, :stack
  ...
  def show
    latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
    render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
  end

  private

  def stack
    @stack ||= Stack.from_param!(params[:stack_id])
  end

  def authenticate_api_client
    @current_api_client = ApiClient.authenticate(params[:token])
    super unless @current_api_client
  end
end
```

`stack` here calls `Stack.from_param!` on the unrestricted `Stack` model class, not on the `stacks` scope that consults `current_api_client.stack_id`. `require_permission :read, :stack` only checks that the client's `permissions` array contains `read:stack` (`ApiClient#check_permissions!`, [4](#0-3) ); it never checks *which* stack the client is scoped to. As a result, any client holding `read:stack` — even one created with `stack: some_stack` specifically to limit it to that stack — can pass an arbitrary `stack_id` in the URL and read build/deploy status for any stack in the installation, including private/internal ones the client was never meant to see.

### Impact Explanation
This is an unauthenticated-relative-to-scope read of stack state: a token deliberately restricted to one stack (e.g. distributed to a CI dashboard/CCMenu integration for a single, low-sensitivity stack) can be used to enumerate deploy status, last build result, and related metadata (`name`, `activity`, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`) for every other stack managed by the Shipit instance. This matches the High-severity criterion "escalation into ... unauthenticated read of stack state ... or task streams."

### Likelihood Explanation
Exploitation requires only possession of any valid `ApiClient` token with `read:stack` permission — a low privilege level explicitly intended to be scoped to a single stack via the `stack_id` column. No special access, GitHub credentials, or session is needed beyond the token itself; the token is used exactly as designed (via Basic Auth or the documented `?token=` query parameter), just against a `stack_id` outside its intended scope.

### Recommendation
Change `CCMenuController#stack` to resolve through the scoped `stacks` collection defined in `BaseController`, i.e. remove the private `stack` override (or reimplement it as `stacks.from_param!(params[:stack_id])`), so CCMenu lookups respect `current_api_client.stack_id` the same way every other API controller does.

### Proof of Concept
1. Create (or use) an `ApiClient` scoped to `stack_id` of `stack_a`, with permission `read:stack` (mirrors fixture `here_come_the_walrus`, scoped to `shipit_stacks(:shipit)` with only `read:stack`) [2](#0-1) .
2. Authenticate as this client (Basic Auth or `?token=` query param, both accepted per `CCMenuController#authenticate_api_client`).
3. Issue `GET /api/<stack_b_owner>/<stack_b_repo>/<stack_b_env>/ccmenu.xml` (or the equivalent `stack_id` param) for `stack_b`, a completely unrelated stack the client's `stack_id` does not reference.
4. Because `CCMenuController#stack` calls `Stack.from_param!` directly instead of `stacks.from_param!`, the request succeeds (`200 OK`) and returns `stack_b`'s CCMenu XML (name, lastBuildStatus, lastBuildLabel, etc.), even though `BaseController#stacks` would have raised `RecordNotFound` for the same client on any other controller (compare `CommitsController`, `DeploysController`, `TasksController`, which all use the inherited scoped `stack` method) [5](#0-4) [6](#0-5) .

module Shipit
  module Api
    class TasksController < BaseController
      require_permission :read, :stack
      require_permission :deploy, :stack, only: %i[trigger abort]

      def index
        render_resources(stack.tasks)
      end

      def show
        render_resource(task)
      end

      params do
        accepts :env, Hash, default: {}
      end
      def trigger
        render_resource(stack.trigger_task(params[:task_name], current_user, env: params.env), status: :accepted)
      rescue Shipit::Task::ConcurrentTaskRunning
        render(status: :conflict, json: {
                 message: 'A task is already running.'
               })
      end

      def abort
        if task.active?
          task.abort!(aborted_by: current_user)
          head(:accepted)
        else
          render(status: :method_not_allowed, json: {
                   message: "This task is not currently running."
                 })
        end
      end

      private

      def task
        stack.tasks.find(params[:id])
      end
    end
  end
end
