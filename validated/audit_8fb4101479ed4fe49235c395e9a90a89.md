### Title
Unprivileged AssetHub account can obtain `RuntimeOrigin::root()` on Kusama relay via `LocationAsSuperuser<Equals<AssetHubLocation>, ...>` - (File: relay/kusama/src/xcm_config.rs)

### Summary
`LocalOriginConverter` on the Kusama relay chain unconditionally maps any XCM whose *transport-level* origin equals `AssetHubLocation` (i.e. `Parachain(ASSET_HUB_ID)`) to `RuntimeOrigin::root()`. Because Asset Hub's own `pallet_xcm::Config::SendXcmOrigin` permits any signed account to call `PolkadotXcm::send`, any unprivileged AssetHub user can construct a UMP message containing `Transact { origin_kind: OriginKind::Superuser, .. }` that will arrive at Kusama tagged with the trusted `Parachain(ASSET_HUB_ID)` origin and be dispatched as root.

### Finding Description
On Kusama, `LocalOriginConverter` includes `LocationAsSuperuser<Equals<AssetHubLocation>, RuntimeOrigin>` as the final converter [1](#0-0) , and `AssetHubLocation` is defined as `Parachain(ASSET_HUB_ID).into_location()` [2](#0-1) . The origin an inbound UMP message is tagged with at the relay is fixed by which parachain's DMP/UMP channel delivered it — not by anything internal to the sender's chain — so *every* message sent by Asset Hub via `PolkadotXcm::send`/`ParentAsUmp` arrives at the relay with origin exactly `Parachain(ASSET_HUB_ID)`, with no `DescendOrigin` trick required.

On Asset Hub, `pallet_xcm::Config::SendXcmOrigin = EnsureXcmOrigin<RuntimeOrigin, LocalPalletOrSignedOriginToLocation>`, and `LocalPalletOrSignedOriginToLocation` includes `SignedToAccountId32<...>` [3](#0-2) [4](#0-3) . This means any ordinary signed account on Asset Hub can call `pallet_xcm::send(dest = Parent, Xcm([Transact { origin_kind: OriginKind::Superuser, call, .. }]))`. `SendXcmOrigin` only governs who may invoke `send`; it does not filter the *content* of the program being sent, so the attacker fully controls the `OriginKind` field passed to `Transact`.

At Kusama, the Barrier allows this message unpaid because Asset Hub is recognized as a system parachain (`AllowExplicitUnpaidExecutionFrom<(IsChildSystemParachain<ParaId>, AssetHubPlurality)>`) [5](#0-4) . The executor then processes `Transact`, calling `OriginConverter::convert_origin(Parachain(ASSET_HUB_ID), OriginKind::Superuser)`. Earlier converters in the tuple (`SovereignSignedViaLocation`, `ChildParachainAsNative`, `SignedAccountId32AsNative`, `XcmPassthrough`) do not match `OriginKind::Superuser` for this location, so the fallback `LocationAsSuperuser<Equals<AssetHubLocation>, RuntimeOrigin>` matches and returns `RuntimeOrigin::root()`. `SafeCallFilter = Everything` [6](#0-5)  imposes no restriction on the dispatched call, so the resulting `Transact` executes an attacker-chosen call with full root privileges on the Kusama relay chain.

The specific mechanism hypothesized in the question (`DescendOrigin`/`AliasChildLocation` re-aliasing a sub-location back up to `AssetHubLocation`) does not work, because `AliasChildLocation` and `DescendOrigin` only ever narrow an origin into a *child* location, never generalize it back to a parent/ancestor — so a genuine sub-origin cannot "re-alias" itself into the bare `AssetHubLocation`. However, no such trick is needed: the trust boundary is the whole parachain, not a specific account or governance track within it, so any signed AssetHub account already satisfies the scoped attack.

### Impact Explanation
Any funded, unprivileged signed account on Asset Hub can obtain `RuntimeOrigin::root()` on the Kusama relay chain, enabling arbitrary root-level actions (e.g. `set_code`, forced balance/staking manipulation, force-setting arbitrary storage) — a complete privilege escalation and full compromise of relay chain governance/state integrity, violating the "no unauthorized privileged state transitions" invariant.

### Likelihood Explanation
Highly feasible and repeatable: it requires only (1) a signed account on Asset Hub with enough KSM to pay a UMP delivery fee, and (2) a single `pallet_xcm::send` extrinsic with a crafted `Transact { origin_kind: OriginKind::Superuser, call }`. No governance, proxy, or special permission is needed on either chain — `SendXcmOrigin` on Asset Hub is open to `Everything`-equivalent signed accounts, and the Kusama-side `LocationAsSuperuser` check trusts the entire `AssetHubLocation` unconditionally.

### Recommendation
Do not equate the entire Asset Hub parachain location with root. Restrict which senders inside Asset Hub are allowed to reach `OriginKind::Superuser` semantics at the relay — e.g. require the inbound message to also carry a specific plurality/origin marker only producible by Asset Hub governance (via `UniversalOrigin`/authorized aliasing gated by `AuthorizedAliasers`/root-only extrinsics), rather than trusting any message whose transport origin is `Parachain(ASSET_HUB_ID)`. Alternatively, restrict `SendXcmOrigin` (or add a dedicated filter on the content of messages destined for `Parent` containing `Transact` with `OriginKind::Superuser`) on Asset Hub so only a privileged/governance origin can produce such a message.

### Proof of Concept
xcm-emulator test:
1. On Asset Hub Kusama, fund a plain signed account `alice` (non-privileged).
2. From `alice`, call `PolkadotXcm::send(RuntimeOrigin::signed(alice), Location::parent(), Xcm(vec![Transact { origin_kind: OriginKind::Superuser, call: <encoded System::remark or System::set_code_without_checks>, ..}]))`.
3. Process the UMP queue on Kusama.
4. Assert that the dispatched call executed with `frame_system::RawOrigin::Root` (e.g. via an event or a privileged-only call succeeding), proving that an unprivileged Asset Hub account achieved root on the relay chain.
5. Contrast with expected invariant: assert failure/`BadOrigin` should have occurred instead.

/// The means that we convert the XCM message origin location into a local dispatch origin.
type LocalOriginConverter = (
	// A `Signed` origin of the sovereign account that the original location controls.
	SovereignSignedViaLocation<SovereignAccountOf, RuntimeOrigin>,
	// A child parachain, natively expressed, has the `Parachain` origin.
	ChildParachainAsNative<parachains_origin::Origin, RuntimeOrigin>,
	// The AccountId32 location type can be expressed natively as a `Signed` origin.
	SignedAccountId32AsNative<ThisNetwork, RuntimeOrigin>,
	// Xcm origins can be represented natively under the Xcm pallet's Xcm origin.
	XcmPassthrough<RuntimeOrigin>,
	// AssetHub can execute as root (based on: https://github.com/polkadot-fellows/runtimes/issues/651).
	LocationAsSuperuser<Equals<AssetHubLocation>, RuntimeOrigin>,
);
