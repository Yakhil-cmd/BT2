### Title
Insolvent account wedged permanently between the whole-unit liquidation floor and the $5 bad-debt dust gate - (File: contracts/controller/src/positions/liquidation/curve.rs)

### Summary

CVE-2021-28951 is a circular wait: `exit` blocks on parking an SQPOLL thread that itself blocks on a start signal — two progress paths each gated on a condition the other can no longer satisfy. The analog here is a permissionlessly constructible account state where **both** cleanup paths refuse it forever: `liquidate` always reverts with `InvalidPayments` because the account's single sub-3-decimal collateral leg rounds to zero whole units against the backed quote, while `clean_bad_debt` always reverts with `CannotCleanBadDebt` because the same collateral is worth strictly more than the $5 `BAD_DEBT_USD_THRESHOLD`. The debt can never be repaid through liquidation and never socialized without the owner-gated `force_socialize_bad_debt`.

### Finding Description

On an insolvent account, the liquidation quote is `floor(C / (1 + base))` and each kept repayment leg is rounded **down to whole token units**; a leg whose kept amount rounds to zero is dropped and refunded, and a plan with no remaining leg reverts with `InvalidPayments` (16) [1](#0-0) . This is exercised end-to-end in `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote`, where an account holding collateral worth $9 in a 0-decimal token (one unit = $10) causes every liquidation call to revert [2](#0-1) .

Meanwhile the permissionless cleanup gate requires `total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD` [3](#0-2) , enforced in `socialize_bad_debt` under `BadDebtGate::DustCapped` [4](#0-3) . With collateral of $9 the gate refuses (collateral > $5), yet the account is insolvent and unliquidatable.

Unlike the documented *solvent* narrow band — which "every offer reverts until accrual or a price move ends that state" — the insolvent case is self-sealing: debt `D` grows via interest accrual while collateral `C` stays fixed, so the backed quote `floor(C/(1+base))` never rises toward one whole unit. No oracle move that makes the account *more* insolvent helps either, since `C` is unchanged. The two exits therefore deadlock permanently.

### Impact Explanation

Permanent protocol insolvency / frozen funds. The bad debt sits on the pool's books indefinitely, inflating `total_debt` without any reachable path to write it down (`clean_bad_debt` reverts, `liquidate` reverts, and suppliers' claims are implicitly impaired by the unbacked debt). Only the privileged `force_socialize_bad_debt` (`BadDebtGate::InsolventOnly`) can clear it — and only if governance chooses to act. The cost to create such a wedge is trivial: supply ~$6–$9 of a listed sub-3-decimal asset, borrow slightly above it, and let the position go underwater.

### Likelihood Explanation

Fully permissionless and deterministically reachable: any user can open a small account whose only supply position is a listed asset below 3 decimals whose whole-unit value exceeds `floor(C/(1+base))` and whose `C` exceeds $5. No timing, MEV, or privileged cooperation is needed — only a price move or accrual pushing `HF < 1` with `C` in ($5, one-unit-backed-quote]. Severity Medium: impact is real (unresolvable bad debt without governance action) but bounded per-account and requires an illiquid, coarse-grained listed market.

### Recommendation

Bridge the gap in one of the two gates:
- Let `clean_bad_debt` admit accounts whose every liquidation plan provably seizes nothing (e.g., a "no executable seizure leg" condition), or
- In the insolvent branch, when the only collateral leg's kept units round to zero, round the seized leg **up to one whole unit** and socialize the unbacked residue in the same call instead of reverting — mirroring how `force_socialize` treats the straddle.

### Proof of Concept

1. `supply(victim, "EXP", 1)` — one unit of a listed 0-decimal asset priced at $9.
2. `borrow(victim, ...)` to ~$9.1 (or move the price so `C = $9 < D`).
3. Any `liquidate(liquidator, victim, payments, SeizeMode::Transfer)` → `InvalidPayments`; `get_liquidation_estimate` returns `max_payment_wad = 0`, empty `seized_collaterals` [5](#0-4) .
4. `clean_bad_debt(caller, victim)` → `CannotCleanBadDebt`, since `collateral = $9 > BAD_DEBT_USD_THRESHOLD` [6](#0-5) .
5. State persists forever: accrual only grows `D`, never `C`. Neither permissionless exit ever opens.

fn test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote() {
    let (mut t, account_id) = insolvent_book_with_a_ten_dollar_unit(usd(9) / 1_000);
    let exp = t.resolve_asset("EXP");
    let payments = vec![&t.env, (hub_asset(exp.clone()), 2)];
    let estimate =
        t.ctrl_client()
            .get_liquidation_estimate(&account_id, &payments, &SeizeMode::Transfer);
    assert_eq!(estimate.max_payment_wad, 0);
    assert!(estimate.seized_collaterals.is_empty());
    let refund = estimate.refunds.get(0).expect("EXP refund");
    assert_eq!((refund.asset, refund.amount), (exp, 2));

    let liquidator = t.get_or_create_user(LIQUIDATOR);
    t.resolve_market("EXP").token_admin.mint(&liquidator, &2);
    let result = map_try_ok_value(t.ctrl_client().try_liquidate(
        &liquidator,
        &account_id,
        &payments,
        &SeizeMode::Transfer,
    ));
    assert_contract_error(result, errors::INVALID_PAYMENTS);
    assert_eq!(t.token_balance_raw(LIQUIDATOR, "EXP"), 2);
    assert_eq!(t.borrow_balance_raw(ALICE, "EXP"), 2);
}
