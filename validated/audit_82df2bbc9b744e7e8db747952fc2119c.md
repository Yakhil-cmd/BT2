### Title
Webhook signature verification is bound to `repository.owner.login`/`organization.login` while every handler acts on `repository.full_name` — organization-authenticated vs. repository-written binding break - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and thus which `webhook_secret`) to verify the inbound signature against using `repository_owner`, which is read directly from attacker-controlled JSON (`repository.owner.login` or `organization.login`). Every webhook handler, however, resolves the repository/stack to actually mutate using a completely different, also attacker-controlled field: `repository.full_name`. Nothing ties these two fields together, so the "organization that authenticated" and "the repository that is written" are never checked for consistency.

### Finding Description
`verify_signature` picks the app/secret to check against based on the payload itself: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` uses that attacker-supplied organization name to look up a per-organization config (`github_app_config`), which is the documented "Using Multiple GitHub Applications" setup: [3](#0-2) 

Crucially, `GitHubApp#verify_webhook_signature` short-circuits to `true` if that organization has no `webhook_secret` configured — a state explicitly documented as "optional": [4](#0-3) 

Once "verified" (trivially, if the chosen org has a blank secret — as seen even in the repo's own multi-app fixture where both orgs have `webhook_secret: # nil`), the payload is dispatched to handlers unchanged. Every handler determines the actual repository/stack to mutate from a *different* JSON key, `repository.full_name`, with no cross-check against the `repository.owner.login`/`organization.login` used for signature selection: [5](#0-4) [6](#0-5) [7](#0-6) 

So an attacker who knows (or can cause) an organization in the multi-app config to have no `webhook_secret` can set `repository.owner.login` to that organization to skip signature verification entirely, while setting `repository.full_name` to any other victim repository configured in Shipit (in any other organization, secret or not). The binding broken is exactly: `organization authenticated == repository written`, which the code never enforces.

### Impact Explanation
This is an authentication bypass on the webhook ingress: an unauthenticated network attacker can forge `push`, `pull_request`, `status`, and `check_suite` events for arbitrary repositories/stacks tracked by Shipit, as long as any one organization in the multi-app configuration lacks a webhook secret (a supported, documented configuration). Consequences include forcing `GithubSyncJob` on arbitrary stacks (`PushHandler`), archiving/unarchiving/deprovisioning review stacks and capturing labels on arbitrary pull requests (`PullRequest::*Handler`), and injecting fabricated commit statuses (`StatusHandler`) — all without ever presenting a valid signature for the targeted organization.

### Likelihood Explanation
Exploitability depends entirely on operator configuration: it requires the "Using Multiple GitHub Applications" setup (documented in `docs/setup.md`) with at least one organization configured without a `webhook_secret`. This is a supported and documented configuration, not a hypothetical misuse, and the repository's own test fixtures for multi-app configs demonstrate organizations with blank secrets, indicating this is a realistic deployment shape.

### Recommendation
Do not use payload-controlled fields to select the verification key. Verify the signature against every configured organization's secret (or require the payload's `repository.full_name` owner to exactly match the organization whose secret produced a valid signature) before dispatching to handlers. Additionally, treat a missing `webhook_secret` as "verification required to fail closed" rather than "always verified," or require operators to configure a secret for every organization in a multi-app setup.

### Proof of Concept
1. Configure Shipit with multiple GitHub Apps, e.g. `OrgNoSecret` (no `webhook_secret`) and `victim-org` (real secret, hosts a tracked stack `victim-org/victim-repo`).
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "OrgNoSecret" },
    "full_name": "victim-org/victim-repo"
  }
}
```
No `X-Hub-Signature` (or any garbage value) is required.
3. `verify_signature` resolves `repository_owner` to `OrgNoSecret`, whose `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-83`).
4. `PushHandler#process` uses `repository.full_name` (`victim-org/victim-repo`) to look up stacks and enqueues `GithubSyncJob` for the victim's real stack — fully unauthenticated with respect to `victim-org`'s webhook secret.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
