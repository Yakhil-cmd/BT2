Confirmed: `stakes.upsert_vote_account` is invoked from `StakesCache::check_and_store` (called in `Bank::store_account`) any time a vote-program-owned account with nonzero lamports is written, regardless of stake delegation.### Title
Unbounded growth of `bank.vote_accounts()` via zero-stake vote account creation inflates per-slot cost of `AggregateCommitmentService::aggregate_commitment` - (File: `core/src/commitment_service.rs`)

### Summary
`AggregateCommitmentService::aggregate_commitment` iterates every entry of `bank.vote_accounts()` on every commitment-cache update, and this map contains **all** vote-program-owned accounts with nonzero lamports regardless of whether they have any delegated stake. An unprivileged attacker can create arbitrarily many zero-stake vote accounts cheaply (rent-exempt minimum only), permanently inflating this map and thus the O(N) iteration cost paid by every validator on every aggregation cycle.

### Finding Description
`aggregate_commitment` loops over `bank.vote_accounts().iter()` and only skips further per-account work (`TowerVoteState::from(account.vote_state_view())` and the confirmation-count bookkeeping) after first visiting the map entry and checking `if *lamports == 0 { continue; }`: [1](#0-0) 

The `lamports` here is actually the cached delegated *stake* value from `VoteAccountsHashMap = HashMap<Pubkey, (/*stake:*/ u64, VoteAccount)>`: [2](#0-1) 

Crucially, this map is populated for *every* vote-program-owned account with nonzero lamports, independent of stake delegation. `StakesCache::check_and_store` (invoked from `Bank::store_account` on every account write) calls `stakes.upsert_vote_account(pubkey, vote_account)` whenever `owner` is the vote program and `account.lamports() != 0`, with no minimum-stake or minimum-balance gating: [3](#0-2) 

`upsert_vote_account` unconditionally inserts the account into `VoteAccounts` with whatever delegated stake currently exists for that pubkey (0 if none): [4](#0-3) 

`VoteAccounts::insert` on the vacant-entry path stores the entry regardless of the computed stake being zero: [5](#0-4) 

The only place a filtering/truncation mechanism exists is `clone_and_filter_for_vat`, which is used to build the leader-schedule/VAT input set (bounded, top-stake based), not the live `Bank::vote_accounts()` map that `aggregate_commitment` reads: [6](#0-5) 

So an attacker can, using only ordinary system-program funding and `vote::instruction::create_account` (no stake delegation, no validator/operator privilege), create N vote accounts funded only to the rent-exempt minimum. Each such account permanently occupies a slot in `bank.vote_accounts()` (until its lamports are withdrawn to zero, which only the attacker's own authorized withdrawer can do), and `aggregate_commitment` — which runs on every notarize/root commitment update in `AggregateCommitmentService::run` — must visit all N entries every time, even though the per-entry work for zero-stake accounts is just a hashmap-iteration step plus a branch. The invariant that "epoch/commitment-boundary work is bounded by validator/stake count" is violated: this loop bound is bounded by the number of *any* vote-program account ever created with nonzero lamports, which is attacker-controlled and unbounded.

### Impact Explanation
This is a validator CPU-exhaustion / DoS vector: `AggregateCommitmentService::run`'s hot loop, executed on every validator for every vote/root commitment update, becomes linear in attacker-created junk vote accounts rather than real validator/stake count. Enough accumulated zero-stake vote accounts (cheap, no stake required) can measurably slow down or, at extreme N, stall the commitment thread on every node in the cluster, since all validators run this same code against the same global bank state. This falls into Agave's "validator can be crashed/hung by processing a message it receives from the Solana blockchain" DoS category (not RPC-specific, not requiring validator/gossip/staked-node control).

### Likelihood Explanation
- Precondition is trivial: attacker only needs funds for many vote-account rent-exempt deposits and normal `system_instruction::create_account` + `vote::instruction::create_account` calls — no stake delegation, no special authority.
- Fully repeatable and cumulative: each created zero-stake vote account persists in the bank state (and is inherited across the whole cluster since bank state is consensus state) until explicitly closed by the attacker's own authorized withdrawer.
- Growth is unbounded over time as more transactions are submitted; cost to attacker is only the aggregate rent-exempt deposit (recoverable later), not a per-cycle expense.

### Recommendation
Have `aggregate_commitment` iterate over a stake-filtered view of vote accounts (e.g., only over accounts present in `bank.epoch_vote_accounts()` / accounts with `staked_nodes()` membership) instead of the raw `bank.vote_accounts()` map, or maintain a separate bounded "active/staked vote accounts" index for this hot path so its cost scales with real staked-validator count, not with the number of vote-program accounts ever created.

        vec![(pk, vote_account.clone()), (sk, stake_account)]
            .into_iter().map(|(k, a)| (k, Account::from(a))),
    );

    // Baseline timing with 1 vote account
    let node_vote_state = (pk, TowerVoteState::default());
    let start = Instant::now();
    AggregateCommitmentService::aggregate_commitment(&ancestors, &bank, &node_vote_state);
    let baseline = start.elapsed();

    const N: usize = 200_000;
    for _ in 0..N {
        let attacker_pk = solana_pubkey::new_rand();
        let zero_stake_vote_account = vote_state::create_v4_account_with_authorized(
            &solana_pubkey::new_rand(), &attacker_pk, [0u8; BLS_PUBLIC_KEY_COMPRESSED_SIZE],
            &attacker_pk, 0, &attacker_pk, 0, &attacker_pk, 0,
        );
        // Simulates vote::instruction::create_account funding to rent-exempt minimum,
        // no stake delegation -> stake stays 0 in VoteAccounts map.
        bank.store_account(&attacker_pk, &zero_stake_vote_account);
    }

    let start = Instant::now();
    AggregateCommitmentService::aggregate_commitment(&ancestors, &bank, &node_vote_state);
    let inflated = start.elapsed();

    // Invariant under test: per-slot commitment aggregation work should not scale
    // linearly with attacker-created zero-stake accounts.
    assert!(
        inflated < baseline * 10,
        "aggregate_commitment time grew from {baseline:?} to {inflated:?} due to {N} \
         attacker-created zero-stake vote accounts, violating bounded-work invariant"
    );
}

Expected result: the assertion fails, demonstrating that `aggregate_commitment`'s wall time scales linearly with attacker-created zero-stake vote-account count rather than with real staked-validator count.

    // This implements the filtering logic described in SIMD-357.
    // 1. Filter out any vote accounts without BLS pubkey
    // 2. Given minimum_vote_account_balance, filter out any vote account
    //    without required balance
    // 3. If we have more than max_vote_accounts vote accounts after above
    //    filtering, sort by stake and truncate
    // 4. If any vote account in the resulting list has the same stake as any
    //    truncated vote account, just remove this vote account as well (A and
    //    B have the same stake amount, it's unfair to keep A in and kick B out
    //    just because of Pubkey difference, because that can be grinded)
    // 5. If we end up with an empty list (can happen if everyone in the world
    //    has the same stake, happens in tests, doesn't happen in real world),
    //    log a warning
    pub fn clone_and_filter_for_vat(
        &self,
        max_vote_accounts: usize,
        minimum_vote_account_balance: u64,
    ) -> VoteAccounts {
        assert!(max_vote_accounts > 0, "max_vote_accounts must be > 0");
        let capacity = max_vote_accounts.min(self.vote_accounts.len());
        let mut entries_to_sort: Vec<(&Pubkey, &VoteAccount, u64)> = Vec::with_capacity(capacity);
        for (pubkey, (stake, vote_account)) in self.vote_accounts.iter() {
            let has_bls = vote_account
                .vote_state_view()
                .bls_pubkey_compressed()
                .is_some();
            let has_stake = *stake != 0u64;
            let has_balance = vote_account.lamports() >= minimum_vote_account_balance;

            if !has_bls || !has_stake || !has_balance {
                continue;
            }
            entries_to_sort.push((pubkey, vote_account, *stake));
        }

        let valid_len = entries_to_sort.len();
        if entries_to_sort.len() > max_vote_accounts {
            // Find the cutoff stake using partial sort (more efficient than full sort).
            let (_, cutoff_entry, _) =
                entries_to_sort.select_nth_unstable_by(max_vote_accounts, |a, b| b.2.cmp(&a.2));
            let floor_stake = cutoff_entry.2;

            // Per SIMD 357, we remove all vote accounts with stake smaller or equal to
            // the first truncated one.
            entries_to_sort.retain(|(_, _, stake)| *stake > floor_stake);
        }

        let mut top_entries: HashMap<Pubkey, (u64, VoteAccount)> =
            HashMap::with_capacity(entries_to_sort.len());
        top_entries.extend(
            entries_to_sort
                .into_iter()
                .map(|(pubkey, vote_account, stake)| (*pubkey, (stake, vote_account.clone()))),
        );
        if top_entries.is_empty() {
            if cfg!(test) {
                info!("No valid vote accounts found");
            } else {
                error!("No valid vote accounts found");
            }
        }
        info!(
            "Out of {} vote accounts, {} are valid vote accounts after filtering, {} remain after \
             truncation",
            self.vote_accounts.len(),
            valid_len,
            top_entries.len()
        );
        VoteAccounts {
            vote_accounts: Arc::new(top_entries),
            staked_nodes: OnceLock::new(),
        }
    }

    fn upsert_vote_account(
        &mut self,
        vote_pubkey: &Pubkey,
        vote_account: VoteAccount,
    ) -> Option<VoteAccount> {
        debug_assert_ne!(vote_account.lamports(), 0u64);

        let calculate_delegated_stake = || {
            self.delegated_stakes
                .get(vote_pubkey)
                .copied()
                .unwrap_or_default()
        };
        self.vote_accounts
            .insert(*vote_pubkey, vote_account, calculate_delegated_stake)
    }
