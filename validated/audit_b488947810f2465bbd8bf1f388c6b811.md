The Covalent bug class relies on a two-step unstake→cooldown→withdraw flow where an unprivileged validator can race a privileged "freeze" transaction because the withdrawal step (`transferUnstakedOut()`) fails to re-check the frozen flag. `raydium-cp-swap` has no analogous multi-step staking/cooldown/freeze mechanism. Its pause/status control (`update_pool_status`) is a single privileged instruction restricted to `crate::admin::ID` [1](#0-0) , and both `withdraw` and `swap_base_input` synchronously re-check the pool status bit inside the same atomic instruction before executing any transfer [2](#0-1) [3](#0-2) . There is no separate "unstake" transaction followed by a delayed, unchecked "withdraw" transaction that a user could front-run relative to a freeze — deposit/withdraw/swap all gate on `PoolState::get_status_by_bit` at call time [4](#0-3) . Additionally, the only relevant control here (`update_pool_status`) is a privileged-signer action, which is explicitly out of scope per the rules. No unprivileged-reachable path exhibits a comparable TOCTOU gap.

pub fn update_pool_status(ctx: Context<UpdatePoolStatus>, status: u8) -> Result<()> {
    require_gte!(255, status);
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    pool_state.set_status(status);
    pool_state.recent_epoch = Clock::get()?.epoch;
    Ok(())
