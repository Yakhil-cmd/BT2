Host validation restricts `github-repo` metadata to `github.com` and GHEC tenancy hosts, which forecloses an SSRF-style redirect to an attacker-controlled host. So the strongest attacker-published-content analog is a **verification-bypass / installation-integrity** issue, not a credential-exfiltration one: `gh skill update` (and the `--upstream` redirect in `gh skill install`) both re-derive the "source of truth" for a locally installed skill entirely from the `github-repo` (and `github-tree-sha`, `github-path`) fields embedded in that skill's own `SKILL.md` frontmatter — content that is 100% attacker-controlled by whoever published the skill — with no cryptographic or out-of-band binding between "this installed skill" and "this repo/commit is really where it came from."

### Title
Skill provenance (`github-repo`/`github-tree-sha` metadata) is self-declared and unverified, allowing `gh skill update` to be redirected to attacker content - ([File: pkg/cmd/skills/update/update.go], [File: internal/skills/source/source.go])

### Summary
`gh skill update` determines which remote repository to fetch fresh content from purely by reading the `github-repo` key out of the locally installed `SKILL.md`'s YAML frontmatter [1](#0-0) . That same field was originally injected by `frontmatter.InjectGitHubMetadata` when the skill was first installed, using values taken from the skill's *own* content at install/publish time [2](#0-1) , and `ParseMetadataRepo`/`ParseRepoURL` do no verification beyond syntactic parsing of the string [3](#0-2) .

### Finding Description
This mirrors the report's root cause: an entrypoint trusts a self-asserted identifier (there, `token_id`/sender address; here, `github-repo` frontmatter) as if it had been independently verified, instead of validating it against the actual provenance of the artifact. Concretely:

- At install time, a skill author fully controls the content of `SKILL.md`, including any pre-existing `metadata.github-repo` block, before `gh` even injects its own metadata [4](#0-3) .
- `checkUpstreamProvenance` explicitly reads this attacker-supplied `github-repo` claim out of the raw file content fetched from the repository being installed and, based on it alone, treats another repository as the "real" upstream and can redirect the entire install flow to fetch from that repo instead [5](#0-4) .
- `gh skill update`'s `parseInstalledSkill` re-reads this same field from disk on every future update and uses it, unauthenticated and unverified, as the sole key (`repoHost`, `owner`, `repo`) for where to fetch new content and rewrite the skill on disk [6](#0-5) .
- The only guardrail is `ValidateSupportedHost`, which restricts the *host* to `github.com` or a GHEC tenant, but performs no check that the `owner/repo` pair is actually the true origin of the previously-installed content [7](#0-6) .

Because the constraint is scoped to host only, an attacker who publishes a skill can freely set `github-repo` to point at any `owner/repo` on `github.com`/GHEC (including a legitimate-looking or actually-legitimate repository), and that claim is silently accepted as the update source for as long as the skill remains installed — there is no binding of "this installed skill" to "this is genuinely where it was pulled from" beyond the string the attacker wrote into their own file.

### Impact Explanation
This is a verification/provenance-binding bypass, not remote code execution by itself: written files still go through the skill installer's path-traversal protections (`safepaths.ParseAbsolute`/`Join`) [8](#0-7) , and users are shown a disclaimer that skill content is unverified before every install [9](#0-8) . However, because subsequent `gh skill update --all`/`--force` runs trust the self-declared `github-repo` metadata without any independent verification of provenance, a malicious skill author can cause future automatic updates to fetch and overwrite locally-installed files from a source that was never actually vetted or chosen by the operator, silently persisting attacker influence across the update lifecycle.

### Likelihood Explanation
Requires only that a victim install a skill from an attacker-controlled or attacker-influenced repository — no special privileges, redirects, or MITM — which fits the "attacker-published content" path emphasized in the validation criteria. `gh skill update --all` is documented as the normal, expected way to keep skills current [10](#0-9) , so the vulnerable path is reachable during ordinary CLI use, not an edge case.

### Recommendation
- Bind installed-skill provenance to metadata recorded by `gh` at install time in a location the skill content cannot rewrite (e.g., the local lockfile written by `lockfile.RecordInstall`), rather than re-trusting the `github-repo`/`github-tree-sha` fields embedded in the skill's own frontmatter on every `update` run.
- If frontmatter metadata must be read back, cross-check it against the lockfile-recorded source and refuse (or explicitly warn/require confirmation) on mismatch, rather than silently treating the frontmatter claim as authoritative.
- Apply the same non-repudiation principle to the `checkUpstreamProvenance` redirect path in `gh skill install`, since it currently makes a routing decision based purely on attacker-controlled content.

### Proof of Concept
1. Publish a skill repository `attacker/evil-skills` containing `skills/foo/SKILL.md` with a body that is currently benign, but frontmatter `metadata.github-repo: https://github.com/some-legit-org/some-legit-repo`.
2. Victim runs `gh skill install attacker/evil-skills foo`; `installSkill` injects/overwrites the `github-repo` field via `frontmatter.InjectGitHubMetadata`, but only after `checkUpstreamProvenance` has already read and acted on the attacker's pre-existing claim if present [11](#0-10) ; in non-interactive/`--upstream` mode the redirect happens automatically.
3. Regardless, on any subsequent `gh skill update --all`, `parseInstalledSkill` reads whatever `github-repo` value is present in the on-disk `SKILL.md` (which the attacker fully controlled at initial content-generation time before injection, or which persists across in-place updates) and fetches new content from that repo/owner without validating it matches the originally chosen install source [12](#0-11) .

Note: I could not find any code path where the `github-repo` host restriction is bypassable (it is hard-limited to `github.com`/GHEC tenants), so this analog is scoped to a provenance/verification-bypass within GitHub-hosted repos rather than an SSRF or credential-exfiltration to an arbitrary attacker host; I flag this restriction explicitly since it materially limits (but does not eliminate) the exploitability described above.

		name:  name,
		dir:   dir,
		host:  host,
		scope: scope,

		} else if ok {

		s.pinned, _ = result.Metadata.Meta["github-pinned"].(string)

	}

// ParseRepoURL parses a repository URL stored in skill metadata.
func ParseRepoURL(raw string) (ghrepo.Interface, error) {
	raw = strings.TrimSpace(raw)
	if raw == "" {
		return nil, fmt.Errorf("repository URL is empty")
	}

	repo, err := ghrepo.FromFullName(raw)
	if err != nil {
		return nil, fmt.Errorf("invalid repository URL %q: %w", raw, err)
	}

	return repo, nil
}

// ParseMetadataRepo extracts repository information from skill metadata.
func ParseMetadataRepo(meta map[string]interface{}) (ghrepo.Interface, bool, error) {
	if meta == nil {
		return nil, false, nil
	}

	repoValue, _ := meta["github-repo"].(string)
	if repoValue == "" {
		return nil, false, nil
	}

	repo, err := ParseRepoURL(repoValue)
	if err != nil {
		return nil, true, err
	}

	return repo, true, nil
}

// Supported hosts are github.com and GHEC with data residency (*.ghe.com).

func ValidateSupportedHost(host string) error {
	host = normalizeHost(host)
	if host == "" {
		return fmt.Errorf("could not determine repository host")
	}
	if host == SupportedHost || ghauth.IsTenancy(host) {
		return nil
	}
	if ghauth.IsEnterprise(host) {
		return fmt.Errorf("GitHub Skills does not currently support GitHub Enterprise Server; got %s", host)
	}
	return fmt.Errorf("unsupported host for GitHub Skills: %s", host)
}

// checkUpstreamProvenance fetches the skill's SKILL.md via the contents API
// to check if it contains github-repo metadata pointing to a different
// repository, indicating the skill was re-published from an upstream source.
// In interactive mode, the user is asked whether to install from the
// re-publisher or redirect to the upstream. Non-interactive mode always
// installs from the re-publisher.
// Returns (repo to redirect to, whether upstream was detected, error).
func checkUpstreamProvenance(opts *InstallOptions, client *api.Client, hostname string, skill discovery.Skill, commitSHA string) (ghrepo.Interface, bool, error) {
	u, err := safeurl.JoinPath("repos", opts.repo.RepoOwner(), opts.repo.RepoName(), "contents", skill.Path+"/SKILL.md")
	if err != nil {
		return nil, false, err
	}
	u.SetQuery("ref", commitSHA)
	var fileResp struct {
		Content  string `json:"content"`
		Encoding string `json:"encoding"`
	}
	if err := client.REST(hostname, "GET", u.String(), nil, &fileResp); err != nil {
		return nil, false, nil //nolint:nilerr // best-effort check; failing to fetch is not fatal
	}
	if fileResp.Encoding != "base64" {
		return nil, false, nil
	}
	decoded, decodeErr := io.ReadAll(base64.NewDecoder(base64.StdEncoding, strings.NewReader(fileResp.Content)))
	if decodeErr != nil {
		return nil, false, nil //nolint:nilerr // best-effort; decode failure is not fatal
	}
	content := string(decoded)

	result, parseErr := frontmatter.Parse(content)
	if parseErr != nil || result.Metadata.Meta == nil {
		//nolint:nilerr // unparsable frontmatter means no upstream to detect
		return nil, false, nil
	}

	existingRepo, _ := result.Metadata.Meta["github-repo"].(string)
	if existingRepo == "" {
		return nil, false, nil
	}

	currentRepoURL := source.BuildRepoURL(hostname, opts.repo.RepoOwner(), opts.repo.RepoName())
	if existingRepo == currentRepoURL {
		return nil, false, nil
	}

	upstreamRepo, parseErr := source.ParseRepoURL(existingRepo)
	if parseErr != nil {
		//nolint:nilerr // invalid repo URL means we can't redirect; install normally
		return nil, false, nil
	}
