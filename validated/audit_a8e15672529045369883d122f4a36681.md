### Title
Cross-repository commit-status/push forgery via organization/repository binding mismatch in `WebhooksController` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate a webhook against using `repository.owner.login` (or `organization.login`) from the untrusted JSON body, but the handlers that actually act on the payload (`StatusHandler`, `PushHandler`) do not verify that the same organization/repository is the one being mutated. This breaks the intended equality: *organization whose secret authenticated the request* == *repository/stack that is written*.

### Finding Description
`WebhooksController#verify_signature` picks a `GitHubApp` instance keyed by `repository_owner`, and calls `verify_webhook_signature`: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` **returns `true` unconditionally when no `webhook_secret` is configured** for that organization: [3](#0-2) 

`webhook_secret` is documented as optional per-organization, and Shipit explicitly supports multiple GitHub organizations sharing one instance, each with its own independent `webhook_secret`: [4](#0-3) [5](#0-4) 

Once signature verification passes (because the attacker-chosen `repository.owner.login`/`organization.login` maps to an org with no `webhook_secret`, or to a secret the attacker knows), the event body is handed to `Shipit::Webhooks.for_event(event)` handlers **as-is**, with no re-check that the authenticated org matches the object being modified: [6](#0-5) 

- `StatusHandler` performs **no repository/organization check at all** — it updates the status of *any* `Commit` row in the entire database matching the attacker-supplied `sha`, independent of which org authenticated the request: [7](#0-6) 

- `PushHandler`/`Handler` resolve the target `Repository`/`Stack` using `payload.dig('repository', 'full_name')`, a JSON field that is *distinct* from `repository.owner.login` used for signature-org selection — the two are never cross-validated to belong together: [8](#0-7) [9](#0-8) 

This is the direct analog of the reported bug class: the contract's accounting used one value (`totalVirtual`) to authorize actions while binding the mint/burn to a different, uncontrolled value (`realTotal`), letting a zero-cost donation dominate an unrelated user's deposit. Here, one payload field (`repository.owner.login`) is used to select the *authenticating* secret, while a different, independently-attacker-controlled field (`repository.full_name`, or nothing at all for `status`) determines the *target* that gets mutated — the two are never bound together.

### Impact Explanation
An attacker who controls (or is the sole webhook sender for) any GitHub organization configured on the same Shipit instance — or any org configured without a `webhook_secret`, which is a documented, legitimate configuration — can:
1. Send a `status` event with a valid/bypassed signature for their own org, and an arbitrary `sha` belonging to a commit tracked under a completely unrelated stack, forging a "success" CI status via `Commit#create_status_from_github!` for that commit.
2. Because required-status checks (`DeploySpec#required_statuses`) gate `deployable?`, this can make an otherwise-non-deployable commit on a victim's production stack appear deployable, enabling an **unauthorized deploy**.
3. Similarly, `PushHandler` can be triggered against any `repository.full_name` present in the datastore regardless of the authenticating org, injecting an attacker-chosen `expected_head_sha` into `GithubSyncJob` for a victim stack.

This satisfies the "unauthorized deploy" High-impact criterion defined in the rules.

### Likelihood Explanation
Likelihood is moderate-to-high in any deployment using the documented multi-organization feature, or any single organization that has not set a `webhook_secret` (explicitly optional per the setup docs). No `ApiClient` token, GitHub App private key, or session is required — the `/webhooks` endpoint is public and unauthenticated by design (that's the whole point of signature verification), and the attacker only needs the ability to author a POST body with attacker-chosen JSON fields, i.e., no GitHub write access to the victim's repository is required at all.

### Recommendation
- Cross-validate that the resolved authenticating organization matches the organization embedded in `repository.full_name` (and any other field used for target resolution) before dispatching to handlers.
- In `StatusHandler`, require and check a `repository` field, and confirm the resolved `Commit`'s stack belongs to the authenticated organization before calling `create_status_from_github!`.
- Consider making `webhook_secret` mandatory (removing the `return true unless webhook_secret` bypass in `GitHubApp#verify_webhook_signature`), or at minimum warn loudly / refuse in multi-org configurations when any org lacks a secret.

### Proof of Concept
Given a Shipit instance configured with multiple GitHub orgs (`OrgWithoutSecret` and `OrgWithSecret`) per `docs/setup.md`'s multi-org example, and `OrgWithoutSecret` has no `webhook_secret` set:

```
POST /webhooks
X-Github-Event: status
Content-Type: application/json

{
  "repository": { "owner": { "login": "OrgWithoutSecret" } },
  "sha": "<sha of a commit belonging to OrgWithSecret's production stack>",
  "state": "success",
  "context": "<the CI context required by OrgWithSecret's shipit.yml ci.require>"
}
```

`verify_signature` resolves `Shipit.github(organization: "OrgWithoutSecret")`, whose `verify_webhook_signature` returns `true` regardless of any signature header, per `lib/shipit/github_app.rb` lines 76-77. `StatusHandler#process` then unconditionally applies the forged "success" status to the targeted commit, with no check that it belongs to `OrgWithoutSecret`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
