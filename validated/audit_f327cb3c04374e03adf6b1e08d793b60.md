### Title
Partial-rewind race in `RemoveVotesAfter` allows `VerifyGov` to reject a valid epoch block, causing consensus divergence — (`kaiax/gov/headergov/impl/rewind.go`)

### Summary
`RemoveVotesAfter` acquires and releases `h.mu.Lock()` once per deleted vote entry rather than holding it for the entire rewind. A concurrent reader (e.g., the fetcher's `verifyHeader` goroutine calling `getVotesInEpoch`) can acquire `h.mu.RLock()` between two consecutive per-entry lock windows and observe a partially-rewound `groupedVotes` map. This causes `getExpectedGovernance` to compute a governance payload that differs from what the proposer computed, making `VerifyGov` return `ErrGovVerification` and reject a valid epoch block.

### Finding Description

`RemoveVotesAfter` iterates over `h.groupedVotes` and deletes qualifying entries one at a time, each time acquiring and releasing `h.mu`:

```go
// rewind.go lines 18-38
func (h *headerGovModule) RemoveVotesAfter(blockNum uint64) {
    for epochIdxIter, votes := range h.groupedVotes {
        for blockNumIter := range votes {
            if blockNumIter > blockNum {
                h.mu.Lock()                                    // acquired per entry
                delete(h.groupedVotes[epochIdxIter], blockNumIter)
                if len(h.groupedVotes[epochIdxIter]) == 0 {
                    delete(h.groupedVotes, epochIdxIter)
                }
                h.mu.Unlock()                                  // released per entry
            }
        }
    }
    ...
}
``` [1](#0-0) 

Between any two consecutive `Lock/Unlock` pairs, `h.mu` is free. The fast path of `getVotesInEpoch` acquires `h.mu.RLock()` and snapshots `h.groupedVotes[epochIdx]` during that window:

```go
// header.go lines 246-249
h.mu.RLock()
defer h.mu.RUnlock()
maps.Copy(votes, h.groupedVotes[epochIdx])
``` [2](#0-1) 

The snapshot therefore contains some-but-not-all of the votes that should have been removed, producing a `govs` map that differs from the one the proposer computed when it called `getExpectedGovernance` and wrote `header.Governance`. [3](#0-2) 

`VerifyGov` then performs a `reflect.DeepEqual` comparison and returns `ErrGovVerification`: [4](#0-3) 

**Why `Stop()` does not close the window:**
`Stop()` only signals and joins the background migration goroutine via `h.quit` / `h.wg`. It does not prevent concurrent `VerifyHeader` calls from other goroutines. [5](#0-4) 

**Why `bc.mu` does not close the window:**
`setHeadBeyondRoot` holds `bc.mu.Lock()` while calling `RewindDelete`. However, the fetcher's `insertWork` calls `f.verifyHeader(block.Header())` — which resolves to `headerGovModule.VerifyHeader` — **before** calling `f.insertChain`, and this call runs in a dedicated `insertWorker` goroutine that does not hold `bc.mu`. [6](#0-5) [7](#0-6) 

### Impact Explanation
An honest verifier node rejects a valid epoch block proposed by an honest proposer. The verifier stays on the wrong fork or stalls, constituting a consensus divergence. No attacker key or privileged access is required; the race is triggered by normal fork-resolution activity (any competing chain tip causes `setHeadBeyondRoot` → `RewindDelete`) concurrent with the fetcher processing the next epoch block from a peer.

### Likelihood Explanation
Fork resolution is a routine event on any live network. The fetcher's `insertWorker` goroutines run continuously and call `verifyHeader` outside `bc.mu`. The race window exists for every vote entry deleted during a rewind that overlaps with an epoch boundary. On a network with active governance voting and occasional short forks, the conditions align regularly.

### Recommendation
Hold `h.mu.Lock()` for the **entire** rewind operation rather than per entry:

```go
func (h *headerGovModule) RemoveVotesAfter(blockNum uint64) {
    h.mu.Lock()
    defer h.mu.Unlock()
    dirty := false
    for epochIdxIter, votes := range h.groupedVotes {
        for blockNumIter := range votes {
            if blockNumIter > blockNum {
                dirty = true
                delete(h.groupedVotes[epochIdxIter], blockNumIter)
                if len(h.groupedVotes[epochIdxIter]) == 0 {
                    delete(h.groupedVotes, epochIdxIter)
                }
            }
        }
    }
    // release lock before DB write
    if dirty {
        WriteVoteDataBlockNums(h.ChainKv, h.VoteBlockNums())
    }
}
```

Apply the same fix to `RemoveGovAfter`. [8](#0-7) 

### Proof of Concept

1. Configure a chain with epoch = 100 and at least two governance votes in blocks 1–99.
2. Start two goroutines:
   - **G1**: call `RemoveVotesAfter(50)` (removes votes at blocks 51–99).
   - **G2**: call `getVotesInEpoch(0)` (fast path, acquires RLock, snapshots `groupedVotes[0]`).
3. Synchronize so G2 acquires RLock between G1's first and second `Lock/Unlock` pairs.
4. Assert that G2's snapshot contains exactly the votes that should remain after a complete rewind — it will instead contain a partial set.
5. Run with `go test -race`; the race detector will flag the unsynchronized concurrent map access between the outer loop read (no lock) and the concurrent RLock read.
