### Title
Stack-scoped API tokens can read the CI status of any stack via the CCMenu endpoint - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::CCMenuController` re-implements its own `stack` lookup instead of using the stack-scoping logic inherited from `Shipit::Api::BaseController`, so an `ApiClient` token that is supposed to be restricted to a single stack can be used to fetch deploy/CI status for *any* stack in the installation.

### Finding Description
`Shipit::Api::BaseController` implements a scoping mechanism so that a client created with a `stack_id` (e.g. via `CCMenuUrlController#client`) can only see the stack it was bound to: [1](#0-0) 

`stacks` filters by `current_api_client.stack_id?`, and `stack` (used by `StacksController` and others) is derived from that scoped relation, enforcing the equality "stack a token authorises == stack it touches".

`CCMenuController`, however, overrides `stack` with an unscoped lookup and overrides `authenticate_api_client` to accept a bare `token` query param instead of the standard Basic-Auth flow: [2](#0-1) 

`Stack.from_param!(params[:stack_id])` resolves the stack directly against `Stack`, completely bypassing the `stacks` scope from the base controller. `require_permission :read, :stack` only calls `ApiClient#check_permissions!`, which merely checks that the `read:stack` permission string is present in `permissions` — it never checks `stack_id`: [3](#0-2) 

So any token holding `read:stack` (including a token that was intentionally scoped to one specific stack, such as the one minted by `CCMenuUrlController#client`) can be replayed with a different `stack_id` in the URL and will successfully render another stack's CCMenu XML (build status, last build label/time, web URL).

This mirrors the reported bug class: a binding that is supposed to be enforced ("the stack this credential authorises") is not actually checked at the point where the sensitive action ("the stack this request touches") occurs, exactly as the withdrawal-lock binding was checked in `withdrawDeposit` but not enforced consistently when committing a channel.

`CCMenuUrlController` demonstrates that this scoping is a real, intended security boundary — it deliberately mints a `read:stack`-only, stack-bound client for embedding in third-party CI dashboard tools: [4](#0-3) 

### Impact Explanation
This breaks the "stack a token authorises versus a stack it touches" binding. A token meant to be readable-only for one stack (typically embedded in third-party dashboard tools, e.g. CCMenu clients, and therefore more exposed to leakage) can be used to read the deploy status of every other stack in the Shipit instance — an authorization-scope bypass leading to unauthorized read of stack state across tenant/stack boundaries.

### Likelihood Explanation
Exploitation requires only possession of any valid `read:stack` token (including a narrowly stack-scoped one, which is exactly the kind of token designed to be embedded in low-trust external tools like CI status dashboards). No special privilege beyond having *a* token is needed, and the request is a single unauthenticated-looking GET with a different `stack_id` parameter substituted.

### Recommendation
Have `CCMenuController#stack` use the inherited, scoped `stacks` collection (`stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!`, so the `current_api_client.stack_id` restriction from `BaseController` is enforced consistently across all API endpoints.

### Proof of Concept
1. Obtain (or be issued) a CCMenu token scoped to Stack A via `GET /stacks/:A/ccmenu_url` (creates an `ApiClient` with `stack_id = A`, `permissions = [read:stack]`).
2. Call `GET /api/stacks/:B/ccmenu.xml?token=<token>` where `B` is a different stack.
3. The request succeeds and returns Stack B's build status/label/time, even though the token is only supposed to authorize access to Stack A. [5](#0-4)

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
```
