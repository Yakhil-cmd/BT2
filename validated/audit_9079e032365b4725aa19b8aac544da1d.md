### Title
Webhook signature verification keyed on `repository.owner.login` while all handlers dispatch on `repository.full_name` allows cross-organization stack/commit mutation - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which organization's `webhook_secret` to verify `X-Hub-Signature` against using `repository.owner.login` from the (attacker-controlled, since the attacker crafts the whole raw HTTP body themselves) JSON body, then `#create` dispatches the same body to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`, whose handlers resolve the target `Repository`/`Stack` via `payload.dig('repository', 'full_name')`. Because these two fields are read independently and never cross-checked, an attacker who legitimately knows the `webhook_secret` configured for their own organization can sign a body whose `repository.owner.login` is their own org but whose `repository.full_name` names a repository owned by a different organization, causing that victim organization's `Stack`/`Commit`/`Team` records to be mutated.

### Finding Description
The intended binding is: `organization_whose_secret_verified_the_signature == organization_that_owns_the_repository_being_mutated`. In code this should mean `repository_owner` (used in `verify_signature`) equals the owner segment of `repository.full_name` (used everywhere else). This binding is broken.

- `verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-30) computes:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
with `repository_owner` defined as:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

- `#create` then dispatches the raw parsed JSON, unmodified, to handlers:
```ruby
params = JSON.parse(request.raw_post)
Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
``` [2](#0-1) 

- Every base `Handler` resolves the target repository via a *different* field of the same body:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [3](#0-2) 

- `Repository.from_github_repo_name` splits `full_name` on `/` to find owner/name, entirely independent of `repository.owner.login`:
```ruby
def self.from_github_repo_name(github_repo_name)
  repo_owner, repo_name = github_repo_name.downcase.split('/')
  find_by(owner: repo_owner, name: repo_name)
end
``` [4](#0-3) 

- Concrete handlers such as `PushHandler#process` act on the resolved `stacks` (`stack.sync_github(...)`), and pull-request handlers such as `OpenedHandler#repository` independently re-derive the repository from `params.repository.full_name` and mutate `ReviewStack`s through it. [5](#0-4) [6](#0-5) 

**Attacker's request**: an attacker who administers/owns some organization "attacker-org" registered in Shipit (and therefore knows the `webhook_secret` configured for that org, as they are the one who set up the GitHub App/webhook integration for it) sends directly (not relayed via GitHub) a `POST /webhooks` with:
- `X-Github-Event: push`
- `X-Hub-Signature: sha1=<HMAC-SHA1(attacker-org webhook_secret, raw_body)>`
- body: `{"ref":"refs/heads/master","after":"<sha>","repository":{"full_name":"victim-org/victim-repo","owner":{"login":"attacker-org"}}}`

`repository_owner` resolves to `"attacker-org"`, `Shipit.github(organization: "attacker-org")` uses the secret the attacker knows, `verify_webhook_signature` returns true because the HMAC is computed over the exact raw body the attacker crafted (they are not proxying a genuine GitHub delivery, so they fully control both fields). `drop_unhandled_event`/`check_if_ping` do not filter this (push events are handled). `PushHandler` then resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: params.after)` on `victim-org`'s stacks, forcing a sync to an attacker-chosen SHA — none of `ExplicitParameters`, `force_github_authentication`, `User#authorized?`, or `Repository` format validators intervene, because this is server-to-server webhook authentication, not user session/API-token authentication, and none of those guards check owner/full_name consistency.

### Impact Explanation
An attacker who only controls one organization's Shipit webhook secret can forge webhook events (`push`, `pull_request`, `status`, `check_suite`, `membership`, etc.) that are accepted as authentic and dispatched against an arbitrary victim repository named in `repository.full_name`. This can force `GithubSyncJob` runs, create/mutate `ReviewStack`s via pull_request handlers, write bogus `Status`/`Commit` state, or modify `Team`/`Membership` records — all scoped to a different tenant than the one whose secret authenticated the request. This is a cross-tenant authentication-bypass-style vulnerability (payload authenticated for org B mutating org A's stack/commit/team), matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." It is fully repeatable against any repository already known/tracked in Shipit, for every event type routed through `Handler#stacks`/`repository_name`.

### Likelihood Explanation
Requires the attacker to legitimately administer at least one organization onboarded into this Shipit instance (i.e., to know that org's configured `webhook_secret`) — a low bar in any multi-tenant Shipit deployment where organizations self-configure their own webhook secrets. The attacker does not need any Shipit session, API token, or the victim's secret. Constructing the forged HTTP request is trivial (any HTTP client, one HMAC computation with a known key). It is fully repeatable, at will, against any repository present in the datastore.

### Recommendation
In `WebhooksController`, after verifying the signature, cross-check that the resolved `repository_owner` (or `organization.login`) matches the owner segment of `repository.full_name` (and, ideally, that this owner corresponds to the actual GitHub App/organization installation for that repository) before dispatching to handlers; reject the request with `422` on mismatch. Alternatively, resolve the target `Repository`/organization solely from the verified `repository_owner` field rather than trusting `full_name` independently in handler code (`app/models/shipit/webhooks/handlers/handler.rb`, and the pull_request handlers that re-derive `repository_name`/`full_name`).

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "signature valid for org B cannot mutate org A's stack via mismatched full_name" do
  victim_stack = shipit_stacks(:shipit) # belongs to Repository owned by "shopify"
  attacker_org = "attacker-org"

  body = {
    ref: "refs/heads/#{victim_stack.branch}",
    after: "deadbeef",
    repository: { full_name: victim_stack.repository.github_repo_name, owner: { login: attacker_org } }
  }.to_json

  Shipit.github(organization: attacker_org).stubs(:verify_webhook_signature).returns(true)

  request.headers['X-Github-Event'] = 'push'
  request.headers['X-Hub-Signature'] = 'sha1=forged-but-accepted'

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: "deadbeef"]) do
    post :create, body: body, as: :json
  end
  # Assert broken binding: repository_owner ("attacker-org") != victim_stack.repository.owner ("shopify")
  assert_not_equal attacker_org, victim_stack.repository.owner
end
```
This demonstrates that a signature validated against `attacker-org`'s secret (the only side of the equality the attacker controls) results in a mutation queued for `victim_stack`, owned by a different organization — confirming the binding `repository_owner == owner(repository.full_name)` is not enforced.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
