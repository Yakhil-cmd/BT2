### Title
`capiTransport.RoundTrip` attaches the Copilot bearer token to every request regardless of destination host - ([File: pkg/cmd/agent-task/capi/client.go])

### Summary
`capiTransport.RoundTrip`, installed as the `http.Client.Transport` used by `CAPIClient`, unconditionally sets `Authorization: Bearer <token>` on every outgoing request before delegating to the wrapped `RoundTripper`, and only gates the CAPI-specific headers (`Copilot-Integration-Id`, `X-GitHub-Api-Version`) behind a host check.

### Finding Description
`NewCAPIClient` wraps the caller-supplied `http.Client` (built by `f.HttpClient()`, the authenticated GitHub HTTP client) with `capiTransport`: [1](#0-0) 

`capiTransport.RoundTrip` sets the bearer token header first, and only conditionally adds the Copilot-specific headers if `req.URL.Host == ct.capiHost`: [2](#0-1) 

This is structurally the same class of bug as the reported Stargate issue: a credential/asset is unconditionally directed based on the caller's request rather than being scoped/validated against the intended destination. Here, the intended scoping check (`req.URL.Host == ct.capiHost`) exists for the CAPI-only headers, but the `Authorization` header carrying the actual bearer token is set unconditionally for *any* host the underlying `http.Client` is asked to hit through this transport. The comment even acknowledges "this RoundTrip is reused for both Copilot API and GitHub API requests," confirming the transport is intentionally shared across multiple destinations without host-scoping the credential itself.

This same underlying `*http.Client` is also used via `api.NewClientFromHTTP(c.httpClient)` to send GraphQL queries to `hostname` values that are function parameters, e.g. `GetPullRequestDatabaseID(ctx, hostname, ...)`: [3](#0-2) 

Because `capiTransport` sits as the outer transport (wrapping whatever `f.HttpClient()` returned, which itself has `AddAuthTokenHeader` logic that *does* correctly gate on host/redirect changes for the standard `gh` auth token — see below), the bearer token set by `capiTransport` bypasses that safer host-check logic entirely and is applied indiscriminately.

For contrast, the "correct" pattern elsewhere in the codebase explicitly checks for redirect/host changes before attaching a token: [4](#0-3) 

### Impact Explanation
If any code path causes a request to be issued through this `http.Client`/`capiTransport` to a host other than the intended CAPI host or the user's configured GitHub host, the Copilot bearer token would be sent to that host. Given the CAPI token is a live, potentially highly privileged Copilot/agent-task credential, exfiltration to an unintended host (e.g. via a server-controlled redirect target, or via a hostname parameter that isn't tightly restricted) would allow an attacker-controlled host to receive valid authorization credentials.

### Likelihood Explanation
I could not fully confirm, within available tooling, whether `hostname` in `GetPullRequestDatabaseID` or any other call path can be attacker-influenced (e.g., derived from PR/session data returned by the API) or whether Go's default `http.Client` redirect-following behavior is disabled for this specific client. The gating logic for the CAPI-specific headers implies host-awareness was considered by the developers for those headers but was not applied to the `Authorization` header itself. Given the index's size limits, I was not able to trace every call site that constructs the `hostname` argument or verify redirect policy configuration for this specific client instance with full certainty.

### Recommendation
Scope the `Authorization: Bearer <token>` header the same way the `Copilot-Integration-Id`/`X-GitHub-Api-Version` headers are scoped — only attach the CAPI bearer token when `req.URL.Host` matches an expected/allow-listed host (the resolved `capiHost`, or the user's configured GitHub host), mirroring the redirect/host-change check already implemented in `AddAuthTokenHeader` (`api/http_client.go`). Additionally, verify that hostnames passed into `GetPullRequestDatabaseID` and similar methods originate only from trusted configuration/user input, not from remotely-supplied data.

### Proof of Concept
Not able to construct a concrete end-to-end exploit chain with the tools available (would require tracing whether `hostname` inputs to `GetPullRequestDatabaseID` can be attacker-supplied, and confirming the redirect policy of the underlying `http.Client`). The code-level root cause — unconditional `Authorization` header attachment in `capiTransport.RoundTrip` regardless of destination host — is confirmed directly from `pkg/cmd/agent-task/capi/client.go:64-77`.

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}

// GetPullRequestDatabaseID retrieves the database ID and URL of a pull request given its number in a repository.
func (c *CAPIClient) GetPullRequestDatabaseID(ctx context.Context, hostname string, owner string, repo string, number int) (int64, string, error) {
	// TODO: better int handling so we don't need to do bounds checks
	// to both ensure a panic is impossible and that we do not trigger
	// CodeQL alerts.
	if number <= 0 || number > math.MaxInt32 {
		return 0, "", fmt.Errorf("pull request number %d out of bounds", number)
	}

	var resp struct {
		Repository struct {
			PullRequest struct {
				FullDatabaseID string `graphql:"fullDatabaseId"`
				URL            string `graphql:"url"`
			} `graphql:"pullRequest(number: $number)"`
		} `graphql:"repository(owner: $owner, name: $repo)"`
	}

	variables := map[string]interface{}{
		"owner":  githubv4.String(owner),
		"repo":   githubv4.String(repo),
		"number": githubv4.Int(number),
	}

	apiClient := api.NewClientFromHTTP(c.httpClient)
	if err := apiClient.Query(hostname, "GetPullRequestFullDatabaseID", &resp, variables); err != nil {
		return 0, "", err
	}

	databaseID, err := strconv.ParseInt(resp.Repository.PullRequest.FullDatabaseID, 10, 64)
	if err != nil {
		return 0, "", err
	}
	return databaseID, resp.Repository.PullRequest.URL, nil
}

// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
