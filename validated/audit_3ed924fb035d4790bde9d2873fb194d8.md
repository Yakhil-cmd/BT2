### Title
Unrestricted swap routes can attach attacker-controlled token transfers to the caller's authorization tree - (File: `contracts/controller/src/strategies/swap.rs`)

### Summary
`swap_collateral`, `swap_debt`, `multiply`, and `repay_debt_with_collateral` accept opaque, caller-supplied route data and pass it to the configured router after authorizing only the controller's input transfer. [1](#0-0)  Because route venues are not constrained by the controller, third-party code reached by the route can add an unrelated `token.transfer(victim, attacker, amount)` beneath the victim's root authorization; simulation records that child, and enforcing mode executes it if the victim signs the expanded tree. [2](#0-1) 

### Finding Description
`swap_collateral` authenticates the caller and checks ownership or delegation, but it forwards the attacker-influenced `StrategySwap` without decoding or constraining the venue addresses encoded inside it. [3](#0-2)  The controller then invokes `router.execute_strategy(controller, amount_in, swap)` under the flash guard. [1](#0-0) 

The controller's own token grant is narrow: it authorizes exactly one transfer of `token_in` from the controller to the configured router. [4](#0-3)  However, Soroban authorization is represented as an invocation tree: a contract reached below the router can request `victim.require_auth()` for an unrelated token transfer, causing simulation to attach that transfer as a child of the victim's `swap_collateral` authorization. [5](#0-4) 

The repository's regression test demonstrates that simulation records the malicious wallet transfer under Alice's `swap_collateral` root and that submitting the recorded tree transfers her unrelated wallet token to the attacker while the collateral swap succeeds. [6](#0-5)  A control test rejects the malicious transfer under an honest root-only tree, but accepts it once the victim signs the child invocation returned by simulation. [7](#0-6) 

### Impact Explanation
A malicious route can steal arbitrary SEP-41 token balances from the swapping user, including tokens unrelated to the lending position and not limited by `amount_in`. [5](#0-4)  The measured input, positive-output check, and final account-risk checks do not bound this loss because the stolen token movement is a separate authorization-tree child rather than controller-routed input. [2](#0-1) 

### Likelihood Explanation
Exploitation requires the victim to submit a crafted route and sign the poisoned authorization tree produced during simulation. [8](#0-7)  This is still a practical authorization-confusion risk because routes and nested authorization entries can be opaque to users and signing clients, and an honest strategy normally produces no extra child transfer under controller-authorized strategy calls. [9](#0-8) 

### Recommendation
Restrict strategy routes to explicitly vetted venue contracts or venue identifiers instead of allowing routes to invoke arbitrary contracts. [10](#0-9)  In addition, require clients to decode the complete simulated authorization tree and reject any child invocation beyond the protocol's expected token transfer; a controller strategy should normally have no caller child invocation at all. [9](#0-8) 

### Proof of Concept
1. Alice supplies USDC and owns an unrelated token; the attacker deploys a contract whose `swap` function calls `token.transfer(alice, attacker, WALLET_BALANCE)`. [5](#0-4) 
2. Alice calls `swap_collateral(alice, account_id, USDC_hub_asset, amount, ETH_hub_asset, route)`, where `route` names the attacker's contract as a hop. [11](#0-10) 
3. During simulation, the router invokes the attacker hop, and the unrelated token transfer is recorded as a child of Alice's `swap_collateral` authorization. [12](#0-11) 
4. If Alice signs that returned tree, the malicious transfer executes: her unrelated wallet-token balance becomes zero, the attacker receives it, and the expected ETH collateral output is still deposited. [13](#0-12) 
5. The same test shows enforcement behavior: the rogue transfer fails under an unsigned honest tree, but succeeds when the simulated child transfer is included in Alice's signed authorization. [14](#0-13)

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
