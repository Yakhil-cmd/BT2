### Title
Unhandled `throw` in `definition template` evaluation crashes the node - ([File: definition.js])

### Summary
`CVE-2015-4646` describes squashfs-tools/sasquatch crashing when parsing crafted archive data because the unsquash code does not handle malformed input gracefully and dies instead of failing safely. The analogous class in ocore is code that, when it encounters malformed/unexpected but attacker-reachable input, does `throw Error(...)` from inside an asynchronous database callback instead of returning an error through the normal `cb()`/`callback()` error channel. Such a throw cannot be caught by any surrounding `try/catch` (the call stack that entered the async callback is gone by the time it fires), so it becomes an uncaught exception in Node. `network.js` installs a global `process.on('uncaughtException', ...)` handler that deliberately re-throws to crash the whole process "to avoid ending up in an inconsistent state" [1](#0-0) . Any attacker who can get this code path to fire can therefore remotely crash a node, matching the CVE's "crafted input causes application crash" pattern.

### Finding Description
`Definition.validateAuthentifiers()`'s inner `evaluate()` function handles the `'definition template'` operator of an address/asset definition. It looks up a `definition_template` message referenced by `unit` in the DAG and expects exactly one matching row:

```js
case 'definition template':
    // ['definition template', ['unit', {param1: 'value1'}]]
    var unit = args[0];
    var params = args[1];
    conn.query(
        "SELECT payload FROM messages JOIN units USING(unit) \n\
        WHERE unit=? AND app='definition_template' AND main_chain_index<=? AND +sequence='good' AND is_stable=1",
        [unit, objValidationState.last_ball_mci],
        function(rows){
            if (rows.length !== 1)
                throw Error("not 1 template");
            var template = rows[0].payload;
            var arrTemplate = JSON.parse(template);
            var arrFilledTemplate = replaceInTemplate(arrTemplate, params);
            evaluate(arrFilledTemplate, path, cb2);
        }
    );
    break;
``` [2](#0-1) 

If `rows.length !== 1` — i.e., the referenced `unit` does not contain a stable, good `definition_template` message at or before `last_ball_mci` (the normal case when an attacker references a non-existent unit, a unit whose template message hasn't stabilized yet, or one with the wrong `app`) — the code executes `throw Error("not 1 template")` inside the `conn.query` result callback. This throw does not go through the `cb2(err)` error-propagation path used everywhere else in this function; it propagates as an uncaught exception. This code is reached during authentifier/signature validation of any unit whose author uses an address definition containing `['definition template', [unit, params]]`, which is fully attacker-controlled content in a posted unit's `author.definition` (or in a nested/referenced address definition evaluated via `'address'`).

The equivalent code path in `validateDefinition()` (the first-pass structural validator) does perform a `+sequence='good'` filter and looks similar, but the authentifier-evaluation path shown above is exercised during actual signature checking of every unit using this definition, and is the one lacking the safe-error return.

### Impact Explanation
Because the thrown error is not caught anywhere in the validation call chain (it originates inside a DB driver callback, several event-loop turns removed from any `try/catch`), it surfaces as a Node.js `uncaughtException`. `network.js` explicitly re-throws inside its `uncaughtException` handler to crash the process rather than continue in a possibly inconsistent state [1](#0-0) . A crashed full/witness node stops relaying, validating, and stabilizing units — a "network unable to confirm new units" condition if triggered broadly, or at minimum denial of service against any node (hub, witness, or full node) that processes the malicious unit. This is a legitimate, unauthenticated, remotely triggerable crash from a single crafted unit, which is the direct analog of the CVE's "denial of service (application crash) via a crafted input."

### Likelihood Explanation
Likelihood is high for any node performing normal unit validation: an attacker only needs to author and broadcast one ordinary unit whose address definition (first use of the address, so `definition` is required in the author) contains a `['definition template', [<any_unit_hash>, {}]]` clause where `<any_unit_hash>` does not correspond to a message with `app='definition_template'` that is stable and marked `sequence='good'` at or below the referenced `last_ball_mci` — trivially satisfied by using a bogus/nonexistent unit id, or a unit whose `definition_template` message is unstable or marked `sequence='final-bad'`/`'temp-bad'`. This is reachable from the standard "unprivileged unit poster" validation flow and requires no special privileges, hub cooperation, or timing.

### Recommendation
Replace the `throw Error("not 1 template")` with the same error-propagation convention used elsewhere in this function, e.g. `return cb2(false)` or `return cb2(err)`/pass an explicit validation failure so that ambiguous/missing templates simply fail definition validation instead of crashing the process. Wrap the `JSON.parse(template)` / `replaceInTemplate` calls in a `try/catch` as well, mirroring the pattern already used for `readAADefinition`/other JSON.parse call sites, and ensure any thrown `NoVarException` from `replaceInTemplate` is likewise converted to a `cb2` error rather than left to propagate uncaught.

### Proof of Concept
1. Attacker crafts a new address whose definition (used as `author.definition` on first use of the address in a unit) is:
   ```json
   ["definition template", ["NONEXISTENT_UNIT_HASH_BASE64==", {}]]
   ```
   (`NONEXISTENT_UNIT_HASH_BASE64==` is any syntactically valid but non-existent/irrelevant unit id.)
2. Attacker signs and broadcasts a unit authored by that address (the definition evaluation runs during `validateAuthentifiers` as part of standard unit validation, e.g. via `validation.js` → `Definition.validateAuthentifiers` → `evaluate` → `case 'definition template'`).
3. On any node receiving/validating this unit, `conn.query(... app='definition_template' ...)` returns 0 rows because no such stable `definition_template` message exists.
4. `if (rows.length !== 1) throw Error("not 1 template");` fires inside the SQL callback, escapes as an uncaught exception, and `network.js`'s `uncaughtException` handler crashes the node process [1](#0-0) .
