### Title
Bad-debt write-down frees supplier value but the supply-index floor clamp leaves the "freed" scaled shares payable — wiped suppliers withdraw real cash backed by later deposits — (File: contracts/pool/src/interest.rs)

### Summary
The analog of `kfree_rcu(new_node); ... deref(new_node)` is a free-then-dereference on a financial claim: `apply_bad_debt_to_supply_index` destroys supplier value by scaling `supply_index` down, but clamps it at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of letting the claim reach zero. The wiped position's scaled shares — logically freed — still unscale to a nonzero token amount and are honored by `withdraw`, paying out real pool cash contributed by post-wipeout suppliers. The pool's own unit test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` demonstrates the end-to-end theft: a stranded claim withdraws exactly a fresh supplier's deposit [1](#0-0) .

### Finding Description
When bad debt is socialized (via `clean_bad_debt` → `pool_seize_positions_call` → `ops/seize.rs::apply` → `interest::apply_bad_debt_to_supply_index`), the pool reduces `supply_index` proportionally to the written-off debt [2](#0-1) . If the write-off exceeds supplied value, the index is clamped up to `SUPPLY_INDEX_FLOOR_RAW` instead of reaching zero, so `unscale_supply_floor(old_scaled)` returns a positive amount for a position whose backing was entirely destroyed [3](#0-2) . The withdrawal path (`ops/withdraw.rs::apply` → `cache.resolve_withdrawal` → `require_reserves` → `burn_supply` → `debit_cash` → `transfer_out`) treats that residual scaled balance as a live claim and transfers real tokens [4](#0-3) . Because `cash` bookkeeping and `supplied` share totals no longer include the wiped value, the payout is funded by other suppliers' deposits — `require_backed_market` only gates *new supply*, not withdrawals of the stranded claim [5](#0-4) .

### Impact Explanation
Theft of user funds / protocol insolvency. Every supplier whose position is wiped by a large bad-debt cleanup retains a scaled claim valued at the floored index. Withdrawing it debits `cash` that belongs to other suppliers: the test shows `gross == fresh_cash`, i.e., the wiped account drains exactly a fresh deposit and the pool can no longer cover the fresh supplier's claim [6](#0-5) . Note `docs/reference/invariants.md` INV-IDX-02 mentions the bound "can preserve an unbacked residual claim", but no guard prevents that claim from being paid; the unit test exists precisely because the payout path has no supply-side guard [7](#0-6) .

### Likelihood Explanation
Reachable by a single unprivileged address through `supply` → wait for/trigger conditions producing bad debt → `clean_bad_debt` (permissionless dust-threshold cleanup) → `withdraw(amount = i128::MAX)` on the same or another wiped account. Bad debt beyond total supplied is required for the index to hit the floor; under-collateralized positions plus price movement produce this naturally, and the test shows zero additional privileges are needed once the clamp engages. Any supplier can withdraw their own stranded claim; no timing race or privileged call is involved.

### Recommendation
When `apply_bad_debt_to_supply_index` computes a below-floor index, zero out the stranded claims rather than resurrecting them: either allow `supply_index` to reach `0` and make `unscale_supply_*`/`resolve_withdrawal` return zero on a zero divisor, or track a wipeout flag per market that causes `resolve_withdrawal`/`burn_supply` to treat pre-wipeout scaled balances as zero. At minimum, gate withdrawal payout in `ops/withdraw.rs::accounting` on the position still being backed (`require_reserves` plus a supplied-vs-cash check per leg) so a claim whose value was already socialized cannot transfer out cash [8](#0-7) .

### Proof of Concept
Encoded by the pool's own test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` [1](#0-0) :

1. Market has an old supplier holding `old_scaled = 1000*RAY` scaled shares, index `RAY`, `cash = 0` (fully lent out / under water).
2. `clean_bad_debt` seizes the insolvent borrow; `apply_bad_debt_to_supply_index(cache, 5000*RAY)` would drive `supply_index` to ~0.2·RAY but clamps it **up** to `RAY/1000` [9](#0-8) .
3. `unscale_supply_floor(old_scaled) > 0` — the freed claim still dereferences to tokens [10](#0-9) .
4. A victim supplies `fresh_cash` (mints shares at floored index, `claim == deposit`) [11](#0-10) .
5. Attacker calls `withdraw` with `amount = i128::MAX` on `old_scaled`; `resolve_withdrawal`/`require_reserves`/`burn_supply`/`debit_cash` pay `gross = fresh_cash` — the fresh deposit is drained and `cash < fresh_claim` (insolvency) [12](#0-11) .

Caveat: INV-IDX-02 documents the residual-claim possibility, but it describes the state bound, not an authorization for the claim to be paid out; the payout path contains no corresponding guard, so the theft path stands on the code.

```rust
#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
```

```markdown
### INV-IDX-02 — Supply index is bounded

The supply index stays within 10^24 to 10^36 raw RAY, inclusive. Interest
distribution cannot lower it; bad-debt writeoff applies the lower bound. These
are protocol constants, not per-market governance settings.

The lower bound prevents a zero conversion divisor but can preserve an unbacked
```
