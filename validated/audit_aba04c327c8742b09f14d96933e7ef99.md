## Analog Found

### Title
Arbiter-contract escrow funds can be permanently frozen when the arbiter never resolves the dispute - ([File: arbiter_contract.js])

### Summary
The RocketDAO report describes a challenge/dispute mechanism whose funds get irrecoverably locked because no timeout or fallback spending path was implemented if the counterparty (the challenged node) never responds. The ocore arbiter-contract escrow feature exhibits the same structural flaw: money placed into a two-party escrow (`shared_address`) can only be released by (a) mutual agreement of both parties, or (b) a data-feed message published by the arbiter naming a winner. If the arbiter becomes unresponsive, disappears, or simply refuses to rule (deliberately or through negligence), and the two parties cannot reach mutual agreement, the escrowed funds have no other exit path and remain frozen in the shared address forever.

### Finding Description
`deriveSharedAddress()` builds the address definition governing the escrow used for arbiter contracts: [1](#0-0) 

The definition is an `or` of: (1) mutual `and` of both addresses, and (2)/(3) `and` branches that only release funds to a party if a matching `"CONTRACT_" + hash` (or `"CONTRACT_DONE_" + hash`) key appears in a data feed posted **by the arbiter address** (public-asset case) or by the peer itself (private-asset case): [2](#0-1) 

Funds are paid into this address by the payer via `pay()`: [3](#0-2) 

and are only released via `complete()` after the arbiter's decision (`dispute_resolved`/`in_dispute`) or by mutual completion: [4](#0-3) 

The dispute is opened with `openDispute()`, which sends an HTTP request to the arbstore and merely watches the arbiter's address for a response, with no expiry: [5](#0-4) 

Unlike Oscript address definitions which support time-based release conditions (`age`, `timestamp`, `mci` ops): [6](#0-5) 

the escrow definition built in `deriveSharedAddress()` never uses any of these time-based fallback branches. There is no branch that lets either party reclaim/split the funds after some elapsed time if the arbiter never issues a `CONTRACT_<hash>` data-feed resolution and the counterparty refuses to co-sign a release. This mirrors the RocketDAO issue precisely: a dispute/challenge process that is only "half-implemented" — initiation works, but there is no enforced response window, and funds sent into escrow have no recovery path if the counterpart (arbiter) never acts.

### Impact Explanation
Funds paid into an arbiter-contract escrow (which can be any amount and any asset, public or private) can become permanently unspendable if the arbiter goes offline, refuses to rule, or is compromised/malicious, and the peer does not cooperate on a mutual release. This is a concrete asset-freezing condition reachable purely through the normal wallet/contract-message flow between two paired devices and an arbiter, with no code path in ocore providing a timeout-based escape, exactly as described in the referenced report's "funds ... locked forever ... no means to recover the funds" finding.

### Likelihood Explanation
Any user entering into an arbiter contract is exposed: the arbiter is chosen by mutual agreement of possibly untrusted counterparties, and there is no protocol-level mechanism forcing a decision within a bounded time. An uncooperative or disappearing arbiter (deliberately, through negligence, or shutting down their arbstore service) is a realistic real-world scenario, not requiring any privileged access — only normal use of the arbiter-contract feature by two paired devices.

### Recommendation
Add a time-bound fallback branch to the escrow address definition generated in `deriveSharedAddress()` (e.g., using the `age`/`timestamp` definition operators) allowing funds to be released back to the payer, split according to a pre-agreed default, or unlocked for a new dispute/arbiter selection after a configurable window elapses without an arbiter resolution. Additionally, implement/execute a monitored expiry check in `openDispute()`/watch logic so wallets can proactively react (e.g., notify the user, offer to switch arbiter) instead of relying solely on watching for an arbiter response that may never come.

### Proof of Concept
1. Alice and Bob create an arbiter contract via `createAndSend`/`respond`, designating arbiter Carol, and derive the shared address via `deriveSharedAddress` (arbiter_contract.js:454-575).
2. Alice pays the contract amount into `shared_address` via `pay()` (arbiter_contract.js:692-717).
3. A dispute arises; Bob calls `openDispute()` (arbiter_contract.js:262-319), which notifies Carol's arbstore and starts watching Carol's address, but sets no deadline.
4. Carol never publishes a `CONTRACT_<hash>` data-feed unit (goes offline, refuses, or is compromised) and Bob refuses to co-sign any mutual release with Alice.
5. Because the escrow address definition (arbiter_contract.js:465-538) only allows release via mutual agreement or Carol's data feed, and contains no time-based fallback branch, the funds in `shared_address` remain permanently unspendable — no user, including Alice who funded it, can ever recover them.

function pay(hash, walletInstance, arrSigningDeviceAddresses, cb) {
	getByHash(hash, function(objContract) {
		if (!objContract.shared_address || objContract.status !== "signed" || !objContract.me_is_payer)
			return cb("contract can't be paid");
		var opts = {
			asset: objContract.asset,
			to_address: objContract.shared_address,
			amount: objContract.amount,
			spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own'
		};
		if (arrSigningDeviceAddresses.length)
			opts.arrSigningDeviceAddresses = arrSigningDeviceAddresses;
		walletInstance.sendMultiPayment(opts, function(err, unit){								
			if (err)
				return cb(err);
			setField(objContract.hash, "status", "paid", function(objContract){
				cb(null, objContract, unit);
			});
			// listen for peer announce to withdraw funds
			storage.readAssetInfo(db, objContract.asset, function(assetInfo) {
				if (assetInfo && assetInfo.is_private)
					db.query("INSERT "+db.getIgnore()+" INTO my_watched_addresses (address) VALUES (?)", [objContract.peer_address]);
			});
		});
	});
}

function complete(hash, walletInstance, arrSigningDeviceAddresses, cb) {
	getByHash(hash, async function(objContract) {
		if (objContract.status !== "paid" && objContract.status !== "in_dispute")
			return cb("contract can't be completed");
		const err = await fillArbstoreAddresses(objContract);
		if (err)
			return cb(err);
		storage.readAssetInfo(db, objContract.asset, function(assetInfo) {
			var opts;
			new Promise((resolve, reject) => {
				if (assetInfo && assetInfo.is_private) {
					var value = {};
					value["CONTRACT_DONE_" + objContract.hash] = objContract.peer_address;
					opts = {
						spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own',
						paying_addresses: [objContract.my_address],
						signing_addresses: [objContract.my_address],
						change_address: objContract.my_address,
						messages: [{
							app: 'data_feed',
							payload_location: "inline",
							payload_hash: objectHash.getBase64Hash(value, true),
							payload: value
						}]
					};
					resolve();
				} else {
					opts = {
						spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own',
						paying_addresses: [objContract.shared_address],
						change_address: objContract.shared_address,
						asset: objContract.asset
					};
					if (objContract.me_is_payer && !(assetInfo && (assetInfo.fixed_denominations || assetInfo.is_private))) { // complete
						require("./wallet_defined_by_addresses.js").readSharedAddressDefinition(objContract.shared_address, function (arrDefinition) {
							const index = objContract.is_incoming ? 2 : 1;
							const peer_amount = arrDefinition[1][index][1][1][1].amount;
							const arbstore_amount = arrDefinition[1][index][1][2] && arrDefinition[1][index][1][2][0] === 'has' ? arrDefinition[1][index][1][2][1].amount : 0;
							if (!isFinite(peer_amount) || !isFinite(arbstore_amount))
								throw new Error("invalid amounts in shared address definition: " + JSON.stringify(arrDefinition));
							if (peer_amount + arbstore_amount !== objContract.amount)
								throw new Error(`amounts in shared address definition do not sum up to contract amount: ${peer_amount} + ${arbstore_amount} !== ${objContract.amount}`);
							if (arbstore_amount > peer_amount)
								throw new Error(`arbstore cut is more than 50% of the total amount, peer_amount: ${peer_amount}, arbstore_amount: ${arbstore_amount}`);
							if (arbstore_amount === 0) {
								opts.to_address = objContract.peer_address;
								opts.amount = objContract.amount;
							} else {
								opts[objContract.asset && objContract.asset != "base" ? "asset_outputs" : "base_outputs"] = [
									{ address: objContract.peer_address, amount: peer_amount},
									{ address: objContract.arbstore_address, amount: arbstore_amount},
								];
							}
							resolve();
						});
					} else { // refund
						opts.to_address = objContract.peer_address;
						opts.amount = objContract.amount;
						resolve();
					}
				}
			}).then(() => {
				if (arrSigningDeviceAddresses.length)
					opts.arrSigningDeviceAddresses = arrSigningDeviceAddresses;
				walletInstance.sendMultiPayment(opts, function(err, unit){
					if (err)
						return cb(err);
					var status = objContract.me_is_payer ? "completed" : "cancelled";
					setField(objContract.hash, "status", status, function(objContract){
						cb(null, objContract, unit);
					});
				});
			}).catch(err => {
				cb(err);
			});
		});
	});
}
