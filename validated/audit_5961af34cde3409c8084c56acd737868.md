### Title
Repay path never renews the supply-position map, so a borrower's collateral can silently expire to an empty map while debt stays live — (File: contracts/controller/src/storage/account.rs)

### Summary
The bug class in the report is a read that touches data which was never (or no longer) initialized and silently proceeds on a default. The controller exhibits the same shape: `get_supply_positions` and `get_debt_positions` return `Map::new(env)` when the persistent entry is absent, treating "archived/expired" as "no positions", while `get_account_borrow_only` — used by `repay` — deliberately loads only the debt side and therefore only renews the TTL of `AccountMeta` and `BorrowPositions`, never `SupplyPositions` [1](#0-0) [2](#0-1) . Position-map writes also never renew TTL (`write_side_map` does a bare `persistent.set/remove`) [3](#0-2) .

### Finding Description
Per-entry TTL renewal happens either through `get_user` on the specific key read, or through `renew_user_account`, which renews only keys that currently exist (`persistent.has(key)`), so an already-expired key is skipped permanently [4](#0-3) . `repay` resolves the account via `get_account_borrow_only`, which loads `AccountMeta`, owner, and the debt map, but passes a fresh `Map::new(env)` for supply — so a borrower who only repays (or whose account is only touched by repay-type flows) renews meta and debt entries indefinitely while `SupplyPositions(account_id)` receives no renewal and eventually expires.

Once expired, every reader sees a legitimate but *wrong* empty supply map:

- `calculate_account_risk_totals` iterates `supply_positions` to build `total_collateral` / `weighted_collateral` [5](#0-4) . With the collateral silently zeroed, the account's health factor collapses to ~0 while its real tokens are still inside the pool and still counted in the market's `supplied` scaled-share total.
- `try_get_account` only requires meta + owner; a missing map is not an error [6](#0-5) .
- `liquidate` / `clean_bad_debt` then operate on a debt position with zero recorded collateral: the debt is written down via the supply-index write-down path, socializing the loss to all suppliers of that market, while the orphaned collateral shares remain forever unclaimable inside `supplied` (they have no owner row).

The symmetric case (debt map expiring while supply stays live) is largely defended because `renew_user_account` renews all live keys and verbs like `withdraw`/`borrow` load both maps; but the repay path is explicitly asymmetric by design ("leaves supply deliberately unloaded"), which is exactly the uninitialized-read shape: a missing row is indistinguishable from a legitimately empty one.

### Impact Explanation
Two acceptable-impact outcomes, both reachable by a single unprivileged borrower:

1. **Protocol insolvency / socialized loss**: the borrower keeps `BorrowPositions` alive with dust repays until `SupplyPositions` expires, then stops. `clean_bad_debt` finds debt with no collateral and performs a supply-index write-down, transferring the loss to all suppliers even though the collateral tokens are still physically in the pool.
2. **Permanent freezing of funds**: the expired supply shares can never be withdrawn by anyone — the position row is gone, `withdraw`/`supply` reconstruct from the (empty) map, and `supplied` still includes the shares, so the tokens are locked in the pool contract permanently.

### Likelihood Explanation
Severity **Medium**. Triggering requires only that the supply-position entry outlive its TTL without any path that calls `renew_user_account` or loads the supply map — a borrower performing periodic small `repay` calls (renewing meta + debt via `get_user` reads) while never supplying, withdrawing, or being touched by `update_account_threshold` achieves exactly this. Persistent-entry TTL expiry is an ordinary Soroban condition over an inactivity window, not an attacker-consumed resource; however, it is passive (relies on TTL lapse rather than a single crafted call), and the window is bounded by `TTL_BUMP_SHARED`/`TTL_THRESHOLD_SHARED`, which keeps it out of Critical/High territory.

### Recommendation
- Make `repay` (and any other borrow-only path) also renew the supply-map key when it exists — e.g., call `renew_user_account(env, account_id)` or an explicit `extend_ttl` on `ControllerKey::SupplyPositions(account_id)` inside `get_account_borrow_only`.
- Distinguish "never existed" from "expired": consider storing a tombstone/flag in `AccountMeta` (e.g., `has_supply`) so a missing map on a collateralized account fails closed rather than reading as empty.
- More generally, treat missing-but-expected position rows as an invariant violation (`expect_invariant`) in risk-critical paths instead of defaulting to `Map::new(env)`.

### Proof of Concept
1. User calls `supply` (creates `account_id` N) with collateral asset A on spoke S, then `borrow` asset B up to near max LTV. Both `SupplyPositions(N)` and `BorrowPositions(N)` are written.
2. User repeats `repay(N, B, dust_amount)` on a schedule shorter than the persistent TTL. Each call goes through `get_account_borrow_only` (`contracts/controller/src/storage/account.rs:167`), renewing `AccountMeta(N)` and `BorrowPositions(N)` only.
3. After the supply-map TTL lapses without any `withdraw`/`supply`/`borrow`/`update_account_threshold` touching it, `persistent.has(&SupplyPositions(N))` is false; all subsequent reads return `Map::new(env)` (`account.rs:67`).
4. `update_indexes`/`liquidate` now compute `weighted_collateral = 0` against the live debt → HF ≈ 0. The borrower abandons the account.
5. Any unprivileged liquidator calls `clean_bad_debt`; the pool performs the supply-index write-down for the full debt amount, while the real collateral shares remain inside `supplied` with no owner — loss is borne by suppliers and the collateral tokens are permanently unwithdrawable.

Uncertainty note: I did not confirm the exact TTL durations nor whether `repay` elsewhere in the codebase calls `renew_user_account` (which would renew both live keys and close this path); if `repay` does renew the whole account entry set, the supply-expiry branch is not reachable and only the shorter debt-side asymmetry remains, weakening this to a near-miss.

/// Stores a nonempty position map without renewing TTL; deletes an empty map.
fn write_side_map<V: TryFromVal<Env, Val> + IntoVal<Env, Val>>(
    env: &Env,
    key: &ControllerKey,
    map: &Map<HubAssetKey, V>,
) {
    let persistent = env.storage().persistent();
    if map.is_empty() {
        persistent.remove(key);
    } else {
        persistent.set(key, map);
    }
}

/// Renews user TTL for each existing account entry; does not renew the NFT.
pub(crate) fn renew_user_account(env: &Env, account_id: u64) {
    let persistent = env.storage().persistent();
    let keys = [
        ControllerKey::AccountMeta(account_id),
        ControllerKey::SupplyPositions(account_id),
        ControllerKey::BorrowPositions(account_id),
        ControllerKey::Delegates(account_id),
    ];
    for key in &keys {
        if persistent.has(key) {
            renew_user_key(env, key);
        }
    }
}
