### Title
Large debt accrual can permanently freeze a market through RAY-value overflow - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large market can make `borrowed * borrow_index` exceed the `i128` domain before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`. Because every pool mutation synchronizes interest before changing state, the first `MathOverflow` becomes persistent and blocks repayment, withdrawal, liquidation, revenue claims, and further index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` calls `scaled_to_original(env, borrowed, borrow_index)`, which is `scaled.mul(env, index)`, before applying the borrow-index cap. [3](#0-2) [4](#0-3)  `Ray::mul` routes to `mul_div_half_up`, which panics with `GenericError::MathOverflow` when the exact result does not fit `i128`. [5](#0-4) [6](#0-5)  Although `update_borrow_index` caps the resulting index, that cap is evaluated only after the earlier debt-value multiplication has already panicked. [7](#0-6) 

The same accrual runs at the start of ordinary market legs through `synced_market` or `load_leg`, including repay and withdraw, and is directly invoked by `update_indexes`. [8](#0-7) [9](#0-8) [10](#0-9) [11](#0-10)  The controller exposes `update_indexes(caller, assets)` as a permissionless authenticated entrypoint. [12](#0-11) 

### Impact Explanation
Once `borrowed * borrow_index` crosses the representable RAY-value domain, every operation that could reduce debt or remove supply first repeats the overflowing accrual and reverts. [8](#0-7)  Supplier principal and yield, borrower collateral associated with the market, and unclaimed protocol revenue become inaccessible through normal pool operations; the in-repo reproducer explicitly confirms that both withdrawal and repayment fail with `MATH_OVERFLOW`. [13](#0-12)  This is permanent freezing of funds absent a contract upgrade, not merely a temporary price outage or fail-closed check.

### Likelihood Explanation
Reaching the condition requires an exceptionally large position and sustained high utilization, so it is capital-intensive rather than a low-cost transaction. The code nevertheless permits the state transition: `supply` and `borrow` build the scaled balances, permissionless `update_indexes` advances accrual, and `accrue_step` performs the overflowing multiplication before any index bound is applied. [14](#0-13) [12](#0-11) [15](#0-14)  The existing test demonstrates the failure below the nominal borrow-index ceiling, proving that the index cap does not protect the RAY-value domain. [16](#0-15) 

### Recommendation
Bound market debt and supply values against the maximum representable `scaled * index` result, rather than only bounding the indexes themselves. In particular, reject borrow or supply growth that could make `scaled_to_original` overflow under `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY`, or use a checked/saturating value calculation that still permits repayment and withdrawal paths to execute safely. Add a protocol-level regression covering high-utilization markets near the `i128` RAY-value boundary.

### Proof of Concept
The repository contains a reproducible harness test, `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`, which:

1. Creates an 18-decimal debt market and a collateral market.
2. Supplies `1_000_000_000 * 10^18` base units of the debt asset and sufficient collateral.
3. Borrows 98% of the supplied amount.
4. Repeatedly advances time and invokes the permissionless `update_indexes` path.
5. Observes `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.
6. Confirms subsequent `withdraw` and `repay` calls also fail with `MATH_OVERFLOW`. [17](#0-16) 

On-chain, the equivalent unprivileged trigger is `Controller::update_indexes(caller, vec![hub_asset])` after the market has accumulated a sufficiently large scaled debt at high utilization.

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
