### Title
Accrual value-overflow panic permanently freezes a saturated market — every state-changing entrypoint traps before acting - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs), [File: contracts/pool/src/interest.rs](contracts/pool/src/interest.rs))

### Summary
The GPAC CVE is a reachable crash primitive (invalid pointer dereference → process DoS). The structural analog in XOXNO Lending is a reachable arithmetic trap in the shared accrual path: `accrue_step` calls `scaled_to_original`, which multiplies `borrowed * borrow_index / RAY` and `supplied * supply_index / RAY` via `Ray::mul` → `mul_div_half_up`, panicking with `GenericError::MathOverflow` when the product no longer fits `i128`. Because the pool runs `global_sync` before every mutating verb, once a market's scaled totals or indexes cross that product bound, the panic is hit unconditionally on the next `update_indexes` — and from then on *every* verb on that market (repay, withdraw, liquidate, clean_bad_debt, recapitalize) reverts before doing any work. The borrow-index ceiling at `MAX_BORROW_INDEX_RAY` clamps the *index* but not the *value* `borrowed * index`, so the cap never saves it; the test suite demonstrates the market frozen with `last.borrow_index < MAX_BORROW_INDEX_RAY`.

### Finding Description
`accrue_step` computes `borrowed_original = scaled_to_original(env, borrowed, borrow_index)` and `supplied_original = scaled_to_original(env, supplied, supply_index)` before anything else [1](#0-0) . `scaled_to_original` is a plain `scaled.mul(env, index)` [2](#0-1)  backed by `mul_div_half_up`, which panics with `MathOverflow` when the `x * y` product or quotient overflows `i128` [3](#0-2) . The pool's `global_sync` invokes `accrue_step` via `accrue_chunk` on every call that needs accrual [4](#0-3) , and all user verbs (supply/borrow/withdraw/repay/liquidate/clean_bad_debt/flash paths) accrue first.

`update_borrow_index` clamps the *index* at `10^36` but multiplies before clamping and, crucially, does nothing about `borrowed * borrow_index` overflowing [5](#0-4) . The repo's own harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` proves reachability end-to-end through unprivileged calls: `supply_raw`, `borrow_raw`, then `advance_time` + `update_indexes` until `try_update_indexes_for` fails with `MATH_OVERFLOW`, after which both `try_withdraw_raw` and `try_repay` also fail with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY` [6](#0-5) . The panic cannot be unwound past: interest is monotone, indexes never decrease from accrual, and `clean_bad_debt`/write-down paths also accrue first — so the trap is permanent for that market, not a transient revert.

### Impact Explanation
Permanent freezing of all funds in the affected book: suppliers cannot withdraw, borrowers cannot repay (so their collateral elsewhere is locked or liquidatable only in other markets), liquidators cannot liquidate debt in this book, and `clean_bad_debt`/`recapitalize` cannot recover it. Every reachable entrypoint for the market traps in `accrue_step` before touching state. This maps directly to the CVE's "crash on reach" class, but on-chain it is strictly worse than a process DoS: the state is unrecoverable because no code path skips accrual on the frozen book. Severity: **Medium** — the impact is a total, permanent market freeze, but mounting it requires a book near the admitted cap domain (~170B whole-token RAY ceiling) held at high utilization for sustained time.

### Likelihood Explanation
Reachable entirely by unprivileged calls: `supply`/`borrow`/`update_indexes` with no governance action required at trigger time. Cost is real but bounded by the protocol's own admitted domain: the harness fills a ~1-billion-token 18-decimal market to 98% utilization on the steep 175%-APR stress curve and hits the cliff in a few years of ledger time; on high-supply tokens (or lower-decimal assets where `borrowed` is larger in RAY terms) the threshold is lower since the overflow is on `scaled * index`, not on token count. Any single motivated whale, or organic drift of an untouched high-utilization book, gets there. Once crossed, there is no recovery verb. Note the docs acknowledge value overflow can precede the index ceiling [7](#0-6) , but awareness does not restore frozen funds — no mitigation path exists in the deployed code.

### Recommendation
Make accrual fail-safe at the value-overflow boundary rather than trapping the whole market. Options: (a) in `accrue_step`/`scaled_to_original`, saturate the computed originals to `i128::MAX` for the *utilization/rate* calculation only (the rate then just pegs at the curve maximum and the index clamps at `MAX_BORROW_INDEX_RAY`), while keeping panicking conversions for per-position debit/credit paths; (b) gate `global_sync` so that when the borrow index is already at `MAX_BORROW_INDEX_RAY` it stops compounding instead of multiplying further; (c) add a market-level freeze flag that repayment/withdrawal/liquidation entrypoints can traverse with accrual skipped. At minimum, emit/index an event when a book approaches the cliff and lower `max_utilization` so utilization cannot sit in the runaway segment indefinitely.

### Proof of Concept
Covered by the repo's own harness test — it is a concrete, executable PoC:

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);              // unprivileged supply
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);                 // unprivileged borrow @98% util

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }  // anyone can call
}
// -> MathOverflow from scaled_to_original inside accrue_step
// Market is now permanently frozen:
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
assert!(last.borrow_index < MAX_BORROW_INDEX_RAY);  // index cap never engaged
```

The trigger path is `update_indexes` → `global_sync` → `accrue_chunk` → `accrue_step` → `scaled_to_original(borrowed, borrow_index)` → `mul_div_half_up` → `panic_with_error!(MathOverflow)`. Because `global_sync` runs before every verb, `withdraw`, `repay`, `liquidate`, and `clean_bad_debt` all hit the identical panic — the market is bricked for all participants, permanently.

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );
```

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
