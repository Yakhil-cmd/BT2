## Title
Stack-scoped `ApiClient` tokens can read the CI/build status of any stack via the CCMenu endpoint (`Stack` scoping bypass) - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::ApiClient` supports scoping a token to a single stack via its `stack_id` column, and every API controller is expected to resolve the target `stack` through the scoped `stacks` relation so a client can only touch the stack it was authorized for. `Api::CCMenuController` overrides this resolution and looks the stack up directly against the global `Stack` table, bypassing the scoping entirely.

### Finding Description
`BaseController` defines the token-to-stack binding: a client scoped to a stack should only ever resolve stacks from that restricted relation. [1](#0-0) 

Every other API controller (`DeploysController`, `TasksController`, `CommitsController`, `RollbacksController`, `MergeRequestsController`, `OutputsController`, `ReleaseStatusesController`) inherits `stack` unmodified, so `require_permission :read, :stack` combined with `stacks.from_param!` together enforce "this token's `read:stack` permission applies only to the stack it is bound to."

`Api::CCMenuController` breaks that binding by redefining `stack` to query the unrestricted `Stack` model directly, ignoring `current_api_client.stack_id`: [2](#0-1) 

The `require_permission :read, :stack` check only validates that the token carries the `read:stack` permission string via `ApiClient#check_permissions!`, which never inspects `stack_id`: [3](#0-2) 

Because `stack` is resolved from `params[:stack_id]` against the entire `Stack` table instead of the client-scoped `stacks` relation, the equality the engine is supposed to preserve —
`stack the token is authorized for == stack the request acts on`
— is broken specifically in this controller: any stack ID (or slug) can be substituted, and the controller will happily render that other stack's build/CI data.

### Impact Explanation
A token deliberately scoped to a single stack (`ApiClient#stack_id` set, intended to restrict a low-trust integration — e.g. a CI dashboard widget — to its own stack's data) can be replayed against `Api::CCMenuController#show` with a different `stack_id` and successfully read another stack's deploy/build status (name, last build status/label, timestamps) via `render('shipit/ccmenu/project', ...)`. This is an unauthorized cross-stack read that the token's scoping was explicitly designed to prevent, matching the "unauthenticated/unauthorized read of stack state" class of impact.

### Likelihood Explanation
Exploitation requires possessing any valid `ApiClient` token scoped to one stack with `read:stack` permission — no admin/session/GitHub credentials are needed, and no special conditions beyond swapping the `stack_id` request parameter. This is a straightforward, deterministic bypass rather than a race condition or timing issue.

### Recommendation
Make `Api::CCMenuController#stack` resolve through the scoped `stacks` relation (as `BaseController` does), e.g. `stacks.from_param!(params[:stack_id])`, so the `stack_id` scoping on `ApiClient` is honored consistently across all controllers.

### Proof of Concept
1. Admin creates an `ApiClient` scoped to `Stack A` (`stack_id: A.id`, `permissions: ['read:stack']`), intended only for a CCMenu widget showing Stack A's status.
2. Attacker (holder of that token, e.g. embedded in a public CI dashboard config) sends:
   `GET /api/stacks/<STACK_B_ID_OR_SLUG>/ccmenu.xml` using Basic auth with the Stack-A-scoped token.
3. `Api::CCMenuController#authenticate_api_client` authenticates the token via `ApiClient.authenticate(params[:token])` (or the shared Basic-auth path), `require_permission :read, :stack` succeeds because the token has `read:stack` in its permission list.
4. `stack` resolves via `Stack.from_param!(params[:stack_id])` — not the scoped `stacks` relation — returning `Stack B`, and the XML for Stack B's latest deploy is rendered, even though the token was only meant to authorize Stack A. [4](#0-3)

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
