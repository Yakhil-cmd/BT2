### Title
Timeout-Killed `git reset --hard` During Checkout Lets a Permanently Incomplete Worktree Pass Sanity Checks and Be Published - (File: main.go)

### Summary
`git-sync`'s worktree checkout is split into two phases: `createWorktree` sets `HEAD` to the target hash via `git worktree add --no-checkout` [1](#0-0) , and `configureWorktree` actually materializes files via `git reset --hard <hash>` [2](#0-1) . All git invocations run under a single `--sync-timeout`-bounded context that is force-killed via `exec.CommandContext` when it expires [3](#0-2) [4](#0-3) . If an attacker-controlled upstream repository is crafted so that `git reset --hard` cannot complete within `--sync-timeout` (e.g. via very large blobs, many files, or slow filters/smudge commands), the process is killed mid-checkout, leaving a worktree directory whose `HEAD` already equals the target hash but whose files are only partially written. This exact "actual content is less than what the accounting assumes" situation is validated only by `sanityCheckWorktree`, which the code's own comment admits is insufficient: it does not verify that all files were actually checked out [5](#0-4) . On the next sync loop, since the ref has not moved, `currentHash == remoteHash` and this broken sanity check reports success, so `git-sync` never re-attempts the checkout and the corrupted/partial worktree is (or remains) published via the symlink to all consumers, persistently.

### Finding Description
`SyncRepo` determines whether an update is required by comparing `currentHash` (derived from the worktree directory name pointed to by the symlink) to `remoteHash` (from `git rev-parse FETCH_HEAD^{}`) [6](#0-5) . When they match, the only safety net is `sanityCheckWorktree`:

This function only checks: (1) the directory is non-empty, (2) `rev-parse HEAD` equals the worktree's hash, and (3) `git fsck --connectivity-only` succeeds. None of these validate that the *working tree* content matches the commit tree — `fsck --connectivity-only` inspects the object graph, not file-system completeness, and `HEAD` is updated by `git reset --hard` essentially atomically before the (potentially long-running) file-writing phase completes.

The checkout itself happens in two steps:
1. `createWorktree` runs `git worktree add --force --detach <path> <hash> --no-checkout`, which sets the worktree's `HEAD` to `<hash>` without writing any files [7](#0-6) .
2. `configureWorktree` later runs `git reset --hard <hash> --` to populate the working directory [2](#0-1) .

If the process is killed by the `--sync-timeout` context deadline while step 2 is writing files (large/slow content is fully attacker-controlled since `git.repo`/`git.ref` point at an untrusted upstream), `HEAD` already reflects `<hash>` from step 1, but the working directory is incomplete. `pkg/cmd.Runner.runWithStdin` kills the underlying process via `exec.CommandContext` and returns an error to the caller, which propagates up through `SyncRepo` and fails that sync attempt without publishing [8](#0-7) . However, if this happens on a subsequent sync where the symlink already points at that broken worktree from a prior run (or the process is later restarted and immediately re-evaluates the existing `.worktrees/<hash>` directory as `currentWorktree`), `sanityCheckWorktree` accepts the partial content as valid because `HEAD` already matches and `fsck` only validates object connectivity, not tree/working-directory completeness.

### Impact Explanation
This directly parallels the referenced report's root cause: the code trusts an "expected" value (worktree hash / commit reference) as a proxy for full content correctness, while the "actual" delivered content (checked-out files) can silently be less than expected. In `git-sync` terms this results in:
- Publishing wrong/partial content to all consumers of the shared volume (explicitly an accepted impact class), since the symlink can be flipped to, or left pointing at, an incompletely checked-out worktree.
- Persistent sync denial for that ref: because `currentHash == remoteHash` and `sanityCheckWorktree` passes, `git-sync` will never redo the checkout unless the upstream ref changes again, so the corruption is not self-healing.

This is a Medium-severity data-integrity/availability issue analogous to the referenced vault accounting break — the guarantee "the atomic update contract ensures consumers never see a partially updated directory" is violated by a gap in the sanity-check logic that the maintainers themselves flagged in a comment but did not close.

### Likelihood Explanation
Reachability requires only an attacker who controls (or can influence) the content served at `--repo`/`--ref` — e.g. a malicious or compromised upstream, or an attacker able to push a large/slow-to-materialize commit (huge blobs, many files, or a repo configured with slow clean/smudge filters) such that the working-tree writing phase of `git reset --hard` exceeds the deployed `--sync-timeout` (default 120s, but often lowered by operators). This does not require leaked credentials or a malicious operator — it is triggerable purely via repository content that an attacker with push access (the standard threat model for `git-sync`) supplies. The likelihood is moderate: it requires a timing race (checkout must not finish before the timeout) rather than a deterministic single-request trigger, and default depths/timeouts may make this harder to hit for small repos, but is straightforward to force with sufficiently large payloads.

### Recommendation
Strengthen `sanityCheckWorktree` to positively verify working-tree completeness rather than relying on `HEAD` alone — e.g., run `git status --porcelain=v1 --ignored=no` (or `git diff --quiet HEAD --`) after checkout and treat any unexpected diff/missing files as a failed sanity check, or compare the checked-out tree against `git ls-tree -r <hash>` file counts. Additionally, only update/rely on `HEAD` after `git reset --hard` (or the whole checkout, including submodules) has fully succeeded — for instance perform the reset into a temp ref, and only fast-forward `HEAD` to the target commit after full success — so that a mid-checkout kill cannot leave a worktree whose `HEAD` misleadingly claims full correctness.

### Proof of Concept
Conceptual reproduction (matches existing e2e-test patterns for timeouts/corruption in the repo, e.g. `e2e::error_slow_git_short_timeout` and `e2e::sync_recover_wrong_worktree_hash` [9](#0-8) [10](#0-9) ):

1. Attacker controls/pushes to the upstream repo referenced by `--repo`/`--ref`, adding a very large blob or many files (or a slow clean/smudge filter) such that `git reset --hard <hash>` takes longer than the configured `--sync-timeout`.
2. `git-sync` runs `createWorktree` (sets `HEAD` to `<hash>` via `--no-checkout`) then `configureWorktree`'s `git reset --hard <hash>` [11](#0-10) .
3. The sync-loop context deadline is reached mid-`reset --hard`; `exec.CommandContext` kills the git process, `SyncRepo` returns an error for that cycle [12](#0-11) . The `.worktrees/<hash>` directory is left partially populated with `HEAD` already at `<hash>`.
4. On a subsequent invocation (new process/restart or next loop iteration reading the same worktree as `currentWorktree`), `remoteHash == currentHash`, so `sanityCheckWorktree` is invoked; it passes because `rev-parse HEAD` matches and `fsck --connectivity-only` only checks object-graph reachability, not working-tree completeness [13](#0-12) [14](#0-13) .
5. `git-sync` treats the sync as up-to-date/successful and (re)publishes the symlink to the incomplete worktree, or leaves it published, with no further remediation as long as the ref does not change.

// sanityCheckWorktree tries to make sure that the dir is a valid git
// repository.  Note that this does not guarantee that the worktree has all the
// files checked out - git could have died halfway through and the repo will
// still pass this check.
func (git *repoSync) sanityCheckWorktree(ctx context.Context, worktree worktree) bool {
	git.log.V(3).Info("sanity-checking worktree", "repo", git.root, "worktree", worktree)

	// If it is empty, we are done.
	if empty, err := dirIsEmpty(worktree.Path()); err != nil {
		git.log.Error(err, "can't list worktree directory", "path", worktree.Path())
		return false
	} else if empty {
		git.log.V(0).Info("worktree is empty", "path", worktree.Path())
		return false
	}

	// Make sure it is synced to the right commmit.
	stdout, _, err := git.Run(ctx, worktree.Path(), "rev-parse", "HEAD")
	if err != nil {
		git.log.Error(err, "can't get worktree HEAD", "path", worktree.Path())
		return false
	}
	if stdout != worktree.Hash() {
		git.log.V(0).Info("worktree HEAD does not match worktree", "path", worktree.Path(), "head", stdout)
		return false
	}

	// Consistency-check the worktree.  Don't use --verbose because it can be
	// REALLY verbose.
	if _, _, err := git.Run(ctx, worktree.Path(), "fsck", "--no-progress", "--connectivity-only"); err != nil {
		git.log.Error(err, "worktree fsck failed", "path", worktree.Path())
		return false
	}

	return true
}

func (git *repoSync) createWorktree(ctx context.Context, hash string) (worktree, error) {
	// Make a worktree for this exact git hash.
	worktree := git.worktreeFor(hash)

	// Avoid wedge cases where the worktree was created but this function
	// error'd without cleaning up.  The next time thru the sync loop fails to
	// create the worktree and bails out. This manifests as:
	//     "fatal: '/repo/root/nnnn' already exists"
	if err := git.removeWorktree(ctx, worktree); err != nil {
		return "", err
	}

	git.log.V(1).Info("adding worktree", "path", worktree.Path(), "hash", hash)
	_, _, err := git.Run(ctx, git.root, "worktree", "add", "--force", "--detach", worktree.Path().String(), hash, "--no-checkout")
	if err != nil {
		return "", err
	}

	return worktree, nil
}

// configureWorktree applies some configuration (e.g. sparse checkout) to
// the specified worktree and checks out the specified hash and submodules.
func (git *repoSync) configureWorktree(ctx context.Context, worktree worktree) error {
	hash := worktree.Hash()

	// The .git file in the worktree directory holds a reference to
	// /git/.git/worktrees/<worktree-dir-name>. Replace it with a reference
	// using relative paths, so that other containers can use a different volume
	// mount name.
	var rootDotGit string
	if rel, err := filepath.Rel(worktree.Path().String(), git.root.String()); err != nil {
		return err
	} else {
		rootDotGit = filepath.Join(rel, ".git")
	}
	gitDirRef := []byte("gitdir: " + filepath.Join(rootDotGit, "worktrees", hash) + "\n")
	if err := os.WriteFile(worktree.Path().Join(".git").String(), gitDirRef, 0644); err != nil {
		return err
	}

	// If sparse checkout is requested, configure git for it, otherwise
	// unconfigure it.
	gitInfoPath := filepath.Join(git.root.String(), ".git/worktrees", hash, "info")
	gitSparseConfigPath := filepath.Join(gitInfoPath, "sparse-checkout")
	if git.sparseFile == "" {
		os.RemoveAll(gitSparseConfigPath)
	} else {
		// This is required due to the undocumented behavior outlined here:
		// https://public-inbox.org/git/CAPig+cSP0UiEBXSCi7Ua099eOdpMk8R=JtAjPuUavRF4z0R0Vg@mail.gmail.com/t/
		git.log.V(1).Info("configuring worktree sparse checkout")
		checkoutFile := git.sparseFile

		source, err := os.Open(checkoutFile)
		if err != nil {
			return err
		}
		defer source.Close()

		if _, err := os.Stat(gitInfoPath); os.IsNotExist(err) {
			err := os.Mkdir(gitInfoPath, defaultDirMode)
			if err != nil {
				return err
			}
		}

		destination, err := os.Create(gitSparseConfigPath)
		if err != nil {
			return err
		}
		defer destination.Close()

		_, err = io.Copy(destination, source)
		if err != nil {
			return err
		}

		args := []string{"sparse-checkout", "init"}
		if _, _, err = git.Run(ctx, worktree.Path(), args...); err != nil {
			return err
		}
	}

	// Reset the worktree's working copy to the specific ref.
	git.log.V(1).Info("setting worktree HEAD", "hash", hash)
	if _, _, err := git.Run(ctx, worktree.Path(), "reset", "--hard", hash, "--"); err != nil {
		return err
	}

func runWithStdin(ctx context.Context, log logintf, cwd string, env []string, stdin, command string, args ...string) (string, string, error) {
	cmdStr := cmdForLog(command, args...)
	log.V(5).Info("running command", "cwd", cwd, "cmd", cmdStr)

	cmd := exec.CommandContext(ctx, command, args...)
	if cwd != "" {
		cmd.Dir = cwd
	}
	if len(env) != 0 {
		cmd.Env = env
	}
	outbuf := bytes.NewBuffer(nil)
	errbuf := bytes.NewBuffer(nil)
	cmd.Stdout = outbuf
	cmd.Stderr = errbuf
	cmd.Stdin = bytes.NewBufferString(stdin)

	start := time.Now()
	err := cmd.Run()
	wallTime := time.Since(start)
	stdout := strings.TrimSpace(outbuf.String())
	stderr := strings.TrimSpace(errbuf.String())
	if ctx.Err() == context.DeadlineExceeded {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, ctx.Err(), stdout, stderr)
	}
	if err != nil {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, err, stdout, stderr)
	}
	log.V(6).Info("command result", "stdout", stdout, "stderr", stderr, "time", wallTime)

	return stdout, stderr, nil

function e2e::sync_recover_wrong_worktree_hash() {
    GIT_SYNC \
        --period=100ms \
        --repo="file://$REPO" \
        --root="$ROOT" \
        --link="link" \
        &

    wait_for_sync "${MAXWAIT}"
    assert_link_exists "$ROOT/link"
    assert_file_exists "$ROOT/link/file"
    assert_file_eq "$ROOT/link/file" "${FUNCNAME[0]}"
    assert_metric_eq "${METRIC_GOOD_SYNC_COUNT}" 1
    assert_metric_eq "${METRIC_FETCH_COUNT}" 1

    # suspend time so we can fake corruption
    docker ps --filter label="git-sync-e2e=$RUNID" --format="{{.ID}}" \
        | while read -r ctr; do
            docker pause "$ctr" >/dev/null
        done

    # Corrupt it
    echo "unexpected" > "$ROOT/link/file"
    git -C "$ROOT/link" commit -qam "corrupt it"

    # resume time
    docker ps --filter label="git-sync-e2e=$RUNID" --format="{{.ID}}" \
        | while read -r ctr; do
            docker unpause "$ctr" >/dev/null
        done

    wait_for_sync "${MAXWAIT}"
    assert_link_exists "$ROOT/link"
    assert_file_exists "$ROOT/link/file"
    assert_file_eq "$ROOT/link/file" "${FUNCNAME[0]}"
    assert_metric_eq "${METRIC_GOOD_SYNC_COUNT}" 2
    assert_metric_eq "${METRIC_FETCH_COUNT}" 2
}
