The report concerns a nonce-length/overflow defect in the TypeScript `js-libp2p-noise` library's handshake implementation, which is unrelated to how Substrate's networking stack integrates Noise. Substrate uses the external `libp2p`/`snow` Rust crates for its Noise transport rather than a custom nonce implementation [1](#0-0) [2](#0-1) , so this would at best be a dependency-only finding on an external crate, not polkadot-sdk's own production code, and it is excluded by the scan methodology's rejection of dependency-only findings.

More importantly, the methodology requires a real user entry point — a signed extrinsic, contract call, XCM message, or public proof submission — reachable by an attacker with no privileged role. Noise handshake nonce handling operates purely at the peer-to-peer transport/session layer between nodes, before any FRAME pallet, XCM executor, or contract logic is reached; it is not reachable through any extrinsic, XCM instruction, or contract call path. This places it outside the required scope of "attacker-controlled input through a real user entry" into runtime state, and it does not map onto any of the FRAME/XCM/bridge invariants (issuance, nonce/replay in `frame_system::CheckNonce` [3](#0-2) , staking shares, contract deposits, bridge lane/nonce binding) that this scan is meant to analyze.

No FRAME/XCM/runtime analog with a genuine attacker-controlled entry point, checks bypass, and measurable loss was found for this report.
