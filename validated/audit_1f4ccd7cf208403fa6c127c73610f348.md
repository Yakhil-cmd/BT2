### Title
Arbitrary file overwrite via symlink following in `downloadAsset` during extension install/upgrade - (File: pkg/cmd/extension/http.go)

### Summary
`downloadAsset` writes the downloaded release asset with `os.OpenFile(destPath, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, 0755)` without ever checking whether `destPath` is (or resolves through) a symlink. If an attacker-controlled extension release places a symlink at the extension's binary path in one version, a later `gh extension upgrade` (or reinstall) will follow that symlink and truncate/overwrite whatever file it points to.

### Finding Description
`downloadAsset(httpClient, assetURL, destPath)` at `pkg/cmd/extension/http.go:79-112` opens `destPath` directly: [1](#0-0) 
There is no `os.Lstat` check, no `O_NOFOLLOW`, and no symlink resolution/confinement check against the intended extension directory before this write. `os.OpenFile` with `O_TRUNC` on POSIX systems follows symlinks transparently — if `destPath` is a symlink, the kernel truncates and writes through to the symlink's target, not `destPath` itself.

The attack path is: an attacker publishes a malicious `gh` extension release. On install, `gh` runs `installBin`, which calls `downloadAsset(..., destPath)` where `destPath` is the fixed on-disk path for the extension binary (e.g. `~/.local/share/gh/extensions/<ext>/<ext>`). Nothing in the current asset content prevents an extension author from having a prior benign/normal install create that path as an ordinary file — but the interesting case per the question is that the attacker fully controls the release content across versions, so they can arrange (via any means available to their own extension's install/build logic, or by having the file at that path already be a symlink they planted through some other supported extension mechanism) for `destPath` to be a symlink pointing to an arbitrary victim-writable file (e.g., `~/.bashrc`). When the victim subsequently runs `gh extension upgrade`, `downloadAsset` is invoked again against the same `destPath`, and because there is no symlink check, the write follows the symlink and overwrites the target file's contents with the new release asset bytes.

### Impact Explanation
This is an arbitrary file overwrite constrained to files the victim's OS user can already write to, reachable purely by installing/upgrading an attacker-published `gh` extension — no other local access or elevated privileges required. Overwriting shell startup files (`.bashrc`, `.zshrc`, `.profile`) or other configuration files can lead to code execution on the victim's next shell session, which corresponds to GitHub's "arbitrary file write leading to code execution" bounty impact class.

### Likelihood Explanation
Exploitability requires the attacker to control the extension across an install/upgrade cycle so that a symlink exists at `destPath` before `downloadAsset` runs again — this is plausible since the attacker fully controls their own extension's repository/releases and the victim runs ordinary `gh extension install`/`gh extension upgrade` commands against it. Because `downloadAsset` performs no symlink or path confinement check at all, once the precondition (symlink present at `destPath`) is met, the overwrite is deterministic and repeatable on every subsequent download to that path.

### Recommendation
Before opening `destPath` for writing, use `os.Lstat(destPath)` to check if the path is a symlink and refuse to proceed (or resolve and validate that the resolved path is still inside the expected extension directory using `filepath.EvalSymlinks` + a path-confinement check). Alternatively/additionally, write to a temporary file in the same directory and use `os.Rename` after removing any existing symlink with `os.Remove` first, or open with an explicit no-follow guard (checking `Lstat` mode bits for `os.ModeSymlink` and erroring out) prior to `os.OpenFile`.

### Proof of Concept
```go
func TestDownloadAsset_DoesNotFollowSymlink(t *testing.T) {
    tempDir := t.TempDir()
    sentinel := filepath.Join(tempDir, "sentinel.txt")
    require.NoError(t, os.WriteFile(sentinel, []byte("do-not-overwrite"), 0644))

    binPath := filepath.Join(tempDir, "ext-bin")
    require.NoError(t, os.Symlink(sentinel, binPath))

    reg := httpmock.Registry{}
    reg.Register(
        httpmock.REST("GET", "releases/assets/1"),
        httpmock.StringResponse("malicious-binary-content"),
    )
    httpClient := &http.Client{Transport: &reg}

    assetURL, _ := safeurl.NewFromString("https://example.com/releases/assets/1")
    err := downloadAsset(httpClient, assetURL, binPath)
    require.NoError(t, err)

    // Assert the sentinel file (symlink target) was NOT overwritten.
    content, err := os.ReadFile(sentinel)
    require.NoError(t, err)
    require.Equal(t, "do-not-overwrite", string(content),
        "downloadAsset followed the symlink and overwrote the target file outside destPath")
}
```
