### Title
Webhook signature verification selects the GitHub App/secret from an unauthenticated payload field, letting a low-trust organization's config bypass checks for a different organization's repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which per-organization webhook secret to validate the request against using a value taken directly from the untrusted JSON body, not from anything already authenticated. In multi-GitHub-App deployments this breaks the binding "organization whose secret authenticated the request" == "repository the webhook payload actually causes writes for."

### Finding Description
The controller resolves the signing secret to use like this: [1](#0-0) [2](#0-1) 

`repository_owner` is read straight out of `params.dig('repository', 'owner', 'login')` (or `organization.login`), before any signature has been checked, and is used to select which `GitHubApp` instance (and therefore which `webhook_secret`) will validate the request: [3](#0-2) 

`GitHubApp#verify_webhook_signature` trivially returns `true` when that organization's `webhook_secret` is blank: [4](#0-3) 

Meanwhile, the code that actually acts on the payload (creating stacks, syncing commits, labeling PRs, etc.) resolves the target repository from a *different* field of the same untrusted body - `payload.dig('repository', 'full_name')` - which is never cross-checked against `repository_owner`: [5](#0-4) 

So in a multi-org configuration (`Shipit.github(organization: ...)` scheme, as documented for supporting several GitHub Apps), the two payload fields are independently trusted for two different purposes:
- `repository.owner.login` → picks *whose* secret authenticates the request.
- `repository.full_name` → picks *which* repository/stack the request acts on.

If any configured organization has `webhook_secret` unset/blank (a state explicitly shown as a valid, common configuration in the example secrets files), an attacker can submit a forged webhook with `repository.owner.login` set to that blank-secret organization while `repository.full_name` targets a stack belonging to an entirely different, secret-protected organization. `verify_webhook_signature` returns `true` unconditionally for the blank-secret org, so the request is accepted, and the handler then acts on the unrelated target repository named in `full_name`. [6](#0-5) 

### Impact Explanation
Handlers dispatched this way include `PushHandler`, which for any stack matching the spoofed `full_name`/branch enqueues `GithubSyncJob` with an attacker-controlled `expected_head_sha`: [7](#0-6) 

This forces unauthenticated syncing/commit ingestion (and, indirectly, deploy-spec cache refresh and downstream continuous-deployment triggers) against a repository/stack that never authorized the request via its own webhook secret - a cross-organization/cross-repository write triggered without the target's credential. Other handlers (`PullRequest` handlers, `StatusHandler`, `MembershipHandler`) are reachable through the same bypass and can create/archive review stacks, forge commit statuses, or manipulate team membership for the spoofed target repository.

### Likelihood Explanation
Exploitation requires only an unauthenticated HTTP POST to the public `/webhooks` endpoint; no Shipit session, API token, or the target organization's secret is needed. The only precondition is that the Shipit instance's multi-organization GitHub config contains at least one organization without a `webhook_secret` (the documented example templates show this as `# nil`, i.e., an easy-to-reach misconfiguration state, not a hardened default). Once that condition holds, forging the `repository.owner.login` field is trivial since it is plain JSON with no other guard.

### Recommendation
Do not let the payload determine which organization's secret is used for verification without cross-checking. Concretely:
- After successfully verifying the signature, re-derive the acted-upon repository/organization strictly from the *same* authenticated identity, and reject/ignore any mismatch between `repository.owner.login` (used to pick the secret) and `repository.full_name` (used to pick the target).
- Treat a blank `webhook_secret` for one organization as isolated: it must never be able to authenticate events aimed at other organizations' repositories.
- Optionally, warn/fail startup if any org in a multi-org config has no `webhook_secret` configured.

### Proof of Concept
1. Configure Shipit with two GitHub Apps: `orgA` (no `webhook_secret`) and `orgB` (with a `webhook_secret`, hosting the real target stack `orgB/private-repo`).
2. POST to `/webhooks` with header `X-Github-Event: push` and a body:
```json
{
  "ref": "refs/heads/main",
  "after": "attacker-controlled-sha",
  "repository": {
    "owner": { "login": "orgA" },
    "full_name": "orgB/private-repo"
  }
}
```
No `X-Hub-Signature` header is required to be valid because `verify_webhook_signature` short-circuits to `true` for `orgA`'s blank secret [8](#0-7) .
3. `WebhooksController#verify_signature` passes, and `PushHandler` (via `Handler#stacks`/`#repository_name`) resolves and acts on the `orgB/private-repo` stack [5](#0-4) [7](#0-6) , enqueuing `GithubSyncJob` for `orgB`'s stack without ever presenting `orgB`'s webhook secret.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
