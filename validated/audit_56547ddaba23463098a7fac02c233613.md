### Title
Revived delegate grants let a former position owner restore the victim’s stolen access rights - (File: contracts/controller/src/storage/account.rs)

### Summary
A delegate grant is keyed to the account and stamped with the granting owner, but it is not invalidated permanently when the position NFT moves to another owner. If that intermediate owner transfers the NFT back to the original owner, the original owner’s stale grant becomes active again. A malicious delegate that acquired the position can therefore return it and immediately regain authority without the restored owner’s signature.

### Finding Description
`is_owner_or_delegate` accepts a caller when it is an active position manager and appears in `get_delegates(account_id, owner)`. [1](#0-0)  The stored `DelegateGrant` is considered valid whenever its `granted_by` field equals the NFT’s current owner. [2](#0-1)  Account ownership is read dynamically from the position NFT rather than from immutable account metadata. [3](#0-2) 

An intervening owner can explicitly remove the stale grant, but nothing in an NFT transfer purges `ControllerKey::Delegates(account_id)`. [4](#0-3)  Consequently, returning the NFT to the grantor rebinds the old `granted_by` value to the restored owner and revives the old authorization. The revived delegate can call owner/delegate endpoints such as `withdraw` and direct proceeds through the optional `to` argument. [5](#0-4) 

### Impact Explanation
An unprivileged active position manager can steal collateral from a returned account. For an account with no debt, `withdraw` can move all collateral to the malicious delegate; for an indebted account, it can withdraw the collateral permitted by the post-withdrawal solvency check and can also use other owner/delegate paths such as `borrow` within risk limits. This is theft of user funds because the restored owner never reauthorized the old delegate after receiving the NFT.

### Likelihood Explanation
The path requires the victim to have previously granted the attacker an active position-manager delegation and the attacker or a cooperating intermediate holder to obtain the position NFT. Once obtained, returning the NFT is unilateral because NFT transfer authorization comes from the intermediate owner, not the recipient. The stale grant then survives unless the intervening owner happened to call `remove_delegate`, which deletes a grant stamped by a different owner even though it returns `false`. [6](#0-5) 

### Recommendation
Bind delegate grants to an ownership epoch rather than only to the owner address. Store and increment an `ownership_epoch` on every position-NFT transfer, include that epoch in `DelegateGrant`, and require it to match the account’s current epoch in `get_delegates`. Alternatively, clear `ControllerKey::Delegates(account_id)` whenever NFT ownership changes; an epoch is safer because the controller can validate the current epoch without relying on an NFT transfer hook.

### Proof of Concept
1. Alice owns `account_id = A`, and governance has activated Mallory as a position manager.
2. Alice calls `add_delegate(alice, A, mallory)`, writing `DelegateGrant { granted_by: alice, delegates: [mallory] }`. [7](#0-6) 
3. Alice transfers NFT `A` to Mallory or sells it through an intermediate owner. While Mallory or the intermediate owner owns the NFT, `get_delegates` filters the stale Alice-stamped grant out. [2](#0-1) 
4. Mallory, now able to transfer the NFT as its holder, calls the position NFT’s `transfer`/`transfer_from` path and sends token `A` back to Alice. The stale grant remains in controller storage because account deletion is the only shown path that removes metadata, positions, and delegates together. [8](#0-7) 
5. `account_owner(A)` again resolves to Alice, so the stale grant’s `granted_by == alice` check passes and Mallory is again accepted by `is_owner_or_delegate`. [9](#0-8) 
6. Mallory calls `withdraw(mallory, A, withdrawals, Some(mallory))`; the account check succeeds from the revived grant, and the endpoint pays the allowed withdrawal to Mallory. [10](#0-9)

```rust
/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}
```

```rust
/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
```

```rust
/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
```
