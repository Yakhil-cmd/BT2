### Title
Gist description printed to terminal without ANSI/escape-sequence sanitization, unlike sibling file-content field - (File: pkg/cmd/gist/view/view.go)

### Summary
In `viewRun`, `gist.Description` is written to `opts.IO.Out` via `fmt.Fprintf(opts.IO.Out, "%s\n\n", cs.Bold(gist.Description))` with no sanitization, while the sibling gist file content is explicitly wrapped in `iostreams.NewUntrusted(...)` before being rendered. Since `gist.Description` is a plain `string` decoded directly from the GitHub API JSON response, an attacker-controlled description can carry raw ANSI/terminal escape sequences that reach the victim's terminal unmodified.

### Finding Description
`shared.GetGist` decodes the gist JSON response into a `Gist` struct whose `Description` field is a plain string, populated straight from attacker-controlled API data [1](#0-0) . In `viewRun`, the file-content path treats gist file bytes as untrusted, explicitly opting into sanitization: `content := iostreams.NewUntrusted(gf.Content)`, whose `String()`/print path passes through `asciisanitizer` to neutralize escape sequences [2](#0-1) [3](#0-2) . In contrast, the description path skips this entirely:

```go
if gist.Description != "" && !opts.ListFiles {
    fmt.Fprintf(opts.IO.Out, "%s\n\n", cs.Bold(gist.Description))
}
``` [4](#0-3) 

`opts.IO.Out` is a plain `fileWriter`, distinct from `ContentOut`, which is the only writer with built-in sanitization toggled by `sanitizeContent`/`SetContentSanitization` [5](#0-4) . Because `Description` is typed `string` (not `iostreams.Untrusted`), there is no automatic sanitization on any print path — the `String()`-based ANSI neutralization that protects `Untrusted` values via `fmt` never triggers for a raw `string` [6](#0-5) . `cs.Bold(...)` only adds SGR bold codes around the text and does not strip or escape any embedded control sequences from the input.

An attacker who creates a public gist with a description containing terminal escape sequences (e.g., cursor movement, screen-clearing sequences, OSC sequences that rewrite the terminal title, or sequences supported by some terminal emulators for clipboard writes / hyperlink injection) can have those sequences executed verbatim on the victim's terminal simply by having them run `gh gist view <attacker-gist-id>`.

### Impact Explanation
This is a terminal escape-sequence / ANSI injection issue affecting the "unsanitized output" bounty class. Depending on the victim's terminal emulator, impact ranges from cosmetic terminal corruption and misleading output (e.g., hiding/faking following command output) up to more severe consequences on terminals with known escape-sequence vulnerabilities (title-bar injection, clipboard write via OSC 52, or attacks against poorly-hardened terminal emulators). It does not by itself achieve remote code execution or credential exfiltration within `gh`, but it is a clear gap in the codebase's own content-sanitization model — the file-content sibling path was explicitly hardened against this exact issue while the description path was missed.

### Likelihood Explanation
Fully attacker-reachable with no privileges required: any GitHub user can create a public gist with an attacker-chosen description and share the gist ID/URL. The victim only needs to run the ordinary command `gh gist view <attacker-gist-id>` on an interactive terminal (`opts.IO.Out` is written to regardless of TTY status, and there is no `--allow-escape-sequences` gate on this path, nor any dependency on `opts.Raw`). This makes the finding fully reproducible and repeatable.

### Recommendation
Wrap `gist.Description` in `iostreams.NewUntrusted(...)` (or otherwise sanitize it through the same `asciisanitizer`-based path used for gist file content) before formatting/printing, consistent with the sibling file-content handling in the same function. Alternatively, print it through `opts.IO.ContentOut` with sanitization enabled by default, matching the file-content rendering convention already established in `viewRun`.

### Proof of Concept
Go test using `httpmock` to simulate `GetGist`, with a gist description containing an ANSI escape sequence (e.g., `"\x1b[2J\x1b[H<injected>"`), asserting that `viewRun`'s stdout buffer contains the raw, unescaped bytes rather than a sanitized/neutralized version — contrasted with an equivalent gist file body containing the same escape sequence, which is sanitized when passed through `iostreams.NewUntrusted`. Expected assertion: file-content test output has escape bytes stripped/neutralized; description output retains raw escape bytes verbatim, demonstrating the sanitization gap.

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
```
