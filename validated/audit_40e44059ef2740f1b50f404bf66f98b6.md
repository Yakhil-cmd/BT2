### Title
`StatusHandler#process` creates `Status` records by matching `sha` alone, with no repository/tenant check - ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
The regression test `":state create a Status for the specific commit"` never asserts `status_payload['repository']['full_name'] == commit.stack.repository.full_name`; it only checks that `repository.owner.login` equals `'shopify'` so that `verify_signature` passes. `StatusHandler#process` itself never reads the payload's `repository` key at all - it resolves the target commit purely via `Commit.where(sha: params.sha)`, so any payload whose `sha` collides with an existing `Commit` row is accepted regardless of which repository it claims to be from.

### Finding Description
The binding the question asks about is: `repository_params['full_name'] == commit.stack.repository.full_name`. Tracing the code shows this equality is never checked anywhere on the write path:

- `WebhooksController#create` parses the raw JSON body and dispatches it to `Shipit::Webhooks.for_event(event)` handlers [1](#0-0) .
- The only repository-aware guard, `verify_signature`, resolves `repository_owner` from `params.dig('repository','owner','login')` and validates the HMAC signature against the secret configured for *that organization* [2](#0-1) [3](#0-2) . This only proves the payload came from a legitimately-signed webhook of *some* known organization - it says nothing about whether that organization/repository owns the commit being targeted.
- `StatusHandler#process` then does:
```ruby
Commit.where(sha: params.sha).each do |commit|
  commit.create_status_from_github!(params)
end
``` [4](#0-3) 
No `repository`, `owner`, or `stack` filter is applied - `sha` is matched globally across the entire `commits` table, spanning every stack/repository/tenant Shipit hosts. Compare this to `PushHandler#process`, which scopes the affected stacks with `stacks.not_archived.where(branch:)` [5](#0-4)  - even that scoping is by branch name, not repository identity, but `StatusHandler` doesn't even attempt branch/repo scoping for the SHA lookup.

The test itself confirms the gap: `repository_params` only ever sets `{ repository: { owner: { login: 'shopify' } } }` [6](#0-5) , which is sufficient to pass `verify_signature`, and the status test merges this into the payload and asserts `commit.statuses.count` increases by 1, with no check that the merged repository matches `commit.stack.repository.full_name` [7](#0-6) . Swapping `repository_params` to any other org whose signature check passes (i.e., any org known to `Shipit.github`) but keeping the same `sha` would still hit the same `Commit.where(sha:)` row and pass the assertion, since the production code performing the write never consults the `repository` payload field.

Root cause: `Commit` has no repository/owner column to cross-check against the incoming payload's `repository.full_name`; `sha` is treated as a global, not per-tenant, key by `StatusHandler`.

### Impact Explanation
Any organization/repository that Shipit knows about (i.e., has a valid webhook signing secret registered via `Shipit.github(organization:)`) can inject a `status` webhook whose `sha` matches a commit belonging to a completely unrelated stack/tenant, causing a `Status` record to be written onto that unrelated commit. Since `commit.status`/`checks` feed into `deployable?` and `blocked?` [8](#0-7) , and successful statuses can trigger `schedule_merges`/`ContinuousDeliveryJob` [9](#0-8) , a cross-tenant forged "success" status can make a victim stack's commit appear CI-green and eligible for auto-merge/auto-deploy - an unauthorized deploy/merge condition, matching the Critical category "a payload for one repository mutating another's stack, commit... or an unauthorized deploy/merge." Repeatable against any commit whose `sha` an attacker can predict or reproduce (e.g. forking a public upstream repository tracked by a victim stack, where forked commits retain identical SHAs).

### Likelihood Explanation
Exploitation requires the attacker to control (or trigger real, validly-signed GitHub webhook deliveries for) an organization/repository that Shipit already recognizes and has a webhook secret configured for - this is a real precondition in any multi-tenant Shipit deployment serving multiple orgs/repos from one instance. It does not require any Shipit session, API token, or admin secret; it only requires the attacker's own repo to be one of the tenants already onboarded, and a `sha` collision with the victim's commit (trivially achieved by forking a shared upstream history). This is a moderate-cost, but fully repeatable, attack per matching `sha`.

### Recommendation
Scope `StatusHandler#process` (and any other handler resolving commits purely by `sha`) to only affect commits belonging to stacks whose repository matches `params` payload's `repository.full_name`/`owner.login`, e.g. filter through `Stack.where(repository: ...).commits.where(sha: params.sha)` instead of unscoped `Commit.where(sha:)`, mirroring the repository-scoping already partially done in other handlers.

### Proof of Concept
```ruby
test ":state does not create a Status when repository does not match the commit's stack" do
  request.headers['X-Github-Event'] = 'status'

  commit = shipit_commits(:first)
  assert_equal 'shopify', commit.stack.repository.owner # sanity check on binding
  refute_equal 'unrelated-org', commit.stack.repository.owner

  unrelated_repo_params = { repository: { owner: { login: 'unrelated-org' }, full_name: 'unrelated-org/unrelated-repo' } }
  Shipit.expects(:github).with(organization: 'unrelated-org').returns(stub(verify_webhook_signature: true))

  body = JSON.parse(payload(:status_master)).merge(unrelated_repo_params).to_json

  assert_no_difference 'commit.statuses.count' do
    post :create, body:, as: :json
  end
end
```
Running this against current `StatusHandler#process` fails (the status is still created), demonstrating that `repository_params['full_name'] == commit.stack.repository.full_name` is never enforced by the production code path.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))

      ].join(' '))
    end
