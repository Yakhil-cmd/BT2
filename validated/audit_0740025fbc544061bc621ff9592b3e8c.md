**Reasoning:**

The `MAX_DELAYED_FIELDS_PER_RESOURCE` cap in `DelayedFieldsExtension::inc_and_check_delayed_fields_count` is explicitly designed as a per-resource, per-(de)serialization-call limit, not a per-transaction aggregate budget. Each `DelayedFieldsExtension` instance is freshly constructed with `RefCell::new(0)` whenever a resource is (de)serialized (e.g. via `with_delayed_fields_serde()`/`with_delayed_fields_replacement()`), and this happens once per resource load in call sites like `create_data_cache_entry` in `data_cache.rs`, `replace_values_with_identifiers`/`replace_identifiers_with_values` in `view.rs`, and `deserialize_value` in `table-natives/src/lib.rs`. [1](#0-0) [2](#0-1) 

The code comment itself states the limit is "Temporarily limit the number of delayed fields per resource, until proper charges are implemented," confirming this is a gas-metering/resource-cost safeguard for a single resource's value, not a cross-resource or per-transaction admission invariant. [3](#0-2) 

Since each resource independently enforces its own cap of 10 delayed fields when loaded, there is no "aggregate budget" being bypassed by spreading delayed fields across multiple resources — this behavior is intended. The gas-payer balance check in `prologue_common`/`epilogue_gas_payer_extended` via `aptos_account::is_fungible_balance_at_least` reads specific coin/fungible-store resources, and each such resource resolution is subject to its own independent per-resource delayed-field cap; no cross-resource aggregation was ever claimed or required by this mechanism. [4](#0-3) 

This mechanism has no bearing on sender/signer binding, authenticator parsing, sequence number, chain-id, expiry, or fee-payer/secondary-signer authorization — the required admission invariants per the review's Boundary Conditions and Admission Pivots. At most, this concerns per-resource gas/resolution cost accounting, which is explicitly out of scope ("generic DoS" and non-admission resource cost concerns are excluded). No unprivileged input path exists here that binds an unintended sender, signer, or fee payer, or that breaks sequence/replay/chain-id/expiry guarantees.

impl DelayedFieldsExtension<'_> {
    // Temporarily limit the number of delayed fields per resource, until proper charges are
    // implemented.
    // TODO[agg_v2](clean):
    //   Propagate up, so this value is controlled by the gas schedule version.
    const MAX_DELAYED_FIELDS_PER_RESOURCE: usize = 10;

    /// Increments the delayed fields count, and checks if there are too many of them. If so, an
    /// error is returned.
    pub(crate) fn inc_and_check_delayed_fields_count(&self) -> PartialVMResult<()> {
        *self.delayed_fields_count.borrow_mut() += 1;
        if *self.delayed_fields_count.borrow() > Self::MAX_DELAYED_FIELDS_PER_RESOURCE {
            return Err(PartialVMError::new(StatusCode::TOO_MANY_DELAYED_FIELDS)
                .with_message("Too many Delayed fields in a single resource.".to_string()));
        }
        Ok(())
    }
