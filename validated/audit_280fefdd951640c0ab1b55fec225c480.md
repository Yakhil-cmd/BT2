### Title
Terminal escape sequence injection via unsanitized bundle fields in `gh attestation inspect` output - (File: pkg/cmd/attestation/inspect/inspect.go)

### Summary
`printInspectionSummary` writes attacker-controlled certificate and statement fields (e.g. `SubjectAlternativeName`, `RunInvocationURI`, `SourceRepositoryURI`, `PredicateType`) directly to the terminal via `logger.OutPrintf` without any escape-sequence sanitization. A bundle whose certificate SAN or predicate fields contain raw ANSI/terminal control sequences will have those sequences executed verbatim by the victim's terminal emulator when they run `gh attestation inspect`.

### Finding Description
In `runInspect`, the certificate summary is built directly from the leaf certificate via `certificate.SummarizeCertificate(leafCert)` [1](#0-0) , and the statement is parsed straight from the DSSE envelope with `envelope.Statement()` [2](#0-1) . Both structures carry attacker-influenced string content: `Certificate.SubjectAlternativeName` and `RunInvocationURI` come straight from the X.509 certificate SAN/extensions (self-issued/attacker-controlled in an untrusted bundle since `runInspect` explicitly uses an "unsafe" policy and continues even when verification fails), and `Statement.GetPredicateType()` / other statement fields come from the DSSE payload, which is fully attacker-controlled JSON.

These values are placed into `bundleSummaries` and printed with:
```go
logger.OutPrintf("%s:%s %s\n", scheme.Bold(colName), strings.Repeat(".", dots), pair[1])
``` [3](#0-2) 

`OutPrintf` is a thin wrapper over `fmt.Fprintf(h.IO.Out, f, v...)` with no filtering of control characters: [4](#0-3) . `formatNwo` only rewrites the value if `ghrepo.FromFullName` successfully parses it as `owner/repo`; otherwise it returns the raw, unsanitized string unchanged [5](#0-4) , so an attacker can embed escape sequences in a URI that fails that strict parse and have them pass through untouched.

There is no invocation of any ANSI-stripping or control-character-escaping utility (e.g. `text.RemoveExcessiveWhitespace`, `strconv.Quote`, or similar) anywhere along this path before the data reaches the terminal, unlike patterns used elsewhere in the codebase to sanitize untrusted display strings.

### Impact Explanation
An attacker who publishes an attestation bundle (e.g. attached to a release/artifact or shared as a file) with a crafted certificate SAN, run-invocation URI, or predicate content containing ANSI/terminal escape sequences can manipulate the victim's terminal when they run `gh attestation inspect <bundle>`. This can be used to hide malicious output, forge fake prompts/text, clear the screen to hide evidence, or (depending on terminal emulator features) trigger more advanced escape-sequence-based attacks (e.g. title-bar manipulation, clipboard writes in some terminals). This matches the "terminal escape injection / spoofed output" class of impact.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs to craft a bundle JSON/JSONL file with a certificate or statement containing control bytes and have the victim run `gh attestation inspect` against it — no authentication, elevated privileges, or special server interaction required. Since `runInspect` explicitly supports inspecting bundles it cannot verify (using `verify.NewPolicy(verify.WithoutArtifactUnsafe(), verify.WithoutIdentitiesUnsafe())` and continuing on verification error) [6](#0-5) , self-signed/attacker-forged bundles are a supported, expected input to this command.

### Recommendation
Sanitize all bundle-derived strings before printing to the terminal in `printInspectionSummary` — strip or escape non-printable/control characters (particularly `ESC` (`\x1b`) and other C0 control codes) from `Certificate.SubjectAlternativeName`, `Certificate.RunInvocationURI`, `Certificate.SourceRepositoryURI`, and `Statement.GetPredicateType()` (and any other statement-derived text) prior to formatting. Consider adding a shared sanitization helper (e.g. reusing/extending `text` package utilities) used consistently by `OutPrintf`/`Printf` wrappers in `pkg/cmd/attestation/io/handler.go` whenever printing untrusted, bundle-sourced data.

### Proof of Concept
```go
func TestPrintInspectionSummary_SanitizesEscapeSequences(t *testing.T) {
    ios, _, out, _ := iostreams.Test()
    logger := io.NewHandler(ios)

    malicious := "\x1b[2J\x1b[H\x1b]0;pwned\x07github.com/attacker/repo"

    bundles := []BundleInspection{
        {
            Authentic: false,
            Certificate: CertificateInspection{
                Summary: certificate.Summary{
                    SubjectAlternativeName: malicious,
                    SourceRepositoryURI:    malicious,
                    RunInvocationURI:       malicious,
                },
            },
            Statement: &in_toto.Statement{PredicateType: malicious},
        },
    }

    printInspectionSummary(logger, bundles)

    output := out.String()
    // Expected assertion once fixed: raw ESC bytes must not appear in output
    require.NotContains(t, output, "\x1b")
}
```
Run this test against current code: it fails, demonstrating the raw `\x1b` escape sequences are written verbatim to `IO.Out` via `OutPrintf`.
