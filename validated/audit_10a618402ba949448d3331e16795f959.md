### Title
`GitHubApp#verify_webhook_signature` vacuously trusts webhooks for any organization lacking a `webhook_secret`, letting an unauthenticated request spoof a different (secured) organization's repository via the decoupled `repository.owner.login` / `repository.full_name` fields - ([File: lib/shipit/github_app.rb], [File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` before even inspecting the signature argument when `@webhook_secret` is blank, and the `GitHubApp` instance used for verification is selected purely from the attacker-controlled `repository.owner.login` (or `organization.login`) field of the JSON body, not from `repository.full_name`, which is what handlers actually use to resolve the target stack/repository. An attacker who knows any org configured on the host without a `webhook_secret` can send a completely unsigned POST to `/webhooks` naming that org as `repository.owner.login` while setting `repository.full_name` to any other configured organization's repository, and every registered webhook handler executes against that other repository with zero authentication.

### Finding Description
The broken binding: `webhook_secret.present?(org) == request_authenticated(org)`. The code implicitly assumes that if an org has no `webhook_secret` configured, there's nothing to check, so treat the request as trusted. In reality the correct binding is `webhook_secret.present?(org) == able_to_authenticate(org)`; when absent, no authentication is possible and the request should be rejected, not accepted.

Code path:
- `WebhooksController#verify_signature` selects the app config using only the attacker-controlled owner field: `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` short-circuits to `true` before touching the `signature` argument at all: `return true unless webhook_secret` [3](#0-2) 
- `@webhook_secret` is set from `@config[:webhook_secret].presence` per-organization at initialization, so this is genuinely a per-org toggle, matching the question's premise [4](#0-3) 
- Downstream, `WebhooksController#create` dispatches to handlers using the full parsed body regardless of which field was used for org lookup: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [5](#0-4) 
- Handlers key off `repository.full_name` to resolve the actual `Stack`/`Repository`, independent of `repository.owner.login`. This decoupling is directly demonstrated in the test suite, where `repository.full_name` is overridden independently of the owner used for signature checks: `unknown_repo_payload["repository"]["full_name"] = "owner/unknown-repository"` [6](#0-5) 

Exploit flow: attacker discovers (or is told, e.g. via a dev/staging org) that org `no-secret-org` is configured on the Shipit host without `webhook_secret`. Attacker POSTs to `/webhooks` with `X-Github-Event: push` (or any other handled event) and **no** `X-Hub-Signature` header, body: `{"repository": {"owner": {"login": "no-secret-org"}, "full_name": "victim-org/victim-repo"}, ...}`. `repository_owner` resolves to `no-secret-org`, `Shipit.github(organization: 'no-secret-org')` returns a `GitHubApp` with `@webhook_secret` nil, `verify_webhook_signature(nil, body)` returns `true` immediately, `verify_signature` logs and does not `head(422)`, and `create` runs every handler registered for that event against the forged body, which reference `victim-org/victim-repo` for stack/commit mutation.

Why existing guards fail: `drop_unhandled_event` only filters unknown event types, not authenticity [7](#0-6) ; `Shipit.github(organization: ...)` only raises `GithubOrganizationUnknown` for orgs not configured at all, not for configured-but-secretless orgs (confirmed by the "unknown github organization" test using a distinct exception path) [8](#0-7) ; there is no code anywhere in `verify_signature` or the handlers that cross-checks `repository.owner.login` against `repository.full_name`'s owner segment.

### Impact Explanation
An attacker with zero credentials can trigger any webhook-driven mutation (queueing `GithubSyncJob`, creating commit statuses, creating/deleting team memberships, driving check-run refreshes, etc.) against **any** repository/stack configured on the Shipit host, as long as one org on that host lacks a `webhook_secret`. This is a full authentication bypass enabling cross-tenant/cross-organization writes with no signature at all, matching the "Critical" category: authentication bypass and a payload for one repository mutating another's stack/commit/task/team.

### Likelihood Explanation
Requires only that the Shipit host has multiple GitHub orgs configured (multi-tenant Shipit deployments are the intended use case per `Shipit.github(organization:)` existing at all) and that at least one of those orgs was configured without a `webhook_secret` — a realistic and easy-to-make operational mistake (e.g., a dev/staging org added without the secret field, or an org added purely for OAuth/team sync without webhook use). No GitHub secrets, sessions, or private keys are needed by the attacker; the request is a plain unauthenticated HTTP POST. This is trivially repeatable against arbitrary target repositories by simply changing `repository.full_name` in the forged body.

### Recommendation
Change `GitHubApp#verify_webhook_signature` so a missing `webhook_secret` causes verification to fail closed (`return false unless webhook_secret`) rather than fail open. Additionally, bind the verification org to the actual mutation target: reject or re-derive `repository_owner` strictly from `repository.full_name`'s owner segment (not a separately attacker-suppliable `repository.owner.login`/`organization.login` field), so the org used to select the `GitHubApp`/secret is guaranteed to match the org that handlers will act upon.

### Proof of Concept
```ruby
# lib/shipit/github_app_test.rb (minitest)
test "verify_webhook_signature returns true with no secret and no signature header" do
  app = Shipit::GitHubApp.new('no-secret-org', {})
  assert_equal true, app.verify_webhook_signature(nil, '{"repository":{"owner":{"login":"no-secret-org"},"full_name":"victim-org/victim-repo"}}')
end

# test/controllers/webhooks_controller_test.rb (minitest, integration)
test "unsigned request naming secretless org bypasses signature check and mutates victim org's stack" do
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(Shipit::GitHubApp.new('no-secret-org', {}))
  request.headers['X-Github-Event'] = 'push'
  # No X-Hub-Signature header set at all
  forged_body = JSON.parse(payload(:push_master))
  forged_body['repository']['owner']['login'] = 'no-secret-org'
  forged_body['repository']['full_name'] = @stack.repository.full_name # victim org/repo
  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: @stack.id, expected_head_sha: forged_body['after']]) do
    post :create, body: forged_body.to_json, as: :json
  end
  assert_response :ok
end
```
Both sides of the binding diverge: `webhook_secret.present?('no-secret-org') == false`, but `request_authenticated == true` (per `verify_webhook_signature` returning `true`), and the enqueued job proves a write occurred for `victim-org/victim-repo`, a repository whose org was never named or authenticated in the request.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
