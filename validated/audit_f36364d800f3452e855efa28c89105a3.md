### Title
Service Chain Bridge Permanently Blocked by KLAY Transfer Request to Non-Payable Recipient — (`node/sc/bridge_manager.go`, `contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

The Kaia service-chain bridge's `_requestKLAYTransfer()` does not validate that the `_to` address can receive KLAY. Any unprivileged user can call `requestKLAYTransfer()` with a non-payable contract as `_to`, causing the bridge operator's `handleRequestValueTransferEvent()` to permanently fail on that request nonce. Because `processingPendingRequestEvents()` re-queues the failing event and halts processing on error, all subsequent bridge transfers (every nonce after the poisoned one) are permanently blocked.

---

### Finding Description

**Source-side — missing recipient validation**

`_requestKLAYTransfer()` only checks `isRunning` and `msg.value > _feeLimit`. It emits `RequestValueTransfer` with the caller-supplied `_to` without any check that `_to` can receive KLAY: [1](#0-0) 

**Destination-side — KLAY transfer can revert**

`handleKLAYTransfer()` updates the nonce tracking and emits the event, then performs the actual KLAY transfer. If `_to` is a contract with no payable fallback, `_to.call.value(_value)("")` returns `false` and the `require` reverts the entire transaction — including the nonce update: [2](#0-1) 

Because the transaction reverts, `_updateHandleNonce` is rolled back and the bridge contract's `lowerHandleNonce` does not advance past nonce N.

**Operator-side — error causes permanent queue block**

The Go bridge operator calls `HandleKLAYTransfer` via the ABI binding. The binding performs `eth_estimateGas` before sending; if the simulated call would revert (because `_to` rejects KLAY), it returns an error immediately — no transaction is sent and `bridgeAcc.IncNonce()` is never called.

`processingPendingRequestEvents()` then re-queues the failing event **and all subsequent events** (`ReadyEvent[idx:]`) and returns: [3](#0-2) 

On every subsequent tick (every second), the same failing event is at the front of the sorted queue. The only skip conditions are `nonce < lowerHandleNonce` or `handledEvent.Exist(nonce)` — neither is satisfied because the bridge contract's nonce never advanced and no `HandleValueTransfer` event was ever emitted: [4](#0-3) 

The result is a permanent, irrecoverable stall of the bridge operator for all nonces ≥ N.

---

### Impact Explanation

- **Asset impact**: All KAIA and ERC-20/ERC-721 bridge transfers with request nonce ≥ N are permanently frozen. Funds locked in the source bridge contract cannot be released on the destination chain.
- **Protected-state impact**: The bridge's `lowerHandleNonce` / `upperHandleNonce` accounting is permanently stuck; the `recoveryBlockNumber` used by `valueTransferRecovery` also stops advancing, so the recovery mechanism re-injects the same poisoned event and does not help. [5](#0-4) 

---

### Likelihood Explanation

- **Unprivileged trigger**: `requestKLAYTransfer()` is callable by any EOA or contract.
- **Low cost**: The attacker only needs to deploy a contract with no payable fallback (or use any existing non-payable contract address) and send a single bridge request with a small KLAY value.
- **No recovery path**: There is no on-chain or off-chain mechanism to skip or cancel a stuck request nonce without operator manual intervention at the Go layer (which is not documented or exposed).

---

### Recommendation

1. **Validate `_to` on the source bridge**: In `_requestKLAYTransfer()`, reject transfers where `_to` is a contract address (check `_to.code.length == 0`) or add a test-transfer guard. Alternatively, mirror the ERC-20 path and require `_value > 0` plus a whitelist/allowlist of valid recipient types.

2. **Make the operator resilient to permanent failures**: In `processingPendingRequestEvents()`, distinguish between transient errors (RPC failure) and permanent errors (transaction will always revert). For permanent failures, skip the event (log it, emit a metric, and advance past it) rather than re-queuing it indefinitely.

3. **Add a `_to` payability check on the destination bridge**: In `handleKLAYTransfer()`, consider using a try/catch pattern (Solidity ≥ 0.6) or checking `_to.code.length` before the low-level call, and emit a failure event rather than reverting, so the nonce is still consumed.

---

### Proof of Concept

```
1. Deploy MaliciousRecipient (no payable fallback) on the destination chain.

2. On the source bridge, call:
   requestKLAYTransfer(
       MaliciousRecipient,   // _to — rejects KLAY
       1 wei,                // _value
       ""                    // _extraData
   ) with msg.value = 1 wei + feeOfKLAY

3. Source bridge emits RequestValueTransfer(KLAY, attacker, MaliciousRecipient, ..., requestNonce=N, ...)

4. Bridge operator picks up the event and calls:
   bi.bridge.HandleKLAYTransfer(auth, txHash, attacker, MaliciousRecipient, 1, N, blkNum, nil)
   → eth_estimateGas simulates: MaliciousRecipient.call.value(1)("") → false → require fails → revert
   → Go binding returns error

5. processingPendingRequestEvents re-queues ReadyEvent[N:] and returns.

6. Every subsequent tick retries nonce N → same error → all nonces N+1, N+2, ... permanently blocked.
``` [6](#0-5) [7](#0-6)

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
}

    // _updateHandleNonce increases lower and upper handle nonce after the _requestedNonce is handled.
    function _updateHandleNonce(uint64 _requestedNonce) internal {
        if (_requestedNonce > upperHandleNonce) {
            upperHandleNonce = _requestedNonce;
        }

        uint64 limit = lowerHandleNonce + 200;
        if (limit > upperHandleNonce) {
            limit = upperHandleNonce;
        }

        uint64 i;
        for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
            recoveryBlockNumber = handleNoncesToBlockNums[i];
            delete handleNoncesToBlockNums[i];
            delete closedValueTransferVotes[i];
        }
        lowerHandleNonce = i;
    }
