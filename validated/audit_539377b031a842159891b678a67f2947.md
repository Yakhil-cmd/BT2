### Title
Accrual-time RAY-value overflow permanently freezes a high-utilization market - (File: common/src/rates/scaling.rs)

### Summary
XOXNO Lending scales balances as `scaled_amount * index / RAY`. During interest accrual, `accrue_step` converts the market-wide borrowed and supplied share totals back to RAY-denominated asset values before applying the configured index ceiling. If either product exceeds `i128::MAX`, `scaled_to_original` panics with `MathOverflow`. Because `global_sync` runs before market mutations, the next accrual that crosses the representable-value boundary causes `update_indexes`, `withdraw`, `repay`, `borrow`, liquidation settlement, and other market verbs to revert. This is the protocol-level analog of CVE-2021-3409: a boundary calculation is allowed to reach an unchecked representational limit, after which the operation can no longer execute safely.

### Finding Description
`global_sync` splits elapsed time into bounded chunks and calls `accrue_chunk` for each chunk. `accrue_chunk` invokes `accrue_step`, which first computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` to derive utilization. [1](#0-0) [2](#0-1) 

`scaled_to_original` is just `scaled.mul(index)`, which panics when the resulting RAY value cannot fit in `i128`. [3](#0-2) [4](#0-3) 

The borrow-index ceiling does not protect this calculation. `update_borrow_index` clamps the index only after calculating utilization, while the market's `borrowed * borrow_index` and `supplied * supply_index` products can cross the `i128` boundary before either index reaches `10^36`. [5](#0-4) [6](#0-5) 

The repository already documents that valid caps and bounded indexes do not guarantee future accrued values fit the RAY domain, and that repayment and withdrawal can be blocked because they accrue first. [7](#0-6) 

A deterministic harness test demonstrates the cliff: a one-billion-whole-token, 18-decimal market at 98% utilization eventually fails `update_indexes` with `MathOverflow`, and subsequent withdrawal and repayment fail for the same reason before the index cap engages. [8](#0-7) 

### Impact Explanation
Once a market reaches the overflow boundary, all operations that accrue that market revert. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot settle unhealthy debt, and `update_indexes` cannot advance the market. The result is permanent freezing of the market's supplied funds and a protocol unable to operate that market for lack of representable accounting state. This is stronger than a transient fail-closed condition: no later call can pass the accrual step, and no permissionless path such as `repay` or `recapitalize` can reduce the scaled debt before accrual because those calls also accrue first. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
Likelihood is medium-low but plausible under valid protocol limits. An 18-decimal asset can represent roughly 170 billion whole tokens before direct token-to-RAY conversion overflows, while a one-billion-token position already reaches the accrued-value cliff after sustained high utilization. [11](#0-10)  An unprivileged address can establish the large supply and borrow positions through ordinary `supply` and `borrow` calls if the market's configured caps and liquidity admit them, after which any caller can trigger the fatal transition through permissionless `update_indexes`. The main mitigating factors are the large required position, suitable market caps, and sustained high utilization over multiple accrual periods.

### Recommendation
Enforce a representable-value bound directly, rather than relying on the index ceiling alone.

- Before minting supply or debt shares, check that `scaled_amount * current_index / RAY` and the corresponding market total remain below the `i128` domain with sufficient headroom for the next allowed index increase.
- Derive a maximum safe `scaled_amount` per market from the index ceiling and reject supply, borrow, strategy debt minting, revenue share minting, and bad-debt state transitions that would make future accrual unrepresentable.
- In `accrue_step`, detect a value-domain overflow before calling `scaled_to_original` and clamp accrual at the largest representable index or enter an explicit settlement state that still permits repayment, withdrawal, liquidation, and bad-debt processing.
- Add boundary tests around `scaled * index == i128::MAX` for both `borrowed` and `supplied`, including the `update_indexes`, `repay`, `withdraw`, `liquidate`, and `clean_bad_debt` paths.

### Proof of Concept
The repository contains a deterministic reproducer in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`. Conceptually, the exploit path is:

```rust
// Listed 18-decimal market whose cap admits a very large position.
let principal = 1_000_000_000i128 * 10i128.pow(18);

// One unprivileged caller supplies enough collateral and liquidity
// through ordinary controller entrypoints.
supply(caller, 0, spoke_id, vec![(collateral_asset, collateral_amount)]);
supply(caller, account_id, spoke_id, vec![(big_asset, principal)]);
borrow(caller, account_id, vec![(big_asset, principal * 98 / 100)], None);

// Time passes while utilization remains high.
// Any caller can then submit:
update_indexes(caller, vec![big_asset]);
```

The harness version supplies `1e36` raw units, borrows 98%, advances annual accrual until `update_indexes` returns `MathOverflow`, and then demonstrates that both withdrawal and repayment also fail with `MathOverflow` while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [12](#0-11)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
