The Chainlink VRF report describes a design/upgradeability concern — an immutable EVM contract's *hardcoded, non-replaceable dependency* on an external oracle service that the oracle provider itself may deprecate — not an attacker-exploitable defect with a violated invariant or attacker-controlled input. This pattern does not map onto FRAME's randomness architecture: consumers of randomness (e.g., `pallet-lottery`, `pallet-babe`, `polkadot-runtime-parachains::initializer`) already declare randomness as a pluggable associated type `type Randomness: Randomness<Self::Hash, BlockNumberFor<Self>>` in their `Config` trait [1](#0-0) , and runtime configuration (including which concrete `Randomness` implementation is wired in) is itself replaceable via a standard runtime upgrade — there is no immutable, non-upgradeable contract analog here.

Additionally, the underlying randomness trait `Randomness<Output, BlockNumber>` is a Substrate-internal abstraction implemented by pallets like `pallet-insecure-randomness-collective-flip` or BABE's VRF-derived randomness [2](#0-1) [3](#0-2) , not a call to an external, independently-operated third-party service (like Chainlink) that could unilaterally deprecate an API version out from under dependent chains. There is no reachable attacker entry point, no attacker-controlled input, and no missing check to identify — the report's core issue (external-service deprecation risk mitigated by an upgradeable bridge contract) has no exploitable FRAME/XCM/bridge analog satisfying the required entry-point, root-cause, and PoC criteria.

```rust
/// A trait that is able to provide randomness.
///
/// Being a deterministic blockchain, real randomness is difficult to come by, different
/// implementations of this trait will provide different security guarantees. At best,
/// this will be randomness which was hard to predict a long time ago, but that has become
/// easy to predict recently.
pub trait Randomness<Output, BlockNumber> {
	/// Get the most recently determined random seed, along with the time in the past
	/// since when it was determinable by chain observers.
	///
	/// `subject` is a context identifier and allows you to get a different result to
	/// other callers of this function; use it like `random(&b"my context"[..])`.
	///
	/// NOTE: The returned seed should only be used to distinguish commitments made before
	/// the returned block number. If the block number is too early (i.e. commitments were
	/// made afterwards), then ensure no further commitments may be made and repeatedly
	/// call this on later blocks until the block number returned is later than the latest
	/// commitment.
	fn random(subject: &[u8]) -> (Output, BlockNumber);
```
