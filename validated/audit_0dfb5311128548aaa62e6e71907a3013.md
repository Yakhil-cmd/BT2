### Title
Delisted collateral keeps its stamped LTV/LT and still backs new borrows (HF never re-checks the listing) - (File: contracts/controller/src/risk/totals.rs)

### Summary
Analog of CVE-2025-11429 (realm-level "Remember Me" disabled, but session-local flag keeps extended lifetime): XOXNO Lending stamps `loan_to_value` / `liquidation_threshold` / `liquidation_bonus` / `liquidation_fees` onto each supply position at creation (`AccountPositionRaw`, common/src/types/pool.rs:235-245). After governance removes an asset from a spoke (delisting), the position-level stamp is never invalidated: `calculate_account_risk_totals_body` iterates every stored supply position and weights it by its stored stamps without consulting the current `SpokeAssetConfig` (contracts/controller/src/risk/totals.rs:171-198), and `restamp_listed_supply_ltv` explicitly skips unlisted assets (`else { continue }`, contracts/controller/src/risk/params.rs:48-50). The delisting — the "realm setting change" — therefore has no effect on already-open "sessions" (positions).

### Finding Description
- On `borrow`, `validate_position_entry_gates` only enforces `require_can_borrow` on the *debt* legs (contracts/controller/src/positions/mod.rs:243-252). Collateral legs are not re-validated against `is_collateralizable` or listing status.
- The LTV restamp that runs in the borrow/withdraw risk gates (`restamp_listed_supply_ltv`) does `let Some(listed) = cache.cached_spoke_asset(...) else { continue }` — a delisted asset keeps its stale stamp (params.rs:48-50).
- The post-action gate `require_post_pool_risk_gates` (risk/validation.rs:29-60) and `build_liquidation_plan` (positions/liquidation/plan.rs:34-44) both use `calculate_account_risk_totals`, which values `scaled_amount × supply_index × price` weighted by the **stored** `liquidation_threshold`, with no listing check.
- `enforce_spoke_asset_flags` deliberately treats a missing listing as a no-op (`if let Some(sa) = ...`, positions/mod.rs:264-277) — documented so delisted assets stay exitable/seizable, but the same absence also leaves the stale risk weights untouched.
- Contrast: merely setting `is_collateralizable = false` while keeping the listing lets the next borrow restamp LTV to whatever the config still holds, but full delisting removes the only path that could ever rewrite the stamp (delisted legs are skipped in `sync_account_thresholds`/`restamp_listed_supply_ltv` via `cached_spoke_asset → None`).

So an account holding a delisted asset retains full collateral weight at its original LTV/LT and can keep calling `borrow` against it — exactly the "session overrides the new realm config" flaw.

### Impact Explanation
Protocol insolvency / theft of user funds. When governance delists an asset (typically because its oracle, liquidity, or issuer is no longer trusted), holders of that asset keep full stamped borrowing power. An unprivileged attacker who pre-positioned the asset (or already held it) can `borrow` liquid assets (USDC/XLM) up to the stale LTV against collateral the protocol intended to exclude. If the asset was delisted because its price feed is unreliable or its value is collapsing, the resulting debt is unbacked and becomes bad debt socialized onto suppliers via the supply-index write-down in `clean_bad_debt`.

### Likelihood Explanation
Requires a governance delisting while an attacker holds the asset — a routine operational action, and the attacker's only step is calling `borrow` (unprivileged) before liquidators/keepers react. No price manipulation is needed; the mere fact that HF ignores listing status makes the borrow succeed until the delisted collateral's price itself drops HF below 1 — which is precisely the scenario delisting is meant to preempt. Medium.

### Recommendation
In `calculate_account_risk_totals_body` (or `restamp_listed_supply_ltv`), treat an unlisted spoke asset as LTV = 0 / LT = 0 for risk weighting (while still valuing it at `position_value` for seizure purposes), or explicitly zero the weights when `cached_spoke_asset` returns `None` / `is_collateralizable == false`. Alternatively, have the delisting admin path zero the stamped parameters on write, and add a `has_risks` refresh path that applies to delisted legs.

### Proof of Concept
1. Alice supplies asset A (listed, LTV 7500 / LT 8000) and borrows a small amount.
2. Governance executes `EditAssetInSpoke`/removal that deletes A's `SpokeAssetConfig` (or the admin removes the listing; `get_spoke_asset` then returns `None` — the code explicitly handles missing listings).
3. Alice calls `borrow` for asset B: `validate_position_entry_gates` checks only B's `is_borrowable`; `restamp_listed_supply_ltv` skips A (`cached_spoke_asset → None`); `require_post_pool_risk_gates` computes `ltv_collateral`/`health_factor` with A's stale 7500/8000 stamps — the borrow succeeds against collateral the protocol no longer lists.
4. A's price collapses (the reason it was delisted); the position goes bad, `clean_bad_debt` writes the loss down to suppliers.
