## Title
Cross-org webhook auth bypass: verification org (`organization.login`) is decoupled from the mutated repo's org (`repository.full_name`) — ([File: app/controllers/shipit/webhooks_controller.rb])

## Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App/webhook secret to check against using `repository_owner`, which falls back to `params.dig('organization', 'login')` when `repository.owner.login` is absent. All downstream handlers (e.g. `LabelCapturingHandler`, `OpenedHandler`, `ClosedHandler`) instead resolve the target `Repository` purely from `params.repository.full_name`. Nothing binds these two values together, so an attacker can pick an org with no `webhook_secret` for verification while pointing `repository.full_name` at a completely different, protected org's repo.

## Finding Description
The broken binding, stated as an equality that must hold but does not:

`org_used_for_verification (params.dig('organization','login'))` == `org_owning_target_repo (Repository.from_github_repo_name(params.repository.full_name).org)`

Trace:
- `verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` [1](#0-0) .
- `repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')` [2](#0-1) .
- `verify_webhook_signature` returns `true` unconditionally when the resolved `GitHubApp` has no `webhook_secret` configured [3](#0-2) .
- On success, `create` parses the raw body and dispatches the *same, unmodified* `params` hash to every registered handler for the event: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
- `LabelCapturingHandler` (and sibling handlers `OpenedHandler`, `ClosedHandler`, `LabeledHandler`, etc.) resolve the mutated repository solely via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, with no reference back to `organization.login` or to the org used in `verify_signature` [5](#0-4) , [6](#0-5) .
- The `params` schema for these handlers only requires `repository.full_name`, not `repository.owner.login` [7](#0-6) , so an attacker's raw JSON body is free to omit `repository.owner.login` entirely, forcing the controller's fallback to `organization.login`.

Exploit flow: attacker crafts a raw POST to `/webhooks` with header `X-Github-Event: pull_request`, body containing `{"organization":{"login":"OrgOne"}, "repository":{"full_name":"OrgTwo/victim-repo"}, "pull_request": {...fully populated...}, "action":"opened", ...}` and no `X-Hub-Signature` (or any garbage value). `OrgOne` is a configured GitHub App with `webhook_secret: nil`; `OrgTwo` is the protected org that actually owns the target repo and has a real `webhook_secret` configured. `repository_owner` resolves to `"OrgOne"`, `Shipit.github(organization: "OrgOne").verify_webhook_signature` short-circuits to `true` because `OrgOne` has no secret — no signature or secret is ever needed. The handler then loads and mutates the real `OrgTwo/victim-repo` repository/stack/pull-request records based on `repository.full_name`, e.g. updating PR labels via `capture_labels` [8](#0-7) , or provisioning/unarchiving a review stack through `ReviewStackAdapter#find_or_create!` for `OpenedHandler` [9](#0-8) .

Existing guards do not catch this: `verify_signature` only checks the secret of the org it derives from the payload itself (attacker-controlled), and never cross-checks that org against `repository.full_name`'s org; `drop_unhandled_event` only filters by event type, not by org/repo consistency; the `ExplicitParameters` schema (`params do ... end`) for these handlers does not require or validate `repository.owner.login` at all, so it does not force the two org references to agree.

## Impact Explanation
An unauthenticated, unprivileged attacker (any internet user, no GitHub App secret, no Shipit session) can forge webhook events that mutate state belonging to a different, protected GitHub organization/repository than the one used for signature "verification." Concretely this allows: writing to `PullRequest#labels` for a victim repo's review stack, and — via `OpenedHandler`/`ClosedHandler`/`LabeledHandler` — creating, unarchiving, or otherwise driving lifecycle transitions of `ReviewStack`s belonging to a different org than the (unauthenticated) one nominally checked. This is a payload for one repository (nominally "OrgOne", unauthenticated) mutating another organization's (`OrgTwo`) stack/PR state — matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." The attack is fully repeatable against any org pair where one org in the Shipit deployment has `webhook_secret` unset/nil while another has repos worth protecting; the attacker can target arbitrary `full_name` values as long as such a repository exists in the datastore.

## Likelihood Explanation
Preconditions: the Shipit deployment must be configured with the multi-org `secrets.github` schema and at least one configured org with `webhook_secret` nil/blank (as in the `secrets_double_github_app.yml` dummy config pattern) alongside another org that has a real secret and owns a tracked repository. Given that precondition, attacker cost is trivial: a single unauthenticated HTTP POST with a hand-crafted JSON body and no valid signature. No GitHub App keys, no session, no API token are required. This is fully repeatable and scriptable against any repo tracked by Shipit as long as one org in the same instance has no webhook secret.

## Recommendation
Bind the org used for signature verification to the org that will actually be mutated. Concretely: derive `repository_owner` strictly from `repository.full_name`'s owner (or from `repository.owner.login`) rather than falling back to the independent `organization.login` field, and/or require handlers to validate that `params.repository.full_name`'s org matches the org whose `GitHubApp`/secret was used to verify the request signature before processing. At minimum, remove the `organization.login` fallback in `repository_owner`, or reject requests where `repository.owner.login` is missing but a `repository` block with `full_name` is present.

## Proof of Concept
Minitest plan (to be placed under `test/controllers/webhooks_controller_test.rb` and/or `test/models/shipit/webhooks/handlers/pull_request/label_capturing_handler_test.rb`, using a fixture setup mirroring `test/dummy/config/secrets_double_github_app.yml` with `OrgOne` (`webhook_secret: nil`) and `OrgTwo` (`webhook_secret: "real-secret"`)):

1. Create `shipit_repositories(:org_two_repo)` with `owner: "OrgTwo"`, `name: "victim-repo"`, review stacks enabled, and an existing `Shipit::ReviewStack`/`PullRequest` for PR #2.
2. Build a raw JSON body: `{"action":"labeled","number":2,"pull_request":{...valid full pull_request block, including a new label...},"repository":{"full_name":"OrgTwo/victim-repo"},"organization":{"login":"OrgOne"},"sender":{"login":"attacker"}}` — deliberately omitting `repository.owner`.
3. POST to `:create` with `X-Github-Event: pull_request` and no valid `X-Hub-Signature` header.
4. Assert on both sides of the binding:
   - `repository_owner` resolves to `"OrgOne"` (assert via stubbing/inspecting `Shipit.github(organization: "OrgOne")` is the one queried, e.g. `Shipit.github(organization: "OrgOne").expects(:verify_webhook_signature).returns(true)` is NOT needed to be stubbed since `webhook_secret` is nil — assert `response.status` is not `422`).
   - Assert `Shipit::Repository.from_github_repo_name("OrgTwo/victim-repo")` is the repository actually mutated: `assert_equal ["new-label"], pull_request.reload.labels` where `pull_request` belongs to the `OrgTwo` stack.
5. Assert explicitly that `"OrgOne" != "OrgTwo"` (the verification org vs. the mutated repo's org) to document the broken binding, while the PR/stack record for `OrgTwo` was nonetheless updated.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
