### Title
Binary extension installation trusts unverified downloaded content before execution - (File: pkg/cmd/extension/http.go)

### Summary
The OpenLevV1 report describes a root cause of using an externally-reported value (a DEX-returned swap amount) for critical accounting/repayment logic without verifying what was *actually* received. The analogous class of bug in `gh` is trusting externally-supplied downloaded content for a security-sensitive purpose (execution) without any content verification. In `gh`, the binary-extension install path downloads a release asset and writes it directly to disk as an executable with no digest/checksum verification, unlike the equivalent Copilot CLI downloader in the same codebase, which does perform such verification.

### Finding Description
`downloadAsset` in `pkg/cmd/extension/http.go` streams an HTTP response body directly to a file opened with executable permissions, with no validation that the received bytes match any expected value: [1](#0-0) 

This function is called by `Manager.installBin` in `pkg/cmd/extension/manager.go`, which selects a release asset returned by the GitHub API and downloads it straight into the extension's install directory as the binary that will later be executed: [2](#0-1) [3](#0-2) 

Once installed, the file is later executed directly via `exec.Cmd` in `Manager.Dispatch`: [4](#0-3) 

No digest, checksum, or attestation is checked between what the release metadata described and what was actually written to disk before that content is treated as a trusted, executable binary.

Contrast this with `downloadCopilot` in `pkg/cmd/copilot/copilot.go`, which performs the same category of operation (download a binary release asset over HTTP and use it as an executable) but explicitly fetches a `SHA256SUMS.txt` file and validates the actual downloaded bytes' hash against the expected checksum before extracting/using the binary: [5](#0-4) 

This mirrors the OpenLevV1 pattern exactly: one code path (`downloadCopilot`, analogous to the "V2 DEX" path with balance-diff accounting) verifies the actual result of an external operation before trusting it, while the other code path (`downloadAsset`/`installBin`, analogous to the "V3 DEX" path) blindly trusts what was returned/received and uses it directly for a sensitive operation — here, subsequent execution as a native binary rather than fund transfer accounting.

### Impact Explanation
If the bytes delivered by the asset URL differ from what was actually published/intended (due to compromise of the release asset, a compromised or malicious intermediary in the download path, or any tampering between publication and download), `gh extension install`/`upgrade` will silently accept and later execute the unverified content with no detection, since there is no checksum, size, or attestation cross-check performed. This is a verification-bypass / integrity gap directly analogous to the reported class ("accounting/trust of an externally reported value instead of the actually delivered value"), and it can lead to arbitrary native code execution on the user's machine because the file is executed unconditionally by `Manager.Dispatch` once installed.

### Likelihood Explanation
The binary-extension install flow is a common feature (`gh extension install <owner>/<repo>`) exercised whenever a user installs or upgrades a binary-type extension, and the vulnerable function (`downloadAsset`) is reached on every such install without any opt-out or extra flag. The presence of a checksum-verified sibling implementation (`downloadCopilot`) in the same codebase for essentially the same operation demonstrates that this integrity check is a known, applicable mitigation that was implemented for one binary-download path but not for the extension-binary path, increasing confidence that the omission is a real gap rather than an intentional design choice unique to this feature.

### Recommendation
Apply the same download-and-verify pattern used in `downloadCopilot` to `downloadAsset`/`installBin`: fetch a checksum/digest (or, ideally, a cryptographic attestation as already supported elsewhere in `gh`, e.g. `pkg/cmd/release/verify-asset`) associated with the release asset, download to a temporary location while computing a hash over the actual received bytes via `io.TeeReader`, and only move/rename the file into the extension's executable install path after the computed hash matches the expected value. Reject and abort installation on any mismatch, exactly as `downloadCopilot` does.

### Proof of Concept
Because this repository is a CLI application (not a smart contract), there is no on-chain PoC. The vulnerable logical flow can be traced statically:
1. `Manager.Install` → `Manager.installBin` selects a release asset from GitHub API-reported metadata: [6](#0-5) 
2. `downloadAsset` writes the HTTP response body directly to `binPath` with mode `0755` and no verification: [1](#0-0) 
3. The resulting file is later executed unconditionally by `Manager.Dispatch`: [7](#0-6) 

If the content delivered at asset download time diverges from what was intended/published (any tampering along that HTTP path or on the hosting side), `gh` has no mechanism to detect the discrepancy before executing it — the same "trust the returned amount/content without verifying what was actually received" root cause identified in the original report.

// downloadAsset downloads a single asset to the given file path.
func downloadAsset(httpClient *http.Client, assetURL safeurl.SafeURL, destPath string) (downloadErr error) {
	var req *http.Request
	if req, downloadErr = http.NewRequest("GET", assetURL.String(), nil); downloadErr != nil {
		return
	}

	req.Header.Set("Accept", "application/octet-stream")

	var resp *http.Response
	// TODO(api-client-rollout)
	// This has been deferred from moving to api.Client due to its custom Accept header and binary response streaming.
	if resp, downloadErr = httpClient.Do(req); downloadErr != nil {
		return
	}
	defer resp.Body.Close()

	if resp.StatusCode > 299 {
		downloadErr = api.HandleHTTPError(resp)
		return
	}

	var f *os.File
	if f, downloadErr = os.OpenFile(destPath, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, 0755); downloadErr != nil {
		return
	}
	defer func() {
		if err := f.Close(); downloadErr == nil && err != nil {
			downloadErr = err
		}
	}()

	_, downloadErr = io.Copy(f, resp.Body)
	return
}

func (m *Manager) Dispatch(args []string, stdin io.Reader, stdout, stderr io.Writer) (bool, error) {
	if len(args) == 0 {
		return false, errors.New("too few arguments in list")
	}

	var exe string
	extName := args[0]
	forwardArgs := args[1:]

	exts, _ := m.list(false)
	var ext *Extension
	for _, e := range exts {
		if e.Name() == extName {
			ext = e
			exe = ext.Path()
			break
		}
	}
	if exe == "" {
		return false, nil
	}

	var externalCmd *exec.Cmd

	if ext.IsBinary() || runtime.GOOS != "windows" {
		externalCmd = m.newCommand(exe, forwardArgs...)
	} else if runtime.GOOS == "windows" {
		// Dispatch all extension calls through the `sh` interpreter to support executable files with a
		// shebang line on Windows.
		shExe, err := m.findSh()
		if err != nil {
			if errors.Is(err, exec.ErrNotFound) {
				return true, errors.New("the `sh.exe` interpreter is required. Please install Git for Windows and try again")
			}
			return true, err
		}
		forwardArgs = append([]string{"-c", `command "$@"`, "--", exe}, forwardArgs...)
		externalCmd = m.newCommand(shExe, forwardArgs...)
	}
	// Signal to the extension that it is being run by gh rather than standalone, so it can
	// adjust things like usage strings.
	externalCmd.Env = append(externalCmd.Environ(), "GH_EXTENSION=1")

	externalCmd.Stdin = stdin
	externalCmd.Stdout = stdout
	externalCmd.Stderr = stderr
	return true, externalCmd.Run()

// Install installs an extension from repo, and pins to commitish if provided
func (m *Manager) Install(repo ghrepo.Interface, target string) error {
	isBin, err := isBinExtension(m.client, repo)
	if err != nil {
		if errors.Is(err, releaseNotFoundErr) {
			if ok, err := repoExists(m.client, repo); err != nil {
				return err
			} else if !ok {
				return repositoryNotFoundErr
			}
		} else {
			return fmt.Errorf("could not check for binary extension: %w", err)
		}
	}
	if isBin {
		return m.installBin(repo, target)
	}

	hs, err := hasScript(m.client, repo)
	if err != nil {
		return err
	}
	if !hs {
		return fmt.Errorf("extension is not installable: no usable release artifact or script found in %s", ghrepo.FullName(repo))
	}

	return m.installGit(repo, target)
}

		r, err = fetchReleaseFromTag(m.client, repo, target)

		r, err = fetchLatestRelease(m.client, repo)

		return err

	platform, ext := m.platform()
	isMacARM := platform == "darwin-arm64"
	trueARMBinary := false

	var asset *releaseAsset

		if strings.HasSuffix(a.Name, platform+ext) {
			asset = &a

			break
		}
