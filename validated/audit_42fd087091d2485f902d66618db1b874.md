### Title
Unvalidated `payload` access in `definition` messages causes NULL/undefined pointer dereference and node crash - (File: network.js)

### Summary
`network.js`'s `getAllAuthorsAndOutputAddresses()` dereferences `message.payload.definition[1].base_aa` for any message with `app === 'definition'` without first checking that `payload` (or `payload.definition`) actually exists, unlike the sibling `"payment"` branch which explicitly checks `payload` truthiness first. This mirrors the CVE-2020-35507 pattern: a NULL pointer dereference while processing a crafted/attacker-controlled structure whose expected sub-field is absent, causing a crash and loss of availability.

### Finding Description
`validation.js` only validates the shape of a `"definition"` message's payload inside `validateInlinePayload`'s `case "definition":` branch [1](#0-0) , which is reached only when `payload_location === "inline"`. Nothing in `validateMessage`/generic message validation forces `app === "definition"` messages to have `payload_location === "inline"`; a unit poster can submit a message `{app: "definition", payload_location: "none", payload_hash: <hash>}` (or `"uri"`) which never enters the `case "definition"` shape checks, leaving `message.payload` absent, and such a unit still passes overall unit validation.

Later, when the unit/joint is processed for watcher notification, `getAllAuthorsAndOutputAddresses()` iterates all messages and does:
```
else if (message.app === 'definition' && payload.definition[1].base_aa)
``` [2](#0-1) 
Here `payload` is `message.payload`, which is `undefined` for a non-inline `"definition"` message, so `payload.definition` throws a `TypeError: Cannot read properties of undefined`. Note that the adjacent `"payment"` branch guards against a missing payload (`payload && ...`) but the `"definition"` branch does not [3](#0-2) .

This function is invoked from `notifyOfBadSequence`-style flow when reading joints for watcher notification [4](#0-3) , a code path executed by the node for every stored/rewritten unit it becomes aware of, not requiring any special privilege from the sender — a normal unit author can trigger it simply by posting a unit containing a `"definition"` message without an inline payload.

### Impact Explanation
An uncaught `TypeError` thrown synchronously inside a `storage.readJoint` callback used during watcher/sequence notification will propagate as an uncaught exception in Node.js, which by default terminates the process. Any full node (including hubs) that processes such a unit while running sequence/notification logic can be crashed, denying service and preventing that node from confirming/serving new units until restarted — matching the "network unable to confirm new units" impact criterion.

### Likelihood Explanation
Likelihood is high: constructing a message with `app: "definition"` and `payload_location: "none"`/`"uri"` (thus omitting `payload`) requires no special permissions beyond being able to post a unit, and passes the generic message-shape checks since the `"definition"`-specific payload validation is gated behind `payload_location === "inline"`.

### Recommendation
In `getAllAuthorsAndOutputAddresses()` (network.js), guard the `"definition"` branch the same way the `"payment"` branch is guarded, e.g.:
```
else if (message.app === 'definition' && payload && payload.definition && payload.definition[1] && payload.definition[1].base_aa)
```
Additionally/alternatively, enforce in `validateMessage`/`validation.js` that `app === "definition"` messages must have `payload_location === "inline"`, eliminating the possibility of a definition message with a missing payload reaching downstream code.

### Proof of Concept
1. Craft and post a unit containing a message: `{ "app": "definition", "payload_location": "none", "payload_hash": "<valid 44-char base64 hash>" }` (no `payload` field), alongside a valid base payment message so the unit otherwise validates.
2. Once the node accepts/stores this unit and later calls `getAllAuthorsAndOutputAddresses(objUnit)` during watcher/sequence notification (`network.js:1613`), the loop reaches the `"definition"` branch with `payload === undefined`, and `payload.definition[1].base_aa` throws `TypeError: Cannot read properties of undefined (reading 'definition')`, crashing the node process.
