### Title
Path traversal in `gh release download` via unsanitized asset `Name` allows arbitrary file write outside `--dir` - ([File: pkg/cmd/release/download/download.go])

### Summary
`downloadRun` builds `downloadTarget.name` directly from the untrusted `ReleaseAsset.Name` field of the release JSON and passes it unmodified to `destinationWriter.makePath`, which does a bare `filepath.Join(w.dir, name)` with no traversal/confinement check. Unlike `pkg/cmd/run/download` and `internal/zip`, which use `internal/safepaths.Absolute.Join` to reject paths that escape the destination directory, the release-download code path has no such protection, so an asset name containing `../` sequences (or, on a malicious/attacker-controlled host, an absolute path) can cause writes outside `--dir`.

### Finding Description
The vulnerable flow is:
- `downloadRun` iterates `release.Assets` and copies `a.Name` verbatim into `targets[i].name` [1](#0-0)  where `a` comes from `shared.Release.Assets`, a `[]ReleaseAsset` decoded straight from the release API JSON with no path sanitization on the `Name` field [2](#0-1) .
- `downloadAsset` calls `dest.Check(fileName)` and `dest.Copy(fileName, resp.Body)` with that name [3](#0-2) [4](#0-3) .
- `destinationWriter.makePath` resolves the final path with a plain `filepath.Join(w.dir, name)`, with no call to `internal/safepaths.Absolute.Join` or any traversal check [5](#0-4) .
- `Copy` then does `os.MkdirAll(filepath.Dir(fp), 0755)` and `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` on that unconfined path [6](#0-5) .

In contrast, the actions-artifact download path in `pkg/cmd/run/download` and the zip-extraction code in `internal/zip` deliberately confine extracted paths using `internal/safepaths.Absolute.Join`, which explicitly rejects joins that traverse outside the base directory via `PathTraversalError` [7](#0-6) . No equivalent check exists in `destinationWriter.makePath`.

Against the real GitHub API, asset names are sanitized server-side on upload (the client itself documents and mimics this behavior in `sanitizeFileName`, which strips characters including `/` before upload) [8](#0-7) , so a normal repository owner cannot get a `/`-containing name into a genuine github.com release asset. However, `gh` is also used against attacker-controlled or malicious hosts (e.g., a `-R`-targeted repo on a rogue GHES-compatible endpoint, or any host the victim points `gh` at), and in that scenario the attacker fully controls the JSON response and is not bound by GitHub's real upload-time sanitization, so `name` can be set to arbitrary values such as `../../.ssh/authorized_keys`.

### Impact Explanation
If the response is fully attacker-controlled, `filepath.Join(w.dir, "../../.ssh/authorized_keys")` escapes the intended `--dir` and `os.OpenFile` with `O_TRUNC|O_CREATE` overwrites/creates an arbitrary file reachable from the resolved path relative to the victim's working directory, potentially clobbering sensitive files (SSH authorized_keys, shell rc files, git hooks) — matching GitHub Bug Bounty's "arbitrary file write" impact class.

### Likelihood Explanation
This is only reachable when the victim runs `gh release download` (or `gh release download --archive`, which sets an empty pseudo-name and is not directly affected by the asset-name vector) against a release whose JSON metadata is not subject to github.com's own upload-time name sanitization — i.e., an attacker-controlled/malicious API host, or any future/alternate scenario where the sanitization in `sanitizeFileName` is bypassed or absent server-side. Against genuine github.com repositories, the described exploit is blocked by the platform's own asset-name sanitization, which limits real-world exploitability of this specific vector but does not remove the underlying missing-confinement defect in `destinationWriter.makePath`, which is inconsistent with the confinement discipline used elsewhere in the codebase (`internal/safepaths`, `internal/zip`, `pkg/cmd/run/download`).

### Recommendation
Confine `makePath`'s output using `internal/safepaths.Absolute.Join` (as already done in `pkg/cmd/run/download`), rejecting or erroring out on any asset `Name` that resolves outside `w.dir`, regardless of the trustworthiness of the API host.

func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}

// this method attempts to mimic the same functionality on the client that the platform does on
// uploaded assets in order to allow the --clobber logic work correctly, since that feature is
// one that only exists in the client
func sanitizeFileName(name string) string {
	value := text.RemoveDiacritics(name)
	// Stripped all non-ascii characters, provide default name.
	if strings.HasPrefix(value, ".") {
		value = "default" + value
	}

	// Replace special characters with the separator
	value = regexp.MustCompile(`(?i)[^a-z0-9\-_\+@]+`).ReplaceAllLiteralString(value, ".")

	// No more than one of the separator in a row.
	value = regexp.MustCompile(`\.{2,}`).ReplaceAllLiteralString(value, ".")

	// Remove leading/trailing separator.
	value = strings.Trim(value, ".")

	// Just file extension left, add default name.
	if name != value && !strings.Contains(value, ".") {
		value = "default." + value
	}

	return value
}
