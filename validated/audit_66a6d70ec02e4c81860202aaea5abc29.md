### Title
Webhooks are unauthenticated for any GitHub organization configured without a `webhook_secret` - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when `webhook_secret` is not configured for the resolved organization, and `WebhooksController#verify_signature` treats that as a verified webhook. Any unauthenticated attacker can therefore POST a completely unsigned payload to `/webhooks` naming such an organization in `repository.owner.login`, and every registered `Webhooks::Handlers::*` for that event will execute with attacker-controlled `params`.

### Finding Description
The binding that must hold for verification to be meaningful is: `webhook_secret.present?` for the organization named in the request must be `true`, otherwise the "verified" result carries no authentication information. In code: [1](#0-0) 

`verify_webhook_signature` starts with `return true unless webhook_secret` — when the configured `@webhook_secret` for that org is blank, the method returns `true` regardless of the signature argument, even if `signature` is `nil` (no `X-Hub-Signature` header at all).

`WebhooksController#verify_signature` resolves the app purely from the attacker-supplied payload field `repository.owner.login` (or `organization.login`) and passes the (possibly absent) `X-Hub-Signature` header straight through: [2](#0-1) [3](#0-2) 

If `verified` is `true`, no 422 is raised, and `create` runs every handler registered for the event with the raw, attacker-supplied JSON body: [4](#0-3) 

Exploit flow: attacker identifies (via `Shipit` operator's public config conventions/deployment docs, or simply by trial) an organization entry in the host's GitHub apps config that has no `webhook_secret` set. Attacker sends `POST /webhooks` with header `X-Github-Event: push` (or `check_suite`, `status`, `membership`, etc.) and a JSON body where `repository.owner.login` (or `organization.login`) equals that organization's slug — with no `X-Hub-Signature` header. `Shipit.github(organization: <that org>)` resolves the `GitHubApp` for it, `verify_webhook_signature(nil, raw_post)` returns `true` because `webhook_secret` is blank, and the corresponding handler (e.g. `Webhooks::Handlers::Push`, which enqueues `GithubSyncJob`, or `Webhooks::Handlers::Status`, which writes a `CommitStatus`) executes as if GitHub had sent it.

No existing guard blocks this: `drop_unhandled_event` only filters unknown event types, not authentication; `check_if_ping` is unrelated; there is no `force_github_authentication`/`ExplicitParameters`/model validation standing between the unsigned request and handler execution — the only authentication gate is `verify_signature`, and it is bypassed by design once `webhook_secret` is absent for the named org.

### Impact Explanation
For any organization whose `Shipit.github` config lacks `webhook_secret`, an unauthenticated internet attacker can forge arbitrary webhook events (push, status, check_suite, membership, pull_request, etc.) attributed to any repository under that organization. This drives real writes: `GithubSyncJob` enqueuing for arbitrary stacks, `CommitStatus` creation/mutation, team/membership creation or deletion, and any other `Webhooks::Handlers::*` logic — all without possessing `webhook_secret`, a session, or an API token. This is an authentication bypass on webhook ingestion, matching the Critical category ("authentication bypass (forged webhook ... accepted)"). The attack is fully repeatable against every event type and every repository belonging to the affected organization, and is repeatable indefinitely (no rate limiting/nonce).

### Likelihood Explanation
The only precondition is that the deployed Shipit instance has at least one organization configured in `Shipit.github` without a `webhook_secret` value — a configuration state the code explicitly tolerates (`@webhook_secret = @config[:webhook_secret].presence`) rather than rejecting. No attacker-held secret is required; cost is a single unauthenticated HTTP POST. This is entirely a function of host configuration, but the engine's code is what silently converts "no secret configured" into "request verified," rather than failing closed or refusing to serve webhooks for that org.

### Recommendation
Fail closed instead of open: in `GitHubApp#verify_webhook_signature`, if `webhook_secret` is blank, return `false` (or raise/log a misconfiguration error) rather than `true`. Optionally, add a startup/config validation that requires `webhook_secret` to be present for every configured GitHub organization, and have `WebhooksController#verify_signature` reject requests missing `X-Hub-Signature` outright before delegating to `verify_webhook_signature`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "unsigned webhook is accepted when organization has no webhook_secret configured" do
  github_app = Shipit::GitHubApp.new('unsecured-org', { app_id: 1, installation_id: 1, private_key: 'x' }) # no webhook_secret
  Shipit.stubs(:github).with(organization: 'unsecured-org').returns(github_app)

  @request.headers['X-Github-Event'] = 'push'
  # deliberately NOT setting X-Hub-Signature

  payload = JSON.parse(payload(:push_master))
  payload['repository']['owner']['login'] = 'unsecured-org'

  mock_handler = mock
  mock_handler.expects(:call).once
  Shipit::Webhooks.handlers['push'] = [mock_handler]

  post :create, body: payload.to_json, as: :json

  assert_response :ok # not :unprocessable_entity
end
```
Both sides of the binding diverge: `webhook_secret.present?` is `false` for `unsecured-org`, yet `verified` is forced `true` and the handler still runs — confirming the bypass.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
