### Title
Webhook signature is verified against `repository.owner.login`'s organization while stack resolution uses the unrelated `repository.full_name` field, letting a secret-less/attacker-controlled org's "valid" signature unarchive a victim org's review stack - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/reopened_handler.rb`)

### Summary
`WebhooksController#verify_signature` derives the organization used to look up the HMAC secret from `params.dig('repository', 'owner', 'login')`, while `PullRequest::ReopenedHandler#repository` independently resolves the target `Shipit::Repository` from `params.repository.full_name`. Nothing ties these two payload fields together, so a JSON body can name one organization for signature verification and a completely different organization/repo for the actual mutation.

### Finding Description
The claimed binding is: `organization used in Shipit.github(organization: repository_owner)` (webhooks_controller.rb:25, derived at line 61 from `params.dig('repository','owner','login')`) `== organization owning the ReviewStack unarchived by stack.unarchive!` (reopened_handler.rb:44, resolved at lines 50-52 via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`).

These are two independently-read fields of the same attacker-supplied JSON body:
- `repository_owner` (webhooks_controller.rb:59-62) reads `repository.owner.login`.
- `repository` in the handler (reopened_handler.rb:49-53) reads `repository.full_name` and splits it on `/` (`Repository.from_github_repo_name`, repository.rb:53-56).

`GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) contains `return true unless webhook_secret` - if the organization resolved for verification has no `webhook_secret` configured in Shipit's secrets, **any signature (or none) is accepted** for that organization's traffic.

Exploit flow: an attacker crafts a raw POST to `/webhooks` with header `X-Github-Event: pull_request` and a JSON body where `repository.owner.login` = an organization known to be registered in Shipit without a `webhook_secret` (secret-less org), but `repository.full_name` = `"victim_org/victim_repo"`. `verify_signature` calls `Shipit.github(organization: "secretless_org")`, gets a `GitHubApp` with `@webhook_secret` nil, and `verify_webhook_signature` returns `true` unconditionally - no valid signature is required at all. The request passes to `ReopenedHandler#process`, which resolves `repository` from `full_name = "victim_org/victim_repo"`, looks up that org's `provisioning_behavior`/`review_stacks_enabled` settings, and if `unarchive?` conditions hold (e.g., `provisioning_behavior_allow_all?`), calls `stack.unarchive!` on the victim's archived `ReviewStack`, re-enabling its deploy eligibility.

Existing guards that fail to prevent this: `verify_signature` only checks that *some* valid (or trivially bypassed) signature exists for whatever org happens to be named in `repository.owner.login`; it never confirms that org matches the org actually referenced by `repository.full_name`, which is what the handler and `Repository.from_github_repo_name` actually act on. `drop_unhandled_event` and `ExplicitParameters` schema checks only validate shape/types, not cross-field consistency.

### Impact Explanation
An attacker with no Shipit credentials can force an unauthorized lifecycle mutation (`ReviewStack#unarchive!`) on a victim organization's stack, re-enabling deploy/provisioning eligibility for a repository the attacker never authenticated against - a payload nominally "from" one (secret-less) organization mutating another organization's stack. This matches the Critical category "a payload for one repository mutating another's stack." The attack is repeatable against any victim repo/PR-number combination as long as at least one organization in the Shipit instance's config lacks a `webhook_secret` (or the attacker can otherwise produce a valid signature for the organization named in `repository.owner.login`, independent of `full_name`).

### Likelihood Explanation
This requires that the Shipit deployment has at least one configured GitHub organization with no `webhook_secret` set (a real, documented configuration state, per `lib/shipit/github_app.rb:50,76-77` and `config/secrets.development.example.yml`), and that the victim organization has `review_stacks_enabled` with a permissive `provisioning_behavior` and an existing archived `ReviewStack` matching the crafted `environment`/PR number. The attacker needs no Shipit session, API token, or webhook secret - only the ability to send a raw HTTP POST to `/webhooks` with a crafted body, which is explicitly in-scope for the attacker model.

### Recommendation
Bind signature verification to the same repository identity used by handlers: derive the verification organization from `repository.full_name`'s owner segment (not `repository.owner.login`), or explicitly validate that `repository.owner.login` matches the owner segment parsed from `repository.full_name` before proceeding. Additionally, treat a missing `webhook_secret` as a configuration error rather than an implicit signature bypass (`GitHubApp#verify_webhook_signature` should not `return true unless webhook_secret`).

require 'test_helper'

module Shipit
  class ReopenedCrossOrgUnarchiveTest < ActionController::TestCase
    tests Shipit::WebhooksController

    setup do
      # victim org/repo, fully configured with a webhook_secret in test secrets
      @victim_repo = shipit_repositories(:shipit) # or create one with owner: 'victim_org', name: 'victim_repo'
      @victim_repo.update!(provisioning_behavior: 'allow_all', review_stacks_enabled: true)
      @stack = @victim_repo.review_stacks.create!(environment: 'pr42', branch: 'master')
      @stack.archive!(shipit_users(:walrus))
      assert @stack.archived?
    end

    test "reopened webhook naming a secret-less org's owner.login cannot unarchive victim org's stack via mismatched full_name" do
      payload = {
        action: 'reopened',
        number: 42,
        pull_request: {
          id: 1, number: 42, url: 'x', title: 'x', state: 'open',
          additions: 1, deletions: 1,
          head: { sha: 'a' * 40, ref: 'feature' },
          user: { login: 'attacker' },
          assignees: [], labels: []
        },
        repository: {
          full_name: 'victim_org/victim_repo',        # <- names the victim
          owner: { login: 'secretless_org' }           # <- org with no webhook_secret configured
        },
        sender: { login: 'attacker' }
      }.to_json

      @request.headers['X-Github-Event'] = 'pull_request'
      @request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # invalid/unrelated signature

      post :create, body: payload

      @stack.reload
      # Binding check: verifying org ('secretless_org') != owning org ('victim_org').
      # A correct implementation must reject this and leave the victim stack archived.
      assert @stack.archived?, "victim org's stack was unarchived by a payload verified under a different, secret-less org"
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
