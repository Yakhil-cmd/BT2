### Title
Strategy fee is minted as debt and accrues interest although the borrower never receives it - (File: contracts/pool/src/ops/strategy.rs)

### Summary
`strategy::accounting` mints debt for the full requested `amount` but only transfers `amount - fee` to the receiver; the withheld `fee` is immediately booked as protocol revenue. The fee portion of the debt sits in the borrower's scaled-debt position and compounds at the borrow index forever, so the user pays interest on tokens they never received and that the protocol already collected.

### Finding Description
In `contracts/pool/src/ops/strategy.rs`:

- `compute_fee` computes `fee = flashloan_fee_bps × amount` when `charge_fee` is true (lines 94-100).
- `borrow::mint_debt(env, &mut cache, &mut position, amount)` mints scaled debt for the **gross** `amount` (line 70), not `amount - fee`.
- `add_protocol_revenue` converts `fee` to supply shares and mints them into `revenue`/`supplied` (line 73), i.e. the fee is paid to the treasury immediately.
- `cache.debit_cash(amount - fee)` and `transfer_out(receiver, amount_received)` send only the net to the receiver (lines 75-79, 39).

The minted scaled debt is a claim against `borrowed × borrow_index`; `accrue_step` (`common/src/rates/simulate.rs:51-94`) grows `borrow_index` on the whole `borrowed` balance, including the fee component. The pool's cash and the treasury's revenue shares are already correct — yet the borrower keeps accruing compounding interest on the fee leg. This is exactly the reported class: a borrowing fee added to debt that the borrower never received, accumulating interest.

Reachability is unprivileged: the controller's `multiply`/`flash_position` strategy path calls `create_strategy`/`strategy::apply` with `charge_fee = true` (the test `test_create_strategy_fee_cannot_bypass_max_utilization` in `contracts/pool/tests/flows.rs:1405-1426` exercises exactly this path with a non-zero `flashloan_fee`).

### Impact Explanation
Every strategy opened with `charge_fee` overstates the borrower's debt by `fee` in asset terms, and that overstatement compounds at the market borrow rate. The borrower pays interest on the fee indefinitely and can be pushed toward liquidation by debt growth on funds never received. This is a direct, unbounded loss of user funds proportional to fee size and time.

### Likelihood Explanation
Any user calling the strategy/multiply entrypoint on a market with `flashloan_fee > 0` incurs it deterministically. `flashloan_fee` is a configured market parameter; the fee path is the designed behavior for charged strategies, so it triggers on every use, not an edge case.

### Recommendation
Mint debt only for the amount the borrower actually owes or received: either mint `amount - fee` of debt (fee collected purely from cash), or track the fee as a separate non-interest-bearing liability. Do not include withheld fees in scaled debt that the borrow index compounds.

### Proof of Concept
```rust
// contracts/pool/src/ops/strategy.rs (simplified actual flow)
let fee = compute_fee(env, &cache, amount, charge_fee);        // fee = bps * amount
borrow::mint_debt(env, &mut cache, &mut position, amount);     // debt = GROSS amount
interest::add_protocol_revenue(&mut cache, protocol_fee);      // fee -> treasury shares
let amount_to_send = amount - fee;
cache.debit_cash(amount_to_send);                              // receiver gets NET
```
1. Market has `flashloan_fee = 500` (5%), flash loans enabled, supplier deposits 10_000e6.
2. User opens a strategy via controller `multiply`/`flash_position` with `amount = 1_000e6`, `charge_fee = true`.
3. Debt minted: `1_000e6` scaled; user receives `950e6`; treasury booked `50e6` of revenue shares.
4. After time passes and `update_indexes` runs, `borrow_index` grows; user's owed amount exceeds `1_000e6 × index`, i.e. interest was charged on the `50e6` fee the user never received and the treasury already holds. Repaying principal+interest requires the user to cover the compounding fee leg — pure overcharge.
