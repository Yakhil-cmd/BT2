### Title
Hand-rolled frontmatter parser fails to strip inline `#` comments, silently downgrading `action: block` rules to warn - ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter()` in `plugins/hookify/core/config_loader.py` parses top-level `key: value` lines with a naive `split(':', 1)` and only strips surrounding quotes, without stripping trailing inline `#` comments as a real YAML parser (e.g. PyYAML) would. A `.claude/hookify.*.local.md` file authored/committed by an attacker with a line like `action: block  # do not remove` is parsed into `action = "block  # do not remove"` instead of `"block"`, which fails the exact string comparison `rule.action == 'block'` in `plugins/hookify/core/rule_engine.py`, silently routing the rule into the warn-only path even though the file visually declares a blocking rule.

### Finding Description
The call chain is `load_rules()` → `load_rule_file()` → `extract_frontmatter()` → `Rule.from_dict()`, all in [1](#0-0) . `load_rules()` globs `.claude/hookify.*.local.md` relative to the process's current working directory, i.e. any repo-tracked file matching that pattern that ends up in a cloned/checked-out repository is picked up automatically without any additional trust check [2](#0-1) .

Inside `extract_frontmatter()`, top-level key/value lines are parsed with:
```python
key, value = line.split(':', 1)
key = key.strip()
value = value.strip()
...
value = value.strip('"').strip("'")
if value.lower() == 'true':
    value = True
elif value.lower() == 'false':
    value = False
frontmatter[key] = value
``` [3](#0-2) 

There is no logic to strip a trailing ` # comment` portion of the value. A line such as `action: block  # critical safety rule, do not disable` therefore produces `frontmatter['action'] = "block  # critical safety rule, do not disable"` verbatim, rather than the semantically-equivalent YAML value `"block"` that PyYAML (or any spec-compliant parser) would produce.

`Rule.from_dict()` copies this raw string through unchanged: `action=frontmatter.get('action', 'warn')` [4](#0-3) .

The enforcement point in `RuleEngine.evaluate_rules()` uses an exact string equality check to decide whether a matched rule blocks or merely warns:
```python
if rule.action == 'block':
    blocking_rules.append(rule)
else:
    warning_rules.append(rule)
``` [5](#0-4) 

Because the corrupted value `"block  # critical safety rule, do not disable"` is not equal to the literal string `"block"`, the rule is silently placed into `warning_rules` instead of `blocking_rules`. When the rule matches a dangerous `Bash`/`Write` operation, `evaluate_rules()` returns only a `systemMessage` (informational warning) instead of `hookSpecificOutput.permissionDecision = "deny"` [6](#0-5) , so the guarded operation is allowed to proceed. No exception, warning, or validation catches this: `load_rule_file()` only checks that `frontmatter` is non-empty, not that field values are well-formed [7](#0-6) .

This is a genuine parser differential: the file's visible YAML text (`action: block`) reads as an unambiguous blocking directive to a human reviewer (and to PyYAML), but the plugin's actual enforcement engine treats it as `warn`, i.e. "deny-means-deny" is violated purely through the custom parser's failure to model YAML comment semantics — no shell access or elevated privilege is needed by the attacker, only the ability to have such a `.claude/hookify.*.local.md` file present in a checked-out repository (e.g. via a merged pull request adding/editing a rule file, or a cloned malicious repo).

### Impact Explanation
This degrades a repo-shipped safety control (Bash/Write approval guard) from "block" to "warn" without any visible indication to the user or reviewer that the rule is broken. Combined with any other means of getting Claude Code to attempt the guarded dangerous operation (e.g. destructive `rm -rf`, credential exfiltration write, etc.), the operation that was intended to be hard-blocked will instead only produce a `systemMessage` that Claude Code (or an operator working with reduced scrutiny) can proceed past, resulting in unauthorized command/file execution. This matches an approval/guard bypass impact class: a hook-based blocking mechanism believed to enforce deny is silently converted to advisory-only.

### Likelihood Explanation
- Precondition is minimal: the attacker only needs to get a `.claude/hookify.*.local.md` file with this pattern into a repository that a victim later checks out and runs Claude Code against (via PR merge, cloned malicious repo, or checked-in plugin/rule template).
- The bug triggers deterministically for any top-level frontmatter line with a trailing `#` comment (a very natural, innocuous-looking thing to write, and even encouraged as documentation/justification text next to `action: block`).
- No shell execution or special privilege is required, and the corruption is entirely silent — `load_rule_file()` does not log or reject malformed action values, and `load_rules()` swallows only I/O/parsing exceptions, not "successfully-parsed-but-wrong" values [8](#0-7) .
- This is highly repeatable and easily reviewed: the vulnerability is essentially "does a comment after a scalar value survive the hand-rolled parser," which is true for every top-level key, not just `action`.

### Recommendation
- Strip unquoted trailing `#...` comments from parsed scalar values in `extract_frontmatter()` before applying quote-stripping and boolean coercion (careful to not strip `#` inside quoted strings).
- Better: replace the hand-rolled frontmatter parser with `yaml.safe_load()` (PyYAML) for the frontmatter block, eliminating this entire class of parser-differential bugs.
- Add strict validation in `Rule.from_dict()`/`load_rule_file()` that rejects (rather than silently normalizes) unrecognized `action` values (only `"warn"`/`"block"` allowed) and unrecognized `enabled` values, logging/erroring loudly rather than defaulting.

### Proof of Concept
Differential/unit test in `plugins/hookify` test suite:
```python
import yaml
from hookify.core.config_loader import extract_frontmatter

CONTENT = """---
name: block-dangerous-rm
enabled: true
event: bash
pattern: rm\\s+-rf
action: block  # critical safety rule, do not disable
---

Blocked!
"""

def test_action_comment_not_dropped():
    fm, _ = extract_frontmatter(CONTENT)
    # Reference parser (PyYAML) strips the comment correctly
    ref = yaml.safe_load(CONTENT.split('---')[1])
    assert ref['action'] == 'block'
    # Hand-rolled parser should match, but currently does not:
    assert fm['action'] == 'block'  # FAILS: fm['action'] == 'block  # critical safety rule, do not disable'
```
Integration-level assertion: build a `Rule` via `Rule.from_dict(fm, msg)` and assert `rule.action == 'block'`, then feed it through `RuleEngine.evaluate_rules()` with a matching `Bash` command and assert the response contains `hookSpecificOutput.permissionDecision == "deny"` rather than only `systemMessage` — demonstrating the guard-bypass end-to-end.

def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules


def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule
```
