### Title
Attacker-controlled artifact ZIP entries preserve name and can set executable file mode (0755) on extraction - ([File: internal/zip/zip.go])

### Summary
`downloadArtifact` in `pkg/cmd/run/download/http.go` streams an artifact ZIP to a temp file and hands it to `ghzip.ExtractZip` for extraction, without any sanitization of file names or permission bits. `ExtractZip`/`extractZipFile` in `internal/zip/zip.go` writes each entry using the exact name from the ZIP (after only a path-traversal check) and derives the on-disk file mode from the ZIP entry's own mode metadata (`getPerm`), setting 0755 (executable) whenever the attacker-supplied mode has any of the `0111` execute bits set.

### Finding Description
`downloadArtifact` ( [1](#0-0) ) downloads the artifact ZIP and calls `ghzip.ExtractZip(zipfile, destDir)` [2](#0-1) .

`ExtractZip` iterates `zr.File` and joins `zf.Name` (fully attacker-controlled, since it is the name of a file inside an artifact the repo/workflow owner controls) with `destDir`, only rejecting entries that trigger a path-traversal error; it performs no extension/name allowlisting [3](#0-2) .

`extractZipFile` then opens the destination file with a permission mode computed by `getPerm(zf.Mode())`, which returns the fixed executable mode `0755` whenever the ZIP entry's stored Unix mode has any of the `0111` bits set, and `0644` otherwise [4](#0-3) . The Unix file mode embedded in a ZIP's central directory external attributes is fully attacker-controlled data written by whoever created the artifact ZIP (e.g., via a malicious workflow that produces the artifact, or by controlling `zip.FileHeader.SetMode` when constructing the archive).

As a result, an attacker who controls the content of a workflow artifact can name an entry (e.g., `run-me.command`, `payload.sh`, `install.desktop`) and mark it executable in the ZIP metadata; `gh run download` will materialize that file on the victim's disk with the attacker-chosen name and mode `0755`, with no re-extension, quarantine attribute, or name-based warning.

### Impact Explanation
This does not by itself execute code — the victim must still open/run the extracted file — but it removes two of the OS-level speed bumps that normally prevent inadvertent execution: (1) the file already carries the execute bit on Unix/macOS, so a user simply double-clicking a `.command`/`.sh` file (or running it from a script that iterates artifact contents) executes it without a manual `chmod +x` step, and (2) the exact attacker-chosen filename/extension is preserved. Combined with typical developer workflows of downloading and inspecting/running CI artifacts, this constitutes an elevated risk of client-side code execution, though it stops short of a fully automatic RCE described in the "Critical" scenario in the question (no `.lnk`/`.bat` auto-run is implicated by this code path on Windows, since Windows ignores the Unix mode bits and the ZIP writer for artifacts is server-generated, not raw attacker bytes for the top-level `gh run download` archive itself).

### Likelihood Explanation
Feasible for any GitHub Actions workflow author (an "unprivileged" contributor in the sense of not needing gh maintainer/org rights) to produce an artifact ZIP whose entries have execute permission bits set and attacker-chosen names, then have another user run `gh run download` against that run. No path traversal, host confusion, or auth bypass is required; this is a straightforward property of `getPerm`/`ExtractZip`.

### Recommendation
Do not propagate untrusted executable bits from ZIP entries; always extract files as non-executable (e.g., always use `fileMode` `0644` regardless of `zf.Mode()`), and/or strip or warn on filenames with dangerous extensions before extraction.

### Proof of Concept
Add a Go test to `internal/zip/zip_test.go` that builds an in-memory `archive/zip.Writer`, adds an entry named `payload.sh` (or `payload.command`) whose header mode is set via `fh.SetMode(0755)` before writing, extracts it with `ExtractZip`, and asserts (a) the extracted file exists with the exact attacker-chosen name in `destDir`, and (b) `os.Stat` reports mode `0755` (i.e., `info.Mode()&0111 != 0`) rather than the intended non-executable `0644`, demonstrating that `downloadArtifact` → `ExtractZip` writes attacker-controlled executable files under an attacker-controlled name.

func ExtractZip(zr *zip.Reader, destDir safepaths.Absolute) error {
	for _, zf := range zr.File {
		fpath, err := destDir.Join(zf.Name)
		if err != nil {
			var pathTraversalError safepaths.PathTraversalError
			if errors.As(err, &pathTraversalError) {
				continue
			}
			return err
		}

		if err := extractZipFile(zf, fpath); err != nil {
			return fmt.Errorf("error extracting %q: %w", zf.Name, err)
		}
	}
	return nil
}
