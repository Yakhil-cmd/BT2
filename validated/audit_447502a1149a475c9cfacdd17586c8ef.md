### Title
Unbounded `reward.mintingamount` Governance Parameter Allows Unlimited KAIA Minting Per Block — (`kaiax/gov/param.go`)

---

### Summary

The `reward.mintingamount` governance parameter is registered with `noopFormatChecker`, which unconditionally returns `true` for any value. No upper-bound validation exists at the vote-acceptance layer (`PartialParamSet.Add`), the consistency-check layer (`checkConsistency`), or the reward-execution layer (`FinalizeState`). A governing node (or any GC member in `none` mode) can cast a valid governance vote setting `reward.mintingamount` to an arbitrarily large value. Once ratified, every subsequent block mints that amount of KAIA unconditionally via `state.AddBalance`, causing unbounded inflation of the native token.

---

### Finding Description

**Root cause — `kaiax/gov/param.go`**

`RewardMintingAmount` is the only reward-distribution parameter that carries `noopFormatChecker`:

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: noopFormatChecker,   // always returns true
    ...
    DefaultValue: big.NewInt(0),
},
``` [1](#0-0) 

`noopFormatChecker` is defined as:

```go
func noopFormatChecker(cv any) bool {
    return true
}
``` [2](#0-1) 

Compare this with `RewardRatio` and `RewardKip82Ratio`, which both enforce `sum == 100` in their `FormatChecker`: [3](#0-2) [4](#0-3) 

**Vote acceptance — `PartialParamSet.Add`**

When a vote is cast via `governance_vote`, `PartialParamSet.Add` calls `param.FormatChecker(cv)`. Because `noopFormatChecker` always returns `true`, any `*big.Int` value — including `2^256-1` — passes without error: [5](#0-4) 

**Consistency check — `checkConsistency`**

`VerifyVote` calls `checkConsistency`, which explicitly lists `gov.RewardMintingAmount` in the no-op branch that returns `nil` unconditionally: [6](#0-5) 

**Execution — `FinalizeState` → `state.AddBalance`**

At the end of every block, `FinalizeState` calls `GetDeferredReward`, which reads `config.MintingAmount` directly from the governance parameter set and distributes it via `state.AddBalance` with no cap: [7](#0-6) [8](#0-7) 

The minting amount flows directly into `spec.Minted` and then into recipient balances: [9](#0-8)

### Impact Explanation

Once a governance vote for `reward.mintingamount` with an extreme value (e.g., `2^200`) is ratified, every block thereafter mints that amount of KAIA and distributes it to the proposer, stakers, KIF, KEF, and KPF addresses via `state.AddBalance`. This constitutes an **unauthorized mint** of KAIA at the state level — the exact impact class listed in the allowed impact gate ("unauthorized mint … affecting KAIA … or system-managed funds"). The corrupted value is the balance of every reward recipient address, inflated by the unbounded minting amount each block.

---

### Likelihood Explanation

In `single` governance mode (Kaia Mainnet and Kairos), only the governing node can cast a ratifiable vote. In `none` mode, any GC member can. The governing node is a semi-trusted actor analogous to the `treasury` in the external report — it is expected to set `reward.mintingamount` to reasonable values, but the protocol provides no on-chain enforcement of an upper bound. A compromised or malicious governing node can exploit this without any additional privilege escalation.

---

### Recommendation

Add an upper-bound `FormatChecker` for `RewardMintingAmount`, analogous to the bounds enforced on ratio parameters:

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok {
            return false
        }
        // Enforce non-negative and a reasonable upper bound,
        // e.g., no more than 1 billion KAIA per block (1e27 kei).
        maxMinting, _ := new(big.Int).SetString("1000000000000000000000000000", 10)
        return v.Sign() >= 0 && v.Cmp(maxMinting) <= 0
    },
    ...
},
```

Additionally, add a corresponding case in `checkConsistency` to reject votes that exceed the bound at the header-verification layer.

### Proof of Concept

1. In `none` governance mode, any GC member calls `governance_vote("reward.mintingamount", "115792089237316195423570985008687907853269984665640564039457584007913129639935")` (i.e., `2^256 - 1` as a decimal string).
2. `PartialParamSet.Add` canonicalizes the string to a `*big.Int` via `bigIntCanonicalizer`, then calls `noopFormatChecker` → `true`. The vote is accepted.
3. `VerifyVote` → `checkConsistency` hits the `gov.RewardMintingAmount` case → `return nil`. The vote is written to `header.Vote` and stored.
4. At the next epoch boundary, the vote is ratified and written to `header.Governance`. `GetParamSet` now returns `MintingAmount = 2^256-1`.
5. Every subsequent block: `FinalizeState` → `getDeferredRewardFull` → `minted = new(big.Int).Set(config.MintingAmount)` → `state.AddBalance(proposerAddr, <2^256-1 proportional share>)`. All reward recipient balances overflow to astronomically large values, destroying the KAIA token economy.
