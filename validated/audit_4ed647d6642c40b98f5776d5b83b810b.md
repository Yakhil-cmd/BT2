### Title
Unrestricted Arbitrary RPC Dispatch via `ServiceChainCall` P2P Message in MainBridge — (`node/sc/main_bridge_handler.go`)

---

### Summary

The `MainBridge` handler in `node/sc/main_bridge_handler.go` accepts a `ServiceChainCall` P2P message from any connected peer and writes its raw payload directly into the internal RPC server pipe with no method whitelist, no caller authentication beyond the basic protocol handshake, and no filtering of the JSON-RPC method name or parameters. This is the Go-layer analog of the GenericBridgeFacet arbitrary-call vulnerability: just as `_bridgeData.callTo.call{value}(_bridgeData.callData)` allowed any caller to invoke any contract function, `mb.rpcConn.Write(data)` allows any bridge peer to invoke any registered RPC method on the parent-chain node.

---

### Finding Description

**Architecture of the internal RPC pipe**

In `NewMainBridge`, a `net.Pipe()` pair is created. One end (`p2`) is given to an `rpc.Server` that serves it as a codec; the other end (`p1`) is stored as `mb.rpcConn`. [1](#0-0) 

`SetComponents` then registers every public `kaia`/`klay` API onto that server: [2](#0-1) 

The `RemoteBackend` (used by the SubBridge) calls methods such as `kaia_getBalance`, `kaia_call`, `kaia_getTransactionReceipt`, `kaia_sendRawTransaction`-equivalent paths, etc., by writing JSON-RPC frames through its own pipe end and reading responses back over P2P. [3](#0-2) 

**The vulnerable handler**

When a `ServiceChainCall` message arrives, `handleCallMsg` decodes the raw bytes and writes them verbatim to `mb.rpcConn`: [4](#0-3) 

There is no inspection of the JSON-RPC `method` field, no allowlist of permitted method names, and no check that the peer is a legitimate SubBridge node beyond the initial protocol handshake (which only verifies `networkId` and `chainID` — both public values). [5](#0-4) 

**How a peer connects**

The MainBridge listens on a configurable port with `NoDiscovery = true` and `NoDial = true`, but any node that knows the address and can complete the `servicechain/2` handshake (public `networkId` + `chainID`) is accepted as a peer: [6](#0-5) 

Once registered, the peer can immediately send `ServiceChainCall` messages. [7](#0-6) 

---

### Impact Explanation

Every public `kaia`/`klay` RPC method registered on the internal server is reachable by any peer that can connect to the MainBridge port. Concretely:

- **Transaction injection**: `kaia_sendRawTransaction` (or its `klay_` alias) is a public API. A malicious peer can craft a JSON-RPC frame calling it with an attacker-signed transaction, injecting it into the parent-chain txpool without going through any normal RPC authentication layer.
- **Nonce/state read-out**: `kaia_getTransactionCount`, `kaia_getBalance`, `kaia_call` expose full parent-chain state to the attacker, enabling precise replay or front-running of bridge operator transactions.
- **Response hijacking**: The RPC response is broadcast back to *all* peers via `SendRPCResponseData`. A racing attacker peer can receive responses intended for the legitimate SubBridge, disrupting the bridge's nonce-sync and value-transfer logic. [8](#0-7) 

The `handleParentChainInfoResponseMsg` in the SubBridge unconditionally trusts the nonce value returned over this channel and sets the parent operator nonce from it: [9](#0-8) 

An attacker who can inject a crafted `ServiceChainResponse` (by first sending a `ServiceChainCall` that triggers a response) can feed a manipulated nonce back to the SubBridge, causing it to skip or double-spend bridge operator transactions.

---

### Likelihood Explanation

The MainBridge port is operator-configured and not publicly advertised via discovery, but:
- It is a plain TCP port; any node on the same network segment or with firewall access can connect.
- The only gate is the `servicechain/2` handshake, which requires only the public `networkId` and `chainID`.
- No TLS, no shared secret, no certificate pinning is applied.
- Service-chain deployments often co-locate the MainBridge node with the parent-chain RPC node, making the port reachable from the same host or LAN.

---

### Recommendation

1. **Whitelist allowed RPC methods**: Before writing to `mb.rpcConn`, parse the JSON-RPC `method` field and reject any call not in an explicit allowlist (e.g., `kaia_getBalance`, `kaia_getCode`, `kaia_call`, `kaia_getTransactionReceipt`, `kaia_blockNumber`, `kaia_getLogs`, `kaia_gasPrice`, `kaia_getTransactionCount`). State-mutating methods such as `kaia_sendRawTransaction` must not be reachable via this path.
2. **Authenticate bridge peers**: Require the connecting SubBridge to prove ownership of a pre-registered operator key (e.g., via a signed challenge) before accepting `ServiceChainCall` messages.
3. **Isolate the internal RPC server**: Register only the minimal read-only subset of APIs on `mb.rpcServer`, separate from the full public API set.
4. **Unicast responses**: Send RPC responses only to the peer that originated the request, not to all peers.

---

### Proof of Concept

```
Attacker node A connects to MainBridge port (e.g., :50505).
A completes servicechain/2 handshake with correct networkId and chainID (both public).
A is registered as a BridgePeer.

A sends a P2P message with code ServiceChainCall (0x06) whose payload is:
  {"jsonrpc":"2.0","id":1,"method":"kaia_sendRawTransaction","params":["<attacker_signed_raw_tx>"]}

handleCallMsg decodes the bytes and writes them to mb.rpcConn.
The internal rpc.Server processes the call and submits the transaction to the parent-chain txpool.
The response {"jsonrpc":"2.0","id":1,"result":"<txHash>"} is read from mb.rpcConn
and broadcast to ALL peers via SendRPCResponseData / ServiceChainResponse (0x07).

The legitimate SubBridge receives the response and, if its rpcClient is waiting on a matching id,
may process the attacker-injected result as its own.
``` [4](#0-3) [8](#0-7)

func (mb *MainBridge) handle(p BridgePeer) error {
	// Ignore maxPeers if this is a trusted peer
	if mb.peers.Len() >= mb.maxPeers && !p.GetP2PPeer().Info().Networks[p2p.ConnDefault].Trusted {
		return p2p.DiscTooManyPeers
	}
	p.GetP2PPeer().Log().Debug("Kaia peer connected", "name", p.GetP2PPeer().Name())

	// Execute the handshake
	var (
		head   = mb.blockchain.CurrentHeader()
		hash   = head.Hash()
		number = head.Number.Uint64()
		td     = mb.blockchain.GetTd(hash, number)
	)

	err := p.Handshake(mb.networkId, mb.getChainID(), td, hash)
	if err != nil {
		p.GetP2PPeer().Log().Debug("Kaia peer handshake failed", "err", err)
		return err
	}

	// Register the peer locally
	if err := mb.peers.Register(p); err != nil {
		// if starting node with unlock account, can't register peer until finish unlock
		p.GetP2PPeer().Log().Info("Kaia peer registration failed", "err", err)
		return err
	}
	defer mb.removePeer(p.GetID())

func (mbh *MainBridgeHandler) handleCallMsg(p BridgePeer, msg p2p.Msg) error {
	logger.Trace("mainbridge writes the rpc call message to rpc server", "msg.Size", msg.Size, "msg", msg)
	data := make([]byte, msg.Size)
	err := msg.Decode(&data)
	if err != nil {
		logger.Error("error in mainbridge message handler", "err", err)
		return err
	}

	// Write to RPC server pipe
	_, err = mbh.mainbridge.rpcConn.Write(data)
	if err != nil {
		logger.Error("failed to write to the rpc server pipe", "err", err)
		return err
	}
	return nil
}

func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil
