## Title
Clear-Text Logging of Textcoin Spending Mnemonics Enables Theft of Funds - (File: wallet.js)

### Summary
`ocore`'s textcoin feature stores a BIP39 mnemonic per textcoin output; this mnemonic is the sole credential needed to derive the private key that controls the textcoin address. In `claimBackOldTextcoins()`, the raw mnemonic is written to the process log in clear text on both success and failure paths, mirroring the reported pattern of logging a decoded private key (`fmt.Println(keyS)`) instead of sanitizing it before logging.

### Finding Description
`expandMnemonic()` derives a full HD private key and address directly from a textcoin mnemonic string: [1](#0-0) 

Anyone possessing this mnemonic can reconstruct `xPrivKey` and spend all funds sent to that address — the mnemonic is functionally equivalent to a raw private key. `claimBackOldTextcoins()` reads these mnemonics from the `sent_mnemonics` table for outputs not yet claimed and logs the plaintext mnemonic on every iteration, both when the reclaim fails and when it succeeds: [2](#0-1) 

The mnemonics are also handled elsewhere in wallet flows — generated in `generateNewMnemonicIfNoAddress` inside `sendMultiPayment`, stored via `assocMnemonics`, optionally emailed by `sendTextcoinEmail`, and persisted to `sent_mnemonics` — but `claimBackOldTextcoins` is the code path that unconditionally pushes the secret into application logs: [3](#0-2) 

Since this function runs periodically/automatically for any unclaimed textcoin past its expiry, every private-payment or bytes-payment made to an email/text address that lingers unclaimed for the configured number of days results in its spending mnemonic being written to disk-based logs in clear text.

### Impact Explanation
Any party with read access to the node's logs (log aggregation systems, shared hosting, backup files, misconfigured log shipping, support/ops staff, etc.) can extract the mnemonic and derive the private key via the exact same `expandMnemonic()` logic used by the wallet itself, then race the legitimate owner to claim the textcoin funds — resulting in concrete unauthorized spending / theft of the underlying bytes or asset, not simply reputational or informational risk.

### Likelihood Explanation
Moderate: it requires access to the node's logs, but any textcoin sent to an email/text recipient that is not claimed within the configured `days` window automatically triggers this log line via `claimBackOldTextcoins`, so the sensitive data is emitted without any special or malicious action by an attacker — only log access is needed, and log access is a far lower bar than compromising the wallet process itself.

### Recommendation
Never log the raw mnemonic. Log only a non-reversible identifier (e.g., the destination address `addrInfo.address`, unit hash, or a truncated/hashed reference) in `claimBackOldTextcoins()`, and audit all other `console.log` call sites in `wallet.js` that interpolate `mnemonic` to ensure the secret value itself is never written to any log sink.

### Proof of Concept
1. Send bytes or a private asset to an email address using `sendMultiPayment` so a textcoin mnemonic is generated and persisted to `sent_mnemonics` (see `generateNewMnemonicIfNoAddress`, wallet.js:2213-2237).
2. Let the textcoin remain unclaimed past the configured `days` threshold.
3. When the node's scheduled job calls `claimBackOldTextcoins(to_address, days)` (wallet.js:2818), it executes `receiveTextCoin(row.mnemonic, ...)` and on completion logs the full mnemonic in clear text:
   `console.log("claimed back mnemonic "+row.mnemonic+", unit "+unit+", asset "+asset);` (wallet.js:2832).
4. An attacker who can read the node's stdout/log files extracts this mnemonic and calls `expandMnemonic(mnemonic)` (wallet.js:2643) themselves to derive `xPrivKey`/`address`, then uses `receiveTextCoin` to claim the funds first — achieving unauthorized spending of the textcoin's balance.

```javascript
function expandMnemonic(mnemonic) {
	var addrInfo = {};
	mnemonic = mnemonic.toLowerCase().split('-').join(' ');
	if ((mnemonic.split(' ').length % 3 !== 0) || !Mnemonic.isValid(mnemonic)) {
		throw new Error("invalid mnemonic: "+mnemonic);
	}
	mnemonic = new Mnemonic(mnemonic);
	addrInfo.xPrivKey = mnemonic.toHDPrivateKey().derive("m/44'/0'/0'/0/0");
	addrInfo.pubkey = addrInfo.xPrivKey.publicKey.toBuffer().toString("base64");
	addrInfo.definition = ["sig", {"pubkey": addrInfo.pubkey}];
	addrInfo.address = objectHash.getChash160(addrInfo.definition);
	return addrInfo;
```

```javascript
function claimBackOldTextcoins(to_address, days){
	if (typeof days !== 'number')
		throw Error("bad days: " + days);
	db.query(
		"SELECT mnemonic FROM sent_mnemonics LEFT JOIN unit_authors USING(address) \n\
		WHERE mnemonic!='' AND unit_authors.address IS NULL AND creation_date<"+db.addTime("-"+days+" DAY"),
		function(rows){
			async.eachSeries(
				rows,
				function(row, cb){
					receiveTextCoin(row.mnemonic, to_address, function(err, unit, asset){
						if (err)
							console.log("failed claiming back old textcoin "+row.mnemonic+": "+err);
						else
							console.log("claimed back mnemonic "+row.mnemonic+", unit "+unit+", asset "+asset);
						cb();
					});
				}
			);
		}
	);
```
