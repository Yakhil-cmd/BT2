### Title
Accrual-time `scaled_to_original` overflow permanently freezes an oversized market - (File: common/src/rates/scaling.rs)

### Summary
A market whose scaled debt or supply value grows past the `i128` RAY domain cannot accrue successfully. `accrue_step` unconditionally converts `borrowed` and `supplied` shares back to value with `scaled_to_original`, and unrepresentable fixed-point results raise `MathOverflow` rather than clamping to the index ceilings [1](#0-0) [2](#0-1) [3](#0-2) . Because `update_indexes` is permissionless and every pool mutation syncs interest first, one caller can reach the overflow and afterward repay, withdraw, liquidation and later accrual attempts all revert on the same market [4](#0-3) [5](#0-4) [6](#0-5) .

### Finding Description
`Controller::update_indexes(caller, assets)` is permissionless and forwards the selected hub assets into the owner-gated pool accrual entrypoint [4](#0-3) [7](#0-6) . The pool loads each market cache and calls `interest::global_sync`; each chunk calls `accrue_step`, whose first operations multiply the stored scaled `borrowed` and `supplied` totals by their indexes [6](#0-5) [8](#0-7) [9](#0-8) .

The failure is that index caps bound the indexes themselves, not the product `scaled_shares * index`: `update_borrow_index` caps only `new_index` at `MAX_BORROW_INDEX_RAY`, while `calculate_supplier_rewards` separately computes `borrowed * new_borrow_index` [10](#0-9) [11](#0-10) . Thus a market can cross the total RAY-value domain while the index remains below its cap. The repository’s regression test demonstrates that exact ordering: `update_indexes` fails with `MATH_OVERFLOW`, `last.borrow_index < MAX_BORROW_INDEX_RAY`, and both withdrawal and repayment fail for the same reason [12](#0-11) .

### Impact Explanation
This is a permanent freezing-of-funds condition for the affected `(hub, asset)` market. Once the accrued total debt or total supply value exceeds the representable domain, every state-changing path that touches the market panics before it can burn shares, transfer cash, repay debt, seize collateral or socialize bad debt [13](#0-12) [14](#0-13) . The stored index cap does not rescue the market because the total-value multiplication overflows before capped index logic completes [10](#0-9) [11](#0-10) .

### Likelihood Explanation
Reaching the state requires an extremely large admitted market and sustained high utilization over a long accrual horizon; the in-repo scenario uses a one-billion-token 18-decimal market at 98% utilization and shows the cliff after a multi-year loop rather than instantly [15](#0-14) . No admin action is needed during the accrual itself: a user supplies and borrows through the normal controller verbs, then any caller can invoke `update_indexes` once ledger time makes the product overflow [16](#0-15) [4](#0-3) . The dependency on market caps, asset decimals, curve parameters and ledger time lowers practical likelihood, but once crossed the failure is deterministic.

### Recommendation
Bound the value products, not only the indexes. At minimum, make accrual detect `borrowed * new_borrow_index` or `supplied * supply_index` overflow before committing a state that can never accrue again. Prefer a protocol-defined terminal mode that clamps indexes and totals before value overflow, or rejects further exposure/accrual while still allowing repayments and withdrawals through a non-accruing safe path. Add a market-level invariant test asserting the index cap engages before any `scaled_to_original` value overflow and that `repay`, `withdraw`, `liquidate`, and `clean_bad_debt` remain callable at the configured cap boundary [17](#0-16) [11](#0-10) [18](#0-17) .

### Proof of Concept
The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` is a direct PoC. It creates an 18-decimal market, supplies `BILLION * 10^18`, borrows 98%, advances ledger time yearly until `try_update_indexes_for(["BIG18"])` returns `MATH_OVERFLOW`, then verifies the index cap was not reached and that `withdraw` and `repay` also fail with `MATH_OVERFLOW` [12](#0-11) . The reachable sequence is:

```text
supply(caller, account_id, spoke_id, [(BIG18, 1_000_000_000e18)])
borrow(owner, account_id, [(BIG18, 980_000_000e18)], to)
// wait until scaled debt valuation exceeds i128
update_indexes(any_caller, [BIG18])        // reverts: MathOverflow
withdraw(supplier, account_id, [(BIG18, 1)], None) // reverts first
repay(any_caller, account_id, [(BIG18, 1)])        // reverts first
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
