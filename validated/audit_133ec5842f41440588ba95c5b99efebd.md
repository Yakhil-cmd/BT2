### Title
Webhook signature check is fully bypassed for any organization configured without a `webhook_secret`, allowing unauthenticated forged GitHub events to mutate stack state - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` treats a blank `webhook_secret` as automatic success, and `WebhooksController#verify_signature` selects which organization's secret to check using an attacker-supplied, unverified field from the request body. For any organization configured without a webhook secret, this collapses the trust binding "the GitHub organization that authenticated the webhook" == "the organization/repository whose state the handlers subsequently write," because there is no authentication step at all for that organization — any unauthenticated caller can post directly to `/webhooks` and have it processed as a legitimate GitHub-originated event.

### Finding Description
`WebhooksController#verify_signature` resolves which GitHub App configuration (and thus which `webhook_secret`) to validate against purely from the JSON body itself: [1](#0-0) [2](#0-1) 

`repository_owner` is read straight from `params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')` — fields entirely controlled by the POST body, before any signature is validated.

`Shipit.github(organization: repository_owner)` returns a `GitHubApp` instance whose `verify_webhook_signature` method is: [3](#0-2) 

Note the guard clause `return true unless webhook_secret`. The documented and supported configuration schema explicitly allows `webhook_secret` to be nil/blank per organization (it is labeled "optional" and multiple sample configs, e.g. the double-org secrets fixture, ship with `webhook_secret: # nil` for one org while the other org has a real secret): [4](#0-3) 

Consequently: for any org whose `webhook_secret` is unset, `verify_webhook_signature` unconditionally returns `true` regardless of the `X-Hub-Signature` header contents. Combined with the fact that the org used for this check is picked from the unauthenticated payload itself, an attacker who knows (or guesses) the name of any Shipit-tracked organization/installation that has no webhook secret configured can POST an arbitrary, entirely self-crafted JSON body directly to `/webhooks` and have `WebhooksController#create` dispatch it to real handlers: [5](#0-4) 

Those handlers (`push`, `status`, `check_suite`, `membership`, `pull_request/*`) mutate real model state — creating commits, `CommitStatus` rows, teams/users, and enqueuing jobs like `RefreshCheckRunsJob` — based purely on attacker-chosen field values, with no cryptographic proof any of it came from GitHub.

This breaks the required equality binding: *the identity that the webhook signature authenticates* must equal *the repository/organization whose Shipit state is written by the handler*. When the secret is blank, the left side of that equality is vacuous (nothing is authenticated), yet the right side (arbitrary stack/commit/status mutation) still executes.

### Impact Explanation
This is High severity per the rubric ("unauthenticated read of stack state" is explicitly listed, and this goes further — unauthenticated *write*). Concretely, an attacker can inject fabricated `status` webhook events that create green `CommitStatus` records for a commit on an org configured without a secret. Shipit's merge-queue / continuous-delivery logic gates automatic merges and deploys on exactly this kind of status/check state: [6](#0-5) 

By forging green statuses/check-suite completions for a stack, an unauthenticated attacker can influence `Stack#allows_merges?` and continuous-delivery triggers, pushing the system toward an unauthorized merge/deploy decision — squarely within the "unauthorized deploy, rollback, or merge" impact bucket. It also allows spurious `Team`/`User` creation via forged `membership` events and enqueuing of jobs (`RefreshCheckRunsJob`) without any GitHub-verified origin.

### Likelihood Explanation
Likelihood is realistic wherever an operator follows the documented, supported configuration option of leaving `webhook_secret` blank for one or more organizations (as shown in the shipped example/fixture configs) — no misconfiguration beyond using a documented, optional feature is required, and the endpoint (`/webhooks`) is public and unauthenticated by design (it must accept traffic from GitHub).

### Recommendation
- Do not treat a blank `webhook_secret` as "verification passed." Either require a non-empty `webhook_secret` for every configured organization, or, if truly optional, fail closed (reject with 422) rather than fail open when no secret is configured.
- Do not derive the organization used for signature verification from unauthenticated payload fields; instead, verify the signature against every configured secret (or a fixed/default secret) before trusting any payload-derived routing field.

### Proof of Concept
1. Configure Shipit with two organizations where `OrgTwo` has `webhook_secret: nil` (a supported configuration, as in `test/dummy/config/secrets_double_github_app.yml`).
2. As an unauthenticated attacker, `POST /webhooks` with header `X-Github-Event: status` and a hand-crafted JSON body: `{"sha": "<target commit>", "state": "success", "context": "ci/forged", "repository": {"owner": {"login": "OrgTwo"}, "name": "<target-repo>"}, ...}`. No valid `X-Hub-Signature` header is required.
3. `verify_signature` resolves `repository_owner` = `"OrgTwo"` from the forged body, loads `Shipit.github(organization: "OrgTwo")`, whose `verify_webhook_signature` returns `true` unconditionally because `webhook_secret` is blank (`lib/shipit/github_app.rb:76-83`).
4. The request proceeds to `create`, and `Shipit::Webhooks.for_event('status')` handlers create a `CommitStatus` for the target commit exactly as if GitHub had sent it, with no GitHub authentication ever performed.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
