### Title
Stale Votes From Deregistered Bridge Operators Can Authorize Unauthorized Asset Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`BridgeOperator.deregisterOperator` removes an operator from the `operators` mapping and `operatorList`, but does **not** revoke or clear that operator's outstanding votes stored in the `votes` mapping. A deregistered operator's vote count persists and can combine with a subsequent vote from any remaining active operator to reach the threshold and execute a bridge value transfer — even though the deregistered operator's authorization has been revoked.

---

### Finding Description

In `BridgeOperator.sol`, the `deregisterOperator` function removes the operator from the active set:

```solidity
delete operators[_operator];
// removes from operatorList array
```

However, the `votes` mapping — which stores per-nonce vote counts keyed by `keccak256(msg.data)` — is never cleared for the deregistered operator. The `_voteCommon` function checks only `vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]`, with no check that all contributing voters are still registered operators.

The contract itself documents this as a known counterintuitive scenario:

> *"Note that outstanding votes by the deregistered operator are not revoked. … In this case the request was executed with A's vote after A is deregistered."*

The attack path is:

1. Operators A and B are registered; threshold = 2.
2. Compromised operator A calls `handleKLAYTransfer` (or `handleERC20Transfer`) with attacker-controlled `_to` and nonce N. Vote count for nonce N = 1; transfer not yet executed.
3. Owner discovers A is compromised and calls `deregisterOperator(A)`, believing the attack is neutralized.
4. Operator B (colluding, also compromised, or deceived) calls `handleKLAYTransfer` with the same parameters. `_voteCommon` sees `voteCounts[voteKey] = 2 >= threshold(2)` and returns `true`.
5. `handleKLAYTransfer` executes the KLAY transfer to the attacker's address. [1](#0-0) 

The `_voteCommon` function that tallies votes and triggers execution: [2](#0-1) 

The `handleKLAYTransfer` function that transfers KAIA from the bridge upon vote success: [3](#0-2) 

---

### Impact Explanation

A deregistered operator's vote permanently contributes to the vote tally for any nonce they voted on before deregistration. If a remaining active operator votes on the same nonce with the same calldata, the threshold is met and the bridge executes an unauthorized KAIA, ERC20, or ERC721 transfer to an attacker-controlled address. The owner's emergency response action (deregistering the compromised operator) provides a false sense of security while the attack can still complete.

---

### Likelihood Explanation

The scenario requires: (a) a compromised operator to have voted on a malicious nonce before being deregistered, and (b) a second operator to vote on the same nonce afterward. In a multi-operator bridge with threshold ≥ 2, this is a realistic attack window during the period between a compromised operator's vote and the owner's deregistration response. The code explicitly acknowledges this window exists and warns operators about it, confirming the scenario is reachable in production.

---

### Recommendation

In `deregisterOperator`, revoke the deregistered operator's outstanding votes by decrementing their vote counts for all open nonces, or alternatively clear the operator's `voted` entry and decrement the corresponding `voteCounts` entry. A targeted fix:

```solidity
function deregisterOperator(address _operator) external onlyOwner {
    require(operators[_operator]);
    // Revoke outstanding votes for all open value-transfer nonces
    // (iterate over known open nonces or store per-operator vote references)
    delete operators[_operator];
    // ... remove from operatorList ...
    emit OperatorDeregistered(_operator);
}
```

Alternatively, store a per-operator list of (voteType, nonce) pairs they have voted on, and clear them atomically during deregistration.

---

### Proof of Concept

Setup: Bridge deployed with operators [Owner, A, B], threshold for `ValueTransfer` = 2.

```
1. A.handleKLAYTransfer(txHash, from, attacker, 1e18, nonce=5, blockNum=100, "")
   → votes[ValueTransfer][5].voteCounts[voteKey] = 1  (threshold not met, no transfer)

2. Owner.deregisterOperator(A)
   → operators[A] = false, A removed from operatorList
   → votes[ValueTransfer][5].voteCounts[voteKey] still = 1  ← stale vote persists

3. B.handleKLAYTransfer(txHash, from, attacker, 1e18, nonce=5, blockNum=100, "")
   → _voteCommon: voteCounts[voteKey]++ → 2 >= threshold(2) → returns true
   → closedValueTransferVotes[5] = true
   → 1e18 KAIA transferred to attacker  ← unauthorized transfer executes
``` [4](#0-3) [5](#0-4)

    // _voteCommon handles common functionality for voting.
    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    //
    // Note that outstanding votes by the deregistered operator are not revoked.
    // This enables a subtle counterintuitive scenario.
    //
    // Suppose there are two operators A, B and C with threshold 2.
    // 1. Operator A votes on nonce N
    // 2. Owner deregisters A
    // 3. Operator B votes on nonce N, thereby executing the request N.
    // In this case the request was executed with A's vote after A is deregistered.
    //
    // The Owner shall recognize this issue and expect that operator deregistration
    // takes some time to be fully effective.
    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
