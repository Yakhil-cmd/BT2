### Title
Missing Zero-Address Check for `governance.governingnode` Vote Permanently Locks Chain Governance — (`kaiax/gov/param.go`, `kaiax/gov/headergov/impl/header.go`)

---

### Summary

The `GovernanceGoverningNode` parameter's `FormatChecker` accepts `common.Address{}` (the zero address) as a valid governing node. The `checkConsistency` function validates only that the **current** governing node is in the council — it never validates that the **new** voted value is non-zero. A governance vote to set `governance.governingnode` to `0x0000000000000000000000000000000000000000` passes all validation layers and, once ratified, permanently locks governance in `single` mode because no real validator can ever cast a valid vote again.

---

### Finding Description

**Layer 1 — FormatChecker accepts zero address**

The `GovernanceGoverningNode` parameter definition uses a `FormatChecker` that only asserts the canonical value is of type `common.Address`. It does not reject the zero address: [1](#0-0) 

The test suite explicitly confirms `"0x0000000000000000000000000000000000000000"` is treated as a **good vote** for `governance.governingnode`: [2](#0-1) 

**Layer 2 — `checkConsistency` validates the wrong address**

When a `GovernanceGoverningNode` vote is verified, `checkConsistency` checks whether the **current** `params.GoverningNode` is in the council — not whether the **new** vote value is non-zero: [3](#0-2) 

The new value (`vote.Value()`) is never inspected for zero-address in this branch. If the current governing node is in the council (the normal state), the check returns `nil` unconditionally, regardless of what the new value is.

**Layer 3 — `Vote()` API applies the same gap**

The `Vote()` API in `headergov` calls `checkConsistency` with the same logic and does not add any additional zero-address guard: [4](#0-3) 

**Layer 4 — Post-ratification effect**

Once the vote is ratified at an epoch boundary and stored via `HandleGov` → `AddGov`, `GetParamSet` returns `GoverningNode = common.Address{}`. In `single` mode, the `Vote()` API then rejects every real validator:

```go
if gMode == "single" && voter != gp.GoverningNode {
    return "", ErrVotePermissionDenied
}
```

And `VerifyVote` enforces the same post-Permissionless: [5](#0-4) 

Since no real validator has address `0x0000...0000`, governance is permanently frozen.

---

### Impact Explanation

- **Governance parameters permanently frozen**: `reward.mintingamount`, `reward.ratio`, `reward.kip82ratio`, `governance.unitprice`, and all other mutable parameters can never be changed again.
- **Reward distribution locked**: The minting amount and reward ratio are governance-controlled. A frozen governance means the chain cannot adapt reward distribution, directly affecting KAIA token economics and validator reward accounting.
- **No recovery path**: There is no on-chain mechanism to override a ratified `governance.governingnode` value once it is set to zero in `single` mode. The only recovery would require a hard fork.

This matches the allowed impact gate: **governance privilege escalation that changes protected chain state** (the governing node address is protected state that controls all future parameter changes).

---

### Likelihood Explanation

- **Trigger**: The current governing node (a semi-trusted actor) must cast a vote for `governance.governingnode` = `0x0000...0000`. This could happen by operator error (analogous to the "Alice accidentally sets factoryRegistry to zero" scenario in the external report), or by a compromised governing node key.
- **No existing guard**: All three validation layers (`FormatChecker`, `checkConsistency`, `Vote()`) pass without error for the zero address, as confirmed by the test suite.
- **Mainnet relevance**: Kaia Mainnet and Kairos testnet both operate in `single` governance mode, making this directly applicable.

---

### Recommendation

1. **Short term**: Add a zero-address check in the `FormatChecker` for `GovernanceGoverningNode`:
   ```go
   GovernanceGoverningNode: {
       FormatChecker: func(cv any) bool {
           addr, ok := cv.(common.Address)
           return ok && addr != (common.Address{})
       },
   ``` [1](#0-0) 

2. **Short term**: Add a zero-address check in `checkConsistency` for the `GovernanceGoverningNode` case, validating `vote.Value().(common.Address) != (common.Address{})`. [3](#0-2) 

3. **Long term**: Apply the same zero-address guard to `GovernanceGovParamContract` (which also uses `addressCanonicalizer` with a type-only `FormatChecker`) and audit all address-typed governance parameters for similar gaps. [6](#0-5) 

---

### Proof of Concept

**Pre-conditions**: Chain is in `single` governance mode. The current governing node is `0xGOVNODE` and is in the council.

1. `0xGOVNODE` calls `governance_vote("governance.governingnode", "0x0000000000000000000000000000000000000000")`.
2. `Vote()` passes: `voter == gp.GoverningNode` (current governing node is allowed to vote).
3. `NewVoteData()` passes: `"0x0000000000000000000000000000000000000000"` is a valid hex address string → canonicalized to `common.Address{}` → `FormatChecker` returns `true`.
4. `checkConsistency()` passes: `slices.Contains(council, params.GoverningNode)` is `true` (current governing node is in council).
5. Vote is inscribed in `header.Vote` when `0xGOVNODE` proposes a block.
6. `VerifyVote` passes on all nodes (same logic).
7. At the next epoch block, the vote is ratified and `header.Governance` encodes `{"governance.governingnode": "0x0000000000000000000000000000000000000000"}`.
8. `GetParamSet` now returns `GoverningNode = common.Address{}` for all subsequent blocks.
9. Any call to `governance_vote(...)` by any real validator returns `ErrVotePermissionDenied`.
10. Governance is permanently locked. `reward.mintingamount`, `reward.ratio`, and all other mutable parameters are frozen forever.

func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList
```

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
