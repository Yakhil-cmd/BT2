### Title
A borrower can wedge its own sub-3-decimal collateral account so every liquidation offer reverts, indefinitely blocking liquidation - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
The controller's whole-unit seizure rule for collateral legs whose asset has fewer than `MIN_BORROWABLE_ASSET_DECIMALS` decimals creates a dead zone: for a range of debt sizes no repayment quote can seize even one whole unit, so the seizure plan comes out empty and `liquidate` reverts. An unprivileged borrower can construct and hold an account inside this dead zone so that every liquidation attempt reverts, leaving the debt to accrue toward bad debt.

### Finding Description
For a solvent account whose only supply position is a sub-3-decimal asset, `calculate_seized_collateral` floors a partial seizure to whole units (contracts/controller/src/positions/liquidation/math.rs:401-417). If the floored seizure is zero, the leg is dropped (line 419 `if seizure_ray <= Ray::ZERO { continue; }`). With a single collateral leg, dropping it yields an empty `seized_collaterals`, and `build_liquidation_plan` releases all repayment, so `require_non_empty_payments(env, &result.repaid)` in `liquidate` reverts with `InvalidPayments` (contracts/controller/src/positions/liquidation/plan.rs:73-79; contracts/controller/src/positions/liquidation/mod.rs:64-66).

The quote-raising rule that would otherwise rescue this ("raised" quote seizing exactly one unit) only applies when `raised < D`. The documented residue `unit_at_bonus − R < D ≤ raised` is a state where no rule changes the quote, so the quote still backs less than one whole unit and every possible offer reverts. The protocol's own documentation acknowledges this: "every offer reverts until accrual or a price move ends that state" (skills/xoxno-lending/math.md, whole-unit quote section).

An unprivileged borrower reaches this state purely through normal entrypoints: `supply` of a single unit-valued sub-3-decimal listed asset, then `borrow` to a debt `D` inside the gap (feasible since `HF < 1` already requires `D` of the same order as `U`), and let interest accrue until `HF < 1`. From then on, `liquidate`, and likewise any strategy that seizes collateral on this account, deterministically reverts.

### Impact Explanation
A liquidatable account becomes un-liquidatable for an unbounded period controlled by the attacker (it persists until price drift or index accrual moves `D` out of the band — accrual can also push `D` deeper into the wedge since the gap condition `D ≤ raised` widens as `U` grows relative to bonus). Meanwhile the debt keeps accruing interest. If collateral value deteriorates or the account sits at `total_collateral > 5 WAD`, `clean_bad_debt` cannot socialize it either, so the protocol accrues real bad debt → temporary freezing of funds and a path to protocol insolvency.

### Likelihood Explanation
Requires a listed market with `asset_decimals < 3` (the codebase explicitly supports such listings — whole-unit seizure and "a listing below 3 decimals has no liquidation fee" are first-class behaviors). Given such a listing, the attacker needs only `supply` + `borrow` on their own account and a modest adverse price move; all other positions being absent makes the wedge automatic since the dropped leg empties the seizure plan. Cost is the collateral posted.

### Recommendation
In `calculate_seized_collateral`, never let the whole-unit floor silently zero out an account's last leg: when `seized_collaterals` would become empty solely due to whole-unit flooring, seize one whole unit (ceil instead of floor) capped at `actual_ray` and recompute the backed repayment, or reject account states at `borrow`/`supply` time that place `D` inside the `unit_at_bonus − R < D ≤ raised` dead zone.

### Proof of Concept
1. Assume listed market `X` with `decimals = 2`, price such that one unit `U = 100 WAD`, liquidation threshold 80%.
2. Attacker calls `supply(caller, 0, spoke, [(hub X, 1 unit)])` then `borrow(...)` for debt `D = 85 WAD` worth of USDC.
3. Price moves/`update_indexes` accrual pushes `HF < 1` (e.g., `U` drops to ~90 WAD → `HF ≈ 80×90/8500 < 1`).
4. Liquidator calls `liquidate(liquidator, account_id, [(hub USDC, k)], SeizeMode::Transfer)` for any `k`:
   - Curve quote `ideal` backs less than one unit of `X` → `seizure_ray` floors to zero → leg dropped → empty `seized` → `repaid` emptied → revert `InvalidPayments`.
   - Offering the whole debt triggers the full-close rule only if `unit_at_bonus ≥ D + R`; in the wedge `unit_at_bonus − R < D`, so rule 1 does not apply and rule 2's `raised < D` fails since `D ≤ raised`.
5. Every liquidation reverts; `is_liquidatable(account_id)` stays true; debt accrues unchecked. Repeat at will for the cost of one unit of `X`.
