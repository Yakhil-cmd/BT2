## Finding

### Title
Missing verification that the local signer's presence in a peer-supplied shared-address definition is actually required, enabling unilateral fund theft via a fake "shared" address - (File: wallet_defined_by_addresses.js)

### Summary
The `shopper/framework` advisory describes two authorization defects: a mount lacking any authorization check, and a write action gated on an insufficient permission (read-only `view_users` instead of `manage_users`). The reachable ocore analog is `handleNewSharedAddress()` in `wallet_defined_by_addresses.js`, invoked directly from an unauthenticated-content network message sent by any paired device (`case "new_shared_address"` in `wallet.js`). This handler performs a *structural* check that "my" address appears somewhere in the attacker-supplied definition tree, but never verifies that my participation is actually **required** to spend from the address (i.e., it doesn't reject definitions where an `or` branch lets the peer spend unilaterally). This is the same class of bug: a sensitive state-changing action ("register this address as a jointly-controlled shared wallet") is authorized based on a check that is too weak for the trust decision being made.

### Finding Description
`handleNewSharedAddress()` is reached from `wallet.js`'s `handleMessageFromHub` for the `"new_shared_address"` message type with no additional gating: [1](#0-0) 

Inside `handleNewSharedAddress`, the checks performed are:
1. Structural validity of `body.definition` and that `body.address` matches its c-hash.
2. That every `signers` entry maps to a valid address.
3. That the `signers` map is *consistent* with the address leaves actually present in the definition (`extractAddressPathsFromDefinition`).
4. That "I" (the local device) appear as a member address somewhere in the definition, via `determineIfIncludesMeAndRewriteDeviceAddress`.
5. Generic structural `Definition.validateDefinition()` (complexity/op limits, "each branch must have a signature"). [2](#0-1) 

None of these steps verify that the victim's inclusion in the definition tree is *necessary* to authorize spending. `determineIfIncludesMeAndRewriteDeviceAddress` only checks that at least one leaf address in the definition belongs to `my_addresses`/`shared_addresses`; it accepts the definition even if that leaf sits behind an `or` with an attacker-controlled branch: [3](#0-2) 

Likewise, `validateAddressDefinition()` only calls the generic definition validator, which enforces global complexity/signature-presence rules but has no concept of "is this specific address's participation load-bearing": [4](#0-3) 

Contrast this with the earlier template-creation flow `validateAddressDefinitionTemplate`, which does check that the message sender (`from_address`) is one of the referenced devices — but even that check is only about "referenced somewhere," not "required." The direct `new_shared_address` path is weaker still: it never even checks that `from_address` (the actual sender of the message) is one of the devices referenced in the definition at all. [5](#0-4) 

Once `addNewSharedAddress()` runs, the address is persisted into `shared_addresses` / `shared_address_signing_paths` and surfaced to the wallet UI/API as a legitimate multi-party address, and it is also propagated to other correspondents via `forwardNewSharedAddressToCosignersOfMyMemberAddresses`: [6](#0-5) 

### Impact Explanation
A malicious paired correspondent can craft a definition such as `["or", [["address", victim_address], ["address", attacker_address]]]`, compute its c-hash, and send it as a `"new_shared_address"` message with `signers` that satisfy the structural checks above. Because the victim's address is present as a leaf, `determineIfIncludesMeAndRewriteDeviceAddress` succeeds and the address is silently registered as a "shared" wallet the victim believes requires joint cosignature. In reality the attacker can spend from this address alone at any time, since the `or` branch makes the victim's signature non-mandatory. If the victim (or their wallet's automatic co-signer sharing logic) sends funds into that address, believing it is protected by multisig, the attacker can unilaterally drain it — concrete unauthorized spending / fund loss, matching the "unauthorized spending" bar for validity.

### Likelihood Explanation
Any correspondent that is already a paired device (a normal, low-trust relationship — e.g., anyone who has exchanged pairing codes, which is the standard way wallets interact for shared addresses and contracts) can trigger this path with a single crafted message; no special network position, hub compromise, or additional privilege is required. The complexity/op-limit checks in `Definition.validateDefinition` do not enforce "necessity" of a given leaf's participation, so the bypass definition passes validation trivially.

### Recommendation
In `handleNewSharedAddress`/`determineIfIncludesMeAndRewriteDeviceAddress`, in addition to checking that my address is *present* in the definition, verify that my signature (or one of my member addresses) is actually *required* along every accepting path (e.g., reject definitions where my address sits under an `or`/`r of set` branch that can be satisfied without it, or explicitly warn/require explicit user confirmation showing the full logical structure before treating the address as a trusted joint wallet). Additionally, verify that `from_address` (the actual message sender) is one of the referenced signer device addresses, consistent with the check already performed in `validateAddressDefinitionTemplate`.

### Proof of Concept
1. Attacker (device B) pairs with victim (device A) — an ordinary correspondent relationship.
2. Attacker builds `arrDefinition = ["or", [["address", VICTIM_ADDR], ["address", ATTACKER_ADDR]]]`, computes `shared_address = getChash160(arrDefinition)`.
3. Attacker sends a `"new_shared_address"` message: `{address: shared_address, definition: arrDefinition, signers: {"r.0": {address: VICTIM_ADDR, device_address: VICTIM_DEVICE}, "r.1": {address: ATTACKER_ADDR, device_address: ATTACKER_DEVICE}}}`.
4. `handleNewSharedAddress` on the victim's node passes all checks (address matches hash, signers consistent with leaves, victim's address present) and calls `addNewSharedAddress`, registering `shared_address` in the victim's `shared_addresses` table as a "shared" wallet.
5. Victim's wallet (or automated flows using `readAllControlAddresses`/`forwardPrivateChainsToOtherMembersOfAddresses`) treats this as a legitimate joint address and funds may be sent to it.
6. Attacker alone signs and posts a payment from `shared_address` (satisfying the `or` branch with only `ATTACKER_ADDR`'s signature), draining the funds without the victim's cosignature ever being needed.

// Checks if any of my payment addresses is mentioned.
// It is possible that my device address is not mentioned in the definition if I'm a member of multisig address, one of my cosigners is mentioned instead
function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

function validateAddressDefinitionTemplate(arrDefinitionTemplate, from_address, handleResult){
	try{
		var assocMemberDeviceAddressesBySigningPaths = getMemberDeviceAddressesBySigningPaths(arrDefinitionTemplate);
	}
	catch (e) {
		return handleResult("failed to get member device addresses of new shared address: " + e.toString());
	}
	var arrDeviceAddresses = _.uniq(_.values(assocMemberDeviceAddressesBySigningPaths));
	if (arrDeviceAddresses.length < 2)
		return handleResult("less than 2 member devices");
	if (arrDeviceAddresses.indexOf(device.getMyDeviceAddress()) === - 1)
		return handleResult("my device address not mentioned in the definition");
	if (arrDeviceAddresses.indexOf(from_address) === - 1)
		return handleResult("sender device address not mentioned in the definition");
	
	var params = {};
	// to fill the template for validation, assign my device address (without leading 0) to all member devices 
	// (we need just any valid address with a definition)
	var fake_address = device.getMyDeviceAddress().substr(1);
	arrDeviceAddresses.forEach(function(device_address){
		params['address@'+device_address] = fake_address;
	});
	try{
		var arrFakeDefinition = Definition.replaceInTemplate(arrDefinitionTemplate, params);
	}
	catch(e){
		return handleResult(e.toString());
	}
	var objFakeUnit = {authors: [{address: fake_address, definition: ["sig", {pubkey: device.getMyDevicePubKey()}]}]};
	var objFakeValidationState = {last_ball_mci: MAX_INT32};
	Definition.validateDefinition(db, arrFakeDefinition, objFakeUnit, objFakeValidationState, null, false, function(err){
		if (err)
			return handleResult(err);
		handleResult(null, assocMemberDeviceAddressesBySigningPaths);
	});
}
