## Finding: Unauthenticated forged GitHub webhooks can grant Shipit access when `webhook_secret` is unset

### Title
Webhook signature verification is skipped entirely when no `webhook_secret` is configured, allowing an unauthenticated attacker to forge a `membership` event and self-escalate into a `Shipit.github_teams` authorized user — ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` treats an unset `webhook_secret` as "always verified," and the webhook secret used for that check is selected purely from an attacker-controlled field of the same unauthenticated JSON body. Because `webhook_secret` is documented as optional, any Shipit deployment that hasn't set it accepts arbitrary, unsigned webhook payloads at `/webhooks`. `MembershipHandler` then blindly trusts a forged `membership` event and writes it straight into the local `Team`/`Membership` tables that gate application authorization via `User#authorized?`.

### Finding Description
`WebhooksController#verify_signature` picks the GitHub App/secret to validate against using a value taken straight from the unauthenticated request body (`repository_owner`), then calls `verify_webhook_signature`: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever no `webhook_secret` is configured for that organization: [3](#0-2) 

The setup docs explicitly mark `webhook_secret` as **optional**: [4](#0-3) [5](#0-4) 

and the shipped example/dummy secrets ship with it unset: [6](#0-5) [7](#0-6) 

With signature verification bypassed, `WebhooksController#create` dispatches the fully attacker-controlled JSON to any registered handler for the claimed `X-Github-Event` header: [8](#0-7) 

`MembershipHandler` accepts a `membership` event and, without any cross-check against real GitHub state, creates the named `Team` if unknown and adds/removes the named `member` from it: [9](#0-8) 

`User.find_or_create_by_login!` looks the login up via the GitHub API (so it must be a real GitHub account, but not necessarily one under the attacker's control unless the attacker names their own account) and creates a local `User` row: [10](#0-9) 

Finally, `User#authorized?` — the gate used by `Authentication#force_github_authentication` to allow access to the whole engine — is computed purely from the local `teams`/`Membership` association, which the forged webhook just populated: [11](#0-10) [12](#0-11) 

**Binding broken:** the "organization" whose webhook is treated as authenticated (none — verification is skipped) is not equal to the organization whose `Team`/`Membership` records are actually written and later consumed by `User#authorized?`, i.e. `authenticated_org != org_whose_membership_state_is_mutated` (in this case, authentication is absent entirely, yet the write is trusted as if it came from the real GitHub organization admin).

### Impact Explanation
An attacker with no credentials, no repository access, and no Shipit session can:
1. POST a forged `membership` `action: "added"` event naming their own real GitHub login and a `team`/`organization` matching one of `Shipit.github_teams`.
2. Complete the normal GitHub OAuth login flow using that same real (but otherwise unprivileged) GitHub account.
3. Pass `User#authorized?` because the local `Membership` row was fabricated by the forged webhook, gaining full authenticated access to the Shipit instance (viewing stacks, triggering deploys/tasks, etc., subject to further per-action checks).

This matches the "High — escalation into `Shipit.github_teams` authorization" impact class defined by the rules; combined with `deploy:stack`-level actions reachable once authenticated, it can lead to unauthorized deploys.

### Likelihood Explanation
This is only exploitable on deployments that leave `webhook_secret` unset — which the project's own documentation and shipped example configs present as the normal/default state ("optional"). Any such deployment is fully exposed to any internet client capable of POSTing JSON with a spoofed `X-Github-Event: membership` header; no GitHub org membership, API token, or Shipit credential is required.

### Recommendation
- Make `webhook_secret` mandatory (fail closed) instead of defaulting to "always verified" when absent; refuse to boot or refuse all webhook traffic for an organization with no configured secret.
- Do not let `verify_webhook_signature` return `true` when `webhook_secret` is blank — return `false` instead.
- For `MembershipHandler`, do not treat a webhook `membership` payload as ground truth for authorization-affecting state; corroborate with a live GitHub API call (`org_teams`/`team_membership`) before mutating `Team`/`Membership`, or at minimum re-validate periodically via `Team#refresh_members!`.

### Proof of Concept
1. Deploy Shipit with `config/secrets.yml` leaving `github.webhook_secret` unset (as in the shipped example/dummy configs).
2. As an unauthenticated attacker, `POST /webhooks` with header `X-Github-Event: membership` and body:
```json
{
  "action": "added",
  "team": { "id": 999, "name": "Developers", "slug": "developers", "url": "https://example.com" },
  "organization": { "login": "shopify" },
  "member": { "login": "<attacker's real github login>" },
  "repository": { "owner": { "login": "shopify" } }
}
```
3. `verify_signature` calls `Shipit.github(organization: "shopify").verify_webhook_signature(...)`, which returns `true` because no `webhook_secret` is configured — see [3](#0-2) .
4. `MembershipHandler#process` creates/finds the `Team` (`shopify/developers`, matching `Shipit.github_teams`) and adds the attacker's `User` as a member — [9](#0-8) .
5. Attacker logs into Shipit via the normal `/github/auth/github` OAuth flow using their own real GitHub account. `User#authorized?` now returns `true` due to the forged `Membership` row — [11](#0-10) .

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
