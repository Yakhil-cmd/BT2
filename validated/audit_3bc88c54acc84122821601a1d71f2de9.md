## Title
`configureWorktree()` mutates the already-published worktree in place on restart, breaking the atomic symlink contract when the hash is unchanged - (File: `main.go`)

### Summary
`git-sync`'s entire design rests on the "worktree + symlink" contract: a new revision is fully checked out into a *fresh, unpublished* worktree, and only after it has been fully constructed is the symlink atomically swapped to point at it, so a consumer reading through `--link` never sees a partially constructed tree [1](#0-0) [2](#0-1) . This mirrors the semantics that `insertValidatorSet()` was supposed to enforce in the original report: a mutation must be fully valid before it is exposed, and any error partway through must not leave the visible/consumed state changed. In `SyncRepo()`, however, on process restart (`git.syncCount == 0`) when the local hash already matches the remote hash, `configureWorktree()` is invoked directly on `currentWorktree` — the worktree the live symlink is *already* pointing at — rather than on a fresh, unpublished worktree, violating that contract if the call fails partway through.

### Finding Description
In `SyncRepo()`, when the loop restarts and finds `currentHash == remoteHash`, `changed` stays `false`, so `newWorktree` is simply assigned `currentWorktree` (the currently-published worktree), and `createWorktree()` is skipped: [3](#0-2) 

Regardless of whether a new worktree was created, `configureWorktree(ctx, newWorktree)` is unconditionally invoked whenever `changed || git.syncCount == 0`: [4](#0-3) 

`configureWorktree()` performs several destructive, multi-step, non-atomic operations directly against `worktree.Path()`: rewriting the `.git` file, enabling/disabling sparse-checkout (which can involve creating/removing files under `.git/worktrees/<hash>/info`), running `git reset --hard <hash>`, and running `git submodule update --init [--recursive]`: [5](#0-4) 

Because `newWorktree == currentWorktree` in this branch, all of these operations are executed **in place on the directory the `--link` symlink is currently pointing at** — the exact "non-atomic checkout" scenario the symlink mechanism was designed to hide from consumers, per the documented rationale: "git checkouts are not 'atomic' operations... If you look at the repository while a checkout is happening, you might see data that is neither exactly the old revision nor the new" [6](#0-5) . If any of these steps fails (e.g., a submodule fetch fails due to a transient network error, a malicious/renamed submodule URL, disk pressure while writing the sparse-checkout file, or the process being killed mid-`reset --hard`/`submodule update`), `configureWorktree()` returns an error and `SyncRepo()` bails out without any rollback or removal of the now-partially-mutated worktree: [7](#0-6) 

The symlink itself is never touched in this failure path, so consumers keep reading through the same `--link` path — but the target directory's contents have already been partially rewritten (e.g., `.git` file replaced, sparse-checkout config toggled, `reset --hard` applied) before the failing step. This is analogous to `insertValidatorSet()` inserting an entry into the table and then failing without removing it: an operation that should be all-or-nothing under validation instead leaves a partially-applied, unvalidated mutation visible to the very interface the code exists to protect.

Recovery on the next loop iteration is not guaranteed to catch this: `sanityCheckWorktree()` only checks that the directory is non-empty, that `git rev-parse HEAD` matches the worktree's hash, and that `git fsck --connectivity-only` passes [8](#0-7) . None of these checks detect a worktree whose `reset --hard` succeeded but whose submodules were left partially initialized, or whose sparse-checkout state is inconsistent with the files actually on disk, since `HEAD` and object connectivity are unaffected by such partial content-level failures.

### Impact Explanation
This can result in already-published content being silently corrupted or left in a partially-updated state without the atomicity guarantee git-sync advertises, i.e., "publishing wrong or partial content" to the consuming application — one of the explicitly accepted impact categories. Because the failure can be triggered by content under the control of whoever controls the remote repository/submodules (a malicious or unreachable submodule URL, or a race causing the process to be killed during this window), this is reachable from attacker-pushed repository content, not merely a local/operator misconfiguration.

### Likelihood Explanation
This requires no special flags beyond normal use of `--submodules` and/or `--sparse-checkout-file`, and a restart of the git-sync process (`syncCount == 0`) while the remote ref is unchanged — a routine occurrence (pod restarts, container restarts in Kubernetes). Any transient failure during the in-place `configureWorktree()` call (network blip during submodule fetch, disk error, OOM-kill) is enough to trigger the corruption; a malicious upstream can also intentionally engineer such a failure (e.g. a submodule pointing at a URL that times out or returns partial data).

### Recommendation
Never run `configureWorktree()` against the currently-published worktree. On restart with `changed == false`, either treat the situation identically to `changed == true` by constructing configuration into a fresh worktree (via `createWorktree`) and only swapping the symlink after `configureWorktree()` fully succeeds, or perform the re-configuration into a scratch/staging copy and validate it (akin to the recommended `Validate()`-before-insert pattern) before it is allowed to replace or be treated as the authoritative published worktree.

### Proof of Concept
1. Start `git-sync` with `--repo` pointing to a repository containing a submodule, and `--submodules=recursive`; let it complete an initial sync so `--link` points at a fully checked-out worktree.
2. Kill and restart the `git-sync` process (simulating a pod restart) at the moment the submodule remote becomes unreachable (or configure the submodule URL to fail intermittently).
3. On restart, `SyncRepo()` finds `currentHash == remoteHash`, sets `newWorktree := currentWorktree`, and calls `configureWorktree(ctx, newWorktree)` directly on the live, symlinked worktree [9](#0-8) .
4. `git reset --hard` succeeds, but `git submodule update --init --recursive` fails because the submodule remote is unreachable [10](#0-9) .
5. `SyncRepo()` returns an error without touching the symlink or rolling back the worktree; the directory the symlink already points to is left with a `reset --hard`-mutated state and missing/partial submodule content, while any application consuming through `--link` observes this inconsistent state as "the current sync."

// sanityCheckWorktree tries to make sure that the dir is a valid git
// repository.  Note that this does not guarantee that the worktree has all the
// files checked out - git could have died halfway through and the repo will
// still pass this check.
func (git *repoSync) sanityCheckWorktree(ctx context.Context, worktree worktree) bool {
	git.log.V(3).Info("sanity-checking worktree", "repo", git.root, "worktree", worktree)

	// If it is empty, we are done.
	if empty, err := dirIsEmpty(worktree.Path()); err != nil {
		git.log.Error(err, "can't list worktree directory", "path", worktree.Path())
		return false
	} else if empty {
		git.log.V(0).Info("worktree is empty", "path", worktree.Path())
		return false
	}

	// Make sure it is synced to the right commmit.
	stdout, _, err := git.Run(ctx, worktree.Path(), "rev-parse", "HEAD")
	if err != nil {
		git.log.Error(err, "can't get worktree HEAD", "path", worktree.Path())
		return false
	}
	if stdout != worktree.Hash() {
		git.log.V(0).Info("worktree HEAD does not match worktree", "path", worktree.Path(), "head", stdout)
		return false
	}

	// Consistency-check the worktree.  Don't use --verbose because it can be
	// REALLY verbose.
	if _, _, err := git.Run(ctx, worktree.Path(), "fsck", "--no-progress", "--connectivity-only"); err != nil {
		git.log.Error(err, "worktree fsck failed", "path", worktree.Path())
		return false
	}

	return true
}

// configureWorktree applies some configuration (e.g. sparse checkout) to
// the specified worktree and checks out the specified hash and submodules.
func (git *repoSync) configureWorktree(ctx context.Context, worktree worktree) error {
	hash := worktree.Hash()

	// The .git file in the worktree directory holds a reference to
	// /git/.git/worktrees/<worktree-dir-name>. Replace it with a reference
	// using relative paths, so that other containers can use a different volume
	// mount name.
	var rootDotGit string
	if rel, err := filepath.Rel(worktree.Path().String(), git.root.String()); err != nil {
		return err
	} else {
		rootDotGit = filepath.Join(rel, ".git")
	}
	gitDirRef := []byte("gitdir: " + filepath.Join(rootDotGit, "worktrees", hash) + "\n")
	if err := os.WriteFile(worktree.Path().Join(".git").String(), gitDirRef, 0644); err != nil {
		return err
	}

	// If sparse checkout is requested, configure git for it, otherwise
	// unconfigure it.
	gitInfoPath := filepath.Join(git.root.String(), ".git/worktrees", hash, "info")
	gitSparseConfigPath := filepath.Join(gitInfoPath, "sparse-checkout")
	if git.sparseFile == "" {
		os.RemoveAll(gitSparseConfigPath)
	} else {
		// This is required due to the undocumented behavior outlined here:
		// https://public-inbox.org/git/CAPig+cSP0UiEBXSCi7Ua099eOdpMk8R=JtAjPuUavRF4z0R0Vg@mail.gmail.com/t/
		git.log.V(1).Info("configuring worktree sparse checkout")
		checkoutFile := git.sparseFile

		source, err := os.Open(checkoutFile)
		if err != nil {
			return err
		}
		defer source.Close()

		if _, err := os.Stat(gitInfoPath); os.IsNotExist(err) {
			err := os.Mkdir(gitInfoPath, defaultDirMode)
			if err != nil {
				return err
			}
		}

		destination, err := os.Create(gitSparseConfigPath)
		if err != nil {
			return err
		}
		defer destination.Close()

		_, err = io.Copy(destination, source)
		if err != nil {
			return err
		}

		args := []string{"sparse-checkout", "init"}
		if _, _, err = git.Run(ctx, worktree.Path(), args...); err != nil {
			return err
		}
	}

	// Reset the worktree's working copy to the specific ref.
	git.log.V(1).Info("setting worktree HEAD", "hash", hash)
	if _, _, err := git.Run(ctx, worktree.Path(), "reset", "--hard", hash, "--"); err != nil {
		return err
	}

	// Update submodules
	// NOTE: this works for repo with or without submodules.
	if git.submodules != submodulesOff {
		git.log.V(1).Info("updating submodules")
		submodulesArgs := []string{"submodule", "update", "--init"}
		if git.submodules == submodulesRecursive {
			submodulesArgs = append(submodulesArgs, "--recursive")
		}
		if git.depth != 0 {
			submodulesArgs = append(submodulesArgs, "--depth", strconv.Itoa(git.depth))
		}
		if _, _, err := git.Run(ctx, worktree.Path(), submodulesArgs...); err != nil {
			return err
		}
	}

	return nil
}
