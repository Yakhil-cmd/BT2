### Title
Signature verified against `repository.owner.login`'s org while handlers act on the repo named by `repository.full_name`, enabling cross-tenant PR state forgery when the owner org has no `webhook_secret` - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb)

### Summary
`WebhooksController#verify_signature` selects the signing organization using only `repository.owner.login` [2](#0-1) [3](#0-2) , while every `pull_request` handler (`EditedHandler`, `ClosedHandler`, `OpenedHandler`, `ReopenedHandler`, `LabeledHandler`, `UnlabeledHandler`, `AssignedHandler`) resolves the target repository independently from `params.repository.full_name` via `Repository.from_github_repo_name` [4](#0-3) [5](#0-4) . If the org named in `owner.login` has `webhook_secret` unset in Shipit's config, `verify_webhook_signature` returns `true` regardless of the actual signature [6](#0-5) , letting an attacker submit an unsigned/arbitrary payload naming that no-secret org as `owner.login` and a victim org/repo in `full_name`.

### Finding Description
The broken binding: the code implicitly assumes `repository.owner.login == repository.full_name.split('/').first`, but nothing enforces this equality — they are two independent, attacker-supplied JSON fields with no cross-validation, only the `full_name` field is `require`d by the `ExplicitParameters` schemas [7](#0-6) , and `owner.login` is read purely for signature-org lookup, never checked against `full_name` [3](#0-2) .

Path: `POST /webhooks` → `verify_signature` computes `repository_owner` from `params.dig('repository','owner','login')`, fetches `Shipit.github(organization: repository_owner)`, and calls `verify_webhook_signature` [2](#0-1) . If that org has no `webhook_secret` configured, verification unconditionally returns `true` [6](#0-5) , so the request proceeds regardless of a valid `X-Hub-Signature`. `create` then dispatches to `Webhooks.for_event('pull_request')`, running all PR handlers against the raw `params` [8](#0-7) [9](#0-8) . `EditedHandler#repository` (and siblings) look up the actual mutated repository solely via `params.repository.full_name` [4](#0-3) , which can name a completely different, victim-owned org/repo whose actual `webhook_secret` was never checked. `EditedHandler#process` then calls `pull_request.update(github_pull_request: params.pull_request)` on a `PullRequest` scoped by `repository.id` derived from that victim repo [10](#0-9) , i.e., a payload "signed" (or unsigned) under one org's identity mutates another org's review-stack record.

Existing guards don't catch this: `drop_unhandled_event` only checks event type presence [11](#0-10) ; `ExplicitParameters` schemas only validate types/presence, not cross-field consistency; `GithubOrganizationUnknown` is only raised when the named org isn't configured at all, not when it has no secret.

### Impact Explanation
An attacker who controls (or can trigger webhooks for) any single GitHub organization/repo that is registered in Shipit's `github_apps` config **without** a `webhook_secret` set can forge `pull_request` events naming an arbitrary victim `repository.full_name`, causing that victim's `PullRequest` record (`github_pull_request` field, and via other handlers, archive/unarchive of review stacks, provisioning) to be mutated with attacker-chosen data. This is a payload for one repository mutating another's review-stack/PR state — matching the "Critical: a payload for one repository mutating another's stack" category. The blast radius spans every repository/org configured under Shipit as long as at least one configured org lacks a `webhook_secret`.

### Likelihood Explanation
This requires a specific server-side misconfiguration: at least one org registered in Shipit's `Shipit.github_apps`/`github(organization:)` config must have a blank/absent `webhook_secret`. Given that, the attacker needs no GitHub secret at all — they can send a raw HTTP POST with an arbitrary/unsigned body, since `verify_webhook_signature` short-circuits to `true` [6](#0-5) . If every configured org has a secret set, this specific path is not exploitable (the attacker would need that org's actual secret, which is out of scope per the rules). I could not confirm from the indexed code whether Shipit's setup/deployment conventions guarantee `webhook_secret` is always required for every org — `docs/setup.md` and `config/secrets.*.yml` reference `webhook_secret` as configurable but I did not find a hard validation forcing it to be present for every configured organization.

### Recommendation
Cross-validate that `params.dig('repository','owner','login')` matches the owner segment of `params.dig('repository','full_name')` before dispatching to handlers, and reject (422) on mismatch. Additionally, do not allow `verify_webhook_signature` to silently pass when `webhook_secret` is blank — treat a missing secret as verification failure (or require secrets to be mandatory at config-load time) rather than an implicit bypass.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, not to be placed in `test/` per output rules but described for the assignee):
1. Configure two orgs in the test `github_apps`: `"attacker-org"` with no `webhook_secret`, and `"victim-org"` with a `webhook_secret` set.
2. Create `Repository` records for `victim-org/victim-repo` with an existing `PullRequest`/review stack (number `1`).
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, body: `{"action":"edited","number":1,"pull_request":{...forged title/body...},"repository":{"owner":{"login":"attacker-org"},"full_name":"victim-org/victim-repo"},"sender":{"login":"attacker-org-user"}}`, with an invalid/absent `X-Hub-Signature`.
4. Assert response is `200 OK` (not `422`), and assert `PullRequest.find_by(number: 1, stack: victim_stack).github_pull_request['title']` equals the forged title — proving `repository.owner.login` ("attacker-org", no secret) ≠ `repository.full_name`'s owner ("victim-org", has secret) yet the victim record was mutated.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)

    end
