### Title
DisplayName() collision bypasses FindNameCollisions and lets an attacker-named skill silently merge with a legitimate one during multi-select install - (File: internal/skills/discovery/collisions.go, pkg/cmd/skills/install/install.go)

### Summary
`FindNameCollisions` (and the `collisionError` guard) only groups skills by the raw `Skill.Name` field, while the interactive multi-select UI and `matchSelectedSkills` operate entirely on `Skill.DisplayName()` strings. Because `DisplayName()` is a formatted composite of `Convention` prefix + `Namespace` + `Name`, an attacker can choose a raw `Name` (e.g. `"[root] something"`) that renders to the exact same `DisplayName()` as an unrelated, legitimately discovered skill (e.g. root-convention skill named `"something"`), producing two entries with an identical label that `FindNameCollisions` never flags because their `Name` fields differ.

### Finding Description
`Skill.DisplayName()` builds its output from `Convention`, `Namespace`, and `Name` [1](#0-0) . The only character restriction on a skill directory's raw `Name` is `validateName`/`safeNamePattern`, which permits mixed case letters, digits, spaces, dots, underscores, and hyphens — including literal substrings like `[root] `, `[plugins] `, or `[hidden-dir] ` — as long as the value contains no `/` or `..` [2](#0-1) .

`DiscoverSkillsWithOptions` derives `Skill.Name` purely from `path.Base(dir)` of the matched `SKILL.md` directory with no sanitization against convention-prefix spoofing [3](#0-2) . An attacker can therefore publish a repo containing:
- `SKILL.md` at repo root (`convention: "root"`, `Name: "widget"`) → `DisplayName() == "[root] widget"`
- `skills/[root] widget/SKILL.md` (`convention: "skills"`, `Name: "[root] widget"`) → `DisplayName() == "[root] widget"` (identical string, no prefix added since convention is `"skills"`)

Both entries survive discovery and sorting [4](#0-3) . `FindNameCollisions` groups strictly `byName[s.Name]`, so `"widget"` and `"[root] widget"` land in separate buckets and no collision is ever reported [5](#0-4) ; `collisionError` therefore returns nil and installation proceeds [6](#0-5) .

Meanwhile `skillSearchFunc` builds the multi-select `Keys`/`Labels` solely from `s.DisplayName()`, so both skills appear with the identical label string `"[root] widget"` (plus possibly identical descriptions) [7](#0-6) . When the user selects that single visible entry, `matchSelectedSkills` builds a `nameSet` from the selected label strings and then iterates every discovered `Skill`, appending **any** skill whose `DisplayName()` is in that set [8](#0-7) . Because both the legitimate root skill and the attacker's spoofed `skills/` entry share the key `"[root] widget"`, **both** get silently appended to `result` — the user believes they approved one skill but both are installed, including the attacker-controlled one, with its own `Path`/`TreeSHA`/`BlobSHA` fetched and persisted via `lockfile.RecordInstall`.

### Impact Explanation
This breaks verification soundness: content the user never explicitly saw or approved (an attacker's `SKILL.md` at a different path with a different tree/blob SHA) is silently installed and pinned under a trusted-looking label. Because the lockfile is later used by `gh skill update` to validate against pinned SHAs, the attacker-controlled entry becomes durably trusted going forward. This matches GitHub's "verification/authorization bypass leading to unintended file write/installation of untrusted content" impact class.

### Likelihood Explanation
Requires only that an attacker publish a public repository with two conventionally-discoverable `SKILL.md` files (root + `skills/` directory named to include a bogus convention tag) and that a victim run `gh skill install` in interactive multi-select mode against that repo — no elevated privileges, tokens, or MITM needed. It is fully repeatable and deterministic; the collision fires anytime an attacker crafts a directory name containing a convention-tag prefix that matches a naturally occurring `DisplayName()` from another convention in the same repo.

### Recommendation
- Change `FindNameCollisions` (and any equivalent grouping) to key by `DisplayName()` rather than raw `Name`, since `DisplayName()` is what the user actually sees and selects.
- Additionally, reject/normalize raw skill `Name` values that contain characters resembling convention markers (e.g. `[`, `]`) or otherwise ensure `DisplayName()` cannot collide across skills discovered via different paths.
- Make `matchSelectedSkills` fail closed (return an error) whenever more than one `Skill` maps to a single selected label, instead of silently including all matches.

### Proof of Concept
```go
func TestMatchSelectedSkills_DisplayNameCollisionInstallsBothSilently(t *testing.T) {
    skills := []discovery.Skill{
        {Name: "widget", Path: "widget", Convention: "root"},                       // legit root skill
        {Name: "[root] widget", Path: "skills/[root] widget", Convention: "skills", // attacker-crafted
            TreeSHA: "attacker-tree-sha", BlobSHA: "attacker-blob-sha"},
    }
    // Both render to the same visible label:
    require.Equal(t, "[root] widget", skills[0].DisplayName())
    require.Equal(t, "[root] widget", skills[1].DisplayName())

    // FindNameCollisions fails to catch it because Name fields differ.
    require.Empty(t, discovery.FindNameCollisions(skills))

    // User selects the single visible entry "[root] widget"...
    result, err := matchSelectedSkills(skills, []string{"[root] widget"})
    require.NoError(t, err)

    // ...but BOTH skills — including the attacker's — are silently returned.
    require.Len(t, result, 1, "expected exactly one skill for one user selection, got both legit and attacker entries")
}
```
Expected (buggy) behavior: `len(result) == 2`, demonstrating the attacker's `Skill{Path: "skills/[root] widget", TreeSHA: "attacker-tree-sha"}` is installed alongside the one the user intended, with no warning surfaced by `collisionError`.

func (s Skill) DisplayName() string {
	name := s.Name
	if s.Namespace != "" {
		name = s.Namespace + "/" + name
	}
	switch s.Convention {
	case "plugins":
		return "[plugins] " + name
	case "root":
		return "[root] " + name
	case "hidden-dir", "hidden-dir-namespaced":
		return "[hidden-dir] " + name
	default:
		return name
	}
}

// validateName checks if a skill name is safe for use (filesystem-safe).
func validateName(name string) bool {
	if len(name) == 0 || len(name) > 64 {
		return false
	}
	if strings.Contains(name, "/") || strings.Contains(name, "..") {
		return false
	}
	return safeNamePattern.MatchString(name)
}

func FindNameCollisions(skills []Skill) []NameCollision {
	byName := make(map[string][]Skill)
	for _, s := range skills {
		byName[s.Name] = append(byName[s.Name], s)
	}

	var collisions []NameCollision
	for name, group := range byName {
		if len(group) <= 1 {
			continue
		}
		names := make([]string, len(group))
		for i, s := range group {
			names[i] = s.DisplayName()
		}
		collisions = append(collisions, NameCollision{Name: name, DisplayNames: names})
	}

func matchSelectedSkills(skills []discovery.Skill, selected []string) ([]discovery.Skill, error) {
	nameSet := make(map[string]struct{}, len(selected))
	for _, name := range selected {
		nameSet[name] = struct{}{}
	}

	var result []discovery.Skill
	for _, s := range skills {
		if _, ok := nameSet[s.DisplayName()]; ok {
			result = append(result, s)
		}
	}
	if len(result) == 0 {
		return nil, fmt.Errorf("no matching skills found")
	}
	return result, nil
}

// collisionError checks for name collisions among the selected skills.
func collisionError(ss []discovery.Skill) error {
	collisions := discovery.FindNameCollisions(ss)
	if len(collisions) == 0 {
		return nil
	}
	return fmt.Errorf("cannot install skills with conflicting names; they would overwrite each other:\n  %s",
		discovery.FormatCollisions(collisions))
}
