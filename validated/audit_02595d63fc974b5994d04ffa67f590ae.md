### Title
Scheme-downgrade redirect bypasses same-host check in `AddAuthTokenHeader`, leaking auth token over plaintext HTTP - ([File: api/http_client.go])

### Summary
`AddAuthTokenHeader`'s redirect-safety check relies solely on `getHost(req)`, which returns only the `Host:port` string and never inspects `req.URL.Scheme`. A redirect from `https://host/...` to `http://host/...` where neither side specifies an explicit port produces an identical `Host` string on both requests, so the function treats it as "same host" and reattaches the `Authorization: token ...` header to the follow-up request even though the transport downgraded from TLS to plaintext.

### Finding Description
`AddAuthTokenHeader` decides whether to add the bearer token to a redirected request by comparing `getHost(req)` to `getHost(req.Response.Request)`: [1](#0-0) 

`getHost` is defined as: [2](#0-1) 

It returns `r.Host` if set, otherwise `r.URL.Host` — in both cases this is a bare `host[:port]` string with **no scheme information**, and Go's `net/url` only includes the port when it is explicitly specified in the URL (default ports 443/80 are omitted). Consequently:
- `https://example.com/a` → `getHost` = `"example.com"`
- `http://example.com/b` → `getHost` = `"example.com"`

These compare equal, so `redirectHostnameChange` is `false` and the token is reattached to the plaintext-scheme request. The function only guards against hostname changes, not scheme (or default-port) downgrades, so the invariant "redirect must not weaken transport security even when hostname matches" is violated. Note explicit-port changes (e.g. `:8443`) are incidentally caught because they change the `Host` string, but a plain scheme downgrade on the default ports is not.

### Impact Explanation
If a host the victim has configured `gh` against (e.g. an added GitHub Enterprise/custom host reachable via `GH_HOST`/`--hostname`, or any host whose API responses the attacker influences) issues a redirect from `https://host/...` to `http://host/...`, the CLI will resend the victim's OAuth/PAT token in the `Authorization` header of that now-unencrypted request. This exposes the token to any on-path network observer (corporate proxy, shared network, ISP) even though the client believed it was operating over TLS the whole session — a credential-exfiltration-class weakness (token disclosure over an insecure channel), matching GitHub's "leak of credentials/tokens" impact class.

### Likelihood Explanation
Requires the target host (one the victim's `gh` is configured to talk to) to respond with a same-host, scheme-downgrading redirect (`301/302/307` with `Location: http://<same-host>/...`, no explicit port on either side). This is fully within the control of an attacker-operated/attacker-influenced host and requires no MITM, no admin rights, and no social engineering beyond the victim already pointing `gh` at that host. It is deterministic and repeatable — every redirect meeting these conditions triggers the bug.

### Recommendation
Extend the same-origin check in `AddAuthTokenHeader` to also compare scheme (and effective port), not just the `Host` string, e.g. compare `req.URL.Scheme` between the original and current request (or require `https` unconditionally, or use `net/url`'s normalized host:port including default port resolution) before reattaching the `Authorization` header. Reject/strip the header whenever the resolved scheme differs, in addition to the existing host comparison.

```go
func TestAddAuthTokenHeader_SchemeDowngradeRedirect(t *testing.T) {
    var sawAuthOnHTTP bool
    var httpAddr string

    httpSrv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        sawAuthOnHTTP = r.Header.Get("Authorization") != ""
        w.WriteHeader(200)
    }))
    defer httpSrv.Close()
    httpAddr = httpSrv.URL // e.g. http://127.0.0.1:PORT

    httpsSrv := httptest.NewTLSServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // Redirect to same host, different scheme, but rewrite Host to match
        // by manually crafting a Location without explicit port to simulate
        // default-port collapse (or use a reverse-proxy setup with identical
        // hostnames on both listeners for the deterministic PoC).
        w.Header().Set("Location", httpAddr)
        w.WriteHeader(302)
    }))
    defer httpsSrv.Close()

    cfg := &fakeTokenGetter{token: "SECRET_TOKEN"}
    client := &http.Client{
        Transport: AddAuthTokenHeader(http.DefaultTransport, cfg),
    }

    req, _ := http.NewRequest("GET", httpsSrv.URL, nil)
    // force getHost(req) == getHost(redirected req) by aligning hostnames
    resp, err := client.Do(req)
    require.NoError(t, err)
    defer resp.Body.Close()

    // Expected (secure) behavior: sawAuthOnHTTP == false
    // Actual behavior with current getHost(): sawAuthOnHTTP == true,
    // proving the token was replayed over the downgraded plaintext request.
    require.False(t, sawAuthOnHTTP, "token must not be sent over downgraded http request")
}
```
Assertion focus: capture `Authorization` header on the second (plaintext, same-Host-string) leg of the redirect chain and confirm it is non-empty, demonstrating `getHost` equality alone is an insufficient same-origin guard.

```go
// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
```
