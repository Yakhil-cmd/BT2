### Title
Permanent market freeze: `global_sync` interest accrual overflows `i128` inside `scaled_to_original` before the borrow-index cap can engage - (contracts/pool/src/interest.rs)

### Summary
The bug class from GHSA-jrwr-5x3p-hvc3 is "unhandled hostile input crashes the entrypoint → denial of service." The on-chain analog is stronger: in XOXNO Lending every pool mutation runs `interest::global_sync` first, and the accrual path multiplies scaled debt by the borrow index via `scaled_to_original`/`accrue_step`, which panics with `GenericError::MathOverflow` on `i128` overflow. Once `borrow_index * borrowed` exceeds `i128::MAX` — reachable on large markets at sustained high utilization — the panic becomes a permanent state: no repay, no withdraw, no liquidation, no index update ever succeeds again. The `MAX_BORROW_INDEX_RAY` cap is checked too late (or never) to stop the value-domain cliff, so all supplier funds in that market are frozen forever.

### Finding Description
Every market entrypoint in the pool follows `Cache::load → interest::global_sync → mutate → guards → commit` [1](#0-0) . `global_sync` accrues indexes in `MAX_COMPOUND_DELTA_MS` chunks and calls `accrue_chunk`, which invokes the shared `accrue_step` engine and writes the new `borrow_index`/`supply_index` [2](#0-1) .

The accrual computes the accrued debt value as `borrowed_scaled * borrow_index` through `scaled_to_original`, which is a plain `Ray::mul` that panics on `i128` overflow [3](#0-2) . RAY-scaled values carry a 1e27 factor, so a market holding ~`BILLION` whole 18-decimal tokens already sits at ~1e36 scaled — only ~170x of headroom below `i128::MAX` (~1.7e38). On a steep interest curve at ~98% utilization the `borrow_index` grows past that multiple well before the `MAX_BORROW_INDEX_RAY` ceiling is reached, because the cap limits the *index* while the overflow occurs in the *index × scaled-debt product*. The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates exactly this: `try_update_indexes_for` fails with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and afterward `try_withdraw_raw` and `try_repay` both fail with the same panic because they accrue first [4](#0-3) .

Since `global_sync` runs inside the same transaction before any mutation and `last_timestamp` is only advanced on success (`cache.mark_accrued()` at interest.rs:32), each retry re-executes the same overflowing multiplication — the failure is deterministic and permanent, not transient.

### Impact Explanation
Permanent freezing of all user funds in the affected market: suppliers cannot `withdraw`, borrowers cannot `repay`, liquidators cannot `liquidate` (the pool legs inside liquidation also accrue), and the market cannot accrue or be cleaned via `clean_bad_debt`. All tokens physically held by the pool for that market are bricked. This is the maximum-severity form of the advisory's DoS class — the crash is not per-request but latched into state.

### Likelihood Explanation
An unprivileged address drives the market toward the cliff entirely through allowed entrypoints: `supply` a large position in a high-decimals market, `borrow` up to high utilization on a steep curve (e.g. the XLM-style curve at ~98%), then let time accrue — or keep the utilization high so index growth compounds. No governance action, oracle manipulation, or privileged parameter is needed; the test uses only `supply_raw`/`borrow_raw`/`advance_time`. Likelihood is bounded by needing a whale-scale position and a long horizon at high utilization, hence High rather than Critical.

### Recommendation
In `common/src/rates/` accrual (`accrue_step`), cap the effective `borrow_index` or saturate the accrued-value product so `scaled * index` cannot overflow `i128` — e.g., clamp the index such that `borrowed_scaled * index <= i128::MAX` before computing interest, and stop accruing (pin `last_timestamp` / freeze rate) rather than panic. Alternatively, engage `MAX_BORROW_INDEX_RAY` *before* multiplying by scaled balances, sized against the market's actual scaled debt. Add a regression test mirroring `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` asserting that withdraw/repay keep working after the cliff.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
