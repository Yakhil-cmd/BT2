### Title
CCMenuController bypasses ApiClient stack-scoping, allowing a stack-restricted token to read any stack's status - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::BaseController` enforces that an `ApiClient` restricted to a single stack (`current_api_client.stack_id`) can only resolve stacks within that scope via the `stacks`/`stack` helper methods. [1](#0-0)  `Shipit::Api::CCMenuController` overrides `stack` and resolves it directly from `params[:stack_id]` without going through the scoped `stacks` collection, breaking the binding between "the stack a token authorizes" and "the stack the request actually touches." [2](#0-1) 

### Finding Description
Any `ApiClient` authenticates through `authenticate_api_client`, and its permission scope to a specific stack is expressed by the `stack_id` column, which is deliberately consulted by the base controller's `stacks` method: `current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all`. [3](#0-2) 

`CCMenuController`, however, redefines `stack` to call `Stack.from_param!(params[:stack_id])` directly, entirely skipping the `stacks` scoping method:
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
``` [4](#0-3) 

The only authorization check performed is `require_permission :read, :stack`, which only verifies the permission *name* exists in `current_api_client.permissions` (`ApiClient#check_permissions!`), and never checks whether the requested `stack_id` param matches the token's bound `stack_id`. [5](#0-4) 

This is directly analogous to the referenced GMX finding: a verification mechanism exists (the `SALT`/chain-id binding in GMX, the `stack_id` scoping in Shipit) but a code path (`Oracle` signature verification omitting a fresh chain-id check; `CCMenuController#stack` bypassing the scoped lookup) fails to re-apply that binding, so a credential valid in one narrow context (one chain / one stack) can be used outside of it (another chain / any stack).

### Impact Explanation
An `ApiClient` token intentionally scoped to a single stack (`stack_id` set, e.g. to limit a CI badge/monitoring integration to one project) can be replayed against the CCMenu endpoint with an arbitrary `stack_id` parameter to read build/deploy status (`name`, `activity`, `lastBuildStatus`, `lastBuildLabel`, `webUrl`, etc.) for any other stack in the Shipit instance, exceeding the authorization granted at token-creation time. This is an unauthorized read of stack state through an authorization/scoping bypass — a violation of the intended per-stack ApiClient permission boundary.

### Likelihood Explanation
Exploitation requires possession of a valid `ApiClient` authentication token (Basic Auth or `token` query param) that has `read:stack` permission but is scoped to a specific stack. No further privilege or session is needed; the attacker only needs to change the `stack_id` request parameter, which the base controller pattern elsewhere (e.g. `Api::StacksController`) correctly restricts but `CCMenuController` does not.

### Recommendation
Remove the `stack` override in `CCMenuController` and rely on the inherited, scoped `stacks`/`stack` implementation from `Api::BaseController` (`stacks.from_param!(params[:stack_id])`), so that stack-scoped tokens cannot resolve stacks outside their authorized `stack_id`.

### Proof of Concept
1. Create (via console/administrative API — the model supports `belongs_to :stack, optional: true`) an `ApiClient` with `permissions: ['read:stack']` and `stack_id` set to Stack A's id, yielding token `T`.
2. Authenticate to `GET /api/ccmenu.xml?stack_id=<Stack B param>` using `Authorization: Basic base64(T)`.
3. `authenticate_api_client` succeeds (token is valid); `require_permission :read, :stack` succeeds (`permissions` includes `read:stack`); `CCMenuController#stack` resolves Stack B directly via `Stack.from_param!`, bypassing the `stacks` scoping that would have restricted resolution to Stack A only. [6](#0-5) 
4. The response returns Stack B's build/deploy status even though token `T` was authorized only for Stack A.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
