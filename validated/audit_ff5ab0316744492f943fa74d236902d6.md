## Title
Unbounded loop in `root_owner` view function via constructible ownership cycle - (`aptos-move/framework/aptos-framework/sources/object.move`)

## Summary
`root_owner` (aptos-framework `object.move`, lines 742-748) walks up an object's ownership chain with no bound, unlike its sibling functions `owns` and `verify_ungated_and_descendant`, which both cap traversal with `MAXIMUM_OBJECT_NESTING`. An unprivileged account can legitimately construct a two-object ownership cycle (`A` owned by `B`, `B` owned by `A`) using only the public, unrestricted `transfer`/`transfer_raw` entry functions, because `verify_ungated_and_descendant` only validates that the *caller* transitively owns the object being moved — it never checks whether the destination address is itself a descendant of the object, so nothing prevents weaving a cycle across two independent transfers. Once the cycle exists, any unprivileged caller invoking the `#[view]` function `root_owner` on either object causes an infinite loop.

## Finding Description
`root_owner` is defined as: [1](#0-0) 

Note it has no counter/cap, unlike `owns`: [2](#0-1) 
and `verify_ungated_and_descendant`: [3](#0-2) 

`transfer_raw` calls `verify_ungated_and_descendant(owner_address, object)` to confirm the signer transitively owns `object`, then unconditionally sets `object`'s owner to `to`: [4](#0-3) 

Crucially, `verify_ungated_and_descendant` only walks upward from `object` toward `owner`; it never inspects `to` or whether `to` is itself a descendant of `object`. This means a real owner can build a cycle in two ordinary, permitted transfers:

1. Owner creates objects `A` and `B` (both directly owned by owner).
2. `transfer(owner, B, A_address)` — verification succeeds trivially (`B.owner == owner`), then `B.owner` is set to `A`.
3. `transfer(owner, A, B_address)` — verification succeeds trivially (`A.owner` is still `owner`), then `A.owner` is set to `B`.

After step 3, `A.owner == B` and `B.owner == A`: a genuine 2-cycle, created entirely through publicly-callable, unprivileged transfer operations, with no nesting-cap violation at any single step because each individual verification call only sees a length-1 chain back to the real owner at the time it runs.

The existing test `test_cyclic_ownership_transfer_should_fail` only covers the direct self-loop case (`obj1` transferred to itself), which is caught because `verify_ungated_and_descendant`'s traversal from the object never reaches the real owner and hits `MAXIMUM_OBJECT_NESTING`: [5](#0-4) 
It does not cover the multi-object cycle case shown above, which bypasses the cap entirely.

Once the cycle exists, `is_object(obj_owner)` is always true for both `A` and `B`, so `root_owner`'s `while` loop never terminates: [6](#0-5) 

The spec file even flags this class of gap with a TODO comment ("Verify the link list loop in verify_ungated_and_descendant") without addressing it: [7](#0-6) 

## Impact Explanation
`root_owner` is a `#[view]` function, callable by anyone without any signer or privilege via the REST `/view` endpoint or Move script/simulation, on any object address the caller can name. Any account (even the object owner who created the cycle, or any third party who merely knows the object's address) triggering `root_owner` on `A` or `B` causes non-terminating execution instead of a bounded computation, consuming gas/CPU without termination in a call path that the nesting-cap design elsewhere assumes is bounded. This breaks the invariant enforced by `MAXIMUM_OBJECT_NESTING` in `owns` and `verify_ungated_and_descendant`, and constitutes unbounded resource consumption triggerable by unprivileged, ordinary object owners using only standard entry functions.

## Likelihood Explanation
High likelihood: no privileged signer, no exploit of authenticator/mempool/VM validation is required — only two ordinary `transfer` calls by the object's legitimate owner, followed by any caller invoking the unauthenticated view function `root_owner`. All operations use existing public entry points with no special preconditions.

## Recommendation
Add a bounded-nesting guard (using `MAXIMUM_OBJECT_NESTING`, consistent with `owns`/`verify_ungated_and_descendant`) to `root_owner`'s traversal loop, aborting with `EMAXIMUM_NESTING` if the bound is exceeded. Additionally, consider strengthening `verify_ungated_and_descendant` (or adding a check in `transfer_raw`) to detect/reject constructing cross-object cycles, not just direct self-loops, so that other traversal code relying on the "no cycles / bounded depth" invariant cannot be violated in the first place.

## Proof of Concept
```move
#[test(creator = @0x123)]
fun test_two_object_cycle_root_owner_infinite_loop(creator: &signer) {
    let obj_a = create_simple_object(creator, b"a");
    let obj_b = create_simple_object(creator, b"b");

    // Step 1: B is owned by A. Verification trivially passes since B.owner == creator.
    transfer(creator, obj_b, obj_a.object_address());

    // Step 2: A is owned by B. Verification trivially passes since A.owner == creator
    // (unchanged by step 1). No nesting cap is ever hit because each verification
    // call only walks a length-1 chain back to `creator`.
    transfer(creator, obj_a, obj_b.object_address());

    // Now: A.owner == B, B.owner == A -- a genuine two-object ownership cycle,
    // constructed without ever triggering EMAXIMUM_NESTING.

    // Calling root_owner on either object should abort deterministically (e.g. with
    // EMAXIMUM_NESTING) or otherwise be bounded. Instead it loops forever, since
    // is_object() is always true for both A and B.
    let _ = obj_a.root_owner();
}
```
`create_simple_object` (a `#[test_only]` helper already used by `test_cyclic_ownership_transfer_should_fail`) creates a plain object directly owned by `creator` with ungated transfer enabled, matching the referenced test at `object.move:1081-1089`. Running this test should hang (never terminate) rather than abort, demonstrating that `root_owner` is missing the bounded-nesting guard present elsewhere in the module.

    /// This checks that the destination address is eventually owned by the owner and that each
    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8
    /// objects may have cyclic dependencies.
    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }

    /// Return true if the provided address has indirect or direct ownership of the provided object.

    /// Note: intentionally not using `self` as first argument, as a.owns(b) syntax would be ambiguous.
    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }

    public fun root_owner<T: key>(self: Object<T>): address {
        let obj_owner = self.owner();
        while (is_object(obj_owner)) {
            obj_owner = address_to_object<ObjectCore>(obj_owner).owner();
        };
