### Title
Missing request timeout/context deadline in `downloadAsset` enables indefinite hang on attacker-controlled asset/archive download - (File: pkg/cmd/release/download/download.go)

### Summary
`downloadAsset` builds its GET request with `http.NewRequest` (no context) and issues it via `httpClient.Do(req)` with no `context.WithTimeout`/`context.WithDeadline` wrapping the call, and the response body is then streamed to disk with a plain `io.Copy`. An attacker who controls the release asset host, archive URL (codeload tarball/zip), or the served asset bytes can slow-loris the connection (trickle headers or body bytes) and cause the victim's `gh release download` invocation to hang indefinitely, which is especially damaging in CI pipelines that lack their own external timeouts.

### Finding Description
`downloadRun` (pkg/cmd/release/download/download.go:142-246) builds `context.Background()` and never derives a bounded child context from it before calling `downloadAssets`/`downloadAsset`. [1](#0-0) 

`downloadAsset` itself constructs the request with `http.NewRequest("GET", assetURL.String(), nil)` (not `NewRequestWithContext`), so there is no per-call cancellation path at all: [2](#0-1) 

The request is then executed and the body copied without any deadline: [3](#0-2) [4](#0-3) 

`assetURL` is attacker-influenced: for normal assets it is `a.APIURL` taken directly from the GitHub API's asset listing (`release.Assets`), and for `--archive` downloads it is `release.TarballURL`/`release.ZipballURL`, both API-provided URLs pointing at `codeload.github.com` or the asset host. [5](#0-4) 
While `safeurl.NewImmutableSafeURL` presumably restricts the URL to expected trusted hosts (github.com/codeload/api hosts), it does not address timing — a compromised or malicious response from that same legitimate-looking host (e.g., slow header delivery, or a legitimate GitHub-hosted redirect target such as a release asset stored on a slow/attacker-controlled release-asset CDN) can still stall indefinitely because neither the HTTP client nor the request carries a deadline.

None of `net/http.Client{Timeout: ...}` is visible being set in the client construction path reachable from this code (`api.NewHTTPClient`), and no `context.WithTimeout` is used anywhere in this call chain, so the invariant "every outbound request carries a bounded timeout" is violated for this endpoint.

### Impact Explanation
An attacker who publishes a release asset (or otherwise controls bytes served under a URL returned by the Releases API) can serve an extremely slow response (classic slow-loris: dribble a few bytes then stall) to make `httpClient.Do(req)` or the subsequent `io.Copy` in `destinationWriter.Copy` block indefinitely. This causes unbounded resource consumption (a hung goroutine/worker, held file handle, blocked CI job) on the victim's machine from a single attacker-published asset, matching the "Unbounded resource consumption" impact class. In CI environments this can hang pipelines until an external CI-level timeout (if any) kills the job, wasting compute/minutes and potentially blocking dependent jobs.

### Likelihood Explanation
Preconditions are minimal and match the stated attacker model: an unprivileged remote user only needs to publish a release with an asset (or control the archive/asset host content) that the victim later downloads via `gh release download`. No token, MITM, or special privilege is required — the victim just needs to run an ordinary `gh release download` (with or without `--pattern`/`--archive`) against the attacker's repo/release. This is trivially repeatable and requires no race conditions.

### Recommendation
Wrap the download request with a bounded context, e.g. derive `ctx, cancel := context.WithTimeout(context.Background(), someDeadline)` in `downloadRun`/`downloadAssets` and use `http.NewRequestWithContext(ctx, ...)` in `downloadAsset`; additionally set an idle/read deadline via `http.Client.Timeout` or a `context.WithTimeout` around the full request+body-read cycle (not just headers) so a slow body drip cannot bypass a header-only timeout. Ensure the timeout also covers `io.Copy` in `destinationWriter.Copy`, e.g. by using an `io.Reader` derived from the context-canceled request body rather than the raw `resp.Body`.

### Proof of Concept
```go
func TestDownloadAsset_HangsWithoutTimeout(t *testing.T) {
    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.WriteHeader(200)
        flusher, _ := w.(http.Flusher)
        for i := 0; i < 1000; i++ {
            w.Write([]byte("a"))
            flusher.Flush()
            time.Sleep(2 * time.Second) // slow-loris drip
        }
    }))
    defer srv.Close()

    dest := destinationWriter{dir: t.TempDir()}
    done := make(chan error, 1)
    go func() {
        u, _ := safeurl.NewSafeURL(srv.URL) // or appropriate constructor
        done <- downloadAsset(&dest, http.DefaultClient, u, "asset.bin", false)
    }()

    select {
    case <-done:
        // expected: should complete or fail within a bounded deadline
    case <-time.After(5 * time.Second):
        t.Fatal("downloadAsset did not respect a bounded timeout; call is still hanging")
    }
}
```
Expected result today: the test times out after 5s because `downloadAsset` has no deadline, confirming the missing-timeout hang. After adding a context deadline/`http.Client.Timeout`, the call should return an error before the 5s assertion fires.

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
