### Title
Division-before-multiplication truncation in `min-ustx-for-sats-amount` understates the required STX collateral for sBTC bond registration - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`min-ustx-for-sats-amount` computes the floor amount of uSTX a staker must lock relative to the sats they custody in a protocol bond, using `min-ustx-ratio` (basis points) and `stx-value-ratio` (uSTX per 100 sats). The implementation performs an intermediate division (`/ ... u100`) before multiplying by `min-ustx-ratio`, truncating precision before the final scale-up — the exact anti-pattern flagged in the referenced report (`amountInterest = bareIncrease / PRECISION_FACTOR_YEAR` then `* poolFee`). [1](#0-0) 

### Finding Description
```
(define-read-only (min-ustx-for-sats-amount
        (sats-amount uint)
        (stx-value-ratio uint)
        (min-ustx-ratio uint)
    )
    (/ (* (/ (* stx-value-ratio sats-amount) u100) min-ustx-ratio) u10000)
)
``` [2](#0-1) 

The mathematically precise value is `stx-value-ratio * sats-amount * min-ustx-ratio / 1,000,000`. The contract instead first computes `floor(stx-value-ratio * sats-amount / 100)`, discarding up to 99 units of precision, and only then multiplies by `min-ustx-ratio` and divides by `u10000`. This means the final floor computed on-chain is systematically `<=` the mathematically correct floor, and in some cases (e.g. `stx-value-ratio=101`, `sats-amount=1`, `min-ustx-ratio=9999`) rounds all the way down to `0` where the correct value is `1`.

This function directly gates the collateral check in `register-for-bond`:
```
(asserts!
    (>= amount-ustx
        (min-ustx-for-sats-amount sats-total (get stx-value-ratio bond)
            (get min-ustx-ratio bond)
        ))
    ERR_INSUFFICIENT_STX
)
``` [3](#0-2) 

Because the check compares the caller-supplied `amount-ustx` against this truncated (understated) floor, every unprivileged staker who calls `register-for-bond` can lock strictly less uSTX than the protocol's `min-ustx-ratio` parameter actually intends relative to their custodied sats. The test-side model in `contrib/core-contract-tests/tests/pox-5/commands/utils.ts` reproduces the exact same truncation order ("Integer division at each step, matching the contract's truncation"), confirming this is the contract's real (unmitigated) behavior rather than a test artifact. [4](#0-3) 

### Impact Explanation
`min-ustx-ratio` is meant to enforce a floor on how much STX value must back a given amount of sats custodied in a bond, i.e. it enforces that the signer's/staker's uSTX-denominated stake is proportionate to the BTC value they're staking. Any staker (fully unprivileged — this is reachable directly through `register-for-bond`) can supply exactly the truncated (lower) minimum and satisfy the on-chain check while providing less STX collateral than the bond's configured ratio requires. This lets the sats-backed weight (signer shares, reward eligibility, and reward-slot proportion computed later from `sats-total`/`amount-ustx`) exceed what is properly backed by locked STX — matching the "signing weight or reward slots exceeding locked value" High-impact category, since it weakens the STX-backing guarantee behind every registered bond position rather than costing only the caller's own funds.

### Likelihood Explanation
The flaw is triggered on every call to `register-for-bond` with any `stx-value-ratio`/`min-ustx-ratio`/`sats-amount` combination where the two-step truncation loses a non-zero remainder (which is the general case for arbitrary parameters), requiring no special privileges — any allow-listed staker choosing an `amount-ustx` at or slightly above the contract-reported floor benefits from the understated minimum.

### Recommendation
Reorder the arithmetic to multiply before dividing, matching the mathematically precise formula:
```
(/ (* stx-value-ratio sats-amount min-ustx-ratio) u1000000)
```
This preserves full precision (Clarity's 128-bit `uint` arithmetic has ample headroom for this product) and removes the systematic understatement of the STX collateral floor.

### Proof of Concept
With `stx-value-ratio = 101`, `sats-amount = 1`, `min-ustx-ratio = 9999`:
- Correct: `101 * 1 * 9999 / 1,000,000 = 1,009,899 / 1,000,000 = 1` (floor).
- Contract: `floor(101 * 1 / 100) = 1`; then `floor(1 * 9999 / 10000) = 0`.

The contract computes a floor of `0` where the precise floor is `1`, so `register-for-bond` accepts `amount-ustx = 0` for this configuration even though the bond's `min-ustx-ratio` requires a non-zero STX lock relative to the sats being custodied. This effect scales with larger `sats-amount`/`stx-value-ratio` values, systematically discounting the required collateral across every registration.

/**
 * Contract's `min-ustx-for-sats-amount`: the floor uSTX a staker must lock for
 * `sats`. Integer division at each step, matching the contract's truncation.
 */
export function minUstxForSats(
  sats: bigint,
  stxValueRatio: bigint,
  minUstxRatio: bigint,
): bigint {
  return (((stxValueRatio * sats) / 100n) * minUstxRatio) / 10000n;
}
