### Title
Webhook repository-owner used for signature verification does not have to match `repository.full_name` used for the actual stack action - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp`/`webhook_secret` to use for HMAC verification based on `repository.owner.login` (or `organization.login`) taken from the unsigned request body, while `Handler#repository_name`/`Handler#stacks` independently read `repository.full_name` from the same body to look up the target `Stack`. Nothing ties the verifying org to the acted-upon repository, so a signature valid for org-X's webhook secret can authorize an action against org-Y's stack.

### Finding Description
The broken binding, stated as an equality that the code assumes but never enforces:

`organization_used_for_verification (params.dig('repository','owner','login'))` **==** `owner_of(repository_used_for_action (params.dig('repository','full_name')))`

Trace:
- `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` and fetches `Shipit.github(organization: repository_owner)`, then calls `verify_webhook_signature` with that org's `webhook_secret`. [1](#0-0) 
- `Shipit.github` / `github_app_config` resolve the `GitHubApp` (and its `webhook_secret`) purely by the organization name found in `secrets.github`, with no cross-check against any other field of the payload. [2](#0-1) 
- `GitHubApp#verify_webhook_signature` only proves the raw body was HMAC-signed with the secret belonging to whatever organization `repository_owner` named - it does not scope trust to any particular repository within that org. [3](#0-2) 
- After verification succeeds, `WebhooksController#create` re-parses the same raw body and dispatches to handlers (e.g. `PushHandler`) with the full, attacker-controlled JSON. [4](#0-3) 
- `Handler#repository_name` reads `payload.dig('repository', 'full_name')` - a completely separate field from the one used for verification - and `Handler#stacks` resolves `Repository.from_github_repo_name(repository_name)&.stacks`. [5](#0-4) 
- `PushHandler#process` iterates `stacks.not_archived.where(branch:)` and calls `stack.sync_github(expected_head_sha: params.after)` - a real mutating action - purely off that unchecked `full_name`. [6](#0-5) 

Exploit flow: the attacker administers (or has been granted webhook configuration control over) an org "org-X" that is legitimately onboarded to this Shipit instance with its own `webhook_secret` entry in `secrets.github` (multi-org config, as documented/supported by `github_app_config`). Because the attacker set up that webhook themselves, they know org-X's `webhook_secret`. They then send a raw `POST /webhooks` directly to the Shipit host (bypassing GitHub entirely) with:
- `X-Github-Event: push`
- body: `{"repository":{"owner":{"login":"org-X"},"full_name":"org-Y/target-repo"}, "ref":"refs/heads/master", "after":"<attacker-chosen sha>"}`
- `X-Hub-Signature: sha1=<HMAC-SHA1(org-X_webhook_secret, raw_body)>`

`verify_signature` picks org-X's `GitHubApp` (via `repository_owner == "org-X"`) and the signature checks out, since the attacker computed it correctly with org-X's own secret. `create` then dispatches `PushHandler`, which reads `repository.full_name == "org-y/target-repo"` and calls `sync_github` on org-Y's real `Stack`, entirely without org-Y's or GitHub's involvement.

None of the existing guards catch this: `drop_unhandled_event` only checks the event type is registered; `ExplicitParameters` schema for `PushHandler` only requires `ref`/`after` are present and does not validate `repository.full_name`'s owner against `repository.owner.login`; `Repository.from_github_repo_name` simply parses the `owner/name` string with no authorization check; there is no `force_github_authentication`/session check on this unauthenticated endpoint (webhooks are, by design, unauthenticated except for the HMAC).

### Impact Explanation
An attacker who controls (or has been delegated webhook-secret control for) one onboarded organization can trigger `Stack#sync_github` - a real, mutating GitHub sync/deploy-trigger action - against **any other organization's stack** on the same Shipit instance, by simply naming that other org/repo in the unsigned `repository.full_name` field. This is a cross-tenant record/action write attributed to a repository that never authenticated the request, matching the "payload for one repository mutating another's stack" Critical category. The attack is fully repeatable against arbitrary target repositories/stacks known to the attacker, and works identically for other handlers keyed the same way (`PullRequest::*Handler`, `status`, `check_suite`, etc.) since they all inherit `Handler#stacks`/`#repository_name`.

### Likelihood Explanation
This requires the Shipit deployment to be configured with the multi-organization `github:` secrets schema (documented and supported via `github_app_config`/`TOP_LEVEL_GH_KEYS`), and the attacker must control webhook-secret setup for at least one org already onboarded to that instance - i.e., they are not an "any internet user" with zero relationship to the target Shipit instance, but they are still an unprivileged actor with respect to org-Y (no Shipit session, no API token, no knowledge of org-Y's secret). Feasibility is high once that precondition holds: the request is a single crafted HTTP POST with a correctly computed HMAC using a secret the attacker legitimately possesses for their own org, requiring no GitHub interaction at all.

### Recommendation
Bind the two identities that verification is supposed to establish: after computing `repository_owner` for secret selection, re-derive the owner from `repository.full_name` (or `organization.login`) and reject the request (422) if they don't match, before dispatching to any handler. Alternatively, look up the `Repository`/`Stack` for `repository.full_name` and confirm its recorded GitHub organization equals `repository_owner` used for verification, inside `Handler#stacks`, rather than trusting `full_name` unconditionally.

test "push payload verified with org-X secret cannot mutate org-Y's stack" do
  # secrets configured with two orgs: OrgX (attacker-controlled secret) and OrgY (victim, has stack `victim_stack`)
  request.headers['X-Github-Event'] = 'push'

  body = {
    repository: { owner: { login: 'OrgX' }, full_name: 'OrgY/target-repo' },
    ref: 'refs/heads/master',
    after: 'deadbeef'
  }.to_json

  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', org_x_webhook_secret, body)
  @request.headers['X-Hub-Signature'] = signature

  # Equality that SHOULD hold but does not:
  # params.dig('repository','owner','login') ('OrgX')
  #   != owner_of(params.dig('repository','full_name')) ('OrgY')
  Shipit::Stack.any_instance.expects(:sync_github).never # desired secure behavior

  post :create, body: body, as: :json

  assert_response :unprocessable_entity # expected fix; currently returns :ok and triggers sync_github on OrgY's stack
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
