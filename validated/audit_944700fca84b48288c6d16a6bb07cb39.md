### Title
Webhook authentication bypass for organizations configured without `webhook_secret` allows unauthenticated `pull_request` `opened` events to provision review stacks - (File: lib/shipit/github_app.rb)

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when the resolved organization's config has no `webhook_secret`, so `WebhooksController#verify_signature` accepts any forged `pull_request` payload for that organization without checking `X-Hub-Signature`. An attacker can forge an `opened` event for a real repository under such an organization and cause `OpenedHandler` to create a `ReviewStack` and enqueue provisioning, entirely without possessing the org's secret (because there isn't one) or any other credential.

### Finding Description
The intended binding is: `verified == true` **iff** `HMAC(webhook_secret_for(repository_owner), raw_body) == X-Hub-Signature header`. The actual code breaks this equivalence: [1](#0-0) 

`verify_webhook_signature` short-circuits with `return true unless webhook_secret` — when the organization's config carries no `webhook_secret`, `verified` is `true` unconditionally, regardless of the (attacker-controlled or absent) signature header.

`WebhooksController#verify_signature` selects the `GitHubApp` instance purely from attacker-controlled payload data (`repository.owner.login`), then trusts its verdict: [2](#0-1) [3](#0-2) 

No other before_action (`check_if_ping`, `drop_unhandled_event`) authenticates the request; `drop_unhandled_event` only checks whether a handler exists for `pull_request`, which it does, so the request reaches `create`, which parses the raw JSON and dispatches to `Shipit::Webhooks.for_event('pull_request')` handlers including `OpenedHandler`: [4](#0-3) 

`OpenedHandler#process` looks up the real `Repository` record by the attacker-supplied `repository.full_name`, and if that repository has review stacks enabled with a matching provisioning behavior (`allow_all`, or label-gated conditions the attacker can also satisfy since they control PR labels on their own PR), it provisions a `ReviewStack`: [5](#0-4) 

The stack is created directly from attacker-controlled `params.pull_request.head.ref` and queued for provisioning: [6](#0-5) 

Existing guards do not prevent this: `ExplicitParameters` schema only validates payload *shape*, not authenticity; there is no `force_github_authentication`, session, or API-client check on this unauthenticated controller; and `Repository.from_github_repo_name` (app/models/shipit/repository.rb:53-56) correctly binds to the exact repo named in the payload, but that binding is worthless once the signature check protecting the whole endpoint is void for that organization.

### Impact Explanation
For any organization configured in Shipit without a `webhook_secret`, an unauthenticated internet requester can forge arbitrary `pull_request` (and other handled) webhook events for that organization's real repositories, causing Shipit to write new records (`ReviewStack`, `PullRequest`) and enqueue provisioning/deploy workflows that were never validated as originating from GitHub. This is an authentication bypass on the primary trust boundary of the webhook endpoint, matching the Critical category "authentication bypass (forged webhook accepted)". The blast radius is scoped to organizations/repositories whose Shipit config omits `webhook_secret`; it is fully repeatable per request and does not require any secret, session, or team membership.

### Likelihood Explanation
Precondition: a Shipit-configured GitHub organization exists whose `config[:webhook_secret]` is blank/absent (an operator misconfiguration, but one the code silently accepts as "verified" rather than rejecting or requiring). Given that precondition, the attacker's cost is a single unauthenticated `POST /webhooks` with a crafted JSON body and the `X-Github-Event: pull_request` header — no signature computation needed. The additional condition that the target repository has `review_stacks_enabled` with a satisfiable `provisioning_behavior` further gates real stack creation, but is a normal/expected repository configuration for review-stack usage, not a security control.

### Recommendation
Reject webhook verification when `webhook_secret` is not configured, instead of treating a missing secret as automatically verified — e.g., have `verify_webhook_signature` return `false` (or raise a configuration error) when `webhook_secret` is blank, and/or make `webhook_secret` a mandatory config field enforced at boot for every configured organization.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` or a new test, not included per repo scope but described):
1. Configure `Shipit.github(organization: 'no-secret-org')` with a config hash lacking `webhook_secret` (and, if exercising bot amplification, with `bot_login` set).
2. Create a real `Shipit::Repository` under `owner: 'no-secret-org'` with `review_stacks_enabled: true`, `provisioning_behavior: 'allow_all'`.
3. Assert the invariant before tracing: `github_app.verify_webhook_signature(nil, forged_body) == false` is the expected secure behavior; trace shows it currently evaluates to `true`.
4. `POST /webhooks` with header `X-Github-Event: pull_request`, no/garbage `X-Hub-Signature`, and a JSON body with `action: "opened"`, `repository: { full_name: "no-secret-org/repo", owner: { login: "no-secret-org" } }`, attacker-controlled `pull_request.head.ref`, `sender.login`.
5. Assert response is `200 OK` (not `422`), and assert `Shipit::ReviewStack.find_by(environment: "pr#{number}")` now exists with `branch` equal to the attacker-supplied `head.ref` — proving an unauthenticated forged request wrote a record for a repository whose webhook never validated the request's authenticity.

      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
