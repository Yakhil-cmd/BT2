### Title
`Team.find_or_create_by!` in `MembershipHandler#find_or_create_team!` binds membership webhooks to teams by `github_id` alone, letting a second registered organization take over a privileged team - ([File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`MembershipHandler#process` resolves the target `Team` with `Team.find_or_create_by!(github_id: params.team.id)`, but the create-block that sets `team.organization = params.organization.login` only runs on the *creation* path, not when an existing row is found by primary/unique key. Because GitHub team IDs are global, sequential integers, any organization that has a legitimately-registered `webhook_secret` in Shipit can send a validly-signed `membership` webhook whose `team.id` collides with an already-existing, privileged `Team` row belonging to a different organization, and get its own user added as a member of that team.

### Finding Description
The broken binding is: `params.organization.login == team.organization` for the `Team` record being mutated. This is never checked.

Code path:
- `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-30) picks the `GitHubApp` via `Shipit.github(organization: repository_owner)`, where `repository_owner` falls back to `params.dig('organization', 'login')` (line 61). For a `membership` event with no `repository` key, this is simply the attacker-controlled `organization.login` field in the payload.
- Since `attacker-org` is a real organization configured in Shipit's multi-org `github:` secrets block (a legitimate, distinct `GithubHook::Organization`/`GitHubApp` config, as documented in docs/setup.md's "Using Multiple Github Applications" section), `Shipit.github(organization: 'attacker-org').verify_webhook_signature` succeeds using attacker-org's own genuine secret. No cross-organization check occurs here — this step only validates *that a body was signed by some registered org*, not that the payload's *content* (the team it refers to) belongs to that org.
- `Webhooks.for_event('membership')` dispatches to `Handlers::MembershipHandler` (app/models/shipit/webhooks.rb:20).
- `MembershipHandler#process` (app/models/shipit/webhooks/handlers/membership_handler.rb:22-34) calls `find_or_create_team!`:
  ```
  Team.find_or_create_by!(github_id: params.team.id) do |team|
    team.github_team = params.team
    team.organization = params.organization.login
  end
  ``` [1](#0-0) 
  `find_or_create_by!` first performs a `find_by(github_id: ...)`; if a row already exists (the privileged team originally created for the org in `Shipit.github_teams`), that row is returned as-is and the block is **never executed** — `team.organization` is left untouched at its original, correct value, but the *code that would have detected the mismatch never runs* and no comparison against `params.organization.login` is ever made anywhere in the handler.
- The handler proceeds to `User.find_or_create_by_login!(params.member.login)` (app/models/shipit/user.rb:22-28) creating/fetching the attacker's own User row, then `team.add_member(member)` (app/models/shipit/team.rb:41-43), which appends the attacker to `team.memberships` regardless of which organization's webhook triggered the call.
- `User#authorized?` (app/models/shipit/user.rb:80-82) checks `teams.where(id: Shipit.github_teams.map(&:id)).exists?`. If the pre-existing colliding `Team` row is one of the teams in `Shipit.github_teams`, this now returns `true` for the attacker, granting full authenticated access via `Authentication` concern.

None of the existing guards prevent this: `verify_signature` only validates the HMAC against the org named in the payload, not that the *referenced team* belongs to that org; the `ExplicitParameters` schema (`requires :team { requires :id, Integer ... }`) only validates types, not ownership; there is no `require_permission!`/`stacks` scoping for this global (non-stack-scoped) webhook event.

### Impact Explanation
An attacker who registers/administers any organization with its own valid `webhook_secret` in Shipit's multi-org config can forge a `membership` `added` event that adds their own GitHub login to a `Team` row that is not owned by their organization — including a team listed in `Shipit.github_teams`. This flips `User#authorized?` to `true` for the attacker's account, granting them full session-based access to every stack, deploy, rollback and task in the Shipit instance. This matches the "High — escalation into `Shipit.github_teams` authorization" impact category. It is repeatable per team-id guess/enumeration and is not scoped to a particular repository — it affects the entire multi-tenant Shipit instance.

### Likelihood Explanation
Requires: (1) Shipit configured for multiple GitHub organizations (each with its own `webhook_secret`), a documented and supported configuration; (2) the attacker controls one of those registered organizations (a low bar — Shipit operators may onboard many orgs, and the attacker only needs to be an admin of one, not the privileged one); (3) a `Team` row for the privileged org's team must already exist (created at least once via a prior legitimate webhook or `Team.find_or_create_by_handle`) with a `github_id` the attacker can predict — GitHub team IDs are sequential and globally enumerable via `GET /orgs/{org}/teams` API scraping (which the attacker could do without special privilege if the target org's team listing is discoverable, or simply by brute-forcing a plausible numeric range). Given these are realistic conditions in any multi-org Shipit deployment, the likelihood is non-trivial once the multi-org feature is used.

### Recommendation
In `MembershipHandler#find_or_create_team!`, always validate that the found (or created) team's `organization` matches `params.organization.login` before proceeding, e.g.:
```ruby
def find_or_create_team!
  team = Team.find_or_create_by!(github_id: params.team.id) do |team|
    team.github_team = params.team
    team.organization = params.organization.login
  end
  raise ArgumentError, "Team #{team.id} organization mismatch" unless team.organization.casecmp?(params.organization.login)
  team
end
```
Alternatively, scope the lookup itself: `Team.find_or_create_by!(github_id: params.team.id, organization: params.organization.login)`, ensuring a webhook can never mutate a team it doesn't own even if `github_id` collides.

module Shipit
  module Webhooks
    module Handlers
      class MembershipHandler < Handler
        params do
          requires :action, String
          requires :team do
            requires :id, Integer
            requires :name, String
            requires :slug, String
            requires :url, String
          end
          requires :organization do
            requires :login, String
          end
          requires :member do
            requires :login, String
          end
        end
        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
      end
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
