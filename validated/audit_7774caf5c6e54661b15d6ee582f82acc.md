### Title
Cross-Stack CI Status Disclosure via CCMenuController Bypassing API Client Stack Scoping - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::CCMenuController` overrides the `#stack` accessor to look up the stack directly with `Stack.from_param!(params[:stack_id])` instead of using the stack-scoped collection that every other API controller relies on. This breaks the binding "the stack a token authorises == the stack it can touch," letting any API token that only holds `read:stack` permission on **one** stack read the CI/build status of **any** stack in the installation, by supplying a different `stack_id`.

### Finding Description
`Shipit::Api::BaseController` implements a stack-scoping mechanism for tokens: if the `ApiClient` has a `stack_id` set, the token is restricted to that single stack, otherwise it can see all stacks. [1](#0-0) 

`Shipit::ApiClient` supports being scoped to a specific `stack` (`belongs_to :stack, optional: true`), and `#check_permissions!` only validates the `operation:scope` string (e.g. `read:stack`), never the specific stack instance being accessed. [2](#0-1) 

The fixture `here_come_the_walrus` demonstrates the intended design: a token scoped to a single stack with only `read:stack` permission, confirmed by the test "an api client scoped to a stack will only see that one stack" against `StacksController#index`. [3](#0-2) [4](#0-3) 

However, `CCMenuController`, which also only requires `read:stack` permission, overrides `#stack` to bypass the `stacks` scoping helper entirely: [5](#0-4) 

Compare `BaseController#stack` (`stacks.from_param!(params[:stack_id])`, respecting `current_api_client.stack_id`) with `CCMenuController#stack` (`Stack.from_param!(params[:stack_id])`, a bare class-method lookup with no scoping at all). The stack the token is authorised for (`current_api_client.stack_id`) and the stack actually touched (`params[:stack_id]` resolved against *all* stacks) diverge.

### Impact Explanation
An attacker holding a legitimately-issued, stack-scoped `read:stack` token (e.g. the "CCMenu Client" token generated per user/stack by `CCMenuUrlController`, which is designed to be embedded in external CI dashboards) can supply an arbitrary `stack_id` to `GET /api/stacks/:stack_id/ccmenu.xml` and receive the name, last build status (Success/Failure), last build label, and last build time of any stack in the Shipit installation — including private/internal repositories the token was never authorised to see. This is an unauthorized cross-stack read of stack state, matching the High-severity category "unauthenticated/unauthorized read of stack state, task streams or deploy output."

### Likelihood Explanation
Any holder of a valid stack-scoped API token (which are explicitly designed to be embedded in low-trust contexts such as CCMenu/CI-status widgets, see `CCMenuUrlController`) can trivially exploit this by changing the `stack_id` path parameter — no privilege escalation on GitHub or additional secrets are required.

### Recommendation
Change `CCMenuController#stack` to use the inherited, scope-respecting `stacks` collection instead of the unscoped `Stack.from_param!`, e.g.:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
so that stack-scoped tokens can only resolve the stack they were issued for.

### Proof of Concept
1. Provision a stack-scoped API client `T` with `permissions: ['read:stack']` and `stack: stack_A` (as in the `here_come_the_walrus` fixture).
2. As the token holder, issue `GET /api/stacks/<stack_B_owner>/<stack_B_name>/<stack_B_env>/ccmenu.xml` using Basic Auth with `T`'s `authentication_token` (or `?token=...` per `CCMenuController#authenticate_api_client`), where `stack_B` is a different stack than `stack_A`.
3. `require_permission :read, :stack` passes because `T` holds `read:stack`.
4. `CCMenuController#stack` resolves `stack_B` via `Stack.from_param!(params[:stack_id])`, ignoring that `T.stack_id == stack_A.id`.
5. The response renders `stack_B`'s CI status, build label, and last build time — data the token was never scoped to access.

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
