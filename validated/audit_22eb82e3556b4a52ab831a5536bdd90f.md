### Title
PR titles containing raw ANSI/terminal control sequences are passed unsanitized into interactive `gh pr checkout` selector prompts - ([File: pkg/cmd/pr/checkout/checkout.go])

### Summary
`promptingPRResolver.Resolve` builds selector candidate strings by embedding `pr.Title` (only passed through `text.RemoveExcessiveWhitespace`, which merely collapses whitespace via a `\s+` regex) directly into the string handed to `prompter.Select`. Since GitHub PR titles are attacker-controlled free text and `RemoveExcessiveWhitespace` performs no ANSI/control-byte stripping, an attacker's PR title can carry raw escape sequences into the victim's terminal rendering pipeline.

### Finding Description
In `promptingPRResolver.Resolve` [1](#0-0) , candidate strings are built as:
```go
candidates = append(candidates, fmt.Sprintf("%d\t%s %s [%s]",
    pr.Number,
    shared.PrStateWithDraft(&pr),
    text.RemoveExcessiveWhitespace(pr.Title),
    pr.HeadLabel(),
))
```
`text.RemoveExcessiveWhitespace` is defined as:
```go
func RemoveExcessiveWhitespace(s string) string {
    return whitespaceRE.ReplaceAllString(strings.TrimSpace(s), " ")
}
``` [2](#0-1) 
This only collapses runs of whitespace matched by `\s+`; it does not strip ESC (`\x1b`), CSI, OSC 8 hyperlink sequences, or other C0 control bytes. `pr.Title` comes directly from the GraphQL API response for PRs in the target repo and is fully attacker-controlled (an attacker opens a PR against the victim's repo with a title containing raw escape bytes). These candidate strings are then passed to `prompter.Select("Select a pull request", "", candidates)` [3](#0-2) , which under the `huh`-based prompter renders the option list directly in the terminal via `huh.NewSelect[int]().Options(...)` [4](#0-3) .

For `pr.HeadLabel()`, the value is derived from the head repo owner login and `headRefName` (a git ref name) rather than arbitrary free text; git ref names cannot contain most control characters or spaces, which limits (but the code shown here does not itself confirm complete elimination of) the injection surface for that field. The clear, unmitigated injection point is `pr.Title`.

Because no sanitization of control/escape sequences occurs anywhere between the API response and the terminal-rendering call, a malicious title such as one containing cursor-repositioning or text-overwrite escape codes (e.g., `\x1b[2K\x1b[1G`) could overwrite or visually obscure adjacent legitimate candidate lines in the interactive list, or use OSC 8 hyperlink escapes to make displayed text link to attacker-controlled targets, or bracketed-paste-like sequences to manipulate what appears to be selected.

### Impact Explanation
This is a terminal/prompt-spoofing issue: a victim who runs `gh pr checkout` interactively (`IO.CanPrompt()` true) against a repository that includes the attacker's PR among the 10 most recently listed open PRs could see a manipulated selection list. In the worst case, this could increase the chance the victim selects and checks out the attacker's PR believing it is a different, legitimate one. However, checking out the wrong PR by itself does not directly grant code execution, exfiltrate credentials, or bypass authorization — the actual "impact" is limited to influencing a subsequent voluntary, informed choice by the victim. This maps to a low-severity "output/terminal injection affecting decision-making" class rather than a direct compromise (no code execution, no credential leak, no unauthorized file write, no host-routing bypass is achieved by this path alone).

### Likelihood Explanation
Feasible and fully within an unprivileged attacker's control: opening a PR with an arbitrary title is available to any user who can open PRs against the repo (or via a fork/PR to a public repo). Preconditions are narrow but realistic: victim must run `gh pr checkout` with no arguments interactively, and the malicious PR must be among the 10 most recently listed open PRs for the repo. Repeatable and reliable, since PR titles returned by the GraphQL API are used verbatim.

### Recommendation
Strip or escape ANSI/control sequences from any attacker-controlled text (PR titles, labels, branch/head labels, etc.) before constructing terminal prompt candidates. Add a general sanitization helper (e.g., in `internal/text`) that removes/escapes C0/C1 control characters and CSI/OSC escape sequences, and apply it to `pr.Title` (and defensively to `pr.HeadLabel()`) in `promptingPRResolver.Resolve` before calling `prompter.Select`. Consider applying the same sanitization broadly wherever `RemoveExcessiveWhitespace` is currently relied upon as the sole sanitizer for user-controlled text destined for terminal display (e.g., `pkg/cmd/pr/list/list.go`, `pkg/cmd/issue/shared/display.go`, `pkg/cmd/gist/shared/shared.go`, etc.).

    malicious := "Fix bug\x1b[2K\x1b[1GEVIL PR TITLE"

    // Currently fails to strip ESC/CSI bytes, proving no sanitization occurs.

    }
}
