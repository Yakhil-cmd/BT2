### Title
Webhook signature verification org (`repository.owner.login`) is decoupled from the mutated repository (`repository.full_name`), letting a payload authenticated by one org's secret provision a `ReviewStack`/RCE on another org's repository - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) used to authenticate a webhook solely from `params.dig('repository','owner','login')`, but the `pull_request` `OpenedHandler` resolves and mutates the target `Repository`/`Stack` from the independent field `params.repository.full_name` [1](#0-0) [2](#0-1) [3](#0-2) . Because these two fields are never checked for consistency, a payload whose `owner.login` resolves to an org with no `webhook_secret` configured (or any org the attacker can authenticate against) bypasses signature verification entirely, while `full_name` can point at an arbitrary victim repository whose review-stack-enabled, allow-all stack is then auto-provisioned via `ReviewStackAdapter#find_or_create!` and runs `shipit.yml` [4](#0-3) .

### Finding Description
The invariant that should hold: `verified_org(request) == owner(resolved_repository)`, i.e., the org whose secret authenticated the webhook must equal the org that owns the repository/stack the handler mutates. This invariant is never enforced.

Trace:
1. `WebhooksController#verify_signature` computes `repository_owner` purely from `params.dig('repository', 'owner', 'login')` (or `organization.login`) and fetches `Shipit.github(organization: repository_owner)` to get that org's `webhook_secret` for HMAC verification [1](#0-0) [2](#0-1) .
2. `GitHubApp#verify_webhook_signature` short-circuits to `true` if that org's `webhook_secret` is blank: `return true unless webhook_secret` [5](#0-4) . Thus naming an org with no configured secret (or any org whose secret is empty) in `repository.owner.login` trivially satisfies signature verification for the entire raw JSON body, regardless of its contents.
3. Once verification passes, `Shipit::Webhooks.for_event('pull_request')` dispatches to `OpenedHandler#process`, which resolves the target repository from a completely different, unchecked field: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [3](#0-2) .
4. If that resolved repository's stack has `review_stacks_enabled` true and `provisioning_behavior_allow_all?`, `respond_to_pull_request_opened?` returns true and `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` provisions a new review stack from `params.pull_request.head.ref`, which will execute the repository's `shipit.yml` deploy pipeline [6](#0-5) .

No code path cross-checks that the org used to select the HMAC secret in step 1 matches the owner embedded in `full_name` used in step 3. `drop_unhandled_event` and `check_if_ping` don't touch this; the `ExplicitParameters` schema on `OpenedHandler` only requires `repository.full_name` to be a `String`, performing no ownership cross-validation [7](#0-6) .

Exploit: attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, a forged `X-Hub-Signature` (irrelevant if the chosen org has no secret), and a JSON body where `repository.owner.login` = an org configured in `Shipit.github_organizations` with no `webhook_secret`, while `repository.full_name` = `victim-org/victim-repo` (a repo with `review_stacks_enabled: true`, `allow_all`). The handler provisions a review stack and executes the victim repo's deploy pipeline, entirely unauthenticated with respect to the victim org's actual secret.

### Impact Explanation
This allows an unauthenticated attacker to make a webhook payload nominally "authenticated" by a low-value/no-secret org actually mutate an arbitrary victim repository's stacks — provisioning review stacks and triggering `shipit.yml` execution on the deploy host for a repository the attacker never authenticated against. This matches the explicitly listed Critical category: "a payload for one repository mutating another's stack ... or an unauthorized deploy." Blast radius spans every tenant/org configured in the same Shipit instance whose stacks have `review_stacks_enabled`/`allow_all`, since the attacker only needs control of (or knowledge of) one weakly-configured org entry to pivot into any other.

### Likelihood Explanation
Preconditions: (a) the Shipit deployment must have at least one GitHub organization entry in configuration with no `webhook_secret` set (or one the attacker can otherwise satisfy), which `verify_webhook_signature` treats as "always verified"; (b) the victim repository/stack must have `review_stacks_enabled` true with `allow_all` provisioning. Given those, the attack costs a single crafted HTTP POST with no GitHub account, session, token, or secret required — fully repeatable against any repository resolvable via `Repository.from_github_repo_name`. The main uncertainty is whether a concrete deployment actually has an org configured without a secret; the code itself provides no defense once that condition holds, since the org-selection and repository-resolution fields are structurally independent.

### Recommendation
Enforce that the resolved repository's owner (parsed from `full_name`) matches the org used to select the webhook secret (`repository.owner.login`/`organization.login`) before dispatching to any handler — reject the request otherwise. Additionally, do not allow `verify_webhook_signature` to silently return `true` when `webhook_secret` is blank in production; require every configured org to have a non-empty secret, or fail closed.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, hypothetical):
```ruby
test "pull_request opened from a no-secret org full_name-targets a different org's allow_all review stack" do
  # Configure org "attacker-org" with no webhook_secret (or stub Shipit.github(organization: 'attacker-org').webhook_secret => nil)
  victim_repo = shipit_repositories(:some_allow_all_review_stack_repo) # review_stacks_enabled: true, allow_all
  payload = {
    action: 'opened',
    number: 1,
    pull_request: {
      id: 1, number: 1, url: 'https://api.github.com/x', title: 't', state: 'open',
      additions: 1, deletions: 0,
      head: { sha: 'a' * 40, ref: 'feature-branch' },
      user: { login: 'attacker' }, assignees: [], labels: []
    },
    repository: { full_name: victim_repo.github_repo_name, owner: { login: 'attacker-org' } },
    sender: { login: 'attacker' }
  }.to_json

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # irrelevant, org has no secret

  assert_difference -> { victim_repo.review_stacks.count }, 1 do
    post :create, body: payload, as: :json
  end
  assert_response :ok
end
```
Assert both sides of the binding: `params.dig('repository','owner','login')` == `"attacker-org"` (verified org) while `Shipit::Repository.from_github_repo_name(params.dig('repository','full_name'))` == `victim_repo` (mutated org) — they differ, and the review stack is still created, proving the invariant is broken.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
