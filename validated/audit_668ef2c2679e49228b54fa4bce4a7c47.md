## Analysis

The report's bug class — two configuration values that must be validated together (a fee-accrual toggle and its payout-destination address), where the destination can be left invalid while accrual remains enabled — has a direct analog in `initialize_with_permission`.

### Title
Unvalidated arbitrary `creator` account in `initialize_with_permission` permanently locks accrued creator trading fees - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
`initialize_with_permission` hardcodes `enable_creator_fee = true` when initializing a pool, while the `creator` account that becomes `pool_state.pool_creator` (the sole destination for all future creator-fee collections) is an unconstrained `UncheckedAccount` with no ownership check, no signature requirement, and no check against a default/invalid public key.

### Finding Description
`InitializeWithPermission.creator` is declared as `/// CHECK: creator of pool` `pub creator: UncheckedAccount<'info>` with no constraint tying it to `payer` or requiring it to sign or be non-default. [1](#0-0) 

When the pool is created, `pool_state.initialize(...)` is called with `ctx.accounts.creator.key()` as `pool_creator` and `enable_creator_fee` hardcoded to `true` (unlike the regular `initialize` path, which passes `false`). [2](#0-1) [3](#0-2) 

`PoolState.pool_creator` is the value used to gate/target creator-fee collection: `CollectCreatorFee` requires the `creator` signer to equal `pool_state.pool_creator`, and `collect_creator_fee_permissionless` sends the accrued fees to an associated token account whose `authority` is `pool_state.pool_creator`, with no signature required from that account. [4](#0-3) [5](#0-4) [6](#0-5) 

Because `enable_creator_fee` is `true` for this pool, `update_fees` will accumulate `creator_fees_token_0`/`creator_fees_token_1` on every swap as long as `amm_config.creator_fee_rate` is non-zero (the fee is only zeroed via `adjust_creator_fee_rate` when `enable_creator_fee` is false). [7](#0-6) 

Since `creator` is never validated to be a controllable address (e.g., it can be `Pubkey::default()`, a foreign PDA, or any account with no corresponding keypair), any accrued `creator_fees_token_0/1` become permanently unspendable: `collect_creator_fee` can never be signed by that key, and `collect_creator_fee_permissionless` will only ever deposit into an ATA owned by that unowned/uncontrollable authority.

### Impact Explanation
Trading fees earmarked as "creator fees" (a portion of every swap's trade fee, per `Fees::creator_fee`/`Fees::split_creator_fee`) are permanently locked in the pool with no recovery path if the `creator` account supplied at pool creation is not a controllable key. This is a direct loss of protocol/creator funds analogous to the escrow-portion/escrow-pool issue: a fee-accrual flag (`enable_creator_fee`) is enabled without validating that its payout target (`pool_creator`) is capable of ever receiving/spending the funds. [8](#0-7) 

### Likelihood Explanation
`initialize_with_permission` is reachable by any account holding a `Permission` PDA (a permissioned pool creator, one of the explicitly in-scope actors). The attacker/careless caller fully controls the `creator` account passed into the instruction — no code path validates it against `payer`, requires its signature, or rejects the default/zero pubkey. Every subsequent swap through the pool will silently accrue unrecoverable creator fees as long as `amm_config.creator_fee_rate > 0`.

### Recommendation
Constrain `creator` in `InitializeWithPermission` to a controllable identity — e.g., require `creator` to be a `Signer`, or require `creator.key() == payer.key()`, and/or explicitly reject `Pubkey::default()`. Alternatively, only set `enable_creator_fee = true` after validating `creator` is non-default and capable of holding/signing for an associated token account.

### Proof of Concept
1. Caller obtains a `Permission` PDA for `payer` (via `create_permission_pda`).
2. Caller invokes `initialize_with_permission`, passing `creator = Pubkey::default()` (or any address with no known private key) as the `creator` account; all other accounts are valid.
3. Pool initializes successfully with `pool_state.pool_creator = Pubkey::default()` and `pool_state.enable_creator_fee = true`.
4. Users perform swaps (`swap_base_input`/`swap_base_output`); `creator_fee_rate` causes `creator_fees_token_0/1` to accumulate in `pool_state`.
5. `collect_creator_fee` can never succeed (no signer can equal `Pubkey::default()`), and `collect_creator_fee_permissionless` only creates/funds an ATA owned by `Pubkey::default()`, which no party can ever withdraw from — funds are permanently frozen.

    pub fn creator_fee(amount: u128, creator_fee_rate: u64) -> Option<u128> {
        ceil_div(

            u128::from(creator_fee_rate),
            u128::from(FEE_RATE_DENOMINATOR_VALUE),
        )
    }

    pub fn split_creator_fee(
        total_fee: u128,
        trade_fee_rate: u64,
        creator_fee_rate: u64,
    ) -> Option<u128> {
        floor_div(
            total_fee,
            u128::from(creator_fee_rate),
            u128::from(trade_fee_rate + creator_fee_rate),
        )
    }
