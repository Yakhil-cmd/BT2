### Title
Webhook signature is verified against the organization named in the payload, not the repository actually acted upon - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App config (and thus which HMAC `webhook_secret`) to validate a webhook against using `repository_owner`, a value read straight out of the unauthenticated JSON body. The event handlers, however, resolve the `Stack`/`Repository` they act on using a *different* field of the same unauthenticated body: `repository.full_name` (`Shipit::Webhooks::Handlers::Handler#repository_name`). Nothing ties these two payload fields together, so the organization whose secret is used to authenticate the request is not guaranteed to be the organization whose repository is actually synced/acted upon.

### Finding Description
`verify_signature` does:
```ruby
# app/controllers/shipit/webhooks_controller.rb:24-30
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(...)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) [2](#0-1) 

Every default handler, however, resolves the stack to operate on via a *different* payload key:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [3](#0-2) 

`PushHandler#process` uses that `stacks` scope directly to enqueue a `GithubSyncJob`: [4](#0-3) 

Crucially, `verify_webhook_signature` treats a missing `webhook_secret` as automatically valid:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [5](#0-4) 

Shipit explicitly supports hosting multiple GitHub organizations behind one installation, each with its own (optional) `webhook_secret`: [6](#0-5) [7](#0-6) 

Because `repository_owner` (used to select the signing secret) and `repository.full_name` (used to select the target repository/stack) come from two independent, attacker-controlled JSON fields in the same unauthenticated request body, an attacker can submit a forged `push` webhook where:
- `repository.owner.login` = an organization configured in this Shipit instance **without** a `webhook_secret` (or one whose secret the attacker somehow knows), so `verify_webhook_signature` short-circuits to `true`.
- `repository.full_name` = the full name of a *different, secret-protected* organization's repository that has a Stack registered in Shipit.

The signature check passes (because it validated against the “no-secret” org), yet the handler acts on the targeted repository/stack from the other org, triggering `Shipit::GithubSyncJob` (and, if `continuous_deployment` is enabled on the target stack, an eventual automatic deploy) — all without ever proving knowledge of the real webhook secret protecting that repository.

### Impact Explanation
This breaks the equality "organization that authenticated the webhook == organization whose repository/stack is written." An unprivileged external attacker who can send arbitrary HTTP requests to the public `/webhooks` endpoint (no session or token required — this is explicitly the endpoint's purpose) can spoof push/status/check_suite events for stacks belonging to an organization that does enforce webhook secrets, as long as any other configured organization in the same Shipit installation has no `webhook_secret` set. This can enqueue `GithubSyncJob` for arbitrary stacks and, combined with `continuous_deployment`, drive an unauthorized deploy — matching the Critical bar "unauthorized deploy" defined in scope.

### Likelihood Explanation
Requires: (1) the target Shipit instance is multi-org configured (documented, supported feature), and (2) at least one configured organization lacks a `webhook_secret` (also documented/allowed as "optional"). Given `webhook_secret` is explicitly optional and several shipped example configs (`config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`) show `webhook_secret: # nil` for organizations, this is a realistic and low-effort misconfiguration, not a contrived edge case. No credentials, session, or prior access are needed — only knowledge that a permissive organization exists in the deployment (discoverable by trial, since the response differs for known vs. unknown organizations via `GithubOrganizationUnknown`).

### Recommendation
Bind the signature-verification organization to the same repository identity used by handlers. Concretely:
- Derive the GitHub App/organization strictly from `repository.full_name`'s owner segment (or from a `Repository` record already resolved from `full_name`), not from `repository.owner.login`/`organization.login` independently.
- Reject webhooks where `repository.owner.login` does not match the owner segment of `repository.full_name`.
- Consider making `webhook_secret` mandatory per-organization in multi-org configurations, or fail closed (not verified) when it is unset in a multi-org context.

### Proof of Concept
1. Configure Shipit with two orgs: `OrgNoSecret` (no `webhook_secret`) and `OrgProtected` (has `webhook_secret` and an active Stack `OrgProtected/app`).
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha already known to exist on GitHub>",
  "repository": {
    "owner": { "login": "OrgNoSecret" },
    "full_name": "OrgProtected/app"
  }
}
```
No `X-Hub-Signature` needed (or any arbitrary value), because `Shipit.github(organization: "OrgNoSecret").verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-83`).
3. `verify_signature` passes, `PushHandler#process` looks up stacks via `repository.full_name` = `OrgProtected/app` and enqueues `GithubSyncJob` for that stack, even though the request never proved knowledge of `OrgProtected`'s webhook secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
