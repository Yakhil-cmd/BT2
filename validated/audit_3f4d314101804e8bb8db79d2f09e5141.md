### Title
`git commit --amend` collapses the Stop-hook review set to empty, silently skipping dangerous changes - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` in `diffstate.py` intersects `dirty_now` (git-status-derived) with `changed_since` (diff-vs-baseline-derived) to build the Stop-hook review set. A `git commit --amend` performed mid-turn makes the working tree clean (`dirty_now` empty for that file) while `_is_ancestor(head_at_capture, current_head)` returns `False` because an amend is a sibling commit, not a fast-forward descendant, so the "HEAD advanced linearly" branch that would otherwise add the committed file to `dirty_now` never fires. The intersection with an empty `dirty_now` zeroes the review set even though `changed_since` (computed via `git diff --name-only <baseline_sha>`) still correctly shows the file as changed.

### Finding Description
In `plugins/security-guidance/hooks/diffstate.py`, `capture_git_baseline` (called from `UserPromptSubmit` via `handle_user_prompt_submit` in `security_reminder_hook.py`) snapshots `baseline_sha` (via `git stash create`) and `head_at_capture` (via `_git_rev_parse_head`) at the start of a turn [1](#0-0) .

At Stop, `compute_v2_review_set` computes:
```
tracked_dirty, untracked = _git_status_porcelain(repo)
...
dirty_now = tracked_dirty | new_untracked
...
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
...
review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
``` [2](#0-1) 

`_is_ancestor` checks `merge-base --is-ancestor maybe_ancestor descendant`, i.e., whether HEAD moved forward via commit/merge [3](#0-2) . A `git commit --amend` rewrites HEAD to a **sibling** commit that shares the same parent as `head_at_capture` — `head_at_capture` is therefore not reachable from the new HEAD, so `_is_ancestor` returns `False`. As a result, the amend commit's file changes never enter `dirty_now` via that branch. Since the amend also commits the working-tree changes, `git status --porcelain` (`_git_status_porcelain`) shows nothing dirty for that file, so it doesn't enter `dirty_now` via the tracked-dirty path either. `dirty_now` for the dangerous file is therefore empty.

Meanwhile, `changed_since` is computed independently via `_git_name_only(repo, baseline_sha)`, i.e. `git diff --name-only <baseline_sha>` against the current working tree [4](#0-3) . Since the working tree content differs from the pre-turn stash baseline (the amended file's content changed), `changed_since` correctly still contains the file.

The final line `review_set = dirty_now & changed_since` intersects an empty `dirty_now` with a non-empty `changed_since`, producing an **empty review set** — the dangerous file is dropped from review entirely, even though it is genuinely new/changed content introduced during the turn. `record_touched_path`/`touched_paths` state does not independently rescue this because the review-set computation, not the touched-paths list, is what's used to select files to diff and send to the LLM reviewer (`get_git_diff` is invoked with the review-set paths).

The docstring on `compute_v2_review_set` documents an analogous "known limitation" only for interrupted Bash-only turns, not for this amend-specific empty-intersection collapse [5](#0-4) , and no explicit test/guard is present to prevent `dirty_now` from going empty while `changed_since` is non-empty for the amend case.

### Impact Explanation
This lets an attacker-influenced Claude Code turn (e.g., a repo-supplied task or a compromised sub-agent) introduce a dangerous code change, commit it, then run `git commit --amend` (a completely ordinary git operation) before the turn ends. The Stop-hook security review — which is the mechanism that catches vulnerable/malicious code changes and forces the model to address them via `exit(2)` — silently computes an empty review set for that file and skips it. This is a Security-control bypass: it silently disables the review/blocking mechanism for a specific class of ordinary git operations without any error, exception, or observable signal to the user, breaking the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths."

### Likelihood Explanation
Fully reachable with unprivileged, ordinary git commands: no admin privilege, leaked keys, or social engineering needed — just a repo-controlled `git commit --amend` sequence during a Claude Code turn that already writes/commits attacker-desired content. This is a normal developer workflow pattern (create commit, then amend it) that is not unusual or suspicious, making it easily and repeatably triggerable, including inadvertently (a legitimate agent workflow amending a fix would also silently lose review coverage).

### Recommendation
In `compute_v2_review_set`, don't require `dirty_now` and `changed_since` to be non-empty via intersection when `head_at_capture` diverged non-ancestrally from `current_head` (i.e., HEAD moved but not via a simple fast-forward, e.g., amend, rebase, or reset). Detect this divergence case explicitly (e.g., `head_at_capture != current_head and not _is_ancestor(...)`) and fall back to unioning in `_git_name_only(repo, head_at_capture)` (a full diff against the pre-turn HEAD, not just the `head_at_capture..HEAD` range) so amended/rewritten commits' changed files are captured regardless of ancestry, rather than relying solely on the ancestor-only fast-forward branch.

### Proof of Concept
Integration test plan (pytest style) against `compute_v2_review_set`:
1. Init a git repo with an initial commit containing `safe.py`.
2. Capture baseline: call `capture_git_baseline(repo)` → `baseline_sha`; record `head_at_capture = _git_rev_parse_head(repo)`.
3. Simulate the turn: write a dangerous payload into `danger.py` (e.g., `os.system(user_input)`), `git add danger.py`, `git commit -m "add danger"`.
4. Run `git commit --amend --no-edit` (no content change needed — reproduces the sibling-commit rewrite).
5. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture, {})`.
6. Assert: `danger.py` (absolute path) **is** present in the returned `review_paths` list.
   - Current behavior: assertion fails — `review_paths` is empty because `dirty_now` is empty (working tree clean post-amend) while `changed_since` contains `danger.py`, and their intersection drops it.
   - Expected/fixed behavior: `danger.py` should always appear in `review_paths` since its content is genuinely new since `baseline_sha`.

def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None

def _git_name_only(cwd, base, include_untracked=False):
    """Return the set of repo-root-relative paths that differ from `base`,
    or None if git failed (unresolvable ref, not a repo, timeout). Callers
    must distinguish None (error → don't trust as a filter) from set()
    (genuinely nothing changed). `-c core.quotePath=false -z` keeps non-ASCII
    and space-containing paths intact."""
    def _run(env):
        result = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "diff", "--name-only", "-z", base],
            cwd=cwd, capture_output=True, text=True, timeout=30,
            env=env,
        )
        if result.returncode != 0:
            debug_log(f"_git_name_only({base!r}) rc={result.returncode}: {result.stderr[:200]}")
            return None
        return {p for p in result.stdout.split("\0") if p}

    try:
        if not include_untracked:
            return _run(None)
        with _temp_index(cwd) as env:
            return _run(env)
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"_git_name_only({base!r}) error: {e}")
        return None

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
