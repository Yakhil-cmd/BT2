## Title
`Api::CCMenuController` bypasses per-token stack scoping, letting a stack-scoped API token read any stack's status - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

## Summary
Shipit lets administrators mint stack-scoped `ApiClient` tokens (`belongs_to :stack, optional: true`), which are supposed to be readable only for the one `Stack` they are bound to. `Api::BaseController#stack` enforces that binding by resolving the stack through the `stacks` relation, which is filtered by `current_api_client.stack_id`. `Api::CCMenuController`, however, overrides `#stack` to resolve directly from the unscoped `Stack` model using the attacker-supplied `stack_id` request parameter, never checking it against the token's bound `stack_id`. This is the same bug class as the MIMOProxy finding: a permission check is computed and enforced on one binding (the permission string `read:stack`, checked by `require_permission`), while the actual resource acted upon (`stack_id` param) is taken from unrelated, unchecked, attacker-controlled input — breaking the equality `token.stack_id == stack_being_read`.

## Finding Description
`Api::BaseController` implements the intended per-client scoping: [1](#0-0) 

`stacks` restricts the visible set of stacks to `current_api_client.stack_id` when the client is stack-scoped, and `stack` resolves `params[:stack_id]` only within that restricted relation — so a token bound to stack A can never look up stack B through this method.

`ApiClient` supports this scoping via `belongs_to :stack, optional: true`, and permission checks are purely a string match against the `PERMISSIONS` list, unrelated to which stack is being accessed: [2](#0-1) 

The test fixtures confirm this scoping model is actively used/expected: `here_come_the_walrus` is a client bound to `stack: shipit` with only `read:stack`, distinct from `spy` which is unscoped: [3](#0-2) 

`Api::CCMenuController`, which serves CI status/build info for CCMenu integrations, declares `require_permission :read, :stack` (a pure permission-string check via `ApiClient#check_permissions!`) but overrides `#stack` to bypass the `stacks` scoping entirely: [4](#0-3) 

Specifically:
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```
This calls `Stack.from_param!` on the entire `Stack` relation, not on `stacks` (the client-scoped relation defined in `BaseController`). The `require_permission` before_action only verifies that the token's `permissions` array contains `"read:stack"` — it never checks that `stack_id` in the request matches the token's bound `stack_id`. As a result, any token carrying `read:stack` (including a token that an admin deliberately scoped to a single, low-sensitivity stack via `ApiClient.stack`) can be used to fetch `show` for *any* stack ID by simply changing the `stack_id` URL segment, since `stack` never consults `current_api_client.stack_id`.

This mirrors the MIMOProxy root cause exactly: the authorization check (`check_permissions!`/`require_permission`) and the actual resource touched (`stack` via `Stack.from_param!`) are computed from two different, unlinked sources — the permission string is checked, but the binding between "token's authorized stack" and "stack acted upon" is never enforced in this controller, even though the sibling `BaseController#stack` method demonstrates that binding is the intended design elsewhere in the same API namespace.

## Impact Explanation
This falls under the listed High severity category: "escalation into `Shipit.github_teams` authorization" is not directly hit, but "unauthenticated read of stack state, task streams or deploy output" is a listed High-severity impact, and this is exactly a scoped, low-privilege API credential (issued for a single stack) achieving unauthorized read of a different stack's deploy/build status (`stack.deploys_and_rollbacks.last`) that the token was never meant to see. It breaks the binding "a stack a token authorises versus a stack it touches" called out explicitly in the rules.

## Likelihood Explanation
Any holder of a legitimately-scoped `read:stack` API token (e.g., a CI/CCMenu integration purposely restricted to one project) can trivially exploit this by changing the `stack_id` in the URL/path of the CCMenu endpoint — no additional secrets, sessions, or privileged access needed beyond the token they already legitimately hold for their own stack. This is a straightforward parameter substitution, requiring no race conditions or complex preconditions.

## Recommendation
In `app/controllers/shipit/api/ccmenu_controller.rb`, change `#stack` to resolve through the scoped `stacks` relation exactly as `BaseController` does:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
This ensures a stack-scoped `ApiClient` cannot read state for any stack other than the one it was explicitly bound to.

## Proof of Concept
1. As an admin, create two stacks: `stack_a` (sensitive) and `stack_b`.
2. Create an `ApiClient` scoped to `stack_b` only, with permission `read:stack` (mirrors fixture `here_come_the_walrus`, bound via `stack: stack_b`).
3. Using that client's token, call:
```
GET /api/stacks/stack_a_owner/stack_a_repo/stack_a_env/ccmenu.xml?token=<stack_b_scoped_token>
```
(route resolves to `Api::CCMenuController#show`, authenticated via `authenticate_api_client` using `params[:token]`).
4. Because `Api::CCMenuController#stack` calls `Stack.from_param!(params[:stack_id])` directly instead of `stacks.from_param!(...)`, the request succeeds and returns `stack_a`'s CCMenu status/build data — even though the token is only authorized (bound) for `stack_b`. [5](#0-4) [1](#0-0)

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
