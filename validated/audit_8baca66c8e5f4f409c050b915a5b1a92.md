This confirms multi-tenant GitHub App support: `Shipit.github_organizations` returns multiple orgs from `secrets.github.keys`, each with its own independent `webhook_secret` via `github_app_config(organization)` [1](#0-0) . This is the exact analog to the WooFi bug class: a value is *acted upon* that was never covered by the check that authenticated it.

### Title
Webhook signature verified against attacker's own organization secret while the payload's `repository.full_name` targets a victim's stacks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App / webhook secret to validate the HMAC signature against using `repository_owner`, derived from `params.dig('repository','owner','login')` (falling back to `organization.login`) [2](#0-1) [3](#0-2) . That signature check only proves the request was signed with **that organization's** `webhook_secret`, obtained via `Shipit.github(organization: repository_owner)` → `github_app_config(organization)` [1](#0-0) .

However, the actual side effects executed afterward are driven by `Handler#repository_name`, which independently reads `payload.dig('repository', 'full_name')` and resolves stacks via `Repository.from_github_repo_name(repository_name)` [4](#0-3) [5](#0-4) . Nothing enforces that `repository.owner.login` (used to pick the verifying secret) matches the owner segment inside `repository.full_name` (used to pick the target stacks/repository). In a multi-organization Shipit deployment (`Shipit.github_organizations` supports several orgs, each with distinct `app_id`/`installation_id`/`webhook_secret`) [6](#0-5) , an organization admin who legitimately controls their own GitHub App/webhook secret for org "attacker-org" can sign a payload with `repository.owner.login = "attacker-org"` (so it passes `verify_signature` against their own known secret) while setting `repository.full_name = "victim-org/victim-repo"`. `PushHandler` (and other handlers) will then act on `victim-org/victim-repo`'s stacks — e.g. `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(...) }` [7](#0-6)  — even though the signature never covered that repository at all.

### Finding Description
This is the "organization that authenticated versus the repository that is written" binding named in scope. Before/after the PR that introduced multi-org support (`github_app_config(organization)` in `lib/shipit.rb`), the single-tenant case (`github_default_organization.nil?`) used one global secret, so this split didn't matter. Once multi-tenant configuration is supported, `WebhooksController#verify_signature` binds the signature check to `repository_owner` (from the payload) rather than to the repository the handler will actually mutate (`repository.full_name`). The two fields are never cross-validated, so the equality "organization whose secret verified the signature == owner of the repository acted upon" can be broken by any party that legitimately controls a webhook secret for *any one* configured organization.

### Impact Explanation
An attacker who is a legitimate GitHub App installer/admin for one configured organization in a multi-org Shipit deployment can forge webhook deliveries that are accepted as authentic for a different organization's repositories, triggering `sync_github`, membership/team writes, check-run refreshes, and pull-request/merge-queue state changes cross-repository/cross-organization without ever possessing that victim organization's webhook secret. This matches the "cross-repository writes" Critical impact category.

### Likelihood Explanation
Requires a Shipit instance configured with more than one GitHub organization/app (multi-tenant `secrets.github` config), and requires the attacker to already control a valid webhook secret for at least one configured organization (i.e., be a legitimate admin of their own org's GitHub App integration) — this is not the general "unprivileged internet attacker" case, but a cross-tenant confused-deputy attack. Whether this is exploitable depends on the deployment actually hosting multiple untrusted organizations sharing one Shipit instance, which I could not fully verify from static code alone since I don't have access to a running/multi-tenant configuration to test.

### Recommendation
In `WebhooksController#verify_signature`/`Handler`, after verifying the signature, ensure the organization used to select the verifying secret matches the owner segment of `payload.dig('repository','full_name')` (and of `organization.login`, when present) before dispatching to any handler; reject the webhook otherwise.

### Proof of Concept
1. Configure Shipit with two organizations, `attacker-org` and `victim-org`, each with its own GitHub App and `webhook_secret` (via `secrets.github`).
2. As the admin of `attacker-org`'s GitHub App, craft a `push` payload: `{"repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"}, "ref": "refs/heads/main", "after": "<sha>"}`.
3. Sign it with `attacker-org`'s known `webhook_secret` and set `X-Hub-Signature` accordingly.
4. `WebhooksController#verify_signature` calls `Shipit.github(organization: "attacker-org")` and verification succeeds [2](#0-1) .
5. `PushHandler` resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `sync_github` on its stacks — mutating victim-org state despite the signature never having been produced by victim-org's secret [7](#0-6) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
