### Title
RAY value overflow during interest accrual permanently freezes an oversized market - (File: contracts/pool/src/interest.rs)

### Summary
An unprivileged user can place a sufficiently large market at sustained high utilization until the next interest-accrual calculation overflows `i128` while converting scaled debt to its underlying RAY value. Because every subsequent market operation loads and synchronizes the market before mutating it, `update_indexes`, `repay`, `withdraw`, and liquidation paths all revert with `MathOverflow`, permanently freezing the market absent a contract upgrade. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`global_sync` divides elapsed time into bounded chunks and calls `accrue_step`, which computes utilization from the scaled borrow and supply balances. [4](#0-3) [5](#0-4) 

`Cache::calculate_utilization` converts those scaled balances through `scaled_to_original`; this multiplication can exceed the `i128` domain before the configured borrow-index ceiling is reached. [6](#0-5) [7](#0-6) 

The repository's regression test demonstrates the reachable sequence: an 18-decimal market holding one billion whole tokens is borrowed to 98% utilization, yearly `update_indexes` calls eventually panic with `MATH_OVERFLOW`, and later repayment and withdrawal attempts panic during their mandatory synchronization. [8](#0-7) 

### Impact Explanation
Once the overflow condition is reached, no operation touching the affected market can progress because `synced_market` runs `global_sync` before the requested mutation. [9](#0-8) 

This permanently freezes supplied and borrowed funds in that market: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot unwind unsafe debt, and bad-debt cleanup or recapitalization paths that synchronize the market are also blocked. [10](#0-9) [11](#0-10) [12](#0-11) 

### Likelihood Explanation
The attack requires a listed market whose configured cap, token supply, and collateral constraints admit approximately one billion whole 18-decimal tokens, followed by sustained borrowing near 98% utilization until the accrued RAY value crosses `i128::MAX`. [13](#0-12) [14](#0-13) 

The capital and time requirements make this Medium rather than Critical or High, but neither the borrow-index ceiling nor the admitted cap bound prevents the condition: valid caps can still permit a book whose future accrued value overflows, and the test shows the index remains below `MAX_BORROW_INDEX_RAY` when accrual first fails. [7](#0-6) [15](#0-14) 

### Recommendation
Make accrual saturation explicit before evaluating `scaled * index` in the `i128` domain. `accrue_step` should clamp the indexes at `MAX_BORROW_INDEX_RAY` or the maximum index representable for current scaled totals rather than allowing `scaled_to_original` to panic, while preserving accurate accounting below that bound. [5](#0-4) [2](#0-1) 

Governance-facing cap validation should also reject market sizes for which a plausible index path can exceed the RAY-value domain before the index ceiling, and index saturation should emit an observable event rather than silently stopping borrower interest. [7](#0-6)

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
```
