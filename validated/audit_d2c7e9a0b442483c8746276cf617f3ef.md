### Title
`recapitalize` refunds tokens it never received — unfunded payer drains pool custody (File: `contracts/pool/tests/flows.rs`)

### Summary
The kernel report's bug class — continuing a subsequent process after a failed sub-step, operating on stale/invalidated state — maps onto the pool's `recapitalize` path. `recapitalize(payer, hub_asset, amount)` is documented as "Covers a pool backing shortfall using measured receipts from `payer`. Refunds excess" (`contracts/controller/src/lib.rs:390-394`). The regression test `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` proves that when the payer's funding leg delivers nothing, the settlement still proceeds and pays out a refund equal to the offered amount, draining the pool's real token custody while the cash book keeps claiming the funds are there.

### Finding Description
The test performs a measured receipt that returns zero and shows the settlement continues anyway:

```rust
// contracts/pool/tests/flows.rs:3430-3439
// Drain every token via an unfunded refund.
let custody = token.balance(&t.pool);
t.client().recapitalize(&hub(&t.asset), &payer, &custody);
assert_eq!(token.balance(&t.pool), 0, "custody is gone");

let book = t.state_snapshot().cash;
assert!(
    book >= deposit,
    "the book still claims more than the supplier's deposit: {book}"
);
```

`payer` is a freshly generated address with no tokens; the pull leg transfers nothing, yet the refund leg still sends `custody` tokens out of the pool. The `cash` field in `PoolStateRaw` (committed by `Cache::commit`, `contracts/pool/src/cache/mod.rs:74-86`) is not decremented, so `require_liquidation_buffer` and `require_backed_market` (`contracts/pool/src/guards.rs:39-58`) keep reading the overstated book. Subsequent supplier exits pass the pool's own solvency and liquidity guards and only fail inside the SAC transfer with `BalanceError = 10` — verified by the test's assertions that neither `InsufficientLiquidity` nor `PoolInsolvent` fires.

This is the same structural defect as CVE-2025-38227: an initialization/funding step fails (zero tokens received) and the following process proceeds against state that no longer reflects reality — here, paying out against a cash book that was never funded.

### Impact Explanation
- Theft of user funds: a permissionless caller can call `controller.recapitalize` (or the pool directly) with `payer` = attacker and `amount` = pool token balance, and receive the pool's entire custody while contributing nothing. No supplied shares are minted to the attacker; the refund is a straight token transfer out.
- Even if the refund were somehow bounded, the residual state is permanent freezing of funds: the book overstates custody, so every subsequent `withdraw` for real suppliers reverts inside the token transfer rather than at a pool guard.

### Likelihood Explanation
`recapitalize` is permissionless and requires only `payer.require_auth` — the attacker is the payer. It needs no privileged role, no oracle manipulation, no flash loan, and no prior position. The only precondition is a pool market with token custody, i.e., normal operation. A single transaction empties a market.

### Recommendation
- In the recapitalize settlement, compute the refund strictly from measured receipts: `refund = received - applied`, where `received` is the balance-delta of the pull (the codebase already uses `transfer_amount_measured` elsewhere, e.g. `apply.rs:58`). Never pay out more than was actually received.
- After applying, reconcile the `cash` book against actual custody, or derive `cash` from `received` alone so an unfunded call leaves both custody and the book unchanged.
- Keep and extend the regression test to assert `token.balance(pool)` and `state.cash` both remain unchanged when `received == 0`.

### Proof of Concept

```rust
// Pattern demonstrated by test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody
// contracts/pool/tests/flows.rs:3407-3482
let payer = Address::generate(&env);          // attacker, zero balance
let custody = token.balance(&pool);           // all tokens in a market
client.recapitalize(&hub(&asset), &payer, &custody);
// post-state: token.balance(&pool) == 0; state.cash still >= custody
// supplier withdraw now reverts inside the SAC transfer (BalanceError 10)
```
