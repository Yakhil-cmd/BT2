### Title
Webhook signature check binds the wrong organization to the acted-upon repository, allowing cross-repository sync/writes - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate an incoming payload against by reading `repository.owner.login` (falling back to `organization.login`) from the *unauthenticated* JSON body, while the event handlers (e.g. `Shipit::Webhooks::Handlers::Handler#repository_name`, used by `PushHandler`) resolve which `Stack`/`Repository` to act on from a *different* field in the same body: `repository.full_name`. Nothing ties these two fields together, so the field that is covered by the HMAC check (`repository.owner.login`) is not the field that is actually acted upon (`repository.full_name`).

### Finding Description
`verify_signature` does:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

The HMAC is verified over the raw request body using the secret configured for the organization named in `repository.owner.login`. Since HMAC verification only proves the payload was signed by whoever holds that organization's `webhook_secret`, it proves nothing about any other field inside that same signed body — the signature covers the *bytes*, not a specific semantic binding between `repository.owner.login` and `repository.full_name`.

Once the signature passes, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches to handlers such as `PushHandler`, which resolve the target repository/stacks via:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [2](#0-1) 

and then:
```ruby
def process
  stacks
    .not_archived
    .where(branch:)
    .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [3](#0-2) 

Because `repository.owner.login` (checked by the signature-selection logic) and `repository.full_name` (used to pick the `Stack` to sync/act on) are two independent, attacker-controlled fields inside the same JSON body, an attacker who legitimately controls one organization's webhook secret (e.g., their own org, onboarded into a multi-tenant Shipit instance) can craft a payload where `repository.owner.login` = their own org (so the signature check picks their own, correctly-known secret) but `repository.full_name` = `"other-org/other-repo"` (a repository belonging to a different organization/tenant also connected to the same Shipit instance). The signature verification succeeds using the attacker's own secret, yet the handler acts on the victim organization's repository/stack. This is exactly the "organization that authenticated versus the repository that is written" binding break described in the rules — it mirrors the reported bug class where a check performed on one field (`pool.amount` / here, `repository.owner.login`) is disconnected from the field the logic actually depends on (funds in `shared_escrow` / here, `repository.full_name`).

### Impact Explanation
This crosses the "cross-repository writes" / "unauthorized deploy" bar. The `push` handler triggers `Stack#sync_github`, which enqueues `GithubSyncJob`, which uses the *stack's own* GitHub credentials (`stack.github_api`) to fetch commits and can enqueue `CacheDeploySpecJob`. More importantly, this same `repository.full_name`-vs-`owner.login` disconnect exists for every handler using `Handler#repository_name` (`PullRequest::OpenedHandler`, `ReopenedHandler`, `EditedHandler`, `LabeledHandler`, `ClosedHandler`, etc.), letting an attacker who controls one tenant's webhook secret forge push/pull_request events that are attributed to a different tenant's repository, causing Shipit to re-sync commits, create/unarchive review stacks, or otherwise mutate state for a stack the attacker does not control — without ever needing that victim organization's webhook secret, GitHub access token, or Shipit session.

### Likelihood Explanation
Exploitability depends on the deployment being multi-tenant (multiple organizations/GitHub Apps configured via `Shipit.github(organization:)`, each with its own `webhook_secret`), which is an explicitly supported configuration in this engine (`Shipit.github` is looked up per-organization and raises `Shipit::GithubOrganizationUnknown` for unrecognized orgs, implying multiple known orgs are expected). An attacker onboarding their own organization/repository into such a shared Shipit instance already knows their own webhook secret and can send arbitrary raw POST bodies to `/webhooks`, satisfying the "unprivileged attacker" bar (no Shipit session, API token, or victim's credentials required).

### Recommendation
Bind the field used for signature-secret selection to the same field used for repository resolution: derive both from `repository.full_name` (parsing the owner segment) rather than trusting `repository.owner.login`/`organization.login` independently, or explicitly verify that `repository.owner.login` matches the owner segment of `repository.full_name` before dispatching to handlers. Reject the webhook if they diverge.

### Proof of Concept
1. Attacker's organization `attacker-org` is configured in the multi-tenant Shipit instance with webhook secret `S_attacker` (known to the attacker).
2. Attacker crafts a `push` event JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" }
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC(S_attacker, body)` and POSTs to `/webhooks` with header `X-Github-Event: push`.
4. `verify_signature` resolves `repository_owner` → `"attacker-org"`, fetches `Shipit.github(organization: "attacker-org")`, and the HMAC check passes (attacker used their own valid secret).
5. `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, whose `stacks` method resolves via `repository_name` = `"victim-org/victim-repo"`, matching and syncing the victim's `Stack` — despite the request never being signed by `victim-org`'s webhook secret. [4](#0-3) [5](#0-4) [6](#0-5)

# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
