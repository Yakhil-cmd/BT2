# [H-09 Analog] Unvalidated Oracle Data Feed Values Used Directly in AA Logic Without Bounds or Sanity Checks - (File: `data_feeds.js`, `formula/evaluation.js`)

### Summary
Autonomous Agents (AAs) in ocore retrieve external price/data values via the `data_feed[[...]]` and `in_data_feed[[...]]` oscript primitives, which read whatever value an oracle address last posted to the DAG and return it to the AA formula engine with no plausibility, bounds, or outlier checking — directly analogous to `PriceOracle.getLatestPrice()` in the referenced report, which passes through Chainlink prices unconditionally as long as they are non-zero.

### Finding Description
The `data_feed` formula operator resolves to `dataFeeds.readDataFeedValue()`, which walks unstable/stable units authored by the configured oracle address(es) and returns the most recent matching `feed_value` for the given `feed_name`, subject only to structural constraints (address validity, MCI range, `ifseveral` disambiguation) — never a value-range or deviation check: [1](#0-0) 

The evaluator (`formula/evaluation.js`) takes this raw `objResult.value` and returns it directly into the running AA formula as a Decimal, again without any sanity check on the magnitude or direction of the value relative to prior values: [2](#0-1) 

Likewise, `in_data_feed`/`dataFeedExists` (used for oscript `definition.js` address conditions such as `in data feed`) evaluates a relational comparison (`>`, `<`, `=`, etc.) against whatever the oracle posted, with the same absence of outlier filtering: [3](#0-2) [4](#0-3) 

The AA test-suite itself demonstrates the intended real-world usage pattern: reading an exchange-rate feed (`GBYTE_USD_MA_2019_04_30`) directly to compute a payout amount, with only a "blackswan" fallback based on a *second* oracle-posted flag (`GBYTE_USD_MA < 25`) — itself just another unvalidated feed read, not an independent sanity bound: [5](#0-4) 

There is no mechanism anywhere in `data_feeds.js`, `formula/evaluation.js`, or `formula/validation.js` that cross-checks a data feed value against a second independent source, a moving-average/historical bound, or a maximum-deviation threshold before the value is consumed by AA logic. `formula/validation.js`'s `validateDataFeedExists()` only validates parameter *shape* (valid address, non-empty feed name, MCI format), not the *substance* of feed values: [6](#0-5) 

### Impact Explanation
Any AA whose bytecode uses `data_feed[[...]]` (or `in_data_feed`/`in data feed` for address definitions) to price assets, trigger payouts, or gate spending conditions trusts the oracle address's most recently posted value unconditionally. If the oracle key is compromised, the oracle software malfunctions, or the oracle simply posts a single malformed/extreme value (e.g., due to a bug, a manipulated upstream price source, or a fat-fingered post), any AA relying on that feed for financial computations (exchange-rate based payouts, collateral valuation, liquidation thresholds, etc.) will use that value as-is. This can lead to attackers draining AA funds (buying underpriced assets or triggering favorable payouts) or the AA's funds becoming frozen/miscalculated, i.e., concrete AA fund loss.

### Likelihood Explanation
Since this is a language/engine-level primitive rather than a specific AA bug, exploitability depends on how a given deployed AA uses `data_feed`. However, because ocore ships and tests exactly this pattern (single-oracle exchange-rate reads driving payout math, as in the `ojson.test.js` example), and because the platform provides no primitive for bounding/cross-checking feed values, any AA author who does not manually implement bounds-checking (e.g., comparing against a second oracle or a moving average with a deviation cap) is exposed. This mirrors the disputed-but-left-open judgment in the original report: "fairly reliable != 100% reliable" — a single bad post from one oracle address is sufficient to move AA-controlled funds.

### Recommendation
- Provide (or strongly document/encourage) an oscript-level pattern/helper for cross-checking two independent oracle feeds and rejecting values that diverge beyond a configurable bound, similar to the report's Chainlink/Uniswap TWAP cross-check recommendation.
- Consider adding an optional "max staleness" / "max deviation from N-th previous value" parameter to `data_feed[[...]]` so AA authors can opt into bounding without hand-rolling additional oscript logic.
- At minimum, update ocore documentation/AA best-practice guidance to explicitly warn that `data_feed` values are unauthenticated beyond the poster's address and are not validated for plausibility by the engine — the responsibility for outlier filtering rests entirely on AA bytecode.

### Proof of Concept
1. An AA is deployed with logic such as the exchange-rate AA in `test/ojson.test.js`: [5](#0-4) 

using `$exchange_rate = data_feed[[oracles='ORACLE_ADDR', feed_name='GBYTE_USD_MA_2019_04_30']];` to compute `$bytes` to pay out per unit of asset received.

2. The oracle address posts a single malformed `data_feed` message (compromised key, software bug, or bad upstream price) with an extreme `GBYTE_USD_MA_2019_04_30` value.
3. `readDataFeedValue()` in `data_feeds.js` (lines 205-240) returns this value unconditionally as the "last" feed value for the address/feed_name pair — there is no check comparing it to previous posts or any external reference.
4. The AA's formula evaluation (`formula/evaluation.js` lines 644-663) consumes the value directly into `$exchange_rate`, and the resulting `$bytes` payout is computed and sent from AA balance to any trigger sender who transacts against the (now-manipulated) exchange rate, draining AA funds.

function validateDataFeedExists(params) {
	var complexity = 1;
	if (!params.oracles || !params.feed_name || !params.feed_value)
		return {error: 'no oracles or feed name or feed value', complexity};
	for (var name in params) {
		var operator = params[name].operator;
		var value = params[name].value;
		if (Decimal.isDecimal(value)){
			if (!isFiniteDecimal(value))
				return {error: 'not finite', complexity};
			value = toDoubleRange(value).toString();
		}
		if (operator === '==') return {error: 'op ==', complexity};
		if (['oracles', 'feed_name', 'min_mci', 'feed_value'].indexOf(name) === -1)
			return {error: 'unknown param: ' + name, complexity};
		if ((name === 'oracles' || name === 'feed_name' || name === 'min_mci') && operator !== '=')
			return {error: 'not =', complexity};
		if (typeof value !== 'string')
			continue;
		switch (name) {
			case 'oracles':
				if (value.trim() === '') return {error: 'empty oracles', complexity};
				var addresses = value.split(':');
				if (addresses.length === 0) return {error: 'empty oracles list', complexity};
			//	complexity += addresses.length;
				if (!addresses.every(ValidationUtils.isValidAddress)) return {error: 'not valid oracle address', complexity};
				break;

			case 'feed_name':
				if (value.trim() === '') return {error: 'empty feed name', complexity};
				break;

			case 'min_mci':
				if (!(/^\d+$/.test(value) && ValidationUtils.isNonnegativeInteger(parseInt(value))))
					return {error: 'bad min_mci', complexity};
				break;

			case 'feed_value':
				break;
			default:
				throw Error("unrecognized name after checking: "+name);
		}
	}
	return {error: false, complexity};
