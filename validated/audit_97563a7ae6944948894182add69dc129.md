### Title
Unprotected/front-runnable `InitializeNonceAccount` allows attacker to seize nonce authority and drain funds - (File: programs/system/src/system_instruction.rs)

### Summary
`SystemInstruction::InitializeNonceAccount` sets a nonce account's `authority` field to an arbitrary pubkey taken directly from instruction data, with no requirement that the nonce account itself, its owner/creator, or the new authority be a transaction signer. This mirrors the reported `UXDController.initialize()` pattern: an unprotected "become owner" call that anyone can submit for an uninitialized account, which an attacker can front-run to seize privileged control.

### Finding Description
`system_processor.rs`'s handler for `SystemInstruction::InitializeNonceAccount` only validates account count, the `RecentBlockhashes` and `Rent` sysvars, then calls `initialize_nonce_account`: [1](#0-0) . That function only checks the account is writable and currently `State::Uninitialized` before unconditionally storing the caller-supplied `nonce_authority` as the account's `authority`: [2](#0-1) .

Nonce accounts are commonly created via `system_instruction::create_nonce_account`, which normally bundles `CreateAccount` + `InitializeNonceAccount` atomically in one signed transaction (`cli/src/nonce.rs`). However, the protocol does not enforce that these two steps happen atomically — an account can exist in system-program-owned, zeroed (`Uninitialized`) state after `CreateAccount` alone (e.g. pre-funded accounts, split creation/initialization flows, or offline-signing workflows where `InitializeNonceAccount` is submitted as a separate transaction later). During that window, the `InitializeNonceAccount` instruction can be submitted by *anyone* targeting that account address, since neither the account nor the specified `nonce_authority` need to sign. An attacker monitoring the mempool for such a pending initialize transaction can front-run it with their own transaction, supplying their own pubkey as `nonce_authority`.

This is directly comparable to `advance_nonce_account` and `withdraw_nonce_account`, which do correctly require `signers.contains(&data.authority)` once the state is initialized [3](#0-2) [4](#0-3)  — but `initialize_nonce_account` has no equivalent authority-establishment check, since by construction there is no pre-existing authority to check against, and no substitute check (e.g., requiring the account itself to sign) is enforced instead.

### Impact Explanation
If the attacker's front-run `InitializeNonceAccount` succeeds first, the account transitions to `State::Initialized` with the attacker as `authority`. The legitimate initializer's subsequent transaction fails with `InstructionError::InvalidAccountData` ("Initialize nonce account: Account ... state is invalid"). The attacker, now the nonce authority, can call `WithdrawNonceAccount` to drain all lamports funded into the account (down to rent-exemption or fully, depending on nonce advancement state) [5](#0-4) , resulting in concrete unsigned fund movement to the attacker. The attacker can also use `AdvanceNonceAccount` to manipulate the durable nonce, disrupting the victim's intended durable-transaction usage.

### Likelihood Explanation
Requires that a user create a nonce account and submit `InitializeNonceAccount` as a separate, later transaction (rather than atomically bundled with `CreateAccount` in the same transaction, which is the common CLI default but not enforced by the runtime). This is a realistic pattern for offline/multisig/durable-nonce setup flows, and the attacker only needs to observe the pending transaction in the mempool and win the race with a higher fee/priority.

### Recommendation
Require an explicit authorization signal for `InitializeNonceAccount`, e.g., require the nonce account itself (or a designated creator/authority) to be a signer of the initialize instruction, similar to how `Allocate`/`Assign` require the target address to sign (`Address::is_signer` check in `allocate`/`assign`). Alternatively, document and/or enforce that `CreateAccount` and `InitializeNonceAccount` must be atomic within the same transaction so no window of unauthenticated initialization exists.

### Proof of Concept
1. Victim submits Transaction A: `system_instruction::create_account(payer, nonce_pubkey, lamports, NonceState::size(), &system_program::id())` only (no bundled initialize), funding `nonce_pubkey` to rent-exemption. This succeeds, leaving `nonce_pubkey` as an `Uninitialized` `Versions` account owned by the system program.
2. Victim prepares Transaction B: `system_instruction::initialize_nonce_account(&nonce_pubkey, &victim_authority)` and broadcasts it.
3. Attacker observes Transaction B in the mempool, and before it lands, submits Transaction C with higher priority fee containing `SystemInstruction::InitializeNonceAccount(attacker_pubkey)` targeting the same `nonce_pubkey` account — no signature from `nonce_pubkey` or `attacker_pubkey` is required for this instruction to be accepted per `initialize_nonce_account`'s checks (writable + `Uninitialized` only).
4. Transaction C lands first, setting `authority = attacker_pubkey`. Transaction B subsequently fails with `InstructionError::InvalidAccountData` (already initialized).
5. Attacker submits `SystemInstruction::WithdrawNonceAccount(all_lamports)` signed only by `attacker_pubkey` as `nonce_authority`, which passes the `check_signer(&data.authority)` check in `withdraw_nonce_account`, transferring the victim's funded lamports to an account of the attacker's choosing.

pub(crate) fn withdraw_nonce_account(
    from_account_index: IndexOfAccount,
    lamports: u64,
    to_account_index: IndexOfAccount,
    rent: &Rent,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
    instruction_context: &InstructionContext,
) -> Result<(), InstructionError> {
    let mut from = instruction_context.try_borrow_instruction_account(from_account_index)?;
    if !from.is_writable() {
        ic_msg!(
            invoke_context,
            "Withdraw nonce account: Account {} must be writeable",
            from.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    let check_signer = |signer: &Pubkey| {
        if !signers.contains(signer) {
            ic_msg!(
                invoke_context,
                "Withdraw nonce account: Account {} must sign",
                signer
            );
            return Err(InstructionError::MissingRequiredSignature);
        }
        Ok(())
    };

    let state: Versions = from.get_state()?;
    match state.state() {
        State::Uninitialized => {
            if lamports > from.get_lamports() {
                ic_msg!(
                    invoke_context,
                    "Withdraw nonce account: insufficient lamports {}, need {}",
                    from.get_lamports(),
                    lamports,
                );
                return Err(InstructionError::InsufficientFunds);
            }
            check_signer(from.get_key())?;
        }
        State::Initialized(data) => {
            if lamports == from.get_lamports() {
                let durable_nonce =
                    DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
                if data.durable_nonce == durable_nonce {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: nonce can only advance once per slot"
                    );
                    return Err(SystemError::NonceBlockhashNotExpired.into());
                }
                check_signer(&data.authority)?;
                from.set_state(&Versions::new(State::Uninitialized))?;
            } else {
                let min_balance = rent.minimum_balance(from.get_data().len());
                let amount = checked_add(lamports, min_balance)?;
                if amount > from.get_lamports() {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: insufficient lamports {}, need {}",
                        from.get_lamports(),
                        amount,
                    );
                    return Err(InstructionError::InsufficientFunds);
                }
                check_signer(&data.authority)?;
            }
        }
    };

    from.checked_sub_lamports(lamports)?;
    drop(from);
    let mut to = instruction_context.try_borrow_instruction_account(to_account_index)?;
    to.checked_add_lamports(lamports)?;

    Ok(())
}

pub(crate) fn initialize_nonce_account(
    account: &mut BorrowedInstructionAccount,
    nonce_authority: &Pubkey,
    rent: &Rent,
    invoke_context: &InvokeContext,
) -> Result<(), InstructionError> {
    if !account.is_writable() {
        ic_msg!(
            invoke_context,
            "Initialize nonce account: Account {} must be writeable",
            account.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    match account.get_state::<Versions>()?.state() {
        State::Uninitialized => {
            let min_balance = rent.minimum_balance(account.get_data().len());
            if account.get_lamports() < min_balance {
                ic_msg!(
                    invoke_context,
                    "Initialize nonce account: insufficient lamports {}, need {}",
                    account.get_lamports(),
                    min_balance
                );
                return Err(InstructionError::InsufficientFunds);
            }
            let durable_nonce =
                DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
            let data = nonce::state::Data::new(
                *nonce_authority,
                durable_nonce,
                invoke_context
                    .environment_config
                    .blockhash_lamports_per_signature,
            );
            let state = State::Initialized(data);
            account.set_state(&Versions::new(state))
        }
        State::Initialized(_) => {
            ic_msg!(
                invoke_context,
                "Initialize nonce account: Account {} state is invalid",
                account.get_key()
            );
            Err(InstructionError::InvalidAccountData)
        }
    }
}
