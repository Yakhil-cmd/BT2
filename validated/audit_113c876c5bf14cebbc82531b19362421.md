### Title
Route payload names arbitrary venue contract that escapes caller auth scope to drain wallet tokens - (File: contracts/swap-aggregator/src/venues/mod.rs)

### Summary
The pnpm bug class is a caller-supplied component (`directories.bin`) concatenated into a path without a containment check, letting it escape the intended root and act on arbitrary filesystem locations. The on-chain analog exists: each `SwapHop` in the router's `swap_xdr` payload carries a caller-supplied `pool` address, and `dispatch_hop` invokes whatever contract the payload names with no venue allowlist. A malicious "pool" contract invoked below the caller's `require_auth` can call `token.transfer(victim, attacker, amount)` on any token the victim holds; the host records that transfer as a child of the caller's authorization entry, and it executes when the caller signs the simulated auth tree. The theft is bounded by the victim's whole wallet, not by the routed amount, the payload `min_out`, or the controller's final risk gates.

### Finding Description
`execute_strategy(sender, total_in, swap_xdr)` decodes a `StrategyPayload` whose hops name arbitrary `pool` addresses (contracts/swap-aggregator/src/lib.rs:250). `dispatch_hop` matches only on `hop.venue` and calls `soroswap::swap(&ctx)` / `aquarius::swap(&ctx)` etc. against `hop.pool` with no check that the address is a real venue contract (contracts/swap-aggregator/src/venues/mod.rs:34-40). Because the venue call sits under the sender's authorization, any token transfer the rogue contract performs from the sender is recorded as a child of the sender's auth entry. The harness proves this end-to-end: `RogueHopPool::swap` calls `token::Client::transfer(&victim, &to, &amount)` on an unrelated wallet token, and the recorded auth tree shows the theft attached beneath Alice's `swap_collateral` invocation, emptying her balance while the swap itself settles fairly (tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs:62-72, 195-226). The controller-side defenses do not bound it: `swap_tokens` authorizes only the controller's own input transfer and checks controller balance deltas and final account risk (contracts/controller/src/strategies/swap.rs:34-54), none of which constrains what payload-named third-party code does under the caller's auth. The threat model acknowledges the vector and pushes mitigation to clients ("a client must decode the route it signs and refuse an authorization tree with any other child"), so wallets that display only the top-level call leave users exposed.

### Impact Explanation
Theft of user funds: an attacker who supplies a crafted route to a victim (e.g., via a poisoned quote or phishing front-end) can drain arbitrary tokens from the victim's wallet in the same transaction as a legitimate-looking `swap_collateral`, `swap_debt`, `multiply`, `repay_debt_with_collateral`, or standalone `execute_strategy` call. The stolen amount is unbounded by the swap size — the test drains a 77,770-unit token the protocol never listed.

### Likelihood Explanation
Exploitation requires the victim to sign an authorization tree containing the extra child transfer; an honest simulator records it, so a wallet or client that inspects the full tree would refuse it. The threat model documents the hazard but places enforcement entirely on client behavior, which not all wallets/SDK flows do. Medium severity: user action (signing a poisoned route) is required, but the contract itself provides no containment — the direct `execute_strategy` path has the same exposure for every swap user.

### Recommendation
Constrain `hop.pool` to a verified venue set (e.g., pools resolvable from the named venue's factory/registry, or a governance-maintained allowlist), or have venue adapters validate the pool address against the venue's own registry (e.g., Aquarius pool lookup by token pair) instead of trusting the payload-supplied address. Additionally, client SDKs should hard-fail on any unexpected child invocation in the simulated auth tree.

### Proof of Concept
Existing harness test `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` in `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`: registers `UnlistedPoolRouter` (router double) and `RogueHopPool` whose `swap` transfers the victim's unlisted wallet token to the attacker; a `swap_collateral` route naming that pool executes under mock auth, records the theft as a child of Alice's auth entry, and asserts `wallet(alice) == 0` and `wallet(attacker) == WALLET_BALANCE` while Alice still receives the fair swap output.
