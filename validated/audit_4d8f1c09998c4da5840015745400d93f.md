### Title
Silent Error Swallow in `FinalizeState` Allows Partial Treasury Rebalance State Mutations to Persist — (`kaiax/system/impl/blockstate.go`)

### Summary

`SystemModule.FinalizeState` calls `bcsystem.RebalanceTreasury` — a function that performs multiple `StateDB` mutations (zeroing retired accounts, crediting newbie accounts) — but silently swallows any returned error instead of propagating it. There is no `statedb.Snapshot()` / `statedb.RevertToSnapshot()` guard at the call site. If `RebalanceTreasury` mutates state for some retired accounts and then returns an error before completing all mutations, those partial balance changes are permanently committed to the canonical state root.

### Finding Description

In `kaiax/system/impl/blockstate.go`, `FinalizeState` handles the KIP-103 and KIP-160 fork blocks by calling `RebalanceTreasury`:

```go
rebalanceResult, err := bcsystem.RebalanceTreasury(state, m.Chain, header)
if err != nil {
    logger.Error("failed to execute treasury rebalancing. State not changed", "err", err)
} else { ... }
``` [1](#0-0) 

The error is **only logged** — it is not returned to the caller. `FinalizeState` continues executing and eventually returns `nil`, so `StateProcessor.FinalizeState` proceeds to compute `header.Root = statedb.IntermediateRoot(true)` and seals the block. [2](#0-1) 

The `StateDB` journal/snapshot mechanism is the only way to atomically roll back multiple mutations: [3](#0-2) 

No snapshot is taken before the `RebalanceTreasury` call, and no `RevertToSnapshot` is called on the error path. The comment `"State not changed"` is aspirational — it is not enforced by any code.

`RebalanceTreasury` reads the list of retired addresses (to zero out) and newbie addresses (to credit) from the on-chain `TreasuryRebalance` contract. It performs a sequence of `state.SetBalance(retired, 0)` and `state.AddBalance(newbie, amount)` calls. If it returns an error after completing some but not all of these mutations, the `StateDB` journal already contains those partial changes. Because `FinalizeState` does not revert and does not propagate the error, `Finalise` is called on the dirty journal, writing the partial mutations into the trie. [4](#0-3) 

### Impact Explanation

At the KIP-103 or KIP-160 fork block, a partial execution of `RebalanceTreasury` can result in:

- One or more **retired accounts having their KAIA balance set to zero** while the corresponding newbie accounts are **not yet credited** — net effect: KAIA is permanently destroyed from the canonical state.
- Alternatively, some newbie accounts are credited while some retired accounts are not yet zeroed — net effect: KAIA is minted without the corresponding burn.

Both outcomes corrupt the canonical KAIA supply and account balances in the state trie. Because all honest nodes run the same code path and swallow the same error, they all converge on the same corrupted state root — the corruption is consensus-consistent but economically incorrect.

### Likelihood Explanation

`RebalanceTreasury` is triggered exactly once per fork block (KIP-103 or KIP-160). The function reads from the deployed `TreasuryRebalance` contract; if that contract's state is malformed, or if a trie read error occurs mid-loop, the function can return an error after partial mutations. The trigger is automatic (no user action required at the fork block), and the error path is reachable whenever the contract data is inconsistent or a database error occurs during state access.

### Recommendation

Take a `StateDB` snapshot before calling `RebalanceTreasury` and revert to it on error, then propagate the error:

```go
if chainConfig.IsKIP160ForkBlock(header.Number) || chainConfig.IsKIP103ForkBlock(header.Number) {
    snap := state.Snapshot()
    rebalanceResult, err := bcsystem.RebalanceTreasury(state, m.Chain, header)
    if err != nil {
        state.RevertToSnapshot(snap)
        return err  // propagate; do not silently swallow
    }
    logger.Info("successfully executed treasury rebalancing", ...)
}
```

This mirrors the pattern used throughout the EVM execution layer for atomic sub-call protection.

### Proof of Concept

1. At the KIP-103 or KIP-160 fork block, `SystemModule.FinalizeState` is invoked by `StateProcessor.FinalizeState`.
2. `bcsystem.RebalanceTreasury(state, ...)` begins executing: it zeroes the balance of retired address `R1` via `state.SetBalance(R1, 0)` — this is journaled in `StateDB`.
3. Before crediting newbie address `N1`, `RebalanceTreasury` encounters an error (e.g., malformed contract data for the next entry) and returns `err != nil`.
4. The call site logs the error and **does not revert** and **does not return the error**.
5. `FinalizeState` returns `nil`; `StateProcessor` calls `statedb.IntermediateRoot(true)` → `Finalise` → the journal entry zeroing `R1` is committed to the trie.
6. The block is sealed with a state root where `R1.balance == 0` but `N1.balance` is unchanged — KAIA has been permanently destroyed from the canonical chain state. [5](#0-4) [6](#0-5)

func (p *StateProcessor) FinalizeState(header *types.Header, statedb *state.StateDB, txs []*types.Transaction, receipts types.Receipts) (*types.Block, error) {
	// We can assure that if the magma hard forked block should have the field of base fee
	if p.config.IsMagmaForkEnabled(header.Number) {
		if header.BaseFee == nil {
			logger.Error("Magma hard forked block should have baseFee", "blockNum", header.Number.Uint64())
			return nil, errors.New("Invalid Magma block without baseFee")
		}
	} else if header.BaseFee != nil {
		logger.Error("A block before Magma hardfork shouldn't have baseFee", "blockNum", header.Number.Uint64())
		return nil, ErrInvalidBaseFee
	}

	for _, module := range p.blockStateModules {
		if err := module.FinalizeState(header, statedb, txs, receipts); err != nil {
			return nil, err
		}
	}

	header.Root = statedb.IntermediateRoot(true)

	// Assemble and return the final block for sealing
	return types.NewBlock(header, txs, receipts), nil
}

// Snapshot returns an identifier for the current revision of the state.
func (s *StateDB) Snapshot() int {
	id := s.nextRevisionId
	s.nextRevisionId++
	s.validRevisions = append(s.validRevisions, revision{id, s.journal.length()})
	return id
}

// RevertToSnapshot reverts all state changes made since the given revision.
func (s *StateDB) RevertToSnapshot(revid int) {
	// Find the snapshot in the stack of valid snapshots.
	idx := sort.Search(len(s.validRevisions), func(i int) bool {
		return s.validRevisions[i].id >= revid
	})
	if idx == len(s.validRevisions) || s.validRevisions[idx].id != revid {
		panic(fmt.Errorf("revision id %v cannot be reverted", revid))
	}
	snapshot := s.validRevisions[idx].journalIndex

	// Replay the journal to undo changes and remove invalidated snapshots
	s.journal.revert(s, snapshot)
	s.validRevisions = s.validRevisions[:idx]
}

// Finalise finalises the state by removing the self destructed objects
// and clears the journal as well as the refunds.
func (stateDB *StateDB) Finalise(deleteEmptyObjects bool, setStorageRoot bool) {
	for addr := range stateDB.journal.dirties {
		so, exist := stateDB.stateObjects[addr]
		if !exist {
			// ripeMD is 'touched' at block 1714175, in tx 0x1237f737031e40bcde4a8b7e717b2d15e3ecadfe49bb1bbc71ee9deb09c6fcf2
			// That tx goes out of gas, and although the notion of 'touched' does not exist there, the
			// touch-event will still be recorded in the journal. Since ripeMD is a special snowflake,
			// it will persist in the journal even though the journal is reverted. In this special circumstance,
			// it may exist in `stateDB.journal.dirties` but not in `stateDB.stateObjects`.
			// Thus, we can safely ignore it here
			continue
		}

		if so.selfDestructed || (deleteEmptyObjects && so.empty()) {
			stateDB.deleteStateObject(so)

			// If state snapshotting is active, also mark the destruction there.
			// Note, we can't do this only at the end of a block because multiple
			// transactions within the same block might self destruct and then
			// resurrect an account; but the snapshotter needs both events.
			if stateDB.snap != nil {
				stateDB.snapDestructs[so.addrHash] = struct{}{} // We need to maintain account deletions explicitly (will remain set indefinitely)
				delete(stateDB.snapAccounts, so.addrHash)       // Clear out any previously updated account data (may be recreated via a resurrect)
				delete(stateDB.snapStorage, so.addrHash)        // Clear out any previously updated storage data (may be recreated via a resurrect)
			}
		} else {
			so.updateStorageTrie(stateDB.db)
			so.setStorageRoot(setStorageRoot, stateDB.stateObjectsDirtyStorage)
			stateDB.updateStateObject(so)
		}
		so.created = false
		stateDB.stateObjectsDirty[addr] = struct{}{}
	}
	// Invalidate journal because reverting across transactions is not allowed.
	stateDB.clearJournalAndRefund()
