**Who can exploit this:**

- **Pre-Permissionless fork**: Lines 103–107 only restrict non-governing-node voters *after* `IsPermissionlessForkEnabled`. Before that fork, any council member can vote in single mode. The test `TestVerifyVote_SingleMode` explicitly confirms this: `"pre-permissionless allows non-governing node"`.

### Title
`checkConsistency` validates the current `GoverningNode` instead of the proposed vote value, allowing a council member to set `GoverningNode` to an off-council address — (`kaiax/gov/headergov/impl/header.go`)

### Summary

`checkConsistency` for `GovernanceGoverningNode` votes checks whether `params.GoverningNode` (the **current** governing node) is in the council, rather than `vote.Value()` (the **proposed** new governing node). Before the Permissionless fork, any council member can cast a `governance.governingnode` vote. The wrong membership check allows a vote nominating an off-council address to pass validation, be ratified at the next epoch boundary, and permanently corrupt single-mode governance.

### Finding Description

In `checkConsistency` (`kaiax/gov/headergov/impl/header.go`, lines 159–178), the `GovernanceGoverningNode` case fetches `params.GoverningNode` and checks whether **it** is in the council:

```go
if slices.Contains(council, params.GoverningNode) {
    return nil
}
return ErrGovNodeNotInValSetList
``` [1](#0-0) 

The intent of this guard is to ensure the **proposed** new governing node is a council member, but `params.GoverningNode` is the **existing** governing node — not `vote.Value()`. Because the existing governing node is already in the council (it must be, to be a proposer), this check is a no-op: it always returns `nil` for any proposed value, including off-council addresses.

The voting restriction that limits votes to the governing node only applies after the Permissionless fork:

```go
if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
    params.GovernanceMode == "single" &&
    vote.Voter() != params.GoverningNode {
    return ErrVotePermissionDenied
}
``` [2](#0-1) 

Before that fork, any council member can vote in single mode, as confirmed by the existing test: [3](#0-2) 

### Impact Explanation

Once the malicious vote is ratified at the epoch boundary, `GetParamSet` returns `GoverningNode = <off-council address>` for all subsequent blocks. Since the off-council address can never be a block proposer (it is not in the council), the single-mode permission check at line 105 permanently denies all future votes. Governance is irreversibly locked. Additionally, `getDemotedValidatorsIstanbul` uses `GoverningNode` to unconditionally qualify the governing node as a validator — with an off-council address, this protection is applied to a phantom address, potentially affecting validator set composition. [4](#0-3) 

The Kaia Mainnet README documents `governance.governancemode: single` as an immutable parameter, making this the live governance mode. [5](#0-4) 

### Likelihood Explanation

Requires a single malicious council member (validator) acting before the Permissionless fork is activated. No majority collusion, no privileged key, and no external service compromise is needed. The attack is a single crafted block header with a valid vote field.

### Recommendation

Replace the check in `checkConsistency` to validate the **proposed** value rather than the current parameter:

```go
// Before (wrong):
if slices.Contains(council, params.GoverningNode) {

// After (correct):
proposedNode, ok := vote.Value().(common.Address)
if !ok {
    return ErrInvalidKeyValue
}
if slices.Contains(council, proposedNode) {
``` [6](#0-5) 

### Proof of Concept

1. Configure a chain: `GovernanceMode=single`, `epoch=10`, council = `[addr0..addr4]`, `GoverningNode=addr0`, Permissionless fork **not** enabled.
2. `addr1` (a council member, not the governing node) waits to be selected as proposer.
3. `addr1` crafts a block with `header.Vote = VoteData{Voter: addr1, Name: "governance.governingnode", Value: addr10}` where `addr10` is not in the council.
4. `VerifyVote` passes: `addr1` is in council ✓, `addr1` is the block author ✓, Permissionless fork not enabled so no `ErrVotePermissionDenied` ✓.
5. `checkConsistency` passes: `slices.Contains(council, params.GoverningNode)` = `slices.Contains(council, addr0)` = `true` → returns `nil` ✓.
6. Block is accepted and the vote is stored.
7. At block 10 (epoch boundary), `getExpectedGovernance` collects the vote and `header.Governance` is set to `{"governance.governingnode": addr10}`.
8. After block 10, `GetParamSet` returns `GoverningNode = addr10`.
9. All subsequent `VerifyVote` calls in single mode check `vote.Voter() != params.GoverningNode` = `vote.Voter() != addr10`. Since `addr10` is never a proposer (not in council), no vote can ever pass again.
10. Single-mode governance is permanently broken.
