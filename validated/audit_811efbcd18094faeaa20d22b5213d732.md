### Title
Backslash host-confusion allows attacker-controlled ServerUrl to bypass loopback check in isJupyterServerURLValid - ([File: internal/codespaces/rpc/invoker.go])

### Finding Description
`isJupyterServerURLValid` (internal/codespaces/rpc/invoker.go:321-335) parses the `ServerUrl` field returned by the (attacker-reachable via a malicious/compromised codespace RPC host) `GetRunningServer` gRPC response using Go's `net/url.Parse`, then checks `u.Hostname()` against `"localhost"` (case-insensitive) or a parsed loopback IP. The validated URL is later passed unchanged (only the port is substituted) to `a.browser.Browse(targetUrl)` in `pkg/cmd/codespace/jupyter.go:91-95`, which opens the URL in the user's actual web browser.

Go's `net/url` parser (RFC 3986-based) treats a backslash `\` as an ordinary character with no special meaning inside the authority component. In contrast, every major browser's WHATWG URL parser normalizes backslashes to forward slashes for "special" schemes (`http`, `https`, `ws`, `wss`, `ftp`, `file`) before locating the authority/userinfo boundary. This produces a parser differential:

- Input: `http://evil.com\@localhost/lab`
- Go `net/url.Parse`: authority is scanned up to the first `/`, `?`, or `#`. Because `\` is not treated as a separator, the whole string `evil.com\@localhost` becomes the authority; splitting on the last `@` yields userinfo=`evil.com\`, host=`localhost`. `u.Hostname()` returns `"localhost"`, so `isJupyterServerURLValid` returns `true`.
- Browser (WHATWG parser): backslashes are normalized to `/` for the `http` scheme, turning the URL into `http://evil.com/@localhost/lab`. The authority ends at the first `/`, so the browser resolves the host as `evil.com` and treats `/@localhost/lab` as the path — with no userinfo at all.

Because the RPC-controlled `ServerUrl` value is passed straight through to `a.browser.Browse` without re-validating the host the browser will actually navigate to, this differential lets a malicious/compromised RPC host name any attacker-controlled domain as the effective navigation target while sailing through the "loopback-only" check.

### Impact Explanation
This breaks the loopback trust boundary that `isJupyterServerURLValid` is meant to enforce: `codespace jupyter` opens the user's browser at an attacker-chosen external host instead of the local Jupyter server, while still carrying the JupyterLab access token in the query string (`?token=...`), so the token/credential could be exfiltrated to the attacker's server via the Referer/URL. This matches an SSRF-like/URL-redirection impact class — wrong-host request routing initiated from a legitimate `gh` command, with potential secondary token disclosure.

### Likelihood Explanation
The attacker must control (or MITM/compromise) the internal gRPC "CodespacesInternal" server that answers `GetRunningServer`, i.e., control the `ServerUrl` field in the RPC response. This is a plausible position for an attacker who controls/compromises a codespace or its port-forwarded RPC channel (the trust model this specific function exists to defend against), and requires no further user interaction beyond running `gh codespace jupyter`. The crafted payload (`http://evil.com\@localhost/lab`) is simple and reliably reproducible since it exploits a well-documented, stable parser difference between Go's `net/url` and WHATWG-URL browsers.

### Recommendation
Do not rely on string/hostname comparison of a parser that can diverge from browser URL parsing. Recommended fixes:
1. Reject any `ServerUrl` containing a backslash (`\`) before/along with parsing, since it has no legitimate meaning in `http`/`https` URLs and is the primary vector for parser-differential host confusion.
2. After validating, re-serialize the URL from its parsed components (`u.Scheme`, `u.Hostname()`, `u.Port()`, `u.EscapedPath()`, `u.RawQuery`) rather than passing through the original attacker-supplied string, so what gets validated is exactly what gets opened.
3. Additionally reject URLs containing userinfo (`u.User != nil`) entirely, since a legitimate local Jupyter URL never needs a userinfo component.

```go
// Ensures that the Jupyter server URL is valid and points to a loopback http(s) URL
func isJupyterServerURLValid(serverURL string) bool {
	u, err := url.Parse(serverURL)
	if err != nil {
		return false
	}
	if u.Scheme != "http" && u.Scheme != "https" {
		return false
	}
	host := u.Hostname()
	if strings.ToLower(host) == "localhost" {
		return true
	}
	ip := net.ParseIP(host)
	return ip != nil && ip.IsLoopback()
}
```
