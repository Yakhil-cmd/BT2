### Title
`ProxyType::NonTransfer` identity-deposit exclusion bypassed via `Utility::batch_all` wrapping - (File: system-parachains/people/people-kusama/src/lib.rs)

### Summary
The `people-kusama` `ProxyType::NonTransfer` filter explicitly excludes `Identity::request_judgement`, `set_subs`/`add_sub`, and other deposit-moving Identity calls, with an inline comment stating they "should not be allowed" because they transfer/repatriate deposits from the proxied account. However, the same match arm unconditionally allows `RuntimeCall::Utility(_)`, and `pallet_proxy`'s call filter is only ever applied to the top-level call passed to `Proxy::proxy`, never recursively to calls nested inside `Utility::batch_all`. A delegate holding only a `NonTransfer` proxy can therefore wrap the excluded `Identity::request_judgement` call inside `Utility::batch_all` to have it dispatched with the real (proxied) account's origin, defeating the documented restriction.

### Finding Description

Note the comment at lines 516-519 explicitly stating that `request_judgement` "puts up a deposit to transfer to a registrar" and "should not be allowed," yet the same `matches!` block unconditionally permits `RuntimeCall::Utility(_)` at line 513.

`pallet_proxy::Pallet::proxy` checks `ProxyType::filter` exactly once, against the outer call supplied by the caller. When that outer call is `Utility::batch_all(vec![inner_calls])`, the filter only observes the `RuntimeCall::Utility(_)` variant and returns `true`; it never inspects `inner_calls`. `pallet_utility::batch_all` then dispatches each inner call using the origin established for the proxied call — i.e. `RuntimeOrigin::signed(real_account)` — without re-invoking the `ProxyType` filter.

Exploit flow:
1. Victim (`real`) adds an attacker-controlled delegate with `ProxyType::NonTransfer`, relying on the documented exclusion of deposit-transferring Identity calls.
2. Attacker calls `Proxy::proxy(real, Some(NonTransfer), Utility::batch_all(vec![Identity::request_judgement { reg_index, max_fee }]))`.
3. Filter check passes because the outer call matches `RuntimeCall::Utility(_)`.
4. `Utility::batch_all` dispatches `Identity::request_judgement` as `Signed(real)`, placing/holding a deposit from `real`'s balance for judgement by registrar `reg_index`, exactly the action the `NonTransfer` proxy type was designed to block.
5. `frame_system::Config::BaseCallFilter = Everything` for this runtime, so no chain-wide filter blocks the nested dispatch either. [2](#0-1) 

### Impact Explanation
This lets a `NonTransfer` proxy delegate — a deliberately restricted, lower-trust delegate — trigger identity-deposit-moving operations on behalf of the proxied account, something the code's own comment says must not be possible. Depending on subsequent registrar behavior (`provide_judgement`), the deposit placed via the bypassed call can later be slashed, causing the victim's funds to be moved/lost through an action the victim never authorized for that proxy type. This is an unauthorized-execution-against-another-account class issue.

### Likelihood Explanation
The path requires only: (a) a victim who has granted a `NonTransfer` proxy (a standard configuration explicitly intended to be safer than `Any`), and (b) the delegate issuing a single `Proxy::proxy` extrinsic wrapping `Identity::request_judgement` in `Utility::batch_all`. No governance, no privileged origin, and no XCM aliasing is needed — it is fully reachable by a signed proxy delegate. This is deterministic and repeatable on every extrinsic submission.

### Recommendation
Make `ProxyType::filter` recursively inspect calls nested in `Utility::batch`, `batch_all`, `force_batch`, and any other composite/dispatch-wrapping calls (and `Multisig::as_multi`/`as_multi_threshold_1` where relevant), applying the same per-call restrictions to each inner call as would apply if it were the outer call. Alternatively, remove the blanket `RuntimeCall::Utility(_)` allowance from `NonTransfer` and instead scope it to permit only batches whose every inner call is independently permitted under `NonTransfer`.

### Proof of Concept
Integration test in `people-kusama` runtime tests:
1. Fund `real` account, register a `NonTransfer` proxy for `delegate` via `Proxy::add_proxy`.
2. As `delegate`, call `Proxy::proxy(real, Some(ProxyType::NonTransfer), RuntimeCall::Utility(pallet_utility::Call::batch_all{ calls: vec![RuntimeCall::Identity(pallet_identity::Call::request_judgement{ reg_index: 0, max_fee: X })] }))`.
3. Assert the call succeeds (`assert_ok!`) and that `real`'s balance is reduced/held for the judgement deposit, proving the excluded action executed.
4. Contrast with directly calling `Proxy::proxy(real, Some(NonTransfer), RuntimeCall::Identity(Call::request_judgement{..}))`, which must fail with `Error::<Runtime>::NotProxy`/`BadOrigin`, demonstrating the discrepancy/bypass.
