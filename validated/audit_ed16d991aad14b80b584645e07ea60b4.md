### Title
Webhook signature is verified against the sender's own organization secret while the payload's `repository.full_name` field can target a *different* organization's Stack, allowing a cross-tenant, unauthorized trigger of GitHub sync/deploy - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/secret to verify the HMAC against using `repository_owner`, taken only from `params.dig('repository', 'owner', 'login')` (or `organization.login`). The actual repository/stack that gets acted on is resolved later, independently, in `Shipit::Webhooks::Handlers::Handler#repository_name`, from `payload.dig('repository', 'full_name')`. Nothing enforces that the owner used to pick the verifying secret is the same owner encoded in `full_name`, so a valid signature computed with **organization A's** webhook secret can carry a payload whose `repository.full_name` points at **organization B's** repository/stack.

### Finding Description [1](#0-0) 

`verify_signature` computes the verifying GitHub App as `Shipit.github(organization: repository_owner)` where `repository_owner` reads only `repository.owner.login` (falling back to `organization.login`). This binds trust to "did the sender know org X's `webhook_secret`" — nothing else in the payload is authenticated.

The handlers that actually act on the payload use a *different* field to decide which repository/Stack to mutate: [2](#0-1) [3](#0-2) 

`Repository.from_github_repo_name` splits `full_name` on `/` and looks the repository up globally, with no scoping to the organization that supplied the verified signature: [4](#0-3) 

This is exactly the "organization authenticated vs. repository written" binding break described in the rules: `repository.owner.login` (signed/authenticated field) ≠ `repository.full_name`'s owner (field actually acted upon), and the code never checks `repository.full_name == "#{repository_owner}/..."`.

In a multi-tenant Shipit deployment (explicitly supported, see `docs/setup.md` "Using Multiple Github Applications" section), each organization admin legitimately possesses their *own* org's `webhook_secret` (they create it themselves in GitHub App settings). Such an admin/attacker can craft a POST to `/webhooks` with:
- `repository.owner.login = "orgA"` (their own org, used only to select the verifying secret)
- `repository.full_name = "orgB/victim-repo"` (a target belonging to a different tenant)
- a valid `X-Hub-Signature` computed with orgA's own webhook secret

`verify_signature` succeeds (it validates against orgA's app, which is legitimate), and `PushHandler#process` then resolves stacks belonging to `orgB/victim-repo` and calls `stack.sync_github(expected_head_sha: params.after)`, enqueuing `GithubSyncJob` against a Stack the attacker does not own or have any authorization over.

### Impact Explanation
`GithubSyncJob` fetches real commits through `stack.github_api` (scoped to the victim's own Repository/App), so it doesn't inject forged commit content, but it does let an unrelated organization's webhook-secret holder force synchronization of an arbitrary victim Stack in another tenant on demand: [5](#0-4) 
If the targeted Stack has continuous deployment enabled, forcing an out-of-band sync can trigger an unsolicited/unscheduled automatic deploy of the victim's latest reachable commit — an unauthorized deploy performed by a party outside that organization's trust boundary, meeting the "unauthorized deploy" criterion. At minimum it is a cross-tenant authorization bypass: any organization onboarded to this Shipit instance can force webhook-triggered side effects (push sync, PR-driven review-stack creation/archival via `OpenedHandler`/`ReopenedHandler`, which also key off `repository.full_name` and not the verified owner) against every other onboarded organization's stacks.

### Likelihood Explanation
Requires a Shipit deployment configured with multiple GitHub organizations (documented, supported configuration) and requires the attacker to control (be an admin of) at least one onboarded organization whose `webhook_secret` they legitimately know. That is a modest bar in shared/multi-tenant Shipit installations, and no interaction beyond a single crafted HTTP POST is needed.

### Recommendation
In `WebhooksController#verify_signature` / `Handler#repository_name`, cross-validate that the owner encoded in `repository.full_name` matches `repository_owner` (the field used to select the verifying GitHub App/secret) before processing, e.g. reject the webhook if `payload.dig('repository','full_name')&.split('/')&.first&.downcase != repository_owner&.downcase`. Alternatively, scope `Repository.from_github_repo_name` lookups to the authenticated organization rather than trusting the unauthenticated `full_name` field globally.

### Proof of Concept
Not independently executable from the index alone (would require a running multi-org Shipit instance with two onboarded organizations to demonstrate end-to-end), but the code path is fully traceable:
1. Attacker is admin of `orgA`, onboarded to the shared Shipit instance, and knows `orgA`'s `webhook_secret`.
2. Attacker computes `sha1=HMAC(orgA_secret, body)` for a body: `{"ref":"refs/heads/master","after":"<any-known-sha-of-orgB-repo>","repository":{"owner":{"login":"orgA"},"full_name":"orgB/victim-repo"}}`.
3. POST to `/webhooks` with header `X-Github-Event: push` and the computed `X-Hub-Signature`.
4. `verify_signature` calls `Shipit.github(organization: "orgA")` and succeeds validating the signature against orgA's secret.
5. `PushHandler#process` resolves `Repository.from_github_repo_name("orgb/victim-repo")` and enqueues `GithubSyncJob` for orgB's Stack, which the attacker has no privileges over.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
