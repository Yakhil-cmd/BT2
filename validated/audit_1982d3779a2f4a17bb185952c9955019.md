### Title
Credential cache keyed by host (not full URL/path) allows cross-repo credential collision when multiple repos/submodules share a host - (File: `main.go`)

### Summary
`git-sync` configures the git credential system globally with `credential.helper=cache --timeout 3600` [1](#0-0) , and credentials for the main repo, `--credential` entries, `--askpass-url`, and GitHub App tokens are all stored via `StoreCredentials`, which calls `git credential approve` with a `url=...` field [2](#0-1) . This mirrors the reported bug class: a value (an oracle / here, a credential) is bound to a coarser key (`foreignAsset` / here, protocol+host) instead of the specific entity that actually needs distinct treatment (the pair / here, the full repo URL+path).

### Finding Description
Git's `cache` credential helper, by default, matches and stores credentials keyed by `protocol://host[:port]` — it does **not** include the URL path unless `credential.useHttpPath=true` is configured. `git-sync` never sets `credential.useHttpPath` anywhere in the codebase (confirmed absent from `main.go` and only referenced in `test_e2e.sh`). This means that when `--credential` is used to register different username/password pairs for multiple repositories or submodules that happen to share the same host (e.g. `http://ip/repo-a` and `http://ip/repo-b`, as constructed in the e2e test `e2e::submodule_sync_over_http_different_passwords` at [3](#0-2) ), the git credential cache — keyed only by host — can serve the wrong credential for one of the paths, exactly analogous to the oracle-mapping bug where a value keyed by a coarser identifier (`foreignAsset`) unexpectedly applies to a differing narrower identity (the pair) that shares that coarser key.

The `--credential` flag is explicitly documented as being intended "for specific URLs, for example when using submodules" [4](#0-3) , implying the design intent is per-URL isolation, but the underlying `git credential cache` mechanism used (`git.SetupDefaultGitConfigs`) does not enforce path-level scoping.

### Impact Explanation
If a deployment relies on `--credential` to segregate different tokens/passwords for multiple repos or submodules hosted on the same server (a supported and documented use case for submodules), the wrong credential could be presented to the wrong repo path. Depending on the git host's ACL model, this could manifest as: an unrelated repo/submodule fetch succeeding with credentials that shouldn't apply to it (credential/token disclosure via unintended use), or sync failures due to using mismatched credentials. This is a persistent-sync-denial or credential-misuse issue rather than remote code execution.

### Likelihood Explanation
Requires the operator to configure multiple `--credential` entries (or submodules) whose distinguishing URL differs only by path on the same host — a realistic but non-default configuration. No malicious operator or leaked-key assumption is needed; this is purely a git default-behavior interaction that `git-sync` does not compensate for.

### Recommendation
Set `credential.useHttpPath=true` globally in `SetupDefaultGitConfigs` [5](#0-4)  so that the credential cache is keyed by the full URL path in addition to host, preventing collisions between distinct repos/submodules on the same host — analogous to the recommended fix of binding the oracle to the pair instead of the shared asset key.

### Proof of Concept
1. Configure two `--credential` entries for `http://<same-ip>/repoA` (user `u1`/pass `p1`) and `http://<same-ip>/repoB` (user `u2`/pass `p2`), as done in [6](#0-5) .
2. Both are stored via `git credential approve` [7](#0-6)  under the default `cache` helper, which without `credential.useHttpPath` matches only on `protocol://host`.
3. When git subsequently performs `credential fill` for either repoA or repoB, the cache can return the credential last stored for that host, independent of path, potentially serving `p1` to repoB or vice versa.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}
```

// SetupDefaultGitConfigs configures the global git environment with some
// default settings that we need.
func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {
	configs := []keyVal{{
		// Never auto-detach GC runs.
		key: "gc.autoDetach",
		val: "false",
	}, {
		// Fairly aggressive GC.
		key: "gc.pruneExpire",
		val: "now",
	}, {
		// How to manage credentials (for those modes that need it).
		key: "credential.helper",
		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",
	}}

	for _, kv := range configs {
		if _, _, err := git.Run(ctx, "", "config", "--global", kv.key, kv.val); err != nil {
			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
}
```
