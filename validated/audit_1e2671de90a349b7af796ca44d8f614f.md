The reported CVE concerns a Node.js/TypeScript agent orchestrator (`Network-AI`) where a `SandboxPolicy.isCommandAllowed` allowlist glob-matches a whole command string that is then passed to `/bin/sh -c` via `ShellExecutor`, letting shell metacharacters in an otherwise-allowed prefix (e.g. `git *`) achieve arbitrary command execution. This bug class requires (1) an attacker-controlled string reaching a shell interpreter, and (2) an allowlist that inspects the string before shell parsing occurs.

Searching polkadot-sdk for equivalent patterns — `std::process::Command`/`tokio::process::Command` usage, PVF worker sandboxing (`polkadot/node/core/pvf/**`), and command allowlisting — found no such construct reachable from attacker-controlled runtime input:

- The PVF worker spawn paths (`polkadot/node/core/pvf/src/worker_interface.rs`, `polkadot/node/core/pvf/src/security.rs`) build argument vectors directly with `.arg(...)`/`.args(...)` on a fixed, hardcoded binary path, never through a shell, and never with attacker-supplied command strings gated by a glob allowlist. [1](#0-0) [2](#0-1) 
- Other `Command::new(...)`/`process::Command` usages found (`polkadot/tests/purge_chain_works.rs`, `substrate/test-utils/cli/src/lib.rs`, `cumulus/polkadot-omni-node/lib/src/tests/common.rs`, `substrate/client/rpc/src/system/tests.rs`) are all test/CLI infrastructure with no untrusted-input pathway from a signed extrinsic, contract call, or XCM message. [3](#0-2) [4](#0-3) 
- There is no `SandboxPolicy`-style allowlist gating shell command strings anywhere in this codebase; PVF sandboxing instead uses OS-level `landlock`/`seccomp`/namespace isolation rather than command-string allowlisting, which is a structurally different (and not vulnerable-to-this-bug-class) mechanism. [5](#0-4) 

Since polkadot-sdk is a Rust/FRAME blockchain runtime and node stack with no user-facing shell-command execution surface gated by a glob allowlist, there is no demonstrable analog to this CVE's root cause (shell metacharacter injection bypassing a string-based allowlist before `/bin/sh -c` invocation).
