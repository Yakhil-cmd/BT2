### Title
Dust-threshold straddle: third-party supply top-ups permanently block `clean_bad_debt` on insolvent accounts - ([File: contracts/controller/src/positions/liquidation/curve.rs](contracts/controller/src/positions/liquidation/curve.rs))

### Summary
Analogous to HTTP/2 Rapid Reset — where an attacker cheaply resets the "stream admits work" condition an unbounded number of times — an unprivileged address can repeatedly reset the one condition that admits an insolvent account to permissionless bad-debt cleanup (`total_collateral <= BAD_DEBT_USD_THRESHOLD`) by topping up the victim's *existing* supply position with dust via `supply`. Each top-up is a one-line call that costs the attacker only the gap between the account's current collateral and the $5 gate (arbitrarily small on a dust-priced book), and it can be repeated indefinitely every time liquidation erodes the collateral back below the threshold, indefinitely denying `clean_bad_debt` and the in-liquidation auto-cleanup `check_bad_debt_after_liquidation`.

### Finding Description
`clean_bad_debt` → `socialize_bad_debt` (DustCapped gate) admits cleanup only when `is_socializable_bad_debt` holds:

`contracts/controller/src/positions/liquidation/curve.rs` (lines 23-27):
```rust

    total_debt > total_collateral && total_collateral <= Wad::from(BAD_DEBT_USD_THRESHOLD)
}

An insolvent account eligible for cleanup necessarily holds residual supply positions (collateral ≤ $5 but positive, since a fully-drained account would have been cleaned inside the liquidation itself). So the attacker:

1. Waits for a victim account to become insolvent with collateral near the $5 gate — a state reachable permissionlessly by liquidation (`liquidate` accepts `debt_payments` and drives collateral down) or by price movement.
2. Calls `supply(attacker, victim_id, spoke_id, [(existing_hub_asset, dust)])`, pushing `total_collateral` to `$5 + ε`. The Certora spec `bad_debt_straddle_blocks_dust_gate` confirms that `BAD_DEBT_USD_THRESHOLD + 1` shuts the dust gate entirely while the account remains insolvent [4](#0-3) .
3. Every `clean_bad_debt` call now reverts `CannotCleanBadDebt`, and the same gate evaluated inside `liquidate` via `check_bad_debt_after_liquidation` skips auto-socialization [5](#0-4) .
4. Whenever subsequent liquidation legs push `total_collateral` back under $5, the attacker re-arms the block with another dust top-up — the same "create work / cancel admission" loop the advisory describes, here priced at cents per iteration.

The donated dust is unrecoverable for the attacker (withdrawal requires post-state solvency, which fails on an insolvent account), but the per-block cost is bounded by the straddle gap, not by the bad debt size — on a $4.99 residual the block costs ~$0.02.

### Impact Explanation
While the straddle holds, the victim's debt keeps compounding at the borrow index while its collateral cannot be socialized and removed. Suppliers' unrealized loss grows, the supply-index write-down that would cap the damage is deferred, and the bad-debt account cannot be cleared by any unprivileged party. The only remaining path is `force_socialize_bad_debt` (owner-gated, `BadDebtGate::InsolventOnly`), which the spec confirms admits exactly this straddled domain [6](#0-5)  — so the attack converts a permissionless, immediate cleanup into a governance-timelocked one: a temporary freezing of supplier funds and a delay during which protocol insolvency accrues. On an account that oscillates around the gate, the attacker can keep this state alive indefinitely at trivial recurring cost.

### Likelihood Explanation
- Fully unprivileged: `supply` third-party top-ups are explicitly allowed on existing supply positions (`INV-AUTH-03`), and `liquidate`/`clean_bad_debt` are permissionless. No leaked key, no privileged call, no oracle manipulation — the attacker uses strict prices as they are.
- Cheap: the cost per re-arm is `BAD_DEBT_USD_THRESHOLD + 1 − current_collateral`, which trends toward zero as liquidation consumes collateral; it does not require holding value above the cap because the cap test is on the *victim's* collateral, funded by the victim itself plus attacker dust.
- Detectable-but-not-preventable: keepers cannot clean the account while the straddle holds, and each liquidation transaction atomically re-checks the same gate, so there is no interposition window to exploit — only the owner force-path works.

### Recommendation
Bind the dust gate to collateral the cleanup itself can reach rather than to any balance a stranger can inflate. Options:
- Make `clean_bad_debt` (and `check_bad_debt_after_liquidation`) socializable when collateral net of the most recent same-ledger top-up is ≤ the threshold, or snapshot/track the collateral delta attributable to third-party top-ups on insolvent accounts.
- Alternatively, treat the dust gate as debt-side only (e.g., socialize when residual *debt* ≤ threshold), or cap cleanup eligibility by collateral measured excluding positions whose last touch was a third-party `supply` after insolvency — storing a `last_third_party_supply_ledger` per account would let the gate ignore top-ups used only to straddle the bound.
- Cheapest mitigation that preserves the current shape: allow `clean_bad_debt` to first reclassify *all* remaining supply legs (it already converts collateral to revenue) and evaluate the dust gate on pre-top-up collateral — i.e., ignore supply credited to an already-insolvent account in the same block/after the insolvency was first provable.

/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));

    // Explicit +1 witness: one raw WAD unit above the cap blocks it.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(BAD_DEBT_USD_THRESHOLD + 2),
        Wad::from(BAD_DEBT_USD_THRESHOLD + 1)
    ));
}

/// Straddle, second half. The owner-gated force path
/// (`force_socialize_bad_debt`, `BadDebtGate::InsolventOnly`) admits exactly the straddling
/// state that `bad_debt_straddle_blocks_dust_gate` shows the dust gate rejects. The dust gate
/// does not cover the whole insolvent domain, so without the force path straddled bad debt
/// cannot be socialized.
#[rule]
fn bad_debt_straddle_admitted_by_force_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(debt_wad >= 0 && debt_wad <= 2_000_000 * WAD);
    cvlr_assume!(collateral_wad >= 0 && collateral_wad <= 2_000_000 * WAD);

    let debt = Wad::from(debt_wad);
    let collateral = Wad::from(collateral_wad);
    let dust_gate = is_socializable_bad_debt(debt, collateral);
    let force_gate = insolvent_gate_admits(debt, collateral);

    // Containment: the force gate is strictly looser, so it never rejects what the
    // permissionless path accepts.
    cvlr_assert!(!dust_gate || force_gate);

    // Anchor: the dust gate is exactly the force gate conjoined with the dust cap. Keeps the
    // mirrored `InsolventOnly` predicate from drifting away from production silently.
    cvlr_assert!(dust_gate == (force_gate && collateral_wad <= BAD_DEBT_USD_THRESHOLD));

    // The straddle separates the two gates: dust blocked, force admits.
    if collateral_wad > BAD_DEBT_USD_THRESHOLD && debt_wad > collateral_wad {
        cvlr_assert!(!dust_gate);
        cvlr_assert!(force_gate);
    }
