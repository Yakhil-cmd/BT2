## Analysis

The Rancher CVE's core issue is a **role-hierarchy invariant violation**: a broadly-granted role (`global-data`) was implicitly treated as containing narrower catalog write permissions it was never audited to include, so a low-privilege user could escalate by exploiting a shared role binding. The Polkadot SDK analog is `pallet_proxy`'s `is_superset` relation, which plays exactly the role-hierarchy role that gates `add_proxy`/`remove_proxy`: [1](#0-0) .

This exact bug class was already found and fixed for `asset-hub-westend` — `NonTransfer` falsely declared itself a superset of `Governance` (paritytech/polkadot-sdk#12724, fixed by [2](#0-1)  and [3](#0-2) ) and covered by regression tests [4](#0-3) .

However, the identical unfixed instance exists in `polkadot/runtime/rococo`, `polkadot/runtime/westend` (relay chain), and `substrate/frame/staking-async/runtimes/rc`, where `NonTransfer` is unconditionally declared a superset of *every* proxy type: [5](#0-4) 

while its own filter explicitly *excludes* `Registrar::swap`: [6](#0-5) 

but `ProxyType::Auction`'s filter admits *all* `Registrar` calls, including `swap`: [7](#0-6) 

Since `pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` purely on `is_superset` (not `filter`), a `NonTransfer` delegate can grant itself an `Auction` sub-proxy and then invoke `paras_registrar::swap`, a call its own `NonTransfer` filter comment explicitly says is "specifically omitting." The same pattern (`(ProxyType::NonTransfer, _) => true` plus `Auction => Registrar(..)` blanket match versus `NonTransfer`'s narrower register/deregister/reserve-only Registrar admission) repeats in `polkadot/runtime/westend/src/lib.rs` (lines 1022-1029, 1004-1010, 975-979) and `substrate/frame/staking-async/runtimes/rc/src/lib.rs` (lines 1410-1418, 1392-1398, 1356-1359).

`Registrar::swap` is gated by `ensure_root_para_or_owner`, so it accepts Root, the para's owner, or the para's own origin: [8](#0-7) . Because `do_proxy` dispatches with `RawOrigin::Signed(real)` (the delegator's own account) [9](#0-8) , if the delegator legitimately owns a registered para, the delegate — who was only granted `NonTransfer` — can reach `swap` via the self-escalated `Auction` proxy, letting them swap the delegator's parachain/parathread slot, auction info and deposits with another para: [10](#0-9) .

### Title
`NonTransfer` proxy falsely claims superset of `Auction`, letting a delegate reach `Registrar::swap` in rococo/westend/staking-async-rc runtimes - ([File: polkadot/runtime/rococo/src/lib.rs])

### Summary
`ProxyType::is_superset` in the `rococo`, relay-chain `westend`, and `staking-async` `rc` runtimes unconditionally declares `NonTransfer` a superset of every other `ProxyType`, including `Auction`. `Auction`'s call filter admits the entire `Registrar` call family (`RuntimeCall::Registrar { .. }` / `RuntimeCall::Registrar(..)`), while `NonTransfer`'s own filter deliberately omits `Registrar::swap`. Because `pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` solely via `is_superset` and not `filter`, a delegate holding only a `NonTransfer` proxy can add itself an `Auction` sub-proxy and then dispatch `Registrar::swap` — a call `NonTransfer` was specifically designed to deny.

### Finding Description
`pallet_proxy` treats `is_superset` as the authorization boundary for granting new proxy relationships: `def.proxy_type.is_superset(proxy_type)` must hold before `add_proxy`/`remove_proxy` on behalf of the real account is permitted [1](#0-0) . This means every `(A, B)` pair for which `A.is_superset(B) == true` must satisfy: every call admitted by `B.filter` must also be admitted by `A.filter`; otherwise `A` can grant itself `B` and reach calls `A.filter` denies.

In `rococo`'s `ProxyType`, this invariant is violated:
- `is_superset` declares `NonTransfer` a superset of everything: `(ProxyType::NonTransfer, _) => true` [5](#0-4) .
- `NonTransfer.filter` explicitly admits only `Registrar::register`, `deregister`, and `reserve`, with the code comment "Specifically omitting Registrar `swap`" [6](#0-5) .
- `Auction.filter` admits the entire `Registrar` pallet via a blanket match: `RuntimeCall::Registrar { .. }` [7](#0-6) .

So `NonTransfer.is_superset(Auction) == true`, but `Auction.filter` admits `Registrar::swap` while `NonTransfer.filter` denies it — the exact lattice violation that was already identified and fixed for `NonTransfer`/`Governance` on Asset Hub Westend (paritytech/polkadot-sdk#12724). The identical pattern (`NonTransfer, _) => true` superset plus a narrower `Registrar` admission than `Auction`'s blanket match) is also present, unpatched, in:
- `polkadot/runtime/westend/src/lib.rs` (relay chain), lines 1022-1029 (`is_superset`), 1004-1010 (`Auction`), 975-979 (`NonTransfer`'s `Registrar` admission).
- `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, lines 1410-1418 (`is_superset`), 1392-1398 (`Auction`), 1356-1359 (`NonTransfer`'s `Registrar` admission).

The attack path requires no privileged role: any account that has been delegated a `NonTransfer` proxy by a real account (a normal, permissionless `pallet_proxy::add_proxy` call by the real account) can perform the escalation entirely on its own.

### Impact Explanation
`Registrar::swap` swaps the on-demand/lease-holding status, auction info, and deposit accounting between two `ParaId`s, and is authorized for Root, the para owner, or the para's own origin [8](#0-7) . Because `do_proxy` dispatches the proxied call as `RawOrigin::Signed(real)` [9](#0-8) , a `NonTransfer` delegate of a para-owning account can reach `swap` on the owner's behalf despite the runtime's explicit design decision to keep `swap` outside `NonTransfer`'s reach. This lets a partially-trusted delegate unilaterally alter which `ParaId` holds a lease/slot and associated deposits for an account that only intended to grant it non-transfer-related permissions — an unauthorized-dispatch/integrity break of the parachain registrar state, exceeding the explicitly documented boundary of the delegated authority.

### Likelihood Explanation
Likelihood is high for any account operator that uses the standard `NonTransfer` proxy pattern (common for cold/hot key separation) on rococo, relay-chain westend, or staking-async `rc`, and who also owns a registered para. The escalation requires two ordinary, permissionless extrinsics (`Proxy::add_proxy` for `Auction`, then `Proxy::proxy` wrapping `Registrar::swap`) with no governance, root, or additional privilege needed.

### Recommendation
Apply the same fix pattern used in `pr_12769`/`pr_12771` for `asset-hub-westend`: either (a) remove the blanket `(ProxyType::NonTransfer, _) => true` and enumerate only the subsets whose filters are fully contained in `NonTransfer`'s filter, or (b) extend `NonTransfer.filter` to admit every `Registrar` call that `Auction.filter` admits (including `swap`) if that is actually the intended policy. Add a lattice-verifying regression test analogous to `proxy_type_superset_relation_matches_call_filters` [11](#0-10)  to `polkadot/runtime/rococo`, `polkadot/runtime/westend`, and `substrate/frame/staking-async/runtimes/rc` to prevent regressions of this class.

### Proof of Concept
Static verification (file:line evidence, no live network execution):
1. `NonTransfer.is_superset(Auction)` returns `true` via the catch-all arm [12](#0-11) .
2. `Auction.filter(Registrar::swap{..})` returns `true` via the blanket `RuntimeCall::Registrar { .. }` arm [13](#0-12) .
3. `NonTransfer.filter(Registrar::swap{..})` returns `false` since only `register`/`deregister`/`reserve` are listed, with `swap` explicitly commented as omitted [6](#0-5) .
4. `do_proxy` uses only `is_superset` to authorize `add_proxy` [1](#0-0) , so step 1 lets a `NonTransfer` delegate add itself as an `Auction` delegate for the same real account, then dispatch `Registrar::swap` through that `Auction` proxy, which step 2 admits.

Minimal reproduction sketch (integration test, following the existing pattern at `paras_registrar/tests.rs` `swap_works`/`asset-hub-westend` proxy tests) would: create a `NonTransfer` proxy from account `A` (para owner of `id`) to `B`; have `B` call `Proxy::proxy(A, None, Proxy::add_proxy(B, Auction, 0))` (succeeds because of the superset bug); have `B` call `Proxy::proxy(A, None, Registrar::swap(id, other))` and observe it dispatches (not filtered), whereas a direct `Proxy::proxy(A, None, Registrar::swap(...))` under the `NonTransfer` proxy alone would be rejected by `CallFiltered`. I did not execute this against a live/test network in this analysis — the finding is derived from exact filter/superset code inspection across `rococo`, `westend`, and `staking-async/rc` runtimes, mirroring the previously-confirmed and fixed `asset-hub-westend` instance of the same bug class.

/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
