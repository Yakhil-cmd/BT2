The reported CVE describes a Python-specific insecure deserialization (pickle-based) RCE in `restore_checkpoint`, which has no structural analog in the polkadot-sdk Rust/FRAME codebase. Deserialization in this codebase (SCALE `Decode`, `TryDecodeEntireStorage`) does not execute arbitrary code on malformed input by design — it either succeeds or fails deterministically with an error, as seen in [1](#0-0)  and [2](#0-1) .

The only genuinely dangerous deserialization primitives found are the `unsafe` wasmtime artifact deserialization functions used by the PVF executor, e.g. `create_runtime_from_artifact_bytes` and `Module::deserialize`, whose doc comments explicitly warn that a modified/untrusted compiled artifact "might lead to crashes and arbitrary code execution" [3](#0-2) [4](#0-3) . However, these artifacts are produced and consumed internally by the trusted PVF "prepare" worker pipeline rather than being decoded from arbitrary user-supplied extrinsic/XCM payloads reachable by an unprivileged actor, so there is no demonstrable permissionless entry point satisfying the required threat model (a real signed extrinsic, enabled contract call, or permitted XCM message providing attacker-controlled bytes into this code path).

Since no unprivileged, reachable entry point maps attacker-controlled input into unsafe/arbitrary-code-executing deserialization in this codebase, this report does not have a supported Polkadot SDK analog.
