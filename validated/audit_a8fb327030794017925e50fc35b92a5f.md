### Title
Unbounded native-JS-stack recursion in `hasReferences` causes stack overflow / node crash when writing a unit with deeply nested address definition - (File: definition.js)

### Summary
`hasReferences()` in `definition.js` is invoked from `writer.saveJoint()` for every author definition of every unit being committed to the DB, and also from `aa_addresses.js` when fetching a remote AA definition. It recurses directly (no depth counter, no `setImmediate` yielding, no reuse of the `MAX_COMPLEXITY`/`MAX_OPS` limits enforced earlier in `validateDefinition`) over `'or'`/`'and'`/`'r of set'`/`'weighted and'`/`'not'` nodes of the definition array. An attacker who can get a syntactically-valid but deeply nested address definition through `validateDefinition`/`validateAuthentifiers` (which do impose `MAX_COMPLEXITY` = a bound on total node count, but that bound still allows enough nested single-branch `'not'`/`'and'` wrapping to exceed Node's default call-stack depth, e.g. ~10,000+ levels of `['not', [...]]`) will cause `hasReferences` to blow the V8 call stack with `RangeError: Maximum call stack size exceeded` while `writer.saveJoint` is executing inside a DB transaction.

### Finding Description
Unlike the definition-evaluation code paths in `definition.js` (`validateDefinition`'s `evaluate`, `validateAuthentifiers`'s `evaluate`) and in `aa_validation.js`/`formula/validation.js`, which explicitly protect against deep recursion via `count % 100 → setImmediate` interruption of the call stack and/or explicit `depth > MAX_DEPTH` checks, the `hasReferences` function added later for the `has_references` column optimization does none of that: [3](#0-2) 
It is a purely synchronous, self-recursive function reached through `'not'` wrapping (single-argument recursion, `evaluate(args)`), `'and'`/`'or'` (array iteration + recursion), and `'r of set'`/`'weighted and'` (`.set` array iteration + recursion). A definition composed almost entirely of nested `['not', [...]]` wrappers costs only 1 complexity/op unit per level in `validateDefinition`'s `evaluate` (since `'not'` just forwards to `evaluate(args, ...)` without adding branching factor), so an attacker can construct a definition that stays under `constants.MAX_COMPLEXITY`/`MAX_OPS` while nesting deep enough (thousands of levels) to exceed V8's default stack limit purely in `hasReferences`, which has no such interrupt mechanism.

This function is invoked:
1. In `writer.js` for the definition of every unit author whenever a new definition is written, inside the DB write transaction: [4](#0-3) 
2. In `aa_addresses.js` when caching a remote/light-fetched non-AA address definition: [5](#0-4) 

Because `hasReferences` runs synchronously to completion (or crash) without yielding, and definitions of this shape pass `validateDefinition`/`validateAuthentifiers` validation earlier in the pipeline (those functions do interrupt the stack via `setImmediate` at every 100 ops, so they don't crash), the crash only manifests downstream in `writer.saveJoint`, at a point where the node is mid-transaction on a unit it already decided was valid.

### Impact Explanation
An unhandled `RangeError: Maximum call stack size exceeded` thrown synchronously inside `writer.saveJoint` (called from the unit-acceptance pipeline in `network.js`'s `handleJoint`) is not caught by any `try/catch` in that call chain, since it originates deep inside a plain function call, not inside a promise/callback boundary that expects errors. This crashes the Node.js process for any full node (hub or peer) that processes/relays such a unit, and equally affects the light-vendor path in `aa_addresses.js`. Because every node that receives and validates the malicious unit reaches the same crash, this can be used to repeatedly crash multiple/all full nodes on the network processing the unit — a network-wide denial of service, matching the "network unable to confirm new units" impact bucket.

### Likelihood Explanation
Any unprivileged party can post a unit with a new address (author `definition`) shaped as deeply nested `['not', [...]]`/`['and', [...]]` wrappers around a terminal `sig`/`hash` leaf; this is ordinary unit-posting functionality, requires no special privileges, hub cooperation, or existing balance beyond what's needed to pay for posting a unit. The complexity/op bound (`MAX_COMPLEXITY`, `MAX_OPS`) enforced by `validateDefinition` does not prevent sufficiently deep single-branch nesting since each `'not'`/`'and'`-with-2-branches level only adds a small, constant amount to complexity/op counts, so a depth in the thousands is well within the allowed budget while still exceeding V8's default stack frame limit.

### Recommendation
Rewrite `hasReferences` (and its `evaluate` inner function) to use the same stack-interruption pattern already used elsewhere in the file (`count`/`setImmediate` yielding as in `validateDefinition`'s `evaluate`, or an explicit `depth`/`MAX_DEPTH` bound as used in `aa_validation.js`'s `validate`), or convert it to an explicit iterative worklist/stack-based traversal instead of native recursion, and enforce a maximum nesting depth consistent with the depth already implicitly bounded elsewhere in address/AA definition validation.

### Proof of Concept
1. Construct an address definition of the form:
```js
let def = ['sig', {pubkey: '<valid pubkey>'}];
for (let i = 0; i < 50000; i++)
    def = ['not', ['not', def]]; // 'not' of 'not' keeps bHasSig semantics for the outer branch while adding depth
```
(Exact wrapping needs to keep `validateAuthentifiers`'s top-level "must have a signature branch" requirement satisfiable — e.g., wrap the whole thing once more in `['or', [def, ['sig', {...}]]]` so the top-level structure still resolves to a valid signature branch while the inner `def` subtree is only reached by `hasReferences`, which recurses unconditionally regardless of `bInNegation`/short-circuiting.)
2. Post a unit whose author uses this address for the first time, with a valid `definition` field and a valid `authentifiers` entry for whatever leaf signature branch is required.
3. The unit passes `validateAuthentifiers`/`validateDefinition` (bounded ops, stack-safe recursion with `setImmediate` yielding).
4. When the unit reaches `writer.saveJoint`, `Definition.hasReferences(definition)` is called synchronously on the same deeply nested structure, causing a `RangeError: Maximum call stack size exceeded` that crashes the node process handling the unit.

function hasReferences(arrDefinition){
	
	function evaluate(arr){
		var op = arr[0];
		var args = arr[1];
	
		switch(op){
			case 'or':
			case 'and':
				for (var i=0; i<args.length; i++)
					if (evaluate(args[i]))
						return true;
				return false;
				
			case 'r of set':
				for (var i=0; i<args.set.length; i++)
					if (evaluate(args.set[i]))
						return true;
				return false;
				
			case 'weighted and':
				for (var i=0; i<args.set.length; i++)
					if (evaluate(args.set[i].value))
						return true;
				return false;
				
			case 'sig':
			case 'hash':
			case 'cosigned by':
			case 'has definition change':
				return false;
				
			case 'not':
				return evaluate(args);
				
			case 'address':
			case 'definition template':
			case 'seen address':
			case 'seen':
			case 'in data feed':
			case 'in merkle':
			case 'mci':
			case 'timestamp':
			case 'age':
			case 'has':
			case 'has one':
			case 'has equal':
			case 'has one equal':
			case 'sum':
			case 'attested':
			case 'seen definition change':
			case 'formula':
				return true;
				
			default:
				throw Error("unknown op: "+op);
		}
	}
	
	return evaluate(arrDefinition);
}
