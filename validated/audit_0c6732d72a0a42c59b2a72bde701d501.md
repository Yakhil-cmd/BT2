### Title
Market-wide permanent freeze from unscaled `Ray` value overflow before the borrow-index cap - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
A sufficiently large and heavily borrowed market can overflow `i128` during interest synchronization while its borrow index is still below `MAX_BORROW_INDEX_RAY`. Because every pool mutation synchronizes interest before applying the requested operation, the failed accrual permanently blocks repayment, withdrawal, liquidation, and further index updates for that market.

### Finding Description
Each pool operation loads the market through `ops::synced_market`, which calls `interest::global_sync` before performing the action. [1](#0-0)  `global_sync` repeatedly executes `accrue_step` until the stored timestamp reaches the current ledger time. [2](#0-1)  `accrue_step` unscales aggregate debt and supply with `scaled_to_original` before calculating utilization. [3](#0-2)  That helper performs `scaled.mul(env, index)`, which panics when the raw product exceeds `i128::MAX`. [4](#0-3) 

The borrow-index ceiling is applied only after multiplying the old index by the interest factor. [5](#0-4)  It therefore does not bound the pre-existing value `borrowed * borrow_index` read on the next accrual. For an extremely large debt book, the index can reach `i128::MAX / borrowed` while remaining below `1e36`; the next sync then panics before any cap can stop interest accrual.

The production test proves the concrete state: a 1-billion-token, 18-decimal market at 98% utilization eventually makes `update_indexes` return `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `withdraw` and `repay` calls fail with the same error. [6](#0-5) 

### Impact Explanation
This is a permanent freezing-of-funds condition for the affected hub market. Once aggregate scaled debt is large enough that the next index makes `borrowed * borrow_index` exceed `i128::MAX`, no path can advance `last_timestamp` past the failing step. Since repayment, withdrawal, liquidation settlement, flash operations, and recapitalization all load a synced market, the shared failure blocks both suppliers trying to exit and borrowers or liquidators trying to reduce debt.

The resulting freeze is market-wide rather than limited to the attacker's account. The test explicitly demonstrates that both supplier withdrawal and borrower repayment fail after the overflow. [7](#0-6) 

### Likelihood Explanation
The attack requires a very large market and sustained high utilization, so it is not practical in ordinary-sized deployments. It is still reachable by unprivileged controller calls: an attacker supplies a large listed asset through `supply`, borrows a large fraction through `borrow` after posting collateral, and lets utilization and time grow the index. If governance leaves sufficiently high caps on a high-decimal market, the configured caps need not prevent the required scale. The regression test reaches the condition through ordinary supply and borrow flows after raising test caps. [8](#0-7) 

### Recommendation
Bound the unscaling inputs before multiplication rather than relying only on the index ceiling. In particular:

- reject or clamp market entries so `borrowed * MAX_BORROW_INDEX_RAY` and `supplied * MAX_SUPPLY_INDEX_RAY` cannot exceed the supported `Ray`/`i128` domain;
- make `global_sync` stop at the index cap without evaluating a new utilization whose unscaling overflows;
- enforce a pool-level aggregate share ceiling at admission based on the maximum admitted index, not merely token-unit caps;
- add production regression coverage equivalent to the large-market test for `supply`, `withdraw`, `repay`, `liquidate`, and `recapitalize` after the boundary.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
