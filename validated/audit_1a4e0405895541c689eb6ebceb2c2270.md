### Title
Case/Unicode-normalization collisions in discovered skill names bypass overwrite protection and cause silent cross-skill file overwrite - ([File: internal/skills/discovery/discovery.go], [File: internal/skills/installer/installer.go], [File: pkg/cmd/skills/install/install.go])

### Summary
`DiscoverSkillsWithOptions` dedupes matched skill directories using exact byte-string equality (`seen[m.skillDir]`), and skill names are validated only against `safeNamePattern` which permits mixed-case names (letters, digits, `._- `). Because the resulting `Skill.Name` (not a normalized/lowercased form) is used verbatim to build the install destination via `filepath.Join(baseDir, skill.Name)`, two attacker-crafted tree entries whose directory names differ only by case (or Unicode normalization form) produce two distinct `Skill` entries that are never recognized as colliding, either during discovery or during the install-time `checkOverwrite` pre-check — yet on a case-insensitive or normalization-folding filesystem (default macOS APFS, Windows NTFS) they resolve to the same on-disk directory, letting one skill's files silently overwrite another's within a single install run.

### Finding Description
`matchSkillConventions`/`matchHiddenDirConventions` derive `skillName` from `path.Base(dir)` and validate it with `safeNamePattern = ^[a-zA-Z0-9][a-zA-Z0-9._\- ]*$` [1](#0-0)  — this pattern accepts letters of any case, so `skills/Foo/SKILL.md` and `skills/foo/SKILL.md` both validate as distinct names "Foo" and "foo".

In `DiscoverSkillsWithOptions`, the dedup key is the raw tree path string `m.skillDir`, so these two entries are byte-distinct and both survive into `matches`, producing two separate `Skill{Name: "Foo", ...}` and `Skill{Name: "foo", ...}` entries: [2](#0-1) 

Neither downstream consumer normalizes the name for filesystem-collision purposes:
- `checkOverwrite` in the install command stats `filepath.Join(targetDir, s.Name)` for each candidate skill up front, before any of the batch is installed, so if the target directory is otherwise empty both "Foo" and "foo" are classified as fresh (non-existing) and neither triggers the "already installed" prompt/error path: [3](#0-2) 
- `installSkill` / `installLocalSkill` then call `os.MkdirAll(filepath.Join(baseDir, skill.Name), 0o755)` and write files under that directory verbatim, using the un-normalized name: [4](#0-3) [5](#0-4) 

On a case-insensitive (or Unicode-normalization-folding) filesystem, `MkdirAll("…/Foo")` followed by `MkdirAll("…/foo")` in the same run resolves to the identical on-disk directory. The second skill's file writes (`os.WriteFile(destPath, …)`) land in the same directory as the first, silently overwriting any same-named files (e.g. `SKILL.md`) from the first skill with content from the attacker's second, differently-cased directory — with no error, prompt, or warning, because the collision was never detected at the string level that `seen` and `checkOverwrite` operate on.

### Impact Explanation
This allows an attacker who publishes a repository (or a fork/branch/PR the victim points `gh skill install` at) to smuggle two "skills" with visually/case-distinct directory names that alias to one filesystem path on the victim's machine. When the victim installs both (e.g. via a multi-select or `--all`-style flow, or sequential installs into the same target directory), one skill's `SKILL.md`/files silently overwrite the other's, without any of the existing overwrite-confirmation UX firing. This is a file-write-outside-intended-scope condition (the installer writes to a directory the discovery/overwrite logic believed was a different, unrelated skill), matching GitHub's "arbitrary file write/overwrite outside intended path" bounty impact class. The severity is bounded: it does not itself grant remote code execution, but it can be used to corrupt or replace the content of a co-installed skill (which the agent will subsequently trust/execute), amplifying its effective impact.

### Likelihood Explanation
Requires: (1) the victim to run `gh skill install` against an attacker-controlled repo/ref containing two directories whose names differ only in case or Unicode normalization form, and (2) the victim's target filesystem to be case-insensitive or normalization-folding (true by default on macOS and Windows, not on typical Linux ext4). It also requires the victim to select/install both colliding skills in a context where neither previously existed on disk (fresh install or first-time multi-skill batch), which is a common flow (`gh skill install owner/repo` discovering multiple skills, or `--all`). No elevated privileges, tokens, or social engineering beyond publishing a public repository are needed, making this moderately likely on the affected platforms but not universally reproducible (Linux hosts with case-sensitive filesystems are unaffected).

### Recommendation
- Normalize skill names for collision detection: lowercase (or apply Unicode NFC normalization) both when computing the discovery dedup key and when performing the `checkOverwrite` on-disk existence check, so visually- or case-colliding names are treated as the same target.
- Consider tightening `safeNamePattern` to require the stricter `specNamePattern` (lowercase-only) for filesystem-derived install names, eliminating case-based collisions entirely.
- In `checkOverwrite`/install execution, re-stat (or track already-created directories in-memory) immediately before each individual skill's `MkdirAll`/write, rather than only performing a single upfront batch check, to catch collisions introduced by the current install batch itself.

```go
func TestDiscoverSkillsWithOptions_CaseCollision(t *testing.T) {
    // tree containing "skills/Foo/SKILL.md" and "skills/foo/SKILL.md"
    tree := treeResponse{Tree: []treeEntry{
        {Path: "skills/Foo/SKILL.md", Type: "blob", SHA: "sha1"},
        {Path: "skills/Foo", Type: "tree", SHA: "treeFoo"},
        {Path: "skills/foo/SKILL.md", Type: "blob", SHA: "sha2"},
        {Path: "skills/foo", Type: "tree", SHA: "treeLowerFoo"},
    }}
    // ... stub client.REST to return `tree` ...
    skills, err := DiscoverSkillsWithOptions(client, host, owner, repo, "sha", DiscoverOptions{})
    require.NoError(t, err)
    require.Len(t, skills, 2) // "Foo" and "foo" both survive dedup

    // Simulate installer.installSkill sequentially into the same baseDir
    // on a case-insensitive filesystem (or use a case-folding stub FS):
    baseDir := t.TempDir()
    require.NoError(t, installSkill(optsFor(skills[0]), skills[0], baseDir)) // writes .../Foo/SKILL.md
    require.NoError(t, installSkill(optsFor(skills[1]), skills[1], baseDir)) // writes .../foo/SKILL.md -> same dir on case-insensitive FS

    // Assert: only one directory exists on disk, and its SKILL.md content
    // now matches skills[1]'s content, silently clobbering skills[0]'s file
    // -- demonstrating the checkOverwrite/seen dedup never flagged the collision.
}
```
Expected assertion: on a case-insensitive filesystem, exactly one on-disk skill directory exists after both installs, its content reflects the second skill's blob, and no error/prompt was raised for either install call — confirming the silent overwrite.

```go
func checkOverwrite(opts *InstallOptions, skills []discovery.Skill, targetDir string, canPrompt bool) ([]discovery.Skill, error) {
	var existing, fresh []discovery.Skill
	for _, s := range skills {
		dir := filepath.Join(targetDir, s.Name)
		if _, err := os.Stat(dir); err == nil {
			existing = append(existing, s)
		} else {
			fresh = append(fresh, s)
		}
	}

	if len(existing) == 0 {
		return skills, nil
	}

	if opts.Force {
		return skills, nil
	}
```
