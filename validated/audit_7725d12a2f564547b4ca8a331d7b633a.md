### Title
Permanent freezing of pool creator fees if the creator's token account is frozen/blacklisted - (File: programs/cp-swap/src/instructions/collect_creator_fee.rs, collect_creator_fee_permissionless.rs)

### Summary
`collect_creator_fee` and `collect_creator_fee_permissionless` both hard-code the fee recipient to an associated token account (ATA) whose authority is fixed to `pool_state.pool_creator`. There is no mechanism in the program to redirect these fees to a different account or update `pool_creator`. If the mint used is a token with issuer-controlled blacklisting (e.g. USDC/USDT via Token-2022 "permanent delegate"/freeze authority, or classic SPL freeze authority), and the creator's ATA gets frozen/blacklisted, the accrued `creator_fees_token_0`/`creator_fees_token_1` become permanently unclaimable, exactly analogous to the referenced TellerV2 issue where collateral is sent to a hard-coded borrower address.

### Finding Description
`CollectCreatorFee` and `CollectCreatorFeePermissionless` both constrain the destination accounts as ATAs owned by the immutable `pool_creator` field: [2](#0-1) [3](#0-2) 

Both instructions call `transfer_from_pool_vault_to_user` targeting these fixed ATAs and then zero out the accumulated fee counters only after a successful transfer: [4](#0-3) [5](#0-4) 

`pool_creator` is stored once in `PoolState` at pool creation [1](#0-0)  and there is no admin or user instruction anywhere in `programs/cp-swap/src/instructions` that permits updating it or specifying an alternate recipient for creator fees.

By contrast, `Withdraw` allows the LP to supply an arbitrary destination token account (`token_0_account`/`token_1_account` are only constrained by mint, not by owner) [6](#0-5) , so ordinary LP withdrawals are not affected by this issue — only the pool-creator fee collection path is.

### Impact Explanation
If the pool creator's ATA for token_0 or token_1 becomes frozen/blacklisted by the token issuer (a realistic scenario for USDC/USDT-style tokens with freeze/blacklist authority), both `collect_creator_fee` and `collect_creator_fee_permissionless` will permanently revert on transfer to that ATA. `creator_fees_token_0`/`creator_fees_token_1` will keep accumulating in the pool vault with no way to ever be withdrawn, since the recipient is hard-coded and immutable. This is a permanent freezing of LP/pool-creator funds, matching the report's root cause and impact category.

### Likelihood Explanation
Requires the specific token mint used by the pool to have a freeze/blacklist authority and the pool creator's account to actually become frozen — a low-probability but externally-triggerable and irreversible event, consistent with the Medium severity rated in the original report.

### Recommendation
Allow the pool creator to specify/update an alternate destination account (or authority) for creator fee collection, or allow `collect_creator_fee` to target any token account chosen by (and signed for by) the creator rather than a fixed ATA derived from `pool_creator`, similar to how `Withdraw`'s destination accounts are caller-supplied.

### Proof of Concept
1. Initialize a pool with a Token-2022 mint that has freeze authority (or a mint controlled by an issuer capable of blacklisting), with `creator` as the pool creator.
2. Perform swaps so that `creator_fees_token_0`/`creator_fees_token_1` accumulate in `pool_state`.
3. Have the mint's freeze authority freeze the `creator`'s associated token account for that mint.
4. Call `collect_creator_fee` or `collect_creator_fee_permissionless` — the transfer CPI to the frozen `creator_token_0`/`creator_token_1` account fails, reverting the instruction.
5. Since `pool_creator` is immutable and no instruction exists to redirect the recipient, the accrued creator fees remain permanently locked in the pool vault.

pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;

    Ok(())
}
