### Title
Webhook signature scoping uses `repository.owner.login` while stack resolution uses `repository.full_name`, letting one configured org's webhook_secret authorize sync of another org's stack - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp`/`webhook_secret` to validate against using `repository_owner` (`params.dig('repository','owner','login')`), while `Handler#stacks` resolves the target `Stack` using `repository_name` (`payload.dig('repository','full_name')`) — a separate, independently attacker-controlled field in the same unsigned-until-verified JSON body. In a multi-org `secrets.yml` configuration, an attacker who legitimately controls one configured organization's GitHub App/webhook_secret can sign a payload whose `repository.owner.login` matches their own org (so signature verification passes) but whose `repository.full_name` points to a different, victim organization's repository, causing `PushHandler#process` to call `stack.sync_github` for a stack that does not belong to the org that authenticated the request.

### Finding Description
The broken binding: the equality the security model requires is `repository_owner_used_for_signature == owner_of(repository_full_name_used_for_stack_lookup)`. Tracing the code shows these are two independent reads of the same untrusted payload with no cross-check tying them together.

- `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0)  and uses it to select the `GitHubApp` config: `Shipit.github(organization: repository_owner)` [2](#0-1) .
- `Shipit.github` / `github_app_config` looks the org name up (case-insensitively) in `secrets.github`, returning that org's own `app_id`/`webhook_secret`/`private_key` in the documented multi-org configuration schema [3](#0-2) .
- `GitHubApp#verify_webhook_signature` only HMACs the raw body against that org's `webhook_secret` — it never checks that the body's `repository.full_name` prefix matches the org whose secret validated it [4](#0-3) .
- Once the request passes, `Handler#stacks` resolves the target using a *different* field: `payload.dig('repository', 'full_name')` fed into `Repository.from_github_repo_name`, which downcases and splits it into `owner/name` for the `find_by` lookup [5](#0-4) [6](#0-5) .
- `PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` on every matching, non-archived stack for the resolved branch [7](#0-6) , which enqueues `GithubSyncJob` to fetch and append real commits from GitHub into that (victim-owned) stack, using the *victim's* stored GitHub credentials via `stack.github_api`/`stack.github_commits`, not the attacker's [8](#0-7) .

Exploit flow (requires the documented multi-organization `secrets.yml` schema, i.e., the operator has configured separate GitHub Apps/webhook_secrets per organization, as in docs/setup.md's "Using Multiple Github Applications" section): an attacker who legitimately controls org `attacker-org` (and thus its `webhook_secret`, e.g. by triggering a real webhook and/or by directly crafting a signed POST) sends `POST /webhooks` with:
```json
{
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>"
}
```
signed with `attacker-org`'s `webhook_secret`. `verify_signature` picks and validates against `attacker-org`'s secret and passes; `Handler#stacks` then resolves `victim-org/victim-repo` and syncs that stack.

Existing guards do not stop this: `verify_signature` only checks HMAC validity for whichever org is named in `repository.owner.login`, never that this org equals the owner segment of `repository.full_name`; `drop_unhandled_event` and `ExplicitParameters` schemas (`PushHandler` only requires `ref`/`after`) don't touch this field; `Repository.from_github_repo_name`/`Stack` validations only constrain format, not cross-tenant ownership.

### Impact Explanation
This lets an org onboarded onto a shared multi-tenant Shipit instance force `GithubSyncJob` to run against a different tenant's `Stack`, appending attacker-influenced-timing (though not attacker-influenced content, since commits are fetched live from GitHub via the victim's own installation) commit records, potentially disrupting `undeployed_commits`, triggering `CacheDeploySpecJob`, and (per `PushHandler`) marking the victim stack's sync state — i.e., a payload for one repository mutating another organization's stack. This matches "a payload for one repository mutating another's stack" under the Critical bucket. Repeatable against any stack whose `full_name` the attacker can guess, across every other tenant configured on the same Shipit instance (blast radius = all orgs sharing the instance), not just one.

### Likelihood Explanation
Requires: (1) the operator to run the multi-org `secrets.yml` schema with more than one org configured, and (2) the attacker to be one of those legitimately-configured, trusted organizations (with a valid `app_id`/`webhook_secret` of their own) — this is a real, documented deployment pattern for multi-tenant Shipit installations, not a hypothetical misconfiguration. Given those (documented, supported) preconditions, exploitation costs only crafting one JSON body and computing an HMAC-SHA1 with a secret the attacker legitimately possesses; it is fully repeatable and requires no cooperation from GitHub or the victim.

### Recommendation
In `Handler#stacks`/`repository_name`, cross-check that the resolved repository's owner matches the organization whose `webhook_secret` verified the request (thread the verified `repository_owner` from the controller into the handler and assert `repository_name.split('/').first.casecmp?(repository_owner)` before resolving/acting on the stack), rejecting/logging mismatches instead of silently syncing.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "signature valid for attacker-org does not authorize syncing victim-org's stack" do
  # Two orgs configured with distinct webhook secrets in secrets.github
  Shipit.stubs(:github_default_organization).returns('attacker-org')
  attacker_app = Shipit::GitHubApp.new('attacker-org', webhook_secret: 'attacker-secret')
  Shipit.stubs(:github).with(organization: 'attacker-org').returns(attacker_app)

  victim_stack = shipit_stacks(:shipit) # owned by repository victim-org/victim-repo
  payload = {
    "ref" => "refs/heads/#{victim_stack.branch}",
    "after" => "deadbeef",
    "repository" => { "owner" => { "login" => "attacker-org" }, "full_name" => victim_stack.repository.full_name }
  }.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest('sha1', 'attacker-secret', payload)
  @request.headers['X-Github-Event'] = 'push'
  @request.headers['X-Hub-Signature'] = signature

  # Assertion: signature validates for attacker-org (left side of the broken equality)
  assert attacker_app.verify_webhook_signature(signature, payload)

  # Assertion: yet the stack acted upon belongs to victim-org, not attacker-org (right side)
  assert_not_equal 'attacker-org', victim_stack.repository.owner

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: "deadbeef"]) do
    post :create, body: payload, as: :json
  end
end
```
This demonstrates that only signature validity (tied to `repository.owner.login`) gates execution, with no check that it equals the owner embedded in `repository.full_name` used to pick the acted-upon `Stack`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
