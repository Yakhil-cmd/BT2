### Title
Staking Reward Overwrite via Map Assignment Instead of Accumulation in `assignStakingRewards` / `assignStakingRewardsFlex` — (`kaiax/reward/impl/getter.go`)

---

### Summary

Both `assignStakingRewards` and `assignStakingRewardsFlex` build a local `alloc` map using direct assignment (`=`) rather than accumulation (`+=`). When a `CLPoolAddr` of one consolidated node equals the `RewardAddr` of another consolidated node (or equals the same CN's own `RewardAddr`), the second write silently overwrites the first, destroying the earlier allocation. The destroyed amount is never credited to any address, causing a permanent loss of KAIA staking rewards every block the collision is present.

---

### Finding Description

In `assignStakingRewards` (Prague path):

```go
if isPrague && cn.CLStakingInfo != nil {
    cnAmount, clAmount := cn.Split(reward)
    alloc[cn.RewardAddr] = cnAmount                    // line 524 — assignment
    alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount      // line 525 — assignment
} else {
    alloc[cn.RewardAddr] = reward                      // line 527 — assignment
}
``` [1](#0-0) 

The identical pattern exists in `assignStakingRewardsFlex`: [2](#0-1) 

`consolidateNodes()` guarantees that each `consolidatedNode` has a unique `RewardAddr`, so `alloc[cn.RewardAddr]` does not collide across iterations. However, `CLPoolAddr` is a separate address sourced from the CLRegistry and is subject to no uniqueness constraint relative to other validators' `RewardAddr` values. [3](#0-2) 

If `CN_A.CLStakingInfo.CLPoolAddr == CN_B.RewardAddr`, then:

1. Iteration for CN_A: `alloc[CN_A.RewardAddr] = cnAmount_A`, `alloc[CN_A.CLPoolAddr] = clAmount_A`
2. Iteration for CN_B: `alloc[CN_B.RewardAddr] = reward_B` — **overwrites** `clAmount_A`

`remaining` is correctly decremented by both `reward_A` and `reward_B`, so the accounting variable is consistent, but the `alloc` map entry for that address holds only `reward_B`. `clAmount_A` is never credited to anyone.

`FinalizeState` then calls `state.AddBalance(addr, amount)` for each entry in `spec.Rewards`, so the destroyed `clAmount_A` is never minted to any account. [4](#0-3) 

The same overwrite can occur within a single CN's iteration if `cn.CLStakingInfo.CLPoolAddr == cn.RewardAddr`: the `cnAmount` assignment on line 524 is immediately overwritten by the `clAmount` assignment on line 525.

By contrast, `IncRecipient` — used everywhere else in the reward pipeline — correctly accumulates: [5](#0-4) 

---

### Impact Explanation

Every block in which the address collision is present, the CL-pool portion of staking rewards (`clAmount_A`) is silently destroyed — never added to any account's balance. This is an unauthorized burn of KAIA staking rewards affecting system-managed funds. The loss is proportional to the CL staking amount of the affected validator and repeats every block.

---

### Likelihood Explanation

The collision requires `CLPoolAddr` of one validator to equal `RewardAddr` of another validator (or the same validator). `CLPoolAddr` values are registered in the CLRegistry system contract; `RewardAddr` values are registered in AddressBook / AddressBookV2. No on-chain constraint prevents overlap. A validator who deliberately or accidentally registers a reward address matching an existing CL pool address triggers the bug. The likelihood is low in a well-operated network but is not prevented by any protocol-level guard.

---

### Recommendation

Replace direct map assignment with accumulation in both functions:

```go
// Instead of:
alloc[cn.RewardAddr] = cnAmount
alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount

// Use:
if _, ok := alloc[cn.RewardAddr]; !ok {
    alloc[cn.RewardAddr] = new(big.Int)
}
alloc[cn.RewardAddr].Add(alloc[cn.RewardAddr], cnAmount)

if _, ok := alloc[cn.CLStakingInfo.CLPoolAddr]; !ok {
    alloc[cn.CLStakingInfo.CLPoolAddr] = new(big.Int)
}
alloc[cn.CLStakingInfo.CLPoolAddr].Add(alloc[cn.CLStakingInfo.CLPoolAddr], clAmount)
```

Apply the same fix to `assignStakingRewardsFlex`. Additionally, add a validation step in `consolidateNodes` or in the staking-info parsing layer to reject or warn when `CLPoolAddr` overlaps with any registered `RewardAddr`.

---

### Proof of Concept

**Setup (Prague hardfork active, `reward.deferredtxfee = true`, `istanbul.policy = WeightedRandom`):**

- Validator A: `NodeId = N_A`, `RewardAddr = 0xAAAA`, `StakingAmount = 6_000_000 KAIA`, `CLPoolAddr = 0xBBBB`, `CLStakingAmount = 1_000_000 KAIA`
- Validator B: `NodeId = N_B`, `RewardAddr = 0xBBBB` (same as A's CLPoolAddr), `StakingAmount = 6_000_000 KAIA`, no CL

**Execution of `assignStakingRewards`:**

1. `cns` = `[{RewardAddr: 0xAAAA, StakingAmount: 6M, CLPoolAddr: 0xBBBB, CLStakingAmount: 1M}, {RewardAddr: 0xBBBB, StakingAmount: 6M, CLStakingInfo: nil}]`
2. Iteration CN_A: `reward_A` computed; `Split` yields `cnAmount_A ≈ 6/7 * reward_A`, `clAmount_A ≈ 1/7 * reward_A`; `alloc[0xAAAA] = cnAmount_A`; `alloc[0xBBBB] = clAmount_A`
3. Iteration CN_B: `reward_B` computed; `alloc[0xBBBB] = reward_B` — **overwrites** `clAmount_A`
4. Returned `alloc`: `{0xAAAA: cnAmount_A, 0xBBBB: reward_B}`
5. `FinalizeState` credits `0xAAAA` with `cnAmount_A` and `0xBBBB` with `reward_B`; `clAmount_A` is never credited to anyone

`clAmount_A` (≈ 1/7 of Validator A's staking reward) is permanently destroyed every block. [6](#0-5) [7](#0-6) [8](#0-7)

func (si *StakingInfo) consolidateNodes() *[]consolidatedNode {
	// because Go map is not ordered, rList keeps track of the occurrence order of RewardAddrs.
	// to later arrange the consolidatedNodes.
	cmap := make(map[common.Address]*consolidatedNode)
	rList := make([]common.Address, 0, len(si.RewardAddrs))
	nToR := make(map[common.Address]common.Address)

	for i, n := range si.NodeIds {
		r := si.RewardAddrs[i]
		// Unique nodeId is guaranteed by AddressBook.
		nToR[n] = r
		if cn, ok := cmap[r]; ok {
			cn.NodeIds = append(cn.NodeIds, n)
			cn.StakingContracts = append(cn.StakingContracts, si.StakingContracts[i])
			cn.StakingAmount += si.StakingAmounts[i]
		} else {
			cmap[r] = &consolidatedNode{
				NodeIds:          []common.Address{n},
				StakingContracts: []common.Address{si.StakingContracts[i]},
				RewardAddr:       r,
				StakingAmount:    si.StakingAmounts[i],
			}
			rList = append(rList, r)
		}
	}

	// CLStakingInfo can only exist after Prague HF.
	if len(si.CLStakingInfos) > 0 {
		for _, clsi := range si.CLStakingInfos {
			// If the nodeId of CLStakingInfo is not found in nToR, it means the validator is not in the AddressBook.
			// So we skip it.
			if r, ok := nToR[clsi.CLNodeId]; ok {
				// One CLStakingInfo per validator is guaranteed by CLRegistry.
				cmap[r].CLStakingInfo = clsi
			}
		}
	}

	carr := make([]consolidatedNode, 0, len(cmap))
	for _, r := range rList {
		carr = append(carr, *cmap[r])
	}
	return &carr
}

func (spec *RewardSpec) IncRecipient(addr common.Address, amount *big.Int) {
	_, ok := spec.Rewards[addr]
	if !ok {
		spec.Rewards[addr] = big.NewInt(0)
	}
	spec.Rewards[addr].Add(spec.Rewards[addr], amount)
}
