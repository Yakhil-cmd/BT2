### Title
Cross-tenant PR mutation via divergent `repository_owner`/`repository.full_name` selection with unset `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb], [File: lib/shipit/github_app.rb], [File: app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb])

### Summary
`Shipit::WebhooksController#repository_owner` picks the verifying `GitHubApp` from `repository.owner.login`, falling back to `organization.login` when the former is absent, while every `PullRequest` handler (e.g. `EditedHandler`) independently reads the mutation target from `params.repository.full_name`. Because these two fields are both attacker-supplied and validated independently, and because `GitHubApp#verify_webhook_signature` unconditionally returns `true` when an organization's `webhook_secret` is unset, an attacker can select a lenient/no-secret tenant for signature verification while pointing the handler at a victim repository's PR.

### Finding Description
The broken invariant, stated as an equality that must hold but doesn't:
`organization_that_verified_signature == organization_owning(params.repository.full_name)`.

Code path:
- `WebhooksController#verify_signature` calls `Shipit.github(organization: repository_owner)` and accepts the request if `github_app.verify_webhook_signature(...)` returns true [1](#0-0) .
- `repository_owner` reads `params.dig('repository','owner','login')` and falls back to `params.dig('organization','login')` if that path is nil/absent [2](#0-1) .
- `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever the resolved app's `webhook_secret` is blank/nil, with no HMAC check at all [3](#0-2) .
- `EditedHandler`'s `ExplicitParameters` schema only requires `repository.full_name`, not `repository.owner.login` [4](#0-3) , so a payload can satisfy the schema while omitting `repository.owner`.
- The handler locates and mutates the target PullRequest purely from `params.repository.full_name` and `params.number`, joined through `stack: :repository` [5](#0-4) .

Exploit request: a `pull_request`/`edited` JSON body where:
- `organization.login` = the login of a Shipit-configured tenant whose `webhook_secret` is unset (a documented-as-optional config field, see `docs/setup.md` "If you've set a webhook secret ... you should copy it here"),
- `repository` = `{"full_name": "victim-org/victim-repo"}` (no `owner` key, so `repository_owner` falls through to `organization.login`),
- `pull_request.number` = a real PR number on the victim repo/stack.

`verify_signature` resolves the "attacker" org's `GitHubApp`, whose missing secret makes `verify_webhook_signature` return true unconditionally, regardless of the actual `X-Hub-Signature` header — no valid signature is required. `Webhooks.for_event('pull_request')` then dispatches to `EditedHandler`, which resolves `repository` from `params.repository.full_name` (victim org), finds the victim's `PullRequest` and overwrites `github_pull_request` with attacker-controlled JSON.

Existing guards fail because: (1) `GithubOrganizationUnknown` only blocks unregistered org names, not registered ones lacking a secret; (2) the `ExplicitParameters` schema for the PR handlers never requires `repository.owner.login`, so it cannot detect the owner/full_name divergence; (3) nothing binds the verifier-selection field to the handler's target-repository field.

### Impact Explanation
An attacker who knows only the public GitHub login of any Shipit tenant configured without a `webhook_secret` can forge a `pull_request`/`edited` (or similarly-shaped `opened`/`closed`/`labeled`/etc.) event that writes to another tenant's `PullRequest`/review-stack records, without possessing that tenant's secret, session, or API token. This is cross-tenant state manipulation matching the Critical category ("a payload for one repository mutating another's stack, commit, task or team"). The blast radius spans every repository/stack reachable via `Repository.from_github_repo_name(params.repository.full_name)`, i.e., any repo onboarded to the Shipit instance, and is repeatable per PR number.

### Likelihood Explanation
Preconditions: the Shipit instance must have at least one configured GitHub organization/app whose `webhook_secret` is unset (an allowed, documented configuration state, and the value seen in this repo's own `test/dummy/config/secrets.yml`), and the attacker must know that org's login (public information) and a target PR number on the victim repo (also usually public via GitHub). No Shipit credentials, GitHub App keys, or webhook secrets are required. Given this precondition, the attack is a single unauthenticated HTTP POST and fully repeatable.

### Recommendation
Bind signature verification to the same repository/organization the handler will act on: require `repository.owner.login` (not `organization.login`) for all events that carry a `repository` object, reject events where a handler's `repository.full_name` organization does not match the organization used for signature verification, and treat a missing/blank `webhook_secret` as verification failure (fail closed) rather than automatic success.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` or `test/models/shipit/webhooks/handlers/pull_request/edited_handler_test.rb` style):
1. Configure two orgs in `Shipit.github_config`-equivalent test setup: `"no-secret-org"` with `webhook_secret: nil`, and `"victim-org"` with a real secret.
2. Create `victim_repo = shipit_repositories(...)` under `"victim-org/victim-repo"`, a stack, and a `PullRequest` with `number: 42` and an original `github_pull_request` payload.
3. Build payload: `{"action" => "edited", "number" => 42, "pull_request" => {..., "title" => "PWNED"}, "repository" => {"full_name" => "victim-org/victim-repo"}, "organization" => {"login" => "no-secret-org"}, "sender" => {"login" => "attacker"}}` — note: no `repository.owner` key.
4. `assert_equal "no-secret-org", @controller.send(:repository_owner)` given this payload (binding LHS).
5. `assert_not_equal "no-secret-org", "victim-org"` while the handler's target repo login is `"victim-org"` (binding RHS) — showing the two never match.
6. POST with an arbitrary/garbage `X-Hub-Signature` header and `X-Github-Event: pull_request`.
7. `assert_response :ok` and `assert_equal "PWNED", pull_request.reload.title` — proving the victim's record was mutated despite an invalid/no-secret signature for the org that "verified" the request.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
