Based on my analysis, I found a concrete analog to CVE-2021-47354's bug class ("killing a job without waiting for all its dependencies to complete, causing data corruption") in the private-payment-chain handling code reachable from an untrusted hub/private-payment counterparty.

### Title
Premature cancellation of pending private-payment-chain validations causes inconsistent local wallet state and unnotified double-spend risk on shared addresses - (File: wallet.js)

### Summary
`handlePrivatePaymentChains()` in [1](#0-0)  processes a batch of private payment chains received from a peer/hub. For chains that must be validated asynchronously (the common `ifQueued` path for light clients), it registers a one-shot `eventBus.once(key, ...)` listener per chain and only finalizes bookkeeping (`checkIfAllValidated`) once every chain's listener fires. However, if *any single chain* in the batch fails, `async.eachSeries` aborts immediately and calls `cancelAllKeys()`, which does `eventBus.removeAllListeners(key)` for *every* key in the batch — including keys belonging to chains whose asynchronous validation (performed independently in `network.handleSavedPrivatePayments`/`network.handleOnlinePrivatePayment`) is still in flight and has not yet completed.

### Finding Description
The relevant code: [2](#0-1) [3](#0-2) 

The listener-removal (`cancelAllKeys`) only detaches the *notification* path in `wallet.js`; it does **not** cancel the actual asynchronous validation/save work, which happens independently in `network.js`: [4](#0-3) 

That code calls `privatePayment.validateAndSavePrivatePaymentChain`, which performs real DB writes (`INSERT`/`UPDATE` on `outputs`/`inputs`, marking outputs spent) regardless of whether the caller in `wallet.js` has already reported the whole batch as failed: [5](#0-4) 

Because `cancelAllKeys()` removes the listener before this in-flight work resolves, when the background validation eventually completes and `eventBus.emit(key, true)` fires (see [6](#0-5) ), nobody is listening anymore. As a result:
- `checkIfAllValidated()` for that batch never runs to completion (its guard at [7](#0-6)  can never see all keys become `true`).
- `forwardPrivateChainsToOtherMembersOfSharedAddresses(...)` (line 1007-1015) — the step that shares spend-proof information with cosigners of a shared address — never runs, even though the private output has already been recorded as spent in the local database via the background path in `network.js`.

This is the same root-cause shape as the kernel CVE: the "job" (the batch of chains) is treated as terminated/killed (`callbacks.ifError(err)` at [8](#0-7) ) while one of its dependent async operations (the sibling chain's background validation/save) is still outstanding, and that operation is allowed to complete and mutate persistent state after the "job" was already considered done/failed — producing a state where the local DB reflects a completed spend that the higher-level completion/forwarding logic never learns about.

### Impact Explanation
On a shared (multi-sig) address, the cosigner device relies on `forwardPrivateChainsToOtherMembersOfSharedAddresses` to learn that a private output was spent. If that step is silently skipped due to this race, the local wallet records the output as spent while the cosigner remains unaware and may independently compose a new private payment spending the same (already-locally-spent) output, creating a genuine double-spend attempt against a shared address. This is triggerable by any counterparty who sends a batch containing one deliberately-malformed/invalid chain alongside otherwise legitimate chains destined for a shared address — an unprivileged private-payment counterparty action, matching the required "reachable by a single posted... private chain" surface.

### Likelihood Explanation
Any peer or hub-relayed sender can construct a `private_payment_chains` message with multiple chains, deliberately making one chain fail validation (e.g., malformed structure or invalid spend proof) while other, legitimate chains for a shared address are still pending validation via the light-client `ifQueued`/background path. Light wallets are the default execution mode for many end users, making the queued path common in practice.

### Recommendation
Do not call `cancelAllKeys()`/abort batch bookkeeping on the first chain error while other chains in the same batch still have `ifQueued` validations outstanding. Either:
1. Wait for all outstanding per-chain validations (success or failure) before finalizing/cancelling the batch, tracking completion independently of the first error, or
2. Make the per-chain outcome (including forwarding to cosigners of shared addresses) unconditional on the batch-level success/failure — i.e., always forward a chain's result once its own validation completes, rather than gating it behind `checkIfAllValidated()` for the whole batch.

### Proof of Concept
1. Attacker (or a compromised hub) sends a `private_payment_chains` justsaying with `body.chains = [chain_invalid, chain_valid_to_shared_address]` to a light wallet.
2. `handlePrivatePaymentChains` processes `chain_invalid` first; `network.handleOnlinePrivatePayment` returns `ifError`/`ifValidationError` synchronously (or quickly), causing `async.eachSeries` to call its final callback with an error before `chain_valid_to_shared_address`'s `ifQueued` background validation (issued moments earlier) has resolved.
3. `cancelAllKeys()` runs ( [8](#0-7) ), removing the listener for `chain_valid_to_shared_address`'s key.
4. Later, `network.handleSavedPrivatePayments` finishes validating/saving `chain_valid_to_shared_address` ( [9](#0-8) ), marking the underlying output `is_spent` in the local DB and emitting the (now-unheard) key event.
5. `forwardPrivateChainsToOtherMembersOfSharedAddresses` for this chain never runs; the cosigner is never informed of the spend, while the local wallet already treats the output as spent — a persistent, silent state divergence between cosigners on a shared address.

	}

		return callbacks.ifError("chains hash failed: " + e.toString());		
	}
	if (handledChainsCache[cache_key]) {
		eventBus.emit('all_private_payments_handled', from_address);
		eventBus.emit('all_private_payments_handled-' + arrChains[0][0].unit);
		return callbacks.ifOk();

	if (conf.bLight)

	var bParsingComplete = false;

			var arrUnits = arrChains.map(function(arrPrivateElements){ return arrPrivateElements[0].unit; });
			db.query("SELECT address FROM unit_authors WHERE unit IN(?)", [arrUnits], function(rows){
				var arrAuthorAddresses = rows.map(function(row){ return row.address; });
				// if the addresses are not shared, it doesn't forward anything
				forwardPrivateChainsToOtherMembersOfSharedAddresses(arrChains, arrAuthorAddresses, from_address, true);
			});
		}

	};
	
	async.eachSeries(
		arrChains,

			var objHeadPrivateElement = arrPrivateElements[0];
			if (!!objHeadPrivateElement.payload.denomination !== ValidationUtils.isNonnegativeInteger(objHeadPrivateElement.output_index))
				return cb("divisibility doesn't match presence of output_index");
			var output_index = objHeadPrivateElement.payload.denomination ? objHeadPrivateElement.output_index : -1;
			try {
				var json_payload_hash = objectHash.getBase64Hash(objHeadPrivateElement.payload, true);
			}
			catch (e) {

			assocValidatedByKey[key] = false;
			network.handleOnlinePrivatePayment(ws, arrPrivateElements, true, {
				ifError: function(error){
					console.log("handleOnlinePrivatePayment error: "+error);
					cb("an error"); // do not leak error message to the hub
				},
				ifValidationError: function(unit, error){
					console.log("handleOnlinePrivatePayment validation error: "+error);
					cb("an error"); // do not leak error message to the hub
				},
				ifAccepted: function(unit){
					console.log("handleOnlinePrivatePayment accepted");
					assocValidatedByKey[key] = true;
					cb(); // do not leak unit info to the hub
				},
				// this is the most likely outcome for light clients
				ifQueued: function(){

					eventBus.once(key, function(bValid){
						if (!bValid)
							return cancelAllKeys();

						if (bParsingComplete)

						else
							console.log('parsing incomplete yet');
					});
					cb();
				}

		function(err){
			bParsingComplete = true;
			if (err){

				return callbacks.ifError(err);
			}
			checkIfAllValidated();
			handledChainsCache[cache_key] = Date.now();
			callbacks.ifOk();
			// forward the chains to other members of output addresses
			if (!body.forwarded)

	);
