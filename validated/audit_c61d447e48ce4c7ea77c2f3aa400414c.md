### Title
Suppliers can exit at the pre-write-down supply index and concentrate socialized bad-debt losses on remaining suppliers - (File: contracts/pool/src/interest.rs)

### Summary
Analogous to the Angle "race on loss" between surplus claimants and loss reporters, XOXNO Lending only realizes bad debt when a `liquidate` / `clean_bad_debt` / `force_socialize_bad_debt` call executes `apply_bad_debt_to_supply_index`. Between the moment an account becomes insolvent (public oracle state) and the moment any caller triggers the write-down, every supplier can call `withdraw` and be paid at the un-written-down index. Each exit transfers that supplier's pro-rata share of the pending loss onto the suppliers who remain, and the protocol performs no debt-vs-loss accounting that would claw the escapees' excess back (there is no equivalent of Angle's corrected "debt to be covered" accrual).

### Finding Description
- Bad debt is written down lazily. `clean_bad_debt_standalone` and `process_force_socialize_bad_debt` (`contracts/controller/src/positions/liquidation/mod.rs:240-249`) call `socialize_bad_debt`, which reaches `interest::apply_bad_debt_to_supply_index` via the pool's seize path (`contracts/pool/src/ops/seize.rs`). Until such a call runs, `supply_index` is untouched and `backing_shortfall` still values the unrecoverable debt at face (`docs/reference/invariants.md` INV-ACCT-04/07 explicitly state the checks do not establish full backing between boundaries).
- `process_withdraw` (`contracts/controller/src/positions/supply.rs:140-169`) pays out `floor(scaled_supply * supply_index)` against cash with no gate that discounts pending bad debt. The only withdrawal gates are listing flags (`FreezePolicy::AllowOnExit`), the utilization ceiling, and the debt-without-supply check — none of which reflect an unreported loss.
- The harness test `supplier_can_exit_ahead_of_bad_debt_writedown` (`tests/test-harness/tests/controller/bad_debt_index.rs:396-473`) demonstrates the mechanics end to end: Bob holds 75% of ETH supply, Carol 25%; after Alice's collateral crashes but before the liquidation write-down, `b.withdraw_all(BOB, "ETH")` succeeds at the stale index and Carol's resulting loss is amplified ~4x.
- Unlike the corrected Angle design, there is no tracked "loss pending" or debt-to-be-covered variable: the write-down is always applied pro-rata over *currently live* supply shares, so escaped suppliers permanently keep the value that should have absorbed part of the loss.

### Impact Explanation
Loss of funds for remaining suppliers — a form of value extraction. A large or fast supplier (or a coordinated set) that monitors oracle prices can exit fully at par after insolvency is publicly knowable, forcing the entire bad-debt loss onto passive suppliers. In the pinned scenario the remaining supplier's loss quadruples; with a dominant supplier exiting, concentration is unbounded up to `SUPPLY_INDEX_FLOOR_RAW` grinding the index to its floor. This is theft-by-ordering of user funds proportional to the socialized debt.

### Likelihood Explanation
Medium. It requires (a) an account to become insolvent, and (b) a supplier to front-run the liquidation/cleanup transaction. Soroban transaction ordering makes pure same-ledger front-running hard, but the window is wide: insolvency can persist across many ledgers while liquidators are economically unincentivized (dust-sized collateral, `no_seize` assets, or debt already cleaned to a position liquidations skip), during which any supplier can withdraw in a normal transaction. Permissionless `clean_bad_debt` is only callable below the $5 dust collateral threshold, so above-dust insolvent accounts rely on the owner-only `force_socialize_bad_debt` governance path — extending the exit window considerably. No privilege is needed for the exploit leg itself; `withdraw` is a standard user entrypoint.

### Recommendation
Track the pending loss explicitly rather than realizing it lazily over live shares. Options: (1) include a conservative estimate of unrecoverable debt (e.g., debt positions whose HF < 1) in the backing/utilization computation used by withdrawal and revenue-claim guards, so exits cannot be paid at par while a known shortfall exists; or (2) apply the Angle-style correction — record a per-market "uncovered loss" accumulator at first insolvency detection so later gains/claims reimburse it before paying out; or (3) gate non-liquidation withdrawals when `backing_shortfall > 0` beyond a tolerance.

### Proof of Concept
Implemented and pinned in `tests/test-harness/tests/controller/bad_debt_index.rs:402-473` (`supplier_can_exit_ahead_of_bad_debt_writedown`):

1. Bob supplies 75 ETH, Carol supplies 25 ETH; Alice supplies 10 USDC and borrows 0.003 ETH.
2. Oracle crash: `set_price("USDC", usd_cents(10))` — Alice is now insolvent; this is public state, but `supply_index` has not moved.
3. Bob calls `withdraw` (withdraw-all sentinel) on the controller → pool pays `floor(bob_shares * supply_index)` at the pre-write-down index; Bob recovers ≥ his full deposit (`bob_recovered >= bob_before_b` asserted).
4. Any caller then runs `liquidate` → `apply_bad_debt_to_supply_index` writes the whole loss down over the remaining supply. Carol's loss is ~4x the no-dodge baseline (`amplification > 3.0` asserted).

No admin key, leaked key, or protocol privilege is required at any step; steps 3 and 4 are ordinary unprivileged `withdraw` / `liquidate` calls. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

```rust
/// Bad debt is written down only when a liquidation or cleanup call runs, and
/// `backing_shortfall` counts the unrecoverable debt at face value until then.
/// A supplier can exit at the pre-write-down index and leave the loss on the
/// suppliers who stay. Runs the same crash with Bob passive and with Bob
/// exiting first, and compares Carol's loss.
#[test]
fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );

    // Carol holds 25% of supply, so passing the whole loss to her is ~4x.
    let amplification = carol_loss_b / carol_loss_a;
    assert!(
        amplification > 3.0,
        "expected ~4x concentration onto the remaining supplier, got {:.3}x \
         (A={:.9} B={:.9})",
        amplification,
        carol_loss_a,
        carol_loss_b
    );

    std::println!(
        "A4-econ dodge: bob_supplied={:.9} bob_recovered={:.9} \
         carol_loss_passive={:.9} carol_loss_after_dodge={:.9} amplification={:.3}x",
        bob_before_b,
        bob_recovered,
        carol_loss_a,
        carol_loss_b,
        amplification
    );
}
```

```rust
/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

/// Socializes debt exceeding collateral without a dust cap, outside flash loans.
pub(crate) fn process_force_socialize_bad_debt(env: &Env, account_id: u64) {
    validation::require_not_flash_loaning(env);
    socialize_bad_debt(env, account_id, BadDebtGate::InsolventOnly);
}
```

```rust
pub(crate) fn process_withdraw(
    env: &Env,
    caller: &Address,
    account_id: u64,
    withdrawals: &Vec<HubPayment>,
    to: Option<Address>,
) -> Vec<HubPayment> {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_payments(env, withdrawals, payments::ZeroLeg::MeansAll);

    let paid = settle_withdraw(env, &mut account, &recipient, &aggregated, &mut cache);
    let _ = enforce_post_pool_solvency(env, &mut cache, &mut account);

    finalize_position_flow(
        env,
        account_id,
        &account,
        &mut cache,
        PositionSides::Supply,
        true,
    );
    paid
}
```

```markdown
### INV-LIQ-04 — Bad-debt socialization is explicit and total

Permissionless cleanup requires ceil risk debt greater than half-up unweighted
collateral and collateral at or below the fixed $5 dust threshold. Owner-only
forced cleanup omits the dust cap. Both require debt, readable account and NFT
state, valid required prices and no active flash guard. Listing flags and
global pause do not block standalone cleanup.

Cleanup reclassifies all remaining collateral shares as revenue and writes off
all remaining debt against each debt's market. It releases spoke usage and
atomically removes account entries and the NFT. It does not net same-market
supply against debt. Standalone cleanup emits `CleanBadDebtEvent` with
pre-cleanup USD totals, without a controller position-update batch.

Ordinary liquidation and cleanup apply no final account-health or full-backing
assertion. The index floor can leave a shortfall. Recapitalization fills that
shortfall without restoring the lost index or deleted account.
```
