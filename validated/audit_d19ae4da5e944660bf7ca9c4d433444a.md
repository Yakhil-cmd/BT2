### Title
`NonTransfer` proxy's unconditional `is_superset` claim lets a restricted proxy escalate to `Auction`/`SudoBalances` and reach calls its own filter explicitly denies - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
`polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs` and `substrate/frame/staking-async/runtimes/rc/src/lib.rs` all define `ProxyType::is_superset` with the blanket arm `(ProxyType::NonTransfer, _) => true`, declaring `NonTransfer` a superset of *every* other proxy type. However `NonTransfer`'s own `filter` explicitly and deliberately omits the entire `Sudo` pallet and `Registrar::swap` (comments: "Specifically omitting Sudo pallet" / "Specifically omitting Registrar `swap`"), while `SudoBalances` and `Auction` admit exactly those calls. `pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` purely via `is_superset`, never re-checking `filter`, so a `NonTransfer` delegate can grant itself (or anyone) an `Auction`/`SudoBalances` proxy and thereby dispatch calls that the delegator explicitly restricted it from reaching. This is the exact bug class already found and fixed for `asset-hub-westend`'s `NonTransfer`/`Governance` pair in [PR #12769](prdoc/pr_12769.prdoc), but the fix was never applied to the relay-chain runtimes.

### Finding Description
`pallet_proxy`'s escalation guard lives in `do_proxy`: [1](#0-0) 

It only blocks `add_proxy`/`remove_proxy` when `!def.proxy_type.is_superset(proxy_type)`. It never consults `filter` for this decision, so `is_superset` alone is the security boundary that stops a low-privilege proxy from minting itself a higher-privilege one.

In `polkadot/runtime/westend/src/lib.rs`, `NonTransfer`'s filter is a curated allow-list that explicitly excludes `Sudo` and `Registrar::swap`: [2](#0-1) 

Yet `SudoBalances` admits `Sudo(sudo{Balances})`, and `Auction` admits the *entire* `Registrar` pallet (`RuntimeCall::Registrar(..)`, which includes `swap`): [3](#0-2) 

`is_superset` nonetheless declares `NonTransfer` a superset of both, unconditionally: [4](#0-3) 

The identical pattern exists in `polkadot/runtime/rococo/src/lib.rs` (`Auction` admits full `Registrar{..}` while `NonTransfer` "Specifically omit[s] Registrar `swap`", and `is_superset` still uses `(ProxyType::NonTransfer, _) => true`): [5](#0-4) [6](#0-5) 

and in `substrate/frame/staking-async/runtimes/rc/src/lib.rs`: [7](#0-6) 

This is the same "nested-scope grants access to a scope created after the fact" invariant violation as CVE-2020-10661: a coarse policy (`NonTransfer`) is treated as dominating a finer policy (`Auction`/`SudoBalances`) for authorization purposes (`is_superset`), while the actual permitted-action set (`filter`) of the finer policy is not a subset of the coarse one. The exact same bug, on the same `ProxyType` enum shape, was already identified and fixed for the `Governance` proxy type on `asset-hub-westend-runtime`: [8](#0-7) [9](#0-8) 

but that fix's regression coverage (`proxy_type_superset_relation_matches_call_filters`, `non_transfer_proxy_is_not_a_superset_of_governance`) only exists for `asset-hub-westend-runtime`; the relay-chain runtimes were never patched or covered by an equivalent lattice test.

### Impact Explanation
A user who granted a third party only a `NonTransfer` proxy — explicitly trusting them *not* to touch `Registrar::swap` (a sensitive parachain-identity operation) or `Sudo` — can have that trust silently widened. The delegate uses the very `NonTransfer` proxy to call `Proxy::add_proxy` and mint itself (or a collaborator) an `Auction`/`SudoBalances` proxy on the delegator's account, then dispatches the previously-denied call under that new proxy type. This is an unauthorized-dispatch / access-control-integrity break exactly matching the report's preferred category ("unauthorized dispatch"), executed by an attacker holding only the low-privilege proxy grant the victim intentionally issued — no privileged role, governance, or stolen keys required beyond the proxy delegation the victim themselves created.

### Likelihood Explanation
Reachability requires only that a victim has assigned someone a `NonTransfer` proxy (a normal, encouraged usage pattern for spending-limited delegation) on Westend or Rococo (or whichever chain uses the staking-async `rc` runtime template). No governance action, no validator collusion, and no privileged role are needed — the attacker is the proxy delegate itself, acting entirely through the public `proxy`/`add_proxy` extrinsics. The `Registrar::swap` path additionally depends on `swap`'s own precondition (I was unable to fully read `pub fn swap` in `polkadot/runtime/common/src/paras_registrar/mod.rs` within available iterations to confirm whether it needs bilateral consent from another registered para); this could reduce standalone exploitability of the `swap` branch, but the authorization-lattice bug itself — `NonTransfer` being wrongly treated as a superset of `Auction`/`SudoBalances` in `is_superset` — is unconditionally demonstrable independent of what `swap` does, and directly mirrors the already-confirmed, already-fixed `NonTransfer`/`Governance` bug on Asset Hub.

### Recommendation
Apply the same fix used in PR #12769 to `polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`: remove the blanket `(ProxyType::NonTransfer, _) => true` arm and enumerate only the proxy types whose `filter` is actually a subset of `NonTransfer`'s filter (excluding `Auction` and `SudoBalances`, whose admitted calls — `Registrar::swap` and `Sudo(Balances)` — are explicitly denied by `NonTransfer`). Add a lattice-covering regression test per runtime (mirroring `proxy_type_superset_relation_matches_call_filters` in `asset-hub-westend`'s test suite) so any future proxy-type addition is checked against this invariant automatically.

### Proof of Concept
Guards examined and found insufficient:
- `pallet_proxy::do_proxy`'s `add_proxy`/`remove_proxy` origin filter, which relies solely on `is_superset` (`substrate/frame/proxy/src/lib.rs:1004-1013`) — does not re-validate against `filter`.
- `ProxyType::is_superset` in the three affected runtimes, which unconditionally asserts `NonTransfer ⊇ Auction` and `NonTransfer ⊇ SudoBalances` without checking that their `filter` implementations actually nest.

Minimal reproduction sketch (structured analogously to the existing, already-merged regression test `non_transfer_proxy_is_not_a_superset_of_governance` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2523-2559`, adapted to `polkadot/runtime/westend`):

title: 'asset-hub-westend: fix `NonTransfer` proxy falsely claiming `Governance` containment'
doc:
- audience: Runtime User
  description: |-
    On Asset Hub Westend, the `NonTransfer` proxy type declared itself a superset of the
    `Governance` proxy type while its call filter denied the `Treasury`, `ConvictionVoting`,
    `Referenda` and `Whitelist` calls that `Governance` admits.

    Because `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `is_superset`, a
    `NonTransfer` proxy could add a `Governance` proxy for its delegator and thereby reach calls
    that its own filter denies. `NonTransfer` no longer declares `Governance` as a subset, so this
    is rejected.

    Existing `Governance` proxies are unaffected; only the ability of a `NonTransfer` proxy to
    create or remove one changes. The `Collator`, `Staking`, `NominationPools` and
    `StakingOperator` subsets of `NonTransfer` are unchanged.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));
