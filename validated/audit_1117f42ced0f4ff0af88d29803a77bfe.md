## Title
CCMenu API endpoint bypasses stack-scoped ApiClient authorization, exposing deploy/task status for any stack - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::BaseController` scopes stack lookups to the stack an `ApiClient` token was authorized for, but `Shipit::Api::CCMenuController` overrides `#stack` to bypass that scoping, resolving the stack directly from the URL parameter without checking `current_api_client.stack_id`. This breaks the trust binding "the stack a token authorizes == the stack it touches."

### Finding Description
In `BaseController`, stack resolution is deliberately scoped to the calling `ApiClient`: [1](#0-0) 

`stacks` filters to `Stack.where(id: current_api_client.stack_id)` whenever the client has a `stack_id` set, and only `#from_param!` on that restricted relation. This is the mechanism that lets an `ApiClient` be minted for a single stack (see fixture `here_come_the_walrus`, scoped to `stack: shipit`) and is explicitly relied upon and tested for the index/show actions of `Api::StacksController`.

`Api::CCMenuController`, however, redefines `#stack` to resolve directly against the global `Stack` relation, ignoring `current_api_client.stack_id` entirely: [2](#0-1) 

The only authorization check performed is `require_permission :read, :stack` (checking that the token has the `read:stack` permission string at all), not that the token is scoped to the requested stack: [3](#0-2) 

So for any `ApiClient` with `read:stack` permission — including one explicitly scoped to a single stack — an attacker in possession of that token can query `GET /api/stacks/*stack_id/ccmenu` for **any** stack in the Shipit instance and receive that stack's deploy status: [4](#0-3) 

### Impact Explanation
This is an authorization-scope escalation: a token deliberately restricted to one stack (`ApiClient#stack_id`) can be used to read deploy/task state (`stack.deploys_and_rollbacks.last`, environment name, activity, last build status/label/time) of any other stack in the instance, including ones the token holder should have no visibility into. This matches the "High - escalation into `Shipit.github_teams` authorization ... unauthenticated read of stack state" impact bucket: an unprivileged caller possessing only a narrowly-scoped credential gains read access to stack state across the whole instance, which the scoping mechanism is specifically designed to prevent.

### Likelihood Explanation
Any holder of a stack-scoped `ApiClient` token (e.g. a CCMenu URL shared for one project/stack, as generated by `Shipit::CcmenuUrlController`) can trigger this by simply changing the `stack_id` segment of the URL — no additional privileges, signing, or session are required, only the token itself, which is exactly the credential this endpoint is meant to accept.

### Recommendation
`Api::CCMenuController#stack` should resolve through the scoped `stacks` relation from `BaseController` (i.e. `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!(params[:stack_id])`, so that a stack-scoped `ApiClient` cannot read status for stacks outside its authorized scope.

### Proof of Concept
1. Create an `ApiClient` scoped to `stack_id = A` with permission `read:stack` (e.g. via `Shipit::CcmenuUrlController` or the admin UI), and obtain its `authentication_token`.
2. Issue `GET /api/stacks/<owner>/<repo-B>/<env-B>/ccmenu?token=<token>` for a *different* stack `B` that the token was never scoped to.
3. Observe that `Api::CCMenuController#stack` calls `Stack.from_param!(params[:stack_id])` unscoped, `require_permission :read, :stack` only checks the permission string (not stack identity), and the response renders stack `B`'s deploy/build status — despite the token being authorized only for stack `A`.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
```
