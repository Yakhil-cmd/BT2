## Title
Use of stale/removed unit-cache entry when reverting a chain of AA responses can crash node validation and desynchronize AA state - ([File: aa_composer.js])

### Summary
`aa_composer.js`'s `revertResponsesInCaches()` reads `storage.assocUnstableUnits[first_unit]` to recover `parent_units` *after* a chain of secondary-AA response units may already have partially mutated or removed cache entries, and *before* deleting all response units from that same cache via `storage.forgetUnit`. If the referenced cache entry for `first_unit` is no longer present (e.g., a secondary trigger in the chain already caused a partial revert/forget earlier in the same trigger's cascade, or ordering assumptions about `arrResponses[0]` don't hold once secondary AAs are chained and can themselves revert), `objFirstUnit` is `undefined`, and `objFirstUnit.parent_units` throws inside a mutex-held, DB-transaction-in-progress code path. [1](#0-0) 

### Finding Description
`revertResponsesInCaches` is invoked from `revert()` (triggered whenever an AA in a trigger/response chain bounces) and from `dryRunPrimaryAATrigger`'s `onDone` callback: [2](#0-1) [3](#0-2) 

The function assumes `arrResponses[0]` (or, more precisely, the first response unit with a `response_unit`) is still present in `storage.assocUnstableUnits`, and that `parent_units` read from it is representative of the whole set of units being forgotten: [1](#0-0) 

This mirrors the bug class in CVE-2022-0289 (use of an object after related state has been freed/invalidated in an asynchronous callback chain): the code takes a reference (`objFirstUnit`) from a shared, mutable, associative cache (`assocUnstableUnits`) at one point in an asynchronous multi-step process (`handleTrigger` → secondary triggers → `revert`), then dereferences it later without re-checking that the cache entry still exists. Because AA triggers can recursively invoke secondary AAs (`handleSecondaryTriggers`, `aa_composer.js:1702-1757`), and each secondary trigger can itself call `revert`/`bounce` and mutate the very same global caches (`storage.assocUnstableUnits`, `assocBestChildren`) via `storage.forgetUnit`/`fixIsFreeAfterForgettingUnit` reachable from within the same call stack, the assumption that `first_unit`'s cache entry is untouched when the *outer* revert finally runs is not guaranteed to hold for all trigger-chain shapes (e.g., a secondary AA that itself creates further secondary responses and then bounces, causing an inner revert to forget units before the outer one runs). This is reachable purely by an AA trigger sender (any user who sends a payment/trigger unit to a public AA address) or an AA author who crafts an AA whose messages provoke complex chains of secondary AA calls that bounce under attacker-controlled conditions.

### Impact Explanation
If `objFirstUnit` is `undefined`, the subsequent `objFirstUnit.parent_units` throws a `TypeError` inside code that is running with a write-mutex held and a live database transaction (`db.takeConnectionFromPool` / `conn.query("BEGIN")` in `handleTrigger`/`dryRunPrimaryAATrigger`/`estimatePrimaryAATrigger`, see `aa_composer.js:91-150`, `152-213`, `272-306`). An uncaught exception in this context crashes the node process (denial of network availability — "a network unable to confirm new units") or, if only partially caught upstream, leaves the mutex held and the DB connection un-released, stalling all further AA-trigger and possibly all further unit processing on that node (since AA processing is serialized through shared locks). This can be triggered remotely by any user able to construct an AA whose trigger chain produces the described ordering, without requiring any special privilege, hub/peer position, or light-vendor trust.

### Likelihood Explanation
Exploiting this requires crafting an AA (or AA graph) such that a secondary AA's own bounce/revert removes units from `assocUnstableUnits` before an outer revert reads `arrResponses[0]`'s cache entry — an author-controlled AA definition combined with attacker-chosen trigger data (`data`, `params`) can arrange bounce timing deterministically since AA execution is fully deterministic given trigger inputs. This makes the trigger reproducible and remotely triggerable by any unprivileged unit poster targeting a pre-deployed (or newly defined, since AAs can be defined and immediately used per `test/aa_composer.test.js:557-649`) malicious AA.

### Recommendation
In `revertResponsesInCaches`, do not assume `storage.assocUnstableUnits[first_unit]` is present; guard the lookup:
```js
var objFirstUnit = storage.assocUnstableUnits[first_unit];
if (objFirstUnit) {
    var parent_units = objFirstUnit.parent_units;
    ...
}
```
More robustly, capture `parent_units` for every response unit at the time each unit is created/added to the cache (rather than relying on `arrResponses[0]` at revert time), and iterate `fixIsFreeAfterForgettingUnit` per-unit using each unit's own recorded parents, so correctness does not depend on a specific unit still being present in a shared mutable cache at an arbitrary later point in the recursive trigger-handling call graph.

### Proof of Concept
Not independently reproduced in this analysis; the trigger-ordering scenario described (an AA that invokes a secondary AA whose own secondary chain bounces and reverts before the outer `revert()`/`revertResponsesInCaches()` runs) is inferred from the code paths in `aa_composer.js:1702-1783` and `aa_composer.js:1900-1916`, and from the existing test suite in `test/aa_composer.test.js` which demonstrates deep, deterministic AA chains (e.g., `chain of AAs`, `define new AA and activate it`) but does not cover the specific interleaving of nested reverts required to hit the stale-cache-read path. Constructing a concrete PoC AA graph that forces this exact ordering would require dynamic testing against the running node, which was not performed here.

function revertResponsesInCaches(arrResponses) {
	// remove the rolled back units from caches and correct is_free of their parents if necessary
	console.log('will revert responses ' + JSON.stringify(arrResponses, null, '\t'));
	var arrResponseUnits = [];
	arrResponses.forEach(function (objAAResponse) {
		if (objAAResponse.response_unit)
			arrResponseUnits.push(objAAResponse.response_unit);
	});
	console.log('will revert response units ' + arrResponseUnits.join(', '));
	if (arrResponseUnits.length > 0) {
		var first_unit = arrResponseUnits[0];
		var objFirstUnit = storage.assocUnstableUnits[first_unit];
		var parent_units = objFirstUnit.parent_units;
		arrResponseUnits.forEach(storage.forgetUnit);
		storage.fixIsFreeAfterForgettingUnit(parent_units);
	}
}
