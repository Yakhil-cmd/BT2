### Title
Unauthenticated read of live task/deploy event stream via `mount Pubsubstub::StreamAction.new, at: "/events"` bypassing `Shipit::Authentication` - (File: config/routes.rb)

### Summary
The route `/events` is mounted directly as a raw Rack endpoint (`Pubsubstub::StreamAction`) rather than as an action on a controller that includes `Shipit::Authentication`, so `force_github_authentication` never runs for it. The comment in `GithubAuthenticationController#callback` claims protection comes from a `UserRequiredMiddleware`, but no such class exists anywhere in `app/` or `lib/`, and no middleware in `Shipit::Engine`'s initializer performs any authentication check.

### Finding Description
The claimed binding is: `app.config.middleware` includes a middleware class matching `/UserRequired/i` that gates `/events` == the comment's assertion in `app/controllers/shipit/github_authentication_controller.rb:15-18`. Tracing `lib/shipit/engine.rb`'s `initializer 'shipit.config'` [1](#0-0)  shows only `OmniAuth::Builder` and `Shipit::SameSiteCookieMiddleware` are inserted into `app.middleware`/`app.config.middleware`; there is no insertion of any user-required/auth-gating middleware. A repo-wide search confirms `UserRequiredMiddleware` is referenced only in the comment itself and nowhere defined.

The actual authentication mechanism in this engine is `Shipit::Authentication#force_github_authentication`, a controller `before_action` included via `Shipit::ShipitController` [2](#0-1)  and enforced per-request in `app/controllers/concerns/shipit/authentication.rb:8,20-34`. This only runs for controllers that inherit from `ShipitController`/`ApplicationController` and go through the Rails controller/action-filter pipeline.

However, `config/routes.rb:9` does `mount Pubsubstub::StreamAction.new, at: "/events", as: :events` — this is a plain Rack endpoint mounted directly into the routes, bypassing the controller filter chain entirely (no `before_action`, no `ShipitController` ancestry, no `force_github_authentication` call path). `Pubsubstub::StreamAction` is a third-party gem class, not defined in this engine, and nothing in this engine's code wraps it with an equivalent auth check.

So both sides of the equality diverge: the comment asserts a `UserRequiredMiddleware` gates `/events`; the actual middleware stack and routing contain no such protection. An unauthenticated `GET /events?channel=stack.<id>` (or `repository.<id>`) is dispatched straight to `Pubsubstub::StreamAction`, which opens an SSE stream and starts publishing pubsub messages for the requested channel with no session/user check.

### Impact Explanation
Any unauthenticated attacker can open a live SSE connection to `/events` and subscribe to `stack.<id>` or `repository.<id>` channels, observing task/deploy status transitions, chunk-append `update` events, and other real-time state broadcast throughout `app/views` (e.g., `stack.updated_at`, task output streaming) for any stack/repository whose channel name/id can be guessed or enumerated (stack/repository ids are exposed elsewhere, e.g. in URLs, API responses). This is an unauthenticated read of stack state and task/deploy streams, matching the "High" impact category (unauthenticated read of stack state, task streams or deploy output). It does not by itself grant write access, RCE, or credential exfiltration, so it does not rise to Critical. It is repeatable against arbitrary stacks/repositories simply by varying the channel parameter, with no session or token required.

### Likelihood Explanation
Preconditions: the Shipit instance must be deployed as documented (engine mounted at `/`, default `config/routes.rb`), which is the assumed baseline per the rules. No GitHub secrets, sessions, or privileged roles are needed — the attacker only needs network access to the Shipit host and knowledge of a valid channel name (stack/repository identifiers are otherwise discoverable, e.g., via public stack listing pages if `authentication_disabled?` isn't set, or by brute-forcing known repo/stack naming conventions). This is a straightforward, cheap, fully repeatable HTTP GET with no rate limiting bypass or race condition required.

### Recommendation
Wrap the `/events` mount with an authentication gate before dispatching to `Pubsubstub::StreamAction` — e.g., route it through a controller action that includes `Shipit::Authentication` (calling `force_github_authentication` and validating the requested channel against the current user's authorization) rather than mounting the Rack app directly, or insert a real Rack middleware ahead of the mount that validates `session[:user_id]`/`session[:authenticated]` and rejects unauthenticated requests. Also correct or remove the misleading `UserRequiredMiddleware` comment in `github_authentication_controller.rb` since it describes protection that does not exist in this codebase.

# frozen_string_literal: true

module Shipit
  module Authentication
    extend ActiveSupport::Concern

    included do
      before_action :force_github_authentication
      helper_method :current_user
    end

    module ClassMethods
      def skip_authentication(*args)
        skip_before_action(:force_github_authentication, *args)
      end
    end

    private

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end

    def current_user
      @current_user ||= find_current_user || AnonymousUser.new
    end

    def find_current_user
      session[:user_id].present? && User.find_by(id: session[:user_id])
    end
  end
