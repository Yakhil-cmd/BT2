### Title
Path traversal via unsanitized `file.Name` in `writeToOutput` allows arbitrary file overwrite outside `--output` directory - ([File: pkg/cmd/repo/read-file/read_file.go])

### Summary
When `--output` points at an existing directory, `writeToOutput` builds the destination with `dest = filepath.Join(dest, file.Name)`, where `file.Name` comes verbatim from the Contents API `name` JSON field. No component sanitization (no rejection of `..` segments, no `filepath.Clean`/containment check against the target directory) is performed, so a `name` value containing `..` traversal segments causes the final write to land outside the chosen output directory.

### Finding Description
`fetchFile` in `pkg/cmd/repo/read-file/http.go` populates `repoFile.Name` directly from `content.Name` (the `name` field of the REST Contents API JSON response) with no validation. That value flows unmodified into `writeToOutput` in `pkg/cmd/repo/read-file/read_file.go`:

```go
if asDir {
    dest = filepath.Join(dest, file.Name)
}
```

`filepath.Join` calls `filepath.Clean` after concatenation, which resolves `..` segments. So if `file.Name` is e.g. `"../../.ssh/authorized_keys"`, `filepath.Join("output_dir", "../../.ssh/authorized_keys")` resolves to a path outside `output_dir`, and the subsequent `writeFileF(dest, file.Content, 0644)` writes there, subject only to `mkdirAllF` succeeding and the existing-file/`--clobber` check.

Note the specific PoC value cited in the question (`file.Name = "/etc/passwd"`) does **not** work: Go's `filepath.Join` does not treat a leading `/` in a joined element as absolute — `filepath.Join("output_dir", "/etc/passwd")` yields `"output_dir/etc/passwd"`, which stays confined under the directory. The real escape vector is a `..`-containing `name`, not a leading-slash absolute path.

For a genuine GitHub-hosted repository, git's tree-entry validation (`verify_path`/fsck checks enforced on push) rejects tree entries literally named `.` or `..`, so a normal repo/PR/fork cannot smuggle a `..` value into the real `name` field returned by the official Contents API. The attack is only reachable when the attacker fully controls the HTTP response for the Contents API endpoint — i.e., the "controls responses from a host the victim points gh at" scenario (a malicious/custom GH_HOST or enterprise-compatible endpoint the victim configures), where the JSON payload is not constrained by real git semantics at all.

### Impact Explanation
Under the malicious-host scenario, this allows arbitrary file write/overwrite outside the directory the victim intended for `gh repo read-file --output <dir>`, which matches GitHub's "file write or overwrite outside the intended path" bounty impact class. Impact is bounded by the victim's file permissions and by the requirement that intermediate directories be creatable via `mkdirAllF`, and by the `--clobber` check when the destination already exists.

### Likelihood Explanation
Requires the victim to run `gh repo read-file ... --output <existing-directory>` against a host fully controlled by the attacker (e.g., a custom `GH_HOST`/enterprise-style endpoint), since a legitimate github.com/GHES-backed repo cannot produce a `..`-named tree entry due to git's own validation. This significantly narrows likelihood compared to a same-repo/PR attacker, but is within the stated attacker model of "controls responses from a host the victim points gh at."

### Recommendation
In `writeToOutput`, after computing `dest = filepath.Join(dest, file.Name)`, validate that `file.Name` contains no path separators and no `.`/`..` components (reject if `filepath.Base(file.Name) != file.Name`), and/or verify that the resulting `dest` remains within the target directory (e.g., via `filepath.Rel` and checking it doesn't start with `..`) before writing.

### Proof of Concept
```go
func TestWriteToOutput_DirEscapeViaTraversalName(t *testing.T) {
	defer func() {
		lstatF = lstat
		mkdirAllF = os.MkdirAll
		writeFileF = os.WriteFile
	}()

	tmp := t.TempDir()
	outDir := filepath.Join(tmp, "outdir")
	require.NoError(t, os.MkdirAll(outDir, 0755))

	lstatF = func(path string) (*lstatResult, error) {
		if path == outDir {
			return &lstatResult{isDir: true}, nil
		}
		return nil, os.ErrNotExist
	}
	var written string
	mkdirAllF = func(path string, perm os.FileMode) error { return nil }
	writeFileF = func(path string, data []byte, perm os.FileMode) error {
		written = path
		return nil
	}

	file := &repoFile{Name: "../../evil.txt", Content: []byte("pwned")}
	dest, err := writeToOutput(file, outDir, false)
	require.NoError(t, err)

	rel, _ := filepath.Rel(outDir, dest)
	require.True(t, strings.HasPrefix(rel, ".."), "expected dest %q to escape %q, got rel %q", dest, outDir, rel)
	require.Equal(t, dest, written)
}
```
Expected: without a fix, `dest` resolves outside `outDir` (assertion on `rel` starting with `..` passes), demonstrating the escape. After adding basename/containment validation to `writeToOutput`, the function should instead return an error for such `file.Name` values.
