### Title
Webhook signature verification is keyed to the payload's claimed organization, not the repository actually written — cross-repository Commit/CI status spoofing via `StatusHandler` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks which GitHub App/secret to validate an inbound webhook against using the attacker-controlled JSON field `repository.owner.login` (or `organization.login`), while the handlers that subsequently act on the payload (e.g. `StatusHandler`) resolve their target purely by `sha`/`full_name` fields taken from that same untrusted body, with no re-check that the authenticated organization actually owns the record being mutated.

### Finding Description
`verify_signature` derives the org used for HMAC verification directly from the JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, then calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. [1](#0-0) 

`GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that specific organization has no `webhook_secret` configured — a state explicitly supported as "optional" by the setup docs (multi-org apps each have their own independent, optionally-blank secret). [2](#0-1) [3](#0-2) 

Once "verified" for that claimed organization, the controller dispatches the same raw, attacker-controlled `params` to every registered handler for the event type with no further scoping. [4](#0-3) 

Critically, `StatusHandler#process` resolves its target purely by commit SHA, globally, with no check that the SHA belongs to a repository owned by the organization whose secret authenticated the request:
```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [5](#0-4) 

This breaks the binding **organization authenticated == repository (commit) written**. Before the attacker's request: signature verification is scoped per-organization config; a commit's CI `Status` history can only legitimately be updated by that commit's own repository's GitHub App/secret. After a forged request: an attacker who can satisfy verification for *any one* configured organization (trivially, one that is documented as valid to leave `webhook_secret` blank) can inject a fabricated `status` event whose `sha` belongs to a totally different, properly-secured organization's commit — because `Commit.where(sha:)` has no organization/repository scoping at all.

### Impact Explanation
`Status` records feed Shipit's `ci.require` gating logic used to decide whether a commit is safe to deploy/merge (`Stack`/`Commit`/`DeploySpec` consult `commit.statuses`). A forged `success` status for a target commit SHA — obtainable from any public commit/PR on GitHub — lets an unprivileged attacker satisfy required CI checks for a stack/repository they have no relationship to, enabling deploys or merge-queue advancement of a commit that never actually passed CI. This matches the in-scope "unauthorized deploy" / cross-organization write impact.

### Likelihood Explanation
Exploitation requires only that the Shipit deployment host at least one GitHub App/organization configuration with an empty `webhook_secret` — a state the project's own setup documentation calls out as optional, not a misconfiguration outside the documented deployment model. No GitHub credentials, `ApiClient` token, session, or knowledge of any other organization's real `webhook_secret` are needed; the attacker only needs the target commit SHA, which is public GitHub information.

### Recommendation
Scope every webhook handler's data lookups (especially `StatusHandler`, but also `Handler#stacks`) to the same organization/repository that was authenticated by `verify_signature`, e.g. by passing the verified `repository_owner`/`repository_name` into the handler and requiring `commit.stack.repository.owner == verified_owner` before mutating state. Additionally, consider rejecting webhooks entirely for organizations with no `webhook_secret` configured rather than silently trusting them, or at minimum never let an unauthenticated/optionally-authenticated organization's verification "success" be usable to affect any other organization's records.

### Proof of Concept
1. Shipit is configured with two GitHub Apps: `OrgA` (no `webhook_secret` set — a documented, supported configuration) and `OrgB` (properly secured, hosts the real target stack/commit).
2. Attacker sends `POST /webhooks` with header `X-Github-Event: status`, body:
```json
{
  "repository": { "owner": { "login": "OrgA" } },
  "sha": "<sha of a real commit under OrgB/target-repo>",
  "state": "success",
  "context": "ci/required-check"
}
```
No `X-Hub-Signature` matching a real secret is required, because `verify_webhook_signature` returns `true` unconditionally for `OrgA` (blank secret): [6](#0-5) .
3. `WebhooksController#create` dispatches to `StatusHandler`, which finds the `OrgB` commit purely by `sha` and writes a spoofed successful `Status` onto it: [5](#0-4) .
4. `OrgB`'s stack now reports the required CI check as passed for that commit, even though `OrgB`'s own webhook secret was never used or known by the attacker.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
