### Title
Sigma-protocol `Proof` allows `comm_A` (used for algebraic verification) to be decoupled from `compressed_comm_A` (used for Fiat-Shamir challenge derivation), enabling complete proof forgery without knowledge of the witness - (File: `aptos-move/framework/aptos-framework/sources/confidential_asset/sigma_protocols/sigma_protocol_proof.move`)

### Summary
The premise in the question (attacker corrupting Fiat-Shamir *input* via "incorrectly decompressed" points) is not quite how the bug manifests, but the underlying observation — that `new_proof` only checks a length equality, not that `compressed_A` is the compression of `_A` — is correct and leads to a much more serious break than a replay: it allows a forged proof that verifies without any knowledge of a valid witness at all.

### Finding Description
`new_proof` in `sigma_protocol_proof.move` only asserts `_A.length() == compressed_A.length()`; it never checks that `compressed_A[i]` actually decompresses to `_A[i]`: [1](#0-0) 

In `sigma_protocol::verify`, the Fiat-Shamir challenge `e` (and the batching coefficients `betas`) are derived from `proof.get_compressed_commitment()` (i.e. `compressed_A`): [2](#0-1) 

...but the actual algebraic MSM check that decides pass/fail is built from `_A = proof.get_commitment()` (the *uncompressed* `comm_A` field), combined with `e` and `f(X)`: [3](#0-2) 

Because `comm_A` and `compressed_comm_A` are never cross-validated, an attacker who controls the raw bytes passed into `new_proof_from_bytes` (`_A_bytes`, `sigma_bytes`) can:
1. Pick `compressed_A` to be anything (e.g. the identity point, repeated), fixing the Fiat-Shamir challenge `e = H(dst, stmt, compressed_A, ...)` and `betas` to values fully computable off-chain, with no dependency on the real `comm_A`.
2. Pick an arbitrary response `sigma` (e.g. all-zero scalars).
3. Compute `A := psi(sigma) - e·f(X)` directly using only public information (`f(X)` from the public statement, `psi` from the known homomorphism) — this requires *no* secret witness at all.
4. Submit `Proof { comm_A: A, compressed_comm_A: compressed_A (unrelated to A), resp_sigma: sigma }`.

`verify` will then compute the same `e` from `compressed_A`, and the MSM identity `Σ β_i·A_i + β_i·e·f(X)_i − β_i·ψ(σ)_i = 0` holds by construction, so `verify` returns `true` even though the "prover" never knew a witness `w` such that `f(X) = ψ(w)`.

This breaks the soundness of every sigma protocol built on this module — registration, withdrawal, transfer, and key-rotation — because the field that the Fiat-Shamir hash is bound to (`compressed_comm_A`) is disjoint from the field that the arithmetic check is performed against (`comm_A`). Note `proof_A` in `FiatShamirInputs` is not "corrupted" in the sense of decoding wrongly; it's simply an independent value the attacker fully controls, decoupled from `comm_A`, which is the real defect (worse than what the question's proof idea describes).

### Impact Explanation
This is a critical soundness break in the confidential-asset ZK verification, not just a Fiat-Shamir/domain-binding replay issue. Confidential asset operations (withdraw, transfer, key rotation, registration — see `sigma_protocol_withdraw.move`'s `assert_verifies`, which is the on-chain gate at `assert_verifies`) rely on `sigma_protocol::verify` to prove the caller knows a valid witness (e.g., decryption key `dk`, balance randomness) tying a state transition to actual encrypted balances: [4](#0-3) 
If this proof can be forged without any real witness, an unprivileged caller could fabricate withdrawal/transfer/key-rotation proofs and get the associated confidential-asset state transition admitted and committed even though no legitimate secret (decryption key, balance opening) was ever known — a "pre-validation mismatch that causes a transaction which should fail admission to execute and commit," per the Admission Impact Gate.

### Likelihood Explanation
High, assuming the proof-input bytes reach `new_proof_from_bytes`/`new_proof` unchecked (as implied by the question) and there is an unprivileged entry point that accepts serialized proof bytes for withdraw/transfer/registration/key-rotation. I was not able to confirm the exact public entry function in `confidential_asset.move` that wires user-supplied bytes into `new_proof_from_bytes` before the tool budget ran out (a targeted grep for `withdraw_proof`/`new_proof_from_bytes`/entry functions in `confidential_asset.move` returned no matches, which is inconsistent with the module clearly needing such wiring — this likely indicates the entry-point naming differs from what I searched, or the file's relevant section wasn't indexed). This should be verified directly against `confidential_asset.move` before treating this as fully confirmed at the transaction-admission boundary.

### Recommendation
In `new_proof` (and/or `new_proof_from_bytes`), assert that each point in `compressed_A` is the compression of the corresponding point in `_A` (e.g., `compressed_A[i] == A[i].compress()` or decompress `compressed_A` and compare/derive `_A` from it directly, eliminating the redundant/uncorrelated field). Alternatively, remove the separate `comm_A`/`compressed_comm_A` duality and derive one deterministically from the other so they can never diverge.

### Proof of Concept
Conceptually (Move pseudocode), given a known statement `stmt` and homomorphism `psi`/`f` for e.g. `Withdrawal`:
```
let sigma = vector[scalar_zero(), scalar_zero(), ...]; // attacker knows no real witness
let compressed_A = vector[point_identity_compressed(), ...]; // arbitrary, attacker's choice
let (e, betas) = fiat_shamir(dst, &stmt, &compressed_A, &sigma, sigma.length());
let fx = evaluate_f(f, &stmt);
let psi_sigma = evaluate_psi(psi, &stmt, &sigma);
// Solve A_i = psi_sigma_i - e * fx_i for each i (no secret needed)
let A = compute_A_from_public_values(psi_sigma, fx, e);
let proof = sigma_protocol_proof::new_proof(A, compressed_A, sigma); // succeeds: only length check
assert!(sigma_protocol::verify(dst, psi, f, &stmt, &proof)); // returns true — forged!
```
This should be turned into an actual `#[test]` in `sigma_protocol_proof_tests.move`/`sigma_protocol_withdraw.move`'s test module to confirm `verify` accepts a proof built this way with an all-zero (or otherwise witness-independent) `sigma`, and to confirm that after adding a `compressed_A[i] == A[i].compress()` check to `new_proof`, the same construction is rejected.
