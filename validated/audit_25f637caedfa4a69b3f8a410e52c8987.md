### Title
Unsanitized `X-Oauth-Scopes` header content is rendered directly to the terminal in `gh auth status`, allowing terminal escape-sequence injection - ([File: pkg/cmd/auth/shared/oauth_scopes.go])

### Summary
`GetScopes` returns the raw `X-Oauth-Scopes` response header value with no sanitization, and this value flows unmodified into `authEntry.Scopes`, then through `displayScopes(e.Scopes)` into `fmt.Fprintf` calls in `authEntry.String`, which write directly to the terminal via `cs.Bold(...)`. Nothing in this path strips ANSI/control bytes, even though the codebase has a dedicated `iostreams.Untrusted` type specifically built to sanitize exactly this class of untrusted external content before printing.

### Finding Description
`GetScopes` performs `res.Header.Get("X-Oauth-Scopes")` and returns it as-is: [1](#0-0) 

This value is stored verbatim into `entry.Scopes` in `buildEntry`: [2](#0-1) 

It is then rendered via `displayScopes`, which only splits on commas and quotes each token but performs no control-character stripping: [3](#0-2) 

and printed with `fmt.Fprintf(... cs.Bold(displayScopes(e.Scopes)) ...)` directly to `stdout`/`stderr`: [4](#0-3) 

Go's HTTP client/`net/textproto` header parsing only prevents raw CR/LF from appearing *within* a single header value (since those bytes terminate the header line), but it does not filter other control bytes such as ESC (`0x1B`) or CSI sequences from a header value. Since `X-Oauth-Scopes` originates from the response of whatever host `gh` is configured to talk to (`GetScopes` builds the request against `ghinstance.RESTPrefix(hostname)`), a malicious or compromised GitHub Enterprise-style host that a victim has configured `gh` to talk to controls this header's contents and can embed ANSI/CSI escape sequences in it.

Critically, this codebase already has a purpose-built defense for this exact scenario — `iostreams.Untrusted`, whose doc comment explicitly says it exists to wrap "HTTP response bodies ... anything that originates outside the CLI" so that ANSI escape sequences are neutralized before being printed: [5](#0-4) 

That type is used in other code paths (e.g. `pkg/cmd/gist/shared/shared.go`, `pkg/cmd/gist/view/view.go`, `pkg/cmd/agent-task/shared/log.go`) but is **not** applied to the `X-Oauth-Scopes` header value in `oauth_scopes.go` or `status.go`, so the escaping mechanism the project already recognizes as necessary for untrusted remote text is simply missing on this path.

### Impact Explanation
This allows terminal escape-sequence / ANSI injection into `gh auth status` output. Depending on the victim's terminal emulator, this can be used for output spoofing (hiding or rewriting displayed text, e.g. making scopes/missing-scope warnings appear different from reality), clearing the screen, manipulating the terminal title, or in vulnerable terminal emulators, more serious effects (e.g. querying/exfiltrating terminal state via response-generating escape sequences, or triggering OSC 52 clipboard writes). This matches a "terminal escape-sequence injection / output spoofing in a trusted CLI's own output" impact class rather than remote code execution, since the payload only reaches the terminal renderer, not the shell.

### Likelihood Explanation
Exploitation requires the victim to run `gh auth status` (or `gh auth login`/`refresh`, which also call `HasMinimumScopes`/`GetScopes`) against a hostname under attacker control or an attacker-controlled GHES-like host the victim has been convinced to add via `gh auth login --hostname`. This is a somewhat narrower precondition than a public GitHub.com attack (github.com's real API would not emit malicious header values), but the code path itself imposes no such restriction — `hostname` and `authToken` are attacker-influenceable inputs to `GetScopes`, and the header value is trusted verbatim all the way to the terminal.

### Recommendation
Sanitize the scopes header before storing/displaying it — either wrap the value with `iostreams.NewUntrusted(...)` at the point it's read in `oauth_scopes.go`/`status.go` and let its `String()` method neutralize ANSI sequences before formatting, or apply the same `asciisanitizer`/control-stripping logic directly in `displayScopes` before quoting each scope token.

### Proof of Concept
```go
func TestDisplayScopesDoesNotLeakControlBytes(t *testing.T) {
    malicious := "repo\x1b[2J\x1b]0;pwned\x07, read:org"
    out := displayScopes(malicious)
    if strings.ContainsAny(out, "\x1b\x07") {
        t.Fatalf("expected control bytes to be stripped, got: %q", out)
    }
}
```
Combined with an `httpmock` responder for `GET /` (or whatever `ghinstance.RESTPrefix` resolves to for the target host) that sets `X-Oauth-Scopes` to a string containing `\x1b[...` sequences, then invoking `statusRun` and asserting that `opts.IO.Out`/`ErrOut` buffers contain no raw `0x1B` bytes, would demonstrate the injection reaching the printed output as it currently stands (no such stripping exists today).

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
