### Title
Stale delegate grant re-arms when the position NFT returns to the granting owner, restoring a manager's borrow/withdraw authority without re-authorization - (File: contracts/controller/src/storage/account.rs)

### Summary
A delegate grant is stored as a single `DelegateGrant` keyed by `account_id` and stamped with `granted_by` (the owner at grant time). When the position NFT is transferred, the grant is not deleted — it merely becomes inactive because `get_delegates` compares `granted_by` to the *current* owner. If the NFT later returns to the original owner without an intervening owner having overwritten (`add_delegate`) or purged (`remove_delegate`) the stale entry, the old delegate silently regains full owner-or-delegate authority over the account. This mirrors the reported class: an authorization bound to an outdated state persists in storage and re-activates after a later change, affecting "previously minted" state the owner reasonably believed was inert.

### Finding Description
- `storage::add_delegate` writes `DelegateGrant { granted_by: owner, delegates }` under `ControllerKey::Delegates(account_id)` — a single per-account slot shared across owner eras [1](#0-0) .
- `get_delegates` returns the stored list only when `grant.granted_by == owner`, so a transfer freezes the grant rather than deleting it [2](#0-1) .
- `storage::remove_delegate` deletes a `granted_by`-mismatched stale grant **only when the current owner explicitly calls it**; if no intervening owner ever touches delegates, the stale entry survives intact [3](#0-2) .
- `is_owner_or_delegate` then accepts the re-armed delegate whenever its position-manager registration is still active — and reactivation of the manager flag re-arms the stored grant too, as pinned by `deactivating_the_manager_kills_a_stored_grant_immediately` [4](#0-3) [5](#0-4) .
- The unit test `remove_delegate_purges_stale_grant_preventing_resurrection` confirms resurrection is the default outcome absent that explicit purge: it exists precisely because the grant would otherwise come back [6](#0-5) .

### Impact Explanation
Theft of user funds. A re-armed delegate can call `borrow` or `withdraw` on the account with `to` set to an address it controls — the threat model itself notes delegates "can borrow/withdraw to their chosen recipient" and the gates "do not constrain them to acting in the owner's economic interest" [7](#0-6) . The regained authority was never authorized by the current ownership context: the returning owner sees an account with no active delegates surfaced in any UI keyed to `granted_by`, yet the stale grant is armed the moment `owner_of` resolves to them again.

### Likelihood Explanation
Requires a specific but realistic sequence: owner grants a manager, transfers the NFT out (secondary-market sale, custody change, collateral reorganization), and later reacquires it, with no intermediate owner calling `add_delegate`/`remove_delegate`. Position NFTs are transferable and enumerated, so out-and-back flows (failed sales, marketplace delisting, wallet migration) are plausible. The delegate (an unprivileged address) needs no action beyond calling `borrow`/`withdraw` once it observes the NFT return — checking `owner_of` is free. Intermediate friction is low: buyers of a lending position have no reason to call `remove_delegate` on a grant that reads empty to them. Medium likelihood, Medium impact → Medium.

### Recommendation
Purge or epoch-bind the grant on transfer rather than on read. Options:
- Stamp the grant with a transfer epoch/counter bumped by the controller whenever NFT ownership changes, and treat `granted_by` mismatches as permanently dead (the current `remove_delegate` purge behavior, applied universally).
- Alternatively, have `add_delegate` by any new owner overwrite unconditionally (it already overwrites wholesale — extend this so the first delegate mutation of any kind by a new owner clears the stale entry), and document that sellers/buyers should call `remove_delegate` once per transfer.
- At minimum, emit an event or expose a view so a returning owner can detect an armed stale grant.

### Proof of Concept
1. Alice owns `account_id` = NFT `token_id`. Governance has activated `M` via `set_position_manager(M, true)`.
2. Alice calls `add_delegate(caller=alice, account_id, delegate=M)`. `DelegateGrant{granted_by: alice, delegates:[M]}` is stored.
3. Alice calls `PositionNft::transfer(alice → bob, token_id)`. `get_delegates(account_id, bob)` now reads empty; `M` calling `borrow` reverts `NotAuthorized` — Bob reasonably believes `M` has no power. Bob never calls `add_delegate` or `remove_delegate`, so the stale entry stays in persistent storage.
4. Bob transfers the NFT back to Alice (sale unwound / repurchase). `grant.granted_by == alice` again; `is_owner_or_delegate(account_id, M, alice)` returns true.
5. `M` calls `borrow(caller=M, account_id, borrows=[...], to=M_controlled)` or `withdraw(..., to=M_controlled)`, draining the account's borrowable value/collateral — authority Alice never re-granted after the ownership round-trip. The purge path in `remove_delegate` (lines 236–238 of `storage/account.rs`) never ran because no intermediate owner invoked it.

```rust
pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
}
```

```rust
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}
```

```rust
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}
```

```rust
#[test]
fn remove_delegate_purges_stale_grant_preventing_resurrection() {
    let env = Env::default();
    env.mock_all_auths();
    let admin = Address::generate(&env);
    let contract_id = env.register(Controller, (admin,));
    let nft = setup_position_nft(&env, &contract_id);

    let alice = Address::generate(&env);
    let bob = Address::generate(&env);
    let delegate = Address::generate(&env);
    let account_id = u64::from(position_nft::PositionNftClient::new(&env, &nft).mint(&alice));

    env.as_contract(&contract_id, || {
        assert!(add_delegate(&env, account_id, &alice, &delegate));
        assert_eq!(get_delegates(&env, account_id, &alice).len(), 1);
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &alice,
        &bob,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert!(!remove_delegate(&env, account_id, &bob, &delegate));
        assert!(
            !env.storage()
                .persistent()
                .has(&ControllerKey::Delegates(account_id)),
            "stale grant must be purged from storage, not merely read as empty"
        );
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &bob,
        &alice,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert_eq!(
            get_delegates(&env, account_id, &alice).len(),
            0,
            "the purged grant must not resurrect when the NFT returns to its original owner"
        );
    });
}
```
