### Title
Delimiter Injection in Arbiter Contract Hash Computation Allows Contract Content Forgery - ([File: arbiter_contract.js])

### Summary
The undici advisory describes a class of bug where a value is pushed into a delimited, structured protocol field without being checked against the same validation rules applied to sibling fields, allowing an attacker to inject the field separator itself and corrupt the parsed structure. `ocore`'s arbiter-contract subsystem has an analogous flaw: `getHashSrc()` in [1](#0-0)  concatenates several free-text, peer-controlled fields (`title`, `text`, `my_party_name`/`peer_party_name`) using a fixed string delimiter `exports.DELIMITER = "[|#|]"` [2](#0-1)  to compute the contract's integrity hash, but none of the incoming-message validation code checks that these fields don't already contain the delimiter substring.

### Finding Description
`getHash()`/`getHashSrc()` builds a single string from `[title, text, creation_date, payer_address, payer_name, arbiter_address, payee_address, payee_name, amount, asset].join(exports.DELIMITER)` and hashes it with SHA-256 [3](#0-2) . This hash is treated as an integrity/authentication check on the contract's terms:
- On receipt of an `arbiter_contract_offer` device message, the code enforces `body.hash === arbiter_contract.getHash(body)` [4](#0-3) .
- On receipt of `arbiter_contract_shared`, the same check is repeated [5](#0-4) .
- During dispute handling (`arbiter_dispute_request`), the arbiter recomputes `expectedContractHash` from decrypted `contractContent.title`/`contractContent.text`/party names and compares it to `body.contract_hash` [6](#0-5) .

The only validation performed on `title`, `text`, `my_party_name`, and `peer_party_name` is a non-empty/string-type check — there is no rejection of the delimiter substring itself [7](#0-6) . Because address fields, `arbiter_address`, `amount`, and `asset` are separately validated to be well-formed addresses/numbers/hashes and therefore cannot contain `[|#|]`, the only unguarded fields are the free-text ones. Since `Array.join(delimiter)` is not a bijective encoding when elements may themselves contain the delimiter, two different `(title, text, my_party_name, peer_party_name)` tuples can be crafted to produce the *same* joined string and thus the same hash — exactly the same defect class as pushing an unvalidated `body.type` directly into a CRLF-delimited header list in the undici advisory: a structural delimiter is trusted to separate fields, but attacker-controlled content bypasses the validation applied to other fields feeding the same structure.

### Impact Explanation
The forged/colliding hash lets a malicious contract counterparty present different contract wording to different recipients (peer device, cosigners, or later the arbstore/arbiter during a dispute) while all sides still validate the same `hash`/`contract_hash`. Since this hash is exactly the value the arbiter trusts to confirm the dispute content matches what was actually signed on-chain (`payload.contract_text_hash !== body.contract_hash` check at [8](#0-7) ), an attacker acting as one of the private-payment counterparties in an arbitrated contract could bias the dispute resolution outcome with forged terms, resulting in an arbiter releasing shared-address funds against different obligations than the ones the honest party actually agreed to — i.e., fund loss/misdirection for the honest party in the multisig `shared_address` used to escrow the contract amount.

### Likelihood Explanation
Reachable by any unprivileged paired device acting as a contract counterparty; no special privileges beyond normal arbiter-contract usage are required. Exploitation only requires the attacker to control the wording of `title`/`text`/party names when creating or accepting a contract, which they always do in this flow, and to include the literal `[|#|]` sequence — an unusual but easily craftable string that ordinary UI text-entry does not filter.

### Recommendation
Reject or escape occurrences of `exports.DELIMITER` (or any characters that could be interpreted as the join separator) in `title`, `text`, `my_party_name`, and `peer_party_name` before they are stored/hashed, matching the same validation rigor already applied to addresses/amounts. Alternatively, replace the delimiter-joined string with a length-prefixed or JSON-based canonical serialization (e.g., hash `JSON.stringify` of a fixed-order object) so field boundaries cannot be manipulated by field content.

### Proof of Concept
1. Party A crafts an `arbiter_contract_offer` with `title = "Sale of item[|#|]Refund: none"`, `text = "Standard terms"`.
2. Party A also computes an alternate tuple `title' = "Sale of item"`, `text' = "Refund: none[|#|]Standard terms"` — both tuples produce the identical joined string once concatenated with the other fixed fields, hence identical `SHA256` hash via `getHash()` [3](#0-2) .
3. Party A sends the peer/cosigner one variant and, during a later `arbiter_dispute_request`, supplies the arbiter with `encrypted_contract` containing the other variant; the arbiter's `expectedContractHash` check at [6](#0-5)  still passes because both variants collide on `getHash()`, letting the arbiter unknowingly adjudicate different contract terms than what the counterparty actually agreed to.

```javascript
function getHashSrc(contract) {
	const payer_name = contract.me_is_payer ? contract.my_party_name : contract.peer_party_name;
	const payee_name = contract.me_is_payer ? contract.peer_party_name : contract.my_party_name;
	const payer_address = contract.me_is_payer ? contract.my_address : contract.peer_address;
	const payee_address = contract.me_is_payer ? contract.peer_address : contract.my_address;
	const src = contract.creation_date > exports.NEW_HASH_DATE
		 ? [contract.title, contract.text, contract.creation_date, payer_address, payer_name || '', contract.arbiter_address, payee_address, payee_name || '', contract.amount, contract.asset || 'null'].join(exports.DELIMITER)
		 : [contract.title, contract.text, contract.creation_date, payer_name || '', contract.arbiter_address, payee_name || '', contract.amount, contract.asset || 'null'].join("");
	return src;
}

function getHash(contract) {
	return crypto.createHash("sha256").update(getHashSrc(contract), "utf8").digest("base64");
}
```
