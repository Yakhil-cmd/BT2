The CVE-2017-12938 concerns UnRAR's directory-traversal bypass via symlink handling during archive extraction — a local file-extraction library flaw. I searched for archive/path-traversal patterns in the codebase and found only:

- Sandbox/defensive code for validator PVF workers (`change_root.rs`, `landlock.rs`) that restricts what the worker process itself can access — this is not attacker-reachable input, it's the validator's own protection mechanism against malicious PVF code, not a directory-traversal check being bypassed by attacker-supplied paths. [1](#0-0) 
- `untar_bundle` usage in zombienet test fixtures, which is test/CI-only tooling operating on developer-controlled paths, not a signed extrinsic, XCM message, or contract call reachable by an unprivileged attacker. [2](#0-1) 
- `pallet-transaction-storage`/archive RPC code, which parses hex parameters and storage queries but does no filesystem path construction from attacker input. [3](#0-2) 

None of these constitute a real user-entry point (signed extrinsic, XCM execute/send, or contract call) that takes an attacker-controlled path/archive and performs extraction with symlink-based directory-traversal checks that could be bypassed the way UnRAR's were. Polkadot SDK's runtime and node code does not perform archive extraction on attacker-supplied data as part of consensus-critical or fee-paying transaction processing, so there is no demonstrable analog to this CVE's violated invariant (symlink-based traversal-check bypass) within the scope of extrinsics, XCM, or contract execution paths.
