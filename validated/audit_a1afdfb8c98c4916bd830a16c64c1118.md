## Confirmed Vulnerability

### Title
Webhook signature verification keyed on `repository.owner.login` while stack mutation keyed on `repository.full_name` allows cross-org signature bypass and unauthenticated stack sync - ([File: app/controllers/shipit/webhooks_controller.rb, File: app/models/shipit/webhooks/handlers/handler.rb, File: lib/shipit/github_app.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App/org's `webhook_secret` to use for HMAC verification based on `params.dig('repository','owner','login')`, but `Shipit::Webhooks::Handlers::Handler#stacks`/`#repository_name` (used by `PushHandler#process`) instead resolve the target `Stack` from `payload.dig('repository','full_name')`. Because these two fields are independently attacker-controlled in the same JSON body and are never cross-checked, an attacker can set `repository.owner.login` to an org that Shipit has configured with no `webhook_secret` (which makes `GitHubApp#verify_webhook_signature` unconditionally return `true`), while setting `repository.full_name` to `victim-org/victim-repo` to target a real stack.

### Finding Description
The broken binding: the code implicitly assumes
`org_used_to_verify_signature (params.repository.owner.login) == org_owning_the_stack_being_mutated (params.repository.full_name)`.
This is never enforced.

- `verify_signature` in `app/controllers/shipit/webhooks_controller.rb:24-30` calls `Shipit.github(organization: repository_owner)` and `repository_owner` reads `params.dig('repository', 'owner', 'login')` (`app/controllers/shipit/webhooks_controller.rb:59-62`).
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) contains: `return true unless webhook_secret` — i.e., if the resolved org's config has no `webhook_secret` set, verification passes for **any** signature/body, including a missing or garbage `X-Hub-Signature` header.
- Once `head(422)` is not triggered, `WebhooksController#create` parses the body and dispatches to handlers (`app/controllers/shipit/webhooks_controller.rb:10-15`).
- `PushHandler#process` (`app/models/shipit/webhooks/handlers/push_handler.rb:12-17`) calls `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }`.
- `stacks` and `repository_name` in `Handler` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) resolve strictly via `payload.dig('repository', 'full_name')`, completely independent of `repository.owner.login` used earlier for signature verification.
- `Shipit.github_app_config`/`github_organizations` (`lib/shipit.rb:170-200`) confirm Shipit natively supports multi-org configuration where each org has its own `webhook_secret`, and the docs (`docs/setup.md:181-209`) and test fixtures (`test/dummy/config/secrets_double_github_app.yml`) show it's a supported, real configuration to have multiple orgs, some without a `webhook_secret` set (`webhook_secret: # nil`).

**Exploit flow**: Attacker sends `POST /webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "attacker_chosen_sha",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "throwaway-org" }
  }
}
```
where `throwaway-org` is any org configured in Shipit's `github` secrets with no `webhook_secret`. `verify_signature` resolves `Shipit.github(organization: 'throwaway-org')`, whose `verify_webhook_signature` returns `true` unconditionally (no secret to check against), regardless of the `X-Hub-Signature` header content. The request proceeds to `PushHandler#process`, which resolves the target stack via `full_name` = `victim-org/victim-repo` (unrelated to the org used for verification) and calls `stack.sync_github(expected_head_sha: 'attacker_chosen_sha')`.

**Why existing guards fail**: `drop_unhandled_event` only filters unknown event types; `verify_signature`'s only guard against unknown orgs is raising `GithubOrganizationUnknown` (422) if the org string doesn't match any configured org — but a valid, intentionally-secretless org name still passes. No code cross-validates that the org used for HMAC verification actually owns the repository named in `full_name`.

### Impact Explanation
This lets any unauthenticated attacker cause `Stack#sync_github` to run for `victim-org/victim-repo` with `expected_head_sha` set to an attacker-chosen string, via `GithubSyncJob` (`app/jobs/shipit/github_sync_job.rb`). This can drive the stack's recorded commit history/head expectations off legitimate GitHub state, is repeatable against any repository whose owning org has a Shipit stack, provided the Shipit deployment (a) uses the multi-org config format and (b) has at least one configured org without a `webhook_secret`. This matches the Critical category: "a payload for one repository mutating another's stack" / "unauthorized deploy, rollback."

### Likelihood Explanation
Requires the specific but realistic and documented precondition of a multi-org Shipit deployment where at least one configured org has no `webhook_secret` (shown as a supported pattern in `docs/setup.md`, `test/dummy/config/secrets_double_github_app.yml`, and `config/secrets.development.shopify.yml`). Attacker cost is a single unauthenticated HTTP POST with a crafted JSON body — no secrets, sessions, or tokens needed. Fully repeatable and scriptable against arbitrary victim repos as long as the secretless-org precondition holds in that deployment.

### Recommendation
Cross-validate that the organization resolved from `repository.owner.login` (used for signature verification) matches the organization implied by `repository.full_name` before processing any handler; reject mismatches. Additionally, treat a missing `webhook_secret` for a configured org as a hard misconfiguration (fail closed, e.g. raise/reject) rather than silently bypassing signature verification in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
minitest plan (extends `test/controllers/webhooks_controller_test.rb`):
```ruby
test "push payload with mismatched owner login vs repository full_name syncs the wrong stack" do
  # Precondition: configure Shipit with a secretless org "throwaway-org"
  Shipit.stubs(:github_app_config).with('throwaway-org').returns({}) # no webhook_secret
  Shipit.stubs(:github_default_organization).returns('throwaway-org')

  victim_stack = shipit_stacks(:shipit) # repository full_name = "victim-org/victim-repo"

  body = {
    ref: "refs/heads/#{victim_stack.branch}",
    after: "attacker_chosen_sha",
    repository: {
      full_name: victim_stack.repository.full_name,
      owner: { login: "throwaway-org" }
    }
  }.to_json

  @request.headers['X-Github-Event'] = 'push'
  @request.headers['X-Hub-Signature'] = 'sha1=not_a_real_signature'

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: "attacker_chosen_sha"]) do
    post :create, body: body, as: :json
  end
  assert_response :ok
end
```
This asserts: (1) the bogus `X-Hub-Signature` is never actually validated against `victim-org`'s secret (the org used, `throwaway-org`, has none), and (2) `Stack#sync_github` still receives the attacker-chosen `expected_head_sha` for the victim's stack — proving the two org identities (`repository.owner.login` vs `repository.full_name`'s owner) diverge without being caught.     def verify_webhook_signature(signature, message)
```ruby
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

A Github application can only authenticate to the Github organization it's installed in. If you want to deploy code from multiple Github organizations the `github` section of your `config/secrets.yml` will need to be formatted differently.
