Based on my research, I found a direct structural analog to the reported `Minter` depeg issue within `pallet-psm`, which implements a Peg Stability Module wired into the `asset-hub-westend` runtime.

### Title
`pallet-psm::mint`/`redeem` assume a permanent 1:1 peg between internal and external assets with no on-chain price check, allowing depeg drain during the governance reaction window - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet-psm` implements a 1:1 swap mechanism between an internal stablecoin (e.g. pUSD) and pre-approved external assets (e.g. USDC, USDT), converting only for **decimal precision**, never for **price**. If an approved external asset depegs (trades below its assumed $1 value), any signed account can call `mint` and receive internal-asset debt at the stale 1:1 rate, extracting more value than deposited. The only backstop is a human-operated circuit breaker (`set_asset_status`) reachable via a `Full`/`Emergency` admin or the `MonetaryGuard` governance track — there is no on-chain price oracle or automatic halt. This is structurally identical to the reported `Minter` bug, where `baseAsset`→`hilBTCToken` conversion ignored exchange rate/depeg risk and the vendor's fix relied on an off-chain bot to pause the contract, a mitigation Cyfrin explicitly flagged as leaving residual risk.

### Finding Description
`Psm::mint` (`substrate/frame/psm/src/lib.rs:703-768`) converts `external_amount` to `internal_equivalent` purely via decimal scaling helpers `external_to_internal`/`internal_to_external` (`substrate/frame/psm/src/lib.rs:1621-1651`), with no reference to a live price feed: [1](#0-0) 

The pallet's own design doc confirms the swap is *always* treated as 1:1 modulo fees: [2](#0-1) 

The only protection against a depegged external asset is the per-external `CircuitBreakerLevel` (`AllEnabled`/`MintingDisabled`/`AllDisabled`), toggled via `set_asset_status`, which requires the PSM instance's `full_admin`/`emergency_admin` or (on Asset Hub Westend) the `MonetaryGuard` governance track: [3](#0-2) [4](#0-3) 

This is the on-chain equivalent of the external report's "off-chain bot" mitigation: someone (bot, `emergency_admin`, or governance) must *observe* the depeg and *react* by calling `set_asset_status` before an attacker exploits it. Between the depeg event and that reaction, `mint` is fully permissionless and unguarded — exactly the residual risk Cyfrin flagged as "Verified" in the source report.

### Impact Explanation
If an approved external asset (e.g. a stablecoin) depegs below $1, any signed account can:
1. Acquire the depegged asset cheaply on a DEX.
2. Call `Psm::mint` to receive `internal_asset` (pUSD or equivalent) at the stale 1:1 rate, up to the per-asset/aggregate debt ceiling (`ExceedsMaxPsmDebt` check, `substrate/frame/psm/src/lib.rs:733-742`).
3. Immediately `redeem` against *other* healthy externals in the same PSM instance (draining their reserves), or dump the freshly minted internal asset elsewhere, realizing an arbitrage profit funded by the PSM reserve/other depositors.

This is unbacked issuance / reserve drain — a Critical/High-class outcome (theft/loss of protocol funds) — but it is entirely contingent on an external market depeg event, and the window of exposure is bounded by how quickly `MonetaryGuard`/admins react. No privileged role or key compromise is needed by the attacker; a normal `Signed` origin suffices.

### Likelihood Explanation
Likelihood is Medium, not High: exploitation requires (a) an external asset actually depegging while approved, and (b) the emergency/governance response failing to act before the debt ceiling is exhausted. Because the emergency track (`MonetaryGuard`) exists specifically to react quickly, this mirrors the vendor's already-implemented, already-audited mitigation pattern (off-chain bot/governance pause) — the same residual-risk class the original report's auditor accepted rather than required a hard on-chain fix for. This is a known-and-accepted design tradeoff of peg-stability modules (e.g. MakerDAO's PSM has the same property), not a novel logic bug, and the report explicitly frames it as "Verified" with residual risk rather than a blocking Critical.

### Recommendation
- Integrate an on-chain price oracle (e.g. `pallet-oracle`, already present in this codebase at `substrate/frame/honzon/oracle`) so `mint`/`redeem` can revert or scale amounts if the external asset's observed price deviates from its peg beyond a configurable tolerance.
- Alternatively/additionally, add an automatic debt-velocity or price-deviation circuit breaker that does not depend on a human/governance transaction being submitted in time.
- Document the residual risk window explicitly for `MonetaryGuard` operators and consider tightening per-asset debt ceilings to bound worst-case drain per depeg event.

### Proof of Concept
No new PoC was executed; this is a design-level analog rather than a distinct exploitable code path. The existing test suite already exercises the exact mechanics that make this feasible (unconditional 1:1 mint/redeem, and circuit breaker as the sole guard): [5](#0-4) 

A full reproduction would extend this test module to (1) mint against `USDC_ASSET_ID` at par while simulating a depegged price (no on-chain check exists to simulate against, since price is never read), and (2) confirm `Psm::mint` succeeds and increases `PsmDebt` regardless of any real-world price, only blocked once `set_asset_status`/`ExceedsMaxPsmDebt` intervenes — which is precisely the guard-order this report identifies as insufficient without an oracle. No execution against a public network was performed or claimed.

		pub fn set_asset_status(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			status: CircuitBreakerLevel,
		) -> DispatchResult {
			Self::ensure_psm_admin(origin, &internal_asset, |l| l.can_set_circuit_breaker())?;
			ExternalAssets::<T>::try_mutate(
				&internal_asset,
				&external_asset,
				|maybe| -> DispatchResult {
					let info = maybe.as_mut().ok_or(Error::<T>::AssetNotApproved)?;
					info.status = status;
					Ok(())
				},
			)?;

				500 * INTERNAL_UNIT,
				Permill::zero()
			));

			// Baseline: AllEnabled — both swaps work.

				RuntimeOrigin::signed(ALICE),

				Permill::zero()
