### Title
Unbounded per-block work in partitioned epoch-reward distribution despite capped block count - ([File: runtime/src/bank/partitioned_epoch_rewards/mod.rs])

### Summary
`Bank::get_reward_distribution_num_blocks` caps the *number of blocks* used to distribute rewards to `slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH`, but it does not cap the *number of stake accounts processed per block*. An attacker who creates an extremely large number of low-balance, minimally-delegated stake accounts can inflate `total_stake_accounts` (`rewards.num_rewards()`) far beyond `partitioned_rewards_stake_account_stores_per_block * max_num_chunks`, causing each of the (capped) distribution blocks to process a proportionally unbounded number of stake accounts in `store_stake_accounts_in_partition`.

### Finding Description
`get_reward_distribution_num_blocks` computes `num_chunks = total_stake_accounts.div_ceil(partitioned_rewards_stake_account_stores_per_block)` and then clamps it to `[1, slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH]` [1](#0-0) . This clamp only bounds the *count of blocks* (`num_partitions`), which is stored in the `EpochRewards` sysvar and used by `distribute_partitioned_epoch_rewards` to determine the distribution window [2](#0-1) .

Critically, `hash_rewards_into_partitions` (invoked once at the start of the distribution phase) divides *all* `total_stake_accounts` rewards into exactly `num_partitions` partitions — the capped block count — with no secondary bound on how many stake accounts land in a single partition [3](#0-2) . Each block then calls `distribute_epoch_rewards_in_partition` → `store_stake_accounts_in_partition`, which iterates over every index in that block's partition, deserializes/updates/re-serializes each stake account, and stores it to accounts-db [4](#0-3) .

Because `partitioned_rewards_stake_account_stores_per_block` is only used as the divisor to *estimate* `num_chunks` before clamping — and the clamp's upper bound is a fixed fraction of `slots_per_epoch`, independent of `total_stake_accounts` — once `total_stake_accounts` grows large enough that the unclamped `num_chunks` would exceed `slots_per_epoch / 10`, the actual per-block account count (`total_stake_accounts / num_partitions`) grows linearly and unboundedly with the number of stake accounts created, rather than staying near the configured `partitioned_rewards_stake_account_stores_per_block` target. This directly contradicts the intended invariant that per-block work during epoch-boundary reward distribution is bounded.

An unprivileged attacker can reach this path purely through normal `stake::instruction::delegate_stake` calls: fund many stake accounts at/above the minimum delegation, delegate them to attacker-controlled (or any) vote accounts, and wait for an epoch boundary. `process_new_epoch` → `begin_partitioned_rewards` → `get_reward_distribution_num_blocks` will compute an artificially large `total_stake_accounts` figure that inflates work-per-block for every validator processing the same reward distribution blocks (this is deterministic bank-state logic, replayed identically by all validators) [5](#0-4) .

### Impact Explanation
This inflates per-block CPU/IO work (account deserialization, reward math, and `store_accounts` calls) during the fixed set of epoch-boundary reward-distribution blocks, for every validator in the cluster simultaneously (since bank replay of reward distribution is deterministic and mandatory), potentially slowing or stalling block production network-wide. This matches the "stall every validator's epoch-boundary block production" impact category for `core`/`runtime` epoch-boundary processing.

### Likelihood Explanation
Feasibility requires the attacker to fund and activate a very large number (potentially millions, depending on `partitioned_rewards_stake_account_stores_per_block` config and `slots_per_epoch`) of stake accounts at minimum delegation before an epoch boundary. This is costly (rent-exempt reserve × N accounts, plus minimum-delegation lamports), but it uses only unprivileged, self-funded actions (`delegate_stake`) with no signer/authority bypass required, and is fully repeatable each epoch. The severity scales with capital the attacker is willing to spend, so likelihood is moderate-to-low in practice but structurally unbounded — there is no protocol-level cap tying `total_stake_accounts` to a hard ceiling.

### Recommendation
Either (a) cap `total_stake_accounts` participating in a single epoch's reward distribution (e.g., via a maximum number of rewarded stake accounts per epoch, dropping/queuing excess), or (b) make the number of distribution blocks scale with `total_stake_accounts` without an upper clamp tied only to `slots_per_epoch`, ensuring `total_stake_accounts / num_partitions` stays bounded by `partitioned_rewards_stake_account_stores_per_block` even if that requires spilling distribution beyond the current epoch, or (c) impose a global cap on the number of stake accounts eligible to receive partitioned rewards per epoch (independent of delegation count), rejecting/deferring excess delegations from consideration in `calculate_rewards_for_partitioning`.

```rust
#[test]
fn test_reward_distribution_per_block_work_unbounded() {
    // Use small epoch (32 slots) and stake_account_stores_per_block = 10,
    // as in test_get_reward_distribution_num_blocks_cap.
    // max blocks = 32/10 = 3 (clamped).
    let huge_num_stakes = 1_000_000u64; // simulate attacker-created stake accounts
    let stake_rewards = (0..huge_num_stakes)
        .map(|_| Some(PartitionedStakeReward::new_random()))
        .collect::<PartitionedStakeRewards>();

    let num_blocks = bank.get_reward_distribution_num_blocks(&stake_rewards);
    assert_eq!(num_blocks, 3); // capped, as expected

    let accounts_per_block = huge_num_stakes / num_blocks;
    // Assert failure of the intended invariant: per-block work should stay
    // bounded near `stake_account_stores_per_block` (10), but instead grows
    // linearly with attacker-supplied stake count.
    assert!(
        accounts_per_block > 10 * 1000,
        "expected per-block work bounded near configured target, got {accounts_per_block}"
    );
}
```
Expected result: the assertion demonstrating `accounts_per_block` far exceeds `partitioned_rewards_stake_account_stores_per_block` passes, proving the number-of-blocks clamp does not bound per-block work. A follow-up integration test should measure wall-clock time of `distribute_epoch_rewards_in_partition`/`store_stake_accounts_in_partition` for increasing `N` and show it grows roughly linearly with `N`, confirming unbounded per-block work.

```rust
    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }
```

```rust
    pub(in crate::bank) fn distribute_partitioned_epoch_rewards(&mut self) {
        let EpochRewardStatus::Active(status) = &self.epoch_reward_status else {
            return;
        };

        let distribution_starting_block_height = match &status {
            EpochRewardPhase::Calculation(status) => status.distribution_starting_block_height,
            EpochRewardPhase::Distribution(status) => status.distribution_starting_block_height,
        };

        let height = self.block_height();
        if height < distribution_starting_block_height {
            return;
        }

        if let EpochRewardPhase::Calculation(status) = &status {
            // epoch rewards have not been partitioned yet, so partition them now
            // This should happen only once immediately on the first rewards distribution block, after reward calculation block.
            let epoch_rewards_sysvar = self.get_epoch_rewards_sysvar();
            let (partition_indices, partition_us) = measure_us!({
                epoch_rewards_hasher::hash_rewards_into_partitions(
                    &status.all_stake_rewards,
                    &epoch_rewards_sysvar.parent_blockhash,
                    epoch_rewards_sysvar.num_partitions as usize,
                )
            });

            // update epoch reward status to distribution phase
            self.set_epoch_reward_status_distribution(
                distribution_starting_block_height,
                Arc::clone(&status.all_stake_rewards),
                partition_indices,
            );

            datapoint_info!(
                "epoch-rewards-status-update",
                ("slot", self.slot(), i64),
                ("block_height", height, i64),
                ("partition_us", partition_us, i64),
                (
                    "distribution_starting_block_height",
                    distribution_starting_block_height,
                    i64
                ),
            );
        }

        let EpochRewardStatus::Active(EpochRewardPhase::Distribution(partition_rewards)) =
            &self.epoch_reward_status
        else {
            // We should never get here.
            unreachable!(
                "epoch rewards status is not in distribution phase, but we are trying to \
                 distribute rewards"
            );
        };

        let distribution_end_exclusive =
            distribution_starting_block_height + partition_rewards.partition_indices.len() as u64;

        assert!(
            self.epoch_schedule.get_slots_in_epoch(self.epoch)
                > partition_rewards.partition_indices.len() as u64
        );

        if height >= distribution_starting_block_height && height < distribution_end_exclusive {
            let partition_index = height - distribution_starting_block_height;

            self.distribute_epoch_rewards_in_partition(partition_rewards, partition_index);
```

```rust
    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );
```
