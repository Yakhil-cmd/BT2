### Title
`full_admin` on a PSM instance can only be reassigned or the instance removed by itself, with no governance/`Root` override once handed off - ([File: substrate/frame/psm/src/lib.rs])

### Summary
`pallet-psm` gates every administrative operation on a PSM instance — including reassigning the admin roles themselves (`set_full_admin`, `set_emergency_admin`) and removing the instance (`remove_psm`) — exclusively through `Self::ensure_psm_admin`, which requires the caller to equal the instance's currently stored `full_admin` origin. There is no `ForceOrigin`/root bypass anywhere in the pallet. This reproduces the exact "only guardian can change guardian" pattern from the referenced report: once a PSM's `full_admin` is delegated away from a runtime's governance (e.g. to a signed operational account), governance has no mechanism to reclaim, reassign, or even forcibly tear down that PSM instance if the admin becomes unresponsive or adversarial.

### Finding Description
`ensure_psm_admin` is the sole authorization gate for all PSM management calls: it resolves the caller against the stored `PsmAdminInfo::full_admin`/`emergency_admin` and rejects everything else with `DispatchError::BadOrigin`, with no alternate root/governance path: [1](#0-0) 

`set_full_admin` reassigns `full_admin` to an arbitrary `T::PalletsOrigin` chosen by the *current* `full_admin`, gated by `can_manage_admins()` which is `Full`-only: [2](#0-1) 

Removal of the entire PSM instance is likewise `Full`-admin gated (confirmed by `remove_psm_unauthorized`, where a stranger origin fails `BadOrigin` and the `Emergency` admin fails `InsufficientPrivilege` even though it is a legitimate configured admin for the instance): [3](#0-2) 

The test `set_full_admin_works` demonstrates the hand-off explicitly: a PSM created with `full_admin = Root` is reassigned to a plain signed account (`ALICE`), after which `Root` itself is rejected with `BadOrigin` for any further admin action on that instance: [4](#0-3) 

This is structurally identical to the Moonwell `TemporalGovernor` finding: a role (`guardian`/`full_admin`) initially controlled by governance/`Root` can be unilaterally transferred by its current holder to any address, and afterward the higher authority (governance/`Root`) has no override method to reclaim it — it must rely entirely on the current holder's cooperation. The pallet's `Config::CreateOrigin` documentation itself anticipates `Root` as a typical creator/initial-admin (`"useful for privileged origins such as Root"`), confirming this is a realistic wiring, not a contrived one: [5](#0-4) 

Unlike the Solidity report — where governance's fallback was `revokeGuardian` (permanently zeroing the role) — here the fallback (`remove_psm`) is gated by the **same** `Full` privilege that was just given away, so governance loses even that last-resort option once `full_admin` is reassigned off of `Root`. The only way remaining to a runtime is a `Root`-triggered storage-level `RemovePallet`-style migration/runtime upgrade, i.e., stepping fully outside the pallet's own extrinsic surface.

### Impact Explanation
If a PSM instance is created/administered with `Root`/governance as the initial `full_admin` and later delegated to an operational multisig or committee account (a normal pattern for day-to-day PSM parameter tuning), that delegate can permanently exclude governance from the instance: it can reassign `full_admin` to an address governance does not control, and it can refuse to ever bring `PsmDebt`/`ExternalAssets` to zero (a precondition for `remove_psm`), leaving governance with no in-pallet path to intervene, pause fees, change ceilings, or shut the instance down. This is a availability/governance-integrity issue rather than direct fund theft, matching the Medium severity of the referenced report.

### Likelihood Explanation
This requires no attacker privilege beyond being the legitimately configured `full_admin` at some point (a state governance itself puts the system into by delegating administration, exactly as in the original report where governance grants the guardian role). No stolen keys, no malicious validator, and no external trust assumption is needed — only the intended, documented workflow (`create_psm` → optional delegation via `set_full_admin`) followed by the delegate acting against governance's interest, which the pallet's own design permits without restriction.

### Recommendation
Add a `ForceAdminOrigin`/`Config::ForceOrigin` (mirroring `pallet_nfts`' pattern of allowing `ForceOrigin` alongside the resource owner for `set_team`/`transfer_ownership`) that can always reassign `full_admin`/`emergency_admin` or force-remove a PSM instance, independent of the current admin's cooperation, so governance retains an unconditional recovery path.

### Proof of Concept
- **Program/severity rationale**: This is a genuine `pallet-psm` production-pallet finding (not test/mock/config-only), reachable via the pallet's own signed extrinsics `create_psm` → `set_full_admin`, matching the report's "role can only be transferred by itself" bug class.
- **Failed guard**: `ensure_psm_admin` (`substrate/frame/psm/src/lib.rs:1662-1679`) has no `ForceOrigin`/root escape hatch; `can_manage_admins()`/`can_remove_psm()` are both `Full`-only (`substrate/frame/psm/src/lib.rs:247-255`).
- **Deployment evidence**: Existing pallet test suite (`substrate/frame/psm/src/tests.rs:3705-3745`, `3689-3703`) already exercises and confirms this exact behavior — `Root` losing all authority over an instance after `set_full_admin` reassigns to a non-root signed account, and non-full admins (including `Root` post-reassignment) being rejected from `remove_psm`.
- **Execution status**: No new test was run for this analysis; the cited existing `pallet-psm` unit tests (`set_full_admin_works`, `remove_psm_unauthorized`) already demonstrate the described state transition and its outcome under the pallet's real mock runtime, satisfying the "existing test harnesses are allowed" criterion.

```rust
		/// Reassign the PSM's `full_admin`. Callable by the current `full_admin`.
		///
		/// ## Dispatch Origin
		///
		/// Must match the PSM's current `full_admin`.
		///
		/// ## Parameters
		///
		/// - `internal_asset`: The PSM whose `full_admin` is being changed.
		/// - `new_admin`: The new `full_admin` origin.
		///
		/// ## Errors
		///
		/// - [`Error::PsmNotFound`]: No PSM is registered for `internal_asset`.
		/// - [`Error::InvalidAdminOrigin`]: `new_admin` is the system `None` origin.
		///
		/// ## Events
		///
		/// - [`Event::FullAdminChanged`].
		#[pallet::call_index(11)]
		#[pallet::weight(T::WeightInfo::set_full_admin())]
		pub fn set_full_admin(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			new_admin: Box<T::PalletsOrigin>,
		) -> DispatchResult {
			Self::ensure_psm_admin(origin, &internal_asset, |l| l.can_manage_admins())?;
			ensure!(!new_admin.is_none(), Error::<T>::InvalidAdminOrigin);
			let new_admin = *new_admin;
			let old_admin = PsmAdmin::<T>::try_mutate(
				&internal_asset,
				|maybe| -> Result<T::PalletsOrigin, DispatchError> {
					let admin = maybe.as_mut().ok_or(Error::<T>::PsmNotFound)?;
					let old = core::mem::replace(&mut admin.full_admin, new_admin.clone());
					Ok(old)
				},
			)?;
			Self::deposit_event(Event::FullAdminChanged {
				internal_asset,
				old_admin: Box::new(old_admin),
				new_admin: Box::new(new_admin),
			});
			Ok(())
		}
```

```rust
		pub(crate) fn ensure_psm_admin(
			origin: OriginFor<T>,
			internal_asset: &T::AssetId,
			required: impl Fn(PsmManagerLevel) -> bool,
		) -> DispatchResult {
			let admin = PsmAdmin::<T>::get(internal_asset).ok_or(Error::<T>::PsmNotFound)?;
			let caller = <T as Config>::RuntimeOrigin::from(origin).into_caller();
			ensure!(!caller.is_none(), DispatchError::BadOrigin);
			let level = if caller == admin.full_admin {
				PsmManagerLevel::Full
			} else if caller == admin.emergency_admin {
				PsmManagerLevel::Emergency
			} else {
				return Err(DispatchError::BadOrigin);
			};
			ensure!(required(level), Error::<T>::InsufficientPrivilege);
			Ok(())
		}
```
