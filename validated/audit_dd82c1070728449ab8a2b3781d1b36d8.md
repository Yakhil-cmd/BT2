### Title
Grandchild processes spawned via git submodule `ext::` transports can wedge `runWithStdin` indefinitely past context deadline, causing permanent sync stall - ([File: pkg/cmd/cmd.go])

### Summary
`runWithStdin` in [1](#0-0)  uses `exec.CommandContext` and blocks on `cmd.Run()`, whose `Wait()` does not return until stdout/stderr pipes are fully closed — not merely until the direct child exits. `exec.CommandContext`'s cancellation only sends a kill signal to the immediate child process; it does not reach grandchildren spawned by that child (e.g., a helper process forked by a submodule's `ext::` transport command) that inherit the same stdout/stderr pipe file descriptors. If such a grandchild ignores/traps termination and keeps the pipe open, `cmd.Run()` can block well past `ctx`'s deadline, or indefinitely, because the Go runtime does not set `cmd.WaitDelay` here nor kill the process group.

### Finding Description
`runWithStdin` constructs `cmd := exec.CommandContext(ctx, command, args...)` and assigns `bytes.Buffer` for `cmd.Stdout`/`cmd.Stderr`, then calls `cmd.Run()` [2](#0-1) . When `ctx` is canceled/expires, the Go standard library kills only the directly-spawned process; it does not send any signal to descendant processes. `cmd.Wait()` (invoked by `cmd.Run()`) will not return until (a) the direct child has exited, and (b) any goroutines copying from the stdout/stderr pipes observe EOF, i.e., until all file descriptors referencing the write end of those pipes are closed by every process holding them (including inherited copies in grandchildren). No `cmd.WaitDelay` or `cmd.Cancel` override is set in this code, and no process-group kill (`Setpgid`/`syscall.Kill(-pid, ...)`) is performed after ctx cancellation.

If git spawns a submodule transport helper via `ext::<command>` (or similar helper-command mechanisms) that forks a long-lived child inheriting the parent's stdout/stderr fds, and that grandchild ignores SIGTERM/SIGKILL delivered only to the immediate git process, `cmd.Run()` in `runWithStdin` can hang past `ctx`'s deadline — the `ctx.Err() == context.DeadlineExceeded` check at line 85 is never reached because `cmd.Run()` itself has not returned. This ties up the calling goroutine of `Runner.Run`/`Runner.RunWithStdin` and any resources (fds, buffers) associated with it for as long as the grandchild lives, and repeated sync attempts using the same mechanism could accumulate leaked processes/fds, degrading or wedging the sync loop.

### Impact Explanation
This matches "permanent sync wedging via resource exhaustion" — a liveness/availability impact. A stalled `cmd.Run()` call blocks the syncing goroutine indefinitely (not just past the timeout), and repeated triggering (e.g., periodic sync retries after the first hang, if retried in new goroutines) can pile up leaked processes and open file descriptors on the node, eventually exhausting node resources for the git-sync container.

### Likelihood Explanation
This requires: (1) git-sync fetching a repo that references a submodule (or other git-invoked helper) via `ext::` or a similarly permissive transport that git itself would accept, and (2) that helper program forking a persistent process that inherits stdio. Whether this path is reachable depends heavily on git-sync's actual invocation flags — I could not confirm from the indexed code whether git-sync restricts `protocol.ext.allow`/`GIT_ALLOW_PROTOCOL`, disables submodule recursion by default, or otherwise blocks `ext::` transports before this is exploitable; `main.go` contains submodule-related flag handling but I was not able to fully inspect it in the time available due to the final-iteration constraint. This is a real, generic weakness in the `exec.CommandContext` pattern (well documented as a Go footgun — `cmd.WaitDelay` was added in Go 1.20 specifically to address it), but I cannot fully confirm from available context that git-sync's default configuration and git's own protocol allow-listing don't already prevent an attacker-controlled repo from reaching an `ext::` helper without a non-default, attacker-uncontrolled flag/env var (which is explicitly out of scope per the rules, since attacker cannot set flags/env vars).

### Recommendation
Set `cmd.WaitDelay` (Go 1.20+) on the `exec.Cmd` in `runWithStdin` so that after the context is done, the runtime forcibly closes the child's stdio pipes and returns from `Wait()` after a bounded grace period, regardless of grandchildren holding the pipes open. Additionally, run child processes in their own process group (`SysProcAttr{Setpgid: true}`) and kill the entire process group (`syscall.Kill(-pid, syscall.SIGKILL)`) on context cancellation to reap descendants, not just the immediate child.

### Proof of Concept
Not fully constructible without confirming that an attacker-controlled repo (without operator-set flags/env) can actually cause git to invoke an `ext::`-style helper in this codebase's default configuration; this could not be verified with the available tools in this session. A generic reproduction (independent of git-sync's submodule handling) would use `pkg/cmd` directly: invoke `Runner.RunWithStdin` with a short `context.WithTimeout` against a shell script that forks a background child ignoring SIGTERM/SIGKILL and inherits stdout, then assert (using `goleak` or process listing) that `Run` returns promptly at the deadline and no child process remains — this would demonstrate the underlying `exec.CommandContext` limitation, but the "reachable via attacker-controlled submodule URL" claim in the question remains unconfirmed against this repo's actual code paths.

func runWithStdin(ctx context.Context, log logintf, cwd string, env []string, stdin, command string, args ...string) (string, string, error) {
	cmdStr := cmdForLog(command, args...)
	log.V(5).Info("running command", "cwd", cwd, "cmd", cmdStr)

	cmd := exec.CommandContext(ctx, command, args...)
	if cwd != "" {
		cmd.Dir = cwd
	}
	if len(env) != 0 {
		cmd.Env = env
	}
	outbuf := bytes.NewBuffer(nil)
	errbuf := bytes.NewBuffer(nil)
	cmd.Stdout = outbuf
	cmd.Stderr = errbuf
	cmd.Stdin = bytes.NewBufferString(stdin)

	start := time.Now()
	err := cmd.Run()
	wallTime := time.Since(start)
	stdout := strings.TrimSpace(outbuf.String())
	stderr := strings.TrimSpace(errbuf.String())
	if ctx.Err() == context.DeadlineExceeded {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, ctx.Err(), stdout, stderr)
	}
	if err != nil {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, err, stdout, stderr)
	}
	log.V(6).Info("command result", "stdout", stdout, "stderr", stderr, "time", wallTime)

	return stdout, stderr, nil
}
