### Title
Unsanitized codespace `DisplayName`/`Repository.FullName` allow ANSI/terminal escape injection into `survey.Select` prompt options - ([File: pkg/cmd/codespace/common.go])

### Finding Description
`codespace.displayName` (pkg/cmd/codespace/common.go:194-209) builds the prompt option string directly from `c.DisplayName` and `c.Repository.FullName` with no escaping or control-character stripping: [1](#0-0) 
`formatCodespacesForSelect` (common.go:129-138) then feeds these raw strings straight into `survey.Select.Options`, which `chooseCodespaceFromList` renders on the terminal: [2](#0-1) 

`Codespace.DisplayName` is populated from the GitHub Codespaces API, which by default derives the display name from the HEAD commit message of the branch the codespace was created from when no explicit `--display-name` is supplied at creation time. A victim who creates a codespace against an attacker-published public repository or fork (an action fully within "ordinary gh commands on attacker-published content") will have that attacker-controlled commit-message text stored server-side as `DisplayName` and returned verbatim by `ListCodespaces`/`GetCodespace`. Nothing in `internal/codespaces/api/api.go` or in `common.go` strips control bytes from this field before it reaches the terminal via `survey.Select`.

This is inconsistent with the rest of the CLI: other list views that render remotely-sourced free text (issue/PR titles, gist descriptions, search results) route the text through `internal/text` sanitization helpers before display, e.g. `pkg/cmd/issue/shared/display.go`, `pkg/cmd/pr/list/list.go`, `pkg/cmd/gist/list/list.go`. The codespace selector path has no equivalent sanitization call, so raw ANSI/OSC/control sequences (e.g. `\x1b]0;evil\x07`, cursor-movement or line-clearing sequences) embedded in a commit message can be echoed directly into the interactive prompt.

`Repository.FullName` is lower risk since GitHub repository names are restricted to a safe character set, but `DisplayName` has no such restriction because it can originate from an arbitrary commit message.

### Impact Explanation
This enables terminal escape-sequence injection into the victim's terminal while they run `gh codespace select`/`stop`/`delete`/`code` etc. Depending on terminal emulator, an attacker-crafted commit message can set the terminal title, hide/overwrite existing text, or use cursor-repositioning sequences to visually spoof the list of options the victim is choosing from (e.g., making a malicious codespace's line appear to be a different, trusted entry). This does not achieve direct code execution but is a legitimate "Output safety"/terminal-spoofing class issue (matches GitHub bug bounty's "prompt/UI spoofing via terminal injection" impact class) that can be leveraged to mislead the victim into selecting/acting on the wrong codespace, or facilitate further social-engineering by spoofing prompt text.

### Likelihood Explanation
Requires the victim to have created (or been granted) at least one codespace against an attacker-influenced repository/branch/commit-message and to then list/select codespaces interactively. This is a normal, unprivileged workflow (opening a codespace on a public fork or repo an attacker controls), so the precondition is realistic and repeatable, though it requires the victim to actually use the interactive codespace selector afterward rather than `--repo`/`-c` direct targeting.

### Recommendation
Sanitize `DisplayName` (and defensively `Repository.FullName`, branch name, and owner login) before building `survey.Select` option strings in `codespace.displayName` — strip or escape ASCII control/escape characters (e.g., via `internal/text`'s sanitization helpers, extended to strip C0/C1 control codes and ANSI/OSC sequences, not just excessive whitespace) prior to constructing the description string in common.go:202-208.

### Proof of Concept
```go
// pkg/cmd/codespace/common_test.go
func TestDisplayName_StripsControlSequences(t *testing.T) {
    apiCS := &api.Codespace{
        Name:        "legit-cs",
        DisplayName: "safe\x1b]0;evil\x07title",
        Repository: api.Repository{FullName: "owner/repo"},
        GitStatus:  api.CodespaceGitStatus{Ref: "main"},
    }
    cs := codespace{apiCS}
    got := cs.displayName(false)
    if strings.ContainsAny(got, "\x1b\x07") {
        t.Fatalf("displayName leaked raw control/escape bytes into prompt text: %q", got)
    }
}
```
Expected (current buggy) behavior: assertion fails because `displayName` returns the string with the raw `\x1b]0;evil\x07` bytes intact, which then flows unmodified into `formatCodespacesForSelect` and `survey.Select.Options`.

func (c codespace) displayName(includeOwner bool) string {
	branch := c.branchWithGitStatus()
	displayName := c.DisplayName

	if displayName == "" {
		displayName = c.Name
	}

	description := fmt.Sprintf("%s [%s]: %s", c.Repository.FullName, branch, displayName)

	if includeOwner {
		description = fmt.Sprintf("%-15s %s", c.Owner.Login, description)
	}

	return description
}
