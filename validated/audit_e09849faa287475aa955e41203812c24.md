### Title
Liquidator's repayment can be pulled while seizing zero collateral - (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
`liquidate` transfers the liquidator's debt tokens to the pool and reduces the victim's debt even when the seizure plan contains zero collateral legs. There is no parameter letting the liquidator pin a minimum seizure, and no revert when `seized` is empty, so a liquidator pays real tokens and receives nothing — the exact "money wasted on an unwanted outcome instead of a revert" class.

### Finding Description
`build_liquidation_plan` in `contracts/controller/src/positions/liquidation/plan.rs` produces `seized_collaterals` via `calculate_seized_collateral`, which silently drops every leg whose seizure rounds to zero (`capped_ray <= Ray::ZERO → continue`, math.rs:419-429). `LiquidationPlan::validate` (math.rs:54-69) only checks per-entry invariants — it never rejects an empty `seized` vector. Back in `liquidate` (mod.rs:58-94), `apply_liquidation_repayments` pulls the planned debt tokens from the liquidator to the pool via `transfer_amount_measured` and burns the victim's debt *before* `apply_liquidation_seizures` iterates the (possibly empty) seized list. The only non-empty check is `require_non_empty_payments(env, &result.repaid)` on the repayment side (mod.rs:66); there is no symmetric check on the seizure side. The protocol's own operator documentation states: "The contract accepts a liquidation that repays debt and seizes nothing, so the liquidator would pay and receive no collateral" (`skills/xoxno-lending-liquidations/SKILL.md:178-180`), and invariants acknowledge "rounding can leave repayment with no payable seizure" (`docs/reference/invariants.md:421`).

An unprivileged liquidator reaches this via `controller.liquidate(liquidator, account_id, debt_payments, seize_mode)`. Seizure is sized from cached oracle prices and pro-rata shares; a price tick, interest accrual, or a competing liquidation landing between the liquidator's `get_liquidation_estimate` simulation and execution can shrink the planned seizure below the per-leg rounding floor so all legs are dropped while the repayment still succeeds.

### Impact Explanation
Direct loss of the liquidator's funds: debt tokens are irreversibly transferred to the pool and the victim's debt is reduced, while the liquidator receives no collateral tokens (`SeizeMode::Transfer`) or shares (`SeizeMode::Credit`). Unlike the NFT mint case where the user at least receives *some* token, here the payer receives literally nothing.

### Likelihood Explanation
Requires the seizure plan to round all collateral legs to zero — most plausible on accounts with dust-value collateral relative to the repayment size, or when prices/accrual move between estimation and execution (execution reuses cached context prices, so stale-estimate divergence is the trigger). Medium likelihood; the protocol itself documents the need to reject empty-seizure estimates off-chain because the contract does not.

### Recommendation
Mirror the fix suggested in the original report: let the caller pin the expected outcome and revert otherwise. Add a `min_seized` argument (or reject `seized.is_empty()` when `repaid` is non-empty) in `liquidate`, e.g. revert with `InvalidPayments` when the plan contains repayment legs but zero seizure legs, since a zero-collateral liquidation is never the caller's intent.

```rust
assert_with_error!(env, !result.seized.is_empty() || result.repaid.is_empty(),
    GenericError::InvalidPayments);
```

### Proof of Concept
1. Victim account has HF < 1 with a tiny collateral position such that `total_seizure_usd × share / price` rounds to zero whole units for every collateral leg (or prices shift to make it so between estimate and execution).
2. Liquidator calls `liquidate(liquidator, account_id, [(debt_key, amount)], SeizeMode::Transfer)` with a positive `amount`.
3. `calculate_seized_collateral` drops all legs → `seized` empty; `plan.validate` passes; `require_non_empty_payments(&result.repaid)` passes.
4. `apply_liquidation_repayments` pulls `amount` debt tokens from the liquidator into the pool and burns victim debt; `apply_liquidation_seizures` no-ops.
5. Transaction commits: liquidator paid the victim's debt and received nothing. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)
