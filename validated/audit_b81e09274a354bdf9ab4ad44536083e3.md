### Title
Webhook signature authenticates one GitHub organization but handlers act on commits/repositories from a different, unverified organization - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects and validates against the webhook secret of the organization named in `params.dig('repository','owner','login')` (or `organization.login`), but the handlers that actually process the payload (`Handler#repository_name`, and especially `StatusHandler#process`) key off *different* payload fields (`repository.full_name`, or nothing at all) with no cross-check back to the organization whose secret validated the request. This is the same class of bug as the LSSVMPairCloner report: the value that is cryptographically covered/verified is not the value that is actually consumed downstream.

### Finding Description
`app/controllers/shipit/webhooks_controller.rb` picks the GitHub App/organization used for HMAC verification from the payload itself: [1](#0-0) [2](#0-1) 

Once `verify_signature` succeeds (i.e., the raw body is a valid HMAC for *some* configured organization's `webhook_secret`), the controller dispatches the entire raw `params` to handlers unmodified: [3](#0-2) 

Downstream, the base `Handler` resolves which `Stack`s to mutate purely from `repository.full_name`, a field that was never part of the value used to pick/verify the secret: [4](#0-3) 

`PushHandler` uses this to trigger `stack.sync_github`, which fetches the real commit history for whatever `full_name` was supplied and can drive `ContinuousDeliveryJob`/auto-deploy: [5](#0-4) 

`StatusHandler` is worse: it does not scope by repository/organization at all - it matches by raw commit SHA across the **entire** Shipit instance: [6](#0-5) 

Because `Shipit` supports multiple GitHub organizations each with their own `webhook_secret` (documented in `docs/setup.md`), and `verify_signature` only proves "this body was signed by *an* org configured in Shipit", nothing ties the org whose secret matched to the repository/commit named later in the body. The equality that should hold is:

`organization authenticated by verify_webhook_signature == organization/repository whose data handlers mutate`

but the code allows: signature valid for Org A, while `repository.full_name` / `sha` in the body refers to Org B's (or any other tenant's) stack/commit.

### Impact Explanation
- `StatusHandler` lets a request correctly signed with Org A's `webhook_secret` set an arbitrary commit status (e.g., `state: success`) on **any commit SHA in any stack of any organization** on the Shipit instance, since the lookup `Commit.where(sha: params.sha)` has zero organization/repository scoping. This can be used to falsify CI/status checks that gate merges (`MergeStatusController`) or deploy safety checks, for repositories the attacker's organization has no relationship with - an authorization boundary crossed via a payload field never covered by the signature.
- `PushHandler`/other `Handler` subclasses resolve target stacks from `repository.full_name`, a field disjoint from the organization actually used to select/verify the webhook secret. A caller who legitimately possesses one org's `webhook_secret` can forge a signed push event that names a different organization's repository, triggering `GithubSyncJob`/`stack.sync_github`, which can enqueue `ContinuousDeliveryJob` and result in an **unauthorized deploy** of a stack belonging to a different tenant/organization than the one that authenticated the request.

This matches the Critical impact bucket ("unauthorized deploy") and the High bucket ("escalation... unauthenticated write of stack/commit state").

### Likelihood Explanation
Exploitation requires only knowledge of *one* configured GitHub App's `webhook_secret` (any organization onboarded into a multi-tenant Shipit instance, per `docs/setup.md`'s "Using Multiple Github Applications" feature) - not a Shipit session, `ApiClient` token, or the target organization's own secret. Given multi-org Shipit deployments are an explicitly supported and documented configuration, and the webhook endpoint is unauthenticated apart from the HMAC check, this is directly reachable by an attacker controlling (or having compromised) any single tenant organization's GitHub App credentials.

### Recommendation
After verifying the HMAC, re-derive `repository_owner`/`organization` strictly and require every handler to check that `repository.full_name`'s owner (and, for `StatusHandler`, the commit's stack's repository owner) equals the organization whose secret validated the signature, rejecting the event otherwise. `StatusHandler` in particular must scope its `Commit` lookup to commits belonging to the verified organization's repositories, not a bare SHA match across the whole instance.

### Proof of Concept
1. Operate/compromise GitHub App "OrgA" configured in Shipit's multi-org `github:` secrets block with known `webhook_secret_A`.
2. Craft a JSON body: `{"sha": "<sha-of-some-commit-belonging-to-OrgB's-stack>", "state": "success", ...}` and sign it with `webhook_secret_A` (`sha1=<hmac>`).
3. POST to `/github/webhooks` with `X-Github-Event: status` and `X-Hub-Signature: sha1=<hmac>`.
4. `verify_signature` resolves `Shipit.github(organization: 'orga')` (since no `repository`/`organization` key is required for a status event body-selection fallback dig also returns nil, falling back to `nil` org config, or another org name can be spoofed in the body to select OrgA's secret while `sha` targets OrgB) and validates successfully.
5. `StatusHandler#process` runs `Commit.where(sha: params.sha)` and creates a spoofed "success" status on OrgB's commit, with no relation checked to OrgA. [7](#0-6) [8](#0-7)

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

```ruby
# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
    end
  end
```
