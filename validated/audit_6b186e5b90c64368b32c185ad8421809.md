### Title
Unfiltered PR-label-derived environment variables (including `LD_PRELOAD`) reach `Command#start`/`PTY.spawn` in the review-stack `fetch` phase - (File: `app/models/shipit/review_stack.rb`, `lib/shipit/stack_commands.rb`, `lib/shipit/command.rb`)

### Summary
`ReviewStack#env` merges every pull-request label name (uppercased) into the stack's environment hash with no key allowlist, and `StackCommands#env` (used by `fetch`, `fetch_commit`, `fetched?`, `fetch_deployed_revision`) merges this unfiltered `@stack.env` straight into the environment passed to `Command`, which `Command#unbundled_env` merges over `BASE_ENV` before `PTY.spawn`. This differs from the deploy/rollback/task-trigger paths, which explicitly whitelist user-supplied env through `EnvironmentVariables#permit` (`DeploySpec#filter_deploy_envs`/`filter_rollback_envs`, `TaskDefinition#filter_envs`).

### Finding Description
The broken binding: for the `fetch` phase, the code implicitly assumes `stack.env.keys ⊆ SAFE_ENV_KEYS`, but no such filter exists — `stack.env.keys` is actually unconstrained by any allowlist for this phase.

Code path:
- `PullRequest#labels` is set from `github_pull_request.labels.map(&:name)` [1](#0-0)  and refreshed on `labeled`/`unlabeled` webhooks via `LabelCapturingHandler#capture_labels`, which does `pull_request.update!(labels: params.pull_request.labels.map(&:name))` [2](#0-1) .
- `ReviewStack#env` merges these label names, uppercased, with value `"true"`, into the stack's env with **no key allowlist**: `super.merge(pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" })` [3](#0-2) .
- `StackCommands#env` (base class for the `fetch` operations) does `super.merge(@stack.env)` — again no allowlist [4](#0-3) , and this `env` is passed directly into `git(...)`/`Command.new(...)` calls for `fetch`, `fetch_commit`, `fetched?`, and `fetch_deployed_revision` [5](#0-4) .
- `Command#unbundled_env` merges `@env.stringify_keys` on top of `BASE_ENV` with no key filtering: `BASE_ENV.merge('PATH' => ...).merge(@env.stringify_keys)` [6](#0-5) , and `Command#start` passes this directly to `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)` [7](#0-6) .

By contrast, the deploy/rollback/task paths explicitly sanitize any user-influenced env before it is stored/used: `Stack#build_deploy` calls `filter_deploy_envs(env.to_h)` [8](#0-7) , and `filter_deploy_envs`/`filter_rollback_envs` route through `EnvironmentVariables#permit` which raises `NotPermitted` for any key not in the variable whitelist [9](#0-8) , [10](#0-9) . No equivalent filter exists for `ReviewStack#env`/`StackCommands#env`, so the PR-label-derived keys (including an attacker-chosen `LD_PRELOAD`) reach the `fetch` step unfiltered.

Per the audit's attacker-capability definition, an unprivileged actor who can "label their own PR" can set a label literally named `ld_preload` (case-insensitive, since it's uppercased by `ReviewStack#env`), causing `env['LD_PRELOAD'] = 'true'` to be merged into every `fetch`-phase `Command` invocation for that review stack.

### Impact Explanation
This lets an attacker inject an arbitrary environment variable key (not just a value) into every subprocess spawned by the `fetch` phase (git fetch/clone, `fetched?`, and any custom `fetch_deployed_revision_steps!` commands defined in the fork's `shipit.yml` under `allow_all`). Setting `LD_PRELOAD` this way only sets it to the literal string `"true"`, which is not by itself a path to a shared object, so the practical RCE demonstrated by the label mechanism alone requires the value to be an existing/loadable path — the label-name mechanism can only set `KEY=true`, not `KEY=/attacker/path.so`. This significantly limits the immediate RCE impact of the label-based vector specifically (the label capitalization technique controls the *key*, not the *value*), but it does confirm the broader invariant failure: the `fetch` phase environment has no allowlist, so **any mechanism that lets a fork PR influence the stack's env value** (not just key) — including the `machine.environment`/`fetch` config itself in the fork's own `shipit.yml` under `allow_all`, which is fully attacker-controlled — would flow unfiltered into `PTY.spawn`. That is a genuine Critical-class RCE-on-deploy-host primitive, since the fork author fully controls `shipit.yml`'s `fetch:` step content and `machine.environment` values under `provisioning_behavior=allow_all`, and those are executed by `StackCommands#fetch_deployed_revision`/`fetch` on the Shipit host.

### Likelihood Explanation
Requires `review_stacks_enabled=true` and `provisioning_behavior=allow_all` on the target repository (both are documented, supported, and recommended configurations per `docs/review_stacks.md`) [11](#0-10) . The attacker needs no elevated GitHub permission beyond opening a PR from a fork and, per the audit's attacker-capability list, "labeling their own PR." Cost is trivial and fully repeatable against any repository running `allow_all` review stacks. However, achieving actual `LD_PRELOAD` RCE via the label vector specifically requires the value to be a real, loadable shared object path, which the label mechanism (`upcase` key = `"true"` value) does not provide — so this specific PoC (label → `LD_PRELOAD`) does not itself demonstrate value-controlled injection.

### Recommendation
Apply an explicit allowlist (via `EnvironmentVariables#permit` or equivalent) to `ReviewStack#env`'s label-derived keys and to `StackCommands#env` before it reaches any `Command`, rejecting or stripping dangerous keys such as `LD_PRELOAD`, `LD_LIBRARY_PATH`, `DYLD_INSERT_LIBRARIES`, `BASH_ENV`, `ENV`, `IFS`, `PATH`, `GIT_SSH_COMMAND`, etc. Additionally, scrub `BASE_ENV`/`unbundled_env` in `Command` to explicitly `delete` known dangerous keys unconditionally regardless of the source, so that no caller-supplied env hash can smuggle them into `PTY.spawn`.

### Proof of Concept
Fast-validation plan (minitest, no live GitHub):
```ruby
test "[allow_all] fetch step does not inherit LD_PRELOAD from a PR label" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.update!(labels: ["ld_preload"])

  commands = Shipit::StackCommands.new(stack)
  env = commands.env

  # Binding under test: fetch-phase env keys must be restricted to a known-safe set.
  assert_not env.key?("LD_PRELOAD"), "fetch env should not contain LD_PRELOAD derived from a PR label"
end
```
Note: this PoC demonstrates the missing-allowlist invariant failure (arbitrary key injection into `fetch` env) but does NOT demonstrate full RCE via `LD_PRELOAD`, because the label mechanism can only set the value to the literal string `"true"`, not an attacker-supplied file path — full RCE would require a separate value-controlled injection vector (e.g., the fork's own `shipit.yml` `machine.environment` under `allow_all`) which is a distinct, though related, finding.

    def fetched?(commit)

      else

      end
    end

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end

    def sanitize_env_vars(variable_definitions)
      allowed_variables = variable_definitions.map(&:name)

      allowed, disallowed = @env.partition { |k, _| allowed_variables.include?(k) }.map(&:to_h)

      error_message = "Variables #{disallowed.keys.to_sentence} have not been whitelisted"
      raise NotPermitted, error_message unless disallowed.empty?

      allowed
    end
