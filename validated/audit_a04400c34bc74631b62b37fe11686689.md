### Title
Below-threshold signer's snapshot advance leaks phantom STX-only signer rewards via bond co-claim - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`claim-rewards` in `pox-5.clar` unconditionally settles a signer's STX-only reward snapshot (`update-claimable-rewards signer reward-cycle none`) in the same call that settles bond rewards, regardless of whether that signer ever crossed `SIGNER_SET_MIN_USTX` and was actually admitted to the STX-only signer set for that cycle [1](#0-0) . This lets a signer manager that never qualified for a reward cycle drag its STX-only rewards-per-token snapshot forward to the current global value by simply co-claiming any bond reward, which is exactly the class of equality violation the report describes: a payout (STX/sBTC rewards) recorded as owed to a staker without the signer/staker actually having earned it in that window.

### Finding Description
`claim-rewards` computes `stx-rewards` via `update-claimable-rewards signer reward-cycle none`, which calls `settle-rewards` and then zeroes the signer's pending bucket in `signer-unclaimed-rewards-for-cycle`, folding this together with `update-claimable-bond-rewards` over the caller-supplied `bond-periods` list in a single transaction [2](#0-1) [3](#0-2) .

Because `settle-rewards` runs even for the STX-only track (`bond-index: none`) whenever *any* `claim-rewards` call is made — even one whose only purpose is to claim a bond reward — a signer whose combined stake never reached `SIGNER_SET_MIN_USTX` (and therefore was never part of the STX-only signer set for that cycle, contributing zero shares) still has its `signer-rewards-per-token-for-cycle` / `rpt-paid` snapshot advanced to the cycle's current global rewards-per-token value.

This exact scenario is captured by an in-repo regression test, `below-threshold signer leaks phantom stx-only rewards via bond co-claim`, which sets up: bob's tiny bond allocation plus alice's STX-only stake to `signer1` deliberately sized to stay below `SIGNER_SET_MIN_USTX`, while `signer2` (a different signer, above threshold) advances the global STX-only rewards-per-token so the bug is not masked by a zero global [4](#0-3) . The test then triggers `claim-rewards` on `signer1` with a bond index, which internally also settles `signer1`'s STX-only cycle-1 snapshot with `shares = 0`, and the comments explicitly state this "corrupts `signer-rewards-per-token-for-cycle`" and that the assertion "fails on the unfixed code because the snapshot was advanced past a window `signer1` didn't earn in" [5](#0-4) .

### Impact Explanation
If the snapshot-advance bug is exploitable (i.e., the safeguard the test checks for is not actually enforced by the shipped contract logic), a below-threshold signer manager can strategically time a bond co-claim to pull its STX-only `rpt-paid` snapshot up to the current global value. Depending on the direction of the resulting delta in `compute-earned-rewards` (`shares * (rpt-current - rpt-paid) / PRECISION + pending`) [6](#0-5) , this either (a) silently zeroes out rewards a staker should have accrued once the signer later re-qualifies (temporary/permanent freezing of stakers' rightful sBTC), or (b) — the scenario the report's bug class targets — causes rewards to be paid/attributed to a staker for a window their signer never contributed shares in, i.e., sBTC rewards recorded as earned that were never actually backed by that signer's participation. Either outcome breaks the core equality that `signer-rewards-per-token-for-cycle` growth must correspond to shares actually staked into a qualifying signer for that cycle.

### Likelihood Explanation
Any unprivileged staker/signer-manager combination can trigger this: no admin, bond/pause authority, or another user's key is required — only staking under a signer that stays intentionally below `SIGNER_SET_MIN_USTX` and registering for at least one bond, then calling the permissionless `claim-rewards` with a non-empty `bond-periods` list [7](#0-6) . This makes the precondition realistic and repeatable every reward cycle.

### Recommendation
In `claim-rewards`/`update-claimable-rewards`, gate the STX-only snapshot settlement (`bond-index: none`) on the signer actually being a member of the STX-only signer set for that `reward-cycle` (i.e., check the equivalent of `is-signer-in-cycle`/shares > 0 before advancing `rpt-paid`), so that a bond-only claim cannot silently fast-forward an unrelated STX-only snapshot for a signer that never qualified.

### Proof of Concept
The exploit path is already reproduced in-repo as a fast-check unit test: [8](#0-7) 

Steps: (1) register `signer1`, set up a bond with bob sized so his backing uSTX is tiny; (2) have alice stake STX-only to `signer1` such that `aliceStake + bobBondUstx < SIGNER_SET_MIN_USTX`, keeping `signer1` out of the cycle-1 signer set; (3) have an unrelated `signer2` accrue enough STX-only stake to advance the global rewards-per-token for cycle 1; (4) fund the pox-5 contract with sBTC and run `calculateRewards`; (5) call `claimRewards([0n], 1n)` on `signer1` (a bond-only claim) — this internally also settles the STX-only track for `signer1` at cycle 1 with `shares = 0`, advancing its snapshot past a window it never earned in, which the test's final assertion is designed to catch.

(define-read-only (compute-earned-rewards
        (shares uint)
        (rpt-current uint)
        (rpt-paid uint)
        (pending uint)
    )
    (+ pending (/ (* shares (- rpt-current rpt-paid)) PRECISION))

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
