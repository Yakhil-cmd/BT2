### Title
Permanent market freeze: accrual `scaled_to_original` overflows i128 on large markets before the borrow-index cap engages - ([File: common/src/rates/scaling.rs](common/src/rates/scaling.rs))

### Summary
Every pool verb runs `interest::global_sync` → `accrue_step` first, which unscales `borrowed` and `supplied` via `scaled_to_original` (`scaled.mul(index)`). That multiplication panics with `MathOverflow` once `scaled × index / RAY` exceeds `i128::MAX` — a bound reached by *value*, not by the `MAX_BORROW_INDEX_RAY` cap that is supposed to bound accrual. Once a large, high-utilization market crosses this line, accrual panics on every subsequent call, permanently freezing all withdrawals, repayments, liquidations, and bad-debt cleanup on that market.

### Finding Description
`accrue_step` (`common/src/rates/simulate.rs:60-61`) computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` and `supplied_original = scaled_to_original(supplied, supply_index)` unconditionally on every chunk. `scaled_to_original` is `scaled.mul(env, index)` (`common/src/rates/scaling.rs:14-16`), a checked multiply-divide that raises `MathOverflow` when the RAY result no longer fits `i128`. `update_borrow_index` caps the *index* at `MAX_BORROW_INDEX_RAY = 1e36`, but the overflow happens in the *unscaled value*: when `borrowed`/`supplied` are large share counts (whale-scale supply on a high-decimals market), `scaled × index` overflows while the index is still well below its cap, so the cap never engages to stop the runaway.

Because `global_sync` (`contracts/pool/src/interest.rs:20-33`) runs `accrue_chunk` before any mutation on the market, the panic is a hard, permanent gate: `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `supply`, and even governance `recapitalize` all revert in the same place. The repo's own harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-360`) demonstrates this end-to-end: a ~1-billion-token supply at ~98% utilization on the steep XLM curve overflows after a number of years, and subsequent `try_withdraw`/`try_repay` calls revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.

This is the on-chain analog of the CVE-2017-7703 class: a reachable computation whose result domain was not bounded at the boundary crashes the consumer — here the crash is a state-poisoning panic that cannot be bypassed, since no code path on a frozen market can skip accrual.

### Impact Explanation
Permanent freezing of user funds. All suppliers' deposits and all pending interest on the affected market become unrecoverable; outstanding debt can never be repaid or liquidated, and `clean_bad_debt`/`recapitalize` cannot rescue the market because they also accrue first. One frozen hub/spoke book also blocks controller operations that touch that market for any account holding it.

### Likelihood Explanation
Exploitation is permissionless but expensive and slow: a single unprivileged attacker needs to supply a very large principal (the test uses ~1e9 whole units of an 18-decimal asset, i.e. supply caps must permit it or governance must have set high caps), drive utilization to ~98% with their own borrow, and then simply let interest accrue. No privileged access, oracle manipulation, or leaked keys are required — the only ingredients are capital, `supply`/`borrow`, and time. The high capital and multi-year horizon make this a Medium/High-likelihood-limited but High-severity finding; the protocol documents caps as the mitigation, yet caps are rescale-saturating (`calculate_scaled_cap`) and governance-controlled, not a hard bound.

### Recommendation
Bound the unscaled value, not just the index: make `update_borrow_index`/`accrue_step` clamp accrual when `scaled_to_original(borrowed, borrow_index)` saturates (e.g., use a saturating unscale for utilization computation and treat the market as fully accrued/stopped rather than panicking), or compute utilization in a saturating `I256` path and freeze rate accrual once the RAY-value ceiling is reached. At minimum, gate `global_sync` so that an accrual overflow does not block exits — e.g., allow `withdraw`/`repay`/`liquidate`/`clean_bad_debt` to proceed with the last stored indexes when accrual cannot advance.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
