### Title
Webhook signature verification binds to `repository.owner.login`, but event handlers act on the independent `repository.full_name` field, allowing cross-organization status/commit forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/organization config (and thus which `webhook_secret` is checked) using `params.dig('repository','owner','login')` (or `organization.login`) [1](#0-0) , while every actual event handler resolves the repository/stack to write to using the *separate* `payload.dig('repository','full_name')` field [2](#0-1) . These two fields live in the same attacker-supplied JSON body but are never checked for consistency, and the signature only proves the whole raw body came from *some* configured organization's secret — it says nothing about which specific `full_name` string appears inside.

### Finding Description
`Shipit.github(organization:)` is a multi-tenant lookup: it maps a login string to a configured `GitHubApp` for that org, each with its own `webhook_secret` [3](#0-2) . Critically, `GitHubApp#verify_webhook_signature` treats a **blank/unconfigured** `webhook_secret` as automatically verified: `return true unless webhook_secret` [4](#0-3) . The engine's own reference configuration explicitly documents organizations with `webhook_secret: # nil` as a supported setup [5](#0-4) .

The controller picks *which* org's secret to check purely from `repository.owner.login` (attacker-controlled body field) [6](#0-5) . Meanwhile, `Handler#repository_name` — used by every handler (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, etc.) to look up the `Repository`/`Stack` to act on — reads `payload.dig('repository','full_name')` [7](#0-6) .

Nothing enforces `repository.full_name` to be consistent with `repository.owner.login`. Given a multi-org Shipit deployment where at least one configured organization (`org-weak`) has no `webhook_secret` set, an unauthenticated attacker can:
1. Send an unsigned POST to `/webhooks` with `repository.owner.login = "org-weak"` (so `verify_signature` auto-passes, since that org's secret is blank).
2. Set `repository.full_name = "victim-org/victim-repo"` — a *different*, secret-protected org's repository that is actually managed by this Shipit instance.

The `StatusHandler` will then resolve the stack via `Repository.from_github_repo_name("victim-org/victim-repo")` and call `commit.create_status_from_github!(params)` directly with attacker-supplied `state`/`context`/`description` [8](#0-7) , writing a forged commit status for `victim-repo` without ever validating a signature scoped to `victim-org`.

This is the direct analog of the StableToken bug class: the value that is *cryptographically bound/verified* (`repository.owner.login`, checked against an org secret) is not the same value that is *acted upon* (`repository.full_name`, used to select the target repository/stack). The binding `verified_org == acted_on_repo_owner` silently breaks.

### Impact Explanation
A forged `success` commit status on `victim-repo` can satisfy `ci.require` gating used by `Commit#deployable?` (`success? && !blocked?`) [9](#0-8) , and can trigger `schedule_continuous_delivery`, which enqueues `ContinuousDeliveryJob` for stacks with continuous deployment enabled [10](#0-9) . This can result in an unauthorized deploy being scheduled for a commit that never actually passed CI — matching the Critical "unauthorized deploy" impact category. It requires zero credentials, no session, no `webhook_secret`, and no repository write access from the attacker; it only requires knowledge of a public repo name/branch structure and that the Shipit deployment configures at least one organization without a webhook secret (an explicitly documented, supported configuration, not a misconfiguration/undocumented mounting requirement).

### Likelihood Explanation
Requires: (a) the Shipit instance to manage multiple GitHub organizations, and (b) at least one of them configured without a `webhook_secret`. This is a documented, first-class supported configuration (see the shipped `secrets.development.shopify.yml` template with `webhook_secret: # nil`) rather than an edge case, so likelihood is non-trivial in multi-org deployments where some orgs are considered "internal"/"low risk" and left unsigned while others are protected.

### Recommendation
After selecting the `github_app`/organization for signature verification, re-validate that the same organization/owner is the one whose repository is actually acted upon by the handler — i.e., derive `repository_owner` and the handler's `repository_name`'s owner from the same normalized source, and reject the webhook (422) if they diverge. Alternatively, do not allow `verify_webhook_signature` to short-circuit to `true` when `webhook_secret` is blank for any org that co-exists with other orgs that do have secrets configured; require an explicit `webhook_secret` for every configured organization in multi-tenant setups, or bind verification strictly to the resolved `Repository`'s configured owner rather than to attacker-supplied `repository.owner.login`.

### Proof of Concept
```
POST /webhooks HTTP/1.1
X-Github-Event: status
Content-Type: application/json
(no X-Hub-Signature header, or any arbitrary value)

{
  "sha": "<sha of a commit in victim-org/victim-repo tracked by this Shipit>",
  "state": "success",
  "context": "ci/required-check",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "org-weak" }
  }
}
```
Because `Shipit.github(organization: "org-weak")` has no `webhook_secret` configured, `verify_webhook_signature` returns `true` unconditionally [4](#0-3) , and `StatusHandler` then writes the forged `success` status against the commit found via `repository.full_name = "victim-org/victim-repo"` [8](#0-7) [2](#0-1) .

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
