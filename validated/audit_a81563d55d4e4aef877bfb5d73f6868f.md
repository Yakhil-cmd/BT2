Fail-open webhook signature verification when `webhook_secret` is unset - ([File: lib/shipit/github_app.rb])

### Summary
`Shipit::GitHubApp#verify_webhook_signature` unconditionally returns `true` when `@webhook_secret` is blank, and `WebhooksController#verify_signature` trusts this boolean as the sole gate before dispatching webhook payloads to mutating handlers. Any org configured (or misconfigured) without a `webhook_secret` accepts arbitrarily forged webhooks with no valid HMAC, letting an unauthenticated attacker trigger `ReviewStack`/`PullRequest`/`Team` mutations for that org's repositories.

### Finding Description
The binding that should hold is: `organization_that_cryptographically_signed(body) == payload.dig('repository','owner','login')`. In the vulnerable path this collapses to `true == true` with no signature check ever performed, because:

- `lib/shipit/github_app.rb:76-83`: `def verify_webhook_signature(signature, message); return true unless webhook_secret; ...`. When `@webhook_secret = @config[:webhook_secret].presence` (line 50) is `nil` (unconfigured in `secrets.yml` for that org), the method short-circuits to `true` before ever inspecting `signature` or `message`.
- `app/controllers/shipit/webhooks_controller.rb:24-30`: `verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` (attacker-controlled via `params.dig('repository','owner','login')`, `repository_owner` at line 59-62) and calls `github_app.verify_webhook_signature(...)`. Since `verified` is `true`, `head(422) unless verified` never fires.
- `create` (lines 10-15) then parses the raw body and dispatches to `Shipit::Webhooks.for_event(event)` handlers, e.g. `Handlers::PullRequest::OpenedHandler#process` (app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:41-46), which calls `ReviewStackAdapter.find_or_create!`, mutating `Shipit::Stack`/`Shipit::PullRequest` records for the repository named in the forged payload.

None of the existing guards intercept this: `drop_unhandled_event` only filters unknown event names, not authenticity; `check_if_ping` only special-cases `ping`; the `rescue Shipit::GithubOrganizationUnknown` branch only covers unknown orgs, not orgs known but lacking a secret; `ExplicitParameters` schemas in the handlers validate payload shape, not provenance. The existing test suite (`test/controllers/webhooks_controller_test.rb`) stubs `verify_webhook_signature` to return `true`/`false` explicitly but never exercises the `nil`-secret fail-open branch, so this gap is untested. ### Impact Explanation
An attacker who POSTs a crafted `pull_request` (or `push`, `status`, `membership`, `check_suite`) payload naming any organization whose `Shipit.github(organization:)` config has no `webhook_secret` can create/mutate `Shipit::Stack`, `Shipit::PullRequest`, `Shipit::Team`, and `Shipit::Membership` records for that org's repositories without ever holding a valid signature — a full authentication bypass on the webhook ingestion boundary. This is repeatable against every repository under that org and matches the Critical category ("a payload for one repository mutating another's stack ... an unauthorized deploy/rollback"), since forged `pull_request` events can provision review stacks and forged `membership` events can add/remove team memberships that feed into `Shipit.github_teams` authorization.

### Likelihood Explanation
Exploitation requires only that the operator has configured (or left default-unconfigured) an org entry in `secrets.yml` without a `webhook_secret` — a real-world, plausible misconfiguration state since Shipit supports multiple GitHub orgs and nothing in the code enforces that `webhook_secret` be present. No GitHub-side secret, session, or privileged role is needed by the attacker; a single unauthenticated HTTP POST is sufficient and fully repeatable.

### Recommendation
Fail closed instead of failing open: in `GitHubApp#verify_webhook_signature`, treat a missing `webhook_secret` as unverifiable (`return false`) rather than automatically verified, and/or make `verify_signature` in `WebhooksController` reject (`head(422)`) whenever `github_app.webhook_secret` is blank. Additionally, enforce at boot/config-load time that every configured GitHub org must have a non-blank `webhook_secret`.

### Proof of Concept

# test/controllers/webhooks_controller_test.rb (new test)
test "rejects forged pull_request webhook when org has no webhook_secret configured" do
  Shipit.github(organization: 'victim-org').stubs(:webhook_secret).returns(nil)

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # invalid/forged signature

  forged_payload = {
    action: 'opened',
    number: 999,
    pull_request: { id: 1, number: 999, url: 'x', title: 'x', state: 'open',
                     additions: 1, deletions: 0,
                     head: { sha: 'a' * 40, ref: 'attacker-branch' },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { full_name: 'victim-org/some-repo', owner: { login: 'victim-org' } },
    sender: { login: 'attacker' }
  }.to_json

  assert_no_difference -> { Shipit::Stack.count } do
    post :create, body: forged_payload, as: :json
  end
  assert_response :unprocessable_entity # currently FAILS: returns 200 and Stack.count changes
end

Both sides of the equality: expected `verified == false` (no valid HMAC over the raw body under `victim-org`'s secret), actual observed `verified == true` returned by `verify_webhook_signature` purely due to `webhook_secret` being `nil`, demonstrating the divergence and unauthorized `Shipit::Stack` creation.
