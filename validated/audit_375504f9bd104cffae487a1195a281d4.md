### Title
Webhook signature verification org (`repository.owner.login`) is never checked against the ReviewStack-creation org (`repository.full_name`), allowing cross-org `ReviewStack` creation - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb])

### Summary
`WebhooksController#verify_signature` authenticates the inbound webhook using the org derived from `params.dig('repository','owner','login')` [1](#0-0) [2](#0-1) . `OpenedHandler`/`ReopenedHandler` (via `ReviewStackAdapter`) instead resolve the repository/org used for `find_or_create!`'s `scope` from a completely separate field, `params.repository.full_name`, via `Repository.from_github_repo_name` [3](#0-2) [4](#0-3) . Since both are independently attacker-controlled JSON fields in the raw POST body and nothing cross-checks them, an attacker who can produce a valid signature for *any* org configured on the Shipit instance can name an arbitrary *other* org's repository in `repository.full_name` and cause a `ReviewStack` to be created for that unrelated org.

### Finding Description
Binding claimed to hold: `repository_owner` used by `verify_webhook_signature` (org A, verifier) == owning org of `repository` used to build the `scope: repository.review_stacks` passed into `ReviewStackAdapter#find_or_create!` (org B, mutated tenant).

Trace:
1. `WebhooksController#create` parses the raw body once: `params = JSON.parse(request.raw_post)` [5](#0-4) .
2. `verify_signature` computes the verifying org strictly from `params.dig('repository', 'owner', 'login')` and calls `Shipit.github(organization: repository_owner)` to fetch that org's `GitHubApp`, then HMAC-verifies the body against `X-Hub-Signature` using **that org's** `webhook_secret` [6](#0-5) .
3. `GitHubApp#verify_webhook_signature` returns `true` unconditionally if that org's config has no `webhook_secret` set (`return true unless webhook_secret`) [7](#0-6) .
4. Separately, `OpenedHandler#repository` resolves the target repository from a different, attacker-controlled JSON field: `params.repository.full_name`, split on `/` into `owner`/`name` with no relation whatsoever to `repository.owner.login`: `Repository.from_github_repo_name` -> `github_repo_name.downcase.split('/')` -> `find_by(owner:, name:)` [4](#0-3) [3](#0-2) .
5. `OpenedHandler#process` then calls `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` [8](#0-7) , and `find_or_create!` -> `create!` -> `scope.create!(stack_attributes)` builds a `ReviewStack` in whatever `repository`'s `review_stacks` association was resolved in step 4, with `branch: params.pull_request.head.ref` (fully attacker-controlled) [9](#0-8) .

Because steps 2 and 4 read two independent JSON keys (`repository.owner.login` vs `repository.full_name`) from the same attacker-supplied body with no equality assertion between them, the org that "verified" the request and the org whose `review_stacks` table is mutated can differ. No other guard intercepts this: `drop_unhandled_event` only checks the event type is handled [10](#0-9) ; the `ExplicitParameters` schema in `OpenedHandler` only validates field shapes/types, not cross-field consistency with `repository.owner.login` (which isn't even part of the schema) [11](#0-10) ; `Repository` validations only constrain owner/name character sets, not which org is "allowed" to name it [12](#0-11) .

Attacker's exact request: raw `POST /webhooks` with header `X-Github-Event: pull_request`, `X-Hub-Signature: sha1=<HMAC of body using org A's secret>` (org A being any org configured on this Shipit instance whose secret the attacker knows or which has no `webhook_secret` set), and a JSON body where `repository.owner.login = "org-A"` but `repository.full_name = "org-B/victim-repo"` (an org B already onboarded to this Shipit instance with `review_stacks_enabled` and a provisioning behavior that matches), plus attacker-controlled `pull_request.head.ref`, `number`, `sender.login`.

### Impact Explanation
A single forged/self-signed webhook causes a `ReviewStack` record to be created under an org (org B) that never authenticated this request, using a branch/environment named by the attacker. Once created, this stack is queued for provisioning (`Shipit::ReviewStackProvisioningQueue.add(stack)`) which subsequently drives `Command`/`PTY.spawn`-based provisioning using **org B's** `GITHUB_TOKEN`/GitHub App credentials to check out the attacker-named branch. This is a payload from one org/tenant mutating another org's stack/repository state, matching the Critical impact category ("a payload for one repository mutating another's stack ... an unauthorized deploy/rollback"). The attack is repeatable against any onboarded org/repository the attacker can name, provided the attacker controls or has zero-secret access to at least one org configured on the same shared Shipit instance — a realistic condition in multi-tenant deployments where tenants self-configure their own org's webhook.

### Likelihood Explanation
Requires: (a) at least two orgs configured on the same Shipit instance (multi-tenant setup — common per `Shipit.github_app_config`/`secrets.github` supporting multiple orgs) [13](#0-12) ; (b) attacker controls/knows the `webhook_secret` for at least one configured org (their own tenant) or that org has no secret configured; (c) the victim org/repository (org B) already exists as a `Shipit::Repository` with `review_stacks_enabled` and a provisioning behavior that permits creation (`allow_all` or label-based) [14](#0-13) . Given those preconditions — plausible in a shared/SaaS Shipit deployment — the attacker cost is a single crafted HTTP POST with no GitHub interaction required, fully repeatable.

### Recommendation
Assert equality between the verifying org and the resolved repository's owner before processing any handler: in `WebhooksController`, after verifying the signature, store/pass the verified `repository_owner`, and in each PullRequest handler (and any other handler resolving `repository` from `params.repository.full_name`), reject processing (or raise) if `repository.owner.casecmp?(verified_repository_owner)` is false. Alternatively, derive the org used for repository lookup directly from the already-verified `repository_owner` instead of independently re-parsing `params.repository.full_name`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "cross-org forged webhook creates a ReviewStack for an org that did not sign the request" do
  org_a_secret = "org-a-secret"
  Shipit.stubs(:github).with(organization: "org-a").returns(
    Shipit::GitHubApp.new("org-a", webhook_secret: org_a_secret)
  )

  org_b_repo = shipit_repositories(:shipit) # existing repo owned by "org-b", review_stacks_enabled, allow_all
  org_b_repo.update!(review_stacks_enabled: true, provisioning_behavior: "allow_all")

  body = {
    action: "opened",
    number: 999,
    pull_request: {
      id: 1, number: 999, url: "http://x", title: "t", state: "open",
      additions: 1, deletions: 1,
      head: { sha: "a" * 40, ref: "attacker-branch" },
      user: { login: "attacker" }, assignees: [], labels: []
    },
    repository: { owner: { login: "org-a" }, full_name: org_b_repo.github_repo_name },
    sender: { login: "attacker" }
  }.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", org_a_secret, body)

  assert_difference -> { org_b_repo.review_stacks.count }, 1 do
    post shipit.webhooks_path, params: body,
      headers: { "X-Github-Event" => "pull_request", "X-Hub-Signature" => signature,
                 "CONTENT_TYPE" => "application/json" }
  end

  # Equality check that should hold but doesn't:
  verified_org = "org-a"
  created_stack_org = org_b_repo.review_stacks.last.repository.owner
  assert_not_equal verified_org, created_stack_org # demonstrates the divergence
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
