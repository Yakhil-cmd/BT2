### Title
CCMenu API endpoint bypasses `ApiClient` stack scoping, letting a stack-scoped token read any stack's status - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::BaseController` restricts a stack-scoped `ApiClient` to its own `stack_id` via the `stacks` scope, but `Shipit::Api::CCMenuController` overrides `stack` to load a `Stack` directly by `params[:stack_id]` without going through that scope, so the binding "stack a token authorises" vs "stack it touches" is broken for this endpoint.

### Finding Description
`ApiClient#check_permissions!` only checks that the caller's `permissions` array contains the string `"#{operation}:#{scope}"` (e.g. `read:stack`); it never checks which specific stack the token is bound to: [1](#0-0) 

Stack-level authorization is enforced elsewhere, in `Api::BaseController`, where `stacks` restricts the queryable set to the client's own `stack_id` when the client is stack-scoped, and `stack` is derived from that restricted relation: [2](#0-1) 

This is the mechanism the test suite confirms is the intended authorization boundary ("an api client scoped to a stack will only see that one stack"): [3](#0-2) 

However, `Api::CCMenuController` declares `require_permission :read, :stack` (which only checks the permission-name binding above) but defines its own `stack` method that queries `Stack.from_param!(params[:stack_id])` directly — bypassing the `stacks` scoping entirely: [4](#0-3) 

So the equality that should hold — "stack authorised by token == stack acted on by the request" — fails specifically for this controller: any token carrying `read:stack` permission (regardless of its `stack_id` column) can retrieve CCMenu status for **any** stack in the deployment by simply changing the `stack_id` path parameter, since the check that would normally filter `Stack` records to the token's own stack is never applied.

### Impact Explanation
This is an authenticated but unauthorized cross-stack read: a token that was minted to be limited to one repository/stack (e.g. an admin explicitly scopes an `ApiClient` to `stack_id: X` and grants only `read:stack`) can be used to read the deploy/lock/build status (`lastBuildStatus`, `lastBuildLabel`, `activity`, lock state) of every other stack managed by the Shipit instance. This matches the "unauthenticated/unauthorized read of stack state" High-impact class in scope, since it escalates a narrowly-scoped credential into engine-wide stack-state disclosure.

### Likelihood Explanation
Likelihood is straightforward for anyone already holding a valid, stack-scoped `read:stack` token (a legitimate, low-privilege credential by design) — no additional secrets, GitHub access, or session are required. The only action needed is changing the `stack_id` in the request path/params of the CCMenu endpoint.

### Recommendation
Have `CCMenuController#stack` resolve through the same scoped collection as the rest of the API (`stacks.from_param!(params[:stack_id])`) instead of the unscoped `Stack.from_param!`, so stack-scoped tokens cannot access stacks outside their `stack_id`.

### Proof of Concept
1. Admin creates a stack-scoped `ApiClient` bound to `stack_id: A` with `permissions: ['read:stack']` (as the `here_come_the_walrus` fixture models: `stack: shipit`, `permissions: ['read:stack']`) — [5](#0-4) .
2. That token authenticates fine via HTTP Basic against `Api::BaseController#authenticate_api_client` and passes `require_permission :read, :stack` on `CCMenuController`, since only the permission string is checked.
3. Request `GET /:owner_B/:repo_B/:env_B/cc.xml?token=<tokenA>` for a completely different stack `B`. `CCMenuController#stack` calls `Stack.from_param!(params[:stack_id])`, which is not restricted to stack `A`, so it returns stack `B`'s data and is rendered back to the caller — leaking stack `B`'s build/lock status to a token that was only supposed to see stack `A`.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
