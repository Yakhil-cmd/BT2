### Title
Missing request timeout in `downloadAsset` allows a malicious release asset/archive host to hang `gh release download` indefinitely - (File: pkg/cmd/release/download/download.go)

### Summary
`downloadAsset` builds its outbound request with `http.NewRequest` (no context) and issues it via `httpClient.Do(req)` with no deadline set anywhere in the client chain, so a slow/stalling server response can block the goroutine (and thus the whole `gh release download` invocation, since `downloadAssets` waits on all worker results) forever.

### Finding Description
`downloadRun` builds download targets from `release.Assets[].APIURL` (or the tarball/zipball URL) — both values originate from the GitHub API response for the release and, in the case of a release the attacker controls (or via `--archive` codeload redirect targets), the actual bytes are attacker-controlled since assets are attacker-published content [1](#0-0) . Each target is dispatched to `downloadAsset`, which constructs the request with the plain `http.NewRequest` (not `http.NewRequestWithContext`) and calls `httpClient.Do(req)` with no per-request deadline [2](#0-1) .

Tracing the client construction: `downloadRun` obtains its `httpClient` from `opts.HttpClient()`, which is `f.HttpClient`, built by `HttpClientFunc` → `api.NewHTTPClient` → `ghAPI.NewHTTPClient` (go-gh library) [3](#0-2) [4](#0-3) . No `Timeout` field or context deadline is set anywhere in this chain — a repo-wide search for `Timeout` in `api/*.go` and in the release/download path returns no matches, in contrast to other command paths (e.g. `send-telemetry`) that explicitly set `http.Client{Timeout: 2 * time.Second}` [5](#0-4) .

Because `downloadAssets` fans work out to `numWorkers` goroutines and then blocks reading from the `results` channel for every job before returning [6](#0-5) , a single attacker-controlled asset URL that responds slowly (slow-loris style: trickling bytes or holding the connection open after headers) can stall the worker indefinitely, and the overall command will not return until that request completes or the process is killed. There is no context deadline, no `http.Client.Timeout`, and no read-deadline on the response body copy loop to bound this.

### Impact Explanation
This matches "Unbounded resource consumption" / denial-of-service impact: an attacker who merely publishes a release with an asset hosted on a server they control (or controls the response for `--archive` codeload flow) can make any victim running `gh release download` against that release hang forever, consuming a goroutine and blocking script/CI pipelines that invoke this command, with no way to self-recover short of process kill/OS-level timeout. This is a genuine availability issue reachable from wholly attacker-controlled release content, matching a High DoS class per the described impact.

### Likelihood Explanation
High feasibility and full repeatability: the attacker needs only to publish a release with an asset URL pointing to (or redirecting to) a server they control that returns HTTP headers then stalls the body (or never completes headers). No special privileges, no token, no MITM — the victim just runs `gh release download` against the attacker's public repo/release, which is a normal supported workflow (including in CI, where `gh release download` is common in build pipelines). The same construction path (`http.NewRequest` without a client timeout) applies to every asset target and to the archive/tarball path (`opts.ArchiveType`), so the exposure isn't a corner case.

### Recommendation
Set an explicit request context with a bounded timeout (e.g. `context.WithTimeout` per request, or a total operation deadline) and use `http.NewRequestWithContext` in `downloadAsset`, and/or set `http.Client.Timeout` (or a `Transport` with `ResponseHeaderTimeout`/`ReadTimeout` and an `io.Copy` with a deadline-aware reader) for the client(s) used for asset/archive downloads, consistent with the pattern already used in `pkg/cmd/send-telemetry/send_telemetry.go`. Also consider a stall/read-deadline on the body-copy phase (not just header round-trip), since slow-loris can also occur mid-body.

```go
func TestDownloadAsset_HangsWithoutTimeout(t *testing.T) {
    // Server that accepts the connection, sends headers, then stalls forever
    // without closing or sending body bytes.
    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.WriteHeader(http.StatusOK)
        if f, ok := w.(http.Flusher); ok {
            f.Flush()
        }
        // simulate slow-loris: block without ever writing body or returning
        select {}
    }))
    defer srv.Close()

    dest := &destinationWriter{dir: t.TempDir()}
    client := &http.Client{} // as constructed via f.HttpClient() today - no Timeout
    url := safeurl.NewImmutableSafeURL(srv.URL)

    done := make(chan error, 1)
    go func() {
        done <- downloadAsset(dest, client, url, "asset.bin", false)
    }()

    select {
    case <-done:
        // Expected: should return with a timeout error within a bounded deadline
    case <-time.After(5 * time.Second):
        t.Fatal("downloadAsset did not return within expected deadline - hang confirmed")
    }
}
```
Expected today: the test fails with a timeout (call never returns), demonstrating the missing bound. After adding a context timeout / client `Timeout`, the call should return an error within the configured deadline.

```go
func downloadAsset(dest *destinationWriter, httpClient *http.Client, assetURL safeurl.SafeURL, fileName string, isArchive bool) error {
	if err := dest.Check(fileName); err != nil {
		return err
	}

	req, err := http.NewRequest("GET", assetURL.String(), nil)
	if err != nil {
		return err
	}

	req.Header.Set("Accept", "application/octet-stream")
	if isArchive {
		// adding application/json to Accept header due to a bug in the zipball/tarball API endpoint that makes it mandatory
		req.Header.Set("Accept", "application/octet-stream, application/json")

		// override HTTP redirect logic to avoid "legacy" Codeload resources
		oldClient := *httpClient
		httpClient = &oldClient
		httpClient.CheckRedirect = func(req *http.Request, via []*http.Request) error {
			if len(via) == 1 {
				req.URL.Path = removeLegacyFromCodeloadPath(req.URL.Path)
			}
			return nil
		}
	}

	resp, err := httpClient.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()
```

```go
		if err != nil {
			return nil, err
		}
		client.Transport = api.ExtractHeader("X-GitHub-SSO", &ssoHeader)(client.Transport)
		return client, nil
	}
}
```

```go
func NewHTTPClient(opts HTTPClientOptions) (*http.Client, error) {
	// Provide invalid host, and token values so gh.HTTPClient will not automatically resolve them.
	// The real host and token are inserted at request time.
	clientOpts := ghAPI.ClientOptions{
		Host:               "none",
		AuthToken:          "none",
		LogIgnoreEnv:       true,
		SkipDefaultHeaders: opts.SkipDefaultHeaders,
	}

	debugEnabled, debugValue := utils.IsDebugEnabled()
	if strings.Contains(debugValue, "api") {
		opts.LogVerboseHTTP = true
	}

	if opts.LogVerboseHTTP || debugEnabled {
		clientOpts.Log = opts.Log
		clientOpts.LogColorize = opts.LogColorize
		clientOpts.LogVerboseHTTP = opts.LogVerboseHTTP
	}

	ua := fmt.Sprintf("GitHub CLI %s", opts.AppVersion)
	if opts.InvokingAgent != "" {
		ua = fmt.Sprintf("%s Agent/%s", ua, opts.InvokingAgent)
	}

	headers := map[string]string{
		userAgent:  ua,
		apiVersion: apiVersionValue,
	}
	clientOpts.Headers = headers

	if opts.EnableCache {
		clientOpts.EnableCache = opts.EnableCache
		clientOpts.CacheTTL = opts.CacheTTL
	}

	client, err := ghAPI.NewHTTPClient(clientOpts)
	if err != nil {
		return nil, err
	}

	if opts.Config != nil {
		client.Transport = AddAuthTokenHeader(client.Transport, opts.Config)
	}

	if opts.TelemetryDisabler != nil {
		client.Transport = telemetryDisablerTransport{
			wrappedTransport:  client.Transport,
			telemetryDisabler: opts.TelemetryDisabler,
		}
	}

	return client, nil
}
```
