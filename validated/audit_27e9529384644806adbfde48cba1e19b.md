### Title
RAY index accrual overflows before the index cap and permanently freezes a saturated market - ([File: common/src/rates/simulate.rs])

### Summary

`accrue_step` converts scaled debt and supply into their full indexed values before applying the borrow-index cap. When `scaled * index / RAY` exceeds `i128::MAX`, the fixed-point multiplication panics with `MathOverflow`, so the market can become permanently unusable before `MAX_BORROW_INDEX_RAY` is reached. [1](#0-0) [2](#0-1) 

### Finding Description

`update_indexes(caller, assets)` is permissionless and delegates each market to pool accrual. [3](#0-2) [4](#0-3) 

Pool accrual calls `interest::global_sync`, which repeatedly calls `accrue_step`; each step first computes `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original`. [5](#0-4) [6](#0-5) [7](#0-6) 

`scaled_to_original` is a checked `Ray::mul`, so a market whose scaled balance multiplied by its index exceeds the `i128` result domain aborts the transaction. [2](#0-1) [8](#0-7) 

The nominal `MAX_BORROW_INDEX_RAY` cap is applied only to the index after `new_index` is calculated; it does not bound the market-dependent product `scaled * index`. [9](#0-8) 

Every normal market leg reaches the same accrual through `load_leg`/`synced_market`; therefore `withdraw`, `repay`, `borrow`, liquidation settlement, bad-debt cleanup, and later `update_indexes` calls all fail before their own logic can run. [10](#0-9) [11](#0-10) [12](#0-11) 

### Impact Explanation

This causes indefinite freezing of all funds in the affected market: suppliers cannot withdraw and borrowers or third parties cannot repay because those public controller operations must first accrue the same saturated market. [13](#0-12) [10](#0-9) 

Liquidation and `clean_bad_debt` also route through synced pool market state, so underwater positions cannot be resolved and the market can remain stuck even as it becomes insolvent. [14](#0-13) [10](#0-9) 

The checked panic is normally safe for a single bad input, but here the overflow condition is stored market state reachable through ordinary supply and borrow activity; once crossed, it denies every subsequent operation on that market rather than rejecting only the attacker’s transaction. [15](#0-14) [16](#0-15) 

### Likelihood Explanation

Exploitation requires a very large listed market and sustained high utilization long enough for the index to approach the market-specific value ceiling; the checked-in regression demonstrates the condition using an 18-decimal market with `1e27` base units supplied and approximately 98% borrowed. [17](#0-16) 

The final step needs no privilege: any authorized caller can invoke `Controller::update_indexes` with the affected `HubAssetKey`, and user-facing repay or withdrawal attempts independently trigger the same panic. [3](#0-2) [18](#0-17) 

The economic barrier is substantial, so this is a medium-severity market-freeze condition rather than an easily repeatable generic DoS; nevertheless, the protocol allows the state to form through ordinary `supply`, `borrow`, and time accrual without relying on privileged parameter changes. [19](#0-18) [20](#0-19) 

### Recommendation

Bound index growth by the actual scaled balances, not only by `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`. Before committing a new index, cap it at approximately `floor(i128::MAX * RAY / scaled)` for both `borrowed` and `supplied`, or use saturating total-value calculations consistently in `scaled_to_original`, `calculate_supplier_rewards`, `update_supply_index`, and `supply_index_reward_shortfall`. [21](#0-20) [22](#0-21) 

Add a regression that confirms a market at the balance-derived boundary remains repayable and withdrawable and that accrual clamps interest rather than trapping subsequent transactions. [23](#0-22) 

### Proof of Concept

The repository already contains a deterministic proof of the boundary. `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` creates an 18-decimal market, supplies `1_000_000_000 * 10^18` base units, borrows 98%, advances time, and repeatedly calls permissionless `update_indexes` until `MATH_OVERFLOW` occurs before `MAX_BORROW_INDEX_RAY`. [24](#0-23) 

The same test then proves that both `withdraw` and `repay` revert with the same `MATH_OVERFLOW`, establishing the market-wide freeze rather than a one-off failed maintenance call. [25](#0-24) 

A concrete unprivileged call sequence is:

```rust
let debt_key = HubAssetKey {
    hub_id,
    asset: big18_token,
};

let supplier_account = controller.supply(
    attacker,
    0,
    spoke_id,
    vec![(debt_key.clone(), 1_000_000_000 * 10i128.pow(18))],
);

let collateral_account = controller.supply(
    attacker,
    0,
    spoke_id,
    vec![(collateral_key, sufficient_collateral)],
);

controller.borrow(
    attacker,
    collateral_account,
    vec![(debt_key.clone(), 980_000_000 * 10i128.pow(18))],
    None,
);

// After sustained high-utilization accrual:
controller.update_indexes(attacker, vec![debt_key]);
```

The public `supply`, `borrow`, and `update_indexes` signatures correspond directly to these calls. [19](#0-18) [3](#0-2)

pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// Adds two raw values, panicking with `GenericError::MathOverflow` on overflow.
fn checked_add_raw(env: &Env, a: i128, b: i128) -> i128 {
    a.checked_add(b)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Subtracts `b` from `a`, panicking with `GenericError::MathOverflow` if either
/// operand is negative or the subtraction would go negative.
fn checked_sub_nonneg(env: &Env, a: i128, b: i128) -> i128 {
    if a < 0 || b < 0 || b > a {
        panic_with_error!(env, GenericError::MathOverflow);
    }
    a - b

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
