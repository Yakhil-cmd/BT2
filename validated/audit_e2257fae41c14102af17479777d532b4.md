## Title
CCMenu API bypasses per-client stack scoping, allowing a stack-scoped `ApiClient` token to read the build status of any stack - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::ApiClient` tokens can be scoped to a single stack via `stack_id`, and `Api::BaseController` is supposed to enforce that scope for every request by resolving the target stack through the client's own `stacks` relation. `Api::CCMenuController` overrides the `stack` resolver and looks the stack up directly from `Stack.from_param!`, completely bypassing the scoping check, so a token that is only supposed to see one stack can read the CCMenu status of every stack in the installation.

### Finding Description
`Api::BaseController` defines the trust binding between an `ApiClient` and the stack(s) it may act on: [1](#0-0) 

`stacks` restricts the queryable set to `current_api_client.stack_id` when the client is scoped, and `stack` (used by every other API controller such as `LocksController`) resolves `params[:stack_id]` only within that restricted relation, so a client scoped to Stack A raises `ActiveRecord::RecordNotFound` if it tries to touch Stack B.

`Api::CCMenuController`, however, defines its own `stack` method that ignores this scoping entirely: [2](#0-1) 

Because `Stack.from_param!` queries the whole `Stack` table rather than `current_api_client.stacks`, any authenticated `ApiClient` holding the `read:stack` permission — even one whose `stack_id` scopes it to exactly one stack — can fetch `#show` for an arbitrary `stack_id` and see that other stack's name, last build status, last build label/time and web URL.

The only enforcement on this action is the permission check, which validates the operation/scope pair but not the specific stack instance: [3](#0-2) 

This breaks the binding: `stack authorised by the token's stack_id` ≠ `stack actually touched by the request`.

### Impact Explanation
This is an authorization-scope escalation: a credential that an operator deliberately restricted to a single stack (e.g. minted for a specific team/service, as done by `CCMenuUrlController`'s own client-creation pattern) can be used to read build/deploy status information for any other stack managed by the Shipit instance, including stacks the token holder should have no visibility into. This matches the "unauthorized read of stack state" class of High-impact findings, since it crosses a repository/stack authorization boundary using only an already-issued, narrowly-scoped credential.

### Likelihood Explanation
Any holder of a valid `ApiClient` token with `read:stack` permission can trigger this — no privileged access, secret material, or additional social engineering is required beyond having (or obtaining) a legitimately scoped token, which is the exact kind of token the CCMenu integration is designed to hand out (see `CCMenuUrlController`). The only required action is supplying a different `stack_id` in the request path.

### Recommendation
Make `Api::CCMenuController#stack` resolve through the scoped `stacks` relation, consistent with the rest of the API:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
This reuses the existing `Api::BaseController#stacks` scoping logic and removes the special-cased, unscoped lookup.

### Proof of Concept
1. Admin creates (or the app auto-creates via `CCMenuUrlController`) an `ApiClient` with `permissions: ['read:stack']` and `stack_id` set to Stack A's id, intended only for embedding Stack A's CCMenu status.
2. Using that client's Basic-auth credentials or `?token=` query param, request:
   `GET /api/stacks/<owner>/<stack-B-name>/<environment>/ccmenu.xml`
   where Stack B is a different, unrelated stack.
3. Because `Api::CCMenuController#stack` uses `Stack.from_param!` instead of the client-scoped `stacks.from_param!`, the request succeeds (`200 OK`) and returns Stack B's `name`, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, and `webUrl`, even though the token is only authorized for Stack A. [4](#0-3)

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
