### Title
`printArgs` writes raw, attacker-controlled git argv (branch/tag/remote-URL) to the terminal via ANSI escape sequences when debug/verbose mode is enabled - ([File: internal/run/run.go])

### Summary
`cmdWithStderr.Run`/`Output` call `printArgs(os.Stderr, c.Cmd.Args)` whenever `GH_DEBUG`/`DEBUG` is set, and `printArgs` writes the args with a bare `fmt.Fprintf(w, "%v\n", args)` with no escaping. Git command arguments frequently include attacker-controlled strings such as PR head branch names (`pr.HeadRefName`), tag names, and remote URLs, which flow unmodified from the GitHub API/git refs into `exec.Cmd.Args`.

### Finding Description
`internal/run/run.go`'s `printArgs` prints `c.Cmd.Args` directly to `os.Stderr` with no sanitization: [1](#0-0) . This is invoked from both `Output()` and `Run()` on `cmdWithStderr` whenever `utils.IsDebugEnabled()` returns true (i.e. `GH_DEBUG`/`DEBUG` env var set, a common verbose-mode/troubleshooting flag): [2](#0-1) .

Git command argv is built from data such as `pr.HeadRefName` in `pkg/cmd/pr/checkout/checkout.go`'s `cmdsForExistingRemote`, which constructs `fetch`/`checkout` argument lists directly from the pull request's head branch name pulled from the API, with no allowlisting of characters: [3](#0-2) . `pr.HeadRefName` is a plain, unsanitized `string` field populated straight from the GraphQL response (`api/queries_pr.go`), so any bytes an attacker puts in a PR branch name (including raw ANSI escape sequences, which git allows in ref names via `refs/heads/<name>` as long as they're valid ref-name characters, or via query response manipulation for repos the attacker controls) reach `exec.Cmd.Args` unfiltered. Similarly, remote URLs (`git.Client.AddRemote`, `sourceInit` in `pkg/cmd/repo/create/create.go`) place attacker-supplied clone URLs directly into argv: [4](#0-3) .

The codebase already has a purpose-built defense for exactly this class of bug: the `iostreams.Untrusted` wrapper type, whose doc comment explicitly states its purpose is to neutralize ANSI escape sequences from untrusted content (API responses, fetched file contents) before it reaches a terminal writer, using `asciisanitizer.Sanitizer`: [5](#0-4) . `printArgs` does not use this type or any equivalent sanitization — it passes `os.Stderr` directly (not an `iostreams.IOStreams`-wrapped writer) and formats args with `%v`, so no existing allowlist/host-check/sanitizer catches this path.

### Impact Explanation
An attacker who can influence a git ref name or remote URL that a victim's `gh` invokes (e.g., publish a PR from a fork with a crafted `HeadRefName`, or offer a repo/remote URL the victim clones with `gh repo clone`) can inject raw ANSI/terminal escape sequences into the victim's terminal stream when the victim has `GH_DEBUG=1` (or legacy `DEBUG=1`) set — a common workflow for debugging CLI issues, and something attackers can specifically instruct victims to do (e.g. "set GH_DEBUG=1 and run this command to help me debug"). This enables terminal-based prompt spoofing, hiding/rewriting prior output, or (depending on terminal emulator) more exotic escape-sequence-driven attacks (e.g., title-bar manipulation, clipboard writes via OSC 52 in vulnerable terminals). This matches a low/moderate "terminal escape sequence injection / spoofing" impact class, scoped to the local victim terminal session — it does not by itself achieve code execution or credential exfiltration, but it is a genuine breach of the output-safety invariant that the rest of the codebase (via `iostreams.Untrusted`) treats as a defended security boundary.

### Likelihood Explanation
The precondition (`GH_DEBUG`/`DEBUG` env var set) is realistic since it's the standard, documented way to enable verbose git-tracing in `gh`, often turned on precisely when a user is troubleshooting an issue with a specific PR/branch (frequently at an attacker's suggestion). The attacker only needs to control a ref name, PR head branch name, or clone/remote URL — all things reachable by an unprivileged GitHub user via forks/PRs or a self-hosted git remote, requiring no special privileges, tokens, or MITM.

### Recommendation
Sanitize `printArgs` output before writing to the terminal, e.g. wrap each `arg` in `iostreams.NewUntrusted(arg)` (or apply the `asciisanitizer.Sanitizer` transform directly) before formatting, so control/escape sequences are stripped regardless of debug mode. Alternatively, restrict `printArgs`'s writer target to a non-terminal sink or quote/escape non-printable bytes explicitly (e.g., using `%q` on each arg, or an escape-safe join) instead of plain `%v`.

func printArgs(w io.Writer, args []string) error {
	if len(args) > 0 {
		// print commands, but omit the full path to an executable
		args = append([]string{filepath.Base(args[0])}, args[1:]...)
	}

}

func cmdsForExistingRemote(remote *cliContext.Remote, pr *api.PullRequest, opts *CheckoutOptions, reuseWorktree bool) [][]string {
	var cmds [][]string
	remoteBranch := fmt.Sprintf("%s/%s", remote.Name, pr.HeadRefName)

	refSpec := fmt.Sprintf("+refs/heads/%s", pr.HeadRefName)
	if !opts.Detach {
		refSpec += fmt.Sprintf(":refs/remotes/%s", remoteBranch)
	}

	localBranch := pr.HeadRefName
	if opts.BranchName != "" {
		localBranch = opts.BranchName
	}

	remoteBranchRef := fmt.Sprintf("refs/remotes/%s", remoteBranch)
	fetchCmd := []string{"fetch", remote.Name, refSpec, "--no-tags"}

	if opts.Detach {
		return append(cmds, detachCmds(fetchCmd, opts.Worktree, reuseWorktree)...)
	}

	cmds = append(cmds, fetchCmd)

	switch {
	case opts.Worktree != "":
		worktreeCmds, branchExists := shared.WorktreeCheckoutCommands(
			opts.GitClient,
			shared.WorktreeTarget{Path: opts.Worktree, Reuse: reuseWorktree},
			localBranch,
			remoteBranch,
		)
		cmds = append(cmds, worktreeCmds...)
		if branchExists {
			cmds = append(cmds, syncBranchCmds(opts.Worktree, remoteBranchRef, opts.Force)...)
		}
	case opts.GitClient.HasLocalBranch(context.Background(), localBranch):
		cmds = append(cmds, []string{"checkout", localBranch})
		cmds = append(cmds, syncBranchCmds("", remoteBranchRef, opts.Force)...)
	default:
		cmds = append(cmds, []string{"checkout", "-b", localBranch, "--track", remoteBranch})

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
