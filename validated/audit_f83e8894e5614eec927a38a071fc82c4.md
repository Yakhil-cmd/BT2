### Title
`checkConsistency` validates KIP-71 bound votes only against the active param set, allowing `LowerBoundBaseFee > UpperBoundBaseFee` after epoch ratification, inverting the Magma base-fee mechanism — (`File: kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` validates each `kip71.lowerboundbasefee` and `kip71.upperboundbasefee` vote independently against the **currently active** parameter set. It does not cross-check pending votes in the same epoch against each other. Two votes cast in the same epoch — each individually valid — can ratify a state where `LowerBoundBaseFee > UpperBoundBaseFee`. `NextMagmaBlockBaseFee` in `params/kip71_config.go` then produces inverted fee behavior: high-demand blocks are capped at the (smaller) upper bound while low-demand blocks are floored at the (larger) lower bound, corrupting fee burning and validator reward distribution for every subsequent block.

---

### Finding Description

`checkConsistency` performs two independent range checks:

```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    }
``` [1](#0-0) 

`h.GetParamSet(blockNum)` returns the **currently ratified** parameter set, not the pending votes accumulating in the current epoch. [2](#0-1) 

**Attack scenario (none-mode governance):**

The default governance mode is `"none"` (`DefaultGovernanceMode = "none"`), where any GC member can vote for any parameter and the last vote per parameter in the epoch is ratified. [3](#0-2) 

With active params `lower=25 GKEI, upper=750 GKEI`:

1. GC member A proposes block N with `Vote: (kip71.lowerboundbasefee, 500 GKEI)`. Check: `500 > 750`? No → accepted.
2. GC member B proposes block M (same epoch, M > N) with `Vote: (kip71.upperboundbasefee, 100 GKEI)`. Check: `100 < 25`? No → accepted.
3. At the epoch boundary, `getExpectedGovernance` collects both votes and ratifies them together. [4](#0-3) 

The resulting active parameter set has `LowerBoundBaseFee=500 > UpperBoundBaseFee=100`, violating the invariant assumed by `NextMagmaBlockBaseFee`.

---

### Impact Explanation

`NextMagmaBlockBaseFee` clamps `parentBaseFee` using the inverted bounds:

```go
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
    parentBaseFee = upperBoundBaseFee   // clamp to 100 (the smaller value)
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
    parentBaseFee = lowerBoundBaseFee   // clamp to 500 (the larger value)
}
``` [5](#0-4) 

With `lower=500 > upper=100`, any `parentBaseFee >= 100` is clamped to 100. Then:

- **High gas usage** (`parentGasUsed > gasTarget`): shortcut fires because `parentBaseFee == upperBoundBaseFee (100)` → returns 100. Fee stays low despite high demand.
- **Low gas usage** (`parentGasUsed < gasTarget`): computes `nextBaseFee = 100 - delta`; since `nextBaseFee < lowerBoundBaseFee (500)`, returns 500. Fee spikes despite low demand. [6](#0-5) 

The fee market is permanently inverted for all blocks after the epoch boundary. `VerifyMagmaHeader` enforces that every block's `baseFee` matches this deterministic (but wrong) computation, so all honest nodes accept the corrupted fee values. [7](#0-6) 

**Corrupted protected values:**
- **Fee burning**: Magma burns half the transaction fee. With an inverted base fee, the burned amount per block is wrong — either under-burning (during high demand, fee is artificially low) or over-burning (during low demand, fee is artificially high). This directly corrupts the KAIA total supply.
- **Validator reward distribution**: Deferred fee distribution (`FinalizeState`) uses the same base fee. Wrong fee amounts flow to proposers and stakers.

---

### Likelihood Explanation

The default governance mode is `"none"`, meaning any GC member can vote for any mutable parameter. The `kip71.lowerboundbasefee` and `kip71.upperboundbasefee` parameters are both mutable. [8](#0-7) 

Two GC members independently voting to adjust the fee range in opposite directions — a realistic operational scenario — is sufficient to trigger this. Neither member needs to know about the other's vote; each vote passes `checkConsistency` individually. On Mainnet/Kairos (`single` mode), the governing node would need to cast both votes in the same epoch, which is a privileged but plausible misconfiguration when attempting to narrow the fee range.

---

### Recommendation

In `checkConsistency`, when validating a `Kip71LowerBoundBaseFee` vote, also check it against any pending `Kip71UpperBoundBaseFee` vote already accumulated in the current epoch (and vice versa). Alternatively, validate the combined pending parameter set at the epoch boundary in `getExpectedGovernance` before writing `header.Governance`, rejecting the epoch ratification if the resulting `LowerBoundBaseFee >= UpperBoundBaseFee`. [1](#0-0) 

---

### Proof of Concept

**Setup:** Chain in `none` governance mode (the default), Magma fork active, current params: `LowerBoundBaseFee=25 GKEI`, `UpperBoundBaseFee=750 GKEI`, epoch=1000.

**Step 1 (block 100):** GC member A becomes proposer and calls `governance_vote("kip71.lowerboundbasefee", 500_000_000_000)`.
- `checkConsistency`: `500e9 > 750e9`? No → vote accepted, written to `header.Vote`.

**Step 2 (block 200):** GC member B becomes proposer and calls `governance_vote("kip71.upperboundbasefee", 100_000_000_000)`.
- `checkConsistency`: `100e9 < 25e9`? No → vote accepted, written to `header.Vote`.

**Step 3 (block 1000, epoch boundary):** `getExpectedGovernance` collects both votes. `header.Governance` is set to `{"kip71.lowerboundbasefee": 500e9, "kip71.upperboundbasefee": 100e9}`. All nodes accept this block (VerifyGov passes — the governance matches the locally computed expected value). [4](#0-3) 

**Step 4 (block 1001 onward):** Active params now have `LowerBoundBaseFee=500e9 > UpperBoundBaseFee=100e9`. `NextMagmaBlockBaseFee` is called for every block:
- High gas usage: returns `100e9` (should increase).
- Low gas usage: returns `500e9` (should decrease).

Fee burning and reward distribution use these wrong values for every subsequent block until another governance vote corrects the inversion — which itself requires a full epoch to take effect. [9](#0-8)

	switch vote.Name() {

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block

		council, err := h.ValSet.GetCouncil(blockNum - 1)

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}
