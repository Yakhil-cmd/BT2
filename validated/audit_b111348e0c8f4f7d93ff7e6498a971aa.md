### Title
Off-by-one in `isVrankEpoch` check writes `epochVACount=0` to ABv2 at every epoch block, disabling violation demotions for the entire subsequent epoch — (`kaiax/valset/impl/transition.go`)

### Summary

`writeTransitionToABv2` uses `isVrankEpoch(num)` (current block) to decide whether to force a write, while `newTransitionContext` sets `IsEpoch = isVrankEpoch(nextNum)` (next block). These two checks are permanently misaligned by one block. At every block N where `N % VRankEpoch == 0`, the skip guard forces a write but `IsEpoch=false`, so `epochVACountForWrite=0` is passed to `EncodeProcessSystemTransition` and stored in ABv2. For all subsequent blocks in the epoch, `slotLimitsFor(0)` returns `(maxSlotAvailable=0, minActiveCount=0)`, which makes `hasSlot` permanently false and silently disables every violation-based demotion.

### Finding Description

**The off-by-one:**

`newTransitionContext` sets `IsEpoch` using `nextNum = headNum + 1`:

```go
ctx.SetBlockCtx(header, v.isVrankEpoch(nextNum))   // IsEpoch = isVrankEpoch(N+1)
``` [1](#0-0) 

The skip guard in `writeTransitionToABv2` uses `num = headNum`:

```go
if len(diff) == 0 && !v.isVrankEpoch(num) {   // uses isVrankEpoch(N)
    return nil
}
``` [2](#0-1) 

**What happens at every epoch block E (E % VRankEpoch == 0):**

- Skip guard: `isVrankEpoch(E) = true` → write is **forced** (not skipped)
- `IsEpoch = isVrankEpoch(E+1) = false` (for any VRankEpoch > 1)
- `epochVACountForWrite` stays at its zero-initialized value:

```go
epochVACountForWrite := uint64(0)
if ctx.IsEpoch {          // false → branch not taken
    ...
    epochVACountForWrite = nodes.CountByState(valset.ValActive)
}
``` [3](#0-2) 

- `EncodeProcessSystemTransition(diff, 0)` is called, writing `epochVACount=0` to ABv2. [4](#0-3) 

**What happens at block E-1 (where `IsEpoch=true`):**

The epoch transition runs and `epochVACountForWrite` is correctly computed. However, the skip guard checks `isVrankEpoch(E-1) = false`, so the write is skipped if `len(diff) == 0`. Even when the write does occur (non-empty diff), the correct value is immediately overwritten at block E.

**Downstream effect — `slotLimitsFor(0)` disables all violation enforcement:**

For blocks E+1 through E+VRankEpoch-1, `ReadABv2Snapshot` returns `EpochVACount=0`. `newTransitionContext` calls:

```go
ctx.SetSlotsCtx(slotLimitsFor(abv2result.EpochVACount))  // slotLimitsFor(0) = (0, 0)
``` [5](#0-4) 

`slotLimitsFor(0)` returns `(maxSlotAvailable=0, minActiveCount=0)` because `n < 4`:

```go
func maxSlotAvailable(n uint64) uint64 {
    if n < 4 { return 0 }   // n=0 → 0
    ...
}
func minActiveCount(n uint64) uint64 {
    if n < 4 { return n }   // n=0 → 0
    ...
}
``` [6](#0-5) 

In `applyViolationTransition`, `hasSlot` becomes permanently false:

```go
hasSlot = func(state valset.NodeState) bool {
    return newValidators.CountByState(state) < ctx.MaxSlotAvailable  // x < 0 → always false for uint64
}
canDemoteActive = func(targetState valset.NodeState) bool {
    return hasSlot(targetState) && ...  // always false
}
``` [7](#0-6) 

All three slot-gated transitions are blocked:
- `ValActive → ValExiting` (MinStake violation, Rule 1)
- `ValActive → ValPaused` (PFS minor violation, Rule 2)
- `ValPaused → ValExiting` (MinStake violation, Rule 1) [8](#0-7) 

Only `ValReady → ValInactive` (unconditional, no slot check) still fires.

### Impact Explanation

For every epoch of length VRankEpoch blocks, violation enforcement is completely disabled for VRankEpoch-1 blocks (the entire epoch after the epoch block). Validators whose staking drops below `MinStake` or who accumulate PFS violations cannot be demoted from `ValActive`. They remain in the active consensus set and continue receiving block rewards without meeting the protocol's performance or staking requirements. This constitutes unauthorized reward distribution and validator privilege escalation over protected chain state — both within the required impact gate.

### Likelihood Explanation

This is a deterministic, systemic bug triggered automatically at every epoch block. No attacker action, privileged key, or validator collusion is required. It fires unconditionally on any chain running the permissionless fork with VRankEpoch > 1.

### Recommendation

Align the two checks to use the same block number. The skip guard should use `nextNum` (matching `IsEpoch`):

```go
// In writeTransitionToABv2:
nextNum := num + 1
if len(diff) == 0 && !v.isVrankEpoch(nextNum) {
    return nil
}
```

This ensures the forced write (for `epochVACount` snapshot) only occurs on the same block where the epoch transition runs and `epochVACountForWrite` is correctly populated.

### Proof of Concept

Let VRankEpoch = 100. At block 100 (N % 100 == 0):

1. `writeTransitionToABv2` is called. `isVrankEpoch(100) = true` → skip guard does not fire.
2. `newTransitionContext` sets `IsEpoch = isVrankEpoch(101) = false`.
3. `ApplyAllTransitions`: `epochVACountForWrite = 0` (branch not taken).
4. `EncodeProcessSystemTransition(diff, 0)` → ABv2 stores `epochVACount=0`.

At block 101:
5. `ReadABv2Snapshot` returns `EpochVACount=0`.
6. `slotLimitsFor(0)` → `MaxSlotAvailable=0, MinActiveCount=0`.
7. A validator with `StakingAmount < MinStake` and state `ValActive` hits Rule 1: `canDemoteActive(ValExiting)` → `hasSlot(ValExiting)` → `CountByState(ValExiting) < 0` → **false**. Validator stays `ValActive`.
8. Same result for PFS violations (Rule 2). Validator collects rewards for the entire epoch (blocks 101–199) without being demoted.

func minActiveCount(n uint64) uint64 {
	if n < 4 {
