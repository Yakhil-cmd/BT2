### Title
Symlinked `.claude` directory causes ralph-loop state file write to escape workspace - ([File: plugins/ralph-wiggum/scripts/setup-ralph-loop.sh])

### Finding Description
`setup-ralph-loop.sh` unconditionally runs `mkdir -p .claude` followed by `cat > .claude/ralph-loop.local.md <<EOF ... EOF` to persist the Ralph loop state. [1](#0-0) 

`mkdir -p .claude` is a no-op if `.claude` already exists as a symlink (it does not fail, and it does not dereference/validate the target). The subsequent `cat > .claude/ralph-loop.local.md` then opens the path through the shell, which follows the symlink and creates/overwrites `ralph-loop.local.md` inside whatever directory the symlink resolves to — even if that directory is outside the cloned repository (e.g., `$HOME`, `/tmp/target`). There is no `realpath`/`readlink` check, no `[[ -L .claude ]]` guard, and no comparison against a resolved workspace root anywhere in the script before the write. An attacker who can get content merged/cloned into a victim's repo (a malicious repo, branch, or PR) can commit a symlink literally named `.claude` pointing at an attacker-chosen absolute path; the moment the victim runs `/ralph-loop ...` in that checkout, the write escapes the intended workspace boundary.

Note this is a known vulnerability class in this codebase: the project's own changelog documents multiple prior fixes for exactly this pattern — "Fixed workflow saves and scheduled-task writes following a symlink at `.claude`, which could redirect writes outside the project" and "Fixed worktree creation following a repository-committed symlink at `.claude/worktrees`, which could create files outside the repository." [2](#0-1) [3](#0-2) 

`setup-ralph-loop.sh` has no equivalent guard, so it remains vulnerable to the same class of issue that has already been treated as a security fix elsewhere in the product.

### Impact Explanation
Successful exploitation lets a malicious repository redirect a plugin-driven file write to an arbitrary path chosen by the repo's symlink target, creating or overwriting a file named `ralph-loop.local.md` outside the trusted workspace directory. This is a workspace-confinement/escape bug: file mutation is not bound to the approved project directory, matching the "unauthorized file action / workspace escape" bounty category. The write is limited to a fixed filename and content the script controls (YAML frontmatter + prompt text), so it cannot be used to inject attacker-controlled content into an arbitrary target filename, but it can still plant/clobber a `ralph-loop.local.md` at a location outside the repo (e.g., silently landing in `$HOME` or another project directory), and — combined with the symlink also being visible to Claude Code's own `.claude` handling — increases the surface for confused-deputy style follow-on effects.

### Likelihood Explanation
Preconditions are simple and fully attacker-controllable from ordinary repo content: commit a symlink named `.claude` pointing to an absolute path (git supports committing symlinks), and have the victim clone/checkout the repo. No special privileges are needed beyond normal contribution to or cloning of a repository — no admin rights, no leaked secrets, no social engineering beyond "run `/ralph-loop` in this repo," which is the plugin's normal intended usage. The bug reproduces deterministically every time given the precondition, since `mkdir -p` and `cat >` both silently follow the pre-existing symlink.

### Recommendation
Before writing, verify `.claude` is a real directory confined to the workspace root, and refuse to proceed if it is a symlink (or resolves outside the workspace):
```bash
if [[ -L .claude ]]; then
  echo "❌ Error: .claude exists as a symlink; refusing to write state file" >&2
  exit 1
fi
mkdir -p .claude
# Optionally: resolve and compare against $(pwd) to ensure no escape via nested symlinks
target_dir="$(cd .claude && pwd -P)"
if [[ "$target_dir" != "$(pwd -P)"/.claude ]]; then
  echo "❌ Error: .claude resolves outside the workspace" >&2
  exit 1
fi
```
Apply the same guard pattern used for the core CLI's `.claude` symlink fixes referenced in the changelog to this and other plugin scripts that write into `.claude/*.local.md`.

### Proof of Concept
Integration test (bash):
1. In a temp directory, create `ln -s /tmp/outside-target .claude` (create `/tmp/outside-target` as an existing directory the test controls).
2. `cd` into the temp directory and run `setup-ralph-loop.sh "test prompt"`.
3. Assert `/tmp/outside-target/ralph-loop.local.md` was created (demonstrating escape) and that `<tempdir>/.claude/ralph-loop.local.md` resolves to the same file (i.e., no separate in-workspace file exists).
4. Expected fixed behavior: the script should exit non-zero with an error and no file should be created under `/tmp/outside-target`.
