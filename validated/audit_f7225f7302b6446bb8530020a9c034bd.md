### Title
`getProposer` expands committee to `qualified.Len()` post-Permissionless but `getCommitteePermissioned` does not, breaking `Proposer(N,R) ∈ Committee(N,R)` on round changes — (`kaiax/valset/impl/getter_context.go`)

---

### Summary

After the Permissionless hardfork (`IsPermissionless=true`), `gov.DeprecatedAt(gov.IstanbulCommitteeSize, c.rules)` returns `true`, causing `getProposer` to silently expand its internal `committeeSize` to `qualified.Len()`. `getCommitteePermissioned` never performs this expansion and continues to use the governance-configured `c.pset.CommitteeSize`. Both functions call `selectRandaoCommittee` with the same `prevMixHash` seed but different sizes, producing a prefix-subset mismatch. For any round ≥ `CommitteeSize`, the proposer is drawn from outside the committee, permanently breaking the invariant `Proposer(N,R) ∈ Committee(N,R)`.

---

### Finding Description

`gov.DeprecatedAt` is defined as: [1](#0-0) 

`IstanbulCommitteeSize` is in `PermissionlessDeprecated`, so `DeprecatedAt` returns `true` whenever `rules.IsPermissionless == true`.

In `getProposer`, the WeightedRandom+Randao branch reads: [2](#0-1) 

When `DeprecatedAt` fires, `committeeSize` is overridden to `qualified.Len()` (e.g. 10). `selectRandaoCommittee` then returns all 10 validators shuffled by `prevMixHash`, and `selectRandaoProposer` picks `shuffled[round % 10]`.

In `getCommitteePermissioned`, the same WeightedRandom+Randao branch is: [3](#0-2) 

There is **no `DeprecatedAt` check here**. The function always passes `c.pset.CommitteeSize` (e.g. 3) to `selectRandaoCommittee`, returning only `shuffled[0:3]`.

`selectRandaoCommittee` is deterministic on `prevMixHash`: [4](#0-3) 

Because both calls use the same seed, the shuffled order is identical. The committee is `shuffled[0:CommitteeSize]` while the proposer is `shuffled[round % qualified.Len()]`. For any `round ≥ CommitteeSize`, the proposer index falls outside the committee slice.

---

### Impact Explanation

**Consensus divergence / stalling on honest nodes.**

The block validator's permissionless path enforces both checks: [5](#0-4) 

1. `author == GetProposer(N, round)` — passes, because the proposer was correctly selected.
2. Committed seals are counted against `GetCommittee(N, round)` — the 3-validator set. The proposer (not in that set) cannot contribute a counted seal.

In the live IBFT consensus, validators gate PREPARE/COMMIT message acceptance on committee membership. When the proposer is not in the committee (rounds ≥ 3 in the example), the proposer's own COMMIT seal is excluded from quorum counting. Depending on the quorum threshold and the number of remaining committee members, this can prevent a block from being committed, forcing further round changes — which again land on a round ≥ CommitteeSize, repeating the failure. The chain can stall durably.

---

### Likelihood Explanation

The conditions are:

| Condition | Notes |
|---|---|
| `IsRandao=true` AND `IsPermissionless=true` | Normal post-Permissionless state; Permissionless always follows Randao |
| `WeightedRandom` proposer policy | The default policy for Kaia mainnet |
| `CommitteeSize < qualified.Len()` | Requires `CommitteeSize` was set below the validator count before the Permissionless fork; plausible on any chain that grew its validator set |
| Round change (round ≥ CommitteeSize) | Routine; any network hiccup triggers this |

No privileged key, majority collusion, or external compromise is required. The trigger is a normal round change on a chain that has both hardforks active and a `CommitteeSize` smaller than the current validator count.

---

### Recommendation

Apply the same `DeprecatedAt` expansion in `getCommitteePermissioned`. In the `else` branch (WeightedRandom + Randao), mirror the logic from `getProposer`:

```go
} else {
    committeeSize := c.pset.CommitteeSize
    if gov.DeprecatedAt(gov.IstanbulCommitteeSize, c.rules) {
        committeeSize = uint64(c.qualified.Len())
    }
    return selectRandaoCommittee(c.qualified, committeeSize, c.prevHeader.MixHash), nil
}
```

This ensures both functions use the same effective committee size and the invariant `Proposer(N,R) ∈ Committee(N,R)` is preserved for all rounds.

// DeprecatedAt reports whether a governance parameter is deprecated (disallowed
// for voting) given the current chain rules. Deprecation has two sources:
//   - static: params that have always been deprecated regardless of fork state
//   - fork-aware: params that become deprecated only after a specific hardfork
//
// Callers (Vote, VerifyVote) reject votes on any name for which this returns true.
func DeprecatedAt(name ParamName, rules params.Rules) bool {
	if _, ok := AlwaysDeprecated[name]; ok {
		return true
	}
	if rules.IsPermissionless {
		if _, ok := PermissionlessDeprecated[name]; ok {
			return true
		}
	}
	return false

func selectRandaoCommittee(qualified *valset.AddressSet, committeeSize uint64, prevMixHash []byte) []common.Address {
	// Note: If committeeSize == 1, below code is equivalent to return []common.Address{currProposer}.
	// Because, the resulting committee will be one validator, and the only validator is also selected as the proposer.
	// Therefore no special handling for committeeSize == 1 is needed.
	mixHash := prevMixHash
	if len(prevMixHash) == 0 { // At exactly Randao hardfork block, or genesis block, prevMixHash is empty.
		mixHash = params.ZeroMixHash
	}
	seed := valset.HashToSeed(mixHash)
	shuffled := qualified.ShuffledList(seed)
	if len(shuffled) < int(committeeSize) {
		return shuffled
	} else {
		return shuffled[:committeeSize]
	}
}
