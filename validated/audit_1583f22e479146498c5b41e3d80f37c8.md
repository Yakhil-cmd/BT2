### Title
PR title/body/comments printed to terminal bypass ContentOut/asciisanitizer sanitization in `gh pr view` - ([File: pkg/cmd/pr/view/view.go])

### Summary
`newContentWriter` in `pkg/iostreams/iostreams.go:503` and the `Untrusted` wrapper in `pkg/iostreams/untrusted.go` correctly implement ANSI/OSC sanitization when used, but `gh pr view`'s rendering code paths never route server-supplied PR title, body, or comment content through them. `pkg/cmd/pr/view/view.go` writes `pr.Title` and `pr.Body` directly to `opts.IO.Out` / raw `out` using `fmt.Fprintf`/`fmt.Fprintln`, and `pkg/cmd/pr/shared/comments.go` does the same for comment bodies after passing them through `markdown.Render` (glamour), none of which strip control/escape sequences.

### Finding Description
`IOStreams.ContentOut` is explicitly documented as "the writer for external content ... where the application is not the author of the bytes" and by default wraps `s.Out` with `transform.NewWriter(out, &asciisanitizer.Sanitizer{})` via `newContentWriter` [1](#0-0) [2](#0-1) . There is also a purpose-built `Untrusted` type in `pkg/iostreams/untrusted.go` meant to guarantee sanitization on any `fmt` print path [3](#0-2) .

However, `printHumanPrPreview` (the default rendering path for `gh pr view` on a TTY) writes `pr.Title` directly into `fmt.Fprintf(out, "%s %s#%d\n", cs.Bold(pr.Title), ...)` where `out := opts.IO.Out` (the raw, unsanitized stream, not `ContentOut`) [4](#0-3) . The PR body is passed through `markdown.Render` (glamour) and printed the same way [5](#0-4) . `markdown.Render` is a thin wrapper around `charmbracelet/glamour` [6](#0-5)  and performs Markdown-to-ANSI styling; it is not designed to strip attacker-embedded raw C0/C1 control bytes or OSC/DCS sequences that are not valid Markdown syntax (e.g., a literal `\x1b]52;...\x07` inside plain text/body is passed through as literal text by the Markdown renderer, then written unmodified to the terminal).

The same pattern repeats for:
- `printRawPrPreview` (non-TTY `gh pr view`), which writes `pr.Title` and `pr.Body` directly to `io.Out` with no sanitization at all [7](#0-6) .
- Comment/review bodies in `formatComment`, which renders `comment.Content()` (attacker-authored PR comment text) via `markdown.Render` and writes it to a `strings.Builder` that is ultimately `fmt.Fprint`'d to `opts.IO.Out` (not `ContentOut`) in `printHumanPrPreview` [8](#0-7) [9](#0-8) .
- `RawCommentList`, which writes `comment.Content()` unsanitized for the `--comments` non-TTY path [10](#0-9) .

None of these paths call `SetContentSanitization`, use `ContentOut`, or wrap the content in `iostreams.Untrusted`. This contrasts with other parts of the codebase that were clearly hardened against exactly this class of issue: `pkg/cmd/gist/view` refuses/sanitizes truncated raw gist content [11](#0-10) , `pkg/cmd/pr/diff/diff.go` explicitly reasons about escape-sequence neutralization and refusal [12](#0-11) , `pkg/cmd/run/view` sanitizes workflow log output [13](#0-12) , and `pkg/cmd/skills/list/list.go` sanitizes frontmatter fields [14](#0-13) . `gh pr view`'s title/body/comment rendering is a gap in this otherwise-systematic mitigation.

### Impact Explanation
An attacker who authors a PR title, PR body, or PR comment (any GitHub user able to open a PR or comment on one, including on a public repo, or an unprivileged contributor) can embed C0/C1 control sequences or OSC/DCS payloads (e.g., OSC 52 clipboard write, OSC 0/2 title-spoofing, DCS-based terminal state manipulation) that reach the victim's raw terminal unfiltered when the victim runs `gh pr view <number>` (TTY or piped). This matches "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" — e.g., an attacker can rewrite the terminal title to mislead the victim, or use OSC 52 to write attacker-chosen data into the victim's clipboard, or manipulate terminal state to make subsequent trusted output/prompts appear misleading.

### Likelihood Explanation
High feasibility and low precondition: any user who can create a PR or comment on any repository the victim views (public repos with open PRs/issues are sufficient) can craft the payload; the victim only needs to run `gh pr view` (a completely ordinary command) against that PR. No token leakage, MITM, or elevated privilege is required. This is directly and trivially reproducible.

### Recommendation
Route all server-supplied text rendered by `gh pr view` (and the shared comment/review formatting helpers) through the existing sanitization primitives: wrap `pr.Title`, `pr.Body`, `comment.Content()`, `pr.Milestone.Title`, and other externally-authored strings in `iostreams.Untrusted` before formatting, or write the final rendered strings through `opts.IO.ContentOut` instead of `opts.IO.Out`. Ensure `markdown.Render`'s output is also passed through the `asciisanitizer` (since Markdown rendering does not strip raw control/escape bytes embedded in the input) before being written to the terminal.

### Proof of Concept
```go
// pkg/cmd/pr/view/view_test.go (new test)
func Test_printHumanPrPreview_sanitizesTitleAndBody(t *testing.T) {
    ios, _, out, _ := iostreams.Test()
    ios.SetStdoutTTY(true)

    pr := &api.PullRequest{
        Title:  "Legit Title\x1b]0;HIJACKED\x07",
        Body:   "Hello\x1b]52;c;ZXZpbCBjbGlwYm9hcmQ=\x07 world",
        Number: 1,
    }
    opts := &ViewOptions{IO: ios, Now: time.Now}
    baseRepo := ghrepo.New("OWNER", "REPO")

    err := printHumanPrPreview(opts, baseRepo, pr)
    require.NoError(t, err)

    // Golden assertion: no raw ESC byte should reach the "terminal" writer.
    assert.NotContains(t, out.String(), "\x1b",
        "PR title/body escape sequences must be stripped before reaching the terminal")
}
```
Expected current behavior: this test **fails** because `out.String()` contains the raw `\x1b]0;HIJACKED\x07` and `\x1b]52;...` byte sequences, confirming the OSC passthrough. A companion `httpmock`-based integration test (stubbing the PR GraphQL response with an OSC-52 payload in `body`) run through `gh pr view` end-to-end would show the same escape bytes present in the captured stdout buffer.

// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}

	// faithful, so a diff carrying escape sequences is refused rather than silently
	// altered. --allow-escape-sequences streams raw on both. The colored path

	if opts.AllowEscapeSequences {

	if err := opts.IO.StartPager(); err == nil {
		defer opts.IO.StopPager()
	} else {
		fmt.Fprintf(opts.IO.ErrOut, "failed to start pager: %v\n", err)
	}

	if opts.NameOnly {
		return changedFilesNames(opts.IO.ContentOut, diff)
	}

	if opts.UseColor {
		return colorDiffLines(opts.IO.Out, sanitizedReader(diff))
	}

	if !opts.AllowEscapeSequences && !opts.IO.IsStdoutTTY() {
		data, err := io.ReadAll(diff)
		if err != nil {
			return err
		}
		if iostreams.ContainsEscapeSequence(data) {
			return errors.New("the diff contains terminal escape sequences; pass --allow-escape-sequences to output it anyway")
		}
		opts.IO.SetContentSanitization(false)
		_, err = opts.IO.ContentOut.Write(data)
		return err

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}
