### Title
Credential/token leakage across repos due to host-only (not full-URL) scoping of stored git credentials - (File: main.go)

### Summary
`git-sync`'s `StoreCredentials` stores auth material via `git credential approve`, and the global `credential.helper` is configured as a plain in-memory `cache` without `credential.useHttpPath` enabled [1](#0-0) . Git's default credential matching keys only on protocol+host (not path), so credentials approved for the main `--repo` URL are also handed out for *any other URL on the same host* — including submodule URLs that are entirely attacker-controlled content pulled from the synced repository.

### Finding Description
`StoreCredentials` writes `url=<url>\nusername=...\npassword=...` to `git credential approve`, keyed by the `url` argument passed in [2](#0-1) . Two call sites always pass `git.repo` (the top-level synced repository URL) as this scoping URL rather than any submodule-specific URL:
- `CallAskPassURL` stores askpass-url-derived credentials under `git.repo` [3](#0-2) .
- `RefreshGitHubAppToken` stores the short-lived GitHub App installation token under `git.repo` as well [4](#0-3) .

Separately, `SetupDefaultGitConfigs` sets `credential.helper = "cache --timeout 3600"` globally, without setting `credential.useHttpPath` [5](#0-4) . Git's credential subsystem matches stored credentials by protocol+host by default (path is ignored unless `useHttpPath` is enabled), so a credential approved for `https://github.com/org-a/private-repo` will also be handed out for `https://github.com/anyone-else/other-repo` on the same `github.com` host.

`git-sync` supports submodules (`submodulesMode`) and fetches them recursively during checkout . Because `.gitmodules` content is fully attacker-controlled (it comes from the tracked repository content itself), an attacker who can push a commit to the synced repo can add or modify a submodule entry pointing to an attacker-owned repository hosted on the *same host* as the main repo (e.g., a different org/path on `github.com`). When `git-sync` runs `git submodule update`, git will supply the previously approved (main-repo or GitHub-App-token) credentials to that attacker-controlled URL because the credential cache only checks protocol+host.

This is directly analogous to the Paladin `approvedSpenders` bug: the underlying "permission mapping" (here, git's credential cache) is not scoped by the correct discriminator (full target URL / path), only by a coarser key (host). Just as a stale token could be reused across an unintended `token`, a credential approved for the main repo can be reused for an unintended, attacker-chosen submodule URL sharing the same host.

### Impact Explanation
If the operator uses `--askpass-url` or GitHub App authentication, an attacker who can push a commit to the synced repository (or any submodule reachable through the sync chain) can add a `.gitmodules` entry pointing to an attacker-controlled repository on the same host as the main repo. On the next sync, git will present the cached main-repo/App-token credentials to the attacker's endpoint, resulting in disclosure of the GitHub App installation token or askpass-derived password to a third party the operator never authorized. This satisfies the "credential or token disclosure" impact category.

### Likelihood Explanation
Requires: (1) submodules enabled (`--submodules`), (2) authentication via `--askpass-url` or GitHub App, and (3) the attacker having push/commit access to content that ends up as a submodule source (the synced repo itself, since `.gitmodules` is tracked content) and control of a same-host destination (e.g. a public repo on the same forge such as `github.com`). This is a realistic configuration for CI/CD sidecar deployments using submodules with dynamic credentials, making likelihood moderate — it does not require a malicious operator, leaked keys, or node compromise; it is reachable purely from attacker-pushed repository content.

### Recommendation
- Set `credential.useHttpPath = true` globally in `SetupDefaultGitConfigs` so git scopes cached credentials by full URL/path rather than host alone.
- When storing askpass-url or GitHub App credentials, also explicitly restrict/verify submodule URLs against an allow-list of expected hosts+paths before recursive submodule fetch, or disable submodule recursion when using dynamic/short-lived credentials unless explicitly opted in.
- Consider using a shorter-lived, per-invocation credential mechanism (e.g., explicit `GIT_ASKPASS` script invoked per remote) rather than a shared `cache` helper, to avoid any host-wide credential reuse.

### Proof of Concept
1. Configure `git-sync` with `--repo=https://github.com/org-a/private-repo`, `--submodules=recursive`, and `--github-app-*` flags (or `--askpass-url`).
2. `RefreshGitHubAppToken`/`CallAskPassURL` calls `StoreCredentials(ctx, git.repo, ...)`, approving the token for `https://github.com/org-a/private-repo` [4](#0-3) .
3. An attacker with push access to `org-a/private-repo` (or a nested submodule) commits a `.gitmodules` entry: `url = https://github.com/attacker-org/malicious-repo`.
4. On next sync, `git submodule update --recursive` runs; because `credential.useHttpPath` is not set [5](#0-4) , git matches the cached credential by host (`github.com`) only and sends the GitHub App token / password to `attacker-org/malicious-repo`, which the attacker can log via their own git server or HTTP endpoint.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}

func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {

		val: "false",

		val: "now",

		// How to manage credentials (for those modes that need it).

		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",

			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
}
