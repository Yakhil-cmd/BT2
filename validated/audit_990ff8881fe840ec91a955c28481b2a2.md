### Title
Webhook signature verification keys off an unverified `repository_owner`/`organization` field, decoupling the authenticated GitHub App/secret from the repository and commit actually mutated — enabling cross-organization webhook forgery and unauthorized CI status/deploy triggers - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and therefore which `webhook_secret`) to use for HMAC verification based on `repository_owner`, a value read directly out of the *unverified* JSON body (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`). The webhook handlers that subsequently act on the payload use a **different** field, either `repository.full_name` (`Handler#repository_name`) or, in the case of `StatusHandler`, no repository scoping at all — only `sha`. This is the same class of bug as the reported issue: a value trusted for one purpose (`balanceOf` standing in for real accounting; here, `repository_owner` standing in for "this payload is authenticated for this repo") is not the value actually acted upon, so the two can be made to diverge by the attacker, breaking system invariants.

### Finding Description
In `app/controllers/shipit/webhooks_controller.rb`:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
...
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

`repository_owner` is attacker-controlled JSON, read *before* any signature check. It is used solely to pick the `GitHubApp` config (`Shipit.github(organization:)` → `lib/shipit.rb#github_app_config`) whose `webhook_secret` will be used to verify `X-Hub-Signature`. [2](#0-1) 

In `lib/shipit/github_app.rb`, if that organization's `webhook_secret` is blank/nil, verification is bypassed entirely:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [3](#0-2) 

Multi-organization deployments configure a `webhook_secret` per-org (see `test/dummy/config/secrets_double_github_app.yml`, where `OrgOne`/`OrgTwo` each independently set `webhook_secret`). If any configured organization omits or leaves this key blank, an attacker can craft a payload whose `repository.owner.login` (or `organization.login`) names that *unsecured* org — causing `verify_signature` to short-circuit to `true` — while the `repository.full_name` field (used by `Handler#repository_name`) or the bare `sha` field (used by `StatusHandler`) names a completely different, real, secured repository/commit already tracked by this Shipit instance:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [4](#0-3) 

`StatusHandler` is the most severe case — it does not scope by repository at all, only by commit SHA, globally:
```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [5](#0-4) 

`PushHandler` similarly acts on whatever stacks match `repository_name`/`branch`, triggering a `GithubSyncJob`: [6](#0-5) 

This is the direct analog of the reported bug class: the field trusted to establish authenticity/scope (`webhook_secret` selected via `repository_owner`) is never bound to the field the code actually mutates (`repository.full_name` / `sha`), exactly matching the allowed analog "an organization that authenticated versus the repository that is written."

### Impact Explanation
An attacker who knows (or guesses) that a multi-org Shipit deployment has any organization configured without a `webhook_secret` can forge unauthenticated `status` events naming an arbitrary real commit `sha` belonging to a fully-secured, unrelated repository/stack, setting `state: success` for that commit. If that stack has continuous deployment/merge-queue enabled and depends on that CI context, this can trigger an **unauthorized deploy or merge** — one of the explicitly listed Critical/High impacts. It can also forge `push` events for any tracked repository/branch (subject to `full_name` matching), causing spurious `GithubSyncJob`s. This is a cross-repository/cross-organization trust bypass entirely through the engine's own webhook authentication logic, requiring no session, API token, or the correct webhook secret for the targeted repository.

### Likelihood Explanation
Requires a Shipit deployment with more than one GitHub App/organization configured (the multi-tenant schema, documented and tested in this engine) where at least one organization's `webhook_secret` is unset — a realistic operational misconfiguration, since `webhook_secret` is explicitly optional in `lib/shipit/github_app.rb`'s `verify_webhook_signature`. Given that setup, exploitation only requires sending one crafted, unsigned POST to `/webhooks` with a spoofed `repository.owner.login`/`organization.login` and a real target `sha`/`full_name` — no privileged credentials needed.

### Recommendation
Bind the organization used for signature verification to the same value used to select the affected repository/commit, and reject events where they diverge. Do not allow `verify_webhook_signature` to return `true` when `webhook_secret` is blank in production; instead fail closed (refuse to process) or require every configured organization to have a non-blank secret. Additionally, `StatusHandler` should verify that the resolved commit's repository/organization matches the organization whose secret validated the request, not just match on bare `sha`.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgOne` (target, has `webhook_secret: s3cr3t`) and `OrgUnsecured` (has `webhook_secret:` blank/nil) — a supported configuration per `test/dummy/config/secrets_double_github_app.yml`.
2. Locate an existing commit `sha` for a stack under `OrgOne`'s repository (visible on the public Shipit deploy page or GitHub).
3. POST to `/webhooks` with header `X-Github-Event: status`, no valid `X-Hub-Signature` for `OrgOne`, and body:
```json
{
  "sha": "<real sha of OrgOne's tracked commit>",
  "state": "success",
  "context": "ci/required-check",
  "organization": {"login": "OrgUnsecured"}
}
```
4. `verify_signature` computes `repository_owner` = `"OrgUnsecured"`, loads its `GitHubApp`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally — the request is accepted despite never being signed by `OrgOne` or GitHub.
5. `StatusHandler#process` looks up `Commit.where(sha: ...)` with no organization/repository check, and records a fabricated successful status on `OrgOne`'s real commit, which can satisfy `OrgOne`'s continuous-deployment/merge gating and trigger an unauthorized deploy/merge.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
