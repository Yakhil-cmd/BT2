### Title
Cross-organization CI status forgery via globally-scoped `sha` lookup in `StatusHandler` - ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's webhook secret to check against using a payload field (`repository.owner.login`, falling back to `organization.login`), fully controlled by the sender of the raw body. [1](#0-0)  Once the signature is verified for that chosen organization, `StatusHandler#process` applies the status update to *any* commit in the entire database matching `params.sha`, without any scoping to the repository/organization that produced the signature. [2](#0-1)  This breaks the binding "organization that authenticated == repository whose commit is written": every other handler scopes writes through `stacks`/`Repository.from_github_repo_name(repository_name)` [3](#0-2) , but `StatusHandler` does not.

### Finding Description
- `repository_owner` (used only to pick the `GitHubApp`/secret for `verify_signature`) is read straight out of the attacker-supplied JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. [4](#0-3) 
- In a multi-organization deployment, each organization has its own `webhook_secret` in `secrets.github[org]`, selected via `Shipit.github(organization: repository_owner)` and `github_app_config`. [5](#0-4) 
- An attacker who legitimately controls one such configured organization (Org A) knows Org A's `webhook_secret` and can compute a valid `X-Hub-Signature` HMAC over any raw body they construct, since the signature only proves "this body was signed with Org A's secret" — it says nothing about the content's target repository. [6](#0-5) 
- The attacker sets `repository.owner.login = "OrgA"` (so `verify_signature` succeeds using Org A's own secret) but the `status` event's `sha` field is chosen to be a commit SHA belonging to a stack under a completely different, unrelated Org B.
- `StatusHandler#process` does `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` — this is a **global** lookup across the whole Shipit instance, not filtered by `repository_name`/`stacks` as other handlers do. [2](#0-1) 
- Contrast with the base `Handler`, which defines `stacks`/`repository_name` precisely to scope handler actions to the repository that produced the payload — a mechanism `StatusHandler` bypasses entirely. [3](#0-2) 

### Impact Explanation
Commit statuses (CI results) recorded via this path are used by Shipit stacks to gate/allow deploys (required status checks). An attacker controlling one organization's webhook secret can forge a `success` status for a commit belonging to a stack in a different, unrelated organization tracked by the same Shipit instance, satisfying required-check gating and enabling an unauthorized deploy of that unrelated stack — this is a cross-repository/cross-organization write and can lead to an unauthorized deploy, matching the Critical impact bar (cross-repository writes / unauthorized deploy).

### Likelihood Explanation
Requires the attacker to control the webhook secret of at least one organization configured on the shared Shipit instance (a realistic scenario for multi-tenant/self-service Shipit deployments where multiple orgs each configure their own GitHub App integration) and to know the target commit SHA of another organization's stack (SHAs are generally public/discoverable via GitHub). No Shipit session, `ApiClient` token, or repository write access on the victim org is required — only knowledge of one's own configured webhook secret, which the attacker legitimately possesses for their own org.

### Recommendation
Scope `StatusHandler#process` (and any other handler performing lookups independent of `stacks`) to the repository derived from the verified payload, e.g. restrict the `Commit.where(sha: params.sha)` query to `stacks.flat_map(&:commits)` or otherwise join through `Repository.from_github_repo_name(repository_name)` so a commit can only be updated by the organization that owns the repository it belongs to, matching the pattern already used in `PushHandler`/`CheckSuiteHandler`.

### Proof of Concept
1. Attacker administers "OrgA", which is configured in `secrets.github["orga"]` with its own `webhook_secret`, and knows that secret (it is their own org's app secret).
2. Attacker finds a public commit SHA `deadbeef...` belonging to a stack under "OrgB" (unrelated org also tracked by the same Shipit instance).
3. Attacker POSTs to the Shipit webhooks endpoint with `X-Github-Event: status` and body:
   ```json
   {
     "sha": "deadbeef...",
     "state": "success",
     "context": "ci/required-check",
     "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgA/irrelevant-repo" }
   }
   ```
4. Attacker computes `X-Hub-Signature: sha1=HMAC(webhook_secret_of_OrgA, raw_body)` and sends the request.
5. `verify_signature` resolves `repository_owner` to `"OrgA"`, fetches `Shipit.github(organization: "OrgA")`, and the signature validates successfully. [7](#0-6) 
6. `StatusHandler#process` executes `Commit.where(sha: "deadbeef...")`, finds OrgB's commit, and updates its status to `success`, unaffected by the fact that the verified signature belonged to OrgA. [2](#0-1)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
