### Title
Webhook signature verification bound to `repository.owner.login` but repository mutations bound to `repository.full_name` allows cross-repository forged webhooks - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/secret used to authenticate an inbound webhook using `repository_owner`, derived from `payload.dig('repository','owner','login')` (falling back to `payload.dig('organization','login')`), while the handler that actually mutates state (`Shipit::Webhooks::Handlers::Handler#stacks` / `#repository_name`) resolves the target `Repository`/`Stack` from a different field of the same untrusted JSON body: `payload.dig('repository','full_name')`. These two fields are never cross-checked against each other.

### Finding Description
`verify_signature` in [1](#0-0)  picks the `GitHubApp` instance for the *claimed* org (`repository_owner`, lines 59-62) and calls `verify_webhook_signature`. Crucially, `GitHubApp#verify_webhook_signature` in [2](#0-1)  contains `return true unless webhook_secret` — i.e. for any configured organization whose `webhook_secret` is left blank (explicitly documented as **optional** in [3](#0-2) , and demonstrated with `webhook_secret: # nil` in [4](#0-3) ), signature verification is a no-op and any POST body is accepted.

Once past `verify_signature`, `WebhooksController#create` dispatches the raw, attacker-controlled JSON to handlers with no re-validation: [5](#0-4) . Every handler resolves the target `Repository`/`Stack` purely from `payload.dig('repository', 'full_name')` via `Handler#repository_name`/`#stacks`: [6](#0-5) . This field is completely independent of the `repository_owner` field that gated authentication in the controller.

The binding broken is exactly: **organization that authenticated == repository that is written**. Before the attacker's request, both sides of that equality are implicitly assumed equal because legitimate GitHub-signed webhooks always have `repository.owner.login` matching the actual repository named in `repository.full_name`. After a crafted request, the attacker sets `repository.owner.login` (or `organization.login`) to any organization configured in Shipit that has no `webhook_secret`, while setting `repository.full_name` to an arbitrary *other* tracked repository (e.g. one belonging to a different, security-conscious organization that does have a strong `webhook_secret`). The signature check passes trivially (no secret to check), but the mutation is applied to the victim repository named in `full_name`.

### Impact Explanation
Handlers reachable this way include:
- `PushHandler`, which calls `stack.sync_github(expected_head_sha: params.after)` for any stack of the spoofed repository: [7](#0-6) , letting an attacker force syncs to an arbitrary attacker-chosen SHA on a repository/branch they do not own.
- `StatusHandler`, which creates fabricated commit statuses on arbitrary commits by `sha` with no repository binding at all beyond the forged payload: [8](#0-7) .
- `CheckSuiteHandler`, which schedules check-run refreshes for arbitrary stacks/commits: [9](#0-8) .

This is an authentication-bypass class issue (a webhook intended to be authenticated per-organization is accepted for a target repository outside that organization) that can influence which commits Shipit considers deployable/mergeable and can trigger sync/refresh workflows against a repository the attacker does not control, satisfying the "authentication bypass" / "unauthorized deploy" impact bar when it results in Shipit acting on a repository the caller was never authenticated for.

### Likelihood Explanation
Requires only that the Shipit operator has configured at least one GitHub App organization without a `webhook_secret` — a state the project's own setup documentation explicitly presents as a supported, optional configuration [10](#0-9) , and which is exercised in the test fixtures for multi-org installs [11](#0-10) . No GitHub credentials, session, or API token are needed — only knowledge of one such organization's name and the target repository's `full_name`, both public information.

### Recommendation
In `Handler#stacks`/`#repository_name`, cross-validate that the resolved repository's owner matches the organization that was actually used to verify the webhook signature (pass `repository_owner` through to handlers and assert equality with the owner segment of `repository.full_name`). Additionally, treat a missing per-organization `webhook_secret` as a hard misconfiguration (reject the webhook) rather than silently trusting the payload in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
1. Shipit is configured with two GitHub App organizations, e.g. `OrgA` (has `webhook_secret` set, tracks the sensitive `OrgA/victim-repo`) and `OrgB` (misconfigured, `webhook_secret` left blank per the documented optional setting).
2. Attacker (unauthenticated, no session/API token) sends:
```
POST /webhooks
X-Github-Event: push
Content-Type: application/json

{
  "repository": { "owner": { "login": "OrgB" }, "full_name": "OrgA/victim-repo" },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>"
}
```
3. `repository_owner` resolves to `"OrgB"`; `Shipit.github(organization: "OrgB")` returns a `GitHubApp` with `webhook_secret` blank, so `verify_webhook_signature` returns `true` unconditionally (no `X-Hub-Signature` even needed).
4. `PushHandler` resolves `stacks` from `payload.dig('repository','full_name')` = `"OrgA/victim-repo"` and invokes `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on the victim's stack, despite the request never having been authenticated for `OrgA`.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
