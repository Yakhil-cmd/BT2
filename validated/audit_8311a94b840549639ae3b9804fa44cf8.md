### Title
Webhook signature verification is keyed on a payload-controlled organization while writes are keyed on a different payload-controlled repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's HMAC secret to validate against using one field of the attacker-supplied JSON body (`repository.owner.login`, falling back to `organization.login`), while every event handler subsequently performs its writes against a different field of the *same* attacker-supplied body (`repository.full_name`). These two fields are never cross-checked against each other, and if the organization named for signature selection has no `webhook_secret` configured, `verify_webhook_signature` short-circuits to `true` unconditionally. This is the median-formula bug class analog described in the prompt: the "verification index" (organization used to pick a secret) and the "write index" (repository actually mutated) are computed from disjoint parts of the same untrusted input, so the value that is cryptographically checked is not the value that is acted upon.

### Finding Description
`verify_signature` computes the organization solely from the payload: [1](#0-0) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

`GithubApp#verify_webhook_signature` returns `true` unconditionally when no `webhook_secret` is configured for that organization: [2](#0-1) 

Once signature verification passes (or is skipped), every handler resolves the target `Stack`/`Repository` using an entirely different payload field, `repository.full_name`, with no relationship enforced to `repository.owner.login`: [3](#0-2) 

Because the request body is attacker-controlled and JSON, `repository.owner.login` and `repository.full_name` do not need to be consistent. An attacker can name an organization with no (or a known/blank) `webhook_secret` for `repository.owner.login`/`organization.login` to satisfy `verify_signature`, while setting `repository.full_name` to any other organization's repository that is onboarded onto the same Shipit instance. The handler layer then writes/executes against that unrelated repository's stacks, e.g.:
- `PushHandler#process` enqueues `stack.sync_github` for the targeted stack [4](#0-3) 
- `PullRequest::OpenedHandler#process` can provision (deploy) a review stack for the targeted repository [5](#0-4) 
- `PullRequest::ClosedHandler#process` can archive/deprovision a review stack [6](#0-5) 

The binding that should be equal but is not: `organization authenticated (repository.owner.login / organization.login, checked against a secret)` == `repository actually written (repository.full_name, used to resolve the Stack)`. Both are read from the same forged JSON body, so a valid signature for organization A says nothing about whether the write target belongs to organization A.

### Impact Explanation
If any organization configured on the Shipit instance has no `webhook_secret` set (an explicitly supported configuration, since `webhook_secret` is optional per `GithubApp#initialize`), an unauthenticated network attacker can trigger writes, provisioning (deploy), and deprovisioning actions against *any other* repository/stack hosted on the same Shipit instance simply by naming the secret-less organization as `repository.owner.login` and pointing `repository.full_name` at the victim repository. This is a cross-repository/cross-organization unauthorized action, matching the "cross-repository writes" / "unauthorized deploy" impact tier.

### Likelihood Explanation
Exploitability depends entirely on operational configuration: at least one organization mounted on the Shipit instance must have no webhook secret (or one the attacker can guess/knows). Shipit supports multiple organizations with independent, optional per-organization secrets, so this is a realistic misconfiguration rather than a purely theoretical one, and no credential, token, or repository write access is required from the attacker's own account — only network access to the public `/webhooks` endpoint.

### Recommendation
Bind signature verification to the same repository identity that will be acted upon: after selecting `github_app` from `repository_owner`, additionally verify that `repository.full_name`'s owner segment matches `repository_owner` (or resolve the target `Repository`/`Stack` first and verify using that repository's own organization instead of a value freely chosen elsewhere in the body). Also consider rejecting webhooks for organizations with no `webhook_secret` configured rather than treating them as automatically verified.

### Proof of Concept
1. Configure Shipit with two organizations: `attacker-org` (no `webhook_secret` set) and `victim-org` (owns `victim-org/prod-app`, provisioning/CI enabled for PR review stacks).
2. Attacker POSTs directly to `/webhooks` with header `X-Github-Event: pull_request` and body:
```json
{
  "action": "opened",
  "number": 1,
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/prod-app" },
  "pull_request": { ... "head": {"sha": "...", "ref": "attacker-branch"} ... },
  "sender": { "login": "attacker" }
}
```
No `X-Hub-Signature` (or any arbitrary value) is required because `attacker-org` has no `webhook_secret`, so `verify_webhook_signature` returns `true` per `lib/shipit/github_app.rb` line 77.
3. `WebhooksController#verify_signature` passes, `PullRequest::OpenedHandler` resolves `Shipit::Repository.from_github_repo_name("victim-org/prod-app")` and, if provisioning is enabled, creates/provisions a review stack for `victim-org/prod-app`—an action the attacker was never authorized to trigger on `victim-org`'s repository.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
