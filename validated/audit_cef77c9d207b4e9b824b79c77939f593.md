### Title
Null-ptr-deref-analog crash in `validatePayment()` via unchecked `payload.inputs[0]` on asset payments - ([File: validation.js])

### Summary
`validatePayment()` in `validation.js` validates a payment message's `inputs` array only with `isNonemptyArray(payload.inputs)`, which merely checks that the value is an array with `length > 0`; it does **not** verify that the array elements are objects [1](#0-0) . For asset (non-base) payments, immediately after this loose check, the code dereferences `payload.inputs[0].type` inside the async callback of `storage.loadAssetWithListOfAttestedAuthors` [2](#0-1) . Per-element sanity checks (`isNonemptyObject(input)`) only happen later, in `validatePaymentInputsAndOutputs()`'s `async.forEachOfSeries` loop over `payload.inputs` [3](#0-2) , i.e., strictly after the vulnerable line has already executed.

This is the same bug class as CVE-2023-53220: a length/array-presence check is trusted as sufficient proof that an element is safe to dereference, but the element itself (e.g. `null`) is never checked before being accessed, leading to an unhandled `TypeError: Cannot read properties of null` inside an asynchronous callback.

### Finding Description
An attacker posts a unit containing a `payment` message with an `asset` field pointing to any valid (even attacker-issued) asset, and sets `payload.inputs = [null, ...]` (or any other falsy/non-object first element) together with a syntactically valid `outputs` array so it passes the earlier `isNonemptyObject`/`isNonemptyArray` gates at lines 2062–2067 and the surrounding `hasFieldsExcept` guard. Because `isNonemptyArray` does not check element types, execution proceeds to `storage.loadAssetWithListOfAttestedAuthors(...)`'s callback, where `payload.inputs[0].type` is accessed on line 2099 without any prior `typeof input === "object"` check. If `inputs[0]` is `null`, this throws a `TypeError` from inside an asynchronous DB callback, outside of any surrounding `try/catch` in the validation entry point (`validate()` only wraps the synchronous, top-of-function unit-hash calculation in `try/catch`, not deep asynchronous branches such as this one). An exception thrown from an async callback in Node.js is not caught by the caller's stack and becomes an uncaught exception, crashing the node process that is validating the (this) unit.

### Impact Explanation
Any node (full node, hub, or light-vendor performing full validation) that receives and validates this unit crashes. Since the malicious unit is a normal, unprivileged unit any user can post/broadcast, if it propagates across the network, every node attempting to validate it terminates, matching the "network unable to confirm new units" acceptance criterion — this is a straightforward crash-DoS reachable by any single unit poster, not a peer/hub-trust or network-transport issue.

### Likelihood Explanation
High: the trigger requires only crafting one JSON unit with `messages: [{app:"payment", payload:{asset: <valid_asset>, inputs:[null], outputs:[...]}}]` and broadcasting it — no special privileges, keys, or timing are required. The only precondition is that a valid non-base asset exists, which is trivial to issue beforehand.

### Recommendation
In `validatePayment()`, before accessing `payload.inputs[0].type` (both in the base-asset issue-detection path implied elsewhere and explicitly at the asset branch), validate that every element of `payload.inputs` is a non-empty object (`isNonemptyObject`) immediately after the `isNonemptyArray` check at line 2064, mirroring the analogous fix pattern from the referenced kernel commit (checking length/emptiness of the nested field before dereferencing it). Concretely, add `if (!payload.inputs.every(isNonemptyObject)) return callback("bad input");` right after line 2064/2066, before any `payload.inputs[0].type` access.

### Proof of Concept
1. Issue (or reuse) any valid non-base asset `A` on the network.
2. Construct and sign a unit with a message:
```json
{
  "app": "payment",
  "payload": {
    "asset": "A...HASH...",
    "inputs": [null],
    "outputs": [{"address": "SOME_VALID_ADDRESS", "amount": 1}]
  }
}
```
3. Broadcast the unit to the network.
4. Each node calls `validation.validate()` → `validateMessage()` → `validateInlinePayload()` → `validatePayment()`; since `inputs` is a non-empty array, execution reaches the asset branch and, inside the `storage.loadAssetWithListOfAttestedAuthors` callback, executes `payload.inputs[0].type` on `null`, throwing an uncaught `TypeError` that crashes the receiving node process.
