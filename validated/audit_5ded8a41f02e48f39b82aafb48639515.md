### Title
Global cache in `handlePrivatePaymentChains` conflates payment content across different senders, mistakenly treating a cached validation result as valid for a new/different sender - ([File: wallet.js])

### Summary
CVE-2016-10003 describes Squid's Collapsed Forwarding feature mistakenly treating a private response, validated for one client's request, as suitable for delivery to a different client, due to an incorrect key/comparison used to identify "the same" request. In `wallet.js`, `handlePrivatePaymentChains` uses a similar pattern: a global `handledChainsCache` keyed only by a hash of the private-chain payload content, without binding the cache entry to the specific sender/device (`from_address`) that is asserting the private payment.

### Finding Description
`handledChainsCache` is a process-wide map that records "this exact set of chains was already validated" keyed by `cache_key = objectHash.getBase64Hash(arrChains)` [1](#0-0) . When a subsequent call to `handlePrivatePaymentChains` arrives with the same `arrChains` content, the function immediately short-circuits: it emits `all_private_payments_handled` for the *new* `from_address` and calls `callbacks.ifOk()` without re-running `network.handleOnlinePrivatePayment` / `privatePayment.validateAndSavePrivatePaymentChain` for this caller [2](#0-1) . The full per-chain validation path (author checks, signature/authentifier validation, chain linkage) that runs on the "first" arrival is entirely skipped on cache hit [3](#0-2) .

The cache key intentionally ignores `from_address`/`ws`/device pairing context - i.e., it treats "same JSON content" as equivalent to "same validated event for any subsequent asserting party," structurally the same class of error as Squid's Collapsed Forwarding: identity/authorization of the requester (here, the private-payment sender/counterparty) is not part of the comparison key used to decide whether a previously-computed result can be reused for a new caller.

### Impact Explanation
If an attacker (or a compromised/malicious paired device) can replay or resend a valid private-payment chain JSON blob that some legitimate wallet already processed, `handlePrivatePaymentChains` will treat it as validated *from the attacker's own device/address* on cache hit, triggering `eventBus.emit('all_private_payments_handled', from_address)` and (if not `body.forwarded`) potentially `emitNewPrivatePaymentReceived`/forwarding logic keyed to the new sender, without the receiving wallet re-verifying that this `from_address` is actually an authorized counterparty for that payment. This could cause the wallet's UI/state to falsely attribute or double-acknowledge a private payment as coming from/being confirmed by an unauthorized party, undermining the payment-authenticity guarantees private chains rely on.

### Likelihood Explanation
Exploitability depends on whether an attacker (a paired device or MITM at the hub) can supply an identical `arrChains` JSON to trigger the cache hit and how `from_address` is threaded into the eventual UI acknowledgment/forwarding — I was not able to fully trace the call site that sets `from_address` for this handler and how `emitNewPrivatePaymentReceived` consumes it before running out of iterations, so likelihood is uncertain without further tracing.

### Recommendation
Include `from_address` (and/or the requesting `ws`/device identity) as part of `cache_key`, or otherwise re-validate that the caller is an authorized party for the cached chain before emitting `all_private_payments_handled`/forwarding events on a cache hit, mirroring the fix pattern for Collapsed Forwarding (only serve a cached/previously-validated result to the exact same requester context it was computed for).

function handlePrivatePaymentChains(ws, body, from_address, callbacks){
	var arrChains = body.chains;
	if (!ValidationUtils.isNonemptyArray(arrChains))
		return callbacks.ifError("no chains found");
	if (!arrChains.every(c =>
		isNonemptyArray(c) &&
		c.every(e =>
			isNonemptyObject(e) &&
			isNonemptyString(e.unit) &&
			isNonemptyObject(e.payload) &&
			isNonemptyString(e.payload.asset) &&
			isNonemptyArray(e.payload.inputs) &&
			isNonemptyArray(e.payload.outputs) &&
			e.payload.inputs.every(isNonemptyObject) &&
			e.payload.outputs.every(isNonemptyObject)
		)
	))
		return callbacks.ifError("malformed private chain");
	try {
		var cache_key = objectHash.getBase64Hash(arrChains);
	}
	catch (e) {
		return callbacks.ifError("chains hash failed: " + e.toString());		
	}
	if (handledChainsCache[cache_key]) {
		eventBus.emit('all_private_payments_handled', from_address);
		eventBus.emit('all_private_payments_handled-' + arrChains[0][0].unit);
		return callbacks.ifOk();
	}
