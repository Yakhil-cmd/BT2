### Title
Webhook signature verification is keyed to `repository.owner.login`, but every handler acts on `repository.full_name` — organization used to authenticate ≠ repository written - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the HMAC secret (and therefore the trust boundary) using the organization inferred from the payload's `repository.owner.login` field, while every `Webhooks::Handlers::Handler` subclass resolves the target `Repository`/`Stack` from an independently-trusted `repository.full_name` field in the same, already-parsed JSON body. Nothing ties the two together, so the "organization whose secret authenticated the request" and the "repository that gets written to" are two different, unlinked lookups over the same attacker-supplied JSON.

### Finding Description
In a multi-organization Shipit deployment (the officially supported config shape, see `config/secrets.development.example.yml` and `test/dummy/config/secrets_double_github_app.yml`), each organization has its own, optional `webhook_secret`: [1](#0-0) 

`verify_webhook_signature` treats a missing secret as "skip verification": [2](#0-1) 

`WebhooksController#verify_signature` picks *which* org's `GitHubApp` (and thus which secret, possibly none) to use purely from `repository_owner`, computed from the same JSON body that is about to be trusted: [3](#0-2) [4](#0-3) 

Once verification passes (trivially, if the org named in `repository.owner.login` has no `webhook_secret` configured), the raw body is handed unchanged to the registered handlers: [5](#0-4) 

Every handler, however, resolves the actual `Repository`/`Stack`/`Commit` to mutate from `repository.full_name` (a completely separate field), with no cross-check against `repository_owner`/the org used to authenticate: [6](#0-5) [7](#0-6) 

Concretely, `PushHandler` triggers `stack.sync_github` for every stack under the resolved repository: [8](#0-7) 
`StatusHandler` writes CI status onto any `Commit` matching the attacker-supplied `sha`, independent of repository/org entirely: [9](#0-8) 
`MembershipHandler` creates/mutates `Team` membership (which feeds directly into `Shipit.github_teams` authorization) keyed off `params.organization.login`, again a body field never checked against the org whose secret verified the request: [10](#0-9) [11](#0-10) 

**Equality that should hold but doesn't:** `organization(repository_owner) used to select webhook_secret for signature verification` == `organization/repository(repository.full_name / params.organization.login) that handlers write to`. The engine only enforces the left side is *some* configured org (or raises `GithubOrganizationUnknown`); it never enforces the right side is the same org.

### Impact Explanation
In any multi-org install where at least one configured organization has `webhook_secret` left blank (a documented, supported configuration shown in `config/secrets.development.example.yml:11` and `test/dummy/config/secrets_double_github_app.yml:7`), an unauthenticated internet attacker can:
1. Set `repository.owner.login` to that no-secret organization's public name — `verify_signature` returns `true` unconditionally for it (`return true unless webhook_secret`).
2. Set `repository.full_name` (or `organization.login` for `membership` events) to any *other* org/repo actually tracked by Shipit, with a fully attacker-chosen `X-Github-Event` and JSON body.

This lets the attacker: force a `GithubSyncJob`/deploy sync with an attacker-chosen `expected_head_sha` via `push`, forge CI `status` on arbitrary commits via `sha`, forge `check_suite` results, or add/remove `Team` `Membership` rows that gate `User#authorized?` against `Shipit.github_teams` — an unauthenticated escalation into the engine's authorization model. This matches the "escalation into `Shipit.github_teams` authorization" / "unauthorized deploy" impact tier.

### Likelihood Explanation
Requires no credentials, no session, no GitHub App access — only that the target Shipit instance is configured with more than one GitHub organization and at least one of them has no `webhook_secret` set. This is not a hypothetical edge case: the shipped example configs (`config/secrets.development.example.yml`, `secrets_double_github_app.yml`) show `webhook_secret` as commented-out/nil by default, and per-organization secret configuration is explicitly optional per `GitHubApp#initialize`.

### Recommendation
Bind organization identity across the whole request: after selecting the verifying `GitHubApp` from `repository_owner`, require every handler to assert that `payload.dig('repository','owner','login')` (or `organization.login` for org-level events) equals that same `repository_owner` before acting, rejecting mismatches with 422. Additionally, do not allow `verify_webhook_signature` to silently accept unsigned payloads for organizations lacking a `webhook_secret` — either require `webhook_secret` to be present for every configured organization, or fail closed when it is absent instead of returning `true`.

### Proof of Concept
Given a Shipit instance with `config.github` containing `OrgWithoutSecret` (no `webhook_secret`) and `OrgWithStacks` (tracked repositories with real stacks):
```
POST /github/webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # ignored, OrgWithoutSecret has no secret

{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "OrgWithoutSecret" },
    "full_name": "OrgWithStacks/production-app"
  }
}
```
`verify_signature` resolves `Shipit.github(organization: "OrgWithoutSecret")`, whose `verify_webhook_signature` returns `true` unconditionally (no secret configured), so the request passes. `PushHandler#process` then resolves `Repository.from_github_repo_name("OrgWithStacks/production-app")` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on every non-archived stack matching branch `master` — a deploy-relevant state change triggered without any valid signature over the org actually being written to.     def verify_webhook_signature(signature, message)
```ruby
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
