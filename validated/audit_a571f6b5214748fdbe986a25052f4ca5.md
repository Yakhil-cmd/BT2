### Title
RAY-scaled market valuation overflow permanently freezes repayments, withdrawals, and liquidations - (File: common/src/rates/simulate.rs)

### Summary
A market whose scaled supply or debt value exceeds `i128::MAX` makes `accrue_step` revert before it can update `last_timestamp`, permanently disabling every pool operation that synchronizes that market. [1](#0-0) 

### Finding Description
`accrue_step` computes current debt and supply by calling `scaled_to_original`, which multiplies a scaled `Ray` by its index and panics when the resulting value does not fit in `i128`. [2](#0-1) [3](#0-2) [4](#0-3) 

The public controller entrypoint `update_indexes(caller, assets)` requires only caller authorization and forwards the supplied `Vec<HubAssetKey>` to the pool. [5](#0-4) [6](#0-5) 

Pool accrual calls `global_sync` for each selected market, and `global_sync` invokes `accrue_step` without catching the overflow. [7](#0-6) [8](#0-7) 

The normal position paths share this synchronization helper: `load_leg` calls `synced_market`, which loads the market and calls `global_sync` before repayment, withdrawal, liquidation accounting, or other pool mutations proceed. [9](#0-8) 

### Impact Explanation
After the market crosses the representable RAY-value boundary, the accrual transaction reverts before committing a new index or timestamp. [8](#0-7) [10](#0-9) 

Every later call has at least as much elapsed time and encounters the same multiplication result, so neither a borrower nor a third-party repayer can reduce debt, neither a supplier nor liquidator can withdraw collateral, and bad-debt cleanup cannot reach the affected market. [9](#0-8) [11](#0-10) 

This is permanent freezing of user funds absent a privileged contract upgrade: the test demonstrates `MathOverflow` from `update_indexes`, followed by identical failures for `withdraw` and `repay`, while the stored borrow index remains below its configured cap. [12](#0-11) 

### Likelihood Explanation
An unprivileged attacker can create the condition by supplying a large amount to an existing high-rate market and opening a high-utilization borrow position with sufficient collateral, using only `supply`, `borrow`, and later `update_indexes`. [13](#0-12) [5](#0-4) 

The protocol's own test fixture reaches the cliff with a one-billion-whole-token market at 98% utilization and a steep but valid interest-rate curve; the index grows past roughly 170x while remaining below `MAX_BORROW_INDEX_RAY`. [14](#0-13) [15](#0-14) 

The cap validation permits approximately 170 billion whole-token equivalents, far above the demonstrated one-billion-token position, so the triggering book is inside admitted market bounds. [16](#0-15) 

### Recommendation
Clamp each index not only at `MAX_*_INDEX_RAY`, but also at the largest index for which the corresponding scaled total remains representable, such as `max_value_index = floor(i128::MAX * RAY / scaled_amount)`. [17](#0-16) [18](#0-17) 

Apply that dynamic bound in `accrue_step` before evaluating `calculate_supplier_rewards`, `update_supply_index`, and `supply_index_reward_shortfall`, and treat index saturation as a successful accrual state so `last_timestamp` can advance and exits remain usable. [19](#0-18) 

Alternatively, store a value-domain saturation flag or calculate the relevant intermediate totals in `I256`, but do not saturate the position claim itself silently because that could underpay withdrawals. [20](#0-19) 

Add boundary tests that drive the market to `i128::MAX` and then prove `repay`, `withdraw`, `liquidate`, `clean_bad_debt`, `recapitalize`, and `claim_revenue` can still complete. [9](#0-8) 

### Proof of Concept
1. On an existing 18-decimal market using the demonstrated valid curve, an attacker calls controller `supply(caller, 0, spoke_id, [(HubAssetKey { hub_id, asset }, 1_000_000_000 * 10^18)])`, creating their own account and depositing one billion whole tokens. [21](#0-20) 

2. The attacker supplies sufficient collateral in another market and calls `borrow(caller, account_id, [(HubAssetKey { hub_id, asset }, 980_000_000 * 10^18)], None)`, producing a 98%-utilization market. [13](#0-12) [22](#0-21) 

3. Once enough ledger time has passed, the attacker—or any keeper—calls `update_indexes(caller, [HubAssetKey { hub_id, asset }])`; `accrue_step` reaches `scaled_to_original(borrowed, borrow_index)` or `scaled_to_original(supplied, supply_index)` and panics with `MathOverflow` because the resulting RAY value exceeds `i128::MAX`. [23](#0-22) [24](#0-23) 

4. The overflow aborts before `last_timestamp` is committed; all subsequent accruals repeat the same calculation. [8](#0-7) [7](#0-6) 

5. Calls to `withdraw` and `repay` now fail with the same error because their pool legs synchronize the market before resolving positions. [25](#0-24) [26](#0-25)

pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };

/// Computes `floor(x * y / d)`, saturating to `i128::MAX` (or `i128::MIN` for a negative
/// quotient) instead of panicking if the result does not fit in `i128`. Panics with
/// `GenericError::DivisionByZero` if `d == 0`.
pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
