### Title
Unauthenticated Bridge P2P Peer Can Regress Parent Operator Nonce to Zero, Permanently Stalling Anchoring — (`node/sc/sub_bridge_handler.go`)

---

### Summary

`handleParentChainInfoResponseMsg` unconditionally overwrites the parent operator nonce with an attacker-supplied value when the bridge tx pool is empty and the local nonce exceeds the received nonce. Any peer that can connect to the sub-bridge P2P port and pass the weak handshake (NetworkId + ProtocolVersion only) can send a crafted `ServiceChainParentChainInfoResponseMsg` with `Nonce=0`, regressing the operator nonce from N to 0 and causing every subsequent anchoring transaction to be rejected with a stale-nonce error, permanently stalling anchoring.

---

### Finding Description

**Vulnerable branch** — `handleParentChainInfoResponseMsg`, lines 297–299:

```go
} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
    logger.Error("parent chain operator nonce is bigger than the received nonce.", ...)
    sbh.setParentOperatorNonce(pcInfo.Nonce)   // ← blindly accepts attacker value
}
``` [1](#0-0) 

This branch is reached when:
1. `bridgeTxPool.GetMaxTxNonce() == 0` — pool is empty (all prior anchoring txs confirmed and removed via `writeServiceChainTxReceipts` → `RemoveTx`)
2. `getParentOperatorNonce() == N > 0` — the operator has already submitted N anchoring txs (nonce incremented by `addParentOperatorNonce` after each `AddLocal`)
3. `pcInfo.Nonce == 0` — attacker-supplied [2](#0-1) 

The code logs an error but then **overwrites** the correct nonce N with 0. The correct behavior would be to keep the higher local nonce.

**Weak handshake — no ChainID or genesis validation:**

`baseBridgePeer.readStatus` only validates `NetworkId` and `ProtocolVersion`. It does not check `ChainID` or `GenesisBlock`:

```go
if status.NetworkId != network { ... }
if int(status.ProtocolVersion) != p.version { ... }
// ChainID is NOT validated here
``` [3](#0-2) 

The `RegisterNewPeer` ChainID check (`getParentChainID().Cmp(p.GetChainID())`) is trivially bypassed because `p.GetChainID()` is set from the attacker's own status message — the attacker simply claims the correct parent ChainID. [4](#0-3) 

**Sub-bridge accepts inbound connections:**

The sub-bridge P2P server does not set `NoListen = true`, so it listens for inbound connections in addition to dialing out to configured main bridges:

```go
serverConfig.NoDiscovery = true
serverConfig.StaticNodes = sb.config.MainBridges()
// NoListen is NOT set — server accepts inbound connections
``` [5](#0-4) 

**No automatic recovery:**

`handleParentChainInvalidTxResponseMsg` only calls `SyncNonceAndGasPrice()` for `ErrGasPriceBelowBaseFee` errors. For nonce-too-low rejections, the tx stays in the pool and keeps being rebroadcast and rejected — anchoring is stuck until manual operator intervention: [6](#0-5) 

---

### Impact Explanation

After the nonce is corrupted to 0:
- `genUnsignedChainDataAnchoringTx` uses `getParentOperatorNonce()` (now 0) as the tx nonce
- The tx is added to the bridge pool and broadcast to the parent chain
- The parent chain rejects it (nonce already consumed)
- The rejection handler does not re-sync the nonce for this error type
- The corrupted tx stays in the pool; `GetMaxTxNonce()` returns 0; the `poolNonce > 0` branch is never entered on subsequent syncs
- Anchoring is permanently stalled — child chain data is no longer anchored to the parent chain

This is a durable loss of core chain functionality (anchoring) affecting the service chain's security model.

---

### Likelihood Explanation

- The sub-bridge P2P port is network-accessible (no `NoListen`)
- The handshake requires only public knowledge (NetworkId, ProtocolVersion, and the parent ChainID which is public)
- The attack requires no keys, no governance access, no validator collusion
- The precondition (`poolNonce == 0`, `operatorNonce > 0`) is the normal steady-state after any anchoring tx is confirmed
- A single malicious message is sufficient; the attacker does not need to maintain the connection after the nonce is corrupted

---

### Recommendation

1. **Fix the nonce regression**: In the `else if` branch, do not overwrite the local nonce with a lower received value. Log the discrepancy and keep the higher local nonce:
   ```go
   } else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
       logger.Error("parent chain operator nonce is bigger than the received nonce — keeping local nonce",
           "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
       // Do NOT call setParentOperatorNonce here
   }
   ```
2. **Strengthen the bridge handshake**: Validate `ChainID` and `GenesisBlock` in `baseBridgePeer.readStatus`, matching the pattern used in `node/cn/peer.go`'s `readStatus`.
3. **Add nonce recovery for all rejection types**: In `handleParentChainInvalidTxResponseMsg`, call `SyncNonceAndGasPrice()` for any tx rejection that indicates a nonce error, not only gas-price errors.

---

### Proof of Concept

1. Start a service chain sub-bridge with anchoring enabled; advance the parent chain so N anchoring txs are confirmed and the bridge pool is empty (`GetMaxTxNonce() == 0`, `getParentOperatorNonce() == N`).
2. Connect a malicious peer to the sub-bridge P2P port; pass the handshake with the correct `NetworkId`, `ProtocolVersion`, and parent `ChainID`.
3. Send a `ServiceChainParentChainInfoResponseMsg` with `pcInfo.Nonce = 0`.
4. Observe that `getParentOperatorNonce()` is now 0 (the `else if` branch at line 297–299 fires).
5. Wait for the next anchoring period; observe that the generated anchoring tx carries nonce 0, is rejected by the parent chain with a nonce error, and anchoring never recovers without manual operator intervention.

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}
