### Title
Forged `pull_request:labeled` webhook via secretless-organization signature bypass allows cross-repository archive/unarchive of arbitrary review stacks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved organization's config has a blank `webhook_secret`, and the org used for that check (`repository.owner.login`) is independent from the `repository.full_name` used by `LabeledHandler` to resolve the target `Repository`/`ReviewStack`. This lets an attacker who controls (or names) a secretless org authenticate a forged `pull_request` body that names an arbitrary victim repository, causing `LabeledHandler` to archive or unarchive that victim's review stack. The `merge_queue_enabled` / `MergeRequest#merge!` amplification described in the question is not supported by the code — `LabeledHandler` never touches `MergeRequest` or the merge queue.

### Finding Description
The broken binding: the code implicitly assumes `params.repository.owner.login == params.repository.full_name.split('/').first`, i.e., that the organization used to verify the signature is the same organization that owns the repository acted upon. This is never enforced.

- `WebhooksController#verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` where `repository_owner = params.dig('repository','owner','login')`, then calls `github_app.verify_webhook_signature(...)`. [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` short-circuits to `true` when `webhook_secret` is blank, with no HMAC check performed at all. [3](#0-2) 
- Once past `verify_signature`, `WebhooksController#create` parses the raw body and dispatches to handlers for the `X-Github-Event`/action, passing the full attacker-controlled JSON. [4](#0-3) 
- `LabeledHandler` resolves the target repository purely from the body's `params.repository.full_name`, independent of the org used to verify the signature: [5](#0-4) 
and then archives/unarchives the corresponding `ReviewStack` for `pr#{params.number}` via `ReviewStackAdapter`: [6](#0-5) [7](#0-6) 

Exploit flow: attacker crafts a `pull_request` JSON body with `action: "labeled"`, `repository.owner.login` set to any org configured in Shipit with a blank `webhook_secret`, but `repository.full_name` set to the victim repository (any org, secret or not — the value is never cross-checked against `repository.owner.login`). `verify_signature` passes trivially because `verify_webhook_signature` returns `true` for the secretless org, regardless of the `X-Hub-Signature` header or body content. `LabeledHandler` then looks up the victim `Repository` by `full_name` and archives/unarchives its `pr#{number}` review stack based on the labels array supplied in the same forged body.

Existing guards that fail to prevent this: `check_if_ping`/`drop_unhandled_event` only gate on event type, not authenticity; `verify_signature` authenticates against the wrong scope (an attacker-chosen org rather than the org owning the acted-upon repository); `ExplicitParameters` schema only validates shape/types, not cross-field consistency between `repository.owner.login` and `repository.full_name`; there is no `User#authorized?`/`require_permission!`/`stacks` scope check anywhere in this unauthenticated controller.

Correction to the question's specific causal claim: `LabeledHandler`'s `archive!`/`unarchive!` path only calls `stack.remove_from_provisioning_queue`, `stack.deprovision`, `stack.archive!`/`stack.unarchive!`, and `ReviewStackProvisioningQueue.add` — it never touches `MergeRequest`, `MergeRequest#merge!`, or `merge_queue_enabled` in any way. [7](#0-6)  `merge_queue_enabled` only gates `MergeRequest.schedule_merges`, an unrelated feature that operates on `MergeRequest` records created via `request_merge!`, not review-stack archival. [8](#0-7)  The stated "green head advances the merge queue and `merge!` fires" amplification has no code support and does not occur as a consequence of `LabeledHandler`.

### Impact Explanation
Confirmed impact is cross-tenant mutation of Shipit state: an attacker can force archive or unarchive of any victim repository's PR review stack (`pr#{number}` environment) without any credentials for that repository, as long as some org configured in the same Shipit instance has a blank `webhook_secret`. Archiving triggers `stack.deprovision` and removal from the provisioning queue; unarchiving re-queues provisioning — both are real, repeatable, unauthorized writes against a repository/stack that never authenticated the request, matching the Critical category "a payload for one repository mutating another's stack." This is repeatable against any repository with `review_stacks_enabled` and any open PR number, for as long as one secretless-org config exists.

The `merge_queue_enabled` + `MergeRequest#merge!` chain specifically alleged by the question is not real — no additional Critical impact of "unauthorized merge" is achieved through `LabeledHandler`.

### Likelihood Explanation
Requires an operator-side misconfiguration precondition: at least one organization entry in `Shipit.github_config` (or equivalent) with a blank/absent `webhook_secret`. If that precondition holds, the attacker's cost is a single unauthenticated `POST /webhooks` with a hand-crafted JSON body and no valid signature — no Shipit session, API token, or GitHub credentials needed, fully repeatable against arbitrary repositories/stacks.

### Recommendation
- In `WebhooksController#verify_signature`, require that a `webhook_secret` always be configured per organization and reject (422) requests for any org where it is missing, instead of treating blank secret as "verified."
- Alternatively/additionally, in `LabeledHandler` (and all `pull_request`/handler code resolving repository by body content), cross-check that `params.repository.owner.login` matches the org used to authenticate the request before performing any mutation, ensuring the "authenticated org" and "acted-upon repository" are the same.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` conceptually):
1. Configure `Shipit.github_config` (or stub `Shipit.github`) with `organization: "no-secret-org"` having `webhook_secret: nil`, and a separate `victim-org/victim-repo` `Repository` fixture with `review_stacks_enabled: true` and an existing non-archived `ReviewStack` at `environment: "pr42"`.
2. Assert precondition equality before request: `ReviewStack.find_by(environment: "pr42").archived? == false`.
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature` (or an arbitrary bogus value), and JSON body: `{"action":"labeled","number":42,"pull_request":{...,"labels":[{"name":"<provisioning label>"}]},"repository":{"owner":{"login":"no-secret-org"},"full_name":"victim-org/victim-repo"},"sender":{"login":"attacker"}}`.
4. Assert response is `200`, not `422`.
5. Assert divergence: `ReviewStack.find_by(environment: "pr42").archived?` has changed to `true` (or `false` depending on provisioning behavior), proving that a request authenticated against `no-secret-org` mutated `victim-org/victim-repo`'s stack — violating the invariant "a `pull_request` event only affects the repository/stack whose secret authenticated it."
6. Separately assert (to disprove the merge_queue claim) that no `MergeRequest` record for the victim stack changes `merge_status`, and `MergeRequest#merge!` is never invoked, even when the victim stack has `merge_queue_enabled: true`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end
```
