### Title
Stack-scoped ApiClient can read CCMenu status of any stack via `Api::CCMenuController#stack` bypass - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Api::BaseController` enforces token-to-stack binding through the `stacks` helper, which restricts an `ApiClient` scoped to a specific `stack_id` to only that stack: `Stack.where(id: current_api_client.stack_id)` when `stack_id?` is true, or `Stack.all` otherwise [1](#0-0) . `Api::CCMenuController` overrides `stack` to resolve directly against the global `Stack` relation instead of the scoped `stacks` relation, breaking the binding between "the stack(s) a token is authorized for" and "the stack the endpoint actually touches."

### Finding Description
`Api::BaseController#stack` is meant to be the enforcement point for stack-scoping: it looks up the requested stack only within `stacks`, which is filtered by `current_api_client.stack_id` when the client is stack-scoped [1](#0-0) .

`Api::CCMenuController`, however, defines its own `stack` method that resolves the stack via `Stack.from_param!(params[:stack_id])` — the unscoped, global `Stack` model — rather than `stacks.from_param!`: [2](#0-1) 

The controller still authenticates the client and still calls `require_permission :read, :stack` [3](#0-2) , but `check_permissions!` only checks the string permission `"read:stack"` is present in the client's `permissions` array [4](#0-3)  — it never checks whether the requested `stack_id` param matches `current_api_client.stack_id`. That match is only performed inside the (bypassed) `stacks` scoping helper.

The equality that should hold is:
`stack_id(s) authorized for token == stack(s) touched by the endpoint`

Before the bug (in every other API controller that relies on the inherited `stack`/`stacks` helpers, e.g. `Api::StacksController`, `Api::TasksController`), this equality holds because `stack` is resolved through `stacks.from_param!`.

In `Api::CCMenuController`, the right-hand side is widened to "any stack in the database" regardless of the left-hand side, because `stack` is resolved through the global `Stack.from_param!` instead.

### Impact Explanation
A `read:stack`-permissioned `ApiClient` that is intentionally scoped to a single stack (`stack_id` set, as exercised by the `here_come_the_walrus` fixture and tested for the `Api::StacksController#index`/`#show` endpoints [5](#0-4) ) is supposed to be unable to see any other stack's state. Via `Api::CCMenuController#show`, that same token can query `GET /api/1/stacks/:stack_id/ccmenu.xml` (or the query-string-token variant) for an arbitrary `stack_id` belonging to a different repository/team, and receive that stack's latest deploy/build status, name, activity, and last build time [6](#0-5) . This is an unauthorized read of stack state across the scoping boundary the token was explicitly issued to respect, matching the "unauthenticated/unauthorized read of stack state, task streams or deploy output" High-impact category.

### Likelihood Explanation
Exploitation requires only possession of a valid, stack-scoped `ApiClient` token with `read:stack` permission — no elevated or admin privileges are needed, and no test in the suite exercises a scoped client against `CCMenuController` to catch the regression [7](#0-6)  (all tests there use the default, unscoped `authenticate!` client). Any consumer legitimately given a stack-limited CCMenu/CI-status integration token can trivially pivot to reading other stacks simply by changing the `stack_id` route/query parameter.

### Recommendation
Change `Api::CCMenuController#stack` to resolve through the inherited scoped relation instead of the raw model, mirroring every other API controller:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
This restores the invariant that the set of stacks reachable through any API endpoint is exactly the set of stacks the authenticated `ApiClient` is scoped to.

### Proof of Concept
1. Create two stacks, `stack_a` and `stack_b`.
2. Create an `ApiClient` scoped to `stack_a` only: `ApiClient.create!(creator: user, name: 'scoped', permissions: %w[read:stack], stack: stack_a)`.
3. Authenticate as this client and request:
   `GET /api/1/stacks/<stack_b.to_param>/ccmenu.xml` (or with `?token=<client.authentication_token>`).
4. Expected (correct) behavior: 404 / not found, because `stacks` for this client is `Stack.where(id: stack_a.id)` and `stack_b` isn't in it.
5. Actual behavior: the request succeeds with `200 OK` and returns `stack_b`'s CCMenu project XML (name, last build status, etc.), because `Api::CCMenuController#stack` calls `Stack.from_param!(params[:stack_id])` directly, ignoring the client's `stack_id` scope entirely — confirmed by reading [8](#0-7)  against the scoping logic in [1](#0-0) .

# frozen_string_literal: true

require 'test_helper'

module Shipit
  module Api
    class CCMenuControllerTest < ApiControllerTestCase
      setup do
        authenticate!
        @stack = shipit_stacks(:shipit)
      end

      test "a request with insufficient permissions will render a 403" do
        @client.update!(permissions: [])
        get :show, params: { stack_id: @stack.to_param }
        assert_response :forbidden
        assert_json 'message', 'This operation requires the `read:stack` permission'
      end

      test "#show renders the xml" do
        get :show, params: { stack_id: @stack.to_param }
        assert_response :ok
        assert_payload 'name', @stack.to_param
      end

      test "can authenticate with query string token" do
        request.headers['Authorization'] = 'bleh'
        get :show, params: { stack_id: @stack.to_param, token: @client.authentication_token }
        assert_response :ok
        assert_payload 'name', @stack.to_param
      end

      test "xml contains required attributes" do
        get :show, params: { stack_id: @stack.to_param }
        project = get_project_from_xml(response.body)
        %w[name activity lastBuildStatus lastBuildLabel lastBuildTime webUrl].each do |attribute|
          assert_includes project, attribute, "Response missing required attribute: #{attribute}"
        end
      end

      test "locked stacks show as failed" do
        @stack.lock('test', @user)
        get :show, params: { stack_id: @stack.to_param }
        assert_payload 'lastBuildStatus', 'Failure'
      end

      test "stacks with no deploys render correctly" do
        stack = Stack.create!(repository: Repository.new(owner: "foo", name: "bar"), branch: 'main')
        get :show, params: { stack_id: stack.to_param }
        assert_payload 'lastBuildStatus', 'Success'
      end

      private

      def get_project_from_xml(xml)
        Hash.from_xml(xml)['Projects']['Project']
      end

      def assert_payload(key, value)
        @project ||= get_project_from_xml(response.body)
        assert_equal(value, @project[key])
      end
    end
  end
end
