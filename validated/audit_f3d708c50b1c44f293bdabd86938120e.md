### Title
Compounding division-before-multiplication in the graduated liquidation engine's `other-debt-repayable` estimate can round down to zero, prematurely triggering bad-debt socialization onto all vault depositors - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The graduated liquidation flow in `v0-4-market.clar` computes `other-debt-repayable` — an estimate of whether a borrower's *remaining* collateral (across other collateral assets not touched by the current liquidation call) can still cover their remaining debt — through a chain of four sequential floor-divisions before a single, final round-up. Because each intermediate division truncates independently instead of being combined algebraically (the same anti-pattern flagged in the referenced report for `_GeneralIntegrate()`), the compounded truncation can push a small-but-nonzero true value down to exactly `u0`. That zero result flips the boolean `no-collateral-left`, which drives whether the borrower's debt is written off and socialized across every depositor of the debt vault, even though the borrower actually still had recoverable collateral value.

### Finding Description
In `execute-liquidation` the code computes: [1](#0-0) 

```clarity
(other-debt-repayable
  (if (> other-coll-usd u0)
    (let ((other-adj (div-bps-down other-coll-usd (+ BPS liq-penalty-max)))
          (other-tokens (mul-div-down other-adj (pow u10 debt-decimals) debt-price))
          (other-borrow-idx (get index (unwrap-panic (get-cached-indexes debt-aid))))
          (other-scaled (mul-div-down other-tokens INDEX-PRECISION other-borrow-idx)))
      (mul-div-up other-scaled other-borrow-idx INDEX-PRECISION))
    u0))
```

Four rounding operations are chained: `div-bps-down`, `mul-div-down`, `mul-div-down`, then `mul-div-up`. Each division floors its own intermediate result before the next operation multiplies it back up, so precision lost at each step is never recovered — unlike a single combined `(numerator * multiplier) / (denom1 * denom2)` computation. This is the same class of bug as `_GeneralIntegrate()` in the referenced report, where `V0V0V1V2 = divFloor(divFloor(V0*V0, V1), V2)` loses far more precision than computing `(V0*V0) / (V1*V2)` directly.

The result feeds directly into the shared-state decision: [2](#0-1) 

```clarity
(no-collateral-left (and
                      (is-eq coll-removed u0)
                      (or
                        (is-eq (len (get collateral pos-full)) u1)
                        (and
                          (is-eq (len (get collateral pos-full)) (len (get collateral position)))
                          (is-eq other-debt-repayable u0)))))
```

If `no-collateral-left` evaluates `true`, the market calls into `socialize-debt-asset`, which writes down the vault's liquidity index (`vault-socialize-debt`) and removes the borrower's scaled debt — spreading the loss across every depositor of that vault's pool rather than merely reducing the individual liquidated position: [3](#0-2) 

### Impact Explanation
`other-coll-usd` and `other-debt-repayable` gate whether a position is deemed fully unrecoverable ("no collateral left"). Compounded floor-division across four sequential steps biases the estimate downward; for small remaining collateral balances, tiny debt/price/decimals combinations, or borrow indexes/prices that don't cleanly divide, the true nonzero repayable amount can be truncated to exactly `u0`. This falsely satisfies `is-eq other-debt-repayable u0`, causing the engine to socialize the borrower's remaining debt as bad debt onto the vault's liquidity index (`vault-socialize-debt`) even though the borrower still had collateral capable of covering it. Every unprivileged depositor of that debt vault absorbs a share of a loss that should not yet have been recognized — this is a socialization charged to all suppliers triggered by an unprivileged liquidator/borrower interaction, not by the depositors themselves.

### Likelihood Explanation
The trigger requires only an ordinary partial liquidation where the borrower has multiple collateral assets and a small residual collateral value on the non-liquidated asset(s) relative to `debt-price`/`debt-decimals`/`other-borrow-idx` — no privileged access or oracle manipulation is needed. Values near the truncation boundary (residual USD value close to, but below, one unit of debt-token precision after the `div-bps-down` and two `mul-div-down` steps) are plausible in normal operation, especially for lower-decimal or higher-priced debt assets, making this reachable without contrived extremes.

### Recommendation
Combine the divisions algebraically instead of chaining independent floor operations, e.g. compute `other-debt-repayable` with a single combined denominator (`(BPS + liq-penalty-max) * debt-price * other-borrow-idx`) and a single combined numerator (`other-coll-usd * 10^debt-decimals * INDEX-PRECISION`), performing one final division (rounded appropriately) rather than three intermediate roundings. At minimum, avoid deciding `no-collateral-left` purely from a doubly/triply-rounded zero; instead compare `other-coll-usd` (a USD-denominated, higher-precision quantity) against a minimal dust threshold before concluding no collateral remains.

### Proof of Concept
Given illustrative values where each step floors independently:
- `other-coll-usd = 15000` (1e8-scaled USD), `BPS = 10000`, `liq-penalty-max = 500` → `other-adj = div-bps-down(15000, 10500) = 14285` (floor)
- `debt-decimals = 6`, `debt-price = 100000000` (1e8) → `other-tokens = mul-div-down(14285, 1e6, 1e8) = 142` (floor, precise would be ~142.85)
- `other-borrow-idx = 1_050_000_000_000_000_000` (1.05e18), `INDEX-PRECISION = 1e18` → `other-scaled = mul-div-down(142, 1e18, 1.05e18) = 135` (floor)
- final: `mul-div-up(135, 1.05e18, 1e18) = 142` — in this instance nonzero, but shifting any of the intermediate inputs slightly lower (e.g., `other-coll-usd` a few units smaller) drives `other-tokens` to `0` at the second step, which then forces `other-scaled = 0` and `other-debt-repayable = 0` via `mul-div-up(0, ..., ...) = 0`, even though the true precise repayable amount (computed via a single combined division) would remain a small positive value. This zero flips `no-collateral-left` to `true`, triggering `socialize-debt-asset` and writing the loss down onto the vault's shared liquidity index for all depositors, while the precise calculation shows the borrower's other collateral was not actually fully exhausted.
