### Title
Newline injection in git-credential heredoc allows arbitrary host/credential injection into git's credential store - ([File: pkg/cmd/auth/shared/gitcredentials/updater.go])

### Summary
`(*Updater).Update` builds the stdin for `git credential approve` with `heredoc.Docf("...host=%s\nusername=%s\npassword=%s\n", hostname, username, password)` without escaping or validating that `username`/`password` are free of newlines. Both values ultimately originate from data returned by the host being authenticated against (`viewer.login` GraphQL field and the OAuth/device-flow token), so a host the victim points `gh auth login`/`gh auth refresh` at can return a value containing an embedded `\n` to inject additional `key=value` lines (notably `host=`) into the git-credential protocol input.

### Finding Description
`Update` is implemented as:
```go
approveCmd.Stdin = bytes.NewBufferString(heredoc.Docf(`
    protocol=https
    host=%s
    username=%s
    password=%s
`, hostname, username, password))
``` [1](#0-0) 

`git credential approve` parses stdin line by line as `key=value` pairs until a blank line, and later assignments of the same key override earlier ones. Because the values are interpolated verbatim with no newline stripping, a `username` (or `password`) value containing `\nhost=evil.example.com` lets an attacker append/override the `host` field that was already written from the trusted `hostname` argument, causing the credential to be approved (stored) against an arbitrary attacker-chosen host instead of the legitimate one.

The `username` value is sourced from `GetCurrentLogin`, which returns the raw `viewer.login` string from a `UserCurrent{viewer{login}}` GraphQL query against the target host with no format validation: [2](#0-1) 
The same pattern (unsanitized `viewer.login`) is used by the device/web OAuth path via `getViewer`/`CurrentLoginName`: [3](#0-2) [4](#0-3) 

Both `username` and `authToken` (password) flow into `Updater.Update` via `GitCredentialFlow.Setup`: [5](#0-4) 
called from `login_flow.go`'s `Login()` after `username`/`authToken` are obtained from the target host (either interactively pasted or obtained through the OAuth/device flow and `GetCurrentLogin`): [6](#0-5) 

Because this is a host the victim explicitly points `gh` at (`gh auth login -h <attacker-host>` / `gh auth refresh -h <attacker-host>`), the attacker fully controls the GraphQL response for `viewer.login` and the OAuth token content returned to `gh`, satisfying the allowed "controls responses from a host the victim points gh at" attacker model. No existing check in `Update`, `GetCurrentLogin`, or `git_credential.go` strips or rejects newlines/control characters in these values before they are embedded in the credential-helper stdin.

### Impact Explanation
This allows a malicious/attacker-controlled host to make `gh` cause the local `git credential approve` invocation to store credentials (host, username, password) under an arbitrary hostname of the attacker's choosing rather than the host actually being authenticated — e.g., overriding `host=github.com`. Depending on the injected values, this can plant attacker-controlled credentials in the victim's git credential store for a different, legitimate host, so that subsequent `git clone`/`git push` operations against that host use the attacker-supplied identity/token instead of (or alongside) the user's real one. This is a credential-store poisoning / wrong-host credential routing issue (maps to "authenticated request to an attacker/unintended host" and "file/credential store write outside intended scope").

### Likelihood Explanation
Requires the victim to run `gh auth login` or `gh auth refresh` against a host controlled by (or whose API responses are controlled by) the attacker, and to already have a non-`gh` git credential helper configured (`ConfiguredHelper` not `IsOurs`) so that `Updater.Update` path is exercised instead of `ConfigureOurs`. Both preconditions are realistic and match the allowed threat model (attacker publishes/controls a host the victim is instructed to authenticate against). No token leak, MITM, or local access is needed.

### Recommendation
Reject or strip control characters (`\n`, `\r`) from `hostname`, `username`, and `password` before constructing the `git credential` stdin in `Updater.Update`, or write each field using a safe key/value encoder that refuses values containing newlines. Additionally validate `viewer.login` returned by `GetCurrentLogin`/`CurrentLoginName` against GitHub's username character set before using it anywhere sensitive (config write, credential store, shell/heredoc interpolation).

### Proof of Concept
```go
func TestUpdateNewlineInjectionOverridesHost(t *testing.T) {
    git.IsolateConfig(t)
    configureStoreCredentialHelper(t) // as in updater_test.go

    u := &gitcredentials.Updater{GitClient: &git.Client{}}
    maliciousUsername := "monalisa\nhost=evil.example.com\nusername=attacker\npassword=attacker-token"

    require.NoError(t, u.Update("github.com", maliciousUsername, "real-token"))

    // Query the store for the injected host and show the attacker's credential was persisted
    gc := &git.Client{}
    fillCmd, _ := gc.Command(context.Background(), "credential", "fill")
    fillCmd.Stdin = bytes.NewBufferString(heredoc.Docf(`
        protocol=https
        host=%s
    `, "evil.example.com"))
    out, err := fillCmd.Output()
    require.NoError(t, err)
    require.Contains(t, string(out), "username=attacker")
    require.Contains(t, string(out), "password=attacker-token")
}
```
Expected: the credential store ends up with an entry for `evil.example.com` even though `Update` was only invoked with `hostname="github.com"`, confirming the newline injection lets attacker-controlled input override the destination host of stored credentials.

func GetCurrentLogin(httpClient httpClient, hostname, authToken string) (string, error) {
	query := `query UserCurrent{viewer{login}}`
	reqBody, err := json.Marshal(map[string]interface{}{"query": query})
	if err != nil {
		return "", err
	}
	result := struct {
		Data struct{ Viewer struct{ Login string } }
	}{}
	apiEndpoint, err := safeurl.JoinPathWithHostPrefix(ghinstance.GraphQLEndpoint(hostname))
	if err != nil {
		return "", err
	}
	req, err := http.NewRequest("POST", apiEndpoint.String(), bytes.NewBuffer(reqBody))
	if err != nil {
		return "", err
	}
	req.Header.Set("Authorization", "token "+authToken)
	res, err := httpClient.Do(req)
	if err != nil {
		return "", err
	}
	defer res.Body.Close()
	if res.StatusCode > 299 {
		return "", api.HandleHTTPError(res)
	}
	decoder := json.NewDecoder(res.Body)
	err = decoder.Decode(&result)
	if err != nil {
		return "", err
	}
	return result.Data.Viewer.Login, nil

func (flow *GitCredentialFlow) Setup(hostname, username, authToken string) error {
	// If there is no credential helper configured then we will set ourselves up as
	// the credential helper for this host.
	if !flow.helper.IsConfigured() {
		return flow.HelperConfig.ConfigureOurs(hostname)
	}

	// Otherwise, we'll tell git to inform the existing credential helper of the new credentials.
	return flow.Updater.Update(hostname, username, authToken)
