### Title
Global `ProgramCache` eviction only accounts for `Loaded` entries, letting an attacker permanently grow validator memory with uncollectable tombstones - ([File: program-runtime/src/loaded_programs.rs])

### Summary
The Solana/Agave global program cache (`ProgramCache<FG>`) stores, per program pubkey, a `Vec<Arc<ProgramCacheEntry>>` covering every deployment-slot version ever seen, including non-executable tombstone variants (`FailedVerification`, `Closed`, `DelayVisibility`). Both cache-shrinking paths — `sort_and_unload` and `evict_using_random_selection` — build their eviction candidate set exclusively from `get_flattened_entries()`, which filters to `ProgramCacheEntryType::Loaded(_)` only. Tombstones are therefore invisible to eviction and accumulate in the cache forever, exactly analogous to browserslist's unbounded `cache`/`parseCache` maps that grow with every distinct cheap input and are never reclaimed.

### Finding Description
`get_flattened_entries()` only yields `Loaded` entries: [1](#0-0) 

Both memory-reclaiming routines are built on top of this filtered view: [2](#0-1) [3](#0-2) 

Since `candidates`/`sorted_candidates` never contain tombstones, `num_to_unload` is computed purely against the `Loaded` population and tombstones are never selected for `unload_program_entry`/removal — they simply persist in the `entries: HashMap<Pubkey, Vec<Arc<ProgramCacheEntry>>>` index indefinitely.

A tombstone is created and permanently cached whenever a transaction references an account that is owned by one of the four BPF loaders but fails to load/verify as a program. `filter_executable_program_accounts` accepts any account owned by `bpf_loader`/`bpf_loader_deprecated`/`bpf_loader_upgradeable`/`loader_v4` (LoaderV1/V2 accept arbitrary data unconditionally): [4](#0-3) 

`load_program_with_pubkey` then converts any load/verification failure into a `FailedVerification` (or `Closed`) tombstone rather than rejecting the entry: [5](#0-4) 

That tombstone is committed to the shared global cache via `finish_cooperative_loading_task` → `assign_program`, which inserts a new `Vec` entry for the pubkey if none exists yet: [6](#0-5) [7](#0-6) 

Eviction of the global cache is only triggered opportunistically, after batches that loaded/modified something, via `evict_using_random_selection`, which — as shown above — cannot touch tombstones: [8](#0-7) 

### Impact Explanation
Any unprivileged sender can trigger this by including, in an ordinary transaction, an account key that is owned by `bpf_loader`/`bpf_loader_upgradeable`/`bpf_loader_deprecated`/`loader_v4` but does not contain a valid deployed program (e.g., an account created and reassigned to the loader with a few bytes of garbage data, or a system-created account with the loader as owner and insufficient/invalid programdata). Each such distinct pubkey referenced by a transaction results in one permanent `Vec<Arc<ProgramCacheEntry>>` entry in the process-global `ProgramCache`, which is never evicted regardless of memory pressure (`sort_and_unload`/`evict_using_random_selection` both operate on `Loaded`-only candidate lists). Because every validator in the cluster independently replays the same transaction stream, this bloat accumulates identically and simultaneously on every validator, eventually leading to correlated out-of-memory conditions across the fleet — a transaction-triggered path toward a cluster-wide halt, not merely a single-node DoS.

### Likelihood Explanation
The attack requires only account creation (paying the ordinary rent-exempt minimum) and setting the account owner to a BPF loader with arbitrary/invalid data — no working program, ELF compilation, or expensive compute is needed. This is orders of magnitude cheaper than deploying real programs, and pubkeys are free/infinite to generate, so an attacker can create an effectively unbounded stream of unique tombstone-cache keys over time. Likelihood is High for eventual measurable memory growth from sustained traffic, though it requires sustained volume (many transactions/accounts) rather than a single request, similar to the original browserslist finding's "volumetric, not single-request" characterization.

### Recommendation
Include tombstone entries (`FailedVerification`, `Closed`, `DelayVisibility`) in the candidate set used by `get_flattened_entries()` (or add a separate accounting path) so that `sort_and_unload`/`evict_using_random_selection` can also reclaim them, and/or impose a hard cap on the number of distinct tombstoned pubkeys the global `ProgramCache` will retain, evicting the oldest/least-recently-referenced ones once the cap is reached — mirroring the bounded-`Map` fix applied upstream in browserslist.

### Proof of Concept
Conceptually:
1. Attacker creates an account and assigns its owner to `bpf_loader::id()` (LoaderV2), storing a few bytes of non-ELF garbage data, via ordinary `SystemProgram::CreateAccount` + `Assign`/`CreateAccountWithSeed` instructions costing only the rent-exempt minimum.
2. Attacker submits a transaction that references this account key as an instruction "program id" (or otherwise causes it to enter `filter_executable_program_accounts`'s missing-program list).
3. `load_program_with_pubkey` fails ELF verification and returns a `FailedVerification` tombstone (`svm/src/program_loader.rs:179-182`), which `finish_cooperative_loading_task`/`assign_program` permanently inserts into the global `ProgramCache`'s `entries` map.
4. Repeat with a fresh pubkey each time (cheap, since pubkeys are free and only rent-exempt lamports are required per account). `evict_using_random_selection`, invoked after each batch that loads something (`svm/src/transaction_processor.rs:688-699`), never removes these tombstones because its candidate set (`get_flattened_entries`) excludes non-`Loaded` variants.
5. Over sustained submission, the `entries` HashMap grows without bound on every validator processing the stream, consuming increasing amounts of memory with no reclamation path, until OOM pressure is reached cluster-wide.

Note: I was unable to run this PoC end-to-end (no execution environment available in this session) — the above is based on static code-path analysis of the cited functions. A Devin session with a build/test environment would be needed to empirically measure the growth rate and confirm no other reclamation mechanism (e.g., snapshot-triggered full cache rebuild) mitigates this in practice.

    /// Insert a single entry. It's typically called during transaction loading,
    /// when the cache doesn't contain the entry corresponding to program `key`.
    pub fn assign_program(
        &mut self,
        program_runtime_environment: &ProgramRuntimeEnvironment,
        key: Pubkey,
        _current_slot: Slot,
        entry: Arc<ProgramCacheEntry>,
    ) -> bool {
        debug_assert!(
            !matches!(&entry.program, ProgramCacheEntryType::DelayVisibility),
            "Unexpected assignment of a DelayVisibility tombstone"
        );
        // This function always returns `true` during normal operation.
        // Only during the cache preparation phase this can return `false`
        // for entries with `upcoming_environment`.
        fn is_current_env(
            program_runtime_environment: &ProgramRuntimeEnvironment,
            env_opt: Option<&ProgramRuntimeEnvironment>,
        ) -> bool {
            env_opt
                .map(|env| env == program_runtime_environment)
                .unwrap_or(true)
        }
        match &mut self.index {
            IndexImplementation::V1 { entries, .. } => {
                let slot_versions = &mut entries.entry(key).or_default();
                let insertion_point = slot_versions.binary_search_by(|at| {
                    at.deployment_slot
                        .cmp(&entry.deployment_slot)
                        .then(at.account_owner.cmp(&entry.account_owner))
                        .then(
                            // This `.then()` has no effect during normal operation.
                            // Only during the cache preparation phase this does allow entries
                            // which only differ in their environment to be interleaved in `slot_versions`.
                            is_current_env(
                                program_runtime_environment,
                                at.program.get_environment(),
                            )
                            .cmp(&is_current_env(
                                program_runtime_environment,
                                entry.program.get_environment(),
                            )),
                        )
                });
                match insertion_point {
                    Ok(index) => {
                        let existing = slot_versions.get_mut(index).unwrap();
                        match (&existing.program, &entry.program) {
                            (
                                ProgramCacheEntryType::Builtin(_),
                                ProgramCacheEntryType::Builtin(_),
                            )
                            | (ProgramCacheEntryType::Closed, ProgramCacheEntryType::Unloaded(_))
                            | (
                                ProgramCacheEntryType::Unloaded(_),
                                ProgramCacheEntryType::Loaded(_),
                            )
                            | (
                                ProgramCacheEntryType::Unloaded(_),
                                ProgramCacheEntryType::FailedVerification(_),
                            ) => {}
                            _ => {
                                // Something is wrong, I can feel it ...
                                error!(
                                    "ProgramCache::assign_program() failed key={key:?} \
                                     existing={slot_versions:?} entry={entry:?}"
                                );
                                debug_assert!(false, "Unexpected replacement of an entry");
                                self.stats.replacements.fetch_add(1, Ordering::Relaxed);
                                return true;
                            }
                        }
                        entry.stats.merge_from(&existing.stats);
                        *existing = Arc::clone(&entry);
                        self.stats.reloads.fetch_add(1, Ordering::Relaxed);
                    }
                    Err(index) => {
                        self.stats.insertions.fetch_add(1, Ordering::Relaxed);
                        slot_versions.insert(index, Arc::clone(&entry));
                    }
                }
                // Remove existing entries in the same deployment slot unless they are for a different
                // environment.
                // This overwrites the current status of a program in program management instructions.
                slot_versions.retain(|existing| {
                    existing.deployment_slot != entry.deployment_slot
                        || existing
                            .program
                            .get_environment()
                            .zip(entry.program.get_environment())
                            .map(|(a, b)| a != b)
                            .unwrap_or(false)
                        || Arc::ptr_eq(existing, &entry)
                });
            }
        }
        false
    }

    /// Evicts programs using random selection, choosing the worst scoring program out of the
    /// entries sampled.
    ///
    /// The eviction is performed enough number of times to reduce the cache usage to the given
    /// percentage.
    pub fn evict_using_random_selection(&mut self, shrink_to_percent: Percent, now: Slot) {
        let mut candidates = self.get_flattened_entries();
        let mut rng = rng();
        self.stats
            .water_level
            .store(candidates.len() as u64, Ordering::Relaxed);
        let num_to_unload = candidates
            .len()
            .saturating_sub(percent_of_max_entries(shrink_to_percent));
        let mut sample_entry = |candidates: &Vec<(Pubkey, Arc<ProgramCacheEntry>)>| {
            // gen_range is deprecated in favor of random_range in rand>=0.9, but we also get
            // rnd() from shuttle, which doesn't yet support rand 0.9 APIs
            #[cfg(feature = "shuttle-test")]
            let index = rng.gen_range(0..candidates.len());
            #[cfg(not(feature = "shuttle-test"))]
            let index = rng.random_range(0..candidates.len());
            let usage_counter = candidates
                .get(index)
                .expect("Failed to get cached entry")
                .1
                .retention_score();
            (index, usage_counter)
        };

        // Random sampling with just 2 choices can frequently lead to a situation where both
        // entries chosen have relatively high retention scores, having us to pick one out of two
        // poor options. We can tell what a relatively high retention score is, so we can make a
        // few additional samples until we hit some other entry that isn't as highly scoring.
        //
        // Note that the "high enough" compilation time and use count numbers used here are
        // relatively arbitrary.
        const MAX_ADDITIONAL_SAMPLES: usize = 3;
        let avoid_evicting_above_score = retention_score(now, 500 * EMA_SCALE, 500);
        for _ in 0..num_to_unload {
            let (mut index, mut score) = sample_entry(&candidates);
            for _ in 0..MAX_ADDITIONAL_SAMPLES {
                let (sample_index, sample_score) = sample_entry(&candidates);
                if score > sample_score {
                    index = sample_index;
                    score = sample_score;
                }
                if score < avoid_evicting_above_score {
                    break;
                }
            }
            let (id, entry) = candidates.swap_remove(index);
            self.unload_program_entry(id, &entry);
        }
    }

pub(crate) fn filter_executable_program_accounts<'a, CB: TransactionProcessingCallback>(
    callbacks: &CB,
    program_cache_for_tx_batch: &ProgramCacheForTxBatch,
    keys: impl Iterator<Item = &'a Pubkey>,
) -> Vec<ProgramToLoad<'a>> {
    let mut result = Vec::new();
    for account_key in keys {
        if let Some(cache_entry) = program_cache_for_tx_batch.find(account_key) {
            cache_entry.stats.uses.fetch_add(1, Ordering::Relaxed);
        } else if let Some(account) = callbacks.get_account_shared_data(account_key) {
            // A valid program must be owned by one of the four BPF loaders.
            let loader = if loader_v4::check_id(account.owner()) {
                ProgramCacheEntryOwner::LoaderV4
            } else if bpf_loader_upgradeable::check_id(account.owner()) {
                ProgramCacheEntryOwner::LoaderV3
            } else if bpf_loader::check_id(account.owner()) {
                ProgramCacheEntryOwner::LoaderV2
            } else if bpf_loader_deprecated::check_id(account.owner()) {
                ProgramCacheEntryOwner::LoaderV1
            } else {
                continue;
            };
            // A valid program must also have a deployment slot stored.
            // If the deployment slot cannot be determined, this program is
            // likely *closed*; DON'T return it!
            let Ok(deployment_slot) = get_program_deployment_slot(callbacks, &account, loader)
            else {
                continue;
            };
            result.push(ProgramToLoad {
                program_id: account_key,
                loader,
                deployment_slot,
            });
        }
    }
    result
}
