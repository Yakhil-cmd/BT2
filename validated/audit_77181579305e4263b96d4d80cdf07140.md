### Title
RAY-valued debt overflow permanently freezes a high-utilization market - (File: common/src/rates/simulate.rs)

### Summary
`accrue_step` converts total scaled debt and supply back into RAY asset values before calculating utilization. When `scaled_amount * index / RAY` no longer fits in `i128`, `scaled_to_original` panics through `Ray::mul` / `mul_div_half_up`, reverting the entire transaction rather than capping the represented value or isolating the arithmetic failure. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
An unprivileged account can create the prerequisite state by supplying a very large amount and borrowing near the market's permitted cash/utilization limit. Interest then grows the borrow index until `borrowed * borrow_index / RAY` exceeds `i128::MAX`. [4](#0-3) [5](#0-4) 

The public `update_indexes` path calls the pool, loads the market, and executes `global_sync`; every step calls `scaled_to_original` for both debt and supply. Once the RAY value is unrepresentable, the panic occurs before the borrow-index ceiling can be reached and before state can be committed. [6](#0-5) [7](#0-6) [8](#0-7) 

The same accrual executes before ordinary market mutations, so the overflow also blocks repayment, withdrawal, liquidation-oriented settlement, and other operations for that market. The repository's long-horizon test explicitly demonstrates `MATH_OVERFLOW`, followed by failed withdrawal and repayment. [9](#0-8) 

### Impact Explanation
All funds represented by the affected market can become permanently frozen: suppliers cannot withdraw, borrowers cannot repay, and liquidation or cleanup cannot complete because they first hit the same accrual panic. [10](#0-9) 

This is stronger than a temporary transaction failure because future timestamps only increase the interval that accrual must process, and the stored market state has no alternate non-accruing escape path. [8](#0-7) 

### Likelihood Explanation
The attacker needs a sufficiently large accepted supply and a market able to sustain high utilization until the RAY value crosses the `i128` boundary. The test configuration demonstrates the reachable shape with one billion whole tokens at 98% utilization, while noting that smaller or lower-utilization markets require longer or may remain below the practical boundary. [9](#0-8) 

Market caps and asset availability constrain how readily an attacker can create the state, so this is best treated as a conditional permanent-freeze issue rather than an immediate theft primitive. [11](#0-10) 

### Recommendation
Represent aggregate debt and supply valuation in a wider type throughout accrual, or calculate utilization as a bounded ratio without materializing `scaled * index` in `i128`. If a market approaches the representable boundary, fail the incoming operation before committing state that later cannot be accrued, and provide a recovery path that can reduce shares or debt without invoking the overflowing valuation. At minimum, enforce a documented maximum `scaled_amount * index / RAY` before debt minting, supply minting, revenue minting, and bad-debt mutation. [12](#0-11) [13](#0-12)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
