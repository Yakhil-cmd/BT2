Before the final write-up: the specific bug class most directly analogous to CVE-2019-20889 (a permission model failing to enforce the intended privilege boundary when authorizing creation of an access credential) is the `pallet_proxy` `ProxyType::is_superset` vs. `InstanceFilter::filter` mismatch. This exact class was already found and patched in `asset-hub-westend-runtime` (see `prdoc/pr_12769.prdoc` and `prdoc/pr_12771.prdoc`, tracking upstream issue #12724), with regression tests added at [1](#0-0) . That instance is not reproducible here since it is fixed. However, checking sibling runtimes for the same lattice-consistency defect surfaced an unpatched analog in the live Westend relay-chain runtime (and the same code pattern in Rococo and the staging RC runtime).

### Title
`ProxyType::NonTransfer` on Westend/Rococo relay chain falsely claims superset of `ProxyType::Auction`, letting a `NonTransfer` proxy self-escalate to `paras_registrar::swap` - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
`pallet_proxy` authorizes `add_proxy`/`remove_proxy` purely through `ProxyType::is_superset`, without re-checking `InstanceFilter::filter` on the target permission set [2](#0-1) . On the Westend and Rococo relay-chain runtimes (and the staging `staking-async` RC runtime), `ProxyType::is_superset` declares `NonTransfer` a superset of every other proxy type (`(ProxyType::NonTransfer, _) => true`), while `ProxyType::Auction`'s filter admits the *entire* `Registrar` pallet (`RuntimeCall::Registrar(..)`/`RuntimeCall::Registrar { .. }`), including `paras_registrar::swap`, which `NonTransfer`'s own filter explicitly excludes ("Specifically omitting Registrar `swap`"). A delegate holding only a `NonTransfer` proxy can therefore add itself an `Auction` proxy and dispatch `Registrar::swap` on behalf of the delegator — a call the delegator's grant was designed to forbid.

### Finding Description
`do_proxy` gates a proxied `add_proxy`/`remove_proxy` call solely on `!def.proxy_type.is_superset(proxy_type)`; if `is_superset` returns `true`, the call falls through to the generic `def.proxy_type.filter(c)` check [3](#0-2) .

On Westend:
- `is_superset` declares `(ProxyType::NonTransfer, _) => true` for every other `ProxyType`, including `Auction` [4](#0-3) .
- `NonTransfer`'s filter admits the whole `Proxy` pallet (`RuntimeCall::Proxy(..)`) and only a restricted subset of `Registrar` (`register`, `deregister`, `reserve`), deliberately omitting `swap` [5](#0-4) .
- `Auction`'s filter admits `RuntimeCall::Registrar(..)` unrestricted — i.e., every Registrar call including `swap` [6](#0-5) .

Because `NonTransfer`'s filter allows `RuntimeCall::Proxy(..)` (unrestricted), a `NonTransfer` delegate proxying `Proxy::add_proxy{ delegate: <attacker or accomplice>, proxy_type: Auction, .. }` on behalf of the real account passes both the `is_superset(Auction)==true` guard (so the special-case denial in `do_proxy` does not trigger) and the fallback `NonTransfer.filter(Proxy::add_proxy)==true` check. The new `Auction` proxy entry is persisted for the delegator. The delegate (or accomplice) can then call `Proxy::proxy(real, Some(Auction), Registrar::swap{ .. })`, which `Auction`'s filter admits unconditionally, dispatching `paras_registrar::swap` from the victim's origin — a call class the victim's original `NonTransfer` grant explicitly intended to deny (per the inline "Specifically omitting Registrar `swap`" comment, and consistent with the fix rationale already applied for the identical class of bug on Asset Hub Westend, see `prdoc/pr_12769.prdoc`).

The identical pattern (same `NonTransfer` filter denies `Registrar::swap`, same `Auction` filter admits `Registrar(..)` in full, same `(NonTransfer, _) => true` superset) also exists in `polkadot/runtime/rococo/src/lib.rs` [7](#0-6)  and in the staging relay-chain runtime used by `staking-async` [8](#0-7) .

### Impact Explanation
A user who grants only a `NonTransfer` proxy — intending to withhold `paras_registrar::swap` (a manager-privileged operation that changes a parachain/parathread's registrar slot association, tracked in the runtime as an explicitly denied high-sensitivity capability distinct from ordinary balance transfers) — unknowingly grants the delegate the ability to self-escalate to a proxy type (`Auction`) whose filter admits that call unrestricted. This is an unauthorized-dispatch / privilege-escalation bug: the delegate obtains capabilities the delegator's on-chain grant was specifically designed to exclude, using only a signed extrinsic with no privileged role, matching the CVE-2019-20889 root cause (a permission check for issuing a broader-scoped credential/token that fails to validate the requested scope against the caller's actual privileges).

### Likelihood Explanation
No privileged role, governance action, or off-chain trust is required — any account that has been delegated a `NonTransfer` proxy (an extremely common, "safe-looking" grant used for governance/voting proxies) can trigger it with two ordinary signed extrinsics (`Proxy::proxy(..., add_proxy(Auction))` then `Proxy::proxy(..., Registrar::swap)`), paying only standard transaction fees. This mirrors exactly the bug class already confirmed and fixed for `NonTransfer`/`Governance` on Asset Hub Westend, which strongly indicates the underlying lattice-consistency invariant (`is_superset` must never claim more than `filter` admits) was not audited across all runtimes sharing this `ProxyType` design.

### Recommendation
Apply the same fix pattern used in `prdoc/pr_12769.prdoc`/`prdoc/pr_12771.prdoc`: either (a) remove the blanket `(ProxyType::NonTransfer, _) => true` superset claim on Westend/Rococo/staging-RC and replace it with an explicit, filter-consistent list of subsets (as was done for `asset_hub_westend_runtime::ProxyType::is_superset`), or (b) add `paras_registrar::swap` to the `NonTransfer` allow-list only if it is truly safe, or (c) restrict `Auction`'s filter to the same call subset `NonTransfer` intends to allow (`register`/`deregister`/`reserve`) instead of the full `Registrar(..)` pallet match. Add a lattice-consistency regression test analogous to `proxy_type_superset_relation_matches_call_filters` (already present for asset-hub-westend) to every runtime defining `ProxyType`, so this class cannot silently reappear.

### Proof of Concept
Reproduction sketch (logic verified by source review of `do_proxy`, `is_superset`, and both filters; not executed against a live network or compiled test harness due to current read-only tooling — this should be validated with an integration test before filing):

```rust
// Runtime: polkadot/runtime/westend/src/lib.rs (or rococo)
// 1. Victim grants Alice a NonTransfer proxy.
Proxy::add_proxy(RuntimeOrigin::signed(VICTIM), ALICE, ProxyType::NonTransfer, 0);

// 2. Alice, using only her NonTransfer proxy, adds herself an Auction proxy for VICTIM.
// Passes because ProxyType::NonTransfer::is_superset(&ProxyType::Auction) == true,
// and NonTransfer::filter(RuntimeCall::Proxy(add_proxy{..})) == true (Proxy(..) unrestricted).
Proxy::proxy(
    RuntimeOrigin::signed(ALICE),
    VICTIM,
    None,
    Box::new(RuntimeCall::Proxy(pallet_proxy::Call::add_proxy {
        delegate: ALICE,
        proxy_type: ProxyType::Auction,
        delay: 0,
    })),
);

// 3. Alice now dispatches Registrar::swap on behalf of VICTIM via the Auction proxy,
// a call NonTransfer explicitly denies ("Specifically omitting Registrar `swap`") but
// Auction's filter admits unrestricted (`RuntimeCall::Registrar(..)`).
Proxy::proxy(
    RuntimeOrigin::signed(ALICE),
    VICTIM,
    Some(ProxyType::Auction),
    Box::new(RuntimeCall::Registrar(paras_registrar::Call::swap { id: PARA_A, other: PARA_B })),
);
// Expected: rejected as CallFiltered under NonTransfer's intended policy.
// Actual (per source-level trace): dispatched successfully as VICTIM's origin.
```

Guards checked and found insufficient: `do_proxy`'s `is_superset` special-case for `add_proxy`/`remove_proxy` [2](#0-1) ; `ProxyType::is_superset` on Westend [4](#0-3) ; `ProxyType::filter` for `NonTransfer` and `Auction` on Westend [9](#0-8) .

Uncertainty: I was unable to run this as an executed integration test (only read-only source access), and I could not independently confirm the precise semantics/impact of `paras_registrar::swap` beyond what its usage/comments imply — a background Devin session with repo/test execution access would be needed to compile the reproduction, confirm `swap`'s exact effects, and confirm whether Rococo is still an actively bountied network (Rococo has reportedly been sunset; Westend remains live, so the Westend instance is the primary basis for eligibility).

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});
