### Title
Webhook signature is verified against an attacker-chosen organization while the write target is a different, unrelated repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App / secret to check the HMAC against using `repository_owner`, a field read straight from the untrusted JSON payload (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). The actual state-changing target of the event, however, is resolved independently by each `Shipit::Webhooks::Handlers::Handler` using `payload.dig('repository','full_name')`. Nothing ties these two payload fields together, so the "organization whose secret authenticated the request" and the "repository that gets written to" can be made to diverge.

### Finding Description
`verify_signature` picks the `GitHubApp` instance to validate against based on attacker-controlled JSON: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` unconditionally returns `true` (i.e. skips verification entirely) whenever that organization's `webhook_secret` is blank: [3](#0-2) 

Once `verify_signature` passes, `WebhooksController#create` dispatches the raw parsed payload to handlers: [4](#0-3) 

Every handler resolves the target `Repository`/`Stack` from a *different* payload field, `repository.full_name`, completely independent of the `owner.login`/`organization.login` value used for signature selection: [5](#0-4) 

For example, `PushHandler` triggers a GitHub sync (which updates commits and can drive continuous deployment) purely off `stacks` (resolved via `full_name`) and `params.after`: [6](#0-5) 

`StatusHandler` writes CI status records looked up only by commit `sha`, with no repository/owner check at all: [7](#0-6) 

The equality that the engine implicitly relies on but never enforces is:
`organization authenticated by verify_signature (payload.repository.owner.login)` == `repository/stack actually written to by the handler (payload.repository.full_name)`

Because the raw request body is only checked against the secret belonging to whichever organization the attacker names in `repository.owner.login`/`organization.login`, an attacker who can get *any* onboarded organization configured with a blank `webhook_secret` (a legitimate, easy-to-make misconfiguration — the shipped test fixtures even demonstrate this exact configuration, `webhook_secret: # nil`) can craft a payload whose `owner.login`/`organization.login` names that unsecured org (so `verify_webhook_signature` short-circuits to `true`) while `repository.full_name` names a completely different, secured victim repository elsewhere in the same Shipit instance: [8](#0-7) 

This breaks the intended per-organization authentication boundary: signature verification is meant to prove "this request truly comes from GitHub for organization X", but the code never confirms that the repository being mutated (`full_name`) belongs to organization X.

### Impact Explanation
An attacker can inject forged, unauthenticated GitHub webhook events (`push`, `status`, `pull_request` label/merge/close events, etc.) that act on any repository/stack in a multi-organization Shipit deployment, as long as one configured GitHub App organization has no `webhook_secret` set. Depending on handler, this can trigger `sync_github`, alter CI `Status` records used to gate deploy safety checks, or archive/unarchive review stacks and mutate `PullRequest` records for a repository the attacker does not own — an authorization bypass across the organization boundary that the webhook signature is supposed to enforce.

### Likelihood Explanation
Requires the operator to have at least one onboarded GitHub App organization with a blank `webhook_secret`, which is an easily-made and not-uncommon misconfiguration (illustrated by the shipped fixture `test/dummy/config/secrets_double_github_app.yml`). Given such a configuration exists anywhere in the deployment, forging the payload requires no privileged credentials, GitHub token, or repository access — only knowledge of the target repository's `full_name`, which is public information for public repos.

### Recommendation
Do not select the verification secret from an unauthenticated field that is disjoint from the field used to determine the write target. Either verify against a single, deployment-wide secret validated before any payload field is trusted, or after successful signature verification, re-derive and cross-check that the resolved `repository.full_name`'s owner matches the `repository_owner`/`organization` that authenticated the signature. Additionally, `verify_webhook_signature` should not silently pass when `webhook_secret` is blank — it should fail closed (reject the webhook) unless webhook verification is explicitly and globally disabled by configuration.

### Proof of Concept
1. Deployment has two GitHub App organizations configured: `victim-org` (with `webhook_secret` set) owning a Shipit stack for `victim-org/victim-repo`, and `unsecured-org` (onboarded with `webhook_secret` left blank).
2. Attacker sends `POST /webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "unsecured-org" }
  }
}
```
3. `WebhooksController#repository_owner` returns `"unsecured-org"`; `Shipit.github(organization: "unsecured-org")` resolves the app config with blank `webhook_secret`, so `verify_webhook_signature` returns `true` unconditionally — no valid `X-Hub-Signature` is even required.
4. `PushHandler` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` and enqueues `sync_github(expected_head_sha: "<attacker-chosen-sha>")` against the victim stack, entirely bypassing the signature check meant to gate that repository's events.

```ruby
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
```
