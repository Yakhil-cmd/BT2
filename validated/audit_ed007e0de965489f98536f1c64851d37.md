### Title
Permanent KLAY Lock in Source Bridge When Destination Contract Rejects KLAY — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

### Summary
When a user bridges KLAY to a contract address whose fallback reverts, the KLAY is permanently locked in the source bridge. The Value Transfer Recovery (VTR) system retries indefinitely but can never succeed, and no refund or cancellation path exists for the user.

### Finding Description

`handleKLAYTransfer` in `BridgeTransferKLAY.sol` executes in this order after operator votes reach threshold:

1. State writes: `_setHandledRequestTxHash`, `handleNoncesToBlockNums[_requestedNonce]`, `_updateHandleNonce`
2. Event emission: `emit HandleValueTransfer(...)`
3. KLAY transfer: `(bool ok, ) = _to.call.value(_value)("")`
4. Hard require: `require(ok, "handleKLAYTransfer: transfer failed")` [1](#0-0) 

If `_to` is a contract whose fallback reverts, step 3 fails and the EVM reverts the entire transaction — including all state writes in step 1. The nonce is never marked handled. The source-chain bridge permanently holds the KLAY deposited by `_requestKLAYTransfer`, which only emits a `RequestValueTransfer` event and increments `requestNonce` without any rollback path. [2](#0-1) 

The VTR system (`valueTransferRecovery`) detects the gap between `requestNonce` and `lowerHandleNonce` and re-submits the pending event via `recoverPendingEvents` → `AddRequestValueTransferEvents`. Since the root cause (rejecting `_to`) is unchanged, every retry reverts identically. [3](#0-2) 

A secondary effect: `_updateHandleNonce` advances `lowerHandleNonce` only through a consecutive run of handled nonces starting from `lowerHandleNonce`. A permanently unhandled nonce N prevents `lowerHandleNonce` from ever passing N, so `recoveryBlockNumber` is frozen at the block before N. The VTR must re-scan from that early block on every recovery interval, degrading efficiency for all subsequent transfers. [4](#0-3) 

There is no `cancelTransfer`, `refundTransfer`, or skip-and-refund function anywhere in the bridge contract hierarchy. The `BridgeFee._payKLAYFeeAndRefundChange` only refunds excess fee at request time, not the principal on handle failure. [5](#0-4) 

### Impact Explanation
The user's KLAY is permanently locked in the source bridge contract with no on-chain recovery path. The exact corrupted value is `msg.value - feeLimit` (the bridged principal) held by the source `BridgeTransferKLAY` contract forever. This is an unauthorized permanent loss of KAIA from the user's perspective with no operator-accessible remedy short of a contract upgrade.

### Likelihood Explanation
Any unprivileged user can trigger this by calling `requestKLAYTransfer` (or the payable fallback) with `_to` set to any contract that lacks a payable fallback or explicitly reverts on KLAY receipt. This includes: contracts deployed without `receive()`/`payable fallback`, proxy contracts whose implementation reverts, or contracts that conditionally reject KLAY. No special privilege is required.

### Recommendation
Two complementary fixes:

1. **Try-and-skip on the handle side**: Wrap the `_to.call.value(_value)("")` in a try/catch (or check-and-continue) pattern. If the transfer fails, mark the nonce as handled anyway and emit a `HandleValueTransferFailed` event so the source chain can issue a refund.

2. **Refund path on the source side**: Add a `cancelTransfer(uint64 requestNonce)` function (owner/operator-gated) that, given proof that the handle permanently failed, returns the locked KLAY to the original `from` address and clears the pending request.

### Proof of Concept

```solidity
// RejectKLAY: a contract whose fallback always reverts
contract RejectKLAY {
    fallback() external payable { revert("no KLAY"); }
}
```

1. Deploy `RejectKLAY` at address `R` on the destination chain.
2. User calls `sourceBridge.requestKLAYTransfer{value: 1 ether + fee}(R, 1 ether, "")`.
   - Source bridge receives 1 ether; emits `RequestValueTransfer(KLAY, user, R, 0, 1e18, nonce, fee, "")`.
   - `requestNonce` increments; KLAY is now held by source bridge.
3. Operators observe the event and call `destBridge.handleKLAYTransfer(txHash, user, R, 1e18, nonce, blockNum, "")`.
   - Votes reach threshold; state writes execute.
   - `R.call{value: 1e18}("")` → `RejectKLAY.fallback()` reverts.
   - `require(ok, "handleKLAYTransfer: transfer failed")` causes full revert.
   - All state writes (nonce, tx hash, handle nonce) are rolled back.
4. VTR detects `requestNonce > lowerHandleNonce`, re-queues the event, operators retry → same revert.
5. 1 ether is permanently locked in source bridge. `lowerHandleNonce` never advances past `nonce - 1`. No user-accessible refund exists. [6](#0-5) [7](#0-6)

// recoverPendingEvents recovers all pending events by resending them.
func (vtr *valueTransferRecovery) recoverPendingEvents() error {
	defer func() {
		vtr.childEvents = []IRequestValueTransferEvent{}
		vtr.parentEvents = []IRequestValueTransferEvent{}
	}()

	if len(vtr.childEvents) > 0 {
		logger.Warn("VT Recovery : Child -> Parent Chain", "cBridge", vtr.cBridgeInfo.address.String(), "events", len(vtr.childEvents))
	}

	vtRequestEventMeter.Mark(int64(len(vtr.childEvents)))
	vtRecoveredRequestEventMeter.Mark(int64(len(vtr.childEvents)))

	events := make([]IRequestValueTransferEvent, len(vtr.childEvents))
	for i, event := range vtr.childEvents {
		events[i] = event
	}
	vtr.pBridgeInfo.AddRequestValueTransferEvents(events)

	if len(vtr.parentEvents) > 0 {
		logger.Warn("VT Recovery : Parent -> Child Chain", "pBridge", vtr.pBridgeInfo.address.String(), "events", len(vtr.parentEvents))
	}

	vtHandleEventMeter.Mark(int64(len(vtr.parentEvents)))
	events = make([]IRequestValueTransferEvent, len(vtr.parentEvents))
	for i, event := range vtr.parentEvents {
		events[i] = event
	}
	vtr.cBridgeInfo.AddRequestValueTransferEvents(events)

	return nil

    function _updateHandleNonce(uint64 _requestedNonce) internal {
        if (_requestedNonce > upperHandleNonce) {
            upperHandleNonce = _requestedNonce;
        }

        uint64 limit = lowerHandleNonce + 200;
        if (limit > upperHandleNonce) {
            limit = upperHandleNonce;
        }

        uint64 i;
        for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
            recoveryBlockNumber = handleNoncesToBlockNums[i];
            delete handleNoncesToBlockNums[i];
            delete closedValueTransferVotes[i];
        }
        lowerHandleNonce = i;
    }

    function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }
