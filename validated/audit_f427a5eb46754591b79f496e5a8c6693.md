### Title
Whale debt value can overflow before index cap and permanently freeze a market - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
`accrue_step` converts the entire scaled debt and supply balances back to RAY values before applying the borrow-index cap. For a sufficiently large 18-decimal market, sustained high utilization can grow the borrow index enough that `borrowed * borrow_index` exceeds `i128::MAX` while the index remains below `MAX_BORROW_INDEX_RAY`. Because every market mutation performs accrual first, the resulting `MathOverflow` permanently blocks withdrawal, repayment, liquidation, bad-debt cleanup, recapitalization, and further index updates for that market.

### Finding Description
The permissionless `Controller::update_indexes(caller, assets)` path calls `pool_update_indexes_call`, which invokes pool `update_indexes`; the pool loads each market and calls `interest::global_sync`. [1](#0-0) [2](#0-1) 

`global_sync` splits elapsed time into bounded chunks and calls `accrue_chunk`; `accrue_chunk` delegates the arithmetic to `accrue_step`. [3](#0-2) 

Inside `accrue_step`, utilization is calculated by first evaluating `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`. `scaled_to_original` is a non-saturating `Ray::mul`, so it panics on overflow. [4](#0-3) [5](#0-4) 

Only after those conversions does the code call `update_borrow_index`; that function caps the index at `MAX_BORROW_INDEX_RAY`, but the cap cannot protect the earlier total-value multiplication. [6](#0-5) [7](#0-6) 

The repository's regression test demonstrates the exact failure: an 18-decimal market holding one billion whole tokens and approximately 98% utilization eventually returns `MathOverflow` from `update_indexes`, while the stored borrow index is still below `MAX_BORROW_INDEX_RAY`; subsequent withdrawal and repayment calls fail for the same reason. [8](#0-7) 

### Impact Explanation
This is a permanent market freeze. Once the scaled debt's RAY valuation crosses the `i128` ceiling, every path that performs `global_sync` hits the overflow before it can mutate the market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce the debt, and governance cannot cleanly recover through a path that accrues the market.

The resulting exposure is larger than the attacker's own position: all user funds in the same `(hub_id, asset)` market are frozen, including unrelated suppliers' deposits. The borrower also cannot repay, so the pool cannot restore normal operation through the accepted permissionless remediation paths. The repository test explicitly verifies that both withdrawal and repayment revert after the cliff is reached. [9](#0-8) 

### Likelihood Explanation
Likelihood is market- and scale-dependent rather than universally reachable. An unprivileged caller cannot choose the rate model or listing caps, but on an active market with a high-decimal asset, permissive caps, and a sufficiently steep curve, the caller can:

1. Supply the debt asset directly or through `Controller::supply`.
2. Supply sufficient collateral in another listed market.
3. Call `Controller::borrow` to place the debt market near its maximum utilization.
4. Leave the debt outstanding while the borrow index compounds.
5. Call permissionless `Controller::update_indexes` with `assets = [HubAssetKey { hub_id, asset }]` once the RAY debt value exceeds `i128::MAX`.

The test uses one billion 18-decimal tokens, approximately 98% utilization, and a 175% maximum-rate stress curve, then reaches the overflow before the index cap. [10](#0-9) 

The large capital requirement and dependence on configured parameters reduce practical likelihood, but no privileged action is required once such a market exists.

### Recommendation
Enforce a protocol-level bound on the scaled-position/index product before evaluating utilization and interest. Specifically:

- Compute `borrowed * borrow_index` and `supplied * supply_index` with checked or saturating helpers that cannot trap.
- Reject or cap market states whose total RAY value can exceed the arithmetic domain before increasing the index.
- Enforce market-level scaled supply/borrow caps based on `i128::MAX / max_supported_index`, rather than caps based only on current index and asset decimals.
- Consider a wider intermediate type or saturating fixed-point multiplication for aggregate utilization and interest calculations.
- Apply the same bound before `calculate_supplier_rewards`, which separately multiplies `borrowed` by both the old and new indexes. [11](#0-10) 

The fix must preserve the intended index ceiling and prevent the state from entering a range where no subsequent operation can reduce the balance.

- `update_indexes` returns shared error `MathOverflow`.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
