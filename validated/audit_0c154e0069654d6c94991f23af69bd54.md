### Title
Goroutine/listener leak in `connect()` due to unnamed-return `err` never propagating to the cancel-guard, leaving `pfctx` uncancelled on timeout - ([File: internal/codespaces/rpc/invoker.go])

### Summary
`connect()` creates a cancelable `connectctx`/`pfctx` and defers `cancel()` only `if err != nil`, but `err` is the plain local variable declared at `listener, err := listenTCP()` — it is never assigned by the `return nil, ctx.Err()` / `return nil, err` statements since the function has no named return values. When the `ctx.Done()` branch fires (e.g., after the 5s `ConnectionTimeout`), the local `err` remains `nil`, so `cancel()` is skipped and the still-running `fwd.ForwardPortToListener(pfctx, ...)` goroutine and its listener are never cancelled or reclaimed. Because `CreateInvoker` returned an error in this case, the caller never receives an `invoker` to call `Close()` on, so nothing else can ever cancel `pfctx`.

### Finding Description
In `connect()` [2](#0-1) , a `connectctx`/`pfcancel` pair is created independently of the caller-supplied `ctx`:
```go
connectctx, cancel := context.WithCancel(context.Background())
defer func() {
    if err != nil {
        cancel()
    }
}()
...
pfctx, pfcancel := context.WithCancel(connectctx)
invoker.cancelPF = pfcancel

go func() {
    ch <- fwd.ForwardPortToListener(pfctx, opts, listener)
}()

go func() {
    conn, err = grpc.NewClient(localAddress, opts...)
    ch <- err
}()

select {
case <-ctx.Done():
    return nil, ctx.Err()
case err := <-ch:
    ...
}
```
`err` here is the outer function's local variable from `listener, err := listenTCP()` (line 78), captured by both the deferred closure and the `grpc.NewClient` goroutine. The `return nil, ctx.Err()` on the `ctx.Done()` branch is a **plain return of a new value**, not an assignment to the outer `err`, because `connect` has no named return parameters [3](#0-2) . Consequently, when the caller-supplied `ctx` (bounded by `ConnectionTimeout = 5 * time.Second` in `CreateInvoker`) expires before the port-forwarding goroutine calls back, `connect()` returns via the `ctx.Done()` branch while the local `err` is still `nil` from the earlier successful `listenTCP()` call. The deferred `if err != nil { cancel() }` therefore does not fire, `connectctx`/`pfctx` are never cancelled, and the goroutine running `fwd.ForwardPortToListener(pfctx, opts, listener)` [4](#0-3)  keeps running indefinitely along with the open `listener`. Because `CreateInvoker` returns an error in this path [5](#0-4) , no `invoker` object is ever exposed to callers, so `invoker.Close()` (which would call `cancelPF()`) is never invoked either — the leak is unrecoverable within that process's lifetime.

An attacker who controls the internal codespace (e.g., a devcontainer/codespace whose internal RPC server at port `16634` intentionally never becomes reachable/forwarded) can force every `gh codespace` invocation that calls `CreateInvoker` (`ssh`, `logs`, `jupyter`, post-create polling, etc.) to hit this exact timeout path, leaking a goroutine + open TCP listener each time.

### Impact Explanation
Each triggered timeout leaks one goroutine (running `ForwardPortToListener`) plus its listener/socket resource on the victim's machine, and this accumulates without bound across repeated invocations of `gh codespace ssh`/`logs`/`jupyter` against the attacker's codespace, matching the unbounded local resource-consumption / DoS class described.

### Likelihood Explanation
Trivial to trigger: the attacker only needs to control (or delay) the codespace-side listener on internal port 16634 so it never accepts the forwarded connection within 5 seconds, which is fully within the "victim runs `gh codespace` command against attacker-controlled codespace" threat model, and is deterministically repeatable on every invocation.

### Recommendation
Use named return values (or an explicit local error flag) in `connect()` so the deferred cleanup reliably observes the function's actual outcome, e.g. change the signature to `func connect(ctx context.Context, fwd portforwarder.PortForwarder) (_ Invoker, err error)` and ensure every `return` sets `err`, so `cancel()` (and thus `pfcancel`) always fires when `connect` fails, including on the `ctx.Done()` path. Additionally consider deriving `connectctx` from the caller's `ctx` rather than `context.Background()`.

### Proof of Concept
Using the existing stub `test.PortForwarder` [6](#0-5)  whose `ForwardPortToListener` blocks on `<-ctx.Done()`:
```go
func TestConnectLeaksGoroutineOnTimeout(t *testing.T) {
    before := runtime.NumGoroutine()
    for i := 0; i < 5; i++ {
        ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
        _, err := rpc.CreateInvoker(ctx, blockingStubForwarder{}) // never connects to port 16634
        cancel()
        require.Error(t, err) // ctx.Done() branch taken
    }
    time.Sleep(200 * time.Millisecond)
    after := runtime.NumGoroutine()
    // Expect growth roughly proportional to iterations because pfctx is never cancelled.
    require.Greater(t, after, before+3)
}
```
Assert that `runtime.NumGoroutine()` grows monotonically with each failed `CreateInvoker` call and does not return to baseline, confirming the leaked `ForwardPortToListener` goroutines/listeners are never cancelled.

func connect(ctx context.Context, fwd portforwarder.PortForwarder) (Invoker, error) {
	listener, err := listenTCP()
	if err != nil {
		return nil, err
	}
	localAddress := listener.Addr().String()

	invoker := &invoker{
		fwd:      fwd,
		listener: listener,
	}

	// Create a cancelable context to be able to cancel background tasks
	// if we encounter an error while connecting to the gRPC server
	connectctx, cancel := context.WithCancel(context.Background())
	defer func() {
		if err != nil {
			cancel()
		}
	}()

	ch := make(chan error, 2) // Buffered channel to ensure we don't block on the goroutine

	// Ensure we close the port forwarder if we encounter an error
	// or once the gRPC connection is closed. pfcancel is retained
	// to close the PF whenever we close the gRPC connection.
	pfctx, pfcancel := context.WithCancel(connectctx)
	invoker.cancelPF = pfcancel

	// Tunnel the remote gRPC server port to the local port
	go func() {
		// Start forwarding the port locally
		opts := portforwarder.ForwardPortOpts{
			Port:     codespacesInternalPort,
			Internal: true,
		}
		ch <- fwd.ForwardPortToListener(pfctx, opts, listener)
	}()

	var conn *grpc.ClientConn
	go func() {
		// Attempt to connect to the port
		opts := []grpc.DialOption{
			grpc.WithTransportCredentials(insecure.NewCredentials()),
		}
		conn, err = grpc.NewClient(localAddress, opts...)
		ch <- err // nil if we successfully connected
	}()

	// Wait for the connection to be established or for the context to be cancelled
	select {
	case <-ctx.Done():
		return nil, ctx.Err()
	case err := <-ch:
		if err != nil {
			return nil, err
		}
	}

	invoker.conn = conn
	invoker.jupyterClient = jupyter.NewJupyterServerHostClient(conn)
	invoker.codespaceClient = codespace.NewCodespaceHostClient(conn)
	invoker.sshClient = ssh.NewSshServerHostClient(conn)

	// Send initial connection heartbeat (no need to throw if we fail to get a response from the server)
	_ = invoker.notifyCodespaceOfClientActivity(ctx, connectedEventName)

	// Start the activity heartbeats
	go invoker.heartbeat(pfctx, 1*time.Minute)

	return invoker, nil
}

func (PortForwarder) ForwardPortToListener(ctx context.Context, opts portforwarder.ForwardPortOpts, listener *net.TCPListener) error {
	// Start forwarding the port locally
	hostConn, err := net.Dial("tcp", fmt.Sprintf("127.0.0.1:%d", opts.Port))
	if err != nil {
		return err
	}

	// Accept the connection from the listener
	listenerConn, err := listener.Accept()
	if err != nil {
		return err
	}

	// Copy data between the two connections
	go func() {
		_, _ = io.Copy(hostConn, listenerConn)
		hostConn.Close()
	}()
	go func() {
		_, _ = io.Copy(listenerConn, hostConn)
		listenerConn.Close()
	}()

	// ForwardPortToListener typically blocks until the context is cancelled so we need to do the same
	<-ctx.Done()

	return nil
}
