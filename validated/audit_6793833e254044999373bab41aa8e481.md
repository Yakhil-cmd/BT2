### Title
Permanent market freeze via i128 value overflow in interest accrual - (File: contracts/pool/src/interest.rs)

### Summary
The Rocket.Chat report is a CWE-400 denial of service: a reachable input pushes a shared component past a numeric limit and every subsequent request crashes. The analog in XOXNO Lending is the RAY value ceiling in accrual. Every pool entrypoint runs `interest::global_sync` first, which grows `borrow_index`/`supply_index` by compounding. When the unscaled token value of the market's scaled share totals approaches `i128::MAX`, the next `scaled_to_original` unscale inside `accrue_step`/utilization calculation overflows and panics with `MathOverflow` (33). From that ledger time onward **every** verb on that market — `supply`, `borrow`, `withdraw`, `repay`, `net_settle`, `seize_positions`, `flash_loan`, `claim_revenue`, and controller-level `liquidate`/`clean_bad_debt`/`recapitalize` that route through the same accrual — reverts before mutating state. The market is permanently frozen: suppliers cannot exit, borrowers cannot repay, liquidators cannot liquidate.

### Finding Description
`global_sync` accrues unconditionally before any mutation and is a pure function of `last_timestamp` and stored scaled totals; there is no cap that engages before the value ceiling, no catch of the overflow, and no escape hatch that skips accrual [1](#0-0) . Each chunk calls `accrue_step` and commits the new indexes [2](#0-1) . The unscale path multiplies scaled RAY shares by the index [3](#0-2) . The integration test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the cliff concretely: with ~1e9 whole tokens at 18 decimals and ~98% utilization on the XLM curve, `update_indexes` starts failing with `MATH_OVERFLOW` within ~40 simulated years while `borrow_index < MAX_BORROW_INDEX_RAY` (the index cap never engages), and subsequent `withdraw` and `repay` calls fail with the same panic — proving the freeze covers exits and repayments [4](#0-3) . The pool's own README confirms every market entrypoint accrues first and panics with `MathOverflow` on checked-arithmetic overflow [5](#0-4) .

### Impact Explanation
Permanent freezing of funds. Once the market's unscaled value crosses the ceiling, no entrypoint can complete because accrual panics before any guard or mutation runs. All supplier claims, borrower collateral backing, and pending revenue in that `(hub, asset)` book are locked forever — `upgrade`-independent, and not reversible by `clean_bad_debt` or `recapitalize` since those also accrue. This matches the accepted impact class "permanent freezing of funds" / "contract unable to operate".

### Likelihood Explanation
Low-to-moderate. An unprivileged attacker cannot trigger it instantly; it requires a whale-scale market (on the order of 10^9 whole tokens at high decimals, i.e. scaled totals near `i128::MAX / 170`) sustained at very high utilization on a steep rate curve for years of compounding — or a listing with extreme decimals/supply where the ceiling is closer. It is, however, reachable purely through `supply` + `borrow` and the passage of ledger time, requires no privilege, and the cliff is a hard wall with no recovery path once crossed. The protocol partially acknowledges this domain (`MAX_BORROW_INDEX_RAY`, chunking, the dedicated cliff test), but the index cap demonstrably does not protect the value-overflow path. Capital cost and time requirement place this at Medium.

### Recommendation
- Engage the borrow/supply index cap (`MAX_BORROW_INDEX_RAY`) — or a value-based cap — *before* the unscale that can overflow, e.g. clamp inside `accrue_step` when `scaled * index` approaches `i128::MAX`, so accrual saturates instead of panicking.
- Alternatively, make `global_sync` best-effort at the ceiling: freeze `borrow_index` at the cap and set `last_timestamp = now`, so `withdraw`/`repay`/`seize_positions`/`recapitalize` remain executable and users can exit (accepting stopped interest accrual rather than frozen funds).
- Add a regression check that the cap engages before `scaled_to_original` overflows for every permitted `asset_decimals` in 3..=18 and every `InterestRateModel::verify`-accepted curve.

### Proof of Concept
Existing test reproduces it end-to-end: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs::a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [6](#0-5) .

Conceptual reproduction against a fresh market:
1. `create_market(hub, params)` with `asset_decimals = 18` and the steep XLM rate curve; disable/lift `max_utilization` and caps via ordinary supply.
2. `supply(BOB, BIG18, 1e9 * 10^18)`; `borrow(ALICE, BIG18, 0.98 * principal)` after seeding collateral.
3. Advance ledger time. Repeatedly call `update_indexes` (unprivileged).
4. Once `supplied_scaled * supply_index ≈ i128::MAX`, `accrue_step` → `scaled_to_original` panics `MathOverflow` inside `global_sync`.
5. `withdraw`, `repay`, `borrow`, `seize_positions`, `claim_revenue`, `recapitalize` all panic identically — permanent freeze confirmed by the test's `try_withdraw_raw`/`try_repay` assertions at lines 355–356.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
