### Title
Webhook signature verification is bound to `repository.owner.login`, not to the `repository.full_name` that handlers act on, allowing cross-org webhook forgery when any configured GitHub org lacks a `webhook_secret` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks the GitHub App/org whose secret is used to validate `X-Hub-Signature` based on `repository.owner.login` (or `organization.login`) taken directly from the unauthenticated request body. `GitHubApp#verify_webhook_signature` treats a blank/unconfigured `webhook_secret` as "nothing to verify" and returns `true` unconditionally. Handlers, however, resolve the target `Repository`/`Stack` using a *different* field of the same payload, `repository.full_name` (via `Handler#repository_name`). Nothing binds "the org whose secret authenticated this payload" to "the repository the handler will mutate." This mirrors the reported bug class: a zero/absent value (`webhook_secret` unset) is treated as "no check needed" instead of being treated as "still must satisfy the invariant," breaking the equality that should hold: `organization authenticated == owner of repository written`.

### Finding Description
- `verify_signature` selects the app config from attacker-controlled payload data: [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever `webhook_secret` is blank for the resolved org, i.e. it treats "no secret configured" the same way the Solidity bug treated `start == 0`: as "nothing to check" rather than "must still validate": [3](#0-2) 
- The secret is only loaded if present (`.presence`), so an org entry with `webhook_secret:` left blank in `secrets.yml` (a documented, supported configuration - see the `OrgTwo` example) ends up with `webhook_secret == nil`, permanently bypassing signature verification for that org: [4](#0-3) [5](#0-4) 
- Once `create` proceeds, the actual target of the mutation is decided independently, from `repository.full_name`, not from `repository.owner.login`: [6](#0-5) [7](#0-6) 
- `PushHandler` then triggers `stack.sync_github(...)` for every non-archived stack on that resolved repository/branch: [8](#0-7) 

Because `repository.owner.login` (used to pick the verifying secret) and `repository.full_name` (used to pick the mutated repository/stack) are two independent JSON fields with no cross-check, an attacker can submit a payload where these fields disagree: `repository.owner.login` names a configured-but-secret-less org (so verification is skipped entirely, no secret knowledge required), while `repository.full_name` names an arbitrary, properly-configured victim repository whose stacks then get processed as if the request were a legitimate authenticated GitHub delivery.

### Impact Explanation
This breaks the binding "the organization that authenticated the request == the repository being written to." An unprivileged, unauthenticated network attacker who knows only that a Shipit deployment has multiple GitHub orgs configured (a documented multi-org feature) and that one of them has no `webhook_secret` set, can forge arbitrary webhook events (`push`, `pull_request`, `status`, `check_suite`, `membership`) against any stack backed by any other, fully-secured org/repository, with zero knowledge of that org's real `webhook_secret`. For `push`, this drives `Stack#sync_github`, which can advance the deployed commit pointer and, combined with continuous deployment, trigger unauthorized deploys/rollbacks - a cross-repository write reachable without any credential, matching the Critical impact bar (unauthorized deploy / cross-repository writes).

### Likelihood Explanation
Likelihood is moderate-to-high in any installation using the documented multi-org GitHub configuration where at least one org intentionally or accidentally omits `webhook_secret` (the shipped example config explicitly shows `webhook_secret: # nil` as an acceptable value, and the engine ships a test fixture demonstrating two independently configured orgs). No credentials, tokens, or repository access are required - only knowledge that such an org name exists and is registered in `Shipit.github`.

### Recommendation
Do not allow "no secret configured" to mean "signature always valid." At minimum:
1. Require every configured GitHub org/app entry to declare a non-blank `webhook_secret`, and fail closed (reject/`422`) when it is missing, mirroring the Solidity fix of checking the substantive invariant (a real secret) rather than a value that can default to absent.
2. Bind repository resolution to the same identity used for verification: cross-check that `repository.owner.login` (or `organization.login`) used to select the verifying app matches the owner portion of `repository.full_name` that handlers act on, rejecting mismatches before dispatching to handlers.

### Proof of Concept
Preconditions: Shipit deployed with two GitHub orgs configured (as in `test/dummy/config/secrets_double_github_app.yml`), e.g. `OrgOne` (has `webhook_secret`) and `OrgTwo` (`webhook_secret` left blank), and a real `Stack` exists for repository `OrgOne/victim-repo` tracking branch `master`.

1. Attacker sends, with no signature header knowledge needed:
```
POST /github/webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything-or-empty

{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha already known to Shipit, e.g. a stale/older commit>",
  "repository": {
    "owner": { "login": "OrgTwo" },
    "full_name": "OrgOne/victim-repo"
  }
}
```
2. `verify_signature` resolves `repository_owner` = `"OrgTwo"`, loads `Shipit.github(organization: "OrgTwo")`, whose `webhook_secret` is `nil`; `verify_webhook_signature` returns `true` unconditionally, regardless of the (bogus) `X-Hub-Signature`.
3. `Webhooks.for_event('push')` dispatches to `PushHandler`, which resolves `Repository.from_github_repo_name("OrgOne/victim-repo")` and calls `sync_github(expected_head_sha: params.after)` on its stacks - a state change on `OrgOne`'s stack driven entirely by a request that never satisfied `OrgOne`'s signature check.       github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

        request.raw_post
      )

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
