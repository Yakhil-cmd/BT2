### Title
Baseline-preservation race between `consume_stop_state` and `restore_unreviewed_stop_state` lets unreviewed edits get silently absorbed into the next baseline - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`handle_stop_hook` clears `touched_paths` via `consume_stop_state` immediately, but only re-populates it via `restore_unreviewed_stop_state` after slow, blocking work (network reachability check / LLM HTTP call) completes and the Stop hook decides to bail out for a transient reason. During that window, `handle_user_prompt_submit` (UPS) for the next turn can run concurrently and observes an empty `touched_paths` list, so its "preserve baseline" guard does not trigger and it captures a fresh baseline that already includes the unreviewed dangerous edit.

### Finding Description
The Stop hook flow in `plugins/security-guidance/hooks/security_reminder_hook.py::handle_stop_hook` starts with: [1](#0-0) 
which atomically snapshots and **clears** `touched_paths` via `consume_stop_state` (`plugins/security-guidance/hooks/diffstate.py:74-113`) before any slow work happens. `snap_baseline` is saved for later restore purposes.

The hook then performs blocking, potentially slow operations — `ensure_anthropic_reachable()` and, further down, the Haiku LLM review call — before ever calling `restore_unreviewed_stop_state` on a transient-failure path: [2](#0-1) 
and [3](#0-2) 

`restore_unreviewed_stop_state` re-adds `touched_paths` and conditionally the old `baseline_sha` back into session state: [4](#0-3) 

The invariant that is supposed to protect the review set is enforced in `handle_user_prompt_submit`, which only preserves the old baseline (refusing to advance it past unreviewed edits) if `touched_paths` is **still non-empty** at the time UPS runs: [5](#0-4) 

Because Stop is documented as asyncRewake ("runs in the background after Claude's turn ends... The user can submit a new prompt before this hook finishes"), there is a window — between `consume_stop_state` clearing `touched_paths` and the later `restore_unreviewed_stop_state` call — during which `touched_paths` is empty on disk even though the Stop hook has not actually delivered a review verdict. If a new `UserPromptSubmit` (triggered by ordinary retry behavior after a partial/transient stop-hook failure, e.g. a flaky network check or slow Haiku call) lands in that window, `state.get("touched_paths")` is falsy, the preservation guard is skipped, and UPS calls `capture_git_baseline(cwd)` fresh — which is `git stash create` against the *current* working tree, i.e., it now includes the previously-unreviewed dangerous edit as part of the "old" baseline. Later, `compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py:353-439` diffs only against this new baseline, so the dangerous change — already folded into the baseline — never appears in `changed_since`/`review_set` again and is never sent to the LLM reviewer or flagged.

This directly violates the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": the touched-paths bookkeeping that is supposed to keep the baseline pinned behind unreviewed edits has a non-atomic clear/restore split, and ordinary retry timing (not any special git trickery) can land inside that gap.

### Impact Explanation
An edit that introduces a dangerous file change (e.g., a vulnerable file write) made during a turn whose Stop hook happens to hit a transient failure path can be permanently excluded from the security-guidance review pipeline if the next user turn starts before the restore executes. This is the "codebase shift baseline state so the dangerous change is treated as old and skipped" scenario the invariant is designed to prevent — an unauthorized change escapes the intended review/approval gate, which is the Claude Code bounty impact category of unauthorized file write/read bypassing the user-approved review scope (the LLM security review acting as the approval gate here).

### Likelihood Explanation
This does not require any special git manipulation, admin access, or malicious content — it requires only ordinary automation timing: a transient network hiccup or slow LLM call causing the Stop hook to take the `restore=True` skip path, combined with the next turn's `UserPromptSubmit` firing (which is normal, expected behavior in fast-follow-up or automated/CI-driven sessions, and explicitly acknowledged as a known race in the code's own comments about asyncRewake). The race window's size is bounded by the network-check/LLM-call latency, which is realistically on the order of seconds — enough for a fast subsequent prompt (human or scripted) to land in the gap. No privilege escalation is needed; it is a pure TOCTOU issue in state management.

### Recommendation
Make the touched-paths clear-and-eventual-restore atomic with respect to concurrent UPS reads: either (a) don't clear `touched_paths` in `consume_stop_state` until the Stop hook has a final verdict (success or genuine "no findings"), keeping a separate in-flight marker instead, or (b) have UPS's preservation check also consult a persisted "stop-in-flight" flag (set before `consume_stop_state` clears and cleared only after Stop reaches a terminal outcome) so it treats an in-flight Stop the same as unreviewed `touched_paths`, refusing to advance `baseline_sha` while a prior Stop's outcome is still pending.

### Proof of Concept
Integration/invariant test plan for `plugins/security-guidance/hooks/diffstate.py` and `security_reminder_hook.py`:
1. Set up a git repo, capture an initial baseline via `capture_git_baseline`, record it as `baseline_sha` and populate `touched_paths=["dangerous.py"]` in session state (simulating a PostToolUse-recorded edit).
2. Call `consume_stop_state(session_id)` directly (as `handle_stop_hook` does) and assert `touched_paths` is now empty in the on-disk state.
3. Before calling `restore_unreviewed_stop_state`, simulate the concurrent next-turn UPS by invoking `handle_user_prompt_submit`'s state-update logic (or the `_save` closure logic) against the same session — assert that because `touched_paths` is empty, `baseline_sha` gets overwritten to a fresh `capture_git_baseline(cwd)` that already includes the edit to `dangerous.py`.
4. Now call `restore_unreviewed_stop_state(session_id, ["dangerous.py"], old_baseline_sha)` (simulating the delayed transient-failure path) and observe that `baseline_sha` is NOT overwritten back (because `restore_unreviewed_stop_state` only sets baseline if `not state.get("baseline_sha")`, and UPS already set one).
5. Run `compute_v2_review_set(cwd, state["baseline_sha"], ...)` and assert `dangerous.py` is **absent** from the returned review set — demonstrating the dangerous edit is silently excluded from all future Stop-hook reviews, confirming the invariant violation.

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```
