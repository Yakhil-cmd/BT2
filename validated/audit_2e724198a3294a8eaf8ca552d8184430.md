### Title
Attacker-controlled route bytes inject arbitrary contract invocations under the caller's authorization tree, enabling wallet token theft - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
The zend-mail advisory (CWE-74) is argument injection: unsanitized caller input is spliced into a downstream invocation and interpreted as extra commands. The analog in XOXNO Lending is the user-supplied `swap: Bytes` route program. The controller forwards these opaque bytes to the swap router, which decodes them into a `StrategyPayload` and invokes the pool/token addresses the payload names — with no venue allowlist — inside the caller's authorized call tree. A crafted route can therefore "inject" an arbitrary contract call (analogous to an injected sendmail flag) that issues `token.transfer(caller, attacker, amount)` for any token the caller holds; simulation records that transfer as a child of the caller's `swap_collateral` auth entry, and if the caller signs the recorded tree, the transfer executes. A dedicated harness test proves the wallet drain end-to-end.

### Finding Description
`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and `multiply` all accept a `swap: Bytes` argument that flows into `swap_tokens`, which passes it uninspected to `router.execute_strategy(controller, amount_in, swap)` [1](#0-0) . The router decodes the bytes into a `StrategyPayload` (`amounts`, `assets` address registry, packed `ops` instruction stream) and dispatches each instruction to the pool address the payload's `assets` registry names — "The router calls the pool and token addresses its payload names and keeps no allowlist of them" [2](#0-1) . The venue calls execute below the caller's `require_auth` root, so any `require_auth`-protected call the injected contract makes — e.g. `token.transfer(victim, attacker, balance)` on an unrelated wallet token — is recorded by simulation as a sub-invocation of the caller's own controller auth entry and executes if signed [3](#0-2) . This is the same bug shape as ZF2016-04: caller-controlled data is interpreted as additional invocation semantics by a downstream executor, with no sanitization boundary.

### Impact Explanation
Theft of user funds. The injected contract call drains any token balance in the victim's wallet — not just the routed swap amount. Neither the payload `min_out` nor the controller's `RouterOverspend`/`NoSwapOutput`/final-risk checks bound the loss, because the theft is a nested transfer under the caller's signature, not a routed delta [4](#0-3) . The harness test shows Alice's `WALLET_BALANCE` (77 770 units of a token the protocol never listed) moved to the attacker while her swap itself paid a fair output [5](#0-4) .

### Likelihood Explanation
An unprivileged attacker only needs to get a victim to execute a poisoned route — e.g. by serving a malicious `routeXdr` through a compromised or phishing quote path, since clients are instructed to pass `routeXdr` bytes untouched and routes are produced off-chain [6](#0-5) . The theft does require the victim to sign the poisoned authorization tree (the host refuses the transfer under an honest root-only tree), so exploitation depends on a client that signs simulation output without decoding sub-invocations [7](#0-6) . This is documented behavior with a dedicated regression test, and the same exposure applies to the direct `execute_strategy` path. Medium, matching the advisory's severity.

### Recommendation
Short term, enforce client-side: decode every recorded authorization tree before signing and reject any controller/`execute_strategy` entry whose children include anything beyond the single expected input `transfer` — an honest route produces no additional child entries [8](#0-7) . Protocol-side, add a venue/pool allowlist to the router so payload-named addresses must be registered pools, or have the controller validate that the `assets` registry contains only expected token/venue addresses before invoking `execute_strategy`.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` implements it end-to-end:

1. Attacker deploys `RogueHopPool`, whose constructor stores `(victim, wallet_token, attacker, amount)` and whose `swap()` calls `token::Client::transfer(victim, attacker, amount)` [9](#0-8) .
2. Attacker builds route bytes naming the rogue pool as `hop_pool` [10](#0-9) ; the router invokes it via `env.invoke_contract(&route.hop_pool, "swap", ...)` [11](#0-10) .
3. Simulation records `transfer(alice, attacker, WALLET_BALANCE)` as a child of Alice's `swap_collateral` entry [12](#0-11) .
4. With the recorded tree signed, the transfer executes: Alice's wallet balance becomes 0 and the attacker holds `WALLET_BALANCE` [13](#0-12) .

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
