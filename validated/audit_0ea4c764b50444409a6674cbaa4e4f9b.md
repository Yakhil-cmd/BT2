Confirmed. `Shipit::Api::CCMenuController` breaks the token-scope-to-stack binding that the rest of the API enforces.

### Title
API-scoped ApiClient token can read the build/deploy status of any stack via the CCMenu endpoint - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
An `ApiClient` can be created with `permissions: ['read:stack']` and a `stack_id` that restricts it to a single stack, and this restriction is enforced everywhere in `Shipit::Api::BaseController` through the shared `stacks`/`stack` helpers. `Shipit::Api::CCMenuController`, however, overrides `stack` with an unscoped lookup, so the same token can be replayed with a different `stack_id` in the URL to read status data for any stack in the installation.

### Finding Description
`Shipit::Api::BaseController` defines the authorization binding between a token and the stacks it may touch: [1](#0-0) 

`current_api_client.stack_id?` is what turns a single-stack `ApiClient` (e.g. fixture `here_come_the_walrus`, which has `stack: shipit` and only `read:stack`) into a query scoped to that one `Stack`: [2](#0-1) 

This scoping is verified by `Shipit::Api::StacksController`'s own test: "an api client scoped to a stack will only see that one stack". [3](#0-2) 

`Shipit::Api::CCMenuController` inherits `BaseController` and its `require_permission :read, :stack` before_action, which only checks that the client *has* the `read:stack` permission string — it does not check which stack the request targets: [4](#0-3) 

But instead of using the scoped `stack` helper, `CCMenuController` redefines `stack` to resolve the id against the entire `Stack` table, bypassing `current_api_client.stack_id` entirely: [5](#0-4) 

So the equality the system is supposed to maintain — `current_api_client.stack_id == stack.id` (or "no restriction" when `stack_id` is nil) — holds in `StacksController`, `TasksController`, `LocksController`, etc. (all of which use the inherited `stack`/`stacks`), but is broken in `CCMenuController`, where any authenticated token with `read:stack` permission (in-scope or scoped-to-one-stack) can query `stack_id` for an arbitrary stack and receive that stack's CI status payload.

### Impact Explanation
This is an unauthenticated-relative-to-scope read of stack state: build/deploy status, last build label/time, lock state, and web URL for stacks that a given token was never authorized to see. `CCMenuController#show` exposes exactly this data via the rendered CCMenu XML: [6](#0-5) 

Tokens generated through the "CCMenu URL" feature are routinely embedded in query strings (used by external CCTray/CI-dashboard tools) and can leak more easily than Basic-Auth credentials, making this scope-escape practically reachable. This matches the High-impact bucket "unauthenticated read of stack state ... or deploy output."

### Likelihood Explanation
Any party holding a valid `ApiClient` token with `read:stack` — including a token intentionally scoped to a single stack — can trigger this by simply changing the `stack_id` segment of the CCMenu URL. No additional secret, session, or privileged access is required beyond possessing one legitimately-scoped token, which is a normal, low-privilege artifact of this feature (e.g., the CCMenu badge token created by `CCMenuUrlController`).

### Recommendation
Remove the `stack` override in `CCMenuController` and use the inherited, scope-aware `stack` method from `BaseController` (i.e., `stacks.from_param!(params[:stack_id])`) so that a stack-scoped `ApiClient` cannot query stacks outside `current_api_client.stack_id`.

### Proof of Concept
1. Create (or use) an `ApiClient` scoped to `stack_id = A` with `permissions: ['read:stack']` (as in fixture `here_come_the_walrus`), and obtain its `authentication_token`.
2. Send `GET /api/stacks/<owner>/<repo>/<env-B>/ccmenu?token=<token>` where `env-B` belongs to a different stack `B` that the token was never scoped to.
3. Observe `Shipit::Api::CCMenuController#stack` resolving via `Stack.from_param!(params[:stack_id])` (unscoped), returning stack `B`'s deploy/build status in the XML response, despite `current_api_client.stack_id == A`.
