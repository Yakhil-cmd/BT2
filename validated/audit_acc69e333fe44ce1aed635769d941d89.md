### Title
`register-for-bond` rollover never decrements the exited bond's `protocol-bonds-total-staked`, permanently double-counting the staker's sBTC commitment across bond A and bond B - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
When a staker rolls from bond A into bond B via `register-for-bond`, the function computes `old-sbtc` from bond A's membership, nets the physical sBTC transfer through `roll-sbtc`, and credits `sats-total` to bond B's `protocol-bonds-total-staked` entry, but never subtracts the staker's prior contribution from bond A's entry. Because the staker's `protocol-bond-memberships` pointer is overwritten to bond B, no future call (`unstake-sbtc`, `announce-l1-early-exit`) can ever reach bond A again to correct its stale total, leaving it permanently inflated.

### Finding Description
The invariant that should hold is: `get-total-sbtc-staked-for-bond(A) + get-total-sbtc-staked-for-bond(B) == get-total-sbtc-staked()` (sum of per-bond `protocol-bonds-total-staked` entries equals the global `total-sbtc-staked` var), and more specifically that the sats a single staker contributes should be reflected in exactly one bond's total at a time.

In `register-for-bond` (`stackslib/src/chainstate/stacks/boot/pox-5.clar:642-841`), the rollover path:
- reads `old-sbtc` via `get-staker-custodied-sbtc tx-sender` [1](#0-0) 
- nets the physical transfer with `roll-sbtc tx-sender old-sbtc new-sbtc`, which only adjusts the global `total-sbtc-staked` var by the delta [2](#0-1) 
- overwrites `protocol-bond-memberships tx-sender` to point at bond B [3](#0-2) 
- credits bond B's `protocol-bonds-total-staked` with the *full* `sats-total`, on top of `current-total-staked` [4](#0-3) 

There is **no** corresponding `(map-set protocol-bonds-total-staked bond-index-A (- old-total old-sbtc))` anywhere in this function. Compare this to the two other places that legitimately reduce a bond's tracked total — `unstake-sbtc` and `announce-l1-early-exit` — both of which explicitly decrement `protocol-bonds-total-staked` for the bond being exited: [5](#0-4) [6](#0-5) . Both of these decrements are keyed off `map-get? protocol-bond-memberships staker` — i.e., they can only ever fire against whatever bond the staker's *current* membership points to. Once `register-for-bond` overwrites that membership to point at bond B, bond A's `protocol-bonds-total-staked` entry becomes permanently unreachable for correction: no code path can ever decrement it again for that staker's contribution.

Meanwhile, the per-cycle share maps for bond A (`staker-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, `total-shares-staked-for-cycle`) are intentionally left intact by design (per the comment at line 796-798) so the staker keeps earning through bond A's already-elapsed term — this is a separate, deliberate mechanism from `protocol-bonds-total-staked`, and it does not create or fix the double-count in the `protocol-bonds-total-staked` map itself.

Existing guards do not prevent this: `verify-not-prepare-phase`, `verify-signer-key-grant`, `bond-overlaps-new-position?`/`ERR_ALREADY_REGISTERED`, and `verify-bond-rollover-window` all gate *when* a rollover can happen, not the bookkeeping correctness of `protocol-bonds-total-staked` during the rollover.

### Impact Explanation
Bond A's `protocol-bonds-total-staked` entry keeps counting the rolled-over staker's `sats-total` forever after the rollover, while bond B's entry also counts that same `sats-total`. This is a permanent double-count of a commitment across two bond slots, falling under the Critical category "double-counting a commitment or reward." Any downstream logic that trusts `get-total-sbtc-staked-for-bond` (e.g., displaying/reporting bond fill level, or any current/future capacity gating against this map) will see phantom capacity consumed on bond A that is not backed by any physically custodied sBTC there, since `roll-sbtc` has already moved the funds. The bug is repeatable by any unprivileged staker on every rollover they perform (each rollover leaves one more permanently-orphaned stale total on the vacated bond).

### Likelihood Explanation
The precondition is simply that an existing bond-A member reaches `verify-bond-rollover-window`'s allowed window (the last half-cycle of bond A's term) and rolls into an allowlisted bond B — a normal, expected user action requiring no privilege beyond being an allowlisted staker. The cost is a single ordinary `register-for-bond` transaction; the divergence is created unconditionally on every such rollover, with no attacker-controlled edge case needed. This makes it fully deterministic and repeatable, not a rare race condition.

### Recommendation
In `register-for-bond`'s rollover branch, when `existing-membership` is `some` and belongs to a *different* bond index than the target, decrement that old bond's `protocol-bonds-total-staked` by `old-sbtc` (mirroring the pattern already used in `unstake-sbtc` and `announce-l1-early-exit`) before or alongside overwriting `protocol-bond-memberships`, e.g.:
```
(map-set protocol-bonds-total-staked old-bond-index
    (- (get-total-sbtc-staked-for-bond old-bond-index) old-sbtc))
```
guarded so it is skipped when there is no existing bond membership or the rollover is from an STX-only stake.

### Proof of Concept
Rust integration test (extending `stacks-node/src/tests/pox_5_integrations.rs`, which already exercises `register-for-bond` rollover flows):
1. Set up bond A and bond B, allowlist staker S for both.
2. `register-for-bond(A, ...)` with `sats-total = X`; assert `get-total-sbtc-staked-for-bond(A) == X`.
3. Advance to bond A's rollover window (`verify-bond-rollover-window` window).
4. `register-for-bond(B, ...)` for S with `sats-total = Y`, rolling over from A.
5. Assert (currently fails): `get-total-sbtc-staked-for-bond(A) == 0` (or reduced by `X`) — actual result: still `X`.
6. Assert (currently fails): `get-total-sbtc-staked-for-bond(A) + get-total-sbtc-staked-for-bond(B) == get-total-sbtc-staked()` — actual result: sum is inflated by `X` (or `min(X, old-sbtc)`) relative to the global var.

(define-private (roll-sbtc
        (staker principal)
        (old-sbtc uint)
        (new-sbtc uint)
    )
    (begin
        (if (> new-sbtc old-sbtc)
            (let ((delta (- new-sbtc old-sbtc)))
                (try! (contract-call?
                    'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                    transfer delta tx-sender current-contract none
                ))
                (var-set total-sbtc-staked (+ (var-get total-sbtc-staked) delta))
            )
            (if (< new-sbtc old-sbtc)
                (let ((delta (- old-sbtc new-sbtc)))
                    (try! (as-contract?
                        ((with-ft
                            'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                            "sbtc-token" delta
                        ))
                        (try! (contract-call?
                            'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                            transfer delta tx-sender staker none
                        ))
                    ))
                    (var-set total-sbtc-staked
                        (- (var-get total-sbtc-staked) delta)
                    )
                )
                ;; new-sbtc == old-sbtc, no transfer needed
                true
            )
        )
        (ok true)
    )
