### Title
Webhook signature verification is silently skipped when `webhook_secret` is unset for the target organization - allowing full webhook forgery - (File: `lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever the organization resolved from the payload has no `webhook_secret` configured, before any HMAC comparison is attempted. Since `WebhooksController#verify_signature` resolves the organization purely from attacker-supplied JSON (`repository.owner.login` or `organization.login`), any unprivileged internet client can send an unsigned/garbage-signed `POST /webhooks` naming such an organization and have the payload fully processed (job enqueued, commits/statuses/memberships written) with zero cryptographic verification.

### Finding Description
The binding that must hold is: *the organization whose secret validated the HMAC bytes* == *the organization named as `repository_owner`/`organization.login` in the payload that gets processed*. In `lib/shipit/github_app.rb`: [1](#0-0) 

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```

when `webhook_secret` is falsy, the method returns `true` without ever looking at `signature` or `message`. The controller resolves the org exclusively from attacker-controlled JSON: [2](#0-1) 

`repository_owner` is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, and `Shipit.github(organization: repository_owner)` is looked up per-request with no relation to who actually signed anything. If that organization's config has no `webhook_secret` set (e.g. `test/dummy/config/secrets.test.json` ships `"webhook_secret": null` for its configured org), `verify_signature` treats the request as verified and dispatches it to `Shipit::Webhooks.for_event(event)` handlers (push → `GithubSyncJob`, `status` → commit status writes, `membership` → team/user mutation, `check_suite` → `RefreshCheckRunsJob`).

No other guard intervenes: `drop_unhandled_event` only filters by event name, not authenticity; `ExplicitParameters`/model validations only shape the payload, they don't authenticate its origin. The existing test suite's own default config (`webhook_secret: null`) combined with tests such as `":push with the target branch queues a GithubSyncJob"` — which posts a push payload with **no `X-Hub-Signature` header at all** and still asserts the job is enqueued — is a direct, already-present demonstration of the exact behavior the audit describes.

### Impact Explanation
Any org whose `webhook_secret` is not configured loses webhook authentication entirely: an attacker can forge `push` (triggers `GithubSyncJob`, pulling arbitrary refs into the stack's history/build state), `status` (fabricates CI status on arbitrary commits, potentially unblocking deploys/merges gated on green status), `membership` (creates/deletes team memberships, potentially affecting `Shipit.github_teams` authorization), and `check_suite` events for that organization's stacks — with no secret knowledge required. This is a full authentication bypass matching the Critical category (forged webhook accepted as authentic, mutating stack/commit/task state and influencing deploy gating).

### Likelihood Explanation
The precondition is purely a deployment/configuration fact: the targeted organization's `Shipit.github(organization: ...)` entry must have no `webhook_secret` set — no attacker action or secret is needed to satisfy this, only that such a configuration exists for at least one org handled by the instance (as the shipped `test/dummy` config itself does by default). Once that precondition holds, exploitation cost is a single unauthenticated HTTP POST with an arbitrary/absent `X-Hub-Signature`, fully repeatable and scriptable against any repository under that organization.

### Recommendation
Change `verify_webhook_signature` to fail closed when no secret is configured (`return false unless webhook_secret`), or make `webhook_secret` a mandatory, validated configuration field for every organization at boot time, and add a startup/health check that flags orgs with events registered but no `webhook_secret` present.

### Proof of Concept
Minitest plan (mirrors existing `test/controllers/webhooks_controller_test.rb` patterns):
1. Configure `Shipit.github(organization: 'no-secret-org')` with `webhook_secret` explicitly `nil` (as already done for the default dummy config).
2. Create a stack whose repository owner is `no-secret-org`.
3. `post :create` with `X-Github-Event: push`, a push payload naming `no-secret-org` as `repository.owner.login`, and either no `X-Hub-Signature` header or `X-Hub-Signature: 'sha1=deadbeef'`.
4. Assert `assert_enqueued_with(job: GithubSyncJob, ...)` succeeds and `assert_response` is **not** `:unprocessable_entity`, proving the payload is processed despite an invalid/absent signature — directly exercising `GitHubApp#verify_webhook_signature`'s `return true unless webhook_secret` branch (`lib/shipit/github_app.rb:77`).

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
