### Title
Permanent market freeze: `scaled_to_original` overflows `i128` before the borrow-index cap engages, bricking repay/withdraw/liquidate - (File: common/src/rates/scaling.rs)

### Summary
The borrow index is capped at `MAX_BORROW_INDEX_RAY` (`10^36`, i.e. 10^9 × RAY) in `update_borrow_index`, but the real ceiling that breaks the market is lower: every accrual step first unscales `borrowed` and `supplied` via `scaled_to_original` (`scaled.mul(index)` = `scaled * index / RAY` in `i128`). Once `scaled * index` exceeds `i128::MAX` — at roughly 170× the index value for a whale-scale book — `mul_div_half_up` panics with `MathOverflow` *before* the index cap can stick. Since `global_sync` runs accrual at the head of every pool verb, all exits and repayments on that market revert forever.

### Finding Description
`accrue_step` calls `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)` to compute utilization [1](#0-0) . `scaled_to_original` is `scaled.mul(index)`, which routes to `mul_div_half_up` and panics with `GenericError::MathOverflow` when the product `scaled * index` exceeds `i128::MAX` even though the widened `I256` path is exact — the quotient itself no longer fits `i128` [2](#0-1) [3](#0-2) .

`global_sync` iterates `accrue_chunk` before any state mutation, so the panic aborts the whole transaction [4](#0-3) . The cap in `update_borrow_index` only triggers if accrual reaches it, which requires `scaled_to_original` to succeed first [5](#0-4) . The test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the freeze: a ~10^18-unit 18-decimal market at 98% utilization on the steep XLM curve overflows in a few years, and afterwards `withdraw` and `repay` both revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY` [6](#0-5) .

The index caps (`MAX_BORROW_INDEX_RAY = 10^36`, `MAX_SUPPLY_INDEX_RAY` likewise) were designed to bound growth, but the value-ceiling `borrowed * borrow_index ≤ i128::MAX` binds first whenever `borrowed` (RAY-scaled) is above ~`i128::MAX / 10^9` ≈ 1.7e29 RAY — i.e. ~170 whole tokens of an 18-decimal asset scaled to RAY is enough once the index approaches the cap region; for large books it binds at much lower index values.

### Impact Explanation
Permanent freezing of funds: once a market's book value × index exceeds `i128::MAX`, every entrypoint that accrues first — `withdraw`, `repay`, `borrow`, `supply`, `liquidate`, `flash_loan`, `clean_bad_debt` — panics. Suppliers cannot exit, borrowers cannot repay, liquidators cannot liquidate, and `recapitalize` (which also syncs) cannot rescue the market. No governance escape hatch exists because index writes only happen through accrual, which is the panicking step. The position-NFT layer cannot help since the value lives in pool state.

### Likelihood Explanation
Medium-low. The trigger requires an enormous book (RAY value ≳ `i128::MAX / index`) sustained at high utilization for long enough that the index grows ~170× or more, and `max_utilization` enforcement must be off or the market must sit near the steep slope. Caps (`lift_caps` in the test) would normally bound `supplied`/`borrowed` below the cliff for realistic markets, so this mostly threatens whale-scale or high-decimal markets. It is not attacker-instant; but once crossed it is irreversible, and an unprivileged borrower pushing utilization to the steep segment is what drives the index there.

### Recommendation
Make `accrue_step` overflow-safe instead of panicking:
- Compute utilization on saturating/scaled-down values (e.g. `mul_div_floor_saturating` for `scaled_to_original` inside the accrual path, or compute `borrowed/supplied` ratio without unscaling both by the full index — utilization only needs `borrowed*borrow_index / (supplied*supply_index)`, which can be evaluated as a single `mul_div` chain or in `I256`).
- Alternatively, let `update_borrow_index`/`update_supply_index` clamp `borrowed`/`supplied`-value reads so that the index cap always engages before the value ceiling, turning the cliff into the intended sticky-cap behavior.
- Add a regression asserting the cap engages before `scaled_to_original` overflows for `supplied`/`borrowed` up to the configured cap domain (`require_cap_within_asset_domain`).

### Proof of Concept
Reproduced by `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs::a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);          // unprivileged supply
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98); // 98% utilization
loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; } // MathOverflow
}
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
assert!(book(&t, "BIG18").borrow_index < MAX_BORROW_INDEX_RAY); // cap never engaged
```

After the cliff, `repay`, `withdraw`, `liquidate`, and `update_indexes` all revert, permanently freezing ~10^36 units of supplier and collateral value in the market.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
