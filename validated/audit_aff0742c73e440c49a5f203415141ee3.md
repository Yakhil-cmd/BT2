### Title
Webhook signature verification and repository resolution use two independent, uncross-checked payload fields, allowing forged cross-org ReviewStack provisioning - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb])

### Summary
`WebhooksController#verify_signature` selects which org's `webhook_secret` to check against using `params.dig('repository','owner','login')`, while `LabeledHandler#repository` (via `Shipit::Repository.from_github_repo_name`) resolves the target repository from the completely independent `params.repository.full_name` field. [1](#0-0) [2](#0-1)  Because the raw JSON body is fully attacker-controlled, these two fields can be set to different values, so a signature that verifies (or trivially passes) for one org can authorize provisioning actions against a repository belonging to a completely different org.

### Finding Description
Binding claimed/required: `repository_owner` (used to select the `GitHubApp`/secret for signature verification) must equal the owner segment of the repository that the handler actually mutates, i.e. `params.dig('repository','owner','login') == params.repository.full_name.split('/').first`.

Trace:
- `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. [3](#0-2) [4](#0-3) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org has no configured `webhook_secret` (`return true unless webhook_secret`). [5](#0-4) 
- Independently, `LabeledHandler#repository` resolves the actual repository to operate on purely from `params.repository.full_name`, via `Shipit::Repository.from_github_repo_name`, which just splits the string on `/` and does a DB lookup — it never reads or compares `repository.owner.login`. [2](#0-1) [6](#0-5) 
- `LabeledHandler#handle` then calls `stack`/`ReviewStackAdapter` against that resolved repository's `review_stacks` when `provisioning_behavior_allow_with_label?` is true and the label matches, creating/unarchiving a `ReviewStack`. [7](#0-6) 

Exploit: an attacker crafts a raw POST body to `/webhooks` (X-Github-Event: pull_request) with `repository.owner.login = "org-with-no-webhook-secret"` (chosen to make `verify_webhook_signature` pass unconditionally per line 77 of `github_app.rb`) but `repository.full_name = "victim-org/victim-repo"`. Signature verification only checks against the no-secret org and passes trivially; the actual handler then resolves and mutates `victim-org/victim-repo`'s review stacks, entirely bypassing any binding between the verifying org and the targeted repository. `params` schema validation (`ExplicitParameters`) only enforces types/presence of `repository.full_name`, not consistency with `repository.owner.login`, so it does not prevent this. [8](#0-7) 

### Impact Explanation
An attacker can cause `ReviewStack` creation/unarchival (and associated provisioning-queue task launches) for a repository they do not control and never authenticated, provided that repository has `review_stacks_enabled` and `provisioning_behavior_allow_with_label?` configured — a payload targeting one repository/org mutates another repository's stack/task state, matching the Critical "payload for one repository mutating another's stack, commit, task or team" category. This is repeatable against any repository configured for label-based review-stack provisioning, as long as any org in the Shipit deployment has no `webhook_secret` configured (or the attacker separately obtains a valid signature for some org).

### Likelihood Explanation
Requires: (1) at least one configured GitHub org in `secrets.github` without a `webhook_secret` set (a plausible, silent misconfiguration since `GitHubApp#verify_webhook_signature` fails open rather than closed in that case), and (2) a victim repository with `review_stacks_enabled` and `provisioning_behavior_allow_with_label?`. No Shipit credentials, sessions, or GitHub App secrets are needed by the attacker — only knowledge/guessing of an org name lacking a webhook secret, which is discoverable via repeated probing (每 org config independently determines pass/fail). Attacker cost is a single crafted HTTP POST, fully repeatable.

### Recommendation
Enforce that `repository.owner.login` (or the owner segment of `repository.full_name`) matches the org used for signature verification before dispatching to handlers, and make `verify_webhook_signature` fail closed (return `false`, not `true`) when no `webhook_secret` is configured for the resolved org rather than treating an absent secret as "verification passed."

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "rejects pull_request payload naming a different repository/org than the one whose secret verified the signature" do
  # Configure org "no-secret-org" with NO webhook_secret in test credentials/secrets.github
  # Configure victim repo/org ("shopify/shipit-engine") with allow_with_label + matching label
  victim_repo = shipit_repositories(:shipit)
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :allow_with_label,
                       provisioning_label_name: "pull-requests-label")

  payload = JSON.parse(payload(:pull_request_labeled))
  payload["repository"]["owner"]["login"] = "no-secret-org"          # used for verify_signature
  payload["repository"]["full_name"] = victim_repo.github_repo_name  # used by handler
  payload["pull_request"]["labels"] = [{ "name" => "pull-requests-label" }]

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # attacker cannot produce a real signature

  assert_no_difference -> { Shipit::ReviewStack.count } do
    post :create, body: payload.to_json, as: :json
  end
  # Currently FAILS: ReviewStack IS created because verify_webhook_signature
  # returns true for "no-secret-org" (no secret configured), and the handler
  # resolves/mutates victim_repo independently via repository.full_name.
end
```

```ruby
          def handle
            if archive?

            elsif unarchive?

          def stack

              .new(params, scope: repository.review_stacks)
          end

          def repository
            @repository ||= Shipit::Repository.from_github_repo_name(params.repository.full_name) ||
                            Shipit::NullRepository.new
          end

          def pull_request
            params.pull_request
          end

          def pull_request_state
            pull_request.state
          end

          def respond_to_label_change?
            params.action == "labeled" &&
              pull_request_state == "open" &&
              repository.review_stacks_enabled &&
              (archive? || unarchive?)
          end

          def archive?
            (repository.provisioning_behavior_allow_with_label? && !pull_request_has_provisioning_label?) ||
              (repository.provisioning_behavior_prevent_with_label? && pull_request_has_provisioning_label?)
          end

          def unarchive?
            (repository.provisioning_behavior_allow_with_label? && pull_request_has_provisioning_label?) ||
              (repository.provisioning_behavior_prevent_with_label? && !pull_request_has_provisioning_label?)
          end

          def pull_request_has_provisioning_label?
            pull_request_label_names.include?(repository.provisioning_label_name)
          end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
