### Title
Arbiter contract shared-address funds can be permanently frozen with no timelock-based recovery if the arbiter or counterparty is unresponsive - (File: arbiter_contract.js)

### Summary
The Y2K report describes a vault where deposited funds become locked once an epoch is scheduled, with no exit path available to the depositor if they change their mind before the epoch begins — the withdrawal logic only allows exit after the epoch's designated end condition, leaving no fallback for early opt-out. The analogous root cause in ocore is the arbiter-contract shared-address definition constructed in `deriveSharedAddress()`: once a payer funds the shared address, the on-chain spending conditions provide only two ways to release funds — mutual cooperation of both contract parties, or a ruling posted by the (trusted, off-chain) arbiter — with no timelock-based fallback in the `oscript` definition itself.

### Finding Description
`deriveSharedAddress()` in `arbiter_contract.js` builds an `"or"` address definition with four branches: mutual agreement of offeror+acceptor (for the public-asset "complete"/"refund" case), the equivalent private-asset branch, and two branches gated on `["in data feed", [[contract.arbiter_address], "CONTRACT_" + contract.hash, "=", ...]]` that release funds to whichever party the arbiter names as winner via a data feed. [1](#0-0) 

None of these four branches includes any timestamp/expiry-based condition that would let either party unilaterally reclaim the funds if the arbiter never posts a ruling (e.g., the arbiter disappears, is unresponsive, or the arbstore never resolves the dispute) and the counterparty refuses to cooperate on the "complete" flow (which itself requires the peer's out-of-band participation to compose the release transaction). [2](#0-1) [3](#0-2) 

The `ttl` field on `wallet_arbiter_contracts` only governs the *offer* stage before the contract is accepted/paid — it is stored purely as wallet-side metadata and is never encoded into the on-chain shared-address definition, so it provides no protection once funds have actually been paid into the shared address. [4](#0-3) 

Once payment is made (`pay()` sets status to `"paid"`), the only paths out of the shared address are `complete()` (requires cooperative construction of a multi-signature spend by both `offeror_address` and `acceptor_address`) or the arbiter's data-feed ruling. If the counterparty is uncooperative — which is precisely the scenario a dispute exists for — and the arbiter never posts a `CONTRACT_<hash>` resolution (unavailable, colluding, or simply never triggered), the funds sit in the shared address indefinitely with no on-chain path to recovery.

### Impact Explanation
This results in permanent freezing of funds held in the arbiter-contract shared address: neither party can unilaterally recover their payment if the arbiter fails to act and the peer does not cooperate, since the address definition contains no expiry/timelock branch analogous to a "cancel before start" or "timeout" clause. This is a concrete fund-freezing condition reachable by any two ordinary users who set up an arbiter contract and one of whom simply refuses to cooperate while the arbiter stalls or disappears — no privileged access is required to trigger the freeze.

### Likelihood Explanation
Likelihood is moderate to high in practice: arbitration is specifically invoked when parties disagree, so an uncooperative counterparty is the expected case, and arbiters (third-party, possibly informal contacts) going unresponsive or delaying indefinitely is a realistic operational failure mode. Because the shared-address definition is fixed at contract creation and cannot be amended afterward, there is no mitigation once payment has been made.

### Recommendation
Add a timelock branch to the `"or"` definition generated in `deriveSharedAddress()` that allows the paying party (or both parties jointly with a majority/either-party clause) to reclaim/refund the payment after a defined `ttl`/expiry timestamp has elapsed without an arbiter ruling, mirroring how other refund-capable AA samples in this codebase (e.g., `ico_with_milestones.oscript`'s `$expiry_ts` refund case) allow depositors to exit before/without waiting on a stalled counterparty.

### Proof of Concept
1. Alice and Bob create an arbiter contract with Charlie as arbiter and pay funds into the derived shared address per `deriveSharedAddress()` (arbiter_contract.js:454-574).
2. Alice calls `pay()` (arbiter_contract.js:692) to send `contract.amount` to `shared_address`; status becomes `"paid"`.
3. A dispute arises; Bob refuses to sign any cooperative `complete()`/refund transaction, and Charlie (the arbiter) never posts a `data_feed` message with key `CONTRACT_<hash>` (arbiter_contract.js:719-796, 798-814).
4. Because the on-chain definition only allows spending via mutual `offeror`+`acceptor` agreement or an arbiter data-feed ruling (arbiter_contract.js:465-481), and no timelock/expiry branch exists, the funds in `shared_address` remain permanently unspendable by Alice, regardless of how much time has passed.

function pay(hash, walletInstance, arrSigningDeviceAddresses, cb) {
	getByHash(hash, function(objContract) {
		if (!objContract.shared_address || objContract.status !== "signed" || !objContract.me_is_payer)
			return cb("contract can't be paid");
		var opts = {
			asset: objContract.asset,
			to_address: objContract.shared_address,
			amount: objContract.amount,
			spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own'
		};
		if (arrSigningDeviceAddresses.length)
			opts.arrSigningDeviceAddresses = arrSigningDeviceAddresses;
		walletInstance.sendMultiPayment(opts, function(err, unit){								
			if (err)
				return cb(err);
			setField(objContract.hash, "status", "paid", function(objContract){
				cb(null, objContract, unit);
			});
			// listen for peer announce to withdraw funds
			storage.readAssetInfo(db, objContract.asset, function(assetInfo) {
				if (assetInfo && assetInfo.is_private)
					db.query("INSERT "+db.getIgnore()+" INTO my_watched_addresses (address) VALUES (?)", [objContract.peer_address]);
			});
		});
	});
}

function complete(hash, walletInstance, arrSigningDeviceAddresses, cb) {
	getByHash(hash, async function(objContract) {
		if (objContract.status !== "paid" && objContract.status !== "in_dispute")
			return cb("contract can't be completed");
		const err = await fillArbstoreAddresses(objContract);
		if (err)
			return cb(err);
		storage.readAssetInfo(db, objContract.asset, function(assetInfo) {
			var opts;
			new Promise((resolve, reject) => {
				if (assetInfo && assetInfo.is_private) {
					var value = {};
					value["CONTRACT_DONE_" + objContract.hash] = objContract.peer_address;
					opts = {
						spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own',
						paying_addresses: [objContract.my_address],
						signing_addresses: [objContract.my_address],
						change_address: objContract.my_address,
						messages: [{
							app: 'data_feed',
							payload_location: "inline",
							payload_hash: objectHash.getBase64Hash(value, true),
							payload: value
						}]
					};
					resolve();
				} else {
					opts = {
						spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own',
						paying_addresses: [objContract.shared_address],
						change_address: objContract.shared_address,
						asset: objContract.asset
					};
					if (objContract.me_is_payer && !(assetInfo && (assetInfo.fixed_denominations || assetInfo.is_private))) { // complete
						require("./wallet_defined_by_addresses.js").readSharedAddressDefinition(objContract.shared_address, function (arrDefinition) {
							const index = objContract.is_incoming ? 2 : 1;
							const peer_amount = arrDefinition[1][index][1][1][1].amount;
							const arbstore_amount = arrDefinition[1][index][1][2] && arrDefinition[1][index][1][2][0] === 'has' ? arrDefinition[1][index][1][2][1].amount : 0;
							if (!isFinite(peer_amount) || !isFinite(arbstore_amount))
								throw new Error("invalid amounts in shared address definition: " + JSON.stringify(arrDefinition));
							if (peer_amount + arbstore_amount !== objContract.amount)
								throw new Error(`amounts in shared address definition do not sum up to contract amount: ${peer_amount} + ${arbstore_amount} !== ${objContract.amount}`);
							if (arbstore_amount > peer_amount)
								throw new Error(`arbstore cut is more than 50% of the total amount, peer_amount: ${peer_amount}, arbstore_amount: ${arbstore_amount}`);
							if (arbstore_amount === 0) {
								opts.to_address = objContract.peer_address;
								opts.amount = objContract.amount;
							} else {
								opts[objContract.asset && objContract.asset != "base" ? "asset_outputs" : "base_outputs"] = [
									{ address: objContract.peer_address, amount: peer_amount},
									{ address: objContract.arbstore_address, amount: arbstore_amount},
								];
							}
							resolve();
						});
					} else { // refund
						opts.to_address = objContract.peer_address;
						opts.amount = objContract.amount;
						resolve();
					}
				}
			}).then(() => {
				if (arrSigningDeviceAddresses.length)
					opts.arrSigningDeviceAddresses = arrSigningDeviceAddresses;
				walletInstance.sendMultiPayment(opts, function(err, unit){
					if (err)
						return cb(err);
					var status = objContract.me_is_payer ? "completed" : "cancelled";
					setField(objContract.hash, "status", status, function(objContract){
						cb(null, objContract, unit);
					});
				});
			}).catch(err => {
				cb(err);
			});
		});
	});
}
