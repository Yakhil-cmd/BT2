### Title
Stop-hook review set is derived from raw git working-tree state, not from Claude-authored edits, allowing attacker-mutated files to be included in the diff sent to SECURITY_REVIEW_MODEL - (File: plugins/security-guidance/hooks/diffstate.py)

### Summary
`compute_v2_review_set` in `diffstate.py` computes the Stop-hook's review set purely from `git status`/`git diff <baseline_sha>` state (`dirty_now ∩ changed_since`), not from the `touched_paths` list that PostToolUse actually records for Claude's own edits. Any process that mutates tracked files in the working tree between `UserPromptSubmit` and `Stop` — a build step, a `post-checkout`/`post-merge` hook triggered by a `git pull`/`merge`/`rebase` Claude runs, or any other untrusted script with working-tree write access — will have those files show up as both "dirty now" and "changed since baseline," and they will be swept into the diff sent to the external `SECURITY_REVIEW_MODEL`.

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) snapshots `git stash create` (or `HEAD`) at `UserPromptSubmit` time as `baseline_sha` [1](#0-0) . At `Stop`, `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) builds the review set as `dirty_now = tracked_dirty | new_untracked` intersected with `changed_since = git diff --name-only <baseline_sha> | union(new_untracked)` [2](#0-1) . This computation is entirely git-state-based — it never consults `touched_paths`, the list PostToolUse actually populates via `record_touched_path` for files Claude edited through tool calls [3](#0-2) .

Consequently, any file mutated in the working tree between the baseline capture and Stop — regardless of who or what changed it — satisfies both membership conditions (it's dirty relative to the index/HEAD, and it differs from the stashed baseline content) and is included in `review_set`. The docstring for `capture_git_baseline` and the module header claim "Only code Claude actually changed is reviewed (not pre-existing code)" [4](#0-3) , but the implementation does not enforce this via session-scoped attribution; it infers attribution purely from a diff against a point-in-time git snapshot. A tracked file that already existed at baseline and is modified by an out-of-band actor (e.g. a `post-merge`/`post-checkout` git hook triggered when Claude runs `git pull`/`git merge`/`git rebase` on attacker-crafted repo content, or a build/watch script race) will pass both filters and be swept into `git diff <baseline_sha>` output that is subsequently sent to the external review model via `get_git_diff`/`analyze_code_security`.

Note: `GIT_CMD` does set `core.hooksPath=/dev/null` [5](#0-4)  for the plugin's own git invocations, which blocks git hooks *from this plugin's own subprocess calls* specifically, but does not prevent Claude's own `git pull`/`merge`/`rebase`/`checkout` Bash invocations (run without this override) from executing repo-controlled hooks, nor does it stop any other concurrent process (linters, watchers, build tools invoked in the session) from touching tracked files.

### Impact Explanation
Content from files the untrusted mutator wrote/altered — which could include secrets checked into another branch that gets merged, sensitive files unstashed by an unrelated process, or files modified by a malicious repo-controlled git hook — can be captured into the diff and transmitted to the external `SECURITY_REVIEW_MODEL` API endpoint. This is a scope-binding failure: the diff sent externally is not reliably restricted to Claude-session-authored changes, and can leak file contents the user did not intend Claude (or the API) to see. This matches an information-disclosure / trust-boundary-bypass class of impact.

### Likelihood Explanation
Requires: (1) a git repo where the attacker can influence content that triggers a working-tree mutation during the session window (e.g., a merge/rebase/checkout invoking a repo-tracked hook, or a concurrently running build/watch tool touching tracked files) and (2) that mutation to occur between the `UserPromptSubmit` baseline capture and the `Stop` hook firing. This is a realistic but non-trivial race — it depends on session activity that changes HEAD or the working tree via non-Claude-authored means during an active turn, which is plausible in CI-like or automation-heavy workflows but not guaranteed in a typical interactive session.

### Recommendation
Bind the Stop-hook review set to files Claude's tool calls actually touched (`touched_paths`, already tracked via `record_touched_path`) as a positive allowlist, rather than deriving attribution solely from git-state diffing. At minimum, intersect `review_set` with `touched_paths` (mapped to repo-relative paths) before sending anything to `get_git_diff`/the LLM, only falling back to the git-derived heuristic when `touched_paths` is unavailable, and document/telemetry-flag when the git-derived set diverges from the tool-attributed set (a strong signal of exactly this attack).

### Proof of Concept
Integration test in the plugin's test suite (e.g. alongside existing `compute_v2_review_set` tests):
1. Initialize a git repo with one committed file `tracked.txt`.
2. Simulate `UserPromptSubmit`: call `capture_git_baseline(cwd)` to get `baseline_sha`, record `head_at_capture`.
3. Simulate Claude's session: call `record_touched_path(session_id, "other.py")`, create/write `other.py` (an actually Claude-authored change).
4. Simulate an untrusted mid-session mutator (standing in for a `post-merge` hook / build script): directly modify `tracked.txt` to contain a fake secret string, without going through any Claude tool call or `record_touched_path`.
5. Simulate `Stop`: call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline={})`.
6. Assert: `review_set`/`review_paths` returned includes `other.py` (expected) — and, demonstrating the bug, also includes `tracked.txt` even though it was never recorded in `touched_paths` and was never touched by any Claude tool call.
7. Expected (fixed) behavior: `review_paths` should be limited to `other.py` only; `tracked.txt` should be excluded because it's absent from the session's `touched_paths`.

def record_touched_path(session_id, file_path):
    """Append a file path to the touched_paths list (deduped, capped at 200).

    Stop is the consumer and clears under the same lock it reads with; UPS
    no longer wipes. The cap is a defensive bound for sessions where Stop
    never fires (disabled mid-session, abort) — git diff naturally filters
    stale paths so over-retention is harmless, just wasteful.
    """
    def _record(state):
        paths = state.setdefault("touched_paths", [])
        if file_path not in paths:
            paths.append(file_path)
            if len(paths) > 200:
                del paths[:len(paths) - 200]
    with_locked_state(session_id, _record)

def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None

            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already

    # set from status regardless.
    if baseline_sha:

        if changed_since is not None:

    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
