### Title
RAY-valued market totals can overflow before the index cap and permanently freeze a market - ([File: common/src/rates/simulate.rs])

### Summary
A sufficiently large market can reach a state in which `borrowed * borrow_index` or `supplied * supply_index` no longer fits in `i128`, even though both indexes remain below their configured caps. [1](#0-0)  Once this happens, every operation that loads the market runs `global_sync` first and reverts with `MathOverflow`, permanently blocking repayment, withdrawal, liquidation, and index synchronization for that market. [2](#0-1) 

### Finding Description
`accrue_step` unconditionally calls `scaled_to_original` on both total debt shares and total supply shares before calculating utilization or updating the capped indexes. [1](#0-0)  `scaled_to_original` is a checked `Ray` multiplication rather than a saturating or domain-validated operation. [3](#0-2)  The borrow-index cap is applied only to `old_index * interest_factor`; it does not ensure that the independent product `borrowed * borrow_index` remains representable. [4](#0-3) 

Every market operation loads a synchronized cache, and `load_leg` validates only that the submitted amount is non-negative before invoking `synced_market`. [5](#0-4)  `synced_market` calls `global_sync`, which invokes `accrue_step` for each elapsed accrual chunk. [6](#0-5)  Consequently, an unprivileged user can first create the oversized state through `supply(caller, account_id, spoke_id, assets)` and `borrow(caller, account_id, borrows, to)`, and later trigger the overflow through `update_indexes`, `repay(caller, account_id, payments)`, `withdraw(caller, account_id, withdrawals, to)`, or `liquidate(liquidator, account_id, debt_payments, seize_mode)`. [7](#0-6) 

The regression test demonstrates the concrete boundary: a one-billion-token, eighteen-decimal market at sustained 98% utilization hits the RAY-value ceiling while `borrow_index < MAX_BORROW_INDEX_RAY`. [8](#0-7)  Afterward, even a one-unit withdrawal and a minimal repayment revert with `MathOverflow`. [9](#0-8) 

### Impact Explanation
This is a permanent freezing-of-funds condition for the affected `(hub_id, asset)` market. [10](#0-9)  Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot clear the unhealthy position, and `update_indexes` cannot advance the market because all these paths perform the same overflowing accrual before their operation-specific logic. [11](#0-10)  Since the panic occurs before new state is committed, ordinary retries cannot recover the market. [12](#0-11) 

### Likelihood Explanation
The trigger does not require privileged access at exploitation time: `repay`, `withdraw`, `liquidate`, and index synchronization all reach the same public controller flows and the pool accrual path. [13](#0-12)  Creating the vulnerable state requires an extremely large supplied balance and high utilization, so it is capital-intensive rather than a low-cost transaction. [14](#0-13)  Nevertheless, admitted asset amounts can produce RAY-valued totals near the `i128` domain limit, and the code's own documentation states that valid caps and bounded indexes do not guarantee that later accrued market values fit. [15](#0-14) 

### Recommendation
Enforce a derived market-size invariant whenever shares are minted or revenue shares are added: `borrowed * MAX_BORROW_INDEX_RAY / RAY` and `supplied * MAX_SUPPLY_INDEX_RAY / RAY` must remain representable in `i128`. [16](#0-15)  Alternatively, make the two `scaled_to_original` calls in `accrue_step` use a saturating or explicitly bounded value calculation, while keeping normal user-facing balance conversions checked. [1](#0-0)  The fix must cover the existing-state product, not merely the newly computed index, because the overflow occurs before `update_borrow_index` can apply its cap. [3](#0-2) 

### Proof of Concept
1. Configure an 18-decimal borrowable market with caps large enough to admit approximately one billion whole tokens.
2. Call `supply(caller, 0, spoke_id, [(hub_asset, 1_000_000_000 * 10^18)])` to create the oversized scaled-supply position.
3. Supply sufficient collateral in another market and call `borrow(caller, account_id, [(hub_asset, 980_000_000 * 10^18)], to)` to sustain approximately 98% utilization.
4. Advance ledger time and call `update_indexes` or any market operation.
5. `global_sync` calls `accrue_step`; `scaled_to_original(borrowed, borrow_index)` or `scaled_to_original(supplied, supply_index)` overflows `i128` before the index cap is relevant. [1](#0-0) 
6. Subsequent `withdraw`, `repay`, `liquidate`, and `update_indexes` calls all revert with `MathOverflow`, matching the existing regression scenario. [17](#0-16)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");

        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"

    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
