### Title
Webhook organization used for signature verification is never bound to the repository the event handlers act on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub App/secret to validate the HMAC signature using `repository_owner`, i.e. `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`). The event handlers that actually mutate application state (`Shipit::Webhooks::Handlers::Handler#stacks`, and in particular `StatusHandler`) select their target using a *different*, independently attacker-controlled field of the same JSON body (`repository.full_name`, or in `StatusHandler`'s case, nothing about the repository at all). Nothing in the engine ever checks that the organization whose secret validated the request is the same organization that owns the repository/commit being written to.

### Finding Description
`verify_signature` resolves the app/secret purely from the payload's own claimed owner login: [1](#0-0) 

The HMAC check itself, when a secret is configured, is a normal `secure_compare`; but when the org resolved by `Shipit.github(organization: repository_owner)` has no `webhook_secret` configured, verification is unconditionally skipped: [2](#0-1) 

Shipit's own setup docs and secrets template explicitly support multiple GitHub organizations behind one installation, each with its own (optional) `webhook_secret`: [3](#0-2) 

Once `create` proceeds past `verify_signature`, handlers resolve the target strictly from a *different* field of the same body, with no re-check against `repository_owner`: [4](#0-3) 

`StatusHandler` is the starkest example: it doesn't even look at `repository` at all, it matches purely by commit `sha` across the entire installation: [5](#0-4) 

`create_status_from_github!` creates a `Status` row, which on creation enables CI on the stack and schedules continuous delivery evaluation for that commit/stack: [6](#0-5) [7](#0-6) 

So the equality the code implicitly assumes but never enforces is:
`organization that authenticated the request (repository_owner used to pick the GitHub App/secret)` == `organization/repository the resulting handler writes state for (repository.full_name / matched commit sha)`.

In a multi-org Shipit deployment where at least one configured organization has no `webhook_secret` set (documented as optional), an unauthenticated request can claim `repository.owner.login` = that unsecured org (so `verify_webhook_signature` returns `true` unconditionally) while setting `repository.full_name`/`sha` to reference a stack belonging to a completely different, secured organization. `PushHandler` will then force `sync_github`/continuous-delivery scheduling, and `StatusHandler` will inject arbitrary CI statuses for any known commit sha in the whole installation — with zero credentials, zero repository access, and no dependency on any org's actual `webhook_secret`.

### Impact Explanation
This breaks the authorization boundary between GitHub organizations inside a single Shipit installation: the verification step authenticates "some org", not "the org that owns this repository/stack". `StatusHandler` in particular lets an unauthenticated request set a commit's CI status for any stack in the installation (identified only by `sha`), which drives `enable_ci_on_stack`/`schedule_continuous_delivery`, directly influencing whether a commit is treated as deployable and can trigger continuous deployment — an unauthorized action against a repository/organization the request never authenticated for. This matches "escalation ... unauthenticated read of stack state" / contributing to an "unauthorized deploy" impact bucket, since the CI gate used before deploys can be manipulated cross-organization without any credential.

### Likelihood Explanation
Exploitability is gated on a documented, supported configuration choice (multiple GitHub orgs, at least one without `webhook_secret`), which the project's own setup docs describe as optional. Given that condition, no credentials, tokens, or secrets of any kind are required — the request is a plain unauthenticated POST to `/webhooks`. The `StatusHandler` code path additionally requires no organization matching at all, making it the most directly exploitable of the handlers.

### Recommendation
- Have `verify_signature` validate the signature against the organization/App that Shipit actually expects for the resolved `Repository`/`Stack` (looked up from `repository.full_name`), not against whatever `repository.owner.login`/`organization.login` the untrusted payload claims.
- Reject webhook events whose claimed `repository.owner.login` does not match the owning organization of the `Repository` matched by `repository.full_name`.
- In `StatusHandler` (and any other handler), scope lookups by the verified repository/stack rather than a bare `sha`/global match.
- Consider making `webhook_secret` mandatory for every configured organization, or at minimum refuse to process any event whose claimed owner has no secret configured while other organizations do.

### Proof of Concept
Given a Shipit installation configured with two organizations, `unsecured-org` (no `webhook_secret`) and `secured-org` (has a Stack with commits), an unauthenticated client can:
```
POST /webhooks
X-Github-Event: status
Content-Type: application/json

{
  "repository": { "owner": { "login": "unsecured-org" } },
  "sha": "<sha of a real commit belonging to secured-org's stack>",
  "state": "success",
  "context": "ci/required-check"
}
```
`verify_signature` resolves `Shipit.github(organization: 'unsecured-org')`, whose `verify_webhook_signature` returns `true` unconditionally because no secret is configured for it (`lib/shipit/github_app.rb:76-83`). `Webhooks.for_event('status')` then runs `StatusHandler`, which finds the commit purely by `sha` (`app/models/shipit/webhooks/handlers/status_handler.rb:20-24`) and creates a `Status` for `secured-org`'s stack, enabling CI and scheduling continuous delivery for it — despite the request never having authenticated against `secured-org` in any way.

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
