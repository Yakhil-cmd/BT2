### Title
Reward-distribution chunk-count clamp does not bound per-block partition size, allowing unbounded per-block work at epoch boundary - ([File: runtime/src/bank/partitioned_epoch_rewards/distribution.rs])

### Summary
`get_reward_distribution_num_blocks` (in `runtime/src/bank/partitioned_epoch_rewards/mod.rs`) clamps only the *number* of reward-distribution blocks (`num_chunks`) to `(slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1)`, but the number of stake rewards actually processed per block/partition is `total_rewards / num_chunks` (via `epoch_rewards_hasher::hash_rewards_into_partitions`), not a fixed per-block cap. `store_stake_accounts_in_partition` in `distribution.rs` then iterates over the full index list assigned to a single partition with no truncation to `partitioned_rewards_stake_account_stores_per_block`. If `total_rewards` (i.e. `PartitionedStakeRewards::num_rewards()`) grows large enough, the per-partition/per-block workload can exceed the intended `stake_account_stores_per_block` budget by an arbitrary factor.

### Finding Description
The intended invariant, expressed in `accounts-db/src/partitioned_rewards.rs`'s doc comment, is that a bounded number of stake accounts (`stake_account_stores_per_block`, e.g. 4096) are stored per 400ms block during reward distribution [1](#0-0) . The chunk count is computed as `ceil(num_rewards / stake_account_stores_per_block)` and then clamped to a maximum of `(slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1)` blocks — this caps how many blocks the whole distribution can span, but it says nothing about how many reward entries end up in each of those blocks once the cap is hit.

`distribute_partitioned_epoch_rewards` hashes all stake rewards into exactly `epoch_rewards_sysvar.num_partitions` partitions [2](#0-1) , and `distribute_epoch_rewards_in_partition` -> `store_stake_accounts_in_partition` processes *all* indices assigned to a given partition in a single call, with no re-chunking or truncation logic [3](#0-2) . The loop over `indices` builds `updated_stake_rewards` and eventually calls `self.store_accounts(...)` for the entire partition in one shot [4](#0-3) .

Because `num_chunks` is clamped independently of `num_rewards`, once `num_rewards` exceeds `stake_account_stores_per_block * max_blocks`, the average and worst-case partition size necessarily exceeds `stake_account_stores_per_block`, scaling linearly with attacker-controlled `num_rewards`. Nothing in `store_stake_accounts_in_partition` enforces an upper bound on `indices.len()` for a single block — it trusts that the partitioning step already bounded partition sizes, but the partitioning step only bounds partition *count*, not partition *size*, when the clamp is active.

An attacker can inflate `num_rewards` cheaply by creating many rent-exempt delegated stake accounts (minimum stake amount) to any active vote account before an epoch boundary. Each such delegation, if it earns any nonzero reward (even 1 lamport under normal inflation-and-commission math) or otherwise participates in the epoch's active stake, yields a `Some(PartitionedStakeReward)` entry, directly inflating `PartitionedStakeRewards::num_rewards()`.

### Impact Explanation
If per-block work is not actually capped, the validator must perform unbounded account deserialization/serialization and `store_accounts` work inside a single block's reward-distribution step, well beyond the `MAX_PARTITIONED_REWARDS_PER_BLOCK` budget the constant name and doc comment promise [1](#0-0) . This can stall block production during the epoch-boundary reward-distribution window across the whole cluster (since every validator executes the same distribution logic deterministically), matching the "stall of block production" / epoch-boundary halt impact category.

### Likelihood Explanation
Preconditions are within reach of an unprivileged attacker: fund and own many stake accounts, delegate them (via normal `DelegateStake` instructions) to any active vote account, and wait for the natural epoch boundary. The cost is bounded by rent-exempt minimums and transaction fees for creating/delegating many stake accounts, which is a real but non-prohibitive economic cost, and repeatable every epoch. I could not fully verify the exact arithmetic and constant value of `MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH` or the exact chunking formula in `get_reward_distribution_num_blocks` (in `runtime/src/bank/partitioned_epoch_rewards/mod.rs`) because that file's relevant section was not retrieved before the tool budget was exhausted — this should be independently confirmed by reading `mod.rs` in full to verify the exact clamp formula and whether `hash_rewards_into_partitions` distributes indices evenly or with some other bound.

### Recommendation
Enforce a hard per-partition/per-block cap in `store_stake_accounts_in_partition` (or in the partitioning step) equal to `partitioned_rewards_stake_account_stores_per_block`, independent of how many total chunks were allowed by the `slots_per_epoch` clamp. If `num_rewards / max_blocks` would exceed the per-block budget, increase the number of distribution blocks/epoch-reward-active-window instead of silently growing per-block partition size, or reject/limit reward-eligible delegation growth so that `num_rewards` cannot exceed `stake_account_stores_per_block * max_blocks`.

### Proof of Concept
```rust
// runtime/src/bank/partitioned_epoch_rewards/distribution.rs (tests module)
#[test]
fn test_partition_size_not_bounded_by_clamp() {
    let (genesis_config, _mint_keypair) = create_genesis_config(1_000_000 * LAMPORTS_PER_SOL);
    let bank = Bank::new_for_tests(&genesis_config);

    let stake_account_stores_per_block = 4096u64; // from PartitionedEpochRewardsConfig
    let slots_per_epoch = bank.epoch_schedule().slots_per_epoch;
    let max_blocks = (slots_per_epoch / 10 /* MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH */).max(1);

    // Attacker inflates num_rewards far beyond stake_account_stores_per_block * max_blocks
    let expected_num = (stake_account_stores_per_block * max_blocks * 50) as usize;

    let stake_rewards: PartitionedStakeRewards = (0..expected_num)
        .map(|_| Some(PartitionedStakeReward::new_random()))
        .collect();

    // Reproduce the num_chunks computation from get_reward_distribution_num_blocks
    let num_chunks = bank.get_reward_distribution_num_blocks(&stake_rewards);
    assert_eq!(num_chunks, max_blocks, "num_chunks should be clamped to max_blocks");

    let partition_indices = hash_rewards_into_partitions(
        &stake_rewards,
        &Hash::new_from_array([1; 32]),
        num_chunks as usize,
    );

    // Assert that the invariant "each block processes <= stake_account_stores_per_block"
    // is VIOLATED once num_rewards is attacker-inflated.
    let max_partition_size = partition_indices.iter().map(|p| p.len()).max().unwrap();
    assert!(
        max_partition_size > stake_account_stores_per_block as usize,
        "expected per-block work to exceed the intended budget once num_rewards is inflated \
         (got {max_partition_size}, budget {stake_account_stores_per_block})"
    );
}
```
Expected result: `max_partition_size` scales with attacker-supplied `expected_num` and exceeds `stake_account_stores_per_block`, demonstrating the clamp bounds block *count* only, not per-block work, contrary to the intended invariant.

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );
