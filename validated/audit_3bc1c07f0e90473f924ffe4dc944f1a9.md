### Title
Whale-scale market accrual overflows i128 before the index cap engages, permanently freezing the market - (File: common/src/rates/index.rs)

### Summary
The GNU coreutils `split` heap overflow is an overflow that fires only when an input line exceeds a size the code assumed bounded. The analog here is the assumption that `MAX_BORROW_INDEX_RAY` / `MAX_SUPPLY_INDEX_RAY` bound the *value* domain: index updates multiply share totals by the index (`supplied * index`, `borrowed * index`) in plain RAY `mul`, which panics with `MathOverflow` once the product leaves `i128` — before the index ceiling can clamp. A market carrying a very large share total reaches that cliff while the index is still far below its cap, at which point every entrypoint that accrues reverts forever.

### Finding Description
`update_supply_index` computes `supplied.mul(env, old_index)` and `calculate_supplier_rewards` computes `borrowed.mul(env, index)` before any clamp is applied, so the product `shares × index / RAY` is the real bound, not the index caps. [1](#0-0) [2](#0-1) 

The crate docs acknowledge `Ray::mul` uses an `i128` fast path that raises `MathOverflow` on unrepresentable results; only the explicitly saturating sites (`mul_div_floor_saturating`) survive. [3](#0-2)  The Certora spec notes the same panic site and treats it as a residual bound rather than a fixed bug. [4](#0-3) 

Because every pool verb accrues indexes first, once `borrowed × borrow_index` overflows, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and `claim_revenue` all abort on the same panic. The test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` builds a billion-token market at 98% utilization, advances time, and observes `try_update_indexes_for` fail with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY` — the cap never engages — and confirms `withdraw` and `repay` revert identically. [5](#0-4) 

### Impact Explanation
Permanent freezing of funds for the entire affected market: all suppliers' deposits and all borrowers' collateral become unrecoverable, and no liquidation or bad-debt cleanup can run. The overflow is triggered through ordinary unprivileged entrypoints (`supply`, `borrow`, `update_indexes`); no privileged action can recover the market because the panic occurs inside index accrual that precedes every mutation.

### Likelihood Explanation
Reaching the cliff requires a share total large enough that `shares × index / RAY` exceeds `i128::MAX` before the index hits its cap — i.e., a whale-scale supply (near the per-market cap, on the order of `i128::MAX / RAY` whole tokens) plus sustained high borrow utilization so the borrow index keeps compounding. That is a large but attainable economic commitment on a high-decimals asset, and the bug is deterministic once the state is reached. Medium likelihood, high impact → Medium severity, matching the source advisory.

### Recommendation
Make the value-domain the explicitly guarded quantity, not the index:

- Compute `supplied.mul(old_index)` / `borrowed.mul(index)` via a saturating or `I256`-widened variant inside `update_supply_index` and `calculate_supplier_rewards`, the same way `mul_div_floor_saturating` is already used at `index.rs:41`.
- Clamp the grown index not only to `MAX_*_INDEX_RAY` but also to the largest index for which `supplied * index / RAY` still fits `i128`, so accrual stops growing the index instead of panicking.
- Alternatively, cap per-market `supplied`/`borrowed` share totals at listing/accrual time to `i128::MAX / MAX_*_INDEX_RAY` so the product is unreachable by construction.

### Proof of Concept
See the in-repo reproduction `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`): supply `10^9` BIG18 tokens (18 decimals) via `supply`, borrow 98% of it via `borrow`, then repeatedly advance one year and call `update_indexes` (controller `update_indexes` entrypoint). Accrual panics with `MathOverflow` while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`; subsequent `withdraw(1)` and `repay(1)` panic with the same error, demonstrating permanent freeze through unprivileged entrypoints only.

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
