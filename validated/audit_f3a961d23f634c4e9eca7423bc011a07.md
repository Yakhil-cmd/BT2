Looking at the Linea bug class — **immutable committed state used in a later finalization step, where wrong committed state prevents correct finalization** — I need to trace this pattern through Kaia's bridge, consensus, governance, and reward paths.

### Title
Permanently Closed Bridge Vote Nonce Enables Irrecoverable Wrong-Parameter Transfer Execution — (`contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`_voteValueTransfer` in `BridgeOperator.sol` permanently sets `closedValueTransferVotes[_requestNonce] = true` the moment operator vote-count reaches threshold. There is no owner-accessible reset path. If wrong transfer parameters (`_to`, `_value`, `_tokenAddress`, `_requestTxHash`) reach quorum — whether through a single operator mistake at the default threshold of 1, or through multiple operators submitting identical wrong calldata — the wrong transfer executes and the nonce is permanently consumed. The VT recovery subsystem (`node/sc/vt_recovery.go`) then treats the nonce as already handled and will never re-submit the correct transfer, making the loss of bridged assets irrecoverable without a contract upgrade.

---

### Finding Description

**Two-phase structure (direct analog to Linea's `submitData` → `finalizeCompressedBlocks`):**

**Phase 1 — vote submission.** Each operator calls `handleKLAYTransfer` / `handleERC20Transfer` / `handleERC721Transfer`. Inside `_voteValueTransfer`, the vote key is computed as `keccak256(msg.data)` — the hash of the *entire* calldata including `_requestTxHash`, `_from`, `_to`, `_value`, `_tokenAddress`, `_requestedBlockNumber`, and `_extraData`. [1](#0-0) 

`_voteCommon` does allow an operator to amend their own vote before quorum by decrementing the old `voteCount` and incrementing the new one: [2](#0-1) 

**Phase 2 — finalization.** The instant `voteCounts[voteKey] >= operatorThresholds[VoteType.ValueTransfer]`, `closedValueTransferVotes[_requestNonce] = true` is written and the function returns `true`, causing the caller (`handleKLAYTransfer` / `handleERC20Transfer`) to immediately execute the transfer with whatever parameters were in the winning calldata: [3](#0-2) [4](#0-3) 

**No correction path after quorum.** Once `closedValueTransferVotes[_requestNonce] = true`, the guard at line 107 permanently blocks every future call for that nonce — including a corrective call with the right parameters:

```
require(!closedValueTransferVotes[_requestNonce], "closed vote");
```

There is no owner function, no emergency function, and no admin path to reset `closedValueTransferVotes[N]` for a specific nonce. The contract exposes no such method.

**`lowerHandleNonce` seals the nonce permanently.** After execution, `_updateHandleNonce` advances `lowerHandleNonce` and deletes `handleNoncesToBlockNums[N]`. Once `lowerHandleNonce > N`, `_lowerHandleNonceCheck` reverts with `"removed vote"` on any future attempt: [5](#0-4) 

**VT recovery is also blocked.** `valueTransferRecovery.updateRecoveryHintFromTo` reads `RecoveryBlockNumber()` from the destination bridge to determine where to start scanning: [6](#0-5) 

`recoveryBlockNumber` is updated from `handleNoncesToBlockNums[i]` — the `_requestedBlockNumber` submitted by the operator. If that value was wrong, the recovery scan starts from the wrong block. More critically, `isHandledEvent` checks `HandleNoncesToBlockNums(nil, ev.GetRequestNonce())` and skips any nonce for which `blk > 0`: [7](#0-6) 

Because the nonce was already "handled" (with wrong parameters), the recovery loop skips it entirely and the correct transfer is never re-submitted.

---

### Impact Explanation

| Corrupted value | Effect |
|---|---|
| Wrong `_to` | Bridged KAIA / ERC20 / ERC721 transferred to wrong address; original user loses funds permanently |
| Wrong `_value` | Wrong amount minted or transferred; bridge reserve accounting broken |
| Wrong `_tokenAddress` | Wrong token minted/transferred; counterpart token mapping violated |
| Wrong `_requestTxHash` | Wrong source tx marked handled; `handledRequestTx` record is permanently incorrect |
| Wrong `_requestedBlockNumber` | `recoveryBlockNumber` set incorrectly; VT recovery scans from wrong block, missing legitimate pending events |

All of these fall within the allowed impact: **unauthorized transfer / mint of KAIA or bridged assets**.

---

### Likelihood Explanation

- **Default threshold = 1** (set in constructor): a single operator submitting wrong parameters immediately executes the wrong transfer with zero opportunity to correct. This is the production default. [8](#0-7) 

- **Threshold > 1**: requires multiple operators to submit identical wrong calldata before any operator corrects. The `_voteCommon` amendment mechanism only helps if an operator catches the mistake *before* the quorum-reaching call lands.

The Go-side bridge manager (`node/sc/bridge_manager.go`) constructs and submits `handleKLAYTransfer` / `handleERC20Transfer` calls automatically from on-chain event data. A bug in event parsing, a reorg that changes event parameters, or a misconfigured counterpart token mapping can silently produce wrong calldata that is submitted without human review. [9](#0-8) 

---

### Recommendation

1. **Add an owner-controlled reset function** that clears `closedValueTransferVotes[_requestNonce]` and `handleNoncesToBlockNums[_requestNonce]` for a specific nonce, allowing operators to re-vote with correct parameters before `lowerHandleNonce` advances past it.

2. **Validate parameters against the source-chain event hash** before executing: store a commitment (e.g., `keccak256(abi.encode(_requestTxHash, _from, _to, _tokenAddress, _value, _requestedNonce))`) at vote-close time and verify it matches the on-chain `RequestValueTransfer` log before releasing funds.

3. **Separate vote-close from fund release** with a time-lock or a two-step finalization, giving operators a window to detect and correct wrong-parameter quorums before assets move.

---

### Proof of Concept

```
Setup: Bridge deployed with default threshold = 1.
       Bridge holds 100 KAIA.
       Legitimate source-chain event: nonce=5, to=Alice, value=10 KAIA.

Step 1: Operator calls handleKLAYTransfer(txHash, from, Bob /*wrong*/, 10, 5, blockNum, "")
        → _voteValueTransfer(5): keccak256(msg.data) reaches threshold 1
        → closedValueTransferVotes[5] = true
        → handleNoncesToBlockNums[5] = blockNum
        → 10 KAIA transferred to Bob (wrong recipient)

Step 2: Operator realises mistake, calls handleKLAYTransfer(txHash, from, Alice /*correct*/, 10, 5, blockNum, "")
        → _voteValueTransfer(5): require(!closedValueTransferVotes[5]) REVERTS with "closed vote"

Step 3: _updateHandleNonce(5) advances lowerHandleNonce to 6.
        Future call: _lowerHandleNonceCheck(5) REVERTS with "removed vote".

Step 4: VT recovery reads RecoveryBlockNumber() = blockNum (set from wrong handle).
        isHandledEvent checks HandleNoncesToBlockNums(nil, 5) → blk > 0 → skips nonce 5.
        Alice never receives her 10 KAIA. Loss is permanent without a contract upgrade.
``` [10](#0-9) [11](#0-10) [7](#0-6)

    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }

    // _updateHandleNonce increases lower and upper handle nonce after the _requestedNonce is handled.
    function _updateHandleNonce(uint64 _requestedNonce) internal {
        if (_requestedNonce > upperHandleNonce) {
            upperHandleNonce = _requestedNonce;
        }

        uint64 limit = lowerHandleNonce + 200;
        if (limit > upperHandleNonce) {
            limit = upperHandleNonce;
        }

        uint64 i;
        for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
            recoveryBlockNumber = handleNoncesToBlockNums[i];
            delete handleNoncesToBlockNums[i];
            delete closedValueTransferVotes[i];
        }
        lowerHandleNonce = i;
    }

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
}
