### Title
Race between `consume_stop_state`/`restore_unreviewed_stop_state` and a concurrent `UserPromptSubmit` re-baseline lets a reviewed-pending commit permanently bypass Stop-hook security review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`restore_unreviewed_stop_state` restores `touched_paths` unconditionally after a transient Stop-hook failure but only restores `baseline_sha` `if baseline_sha and not state.get("baseline_sha")`. If a concurrent `UserPromptSubmit` (UPS) fires between `consume_stop_state`'s clearing of `touched_paths` and the Stop hook's later `restore_unreviewed_stop_state` call, UPS can already have advanced `baseline_sha` past a dangerous, already-committed change before the restore runs. Because the restore only fills in an *empty* baseline, it cannot undo the wrongly-advanced one, so the next Stop review diffs against a baseline that already contains the dangerous file, silently dropping it from the review set even though `touched_paths` still lists it.

### Finding Description
The relevant state machine:
- `consume_stop_state` (diffstate.py:74-113) snapshots and clears `touched_paths` under lock the moment Stop begins, but leaves `baseline_sha` untouched in state.
- `handle_user_prompt_submit` (security_reminder_hook.py:486-503) only preserves the *existing* baseline (skips re-capture) `if state.get("touched_paths") and state.get("baseline_sha")` — i.e. it depends on `touched_paths` still being non-empty on disk.
- If the asyncRewake Stop hook for turn N has already run `consume_stop_state` (clearing `touched_paths` to `[]`) but hasn't yet failed/exited, and the user's next turn's UPS races in during that window, UPS sees `touched_paths == []` and takes the "capture new baseline" branch, calling `capture_git_baseline` (`git stash create`, diffstate.py:163-204). If the dangerous file `X` was already committed during turn N (via Bash/git), this new baseline (`B2`) already contains `X`'s content.
- Stop then hits a transient failure (`api.anthropic.com` unreachable, or an LLM HTTP error) and calls `restore_unreviewed_stop_state(session_id, touched_paths=[X], snap_baseline=B1)` (diffstate.py:116-137, called from security_reminder_hook.py:1784-1786 and :1949-1951). Because `state["baseline_sha"]` is already `B2` (non-empty), the guard at diffstate.py:135-136 (`if baseline_sha and not state.get("baseline_sha")`) is false, so `B1` is discarded and `B2` remains.
- The next Stop fire runs `compute_v2_review_set(cwd, baseline_sha=B2, ...)` (diffstate.py:353-438). `changed_since = _git_name_only(repo, B2)` shows no diff for `X` (its content is identical to `B2`, since `B2` was captured after `X`'s commit). `review_set = dirty_now & changed_since` therefore excludes `X` even though it is present in the restored `touched_paths` — the intersection logic (diffstate.py:417-426) has no fallback for "path is in touched_paths but not in changed_since," so `X` is silently skipped from the LLM review.
- This breaks the intended invariant that the review set stays bound to the correct baseline and touched paths: `touched_paths` says "review this," `baseline_sha` says "this is old," and the latter wins.

### Impact Explanation
The dangerous change in `X` is never sent to the Stop-hook LLM security reviewer, so vulnerability findings that should have blocked/continued the agent's turn (`sys.exit(2)` with guidance) are silently suppressed. This is a logic-level bypass of a required security guard (the Stop hook's diff-based review), matching the "Logic-level service disruption caused by bypassing a required guard or misbinding security state" impact category — a security control degrades to a no-op for the specific commit that triggered the race, without any error or user-visible signal.

### Likelihood Explanation
This requires no elevated privilege — only ordinary Claude Code usage: a turn that commits a file via Bash/git, a transient Stop-hook failure (network hiccup, Anthropic HTTP error — both explicitly handled and thus not rare), and a fast-follow next prompt (already a documented race target elsewhere in this same file, e.g. the "asyncRewake" comments throughout `security_reminder_hook.py` and `diffstate.py` acknowledging this class of race). The window is narrow but the code base explicitly builds machinery (`consume_stop_state` + `restore_unreviewed_stop_state`) to guard exactly this race, showing it's a recognized and reachable scenario; this particular gap (conditional baseline restore) is not covered by that machinery.

### Recommendation
Make `restore_unreviewed_stop_state` unconditionally roll back `baseline_sha` to `min` (i.e., the older/pre-turn one, `snap_baseline`) whenever it is older than the current `state["baseline_sha"]` (ancestor check via `_is_ancestor`), rather than only restoring when the field is empty. Alternatively, track a monotonic "oldest unreviewed baseline" separately from the "latest capture" baseline so a racing UPS can never mask a still-unreviewed commit, and only advance the effective review baseline once `touched_paths` has actually been drained by a successful (non-`restore`) Stop pass.

```python
def consume_stop_state(session_id):
    """Atomically snapshot all state the Stop hook needs and clear touched_paths.

    The Stop hook is asyncRewake — it runs in the background after Claude's
    turn ends. The user can submit a new prompt before this hook finishes its
    initial state read. Telemetry showed a meaningful share of would-be reviews lost when
    the next turn's UPS wiped touched_paths before Stop read it.

    Single locked read-then-clear closes that window: PostToolUse appends
    after this clear go into the next snapshot; UPS overwrites of baseline_sha
    after this snapshot are invisible to this Stop fire.
    """
    import time as _time
    now = _time.time()

    def _snap(state):
        fire_ts = state.get("stop_hook_fire_count_ts", 0)
        expired = (now - fire_ts) > STOP_LOOP_STATE_TTL_SEC
        findings_ts = state.get("previous_findings_ts", fire_ts)
        findings_expired = (now - findings_ts) > PREVIOUS_FINDINGS_TTL_SEC
        snap = {
            "touched_paths": list(state.get("touched_paths", [])),
            "baseline_sha": state.get("baseline_sha"),
            "head_at_capture": state.get("head_at_capture"),
            "untracked_at_baseline": (
                dict(state["untracked_at_baseline"])
                if isinstance(state.get("untracked_at_baseline"), dict) else {}
            ),
            "fire_count": 0 if expired else state.get("stop_hook_fire_count", 0),
            "fire_count_expired": expired and state.get("stop_hook_fire_count", 0) > 0,
            "previous_findings": [] if findings_expired else list(state.get("previous_findings", [])),
        }
        state["touched_paths"] = []
        return snap

    return with_locked_state(session_id, _snap) or {
        "touched_paths": [], "baseline_sha": None, "head_at_capture": None,
        "untracked_at_baseline": {},
        "fire_count": 0, "fire_count_expired": False, "previous_findings": [],
    }
```

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```
