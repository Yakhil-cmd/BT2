### Title
Missing Content Validation of Peer-Supplied Staking Info During Fast Sync Enables Corrupted Reward Distribution — (`datasync/downloader/queue.go`)

### Summary

`queue.DeliverStakingInfos` accepts peer-supplied `P2PStakingInfo` objects with a deliberately no-op validate function (marked `TODO-Kaia-Snapsync update validation logic`). Unlike `DeliverBodies` and `DeliverReceipts`, which cryptographically verify content against the block header, staking info is written to the persistent database without any content check. A malicious registered peer can inject crafted `CouncilRewardAddrs`, `CouncilStakingAmounts`, `KEFAddr`, and `KIFAddr` values that are then used verbatim for KAIA reward distribution and proposer selection on pre-Kaia blocks.

### Finding Description

During fast sync the downloader fetches staking information from peers via `fetchStakingInfos`. The response handler `handleStakingInfoMsg` decodes the raw P2P message and forwards it to `pm.downloader.DeliverStakingInfos`, which routes it through `queue.DeliverStakingInfos`. [1](#0-0) 

The `validate` closure inside `DeliverStakingInfos` unconditionally returns `nil`:

```go
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
```

Compare this to the sibling functions for bodies and receipts, which verify content against the committed block header: [2](#0-1) [3](#0-2) 

After passing the no-op validation, the staking info is placed into `fetchResult.StakingInfo`. In `commitFastSyncData` and `commitPivotBlock`, it is written directly to the persistent database: [4](#0-3) [5](#0-4) 

The same unvalidated write path exists in `SyncStakingInfo`, where only the `BlockNum` field is checked against the expected sequence — the actual content (addresses, amounts) is never verified: [6](#0-5) 

For pre-Kaia blocks, `GetStakingInfo` reads from this database before falling back to state: [7](#0-6) 

The `P2PStakingInfo` struct carries all fields that govern reward distribution: [8](#0-7) 

`ToStakingInfo` converts the peer-supplied struct directly into a `StakingInfo` with no sanitization: [9](#0-8) 

### Impact Explanation

The `StakingInfo` read from the database is consumed by the reward module's `FinalizeState` to distribute KAIA block rewards: [10](#0-9) 

Specifically, `CouncilRewardAddrs` determines where per-validator KAIA rewards are sent, `CouncilStakingAmounts` determines the proportional split of staking rewards, and `KEFAddr`/`KIFAddr` determine where treasury fund portions (KEF, KIF) are sent: [11](#0-10) 

A malicious peer can craft a `P2PStakingInfo` response that:
- Replaces `CouncilRewardAddrs` with attacker-controlled addresses → KAIA block rewards are minted to the attacker
- Zeroes `CouncilStakingAmounts` for legitimate validators → staking rewards are redirected to the proposer or attacker
- Replaces `KEFAddr`/`KIFAddr` with attacker addresses → treasury fund distributions are stolen

The corrupted values are written to the `"stakingInfo"` key-value store and cached in memory, persisting across restarts.

### Likelihood Explanation

The trigger requires:
1. The node is performing fast sync (the default sync mode for new nodes)
2. A malicious peer is registered with the node (any valid P2P peer that passes the handshake)
3. The chain is operating in the pre-Kaia hardfork era, or the node is syncing pre-Kaia historical blocks

Condition 2 is achievable by any network participant who can establish a P2P connection. Fast sync is the default for new nodes joining the network. The attack is automatic — no admin action is required on the victim node. The `TODO` comment in the validate function confirms this is a known gap, not an intentional design choice.

### Recommendation

Implement content validation in `queue.DeliverStakingInfos` analogous to `DeliverBodies` and `DeliverReceipts`. The staking info for a block should be derived from the canonical state root of that block's header. The validate function should:

1. Re-derive the staking info from the block's state root using `getFromStateByNumber(header.Number.Uint64())`
2. Compare the peer-supplied `CouncilNodeAddrs`, `CouncilRewardAddrs`, `CouncilStakingAmounts`, `KEFAddr`, and `KIFAddr` against the locally derived values
3. Reject the delivery if any field mismatches

```go
validate := func(index int, header *types.Header) error {
    expected, err := stakingModule.GetStakingInfo(header.Number.Uint64())
    if err != nil {
        return err
    }
    supplied := staking.ToStakingInfo(stakingInfoList[index])
    if !reflect.DeepEqual(expected.RewardAddrs, supplied.RewardAddrs) ||
       !reflect.DeepEqual(expected.StakingAmounts, supplied.StakingAmounts) ||
       expected.KEFAddr != supplied.KEFAddr ||
       expected.KIFAddr != supplied.KIFAddr {
        return errInvalidStakingInfo
    }
    return nil
}
```

### Proof of Concept

1. Attacker establishes a valid P2P connection to a victim node performing fast sync.
2. Victim node sends a `StakingInfoRequestMsg` for block hashes during `fetchStakingInfos`.
3. Attacker responds with a `StakingInfoMsg` containing a crafted `P2PStakingInfo`:
   ```
   P2PStakingInfo{
       BlockNum:            <requested block number>,
       CouncilNodeAddrs:    <legitimate node IDs>,
       CouncilRewardAddrs:  [attacker_address, attacker_address, ...],
       CouncilStakingAmounts: [999999999, 999999999, ...],
       KEFAddr:             attacker_address,
       KIFAddr:             attacker_address,
   }
   ```
4. `handleStakingInfoMsg` decodes and forwards to `DeliverStakingInfos`.
5. `queue.DeliverStakingInfos` accepts without validation (no-op `validate`).
6. `commitFastSyncData` calls `PutStakingInfoToDB`, writing the crafted data to the `"stakingInfo"` database.
7. On subsequent calls to `GetStakingInfo` for pre-Kaia blocks, the corrupted entry is returned from DB.
8. `FinalizeState` distributes KAIA block rewards to `attacker_address` instead of legitimate validators and treasury funds. [12](#0-11) [13](#0-12) [14](#0-13)

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
