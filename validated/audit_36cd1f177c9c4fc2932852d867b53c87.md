### Title
Api::CCMenuController bypasses ApiClient stack scoping, letting a stack-scoped token read any stack's build status - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::ApiClient` supports scoping a token to a single stack via the `stack_id` column, and `Api::BaseController` enforces that scope by filtering `stacks` before resolving `params[:stack_id]` [1](#0-0) . `Api::CCMenuController`, however, overrides `stack` to bypass this filter entirely and resolve any stack id directly against the full `Stack` table, while still only requiring the generic `read:stack` permission [2](#0-1) .

### Finding Description
The binding that should hold is: `stack a token authorizes == stack the endpoint touches`.

- `ApiClient#stack_id` is meant to restrict a token to one stack: `stacks` in `BaseController` returns `Stack.where(id: current_api_client.stack_id)` when the client is stack-scoped, and only falls back to `Stack.all` for unscoped clients [3](#0-2) . This is exactly the scoping validated by the test "an api client scoped to a stack will only see that one stack" using the `here_come_the_walrus` fixture [4](#0-3) .
- Every other `Api::*` controller that needs a stack calls the inherited `stack` method, which goes through this scoped `stacks` collection: `@stack ||= stacks.from_param!(params[:stack_id])` [5](#0-4) .
- `Api::CCMenuController` instead defines its own `stack` method that ignores `current_api_client` entirely: `@stack ||= Stack.from_param!(params[:stack_id])` [6](#0-5) .
- The controller still authenticates via a normal `ApiClient` token (either query-string `token` param or Basic Auth) and checks only the generic, non-stack-specific `require_permission :read, :stack` [7](#0-6) [8](#0-7) .

So a caller holding a legitimately-issued `read:stack` token that was scoped to stack A (`stack_id = A`) can request `GET /api/1/stacks/:stack_id/ccmenu.xml` with `:stack_id` set to any other stack B and receive B's build/deploy status, bypassing the per-token stack restriction that every other API endpoint enforces.

### Impact Explanation
This breaks the "stack a token authorizes vs. stack it touches" binding and grants unauthorized cross-stack read access to stack state (build name, last build status/label/time, lock state) for every stack in the installation, using a token that was only meant to expose one stack's CI status widget. This matches the High-impact category "unauthenticated read of stack state" via authorization-scope confusion, since the requester is not authorized for the stacks it can read.

### Likelihood Explanation
Any holder of a stack-scoped, `read:stack`-only `ApiClient` token (the exact kind of low-privilege token the CCMenu integration is designed to hand out, e.g. embedded in a CI dashboard) can trigger this by simply changing the `stack_id` in the URL — no additional privilege, secret, or write access is required beyond the token itself, and the code path (`ccmenu_controller.rb#stack`) is directly reachable and unconditionally bypasses scoping.

### Recommendation
Remove the `stack` override in `Api::CCMenuController` (or make it consistent with `BaseController#stack`) so it resolves the stack through the scoped `stacks` collection, e.g. `@stack ||= stacks.from_param!(params[:stack_id])`, ensuring `current_api_client.stack_id` is honored the same way it is in every other API controller.

### Proof of Concept
1. Create (or obtain) an `ApiClient` with `permissions: ['read:stack']` and `stack_id` set to Stack A (mirrors how `CCMenuUrlController` mints per-stack tokens for the CI widget).
2. As that client, issue `GET /api/1/stacks/:B/ccmenu.xml?token=<clients-token>` where `B` is a different stack's `to_param`.
3. Observe that `Api::CCMenuController#show` renders stack B's project XML (`name`, `lastBuildStatus`, etc.) even though the token is scoped only to stack A — compare with the same request against `Api::StacksController#show`, which is correctly restricted to `stacks.from_param!` and would 404/403 for stack B under the same scoped token.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
