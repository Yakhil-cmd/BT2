### Title
Cross-organization stack mutation via `repository.owner.login` / `repository.full_name` mismatch in webhook signature verification - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the webhook secret) used to authenticate a webhook using `repository.owner.login`, while the handlers that actually mutate data (e.g. `PushHandler`) resolve the target `Stack` using the independent `repository.full_name` field from the same attacker-supplied JSON body. Because nothing checks that these two fields refer to the same organization, an attacker can pick an organization `X` that is configured on the Shipit instance with no `webhook_secret` (which makes signature verification succeed unconditionally) while naming a real repository belonging to a different organization `Y` in `repository.full_name`, causing `Y`'s stack to be synced/mutated with no valid signature for `Y`.

### Finding Description
Broken binding (claimed and confirmed): `organization_whose_secret_verified_bytes(X) == organization_owning_mutated_stack(Y)`. The code never enforces this equality.

- `repository_owner` is read directly from the untrusted JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0)  and used to select the `GitHubApp`: `github_app = Shipit.github(organization: repository_owner)` then `github_app.verify_webhook_signature(...)` [2](#0-1) .
- In `GitHubApp#verify_webhook_signature`, if the selected org's config has no `webhook_secret`, verification is **unconditionally true**: `return true unless webhook_secret` [3](#0-2) . `webhook_secret` per organization is explicitly documented/configured as optional (`webhook_secret: # nil`) in the multi-org schema [4](#0-3)  and `config/secrets.development.shopify.yml`.
- `Shipit.github(organization:)` looks up the config purely by the organization key supplied, raising `GithubOrganizationUnknown` only if that key is missing entirely — it does not validate that the org matches the repository being acted on [5](#0-4) .
- After signature "verification" passes, `WebhooksController#create` re-parses the same raw body and dispatches to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [6](#0-5) .
- `Handler#stacks` resolves the target `Stack` using a **separate** field, `repository.full_name`, taken straight from the payload with no cross-check against `repository.owner.login`: `Repository.from_github_repo_name(repository_name)` where `repository_name = payload.dig('repository', 'full_name')` [7](#0-6) .
- `PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack on the target branch [8](#0-7) , which enqueues `GithubSyncJob.perform_later(stack_id: id, ...)` [9](#0-8) . `GithubSyncJob#perform` then fetches commits via the GitHub API and appends them to the stack's commit history [10](#0-9) .
- `PushHandler`'s `ExplicitParameters` schema only requires `ref` and `after` — it never requires or validates `repository.full_name` against `repository.owner.login` [11](#0-10) .

**Attacker request**: `POST /webhooks` with header `X-Github-Event: push` and a JSON body such as:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": { "owner": { "login": "X" }, "full_name": "Y/real-repo" }
}
```
where `X` is an organization configured in `secrets.github` on this instance with `webhook_secret` unset/nil, and `Y/real-repo` is a real repository with a registered `Stack` belonging to a different organization `Y` (which may itself have a properly configured `webhook_secret`). No valid `X-Hub-Signature` for `Y` is required or even checked, since `X`'s `GitHubApp` unconditionally reports `verified = true`.

**Why existing guards fail**: `drop_unhandled_event` only screens by event type, not payload content. `verify_signature` operates purely on `repository.owner.login`, never on `repository.full_name`. `ExplicitParameters` schemas validate types/presence but do not correlate fields across the payload. `Repository`/`Stack` model validations only constrain format of stored values, not which org triggered the write. There is no `require_permission!`/`current_user` check on this controller by design (it's a webhook endpoint authenticated solely by HMAC), so once `verified` is (incorrectly) true, the handler pipeline runs unchecked against whatever `repository.full_name` says.

### Impact Explanation
An unauthenticated attacker can trigger `GithubSyncJob` (and, by the same mechanism, any other push/status/check_suite/pull_request handler that reads `repository.full_name`) for an arbitrary, real, unrelated organization's `Stack`, as long as the Shipit instance is configured with the multi-organization `github:` schema and at least one configured organization lacks a `webhook_secret`. This is a payload nominally "from" org `X` mutating org `Y`'s stack state (triggering commit ingestion/sync, potentially cascading into deploys depending on stack configuration such as `continuous_deployment`), which matches the Critical category "a payload for one repository mutating another's stack." The attack is fully repeatable against any repository/stack pair on the instance and scales to the number of stacks resolvable via `Repository.from_github_repo_name`.

### Likelihood Explanation
Requires the host to use the multi-organization GitHub App config schema (`github: { OrgOne: {...}, OrgTwo: {...} }`, documented and tested in this repo, e.g. `test/dummy/config/secrets_double_github_app.yml`) and at least one configured organization with `webhook_secret` unset — an explicitly supported, "optional" configuration per `docs/setup.md`. Given that precondition, exploitation costs nothing: a single unauthenticated HTTP POST with attacker-chosen JSON, no valid signature, no credentials, no GitHub account interaction required. It is deterministic and repeatable.

### Recommendation
Enforce that the organization used for signature verification matches the organization embedded in `repository.full_name` (or, more robustly, resolve the target `Stack`/`Repository` first, then verify the signature using that resolved repository's owning organization's `GitHubApp`, rejecting the request if they diverge). Alternatively, require every configured organization to have a non-nil `webhook_secret` and refuse to boot/serve webhooks for organizations missing one.

### Proof of Concept
Minitest under `test/controllers/webhooks_controller_test.rb` style:
```ruby
test "cross-organization stack mutation via mismatched owner.login and repository.full_name" do
  # Configure Shipit with two orgs, "OrgOne" (no webhook_secret) and "OrgTwo" (real, secured stack)
  Shipit.stubs(:github_app_config).with('OrgOne').returns({}) # no webhook_secret
  target_stack = shipit_stacks(:shipit) # belongs to "OrgTwo/cyclimse" for example

  request.headers['X-Github-Event'] = 'push'
  payload = {
    ref: "refs/heads/#{target_stack.branch}",
    after: "deadbeef",
    repository: { owner: { login: 'OrgOne' }, full_name: target_stack.repository.github_repo_name }
  }.to_json

  # No X-Hub-Signature header set / an invalid one — verification for OrgOne passes unconditionally
  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: target_stack.id, expected_head_sha: 'deadbeef']) do
    post :create, body: payload, as: :json
  end
  assert_response :ok
end
```
Assertions establishing both sides of the equality:
- Left side: `Shipit.github(organization: 'OrgOne').verify_webhook_signature(...)` returns `true` with no `webhook_secret` configured, regardless of the actual bytes/signature sent.
- Right side: `GithubSyncJob` is enqueued with `stack_id: target_stack.id`, where `target_stack` belongs to `OrgTwo` — proving the mutated stack's organization differs from the organization that "authenticated" the request.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
