### Title
RAY value overflow in interest accrual permanently freezes a market — all entrypoints panic before touching state - (File: contracts/pool/src/interest.rs)

### Summary
The pool computes accrued values as `shares * index` in RAY with `i128`/`I256` multiply-divide that panics with `MathOverflow` when the RAY-scaled market value exceeds `i128::MAX`. Because every state-changing verb runs `global_sync` accrual first, once a market's `supplied * supply_index` (or the borrow side) crosses the `i128` domain the entire market freezes permanently: `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `update_indexes`, `claim_revenue`, and `recapitalize` all revert. This is an integer-overflow analog of CVE-2014-4607 mapped onto XOXNO's RAY share/index arithmetic.

### Finding Description
`accrue_chunk` calls `accrue_step` with `cache.supplied()`, `cache.borrowed()`, and both indexes; inside the rate engine the compounded value is computed via `Ray::mul` → `mul_div_half_up`/`mul_div_floor` in `common/src/math/fp_core.rs`, which widens to `I256` but still panics with `GenericError::MathOverflow` when the *result* does not fit `i128` [1](#0-0) [2](#0-1) . `global_sync` runs this before any operation on the market [3](#0-2) .

The docs themselves acknowledge the cliff: accrued values "must independently fit the RAY domain; valid caps and bounded indexes do not guarantee that future accrual fits. Value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" [4](#0-3) . The index caps (`MAX_BORROW_INDEX_RAY`, `MAX_SUPPLY_INDEX_RAY`) do not protect against this because the panic happens on `shares * index`, not on the index value — the checked-in harness test proves the market dies *before* the cap engages [5](#0-4) .

Notably there is no graceful path: `update_supply_index` caps the index, but `scaled_to_original`/`supplied.mul(old_index)` still panics, and `apply_bad_debt_to_supply_index` — the only code that could shrink `supplied`'s value — is itself reached only through verbs that accrue first [6](#0-5) .

### Impact Explanation
Permanent freezing of all funds in the affected (hub, token) book. Suppliers cannot withdraw, borrowers cannot repay (so their collateral in other markets is also effectively locked against that debt), liquidations cannot run, and revenue cannot be claimed. The panic is a host trap (`Error(Contract, #33)` / `MathOverflow`), so no partial state survives to recover. This matches the "permanent freezing of funds" impact class.

### Likelihood Explanation
A single unprivileged address can drive a market into the corner: supply up to the admitted cap (≈170 billion whole tokens at 18 decimals, `i128::MAX / 10^(27-d)` [7](#0-6) ), borrow to ~98% utilization, and let millisecond-chunked compounding grow `borrowed * borrow_index` until it exits `i128`. The harness test reaches the cliff on the XLM curve well before the index ceiling, and from then on `update_indexes`, `withdraw`, and `repay` all fail with `MATH_OVERFLOW` [8](#0-7) . Likelihood is gated by capital requirements (a whale-scale supply at the cap) and sustained high utilization, but requires no privilege, no leaked key, and no oracle manipulation — only `supply` and `borrow` calls plus time. Medium.

### Recommendation
Make accrual saturate instead of panic: use the existing `try_mul_div_*` / `mul_div_floor_saturating` paths (already used for `protocol_fee_shares` headroom) when computing `supplied * index` and `borrowed * index`, clamping the RAY value at a representable maximum so the market stays operable. Alternatively, enforce a market-level cap on `supplied` in RAY terms (`supplied <= i128::MAX / MAX_SUPPLY_INDEX_RAY`) inside `supply`/share-mint so the value domain can never be exceeded, and add the same bound on the borrow side at debt-mint time. A dedicated emergency path that skips accrual for `clean_bad_debt`/`recapitalize` would also bound the freeze.

### Proof of Concept
The checked-in test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the exploit end-to-end [9](#0-8) :

1. Attacker calls `supply(BIG18, 1e9 * 10^18 units)` after caps are lifted to the admitted maximum, then `borrow(BIG18, 98% of supply)` against separate collateral.
2. Advance ledger time; each `update_indexes` call compounds `borrowed * borrow_index` in `accrue_chunk`.
3. Once the RAY value exceeds `i128::MAX`, `accrue_step` panics with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`.
4. Thereafter `try_withdraw_raw`, `try_repay`, `liquidate`, `flash_loan`, and `claim_revenue` on `BIG18` all revert with `MATH_OVERFLOW`, since `global_sync` runs first — permanently freezing the ~1e27-unit pool balance.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
