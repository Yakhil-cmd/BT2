### Title
Borrow-index growth overflows `i128` before the index cap engages, permanently freezing a market - (File: common/src/rates/index.rs)

### Summary
The analog of the CVE's "append without bounds checking → overflow" class is `update_borrow_index` in `common/src/rates/index.rs`: it multiplies the old index by the interest factor *before* clamping to `MAX_BORROW_INDEX_RAY`, and the same accrual path multiplies total scaled debt by the new index in `scaled_to_original`. At a sufficiently large market, `borrowed × new_index` overflows `i128` and panics while the index itself is still below the cap — so the cap never engages and every subsequent accrual reverts. Since every controller verb accrues first, the market becomes permanently unusable: no withdraw, repay, or liquidation.

### Finding Description
`update_borrow_index` performs the growth multiply unconditionally, then clamps: `let new_index = old_index.mul(env, interest_factor); if new_index.raw() > MAX_BORROW_INDEX_RAY { return Ray::from(MAX_BORROW_INDEX_RAY); }`. [1](#0-0)  During accrual, `calculate_supplier_rewards` also computes `borrowed.mul(env, new_borrow_index)` (the `scaled_to_original` product `scaled × index`). [2](#0-1) [3](#0-2)  `MAX_BORROW_INDEX_RAY = 1e36` is roughly `170×` the maximum value `Ray::from_asset` can represent (`i128::MAX / RAY`), so a market near the representable balance ceiling hits `scaled × index > i128::MAX` while `index` is still far below `1e36`. [4](#0-3)  The panic is raised as `GenericError::MathOverflow` inside `Ray::mul`. Accrual runs unconditionally at the top of every flow via `global_sync`, which chunks elapsed time and calls `accrue_chunk` → `accrue_step`. [5](#0-4) [6](#0-5) 

The repository's own harness test demonstrates the failure end-to-end: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` asserts `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all revert with `MATH_OVERFLOW` while `last.borrow_index < MAX_BORROW_INDEX_RAY` ("the index cap did not engage before the value overflow… the market is frozen: no repay, no withdraw, no liquidation"). [7](#0-6) 

### Impact Explanation
Permanent freezing of funds for every supplier and borrower in the affected market. Once `borrowed_scaled × borrow_index` overflows `i128`, accrual panics before any state update, and because `global_sync` precedes every verb, `withdraw`, `repay`, `liquidate`, and `update_indexes` itself all revert forever — including governance-driven recovery paths that must touch the market. This is permanent freezing of user funds, satisfying the acceptance criteria.

### Likelihood Explanation
Any unprivileged address can trigger the state via `update_indexes` (or any verb), since accrual is permissionless and automatic. The preconditions are demanding but unprivileged-reachable: a market whose scaled debt is within ~170× of the representable ceiling at sustained high utilization on a steep rate curve — achievable by a whale or a coordinated supply/borrow position, or simply by organic growth in a large high-utilization market over time. The `mul` call does widen to `I256` internally for `mul_div`-style ops, but `scaled.mul(env, index)` is a plain `Ray` multiply that panics on `i128` overflow, as the test confirms. Because an attacker must fund a very large position and wait for index drift, this is Medium severity rather than High.

### Recommendation
Clamp before multiplying: in `update_borrow_index`, detect when `old_index.mul(interest_factor)` would exceed the value ceiling and clamp the *index* first (e.g., compute via `mul_div_floor_saturating` and cap at `MAX_BORROW_INDEX_RAY` before the raw multiply), and in `accrue_step`/`calculate_supplier_rewards` use a saturating or widened (`I256`) computation for `borrowed × new_index` so the index cap can engage instead of the `i128` ceiling being hit first. The index cap should be set at or below `i128::MAX / max_scaled_debt` so it always binds before the arithmetic ceiling.

### Proof of Concept
The in-repo test is the PoC: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360` supplies `BILLION × 10^18` of an 18-decimal asset, borrows ~98% of it against a large collateral position (caps lifted via `lift_caps`, max utilization disabled), then advances `YEAR_SECS` per iteration calling `try_update_indexes_for` until it reverts with `MATH_OVERFLOW`. It then asserts `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` both revert with `MATH_OVERFLOW` while `last.borrow_index < MAX_BORROW_INDEX_RAY`, proving the overflow — not the cap — is the failure and that the freeze is permanent.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
