### Title
Pre-permissionless `verifySeals` quorum formula diverges from consensus-core quorum at CommitteeSize < 4 with qualifiedLen > CommitteeSize, enabling a single malicious proposer to produce a block accepted by sync nodes but rejected by live consensus — (`blockchain/block_validator.go`)

---

### Summary

When `CommitteeSize=2` and `qualifiedLen>2` (pre-permissionless, pre-Randao), `verifySeals` computes the required seal count as `2*F(qualifiedLen, committeeSize)+1 = 1`, while the consensus core computes it as `calcQuorumSize(qualifiedLen, committeeSize) = 2`. A single malicious proposer can craft a block carrying only their own committed seal, which passes `verifySeals` on every sync/import node but would never have been finalized by the live consensus core. This creates a persistent chain split between syncing nodes and live consensus nodes.

---

`IstanbulSealer.F(_, 10, 2)`: [1](#0-0) 

```
qualifiedLen(10) > committeeSize(2) → ceil(2/3) - 1 = 1 - 1 = 0
threshold = 2*0+1 = 1
```

So `verifySeals` accepts any block with **≥ 1** committed seal from the council.

**`calcQuorumSize` (consensus core, live consensus path)** — `consensus/istanbul/core/core.go` line 81: [2](#0-1) 

```
size = min(10, 2) = 2
2 < 4 → return 2
threshold = 2
```

The live consensus core requires **2** committed seals before finalizing a block.

**`selectRandomCommittee` with CommitteeSize=2** produces exactly `{currProposer, nextDistinctProposer}`: [3](#0-2) 

The committee has 2 members. The consensus core requires both to commit. `verifySeals` requires only 1.

**Root cause:** `verifySeals` deliberately uses the legacy `2f+1` formula to preserve historical header validity, but `calcFaultTolerance(10, 2) = 0` makes `2f+1 = 1`, which is strictly less than `calcQuorumSize(10, 2) = 2`. The two formulas are equivalent only when `effectiveSize ≥ 4`; for `effectiveSize ∈ {2, 3}` with `qualifiedLen > committeeSize`, they diverge. [4](#0-3)

### Impact Explanation

A single malicious proposer (one validator key, no collusion required) can:

1. Produce a block at their assigned slot carrying only their own committed seal.
2. Broadcast it directly to syncing peers via the P2P layer.
3. Every syncing node runs `verifySeals`, which accepts the block (`1 ≥ 1`).
4. Live consensus nodes, which ran `calcQuorumSize` and required 2 seals, never finalized this block; they produced a different block at the same height after a round change.
5. Result: a durable chain split — syncing nodes are on a different canonical chain than live consensus nodes.

This satisfies the required impact: **invalid block acceptance on honest sync nodes causing consensus divergence / chain split**.

---

### Likelihood Explanation

- `CommitteeSize=2` is a valid governance parameter explicitly handled by the code (the `CommitteeSize==1` special-case at line 99 of `getter_context.go` implies values of 2 are expected).
- `qualifiedLen > 2` is the normal operating condition for any real network.
- The attack requires only one malicious or compromised proposer — not majority collusion.
- The pre-permissionless era is historical but sync nodes re-validate all historical blocks on every full sync, so the window is permanent for any node that syncs from genesis.

---

### Recommendation

Replace the `2*F+1` formula in the pre-permissionless branch of `verifySeals` with `calcQuorumSize(qualifiedLen, committeeSize)` (or its equivalent inline), so the sync-time threshold is identical to the live-consensus threshold:

```go
// Before (diverges for effectiveSize < 4 when qualifiedLen > committeeSize):
if validSeal < 2*v.sealer.F(blockNum, qualifiedLen, committeeSize)+1 {

// After (matches calcQuorumSize used by the consensus core):
if validSeal < v.sealer.Quorum(blockNum, qualifiedLen, committeeSize) {
```

`IstanbulSealer.Quorum` already implements `calcQuorumSize` exactly: [5](#0-4)

func selectRandomCommittee(qualified *valset.AddressSet, committeeSize uint64, prevBlockHash common.Hash, currProposer, nextDistinctProposer common.Address) []common.Address {
	qualified = qualified.Copy()
	qualified.Remove(currProposer)
	qualified.Remove(nextDistinctProposer)

	seed := valset.HashToSeedLegacy(prevBlockHash)
	shuffled := qualified.ShuffledListLegacy(seed)
	committee := []common.Address{currProposer, nextDistinctProposer}
	committee = append(committee, shuffled[:committeeSize-2]...)
	return committee
}
