### Title
NULL/undefined object dereference in `is_valid_merkle_proof` when proof is a wrapped object - (File: formula/evaluation.js)

### Summary
The `is_valid_merkle_proof` oscript function in the formula evaluator dereferences `objProof.siblings` without first checking that `objProof` is a non-null object, when the proof argument is a `wrappedObject` (e.g., the result of `json_parse`). This mirrors the GStreamer/Matroska root cause: a pointer/reference obtained from parsed, attacker-controlled input is dereferenced without a null check before use.

### Finding Description
In the `is_valid_merkle_proof` case, the evaluator computes `objProof` from the evaluated `proof_expr` in one of two ways: [1](#0-0) 
- if `proof instanceof wrappedObject`, `objProof = proof.obj` — taken directly from a user-controlled value with no shape/type check.
- if `proof` is a string, `objProof = merkle.deserializeMerkleProof(proof)`, which always returns a well-formed `{root, index, siblings}` object.

Immediately afterward, when `bPostPemCurvesFix` is true, the code accesses `objProof.siblings` without checking that `objProof` is a non-null object: [2](#0-1) 

`wrappedObject` is produced by `json_parse` for any JS value where `typeof json === 'object'` — this includes `null`, since `JSON.parse("null")` yields `null` and `typeof null === 'object'`: [3](#0-2) 

If an AA formula does something like `is_valid_merkle_proof(x, json_parse(trigger.data.proof))` and the trigger data field for `proof` is the JSON literal `null` (or an array, which also is `typeof 'object'` and lacks a `.siblings` property directly comparable, though arrays won't throw on property access — the concrete crash case is `null`), then `proof` becomes `wrappedObject(null)`, so `objProof = null`. The subsequent `objProof.siblings` access at line 1793 throws a `TypeError: Cannot read properties of null (reading 'siblings')`. This throw happens **outside** the `try { ... } catch` block that wraps only the `merkle.verifyMerkleProof` call (lines 1798–1803), so it is an unguarded, uncaught-by-local-code exception during AA trigger/formula evaluation.

### Impact Explanation
AA formula evaluation is part of consensus-critical unit/trigger processing reachable by any unprivileged unit poster who sends a trigger to an AA containing this pattern in its formula. An uncaught exception thrown mid-evaluation of an AA response can cause differing behavior/crash across nodes evaluating the same trigger, leading to node disagreement on AA response validity/stability, or a crash of the evaluating process — a denial-of-service against nodes processing that unit. Since AA definitions are attacker-authored (or an AA author can write such a formula) and triggers are attacker-supplied, this is reachable by an ordinary unit poster/AA author, satisfying "node disagreement on validity or stability" / "network unable to confirm new units" impact criteria.

### Likelihood Explanation
Any AA author can include an `is_valid_merkle_proof(element, json_parse(some_trigger_field))` formula, and any trigger sender can supply `null` for that field. This requires no privileged access, no malicious peer/hub, and no network position — only crafting an oscript formula and a trigger message, both of which are core, expected use paths of the AA subsystem.

### Recommendation
Add an explicit type/null check on `objProof` immediately after it is derived from `proof.obj`, before accessing `.siblings`, e.g.:
```js
if (proof instanceof wrappedObject)
    objProof = proof.obj;
...
if (objProof === null || typeof objProof !== 'object' || Array.isArray(objProof))
    return cb(false);
if (bPostPemCurvesFix) {
    if (!Array.isArray(objProof.siblings) || ...)
        return cb(false);
    ...
}
```
Alternatively, wrap the entire `bPostPemCurvesFix` validation block (and the `objProof.siblings` access) inside the existing `try/catch`, or move the try/catch to start before the siblings check, so any malformed `objProof` shape safely resolves to `res = false` instead of throwing.

### Proof of Concept
1. Deploy an AA with a formula such as:
   `is_valid_merkle_proof('leaf', json_parse(trigger.data.proof))`
2. Send a trigger unit to this AA with `data.proof` equal to the string `"null"`.
3. During evaluation, `json_parse` returns `wrappedObject(null)`; `is_valid_merkle_proof` sets `objProof = proof.obj = null`.
4. Once `bPostPemCurvesFix` is active, the line `!Array.isArray(objProof.siblings)` throws `TypeError: Cannot read properties of null (reading 'siblings')`, which is not caught by the local try/catch, propagating out of formula evaluation during AA response processing.
