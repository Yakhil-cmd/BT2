### Title
Unverified Peer-Supplied `P2PStakingInfo` Written to Staking DB During Fast Sync Corrupts Proposer-Selection and Reward-Distribution State — (`datasync/downloader/downloader.go`)

---

### Summary

During fast sync, peer-supplied `P2PStakingInfo` objects are written directly to the local staking database without any verification that the embedded `CouncilStakingAmounts` match the actual native KAIA balances of the corresponding staking contracts at the claimed block number. A malicious peer can inject fabricated staking amounts, causing the victim node to compute wrong proposer lists and wrong reward distributions for all pre-Kaia-hardfork blocks, producing consensus divergence from honest nodes.

---

### Finding Description

The bug class from the external report is: **accepting an asset-backed account as collateral without verifying the account actually holds the asset**. The Kaia analog is: **accepting a `P2PStakingInfo` message from a peer and persisting its `CouncilStakingAmounts` to the staking DB without verifying those amounts against the on-chain native KAIA balances of the staking contracts**.

**Fast-sync write path — no content verification:**

In `commitFastSyncData`, every `fetchResult` that carries a non-nil `StakingInfo` is written unconditionally:

```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum,
        staking.ToStakingInfo(result.StakingInfo))
}
``` [1](#0-0) 

The same pattern appears in `commitPivotBlock`: [2](#0-1) 

**`SyncStakingInfo` recovery path — only `BlockNum` is checked, not content:**

```go
if d.stakingInfoRecoveryBlocks[0] != stakingInfo.BlockNum {
    logger.Error("failed to receive expected block", ...)
    return
}
d.stakingModule.PutStakingInfoToDB(stakingInfo.BlockNum,
    staking.ToStakingInfo(stakingInfo))
``` [3](#0-2) 

The only guard is a sequence-number check (`BlockNum` matches the expected slot). There is no check that `CouncilStakingAmounts[i]` equals `state.GetBalance(CouncilStakingAddrs[i])` at the claimed block.

**How the DB value is later consumed:**

`GetStakingInfo` for pre-Kaia blocks reads the DB first and returns immediately on a cache hit, bypassing the on-chain state entirely:

```go
if !isKaia {
    if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
        s.stakingInfoCache.Add(sourceNum, si)
        return si, nil   // ← fabricated value returned here
    }
}
``` [4](#0-3) 

The returned `StakingInfo.StakingAmounts` feeds directly into proposer-list generation: [5](#0-4) 

and into staking-reward assignment: [6](#0-5) 

**P2P serving side — a malicious peer can return arbitrary amounts:**

`handleStakingInfoRequestMsg` on the serving peer simply looks up its own DB/state and sends the result with no proof of correctness: [7](#0-6) 

The receiving handler passes the decoded `[]*staking.P2PStakingInfo` straight to the downloader with no further validation: [8](#0-7)

---

### Impact Explanation

The corrupted value is `StakingInfo.StakingAmounts[]` (KAIA units, one entry per validator). This value governs:

1. **Weighted-random proposer selection** — a node with inflated amounts for validator X will compute a different shuffled proposer list than honest nodes, causing it to reject valid blocks proposed by the honest proposer or accept blocks from an unexpected proposer, producing **consensus divergence**.
2. **Staking reward distribution** — `assignStakingRewards` divides the staking-reward budget proportionally to `StakingAmount - minStake`; fabricated amounts redirect KAIA rewards to attacker-controlled reward addresses.

Both effects are scoped to pre-Kaia-hardfork blocks (after the Kaia fork, `GetStakingInfo` reads from state directly and ignores the DB). Any node that fast-syncs against a malicious peer before the Kaia fork block is permanently affected for that historical range.

---

### Likelihood Explanation

Fast sync is the default mode for new nodes joining the network. Any peer that the syncing node connects to can serve fabricated `P2PStakingInfo`. No special privilege is required: the attacker only needs to run a reachable Kaia node and respond to `StakingInfoRequestMsg` with crafted payloads. The `SyncStakingInfo` admin-API path additionally requires the operator to invoke it against a malicious peer, but the fast-sync path is fully automatic.

---

### Recommendation

After receiving a `P2PStakingInfo` batch, verify each entry's `CouncilStakingAmounts[i]` against the actual native KAIA balance of `CouncilStakingAddrs[i]` in the state at `BlockNum` before calling `PutStakingInfoToDB`. Concretely, in `SyncStakingInfo` and `commitFastSyncData`, after decoding the peer response, call `getFromStateByNumber(stakingInfo.BlockNum)` and compare the resulting `StakingAmounts` slice element-by-element; reject and disconnect the peer on any mismatch. This mirrors the patch in the external report (`constraint = nft_user_token_account.amount == TOKEN_MINT_SUPPLY`) — verify the claimed balance equals the on-chain balance before accepting the data.

---

### Proof of Concept

1. Attacker deploys a Kaia node that responds to `StakingInfoRequestMsg` with a crafted `P2PStakingInfo` where `CouncilStakingAmounts` are inflated for attacker-controlled validators (e.g., set to `math.MaxUint64 / params.KAIA`).
2. Victim node starts fast sync (`SyncMode = FastSync`) and connects to the attacker's node.
3. The downloader calls `fetchStakingInfos`, which sends `StakingInfoRequestMsg` for each staking-interval block hash.
4. The attacker's node returns the crafted `P2PStakingInfo` for each requested hash.
5. `commitFastSyncData` / `commitPivotBlock` calls `PutStakingInfoToDB` with the fabricated amounts — no balance check is performed.
6. On subsequent calls to `GetStakingInfo(preKaiaBlockNum)`, `ReadStakingInfo` returns the fabricated entry from DB, bypassing the on-chain state.
7. `generateProposerListWeighted` computes a proposer list dominated by the attacker's validators; the victim node rejects honest-proposer blocks and diverges from the canonical chain.
8. `assignStakingRewards` routes a disproportionate share of block rewards to the attacker's reward addresses for all affected historical blocks.

		stakingAmounts = collectStakingAmounts(addrs, si)
		gini           = computeGini(stakingAmounts) // si.Gini is computed over every CN. But we want gini among validators, so we calculate here.

	if useGini {
		for addr, amount := range stakingAmounts {
			stakingAmounts[addr] = math.Round(math.Pow(float64(amount), exponent))
			totalStakes += stakingAmounts[addr]
		}

		for _, amount := range stakingAmounts {
			totalStakes += amount
		}

	if totalStakes > 0 {
		for _, addr := range addrs {
			weight := uint64(math.Round(stakingAmounts[addr] * 100 / totalStakes))
			if weight <= 0 {
				weight = 1
			}
			weights[addr] = weight
		}
	} else {
		for _, addr := range addrs {
			weights[addr] = 0

func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining

// handleStakingInfoRequestMsg handles staking information request message.
func handleStakingInfoRequestMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// Decode the retrieval message
	msgStream := rlp.NewStream(msg.Payload, uint64(msg.Size))
	if _, err := msgStream.List(); err != nil {
		return err
	}
	// Gather state data until the fetch or network limits is reached
	var (
		hash         common.Hash
		bytes        int
		stakingInfos []rlp.RawValue
		lookups      int
	)
	for bytes < softResponseLimit && len(stakingInfos) < downloader.MaxStakingInfoFetch &&
		lookups < 2*downloader.MaxStakingInfoFetch {
		// Retrieve the hash of the next block
		if err := msgStream.Decode(&hash); err == rlp.EOL {
			break
		} else if err != nil {
			return errResp(ErrDecode, "msg %v: %v", msg, err)
		}

		lookups++
		// Retrieve the requested block's staking information, skipping if unknown to us
		header := pm.blockchain.GetHeaderByHash(hash)
		if header == nil {
			continue
		}
		number := header.Number.Uint64()
		var result *staking.P2PStakingInfo
		if pm.chainconfig.IsKaiaForkEnabled(header.Number) {
			st, err := pm.stakingModule.GetStakingInfo(number)
			if st == nil || err != nil {
				continue
			}
			result = staking.FromStakingInfoWithGini(st, false, pm.chainconfig.Governance.Reward.MinimumStake.Uint64())
		} else {
			st := pm.stakingModule.GetStakingInfoFromDB(number)
			if st == nil {
				continue
			}
			result = staking.FromStakingInfoWithGini(st, pm.chainconfig.Governance.Reward.UseGiniCoeff, pm.chainconfig.Governance.Reward.MinimumStake.Uint64())
		}

		// If known, encode and queue for response packet
		if encoded, err := rlp.EncodeToBytes(result); err != nil {
			logger.Error("Failed to encode staking info", "err", err)
		} else {
			stakingInfos = append(stakingInfos, encoded)
			bytes += len(encoded)
		}
	}
	return p.SendStakingInfoRLP(stakingInfos)
```

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
