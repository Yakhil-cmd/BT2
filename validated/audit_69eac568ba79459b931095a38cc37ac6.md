### Title
`gas_key_transfer_exec_fee` underprices trie writes for `GasKeyFunctionCall` gas keys by always estimating the size of the smallest `GasKeyFullAccess` variant - (File: `core/parameters/src/cost.rs`)

### Summary
`gas_key_transfer_exec_fee` charges the exec-side `gas_key_byte` fee using `AccessKey::min_gas_key_borsh_len()`, which is explicitly documented and implemented as the borsh size of the smallest possible gas-key variant (`GasKeyFullAccess`). `TransferToGasKey`/`WithdrawFromGasKey` actions can, however, be executed against a `GasKeyFunctionCall` access key, whose value contains an arbitrarily large `FunctionCallPermission` (variable-length `receiver_id` and `method_names`). Every such transfer/withdraw call re-serializes and rewrites the *entire* `AccessKey` value to the trie via `set_access_key`, but the exec fee only ever accounts for the minimum-size variant, systematically underpricing the real trie write.

### Finding Description
`gas_key_transfer_send_fee` prices the send side purely on `public_key_len` [1](#0-0) , while `gas_key_transfer_exec_fee` prices the exec side on `trie_key_len + AccessKey::min_gas_key_borsh_len()` [2](#0-1) . `min_gas_key_borsh_len()` is defined as the borsh size of `Self::gas_key_full_access(0)`, i.e. the smallest gas-key variant, and is documented as such [3](#0-2) .

`action_transfer_to_gas_key` and `action_withdraw_from_gas_key` operate on *any* existing gas key, matched via `access_key.gas_key_info_mut()`, which matches both `GasKeyFullAccess` and `GasKeyFunctionCall` [4](#0-3) . On execution they load the full `AccessKey` from the trie, mutate only the fixed-width `balance` field, and rewrite the *entire* `AccessKey` (including its permission payload) back via `set_access_key` [5](#0-4) . For a `GasKeyFunctionCall` key, this value includes a `FunctionCallPermission` with attacker-chosen `receiver_id` and `method_names`, which can be large (the `AddKey` fee model itself acknowledges up to ~2000 bytes of method names, charged via `add_function_call_key_byte`) [6](#0-5) .

Both the VM host function path and the runtime `exec_fee` dispatch call `gas_key_transfer_exec_fee` unconditionally with only `account_id_len` and `public_key_len` - never with the actual permission/variant of the target key: [7](#0-6)  and [8](#0-7) . So regardless of whether the targeted gas key is a tiny `GasKeyFullAccess` or a `GasKeyFunctionCall` with a maximal `FunctionCallPermission`, the exec-side per-byte charge is identical and always based on the minimum-size estimate.

This differs from the literal wording in the question (varying `num_nonces` or "many nonces" does not change the serialized size, since `num_nonces: NonceIndex` is a fixed-width `u16` and the nonces themselves live in separate `GasKeyNonce` trie entries, not inline in the `AccessKey` value, and are charged separately via `gas_key_add_key_exec_fee`/`gas_key_nonce_write_base`) [9](#0-8) [10](#0-9) . The actual exploitable gap is the `GasKeyFunctionCall` permission payload, which is not accounted for at all in `gas_key_transfer_exec_fee`.

### Impact Explanation
Every `TransferToGasKey`/`WithdrawFromGasKey` call against a `GasKeyFunctionCall` gas key with a large `FunctionCallPermission` causes the runtime/receiving shard to serialize and write a trie value far larger than `AccessKey::min_gas_key_borsh_len()` estimates, while the attacker is only charged for the minimal size. This is a repeatable metering-completeness gap: an unprivileged account can create one large `GasKeyFunctionCall` gas key (paying the one-time `AddKey` per-byte cost) and then repeatedly submit small `TransferToGasKey`/`WithdrawFromGasKey` transactions, each of which forces the receiving shard to do trie serialization/write work proportional to the large permission payload while only paying gas proportional to the minimum-size `GasKeyFullAccess` estimate. This falls under the "gas/storage metering bypass" and "underpriced execution/storage writes" bounty class - it does not directly cause new state growth (storage usage already accounted for at `AddKey` time) but causes underpriced, repeatable trie write/IO cost on the receiving shard for every subsequent transfer/withdraw call.

### Likelihood Explanation
Fully reachable by an ordinary account: any account holder can (1) call `AddKey`/`promise_batch_action_add_gas_key_with_function_call` with a `GasKeyFunctionCall` permission with a large `receiver_id` and many/long `method_names` (paying the add-key per-byte fee once), then (2) repeatedly issue `TransferToGasKey`/`WithdrawFromGasKey` actions or gas-key-funded transactions targeting that same public key. Each such call is charged via `gas_key_transfer_send_fee`/`gas_key_transfer_exec_fee`, which never inspects the actual permission size. No privileged access, validator, or node-level capability is required - purely public RPC/transaction submission.

### Recommendation
Make `gas_key_transfer_exec_fee` (and its send-side counterpart, if applicable) charge based on the actual serialized size of the target `AccessKey`/permission rather than a fixed minimum estimate. This requires reading the real permission variant (or its known size class - `FullAccess`/`GasKeyFullAccess` vs. `FunctionCall`/`GasKeyFunctionCall` with its `method_names`/`receiver_id` lengths) before computing the exec-side per-byte charge for `TransferToGasKey`/`WithdrawFromGasKey`, mirroring how `permission_exec_fees` already charges `add_function_call_key_byte` proportional to actual method-name bytes for `AddKey`.

### Proof of Concept
Integration test outline:
1. Create account `alice`, add a `GasKeyFunctionCall` gas key via `AddKey`/`promise_batch_action_add_gas_key_with_function_call` with `receiver_id` and `method_names` totaling close to the max allowed (~2000 bytes), `num_nonces = 1`.
2. Record `borsh::object_length(&access_key)` for this key (the actual value size written to trie) - call it `actual_len`.
3. Compare against `AccessKey::min_gas_key_borsh_len()` (the estimate used in `gas_key_transfer_exec_fee`) - assert `actual_len >> min_gas_key_borsh_len()`.
4. Execute a `TransferToGasKey` (or `WithdrawFromGasKey`) action against this key; measure the gas charged via `gas_key_transfer_exec_fee`/`exec_fee` in `runtime/runtime/src/config.rs`, and separately measure/instrument the actual bytes written to the trie by `set_access_key` in `action_transfer_to_gas_key`.
5. Assert that charged `gas_key_byte` exec cost (`(trie_key_len + min_gas_key_borsh_len()) * gas_key_byte.exec_fee()`) is strictly less than the cost that would be charged if using `(trie_key_len + actual_len) * gas_key_byte.exec_fee()`, demonstrating the underpricing on every subsequent transfer/withdraw call.

pub fn gas_key_transfer_send_fee(
    cfg: &RuntimeFeesConfig,

    public_key_len: usize,
) -> GasKeyTransferFee {
    let base = cfg.fee(ActionCosts::gas_key_transfer_base).send_fee(sender_is_receiver);
    let per_byte = cfg
        .fee(ActionCosts::gas_key_byte)
        .send_fee(sender_is_receiver)
        .checked_mul(public_key_len as u64)
        .unwrap();

}

/// Exec fee for TransferToGasKey / WithdrawFromGasKey actions.
/// Based on the access key trie key length + estimated value length (what the
/// receiver needs to read/write in the trie).
pub fn gas_key_transfer_exec_fee(
    cfg: &RuntimeFeesConfig,
    account_id_len: usize,
    public_key_len: usize,
) -> GasKeyTransferFee {
    let base = cfg.fee(ActionCosts::gas_key_transfer_base).exec_fee();
    let trie_key_len = access_key_key_len(account_id_len, public_key_len);
    let estimated_value_len = AccessKey::min_gas_key_borsh_len();
    let per_byte = cfg
        .fee(ActionCosts::gas_key_byte)
        .exec_fee()
        .checked_mul((trie_key_len + estimated_value_len) as u64)
        .unwrap();
    GasKeyTransferFee { base, per_byte }
}

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}

pub(crate) fn action_withdraw_from_gas_key(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &WithdrawFromGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    let Some(updated_balance) = gas_key_info.balance.checked_sub(action.amount) else {
        result.result = Err(ActionErrorKind::InsufficientGasKeyBalance {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
            balance: gas_key_info.balance,
            required: action.amount,
        }
        .into());
        return Ok(());
    };
    gas_key_info.balance = updated_balance;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);

    let new_account_balance = account.amount().checked_add(action.amount).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "Account balance integer overflow".to_string(),
        ))
    })?;
    account.set_amount(new_account_balance);
    Ok(())
}
