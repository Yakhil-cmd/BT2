### Title
Dropped liquidation seizure leg keeps the repayment unrefunded — token-unit rounding to zero steals the liquidator's payment - (contracts/controller/src/positions/liquidation/math.rs)

### Summary
In `calculate_seized_collateral`, when a planned seizure leg's RAY value is positive but converts to zero token base units (`capped_amount <= 0`), or its share conversion floors to zero (`seized_scaled <= 0`), the leg is silently `continue`d — skipped — without crediting `unseized_usd`. The only path that feeds `unseized_usd` is the whole-unit floor for sub-`MIN_BORROWABLE_ASSET_DECIMALS` collateral. Since `unseized_usd` is what `release_unbacked_repayment` uses to refund the unbacked portion of the liquidator's repayment, a skipped leg leaves the repayment intact: the liquidator's tokens are taken, the borrower's debt is burned, and no collateral is seized for that leg. This is the same bug class as the DODO report — low-decimal/unit rounding producing a zero output while the input side is still consumed — surfacing in XOXNO's token-unit conversion boundary rather than in a PMM quadratic.

### Finding Description
`calculate_seized_collateral` (contracts/controller/src/positions/liquidation/math.rs) iterates the debtor's supply positions and computes `seizure_ray = (repay_usd * (1 + bonus) * share) / price` in RAY. Three early-`continue` guards drop a leg entirely:

- `seizure_ray <= Ray::ZERO` (line 419) — unreachable loss only if share is zero, fine.
- `seized_scaled <= Ray::ZERO` (line 456) — `capped_ray.div_floor(supply_index)` can floor to 0 shares while `capped_ray > 0`; the leg is dropped with no `unseized_usd` credit.
- `capped_amount <= 0` (lines 460–467) — `capped_ray.to_asset_floor(decimals)` returns 0 whenever the seized RAY value is below one token base unit (`< 10^(27−d)`). For assets with `decimals >= MIN_BORROWABLE_ASSET_DECIMALS` this branch is entered precisely because the special whole-unit handling at lines 401–417 does not apply, yet that branch is the only one that accumulates `unseized_usd` (lines 411–415).

The function returns `(seized, unseized_usd.div_floor(one_plus_bonus))`; `release_unbacked_repayment` (lines 509–527, invoked by `plan.rs`) only trims repayment by that returned `unseized_usd`. A leg skipped via `capped_amount <= 0` or `seized_scaled <= 0` therefore keeps its full backing repayment: `calculate_repayment_amounts` (lines 110–162) records each payment leg's USD into `repay_usd`, `plan.validate` only requires internal consistency of `repay_usd`, and the repaid legs are executed against the liquidator's transferred tokens while `seized` contains nothing for them.

Reachability by an unprivileged caller: `controller.liquidate` with a `payments` vector. The debtor constructs a liquidatable account whose sole (or dominant) collateral position is dust-valued — e.g., a small supply of an asset where the quote-sized pro-rata seizure is below one base unit — and any liquidator repaying the debt leg forfeits the payment. The borrower (who may arrange the position shape) has debt cleared at the liquidator's expense; the liquidator's tokens are consumed with zero collateral received for the skipped leg.

This mirrors the report's root cause: value flows through a WAD/RAY-denominated plan, but the token-unit settlement boundary can round a positive planned seizure to a zero token transfer while the repayment side — denominated in the debt asset — is not correspondingly zeroed.

### Impact Explanation
Direct loss of liquidator funds: tokens transferred in `payments` are burned against the debtor's debt, yet the corresponding collateral seizure rounds to zero token units (or zero shares) and is dropped without refunding the backing repayment. The debtor receives free debt repayment. Unlike the sub-3-decimal whole-unit path, which explicitly tracks `unseized_usd` so the kept repayment never exceeds what collateral backs, the generic skip paths create a silent asymmetry — repayment value in, seizure value out = 0.

### Likelihood Explanation
Requires a debtor account where a collateral leg's pro-rata seizure is below one base unit (or below one share) while the repayment leg is nonzero — achievable with dust-sized collateral positions on any listed asset, since `MIN_ASSET_DECIMALS = 0` and no minimum supply value is enforced at supply time beyond share-minting. A liquidator calling `liquidate` on such an account (normal public flow) hits the skipped-leg path deterministically; the payment cap at `unscale_borrow_ceil` and the excess-payment trim operate on USD totals, not on the dropped leg. Likelihood is moderate — it needs a dust-collateral account shape, but that shape is cheap to construct and any liquidator bot repaying its debt triggers the loss.

### Recommendation
When a seizure leg is dropped (`seized_scaled <= 0` or `capped_amount <= 0`), accumulate its `seizure_for_asset_usd` into `unseized_usd` exactly as the sub-3-decimal floor branch does, so `release_unbacked_repayment` refunds the unbacked repayment. Alternatively, validate post-planning that every kept `RepayEntry`'s USD is covered by at least one positive `SeizeEntry` and trim via `process_excess_payment` for the residual. Note: I was unable to read `plan.rs` in full to confirm the exact `unseized_usd` plumbing, and index-limit constraints may affect whether `seized_scaled` can hit the zero-share case independently — the `capped_amount == 0` path is confirmed by inspection of the code shown.

### Proof of Concept
1. Governance lists collateral asset C (e.g., 6 decimals, price P wad) and borrowable asset D.
2. Attacker supplies a small position in C — e.g., ~1–2 base units worth a few dollars — and borrows D sized so the account is liquidatable with a small quote (debt value such that `repay_usd * (1+bonus) * share / price_C` converts to less than `10^(27−6)` RAY, i.e., the seizure in C is below one base unit, but the debt leg in D is a normal repayable amount).
3. Attacker lets HF drop below 1 (price movement or accrued interest).
4. Any unprivileged liquidator calls `controller.liquidate(account, payments=[D debt amount])`.
5. In `calculate_seized_collateral`: `seizure_ray > 0` but `< 10^21` → `capped_ray.to_asset_floor(6) == 0` → `continue` (lines 463–467); `unseized_usd` stays 0.
6. `release_unbacked_repayment` receives ~0 excess; the repayment leg remains. The liquidator's D tokens repay the borrower's debt; `result.seized` is empty. The liquidator loses the payment; the borrower's debt is extinguished for free.
