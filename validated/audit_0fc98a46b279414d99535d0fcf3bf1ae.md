### Title
Webhook signature verification keyed on `repository.owner.login` while handlers resolve target via `repository.full_name` allows cross-org stack mutation - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App/org config (and therefore which `webhook_secret`) to check against using `repository_owner`, which is read from `params.dig('repository', 'owner', 'login')`. Every downstream `pull_request` handler (e.g. `LabelCapturingHandler`) instead resolves the actual repository/stack to mutate using `params.repository.full_name`. Because these two fields are independently attacker-controlled in the JSON body and are never checked for consistency, an attacker can pick a no-secret org for `repository.owner.login` (which makes signature verification a no-op) while pointing `repository.full_name` at an entirely different, secured org's repository, causing that victim repository's stack to be mutated by a forged, unauthenticated webhook.

### Finding Description
The broken binding is the implicit assumption that:
`org(repository.owner.login) == org(repository.full_name.split('/').first)`

This is never enforced. Trace:

1. `Shipit::WebhooksController#verify_signature` computes the org used to verify via `repository_owner`, defined as `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. [1](#0-0) 
2. It fetches `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature`. [2](#0-1) 
3. `GitHubApp#verify_webhook_signature` unconditionally returns `true` when the org's config has no `webhook_secret` set: `return true unless webhook_secret`. [3](#0-2) 
4. If verification passes (or is skipped this way), `WebhooksController#create` dispatches to all handlers for the event with the raw, attacker-controlled `params`, entirely unaware of which org "authenticated" the request. [4](#0-3) 
5. `LabelCapturingHandler` (like every other `pull_request` handler) resolves the target repository purely from `params.repository.full_name`, independent of `repository.owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. [5](#0-4) 
6. For `action=opened` against an active stack, it persists attacker-controlled label names onto the resolved `PullRequest`: `pull_request.update!(labels: params.pull_request.labels.map(&:name))`. [6](#0-5) 

**Attacker's exact request**: POST `/webhooks` with header `X-Github-Event: pull_request`, body `action: "opened"`, `repository.owner.login` set to any org that Shipit is configured for without a `webhook_secret`, and `repository.full_name` set to `"secured-org/victim-repo"` (a real, existing, secured stack's repo), with a valid PR/labels payload matching `LabelCapturingHandler`'s schema. No valid `X-Hub-Signature` is required because step 3 short-circuits to `true` for the named (no-secret) org.

**Why existing guards fail**: `drop_unhandled_event` only checks the event type is registered, not repository ownership. `ExplicitParameters` schema on `LabelCapturingHandler` only validates shape/types of `repository.full_name`, `pull_request`, etc. — it does not cross-check it against `repository.owner.login` or against the org used for signature verification. There is no code anywhere that asserts `repository.owner.login`'s org equals the org derived from `repository.full_name`.

### Impact Explanation
An attacker who controls (or merely names) any org configured in Shipit without a `webhook_secret` can forge a `pull_request` `opened`/`labeled`/`unlabeled`/`reopened` webhook that is accepted unconditionally, then use `repository.full_name` to target any other, secured org's stack that has review-stack provisioning. This lets the attacker write attacker-chosen label names onto that victim stack's `PullRequest.labels`. Since `ReviewStack#env` uppercases label names into environment variables, this is a payload from one repository/org mutating another repository's stack state and injecting attacker-controlled data into that stack's deploy environment — matching the Critical category "a payload for one repository mutating another's stack." The blast radius spans every review-stack-enabled repository across all orgs configured in the Shipit instance, and is repeatable per request with no rate limiting concern in scope.

### Likelihood Explanation
Preconditions: the Shipit instance must have at least one org configured in `Shipit.github_configs`/`github_teams` without a `webhook_secret` (an operator misconfiguration or an intentionally "public"/legacy org entry), and a victim org/stack with review-stacks enabled and an active `PullRequest` record. Given that precondition, the attack requires no credentials, no signature, and no prior access — a single crafted HTTP POST from any internet client suffices, and it is fully repeatable against any target repository known to the attacker. The only gating factor is the existence of a no-secret org entry in the deployment's configuration.

### Recommendation
Verify webhook authenticity using the org derived from the same field the handlers use to select the target repository (`repository.full_name`'s owner segment), not a separately-controlled `repository.owner.login`/`organization.login` value. Additionally, `GitHubApp#verify_webhook_signature` should not silently return `true` when no `webhook_secret` is configured — either require every configured org to have a `webhook_secret`, or reject (422) events for orgs without one instead of accepting them unconditionally. As defense in depth, handlers should also assert that the resolved repository's owner matches the org that authenticated the request.

### Proof of Concept
minitest under `test/controllers/webhooks_controller_test.rb` (existing suite already tests `verify_signature`/`repository_owner` behavior, per `grep_search` results):

1. Configure `Shipit.github_configs` (via test helper/stub) with two orgs: `"open-org"` (no `webhook_secret`) and `"secured-org"` (with a `webhook_secret`).
2. Create `secured-org/victim-repo` as a `Shipit::Repository` with `review_stacks_enabled`, and provision a review stack with an active `PullRequest`.
3. Build a `pull_request` `opened` payload (based on fixture `test/fixtures/payloads/pull_request_opened.json`) where `repository.owner.login = "open-org"` but `repository.full_name = "secured-org/victim-repo"`, and `pull_request.labels = [{name: "INJECTED"}]`.
4. POST to `/webhooks` with header `X-Github-Event: pull_request` and no valid `X-Hub-Signature` (or an arbitrary/garbage one).
5. Assert: `equality_before = (org_for("open-org").webhook_secret == nil)` is true and `equality_after`: response is `200 OK` (not `422`), and the victim stack's `PullRequest.labels` now includes `"INJECTED"` — proving that a request "authenticated" (trivially) as `open-org` mutated `secured-org`'s stack, violating the stated invariant "A `pull_request` event only affects the repository/stack whose secret authenticated it."     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
