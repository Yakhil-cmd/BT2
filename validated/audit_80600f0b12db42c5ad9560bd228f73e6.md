### Title
Webhook signature is verified against the org derived from `repository.owner.login`, but handlers act on the unrelated `repository.full_name` field, allowing a tenant of one GitHub organization to write to another organization's stacks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App / `webhook_secret` to validate the HMAC against by reading `repository.owner.login` (or `organization.login`) straight out of the unverified JSON body, before the signature check even happens. Once the signature passes, every event handler (`Shipit::Webhooks::Handlers::Handler#stacks`) resolves the actual target `Repository`/`Stack` using a *different* field of the same body, `repository.full_name`. Nothing binds these two fields together, so the "organization whose secret authenticated the request" and "the repository the request acts on" can be made to diverge.

### Finding Description
The controller picks the verification key from body content, not from a trusted/verified source: [1](#0-0) [2](#0-1) 

`verify_webhook_signature` only proves that the raw body was HMAC-signed with *some* organization's configured `webhook_secret` - it says nothing about which repository inside that body is legitimate for that organization: [3](#0-2) 

Every downstream handler, however, resolves the stack to act on from a separate, unrelated field of the same attacker-controlled JSON body: [4](#0-3) 

Because Shipit is explicitly designed to be configured with multiple GitHub organizations, each with its own `webhook_secret` (as documented for multi-org installs), an actor who legitimately administers/owns a GitHub App installation for OrgA (and therefore knows OrgA's `webhook_secret`) can craft a payload where:
- `repository.owner.login` = `"OrgA"` → `verify_signature` calls `Shipit.github(organization: "OrgA")` and validates the HMAC with **OrgA's** secret, which the attacker legitimately possesses.
- `repository.full_name` = `"OrgB/victim-repo"` → the dispatched handler (e.g. `PushHandler`, `StatusHandler`) resolves stacks via `Repository.from_github_repo_name("OrgB/victim-repo")`, a repository the attacker has no relationship to.

The equality that should hold - `organization that authenticated the payload == organization owning the repository the payload mutates` - is broken. The signature only certifies "signed by OrgA," while the handlers trust "acted on OrgB" from the very same unverified bytes.

### Impact Explanation
This is a cross-tenant write: an entity with legitimate GitHub App/webhook credentials for one organization hosted on a shared Shipit instance can forge webhook events that are attributed to and acted upon a completely different organization's stacks (e.g. injecting `GithubSyncJob` enqueues with attacker-chosen `expected_head_sha`, or forging commit `Status` records via `StatusHandler`, as seen in the push/status handling flow exercised by `test/controllers/webhooks_controller_test.rb`). Forged commit statuses can influence Shipit's deployability/merge decisions for a repository the attacker does not own, which is a cross-repository write against another tenant's stack state.

### Likelihood Explanation
Requires the attacker to already possess a legitimate `webhook_secret` for *some* organization configured on the shared Shipit instance (i.e., they are a real, but unrelated, tenant) - this is a real, low bar for a multi-org Shipit deployment, and involves no privileged access to the victim organization or repository, no Shipit session, and no `ApiClient` token.

### Recommendation
Bind the field used for signature-secret selection to the field used for repository resolution: verify the signature using the organization owner implied by `repository.full_name` (or by `organization.login` used consistently in both places), and reject any payload where `repository.owner.login` does not match the owner segment of `repository.full_name` before dispatching to handlers.

### Proof of Concept
1. Shipit configured with two orgs, `OrgA` (attacker-controlled GitHub App with known `webhook_secret_A`) and `OrgB` (victim, tracked stack `OrgB/victim-repo`).
2. Attacker crafts a `push` event body:
```json
{
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/victim-repo" },
  "after": "<attacker-chosen sha>"
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC(webhook_secret_A, body)` and POSTs to `/webhooks`.
4. `verify_signature` resolves `Shipit.github(organization: "OrgA")`, verifies successfully against `webhook_secret_A`.
5. `PushHandler` resolves the stack via `repository.full_name == "OrgB/victim-repo"` and enqueues `GithubSyncJob` against OrgB's stack - an action originating from an entity with no relationship to OrgB. [5](#0-4) [6](#0-5) [7](#0-6)

# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end

module Shipit
  module Webhooks
    module Handlers
      class Handler
        class << self
          attr_reader :param_parser

          def params(&block)
            @param_parser = ExplicitParameters::Parameters.define(&block)
          end
        end

        def self.call(params)
          new(params).process
        end

        attr_reader :params, :payload

        def initialize(payload)
          @payload = payload
          @params = self.class.param_parser.parse!(payload)
        end

        def process
          raise NotImplementedError
        end

        private

        def stacks
          @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
        end

        def repository_name
          payload.dig('repository', 'full_name')
        end
      end
    end
