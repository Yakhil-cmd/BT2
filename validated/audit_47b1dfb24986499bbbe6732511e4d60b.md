### Title
RAY share-value overflow during accrual permanently freezes a high-utilization whale market - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large market can grow its borrow index until `borrowed * borrow_index` exceeds `i128`, because `accrue_step` computes the unscaled aggregate before applying the borrow-index cap. [1](#0-0)  Once that happens, the permissionless `update_indexes` path and every pool mutation that first syncs the market revert with `MathOverflow`, leaving suppliers and borrowers unable to exit or repay through the affected market. [2](#0-1) [3](#0-2) 

### Finding Description
The controller exposes `supply`, `borrow`, and `update_indexes` to ordinary authorized users. [4](#0-3) [2](#0-1)  `supply(account_id = 0)` creates an account, while `borrow` draws debt against an existing account owned or delegated to the caller; a single address can therefore control both the supplying and borrowing accounts needed to create the condition. [5](#0-4) [6](#0-5) 

`update_indexes` calls the pool’s market-accrual operation. [7](#0-6)  The pool loads each requested market and invokes `global_sync`. [8](#0-7)  `global_sync` processes elapsed time and calls `accrue_step`. [9](#0-8) 

Inside `accrue_step`, `scaled_to_original(borrowed, borrow_index)` is evaluated before `update_borrow_index` can clamp the new index. [1](#0-0)  `scaled_to_original` delegates to `Ray::mul`, whose product is checked against `i128`. [10](#0-9) [11](#0-10)  Consequently, a very large scaled-debt principal can hit the `i128` value ceiling while the index is still far below `MAX_BORROW_INDEX_RAY`, so the intended index cap never gets a chance to prevent the panic. [12](#0-11) [13](#0-12) 

### Impact Explanation
This permanently freezes all funds and debt operations for the affected market because the panic happens during mandatory pre-operation accrual rather than during an optional action. [3](#0-2)  Withdrawals and repayments both call `load_leg`, which loads and syncs the market before resolving the user action. [14](#0-13) [15](#0-14) [16](#0-15) 

There is no in-protocol administrative escape short of changing the code: even `update_params` accrues and commits the existing market before replacing the rate model. [17](#0-16)  The harness demonstrates that after the first failed accrual, both a withdrawal and a repayment fail with `MathOverflow`. [18](#0-17) 

### Likelihood Explanation
The attack requires a real listed market whose governance-configured supply cap, borrow cap, and utilization limit admit enough principal and utilization to approach the `i128` boundary. [19](#0-18) [20](#0-19)  The attacker must also provide enough collateral value to borrow most of that liquidity and leave the position at high utilization while interest compounds. [21](#0-20) 

Those are substantial economic and configuration preconditions, but no privileged call, leaked key, malformed ABI payload, oracle misbehavior, or contract bug outside the listed arithmetic path is required. [2](#0-1)  The protocol’s own test reproduces the cliff with a one-billion-token, 18-decimal market at 98% utilization and confirms that the index remains below its configured cap when accrual fails. [22](#0-21) 

### Recommendation
Do not materialize `borrowed * borrow_index` or `supplied * supply_index` in `i128` merely to compute utilization. Use widened `I256` arithmetic or a saturating mul-div ratio in `accrue_step`, and separately derive market caps so the maximum permitted scaled principal remains safely unscalable at `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`. [1](#0-0) [12](#0-11)  Add regression coverage around the maximum cap/index product for every supported decimal configuration. [23](#0-22) 

### Proof of Concept
1. Use an active 18-decimal market whose valid rate configuration, utilization cap, supply cap, and borrow cap admit approximately one billion whole units and 98% utilization. [24](#0-23) 
2. From one unprivileged address, call `supply(caller, 0, spoke_id, [(BIG18, 1_000_000_000 * 10^18)])` to create and fund a supplying account. [25](#0-24) 
3. From the same address, create and fund a second account with sufficient collateral, then call `borrow(caller, account_id, [(BIG18, 980_000_000 * 10^18)], None)`. [6](#0-5) 
4. Leave the market untouched until the high-utilization rate has grown the index enough that `borrowed * borrow_index > i128::MAX * RAY`. [1](#0-0) 
5. Call `update_indexes(caller, [BIG18])`; accrual panics with `MathOverflow` before the borrow-index cap is reached. [8](#0-7) [26](#0-25) 
6. Subsequent `withdraw` and `repay` calls hit the same accrual panic, demonstrating permanent freezing of the market’s funds. [27](#0-26)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
