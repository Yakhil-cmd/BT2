### Title
Missing Content Validation in P2P-Delivered Staking Info Enables Reward-Distribution Corruption — (`datasync/downloader/queue.go`)

---

### Summary

`queue.DeliverStakingInfos` accepts `P2PStakingInfo` from any connected peer and writes it to the persistent staking-info database with a **no-op validate function** (marked `// TODO-Kaia-Snapsync update validation logic`). Every other data type synced over the same pipeline — block bodies and receipts — is validated against a cryptographic commitment in the block header before acceptance. Because staking info drives reward distribution (validator reward addresses, KEF/KIF/KPF treasury addresses, staking amounts), a malicious peer can inject fabricated data that permanently corrupts the node's reward-distribution state, causing it to compute wrong state roots and diverge from the canonical chain.

---

### Finding Description

During block synchronization (pre-Kaia fork), the downloader fetches staking info from peers via `fetchStakingInfos` → `queue.DeliverStakingInfos`. The `deliver` helper requires a `validate` callback to check each delivered item against its corresponding block header. For bodies and receipts this callback performs a cryptographic check:

**`DeliverBodies`** — validates against `header.TxHash`: [1](#0-0) 

**`DeliverReceipts`** — validates against `header.ReceiptHash`: [2](#0-1) 

**`DeliverStakingInfos`** — validate is a no-op: [3](#0-2) 

The fabricated `P2PStakingInfo` struct carries all fields that drive reward distribution: [4](#0-3) 

After passing the no-op validator, the data is reconstructed into a `fetchResult` and later committed to the database via `PutStakingInfoToDB`: [5](#0-4) 

`GetStakingInfo` reads the database first (before falling back to state derivation) for all pre-Kaia blocks: [6](#0-5) 

The same vulnerability exists in the `SyncStakingInfo` recovery path, where the only check is that `stakingInfo.BlockNum` matches the expected block number — the actual content (addresses, amounts) is never verified: [7](#0-6) 

---

### Impact Explanation

The `StakingInfo` struct controls three categories of protected-state writes during `FinalizeState`:

1. **Validator staking rewards** — `RewardAddrs` and `StakingAmounts` determine how the staker portion of the block reward is split among validators. A fabricated entry can redirect staking rewards to attacker-controlled addresses or zero out legitimate validators. [8](#0-7) 

2. **Treasury fund addresses** — `KEFAddr`, `KIFAddr`, `KPFAddr` are used directly as recipients of the KEF/KIF/KPF portions of every block reward. If these are replaced with attacker addresses, all treasury distributions for the affected epoch range are misdirected. [9](#0-8) 

3. **State-root divergence** — Because the corrupted staking info produces different reward distributions, the node computes a different state root than honest peers. It will reject valid canonical blocks and be unable to participate in or verify the chain — a persistent consensus divergence on the affected node.

---

### Likelihood Explanation

- **Trigger**: Any peer that successfully connects to the syncing node can send a `StakingInfoMsg` response. The P2P handler `handleStakingInfoMsg` decodes the message and forwards it directly to `DeliverStakingInfos` with no prior content check: [10](#0-9) 

- **Scope**: Only pre-Kaia-fork blocks are affected (the database path is bypassed after the Kaia fork). However, the staking info for those historical epochs is what determines validator set weights and reward addresses for the entire pre-Kaia history.

- **Detectability**: The corruption is silent at delivery time. The node only discovers the inconsistency when it attempts to process blocks and finds its computed state root does not match the canonical chain.

---

### Recommendation

1. **Derive and compare from state**: After receiving staking info from a peer, re-derive it from the block's committed state root (using `getFromStateByNumber`) and reject any delivery whose content does not match. This is the same principle used by `DeliverBodies`/`DeliverReceipts`.

2. **Remove the TODO placeholder**: Replace the no-op `validate` closure in `DeliverStakingInfos` with a real check:

```go
validate := func(index int, header *types.Header) error {
    received := stakingInfoList[index]
    derived, err := s.getFromStateByNumber(header.Number.Uint64())
    if err != nil {
        return err
    }
    if !stakingInfoEqual(received, derived) {
        return errInvalidStakingInfo
    }
    return nil
}
```

3. **Apply the same guard to `SyncStakingInfo`**: The recovery path at `downloader.go:677` should also validate content before calling `PutStakingInfoToDB`. [11](#0-10) 

---

### Proof of Concept

1. Attacker runs a Kaia node and connects to a victim node that is syncing pre-Kaia blocks.
2. Victim node sends a `StakingInfoRequestMsg` for block hashes in the staking interval.
3. Attacker intercepts the request and responds with a `StakingInfoMsg` containing a `P2PStakingInfo` where:
   - `CouncilRewardAddrs` are replaced with attacker-controlled addresses
   - `KEFAddr`/`KIFAddr` are replaced with attacker-controlled addresses
   - `CouncilStakingAmounts` are inflated for attacker-controlled validators
4. `handleStakingInfoMsg` decodes the message and calls `pm.downloader.DeliverStakingInfos`. [12](#0-11) 
5. `queue.DeliverStakingInfos` calls `validate(index, header)` which returns `nil` unconditionally. [13](#0-12) 
6. The fabricated staking info is written to the database via `PutStakingInfoToDB`. [5](#0-4) 
7. When the victim node later calls `GetStakingInfo(num)` for a pre-Kaia block, it reads the corrupted entry from the database (database is checked before state derivation). [6](#0-5) 
8. `FinalizeState` distributes block rewards to the attacker's addresses instead of the legitimate validators and treasury funds, producing a state root that diverges from the canonical chain. [9](#0-8)

```go
// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
```

```go
// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
```
