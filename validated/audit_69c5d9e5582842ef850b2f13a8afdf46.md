### Title
Webhook signature verification is scoped to `repository.owner.login`, but the event handlers act on the unrelated `repository.full_name` field, allowing an unauthenticated attacker to spoof push/status events against any stack in a multi-organization Shipit install - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App config (and thus which `webhook_secret`) to validate the incoming payload against using only `repository.owner.login` (or `organization.login`) from the untrusted JSON body. The handlers that subsequently act on the payload (`Handler#stacks` / `Handler#repository_name`) instead resolve the target `Repository` using an entirely different field, `repository.full_name`, which is never checked against the field used for authentication. This breaks the binding "organization that authenticated == repository that is written."

### Finding Description
`verify_signature` computes:
```
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(...)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

`GithubApp#verify_webhook_signature` explicitly treats a missing `webhook_secret` as automatically verified:
```
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [2](#0-1) 

Shipit explicitly supports configuring multiple GitHub organizations in the same instance, each with its own, independently optional `webhook_secret`, as documented in `docs/setup.md` and `config/secrets.development.shopify.yml`: [3](#0-2) [4](#0-3) 

Once `verify_signature` passes, `WebhooksController#create` re-parses the raw body and dispatches it to the matching handler, e.g. `PushHandler`:
```
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [5](#0-4) 

The base `Handler` class resolves the stacks to act on from `repository.full_name`, a field completely independent from `repository.owner.login`:
```
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [6](#0-5) 

`PushHandler` uses this to trigger `stack.sync_github`:
```
def process
  stacks
    .not_archived
    .where(branch:)
    .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [7](#0-6) 

**Equality broken:** the engine implicitly assumes `repository.owner.login` (used to pick the app/secret that authenticates the request) == the owning organization of `repository.full_name` (used to pick the `Repository`/`Stack` that is actually acted upon). Nothing in the code enforces this equality — an attacker fully controls both fields in the raw JSON body they submit.

### Impact Explanation
If any organization configured in `Shipit.github` (a legitimately supported multi-tenant setup) has no `webhook_secret` set — an explicitly optional setting per `docs/setup.md` — then `verify_webhook_signature` for that organization always returns `true`, regardless of the signature header. An attacker can set `repository.owner.login`/`organization.login` in the JSON body to that unsecured organization's name (satisfying signature "verification"), while setting `repository.full_name` to any other stack's repo — including one that belongs to a different, properly-secured organization. This lets an unauthenticated attacker inject a forged `push` webhook (or other handled events) that Shipit will process as legitimate for a repository that was never protected by the unsecured organization's identity, forcing `Stack#sync_github` (and correspondingly continuous-delivery logic) to run for arbitrary stacks across organizational boundaries. This crosses the "cross-repository writes" / "unauthorized deploy" impact category, since sync/CD side effects on the wrong stack's repository can be triggered by an attacker who never had any credential for that organization.

### Likelihood Explanation
The prerequisite (at least one configured GitHub organization without a `webhook_secret`) is entirely plausible and even encouraged by the docs, which describe `webhook_secret` as "(optional)". Any Shipit operator running multi-org setups where even one org's app was created without a secret configured would expose every other org's stacks to this cross-org spoofing, with zero credentials required from the attacker (no Shipit session, API token, or GitHub token needed — an unauthenticated `POST /webhooks` suffices).

### Recommendation
After (or as part of) signature verification, re-derive the target repository strictly from the same organization that was cryptographically authenticated (or explicitly reject when `repository.owner.login` used to authenticate differs from the owner encoded in `repository.full_name`). Additionally, consider making `webhook_secret` mandatory per configured organization so that "verified" can never trivially default to `true`.

### Proof of Concept
1. Deploy Shipit with a multi-org `github` config, e.g. `OrgSecure` (has `webhook_secret` set) and `OrgOpen` (has no `webhook_secret`), both installed and with stacks created for their respective repos.
2. As an unauthenticated attacker, send:
```
POST /webhooks
X-Github-Event: push
Content-Type: application/json

{
  "repository": { "owner": {"login": "OrgOpen"}, "full_name": "OrgSecure/protected-repo" },
  "ref": "refs/heads/main",
  "after": "<any-sha>"
}
```
3. `repository_owner` resolves to `OrgOpen`; `Shipit.github(organization: "OrgOpen")` has no `webhook_secret`, so `verify_webhook_signature` returns `true` unconditionally.
4. `PushHandler` then resolves `repository_name` from `full_name` = `OrgSecure/protected-repo`, finds the real `Stack` for that org, and calls `stack.sync_github`, even though the attacker never authenticated as `OrgSecure` and supplied no valid signature for it.

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
