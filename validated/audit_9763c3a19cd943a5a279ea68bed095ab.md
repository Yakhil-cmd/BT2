### Title
`InitializeWithPermission.creator` accepted without validating it's a non-default, non-system address, permanently locking accrued creator fees - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
`initialize_with_permission` lets an unprivileged `payer` pass an arbitrary `creator` account, which is stored verbatim as `pool_state.pool_creator` and later used as the sole authority for collecting creator fees. There is no constraint requiring `creator` to be a meaningful, controllable address (e.g. not `Pubkey::default()` / the System Program ID).

### Finding Description
`InitializeWithPermission` declares `creator` as a bare `UncheckedAccount<'info>` with only a `CHECK:` comment and no `constraint`: [1](#0-0) 

This value flows directly into `pool_state.initialize`, which stores it unconditionally as `pool_creator`: [2](#0-1) [3](#0-2) 

This is the exact analog of the `SimplePolicySetter.set` bug: a sensitive address argument (`pool_creator`, analogous to `_value`/implementation address) is accepted and permanently recorded without validating it is non-zero/meaningful, and — unlike `SimplePolicySetter`, which can be re-called to fix a bad value — `pool_creator` is set once at pool initialization and can never be changed afterward (no admin "set creator" instruction exists in the reachable instruction set).

Once set, `pool_creator` gates the only two fee-withdrawal paths for the accrued `creator_fees_token_0/1`:
- `CollectCreatorFee` requires the `creator` signer to match `pool_state.pool_creator`: [4](#0-3) 
- `CollectCreatorFeePermissionless` sends fees to an ATA whose authority is `pool_state.pool_creator`, and anyone can trigger it, but the destination authority is fixed to `pool_creator`: [5](#0-4) 

If `pool_creator` is set to `Pubkey::default()` (all-zero, effectively the System Program address) at initialization time, both paths become permanently unusable for withdrawing legitimate funds: `CollectCreatorFee` requires a `Signer` matching `pool_creator`, but no private key exists for the all-zero pubkey, so that instruction can never succeed; `CollectCreatorFeePermissionless` will happily create an ATA owned by `Pubkey::default()` and route the `creator_fees_token_0/1` there forever, with no mechanism to reclaim them, since the System Program cannot sign to move tokens out of that ATA.

### Impact Explanation
Every swap that has creator fees enabled accrues `creator_fees_token_0`/`creator_fees_token_1` into the pool vaults (see `swap_base_input`'s use of `creator_fee_rate` and result fees): [6](#0-5) . If the pool is created with a zero/unusable `pool_creator`, all of these accumulated creator fees become permanently frozen/unrecoverable — a direct, ongoing loss of protocol/LP-adjacent funds with no remediation path, satisfying the "permanent freezing of user or LP funds" criterion.

### Likelihood Explanation
`initialize_with_permission` is reachable by any account holding (or being granted) a `Permission` PDA and simply requires the caller to submit `creator` as an arbitrary pubkey of their choosing; setting it to `Pubkey::default()` costs nothing extra and could happen accidentally (a bug in a client passing an unset/zeroed pubkey) or could be done maliciously by a pool creator wanting to signal "no creator fees" without realizing that funds still accrue and now no one can withdraw them. Given creator fees are enabled/accrued regardless of this flaw (`enable_creator_fee` is independently controlled), the fee loss occurs on every subsequent swap.

### Recommendation
Add an explicit constraint in `InitializeWithPermission` (and mirror it in `Initialize`, whose `creator` is at least forced to be a `Signer`, but same principle could apply to a delegated recipient elsewhere) requiring `creator.key() != Pubkey::default()` and, ideally, `creator.key() != system_program::ID`, before calling `pool_state.initialize`. Reject the instruction with a clear error (e.g. `ErrorCode::InvalidInput`) if the check fails, so a broken pool cannot be created and creator fees are never routed to an unrecoverable address.

### Proof of Concept
1. Caller obtains/creates a valid `Permission` PDA via `create_permission_pda` (or otherwise satisfies whatever authorization gate is checked outside this instruction) so they can call `initialize_with_permission`.
2. Caller submits `initialize_with_permission` with the `creator` account set to `Pubkey::default()` (the System Program's address, all-zero pubkey) and `enable_creator_fee = true` (or leaves default fee-on config that still accrues creator fees per `AmmConfig.creator_fee_rate`).
3. `pool_state.pool_creator` is stored as `Pubkey::default()`. [7](#0-6) 
4. Any user performs `swap_base_input`/`swap_base_output`; creator fees accrue into `pool_state.creator_fees_token_0/1`. [6](#0-5) 
5. Attempting `collect_creator_fee` fails because no signer can produce a valid signature for `Pubkey::default()`. [4](#0-3) 
6. Calling `collect_creator_fee_permissionless` succeeds in transferring the fees, but into an ATA owned by `Pubkey::default()`, from which they can never be moved again, permanently locking those funds. [8](#0-7)

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
```
