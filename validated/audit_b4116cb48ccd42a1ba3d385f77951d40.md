### Title
Webhook signature verification uses `repository.owner.login`/`organization.login` while the target stack is resolved from an independent `repository.full_name` field, allowing an org with no `webhook_secret` to authorize writes against any other org's stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` used to verify the HMAC signature via `repository_owner`, which is read from `params.dig('repository','owner','login')` (falling back to `params.dig('organization','login')`). The record actually mutated by the handler (e.g. `PushHandler`) is selected independently from `payload.dig('repository','full_name')`. Because these two fields are never cross-checked and are both fully attacker-controlled in the JSON body, an attacker can set the "owner" fields to an organization configured with no `webhook_secret` (which makes `GitHubApp#verify_webhook_signature` return `true` unconditionally) while pointing `repository.full_name` at a completely different, secured stack.

### Finding Description
The broken binding, stated as an equality that should hold but doesn't: `organization_whose_secret_verified(signature) == organization_owning(target_stack)`.

Trace:
- `verify_signature` computes `repository_owner` from `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0)  and uses it to fetch a `GitHubApp` and check the signature: [2](#0-1) .
- `GitHubApp#verify_webhook_signature` unconditionally returns `true` when `webhook_secret` is blank/nil for that org: `return true unless webhook_secret` [3](#0-2) .
- `#create` then parses the same raw body and dispatches to handlers such as `PushHandler` [4](#0-3) , which resolves the target `Repository`/`Stack` using `payload.dig('repository', 'full_name')` — a completely separate field from the one used for signature-org selection: [5](#0-4) .
- `PushHandler#process` then finds matching stacks by branch and calls `stack.sync_github(expected_head_sha: params.after)` using attacker-supplied `ref`/`after` values [6](#0-5) .

Exploit request: attacker POSTs `/webhooks` with `X-Github-Event: push`, no valid `X-Hub-Signature` (or garbage), and a JSON body where `repository.owner.login` (or `organization.login` if `repository.owner` is omitted) is set to an org present in `Shipit.github_apps` with no `webhook_secret` configured, while `repository.full_name` is set to `"victim-org/victim-repo"`. Since the org used for verification has no secret, `verify_webhook_signature` returns `true` regardless of signature bytes or body content, and the handler proceeds to mutate the stack looked up via `full_name`, which belongs to an entirely different (and possibly secured) organization.

Existing guards do not prevent this: `drop_unhandled_event` and `check_if_ping` only gate on event type [7](#0-6) ; `GithubOrganizationUnknown` handling only guards against unknown orgs, not orgs with empty secrets [8](#0-7) ; there is no code anywhere in the controller or `Handler` base class that asserts `repository_owner == payload.dig('repository','full_name').split('/').first`.

### Impact Explanation
An unauthenticated attacker can inject forged `push` (and other) webhook events that cause `PushHandler` to call `stack.sync_github` on an arbitrary victim stack, effectively simulating a push and triggering GitHub sync/build behavior for a repository/organization the attacker does not control and whose webhook secret they never possessed — this is a cross-tenant authentication bypass matching the "Critical" category (forged webhook accepted; payload for one repository mutating another's stack). This is repeatable for every request as long as one configured org in `Shipit.github_apps` lacks a `webhook_secret`; the blast radius spans every stack whose full_name is guessable/known, regardless of which org actually owns it or how strong its own secret is.

### Likelihood Explanation
Exploitability is conditioned entirely on operator configuration: it requires at least one entry in `Shipit.github_apps` with `webhook_secret` absent/blank. In that case, attacker cost is a single unauthenticated HTTP POST with a fully attacker-crafted JSON body — no GitHub credentials, sessions, or secrets are needed, and it is trivially repeatable. If no configured org lacks a `webhook_secret`, this specific path is not exploitable directly on this controller (though it still highlights that the two lookups are architecturally decoupled and unchecked against each other).

### Recommendation
Bind signature verification to the same resource identity used for mutation: derive `repository_owner` from `repository.full_name` (the field actually used to resolve the target stack) rather than independently from `repository.owner.login`/`organization.login`, or explicitly assert they match before proceeding. Additionally, treat a missing/blank `webhook_secret` for a configured org as a hard misconfiguration (reject the webhook, e.g. `head(422)`) rather than an implicit "verification passed" default in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
Minitest plan (`test/lib/shipit/github_app_test.rb` and `test/controllers/webhooks_controller_test.rb`, both explicitly noted as out-of-scope directories per the rules but described conceptually):
1. Unit test: instantiate `GitHubApp.new('org-no-secret', {})` (no `webhook_secret` key) and assert `verify_webhook_signature('sha1=garbage', 'any body')` returns `true` — proving signature bytes are never checked when the secret is absent.
2. Integration test: configure `Shipit.github_apps` with two orgs, `org-no-secret` (no `webhook_secret`) and `victim-org` (with a real `webhook_secret`); create a `Stack` under `victim-org/victim-repo`; POST `/webhooks` with `X-Github-Event: push`, an invalid `X-Hub-Signature`, and body `{"repository": {"owner": {"login": "org-no-secret"}, "full_name": "victim-org/victim-repo"}, "ref": "refs/heads/<stack-branch>", "after": "<attacker-chosen-sha>"}`; assert response is `200 OK` and that `stack.sync_github` was invoked/enqueued with the attacker-chosen `expected_head_sha`, proving cross-org state mutation without any validated secret for `victim-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
