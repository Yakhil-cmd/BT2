### Title
Deregistered Operator's Stale Vote Persists and Counts Toward Threshold, Enabling Unauthorized Bridge Settlement — (`contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`deregisterOperator` removes an operator from the `operators` mapping but never clears that operator's already-cast votes from the `votes` storage. Because `_voteCommon` reads only the accumulated `voteCounts[voteKey]` counter — with no check that every contributing voter is still registered — a deregistered operator's prior vote permanently inflates the count. A single remaining registered operator can then push the count to threshold and trigger a KLAY (or token) transfer that the current operator set never fully authorized.

---

### Finding Description

**`deregisterOperator` does not revoke stale votes.** [2](#0-1) 

The function deletes `operators[_operator]` and removes the address from `operatorList`, but the `votes[voteType][nonce]` storage — specifically `vote.voted[_operator]` and `vote.voteCounts[voteKey]` — is left completely intact.

**`_voteCommon` never validates that prior voters are still registered.** [3](#0-2) 

The threshold comparison at line 96 operates on the raw accumulated counter. It has no knowledge of whether the votes that built that counter came from currently-registered operators.

**`handleKLAYTransfer` only guards the *caller*, not the vote history.** [4](#0-3) 

The `onlyOperators` modifier at line 72 ensures the *current* caller is registered. It does nothing to invalidate the stale count already sitting in storage from a deregistered operator.

---

### Impact Explanation

When the stale vote count plus the new vote reaches `operatorThresholds[ValueTransfer]`, `_voteValueTransfer` returns `true`, `closedValueTransferVotes[nonce]` is set, and `handleKLAYTransfer` executes the `.call.value(_value)("")` transfer at line 98. KLAY leaves the bridge contract authorized in part by a vote from an operator the owner explicitly removed. This is an unauthorized transfer of bridge-held KLAY (or ERC-20/ERC-721 in the analogous token paths), satisfying the "Unauthorized transfer… affecting KLAY, bridged assets, or system-managed funds" impact gate.

---

### Likelihood Explanation

The scenario is operationally plausible. Operators are deregistered precisely when they are no longer trusted (key rotation, compromise, personnel change). The window between an operator's last vote and its deregistration is a normal operational gap, not an exotic race. Any remaining registered operator can close the vote during that window. No cryptographic break, majority-validator collusion, or external service compromise is required.

---

### Recommendation

In `deregisterOperator`, iterate over all open `VotesData` entries for the deregistered operator and decrement `voteCounts` for any `voteKey` that operator contributed to (mirroring the re-vote decrement logic already present in `_voteCommon` lines 84-86). Alternatively, store the set of currently-registered voters per `voteKey` and recount live votes on each new submission, discarding contributions from addresses no longer in `operators`.

---

### Proof of Concept

```
1. Deploy bridge; owner registers operatorA and operatorB; set threshold = 2.
2. operatorA calls handleKLAYTransfer(txHash, from, to, 1 ether, nonce=5, blockNum, data).
   → _voteCommon: voteCounts[voteKey] = 1. Threshold not reached. Returns.
3. Owner calls deregisterOperator(operatorA).
   → operators[A] = false. votes storage untouched.
4. operatorB calls handleKLAYTransfer with identical arguments (same voteKey).
   → onlyOperators: B is registered. ✓
   → _voteCommon: voteCounts[voteKey] increments from 1 → 2 ≥ threshold(2). Returns true.
   → closedValueTransferVotes[5] = true.
   → _to.call.value(1 ether)("") executes.
5. 1 KLAY transferred, authorized in part by deregistered operatorA's stale vote.
```

    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
