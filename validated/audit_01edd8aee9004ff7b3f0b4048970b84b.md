### Title
Permanent market freeze from RAY-value overflow during interest accrual - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large market at sustained high utilization can make `scaled * index` exceed `i128::MAX` before the borrow index reaches its configured ceiling. Every state-changing pool path synchronizes interest before applying the operation, so the resulting `MathOverflow` permanently prevents repayment, withdrawal, liquidation, recapitalization, and further index updates for that market.

### Finding Description
`accrue_step` converts both `borrowed` and `supplied` scaled RAY balances back to original RAY values through `scaled_to_original` on every accrual step. [1](#0-0)   
`scaled_to_original` performs a non-saturating `Ray::mul`, so a product over `i128::MAX` traps with `MathOverflow`. [2](#0-1)   
The later borrow-index clamp to `MAX_BORROW_INDEX_RAY` does not help because the unscaled debt/supply multiplication can overflow first. [3](#0-2)   

All pooled position legs use `ops::load_leg`, which always calls `synced_market` before the requested mutation. [4](#0-3)   
`synced_market` calls `interest::global_sync`, which iterates accrual chunks until the market is current. [5](#0-4)   
Once the overflow threshold is crossed, no caller can advance `last_timestamp`, because `accrue_chunk` traps before `mark_accrued` executes. [6](#0-5)   

An unprivileged user reaches the condition through `Controller::supply` to create the large book and `Controller::borrow` to sustain high utilization, then permissionless `Controller::update_indexes` triggers the fatal accrual. [7](#0-6) [8](#0-7) 

### Impact Explanation
The affected market becomes permanently unusable: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot repay or seize collateral, and recapitalization cannot rescue it because those paths all accrue first. [9](#0-8) [10](#0-9)   
This is a permanent freezing of user funds and a market-level complete denial of service, analogous to the CVE’s repeatable crash condition. [11](#0-10) 

### Likelihood Explanation
Exploitation requires a very large admitted book and prolonged high utilization, so it is not practical for ordinary markets but is reachable solely through authorized user entrypoints. [12](#0-11)   
The repository’s regression test demonstrates the failure with a one-billion-token, 18-decimal market at 98% utilization: `update_indexes` returns `MathOverflow`, the borrow index remains below `MAX_BORROW_INDEX_RAY`, and subsequent withdrawal and repayment attempts fail with the same error. [13](#0-12) 

### Recommendation
Make accrual arithmetic saturation-safe before any revert leaves `last_timestamp` unadvanced. In particular, bound or safely saturate `borrowed * borrow_index` and `supplied * supply_index`, clamp `borrow_index` at `MAX_BORROW_INDEX_RAY` before it can make the market value unrepresentable, and ensure a step that hits the numerical ceiling still commits the accrued timestamp rather than trapping.

### Proof of Concept
The existing production-path regression test is a direct proof of concept:

1. Create an 18-decimal market using the XLM interest curve and a collateral market.
2. From one authorized caller, call `supply` with approximately `1_000_000_000 * 10^18` units of the debt asset, then `borrow` 98% of that book against collateral.
3. Repeatedly call `update_indexes(caller, vec![hub_asset])` while utilization remains high.
4. When `scaled_to_original(supplied_or_borrowed, index)` exceeds `i128::MAX`, the call fails with `MathOverflow` before the index cap engages.
5. Subsequent `withdraw`, `repay`, and `update_indexes` calls all fail at the same first accrual step. [14](#0-13)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
