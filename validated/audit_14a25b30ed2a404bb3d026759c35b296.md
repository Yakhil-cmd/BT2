### Title
Push webhook `repository.full_name` is not bound to the org whose `webhook_secret` validated the request, allowing cross-tenant stack sync - (File: `app/models/shipit/webhooks/handlers/handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the signing GitHub App/`webhook_secret` using `payload.dig('repository','owner','login')`, while `Handler#stacks`/`#repository_name` resolves the target `Repository` using the independent `payload.dig('repository','full_name')` field from the same attacker-controlled JSON body. Because these two fields are never cross-checked, an attacker who legitimately owns a GitHub org onboarded to this Shipit instance can sign a push payload with their own `webhook_secret` while setting `repository.full_name` to a victim org's repository, causing `PushHandler#process` to resolve and mutate the victim's `Stack`.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:
`organization selected by Shipit.github(organization: repository_owner)` (used to verify the HMAC signature) **must equal** `organization owning Repository.from_github_repo_name(repository_name)` (used to pick the stacks that get mutated). Nothing in the code enforces this.

- `WebhooksController#verify_signature` picks the app/secret via `repository_owner`, which is `params.dig('repository', 'owner', 'login')`: [1](#0-0)  and [2](#0-1) 
- `Handler#stacks`/`#repository_name` resolve the affected repository via a *different* field, `payload.dig('repository', 'full_name')`, with no reference back to `repository_owner`: [3](#0-2) 
- `Repository.from_github_repo_name` just splits the string and does a case-insensitive `find_by(owner:, name:)` lookup — it has no notion of "which org's webhook signed this": [4](#0-3) 
- `PushHandler#process` uses that same unchecked `stacks` scope to drive a real mutation: `stack.sync_github(expected_head_sha: params.after)`: [5](#0-4) 
- `Stack#sync_github` enqueues `GithubSyncJob`, which fetches commits and **writes new `Commit` rows** into the resolved stack: [6](#0-5) , [7](#0-6) 

Attack: attacker owns `attacker-org`, which is a legitimately onboarded org in this Shipit instance's multi-tenant `github:` config (see `docs/setup.md`'s "Using Multiple Github Applications" section), and therefore knows `attacker-org`'s real `webhook_secret`. Attacker POSTs to `/webhooks` with header `X-Github-Event: push` and a JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "full_name": "victim-org/repo",
    "owner": { "login": "attacker-org" }
  }
}
```
signed with `X-Hub-Signature` computed using `attacker-org`'s own `webhook_secret`.

- `verify_signature` calls `Shipit.github(organization: 'attacker-org')` and verifies the HMAC against `attacker-org`'s secret — this succeeds because it's genuinely the attacker's own signature over their own crafted payload.
- `PushHandler#process` then calls `stacks`, which resolves `Repository.from_github_repo_name('victim-org/repo')` — a real Repository row that belongs to `victim-org` — and returns that repo's `not_archived` stacks whose `branch == 'master'`.
- For each matching stack, `stack.sync_github(expected_head_sha:)` is invoked, enqueuing `GithubSyncJob` against the **victim's** stack ID.

Existing guards do not stop this: `verify_signature` only proves the request was signed by *some* org's secret, not that it was signed by the org that actually owns the repository named in the payload; `drop_unhandled_event`/`check_if_ping` are irrelevant; `ExplicitParameters` only validates types/presence of `ref`/`after`, not cross-field consistency between `repository.owner.login` and `repository.full_name`; and `Repository.from_github_repo_name` performs no tenant check.

### Impact Explanation
The attacker can force `GithubSyncJob` to run against an arbitrary victim stack merely by knowing the victim's `owner/name` string (public information) and the victim stack's tracked branch name (also typically public/guessable, e.g. `master`/`main`). This job writes `Commit` rows into the victim's stack from the victim's real GitHub history (fetched using the victim's own correctly-scoped `github_app`, since `Repository#github_app` is derived from the DB row's `owner`, not attacker input) and can trigger `CacheDeploySpecJob` and downstream state changes (e.g. `stack.mark_as_accessible!`/`inaccessible!`, `schedule_merges_if_necessary` via other `after_commit` callbacks on `Stack`). This is a cross-tenant mutation of another organization's `Stack`/`Commit` records driven by a payload the victim organization never authenticated, matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." It is repeatable at will against any repository/stack whose `owner/name` and tracked branch the attacker can guess, as long as a Repository row with that identity exists in this Shipit instance.

### Likelihood Explanation
Preconditions: (1) the Shipit instance must be configured multi-tenant (attacker's own org and the victim's org both onboarded, each with distinct `webhook_secret`s, as documented in `docs/setup.md`), and (2) a `Repository` row for `victim-org/repo` must already exist in the same Shipit database. Given these, the attack costs the attacker nothing beyond knowing their own valid `webhook_secret` (which they legitimately possess for their own org) and a single crafted HTTP POST — no privileged Shipit role, session, or victim secret is required. This is fully repeatable and scriptable.

### Recommendation
In `Handler#stacks`/`#repository_name` (or centrally in `WebhooksController`), verify that the resolved `Repository#owner` matches the `repository_owner` value that was used to select the signing GitHub App/`webhook_secret`, and reject/ignore the payload otherwise. Concretely, pass the verified `repository_owner` into each handler and have `stacks` do `Repository.from_github_repo_name(repository_name)` only if `repository.owner.casecmp?(verified_repository_owner)`, else treat as unmatched (`Stack.none`).

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
```ruby
test "push payload with mismatched owner and full_name should not sync a victim stack" do
  victim_repo = Shipit::Repository.create!(owner: 'victim-org', name: 'repo')
  victim_stack = Shipit::Stack.create!(repository: victim_repo, environment: 'production', branch: 'master')

  payload = {
    "ref" => "refs/heads/master",
    "after" => "deadbeef",
    "repository" => {
      "full_name" => "victim-org/repo",
      "owner" => { "login" => "attacker-org" }
    }
  }.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest('sha1', attacker_org_webhook_secret, payload)

  request.headers['X-Github-Event'] = 'push'
  request.headers['X-Hub-Signature'] = signature

  # attacker-org's own webhook_secret verifies successfully:
  assert Shipit.github(organization: 'attacker-org').verify_webhook_signature(signature, payload)

  assert_no_enqueued_jobs(only: GithubSyncJob) do
    post :create, body: payload, as: :json
  end
  # Currently FAILS: GithubSyncJob is enqueued for victim_stack.id, proving
  # `repository_owner` ('attacker-org') != `victim_repo.owner` ('victim-org')
  # was never checked before mutating victim_stack.
end
```
Both sides of the binding — `repository_owner` derived at signature-verification time vs. `Repository#owner` of the row resolved by `repository_name` — must be asserted equal before the sync is allowed; today they are never compared.

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
