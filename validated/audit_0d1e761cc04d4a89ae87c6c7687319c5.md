### Title
`StatusHandler#process` writes GitHub commit statuses to any stack sharing a commit sha, with no repository/stack scoping - ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`StatusHandler#process` resolves target commits solely by `Commit.where(sha: params.sha)`, with no join or filter against `Repository.from_github_repo_name(payload['repository']['full_name'])` or any stack ownership check. Because the `commits` table only enforces sha uniqueness per `(sha, stack_id)` and not globally, a webhook `status` event delivered for one repository can write a `Status` row (and trigger its side effects, including `schedule_continuous_delivery`) against a commit belonging to a completely unrelated stack whose commit history happens to share that sha.

### Finding Description
The binding claimed to hold everywhere else in the engine is: `repository == Repository.from_github_repo_name(payload['repository']['full_name'])` before any state mutation. `Handler#stacks`/`#repository_name` implement this scoping [1](#0-0) , and it is honored by every `PullRequest::*` handler (`OpenedHandler`, `ClosedHandler`, `LabeledHandler`, `UnlabeledHandler`, `ReopenedHandler`), each of which resolves `repository` via `Shipit::Repository.from_github_repo_name(params.repository.full_name) || Shipit::NullRepository.new` before mutating anything [2](#0-1) .

`StatusHandler#process`, however, never calls `stacks`, `repository_name`, or `Repository.from_github_repo_name` at all: [3](#0-2) 

Instead it does a global, unscoped lookup: `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }`. The `commits` table's uniqueness constraint is `(sha, stack_id)`, not `sha` alone [4](#0-3) , and the schema confirms the same composite unique index [5](#0-4) . This is intentional: two different `Stack`/`Repository` records (e.g. a fork of a tracked repo, or two Shipit-tracked repos sharing upstream history) can legitimately contain `Commit` rows with the identical `sha`.

`verify_signature` in `WebhooksController` only checks the HMAC signature against the secret associated with `repository_owner` (`params.dig('repository','owner','login')` or `organization.login`) [6](#0-5) . It never cross-checks that the named `repository.full_name` corresponds to the stack whose commits get mutated — it only proves the payload was genuinely delivered by GitHub for *some* org/repo the attacker controls, not that the sha belongs to that repo's own tracked stack. Once the signature passes, `StatusHandler` runs and can create a `Status` on any commit row anywhere in the table that shares the sha, regardless of which repository actually emitted the webhook.

Exploit flow: an attacker who owns/administers a Shipit-tracked repository that is a fork of (or otherwise shares commit history with) a victim's Shipit-tracked repository sets a commit status via the standard GitHub Status API on a shared-history sha in their own fork. GitHub delivers a legitimately signed `status` webhook naming the attacker's own repository. `StatusHandler#process` looks up `Commit.where(sha: ...)`, finds the matching commit row belonging to the victim's stack (because that sha also exists there), and calls `commit.create_status_from_github!(params)`, writing a `Status` scoped to the victim's stack using attacker-chosen `state`/`description`/`target_url`/`context`. `Status` model callbacks `enable_ci_on_stack` and `schedule_continuous_delivery` then fire against the victim's stack [7](#0-6) .

### Impact Explanation
An attacker with no privilege over the victim's stack can inject a fabricated CI status (e.g. `state: "success"`) onto a commit in the victim's Shipit stack, as long as that commit's sha is also present in a repository the attacker controls (a fork or shared-history repo). If the victim stack has `continuous_deployment` enabled and CI gating relies on status checks, this can cause an unauthorized deploy to be scheduled via `schedule_continuous_delivery`, matching the Critical "payload for one repository mutating another's stack ... or an unauthorized deploy" category. The blast radius is any pair of Shipit-tracked repositories on the same instance that share commit history (a common real-world topology given forks/mirrors), and the attack is repeatable for every shared sha.

### Likelihood Explanation
Preconditions: the attacker needs their own Shipit-tracked stack (fork) whose GitHub webhook is validly configured (normal, unprivileged onboarding for any repo they administer), and a victim stack that shares commit history/shas with that fork. No secrets, sessions, or Shipit privileges are required — only the ability to set a commit status on a repo the attacker owns, which any repo admin/CI token can do. This is a realistic, low-cost, repeatable condition (forks are a standard workflow), though it is contingent on sha overlap existing, which is not guaranteed for arbitrary unrelated repositories, only for forked/shared-history ones.

### Recommendation
Scope `StatusHandler#process` to the sending repository by joining `Commit.where(sha: params.sha)` with `stacks`/`Repository.from_github_repo_name(repository_name)` (mirroring the pattern used in all `PullRequest::*` handlers), e.g. `stacks.flat_map(&:commits).where(sha: params.sha)` or a join through the resolved repository's stacks, before calling `create_status_from_github!`.

### Proof of Concept
```ruby
# test/models/shipit/webhooks/handlers/status_handler_test.rb
test "does not create a status on a commit belonging to an unrelated repository sharing the same sha" do
  victim_stack = shipit_stacks(:shipit)
  attacker_stack = shipit_stacks(:cyclimse) # different Repository

  shared_sha = "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef"
  victim_commit = victim_stack.commits.create!(sha: shared_sha, author: shipit_users(:walrus),
    committer: shipit_users(:walrus), authored_at: Time.now, committed_at: Time.now, message: "shared")
  attacker_stack.commits.create!(sha: shared_sha, author: shipit_users(:walrus),
    committer: shipit_users(:walrus), authored_at: Time.now, committed_at: Time.now, message: "shared")

  payload = {
    "sha" => shared_sha, "state" => "success",
    "repository" => { "full_name" => attacker_stack.github_repo_name }
  }

  assert_no_difference -> { victim_commit.statuses.count } do
    Shipit::Webhooks::Handlers::StatusHandler.new(payload).process
  end
  # Currently FAILS: StatusHandler writes a Status to victim_commit because
  # Commit.where(sha: shared_sha) is unscoped by repository.
end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
