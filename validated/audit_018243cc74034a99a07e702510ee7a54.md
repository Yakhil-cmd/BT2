### Title
Byte-prefix trick before '---' silently disables hookify block rules - ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter()` uses a strict `content.startswith('---')` check to detect YAML frontmatter, with no trimming of leading whitespace, CRLF, or a UTF-8 BOM. `open(file_path, 'r')` does not strip a BOM (only `utf-8-sig` would), so any checked-in `hookify.*.local.md` file whose first bytes are altered by even one leading character causes the frontmatter parser to fail silently and `load_rule_file()` to drop the rule and return `None`.

### Finding Description
`load_rule_file()` reads a rule file and passes its content to `extract_frontmatter()` [1](#0-0) . `extract_frontmatter()` immediately returns `({}, content)` if `content.startswith('---')` is `False`, with no normalization step (no `.lstrip()`, no BOM stripping, no CRLF handling) [2](#0-1) . `load_rule_file()` treats an empty frontmatter dict as "missing YAML frontmatter", logs a warning to stderr, and returns `None` [3](#0-2) , so `load_rules()` simply skips that file and it never becomes part of the rule set used by `pretooluse.py` / `RuleEngine.evaluate_rules()` [4](#0-3) [5](#0-4) .

Because the file is opened in text mode without `encoding='utf-8-sig'`, a leading UTF-8 BOM (`\ufeff`) is preserved in `content`, and any leading space or CRLF byte before the first `---` breaks the `startswith` check just as effectively. This means a single-byte edit at the very start of an otherwise valid, checked-in block rule file (e.g., introduced in a PR, or via an editor that silently re-adds a BOM/CRLF on save) is enough to make the rule file invalid in the eyes of the loader, without any parse error being raised — it degrades to the same code path as a file with no frontmatter at all.

### Impact Explanation
Hookify block rules are the mechanism used to deny dangerous Bash commands or file edits before they execute, via `RuleEngine.evaluate_rules()` returning `permissionDecision: deny` for `action: block` rules [6](#0-5) . If a rule file fails to load, it is excluded entirely from `load_rules()`'s output, so the rule engine never even considers it — the "deny" logic for that specific dangerous-command pattern is completely absent, not merely misconfigured. This matches an approval/enforcement bypass: a rule intended to block an unauthorized/dangerous command silently stops functioning, and the failure mode is a warning on stderr rather than a hard error, which is unlikely to be noticed in typical hook invocation (stdout is what's inspected for hook results).

### Likelihood Explanation
The precondition is that an attacker can modify or introduce a single leading byte (BOM, whitespace, CRLF) at the start of a checked-in `.claude/hookify.*.local.md` file, e.g., via a pull request that appears to be a trivial/no-op whitespace change. This is a very low-effort, highly repeatable manipulation — it requires no special privileges beyond the ability to submit a PR that gets merged (a normal contribution flow), and the resulting diff is easy to construct to look innocuous (e.g., "fixed line endings" or an editor auto-adding a BOM).

### Recommendation
Normalize frontmatter detection: strip a UTF-8 BOM (open files with `encoding='utf-8-sig'` or strip `\ufeff` explicitly) and `lstrip()` leading whitespace/newlines before checking `startswith('---')` in `extract_frontmatter()`. Additionally, treat "frontmatter present but empty" differently from "no `---` markers found at all" (e.g., distinguish `{}` from a sentinel), and consider raising a hard error / failing closed (or at least escalating to stdout/systemMessage) instead of merely logging to stderr and silently continuing, so that a broken block rule file is loudly surfaced rather than quietly dropped.

### Proof of Concept
Unit test in `plugins/hookify/core/config_loader.py` test suite:
```python
import io
from hookify.core.config_loader import load_rule_file

def test_bom_prefixed_block_rule_is_not_silently_dropped(tmp_path):
    content = "\ufeff---\nname: block-rm\nenabled: true\nevent: bash\naction: block\npattern: \"rm -rf\"\n---\n\nDangerous rm blocked!\n"
    rule_file = tmp_path / "hookify.block-rm.local.md"
    rule_file.write_text(content, encoding="utf-8")

    rule = load_rule_file(str(rule_file))

    # Current (vulnerable) behavior: rule is None, the block rule is dropped.
    # Expected (fixed) behavior:
    assert rule is not None
    assert rule.action == "block"
    assert rule.enabled is True
```
Expected result on current code: `load_rule_file` returns `None` and stderr contains `"missing YAML frontmatter (must start with ---)"`, demonstrating the intended `action: block` rule is never loaded into `load_rules()`'s output and therefore never enforced by `RuleEngine.evaluate_rules()`.

```python
def extract_frontmatter(content: str) -> tuple[Dict[str, Any], str]:
    """Extract YAML frontmatter and message body from markdown.

    Returns (frontmatter_dict, message_body).

    Supports multi-line dictionary items in lists by preserving indentation.
    """
    if not content.startswith('---'):
        return {}, content

    # Split on --- markers
    parts = content.split('---', 2)
    if len(parts) < 3:
        return {}, content
```
