### Title
Open redirect after OAuth completion via unvalidated `omniauth.origin` - (`app/controllers/shipit/github_authentication_controller.rb`)

### Summary
`Shipit::GithubAuthenticationController#callback` redirects the freshly-authenticated browser to `request.env['omniauth.origin']` with no host validation against `Shipit.host`. An attacker can supply an arbitrary external URL as the OAuth `origin` and have a victim's browser redirected there immediately after a successful, cookie-bearing GitHub login on the Shipit host.

### Finding Description
The claimed binding is `return_url.host == Shipit.host`. Tracing the code: `return_url = request.env['omniauth.auth'] ... session[:user_id] = sign_in_github(auth); session[:authenticated] = true; redirect_to(return_url)` [1](#0-0) . There is no comparison of `return_url`'s host to `Shipit.host` anywhere in the file, and the controller inherits directly from `ActionController::Base` rather than `ApplicationController`, so it is not covered by `Shipit::Authentication#force_github_authentication`, which is the only place in the engine that constructs a *safe* origin value from `request.original_url` [2](#0-1) . When a user is redirected into the OAuth flow by an attacker-controlled link containing an `origin` query parameter, the OmniAuth middleware persists that value and later exposes it via `request.env['omniauth.origin']`; the controller trusts it unconditionally and issues `redirect_to(return_url)` to that exact value with no allowlist check against `Shipit.host`. The equality does not hold: an attacker-chosen external host passes through untouched.

Exploit flow: attacker sends victim a link such as `GET /github/auth/github?origin=https://attacker.example/phish`. Victim completes the real GitHub OAuth handshake on the legitimate Shipit host; `sign_in_github` sets a genuine `session[:user_id]`/`session[:authenticated]=true` for the victim's own account, then the browser is redirected to `https://attacker.example/phish`. No existing guard intercepts this: `force_github_authentication` does not apply to this controller, and there is no `verify_signature`/webhook check involved since this is a plain browser OAuth path.

### Impact Explanation
The attacker cannot steal the victim's Shipit session cookie or GitHub token (those remain on the Shipit host), but they can force a just-authenticated Shipit user's browser to land on an attacker-controlled page immediately after a legitimate-looking GitHub login, which is directly useful for phishing continuation (e.g., presenting a fake "session expired, re-enter credentials" page with high victim trust because the redirect chain began on real Shipit/GitHub domains). This matches the explicitly listed High-severity category "session fixation / forced OAuth completion." It is repeatable against any victim who clicks a crafted link and is not scoped to any particular repository or stack — the blast radius is per-victim-click, not per-tenant data compromise.

### Likelihood Explanation
No special Shipit or repository configuration is required; the attacker needs only to construct a URL to the engine's public `/github/auth/github` OAuth start endpoint with an `origin` parameter and get a target to click it — a normal phishing/social step, but not one requiring any secret, privileged role, or session. This is an unauthenticated, zero-precondition attacker action.

### Recommendation
Validate `return_url` before redirecting: parse it and reject/replace with `root_path` when the parsed host is not blank and does not equal `Shipit.host` (or is not a relative/local path). Apply the same allowlist logic used implicitly by `force_github_authentication`, which only ever builds `origin` from `request.original_url` on the same host.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test ":callback redirects only to Shipit host, not attacker-controlled origin" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(raw_info: OmniAuth::AuthHash.new(
      id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
      login: 'shipit-user', avatar_url: 'https://example.com',
      api_url: 'https://github.com/api/v3/users/shipit-user'
    ))
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://evil.example/phish'

  get :callback

  # Binding under test: return_url.host == Shipit.host
  redirect_host = URI.parse(@response.redirect_url).host
  assert_equal Shipit.host, redirect_host, "expected redirect confined to Shipit.host, got #{@response.redirect_url}"
end
```
Currently this assertion fails because `@response.redirect_url == 'https://evil.example/phish'`, confirming the unrestricted forced redirect.

    def callback
      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']

      return render('failed', layout: false) if auth.blank?

      session[:user_id] = sign_in_github(auth)

      # We need to set this so that the /events and /sidekiq endpoint
      # which leverage `UserRequiredMiddleware` will recognize the user
      # is authenticated.
      session[:authenticated] = true

      redirect_to(return_url)
    end

      if current_user.logged_in? && current_user.requires_fresh_login?

        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
