### Title
Liquidators can seize all collateral after repaying only a fraction of the collateral-backed quote - ([File: contracts/controller/src/positions/liquidation/math.rs](contracts/controller/src/positions/liquidation/math.rs))

### Summary
`seize_all` treats a repayment as collateral-covering when it is merely within the USD value of one base unit of each selected debt token. Because a single low-decimal, high-price debt token can make that tolerance economically large, an unprivileged liquidator can pay less than the collateral-backed quote and still force `capped_ray` to the victim's entire collateral balance. [1](#0-0) [2](#0-1) 

### Finding Description
For an insolvent account with a positive liquidation-threshold proportion, `estimate_liquidation_amount` returns the collateral-backed quote `min(D, floor(C / (1 + base_bonus)))`, not the full debt. [3](#0-2) 

`normalize_repayment_plan` then sets `seize_all` when the kept repayment is nonzero and:

```text
repay_usd + Σ(one base unit USD value of each repaid debt asset) >= ideal_repayment_usd
``` [4](#0-3) 

This check treats the per-leg base-unit rounding slack as proof that the quote was economically reached. With one debt leg, `repay_usd = U` satisfies the check for every quote up to `2U`, where `U` is the value of one base unit. For a 3-decimal debt token priced at $1,000,000 per token, `U = $1,000`; paying one base unit can satisfy a quote of up to $2,000.

When `seize_all` is true, `calculate_seized_collateral` ignores the pro-rata `seizure_ray` and assigns each collateral leg `actual_ray`, the victim's full held value. [2](#0-1)  Execution accepts the partial repayment, measures it, and applies the resulting seizure through `liquidate`. [5](#0-4) 

### Impact Explanation
A liquidator can take all of an insolvent victim's collateral while repaying materially less than the quote that collateral is supposed to back. The liquidated user loses collateral far beyond the configured liquidation bonus, and the account can retain substantial unpaid debt afterward.

Using the example above:

- Debt token: 3 decimals, $1,000,000 per token; one base unit is worth $1,000.
- Victim debt: 3 base units, worth $3,000.
- Victim collateral: $1,995.
- Stamped/base liquidation bonus: 5%.
- Collateral-backed quote: `1,995 / 1.05 = $1,900`.
- Liquidator repays: 1 base unit, worth $1,000.
- `seize_all` check: `$1,000 + $1,000 >= $1,900`.
- Result: all $1,995 of collateral is seized for only $1,000 of debt repayment, less the bounded protocol fee.

This is theft of user funds and can also leave the affected debt market with additional unbacked obligations.

### Likelihood Explanation
The path is permissionless through `Controller::liquidate`; `process_liquidation` only requires the liquidator's authorization and a health factor below one before building the plan. [6](#0-5) 

The required state is ordinary liquidation state, not privileged configuration:

1. A borrowable debt market uses a sufficiently low supported decimal count and a high unit price.
2. A victim becomes insolvent through normal price movement or accrued interest.
3. The victim's collateral-backed quote falls within the base-unit slack window—for one leg, between one and two base units of that debt asset.
4. A liquidator submits a payment for one base unit and selects `SeizeMode::Transfer` when collateral cash exists, or `SeizeMode::Credit` to receive supply shares without requiring immediate pool cash.

Multiple selected repayment legs can add their base-unit values together, widening the aggregate slack.

### Recommendation
Do not convert “within one base unit” into authorization to seize all collateral.

- Remove the `repay_usd + one_unit_per_leg_usd >= ideal_repayment_usd` promotion, or restrict it to a protocol-bounded dust value independent of debt-token unit price.
- For an insolvent partial repayment, cap seizure at the value backed by the actual normalized repayment: `repay_usd * (1 + bonus)`, preserving existing rounding direction.
- If integer debt units make exact repayment impossible, either trim the seizure to the floored repayment or reject when the remaining quote error exceeds an explicit, bounded dust threshold.
- Add regression tests where a high-price, low-decimal debt token has `U < ideal <= 2U`; the expected result must not seize the entire collateral position.

### Proof of Concept
1. Configure or choose a borrowable debt asset with `asset_decimals = 3` and a strict oracle price of `$1,000,000` per whole token.
2. Give victim account `A` a debt position of `3` base units in that market, valued at `$3,000`.
3. Give `A` collateral worth `$1,995`, with a positive liquidation threshold and a stamped/base liquidation bonus of `500` bps. Choose parameters such that the account's health factor is below one.
4. The insolvency quote is `floor(1995 / 1.05) = $1,900`, which is below the $3,000 debt, so this is not a full close.
5. Liquidator `L` calls:

```text
liquidate(
    liquidator = L,
    account_id = A,
    debt_payments = [(debt_hub_asset, 1)],
    seize_mode = SeizeMode::Transfer
)
```

6. `calculate_repayment_amounts` records `repay_usd = $1,000`. `one_unit_per_leg_usd` contributes another `$1,000`, so `$1,000 + $1,000 >= $1,900` sets `seize_all`.
7. `calculate_seized_collateral` assigns `capped_ray = actual_ray` for every collateral leg and emits seizures for the victim's full collateral position.
8. Execution transfers only one debt-token base unit from `L`, burns that amount of debt, and pays nearly all $1,995 of collateral to `L`, minus only the configured fee on the realized bonus.

The correct outcome should seize approximately `$1,000 * 1.05 = $1,050` of collateral, not the full `$1,995`.
