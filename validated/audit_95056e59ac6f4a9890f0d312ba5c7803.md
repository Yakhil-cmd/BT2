### Title
Scaled-share value overflow permanently freezes an overgrown debt market - (File: common/src/rates/simulate.rs)

### Summary
Every accrual step expands the market's aggregate scaled supply and debt by the current indexes before choosing the borrow rate. Once `supplied × supply_index` or `borrowed × borrow_index` exceeds the `i128` RAY-value domain, `scaled_to_original` panics with `MathOverflow` before the borrow-index ceiling can clamp further growth. Because pool mutations accrue the market first, the overflow leaves the entire `(hub_id, asset)` market permanently unable to repay, withdraw, liquidate, clean bad debt, claim revenue, recapitalize, or update indexes.

### Finding Description
`global_sync` invokes `accrue_chunk` for each elapsed chunk, and `accrue_chunk` calls `accrue_step` with the persisted aggregate `borrowed`, `supplied`, `borrow_index`, and `supply_index`. [1](#0-0) [2](#0-1) 

`accrue_step` unconditionally reconstructs aggregate principal with `scaled_to_original` before calculating utilization and interest. [3](#0-2)  `scaled_to_original` performs `scaled.mul(index)`, which is a checked `scaled × index / RAY` operation. [4](#0-3)  The fixed-point helper panics when the representable result exceeds `i128`. [5](#0-4) 

The borrow-index cap does not prevent this condition. `update_borrow_index` multiplies the old index by the interest factor and only then clamps the resulting index to `MAX_BORROW_INDEX_RAY`. [6](#0-5)  Consequently, a large book can cross the aggregate-value ceiling while `borrow_index` remains far below `1e36`.

The spokes cap exposure in token units by converting the configured cap to scaled shares at the current index; they do not bound the future `scaled × index` result after accrual. [7](#0-6) [8](#0-7)  Debt and collateral shares therefore remain valid when minted, but their indexed value can later become unrepresentable.

### Impact Explanation
This is a permanent freeze of all funds and operations in the affected market. A borrower or liquidator cannot repay because repayment first loads and accrues the market; a supplier cannot withdraw for the same reason; and bad-debt cleanup, liquidation seizure, revenue claims, recapitalization, and further index updates all traverse the same accrual path.

Once the panic condition is reached, there is no in-contract recovery path that skips accrual: decreasing positions still requires loading the market, and decreasing the index is not possible outside the separate bad-debt write-down path, which itself accrues first. The market's suppliers lose access to their principal and borrowers' collateral can remain economically locked or unliquidatable through this market.

### Likelihood Explanation
The attack is permissionless but requires a very large market. A single attacker can seed it through `Controller::supply` and `Controller::borrow` with an account holding sufficient collateral elsewhere, then wait for interest growth and call `Controller::update_indexes` until the aggregate indexed value overflows.

The strongest route is:

1. Call `supply(caller, account_id, spoke_id, [(hub_asset, amount)])` repeatedly or across authorized accounts/spokes until the market reaches the largest aggregate supply allowed by its supply caps.
2. Use collateral on a solvent account and call `borrow(caller, account_id, [(hub_asset, amount)], to)` until utilization is near the configured maximum or the liquidation buffer.
3. Leave the position untouched while `borrow_index` compounds faster than `supply_index`.
4. Call `update_indexes(caller, [hub_asset])` after enough elapsed time. The next chunk that makes `borrowed × borrow_index / RAY` exceed `i128::MAX` reverts before committing an index update.
5. Every later `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `claim_revenue`, `recapitalize`, or `update_indexes` touching that market hits the same checked multiplication.

Likelihood is constrained by configured caps, available token supply, collateral capacity, and the time needed for index growth. It does not depend on oracle dishonesty, privileged execution, malformed parameters, callback reentrancy, or resource exhaustion; it is an arithmetic-state condition reachable through normal market usage.

### Recommendation
Bound the accrued RAY value, not only the indexes and entry caps. Practical mitigations include:

- Detect the upcoming `scaled × index` overflow in `accrue_step` and clamp or safely process accrual before the aggregate value becomes unrepresentable.
- Enforce a protocol-wide maximum `scaled × index` value at entry and before each accrual commit, with headroom for future index growth.
- Reduce caps according to worst-case index headroom, or derive caps from the reachable index ceiling rather than only current token units.
- Add an emergency market path that can stop accrual and allow repayment/withdrawal at the last committed index; it should be governance-controlled because skipping accrual changes creditor/debtor value.
- Add regression coverage that starts just below the `i128` aggregate-value boundary and proves `update_indexes`, `repay`, `withdraw`, and liquidation retain a defined recovery path.

### Proof of Concept
The minimal executable sequence is:

```text
// Assume:
// - `H` is a listed debt market with a steep but valid rate curve.
// - `A` has enough collateral capacity on some spoke to support the borrow.
// - `S` is near the maximum aggregate scaled supply admitted for `H`.

supply(attacker, accountA, spoke, [(H, supplyAmount)]);
borrow(attacker, accountA, [(H, borrowAmount)], Some(attacker));

// Wait until:
//     borrowed_scaled(H) * borrow_index(H) / RAY > i128::MAX
// while borrow_index(H) remains below MAX_BORROW_INDEX_RAY.

update_indexes(attacker, [H]);
```

The final call enters `global_sync`, calls `accrue_step`, and reaches `scaled_to_original(borrowed, borrow_index)` before any index clamp can prevent the aggregate-value overflow. The transaction reverts with `MathOverflow`, and because state is not committed, `last_timestamp` does not advance. Every subsequent operation on `H` retries the same overflowing conversion and reverts.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
    delta_scaled: Ray,

    index: Ray,
    decimals: u32,
```
