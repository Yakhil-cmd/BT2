### Title
Webhook signature verified against `repository.owner.login`, but handlers act on the attacker-controlled `repository.full_name` — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App configuration (and therefore which `webhook_secret`) to validate an incoming webhook against using `repository.owner.login` (or `organization.login`) taken straight from the unauthenticated JSON body. Once verification passes, every `Shipit::Webhooks::Handlers::Handler` subclass resolves the target `Repository`/`Stack` using a *different* attacker-controlled field from the same body: `repository.full_name` [1](#0-0) . In a multi-organization Shipit deployment (a documented, supported configuration [2](#0-1) ) where at least one configured organization has no `webhook_secret` set (also a documented, allowed configuration — the secret is described as "optional" [3](#0-2) ), signature verification for that organization is unconditionally bypassed: `verify_webhook_signature` returns `true` whenever `webhook_secret` is blank [4](#0-3) .

### Finding Description
The relevant equality that should hold is:

`organization authenticated by the signature check == organization that owns the repository the handler mutates`

Before/after an attacker's crafted request:
- Before: `verify_signature` computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` and fetches `Shipit.github(organization: repository_owner)` to obtain that org's `webhook_secret` for HMAC verification [5](#0-4) .
- After: `Handler#stacks` (used by every handler, including `PushHandler` and `StatusHandler`) resolves the repository via `payload.dig('repository', 'full_name')`, an entirely independent field in the same JSON body [1](#0-0) .

Nothing enforces that `repository.owner.login` matches the owner embedded in `repository.full_name`. An attacker can therefore submit a webhook body where:
- `repository.owner.login` (or `organization.login`) = `orgB`, an organization configured in Shipit with no `webhook_secret` (blank secret ⇒ `verify_webhook_signature` short-circuits to `true` regardless of the `X-Hub-Signature` header, per `return true unless webhook_secret` [6](#0-5) ), and
- `repository.full_name` = `orgA/critical-repo`, a *different*, properly-secured organization/repository that Shipit tracks.

The request sails through `verify_signature` (verified against `orgB`, which requires no secret at all) and is then dispatched to handlers that act on `orgA/critical-repo` because they only look at `full_name`. `Repository.from_github_repo_name` performs the lookup by splitting `full_name` on `/` with no cross-check against the field used for authentication [7](#0-6) .

### Impact Explanation
Once this binding is broken, an unauthenticated (with respect to `orgA`) attacker can drive any registered webhook handler against `orgA`'s stacks:
- `PushHandler` triggers `stack.sync_github(expected_head_sha:)` on `orgA` stacks with an attacker-chosen `after` SHA [8](#0-7) .
- `StatusHandler` creates arbitrary commit statuses (`state`, `context`, `description`, `target_url`) on any commit SHA it can guess/know for `orgA` via `commit.create_status_from_github!(params)` [9](#0-8) , which is the kind of check that Shipit deploy gating relies on to decide whether a commit is deployable.
- Other handlers (`check_suite`, `membership`, `pull_request/*`) are reachable through the same path and would similarly act on the spoofed `full_name` target.

This is a cross-repository/cross-organization write: an attacker who cannot forge `orgA`'s HMAC signature can nonetheless make Shipit mutate `orgA`'s tracked state (sync triggers, forged commit statuses) by piggy-backing on a co-tenant organization's weaker (secret-less) configuration. Forged "success" commit statuses can feed directly into deploy-readiness checks, which is consistent with the "unauthorized deploy" impact category.

### Likelihood Explanation
Requires no privileged access, no leaked secret, and no GitHub App credentials — only knowledge of two organization names/repo full names, both of which are public GitHub identifiers. The only precondition is that the Shipit instance runs a multi-organization configuration with at least one org lacking `webhook_secret`, which is an explicitly documented and supported setup (the example config ships with `webhook_secret: # nil`) rather than an exotic misconfiguration.

### Recommendation
Bind signature verification to the same identity used for repository/stack resolution:
- Verify the HMAC using the secret associated with the *actual* owner parsed from `repository.full_name` (not a separately-supplied `repository.owner.login`/`organization.login`), or
- After verification, assert `repository.owner.login == full_name.split('/').first` and reject (422) on mismatch, or
- Disallow secret-less webhook configuration entries when any other configured organization has a secret, closing the "weakest org bypasses strongest org" gap.

### Proof of Concept
1. Configure Shipit with two orgs: `orgA` (has `webhook_secret: strongsecret`) and `orgB` (has `webhook_secret:` blank/nil), per the documented multi-org config format [2](#0-1) .
2. POST to `/webhooks` with header `X-Github-Event: push` and any/no `X-Hub-Signature` value, and body:
```json
{
  "organization": { "login": "orgB" },
  "repository": { "owner": { "login": "orgB" }, "full_name": "orgA/critical-repo" },
  "ref": "refs/heads/master",
  "after": "deadbeef"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "orgB")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally [4](#0-3) .
4. `PushHandler` runs `stacks` → `Repository.from_github_repo_name("orgA/critical-repo")` → matches the real, secured `orgA/critical-repo` stacks and calls `sync_github(expected_head_sha: "deadbeef")` [8](#0-7) , despite the request never being validated against `orgA`'s actual `webhook_secret`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

**File:** app/controllers/shipit/webhooks_controller.rb (L24-49)
```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
