### Title
Asset Definer Can Unilaterally Rewrite the Attestor Trust List of a `spender_attested` Asset, Freezing Already-Issued Holdings — (File: `validation.js`)

### Summary
The `TokenManagerEth` finding describes a centralization risk where a single privileged `DEFAULT_ADMIN_ROLE` can redefine the critical trusted external reference (`ethErc20`) that governs spendability/settlement of a token, at any time, without consent of the affected users. The analogous mechanism in ocore is the `spender_attested` asset feature: the asset `definer_address` can unilaterally publish a new `asset_attestors` message at any time after the asset is issued, completely replacing the trust anchor (the attestor list) that determines who is currently allowed to transfer/issue the asset — with no requirement for holder consent, timelock, or grandfathering of previously attested addresses.

### Finding Description
When an asset is created with `spender_attested: true`, only addresses that appear in the attestor list are permitted to transfer or issue the asset (`validation.js` `validatePayment`, checking `objAsset.arrAttestedAddresses`): [1](#0-0) 

The attestor list itself is not fixed at asset-definition time — it can be updated later via an `asset_attestors` message, and the only authorization check is that the message is single-authored by the asset's `definer_address`: [2](#0-1) 

Crucially, when resolving the "current" attestor list for validation, ocore always takes the **most recently posted** `asset_attestors` unit and discards all prior ones — there is no grandfathering of already-issued coins or already-attested holders: [3](#0-2) 

The resolved list is then used to compute which authors are currently attested (`filterAttestedAddresses` / `loadAssetWithListOfAttestedAuthors`), and this attested-address set gates every subsequent transfer of the asset: [4](#0-3) 

This is structurally identical to the `TokenManagerEth` bug: a single address (the definer, analogous to `DEFAULT_ADMIN_ROLE`) fully controls the trusted external state (the attestor list, analogous to `ethErc20`) that a bridge/asset relies on to decide whether spends are valid, and that address can swap it out post-deployment with no counterparty consent.

### Impact Explanation
Once holders already own units of a `spender_attested` asset (obtained legitimately while attested), the definer can post a new `asset_attestors` message that:
- Removes the currently attested addresses from the trust list, immediately freezing every holder's ability to transfer their already-issued coins (denial of use / fund freezing for legitimate holders), since `arrAttestedAddresses` will no longer include them on the next validation pass, or
- Installs an attestor address the definer colludes with, then has that colluding attestor "attest" only addresses of the definer's choosing, effectively turning a public asset into a definer-gated whitelist after the fact, contradicting the trust assumptions holders had when they acquired the asset.

This matches the "AA fund loss or freezing" impact category: value legitimately held by third parties can be rendered unspendable by a single privileged party changing a trust reference they control, with no on-chain safeguard (no timelock, no opt-out, no historical grandfathering).

### Likelihood Explanation
Likelihood is Medium: this requires the asset's `definer_address` to act maliciously or be compromised — a smaller trust circle than an arbitrary attacker, similar to the original finding's `DEFAULT_ADMIN_ROLE`. Since `asset_attestors` messages are cheap, single-authored, and unrestricted in frequency (`validateAttestorListUpdate` only enforces the definer check and a valid attestor list format via `checkAttestorList`), a malicious/compromised definer can execute this at will, at any main-chain index, affecting all holders simultaneously.

### Recommendation
- Consider grandfathering already-attested addresses for coins that were issued/transferred while they were attested, rather than always applying the *latest* attestor list retroactively to previously issued outputs.
- Consider requiring some form of holder consent, delay, or immutability window before an attestor-list change takes effect, so definer-driven trust changes cannot instantly strip transfer rights from existing holders.
- At minimum, document this centralization/freezing risk clearly for asset issuers and wallets so users understand that `spender_attested` assets carry an implicit trust-in-definer risk that persists indefinitely after issuance.

### Proof of Concept
1. Definer `D` creates asset `A` with `spender_attested: true` and an initial `asset_attestors` list `[X]` (attestor `X`).
2. Attestor `X` attests holder `H` (`attestation` message, `address: H`).
3. `H` receives/holds units of asset `A`; per `validatePayment`, `H` is currently in `arrAttestedAddresses` and can freely transfer `A`.
4. `D` posts a new `asset_attestors` message for asset `A` with a different attestor list `[Y]` (a definer-controlled attestor). Validation only checks `objUnit.authors[0].address === objAsset.definer_address`: [5](#0-4) 
5. On the next validation of any transfer by `H`, `storage.readAsset`/`filterAttestedAddresses` resolve the attestor list to the newest unit (`[Y]`), and since `Y` never attested `H`, `H` is no longer in `arrAttestedAddresses` and `validatePayment` rejects `H`'s spend with `"none of the authors is attested"`: [6](#0-5) 
6. `H`'s previously-legitimate holdings of asset `A` are now permanently frozen unless `D`/`Y` chooses to re-attest `H`, demonstrating unilateral, unconsented control by a single privileged address over other users' asset spendability — the direct analog of the `TokenManagerEth` admin rug-pull risk.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

// filter only those addresses that are attested (doesn't work for light clients)
function filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAddresses, handleAttestedAddresses){
	conn.query(
		"SELECT DISTINCT address FROM attestations CROSS JOIN units USING(unit) \n\
		WHERE attestor_address IN(?) AND address IN(?) AND main_chain_index<=? AND is_stable=1 AND sequence='good' \n\
			AND main_chain_index>IFNULL( \n\
				(SELECT main_chain_index FROM address_definition_changes JOIN units USING(unit) \n\
				WHERE address_definition_changes.address=attestations.address AND main_chain_index<=? AND is_stable=1 AND sequence='good' ORDER BY main_chain_index DESC LIMIT 1), \n\
			0)",
		[objAsset.arrAttestorAddresses, arrAddresses, last_ball_mci, last_ball_mci],
		function(addr_rows){
			var arrAttestedAddresses = addr_rows.map(function(addr_row){ return addr_row.address; });
			handleAttestedAddresses(arrAttestedAddresses);
		}
	);
}

// note that light clients cannot check attestations
function loadAssetWithListOfAttestedAuthors(conn, asset, last_ball_mci, arrAuthorAddresses, bAcceptUnconfirmedAA, handleAsset){
	if (arguments.length === 5) {
		handleAsset = bAcceptUnconfirmedAA;
		bAcceptUnconfirmedAA = false;
	}
	readAsset(conn, asset, last_ball_mci, bAcceptUnconfirmedAA, function(err, objAsset){
		if (err)
			return handleAsset(err);
		if (!objAsset.spender_attested)
			return handleAsset(null, objAsset);
		filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAuthorAddresses, function(arrAttestedAddresses){
			objAsset.arrAttestedAddresses = arrAttestedAddresses;
			handleAsset(null, objAsset);
		});
	});
}
