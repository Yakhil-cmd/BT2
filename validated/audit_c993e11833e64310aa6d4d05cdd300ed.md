### Title
Unbounded recursion in `replaceInTemplate` via crafted `definition_template` payload — Denial of Service (Stack Overflow) - (File: definition.js)

### Summary
`definition.js`'s `replaceInTemplate` function recursively walks an attacker-supplied "definition template" array/object tree with no depth limit, mirroring the jQuery CVE-2016-10707 bug class (unbounded recursion on attacker-controlled nested input leading to stack-overflow DoS). A single unprivileged unit poster can post a `definition_template` message whose payload is an arbitrarily deeply nested array (only checked to be `isArrayOfLength(payload, 2)`), and then reference it from an address definition or authentifier evaluation using the `['definition template', ['unit', {...}]]` op, forcing every validating node to recurse over the deep structure with `replaceInTemplate`.

### Finding Description
The `definition_template` app payload is validated in `validateInlinePayload` only by checking `isArrayOfLength(payload, 2)`: [1](#0-0) 

No check is performed on the internal structure, depth, or size of the array itself (unlike the general network-joint check `isTooDeeplyNestedOrHasTooManyNodes`, which is applied to freshly received p2p joints in `network.js`/`wallet.js`, not to the semantic content of a `definition_template` payload during core unit validation).

Later, when an address definition or authentifier chain references this template via the `'definition template'` op, the stored payload is read from the DB, parsed, and passed to `replaceInTemplate`: [2](#0-1) 

`replaceInTemplate` recurses over the entire array/object without any depth guard: [3](#0-2) 

This is unlike other recursive evaluators in the codebase (`formula/validation.js`, `formula/evaluation.js`, `aa_validation.js`'s `validate()`), which explicitly guard against deep recursion via `depth > 100` checks or `count % 100 === 0` stack-unwinding tricks: [4](#0-3) [5](#0-4) [6](#0-5) 

`replaceInTemplate` has none of these protections, so a deeply nested array (e.g. `[[[[[...]]]]]`, which is very cheap to encode — each nesting level costs only 2 bytes) posted as a `definition_template` payload can drive `replaceInTemplate`'s recursion depth into the thousands while staying comfortably within `MAX_UNIT_LENGTH`.

### Impact Explanation
When a unit's address (or asset issue/transfer condition) definition contains `['definition template', ['<unit>', {params}]]` and `<unit>` references the maliciously crafted deeply-nested template, every node validating that unit (and re-validating on every subsequent spend from the address, per the comment at `definition.js:1449-1453` noting definitions are re-validated every time) will call `replaceInTemplate` on the deep structure, risking a "Maximum call stack size exceeded" JS exception. Because this occurs inside the synchronous unit-validation path (`validateAuthentifiers`/`validateDefinition`), an uncaught stack overflow can crash the Node.js process handling validation, causing a node-wide denial of service and preventing the network from confirming units that trigger this evaluation path.

### Likelihood Explanation
Likelihood is high for any unprivileged actor: posting a `definition_template` message requires no special privilege (any wallet address can compose one), and referencing it from an address definition via the `'definition template'` op is a standard, documented feature. No complexity/op counters guard the size of the template's raw JSON structure at ingestion, only `isArrayOfLength(payload, 2)`.

### Recommendation
Add an explicit depth/size guard to `replaceInTemplate` (mirroring the `depth > MAX_DEPTH` pattern used elsewhere, e.g. `aa_validation.js`'s `MAX_DEPTH = 100`), or validate the definition-template payload structure and nesting depth at `definition_template` message-validation time (in `validateInlinePayload`'s `definition_template` case) using `string_utils.isTooDeeplyNestedOrHasTooManyNodes`, rejecting templates that exceed a safe depth/node-count threshold before they can ever be stored or referenced.

### Proof of Concept
1. Attacker composes and posts a unit with a `definition_template` message whose payload is `['and_wrapper_placeholder', [1,2,3]]` structurally valid at top level (array of 2) but with one of the elements replaced by a very deeply nested array, e.g. `[Array(5000).fill(0).reduceRight((a) => [a], 1)]` — cheap to encode, easily fits within `MAX_UNIT_LENGTH`.
2. Attacker (or any other address owner) posts a second unit whose author `definition` (or an asset `issue_condition`/`transfer_condition`) contains `['definition template', ['<unit_from_step_1>', {}]]`.
3. Any node validating an authentifier/definition that reaches this `'definition template'` branch in `validateAuthentifiers`/`validateDefinition` calls `evaluate` → `replaceInTemplate(arrTemplate, params)`, which recurses 5000+ levels deep with no guard, risking a stack overflow and process crash on that node.
