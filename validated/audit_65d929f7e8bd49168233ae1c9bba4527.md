## Title
`Api::CCMenuController` lets a stack-scoped API token read the build status of any other stack - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`ApiClient` records can be scoped to a single stack via `stack_id`, and `Api::BaseController` enforces that scoping through the `stacks`/`stack` helper methods. [1](#0-0)  `Api::CCMenuController`, however, overrides `stack` to resolve `params[:stack_id]` directly against the global `Stack` relation, bypassing the scoping that binds an authenticated token to the specific stack it was authorized for. [2](#0-1) 

### Finding Description
`ApiClient#stack_id` exists specifically to restrict a token to a single stack; fixtures such as `here_come_the_walrus` demonstrate this pattern (`stack: shipit`, permissions `read:stack`). [3](#0-2)  `Api::BaseController#stacks` enforces this: if the client has a `stack_id`, the resolvable set of stacks is restricted to that one stack; only otherwise is `Stack.all` used, and `stack` resolves `params[:stack_id]` against that restricted scope. [1](#0-0) 

`Api::CCMenuController` inherits `require_permission :read, :stack`, which only checks that the token *has* the `read:stack` permission string via `ApiClient#check_permissions!`, not that it is scoped to the requested stack. [4](#0-3)  The controller then defines its own `stack` method that ignores the inherited scoping entirely and resolves any `params[:stack_id]` against the full `Stack` table:
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
``` [5](#0-4) 

This breaks the binding "a stack a token authorizes versus a stack it touches": the token authorization check (`check_permissions!`) is against a generic `read:stack` string, while the object actually rendered (`stack.deploys_and_rollbacks.last`, `stack` fields) comes from any attacker-chosen `stack_id`, not the one the client's `stack_id` column restricts it to.

### Impact Explanation
A holder of a valid, stack-scoped `read:stack` token (e.g. a CCMenu client meant only for one specific stack) can pass an arbitrary `stack_id` param to `Api::CCMenuController#show` and obtain that other stack's name, activity, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, and `webUrl` for any stack in the Shipit instance - including private/internal stacks the token was never meant to see. [6](#0-5)  This is an unauthenticated-for-that-stack read of stack/build state, matching the "unauthorized read of stack state" impact class, since the per-stack authorization boundary encoded by `ApiClient#stack_id` is not enforced here.

### Likelihood Explanation
Exploitation only requires possession of any valid API token with the `read:stack` permission (regardless of which stack it is scoped to) and knowledge or guessing of another stack's `owner/name/environment` param triple used by `Stack.from_param!`. [7](#0-6)  Any stack-scoped CCMenu client (a common integration for CI dashboards) is enough; no privileged access or additional exploit chain is needed once such a token exists.

### Recommendation
Have `Api::CCMenuController#stack` resolve through the inherited, permission-scoped `stacks` collection (i.e. `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!`, so the `ApiClient#stack_id` restriction enforced in `Api::BaseController` cannot be bypassed by subclass overrides.

### Proof of Concept
1. Create (or use) an `ApiClient` scoped to Stack A with `stack_id` set and permission `read:stack` (as in fixture `here_come_the_walrus`). [3](#0-2) 
2. Authenticate to `Api::CCMenuController#show` using that token, but pass `stack_id` for Stack B (a different stack the token was never granted access to), e.g. `GET /api/stacks/:stackB_owner/:stackB_name/:stackB_env/cc.xml?token=<TokenForStackA>`.
3. Because `authenticate_api_client` only verifies the token is valid and `require_permission :read, :stack` only checks the generic permission string, and `stack` resolves `Stack.from_param!(params[:stack_id])` against the full `Stack` table, the request succeeds and returns Stack B's build status/name/URL, even though the token is scoped to Stack A only. [8](#0-7)
