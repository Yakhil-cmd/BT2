### Title
Missing `return` after error handling causes double processing of malformed private payment chains - (File: network.js)

### Summary
In `network.js`, the `validateAndSave` inner function of `handleSavedPrivatePayments` fails to `return` after handling a `try/catch` error, causing the function to fall through and still invoke `privatePayment.validateAndSavePrivatePaymentChain` on a private payment element that already failed basic hash validation, and to invoke the completion callback `cb` a second time.

### Finding Description
`handleSavedPrivatePayments` iterates over rows of `unhandled_private_payments` and, for each one, calls `validateAndSave()`, which attempts to compute the payload hash of the head private element: [1](#0-0) 

```
var validateAndSave = function(){
    var objHeadPrivateElement = arrPrivateElements[0];
    try {
        var json_payload_hash = objectHash.getBase64Hash(objHeadPrivateElement.payload, true);
    }
    catch (e) {
        console.log("getBase64Hash failed for private element", objHeadPrivateElement.payload, e);
        if (ws)
            sendResult(ws, {private_payment_in_unit: row.unit, result: 'error', error: e.toString()});
        deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb);
    }
    var key = 'private_payment_validated-'+objHeadPrivateElement.unit+'-'+json_payload_hash+'-'+row.output_index;
    privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, { ... });
};
```

When `objectHash.getBase64Hash` throws (e.g., the private element's `payload` is malformed and cannot be hashed), the `catch` block reports the error and calls `deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb)`, which itself eventually invokes `cb` (the `async.each` item-completion callback), see the analogous flow used elsewhere in this file: [2](#0-1) . However, there is no `return` statement after this call, so execution falls through to compute `key` using the now-`undefined` `json_payload_hash`, and then unconditionally calls `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {...})` — the very entry point that performs the actual asset/private-payment validation and database writes for divisible/indivisible private payments, per `private_payment.js`: [3](#0-2) 

This second call installs its own `ifOk`/`ifError`/`ifWaitingForChain` handlers, every one of which also calls `deleteHandledPrivateChain(..., cb)` or `cb()` directly: [4](#0-3) 

As a result, on the exact code path where the private element already failed a basic integrity check (hash computation), the code:
1. Calls `cb` (the `async.each` iteratee callback) a second time once `privatePayment.validateAndSavePrivatePaymentChain`'s inner callbacks fire, which is invalid usage of `async.each` and can produce inconsistent completion tracking, exceptions ("callback called multiple times"), or premature termination of the parallel batch.
2. Passes the malformed/un-hashable private element on to `validateAndSavePrivatePaymentChain` → `storage.readAsset` → `divisibleAsset`/`indivisibleAsset` validation and persistence logic, which operate on data that was already known to be inconsistent with the on-chain payload structure. Because `json_payload_hash` is `undefined`, the `key` used with `eventBus.emit(key, ...)` in `handlePrivatePaymentChains` (wallet.js) will not match the key that `wallet.js` is listening on, so a legitimately waiting caller in `handlePrivatePaymentChains` (`wallet.js`, `eventBus.once(key, ...)`) will never be resolved for this chain, silently stalling processing of that private payment for the user.

### Impact Explanation
This is a node/wallet-state-consistency bug reachable by any peer that sends a private payment chain whose payload cannot be hashed (e.g. non-serializable/malformed payload fields), causing:
- Double invocation of the `async.each` iteratee callback, which can corrupt the counting of the batch of `unhandled_private_payments` being processed and, depending on the `async` library's semantics, throw or silently misbehave, potentially leaving the `["saved_private"]` mutex lock or `assocNewUnits` bookkeeping in an inconsistent state.
- Continued processing (DB validation/save attempts) of a private payment element that already failed basic hash-integrity checks, which is exactly the "loss of assets and/or wrong contract state" impact class described in the source report: proceeding with further operations after an error/result was not properly handled.
- A permanently unresolved event key in `handlePrivatePaymentChains` (wallet.js), which can leave in-flight promise/callback chains hanging, freezing that private-payment acknowledgment flow for the wallet.

### Likelihood Explanation
The trigger condition (payload for which `objectHash.getBase64Hash` throws) is attacker-controllable: a counterparty in a private-payment chain (or a peer forwarding one) fully controls the `payload` object of the chain elements they send, per the private-payment message handling path (`network.js` `handleOnlinePrivatePayment` → `unhandled_private_payments` table → `handleSavedPrivatePayments`). No special privileges are required beyond being a payment counterparty capable of sending a private-payment JSON to a node/wallet, which is a normal part of the private-payment protocol.

### Recommendation
Add a `return` immediately after the `deleteHandledPrivateChain(...)` call inside the `catch` block in `validateAndSave` (network.js, around line 2476) so that execution does not fall through to compute `key`/invoke `privatePayment.validateAndSavePrivatePaymentChain` after an unrecoverable hashing error. This ensures `cb` is invoked exactly once per row and that malformed private payment elements are never passed further into validation/persistence logic.

### Proof of Concept
1. A peer/counterparty sends a private-payment chain via the standard flow ending at `network.handleOnlinePrivatePayment`, whose head element's `payload` is crafted so that `objectHash.getBase64Hash(payload, true)` throws (e.g., contains a value type unsupported by the hashing routine, such as a circular reference or unsupported primitive) while still passing the earlier `isNonemptyObject`/`isNonemptyString` checks performed in `handlePrivatePaymentChains` (wallet.js) and `handleOnlinePrivatePayment` (network.js) that don't attempt hashing.
2. This element is queued into `unhandled_private_payments` and later picked up by `handleSavedPrivatePayments`.
3. In `validateAndSave`, the `try` block throws; the `catch` block logs the error, sends an error result if `ws` exists, and calls `deleteHandledPrivateChain(..., cb)` — invoking `cb` once.
4. Execution falls through (no `return`), computing `key` with `json_payload_hash === undefined`, and calls `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {...})`, whose `ifOk`/`ifError`/`ifWaitingForChain` handlers each invoke `cb` again (directly or via `deleteHandledPrivateChain`), resulting in `cb` being called twice for the same `async.each` iteration, and in a second, unnecessary DB validation/write attempt against `storage.readAsset`/`divisibleAsset`/`indivisibleAsset` for an element already known to be malformed.

function validateAndSavePrivatePaymentChain(arrPrivateElements, callbacks){
	if (!ValidationUtils.isNonemptyArray(arrPrivateElements))
		return callbacks.ifError("no priv elements array");
	var headElement = arrPrivateElements[0];
	if (!headElement.payload)
		return callbacks.ifError("no payload in head element");
	var asset = headElement.payload.asset;
	if (!asset)
		return callbacks.ifError("no asset in head element");
	if (!ValidationUtils.isNonnegativeInteger(headElement.message_index))
		return callbacks.ifError("no message index in head private element");
	
	var validateAndSave = function(){
		storage.readAsset(db, asset, null, function(err, objAsset){
			if (err)
				return callbacks.ifError(err);
			if (objAsset.is_private !== 1)
				return callbacks.ifError("asset is not private");
			if (!!objAsset.fixed_denominations !== !!headElement.payload.denomination)
				return callbacks.ifError("presence of denomination field doesn't match the asset type");
			if (!!objAsset.fixed_denominations !== ("output" in headElement))
				return callbacks.ifError("divisible asset must not have output field, indivisible must");
			db.takeConnectionFromPool(function(conn){
				conn.query("BEGIN", function(){
					var transaction_callbacks = {
						ifError: function(err){
							conn.query("ROLLBACK", function(){
								conn.release();
								callbacks.ifError(err);
							});
						},
						ifOk: function(){
							conn.query("COMMIT", function(){
								conn.release();
								callbacks.ifOk();
							});
						}
					};
					// check if duplicate
					var sql = "SELECT address, denomination, amount, blinding FROM outputs WHERE unit=? AND asset=? AND message_index=?";
					var params = [headElement.unit, asset, headElement.message_index];
					if (objAsset.fixed_denominations){
						if (!ValidationUtils.isNonnegativeInteger(headElement.output_index))
							return transaction_callbacks.ifError("no output index in head private element");
						sql += " AND output_index=?";
						params.push(headElement.output_index);
					}
					conn.query(
						sql, 
						params, 
						function(rows){
							if (rows.length > 1)
								throw Error("more than one output "+sql+' '+params.join(', '));
							if (rows.length > 0 && rows[0].address){ // we could have this output already but the address is still hidden
								const stored = rows[0];
								const payload = headElement.payload;
								let bDuplicate = false;
								if (objAsset.fixed_denominations){ // the row we selected is exactly headElement.output_index, filtered in sql above
									const claimed_output = payload.outputs?.[headElement.output_index];
									const revealed_output = headElement?.output;
									bDuplicate =
										ValidationUtils.isNonemptyObject(claimed_output)
										&& ValidationUtils.isNonemptyObject(revealed_output)
										&& stored.denomination === payload.denomination
										&& stored.amount === claimed_output.amount
										&& stored.address === revealed_output.address
										&& stored.blinding === revealed_output.blinding;
								}
								else // divisible outputs are never hidden individually and sql has no output_index filter, so match against any of them
									bDuplicate = (payload.outputs || []).some(output => {
										return ValidationUtils.isNonemptyObject(output)
											&& stored.denomination === 1
											&& stored.amount === output.amount
											&& stored.address === output.address
											&& stored.blinding === output.blinding;
									});
								if (bDuplicate) {
									console.log("duplicate private payment "+params.join(', '));
									return transaction_callbacks.ifOk();
								}
							}
							var assetModule = objAsset.fixed_denominations ? indivisibleAsset : divisibleAsset;
							assetModule.validateAndSavePrivatePaymentChain(conn, arrPrivateElements, transaction_callbacks);
						}
					);
				});
			});
		});
	};
	
	if (conf.bLight)
		findUnfinishedPastUnitsOfPrivateChains([arrPrivateElements], false, function(arrUnfinishedUnits){
			(arrUnfinishedUnits.length > 0) ? callbacks.ifWaitingForChain() : validateAndSave();
		});
	else
		validateAndSave();
}
