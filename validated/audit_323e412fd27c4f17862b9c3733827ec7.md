The GHSA-xpmx-h7xq-xffh report describes Apollo's `admin-service` lacking any built-in access control when mistakenly exposed to the internet — a Java/Maven configuration-management service with no analog to FRAME extrinsics, XCM, or contracts execution. Searching for the closest architectural analog in this Rust/Substrate codebase — the node's JSON-RPC surface, which (like Apollo's admin API) is documented as "designed to work" only on trusted/local interfaces — shows the opposite of the reported flaw: built-in access control already exists and is enforced by default.

Specifically:
- `DenyUnsafe` is inserted as a request extension on every RPC connection and unsafe methods are rejected unless explicitly allowed [1](#0-0) .
- The policy is derived per-listen-address from whether the address is loopback and which `RpcMethods` set is configured, defaulting to denying unsafe calls on any non-loopback interface [2](#0-1) .
- The CLI requires an explicit `--rpc-external`/`--unsafe-rpc-external` opt-in to bind beyond localhost, and additionally refuses to allow unsafe methods for validators unless the operator explicitly overrides it, printing an explicit warning about the risk [3](#0-2) .
- `deny_unsafe` is computed and attached per accepted connection inside the server loop, so even multi-endpoint configurations (`--experimental-rpc-endpoint`) enforce the policy per listen address rather than relying on a single global toggle [4](#0-3) .

Because the "intranet-only service without built-in access control" pattern that caused CVE-2020-15170 does not exist here — the RPC surface has explicit, default-deny access control that must be intentionally and explicitly disabled by the node operator — there is no demonstrable analog vulnerability to report. No unauthenticated, attacker-reachable "admin" surface analogous to apollo-adminservice was found reachable through a signed extrinsic, XCM message, or contract call path as required by the analysis method.

/// Get the `deny_unsafe` setting based on the address and the RPC methods exposed by the interface.
pub fn deny_unsafe(addr: &SocketAddr, methods: &RpcMethods) -> DenyUnsafe {
	match (addr.ip().is_loopback(), methods) {
		(_, RpcMethods::Unsafe) | (true, RpcMethods::Auto) => DenyUnsafe::No,
		_ => DenyUnsafe::Yes,
	}
