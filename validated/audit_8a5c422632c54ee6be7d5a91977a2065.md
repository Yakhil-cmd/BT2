### Title
Webhook signature bypass via unauthenticated/no-secret organization allows forging events (status, push) for any tracked repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to use for HMAC verification based on `repository_owner`, a field pulled straight from the untrusted, attacker-supplied JSON body (`params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`). The event handlers that actually act on the payload (`PushHandler`, `StatusHandler`, etc.), however, resolve the target `Stack`/`Repository` from a *different* field: `payload.dig('repository', 'full_name')`. Because `GithubApp#verify_webhook_signature` returns `true` unconditionally whenever the selected organization has no `webhook_secret` configured, an org with a blank secret becomes a skeleton key: an attacker can name that org in `repository.owner.login` (which only affects HMAC selection) while pointing `repository.full_name` at a completely different, victim stack (which drives the actual write).

### Finding Description [1](#0-0) [2](#0-1) 

`verify_signature` does:
```
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
head(422) unless verified
```
and `repository_owner` is derived purely from the request body itself, not from any trusted, out-of-band source.

`GithubApp#verify_webhook_signature` short-circuits to `true` when no secret is configured for that organization: [3](#0-2) 

The example secrets template ships with `webhook_secret` left blank/optional per org, and the setup docs describe the webhook secret as "(optional)": [4](#0-3) [5](#0-4) 

Meanwhile, every default handler determines *which* repository/stack is mutated using `payload.dig('repository', 'full_name')`, not `repository.owner.login`: [6](#0-5) 

For example `PushHandler` calls `stack.sync_github` for every non-archived stack on the resolved repo/branch: [7](#0-6) 

The bug-class equality this breaks: **the organization that authenticated the webhook (`repository.owner.login`, used to pick the verifying secret) ≠ the repository that is actually written to (`repository.full_name`, used to resolve the `Stack`)**. Signature verification authenticates only "some org configured in Shipit has this secret (or none)"; it does not bind the verified identity to the resource being mutated inside the payload. This is structurally the same class of bug as `CollectionShutdown::execute()`: a decision made against one reference (approved token IDs / authenticated org) is not enforced to cover the actual entity acted upon (locked NFTs / target repository).

### Impact Explanation
Combined with `StatusHandler` (which creates/updates a `Status` on an arbitrary commit of the target stack based only on `repository.full_name`, `sha`, and `state`), an attacker can forge a `success` CI status for any commit on any tracked stack. If that stack has `continuous_deployment` enabled, this directly triggers an unauthorized deploy, confirmed by the test showing that creating a `success` status enqueues `ContinuousDeliveryJob` and creates a `Deploy`: [8](#0-7) [9](#0-8) 

This satisfies the Critical impact bar ("an unauthorized deploy"): a status forged under cover of a permissive/no-secret org authorizes writes (a synthetic passing CI status → automatic deploy) against a repository that org has no actual relationship to.

### Likelihood Explanation
This requires only that at least one organization configured on the Shipit instance has `webhook_secret` unset — which the shipped secrets template explicitly presents as a normal, optional configuration (`webhook_secret: # nil`) and the setup docs mark as optional. No credentials, GitHub App installation, or repository write access on the attacker's side are needed — `/webhooks` is a public endpoint (`GithubAuthentication`/session checks are not applied to `WebhooksController`, only signature verification is), and the attacker only needs to know that such an org exists and the `full_name` of the victim repository, both of which are visible from the public Shipit web UI (stacks listing).

### Recommendation
Bind the signature-verifying organization to the same field used to resolve the acted-upon repository. Concretely:
- Derive `repository_owner` and the repository used by handlers from the same canonical field (e.g. always `repository.full_name`'s owner segment), and reject events where `repository.owner.login`/`organization.login` disagree with `repository.full_name`'s owner.
- Do not allow `verify_webhook_signature` to silently pass when `webhook_secret` is blank in production; require a secret for every configured organization, or explicitly disallow "no secret" configurations from being treated as globally trusted.
- After resolving the target `Stack`/`Repository` in each handler, re-check that its owning organization matches the organization whose secret verified the request.

### Proof of Concept
1. Deploy configures two orgs in `secrets.yml`: `org-no-secret` (no `webhook_secret`) and `victim-org` (owns tracked stack `victim-org/victim-repo`, `continuous_deployment: true`).
2. Attacker POSTs to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "sha": "<victim commit sha>",
  "state": "success",
  "context": "ci/travis",
  "branches": [{"name": "main"}],
  "repository": {"owner": {"login": "org-no-secret"}, "full_name": "victim-org/victim-repo"}
}
```
3. `verify_signature` computes `repository_owner = "org-no-secret"`, fetches its (secret-less) `GithubApp`, and `verify_webhook_signature` returns `true` without checking any HMAC.
4. `StatusHandler` resolves the target repository/stack from `repository.full_name = "victim-org/victim-repo"` and creates a passing status on the given commit.
5. Because the stack has `continuous_deployment` enabled, `ContinuousDeliveryJob` is enqueued and a `Deploy` is created against `victim-org/victim-repo`, entirely outside GitHub's real CI/webhook flow.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
