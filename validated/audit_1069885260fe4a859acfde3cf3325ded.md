### Title
Signature verification keys off an attacker-controlled `repository.owner.login`/`organization.login` field that is decoupled from the field actually acted upon, allowing webhook forgery when any configured GitHub App has no `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which per-organization `GitHubApp` (and therefore which HMAC secret) to verify a webhook payload against by reading an **unverified** field out of the raw JSON body (`repository.owner.login`, falling back to `organization.login`). That organization selection is completely independent from the field that downstream webhook handlers actually use to decide which `Team`/`Repository`/`Stack` to mutate (`organization.login` for `MembershipHandler`, `repository.full_name` for `PushHandler`/PR handlers). Because `GitHubApp#verify_webhook_signature` unconditionally returns `true` when an app's `webhook_secret` is unset/blank, an unauthenticated attacker who knows that *any* org configured in Shipit's multi-tenant `secrets.github` map has no webhook secret can pick that org for the verification-selection field while targeting a completely different, secret-protected org/repo/team for the actual mutation field.

### Finding Description
`verify_signature` computes the app used for HMAC verification from unauthenticated JSON: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` treats a missing/blank `webhook_secret` as "always valid", regardless of the `X-Hub-Signature` header supplied: [3](#0-2) 

Shipit explicitly supports a multi-tenant configuration where each organization has its own independent `webhook_secret` (documented as optional): [4](#0-3) [5](#0-4) 

The field used to *select the verifier* (`repository.owner.login` / `organization.login`) is never cross-checked against the field the handlers use to decide *what gets mutated*. For membership events, `MembershipHandler` uses `params.organization.login` (a field independent from the one `verify_signature` consulted) to create/attach a `Team`, and `params.team.id` to look up an existing `Team` record by its real GitHub numeric id: [6](#0-5) 

Authorization to use Shipit at all is gated purely on DB-level `Team` membership matching `Shipit.github_teams` ids: [7](#0-6) [8](#0-7) 

The binding that should hold is:
`organization whose secret authenticated the request == organization/team the request is allowed to mutate`

but the code instead lets an attacker satisfy:
`organization whose secret authenticated the request (attacker-chosen, secret-less org) != organization/team actually mutated (victim org with Shipit.github_teams membership)`

**Attack path:**
1. Deployment configures multiple GitHub Apps in `secrets.github` (documented multi-org support). At least one org, e.g. `no-secret-org`, has `webhook_secret` unset (explicitly allowed as optional per `docs/setup.md`).
2. Attacker (no Shipit session, no GitHub credentials, no API token) POSTs to the public `/webhooks` endpoint with `X-Github-Event: membership`, an arbitrary/absent `X-Hub-Signature`, and body:
   ```json
   {
     "action": "added",
     "team": { "id": 12345, "name": "admins", "slug": "admins", "url": "https://api.github.com/teams/12345" },
     "organization": { "login": "victim-org" },
     "member": { "login": "attacker-github-login" },
     "repository": { "owner": { "login": "no-secret-org" } }
   }
   ```
   (`team.id` = the real, numeric GitHub team id backing the `Team` row Shipit already created for `victim-org/admins`, which is listed in `Shipit.github_teams` / `oauth.teams`.)
3. `verify_signature` resolves `repository_owner` to `"no-secret-org"`, whose `GitHubApp#verify_webhook_signature` returns `true` unconditionally — the request passes signature verification with no valid HMAC at all.
4. `MembershipHandler` runs using the unrelated `organization.login` = `"victim-org"` and the real `team.id`, finds the existing legitimate `Team` row, and calls `team.add_member(User.find_or_create_by_login!("attacker-github-login"))`.
5. The attacker's real GitHub account is now a DB-level member of a `Team` whose id is in `Shipit.github_teams`, so `User#authorized?` returns `true` and the attacker gets full authenticated access to the Shipit UI/API for that org's stacks — without ever being a member of the real GitHub team.

### Impact Explanation
This is an authentication/authorization bypass that escalates an unprivileged, unauthenticated network attacker into `Shipit.github_teams` authorization by forging a GitHub webhook whose signature check is trivially satisfiable due to organization-key confusion. This matches the "High - escalation into `Shipit.github_teams` authorization" impact tier. The same organization-key confusion also lets an attacker forge `push`/`status`/PR events to trigger `GithubSyncJob`/`CacheDeploySpecJob` against arbitrary tracked stacks by mismatching `repository.owner.login` vs `repository.full_name`.

### Likelihood Explanation
Requires only that one org in a multi-tenant Shipit deployment has no `webhook_secret` configured (explicitly documented as optional, and shown as a valid/nil value in the repo's own sample secrets files) plus knowledge/guessability of a target team's real (often low-entropy, sequential) GitHub team id. No credentials, sessions, or tokens of any kind are required to reach `/webhooks`.

### Recommendation
Do not let any attacker-controlled, unverified field determine which secret is used to verify the signature independently of the field(s) the handler will act on. Concretely: verify the HMAC using the secret that will ultimately gate the same organization/repository the handler mutates (i.e., derive `repository_owner` from the same canonical field used later, and reject cross-field mismatches), and stop treating a blank `webhook_secret` as "signature always valid" — instead require every configured GitHub App used for webhook delivery to have a non-blank `webhook_secret`, or fail closed.

### Proof of Concept
See attack path steps above: with a multi-org config where `no-secret-org.webhook_secret` is nil and `victim-org/admins` is in `Shipit.github_teams`, POST the crafted `membership` payload to `/webhooks` with an arbitrary `X-Hub-Signature` (or none). `WebhooksController#verify_signature` selects `no-secret-org`'s app (via `repository.owner.login`), which accepts any signature; `MembershipHandler#process` then adds the attacker's GitHub login to the real `victim-org/admins` `Team` row (matched via the real `team.id`), granting them `authorized?` on Shipit. module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class MembershipHandler < Handler
        params do
          requires :action, String
          requires :team do
            requires :id, Integer
            requires :name, String
            requires :slug, String
            requires :url, String
          end
          requires :organization do
            requires :login, String
          end
          requires :member do
            requires :login, String
          end
        end
        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
      end
    end
  end
end
