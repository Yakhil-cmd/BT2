### Title
Supply-index floor clamp resurrects wiped suppliers' claims and drains fresh deposits after bad-debt write-down - (File: contracts/pool/src/interest.rs)

### Summary
CVE-2022-21556 is an optimizer logic error enabling unauthorized modification of critical data plus a full denial of service. The analog in XOXNO Lending is the bad-debt write-down in `apply_bad_debt_to_supply_index` (`contracts/pool/src/interest.rs:73-89`), which is reachable from the permissionless `clean_bad_debt` / liquidation seize path (`contracts/pool/src/ops/seize.rs:24-27`). When socialized bad debt equals or exceeds total supplied value, the function clamps the new supply index **up** to `SUPPLY_INDEX_FLOOR_RAW` instead of zeroing supplier claims, leaving every wiped supplier a positive residual claim (`scaled_shares * floor / RAY`). Those unbacked claims later settle against fresh cash: a subsequent honest `supply` deposits real tokens, and the wiped supplier's `withdraw` pays out real tokens against the phantom residual, stealing the fresh deposit.

### Finding Description
`apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - min(bad_debt, total_supplied_value)`; on full wipeout `remaining == 0`, so `reduction_factor == 0` and `new_supply_index == 0` — but the result is clamped to `SUPPLY_INDEX_FLOOR_RAW` (`contracts/pool/src/interest.rs:88`). Shares are not burned; `cache.supplied` is unchanged. Every supplier's `unscale_supply_floor(scaled)` therefore still returns `scaled * floor / RAY > 0`. There is no supply guard that re-scales or zeroes existing share balances: the in-tree test `test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard` (`contracts/pool/tests/interest.rs:317-369`) demonstrates end-to-end that a wiped supplier's `resolve_withdrawal(i128::MAX, scaled)` pays `gross` equal to the next depositor's entire deposit, leaving `cash < fresh_claim`.

Reachable path for a single unprivileged address:
1. Supply a dominant share in a hub market and borrow to near-max LTV against cheap collateral (or simply cause/await bad debt via price movement).
2. Once HF < 1 and collateral is exhausted, any caller triggers `liquidate`/`clean_bad_debt` → controller emits a `PoolSeizeEntry{side: Borrow}` → pool `seize::apply` → `apply_bad_debt_to_supply_index` with `bad_debt >= total_supplied_value` → index clamps to floor.
3. Attacker (also a wiped supplier) retains residual scaled shares worth `scaled * floor / RAY`.
4. A victim supplies fresh tokens; attacker calls `withdraw` — `resolve_withdrawal` honors the floor-priced claim and transfers the victim's tokens.

### Impact Explanation
Theft of user funds / protocol insolvency: unbacked residual claims are settled 1:1 (at floor price) against cash belonging to post-wipeout suppliers. The pool can be drained to zero while honest suppliers' claims remain, i.e. unauthorized modification of critical accounting data (the index) produces exactly the CVE's "unauthorized modification of all accessible data" plus a solvency failure.

### Likelihood Explanation
Requires a bad-debt event approaching total supplied value — a high bar, but the trigger inputs (supply, borrow, liquidate, clean_bad_debt, withdraw) are all permissionless, and the attacker can amplify the wipeout by being the marginal large supplier whose own bad debt socialization hits the cap. The bug is deterministic once the clamp engages; the only uncertainty is market conditions producing near-total wipeout. Medium.

### Recommendation
On full wipeout, reset supplier claims instead of clamping the index: e.g. when `capped == total_supplied_value`, set `supply_index` to the floor but also zero/redistribute `supplied` shares (or mark the market wiped and require re-initialization) so no residual claim survives. Alternatively, burn the residual scaled supply pro-rata when the floor clamp engages, matching the clamp with an explicit share write-down.

### Proof of Concept
The in-tree test `test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard` (`contracts/pool/tests/interest.rs:317-369`) is a direct PoC: after `apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY))` on a `1_000_000 * RAY` supplied market, the index sits at `SUPPLY_INDEX_FLOOR_RAW`, the wiped holder keeps a positive `unscale_supply_floor` claim, a fresh deposit of equal size is minted honestly, and the wiped holder's withdrawal pays `gross == fresh deposit`, leaving `cash == 0` and the honest supplier's claim unbacked. pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

fn test_raw_cache_floor_residual_can_consume_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let scaled_a_raw = 1_000_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: scaled_a_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let scaled_a = Ray::from(scaled_a_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout must clamp supply index UP to the floor, not reset the base"
        );

        let stranded = cache.unscale_supply_floor(scaled_a);
        assert!(stranded > 0, "floor clamp leaves userA a phantom claim");
        assert_eq!(cache.cash(), 0, "empty market: no cash to extract yet");

        let c = stranded;
        let scaled_b = cache.calculate_scaled_supply(c);
        cache.mint_supply(scaled_b);
        cache.credit_cash(c);

        let b_claim = cache.unscale_supply_floor(scaled_b);
        assert_eq!(b_claim, c, "userB's honest claim equals their deposit");

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, scaled_a);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded position pays out non-zero");
        assert_eq!(
            gross, c,
            "userA drains exactly userB's fresh deposit out of the pool"
        );

        assert!(
            cache.cash() < b_claim,
            "pool cash ({}) can no longer cover userB's claim ({}): honest supplier lost funds",
            cache.cash(),
            b_claim
        );
        assert_eq!(cache.cash(), 0, "userA drained the pool to empty");
    });
