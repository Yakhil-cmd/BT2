### Title
Reused L1 Bitcoin-Lockup Proof Allows Double-Counted Bond Stake Without New BTC Locked - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`register-for-bond`'s L1 lockup verification path in `pox-5.clar` deduplicates a proven Bitcoin outpoint only *within a single call* (the `seen-outpoints` accumulator inside `validate-l1-lockup`/`verify-l1-lockups`), not across separate `register-for-bond` calls or across bonds. There is no persistent, contract-level map recording which BTC outpoints have already been credited. This mirrors the report's root cause: the protocol accepts a state-changing action (crediting `sats-total`/stake weight) based on external proof data whose validity is checked at submission time but whose "already consumed" status is never durably tracked, so the same proof can be replayed to credit value that was never re-locked.

### Finding Description
`verify-l1-lockups` [1](#0-0)  folds over the caller-supplied `outputs` list with a fresh `seen-outpoints: (list)` accumulator initialized locally in `verify-l1-lockups`, and `validate-l1-lockup` only asserts `(is-none (index-of? seen-outpoints outpoint))` against that same call's accumulator [2](#0-1) . This protects only against duplicate outpoints *inside one proof list* (as confirmed by the `ERR_DUPLICATE_LOCKUP_OUTPOINT` test scenario) but nothing persists this outpoint to storage.

`register-for-bond` computes `sats-total` from `verify-l1-lockups` and uses it to size `amount-sats`/stake weight for the bond, with `is-l1-lock: (is-ok btc-lockup)` recorded and no sBTC transferred on the L1 path [3](#0-2) . Since only `ERR_ALREADY_REGISTERED` (an overlapping-membership check) prevents the *same staker* from re-registering while still an active bond member [4](#0-3) , once a bond term ends (or via the documented roll-over path) the staker becomes eligible to call `register-for-bond` again. Nothing stops them from presenting the *same* Bitcoin transaction/output (same txid+output-index, still time-locked or even already spent back to the owner after maturity) as a fresh L1 lockup proof for a new bond, since the on-chain check only verifies the proof's cryptographic validity (Merkle inclusion, script match, unlock height) and not whether that specific outpoint has ever been credited to any staker before.

This breaks the equality "sats credited by an L1 proof == sats actually newly locked on Bitcoin for this staker" — the same BTC lockup can back multiple sequential (or, if timing/rollover windows allow, overlapping) bond registrations, crediting stake weight and reward share that has no corresponding new Bitcoin collateral.

### Impact Explanation
This falls under the Critical category described in the rules: "sats credited by an L1 proof that were never locked on Bitcoin" and "double-counting a commitment." A staker could reuse a single BTC lockup across multiple bond cycles to gain reward-share weight and bond membership credit without committing new BTC each time, diluting/inflating counted stake versus actual backing BTC, and after the original lockup matures and is spent on L1, the staker could still register a new bond crediting sats they no longer control on Bitcoin at all.

### Likelihood Explanation
Likelihood is moderate-to-uncertain: exploitation requires the staker to complete a bond term (or otherwise clear their existing membership/roll over) and then successfully resubmit a merkle/script proof for the identical outpoint on a subsequent `register-for-bond` call. I was not able to fully verify within this session whether any other code path (e.g., `verify-bond-rollover-window`, `bond-overlaps-new-position?`, or a lower-level burnchain/UTXO-spent check elsewhere in the node) independently rejects an already-spent or previously-used outpoint; the `.clar` contract logic itself shows no such persistent tracking. This uncertainty should be resolved by an implementer verifying the full call graph before treating this as fully confirmed.

### Recommendation
Add a persistent contract map (e.g., `used-l1-outpoints: {txid: (buff 32), output-index: uint} -> bool`) that is checked and set inside `validate-l1-lockup`/`verify-l1-lockups`, so that once an outpoint has been credited to any bond registration it can never be credited again, regardless of roll-over or re-registration timing.

### Proof of Concept
Conceptual sequence (not executed, derived from code review):
1. Staker locks BTC into the timelock P2WSH script and calls `register-for-bond` with a valid L1 proof; `verify-l1-lockups` credits `sats-total` sats, `is-l1-lock: true` is recorded, and the bond term proceeds [5](#0-4) .
2. After the bond matures (or during the roll-over window per `verify-bond-rollover-window`), the staker's `protocol-bond-memberships` entry no longer overlaps a new bond position, so `ERR_ALREADY_REGISTERED` does not block a fresh `register-for-bond` call [4](#0-3) .
3. The staker resubmits the *same* `tx`/`header`/`output-index` proof for the identical BTC outpoint to a new `register-for-bond` call (for the same or a different bond-index). `validate-l1-lockup`'s dedup check only examines the current call's local `seen-outpoints`, which is empty on this new call, so the proof passes and `sats-total` is credited again [6](#0-5) .
4. The staker now holds bond stake/reward-weight credit backed by BTC that either was already fully consumed (as prior credit) or, if matured, has already been withdrawn from the P2WSH by the staker on L1 — sats are credited with no corresponding freshly-locked Bitcoin.

;; Verify l1 lockup information for a staker. This asserts that each lockup
;; corresponds to the right timelock script for this staker, and that the lockup
;; occurred on-chain. If everything is valid, this returns the sum of all lockups in sats.
(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )
)
