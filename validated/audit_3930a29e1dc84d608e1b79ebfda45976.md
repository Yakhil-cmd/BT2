### Title
`NonTransfer` proxy on Asset Hub Rococo leaks fund/asset-moving calls via unlisted pallets (ForeignAssets, PoolAssets, AssetConversion, PolkadotXcm, Revive) - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`ProxyType::NonTransfer::filter` on Asset Hub Rococo is implemented as a deny-list (`!matches!(c, ...)`) that only excludes `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques`. [1](#0-0) 
This is the exact pattern that was identified and fixed for Asset Hub Westend in [pr_12771](prdoc/pr_12771.prdoc), which added `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, and `Indices::transfer`/`force_transfer` to the deny-list because they move the delegator's funds or assets just as `Balances`/`Assets` do. [2](#0-1) 
Asset Hub Rococo's `ProxyType` never received this hardening, so its `NonTransfer` filter fails open for these pallets.

### Finding Description
The GitLab CVE's violated invariant is: a security restriction (2FA requirement) is enforced on one API path but a semantically equivalent alternate path bypasses it because the check is not comprehensive across all reachable entry points. The Polkadot SDK analog here is structurally identical: `pallet_proxy::do_proxy` enforces authorization purely through `T::ProxyType::filter(c)` before dispatch. [3](#0-2) 
On Asset Hub Rococo, `ProxyType::NonTransfer` is documented as "Can execute any call that does not transfer funds or assets", but its `filter` is a deny-list keyed on hardcoded pallet variants rather than a semantic "does this call move value" property. [4](#0-3) 
The runtime configures `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive` pallets (confirmed present, 117 references in the file), all of which can move the delegator's funds/assets exactly as `Balances::transfer` or `Assets::transfer` do — `ForeignAssets::transfer`/`PoolAssets::transfer` move fungibles, `AssetConversion::swap_exact_tokens_for_tokens` moves the caller's assets, `PolkadotXcm::transfer_assets`/`send`/`execute` can move assets off-chain, and `Revive::call`/`instantiate` carry a `value` transfer. None of these variants are excluded by the `NonTransfer` deny-list, so a `NonTransfer` proxy on this chain can execute them despite the documented guarantee.

### Impact Explanation
A delegator who grants a `NonTransfer` proxy (expecting it cannot move their funds/assets, per the doc comment) is exposed to fund/asset theft or unauthorized cross-chain transfers by that delegate, through `ForeignAssets`/`PoolAssets` transfers, `AssetConversion` swaps that drain liquidity to an attacker-chosen recipient, or `PolkadotXcm::transfer_assets`/`execute` moving assets to another chain/account, and `Revive::call` sending value to arbitrary contracts. This is the same class of authorization/documentation-contract violation Parity classified and fixed at Medium/patch severity for Westend in pr_12771 and for the staking-async parachain in pr_12922.

### Likelihood Explanation
No privileged role is required — any account that has been granted a `NonTransfer` proxy by another signed account can immediately exploit this; this is the normal intended usage pattern of `pallet_proxy` (delegate acting on behalf of a real account) and requires no governance, no forged inherent, and no malicious validator/collator.

### Recommendation
Apply the same fix as pr_12771 to `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs`: extend the `NonTransfer` deny-list to include `RuntimeCall::ForeignAssets`, `RuntimeCall::PoolAssets`, `RuntimeCall::AssetConversion`, `RuntimeCall::PolkadotXcm`, `RuntimeCall::Revive`, and `RuntimeCall::Indices(pallet_indices::Call::transfer{..})`/`force_transfer{..}` (and any other value-moving pallets present in this runtime but absent from Westend's list, e.g. `Scheduler`/`Treasury` if applicable), and add a regression test mirroring `non_transfer_proxy_rejects_value_moving_calls` from the Westend test suite. [5](#0-4)

/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and

#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}

		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
