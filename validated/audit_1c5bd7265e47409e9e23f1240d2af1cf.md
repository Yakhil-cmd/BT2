## Title
Webhook signature verification is keyed off an attacker-controlled organization field that is independent from the field used to select which team/repository the event acts on, allowing cross-organization webhook forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC `webhook_secret`) used to authenticate an inbound webhook using a value read directly out of the *unauthenticated* JSON body (`repository.owner.login`, falling back to `organization.login`). Nothing binds this "signing organization" to the organization/repository that the event handlers subsequently act on. On a multi-organization Shipit installation (the documented `github: { orgA: {...}, orgB: {...} }` setup), if any one configured organization has no `webhook_secret` set (a state the shipped example configs and `docs/setup.md` explicitly show as valid, e.g. `webhook_secret: # nil`), an unauthenticated attacker can post a forged payload whose `repository.owner.login` (used only for signature routing) points at the secret-less org while every other field used by the actual handler (`organization.login`, `repository.full_name`, etc.) points at a different, protected organization/repository.

### Finding Description
`verify_signature` in `app/controllers/shipit/webhooks_controller.rb` (lines 24-49) does: [1](#0-0) [2](#0-1) 

`repository_owner` is computed purely from the raw JSON body, with `repository.owner.login` preferred over `organization.login`:
```
params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
```
That value is used only to pick which `Shipit::GitHubApp` (and therefore which `webhook_secret`) verifies the HMAC, via `Shipit.github(organization: repository_owner)` in `lib/shipit.rb`: [3](#0-2) 
and `verify_webhook_signature` in `lib/shipit/github_app.rb`, which explicitly short-circuits to `true` when no `webhook_secret` is configured for that org: [4](#0-3) 

Once verification (or bypass) succeeds, `WebhooksController#create` hands the **entire raw payload** to the actual event handlers: [5](#0-4) 

Handlers derive the entity they operate on from *different* fields of that same payload, independent of `repository_owner`:
- `PushHandler`/`Handler#repository_name` uses `payload.dig('repository', 'full_name')`: [6](#0-5) 
- `MembershipHandler` uses `params.organization.login` to create/select the `Team` and adds an arbitrary `member.login` to it: [7](#0-6) 

`MembershipHandler` does not require a `repository` key in its schema, so an attacker is free to add one purely to steer signature routing while `organization.login`/`member.login` point elsewhere. `Team` records created/matched this way directly back the authorization gate: [8](#0-7) [9](#0-8) 

**Broken binding (equality that should hold but doesn't):**
`signing_org` (org whose secret validated the HMAC) `== acting_org` (org/repo the handler mutates state for). The controller enforces no such equality; it derives each side from independently-attacker-controlled JSON fields.

### Impact Explanation
If a Shipit instance runs the documented multi-org configuration (`test/dummy/config/secrets_double_github_app.yml`-style, described in `docs/setup.md` "Using Multiple GitHub Applications") and any one configured org is left without a `webhook_secret` (a state the shipped templates present as normal, e.g. `template.rb` and `config/secrets.development.example.yml` default `webhook_secret:` to blank), an attacker can:
- Send unauthenticated `push` events naming an unrelated protected repository's `full_name`, forcing `stack.sync_github(expected_head_sha: ...)` on that stack.
- Send unauthenticated `membership` events naming a protected org in `organization.login` and their own GitHub login in `member.login`/a guessed `team.id`, causing `Team#add_member` to grant that login membership in a `Team` backing `Shipit.github_teams`, which is the sole authorization gate in `Authentication#force_github_authentication` / `User#authorized?`. This is a direct escalation into `Shipit.github_teams` authorization — an explicitly in-scope High-impact category.

### Likelihood Explanation
Requires no credentials, tokens, or repository access — only an HTTP POST to the public, unauthenticated `/github/webhooks` endpoint (`skip_before_action :verify_authenticity_token`). The precondition is a specific but documented/supported operational configuration: multi-org setup with at least one org missing `webhook_secret`, and (for the membership escalation) knowledge/guess of the target `Team`'s GitHub numeric ID, which is not treated as a secret and is often discoverable via GitHub's org API.

### Recommendation
Bind signature verification to the same identity the handler acts on: require that `repository.owner.login`/`organization.login` used to pick the verifying `GitHubApp` matches the org actually referenced by the fields each handler consumes (`repository.full_name`, `organization.login` for membership events), and reject the request if they diverge. Consider also removing the "no secret configured ⇒ auto-verified" fallback, or requiring `webhook_secret` for every configured organization at boot.

### Proof of Concept
Assume Shipit is configured with two orgs, `orgNoSecret` (no `webhook_secret`) and `orgVictim` (has stacks/teams), per `docs/setup.md`'s multi-org schema.

```
POST /github/webhooks
X-Github-Event: membership
Content-Type: application/json

{
  "repository": {"owner": {"login": "orgNoSecret"}},
  "action": "added",
  "team": {"id": 4242, "name": "Deploy Team", "slug": "developers", "url": "https://api.github.com/teams/4242"},
  "organization": {"login": "orgVictim"},
  "member": {"login": "attacker-github-login"}
}
```
- `verify_signature` computes `repository_owner = "orgNoSecret"`, looks up `Shipit.github(organization: "orgNoSecret")`, whose `verify_webhook_signature` returns `true` unconditionally (no secret configured) — no signature header is even required.
- `MembershipHandler.call(params)` then runs against `organization.login = "orgVictim"`, adding `attacker-github-login` to the `orgVictim/developers` Team.
- If that team's handle is present in `Shipit.github_teams`, `attacker-github-login` is now authorized to log into the `orgVictim` Shipit instance. [10](#0-9)

```ruby
# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
