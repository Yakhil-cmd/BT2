The Tokemak `LMPVault` report describes a Solidity ERC-4626-style vault that fails to claim pending destination-vault rewards before computing share price on withdrawal. The closest conceptual analog in `polkadot-sdk` is `pallet-nomination-pools`, where a member's stake ("points") entitles them to a share of pool rewards, and withdrawal (`unbond`) could similarly forfeit unclaimed rewards if not handled.

However, `pallet-nomination-pools` already implements exactly the mitigation the Tokemak report recommends: `Call::unbond` explicitly updates reward records and calls `do_reward_payout` for the member *before* unbonding their points, precisely to prevent reward forfeiture [1](#0-0) . The doc comment on `unbond` states this directly: "It implicitly collects the rewards one last time, since not doing so would mean some rewards would be forfeited" [2](#0-1) . This is verified by test `member_unbond_destroying_with_pending_rewards`, which shows pending rewards are paid out as part of the `unbond` call itself [3](#0-2) , and by `unbond_of_3_works`, which confirms "We claim rewards when unbonding" [4](#0-3) .

Since points are removed from the active bonded pool at the time of `unbond` (moved into `SubPoolsStorage` unbonding pools), no further reward accrual is possible for those points during the unbonding period, so a later `withdraw_unbonded` call has no pending-reward loss to claim — the reward-accrual accounting (`last_recorded_reward_counter`) is already settled at `unbond` time [5](#0-4) .

At the `pallet-staking`/`pallet-staking-async` level, "rewards" (era payout via `payout_stakers`) are a separate, explicit, permissionless claim mechanism unrelated to `unbond`/`withdraw_unbonded` mutating share price implicitly [6](#0-5) ; there's no vault-style share-price calculation that silently excludes unclaimed rewards there, so the Tokemak bug class doesn't map onto that pallet either.

Because the FRAME implementation already forces reward settlement prior to unbonding — the exact fix the original report recommends — there is no reachable, unmitigated analog of this bug class in this codebase.
