### Title
RAY debt-value multiplication overflows before the borrow-index cap, permanently freezing a large market - (File: `common/src/rates/simulate.rs`)

### Summary
Market accrual computes `borrowed * borrow_index` in checked `i128` fixed-point arithmetic before it can apply the borrow-index ceiling. On a sufficiently large, highly utilized market, accrual eventually panics with `MathOverflow`; because `supply`, `repay`, `withdraw`, `liquidate`, and `update_indexes` all load and accrue the market first, subsequent state-changing attempts fail identically. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` first calls `scaled_to_original` on the scaled debt and stored borrow index, then calculates utilization, the rate, and the compounded factor. [3](#0-2)  The later interest calculation repeats the vulnerable multiplication with both the old and new indexes. [4](#0-3) 

Although `update_borrow_index` caps the result at `MAX_BORROW_INDEX_RAY`, the multiplication occurs before the cap check, so it does not protect the `scaled_to_original` or debt-value multiplications. [5](#0-4)  Once the represented debt value exceeds `i128::MAX`, every accrual attempt reverts rather than clamping or salvaging the market.

### Impact Explanation
This creates a permanent market freeze and locks supplier funds: withdrawals and repayments cannot reduce the position because each operation first runs the overflowing accrual. The harness regression demonstrates the terminal state explicitly: after `update_indexes` starts returning `MathOverflow`, both withdraw and repay fail with the same error while the stored borrow index is still below its cap. [6](#0-5) 

### Likelihood Explanation
An unprivileged user can create the precondition through `supply` and `borrow`, but exploitation requires an admitted market whose caps and liquidity permit an extremely large book, sustained high utilization, and enough elapsed time for the index to grow. The referenced scenario uses a one-billion-token market at 98% utilization and reaches the cliff within the tested forty-year bound, before the index cap. [7](#0-6) 

### Recommendation
Saturate RAY-valued debt calculations at a safe maximum before converting debt or multiplying debt by the index, or reorganize accrual to apply the index cap before evaluating the debt value. Accrual should fail open only for isolated rate calculation, never prevent debt repayment or collateral exit; add a regression asserting that post-cap accrual permits `repay` and `withdraw`.

### Proof of Concept
1. Create a high-decimal market with supply and borrow caps admitting the required size.
2. Supply `1_000_000_000 * 10^18` base units and, from separately collateralized collateral, borrow 98% of the market.
3. Advance ledger time until `update_indexes(caller, [BIG18])` returns `MathOverflow`.
4. Attempt `repay` or `withdraw`; both load the market and run `global_sync`, so they return `MathOverflow` before changing state. [8](#0-7) 
5. This exact sequence is encoded by `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`. [9](#0-8)

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
