### Title
Unauthenticated `ServiceChainInvalidTxResponseMsg` allows any bridge P2P peer to permanently evict valid transactions from BridgeTxPool — (`node/sc/sub_bridge_handler.go`)

---

### Summary

`handleParentChainInvalidTxResponseMsg` unconditionally removes bridge transactions from the `BridgeTxPool` based solely on attacker-supplied `TxHash` and `ErrStr` fields in a P2P message, with no verification that the parent chain actually rejected those transactions and no cryptographic authentication of the sending peer beyond a self-reported chainID.

---

### Finding Description

**Entry point:** `HandleMainMsg` dispatches `ServiceChainInvalidTxResponseMsg` (code `0x09`) to `handleParentChainInvalidTxResponseMsg` for any connected bridge peer. [1](#0-0) 

**Vulnerable handler:** [2](#0-1) 

The logic is:
1. Decode `[]InvalidParentChainTx` from the raw P2P message — fully attacker-controlled.
2. For each entry, look up `invalidTx.TxHash` in the live `BridgeTxPool`.
3. If `invalidTx.ErrStr == blockchain.ErrGasPriceBelowBaseFee.Error()` (a static, publicly known string), call `RemoveTx(tx)` with no further checks.

There is **no verification** that the parent chain actually rejected the transaction, and **no verification** of the peer's identity beyond the chainID handshake.

**Peer authentication gap:** `RegisterNewPeer` only checks that the connecting peer's self-reported chainID matches the configured parent chain ID. [3](#0-2) 

The parent chain ID is publicly known. Any node that can reach the bridge P2P port and speaks the `servicechain` protocol can pass this check and become a bridge peer.

**`RemoveTx` is permanent:** The `BridgeTxPool` removes the transaction from both `pool.all` and `pool.queue` with no tombstone or re-queue mechanism. [4](#0-3) 

The developer comment in the handler itself acknowledges the asymmetry:

> "For value transfer txs, Value Transfer Recovery will retry if enabled. For anchoring txs, there is no automatic retry mechanism" [5](#0-4) 

---

### Impact Explanation

- **Anchoring transactions**: Permanently evicted from the pool. The child chain's block data anchoring to the parent chain is silently dropped with no recovery path. This breaks the core cross-chain settlement guarantee.
- **Value transfer transactions**: Evicted; recovery depends on whether Value Transfer Recovery is enabled — not guaranteed.

This satisfies the allowed impact gate: *persistent corruption that breaks withdrawals, transfers, or settlement*, and *durable loss of core chain functionality*.

---

### Likelihood Explanation

The bridge P2P port must be reachable for the bridge to function at all. The `servicechain` protocol name and message codes are defined in the public repository. [6](#0-5) 

An attacker who can reach the bridge P2P port needs only to:
1. Speak the `servicechain/2` protocol.
2. Send a `statusData` with the correct (public) parent chain ID.
3. Send a crafted `ServiceChainInvalidTxResponseMsg` containing real bridge tx hashes (observable by watching the parent chain mempool) and `ErrStr = "gas price is below baseFee"`.

---

### Recommendation

1. **Authenticate bridge peers cryptographically**: Maintain a whitelist of trusted parent-chain node IDs (public keys); reject peers whose node ID is not on the list.
2. **Verify rejection on-chain**: Before removing a tx, query the parent chain (via `remoteBackend`) to confirm the tx was actually rejected or is absent from the mempool.
3. **Minimum guard**: Before calling `RemoveTx`, verify that `tx.GasPrice()` is actually below the current known base fee (`sbh.remoteGasPrice`) so a peer cannot forge rejections for txs with adequate gas prices.

---

### Proof of Concept

1. Connect a malicious node to the sub-bridge's bridge P2P port, completing the `servicechain/2` handshake with the correct parent chain ID.
2. Observe the parent chain mempool to collect hashes of pending bridge transactions (anchoring or value-transfer).
3. Send a `ServiceChainInvalidTxResponseMsg` (code `0x09`) containing:
   ```
   []InvalidParentChainTx{
       {TxHash: <valid_anchoring_tx_hash>, ErrStr: "gas price is below baseFee"},
   }
   ```
4. Observe via `BridgeTxPool.Get(hash)` returning `nil` that the transaction has been permanently removed.
5. Confirm no anchoring receipt is ever written for the corresponding child chain block, and no automatic re-submission occurs.

func (sbh *SubBridgeHandler) handleParentChainInvalidTxResponseMsg(msg p2p.Msg) error {
	var invalidTxs []InvalidParentChainTx
	if err := msg.Decode(&invalidTxs); err != nil && err != rlp.EOL {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	txPool := sbh.subbridge.GetBridgeTxPool()
	for _, invalidTx := range invalidTxs {
		if tx := txPool.Get(invalidTx.TxHash); tx != nil {
			logger.Error("A bridge tx was not executed", "err", invalidTx.ErrStr,
				"txHash", invalidTx.TxHash.String(),
				"txGasPrice", tx.GasPrice().Uint64())
			if invalidTx.ErrStr == blockchain.ErrGasPriceBelowBaseFee.Error() {
				logger.Info("[SC][HandleTxDropped] Request gasPrice and Magma values to parent chain")
				sbh.SyncNonceAndGasPrice()

				logger.Error("Bridge tx is removed which has lower gasPrice than UpperBoundBaseFee")
				// Remove the tx from the pool. For value transfer txs, Value Transfer Recovery
				// will retry if enabled. For anchoring txs, there is no automatic retry mechanism;
				if err := sbh.subbridge.GetBridgeTxPool().RemoveTx(tx); err != nil {
					logger.Error("Failed to remove bridge tx",
						"txType", tx.Type(), "txNonce", tx.Nonce(), "txHash", tx.Hash().String())
				} else {
					logger.Info("Removed bridge tx",
						"txType", tx.Type(), "txNonce", tx.Nonce(), "txHash", tx.Hash().String())
				}
			} // TODO-ServiceChain: Consider other types of tx failures with else {}
		}
	}
	return nil
}

func (pool *BridgeTxPool) RemoveTx(tx *types.Transaction) error {
	pool.mu.Lock()
	defer pool.mu.Unlock()

	err := pool.removeTx(tx.Hash())
	if err != nil {
		logger.Error("RemoveTx", "err", err)
		return err
	}
	return nil
