### Title
Missing `return` after caught hash error in `handleSavedPrivatePayments` desynchronizes `async.each` and permanently stalls the `saved_private` mutex - ([File: network.js])

### Summary
`network.js`'s `handleSavedPrivatePayments` iterates saved private-payment chains with `async.each`, and for each row calls a `validateAndSave` closure that first computes `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)`. If that call throws, the `catch` block invokes the per-item completion callback `cb()` via `deleteHandledPrivateChain(...)` but does not `return`, so execution falls through and calls `privatePayment.validateAndSavePrivatePaymentChain(...)`, which will asynchronously invoke `cb()` again through one of its own callbacks. This is directly analogous to the reported httpd bug: an error path meant to terminate/clean up a unit of work instead lets processing continue with stale/invalid state (`json_payload_hash` is `undefined`), and the worker's completion signal is invoked twice, corrupting the async control-flow bookkeeping that the surrounding lock relies on to ever release.

### Finding Description
`handleSavedPrivatePayments` acquires the `"saved_private"` mutex lock and only releases it in the `async.each` final callback, which `async` invokes once all per-row iteratee callbacks (`cb`) have fired exactly once each: [1](#0-0) 

Inside the per-row iteratee, `validateAndSave` computes a hash from attacker-controlled `payload` data inside a `try`, but the `catch` block for a thrown hash error does not `return` after signalling completion via `deleteHandledPrivateChain(..., cb)`: [2](#0-1) 

Because there is no `return`, execution continues past the `catch` and calls `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {...})` with `json_payload_hash` (and the derived `key`) left `undefined`. This second call will eventually route to one of `ifOk`/`ifError`/`ifWaitingForChain`, each of which also calls `cb()` (via `deleteHandledPrivateChain` or directly): [3](#0-2) 

So the single iteratee callback `cb` for this row is invoked twice — once from the `catch` block, once from the payment-chain validation callbacks. `async.each`'s internal completion counter is only designed to be decremented once per item; a double-call corrupts that counter, in this codebase's context making the final `async.each` callback silently fail to fire when other pending items are still outstanding (or firing prematurely while other iteratees remain in flight, leaving their own eventual completions no longer tracked correctly). Either way, the final callback in `db.query(sql, function(rows){...` (`function(){ unlock(); ... }`) can fail to run, and `mutex.lock(["saved_private"], ...)`'s `unlock` is therefore never called: [4](#0-3) [5](#0-4) 

This mirrors the report's root cause exactly: a malformed input causes a thrown error to be caught, but the surrounding logic treats the aborted branch as if it can still fall through to normal continuation, corrupting shared bookkeeping state (here, `async.each`'s counter and the mutex) instead of cleanly terminating that unit of work — with no timeout ever reclaiming the lock.

The malformed input reaching `objectHash.getBase64Hash` is trivial: `getSourceString`/`getJsonSourceString` throw on values such as `NaN`/`Infinity`, embedded NUL bytes in strings, empty arrays/objects, or `undefined` object values: [6](#0-5) [7](#0-6) 

An unprivileged correspondent device reaches this code by sending a `private_payment_chains` message; `wallet.js`'s `handlePrivatePaymentChains` only checks shallow shape (`isNonemptyObject`, `isNonemptyString(asset)`, `isNonemptyArray(inputs/outputs)`, and that each element `isNonemptyObject`) — it does not validate that every numeric field is finite, that strings contain no NUL bytes, or that nested objects/arrays are non-empty: [8](#0-7) 

Such a chain, if the referenced unit is not yet known locally, is queued into `unhandled_private_payments` via `handleOnlinePrivatePayment`'s `ifNew`/`savePrivatePayment` path: [9](#0-8) 

and is later dequeued and processed by the vulnerable `handleSavedPrivatePayments`, either periodically (`findAndHandleJointsThatAreReady`) or once the missing unit arrives — putting the malformed payload directly on the buggy code path with attacker control over its content.

### Impact Explanation
Holding `"saved_private"` forever means `handleSavedPrivatePayments` can never again make progress: `mutex.lock(["saved_private"], ...)` for a specific `unit` will queue indefinitely (mutex.js queues jobs on locked keys and only runs them after `unlock`), and the `mutex.lockOrSkip` variant for the periodic sweep will keep skipping. This freezes processing of all subsequent legitimate private payments (textcoins, private asset transfers) sent to the same wallet/device, a denial-of-service against that node's private-payment pipeline that persists until the process is restarted, and it can be triggered repeatedly at will by any correspondent sending malformed chains, without requiring authentication beyond an existing pairing/hub relationship that correspondents normally have.

### Likelihood Explanation
Reaching the vulnerable code only requires being an existing correspondent (a normal, unprivileged capability for private/textcoin payments) and crafting a `chains` payload whose head element's payload contains a value that `getBase64Hash`/`getSourceString` rejects (e.g., `NaN`, an embedded `\x00` byte in a string field, or an empty nested array/object) while still satisfying the shallow structural checks in `handlePrivatePaymentChains`. The referenced unit merely needs to not be locally known yet, which is easy to arrange (reference an as-yet-unpropagated or nonexistent unit hash) so the chain is queued and later dequeued through the buggy `validateAndSave` path.

### Recommendation
Add a `return` immediately after the `catch` block's cleanup call in `validateAndSave` so execution does not fall through to `privatePayment.validateAndSavePrivatePaymentChain` after an error, and ensure `cb` is invoked exactly once per iteratee. Additionally, validate the incoming `payload` for hashable content (finite numbers, no NUL bytes, non-empty nested structures) earlier, in `handlePrivatePaymentChains`, so malformed chains are rejected up front rather than reaching the deferred processing path.

### Proof of Concept
1. As a paired correspondent device, send a `private_payment_chains` justsaying/message whose `chains[0]` head element has a syntactically valid `payload` (non-empty object, valid `asset` string, non-empty `inputs`/`outputs` arrays of non-empty objects) but contains a value that fails hashing, e.g. an output object with `amount: Infinity` or a string field containing `"\u0000"`, and references a `unit` hash not yet known to the victim node.
2. `handlePrivatePaymentChains`'s shallow checks pass, `handleOnlinePrivatePayment` takes the `ifNew` branch and stores the chain in `unhandled_private_payments` via `savePrivatePayment`.
3. When `handleSavedPrivatePayments` next runs for this row (on a timer/dependency wake-up), `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)` throws inside `validateAndSave`; the `catch` block calls `cb` via `deleteHandledPrivateChain` but falls through and calls `privatePayment.validateAndSavePrivatePaymentChain`, which also eventually calls `cb` again for the same row.
4. The double-invocation of `cb` desynchronizes `async.each`'s completion tracking, so the final callback that calls `unlock()` on the `"saved_private"` mutex lock never executes for this batch.
5. All further private-payment processing tied to `"saved_private"` on the victim node stalls indefinitely with no timeout to reclaim it, verifiable by observing that subsequent legitimate `private_payment_chains` messages never complete/ack.

function getSourceString(obj) {
	var arrComponents = [];
	function extractComponents(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				if (variable.includes(STRING_JOIN_CHAR))
					throw Error("00 byte in string value in " + JSON.stringify(obj));
				arrComponents.push("s", variable);
				break;
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
				arrComponents.push("n", variable.toString());
				break;
			case "boolean":
				arrComponents.push("b", variable.toString());
				break;
			case "object":
				if (Array.isArray(variable)){
					if (variable.length === 0)
						throw Error("empty array in "+JSON.stringify(obj));
					arrComponents.push('[');
					for (var i=0; i<variable.length; i++)
						extractComponents(variable[i]);
					arrComponents.push(']');
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0)
						throw Error("empty object in "+JSON.stringify(obj));
					keys.forEach(function(key){
						if (typeof variable[key] === "undefined")
							throw Error("undefined at "+key+" of "+JSON.stringify(obj));
						if (key.includes(STRING_JOIN_CHAR))
							throw Error("00 byte in object key in " + JSON.stringify(obj));
						arrComponents.push(key);
						extractComponents(variable[key]);
					});
				}
				break;
			default:
				throw Error("getSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	extractComponents(obj);
	return arrComponents.join(STRING_JOIN_CHAR);
}

function getJsonSourceString(obj, bAllowEmpty) {
	let cache = new WeakMap();  // object to stringified result
	function stringify(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				return toWellFormedJsonStringify(variable);
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
			case "boolean":
				return variable.toString();
			case "object":
				// return cached result if already processed
				if (cache.has(variable))
					return cache.get(variable);
				let result;
				if (Array.isArray(variable)){
					if (variable.length === 0 && !bAllowEmpty)
						throw Error("empty array in "+JSON.stringify(obj));
					result = '[' + variable.map(stringify).join(',') + ']';
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0 && !bAllowEmpty)
						throw Error("empty object in "+JSON.stringify(obj));
					result = '{' + keys.map(function(key){ return toWellFormedJsonStringify(key)+':'+stringify(variable[key]) }).join(',') + '}';
				}
				cache.set(variable, result);  // memoize for future references
				return result;
			default:
				throw Error("getJsonSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	return stringify(obj);
}
