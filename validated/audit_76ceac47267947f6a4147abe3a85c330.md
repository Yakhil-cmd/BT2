### Title
`listAvailableSkills` prints attacker-controlled skill description/name to the terminal without sanitizing control sequences - (File: pkg/cmd/skills/install/install.go)

### Summary
`listAvailableSkills` in `pkg/cmd/skills/install/install.go` builds a table from `discovery.Skill.DisplayName()` and `discovery.Skill.Description` and renders it straight to `opts.IO.Out` via the table printer, with no escape-sequence sanitization applied to either field. [1](#0-0)  This is inconsistent with the sibling `gh skills list` command, which explicitly sanitizes the same class of untrusted, registry/frontmatter-sourced text before printing it. [2](#0-1) 

### Finding Description
`listAvailableSkills` is reached from `selectSkillsWithSelector` when `gh skills install` is run non-interactively without an explicit skill name (`canPrompt == false`), i.e. the normal/default path for scripted or piped usage. [3](#0-2) 

Inside the function, for every discovered skill it writes `s.DisplayName()` and `s.Description` directly into a `tableprinter` row:
```go
table := tableprinter.New(opts.IO, tableprinter.WithHeader("SKILL", "DESCRIPTION"))
for _, s := range skills {
    table.AddField(s.DisplayName())
    desc := s.Description
    if isTTY {
        desc = text.Truncate(descWidth, desc)
    }
    table.AddField(desc)
    table.EndRow()
}
return table.Render()
``` [1](#0-0) 

The only transformation applied on a TTY is `text.Truncate`, which shortens the string but does not strip or neutralize ANSI/OSC/CSI byte sequences. The underlying `internal/tableprinter.New`/`NewWithWriter` wraps `go-gh`'s `tableprinter.New(w, isTTY, maxWidth)`, which formats columns/padding only — it performs no control-sequence stripping. [4](#0-3)  The write target is `opts.IO.Out`, not the sanitized `opts.IO.ContentOut` path that the codebase uses elsewhere for untrusted content (see `pkg/iostreams/iostreams.go`'s `newContentWriter`/`SetContentSanitization`, and `pkg/iostreams/untrusted.go`'s `Untrusted.String()` sanitization). [5](#0-4) [6](#0-5) 

Critically, the sibling command `gh skills list` handles the identical data class (skill name/description originating from registry metadata and skill frontmatter) by explicitly running it through `sanitizeForTerminal`, which uses `asciisanitizer.Sanitizer` to replace ASCII control characters with inert caret-style stand-ins specifically "so frontmatter values cannot inject terminal escapes." [2](#0-1)  `listAvailableSkills` in the `install` package has no equivalent call, meaning `s.DisplayName()` and `s.Description` — both populated from data an attacker controls when they publish a skill (registry entry name/description, or skill frontmatter) — reach the terminal unsanitized.

An attacker who publishes a skill with OSC (e.g. `\x1b]0;...`) or CSI (e.g. cursor movement/hide, alternate screen buffer) sequences embedded in the skill's description or display name can manipulate the victim's terminal output when the victim runs `gh skill install <owner>/<repo>` (or any non-interactive listing invocation) against that source.

### Impact Explanation
This enables terminal output spoofing: an attacker-controlled description could rewrite the terminal title, clear/overwrite prior lines, hide cursor state, or otherwise manipulate what the victim sees in their terminal immediately before an install decision. Combined with the fact this listing precedes install confirmation flows, it could be used to make malicious skill entries visually indistinguishable from benign ones or to obscure warnings, which matches a "Terminal output/prompt spoofing" class of impact. It does not by itself achieve code execution or credential exfiltration — it is a display-integrity issue whose downstream harm depends on what the victim does next (e.g., confirming installation of a spoofed/renamed skill).

### Likelihood Explanation
Precondition is minimal: an attacker only needs to publish a skill (via a repo, registry entry, or extension) with a crafted description or name containing escape bytes, then have the victim run the ordinary, default `gh skill install <source>` command without a specific skill name — which is the documented interactive/non-interactive listing behavior. [7](#0-6)  No elevated privileges, MITM, or social engineering beyond normal skill publication is required, making this easily reproducible.

### Recommendation
Sanitize `s.DisplayName()` and `s.Description` before adding them as table fields in `listAvailableSkills`, mirroring the `sanitizeForTerminal` helper already used in `pkg/cmd/skills/list/list.go`, or wrap the values in `iostreams.Untrusted` so `fmt`-based rendering paths sanitize automatically. Apply this to all other places in `pkg/cmd/skills/install/install.go` that print skill-sourced text (interactive picker labels, error messages, ambiguous-match name lists) to ensure the invariant "all skill-sourced text is sanitized before display" holds consistently across both `skills list` and `skills install`.

### Proof of Concept
Golden/unit test in `pkg/cmd/skills/install/install_test.go`:
```go
func TestListAvailableSkills_SanitizesEscapeSequences(t *testing.T) {
    ios, _, out, _ := iostreams.Test()
    ios.SetStdoutTTY(false) // non-interactive path

    hostileSkill := discovery.Skill{
        Name:        "evil",
        Description: "safe text\x1b]0;PWNED\x07 more text\x1b[2J",
    }

    opts := &InstallOptions{IO: ios}
    sel := skillSelector{sourceHint: "attacker/repo"}

    err := listAvailableSkills(opts, []discovery.Skill{hostileSkill}, sel)
    require.NoError(t, err)

    // Expected assertion (currently FAILS on unpatched code):
    // raw ESC byte must never reach the rendered output.
    assert.NotContains(t, out.String(), "\x1b")
}
```
Running this against the current implementation demonstrates the raw `0x1B` escape byte is present in `out.String()`, confirming unsanitized terminal-bound output; after applying `sanitizeForTerminal` (or `iostreams.Untrusted`) to the fields in `listAvailableSkills`, the assertion passes.

// listAvailableSkills prints discovered skills as a table for non-interactive
// callers, mirroring the information shown in the interactive picker so the
// output can be browsed or piped into tools like grep.
func listAvailableSkills(opts *InstallOptions, skills []discovery.Skill, sel skillSelector) error {
	if len(skills) == 0 {
		return fmt.Errorf("no skills found in %s", sel.sourceHint)
	}

	if sel.fetchDescriptions != nil {
		sel.fetchDescriptions()
	}

	if opts.IO.IsStdoutTTY() {
		fmt.Fprintf(opts.IO.ErrOut, "Showing %s from %s. Re-run with a skill name to install.\n\n",
			text.Pluralize(len(skills), "skill"), sel.sourceHint)
	}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}

// SetContentSanitization toggles ANSI escape sanitization on ContentOut.
// Commands should call this with false when an explicit opt-out flag (e.g.
// --allow-escape-sequences) is set, so subsequent writes of external content
// pass through unmodified.
func (s *IOStreams) SetContentSanitization(enabled bool) {
	s.sanitizeContent = enabled
	s.ContentOut = newContentWriter(s.Out, enabled)
}

// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
