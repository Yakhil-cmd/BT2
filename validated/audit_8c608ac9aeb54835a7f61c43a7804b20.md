### Title
Credentials embedded in `--repo`/`GITSYNC_REPO` URL are disclosed via unredacted error logs - (File: `main.go`, `pkg/cmd/cmd.go`)

### Summary
git-sync supports authenticating via a URL that embeds credentials directly (e.g. `https://user:token@host/repo`), and separately redacts the repo URL in normal informational logs via a `redactURL()` helper. However, the low-level command runner (`pkg/cmd/cmd.go`) builds error strings from the raw, unredacted argv, and `fetch()`/other git operations pass `git.repo` verbatim as a command-line argument. When a `git fetch`/`ls-remote`/`clone` invocation fails, the resulting error (containing the full, credential-bearing URL) is propagated up and logged unconditionally through `git.log.Error(...)`, bypassing the redaction that is applied to the normal info-level "fetching" log line.

### Finding Description
In `fetch()`, the remote URL is placed directly into the git argv: [1](#0-0) 

Note line 2003 explicitly calls `redactURL(git.repo)` for the human-readable info log, indicating the authors are aware the repo URL can carry secrets and must be redacted before logging. But the `args` slice built two lines later still contains the raw `git.repo` value, and this is what gets passed into `git.Run(...)`.

The command runner in `pkg/cmd/cmd.go` builds a command string from the raw args for both the verbose "running command" trace log and — critically — for the error value returned on failure: [2](#0-1) 

`cmdForLog` performs no redaction of URLs or credentials; it merely quotes arguments containing whitespace. On any git failure (`err != nil`), the function returns `fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, err, stdout, stderr)`, embedding the fully-unredacted argv — including a credential-bearing repo URL — inside the error value.

This error is then surfaced through the normal error-handling path of `main()`/`SyncRepo`, which logs errors via `git.log.Error(err, ...)` unconditionally (not gated by `-v` verbosity), unlike the deliberately-redacted `V(2)` info log at `main.go:2003`. As a result, any operator/monitoring pipeline that captures git-sync's stderr/logs (a very common practice for sidecars) will see the plaintext credential whenever a fetch/clone/ls-remote against a credential-embedded URL fails — which is trivially reachable by an attacker who can cause the remote git operation to fail (e.g., a malicious/incompatible ref, an unreachable host, a broken pack, or a repo that returns errors during protocol negotiation).

### Impact Explanation
If an operator configures `GITSYNC_REPO`/`--repo` with embedded HTTP Basic credentials in the URL (a supported, "natural" authentication mode per the README's own AUTHENTICATION section), any transient or attacker-induced git failure discloses the credential in plaintext in git-sync's logs. Logs are frequently shipped to centralized logging/observability systems with broader access than the pod itself, so this is a credential-disclosure path distinct from, but analogous to, the reported issue of secrets being exposed through an insufficiently protected channel (source control there; log aggregation here).

### Likelihood Explanation
This requires the operator to have chosen the URL-embedded-credential authentication style (as opposed to `--username`/`--password-file`, `--askpass-url`, or `--credential`, all of which keep secrets out of argv). This is a real, documented, supported mode, and an attacker able to influence the upstream ref/branch state (e.g., by controlling a branch that CI merges into, or timing repo unavailability) can reliably force fetch failures to trigger the log line. Likelihood is moderate: it depends on configuration choice, but the analog is directly reachable by unprivileged attacker-triggered fetch failures against an in-scope git-sync deployment, without needing a malicious operator or leaked key.

### Recommendation
Short term: apply `redactURL()` (or equivalent) to any URL argument before it is embedded into command argv passed to the command runner (e.g., pass a redacted copy of `git.repo` for logging purposes while still passing the real value to `exec.Cmd`), and/or have `cmdForLog`/`runWithStdin` accept an explicit "safe for logging" version of args distinct from the actual exec args. Long term, strongly discourage/deprecate the URL-embedded-credential auth mode in favor of `--username`+`--password-file`, `--askpass-url`, or `--credential`, none of which place secrets in argv or shell out with secrets present, reducing the attack surface for accidental disclosure via error paths.

### Proof of Concept
1. Deploy git-sync with `--repo=https://myuser:MYTOKEN@github.com/org/repo.git --root=/mnt/git --period=5s`.
2. Trigger a fetch failure — e.g., an attacker (or transient condition) makes the ref temporarily invalid/unreachable, or the repo becomes momentarily unresolvable (rate limiting, network blip, or an attacker force-pushing a ref that breaks shallow-fetch assumptions).
3. Observe git-sync's stderr/log output: the failure is logged via `git.log.Error(err, ...)`, and the error string produced at `pkg/cmd/cmd.go:89` contains `Run(git fetch https://myuser:MYTOKEN@github.com/org/repo.git <ref> --verbose --no-progress --prune --no-auto-gc): ...`, exposing `MYTOKEN` in plaintext in the collected logs — unlike the deliberately redacted `V(2)` "fetching" log line at `main.go:2003`.

func runWithStdin(ctx context.Context, log logintf, cwd string, env []string, stdin, command string, args ...string) (string, string, error) {
	cmdStr := cmdForLog(command, args...)
	log.V(5).Info("running command", "cwd", cwd, "cmd", cmdStr)

	cmd := exec.CommandContext(ctx, command, args...)
	if cwd != "" {
		cmd.Dir = cwd
	}
	if len(env) != 0 {
		cmd.Env = env
	}
	outbuf := bytes.NewBuffer(nil)
	errbuf := bytes.NewBuffer(nil)
	cmd.Stdout = outbuf
	cmd.Stderr = errbuf
	cmd.Stdin = bytes.NewBufferString(stdin)

	start := time.Now()
	err := cmd.Run()
	wallTime := time.Since(start)
	stdout := strings.TrimSpace(outbuf.String())
	stderr := strings.TrimSpace(errbuf.String())
	if ctx.Err() == context.DeadlineExceeded {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, ctx.Err(), stdout, stderr)
	}
	if err != nil {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, err, stdout, stderr)
	}
	log.V(6).Info("command result", "stdout", stdout, "stderr", stderr, "time", wallTime)

	return stdout, stderr, nil
}
