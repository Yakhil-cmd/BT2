### Title
`pull_request action=opened` webhook verified against a no-secret org but mutates a different org's repository via `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/HMAC secret to check using `repository.owner.login` from the untrusted payload, while the actual `pull_request` handler resolves and mutates state using the unrelated `repository.full_name` field. If an attacker names an org in `repository.owner.login` whose config has no `webhook_secret` configured, signature verification is silently bypassed, and the attacker can then point `repository.full_name` at any registered victim repository to create/mutate its `ReviewStack`.

### Finding Description
The broken binding, stated as an equality that the code assumes but never enforces:
`org_used_for_signature_verification (params.repository.owner.login)` == `org_that_owns_the_mutated_repository (params.repository.full_name.split('/').first)`.

Trace:
1. `Shipit::WebhooksController#verify_signature` computes `repository_owner` purely from `params.dig('repository', 'owner', 'login')` [1](#0-0)  and uses it to select the per-org `GitHubApp` config: `Shipit.github(organization: repository_owner)` [2](#0-1) .
2. `GitHubApp#verify_webhook_signature` short-circuits to `true` when that org's config has no `webhook_secret` set: `return true unless webhook_secret` [3](#0-2) . An attacker who names a configured-but-secretless org in `repository.owner.login` therefore bypasses signature verification entirely with a forged, unsigned request.
3. Once past `verify_signature`, `WebhooksController#create` dispatches the raw, attacker-controlled JSON to all `pull_request` handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
4. `OpenedHandler#repository` resolves the repository to mutate using a completely different, attacker-controlled field — `params.repository.full_name` — with no cross-check against `repository.owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) .
5. If `provision?` conditions on that resolved (victim) repository hold, `OpenedHandler#process` calls `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` [6](#0-5) , and `ReviewStackAdapter#create!` creates a `ReviewStack` under the victim repository's `review_stacks` association with attacker-controlled `branch`/`environment`/`github_pull_request` payload [7](#0-6) .

Root cause: the org identity used to authenticate the webhook (`repository.owner.login`) is never reconciled with the org/repo identity that the handler actually reads and writes (`repository.full_name`). No validator, before_action, or handler-level check enforces this equality.

I was not able to confirm within the reviewed files a distinct "status/commit lookup by bare SHA" step inside `OpenedHandler`/`ReviewStackAdapter` — stack lookup/creation there keys off `environment: "pr#{params.number}"`, not off `pull_request.head.sha`. That specific amplification claim (shared-commit-SHA collision) is unconfirmed against this handler; the primary owner/full_name-split bypass is confirmed and independently sufficient to cause cross-tenant state mutation.

### Impact Explanation
An unauthenticated, unprivileged attacker can create/mutate a `ReviewStack` (branch, environment, associated pull-request record) belonging to a repository they do not own or control, as long as: (a) any org configured in Shipit's `secrets.github` lacks a `webhook_secret`, and (b) the victim repository has `review_stacks_enabled` and a matching `provisioning_behavior`. This is a payload from one (attacker-named) org mutating another repository's records — explicitly listed as Critical scope ("a payload for one repository mutating another's stack, commit, task or team").

### Likelihood Explanation
Preconditions: multi-org GitHub config (`github_default_organization` non-nil) with at least one org missing `webhook_secret`, and a victim repository with review stacks provisioning enabled. Given those, the attack is a single unauthenticated `POST /webhooks` with a crafted JSON body and `X-Github-Event: pull_request` header — no signature needed since the no-secret path returns `true` unconditionally. Repeatable against any repository whose `owner/name` the attacker knows, for every PR number/environment the attacker chooses.

### Recommendation
Do not select the verification org from attacker-supplied payload fields alone without binding it to the resolved repository used by downstream handlers. Concretely: after resolving the target `Shipit::Repository` (via `full_name`), require that `repository.owner` equals the `repository.owner.login` used to pick the verifying `GitHubApp`/secret, and reject the request otherwise. Also make `verify_webhook_signature` fail-closed (require `webhook_secret` to be present for every configured org) instead of returning `true` when a secret is absent, and ensure `head(422)` in `verify_signature` is followed by an explicit halt (e.g. `return`) to avoid any ambiguity in the filter chain.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb` (multi-org config fixture with `org-no-secret` lacking `webhook_secret`, and a `Shipit::Repository` for `victim-org/victim-repo` with `review_stacks_enabled: true`, `provisioning_behavior: 'allow_all'`):
```ruby
test "pull_request opened forged with owner/full_name split bypasses signature and mutates victim repo" do
  victim_repo = shipit_repositories(:victim_org_repo) # owner: 'victim-org', name: 'victim-repo'
  assert_equal 0, victim_repo.review_stacks.count

  payload = {
    action: 'opened',
    number: 999,
    pull_request: {
      id: 1, number: 999, url: 'x', title: 't', state: 'open',
      additions: 1, deletions: 0,
      head: { sha: 'deadbeef', ref: 'attacker-branch' },
      user: { login: 'attacker' },
      assignees: [], labels: []
    },
    repository: { owner: { login: 'org-no-secret' }, full_name: 'victim-org/victim-repo' },
    sender: { login: 'attacker' }
  }.to_json

  post shipit.webhooks_path, params: payload,
       headers: { 'X-Github-Event' => 'pull_request', 'Content-Type' => 'application/json' }
       # deliberately NO X-Hub-Signature header / wrong signature

  assert_response :ok
  assert_equal 1, victim_repo.review_stacks.reload.count
  assert_equal 'attacker-branch', victim_repo.review_stacks.first.branch
end
```
Assertions establish both sides of the broken equality: the org used for auth (`org-no-secret`) differs from the org that owns the mutated repository (`victim-org`), yet the mutation (`review_stacks.count` increment, attacker-chosen `branch`) succeeds.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
