### Title
Missing council-membership check on proposed GoverningNode in `checkConsistency` — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` for a `GovernanceGoverningNode` vote validates that the **current** `params.GoverningNode` is a council member, but never validates that the **proposed** new governing node (`vote.Value()`) is a council member. Pre-Permissionless, any council member who is the block proposer can cast this vote with an arbitrary non-council address as the value. The vote passes all checks, is committed at the next epoch boundary, and permanently corrupts the `GoverningNode` parameter — locking governance irreversibly in single mode.

---

### Finding Description

In `checkConsistency`, the `GovernanceGoverningNode` branch: [1](#0-0) 

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if slices.Contains(council, params.GoverningNode) {  // checks CURRENT node
        return nil                                        // never checks vote.Value()
    }
    return ErrGovNodeNotInValSetList
```

The check at line 175 asks: *"Is the current governing node in the council?"* — not *"Is the proposed new governing node in the council?"* If the current governing node is present (the normal, healthy state), the function returns `nil` unconditionally, regardless of what address `vote.Value()` contains. [2](#0-1) 

**Pre-Permissionless path (the exploitable window):** The guard that restricts voting to the governing node only applies post-Permissionless: [3](#0-2) 

Before that fork activates, `VerifyVote` only requires the voter to be (a) in the council and (b) the block proposer. Any council member who is the block proposer can include a `GovernanceGoverningNode` vote with an arbitrary address — including one that is not in the council — and it will pass every check.

**Self-locking consequence:** Once the governing node is updated to an address not in the council, any future attempt to fix it via another `GovernanceGoverningNode` vote will fail `checkConsistency` at line 175 because `slices.Contains(council, params.GoverningNode)` now returns `false` → `ErrGovNodeNotInValSetList`. The parameter is permanently stuck. Post-Permissionless, the invalid governing node can never be the block proposer, so it can never cast a vote, and no other council member is permitted to vote in single mode — governance is frozen forever.

---

### Impact Explanation

Permanent, irreversible corruption of the `GoverningNode` governance parameter. In single mode after the Permissionless fork, this freezes all header-governance votes: the invalid governing node can never propose a block, so it can never include a vote, and no other council member is allowed to vote. The chain continues producing blocks but governance is permanently non-functional — a durable loss of core chain functionality meeting the "persistent corruption of protected chain state" impact gate.

---

### Likelihood Explanation

Requires a single malicious council member (validator) to be the block proposer for one block, before the Permissionless fork activates, while `GovernanceMode == "single"`. In Istanbul BFT, proposer selection rotates among all council members, so any council member will eventually be the proposer. This is a one-block, one-validator action with no collusion required.

---

### Recommendation

In `checkConsistency`, for the `GovernanceGoverningNode` case, add a membership check on the **proposed** value before returning `nil`:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if !slices.Contains(council, params.GoverningNode) {
        return ErrGovNodeNotInValSetList
    }
    // NEW: also validate the proposed new governing node
    newGovNode := vote.Value().(common.Address)
    if !slices.Contains(council, newGovNode) {
        return ErrGovNodeNotInValSetList
    }
    return nil
``` [4](#0-3)

// checkConsistency checks if vote values are consistent with chain states such as other parameters and validator set.
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList
