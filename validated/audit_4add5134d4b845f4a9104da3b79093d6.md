### Title
`flash_position` bypasses the origination fee that `multiply` books as protocol revenue, letting a user open identical leveraged positions without paying - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The Goat.Tech bug class is: a user chooses an alternate, attacker-controlled path (reinvesting into a sybil pool with a 99% owner share) that produces the same economic result as the penalized path (withdrawing) while skipping the accounting/fee that the protocol relies on. XOXNO Lending has the same shape: `multiply` mints strategy debt with `charge_fee = true`, so the pool withholds `flashloan_fee` bps as protocol revenue, while `flash_position` mints the identical strategy debt with `charge_fee = false` and is validated by the same `strategy_finalize` check. The repository's own parity test proves both routes end with the same debt and comparable collateral, yet only `multiply` books revenue. Any unprivileged user can therefore route all leveraged opens through `flash_position` and deprive the protocol of its unclaimed yield.

### Finding Description
- `multiply` withholds the flash-loan fee from the borrowed asset and books it as protocol revenue shares: "multiply mints strategy debt with charge_fee = true, so the pool withholds flashloan_fee bps as protocol revenue" and "flash_position mints the same strategy debt with charge_fee = false". [1](#0-0) 
- Revenue accrual mints shares that increase both `revenue` and `supplied`, i.e., the fee is real claimable yield for the protocol owner. [2](#0-1) 
- The accrued revenue is later burned and paid out via `claim_revenue` to the pool owner, so every bypassed fee is directly lost payout. [3](#0-2) 
- The parity test asserts `multiply` books exactly the fee on 1.0 ETH of strategy debt while `flash_position` books zero, and that the fee-free route ends with more collateral for the same debt — making `flash_position` strictly dominant for the user. [4](#0-3) 

Like the Goat.Tech `reinvestEarnings`-into-99%-pool trick, the penalized path and the bypass path produce the same user outcome, but the bypass silently removes the protocol's take.

### Impact Explanation
Theft of unclaimed yield. Every leveraged position opened via `flash_position` instead of `multiply` skips the origination fee that would otherwise accrue to `revenue` and be claimable by the pool owner through `claim_revenue`. Since the two routes are economically equivalent for the user (same debt, same-or-better collateral), rational users will always choose the fee-free route, draining expected protocol revenue on all leveraged volume.

### Likelihood Explanation
Trivially reachable by any unprivileged address: `flash_position` is a public controller entrypoint, and the user supplies their own flash receiver contract that simply returns the proceeds as collateral — the test's mock receiver does exactly this with no special privileges. No oracle manipulation, timing, or privileged config is needed; the bypass is a permanent, deterministic property of the code paths.

### Recommendation
Charge the origination/flash fee consistently on both routes: pass `charge_fee = true` (or the equivalent fee computation) when `flash_position` mints strategy debt in `PositionMode::Multiply`, or explicitly justify and bound the exemption. Alternatively, deduct the fee from the measured collateral leg in `strategy_finalize` so the user cannot avoid it by choosing the flash-position path.

### Proof of Concept
The behavior is already proven by the repository's own test `flash_position_substitutes_multiply_without_origination_fee` in `tests/test-harness/tests/strategy_origination_fee_parity.rs`: opening 1.0 ETH of leverage via `multiply` books `expected_fee` of ETH revenue, while the same open via `flash_position` with a user-controlled receiver books `0` revenue and leaves the user with strictly more collateral for identical debt.

Note: if the fee-free `flash_position` route is a deliberate, documented design decision rather than an oversight, this finding should be downgraded/rejected per the "documented ADR choices" exclusion — I could not confirm an ADR either way from the indexed sources.
