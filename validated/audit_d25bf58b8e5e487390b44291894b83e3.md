## Title
Stack-scoped `ApiClient` tokens can read any stack's status via `CCMenuController` - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::ApiClient` supports scoping a token to a single stack via its `stack_id` column, and `Api::BaseController` enforces that scope by resolving stacks through a filtered `stacks` relation. `Api::CCMenuController`, however, overrides `#stack` to look the stack up directly from `Stack.from_param!(params[:stack_id])`, completely bypassing the per-token stack restriction. Any valid `ApiClient` token with `read:stack` permission — even one scoped to a single, unrelated stack — can therefore fetch CCMenu status (build/deploy state) for any stack in the installation.

### Finding Description
`ApiClient` permission checks are purely name-based and carry no object binding: [1](#0-0) 

Correct scoping is implemented by `Api::BaseController#stacks`/`#stack`, which restrict lookups to the client's own `stack_id` when one is set: [2](#0-1) 

`Api::CCMenuController` reimplements authentication (accepting the token as a URL param instead of Basic Auth) and, critically, reimplements `#stack` without going through the scoped `stacks` relation: [3](#0-2) 

`require_permission :read, :stack` only calls `current_api_client.check_permissions!(:read, :stack)`, which — as shown above — checks the permission string, not which stack the client is bound to. So the equality that should hold is:

`current_api_client.stack_id (if present) == stack.id used to render the response`

but `CCMenuController#stack` breaks this binding by resolving `params[:stack_id]` against `Stack.from_param!` (all stacks) instead of `stacks.from_param!` (client-scoped stacks), so the equality never gets checked at all.

### Impact Explanation
This is a stack-authorization escalation: an attacker holding a token that was only meant to authorize reading one stack (e.g., a CCMenu URL, which embeds the token in the query string and is commonly shared/pasted into CI dashboards, is naturally scoped this way — see `CCMenuUrlController`) can supply any other `stack_id` and read that stack's build/deploy status (`lastBuildStatus`, `activity`, `lastBuildLabel`, `webUrl`) — data the token was never authorized to see. This matches the in-scope "High" impact category of unauthorized read of stack state via escalation of the token's authorized scope.

### Likelihood Explanation
Low-to-moderate: it requires possession of a stack-scoped `ApiClient` token (which is a normal, supported way to create/limit tokens — see the `here_come_the_walrus` fixture used throughout the API test suite), but no other privilege. Any holder of such a token — which may be distributed more widely than a full-access token because it's believed to be limited to one stack — can immediately pivot to read other stacks simply by changing the `stack_id` request parameter.

### Recommendation
Make `CCMenuController#stack` use the same client-scoped lookup as the rest of the API:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
reusing (or duplicating) `BaseController#stacks`, so the `current_api_client.stack_id` restriction is enforced consistently across all API controllers, not only the ones that rely on the inherited `#stack`/`#stacks` methods.

### Proof of Concept
1. Create (or obtain) an `ApiClient` scoped to `stack_id: A` with permission `read:stack` (this is the exact configuration described by `test/fixtures/shipit/api_clients.yml`'s `here_come_the_walrus` fixture, and is how a CCMenu token is intended to behave in practice). [4](#0-3) 
2. Take that token and call `GET /api/stacks/:stack_B_param/ccmenu.xml?token=<token>` where `stack_B` is a different, unrelated stack.
3. Because `CCMenuController#stack` uses `Stack.from_param!(params[:stack_id])` rather than the token-scoped `stacks.from_param!`, the request succeeds and returns stack B's build/deploy status, even though the token is only supposed to authorize reads of stack A.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
