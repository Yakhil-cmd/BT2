### Title
Empty-signer-list reward set can cause a Nakamoto block to be accepted with zero signatures - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` only rejects a reward set when `reward_set.signers()` is `None`; it never checks whether the returned signer `Vec` is non-empty (`len() == 0`). Combined with `RewardSet::total_signing_weight()`, which folds over an empty vector to `Ok(0)` instead of erroring, a reward set with `signers: Some(vec![])` (zero-length array of signers, analogous to the zero-length pubkey/message arrays in `aggregateVerify`) causes the required signing threshold to be computed as `0`, so a block with zero signer signatures passes verification.

### Finding Description
`verify_signer_signatures` extracts the signer list with: [1](#0-0) 
This only distinguishes `None` (no signers field at all) from `Some`, and does not reject an empty `Vec`. It then computes the total weight via `reward_set.total_signing_weight()`: [2](#0-1) 
This function also only checks for `None`, and folds an empty `Vec` to `0` rather than erroring. Back in `verify_signer_signatures`, `total_weight` (now `0`) is passed to `compute_voting_weight_threshold`: [3](#0-2) 
With `total_weight = 0`, this returns `threshold = 0`. Back in the caller, the comparison `total_weight_signed < threshold` becomes `0 < 0`, which is `false`, so the function returns `Ok(0)` — i.e. the block is treated as validly signed even though `self.signer_signature` is empty. [4](#0-3) 

The precondition (a `RewardSet` with `signers: Some(vec![])`) is reachable through the PoX-4 code path. `StacksChainState::make_signer_set` filters out any entry whose weight rounds down to `0`, and can legitimately return `Some(vec![])` if every stacker's contribution rounds below the per-slot threshold: [5](#0-4) 
`pox_4_compute_and_update_signers` calls `make_reward_set`/`make_signer_set` and stores whatever `RewardSet` results, without any `signer_set.is_empty()` guard: [6](#0-5) 
This is in contrast to the newer PoX-5 path, `pox_5_compute_and_update_signers`, which explicitly checks for and rejects an empty signer set: [7](#0-6) 

So PoX-4's reward-set computation is missing the same "reject the empty/degenerate collection" check that PoX-5 has, and the consumer of that reward set (`verify_signer_signatures`) also fails to reject it — the two "zero-length array" gaps compose to let a block with an empty signature array pass block-signing validation.

### Impact Explanation
If a reward cycle's signer set (as computed under PoX-4) ends up empty due to low/degenerate stacking participation, any Nakamoto block header referencing that reward cycle would be accepted as validly signed with **zero** signer signatures — i.e., an entirely unsigned stacking/consensus action is treated as authorized. This breaks the core equality that block finalization requires signer weight ≥ 70% of total signer weight; with `total_weight = 0` that check is vacuously satisfied. This matches the "unsigned stacking action" / signing-weight-exceeding-locked-value class of High-severity impact in scope.

### Likelihood Explanation
Reachability depends on the network reaching a reward cycle where every stacker's contribution rounds to weight `0` under `make_signer_set`'s `stacked_amt / threshold` computation — a degenerate but not impossible network condition (e.g., very low participation relative to the reward-slot threshold), and specifically only through the PoX-4 path, since PoX-5 already guards against it. It requires no privileged access — an attacker does not need to control the reward-set computation, only for the node to reach this state naturally, or to otherwise drive stacking activity down.

### Recommendation
In `NakamotoBlockHeader::verify_signer_signatures`, explicitly reject an empty signer list (`signers.is_empty()`) the same way `None` is rejected. Additionally, harden `RewardSet::total_signing_weight()` to return an error when the signer list is empty rather than folding to `Ok(0)`, and add the same `signer_set.is_empty()` guard to `pox_4_compute_and_update_signers` that already exists in `pox_5_compute_and_update_signers`.

### Proof of Concept
1. Construct (or reach) a PoX-4 reward cycle where every stacker's `amount_stacked` is below the computed per-slot `threshold`, so `make_signer_set` filters every entry to weight `0`, yielding `signer_set = vec![]` and `reward_set.signers() == Some(vec![])`.
2. Build a `NakamotoBlockHeader` for this reward cycle with `signer_signature = vec![]` (no signatures at all).
3. Call `header.verify_signer_signatures(&reward_set, epoch_id)`.
4. Trace: `signers = Some(vec![])` passes the `None` check; `total_weight = total_signing_weight() = 0`; loop over empty `signer_signature` does nothing, `total_weight_signed = 0`; `threshold = compute_voting_weight_threshold(0) = 0`; `0 < 0` is `false`, so the function returns `Ok(0)` — the header is deemed validly signed.

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();
