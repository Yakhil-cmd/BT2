### Title
Unauthenticated Bridge Peer Can Forge Receipt Responses to Falsely Confirm Anchoring and Corrupt Bridge State — (`node/sc/sub_bridge_handler.go`)

### Summary

`SubBridgeHandler.handleParentChainReceiptResponseMsg` accepts `ServiceChainReceiptResponseMsg` messages from any connected bridge P2P peer and passes them directly to `writeServiceChainTxReceipts` without verifying the receipts against the parent chain block header's `ReceiptHash`. An attacker who connects as a bridge peer, learns pending anchoring tx hashes (which are broadcast to all peers), and sends a forged receipt response can cause the child chain to: (1) falsely advance `WriteAnchoredBlockNumber`, (2) store a forged receipt via `WriteReceiptFromParentChain`, and (3) remove the anchoring tx from `BridgeTxPool`, permanently suppressing re-anchoring.

### Finding Description

**Step 1 — Attacker connects as a bridge peer.**

The bridge peer handshake in `baseBridgePeer.readStatus` only validates `NetworkId` and `ProtocolVersion`: [1](#0-0) 

There is no genesis block hash check (unlike the regular CN peer handshake at `node/cn/peer.go:833`). The attacker only needs to know the public `NetworkId` and protocol version to pass the handshake.

**Step 2 — Attacker learns pending anchoring tx hashes.**

On every new child chain block, `broadcastServiceChainReceiptRequest` sends all pending anchoring tx hashes to **every** connected bridge peer: [2](#0-1) 

The attacker receives these hashes over the P2P connection.

**Step 3 — Attacker sends a forged `ServiceChainReceiptResponseMsg`.**

`handleParentChainReceiptResponseMsg` decodes the message and calls `writeServiceChainTxReceipts` with no source authentication: [3](#0-2) 

**Step 4 — `writeServiceChainTxReceipts` processes the forged receipt without any Merkle proof.**

The only guard is a `BridgeTxPool.Get(txHash)` lookup — which succeeds because the attacker used the real tx hash obtained in Step 2. The code then unconditionally calls `WriteReceiptFromParentChain` and `WriteAnchoredBlockNumber`, and removes the tx from the pool: [4](#0-3) 

There is no call to `DeriveReceiptsRoot` or any comparison against a parent chain block header's `ReceiptHash`. Contrast this with the downloader's `DeliverReceipts`, which does perform this check: [5](#0-4) 

**Step 5 — Persistent state corruption.**

`WriteAnchoredBlockNumber` advances the anchored block number without any actual parent chain confirmation: [6](#0-5) 

`WriteReceiptFromParentChain` stores the forged receipt in the child chain's `bridgeServiceDB`: [7](#0-6) 

### Impact Explanation

- The child chain's bridge state permanently records that child chain block N was anchored to the parent chain, when it was not.
- The anchoring tx is removed from `BridgeTxPool` and will not be re-sent, so the actual anchoring never occurs.
- Any downstream logic that reads `ReadAnchoredBlockNumber()` or `ReadReceiptFromParentChain()` to verify cross-chain state proofs operates on corrupted data.
- This constitutes an invalid state transition on the bridge's protected cross-chain state, accepted without authorization from a permissionless P2P peer.

### Likelihood Explanation

The attacker only needs to:
1. Connect to the child chain's bridge P2P port (public, no key required beyond matching `NetworkId`/protocol version).
2. Receive the anchoring tx hashes that are broadcast automatically.
3. Send a single forged `ServiceChainReceiptResponseMsg`.

No privileged keys, validator collusion, or cryptographic breaks are required.

### Recommendation

In `writeServiceChainTxReceipts`, before calling `WriteReceiptFromParentChain` and `WriteAnchoredBlockNumber`, retrieve the parent chain block that included the anchoring tx and verify the receipt against the block header's `ReceiptHash` using `DeriveReceiptsRoot`. The receipt response message should include the block header (or at minimum the `ReceiptHash`) so the child chain can perform this check. Alternatively, restrict `ServiceChainReceiptResponseMsg` processing to a single trusted parent peer whose identity is verified at connection time (e.g., by checking genesis block hash in the bridge handshake, as the CN peer handshake does).

### Proof of Concept

1. Run a child chain sub-bridge node with anchoring enabled.
2. Connect a mock bridge peer that passes the handshake (correct `NetworkId`, protocol version, any `ChainID`).
3. Wait for `broadcastServiceChainReceiptRequest` to deliver a pending anchoring tx hash `H`.
4. Send a `ServiceChainReceiptResponseMsg` containing a `ReceiptForStorage{TxHash: H, Status: 1}` with all other fields zeroed.
5. Assert: `ReadAnchoredBlockNumber()` returns the block number embedded in the anchoring tx, `ReadReceiptFromParentChain(blockHash)` returns the forged receipt, and `BridgeTxPool.Get(H)` returns `nil` (tx removed) — all without the anchoring tx ever being mined on the parent chain.

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}

func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
	for _, receipt := range receipts {
		txHash := receipt.TxHash
		if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
			if tx.Type().IsChainDataAnchoring() {
				data, err := tx.AnchoredData()
				if err != nil {
					logger.Error("failed to get anchoring data", "txHash", txHash.String(), "err", err)
					continue
				}
				decodedData, err := types.DecodeAnchoringData(data)
				if err != nil {
					logger.Warn("failed to decode anchoring tx", "txHash", txHash.String(), "err", err)
					continue
				}
				sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
				sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
			}
			// TODO-Kaia-ServiceChain: support other tx types if needed.
			sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
		} else {
			logger.Trace("received service chain transaction receipt does not exist in sentServiceChainTxs", "txHash", txHash.String())
		}
		logger.Trace("received service chain transaction receipt", "anchoring txHash", txHash.String())
	}
}

func (dbm *databaseManager) WriteReceiptFromParentChain(blockHash common.Hash, receipt *types.Receipt) {
	receiptForStorage := (*types.ReceiptForStorage)(receipt)
	db := dbm.getDatabase(bridgeServiceDB)
	byte, err := rlp.EncodeToBytes(receiptForStorage)
	if err != nil {
		logger.Crit("Failed to RLP encode receipt received from parent chain", "receipt.TxHash", receipt.TxHash, "err", err)
	}
	key := receiptFromParentChainKey(blockHash)
	if err = db.Put(key, byte); err != nil {
		logger.Crit("Failed to store receipt received from parent chain", "receipt.TxHash", receipt.TxHash, "err", err)
	}
}
