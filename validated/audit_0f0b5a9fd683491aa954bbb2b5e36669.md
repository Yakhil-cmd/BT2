Governance vote of `kip71.gastarget = 0` causes division-by-zero panic in `NextMagmaBlockBaseFee`, permanently halting block production and verification — (`params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter accepts zero as a valid value (its `FormatChecker` is `noopFormatChecker`), but `NextMagmaBlockBaseFee` divides by `gasTarget` without a zero guard. A governance vote setting `kip71.gastarget` to `0` causes a Go runtime panic on every subsequent block where any gas is consumed, permanently halting both block production and block header verification with no recovery path.

---

### Finding Description

`Kip71GasTarget` is registered in the governance parameter table with `noopFormatChecker`, which unconditionally returns `true` for any value including zero: [1](#0-0) 

By contrast, the adjacent `Kip71BaseFeeDenominator` parameter explicitly rejects zero (`v != 0`) in its `FormatChecker`: [2](#0-1) 

`NextMagmaBlockBaseFee` also has a runtime zero guard for `BaseFeeDenominator` (lines 71–76), but has **no equivalent guard for `gasTarget`**. When `parentGasUsed > 0` and `gasTarget == 0`, execution enters the `parentGasUsed > gasTarget` branch and divides by zero: [3](#0-2) 

The `checkConsistency` function in `VerifyVote` performs no additional validation for `Kip71GasTarget` — it falls through to the `return nil` catch-all: [4](#0-3) 

Once the vote is applied at an epoch boundary, `GetParamSet` returns `GasTarget = 0`. Every call to `NextMagmaBlockBaseFee` with any non-zero `parentGasUsed` then panics. This is called in two critical paths:

**Block production** (`work/worker.go`): [5](#0-4) 

**Block header verification** (`params/kip71_config.go` via `VerifyMagmaHeader`): [6](#0-5)

### Impact Explanation

A Go runtime panic from integer division by zero crashes the node process. Because the panic occurs inside both the block proposer's `commitNewWork` and every verifying node's `VerifyMagmaHeader`, **all nodes on the network crash** when they attempt to produce or import the first block after the governance change takes effect. The corrupted governance state is already committed to the chain; there is no in-protocol mechanism to revert it or bypass the zero `gasTarget`. The chain halts permanently.

This satisfies the allowed impact gate: **invalid state transition and consensus divergence on all honest nodes**.

---

### Likelihood Explanation

In Kaia's mainnet `"single"` governance mode, only the governing node can cast a header governance vote. A single compromised or malicious governing node can unilaterally submit a vote for `kip71.gastarget = 0`. The vote passes all on-chain validation (`FormatChecker` is `noopFormatChecker`; `checkConsistency` returns `nil`). After one epoch the parameter takes effect and the chain halts. No majority-validator collusion is required.

In `"none"` governance mode any validator can vote; a majority of validators would need to collude, which is out of scope.

### Recommendation

1. **Add a non-zero `FormatChecker` for `Kip71GasTarget`**, mirroring `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // reject zero
    },
    ...
},
```

2. **Add a runtime zero guard in `NextMagmaBlockBaseFee`**, mirroring the existing guard for `BaseFeeDenominator`:

```go
if kc.GasTarget == 0 {
    // To avoid panic, fall back to a safe default
    gasTarget = DefaultGasTarget
}
```

Both defences are needed: the `FormatChecker` prevents the bad value from entering the governance state, and the runtime guard prevents a panic if the value somehow reaches the calculation (e.g., via a legacy chain state or the contract governance path).

### Proof of Concept

1. Chain is post-Magma fork, governance mode is `"single"`.
2. Governing node proposes a header vote: `kip71.gastarget = 0`.
3. `VerifyVote` → `checkConsistency` → falls through to `return nil` (no rejection).
4. At the next epoch boundary the vote is tallied and `GasTarget = 0` is written to the governance history.
5. `GetParamSet(N)` returns `ParamSet{GasTarget: 0, ...}` for all `N` after the epoch.
6. `worker.commitNewWork` calls `pset.ToKip71Config().NextMagmaBlockBaseFee(...)` with `parentGasUsed > 0` (any non-empty block).
7. Inside `NextMagmaBlockBaseFee`: `parentGasUsed > 0 == gasTarget` → enters the increase branch → `x.Div(x, new(big.Int).SetUint64(0))` → **Go runtime panic: integer divide by zero**.
8. The proposer node crashes. Every other node crashes identically when it calls `VerifyMagmaHeader` on the next block candidate.
9. No block can ever be produced or verified again. Chain is permanently halted.
