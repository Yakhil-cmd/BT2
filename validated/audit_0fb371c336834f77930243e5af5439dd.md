### Title
Missing Zero-Guard on `kip71.gastarget` Governance Parameter Causes Division-by-Zero Panic in `NextMagmaBlockBaseFee`, Halting All Nodes — (`params/kip71_config.go`)

---

### Summary

The governance parameter `kip71.gastarget` accepts zero as a valid value because its `FormatChecker` is `noopFormatChecker`. When `GasTarget == 0` and any block has non-zero gas usage, `NextMagmaBlockBaseFee` performs an integer division by zero, causing a Go runtime panic. This panic fires in both the block-proposer path (`work/worker.go`) and the block-validation path (`blockchain/block_validator.go`), crashing every honest node that attempts to process the next block and permanently halting the chain.

---

### Finding Description

**Insufficient input validation on `kip71.gastarget`**

In `kaiax/gov/param.go`, the governance parameter registry defines `Kip71BaseFeeDenominator` with an explicit non-zero guard:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0          // ← zero rejected
    },
```

But the adjacent `Kip71GasTarget` entry uses `noopFormatChecker`, which always returns `true`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker, // ← zero accepted
    ...
    DefaultValue: uint64(30000000),
},
```

`Kip71GasTarget` is not listed in `AlwaysDeprecated` or `PermissionlessDeprecated`, so it remains a live, voteable parameter.

**Division by zero in `NextMagmaBlockBaseFee`**

`params/kip71_config.go` explicitly guards `BaseFeeDenominator == 0` at runtime:

```go
if kc.BaseFeeDenominator == 0 {
    baseFeeDenominator = new(big.Int).SetUint64(64) // fallback to avoid panic
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
gasTarget := kc.GasTarget   // ← no analogous guard
```

When `gasTarget == 0` and `parentGasUsed > 0`, execution enters the `parentGasUsed > gasTarget` branch and reaches:

```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // big.Int.Div panics on zero divisor
```

The same division appears in the `else` branch (line 120) for the decreasing-fee case.

**Call sites that propagate the panic**

| File | Line | Context |
|---|---|---|
| `blockchain/block_validator.go` | 199 | `validateHeader` → `VerifyMagmaHeader` → `NextMagmaBlockBaseFee` |
| `work/worker.go` | 382 | `commitNewWork` → `NextMagmaBlockBaseFee` (block proposer) |
| `blockchain/chain_makers.go` | 306 | `makeHeader` → `NextMagmaBlockBaseFee` |

Every node that tries to propose or validate a Magma-era block with non-zero gas usage will panic.

---

### Impact Explanation

A successful governance vote setting `kip71.gastarget = 0` causes a **permanent chain halt**:

- The block proposer panics in `commitNewWork` before it can broadcast a block.
- Every peer that receives and validates a block panics in `validateHeader`.
- No node can advance the chain; consensus diverges on all honest nodes.

This matches the allowed impact: *"consensus divergence on honest nodes"* and *"invalid block acceptance"* (the node crashes before it can accept or reject).

---

### Likelihood Explanation

In `"single"` governance mode (Kaia Mainnet), only the designated governing node can cast votes. The governing node is a semi-trusted actor: it is expected to make valid governance decisions but must not be able to crash the chain. A single malicious or compromised governing node can trigger this with one vote. The vote passes the `FormatChecker` silently, takes effect after the epoch boundary, and the crash occurs on the very next block with non-zero gas usage — which is virtually every block on a live network.

---

### Recommendation

1. **Add a non-zero `FormatChecker` for `Kip71GasTarget`** in `kaiax/gov/param.go`, mirroring the existing guard on `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // reject zero
    },
    ...
},
```

2. **Add a runtime zero-guard in `NextMagmaBlockBaseFee`** in `params/kip71_config.go`, consistent with the existing `BaseFeeDenominator` guard:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    gasTarget = DefaultGasTarget // or return lowerBoundBaseFee
}
```

---

### Proof of Concept

1. In "single" governance mode, the governing node submits a vote: `kip71.gastarget = 0`.
2. The vote passes `PartialParamSet.Add` → `noopFormatChecker` returns `true` → vote is stored.
3. After the epoch boundary, `GetParamSet(blockN)` returns `GasTarget = 0`.
4. The block proposer calls `pset.ToKip71Config().NextMagmaBlockBaseFee(parent.Number(), parent.BaseFee, parent.GasUsed())` in `commitNewWork`.
5. `parent.GasUsed() > 0` (any block with transactions) → `parentGasUsed > gasTarget (0)` → `parentBaseFee < upperBoundBaseFee` (normal operating condition) → execution reaches `x.Div(x, new(big.Int).SetUint64(0))`.
6. Go's `big.Int.Div` panics: `"division by zero"`.
7. The proposer node crashes. Every peer that calls `validateHeader` on any subsequent block also crashes.
8. Chain halts permanently until all operators manually patch and restart with a corrected genesis/config. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)
