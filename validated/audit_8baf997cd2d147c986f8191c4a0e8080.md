### Title
Missing path-containment validation before destructive `os.RemoveAll` on worktree resolved from `--link` symlink target - (File: `main.go`)

### Summary
`git-sync` resolves the "current worktree" by reading back the target of the `--link` symlink via `currentWorktree()`, without ever validating that the resolved path is actually confined to `--root/.worktrees`. This untrusted/unvalidated path is subsequently fed into `sanityCheckWorktree()` and, on failure, into `removeWorktree()`, which calls `os.RemoveAll()` on it — and also directly into an `os.RemoveAll()` call inside `SyncRepo()`. If the `--link` path is (or becomes) a symlink pointing outside `--root` before/while `git-sync` runs, `git-sync` will recursively delete that arbitrary target path, analogous to the reported bug class where a destructive operation (`receiveRewards()` burning funds) was missing a required safety gate (`onlyInit`). Here the missing gate is a "resolved worktree path must be under `--root`" check before deletion.

### Finding Description
`currentWorktree()` simply reads the symlink and returns whatever it points to, with no containment check: [1](#0-0) 

That value flows straight into `SyncRepo()`, which treats it as the trusted "current" worktree, calling `sanityCheckWorktree()` against it: [2](#0-1) 

If the sanity check fails (which it trivially will for any directory that isn't the expected git worktree, e.g. `/etc`), `removeWorktree()` is invoked, which does an unguarded `os.RemoveAll()` on the resolved path: [3](#0-2) 

There is also a second, independent `os.RemoveAll` on `currentWorktree.Path()` later in the same function when the hash-derived path check fails: [4](#0-3) 

`worktreeFor()` documents that the intended location is always `--root/.worktrees/<hash>`, but nothing enforces that `currentWorktree()`'s return value actually lives there: [5](#0-4) 

`initRepo()` — the function that is supposed to "make the repo valid" before any sync work happens — only validates `git.root` itself (via `sanityCheckRepo`) and never validates or resets `git.link`: [6](#0-5) 

This mirrors the reported bug class: a destructive action (`os.RemoveAll`) is reachable without the necessary precondition/safety check (here: "target path must be contained under `--root`") being enforced first, just as `receiveRewards()` lacked the `onlyInit` gate before performing a destructive burn.

### Impact Explanation
An attacker who can write to the shared volume that backs `--root`/`--link` (e.g., a co-located/adjacent container sharing the Kubernetes `emptyDir` with the `git-sync` sidecar, or any process with write access to the mount before `git-sync`'s first successful sync) can replace the `--link` path with a symlink pointing at an arbitrary directory (e.g. `/`, `/etc`, application data). On the next sync attempt, `git-sync` will recursively delete that directory tree via `os.RemoveAll`, resulting in file deletion far outside the intended `--root`. This is a "file write or delete outside `--root`" impact and can also cause persistent sync denial or destruction of application/container data sharing the pod.

### Likelihood Explanation
Exploitation requires only filesystem write access to the shared volume/mount point used for `--link` (not git push/commit privileges, not operator/node compromise) — a realistic condition in the common sidecar deployment pattern where multiple containers share the same volume. No git credentials or crafted upstream repo content are needed; the attack is purely local path manipulation of the `--link` location, making it a low-privilege, moderately likely path once volume co-tenancy exists.

### Recommendation
Before treating any resolved worktree path as legitimate (in `currentWorktree()`, or immediately before use in `sanityCheckWorktree`/`removeWorktree`/`os.RemoveAll`), verify that the resolved absolute path is lexically contained within `git.root.Join(".worktrees")` (e.g., using `filepath.Clean` + prefix/`filepath.Rel` checks that reject `..` escapes and non-prefixed targets). If containment fails, treat the link as invalid/corrupt (log and recreate it) rather than deleting the resolved target. This restores the missing safety gate analogous to adding `onlyInit`.

### Proof of Concept
1. Deploy `git-sync` as a sidecar sharing an `emptyDir` volume with another (attacker-controlled or compromised) container, `--root=/git/root --link=link`.
2. Before/at startup, from the co-located container: `ln -s /some/important/dir /git/root/link` (or overwrite the existing `link` after a first sync).
3. Trigger/await the next sync cycle. `git-sync` calls `currentWorktree()` → resolves to `/some/important/dir`; `sanityCheckWorktree` fails (not a valid worktree) → `removeWorktree()` executes `os.RemoveAll("/some/important/dir")`, deleting it entirely.

// initRepo examines the git repo and determines if it is usable or not.  If
// not, it will (re)initialize it.  After running this function, callers can
// assume the repo is valid, though maybe empty.
func (git *repoSync) initRepo(ctx context.Context) error {
	needGitInit := false

	// Check out the git root, and see if it is already usable.
	_, err := os.Stat(git.root.String())
	switch {
	case os.IsNotExist(err):
		// Probably the first sync.  defaultDirMode ensures that this is usable
		// as a volume when the consumer isn't running as the same UID.
		git.log.V(1).Info("repo directory does not exist, creating it", "path", git.root)
		if err := os.MkdirAll(git.root.String(), defaultDirMode); err != nil {
			return err
		}
		needGitInit = true
	case err != nil:
		return err
	default:
		// Make sure the directory we found is actually usable.
		git.log.V(3).Info("repo directory exists", "path", git.root)
		if git.sanityCheckRepo(ctx) {
			git.log.V(4).Info("repo directory is valid", "path", git.root)
		} else {
			// Maybe a previous run crashed?  Git won't use this dir.  We remove
			// the contents rather than the dir itself, because a common use-case
			// is to have a volume mounted at git.root, which makes removing it
			// impossible.
			git.log.V(0).Info("repo directory was empty or failed checks", "path", git.root)
			if err := removeDirContents(git.root, git.log); err != nil {
				return fmt.Errorf("can't wipe unusable root directory: %w", err)
			}
			needGitInit = true
		}
	}

	if needGitInit {
		// Running `git init` in an existing repo is safe (according to git docs).
		git.log.V(0).Info("initializing repo directory", "path", git.root)
		if _, _, err := git.Run(ctx, git.root, "init", "-b", "git-sync"); err != nil {
			return err
		}
		if !git.sanityCheckRepo(ctx) {
			return fmt.Errorf("can't initialize git repo directory")
		}
	}

// removeWorktree is used to remove a worktree and its folder.
func (git *repoSync) removeWorktree(ctx context.Context, worktree worktree) error {
	// Clean up worktree, if needed.
	_, err := os.Stat(worktree.Path().String())
	switch {
	case os.IsNotExist(err):
		return nil
	case err != nil:
		return err
	}
	git.log.V(1).Info("removing worktree", "path", worktree.Path())
	if err := os.RemoveAll(worktree.Path().String()); err != nil {
		return fmt.Errorf("error removing directory: %w", err)
	}
	if _, _, err := git.Run(ctx, git.root, "worktree", "prune", "--verbose"); err != nil {
		return err
	}
	return nil
}

// currentWorktree reads the repo's link and returns a worktree value for it.
func (git *repoSync) currentWorktree() (worktree, error) {
	target, err := os.Readlink(git.link.String())
	if err != nil && !os.IsNotExist(err) {
		return "", err
	}
	if target == "" {
		return "", nil
	}
	if filepath.IsAbs(target) {
		return worktree(target), nil
	}
	linkDir, _ := git.link.Split()
	return worktree(linkDir.Join(target)), nil
}
