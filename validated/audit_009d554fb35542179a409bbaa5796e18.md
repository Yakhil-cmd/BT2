## Finding

The scoped code confirms the exact gap described in the question: `verify_no_instantiations` only pattern-matches `Bytecode::Pack`, and falls through everything else (including any `PackGeneric`/`PackVariant`/`PackVariantGeneric` variant) with `_ => continue`. [1](#0-0) 

### Title
Missing generic-pack instantiation check in one-time-witness verifier allows duplicate OTW construction - (File: `sui-execution/latest/sui-verifier/src/one_time_witness_verifier.rs`)

### Summary
`verify_no_instantiations` is the Sui-specific pass responsible for guaranteeing that a one-time-witness (OTW) candidate struct is "never instantiated anywhere in its defining module" outside of the value handed to `init`. [2](#0-1)  It does this by scanning every instruction in every non-init/non-test function for `Bytecode::Pack(idx)` and comparing the referenced struct definition to the OTW candidate's struct definition. [3](#0-2)  Any other pack-family opcode (`PackGeneric` over a `StructDefInstantiation`, or the enum pack variants) is skipped via the catch-all `_ => continue`. [4](#0-3) 

### Finding Description
The OTW candidate is required to have zero type parameters, which is enforced separately in `verify_one_time_witness`. [5](#0-4)  Nothing in `verify_module`/`verify_no_instantiations` prevents a hand-crafted `CompiledModule` (built directly with `move-binary-format` file-format types rather than via the source compiler, and submitted through a public `Publish`/`Upgrade` transaction) from adding a `StructDefInstantiation` entry that points at the OTW struct's `StructDefinitionIndex` with an empty type-argument signature, and then emitting `Bytecode::PackGeneric` against that instantiation inside an arbitrary non-init function. Because the OTW struct has 0 declared type parameters, a 0-arity type-argument list satisfies the standard Move bytecode-verifier's generic arity check, so nothing in the general-purpose bounds/signature verifiers would reject this structurally. The Sui-specific `verify_no_instantiations` pass, however, never looks at `PackGeneric`, so this second instantiation site is invisible to it.

### Impact Explanation
If a second/third instance of the OTW type can be constructed outside of `init`, the OTW-consuming natives/framework calls (e.g. `sui::types::is_one_time_witness`, `sui::coin::create_currency`, `sui::package::claim`) have no other mechanism to detect reuse — the single-instantiation guarantee enforced by this verifier is the *entire* security boundary. Bypassing it lets a malicious package call `create_currency`/`claim` multiple times, minting duplicate `TreasuryCap`/`Publisher` objects for the same type — this is exactly "unauthorized object creation" and lands in the Critical bucket per the allowed-impact gate.

### Likelihood Explanation
The entrypoint (package publish with raw/precompiled bytecode) is a normal, unprivileged, public transaction — no validator/admin/governance trust is required. The gap is a straightforward reading of the match arm in `verify_no_instantiations`. I was not able to fully re-verify, within the available tool budget, that the generic bytecode-verifier passes (`move-bytecode-verifier/src/signature.rs`, bounds checker) unconditionally accept a `StructDefInstantiation` with a 0-arity type-argument signature against a 0-type-parameter struct definition (this is the one remaining structural precondition for the exploit to reach the loader/interpreter). This should be validated with an actual crafted `CompiledModule` + `move-bytecode-verifier` run before treating this as confirmed-exploitable, but the verifier logic itself, as shown in the source, unambiguously only checks `Bytecode::Pack` and ignores all other pack-family opcodes.

### Recommendation
Extend `verify_no_instantiations` to also match `Bytecode::PackGeneric(inst_idx)` (resolving through `module.struct_instantiation_at(*inst_idx).def`) and any other struct/variant "pack" opcodes present in the bytecode format, comparing the resolved base `StructDefinitionIndex` against the OTW candidate the same way `Bytecode::Pack` is currently checked.

### Proof of Concept
Conceptual PoC (requires binary-format-level crafting, not achievable purely via Move source):
1. Compile a normal module with a valid OTW struct `MODULE_NAME` and legitimate `init(otw: MODULE_NAME, ctx: &mut TxContext)`.
2. Post-process the serialized `CompiledModule`: add a `StructDefInstantiation { def: <OTW struct_def_idx>, type_parameters: <empty Signature index> }` to the `struct_def_instantiations` table.
3. In a separate public function (e.g. `mint_extra`), replace/insert a `Bytecode::PackGeneric(<new_inst_idx>)` instruction that constructs the same struct, followed by a call into `create_currency`/`package::claim`.
4. Publish the module via a normal `Publish` PTB command; because `verify_no_instantiations` only scans `Bytecode::Pack`, verification passes, and calling `mint_extra` at runtime yields a second OTW instance and a duplicate `TreasuryCap`/`Publisher`.

Note: step 4's runtime success depends on the generic-instantiation arity/signature checks in the base Move bytecode verifier accepting a 0-arg `StructDefInstantiation` against a 0-type-param struct — this final link was not independently re-confirmed in this review pass due to tool-call exhaustion and should be validated experimentally.

```rust
/// Checks if this module function does not contain instantiation of the one-time witness type
fn verify_no_instantiations(
    module: &CompiledModule,
    fn_def: &FunctionDefinition,
    struct_name: &str,
    struct_def: &StructDefinition,
) -> Result<(), String> {
    if fn_def.code.is_none() {
        return Ok(());
    }
    for bcode in &fn_def.code.as_ref().unwrap().code {
        let struct_def_idx = match bcode {
            Bytecode::Pack(idx) => idx,
            _ => continue,
        };
        // unwrap is safe below since we know we are getting a struct out of a module (see
        // definition of struct_def_at)
        if module.struct_def_at(*struct_def_idx) == struct_def {
            let fn_handle = module.function_handle_at(fn_def.function);
            let fn_name = module.identifier_at(fn_handle.name);
            return Err(format!(
                "one-time witness type {}::{} is instantiated \
                         in the {}::{} function and must never be",
                module.self_id(),
                struct_name,
                module.self_id(),
                fn_name,
            ));
        }
    }
```
