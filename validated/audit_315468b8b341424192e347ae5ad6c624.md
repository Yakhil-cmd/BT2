### Title
Missing council-membership guard in `checkConsistency` for `GovernanceGovernanceMode` enables permanent governance lock — (`kaiax/gov/headergov/impl/header.go`)

### Summary
`checkConsistency` validates the governing node's council membership when a `GovernanceGoverningNode` vote is cast (in single mode), but performs **no equivalent check** when a `GovernanceGovernanceMode='single'` vote is cast. A single malicious council member on a none-mode chain whose governing node is absent from the council can ratify a mode transition to "single", after which the Permissionless HF guard permanently blocks all votes, freezing governance forever.

### Finding Description
In `VerifyVote`, the Permissionless guard at lines 103-107 only fires when the chain is already in single mode. In none mode the guard is skipped, so any council-member proposer may cast a `governance.governancemode='single'` vote. That vote reaches `checkConsistency`, where `GovernanceGovernanceMode` is handled by the catch-all case (lines 205-211) that returns `nil` unconditionally — no check that `params.GoverningNode` is present in the council.

After the epoch boundary the chain enters single mode with a governing node that is not a council member. From that point, the Permissionless guard rejects every vote from a council member (`ErrVotePermissionDenied`), and the governing node can never be a block proposer (it is not in the council), so it can never embed a vote either. The state is irreversible: neither the mode nor the governing node can be changed.

The `GovernanceGoverningNode` case (lines 159-178) already contains the correct pattern — it calls `h.ValSet.GetCouncil(blockNum-1)` and returns `ErrGovNodeNotInValSetList` if the governing node is absent. The same guard is simply missing for the mode-change vote.

### Impact Explanation
After Permissionless HF activates on a chain that has been driven into this state, all header governance votes are permanently rejected. No council member can change `reward.mintingamount`, `reward.ratio`, `reward.minimumstake`, validator set membership, or any other governance parameter. This is a durable, irreversible loss of core chain governance functionality affecting all future reward distribution and validator-set management.

### Likelihood Explanation
The prerequisite state (none-mode chain, governing node not in council) is reachable in two ways: (a) valid genesis configuration — `ValidateGenesisConfig` only enforces governing-node-in-council for single-mode genesis; (b) runtime — in none mode the `RemoveValidator` consistency check does not protect the governing node, so it can be voted out. Once the state exists, a single council member who becomes block proposer for one block can trigger the attack via the `governance_vote` RPC. No majority collusion is required.

### Recommendation
In `checkConsistency`, add a case for `GovernanceGovernanceMode` that, when the voted value is `"single"`, verifies `params.GoverningNode` is present in `council` (mirroring the existing `GovernanceGoverningNode` logic):

```go
case gov.GovernanceGovernanceMode:
    if vote.Value().(string) == "single" {
        council, err := h.ValSet.GetCouncil(blockNum - 1)
        if err != nil {
            return err
        }
        params := h.GetParamSet(blockNum)
        if !slices.Contains(council, params.GoverningNode) {
            return ErrGovNodeNotInValSetList
        }
    }
    return nil
```

### Proof of Concept
1. Deploy a none-mode chain with governing node `G` not in the council `{A, B, C}`.
2. Node `A` calls `governance_vote("governance.governancemode", "single")` and becomes block proposer — the vote is embedded in `header.Vote`.
3. `VerifyVote` passes (A is in council, A is proposer, mode is none so Permissionless guard skipped). `checkConsistency` returns `nil` (catch-all case).
4. At the next epoch block, `getExpectedGovernance` collects the vote; `header.Governance` is set to `{"governance.governancemode":"single"}`.
5. `GetParamSet` now returns `GovernanceMode="single"`, `GoverningNode=G` (not in council).
6. After Permissionless HF: any vote from A, B, or C hits `ErrVotePermissionDenied`; G cannot propose blocks. Assert all subsequent `governance_vote` calls are rejected. Governance is permanently frozen.

func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList
	case gov.Kip71LowerBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) > params.UpperBoundBaseFee {
			return ErrLowerBoundBaseFee
		} else {
			return nil
		}
	case gov.Kip71UpperBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) < params.LowerBoundBaseFee {
			return ErrUpperBoundBaseFee
		} else {
			return nil
		}
	case gov.AddValidator, gov.RemoveValidator:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}
		if slices.Contains(vote.Value().([]common.Address), params.GoverningNode) {
			return ErrGovNodeInValSetVoteValue
		}
		return nil
		// These votes are valid as long as it passes the format checks in NewVoteData(). No more checks here.
	case gov.GovernanceDeriveShaImpl, gov.GovernanceGovParamContract, gov.GovernanceGovernanceMode, gov.GovernanceUnitPrice,
		gov.IstanbulCommitteeSize, gov.IstanbulEpoch, gov.IstanbulPolicy,

		gov.RewardDeferredTxFee, gov.RewardKip82Ratio, gov.RewardMintingAmount, gov.RewardMinimumStake,
		gov.RewardProposerUpdateInterval, gov.RewardRatio, gov.RewardStakingRewardThreshold,
		gov.RewardStakingUpdateInterval, gov.RewardUseFlexReward, gov.RewardUseGiniCoeff:

}
