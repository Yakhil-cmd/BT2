### Title
`Kip71GasTarget` governance parameter accepts zero via `noopFormatChecker`, causing `big.Int.Div` panic in `NextMagmaBlockBaseFee` and crashing all honest nodes during block header validation — (`File: params/kip71_config.go`, `kaiax/gov/param.go`)

---

### Summary

The `kip71.gastarget` governance parameter is registered with `noopFormatChecker` in `kaiax/gov/param.go`, meaning any value including `0` passes vote validation. When `GasTarget == 0` is committed via governance and any subsequent block has `parentGasUsed > 0`, `NextMagmaBlockBaseFee` in `params/kip71_config.go` reaches an unguarded `big.Int.Div(x, 0)` at line 102, which panics in Go. This panic propagates through `VerifyMagmaHeader` → `BlockValidator.validateHeader` → `ValidateHeader`, crashing every honest node that attempts to validate a post-vote block.

---

### Finding Description

**Root cause — missing `FormatChecker` for `Kip71GasTarget`:**

In `kaiax/gov/param.go`, the `Kip71GasTarget` parameter is registered with `noopFormatChecker`, which unconditionally returns `true` for any value: [1](#0-0) 

By contrast, the developers already recognized the division-by-zero risk for `Kip71BaseFeeDenominator` and gave it a real checker that rejects `0`: [2](#0-1) 

`GasTarget` received no equivalent protection.

**Division-by-zero in `NextMagmaBlockBaseFee`:**

When `GasTarget == 0` and `parentGasUsed > 0` (any non-empty block), execution enters the `parentGasUsed > gasTarget` branch and hits:

```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // gasTarget == 0 → panic
``` [3](#0-2) 

Go's `big.Int.Div` panics unconditionally when the divisor is zero. There is a defensive guard for `BaseFeeDenominator == 0` (lines 71–76) but **no analogous guard for `gasTarget == 0`**.

**Panic propagates through block validation:**

`NextMagmaBlockBaseFee` is called by `VerifyMagmaHeader`: [4](#0-3) 

`VerifyMagmaHeader` is called inside `BlockValidator.validateHeader` for every post-Magma block: [5](#0-4) 

`validateHeader` is called from the Istanbul consensus backend's `Verify` path: [6](#0-5) 

Every honest node that receives and validates a block after the governance vote takes effect will panic and crash.

---

### Impact Explanation

- **Consensus divergence / crash of all honest nodes.** After the governance epoch boundary at which `GasTarget = 0` takes effect, every block with any gas used (i.e., any block containing transactions) causes a Go runtime panic in `NextMagmaBlockBaseFee`. This crashes the node process entirely.
- The corrupted value is the `GasTarget` field in the active `KIP71Config` used for base-fee derivation and header verification. Every subsequent block header fails to validate, halting the chain on all honest nodes.
- This is a **consensus divergence** impact: honest nodes cannot import or verify new blocks, matching the allowed impact gate ("invalid block/proof/snapshot acceptance, or consensus divergence on honest nodes").

---

### Likelihood Explanation

- In `"single"` governance mode, the single governing node can unilaterally cast a vote for `kip71.gastarget = 0`. The vote passes `FormatChecker` (returns `true` for any `uint64`) and is committed at the next epoch boundary.
- No additional collusion is required. This is a single semi-trusted actor, directly analogous to the "owner" in the external report.
- The trigger condition (`parentGasUsed > 0`) is satisfied by virtually every real block on a live network.

---

### Recommendation

Apply a non-zero minimum bound check to `Kip71GasTarget`, mirroring the existing check for `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v > 0   // GasTarget == 0 causes division by zero
    },
    ...
},
```

Additionally, add a defensive guard in `NextMagmaBlockBaseFee` analogous to the existing `BaseFeeDenominator == 0` guard:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    // Governance misconfiguration: avoid division by zero
    gasTarget = 1
}
``` [7](#0-6) 

---

### Proof of Concept

1. Governing node (in `"single"` governance mode) submits a vote: `kip71.gastarget = 0`.
2. The vote passes `FormatChecker` (`noopFormatChecker` returns `true`) and is stored in the header governance field.
3. At the next epoch boundary, the governance parameter set is updated: `GasTarget = 0`.
4. The next block is produced with any transactions (e.g., `parentGasUsed = 1`).
5. Every node calls `BlockValidator.validateHeader` → `govParamSet.ToKip71Config().VerifyMagmaHeader(...)` → `NextMagmaBlockBaseFee(...)`.
6. Inside `NextMagmaBlockBaseFee`: `parentGasUsed (1) > gasTarget (0)` → enters the increase branch → `x.Div(x, new(big.Int).SetUint64(0))` → **Go runtime panic: `division by zero`**.
7. All honest nodes crash. The chain halts. [8](#0-7) [9](#0-8)

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
