### Title
Unsanitized skill descriptions from `FetchDescriptionsConcurrent` allow terminal escape-sequence injection during `gh skill install` - (File: internal/skills/discovery/discovery.go)

### Summary
`FetchDescriptionsConcurrent` fetches each skill's frontmatter `description` field via `fetchDescription`/`frontmatter.Parse` and stores it verbatim on the `Skill` struct with no sanitization of terminal control sequences. [1](#0-0) [2](#0-1)  That raw description is later rendered directly to the terminal by the `install` command's interactive picker, non-interactive table listing, and search labels.

### Finding Description
`fetchDescription` reads a skill's `SKILL.md` blob and extracts `result.Metadata.Description` straight from attacker-controlled frontmatter with no filtering of ANSI/OSC/CSI control bytes. [3](#0-2)  `FetchDescriptionsConcurrent` populates `Skill.Description` for every skill missing a description, again without sanitization. [2](#0-1) 

This value flows into multiple terminal-rendering sinks in `pkg/cmd/skills/install/install.go`:
- The non-interactive table listing writes `s.Description` (only whitespace-normalized and width-truncated, not control-sequence-stripped) directly into a `tableprinter` field. [4](#0-3) 
- The interactive `MultiSelectWithSearch` label builder embeds `s.Description` into the label string shown in the picker, passed only through `text.RemoveExcessiveWhitespace` and `text.Truncate`. [5](#0-4) 
- The search filter itself does a raw substring match against `s.Description`. [6](#0-5) 

I inspected `internal/text/text.go`, which backs `Truncate` and `RemoveExcessiveWhitespace`; neither function strips ANSI escape sequences, OSC/CSI control bytes, or other terminal control characters — they only handle Unicode display width and whitespace collapsing. [7](#0-6)  A repo-wide search found no sanitization helpers such as `Sanitize`, `StripANSI`, `ContainsControl`, or `IsControl` used anywhere in this path, confirming there is no defense-in-depth filter before these strings reach `fmt.Fprintf`/`tableprinter`/prompter output.

**Attacker input path:** a remote GitHub user publishes a repository containing a `SKILL.md` whose YAML frontmatter `description:` field contains raw OSC 8 hyperlink payloads, OSC 52 clipboard-write sequences, or CSI cursor-manipulation sequences. When a victim runs `gh skill install owner/repo` (interactively or non-interactively without a skill name), `discoverSkills` → `FetchDescriptionsConcurrent` fetches and stores this payload, and it is rendered unmodified to the victim's terminal via the table or the interactive multi-select prompt.

### Impact Explanation
This matches the "Terminal output/prompt spoofing" impact class described in the question. A malicious description containing OSC 8 sequences can render a link whose displayed text differs from its underlying URI, or fake trailing terminal state (e.g., overwrite the previous line, hide/alter subsequent CLI prompts) to trick the victim during the skill-selection step, potentially leading to selection of a different/malicious skill than intended, or, on vulnerable terminal emulators, clipboard injection (OSC 52) or window-title spoofing. Because this occurs before installation confirmation, it can influence a security-relevant decision (which skill to trust and install).

### Likelihood Explanation
The precondition is only that the attacker can publish any public repository with a `skills/*/SKILL.md` file — a fully unprivileged action. Any victim running `gh skill install <attacker-repo>` without pre-specifying a skill name triggers `FetchDescriptionsConcurrent` and display of the tainted description, making this reliably reproducible on the interactive path (`opts.Prompter.MultiSelectWithSearch`) and the non-interactive listing path (`listAvailableSkills`).

### Recommendation
Sanitize all skill-sourced text (`Description`, and similarly any file-list/instruction text rendered elsewhere) before it reaches terminal output: strip or escape ANSI/OSC/CSI control sequences and other non-printable control characters in `fetchDescription` (or immediately after `frontmatter.Parse`) in `internal/skills/discovery/discovery.go`, and/or add a shared sanitization step in `internal/text` that is applied wherever skill-derived strings are passed to `tableprinter.AddField`, `fmt.Fprintf`, or prompter labels in `pkg/cmd/skills/install/install.go`.

### Proof of Concept
Golden test plan (to be implemented in `internal/skills/discovery/discovery_test.go` or `pkg/cmd/skills/install/install_test.go`):
1. Stub `client.REST`/blob fetch (via httpmock, consistent with existing tests referencing `FetchDescriptionsConcurrent`) to return a `SKILL.md` blob whose frontmatter `description` is: `"Legit desc\x1b]8;;https://evil.example\x07CLICK\x1b]8;;\x07\x1b[2K\x1b[1A"` (OSC 8 hyperlink + cursor-erase/move sequences).
2. Call `discovery.FetchDescriptionsConcurrent(client, host, owner, repo, skills, nil)` and assert `skills[0].Description` still contains the raw `\x1b` bytes (demonstrating no sanitization occurs).
3. Extend to `pkg/cmd/skills/install/install_test.go`: run `listAvailableSkills`/`skillSearchFunc` against such a skill and assert the rendered table/label bytes contain the literal escape sequence rather than an escaped/stripped representation — expected assertion after fix: output must not contain `\x1b` (or must contain only visually-escaped representations like `\\x1b`).

// fetchDescription fetches and parses the frontmatter description for a skill.
func fetchDescription(client *api.Client, host, owner, repo string, skill *Skill) string {
	if skill.BlobSHA == "" {
		return ""
	}
	content, err := FetchBlob(client, host, owner, repo, skill.BlobSHA)
	if err != nil {
		return ""
	}
	result, err := frontmatter.Parse(content.Raw())
	if err != nil {
		return ""
	}
	return result.Metadata.Description
}

// FetchDescriptionsConcurrent fetches descriptions with bounded concurrency.
func FetchDescriptionsConcurrent(client *api.Client, host, owner, repo string, skills []Skill, onProgress func(done, total int)) {
	total := 0
	for _, s := range skills {
		if s.Description == "" {
			total++
		}
	}
	if total == 0 {
		return
	}

	const maxWorkers = 10
	var wg sync.WaitGroup
	var done atomic.Int32

	jobs := make(chan *Skill)

	workers := min(maxWorkers, total)
	for range workers {
		wg.Go(func() {
			for s := range jobs {
				s.Description = fetchDescription(client, host, owner, repo, s)

				d := int(done.Add(1))
				if onProgress != nil {
					onProgress(d, total)
				}
			}
		})
	}

	for i := range skills {
		if skills[i].Description == "" {
			jobs <- &skills[i]
		}
	}
	close(jobs)
	wg.Wait()
}
