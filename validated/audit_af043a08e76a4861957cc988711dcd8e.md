### Title
Unfiltered pull-request label names merged into task environment - ([File: app/models/shipit/review_stack.rb])

### Summary
`ReviewStack#env` merges every pull-request label name (uppercased) directly into the environment hash used for all task commands, without any allowlist. Because this hash flows unfiltered through `TaskCommands#env` into `Command#unbundled_env` and finally `PTY.spawn`, an unprivileged fork PR author can set security-sensitive interpreter variables such as `PYTHONPATH` (and similarly `LD_PRELOAD`, `RUBYOPT`, `BUNDLE_GEMFILE`, etc.) for the `dependencies.override` step and any other step executed against the review stack.

### Finding Description
The broken binding: `ReviewStack#env` should equal `super` env plus only a bounded, safe set of PR-derived flags, but instead:

```ruby
# app/models/shipit/review_stack.rb:84-93
def env
  return super unless pull_request.present?
  super.merge(
    pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }
  )
end
```

merges **every** label name, uppercased, as a key with no denylist for reserved/interpreter-controlling variable names (`PYTHONPATH`, `LD_PRELOAD`, `RUBYOPT`, `GEM_PATH`, `PATH`, etc.). This is fed into `TaskCommands#env` (`lib/shipit/task_commands.rb:33-48`), which merges `@stack.env` (the `ReviewStack#env` output) directly into the command environment for both `install_dependencies` (`dependencies_steps!`, i.e. the `dependencies.override` phase) and `perform` steps. That merged hash is passed unmodified as `env:` to `Command.new`, stored in `@env`, and ultimately combined in `Command#unbundled_env` (`lib/shipit/command.rb:103-105`):

```ruby
def unbundled_env
  BASE_ENV.merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}").merge(@env.stringify_keys)
end
```

with `@env` values taking precedence over `BASE_ENV`, and finally passed to `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)` (`lib/shipit/command.rb:92`).

Labels are attacker-supplied and require no privilege: they are captured verbatim from the webhook `pull_request.labels[].name` field by `LabelCapturingHandler#capture_labels` (`app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb:98-102`), which the PR author fully controls by labeling their own pull request (any GitHub user can label their own PR from their own fork). No signature/permission check restricts label *content* — `verify_signature`/webhook auth only validates that the request came from GitHub for that repository, not that the label text is safe.

The only limitation is that the *value* is a fixed literal `"true"`, not an attacker-chosen string — so `PYTHONPATH` becomes `"true"` (a relative path), not an arbitrary absolute path. However, because review stacks build and run commands inside the checked-out working directory of the attacker's own fork/PR branch, the attacker also controls the on-disk layout at `chdir`. Combined with `PYTHONPATH=true` (relative import path resolution) or similarly abusable variables, an attacker who also commits a colliding file/module in their PR (e.g. a `true/` directory shadowing a stdlib or third-party module imported by the `dependencies.override` step) can achieve import-time code execution during that step, since Python resolves `sys.path` entries relative to the current working directory when `PYTHONPATH` is a relative value.

No existing guard intercepts this: `EnvironmentVariables#permit` and the `subset`/`url` validators referenced in `Stack`/`TaskDefinition` govern the *declared* `env:` section of `shipit.yml`, not this separate PR-label-derived hash constructed in `ReviewStack#env`, so they never see or filter these keys.

### Impact Explanation
An attacker who can only open/label a pull request on their own fork can inject reserved interpreter/runtime environment variables into every command executed for that review stack, including the `dependencies.override` step. Combined with control over the checked-out working directory contents (their own PR branch), this can result in arbitrary code execution during dependency installation on the Shipit deploy host — matching the Critical "RCE on the deploy host via `Command`/`PTY.spawn`" category. The blast radius is scoped to the review stack for that specific PR/repository (each review stack runs in its own working directory), but is fully repeatable per PR/label change.

### Likelihood Explanation
Preconditions: the target repository's provisioning uses review stacks (`provisioning_behavior` gating review-stack creation) and defines a `dependencies.override`/steps section in `shipit.yml` that invokes an interpreter sensitive to the injected variable (e.g., Python). The attacker needs only fork-PR and self-labeling capability — no Shipit session, API token, or repository maintainer status. This is low cost and fully attacker-controlled/repeatable (relabel triggers `LabelCapturingHandler` again). The main uncertainty is whether a given repo's dependency step is actually vulnerable to a `PYTHONPATH=true` (or similar) style hijack, which depends on the target's build tooling — this is configuration-dependent but the underlying env-injection primitive itself is unconditionally present.

### Recommendation
In `ReviewStack#env`, do not merge raw uppercased label names as environment variable keys. Either: (1) prefix all label-derived keys with a fixed, non-conflicting namespace (e.g. `SHIPIT_LABEL_<NAME>`) so they can never collide with interpreter/runtime variables, and/or (2) apply an explicit allowlist/denylist rejecting reserved variable names (`PATH`, `PYTHONPATH`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `RUBYOPT`, `BUNDLE_*`, `GEM_*`, etc.) before merging into the stack/task environment used by `Command`.

### Proof of Concept
`test/models/shipit/review_stack_test.rb` (or `test/unit/task_commands_test.rb`):
```ruby
test "PYTHONPATH via label name reaches dependencies.override command env" do
  stack = shipit_review_stacks(:review_stack) # or build one with a pull_request
  stack.pull_request.update!(labels: ['pythonpath'])

  env = stack.env
  assert_equal 'true', env['PYTHONPATH'], "attacker-controlled label should not set PYTHONPATH"
end
```
and at the `Command` boundary:
```ruby
command = Shipit::Command.new('python -c "print(1)"', env: stack.env, chdir: some_dir)
assert_equal 'true', command.unbundled_env['PYTHONPATH']
```
Both assertions demonstrate the equality `stack.env['PYTHONPATH'] == 'true'` (attacker-set) reaching `Command#unbundled_env`/`PTY.spawn`, proving the fork-controlled label name propagates into the spawned process environment with no allowlist filtering.
