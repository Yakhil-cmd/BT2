### Title
Peer-Supplied `P2PStakingInfo` Accepted Without Content Validation During Fast Sync, Enabling Corrupted Reward-Distribution State - (File: `datasync/downloader/queue.go`)

---

### Summary

During fast sync, `queue.DeliverStakingInfos` accepts staking information from any connected peer and writes it directly to the local database without verifying its content against the committed chain state. The `validate` callback is an explicit no-op (marked `TODO-Kaia-Snapsync update validation logic`), unlike every other downloaded data type (receipts, bodies) which are cryptographically verified against their block headers. A malicious peer can inject fabricated `P2PStakingInfo` records containing arbitrary validator reward addresses, treasury fund addresses (`KEFAddr`/`KIFAddr`), and staking amounts. These are persisted via `PutStakingInfoToDB` and subsequently consumed by the reward module to distribute KAIA block rewards, causing misdirected treasury and validator reward transfers and/or consensus divergence.

---

### Impact Explanation

A malicious peer responding to staking-info requests during fast sync can inject a `P2PStakingInfo` record with:

- **Arbitrary `KEFAddr`/`KIFAddr`**: treasury fund portions of every block reward (KIF ~54 %, KEF ~12 % of minting amount on mainnet) are credited to attacker-controlled addresses instead of the legitimate fund contracts.
- **Arbitrary `CouncilRewardAddrs`**: per-validator staking rewards are sent to wrong addresses.
- **Inflated/zeroed `CouncilStakingAmounts`**: proposer-selection weights are skewed, enabling a targeted validator to monopolise block proposals.
- **Wrong state root**: because `FinalizeState` uses the corrupted staking info to compute balance changes, the resulting state root diverges from the canonical chain, causing the node to reject all subsequent valid blocks — a persistent consensus divergence.

The corrupted value is the `StakingInfo` record written to the miscDB key `"stakingInfo" || Uint64LE(sourceNum)`, which is the sole source of truth for reward distribution before the Kaia hardfork. [10](#0-9) 

---

### Likelihood Explanation

Fast sync is the default mode for any node syncing from scratch or after a long offline period. The attacker only needs to be a connected P2P peer — no special privilege is required. The node requests staking info by block hash from whichever peers are available; a single malicious peer that responds first to a staking-info request for a given block hash can inject the fabricated record. The attack is silent (no error is returned or logged for content mismatch) and persistent (the record survives node restarts).

---

### Recommendation

Implement content validation in `queue.DeliverStakingInfos` analogous to `DeliverReceipts`. The canonical approach is to re-derive the staking info from the local state at the source block and compare it against the peer-supplied data, or to commit a hash of the staking info into the block header (similar to `ReceiptHash`) so that the validate callback can perform a cryptographic check without re-executing state. At minimum, the `TODO-Kaia-Snapsync update validation logic` placeholder must be replaced with a real check before fast sync is used in production with untrusted peers.

---

### Proof of Concept

1. Node A starts fast sync against a chain where staking info exists at block `N` (a multiple of `StakingUpdateInterval`).
2. Attacker peer B is connected to Node A.
3. Node A sends `StakingInfoRequestMsg` containing the hash of block `N`.
4. Peer B responds with a `StakingInfoMsg` containing a `P2PStakingInfo` where `KEFAddr` is set to attacker address `0xDEAD...` and `CouncilStakingAmounts` are all set to `0`.
5. `handleStakingInfoMsg` → `DeliverStakingInfos` → `queue.DeliverStakingInfos` calls `validate(...)` which returns `nil` unconditionally.
6. `commitFastSyncData` calls `PutStakingInfoToDB(N, ToStakingInfo(fabricated))`.
7. After fast sync completes, when Node A processes block `N+StakingUpdateInterval`, `GetStakingInfo` returns the fabricated record from DB.
8. `FinalizeState` calls `specWithProposerAndFunds` with `si.KEFAddr = 0xDEAD...`, crediting the KEF portion of every block reward to the attacker.
9. The resulting state root differs from the canonical chain; Node A diverges and cannot follow the canonical head.

```go
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")

	// A batch of stakingInfos arrived to one of our previous requests

		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
```

```go
// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
```
