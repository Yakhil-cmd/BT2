### Title

Interest accrual overflows scaled debt before the borrow-index cap, permanently freezing a whale market - (File: common/src/rates/simulate.rs)

### Summary

Although XOXNO clamps the calculated borrow rate at `max_borrow_rate`, accrual can still leave the fixed-point safe domain before the borrow index reaches `MAX_BORROW_INDEX_RAY`. `accrue_step` multiplies aggregate scaled debt by the borrow index to reconstruct the original debt before applying the index cap, so a sufficiently large market can overflow `i128`. Once that state is reached, every operation that synchronizes the market panics, permanently freezing the market absent a contract upgrade. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description

Each accrual step calls `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` before calculating utilization, the borrow rate, and the next index. [4](#0-3)  `scaled_to_original` is a direct `Ray::mul`, so `scaled * index` panics when the raw product exceeds `i128::MAX`. [2](#0-1) 

The configured borrow rate is capped, but the borrow-index ceiling is `1e36` raw RAY—equivalent to an index multiplier of `1e9`—and is applied only after `accrue_step` has already multiplied the scaled balances by the current index. [5](#0-4) [6](#0-5)  Therefore, the protocol does not enforce the actual invariant needed by accrual, which is approximately `scaled_balance * MAX_INDEX <= i128::MAX`.

For an 18-decimal market with 1 billion whole tokens supplied, the scaled balance is about `1e36` raw RAY, meaning the debt-value multiplication overflows once the index exceeds roughly 170x rather than the nominal `1e9x` index cap. [7](#0-6)  The repository’s own integration test demonstrates this exact cliff at sustained 98% utilization and asserts `MATH_OVERFLOW` before `MAX_BORROW_INDEX_RAY` is reached. [8](#0-7) 

All normal pool mutations load a synchronized cache through `synced_market`, which calls `interest::global_sync` before executing the operation. [9](#0-8)  `global_sync` routes every elapsed-time accrual through the vulnerable `accrue_step`. [10](#0-9)  Even replacing the rate model first accrues under the old model, so governance cannot lower the curve through `update_params` once the overflow state exists. [11](#0-10) 

### Impact Explanation

This is permanent freezing of user funds in the affected market: suppliers cannot withdraw, borrowers cannot repay, and liquidations cannot proceed because those paths all accrue first. [12](#0-11)  The panic aborts before state is committed, so retrying after further time advances reaches the same multiplication and fails again. [13](#0-12) 

An unprivileged user can trigger the failing accrual directly through `Controller::update_indexes(caller, assets)`, where `assets` is `Vec<HubAssetKey>` containing the victim `(hub_id, asset)` market. [14](#0-13)  The controller forwards that permissionless request to the pool’s `update_indexes` implementation, which commits accrued state. [15](#0-14) [16](#0-15) 

### Likelihood Explanation

The condition is economically heavy but reachable without privileges: a whale supplies approximately `1_000_000_000 * 10^18` base units of an 18-decimal asset, another account supplies sufficient collateral, and the market remains near 98% utilization while the borrow index compounds toward approximately 170x. [17](#0-16)  No privileged call is required to trigger the failure because `update_indexes` is permissionless, and the integration test demonstrates the state using normal supply and borrow flows. [14](#0-13) [18](#0-17) 

### Recommendation

Enforce the fixed-point domain invariant whenever shares are minted or market parameters are configured: aggregate scaled supply and debt must remain small enough that `scaled * MAX_*_INDEX` and the intermediate calculations in `calculate_supplier_rewards` cannot overflow `i128`. [19](#0-18)  This can be done by deriving a per-market maximum scaled balance from the index ceilings and rejecting supply, debt minting, flash positions, or strategy creation that would exceed it.

Accrual should also use checked or saturating reconstruction for utilization and reward calculations so that reaching the boundary clamps indexes instead of panicking. [2](#0-1)  Finally, add a regression boundary at `scaled_balance <= i128::MAX / MAX_BORROW_INDEX_RAY` and equivalent supply-index coverage, rather than relying only on the nominal `1e9x` index cap.

### Proof of Concept

The existing integration test constructs the vulnerable market through normal user operations:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);
```

It then advances time year-by-year and calls `update_indexes` for `BIG18` until the accrual reverts with `MATH_OVERFLOW`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [20](#0-19)  The same test proves that subsequent `withdraw` and `repay` calls revert with the same overflow, confirming the market freeze. [12](#0-11)

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
