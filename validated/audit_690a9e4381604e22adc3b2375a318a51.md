### Title
Webhook signature is verified against `repository.owner.login` but every event handler acts on `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and therefore the `webhook_secret`) used to validate `X-Hub-Signature` based solely on `repository.owner.login` (or `organization.login`) taken from the unauthenticated JSON body. But every downstream handler resolves the target `Stack`/`Repository` using a *different* field, `repository.full_name`, which is never cross-checked against the field used for signature selection.

### Finding Description
`verify_signature` picks the signing app config like this: [1](#0-0) 

with `repository_owner` defined as: [2](#0-1) 

`Shipit.github(organization:)` looks up per-organization config from `secrets.github`, each of which can have its own independent `webhook_secret` (multi-org config schema): [3](#0-2) 

Once verification passes (or is bypassed), `create` hands the *entire* raw payload to the handlers, unfiltered and un-scoped to the organization that was authenticated: [4](#0-3) 

Every base and event-specific handler then re-derives the target repository from a completely different JSON field — `repository.full_name` — with no relation to `repository.owner.login` used above: [5](#0-4) 

This same pattern repeats in the push handler and every pull-request sub-handler, all resolving the acted-upon repository via `params.repository.full_name`: [6](#0-5) [7](#0-6) 

This is exactly the H-17 bug class: the security check is bound to one field (`msg.sender` in Vader / `repository.owner.login` here) while the state-changing action is executed against a different, unrelated field (`recipient` in Vader / `repository.full_name` here). Concretely: for an operator running the documented multi-org config, if **any** configured organization has `webhook_secret: nil` (unconfigured, explicitly allowed by the setup docs — `webhook_secret: some-secret-value` is optional per org, see `docs/setup.md`), `verify_webhook_signature` short-circuits and returns `true` unconditionally for that organization: [8](#0-7) 

An unprivileged attacker can then submit a raw POST to `/github/webhooks` with `repository.owner.login` set to that unsecured organization (satisfying `verify_signature`), while setting `repository.full_name` to `"victim-org/victim-repo"` — a completely different, secured organization's repository that Shipit tracks. The handler resolves the target stack purely off `full_name` and executes attacker-controlled state changes against it (e.g. triggering `GithubSyncJob`, archiving/creating review stacks, injecting commit statuses, mutating team memberships) without ever having its signature validated by the real owning organization's secret.

### Impact Explanation
This crosses the "an organization that authenticated versus the repository that is written" binding explicitly called out in scope: signature verification authenticates one organization while the write/action targets an entirely different, unrelated repository's stack state. This can cause unauthorized triggering of GitHub syncs, forged commit statuses, forced review-stack archival/unarchival, or spoofed team membership changes against repositories the attacker does not control and never proved knowledge of that repository's own webhook secret for — a cross-repository/cross-tenant write achieved purely by controlling unauthenticated JSON body fields.

### Likelihood Explanation
Requires a Shipit deployment using the multi-org config schema (`secrets.github` keyed by organization, as documented in `docs/setup.md`) with at least one organization lacking a `webhook_secret` — an explicitly supported and documented configuration (`webhook_secret: # nil` in `docs/setup.md` and `config/secrets.development.example.yml`). No credential, session, or GitHub App private key is needed; the attacker only needs network access to `POST /github/webhooks` and knowledge of which org is unsecured (discoverable by trial, since a 422 vs 200 response leaks whether the chosen `repository_owner` is a valid/secured org).

### Recommendation
Bind the field used for signature verification to the field used for action resolution: derive both the authenticating organization and the acted-upon repository/stack from the same, single trusted field (e.g., always use `repository.full_name`'s owner segment for `Shipit.github(organization:)`, or reject payloads where `repository.owner.login` doesn't match the owner segment of `repository.full_name`). Additionally, do not allow silently skipping signature verification (`return true unless webhook_secret`) for named organizations in multi-org mode — require an explicit secret per organization or reject the webhook.

### Proof of Concept
1. Deploy Shipit with multi-org `secrets.github` config: `orgA` has no `webhook_secret`; `victim-org` has a Stack/Repository tracked with `webhook_secret` set and kept private.
2. Attacker sends `POST /github/webhooks` with header `X-Github-Event: push`, no valid `X-Hub-Signature` needed, and body:
```json
{
  "repository": { "owner": { "login": "orgA" }, "full_name": "victim-org/victim-repo" },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "orgA")`, whose `webhook_secret` is `nil`, so `verify_webhook_signature` returns `true` regardless of the (missing/garbage) `X-Hub-Signature` header (`lib/shipit/github_app.rb:76-83`).
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) and triggers `stack.sync_github(expected_head_sha: params.after)` for the victim's stack — an unauthenticated action against a repository whose own webhook secret was never checked.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
