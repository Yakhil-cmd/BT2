### Title
Unsynchronized concurrent mutation of shared unit caches during AA dry-run trigger evaluation - ([File: aa_composer.js])

### Summary
`aa_composer.dryRunPrimaryAATrigger()`, reachable by any unauthenticated light-wallet client through the `light/dry_run_aa` network command, writes a speculative response unit into the process-wide, module-scoped caches `storage.assocUnstableUnits` / `storage.assocBestChildren` via `writer.saveJoint()`, and then unwinds those same caches via `revertResponsesInCaches()` — all **without acquiring any of the mutex locks** (`write`, `handleJoint`, `aa_triggers`) that every other code path uses before touching these shared structures. This is analogous to the kernel bug: one code path (`fb_deferred_io_mkwrite`) appends to a shared list while another path (`fb_deferred_io_fault`) re-initializes the same list node without a shared lock, corrupting the list. Here, a dry run can interleave with a real AA trigger, a real unit save, or another concurrent dry run, corrupting the same in-memory `assocUnstableUnits`/`assocBestChildren` caches that the stability/main-chain algorithm depends on.

### Finding Description
`dryRunPrimaryAATrigger()` is invoked directly from `network.js`'s handler for the unauthenticated command `light/dry_run_aa`: [1](#0-0) 
and it takes no mutex before running: [2](#0-1) 

Inside, `handleTrigger()` → `validateAndSaveUnit()` calls `writer.saveJoint()` directly to persist the speculative response unit into RAM caches: [3](#0-2) 

`writer.saveJoint()` mutates the shared globals `storage.assocUnstableUnits` and `storage.assocBestChildren` (pushing the new unit into the parent's children array) — note the comment showing that the internal "write" lock that would normally serialize this mutation is **commented out**, i.e. callers are expected to already hold it: [4](#0-3) 

After the dry run finishes, `onDone` calls `revertResponsesInCaches()`, which deletes the just-created unit(s) from `storage.assocUnstableUnits` and recomputes `is_free` flags on their parents by scanning the *entire* `assocUnstableUnits` map: [5](#0-4) [6](#0-5) 

Contrast this with every legitimate write path, which explicitly serializes access to these same caches:
- Real primary AA trigger execution is serialized under the `aa_triggers` lock: [7](#0-6) 
- Real unit saving via the composer takes the `handleJoint` lock before calling `writer.saveJoint`: [8](#0-7) 

`dryRunPrimaryAATrigger()` has none of this protection, yet it performs the exact same cache mutations (`writer.saveJoint` push, then `forgetUnit`/`fixIsFreeAfterForgettingUnit` scan-and-mutate) as the locked paths. Because Node's event loop interleaves callbacks at every asynchronous DB/kvstore boundary (of which there are many inside `handleTrigger`/`saveJoint`), a second dry run, a real AA trigger, or a real incoming unit can execute its own cache mutation in between two steps of an in-flight dry run's cache mutation/revert sequence.

### Impact Explanation
Corruption of `storage.assocUnstableUnits` / `storage.assocBestChildren` / `is_free` flags directly feeds the main-chain construction and stability-advancement algorithm (best-parent/best-child selection, freeness). A single light client repeatedly sending `light/dry_run_aa` requests for AAs with existing pending/incoming triggers can desynchronize a full node's in-memory unit graph from its true on-disk state, leading to incorrect determination of unit stability/sequence (`is_free`, best children) on that node — i.e., node disagreement on validity/stability with the rest of the network, and potential downstream miscomputation of AA responses and balances that depend on that graph. This satisfies the "node disagreement on validity or stability" impact bar.

### Likelihood Explanation
`light/dry_run_aa` requires no authentication, no proof-of-work, and no fee beyond a valid trigger object; it is designed to be called freely by light wallets. Triggering the race only requires sending multiple such requests concurrently (or timing one against ordinary unit/AA-trigger traffic the node is already processing), which is trivial for a remote unprivileged peer to do. The intentional absence of a mutex specifically in this function (compared to every sibling function) indicates the developers assumed dry runs are read-only/side-effect-free, but the code path clearly performs live mutation and reversal of shared RAM caches.

### Recommendation
Wrap `dryRunPrimaryAATrigger()`'s body in the same mutex used by real trigger/unit-save paths (e.g. `mutex.lock(['write'])` or `['handleJoint']`) so cache mutation and reversal happen atomically with respect to all other cache writers, mirroring the fix applied upstream (serialize all list/cache mutation under one lock rather than relying on callers to coordinate).

### Proof of Concept
1. Deploy a node with an AA that has pending stable triggers.
2. From a light client (or two colluding light clients), send two overlapping `light/dry_run_aa` requests (or one dry-run request racing a legitimate pending AA trigger) referencing the same AA address, timed so their asynchronous DB callbacks interleave.
3. Observe (or instrument) that `storage.assocBestChildren[parent]` / `storage.assocUnstableUnits` end up with entries pushed by one call and never cleaned by its own `revertResponsesInCaches`, or with `is_free` recomputed incorrectly by `fixIsFreeAfterForgettingUnit`, because a concurrent dry run's `writer.saveJoint`/`forgetUnit` mutated the same structures mid-flight.
4. Show that subsequent stability/main-chain computation on this node yields state inconsistent with an unaffected node.

// parent_units are parent units of the forgotten unit
function fixIsFreeAfterForgettingUnit(parent_units) {
	parent_units.forEach(function(parent_unit){
		if (!assocUnstableUnits[parent_unit]) // the parent is already stable
			return;
		var bHasChildren = false;
		for (var unit in assocUnstableUnits){
			var o = assocUnstableUnits[unit];
			if (o.parent_units.indexOf(parent_unit) >= 0)
				bHasChildren = true;
		}
		if (!bHasChildren)
			assocUnstableUnits[parent_unit].is_free = 1;
	});
}
