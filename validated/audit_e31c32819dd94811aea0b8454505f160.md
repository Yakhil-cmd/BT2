### Title
Unvalidated P2P Staking Info Injection Corrupts Reward Distribution — (`datasync/downloader/queue.go`)

---

### Summary

During fast sync, a malicious peer can inject arbitrary `P2PStakingInfo` values (including inflated `CouncilStakingAmounts`) that are written directly to the node's staking database without any verification against actual on-chain state. Before the Kaia hardfork, `GetStakingInfo` reads from this database first, so the corrupted amounts are used verbatim for reward distribution and validator qualification, causing unauthorized KAIA reward allocation.

---

### Finding Description

The `DeliverStakingInfos` function in `datasync/downloader/queue.go` contains an explicitly empty validation callback:

```go
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
``` [1](#0-0) 

This means any `P2PStakingInfo` delivered by a remote peer during fast sync passes validation unconditionally. The staking info is then stored in the `fetchResult` and committed to the database in `commitFastSyncData` and `commitPivotBlock` with no cross-check against the actual native token balance of the staking contracts:

```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
}
``` [2](#0-1) [3](#0-2) 

The same unverified write occurs in the `SyncStakingInfo` recovery path:

```go
d.stakingModule.PutStakingInfoToDB(stakingInfo.BlockNum, staking.ToStakingInfo(stakingInfo))
``` [4](#0-3) 

The P2P message handler `handleStakingInfoMsg` decodes the peer-supplied payload and forwards it directly to the downloader without any independent verification: [5](#0-4) 

Before the Kaia hardfork, `GetStakingInfo` reads from the database before falling back to computing from state:

```go
if !isKaia {
    if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
        s.stakingInfoCache.Add(sourceNum, si)
        return si, nil
    }
}
``` [6](#0-5) 

The corrupted `StakingAmounts` values are then consumed directly by `assignStakingRewards` and `assignStakingRewardsFlex` to compute each validator's share of block rewards: [7](#0-6) 

And by the validator qualification logic that determines which validators are demoted vs. qualified: [8](#0-7) 

---

### Impact Explanation

**Broken invariant:** `StakingInfo.StakingAmounts[i]` must equal `balance(StakingContracts[i])` at `SourceBlockNum`. The P2P sync path breaks this invariant by accepting peer-supplied amounts without verification.

**Corrupted value:** `StakingAmounts[]` in the persisted `StakingInfo` record — can be set to any `uint64` value by a malicious peer.

**Concrete effects:**
1. **Unauthorized reward distribution** — A malicious validator inflates its own `CouncilStakingAmounts` entry. `assignStakingRewards` distributes staking rewards proportional to `(amount - minStake)`, so an inflated amount causes the attacker to receive a disproportionately large share of KAIA staking rewards at the expense of honest validators.
2. **Invalid validator qualification** — A validator with actual stake below `reward.minimumstake` can be injected with an amount above the threshold, making it appear qualified when it should be demoted, affecting committee selection and consensus integrity.

---

### Likelihood Explanation

- **Trigger:** Any peer a node connects to during fast sync (pre-Kaia hardfork blocks). No special privilege is required beyond being a connectable P2P peer.
- **Scope:** Affects nodes that fast-sync to a chain state before the Kaia hardfork. After the Kaia hardfork, `GetStakingInfo` always recomputes from state and ignores the database, so the corrupted entries have no effect on post-fork blocks.
- **Persistence:** The corrupted `StakingInfo` is written to the key-value database under `"stakingInfo" || Uint64LE(num)` and cached in memory, persisting across restarts until the affected block range is rewound or the Kaia hardfork is crossed. [9](#0-8) 

---

### Recommendation

Replace the no-op `validate` callback in `DeliverStakingInfos` with a check that verifies the delivered `CouncilStakingAmounts[i]` matches the actual native token balance of `CouncilStakingAddrs[i]` at the block identified by `BlockNum`, using the local state database. If the local state for that block is unavailable (e.g., during fast sync before state is downloaded), defer writing the staking info until the state is available and can be verified, or recompute it from state after sync completes rather than trusting the peer-supplied value. [10](#0-9) 

---

### Proof of Concept

**Setup:** A node `V` is fast-syncing to block `N` (before Kaia hardfork). Attacker controls peer `A`.

1. `V` enters fast sync and calls `fetchStakingInfos`, which sends `StakingInfoRequestMsg` to connected peers including `A`. [11](#0-10) 

2. `A` responds with a `StakingInfoMsg` containing a crafted `P2PStakingInfo`:
   ```json
   {
     "blockNum": <source_block>,
     "councilStakingAddrs": ["<attacker_staking_contract>", ...],
     "councilStakingAmounts": [999999999, ...]  // inflated
   }
   ```

3. `V`'s `handleStakingInfoMsg` decodes the message and calls `pm.downloader.DeliverStakingInfos`. [12](#0-11) 

4. `queue.DeliverStakingInfos` runs `validate(i, header)` which unconditionally returns `nil`, accepting the crafted data. [1](#0-0) 

5. `commitFastSyncData` writes the crafted staking info to the database:
   ```
   "stakingInfo" || Uint64LE(source_block) => {StakingAmounts: [999999999, ...]}
   ``` [2](#0-1) 

6. When `V` later calls `GetStakingInfo(N)` for block processing, it reads the corrupted record from the database (database hit, no state recomputation). [6](#0-5) 

7. `assignStakingRewards` uses the inflated `999999999` KAIA amount for the attacker's validator, allocating it a reward share far exceeding its actual stake, draining KAIA from honest validators' reward allocations. [13](#0-12)

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
}

var stakingInfoPrefix = []byte("stakingInfo")

func stakingInfoKey(num uint64) []byte {
	return append(stakingInfoPrefix, common.Int64ToByteLittleEndian(num)...)
}

func ReadStakingInfo(db database.Database, num uint64) *staking.StakingInfo {
	b, err := db.Get(stakingInfoKey(num))
	if err != nil || len(b) == 0 {
		return nil
	}

	var sl staking.StakingInfoLegacy
	if err := json.Unmarshal(b, &sl); err != nil {
		logger.Error("Malformed staking info", "num", num, "err", err)
		return nil
	}
	return sl.ToStakingInfo()
}

func WriteStakingInfo(db database.Database, num uint64, si *staking.StakingInfo) {
	b, err := json.Marshal(si)
	if err != nil {
		logger.Error("Failed to marshal StakingInfo", "num", num, "err", err)
		return
	}

	if err := db.Put(stakingInfoKey(num), b); err != nil {
		logger.Crit("Failed to write StakingInfo", "num", num, "err", err)
	}
}
