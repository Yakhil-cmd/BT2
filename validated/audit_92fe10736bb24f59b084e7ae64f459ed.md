### Title
`ProxyType::NonTransfer` deny-list omits `ForeignAssets`/`PoolAssets` (and other asset-moving calls) on Asset Hub Rococo, letting a restricted proxy transfer the delegator's assets - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`pallet-proxy`'s `InstanceFilter<RuntimeCall>` implementation for `ProxyType` is duplicated, with small variations, across every system-parachain and relay runtime in this monorepo. The `NonTransfer` variant is documented as "Can execute any call that does not transfer funds or assets" and is implemented as a **deny-list** (`!matches!(c, <denied calls>)`), which fails open: any call not explicitly listed is permitted. The Asset Hub Westend copy of this filter was hardened to add `ForeignAssets`, `PoolAssets`, `Scheduler`, `Treasury`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, `Vesting::vested_transfer`, `Indices::transfer`/`force_transfer`, `ConvictionVoting`, `Referenda`, and `Whitelist` to the deny-list (see `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs:826-860`), explicitly noting "a pallet added to the runtime is reachable by a `NonTransfer` proxy unless it is listed here." The sibling Asset Hub Rococo copy of the exact same `ProxyType::NonTransfer` filter was **not** given the same fix and still only denies `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques` (`cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs:605-704`), even though Asset Hub Rococo's runtime configures `ForeignAssetsInstance`/`PoolAssetsInstance` `pallet-assets` instances that transfer value exactly like the `Assets` instance does.

This mirrors the FastChat bug class exactly: a moderation/validation check (`add_text`) was fixed in one handler file (`gradio_block_arena_named.py`) but the same check was never propagated to structurally identical sibling handler files, leaving them exploitable. Here the "check" is the `ProxyType::NonTransfer` deny-list and the "sibling files" are the near-identical `InstanceFilter` implementations copy-pasted across runtimes.

### Finding Description
`pallet-proxy::proxy` (`substrate/frame/proxy/src/lib.rs:248-262`) dispatches an arbitrary `RuntimeCall` supplied by a *proxy delegate* on behalf of the *real* account, gated only by `T::ProxyType::filter(call)` via `Self::do_proxy`. The delegator explicitly chooses `ProxyType::NonTransfer` specifically to prevent the delegate from moving the delegator's funds/assets while still allowing "safe" operations (voting, staking, identity, etc.).

On Asset Hub Rococo:
```rust
ProxyType::NonTransfer => !matches!(
    c,
    RuntimeCall::Balances { .. } |
        RuntimeCall::Assets { .. } |
        RuntimeCall::NftFractionalization { .. } |
        RuntimeCall::Nfts { .. } |
        RuntimeCall::Uniques { .. }
),
``` [1](#0-0) 

This list omits `RuntimeCall::ForeignAssets` and `RuntimeCall::PoolAssets`, which the runtime configures as separate `pallet-assets` instances alongside `TrustBackedAssets` (confirmed present via 9 references to `ForeignAssetsInstance`/`PoolAssetsInstance` in this file). Because the filter is a deny-list, any call to these two pallets — including `transfer`, `transfer_keep_alive`, `force_transfer` — is **admitted** by `ProxyType::NonTransfer::filter`, contradicting the documented invariant ("Can execute any call that does not transfer funds or assets").

Compare Asset Hub Westend's already-hardened equivalent:
```rust
ProxyType::NonTransfer => !matches!(
    c,
    RuntimeCall::Balances { .. } |
        RuntimeCall::Assets { .. } |
        RuntimeCall::ForeignAssets { .. } |
        RuntimeCall::PoolAssets { .. } |
        ...
),
``` [2](#0-1) 

and the corresponding `prdoc` entry documenting exactly this class of "fails-open deny-list" bug being fixed for the `staking-async` parachain runtime: [3](#0-2) 

The `is_superset` relation is also affected transitively: `NonTransfer` is declared a superset of every other proxy type in the lattice (`(ProxyType::NonTransfer, _) => true`), so a `NonTransfer` delegate that can already move `ForeignAssets`/`PoolAssets` can also grant itself any narrower proxy type via `add_proxy`, but that is a secondary amplification, not the root cause.

### Impact Explanation
A user who delegates a `NonTransfer` proxy on Asset Hub Rococo to a partially-trusted account (e.g., a bot, dApp, or automation key) believing that account cannot move their assets is exposed to direct, silent transfer of any `ForeignAssets`/`PoolAssets` balance out of their account. This is a direct violation of the access-control invariant the `NonTransfer` proxy type exists to enforce — an authorization bypass leading to fund/asset theft, matching CWE-670 (incorrect control flow) in the referenced advisory. Severity is Medium/High depending on the value of foreign/pool assets held by Rococo Asset Hub accounts using `NonTransfer` proxies (Rococo is a testnet, which caps real-world impact, but the same duplicated-filter pattern is the root-cause class that was already fixed on the live Westend/Kusama-analog runtime, confirming the bug class is real and was previously exploitable there too).

### Likelihood Explanation
High likelihood of reachability: no privileged role, governance action, or stolen key is required. Any account holder who has granted (or is granted) a `NonTransfer` proxy via the standard, permitted `pallet_proxy::add_proxy` extrinsic is affected. The delegate simply calls the standard `Proxy::proxy` extrinsic with a `ForeignAssets::transfer`/`PoolAssets::transfer` call — this is a normal signed-extrinsic path with no special preconditions beyond an existing proxy relationship, which is the exact intended usage pattern of `pallet-proxy`.

### Recommendation
Add `RuntimeCall::ForeignAssets { .. }` and `RuntimeCall::PoolAssets { .. }` (and audit for other asset-moving pallets configured in this specific runtime) to the `ProxyType::NonTransfer` deny-list in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs`, mirroring the fix already applied in `asset-hub-westend/src/lib.rs`. More durably, replace the deny-list pattern with an allow-list, or add a cross-runtime regression test (as already exists for Asset Hub Westend in `tests/tests.rs`, e.g. `non_transfer_proxy_is_not_a_superset_of_governance` / `proxy_type_superset_relation_matches_call_filters`) to every system-parachain runtime so future pallet additions cannot silently reopen this class of bug.

### Proof of Concept
Reproduction sketch using the existing `pallet-proxy` test harness pattern (`substrate/frame/proxy/src/tests.rs::filtering_works`) adapted to the Asset Hub Rococo runtime's `ProxyType`:
1. Configure a `TestExternalities` for `asset_hub_rococo_runtime` (or use the existing emulated-integration-tests harness for Asset Hub Rococo).
2. Account `ALICE` calls `Proxy::add_proxy(signed(ALICE), BOB, ProxyType::NonTransfer, 0)`.
3. Account `BOB` calls `Proxy::proxy(signed(BOB), ALICE, None, Box::new(RuntimeCall::ForeignAssets(pallet_assets::Call::transfer { id: ..., target: BOB, amount: ALICE_BALANCE })))`.
4. Expected (per documented invariant): `ProxyExecuted { result: Err(CallFiltered) }`.
5. Actual (per code at lines 608-615): `ProxyType::NonTransfer.filter(&call)` returns `true` (not in deny-list) → `ProxyExecuted { result: Ok(()) }` and ALICE's `ForeignAssets`/`PoolAssets` balance moves to BOB.
