### Title
Unauthenticated cross-organization webhook spoofing — signature is verified against the `repository.owner.login` in the payload while handlers act on the independent `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In multi-organization Shipit installations, `WebhooksController#verify_signature` selects which GitHub App config (and thus which `webhook_secret`) to validate the request against using an attacker-controlled JSON field (`repository.owner.login`), while the actual event handlers resolve the target repository/stack using a *different*, equally attacker-controlled field (`repository.full_name`). Because `GitHubApp#verify_webhook_signature` treats a blank `webhook_secret` as automatically valid, an attacker who forges a request against any organization configured *without* a webhook secret can freely choose the `repository.full_name` to point at a stack belonging to a fully-secured organization, causing unauthenticated writes (github sync, review-stack creation/archival) against that other organization's stacks.

### Finding Description
The webhook signature check binds authentication to a value taken from the same untrusted JSON body it is meant to authenticate, and that value is different from the field later used to route the mutation:

```ruby
# app/controllers/shipit/webhooks_controller.rb
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` unconditionally accepts the request when no `webhook_secret` is configured for that organization:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [3](#0-2) 

The `webhook_secret` is explicitly documented and shown as optional in every sample config (`webhook_secret: # nil`), and multi-org configuration is a first-class supported feature (`test/dummy/config/secrets_double_github_app.yml`, `Shipit.github_app_config`). [4](#0-3) [5](#0-4) 

Once `verify_signature` passes (because the *claimed* organization `repository.owner.login` has no secret), the actual handler that performs the mutation resolves its target from a completely separate JSON key, `repository.full_name`:
```ruby
def repository_name
  payload.dig('repository', 'full_name')
end

def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end
``` [6](#0-5) 

Nothing forces `repository.full_name`'s owner segment to equal `repository.owner.login`. This lets an attacker submit a single JSON payload that authenticates as "OrgWithoutSecret" (`repository.owner.login = OrgWithoutSecret`) while acting on "OrgWithSecret/target-repo" (`repository.full_name = OrgWithSecret/target-repo`). `PushHandler` will then trigger `stack.sync_github` for every non-archived stack on the matching branch:
```ruby
def process
  stacks
    .not_archived
    .where(branch:)
    .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [7](#0-6) 

Similarly, `PullRequest::OpenedHandler`/`ClosedHandler` resolve their `repository` and mutate review stacks (`find_or_create!`, `archive!`) purely from `repository.full_name`, independent of the org validated by the signature check. [8](#0-7) [9](#0-8) 

This breaks the binding: `organization authenticated (repository.owner.login, checked against that org's webhook_secret) != repository actually written (repository.full_name, used by handlers)`.

### Impact Explanation
`GithubSyncJob` fetches commits from the real GitHub API and appends them to the stack, and `sync_github` runs on stack creation/branch changes; if the target stack has `continuous_deployment` enabled, ingesting attacker-timed commit metadata (`expected_head_sha`) can influence `trigger_continuous_delivery`/`ContinuousDeliveryJob` and result in an unauthorized deploy trigger for a stack whose organization never issued this webhook. [10](#0-9) [11](#0-10) [12](#0-11) 
Additionally, `PullRequest::ClosedHandler#process` can archive an arbitrary review stack (`review_stack.archive!`) belonging to a different, properly-secured organization purely from an unauthenticated request, matching the "cross-repository writes" impact category. [13](#0-12) 

### Likelihood Explanation
Exploitation requires no credentials, only that the Shipit deployment (a) is configured for multiple GitHub organizations and (b) has at least one organization without a `webhook_secret` set — a configuration explicitly presented as valid/optional in the shipped example secrets files. Given that condition, the attacker sends a single unauthenticated POST to `/webhooks` with a crafted JSON body; no signature needs to be forged at all because verification short-circuits to `true`.

### Recommendation
Bind signature verification and repository resolution to the same trusted value: derive the authenticating organization strictly from the same field(s) used by every handler (`repository.full_name`'s owner segment, not a separately-read `repository.owner.login`), and reject requests where they diverge. Additionally, do not treat a blank `webhook_secret` as an implicit "always verified" bypass across the whole multi-org config — require an explicit secret for every organization that participates in multi-tenant webhook routing, or validate that the resolved target repository's own organization secret was the one used to sign the request.

### Proof of Concept
Preconditions: Shipit configured with two organizations, e.g. `OrgOpen` (no `webhook_secret`) and `OrgSecure` (a real `webhook_secret`), each owning at least one active stack, as demonstrated in `test/dummy/config/secrets_double_github_app.yml`.

```http
POST /webhooks HTTP/1.1
X-Github-Event: push
Content-Type: application/json

{
  "ref": "refs/heads/master",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "owner": { "login": "OrgOpen" },
    "full_name": "OrgSecure/target-repo"
  }
}
```
1. `WebhooksController#repository_owner` returns `"OrgOpen"` from `repository.owner.login`.
2. `Shipit.github(organization: "OrgOpen").verify_webhook_signature(...)` returns `true` unconditionally because `OrgOpen`'s `webhook_secret` is blank (no `X-Hub-Signature` header is even required).
3. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("OrgSecure/target-repo")` and calls `stack.sync_github(expected_head_sha: "deadbeef...")` for every matching, non-archived stack — a mutation performed against `OrgSecure`'s stack without ever validating a signature tied to `OrgSecure`'s secret.

      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
