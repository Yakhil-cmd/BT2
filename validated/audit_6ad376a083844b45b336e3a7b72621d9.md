### Title
Missing Zero-Value Guard on `kip71.gastarget` Governance Parameter Causes Division-by-Zero Panic in `NextMagmaBlockBaseFee`, Halting the Chain — (`params/kip71_config.go`)

### Summary

The `kip71.gastarget` governance parameter accepts `0` as a valid value because its `FormatChecker` is `noopFormatChecker`. When `GasTarget == 0` is ratified and the next block has any non-zero gas usage, `NextMagmaBlockBaseFee` performs an integer division by zero (`big.Int.Div(..., 0)`), causing a Go runtime panic. This panic propagates through `VerifyMagmaHeader` → `validateHeader` and through `commitNewWork`, crashing every node that attempts to validate or produce a block, resulting in a permanent chain halt.

### Finding Description

**Root cause — missing format check in `kaiax/gov/param.go`:**

`Kip71GasTarget` is registered with `noopFormatChecker`, which unconditionally returns `true`:

```go
// kaiax/gov/param.go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // ← accepts any uint64, including 0
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` has an explicit non-zero check:

```go
Kip71BaseFeeDenominator: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // ← explicit guard
    },
    ...
},
``` [2](#0-1) 

The `checkConsistency` function in `VerifyVote` also returns `nil` for `Kip71GasTarget` with no additional constraint: [3](#0-2) 

**Division-by-zero in `NextMagmaBlockBaseFee`:**

`NextMagmaBlockBaseFee` explicitly guards `BaseFeeDenominator == 0` (with a comment "To avoid panic") but has no equivalent guard for `GasTarget == 0`:

```go
// params/kip71_config.go
var baseFeeDenominator *big.Int
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
gasTarget := kc.GasTarget   // ← no zero guard
...
// When parentGasUsed > 0 and gasTarget == 0:
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // ← big.Int.Div panics on zero divisor
``` [4](#0-3) 

The same unguarded division also appears in the `else` branch: [5](#0-4) 

**Panic propagation paths:**

`NextMagmaBlockBaseFee` is called from two critical paths:

1. **Block validation** — `validateHeader` calls `VerifyMagmaHeader` → `NextMagmaBlockBaseFee` for every incoming block: [6](#0-5) 

2. **Block production** — `commitNewWork` calls `NextMagmaBlockBaseFee` before building each new block: [7](#0-6) 

Both paths have no `recover()` wrapper, so the panic crashes the goroutine and the node process.

### Impact Explanation

Once `kip71.gastarget = 0` is ratified and takes effect at `(k+1)*epoch`, every node on the network panics when processing the first block that has any non-zero gas usage. Since virtually every real block includes at least one transaction, this causes a **permanent chain halt**: no node can validate or produce a block, and the chain cannot advance. All KAIA transfers, reward distributions, bridge settlements, and governance operations are frozen indefinitely.

### Likelihood Explanation

In `none` governance mode, any Governance Council member can cast the vote. In `single` mode, the single governing node can do so. The vote passes all existing validation layers (`FormatChecker`, `checkConsistency`, `VerifyVote`) without rejection. The effect is delayed by one epoch (~604,800 blocks on Mainnet, ~1 week), giving no automatic on-chain warning. The asymmetry with `BaseFeeDenominator` — which has an explicit zero guard both in the `FormatChecker` and in `NextMagmaBlockBaseFee` — shows the developer was aware of the risk class but did not apply the same protection to `GasTarget`.

### Recommendation

Apply the same two-layer defense used for `BaseFeeDenominator`:

1. **In `kaiax/gov/param.go`**, replace `noopFormatChecker` for `Kip71GasTarget` with a checker that rejects zero:
   ```go
   FormatChecker: func(cv any) bool {
       v, ok := cv.(uint64)
       return ok && v > 0
   },
   ```

2. **In `params/kip71_config.go`**, add a defensive guard inside `NextMagmaBlockBaseFee` analogous to the existing `BaseFeeDenominator` guard:
   ```go
   if kc.GasTarget == 0 {
       // To avoid panic, treat as lowerBound (no adjustment)
       return makeEvenByFloor(parentBaseFee)
   }
   gasTarget := kc.GasTarget
   ```

### Proof of Concept

1. In `none` governance mode, any GC member calls `governance_vote("kip71.gastarget", 0)`.
2. The vote is inscribed in `header.Vote`; `VerifyVote` passes (voter is proposer, `noopFormatChecker` accepts `0`, `checkConsistency` returns `nil`).
3. At the next epoch block the vote is ratified; `header.Governance` contains `{"kip71.gastarget": 0}`.
4. Starting from `(k+1)*epoch`, `GetParamSet(blockNum).GasTarget == 0`.
5. The next block with `parentGasUsed > 0` triggers `validateHeader` → `VerifyMagmaHeader` → `NextMagmaBlockBaseFee`:
   - `parentGasUsed > gasTarget` (0) → enters the `else if` branch
   - `x.Div(x, new(big.Int).SetUint64(0))` → **Go runtime panic: integer divide by zero**
6. Every node crashes. The chain halts permanently.
