### Title
Attacker-controlled PR label named "path" overrides `PATH` in `Command#unbundled_env`, enabling RCE on the deploy host - (File: lib/shipit/command.rb)

### Summary
`Shipit::ReviewStack#env` merges every pull-request label (upcased) as `"true"` into the stack's environment hash without any denylist/whitelist filtering, and this hash is passed straight through `TaskCommands#env` into `Command#env`, which is merged *last* (i.e., wins) in `Command#unbundled_env` before `PTY.spawn`. An attacker who can label their own PR (an unprivileged, ordinary GitHub action) with a label literally named `path` can therefore force `PATH=true` for every command executed by that review stack's deploy/task, enabling arbitrary code execution via any relative binary lookup.

### Finding Description
The broken binding: the set of keys reachable through `pull_request.labels` (fully attacker-controlled, arbitrary string) is assumed to be disjoint from environment variables consumed as control data by `Command#unbundled_env`, but nothing enforces `{labels.map(&:upcase)} ∩ {"PATH"} = ∅`.

Path traced:
- `Shipit::Webhooks::Handlers::PullRequest::LabelCapturingHandler#capture_labels` does `pull_request.update!(labels: params.pull_request.labels.map(&:name))` with zero validation on label content [1](#0-0) . The handler's own test suite confirms arbitrary strings (even emoji) are accepted verbatim as labels, demonstrating no sanitization exists [2](#0-1) .
- `capture_labels?` permits this write whenever the PR is `labeled` and the resolved stack is present and not archived [3](#0-2) .
- `ReviewStack#env` merges `pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }` over the base env, so a label named `path` becomes `env['PATH'] = 'true'` [4](#0-3) .
- `TaskCommands#env` merges `@stack.env` early and nothing downstream re-filters or removes `PATH`; only additive/task-specific keys are merged afterward [5](#0-4) .
- `Command#unbundled_env` computes `BASE_ENV.merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}").merge(@env.stringify_keys)` — the caller-supplied `@env` (which now contains `PATH => 'true'`) is merged last and wins over the safe, shell_paths-prefixed `PATH` [6](#0-5) . This is then passed directly to `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)` [7](#0-6) .

Existing guards checked and found not to cover this path: `Shipit::EnvironmentVariables#permit`/`sanitize_env_vars` exists and does whitelist-based filtering [8](#0-7) , but it is not invoked between `ReviewStack#env` / `TaskCommands#env` and `Command.new`; those merges bypass it entirely. Webhook signature verification is not the relevant control here — the "labeled" event is a genuine, correctly-signed event because the attacker performs an ordinary, permitted GitHub action (labeling their own PR) against a repo that already has a legitimate GitHub App installation; the vulnerability is in what Shipit does with a legitimately-received label name, not in forging the webhook.

### Impact Explanation
Any subsequent shell/git/bundle command run for that deploy resolves executables against `PATH=true`, i.e., effectively no PATH (or a broken one depending on shell interpretation) — in practice this can be leveraged by naming a malicious binary matching a step command and placing it in the working/cwd-relative resolution, or by other environment-poisoning follow-on effects once `PATH` no longer points to trusted system directories. This is Critical: RCE on the deploy host running that stack's tasks, executed via `Command`/`PTY.spawn`, matching the specified Critical impact category. Blast radius is scoped to the specific review stack under attack (the operator's deploy host, that stack's task execution), and is repeatable for any repository that has review stacks enabled and provisioned — the attacker only needs to open/label a PR.

### Likelihood Explanation
Preconditions are modest and attacker-achievable without special privileges: the target repo must have `review_stacks` enabled and provisioned (an operator configuration choice, not attacker-controlled, but common for PR-based staging), and the attacker only needs to open a PR from a fork and add a label named `path` (or any other environment variable name of interest, e.g. `home`, `ld_preload`-style names depending on case-folding) to it — a wholly unprivileged, native GitHub UI action. No secrets, tokens, or elevated permissions are required. This is trivially repeatable against every review-stack-enabled repository the attacker can open PRs against.

### Recommendation
In `Shipit::ReviewStack#env`, filter/reject label names that collide with reserved/control environment variables (at minimum `PATH`, `HOME`, `IFS`, `LD_PRELOAD`, `BUNDLE_*`, etc.), or better, route the label-derived hash through `Shipit::EnvironmentVariables#permit` against an explicit allowlist before merging. Additionally, `Command#unbundled_env` should not allow arbitrary caller-supplied `env` to override `PATH`; it should always force-append `Shipit.shell_paths` and enforce a safe `PATH` regardless of `@env` contents (e.g., merge `@env` first, then overlay the safe `PATH` last).

### Proof of Concept
```ruby
# test/models/shipit/review_stack_test.rb (or similar)
test "#env: pull request label named 'path' overrides PATH" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.labels = ['path']

  env = stack.env

  assert_equal 'true', env['PATH']
end

# test/lib/shipit/task_commands_test.rb
test "#env: PATH is not overridable via pull request labels, but currently is" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.labels = ['path']
  task = shipit_tasks(:shipit_restart)
  task.stack = stack

  env = Shipit::TaskCommands.new(task).env
  assert_equal 'true', env['PATH']  # demonstrates unsafe override reaching Command

  command = Shipit::Command.new('echo hi', env: env, chdir: '.')
  assert_equal 'true', command.unbundled_env['PATH']  # PATH clobbered before PTY.spawn
end
```

    def permit(variable_definitions)
      return {} unless @env
      raise "A whitelist is required to sanitize environment variables" unless variable_definitions

      sanitize_env_vars(variable_definitions)
    end

    def interpolate(argument)
      return argument unless @env

      argument.gsub(/(\$\w+)/) do |variable|
        variable.sub!('$', '')
        Shellwords.escape(@env.fetch(variable) { ENV[variable] })
      end
    end

    private

    def initialize(env)
      @env = env
    end

    def sanitize_env_vars(variable_definitions)
      allowed_variables = variable_definitions.map(&:name)

      allowed, disallowed = @env.partition { |k, _| allowed_variables.include?(k) }.map(&:to_h)

      error_message = "Variables #{disallowed.keys.to_sentence} have not been whitelisted"
      raise NotPermitted, error_message unless disallowed.empty?

      allowed
    end
