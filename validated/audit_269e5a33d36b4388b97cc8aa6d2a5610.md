### Title
Reopening a PR overrides a maintainer's manual `Stack#archive!` decision, forcing re-provisioning without re-approval - ([File: app/models/shipit/webhooks/handlers/pull_request/reopened_handler.rb])

### Summary
`ReopenedHandler#respond_to_pull_request_reopened?` decides whether to unarchive a review stack purely from repository-wide `provisioning_behavior`/label state, with no check for *why* or *by whom* the stack was archived. Because `Stack#archive!`/`#unarchive!` store no distinction between an automatic (label-driven) archival and a maintainer's manual security archival (both just set/clear `archived_since`, `lock_reason`, `lock_author`), a PR author can close and reopen their own already-flagged PR to force `ReviewStackAdapter#unarchive!` to re-enqueue provisioning (`Shipit::ReviewStackProvisioningQueue.add(stack)`), undoing the maintainer's decision.

### Finding Description
The intended binding is: *the state a maintainer set via `Stack#archive!(current_user)` in `StacksController#update_archived`* == *the state respected by any subsequent automated re-provisioning trigger*. This binding is broken.

- `Stack#archive!`/`#unarchive!` are generic and reason-agnostic: [1](#0-0) . There is no `archived_reason`/`archived_by_maintainer` flag distinguishing a manual security archive from an automated one.
- A maintainer can manually archive a stack through `StacksController#update_archived` using `current_user` [2](#0-1) .
- `ReopenedHandler#process` calls `stack.unarchive!` whenever `respond_to_pull_request_reopened?` is true, and that predicate only inspects `params.action == "reopened"` plus `repository.review_stacks_enabled`/`provisioning_behavior_*`/label presence — nothing about the stack's own archival history or reason: [3](#0-2) .
- `ReviewStackAdapter#unarchive!` unconditionally re-queues provisioning for any archived stack matching the PR's environment: [4](#0-3) .

**Attacker's exact action**: as the author of an open-source fork PR (own branch, own PR, no repo write access, no Shipit account/session/token needed), close the PR and reopen it via the standard GitHub UI/API — actions any PR author can perform on their own PR. GitHub delivers a genuine, correctly-signed `pull_request` `reopened` webhook to `POST /webhooks`. `WebhooksController#verify_signature` passes because the event is a real GitHub-signed event, not a forged one [5](#0-4) . `Shipit::Webhooks.for_event` routes it to `ReopenedHandler`, which, if the repository's global provisioning behavior is `allow_all` (or `allow_with_label`/`prevent_with_label` and the attacker's own PR label state satisfies it — labels on the attacker's own PR are also attacker-controlled if they have triage rights, or already satisfied), calls `stack.unarchive!` and re-queues provisioning, regardless of the maintainer's prior manual archive.

Existing guards do not stop this: `verify_signature` only authenticates that GitHub sent the event, not that the event content should be trusted to override a maintainer decision; `ExplicitParameters` only validates payload shape; there is no re-approval gate, no check of `stack.archived_since`/reason, and no distinction between "archived because label removed" vs "archived because a maintainer flagged malicious content."

### Impact Explanation
Re-provisioning re-runs the deploy pipeline (`Shipit::ReviewStackProvisioningQueue#provision` → `stack.provision` → provisioner/task execution reading `cached_deploy_spec`/`shipit.yml` from the PR's own branch) against content the attacker fully controls and that a maintainer had already deemed malicious enough to archive. Since review-stack provisioning ultimately executes repository-defined commands (Shipit's `Command`/`PTY.spawn` task execution pipeline) using the attacker's own branch content, this is an unauthorized re-execution of attacker-controlled code on the deploy host for that repository/stack, bypassing the maintainer's explicit block. This is repeatable for every close/reopen cycle and for any repository with review stacks enabled and a permissive/label-satisfied `provisioning_behavior`.

### Likelihood Explanation
Preconditions: `repository.review_stacks_enabled` is true and `provisioning_behavior` is `allow_all`, or `allow_with_label`/`prevent_with_label` with the label state the attacker's own PR already has (labels on one's own PR can often be self-applied or already match). The attacker needs only the standard, unauthenticated-to-Shipit ability to close/reopen their own PR on GitHub — no Shipit credentials, no GitHub App keys, no team membership. This is low-cost and fully repeatable.

### Recommendation
Track why/by whom a stack was archived (e.g., an `archived_reason`/`archived_by` distinguishing "manual/maintainer" vs "automated/label-driven" archival), and have `ReopenedHandler`/`ReviewStackAdapter#unarchive!` refuse to auto-unarchive stacks that were manually archived by a maintainer, requiring an explicit maintainer action (via `StacksController#update_archived`) to re-enable provisioning in that case.

### Proof of Concept
Minitest plan (extending `test/models/shipit/webhooks/handlers/pull_request/reopened_handler_test.rb` patterns):
1. Create a stack, then simulate a maintainer's manual archive: `stack.archive!(maintainer_user)` (as done via `StacksController#update_archived`), analogous to `create_archived_stack` helpers already in the test suite.
2. Configure `repository.provisioning_behavior = :allow_all`.
3. Assert precondition: `stack.archived? == true` and `stack.lock_author == maintainer_user`.
4. Post a `pull_request` `reopened` payload for the same PR number/head sha via `ReopenedHandler.new(payload_parsed(:pull_request_reopened)).process`.
5. Assert broken binding: `stack.reload.archived? == false` and `assert_pending_provision(stack)` (i.e., `Shipit::ReviewStackProvisioningQueue` received `add(stack)`), with no re-approval step and no check of `lock_author`/reason — demonstrating the maintainer's archival decision was silently overridden by the PR author's own reopen action.

          def process
            return unless respond_to_pull_request_reopened?

            stack.unarchive!
          end

          private

          def repository
            @repository ||=
              Shipit::Repository.from_github_repo_name(params.repository.full_name) ||
              Shipit::NullRepository.new
          end

          def stack
            @stack ||=
              Shipit::Webhooks::Handlers::PullRequest::ReviewStackAdapter
              .new(params, scope: repository.review_stacks)
          end

          def pull_request
            params.pull_request
          end

          def respond_to_pull_request_reopened?
            params.action == "reopened" &&
              unarchive?
          end

          def unarchive?
            repository.review_stacks_enabled &&
              repository.provisioning_behavior_allow_all? ||
              (repository.provisioning_behavior_allow_with_label? && pull_request_has_provisioning_label?) ||
              (repository.provisioning_behavior_prevent_with_label? && !pull_request_has_provisioning_label?)
          end
