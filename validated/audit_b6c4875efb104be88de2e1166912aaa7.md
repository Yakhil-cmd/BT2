**Rationale:** The LORIS CVE describes an authenticated web-application user supplying a path parameter to an HTTP endpoint that the server uses to read arbitrary files from the local filesystem (a classic server-side path-traversal in a request handler). Mapping this bug class onto Polkadot SDK requires a real, attacker-reachable entry point (signed extrinsic, XCM message, permitted contract call, or unauthenticated-but-exposed RPC) where user-supplied data is used as an OS filesystem path to read node-local files.

Across the areas searched, every instance of filesystem path handling in the codebase falls into one of these categories, none of which match the required threat model:
- CLI subcommands (`inspect-node-key`, `import-blocks`, keystore params, chain-spec loading) that take paths from trusted node-operator command-line arguments [1](#0-0) [2](#0-1) .
- Build-time and test tooling (fuzzer harness, benchmark CLI, sysinfo reader) which never process untrusted chain data [3](#0-2) [4](#0-3) .
- Node-local database/version migration paths derived from operator-configured database directories, not remote input [5](#0-4) .
- The offchain worker/local-storage APIs, which operate on arbitrary key-value pairs in an internal RocksDB column (not OS file paths) and are explicitly RPC calls marked "unsafe," rejected unless the node operator opts into exposing unsafe RPC methods [6](#0-5) [7](#0-6) .

There is no runtime extrinsic, pallet call, or XCM instruction in FRAME/Cumulus/XCM that accepts a user-supplied string and passes it into `std::fs`/`PathBuf` file-read operations reachable by an ordinary signed transaction or unprivileged authenticated caller — extrinsics operate on SCALE-encoded runtime storage keys, not OS filesystem paths, so the "path traversal reads server config with hardcoded credentials" bug class has no equivalent attack surface in this codebase's actual security boundary (a remote node exposes no filesystem to signed-extrinsic senders).

/// Reads current database version from the file at given path.
/// If the file does not exist returns `None`, otherwise the version stored in the file.
fn get_db_version(path: &Path) -> Result<Option<Version>, Error> {
	match fs::read_to_string(version_file_path(path)) {
		Err(ref err) if err.kind() == io::ErrorKind::NotFound => Ok(None),
		Err(err) => Err(err.into()),
		Ok(content) => u32::from_str(&content)
			.map(|v| Some(v))
			.map_err(|_| Error::CorruptedVersionFile),
	}
}

/// Writes current database version to the file.
/// Creates a new file if the version file does not exist yet.
fn update_version(path: &Path, new_version: Version) -> Result<(), Error> {
	fs::create_dir_all(path)?;
	fs::write(version_file_path(path), new_version.to_string()).map_err(Into::into)
}

/// Returns the version file path.
fn version_file_path(path: &Path) -> PathBuf {
	let mut file_path = path.to_owned();
	file_path.push(VERSION_FILE_NAME);
	file_path
}
