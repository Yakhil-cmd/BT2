### Title
Reusable Bitcoin Lockup Proofs Let a Staker Double-Count L1-Locked Sats Across Multiple Bond Registrations - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`register-for-bond`'s L1 lockup path credits a staker with `amount-sats` of stake weight based solely on proving that *a* Bitcoin transaction output pays into the correct timelock script. The dedup logic that guards against reusing a lockup output only operates on the list supplied in a *single* call (`seen-outpoints`), and is discarded once that call returns. There is no contract-level persistent record of which Bitcoin outpoints have already been consumed as bond collateral, so the same still-unspent, still-locked Bitcoin UTXO can be re-presented as proof in a later, unrelated `register-for-bond` call to mint fresh `sats-total` credit without any additional BTC ever being locked — breaking the equality "sats credited by an L1 proof == sats actually (newly) locked on Bitcoin."

### Finding Description
`verify-l1-lockups` seeds the fold accumulator with an empty, call-scoped `seen-outpoints: (list)` and passes it through `validate-l1-lockup`, which only asserts `(is-none (index-of? seen-outpoints outpoint))` against that same call-scoped list: [1](#0-0) [2](#0-1) 

This dedup list is rebuilt from scratch on every invocation of `register-for-bond` — it never touches a persisted map keyed by `(txid, output-index)`. The rest of `validate-l1-lockup` verifies that the output's script matches the staker-committed timelock script, that the block header/merkle proof are valid, and that the claimed `amount` matches the actual Bitcoin output amount: [3](#0-2) 

All of these checks are about the *authenticity* of the proof, not about whether that specific UTXO has already been used to back a bond before. Because a time-locked Bitcoin UTXO stays unspent (by construction) until `unlock-burn-height` matures, its Bitcoin-chain proof remains valid and reproducible for as long as the lock exists. If a staker's bond membership involving that UTXO is ever cleared (e.g., voluntary exit, or any path that removes `protocol-bond-memberships` for that staker) before the underlying UTXO is actually spent on Bitcoin, the staker can call `register-for-bond` again — for the same or a different `bond-index` — and re-submit the identical `tx`/`output-index`/`header` proof. `verify-l1-lockups` will re-validate it successfully and return the same `sats-total`, crediting a brand-new bond membership and a brand-new `staker-shares-staked-for-cycle` entry, entirely decoupled from any new Bitcoin lockup.

Contrast this with the sBTC path, where `roll-sbtc` explicitly nets custodied sBTC balances and moves real tokens on rollover/exit so that `total-sbtc-staked` always corresponds to actual custodied tokens: [4](#0-3) 

The L1 path has no analogous mechanism to "release" or invalidate a consumed lockup proof — it relies entirely on the Bitcoin UTXO being provably spent, which the contract never checks.

### Impact Explanation
This breaks the equality that `amount-sats` recorded in a bond membership must correspond 1:1 to sats actually newly locked on the Bitcoin chain. A staker can obtain reward-eligible stake weight (`staker-shares-staked-for-cycle`) and pass allowlist/bond-collateral requirements multiple times from a single real BTC lockup, i.e., double-counting a commitment. This is analogous to the fee-on-transfer bug class in the external report: the protocol trusts a claimed/observed transfer/lock event to represent a fresh, exclusive backing asset, but the actual underlying value backing that credit is not consumed or marked used, so it can be presented again. Per the rules, double-counting a commitment/reward is Critical severity.

### Likelihood Explanation
Requires only an unprivileged staker (no admin/bond-admin/signer key needed) to control an allowlisted BTC lockup script, exit or roll out of an existing bond membership, and resubmit the same still-valid, unspent lockup proof to `register-for-bond` again. No cryptographic forgery is needed — the same real Bitcoin transaction/output/header/merkle-proof tuple is reused verbatim.

### Recommendation
Persist a durable, contract-level map of consumed L1 outpoints (e.g., `used-l1-outpoints: {txid: (buff 32), output-index: uint} -> bool`) that is checked and updated in `validate-l1-lockup` independent of any single call's `seen-outpoints` list, so that once an outpoint has backed a bond membership it can never be credited again for that or any other bond, until it is provably spent (or an explicit, single, tracked "release" event is recorded on-chain).

### Proof of Concept
1. Staker Alice locks `N` sats into the canonical timelock P2WSH derived from `construct-lockup-output-script(alice, U, ...)`, with `U` far in the future.
2. Alice calls `register-for-bond` for bond 0 with the L1 proof of this UTXO; `verify-l1-lockups` validates it and credits `sats-total = N`, creating `protocol-bond-memberships[alice]` with `amount-sats: N`.
3. Alice exits/rolls out of bond 0 (clearing her membership) while her BTC lockup remains unspent on Bitcoin (since `U` hasn't matured yet).
4. Alice calls `register-for-bond` again for a fresh bond index, submitting the *exact same* `tx`, `output-index`, and `header` as before. `verify-l1-lockups`/`validate-l1-lockup` re-validate successfully (script, merkle proof, and amount all still match; `seen-outpoints` is freshly empty for this new call) and credit `sats-total = N` again — a second, independent bond credit backed by zero new Bitcoin locked.
