### Title
Cross-organization webhook forgery via mismatched organization-selection and repository-selection fields - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate a signature against using `repository_owner`, which is read from the payload field `repository.owner.login` (falling back to `organization.login`). But the handlers that actually act on the payload (`Shipit::Webhooks::Handlers::Handler#stacks`/`#repository_name`) select the target `Repository`/`Stack` using a *different* payload field: `repository.full_name`. Signature verification never binds these two fields together, so the "organization whose secret authenticated the request" and the "repository that gets written to" are two independently attacker-controlled strings inside the same signed JSON body.

### Finding Description
`WebhooksController#verify_signature` does: [1](#0-0) [2](#0-1) 

It picks the app config with `Shipit.github(organization: repository_owner)` and verifies `request.raw_post` against that organization's `webhook_secret`: [3](#0-2) 

In the multi-org configuration mode (documented and tested in `docs/setup.md` and `test/dummy/config/secrets_double_github_app.yml`), each GitHub organization has its own, independent `webhook_secret`: [4](#0-3) [5](#0-4) 

Once the signature is accepted, `create` dispatches the entire parsed body to handlers: [6](#0-5) 

Every handler resolves the target stacks via `Handler#stacks`/`#repository_name`, which reads `repository.full_name` — a completely separate field from the one used to pick the verifying organization: [7](#0-6) [8](#0-7) 

Because `verify_webhook_signature` only proves that *some* configured organization's secret was used to sign the exact bytes of `raw_post`, and the organization used for that lookup (`repository.owner.login`) is not cross-checked against the repository being acted upon (`repository.full_name`), an operator of Organization B (who legitimately possesses Organization B's GitHub App `webhook_secret`, e.g. by owning that GitHub App installation) can craft and sign a payload where:
- `repository.owner.login` = `"OrgB"` (selects OrgB's `webhook_secret` for signature verification, which the attacker controls/knows), and
- `repository.full_name` = `"OrgA/production-app"` (an unrelated, victim organization's repository already registered as a Shipit `Repository`/`Stack`).

The signature check passes (it only validates the byte-for-byte body against OrgB's secret), yet `PushHandler#process`, `StatusHandler`, `CheckSuiteHandler`, etc. all resolve and mutate `OrgA`'s stacks because they trust `repository.full_name` from the same unauthenticated-for-that-purpose body.

This breaks the binding: `organization authenticated by signature == organization owning the repository acted upon`, which is explicitly one of the trust equalities this scan is meant to validate.

### Impact Explanation
This lets an attacker who only controls one configured GitHub organization's webhook secret forge webhook events (`push`, `status`, `check_suite`, `pull_request`) against a completely different organization's Shipit stacks:
- A forged `push` event triggers `stack.sync_github(expected_head_sha:)` on the victim's stack via `GithubSyncJob`, which can trigger Continuous Deployment if enabled for that stack — an unauthorized deploy triggered cross-organization.
- A forged `status` event can inject fake commit statuses (`Status` records) for the victim's commits, which are consumed by the merge-queue / CI gating logic (`ci.require`), enabling bypass of required CI checks and an unauthorized merge/deploy.
- `check_suite` forgery similarly manipulates check-run state used by deploy/merge gating.

This matches the Critical/High impact bar ("an unauthorized deploy, rollback or merge") defined for this exercise, since it crosses an organizational trust boundary without any GitHub-side authorization on the target repo.

### Likelihood Explanation
Exploitability requires the attacker to control a legitimately configured GitHub organization's App/webhook secret in a multi-org Shipit deployment (a normal, low-privilege position for an org that has simply been onboarded to a shared Shipit instance), plus knowledge that another organization's repository/stack is registered on the same instance (repository full names are often guessable/public). No access to the target org, no Shipit account, and no GITHUB_TOKEN/`api_clients_secret` is required — only the ability to send an HTTP POST with a body signed by one's own org's webhook secret. This is realistic in shared/multi-tenant Shipit deployments, which the project explicitly documents and supports.

### Recommendation
Bind the two fields together: after determining `repository_owner` for secret selection, validate that `payload.dig('repository','full_name')` (and `organization.login` fallback) is prefixed by/matches that same owner before dispatching to handlers, or reject the event if `Repository.from_github_repo_name(repository_name)`'s owner differs from the verified `repository_owner`. Ideally, resolve the target `Repository` first, verify the signature using that repository's owning organization's secret exclusively, and reject any mismatch between `repository.owner.login`/`organization.login` and the owner segment of `repository.full_name`.

### Proof of Concept
1. Deploy Shipit with two GitHub orgs configured, `OrgA` and `OrgB`, each with a distinct `webhook_secret` (as in `test/dummy/config/secrets_double_github_app.yml`).
2. `OrgA/production-app` is registered in Shipit as a `Repository`/`Stack` with continuous deployment or CI status gating enabled.
3. As an operator who only controls `OrgB`'s webhook secret, build a JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-existing-sha-in-OrgA-repo>",
  "repository": {
    "full_name": "OrgA/production-app",
    "owner": { "login": "OrgB" }
  }
}
```
4. Compute `X-Hub-Signature: sha1=<hmac-sha1(OrgB_webhook_secret, body)>`.
5. POST to `/github/webhooks` with `X-Github-Event: push`.
6. `verify_signature` calls `Shipit.github(organization: "OrgB")` (from `repository.owner.login`) and validates successfully against `OrgB`'s secret.
7. `PushHandler#process` resolves `stacks` via `repository.full_name` = `"OrgA/production-app"`, and triggers `sync_github`/deploy on `OrgA`'s stack — an unauthorized cross-organization action performed by an entity that never authenticated as `OrgA`. [9](#0-8) [10](#0-9)

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event

    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class Handler
        class << self
          attr_reader :param_parser

          def params(&block)
            @param_parser = ExplicitParameters::Parameters.define(&block)
          end
        end

        def self.call(params)
          new(params).process
        end

        attr_reader :params, :payload

        def initialize(payload)
          @payload = payload
          @params = self.class.param_parser.parse!(payload)
        end

        def process
          raise NotImplementedError
        end

        private

        def stacks
          @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
        end

        def repository_name
          payload.dig('repository', 'full_name')
        end
      end
    end
  end
end
