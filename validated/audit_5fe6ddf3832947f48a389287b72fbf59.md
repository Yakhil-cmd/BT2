### Title
CCMenu API leaks build/deploy status of any stack because it bypasses the `ApiClient#stack_id` scope binding - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Api::CCMenuController` overrides the base `stack` resolver to look up `Stack.from_param!(params[:stack_id])` directly instead of using `Api::BaseController#stack`, which is scoped through `stacks` (`current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all`). This breaks the binding: `ApiClient.stack_id` (the stack a token is authorized for) ≠ the stack `CCMenuController#show` actually touches. Any client holding a `read:stack`-scoped `ApiClient` token for stack A can pass a different `stack_id` in the URL and read build/deploy status for stack B.

### Finding Description
`Api::BaseController` enforces per-client stack scoping centrally: [1](#0-0) 

Every other API controller (`DeploysController`, `RollbacksController`, `TasksController`, `LocksController`, `OutputsController`, `CommitsController`, `ReleaseStatusesController`, `MergeRequestsController`, `HooksController`) relies on this inherited `stack`/`stacks` helper, so a scoped token (e.g. an `ApiClient` with `stack_id` set to stack A) can never resolve `params[:stack_id]` to any stack other than A - `stacks.from_param!` raises if the id doesn't match the scope.

`CCMenuController`, however, redefines `stack` to bypass that scope entirely and also swaps the authentication mechanism to accept the token via a URL query parameter instead of `Authorization: Basic`: [2](#0-1) 

Specifically:
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end

def authenticate_api_client
  @current_api_client = ApiClient.authenticate(params[:token])
  super unless @current_api_client
end
```
`Stack.from_param!` performs an unscoped, global lookup (no relation to `current_api_client`), so `require_permission :read, :stack` only checks that `"read:stack"` is present in the client's `permissions` array - it never checks whether the requested `stack_id` matches `current_api_client.stack_id`: [3](#0-2) 

This is the same class of bug as the reported `Balancer.sol` issue: one field (the destination the caller is authorized to interact with — `dstOft`/`stack_id`) is verified/bound at authorization time, but a *different, attacker-controlled* field (the packed swap address / the `stack_id` URL param) is what the code actually acts on at execution time. Here, the "authorized" scope (`ApiClient#stack_id`) and the "touched" resource (`params[:stack_id]` resolved unscoped) diverge.

Concretely: `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator:, name: 'CCMenu Client')` in `CCMenuUrlController` intentionally creates unscoped tokens today, but any stack-scoped `read:stack` `ApiClient` (an entirely supported/documented configuration, see the `here_come_the_walrus` fixture scoped to a single stack) is equally exploitable through this endpoint, and the token is exposed in a URL query string (further widening exposure via logs/referrers) rather than requiring `Authorization: Basic`.

### Impact Explanation
An attacker who has obtained (or been issued) a stack-scoped, `read:stack`-only `ApiClient` token — the least-privileged read-only credential type in the system, intended to expose CI/build status for a single stack via CCMenu/CCTray feeds — can use that token to read build status (`lastBuildStatus`, `activity`, `lastBuildTime`, `lastBuildLabel`, `webUrl`, stack name) for **any** stack in the Shipit instance, including private/internal stacks the token was never meant to see. This is an unauthorized read of stack state, matching the "High" impact category: unauthenticated/unauthorized read of stack state via a credential-scope violation.

### Likelihood Explanation
Likely for any deployment issuing scoped read-only API clients (a documented, first-class feature — `stack_id` scoping exists specifically to restrict tokens to one stack). Exploitation requires no privileged access beyond possessing any single stack-scoped `read:stack` token (which by design is meant to be low-privilege and is even distributed embedded in a plain URL by `CCMenuUrlController`). The attacker only needs to change the `stack_id` query/path parameter — no cryptography, no secret, no signature to forge.

### Recommendation
Remove the `stack` override in `Api::CCMenuController` and use the inherited, scoped `Api::BaseController#stack`/`stacks` resolution (i.e., `stacks.from_param!(params[:stack_id])`) so client `stack_id` scoping is enforced consistently across all API controllers, exactly as `Balancer.sol`'s fix was to make `_sendToken`'s destination-address encoding consistent with `_sendNative`'s.

### Proof of Concept
1. Create an `ApiClient` scoped to Stack A with `permissions: ['read:stack']` and `stack: A` (mirrors the `here_come_the_walrus` fixture pattern: `stack: shipit`, `permissions: [read:stack]`). [4](#0-3) 
2. Obtain that client's `authentication_token` (e.g. leaked via a CCMenu URL, logs, or a compromised low-privilege integration).
3. Call `GET /api/stacks/<stack-B-owner>/<stack-B-name>/<environment>/ccmenu.xml?token=<clientA_token>` where stack B is *not* the stack the client is scoped to.
4. `authenticate_api_client` in `CCMenuController` authenticates the client via `params[:token]` (bypassing Basic Auth) and `#stack` resolves stack B directly via `Stack.from_param!`, ignoring `current_api_client.stack_id`. The response renders stack B's build status even though the token is only authorized for stack A. [5](#0-4)

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      end
    end
