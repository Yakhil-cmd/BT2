### Title
Permanent market freeze via `MathOverflow` in `accrue_step` — every entrypoint accrues first, so an i128 value overflow bricks supply/borrow/repay/withdraw/liquidation for the market - (File: `contracts/pool/src/interest.rs`)

### Summary
Analog of CVE-2018-2810 (an InnoDB crash/hang DoS): a condition an unprivileged user can create causes the pool's interest-accrual step to panic, and because accrual runs at the head of every state-mutating entrypoint, the panic repeats deterministically on every subsequent call — a "frequently repeatable crash" that permanently freezes all funds in the affected `(hub, token)` market.

### Finding Description
Every pool mutation loads the market cache and runs `interest::global_sync`, which loops `accrue_chunk` over `accrue_step` to compound indexes and mint revenue shares [1](#0-0) . The documented flow confirms this ordering: `Cache::load → global_sync → mutate → guards → commit`, for every market entrypoint [2](#0-1) .

`accrue_step` (from `common::rates`) recomputes utilization and the new indexes by unscaling borrowed/supplied RAY shares into RAY asset values. That multiply (`shares_ray * index_ray`) is done in `i128`/widened `I256` and panics with `GenericError::MathOverflow` when the value no longer fits [3](#0-2) . The protocol's own docs admit this: "Value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" [4](#0-3) .

The repo's own test demonstrates end-to-end reachability: on a whale market (large 18-decimal supply, ~98% utilization on a steep rate curve), advancing time causes `update_indexes` to revert with `MathOverflow`, after which `withdraw` and `repay` revert with the same error — "the market is frozen: no repay, no withdraw, no liquidation. The index cap never engages" [5](#0-4) .

Attacker path (single unprivileged address):
1. `controller.supply` a large amount of a high-decimals asset (caps can be high; lifted caps are a normal governance parameter, not required for the bug class — the overflow threshold is ~170B whole tokens per `formulas.md`).
2. `controller.borrow` ~98% of the market against collateral supplied on another spoke/market, pushing utilization onto the steep segment of the rate curve.
3. Wait. Accrual compounds `borrow_index` until `borrowed_shares * borrow_index` overflows `i128`.
4. Any subsequent `update_indexes`, `supply`, `borrow`, `withdraw`, `repay`, `net_settle`, `seize_positions` (liquidation), `claim_revenue`, or `flash_loan` on that `(hub, token)` market re-enters `global_sync` and panics identically — permanently, since accrual can only move forward in time.

### Impact Explanation
Permanent freezing of funds: once the market's stored totals cross the RAY-value representability boundary, every path that accrues reverts. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot seize, and `clean_bad_debt`/`recapitalize` also accrue first, so no recovery verb exists. All supplier principal and accrued yield in that market is locked forever — a complete availability loss analogous to the MySQL crash-DoS, but with irreversible on-chain consequences.

### Likelihood Explanation
Medium. The attack requires no privilege and no oracle manipulation — only capital and patience: a position large enough that compounded index growth pushes `shares * index` past `i128::MAX` before the `10^36` index ceiling intervenes. The demonstrated configuration needed ~170B whole tokens and ~170× index growth over many years [6](#0-5) . Capital cost is the main barrier, but the frozen state, once reached, is permanent and affects every supplier in the market, not just the attacker.

### Recommendation
Saturate rather than panic in `accrue_step`: clamp `borrow_index`/`supply_index` growth or the unscaled values at the representable bound so accrual becomes a no-op instead of reverting (the index ceiling mechanism already exists but engages too late, since the value multiplication overflows first). Alternatively, compute utilization/interest on widened `I256` values with an explicit saturation to `i128::MAX`, guaranteeing `global_sync` always completes and exits remain possible. Add a regression test asserting `update_indexes` never reverts on monotonically advancing time for any state reachable through valid entrypoints.

### Proof of Concept
Provided by the in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [7](#0-6) :

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);          // ~98% utilization

// advance time year-by-year until accrual panics:
loop { t.advance_time(YEAR_SECS);
       if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; } }
// => errors::MATH_OVERFLOW, borrow_index < MAX_BORROW_INDEX_RAY

assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
// all verbs revert identically — permanent freeze
```

On-chain trace: `withdraw`/`repay` → `Cache::load` → `interest::global_sync` → `accrue_chunk` → `accrue_step` → `scaled_to_original`/`mul_div` overflow → `panic_with_error!(MathOverflow)` [8](#0-7) .

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
