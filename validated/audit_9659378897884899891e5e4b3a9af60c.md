### Title
Division-by-Zero Panic in `consolidatedNode.Split()` Causes `FinalizeState` Crash When Proposer Has Zero CNStaking and Zero CLStaking — (`kaiax/staking/staking_info.go`)

---

### Summary

`consolidatedNode.Split()` divides by `totalAmount = StakingAmount + CLStakingAmount` without a zero-guard. When a proposer's node has both values equal to zero (both rounded down to 0 KAIA) while `CLStakingInfo != nil`, `big.Int.Div` panics at runtime. This panic propagates through `FinalizeState`, crashing every honest node that attempts to finalize the block.

---

### Finding Description

`consolidatedNode.Split()` in `kaiax/staking/staking_info.go` computes the CL-pool share of a reward:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }

    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← panics if totalAmount == 0
    ...
}
``` [1](#0-0) 

Both `StakingAmount` and `CLStakingAmount` are `uint64` values in whole KAIA, derived by integer-dividing the raw wei balance by `params.KAIA` (1e18). Any balance below 1 KAIA rounds to 0. There is no guard preventing `totalAmount == 0`.

`Split()` is called unconditionally for the proposer's node in both `specWithProposerAndFunds` and `specWithProposerAndFundsFlex` (Prague+ path), with no check on `totalAmount`:

```go
// Handle CLStakingInfo for proposer after Prague
cns := si.ConsolidatedNodes()
for _, cn := range cns {
    if cn.RewardAddr != config.Rewardbase { continue }
    if cn.CLStakingInfo == nil { break }

    cnAmount, clAmount := cn.Split(proposer)   // ← no totalAmount guard
    ...
}
``` [2](#0-1) [3](#0-2) 

The staking rewards path (`assignStakingRewards`, `assignStakingRewardsFlex`) is safe because it guards with `cn.StakingAmount >= minStake` before calling `Split()`. The proposer reward path has no such guard. [4](#0-3) 

---

### Impact Explanation

`FinalizeState` calls `GetDeferredReward` → `getDeferredRewardFull` → `specWithProposerAndFunds` → `cn.Split()`. A `big.Int.Div` by zero is a Go runtime panic. If unrecovered, it crashes the node process. Even if recovered, `FinalizeState` returns a fatal error, the block cannot be committed, and the network stalls or diverges on honest nodes.

This is an **invalid state transition / consensus divergence** impact: every honest node attempting to finalize the block containing this proposer will panic or error, permanently blocking that block from being accepted. [5](#0-4) 

---

### Likelihood Explanation

The trigger requires three simultaneous conditions after the Prague hardfork:

1. A validator is registered in both AddressBook and CLRegistry (`CLStakingInfo != nil`).
2. Their CNStaking contract balance is < 1 KAIA (rounds to `StakingAmount = 0`).
3. Their CL pool balance is < 1 KAIA (rounds to `CLStakingAmount = 0`).
4. They are selected as proposer for a block.

Condition 4 is reachable because the proposer list is pre-generated every `ProposerUpdateInterval` (default 3600) blocks. A validator whose staking drops to near-zero after the list was generated can still appear as proposer for up to 3600 subsequent blocks. Additionally, if `reward.minimumstake` is set to 0 via governance, validators with zero staking are permanently eligible.

The existing test suite already demonstrates a node with `StakingAmount = 0` holding a non-nil `CLStakingInfo`: [6](#0-5) 

---

### Recommendation

Add a zero-guard in `consolidatedNode.Split()` before dividing:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }

    cnAmountBig := big.NewInt(int64(c.StakingAmount))
    clAmountBig := big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
    totalAmount := new(big.Int).Add(cnAmountBig, clAmountBig)

    if totalAmount.Sign() == 0 {
        // Both CN and CL staking are zero; assign all to CN (or handle as desired).
        return amount, big.NewInt(0)
    }

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)
    cnAmount := new(big.Int).Sub(amount, clAmount)
    return cnAmount, clAmount
}
``` [1](#0-0)

### Proof of Concept

Construct a `StakingInfo` where the proposer's node has `StakingAmount = 0`, `CLStakingInfo != nil`, and `CLStakingAmount = 0`, then call `getDeferredRewardFull` (or `FinalizeState`) with Prague rules active:

```go
si := &staking.StakingInfo{

    StakingContracts: []common.Address{stakingContract},
    RewardAddrs:      []common.Address{proposerRewardAddr},
    StakingAmounts:   []uint64{0}, // < 1 KAIA → rounds to 0
    CLStakingInfos: staking.CLStakingInfos{
        {
            CLNodeId:        proposerNode,
            CLPoolAddr:      clPoolAddr,
            CLStakingAmount: 0, // < 1 KAIA → rounds to 0
        },
    },
}
config := &reward.RewardConfig{
    Rules:         params.Rules{IsMagma: true, IsKore: true, IsPrague: true},
    Rewardbase:    proposerRewardAddr,
    MintingAmount: big.NewInt(6.4e18),
    RewardRatio:   ..., // "50/20/30"
    Kip82Ratio:    ..., // "20/80"
    DeferredTxFee: true,
}
// This call panics: runtime error: integer divide by zero
_, _ = getDeferredRewardFull(config, big.NewInt(0), big.NewInt(0), si)
```

	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {

		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

	}
