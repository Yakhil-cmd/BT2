### Title
Missing try/catch around `replaceInTemplate()` in `validateAuthentifiers()` allows an uncaught exception during authentifier verification - (File: `definition.js`)

### Summary
The `definition template` operator lets an address definition reference another unit's template and fill it with attacker-supplied `params`. This code path is implemented twice in `definition.js`: once inside `validateDefinition()` and once inside `validateAuthentifiers()`. The first implementation wraps the template-filling call in a `try/catch` that gracefully converts template errors (e.g. `NoVarException`) into a validation failure. The second implementation, used during authentifier/signature verification, calls the identical `replaceInTemplate()` function **without** any exception handling, so any error thrown while filling the template propagates as an uncaught exception.

### Finding Description
In `validateDefinition()`, the `definition template` case fetches a stored template, fills it with the caller-supplied `params`, and explicitly catches template-filling errors: [1](#0-0) 

In `validateAuthentifiers()`, the exact same operation is repeated but the `try/catch` is missing — `replaceInTemplate(arrTemplate, params)` is called directly and any thrown error (e.g. a variable in the template that isn't supplied in `params`, which is exactly what raises `NoVarException` in the other code path) is not caught: [2](#0-1) 

`validateAuthentifiers()` is invoked while checking signatures/authentifiers for every unit that uses an address whose definition contains a `definition template` operator, i.e. it runs on the hot path of ordinary unit validation, reachable by any unit poster who authors (or references) such a definition.

### Impact Explanation
Because the error is not caught, it surfaces as an uncaught exception inside the validation/signature-checking flow. In `ocore`'s single-threaded Node.js model, an uncaught exception thrown from deep inside asynchronous callback chains (as here, inside a `conn.query` callback) is not converted into a normal validation-failure callback — it crashes the running process. Any node (hub, full node, or light client performing local verification of contracts/definitions using authentifier validation) that processes a maliciously crafted unit referencing a definition template with missing/incompatible params can be crashed, i.e., a network-reachable DoS that prevents a node from continuing to confirm/process new units, satisfying the "network unable to confirm new units" impact bar.

### Likelihood Explanation
Likelihood is high for any node that evaluates authentifiers against a definition using `definition template` with parameters that don't match all variables in the referenced template — this only requires posting a definition template unit and then an address/unit whose definition references it with an incomplete `params` object, both of which are actions available to an ordinary, unprivileged unit poster.

### Recommendation
Wrap the `replaceInTemplate()` call (and the surrounding `JSON.parse`) in `validateAuthentifiers()`'s `definition template` case in a `try/catch` identical to the one already present in `validateDefinition()`, translating `NoVarException` (and any other parsing/template error) into a call to `cb2(false)` instead of letting it escape as an uncaught exception.

### Proof of Concept
1. Post a `definition_template` unit whose payload includes a formula/definition referencing a template variable, e.g. `["address", "$myvar"]`.
2. Create an address (or another unit’s author) whose definition uses `["definition template", ["<template_unit_hash>", {"othervar": "value"}]]`, deliberately omitting `myvar` from `params` so that `replaceInTemplate()` throws `NoVarException` when trying to substitute it.
3. When any node runs `validateAuthentifiers()` on a unit signed/authored under that address (e.g., attempting to verify an authentifier path that reaches this branch), the call at `definition.js` line 815 throws, and since there is no `try/catch` (unlike the equivalent code in `validateDefinition()`), the exception is uncaught and crashes the node process handling validation.
