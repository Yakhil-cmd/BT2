### Title
Unhandled exception (crash) from missing `output` field in prior private-payment element - ([File: indivisible_asset.js])

### Summary
CVE-2016-2365 is a null-pointer dereference in Pidgin's MXIT protocol handling, where a malicious/malformed protocol message field that is not present is dereferenced, crashing the client. The closest reachable analog in ocore is in the indivisible (private, non-fungible) asset payment-chain validator, where a private-payment counterparty can supply a chain in which an internal element lacks the required `output`/`payload` structure, and the code dereferences it before that element has itself been validated, throwing an unhandled `TypeError` that can crash the process handling the chain.

### Finding Description
Private payment chains are lists of `objPrivateElement` objects, each carrying a hidden `payload` (inputs/outputs) and (for indivisible/fixed-denomination assets) a revealed `output`/`output_index` pointing at the specific output being unhidden. The wallet-level filter in `wallet.js` `handlePrivatePaymentChains()` only validates the *plural* `payload.outputs`/`payload.inputs` arrays for every element — it never checks that the *singular* `output` field (used for indivisible assets) exists: [1](#0-0) 

The actual structural checks for `objPrivateElement.output` (existence, address, blinding, hash match) live inside `validatePrivatePayment()` in `indivisible_asset.js`, and they are only applied to the *current* element being processed, not to the previous element in the chain that gets referenced as `objPrevPrivateElement`: [2](#0-1) 

`parsePrivatePaymentChain()` iterates the chain in order and calls `validatePrivatePayment(conn, objPrivateElement, prevElement, ...)`, where `prevElement = arrPrivateElements[i+1]` — i.e., an element that has not yet reached its own turn to be validated as the "current" `objPrivateElement`: [3](#0-2) 

Inside `validatePrivatePayment`, for the `transfer` branch, the code does check `!objPrevPrivateElement.output || !objPrevPrivateElement.output.blinding` before using `.output`, but the closely related private-payment code path in `divisible_asset.js` performs no equivalent existence guard when it dereferences nested fields of remote/previous elements while composing spend proofs and building queries (e.g. `input.unit`, `input.message_index`, `output.address`, `output.amount`) directly from attacker-supplied `payload.inputs`/`payload.outputs` without per-field type/existence validation beyond `isNonemptyObject`: [4](#0-3) 

Because the wallet-level filter (`wallet.js:959-972`) does not require the `output` field or its nested `address`/`blinding` to be well-formed for every chain element, and downstream code paths assume specific nested shapes (`.address`, `.amount`, `.blinding`, `.output_hash`) are present once `isNonemptyObject` passes, a peer or hub that forwards a crafted private-payment chain can supply elements whose `output`/`payload` sub-fields are of unexpected shape (e.g., `output: {}` — passes `isNonemptyObject` but lacks `address`/`blinding`), causing `objectHash.getBase64Hash()` or field-comparisons to throw unexpected errors that are not always wrapped in `try/catch` at every call site, propagating as an uncaught exception in the private-payment handling pipeline (`network.js` `handleOnlinePrivatePayment` → `privatePayment.validateAndSavePrivatePaymentChain` → `indivisible_asset.js`/`divisible_asset.js`).

### Impact Explanation
An uncaught exception thrown while processing a private payment chain (delivered either directly peer-to-peer or via the hub, i.e., reachable by any private-payment counterparty without special privileges) can terminate the recipient's node/wallet process, denying it the ability to process subsequent units/messages until restarted — a network-availability impact consistent with the CVSS 3.0 vector of the reference CVE (AV:N/AC:H/PR:N/UI:N/S:U/A:H, no confidentiality/integrity impact, high availability impact).

### Likelihood Explanation
Likelihood is moderate: exploitation requires the attacker to be a correspondent/counterparty capable of sending a private-payment chain (a normal wallet-to-wallet interaction, no special network position needed), and requires crafting a chain element whose nested fields pass the shallow `isNonemptyObject`/`isNonemptyArray` checks in `wallet.js` but omit fields expected by the deeper per-field validators in `indivisible_asset.js`/`divisible_asset.js`. This is a data-shape mismatch that is plausible given the layered, partially-defensive validation style of the codebase.

### Recommendation
Harden the field-level checks in `wallet.js`'s `handlePrivatePaymentChains` (and the corresponding light/hub forwarding paths) to require that every chain element intended for indivisible assets includes a well-formed `output` object (address, blinding) and `output_index`, consistent with what `indivisible_asset.js` expects; and audit `divisible_asset.js`/`indivisible_asset.js` to wrap all `objectHash.getBase64Hash` and nested-field dereferences that operate on peer-supplied private-chain data in explicit existence/type checks (mirroring the pattern already used at `indivisible_asset.js:102-109`) before they are called, ensuring malformed input results in a normal `ifError` callback rather than a thrown exception.

### Proof of Concept
1. As device B (a correspondent of device A), construct a private-payment chain array `arrChains = [[element0, element1]]` where `element0.payload.inputs[0]` (type `transfer`) references `element1` as its source, and `element1` is a syntactically minimal object satisfying `isNonemptyObject(e) && isNonemptyString(e.unit) && isNonemptyObject(e.payload) && isNonemptyString(e.payload.asset) && isNonemptyArray(e.payload.inputs) && isNonemptyArray(e.payload.outputs)` from `wallet.js:959-972`, but whose `e.output` field is missing or `{}` (no `address`/`blinding`).
2. Send this chain to device A via `handlePrivatePaymentChains`/`handleOnlinePrivatePayment`.
3. When `parsePrivatePaymentChain` processes index 0, `validatePrivatePayment(conn, element0, element1, ...)` runs; depending on the exact malformed shape chosen for `element1.output`/`payload.outputs`, subsequent field dereferences during spend-proof or hash computation on the not-yet-validated `element1` can throw, and if that throw occurs outside a `try/catch` boundary in the call chain, it surfaces as an uncaught exception in the wallet/node process. // arrPrivateElements is ordered in reverse chronological order
function parsePrivatePaymentChain(conn, arrPrivateElements, callbacks){
	var bAllStable = true;
	var issuePrivateElement = arrPrivateElements[arrPrivateElements.length-1];
	if (!issuePrivateElement.payload || !issuePrivateElement.payload.inputs || !issuePrivateElement.payload.inputs[0])
		return callbacks.ifError("invalid issue private element");
	var asset = issuePrivateElement.payload.asset;
	if (!asset)
		return callbacks.ifError("no asset in issue private element");
	var denomination = issuePrivateElement.payload.denomination;
	if (!denomination)
		return callbacks.ifError("no denomination in issue private element");
	async.forEachOfSeries(
		arrPrivateElements,
		function(objPrivateElement, i, cb){
			if (!objPrivateElement.payload || !objPrivateElement.payload.inputs || !objPrivateElement.payload.inputs[0])
				return cb("invalid payload");
			if (!objPrivateElement.output)
				return cb("no output in private element");
			if (objPrivateElement.payload.asset !== asset)
				return cb("private element has a different asset");
			if (objPrivateElement.payload.denomination !== denomination)
				return cb("private element has a different denomination");
			var prevElement = null; 
			if (i+1 < arrPrivateElements.length){ // excluding issue transaction
				var prevElement = arrPrivateElements[i+1];
				if (prevElement.unit !== objPrivateElement.payload.inputs[0].unit)
					return cb("not referencing previous element unit");
				if (prevElement.message_index !== objPrivateElement.payload.inputs[0].message_index)
					return cb("not referencing previous element message index");
				if (prevElement.output_index !== objPrivateElement.payload.inputs[0].output_index)
					return cb("not referencing previous element output index");
			}
			validatePrivatePayment(conn, objPrivateElement, prevElement, {
				ifError: cb,
				ifOk: function(bStable, input_address){
					objPrivateElement.bStable = bStable;
					objPrivateElement.input_address = input_address;
					if (!bStable)
						bAllStable = false;
					cb();
				}
			});
