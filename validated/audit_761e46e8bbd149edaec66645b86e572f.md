### Title
Unsanitized extension release URL written to terminal with ANSI color wrapping only, allowing terminal escape sequence injection - (File: pkg/cmd/root/extension.go)

### Summary
`NewCmdExtension`'s `PostRun` closure writes `releaseInfo.URL` (sourced from `ext.URL()`, ultimately populated from `internal/update.ReleaseInfo.URL`, JSON-tagged `html_url`) directly to `io.ErrOut` wrapped only in `cs.Yellow(...)`, which merely prepends/appends ANSI color codes and does not strip or escape any control sequences already present in the string. This is inconsistent with numerous other locations in the codebase (e.g. `pkg/cmd/issue/shared/display.go`, `pkg/cmd/pr/list/list.go`, `pkg/cmd/gist/shared/shared.go`, `pkg/cmd/discussion/list/list.go`, `pkg/cmd/repo/list/list.go`, `pkg/cmd/search/shared/shared.go`) that explicitly call `internal/text.SanitizeControlSequences` before rendering attacker-influenced text (titles, descriptions, etc.) to the terminal.

### Finding Description
The call chain is: `NewCmdExtension` PreRun invokes `checkExtensionReleaseInfo` (defaulting to `checkForExtensionUpdate`) [1](#0-0) , which calls `update.CheckForExtensionUpdate(em, ext, time.Now())` [2](#0-1) . That function builds a `ReleaseInfo{Version: ext.LatestVersion(), URL: ext.URL()}` [3](#0-2) , where `ReleaseInfo.URL` is JSON-tagged `html_url` [4](#0-3) , i.e. attacker-influenced release metadata for extension repos not backed by the standard github.com release-fetch path (`ext.URL()`/`ext.LatestVersion()` are implemented by the extension manager based on the extension's own remote git repository, which need not be github.com and need not obey github.com's release/tag naming constraints).

In `PostRun`, this value is written raw to stderr: [5](#0-4) 
`cs.Yellow` only wraps the string with ANSI color start/reset codes and passes the content through unchanged [6](#0-5)  — it performs no sanitization of embedded control sequences. This differs from the established pattern used elsewhere in the CLI for exactly this threat model (untrusted remote text rendered to a TTY), where `text.SanitizeControlSequences` is applied before display, e.g. in issue/PR/gist/discussion/repo/search listings.

### Impact Explanation
If an attacker-controlled extension release URL/metadata contains raw ANSI/terminal control sequences, the victim's terminal will render them when `gh <extension>` runs a command that triggers the update-check notice, enabling classic terminal-injection effects: hiding or overwriting prior output, moving the cursor, forging fake prompts/text, or (on vulnerable terminal emulators) triggering OSC-based side effects. This is an output-safety/UI-redressing class issue rather than direct code execution or credential theft, but it can be used to deceive the victim (e.g., spoof a trusted-looking gh message) after installing the attacker's extension.

### Likelihood Explanation
Requires the victim to have already installed the attacker-published extension and to run it interactively in a TTY while an update check triggers (`update.ShouldCheckForExtensionUpdate` requires a TTY and no CI/Codespaces env, and the 24h state-file gate) [7](#0-6) . Since extension installation itself is a user action based on trusting a third-party repo, and release metadata for third-party (non-github.com) extension sources is not subject to GitHub's own ref-name restrictions, this is plausible for self-hosted/mirrored extension sources, though feasibility against extensions hosted purely on github.com (where GitHub server-side restricts tag/repo names) is more limited.

### Recommendation
Sanitize `releaseInfo.URL` (and `releaseInfo.Version`, `ext.Name()`, `ext.CurrentVersion()`) with `internal/text.SanitizeControlSequences` before interpolating into the `cs.Yellow`/`cs.Cyan`/`cs.Yellowf` calls in `PostRun`, consistent with the pattern already used in `pkg/cmd/issue/shared/display.go`, `pkg/cmd/pr/list/list.go`, and similar files.

### Proof of Concept
```go
func TestPostRunSanitizesMaliciousReleaseURL(t *testing.T) {
    io, _, _, stderr := iostreams.Test()
    io.SetStdoutTTY(true)
    io.SetStderrTTY(true)

    em := &extensions.ExtensionManagerMock{}
    ext := &extensions.ExtensionMock{
        NameFunc:           func() string { return "gh-evil" },
        CurrentVersionFunc: func() string { return "v1.0.0" },
        IsPinnedFunc:       func() bool { return false },
        IsLocalFunc:        func() bool { return false },
        UpdateAvailableFunc: func() bool { return true },
    }

    malicious := "https://example.com/release\x1b[2J\x1b[H\x1b[33mFAKE PROMPT: Enter your GitHub token:\x1b[0m"
    checkFn := func(_ extensions.ExtensionManager, _ extensions.Extension) (*update.ReleaseInfo, error) {
        return &update.ReleaseInfo{Version: "v1.1.0", URL: malicious}, nil
    }

    cmd := root.NewCmdExtension(io, em, ext, checkFn)
    cmd.SetArgs([]string{})
    _ = cmd.Execute()

    out := stderr.String()
    // Expect: escape sequences should be stripped/escaped, not passed through raw.
    if strings.Contains(out, "\x1b[2J") || strings.Contains(out, "\x1b[H") {
        t.Fatalf("raw ANSI control sequences leaked to terminal output: %q", out)
    }
}
```
Expected (current, vulnerable) behavior: `stderr` contains the raw `\x1b[2J\x1b[H` control sequences interleaved with the colorized message, demonstrating unsanitized pass-through.
