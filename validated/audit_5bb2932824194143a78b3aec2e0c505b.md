### Title
Attacker-controlled `shipit.yml` `machine.environment.PATH` overrides trusted `PATH` reaching `PTY.spawn` - ([File: lib/shipit/command.rb])

### Summary
`Command#unbundled_env` builds the environment for `PTY.spawn` by merging `BASE_ENV`, then a trusted `PATH` derived from `Shipit.shell_paths`, then `@env.stringify_keys` last, so any key in `@env` wins. `@env` originates from `TaskCommands#env`, which merges `deploy_spec.machine_env` — the `machine.environment` block of the deployed repository's own `shipit.yml` — completely unfiltered by `EnvironmentVariables#permit`. Combined with `dependencies_steps` (also attacker-controlled, executed by `Command.new(..., chdir: steps_directory)`), a PR author for a review-stack-enabled repository can plant an executable in a path they name via `PATH`, causing subsequent unqualified binary invocations (`bundle`, `npm`, etc.) inside `PTY.spawn` to run attacker code.

### Finding Description
The broken binding: `Command#unbundled_env['PATH']` should equal `"#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}"` (the trusted value) but instead equals `@env['PATH']` whenever the caller supplies `PATH`, since `.merge(@env.stringify_keys)` is applied last: `BASE_ENV.merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}").merge(@env.stringify_keys)` [1](#0-0) .

For task/deploy commands, `@env` is built by `TaskCommands#env`, which merges `deploy_spec.machine_env` verbatim: `.merge(deploy_spec.machine_env).merge(@task.env)` [2](#0-1) . `machine_env` reads straight from the repo-checked-out config: `config('machine', 'environment') || {}` [3](#0-2) , with `DeploySpec::FileSystem` loading this from files inside the checked-out working directory of the task/deploy (the attacker's PR branch for a review stack). Unlike `deploy_variables`/`rollback_variables`/task `variables`, which are whitelisted through `EnvironmentVariables#permit` (`sanitize_env_vars`, raising `NotPermitted` for unlisted keys) [4](#0-3) , `machine_env` has no such whitelist — it is merged wholesale, so an attacker can set `PATH` (or any other key) to anything.

Exploit flow: attacker opens a PR against a repository with review stacks enabled (`provisioning_behavior_allow_all?` or matching label rules) [5](#0-4) . The PR's own `shipit.yml` in the fork/branch sets `machine.environment.PATH: /tmp/attacker-writable-dir` and a `dependencies` step that writes an executable named `bundle` (or `npm`, etc.) into that directory (`dependencies_steps!` is likewise fully attacker-controlled and run via `Command.new(command_line, env:, chdir: steps_directory)` before `install_dependencies`/`perform` run further steps) [6](#0-5) . On the next deploy/task step whose command line invokes an unqualified binary (e.g. Capistrano's default `bundle exec cap ... deploy`), `PTY.spawn` resolves that binary using the attacker's `PATH` value instead of `Shipit.shell_paths`, executing the attacker's planted binary as the Shipit deploy-host process [7](#0-6) .

Existing guards do not prevent this: `verify_signature`/webhook auth only gate whether the PR event is accepted, not what the `shipit.yml` inside the attacker's own branch may contain; `EnvironmentVariables#permit` is never invoked on `machine_env`; there is no `Stack`/`DeploySpec` validation restricting `machine.environment` keys or values.

### Impact Explanation
This is Critical: arbitrary command execution on the deploy host, run under the Shipit worker's OS user/permissions, for any repository that has review stacks enabled (a repository-owner opt-in, not requiring Shipit operator privilege on the attacker's part beyond opening/owning a PR in their own fork/branch). Because dependency-install and deploy steps run with access to `GIT_COMMITTER_*`, `GITHUB_TOKEN`/`github_access_token` used for that repo's deploys, and the general deploy host environment, this can lead to exfiltration of deploy-time secrets and potentially lateral compromise of the deploy host affecting other stacks/tenants sharing the same host.

### Likelihood Explanation
Preconditions: the target repository must have Review Stacks enabled with a permissive provisioning behavior (repository maintainer opt-in, common default is "Allow All") [5](#0-4) . Given that, the attacker only needs to open a pull request from their own fork with a modified `shipit.yml` — no secrets, tokens, or elevated GitHub permissions required. This is fully repeatable against any review-stack-enabled repository and does not require any race condition or timing.

### Recommendation
Do not let `machine_env` (or any attacker-controlled `@env`) override `PATH` (or other security-sensitive variables like `LD_PRELOAD`, `RUBYOPT`, `BUNDLE_*`) when building `unbundled_env`. Either merge `@env` before computing the trusted `PATH` (so the trusted `PATH` always wins), or explicitly strip/reject `PATH` (and other dangerous vars) from `deploy_spec.machine_env`/`@env` before merging, or force `unbundled_env` to always overwrite `PATH` after the final merge:
```ruby
def unbundled_env
  BASE_ENV.merge(@env.stringify_keys).merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}")
end
```

### Proof of Concept
```ruby
# test/unit/command_test.rb (new test)
test "#unbundled_env does not allow @env to override trusted PATH" do
  Shipit.stubs(:shell_paths).returns(['/trusted/bin'])
  command = Command.new('echo', 'hi', chdir: '/tmp', env: { 'PATH' => '/tmp/attacker' })
  trusted_path = "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}"
  # Binding under test: unbundled_env['PATH'] should equal trusted_path, not '/tmp/attacker'
  assert_equal trusted_path, command.unbundled_env['PATH']
end
```
Running this against current code fails because `command.unbundled_env['PATH']` equals `'/tmp/attacker'` (the attacker-supplied value), confirming the divergence from the intended binding `unbundled_env['PATH'] == "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}"`.

A second, end-to-end test can stub `TaskCommands#deploy_spec` to return `machine_env: { 'PATH' => '/tmp/attacker' }` (as in `test/unit/deploy_commands_test.rb`'s existing `@deploy_spec` stub pattern) and assert that `commands.perform.first.env['PATH']` / the resulting `Command#unbundled_env['PATH']` equals `/tmp/attacker`, demonstrating the full path from `shipit.yml` to `PTY.spawn`.
