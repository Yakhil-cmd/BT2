### Title
Unbounded RAY debt valuation overflows before the borrow-index cap, permanently freezing a high-utilization market - (File: `common/src/rates/index.rs`)

### Summary

XOXNO Lending calculates accrued debt as `borrowed.mul(new_borrow_index)` before the `MAX_BORROW_INDEX_RAY` cap can provide an effective bound on the resulting value. [1](#0-0)  Because `Ray::mul` panics when the resulting fixed-point value does not fit `i128`, a sufficiently large scaled-debt book can reach an unrepresentable valuation while its index remains below the intended cap. [2](#0-1) [3](#0-2) 

The failure occurs inside market accrual, which runs before ordinary pool mutations and is also reached by the permissionless `Controller::update_indexes` maintenance path. [4](#0-3) [5](#0-4) 

### Finding Description

`update_borrow_index` caps the index only after calculating `old_index.mul(interest_factor)`, but the independent `borrowed * borrow_index` valuation in `calculate_supplier_rewards` can overflow earlier. [6](#0-5) [1](#0-0) 

The pool’s accrual loop invokes `accrue_step` for every elapsed chunk and commits the resulting indexes and revenue shares. [7](#0-6) [8](#0-7)  Since the same accrual runs before supply, withdrawal, repayment, liquidation, bad-debt cleanup, and recapitalization, one overflow makes subsequent mutations of that market fail deterministically rather than merely delaying an operation. [5](#0-4) 

An unprivileged address can create a supplier account through `supply(account_id = 0)`, create or control the borrowing account, supply collateral, and draw a large borrow through `borrow`. [9](#0-8)  Anyone can subsequently trigger the accrual through `update_indexes`, while repayment and withdrawal remain reachable entrypoints but revert at the same arithmetic boundary. [10](#0-9) [11](#0-10) 

### Impact Explanation

The affected market can become permanently frozen: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce risk, and maintenance accrual cannot succeed once ordinary ledger-time progression reaches the unrepresentable debt valuation. [12](#0-11) 

The regression test demonstrates that the panic is not the intended index-cap behavior because `borrow_index` is still below `MAX_BORROW_INDEX_RAY` when `update_indexes`, `withdraw`, and `repay` all fail with `MathOverflow`. [13](#0-12)  This is a state-dependent arithmetic denial of service rather than transaction-budget exhaustion.

### Likelihood Explanation

Likelihood is bounded by the need for a very large token book, sustained high utilization, sufficient collateral for the borrow, and enough elapsed time for the index to make `borrowed * index` exceed the finite RAY value domain. [14](#0-13) 

The attacker does not need a privileged role, oracle manipulation, a malicious token, or a callback: the same address can own the supplier and borrower accounts, while the later accrual trigger is permissionless. [9](#0-8) [11](#0-10)  In an already large market, an attacker may only need to supply collateral and borrow enough to maintain high utilization rather than providing all pool liquidity.

### Recommendation

Enforce scaled-book bounds before minting supply or debt so the maximum representable index cannot make `scaled * index` overflow, and make accrual handle an already-boundary book by applying the index cap or a checked recovery path instead of unconditionally evaluating unrepresentable debt values. [6](#0-5) [1](#0-0) 

In particular, `borrow` and `supply` should reject scaled positions whose values would overflow under the protocol’s maximum indexes, and accrual should compute debt growth through a bounded representation that permits the cap to engage. [15](#0-14) [16](#0-15) 

### Proof of Concept

The in-repository test creates an 18-decimal market, supplies `BILLION * 10^18` units, borrows 98% of that principal from a separately collateralized account, advances ledger time yearly, and waits for `update_indexes` to fail. [14](#0-13) 

At the cliff, `try_update_indexes` returns `MathOverflow` even though the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [17](#0-16)  Subsequent `withdraw` and `repay` calls fail with the same `MathOverflow`, proving that the overflow propagates through the mandatory accrual phase and freezes the market’s repayment and exit paths. [18](#0-17)

pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
