### Title
Unvalidated Peer-Supplied Staking Info Accepted During Fast Sync Corrupts Reward Distribution DB — (`datasync/downloader/queue.go`)

### Summary

During fast sync, `queue.DeliverStakingInfos` accepts `P2PStakingInfo` payloads from any connected peer without verifying their content against the canonical state root of the corresponding block. The validate callback is an explicit no-op with a `TODO` comment. A malicious peer can inject fabricated staking info (arbitrary node IDs, reward addresses, staking amounts) for valid block hashes, permanently corrupting the staking info database that drives KAIA reward distribution and validator set selection.

### Finding Description

The fast-sync pipeline downloads staking info alongside blocks. When a peer delivers staking info, `queue.DeliverStakingInfos` is called:

```go
// datasync/downloader/queue.go  lines 953-965
func (q *queue) DeliverStakingInfos(id string, stakingInfoList []*staking.P2PStakingInfo) (int, error) {
    q.lock.Lock()
    defer q.lock.Unlock()
    validate := func(index int, header *types.Header) error {
        // TODO-Kaia-Snapsync update validation logic
        return nil          // ← always accepts, no content check
    }
    reconstruct := func(index int, result *fetchResult) {
        result.StakingInfo = stakingInfoList[index]
        result.SetStakingInfoDone()
    }
    return q.deliver(id, q.stakingInfoTaskPool, q.stakingInfoTaskQueue,
        q.stakingInfoPendPool, stakingInfoReqTimer,
        len(stakingInfoList), validate, reconstruct)
}
```

The accepted `result.StakingInfo` is then written unconditionally to the persistent database in `commitFastSyncData`:

```go
// datasync/downloader/downloader.go  lines 1881-1884
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum,
        staking.ToStakingInfo(result.StakingInfo))
}
```

`PutStakingInfoToDB` calls `WriteStakingInfo`, which does a raw `db.Put` with no further checks:

```go
// kaiax/staking/impl/schema.go  lines 47-57
func WriteStakingInfo(db database.Database, num uint64, si *staking.StakingInfo) {
    b, _ := json.Marshal(si)
    db.Put(stakingInfoKey(num), b)
}
```

The only guard in the separate `SyncStakingInfo` recovery path is a block-number equality check (`stakingInfo.BlockNum == expected`), which a malicious peer trivially satisfies by echoing the correct block number while supplying fabricated content.

Contrast this with receipt delivery, which does verify content against the header's `ReceiptHash`:

```go
// datasync/downloader/queue.go  lines 936-940
validate := func(index int, header *types.Header) error {
    if types.DeriveReceiptsRoot(types.Receipts(receiptList[index]), header.Number) != header.ReceiptHash {
        return errInvalidReceipt
    }
    return nil
}
```

No equivalent check exists for staking info. The correct check would be to re-derive the staking info from the block's state root and compare it to the peer-supplied value.

The analog to the Redstone "time travel" pattern: just as the oracle allowed replaying any valid-timestamped observation to override the cached price, the Kaia fast-sync path allows any connected peer to supply arbitrary content for a valid block hash and have it permanently stored as the authoritative staking snapshot for that block — with no monotonicity or authenticity guard.

### Impact Explanation

`StakingInfo` is the sole input to reward distribution (`assignStakingRewards`, `specWithProposerAndFundsFlex`) and to validator set construction (`GetStakingInfo` → `ConsolidatedNodes`). A corrupted entry causes:

- **Unauthorized KAIA redistribution**: fabricated `RewardAddrs` and `StakingAmounts` redirect block rewards to attacker-controlled addresses for every block that references the corrupted source epoch.
- **Invalid validator set**: fabricated `NodeIds` can add or remove validators from the effective committee, constituting a privilege escalation over chain governance.

Both effects persist across node restarts because the data is written to the persistent misc DB.

### Likelihood Explanation

Fast sync is the default mode for new or recovering nodes. Any peer that the syncing node connects to — including peers on the public P2P network — can supply staking info responses. No special privilege is required beyond being a connected peer. The attack window is the entire fast-sync duration.

### Recommendation

Implement content validation in `queue.DeliverStakingInfos` analogous to receipt validation. After receiving a `P2PStakingInfo` for block `N`, re-derive the staking info from the block's state root (using `StakingModule.getFromState`) and compare it to the peer-supplied value. If they differ, reject the delivery and penalise the peer. The existing `TODO-Kaia-Snapsync` comment acknowledges this gap.

### Proof of Concept

1. A syncing node in fast-sync mode connects to a malicious peer.
2. The malicious peer responds to `StakingInfoRequestMsg` with a `P2PStakingInfo` whose `BlockNum` matches the requested block but whose `RewardAddrs` and `StakingAmounts` are attacker-controlled.
3. `handleStakingInfoMsg` → `downloader.DeliverStakingInfos` → `queue.DeliverStakingInfos` accepts the payload (validate returns `nil`).
4. `commitFastSyncData` calls `PutStakingInfoToDB`, writing the fabricated entry to the misc DB under key `"stakingInfo" || Uint64LE(blockNum)`.
5. All subsequent calls to `GetStakingInfo` for blocks whose `sourceBlockNum` resolves to the corrupted entry return the attacker's data.
6. `assignStakingRewards` distributes KAIA to the attacker's `RewardAddrs` instead of the legitimate validators.

```go
// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
```

```go
// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
```
