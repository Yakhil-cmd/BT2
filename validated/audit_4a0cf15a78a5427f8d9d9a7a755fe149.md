### Title
Cross-organization webhook forgery via independent `repository.owner.login` / `repository.full_name` fields when a configured GitHub org has no `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb], [File: lib/shipit/github_app.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` used to validate the HMAC signature using `repository_owner`, which is read straight from the untrusted JSON body (`repository.owner.login` or `organization.login`). `GitHubApp#verify_webhook_signature` fails open (`return true unless webhook_secret`) when that resolved org has no `webhook_secret` configured. The handlers that actually mutate data (`PushHandler`, `PullRequest::OpenedHandler`, etc.) resolve the target `Repository`/`Stack` from a **different, independently attacker-controlled** field, `repository.full_name`, with no check that its owner matches the org that was used for signature verification.

### Finding Description
The binding that must hold is:
`organization_that_verified_signature == owner(repository.full_name_mutated_by_handler)`

Trace:
1. `verify_signature` computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` and calls `Shipit.github(organization: repository_owner)`. [1](#0-0) [2](#0-1) 
2. In the engine's multi-org config mode, `Shipit.github` resolves a config keyed strictly by that name (`github_app_config(organization)`), so different org names map to distinct `GitHubApp`/`webhook_secret` pairs. [3](#0-2) 
3. `GitHubApp#verify_webhook_signature` returns `true` unconditionally if the resolved org's `webhook_secret` is blank — i.e., signature checking is skipped entirely for that org. [4](#0-3) 
4. Once `verified` is truthy, `create` parses the same raw body and dispatches it to handlers such as `Shipit::Webhooks::Handlers::PushHandler` or `Shipit::Webhooks::Handlers::PullRequest::OpenedHandler`. [5](#0-4) 
5. `Handler#stacks`/`#repository_name` and every PR handler resolve the target repository from `payload.dig('repository', 'full_name')`, a field the attacker can set independently of `repository.owner.login`. [6](#0-5) [7](#0-6) 
6. `Repository.from_github_repo_name` splits `full_name` on `/` and does a plain `find_by(owner:, name:)`, with no cross-check against the org that satisfied step 3. [8](#0-7) 
7. `PushHandler#process` then writes attacker-chosen SHA/branch into the victim stack via `stack.sync_github(expected_head_sha: params.after)`, and `PullRequest::OpenedHandler`/`ReviewStackAdapter#create!` builds a `ReviewStack`/`PullRequest` with attacker-chosen `branch: params.pull_request.head.ref`, labels, and message under the victim repository's `review_stacks`. [9](#0-8) [10](#0-9) 

Exploit request: `POST /webhooks` with `X-Github-Event: push`, no `X-Hub-Signature`, and a body where `repository.owner.login` = `"attacker-org"` (a Shipit-configured org with no `webhook_secret`) but `repository.full_name` = `"victim-org/victim-repo"` (a tracked stack). Verification passes at step 3 for `attacker-org`; the handler then mutates `victim-org/victim-repo`'s stack using the attacker's `after`/`ref` values.

None of the existing guards close this gap: `drop_unhandled_event` only filters by event name, `ExplicitParameters` schemas only validate types/presence (not cross-field consistency), and `verify_signature`'s only real check is the `GithubOrganizationUnknown` rescue for names not configured at all — it never validates that the org resolved for verification matches the owner embedded in `repository.full_name`. This requires the operator to run the engine's supported multi-org configuration (documented and unit-tested in `docs/setup.md` and `test/unit/shipit_test.rb`) with at least one configured org missing `webhook_secret`; the code itself provides no fail-closed default and no cross-field binding.

### Impact Explanation
An attacker who owns/controls any GitHub org that Shipit has configured without a `webhook_secret` can forge unsigned `push`/`pull_request` webhooks that mutate a completely different, victim-owned tracked repository's `Shipit::Stack`/`Shipit::ReviewStack`/`Shipit::Commit`/`Shipit::PullRequest` records — setting attacker-chosen commit SHAs, branches, PR bodies, and labels. This is a cross-tenant record-mutation and provenance-bypass bug matching the "payload for one repository mutating another's stack/commit" Critical category; it can seed the victim stack's `HEAD`/pending commits/PR-based review stack with attacker data that later flows into `lib/shipit/deploy_commands.rb`-driven deploys. It is fully repeatable against any victim repository tracked in Shipit as long as one secret-less org exists in the config.

### Likelihood Explanation
Requires: (a) Shipit deployed with the multi-org GitHub config (supported/documented/tested feature), and (b) at least one configured org left without a `webhook_secret` (an operator misconfiguration the code does nothing to prevent or warn about — it silently fails open). No attacker secrets, sessions, or privileges are needed beyond knowing/owning a GitHub org name that happens to match a secret-less entry in Shipit's config and knowing a victim repository's `owner/name`. Cost is a single crafted HTTP POST; fully repeatable.

### Recommendation
Fail closed instead of open in `GitHubApp#verify_webhook_signature` when `webhook_secret` is blank, and/or require operators to configure a `webhook_secret` for every org. Additionally, in `WebhooksController#verify_signature`/handlers, derive and enforce that the organization used to verify the signature equals the owner segment of `repository.full_name` (and of `organization.login` when present) before dispatching to handlers, rejecting mismatches with `422`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "push webhook for secret-less org cannot mutate a different org's stack" do
  # configure two orgs: "attacker-org" with no webhook_secret, "shopify" (victim) with one
  secrets = ActiveSupport::OrderedOptions.new
  secrets.merge!(YAML.load_file('test/dummy/config/secrets_double_github_app.yml'))
  secrets.github['attacker-org'] = secrets.github['orgone'].except(:webhook_secret)
  secrets.deep_symbolize_keys!
  Shipit.stubs(:secrets).returns(secrets)

  victim_stack = shipit_stacks(:shipit) # tracked under "shopify/shipit-engine" say
  before_sha = victim_stack.commits.last.sha

  payload = JSON.parse(payload(:push_master))
  payload["repository"]["owner"]["login"] = "attacker-org" # binding LHS
  payload["repository"]["full_name"] = victim_stack.repository.github_repo_name # binding RHS (different org)
  payload["after"] = "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef" # attacker-chosen SHA

  @request.headers['X-Github-Event'] = 'push'
  # no X-Hub-Signature header at all

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef"]) do
    post :create, body: payload.to_json, as: :json
  end
  assert_response :ok

  # LHS (verifying org) != RHS (owner of mutated repo) yet the write still happened
  refute_equal "attacker-org", victim_stack.repository.owner
end
```
This demonstrates the request is accepted (`verified` truthy via fail-open path) and the victim stack, owned by a different org than the one that "verified" the signature, receives an attacker-controlled `sync_github` job with an attacker-chosen SHA.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
