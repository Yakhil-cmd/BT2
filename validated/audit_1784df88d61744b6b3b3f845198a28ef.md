### Title
CCMenu API token is not scoped to the stack it was generated for, granting read access to every stack's state and deploy output - ([File: app/controllers/shipit/ccmenu_url_controller.rb])

### Summary
`CCMenuUrlController#fetch` mints an `ApiClient` token intended to expose the build status of a single stack to external CCTray/CCMenu monitors, but the client is created without a `stack` binding. Any `ApiClient` whose `stack_id` is `nil` is treated by `Shipit::Api::BaseController#stacks` as authorized for `Stack.all`, so the resulting token — handed out unauthenticated in a plain URL query string for one stack — actually authorizes reading every stack in the Shipit instance via the `read:stack` API surface, including task/deploy output.

### Finding Description
`CCMenuUrlController#fetch` builds a public monitoring URL for one stack and generates the auth token from a client scoped only by `permissions`: [1](#0-0) 

```ruby
def fetch
  uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
  uri.query = { 'token' => client.authentication_token }.to_query
  render(json: { ccmenu_url: uri.to_s })
end

private

def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
```

`find_or_create_by!` only matches/creates on `creator` and `name` — the `stack:` association (which `ApiClient` supports, `belongs_to :stack, optional: true`) is never set. Consequently `client.stack_id` is `nil` for this token.

`Shipit::Api::BaseController` uses `stack_id` to determine the set of stacks a given token can touch: [2](#0-1) 

```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end
```

Because `stack_id` is blank, `stacks` resolves to `Stack.all` for this token. `Shipit::Api::CCMenuController#authenticate_api_client` authenticates purely from the `token` param and does not re-check that the requested `stack_id` matches the token's binding: [3](#0-2) 

```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end

def authenticate_api_client
  @current_api_client = ApiClient.authenticate(params[:token])
  super unless @current_api_client
end
```

`Stack.from_param!` looks up any stack by id/param directly, not via the `stacks` scope, and the controller's `require_permission :read, :stack` only checks `ApiClient#check_permissions!` for the *permission name*, not for stack scope: [4](#0-3) 

```ruby
def check_permissions!(operation, scope)
  required_permission = "#{operation}:#{scope}"
  unless permissions.include?(required_permission)
    raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
  end
  true
end
```

The equality that should hold — **stack a token authorizes == stack it touches** — is broken: the token is minted in a workflow scoped to one stack, embedded in a URL for that one stack, but its actual authority (via `ApiClient#stack_id?`/`stacks`) is "all stacks". Any other API endpoint gated only by `require_permission :read, :stack` (e.g. `Api::OutputsController`, `Api::TasksController`, `Api::DeploysController`) will accept this same token and controller-level `stack`/`from_param!` lookups for arbitrary `stack_id` values, since none of them re-derive the stack from `current_api_client.stacks` in the CCMenu/task flow.

### Impact Explanation
This maps to the reachable High-severity category "unauthenticated read of stack state, task streams or deploy output": a token generated (and distributed unauthenticated, e.g. embedded in a CI badge/monitor URL) for exposing one stack's CCTray status instead grants `read:stack` scoped access across the entire Shipit instance's stacks — including private/internal stacks, deploy history, and (via other `read:stack`-gated controllers) task and deploy output/log streams — none of which the token holder was meant to see.

### Likelihood Explanation
Likelihood is high for any deployment using the CCMenu integration feature: every time a logged-in user requests a CCMenu URL for any stack, the same unscoped `ApiClient` named "CCMenu Client" is found or created for that user and its token is embedded in a URL intended for external/public tooling. Anyone who obtains that URL (widget embeds, shared dashboards, browser history, proxy logs) gets a token effectively equivalent to a full `read:stack` API key for the whole instance, not just the one stack shown in the URL.

### Recommendation
Bind the `ApiClient` created in `CCMenuUrlController#client` to the specific stack (`stack: stack`) so `find_or_create_by!` keys on `creator`, `name`, and `stack`, and so `stack_id?` returns true, causing `BaseController#stacks` to scope to only that stack. Additionally, `Api::CCMenuController` should verify that `current_api_client.stacks.exists?(stack.id)` (or equivalent) rather than only relying on the generic `read:stack` permission check, closing the path for any legacy/`nil`-scoped tokens.

### Proof of Concept
1. As an authenticated Shipit user, request the CCMenu URL for stack A: `GET /ccmenu/*stack-A-id`. Shipit calls `client` which does `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')`, creating an `ApiClient` with `stack_id = nil`, and returns a URL like `https://shipit.example.com/api/stack-A-id/ccmenu.xml?token=<token>`.
2. Distribute/embed this URL (as intended, e.g. in a CI dashboard widget) — no further authentication is expected by design.
3. Using the same `token`, request `GET /api/stack-B-id/ccmenu.xml?token=<token>` for a different, unrelated stack B that the token was never meant to expose.
4. `ApiClient.authenticate(token)` succeeds (same token, same client record); `require_permission :read, :stack` passes because the client's `permissions` include `read:stack`; `Stack.from_param!('stack-B-id')` resolves stack B directly, unfiltered by `current_api_client.stacks`. The response discloses stack B's latest deploy/build status.
5. The same unscoped token can be replayed against any other `read:stack`-gated API endpoint (e.g. task output) for any stack in the instance, since `BaseController#stacks` treats a `nil` `stack_id` as authorization for `Stack.all`.
