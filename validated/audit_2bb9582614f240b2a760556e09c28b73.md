Based on the code I've examined, the invariant claimed to be broken is already enforced by an explicit subgroup check.

`validate_kzg_g1` in `src/common/bytes.c` explicitly rejects points that pass `blst_p1_uncompress` (on-curve check) but are not in the correct subgroup:

```
static C_KZG_RET validate_kzg_g1(g1_t *out, const Bytes48 *b) {
    blst_p1_affine p1_affine;
    if (blst_p1_uncompress(&p1_affine, b->bytes) != BLST_SUCCESS) return C_KZG_BADARGS;
    blst_p1_from_affine(out, &p1_affine);
    if (blst_p1_is_inf(out)) return C_KZG_OK;
    if (!blst_p1_in_g1(out)) return C_KZG_BADARGS;
    return C_KZG_OK;
}
``` [1](#0-0) 

This is called via `bytes_to_kzg_commitment` and `bytes_to_kzg_proof`, both of which are invoked at the top of `verify_kzg_proof` before any pairing math runs:

```
ret = bytes_to_kzg_commitment(&commitment_g1, commitment_bytes);
if (ret != C_KZG_OK) return ret;
ret = bytes_to_bls_field(&z_fr, z_bytes);
if (ret != C_KZG_OK) return ret;
ret = bytes_to_bls_field(&y_fr, y_bytes);
if (ret != C_KZG_OK) return ret;
ret = bytes_to_kzg_proof(&proof_g1, proof_bytes);
if (ret != C_KZG_OK) return ret;
return verify_kzg_proof_impl(ok, &commitment_g1, &z_fr, &y_fr, &proof_g1, s);
``` [2](#0-1) 

So a point whose compression is accepted by `blst_p1_uncompress` (curve check passes) but that is not in the G1 subgroup is caught by `blst_p1_in_g1` and `bytes_to_kzg_commitment`/`bytes_to_kzg_proof` return `C_KZG_BADARGS` before `verify_kzg_proof_impl` (and therefore `pairings_verify`) ever runs. `*ok` is initialized to `false` and the function returns early with an error code — it never reaches the pairing check with an attacker-controlled non-subgroup point.

This is directly exercised by existing tests, e.g. `test_verify_kzg_proof__fails_proof_not_in_g1` and `test_verify_kzg_proof__fails_commitment_not_in_g1`, and the dedicated `validate_kzg_g1` test suite (`test_validate_kzg_g1__fails_not_in_g1`, `..._fails_not_in_curve`, etc.): [3](#0-2) [4](#0-3) 

The `g2_sub`/`g1_sub` operations in `verify_kzg_proof_impl` operate on already-validated subgroup elements (`commitment`, `proof` come from `bytes_to_kzg_commitment`/`bytes_to_kzg_proof`; `x_g2`/`y_g1` are computed via `g2_mul`/`g1_mul` from the trusted generator and validated scalars), so there is no sign/negation error path that a non-subgroup point could exploit — the point never enters the arithmetic in the first place.

static C_KZG_RET validate_kzg_g1(g1_t *out, const Bytes48 *b) {
    blst_p1_affine p1_affine;

    /* Convert the bytes to a p1 point */
    /* The uncompress routine checks that the point is on the curve */
    if (blst_p1_uncompress(&p1_affine, b->bytes) != BLST_SUCCESS) return C_KZG_BADARGS;
    blst_p1_from_affine(out, &p1_affine);

    /* The point at infinity is accepted! */
    if (blst_p1_is_inf(out)) return C_KZG_OK;
    /* The point must be on the right subgroup */
    if (!blst_p1_in_g1(out)) return C_KZG_BADARGS;

    return C_KZG_OK;
}
