### Title
Cross-organization webhook status forgery breaks the "authenticated organization = repository written" binding, enabling CI-gate bypass and unauthorized deploy - (File: `app/models/shipit/webhooks/handlers/status_handler.rb`, `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate a webhook against using an attacker-controlled payload field (`repository.owner.login` / `organization.login`), but the handler that mutates state (`StatusHandler#process`) never re-checks that binding — it looks up the target `Commit` purely by `sha`, globally, across all stacks/organizations. In a multi-organization Shipit deployment where any configured organization has no `webhook_secret` set, signature verification for that organization is a no-op, letting an unauthenticated attacker forge a `status` webhook "from" that unsecured org while writing a CI status onto a commit that actually belongs to a different, properly-secured organization's stack.

### Finding Description
`WebhooksController#verify_signature` derives the organization to check the signature against directly from the untrusted JSON body: [1](#0-0) [2](#0-1) 

The organization-scoped app config is fetched by `Shipit.github(organization: repository_owner)`, and `GitHubApp#verify_webhook_signature` explicitly treats a missing `webhook_secret` as automatically verified: [3](#0-2) 

Shipit natively supports multiple GitHub App configs keyed by organization (`github_organizations`, `github_app_config`), exactly as shown in the fixture with `OrgOne`/`OrgTwo`: [4](#0-3) [5](#0-4) 

Once signature verification passes (trivially, for an org with no `webhook_secret`), the event is dispatched to handlers with the raw, unverified payload — none of which re-validate `repository.owner.login` against the record being mutated: [6](#0-5) 

`StatusHandler#process` resolves the target purely by commit SHA, with no scoping to the repository/organization that was used to authenticate the request: [7](#0-6) 

This breaks the trust binding "organization that authenticated == repository being written": the signature is checked against the org named in `repository.owner.login`, but the actual database row mutated (`Commit`/`Status`) is selected only by `sha`, which is global across all repositories/stacks tracked by the Shipit instance. If any organization in a multi-org config has no `webhook_secret`, an attacker can name that org in the payload to sail through `verify_signature`, then supply the `sha` of a commit that actually belongs to a stack under a different (properly secured) organization, and inject a fabricated `status` record for it.

### Impact Explanation
Forged `status` events let an attacker set an arbitrary `state`/`context`/`target_url` on a real commit in a target stack via `Commit#create_status_from_github!`. If that stack's `shipit.yml` declares `ci.require` for a given context (a documented, common configuration — see README's CI section), a forged "success" status for the required context can satisfy Shipit's CI-check gate for that commit, enabling continuous delivery/deploy to proceed for code that never actually passed CI. This meets the "unauthorized deploy" bar for High/Critical impact defined in scope, since it lets an unprivileged, unauthenticated attacker cause the engine to treat a commit as deployable when it should not be.

### Likelihood Explanation
Exploitability strictly requires a multi-organization Shipit deployment where at least one configured organization lacks a `webhook_secret` — a configuration explicitly supported and documented in this codebase (`test/dummy/config/secrets_double_github_app.yml`, `github_app_config`), and plausible in real setups (e.g., an org added later without immediately configuring a webhook secret, or intentionally left blank during setup per `docs/setup.md`'s "optional" wording for `webhook_secret`). No credentials, tokens, or session are required — only knowledge of a target commit `sha`, which is public GitHub information. This is a realistic misconfiguration-triggered but code-enforced weakness, not a purely theoretical one, because the engine's own logic (`return true unless webhook_secret`) actively converts "no secret configured" into "always verified."

### Recommendation
- In `WebhooksController#verify_signature` / `Webhooks::Handlers::Handler`, after selecting the organization via `repository_owner`, cross-check that the resolved `Repository`/`Stack` for the payload's `repository.full_name` actually belongs to that same organization before dispatching to handlers.
- In `StatusHandler#process` (and any other handler resolving records solely by SHA, e.g. via `Commit.where(sha:)`), scope the lookup by the verified repository/organization rather than by SHA alone.
- Consider making `webhook_secret` mandatory (fail closed) for every configured organization rather than defaulting to "verified" when absent.

### Proof of Concept
1. Deploy Shipit with two GitHub App orgs configured, e.g. `OrgSecure` (has `webhook_secret`) and `OrgOpen` (no `webhook_secret`), tracking stacks for repos owned by both orgs.
2. Identify a commit `sha` belonging to a stack under `OrgSecure` whose `shipit.yml` has `ci.require: ["ci/required-check"]`.
3. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "sha": "<victim-commit-sha-under-OrgSecure>",
  "state": "success",
  "context": "ci/required-check",
  "repository": { "owner": { "login": "OrgOpen" } }
}
```
4. `verify_signature` resolves `repository_owner` to `"OrgOpen"`, whose `webhook_secret` is unset, so `verify_webhook_signature` returns `true` regardless of the (missing/incorrect) `X-Hub-Signature` header.
5. `StatusHandler#process` finds the commit purely by `sha` and calls `create_status_from_github!`, creating a forged "success" status for `ci/required-check` on a commit under `OrgSecure`, satisfying the CI gate without any real CI run having occurred.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
