### Title
Cross-organization webhook forgery via `repository.owner.login`/`repository.full_name` mismatch archives a victim org's review stack - ([File: app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` authenticates a webhook using the GitHub App secret for the organization found at `params.dig('repository','owner','login')`, but `ClosedHandler#repository` (and every other `PullRequest` handler) resolves the repository to mutate from the independent field `params.repository.full_name`. Nothing in the request pipeline checks that these two fields agree, so a payload whose `repository.owner.login` is an org the attacker controls (with no `webhook_secret` configured) but whose `repository.full_name` names a victim org's repo passes signature verification and then archives the victim's live review stack.

### Finding Description
The broken binding, stated as an equality that the code assumes but never enforces:
`params.dig('repository','owner','login') == owner_portion_of(params.repository.full_name)`.

- `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` and uses it to select the `GitHubApp` instance (and thus the `webhook_secret`) for HMAC verification: [1](#0-0) , [2](#0-1) .
- `GitHubApp#verify_webhook_signature` trivially returns `true` whenever no `webhook_secret` is configured for that org: [3](#0-2) . An unset `webhook_secret` is an explicitly supported, documented configuration (`webhook_secret: # nil` in `config/secrets.development.example.yml` and `docs/setup.md`), so any organization onboarded to Shipit without a configured secret accepts unauthenticated webhooks for that org identifier.
- Once the request passes `verify_signature`, `ClosedHandler#repository` looks up the repo to mutate purely from `params.repository.full_name`, completely independent of `repository.owner.login`: [4](#0-3) . `Repository.from_github_repo_name` just splits `full_name` on `/` and looks the record up by that owner/name pair: [5](#0-4) .
- `ClosedHandler#process` then unconditionally calls `review_stack.archive!` scoped to that repository's `review_stacks`: [6](#0-5) , and `ReviewStackAdapter#archive!` deprovisions and archives the matched stack if found: [7](#0-6) .
- The base `Handler` class exhibits the same pattern (`repository_name` reads `payload.dig('repository', 'full_name')`, independent of the signature-checked owner): [8](#0-7) .
- The `ClosedHandler`'s `ExplicitParameters` schema requires only `repository.full_name`; it does not require or validate `repository.owner.login` at all, so nothing enforces consistency between the two fields: [9](#0-8) .

Exploit flow: attacker controls (or has webhook-triggering ability for) Org A, which is a Shipit-onboarded organization (`Shipit.github_app_config('OrgA')` exists) but has no `webhook_secret` configured. Attacker POSTs directly to `/webhooks` with header `X-Github-Event: pull_request`, body `{"action":"closed", ..., "repository": {"owner": {"login": "OrgA"}, "full_name": "OrgB/victim-repo"}, ...}`. `verify_signature` resolves `Shipit.github(organization: "OrgA")`, whose `verify_webhook_signature` returns `true` unconditionally because `webhook_secret` is blank — no signature knowledge is required at all. `ClosedHandler` then resolves `repository` from `full_name = "OrgB/victim-repo"`, finds the victim's `Repository`/`ReviewStack`, and archives it.

Existing guards do not stop this: `verify_signature` only binds the signature check to `repository.owner.login`, never to `repository.full_name`; `drop_unhandled_event` only checks the event type exists; the `ExplicitParameters` schema on `ClosedHandler` validates presence/type of `full_name` but not its relationship to `owner.login`; there is no `Repository`/`Stack` model validation that cross-checks the archiving actor's org against the payload's stated owner.

### Impact Explanation
A payload scoped/authenticated (weakly) as belonging to Org A mutates a stack (archive, deprovision) that belongs to Org B — this matches the Critical category "a payload for one repository mutating another's stack/task/commit/team." The attacker can repeat this against any victim repository/review-stack whose owner/name they can guess or observe, as long as they control or can trigger a webhook-signature-accepted request for any org lacking a `webhook_secret`. Blast radius: any tenant org configured without a webhook secret becomes a launchpad for archiving arbitrary other orgs' review stacks (deprovisioning running environments, ending PR workflows) system-wide.

### Likelihood Explanation
Preconditions: (1) at least one organization onboarded to the Shipit instance without a `webhook_secret` configured — an explicitly supported and exemplified configuration in this repo's own docs/example secrets files, not a hypothetical; (2) attacker knows/guesses that org's login and the victim's `owner/name`. No GitHub secret, App private key, or Shipit session/token is required. Attacker cost is a single crafted HTTP POST to a public endpoint; fully repeatable, deterministic, and scriptable against any number of victim repositories.

### Recommendation
Enforce that `params.repository.owner.login` (the org used for signature verification) matches the owner portion of `params.repository.full_name` before invoking any handler, e.g. in `WebhooksController#create`/`verify_signature`, reject (422) if `repository.owner.login` differs (case-insensitively) from the owner segment of `repository.full_name`. Additionally, consider requiring `webhook_secret` to be present for all configured organizations (or defaulting to reject unsigned requests) rather than silently bypassing verification when unset.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` or a new test file), no live GitHub required:

```ruby
test "pull_request closed event with mismatched repository.owner.login and repository.full_name archives victim org's stack" do
  # Arrange: victim stack under OrgB/victim-repo
  victim_repo = Shipit::Repository.create!(owner: "orgb", name: "victim-repo", review_stacks_enabled: true, provisioning_behavior: :allow_all)
  victim_stack = # ... create a ReviewStack for victim_repo with environment matching PR number, provisioned, not archived

  # Configure OrgA in Shipit.secrets.github with no webhook_secret (unsecured attacker org)
  # e.g. via test dummy secrets fixture with `OrgA: { webhook_secret: nil, ... }`

  payload = {
    "action" => "closed",
    "number" => victim_stack_pr_number,
    "pull_request" => { ... valid pull_request subtree ... },
    "repository" => { "owner" => { "login" => "OrgA" }, "full_name" => "OrgB/victim-repo" },
    "sender" => { "login" => "attacker" }
  }

  request.headers['X-Github-Event'] = 'pull_request'
  # No valid X-Hub-Signature needed because OrgA has no webhook_secret

  assert_nil victim_stack.reload.archived_since

  post :create, body: payload.to_json, as: :json

  assert_response :ok
  assert_not_nil victim_stack.reload.archived_since, "victim org's review stack was archived by a payload verified only against OrgA"
end
```

Assertions on both sides of the binding: before the request, `params.dig('repository','owner','login') == "OrgA"` while the owner segment of `params.repository.full_name == "OrgB"` — they diverge. The test asserts the divergence is never rejected and results in `victim_stack.archived_since` transitioning from `nil` to non-nil, proving cross-org mutation succeeded despite the mismatched binding.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
