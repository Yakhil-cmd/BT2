### Title
Immutable pool_creator with no override path permanently freezes creator fees if the creator address becomes SPL blocklisted - (File: programs/cp-swap/src/instructions/collect_creator_fee.rs, programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs, programs/cp-swap/src/states/pool.rs)

### Summary
`PoolState.pool_creator` is fixed at pool `initialize` time and cannot be changed by any instruction. Both `collect_creator_fee` and `collect_creator_fee_permissionless` transfer the accrued `creator_fees_token_0`/`creator_fees_token_1` exclusively into ATAs owned by this immutable `creator` address. For USDT/USDC (or any Token-2022 mint with a default-account-state/permanent-delegate freeze authority), if the `creator` account is ever placed on the issuer's blocklist (frozen), the underlying `transfer_checked`/mint-owner transfer used by `transfer_from_pool_vault_to_user` will revert, and there is no alternate recipient, cancel, or redirect mechanism anywhere in the program.

### Finding Description
`initialize` writes `pool_creator` into `PoolState` once, with no setter afterward [1](#0-0) . On every `swap_base_input`/`swap_base_output`, a `creator_fee` is computed by `CurveCalculator::swap_base_input` and accumulated into `pool_state.creator_fees_token_0`/`creator_fees_token_1` (permissionlessly triggerable by any swapper) [6](#0-5) . These fee balances are subtracted out of the pool's tradable/withdrawable balance in `vault_amount_without_fee`, meaning they sit in the vault as a segregated, creator-only claim that LPs cannot withdraw and swappers cannot trade against [3](#0-2) .

The only egress path for these funds is `collect_creator_fee` (creator-signed) or `collect_creator_fee_permissionless` (anyone can call, but the destination ATA authority is hard-constrained to `pool_state.pool_creator`) [7](#0-6) [8](#0-7) . If USDT/USDC (or a Token-2022 mint using default account state/permanent delegate freeze) blocklists/freezes the `creator`'s associated token account, the CPI transfer inside `transfer_from_pool_vault_to_user` will always fail for that mint, both instructions will permanently revert, and `creator_fees_token_0`/`creator_fees_token_1` can never be reset to zero nor redirected. This is directly analogous to the reported SolverVaults issue: an immutably-recorded receiver becomes unable to receive, and the protocol provides no cancel/edit mechanism, so the funds are permanently stuck inside the vault.

### Impact Explanation
The creator-fee share of every swap becomes permanently locked inside the pool vault once the pool creator's token account is blocklisted/frozen by the token issuer. This is a genuine, unrecoverable loss (freezing) of protocol/creator funds with no admin, governance, or user workaround, satisfying the "permanent freezing of user or LP funds"/fee-ledger insolvency criteria: the vault holds tokens accounted in `creator_fees_token_0/1` that will never be collectible again, effectively acting as dead-locked balance while still being subtracted from swappable/withdrawable liquidity.

### Likelihood Explanation
Likelihood is moderate: it requires the specific pool_creator address to be added to a centralized stablecoin issuer's blocklist (a realistic, historically observed event for USDT/USDC) or to be a Token-2022 mint with default frozen state. Since `pool_creator` is set once at pool creation and can be any arbitrary pubkey supplied by the pool initializer, and creator fees accrue automatically on every swap without requiring creator action, the affected balance can grow unboundedly before anyone notices the block, worsening impact over time.

### Recommendation
Allow the `creator` (or an authorized fallback such as `amm_config.owner`) to update `pool_state.pool_creator` to a new receiving address, or add an instruction that lets a governance/admin authority redirect/rescue undistributed `creator_fees_token_0/1` to an alternate address if the recorded creator becomes provably unable to receive funds (e.g., after a grace period). At minimum, decouple the ATA derivation from a single fixed authority by permitting the creator to specify an alternate token account owner at collection time, mirroring the recommendation from the referenced report to allow editing/canceling a stuck destination.

### Proof of Concept
1. Pool is initialized with `pool_creator = C`, where token_0 (or token_1) is USDT/USDC [1](#0-0) .
2. Any user calls `swap_base_input`/`swap_base_output` repeatedly; each swap increments `pool_state.creator_fees_token_0`/`creator_fees_token_1` per `CurveCalculator::swap_base_input` [6](#0-5) .
3. Tether/Circle freezes address `C` (or its ATA) via their standard blocklist functionality.
4. Anyone calls `collect_creator_fee_permissionless`; the `init_if_needed` ATA for `creator_token_0`/`creator_token_1` is owned by frozen `C`, so the SPL/Token-2022 transfer inside `transfer_from_pool_vault_to_user` fails, reverting the whole instruction [9](#0-8) .
5. `creator_fees_token_0`/`creator_fees_token_1` can never be reset or redirected — the corresponding funds are permanently excluded from vault liquidity per `vault_amount_without_fee` and unreachable by any instruction in the program [3](#0-2) .
