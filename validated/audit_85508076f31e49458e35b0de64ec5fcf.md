### Title
Whole-unit collateral floor is enforced in base units instead of whole tokens, letting borrowers strand unliquidatable sub-unit collateral — (File: contracts/controller/src/risk/validation.rs)

### Summary
The wasmtime bug checked a string's *code-unit count* where a *byte-length* bound was required — a bound enforced in the wrong unit scale. `require_whole_unit_collateral_floor` repeats that shape: the specification and the constant's name (`MIN_WHOLE_UNIT_COLLATERAL`, value 2) require **2 whole tokens** in any collateral leg below `MIN_BORROWABLE_ASSET_DECIMALS` (3 decimals), but the implementation computes `units` with `to_asset_floor(env, decimals)`, which yields **base units** (stroops), not whole tokens.

### Finding Description
`contracts/controller/src/risk/validation.rs:153-169`:

```rust
let units = position
    .scaled_amount
    .mul(env, supply_index)
    .to_asset_floor(env, decimals);
assert_with_error!(env, units >= MIN_WHOLE_UNIT_COLLATERAL, ...);
```

`to_asset_floor` divides by `10^(27 - decimals)`, producing token base units. For a 1-decimal asset the check requires `≥ 2` base units = **0.2 tokens** (should be 20); for a 2-decimal asset `≥ 2` base units = **0.02 tokens** (should be 200). Only at 0 decimals does the bound coincide with the intended 2 whole units. The off-by-`10^decimals` scale error mirrors the advisory's factor-of-2 code-unit/byte confusion.

The floor exists because a partial seizure leg below 3 decimals can only be liquidated in whole units: an offer whose seizure backs less than one whole unit is dropped and `liquidate` reverts with `InvalidPayments` (`contracts/controller/src/positions/liquidation/math.rs:401-417`, docs `docs/reference/formulas.md:266-276`, `docs/reference/invariants.md` INV-LIQ-02). The protocol therefore requires that any action leaving debt keeps ≥2 whole units in such a leg (`skills/xoxno-lending/math.md:387`, `docs/reference/formulas.md:275-276`).

### Impact Explanation
An unprivileged borrower on a spoke with a 1- or 2-decimal collateral asset can withdraw (or be partially liquidated) down to ≥2 base units — e.g., 0.02 tokens — while retaining debt. At that size every liquidation offer seizes zero whole units and reverts, so the position is permanently unliquidatable via `liquidate`. With HF < 1 and collateral below the $5 dust cap, `clean_bad_debt` is permissionlessly eligible, which writes the debt down against the market's supply index — a direct loss to that market's suppliers (protocol insolvency / socialized bad debt) that the floor was designed to prevent.

### Likelihood Explanation
Reachable by any account: supply ≥2 whole units of a 1- or 2-decimal listed asset, `borrow`, then `withdraw` collateral until only 2 base units remain — the post-action solvency check passes because it compares base units to 2 instead of `2 * 10^decimals`. Requires only a listed sub-3-decimal collateral market, which the codebase explicitly supports (whole-unit liquidation path, LQVID RWA listings). Likelihood is gated by such a listing existing; severity is Medium (bounded socialized loss, requires a mispriced/illiquid collateral type).

### Recommendation
In `require_whole_unit_collateral_floor`, compare against `MIN_WHOLE_UNIT_COLLATERAL * 10^decimals` base units, i.e.:

```rust
let required = MIN_WHOLE_UNIT_COLLATERAL
    .checked_mul(10i128.pow(decimals))
    .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
assert_with_error!(env, units >= required, CollateralError::MinBorrowCollateralNotMet);
```

Add regression tests at 1 and 2 decimals asserting a post-debt leg of `2 * 10^d - 1` base units is rejected.

### Proof of Concept
1. Governance lists asset `T` with `asset_decimals = 2`, price such that 1 token = $10.
2. Attacker supplies 2.00 `T` (200 base units) as sole collateral, borrows ~$14 of USDC (HF < 1 after a small price move, or borrow near threshold and wait for accrual).
3. Attacker calls `withdraw` leaving exactly 2 base units (0.02 `T` ≈ $0.20) of collateral with debt outstanding. `require_whole_unit_collateral_floor` computes `units = 2 ≥ 2` and passes; intended bound is 200.
4. Any liquidator's offer reverts with `InvalidPayments` since the seizure backs less than one whole unit (`seizure_ray.to_asset_floor(2) == 0`).
5. Debt accrues unbacked; `clean_bad_debt` (collateral ≪ $5, debt > collateral) socializes it via `apply_bad_debt_to_supply_index`, permanently impairing USDC suppliers.

*Caveat: I could not re-verify the exact value of `MIN_WHOLE_UNIT_COLLATERAL` in `common/src/constants/shared.rs` or the call-site coverage of `require_whole_unit_collateral_floor` within the iteration limit; the analysis assumes the documented "2 whole units" semantics and post-action enforcement described in `docs/reference/formulas.md` and INV-LIQ-02.*
