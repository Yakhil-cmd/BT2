### Title

Bad-debt supply-index floor resurrects wiped supplier claims against recapitalization funds - (File: contracts/pool/src/interest.rs)

### Summary

`apply_bad_debt_to_supply_index` clamps a fully wiped market's supply index to `SUPPLY_INDEX_FLOOR_RAW`, so every pre-wipeout supply position remains redeemable for 0.1% of its former value instead of becoming worthless. [1](#0-0)  An attacker who defaults on debt exceeding total supplied value can keep the borrowed proceeds, retain this residual supply claim, and withdraw it after an unrelated payer calls the permissionless `recapitalize` entrypoint. [2](#0-1)  The affected claim is then paid through the normal withdrawal path because withdrawal resolves shares against the floored index and debits the recapitalized cash. [3](#0-2) 

### Finding Description

When bad debt is socialized, the pool caps the loss at the total supplied value and computes the remaining value as `total_supplied_value - capped_bad_debt`. [4](#0-3)  For a complete wipeout, `remaining` is zero and `new_supply_index` is therefore zero, but the code promotes it to `SUPPLY_INDEX_FLOOR_RAW` before committing it. [5](#0-4)  The controller's `clean_bad_debt` entrypoint is permissionless once the account is insolvent and its remaining collateral is at or below the dust threshold. [6](#0-5)  This creates the accounting equivalent of the reported bug: a resource that should have been fully invalidated is still classified as usable, and later operations treat it as backed capacity. [1](#0-0) 

### Impact Explanation

The residual 0.1% claim is backed by neither original cash nor surviving debt after a complete bad-debt wipeout. [1](#0-0)  `recapitalize` credits the caller's measured transfer up to the pool's backing shortfall, which includes this artificially preserved supplier claim. [7](#0-6)  A holder of pre-wipeout shares can then call `withdraw` with a zero amount for the affected asset to withdraw the entire remaining position and receive cash funded by the recapitalizer. [8](#0-7)  This permits theft of user funds from whoever recapitalizes the market and creates a permanent residual claim until it is paid or the market is abandoned. [9](#0-8) 

### Likelihood Explanation

The exploit path uses only unprivileged controller calls: `borrow`, self-`liquidate`, `clean_bad_debt`, and `withdraw`, plus an optional attacker or third-party `recapitalize`. [10](#0-9)  Generating the bad debt requires the account to become insolvent through interest or adverse price movement, so the attack is conditional rather than immediately deterministic. [11](#0-10)  Once the dust-gated insolvency condition exists, any authenticated caller can invoke `clean_bad_debt`, and the index-floor behavior is automatic. [12](#0-11) 

### Recommendation

A complete bad-debt wipeout should not preserve pre-wipeout positions as redeemable at a synthetic nonzero index. [13](#0-12)  Introduce a market generation or explicit wiped-market state so old scaled shares are invalidated while the market can still be reopened safely for new deposits. [5](#0-4)  Alternatively, cap aggregate withdrawals from pre-wipeout shares at the actual remaining value and distinguish recapitalization intended to reopen the market from payments owed to already-socialized positions. [14](#0-13) 

### Proof of Concept

1. Attacker account A supplies `S` units of asset `X`; the market's total supply and scaled position are represented by `S * supply_index`. [15](#0-14) 
2. Attacker account B supplies other collateral and calls `borrow` for `X`, withdrawing the pool's cash. [16](#0-15) 
3. After adverse price movement or accrued interest makes account B insolvent, the attacker self-liquidates the collateral down to the dust cap; self-liquidation is explicitly permitted. [17](#0-16) 
4. The attacker or any third party calls `clean_bad_debt(caller, account_B)`, which passes because `total_debt > total_collateral` and `total_collateral <= BAD_DEBT_USD_THRESHOLD`. [18](#0-17) 
5. The pool receives the borrow-side seize entry and calls `apply_bad_debt_to_supply_index`; with `bad_debt >= total_supplied_value`, `remaining` is zero and the resulting index is clamped to `SUPPLY_INDEX_FLOOR_RAW`. [19](#0-18) 
6. A third party calls `recapitalize(payer, X, amount)`; the pool computes a positive backing shortfall from the floored claims and credits up to that amount as cash. [7](#0-6) 
7. The attacker calls `withdraw(account_A, [(X, 0)])`, where zero requests the full position, and receives approximately `S * SUPPLY_INDEX_FLOOR_RAW` from the newly recapitalized cash. [8](#0-7)

```rust
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

```rust
enum BadDebtGate {

    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
```

```rust
/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}
```
