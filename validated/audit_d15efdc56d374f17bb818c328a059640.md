### Title
Unsanitized manifest-controlled extension URL/version fields allow CR/LF terminal spoofing in extension update notice - ([File: pkg/cmd/root/extension.go])

### Finding Description
`NewCmdExtension`'s `PostRun` writes the "new release available" notice directly to `stderr` with `fmt.Fprintf`, embedding `ext.Name()`, `ext.CurrentVersion()`, `releaseInfo.Version`, and `releaseInfo.URL` without any escaping of control characters (CR, LF, ANSI/cursor sequences). [1](#0-0) 

For a `BinaryKind` extension, these values are not restricted by GitHub's repo/tag-name character rules the way `GitKind` values are:
- `Extension.URL()` builds the URL from `manifest.Owner`, `manifest.Name`, and `manifest.Host` read straight out of the attacker-authored `manifest.yml` release asset, with no validation of the string content. [2](#0-1) 
- `Extension.CurrentVersion()` for `BinaryKind` also returns `manifest.Tag` unmodified from the same manifest file. [3](#0-2) 
- `update.CheckForExtensionUpdate` copies `ext.LatestVersion()` and `ext.URL()` verbatim into `ReleaseInfo.Version` / `ReleaseInfo.URL`, which is exactly what `PostRun` prints. [4](#0-3) 

Since `manifest.yml` is a YAML file entirely authored by the attacker and shipped as part of the extension's release assets, the `owner`, `name`, `host`, and `tag` fields can contain arbitrary byte sequences (YAML double-quoted scalars support `\r`/`\n` escapes), which are never sanitized before being interpolated into the `fmt.Fprintf` calls in `PostRun`. This differs from `GitKind` extensions, where `CurrentVersion`/`LatestVersion` are git SHAs/ref outputs (hex-only, safe) and `URL` comes from `git config remote.origin.url` (still not content-checked, but typically constrained by remote URL syntax).

A `\r` written to a terminal repositions the cursor to the start of the line, allowing an attacker-controlled manifest string to overwrite (visually replace) the previously-printed trusted text — e.g., redrawing the line to look like `? Paste your GitHub token:` — potentially tricking a user who has another prompt pending or is watching combined output.

### Impact Explanation
This is a terminal output/prompt-spoofing primitive: an attacker who publishes a binary extension (with a crafted `manifest.yml`) can cause `gh <extension>` to print attacker-chosen text with cursor-repositioning control characters in place of gh's own trusted "new release" notice, which could be leveraged for social engineering (fake credential prompts, fake confirmation prompts) once a user installs and runs the extension. This matches the "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" impact class, though actual severity is capped by the requirement that the victim already installs and runs an attacker-authored extension binary (a fairly high bar already implying the user trusts the extension).

### Likelihood Explanation
Preconditions: the victim must install a malicious `BinaryKind` extension (`gh extension install`) and later run `gh <ext-name>` while an update is detected. This requires the attacker to get a user to install their extension in the first place — a real but non-trivial precondition (most extension trust models already assume users vet what they install/run). Once installed, the update-check path runs automatically in `PreRun`/`PostRun` on every invocation, and the attacker fully controls `manifest.yml` contents, so exploitation is repeatable and reliable given that precondition.

### Recommendation
Sanitize all remote/manifest-derived strings before they reach any `fmt.Fprintf` destined for the terminal: strip or reject control characters (`\r`, `\n`, ANSI escape sequences) from `manifest.Owner`, `manifest.Name`, `manifest.Host`, `manifest.Tag`, and any derived `ReleaseInfo.Version`/`ReleaseInfo.URL`, either when loading the manifest (`loadManifest`) or as a shared output-sanitization helper applied in `NewCmdExtension`'s `PostRun` before printing.

```go
// pkg/cmd/root/extension_test.go
func TestNewCmdExtension_PostRun_RejectsControlChars(t *testing.T) {
    ios, _, _, stderr := iostreams.Test()

    em := &extensions.ExtensionManagerMock{
        DispatchFunc: func(args []string, stdin io.Reader, stdout, errout io.Writer) (bool, error) {
            return true, nil
        },
    }

    ext := &extensions.ExtensionMock{
        NameFunc:           func() string { return "evil" },
        OwnerFunc:          func() string { return "" },
        CurrentVersionFunc: func() string { return "1.0.0" },
        IsPinnedFunc:       func() bool { return false },
        UpdateAvailableFunc: func() bool { return true },
    }

    checkFunc := func(em extensions.ExtensionManager, ext extensions.Extension) (*update.ReleaseInfo, error) {
        return &update.ReleaseInfo{
            Version: "2.0.0",
            // simulate attacker-controlled manifest.yml Owner/Name/Host containing CR+forged prompt
            URL: "https://example.com/x\r? Paste your GitHub token: ",
        }, nil
    }

    cmd := root.NewCmdExtension(ios, em, ext, checkFunc)
    _, err := cmd.ExecuteC()
    require.NoError(t, err)

    out := stderr.String()
    require.NotContains(t, out, "\r", "rendered output must never contain a raw carriage return")
}
```
Expected today: the assertion fails because `\r` is passed through unmodified in the `fmt.Fprintf(stderr, "%s\n\n", cs.Yellow(releaseInfo.URL))` call, confirming the lack of sanitization.

func (e *Extension) URL() string {
	e.mu.RLock()
	if e.url != "" {
		defer e.mu.RUnlock()
		return e.url
	}
	e.mu.RUnlock()

	var url string
	switch e.kind {
	case LocalKind:
	case BinaryKind:
		if manifest, err := e.loadManifest(); err == nil {
			repo := ghrepo.NewWithHost(manifest.Owner, manifest.Name, manifest.Host)
			url = ghrepo.GenerateRepoURL(repo, "")
		}
	case GitKind:
		if remoteURL, err := e.gitClient.Config("remote.origin.url"); err == nil {
			url = strings.TrimSpace(string(remoteURL))
		}
	}

	e.mu.Lock()
	e.url = url
	e.mu.Unlock()

	return e.url
}
