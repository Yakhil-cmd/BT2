### Title
Low-decimal collateral boundary upgrades liquidation to full debt and over-seizes one unit - ([File: contracts/controller/src/positions/liquidation/math.rs](contracts/controller/src/positions/liquidation/math.rs))

### Summary
A solvent-but-liquidatable account whose only collateral uses fewer than 3 decimals can lose an entire collateral unit for a repayment worth less than that unit after the quoted liquidation bonus. The boundary in `whole_unit_repayment` promotes the quote to total debt whenever `floor(unit_value / (1 + bonus)) >= debt + per-leg-unit-rounding`, without checking that the unit's full value is bounded by `debt * (1 + bonus)`. [1](#0-0) 

### Finding Description
`normalize_repayment_plan` invokes `whole_unit_repayment` for a solvent account when the ordinary liquidation quote is below total debt. [2](#0-1)  For a sole collateral leg below `MIN_BORROWABLE_ASSET_DECIMALS`, `whole_unit_repayment` computes `unit_at_bonus = floor(U / (1 + bonus))` and compares it with `total_debt + one_unit_per_debt_leg_usd`. [3](#0-2)  If that comparison succeeds, it returns `snap.total_debt`, making `full_close` true. [4](#0-3) 

`calculate_seized_collateral` then treats the low-decimal leg specially: when the plan repays all debt, it ceiling-rounds the seizure to a whole unit and caps it only at the victim's held amount. [5](#0-4)  Because the collateral value `U` can exceed `debt * (1 + bonus)` under `HF < 1`, the liquidator receives value above the protocol's configured bonus. For `k` held units and liquidation threshold `LT`, the effective bonus is bounded by approximately `1 / (k * LT) - 1`, rather than by the stamped liquidation bonus. [6](#0-5) 

### Impact Explanation
An unprivileged liquidator can call `liquidate(liquidator, account_id, debt_payments, SeizeMode::Transfer)` and receive collateral worth more than `repayment * (1 + bonus)`. The excess is a direct transfer of the victim's collateral, so this is theft of user funds. `process_liquidation` accepts and executes the plan produced by this boundary logic. [7](#0-6) 

The loss per affected leg is approximately:

```text
loss = U - D * (1 + bonus)
```

whenever:

```text
HF < 1
C >= D
floor(U / (1 + bonus)) >= D + R
```

where `R` is the USD value of one native unit per debt leg. On a listed low-decimal asset with a low liquidation threshold, this can substantially exceed the intended liquidation bonus. [8](#0-7) 

### Likelihood Explanation
The attack requires a liquidatable account with exactly one supply position, an asset below three decimals, at least one whole unit remaining, and debt lying in the boundary band where the unit's discounted value covers the whole debt. These states can occur naturally after earlier partial liquidations or interest accrual, and `liquidate` is permissionless. [9](#0-8) 

The condition is not universally reachable for every account or configuration. It is bounded to low-decimal collateral and requires the liquidation bonus and liquidation threshold to make `floor(U / (1 + bonus)) >= D + R` coexist with `HF < 1`. [10](#0-9) 

### Recommendation
Do not promote the quote to `snap.total_debt` solely because `unit_at_bonus >= D + R`. Instead, size the repayment so the seized unit is economically bounded by the selected bonus, for example by requiring `U <= D * (1 + bonus) + accepted_rounding` before taking the full-close branch. Alternatively, cap the seized low-decimal amount to the exact repayment-plus-bonus equivalent instead of ceiling-rounding the entire unit. [11](#0-10) 

Add a regression test where `HF < 1`, `C >= D`, and `U > D * (1 + bonus)`, asserting that the liquidator's received collateral value never exceeds the configured bonus except for an explicitly bounded native-unit rounding error.

### Proof of Concept
1. Configure or identify a collateral asset with fewer than three decimals, a liquidation threshold `LT`, and stamped bonus `b`.
2. A victim holds `k` units of that collateral as its only supply position, with unit value `U`, and owes total risk debt `D` such that:
   ```text
   k * U * LT < D          // HF < 1
   k * U >= D              // account is not insolvent by total collateral
   floor(U / (1 + b)) >= D + R
   ```
3. The attacker calls:
   ```rust
   controller.liquidate(
       attacker,
       victim_account_id,
       vec![(debt_hub_asset, debt_amount)],
       SeizeMode::Transfer,
   )
   ```
   offering the debt leg up to its ceiling-rounded balance.
4. `whole_unit_repayment` returns `snap.total_debt`, marking the plan as a full close. [12](#0-11) 
5. `calculate_seized_collateral` ceiling-rounds the collateral seizure to one whole unit and the pool transfers it to the attacker. [13](#0-12) 
6. The attacker paid approximately `D` but received `U`; since `U > D * (1 + b)`, the excess over the configured liquidation bonus is extracted from the victim.

**File:** skills/xoxno-lending/math.md (L399-413)
```markdown
Whole-unit quote for a collateral leg below 3 decimals. It applies only when the account is solvent (`C ≥ D`), the curve quote `ideal` is below `D`, the leg is the account's only supply position, and it holds at least one whole unit (one base unit at the asset's decimals). Let `U` be the WAD USD value of one whole unit. The first matching rule applies:

```text
R             = Σ over debt legs of the WAD USD value of one base unit of that debt token
unit_at_bonus = floor(U × WAD / one_plus_b)
margin        = max(floor(U / 1_000_000), 1)                           // raw WAD
raised        = ceil((U + margin) × WAD / one_plus_b)
if unit_at_bonus ≥ D + R:                                      ideal = D       // full close; the leg rounds up to one unit
elif half_up(ideal × one_plus_b / WAD) < U + margin and raised < D: ideal = raised  // seize one unit, refund the margin
else:                                                          ideal unchanged
```

The raised seizure takes one unit and refunds the unseized margin, rounded down to whole debt-token units. The raised quote is a ceiling: a smaller offer is not raised, an offer that backs less than one unit seizes nothing and reverts with `InvalidPayments`, and an offer between `U / one_plus_b` and `raised` still takes one unit. The raised quote is not promoted to full debt (`D − raised` can be below 5 WAD). The HF-preserving cap keeps `one_plus_b ≤ C / D`, so a one-unit sale does not lower `C / D`, and such an account stays liquidatable below `HF = 1`. The exception is `unit_at_bonus − R < D ≤ raised`: no rule changes the quote, and if the curve quote backs less than one unit, every offer reverts until accrual or a price move ends that state.

A rule-1 full close gives the liquidator one unit worth `U` for `D`: the effective bonus is `U / D − 1`, not `b`. With `k` held units and liquidation threshold `LT`, `HF < 1` bounds it at about `1 / (k × LT) − 1`. The borrower loses `U − D × one_plus_b / WAD` above the normal bonus. `bonus_rate_bps` and the `LiquidationEvent` `bonus_bps` show only `b`; a listing below 3 decimals has no liquidation fee. Size offers for such a leg from `get_liquidation_estimate`, not from the close-amount formula above.
```
