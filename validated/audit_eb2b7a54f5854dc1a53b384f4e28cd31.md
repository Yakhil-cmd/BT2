### Title
`ProxyType::NonTransfer` on Asset Hub Rococo still fails open, permitting value-moving calls the proxy is documented to deny - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
The `ProxyType::NonTransfer` filter on the Asset Hub Rococo runtime is documented as "can execute any call that does not transfer funds or assets," but is implemented as a deny-list that only lists `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques`. Any other value-moving pallet configured in this runtime is reachable by a `NonTransfer` proxy. This is the exact same bug class already identified and fixed on Asset Hub Westend (issue [paritytech/polkadot-sdk#12466](https://github.com/paritytech/polkadot-sdk/issues/12466), fixed via [pr_12769](../prdoc/pr_12769.prdoc) and [pr_12771](../prdoc/pr_12771.prdoc)), but the corresponding fix was never applied to Asset Hub Rococo.

### Finding Description
`pallet_proxy` lets a delegate holding a `NonTransfer` proxy dispatch any `RuntimeCall` for which `InstanceFilter::filter` returns `true`. On Asset Hub Rococo the filter is: [1](#0-0) 

This is a deny-list ("fails open"): only `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques` calls are denied. Per the doc comment above the enum, `NonTransfer` should permit "any call that does not transfer funds or assets" — i.e., it is supposed to be a semantic guarantee, not a fixed list of known pallets: [2](#0-1) 

The same runtime configures additional pallets that move a caller's funds/assets but are absent from the deny list, including a second and third instance of `pallet_assets` (`ForeignAssets`, `PoolAssets`), `pallet_asset_conversion` (`AssetConversion`), `pallet_xcm` (`PolkadotXcm`), and `pallet_indices` (whose `transfer`/`force_transfer` repatriate reserved deposits) — confirmed present via `grep_search` for their construct_runtime declarations. Since none of these are matched by the `NonTransfer` arm's `matches!(...)` pattern, `filter()` returns `true` for calls like `ForeignAssets::transfer`, `PoolAssets::transfer`, `AssetConversion::swap_exact_tokens_for_tokens`, `PolkadotXcm::transfer_assets`/`teleport_assets`, and `Indices::transfer`/`force_transfer`.

This is precisely the bug that was identified as issue #12466 and fixed for Asset Hub Westend: [3](#0-2) 

and regression-tested there: [4](#0-3) 

However, Asset Hub Rococo's `ProxyType::NonTransfer` implementation was never updated to add the missing pallets to the deny list, so the same fail-open condition remains live there.

### Impact Explanation
A user who has delegated a `NonTransfer` proxy — intending to authorize a hot/less-trusted key for non-value-moving operations only, per the pallet's own documentation — unknowingly grants that delegate the ability to move funds and assets via `ForeignAssets`, `PoolAssets`, `AssetConversion` swaps/liquidity operations, and `PolkadotXcm` cross-chain transfers, as well as `Indices::transfer`/`force_transfer` to reassign a reserved index deposit. This breaks the access-control invariant the proxy type is documented to enforce and can lead to unauthorized transfer/theft of the proxied account's assets by a delegate that was only meant to have non-transfer permissions — directly analogous to the vault `transferWhitelist` bypass in the source report, where a protection mechanism silently has no effect.

### Likelihood Explanation
Likelihood is high for any account that has actually set up a `NonTransfer` proxy on Asset Hub Rococo and relies on the documented guarantee, since the delegate itself is the "attacker" here (no privileged role or stolen keys needed — the delegate already holds a legitimately-granted, restricted proxy and merely dispatches an in-scope, permitted call type). Asset Hub Rococo is an active Rococo testnet runtime with a live `pallet_proxy` deployment and these value-moving pallets enabled, so the call surface is reachable through the standard `Proxy::proxy` extrinsic without needing any additional wiring.

### Recommendation
Add `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Indices::transfer`/`Indices::force_transfer` to the `NonTransfer` deny-list in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs`, mirroring the fix already applied to Asset Hub Westend in [pr_12771](../prdoc/pr_12771.prdoc), and add a corresponding regression test analogous to `non_transfer_proxy_rejects_value_moving_calls` for the Rococo runtime. More robustly, consider converting `NonTransfer` to an allow-list (or auditing it against every pallet added to `construct_runtime!`) so future pallet additions cannot silently reopen this gap.

### Proof of Concept
No executable PoC was run against a live network, per constraints. The finding is supported by static comparison of the two runtimes' `InstanceFilter` implementations:
- Asset Hub Westend's fixed filter and its regression test (`non_transfer_proxy_rejects_value_moving_calls`) explicitly enumerate the pallets that must be denied: [4](#0-3) 
- Asset Hub Rococo's current filter lacks these entries: [5](#0-4) 

A minimal Rust integration test to confirm the failed guard would follow the same pattern as the Westend regression test — construct a `RuntimeCall::ForeignAssets(pallet_assets::Call::transfer { .. })` (or `PoolAssets`/`AssetConversion`/`PolkadotXcm`/`Indices::transfer`) on the `asset-hub-rococo-runtime`, and assert `!ProxyType::NonTransfer.filter(&call)`; today this assertion would fail (i.e., `filter` returns `true`), demonstrating the bypass. I was not able to execute this test in this session since I only have read access to the codebase; a background Devin session with build/test tooling would be needed to actually run and confirm the assertion failure.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
