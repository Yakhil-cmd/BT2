### Title
`writeServiceChainTxReceipts` Advances Anchored Block Number Without Validating Receipt Status — (`node/sc/sub_bridge_handler.go`)

### Summary

`writeServiceChainTxReceipts` in `node/sc/sub_bridge_handler.go` processes receipts received from the parent chain over P2P without checking `receipt.Status`. A failed anchoring transaction (Status = 0) causes the sub-bridge to permanently advance `anchoredBlockNumber` and remove the transaction from the retry pool, silently losing the anchoring record for that child-chain block.

### Finding Description

`writeServiceChainTxReceipts` is called from `handleParentChainReceiptResponseMsg` whenever the sub-bridge receives a `ServiceChainReceiptResponseMsg` from a parent-chain peer:

```go
// node/sc/sub_bridge_handler.go:436-461
func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
    for _, receipt := range receipts {
        txHash := receipt.TxHash
        if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
            if tx.Type().IsChainDataAnchoring() {
                ...
                sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
                sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
            }
            sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)  // tx removed unconditionally
        }
    }
}
```

There is no check on `receipt.Status` before:
1. Writing the receipt to the DB via `WriteReceiptFromParentChain`
2. Advancing the persistent anchored block number via `WriteAnchoredBlockNumber`
3. Removing the transaction from the bridge tx pool (preventing any retry)

`WriteAnchoredBlockNumber` only guards against going backwards, not against recording a failed execution:

```go
// node/sc/sub_bridge_handler.go:587-591
func (sbh *SubBridgeHandler) WriteAnchoredBlockNumber(blockNum uint64) {
    if sbh.GetLatestAnchoredBlockNumber() < blockNum {
        sbh.subbridge.chainDB.WriteAnchoredBlockNumber(blockNum)
        ...
    }
}
```

The parent-chain main bridge sends real blockchain receipts (including failed ones with `Status = 0`) in `handleServiceChainReceiptRequestMsg`:

```go
// node/sc/main_bridge_handler.go:189-194
receipt := mbh.mainbridge.blockchain.GetReceiptByTxHash(hash)
if receipt == nil {
    continue
}
receiptsForStorage = append(receiptsForStorage, (*types.ReceiptForStorage)(receipt))
```

No status filtering occurs on the sender side either.

### Impact Explanation

When a `TxTypeChainDataAnchoring` transaction is included in a parent-chain block but its EVM execution fails (Status = 0):

- `WriteAnchoredBlockNumber` permanently advances the sub-bridge's anchored block pointer to the child-chain block number embedded in the anchoring payload.
- The failed tx is removed from the bridge tx pool, so no automatic retry occurs.
- The child-chain block whose data was supposed to be anchored is now permanently skipped — the anchoring record is lost.

This is persistent corruption of the `anchoredBlockNumber` state: the sub-bridge believes a block has been anchored on the parent chain when it has not. Any downstream consumer of `ReadAnchoredBlockNumber` (e.g., monitoring, cross-chain proofs) will observe an incorrect anchoring frontier.

### Likelihood Explanation

Anchoring transactions fail in practice. The codebase itself handles one such failure path (`ErrGasPriceBelowBaseFee`) in `handleParentChainInvalidTxResponseMsg`, but that path covers only transactions rejected before execution. Transactions that are included in a block but revert (e.g., due to nonce collision, out-of-gas, or contract-level revert) return a receipt with `Status = 0` through the normal receipt-response path, which is the path that lacks the status check.

### Recommendation

Add a receipt status check before writing the anchoring record and removing the transaction:

```go
if tx.Type().IsChainDataAnchoring() {
    ...
    if receipt.Status != types.ReceiptStatusSuccessful {
        logger.Error("anchoring tx failed on parent chain, skipping", "txHash", txHash)
        // Do NOT remove from pool; allow VT recovery or manual retry
        continue
    }
    sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
    sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
}
sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
```

### Proof of Concept

1. Sub-bridge submits a `TxTypeChainDataAnchoring` transaction anchoring child-chain block N to the parent chain.
2. The transaction is included in a parent-chain block but fails (e.g., out-of-gas or nonce conflict), producing a receipt with `Status = 0`.
3. Sub-bridge calls `broadcastServiceChainReceiptRequest`, which sends the tx hash to the parent peer.
4. Parent peer's `handleServiceChainReceiptRequestMsg` fetches the failed receipt and sends it back.
5. Sub-bridge's `handleParentChainReceiptResponseMsg` → `writeServiceChainTxReceipts` processes the receipt without checking `receipt.Status`.
6. `WriteAnchoredBlockNumber(N)` is called, advancing the anchored block pointer to N.
7. The tx is removed from the bridge tx pool.
8. Child-chain block N's data is never actually anchored; the sub-bridge permanently believes it was. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
	for _, receipt := range receipts {
		txHash := receipt.TxHash
		if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
			if tx.Type().IsChainDataAnchoring() {
				data, err := tx.AnchoredData()
				if err != nil {
					logger.Error("failed to get anchoring data", "txHash", txHash.String(), "err", err)
					continue
				}
				decodedData, err := types.DecodeAnchoringData(data)
				if err != nil {
					logger.Warn("failed to decode anchoring tx", "txHash", txHash.String(), "err", err)
					continue
				}
				sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
				sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
			}
			// TODO-Kaia-ServiceChain: support other tx types if needed.
			sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
		} else {
			logger.Trace("received service chain transaction receipt does not exist in sentServiceChainTxs", "txHash", txHash.String())
		}
		logger.Trace("received service chain transaction receipt", "anchoring txHash", txHash.String())
	}
}

// handleServiceChainReceiptRequestMsg handles receipt request message from child chain.
// It will find and send corresponding receipts with given transaction hashes.
func (mbh *MainBridgeHandler) handleServiceChainReceiptRequestMsg(p BridgePeer, msg p2p.Msg) error {
	// Decode the retrieval message
	msgStream := rlp.NewStream(msg.Payload, uint64(msg.Size))
	if _, err := msgStream.List(); err != nil {
		return err
	}
	// Gather state data until the fetch or network limits is reached
	var (
		hash               common.Hash
		receiptsForStorage []*types.ReceiptForStorage
	)
	for len(receiptsForStorage) < downloader.MaxReceiptFetch {
		// Retrieve the hash of the next block
		if err := msgStream.Decode(&hash); err == rlp.EOL {
			break
		} else if err != nil {
			return errResp(ErrDecode, "msg %v: %v", msg, err)
		}
		// Retrieve the receipt of requested service chain tx, skip if unknown.
		receipt := mbh.mainbridge.blockchain.GetReceiptByTxHash(hash)
		if receipt == nil {
			continue
		}

		receiptsForStorage = append(receiptsForStorage, (*types.ReceiptForStorage)(receipt))
	}
	if len(receiptsForStorage) == 0 {
		return nil
	}
	return p.SendServiceChainReceiptResponse(receiptsForStorage)
