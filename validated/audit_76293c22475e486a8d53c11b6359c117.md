### Title
Incomplete deny-list in `ProxyType::NonTransfer` allows fund/asset transfer bypass on Asset Hub Rococo and the staking-async parachain runtime - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`pallet-proxy`'s `ProxyType::NonTransfer` is documented as a proxy that "can execute any call that does not transfer funds or assets" but is implemented as a deny-list that only lists specific `RuntimeCall` variants. On Asset Hub Rococo (and, to a lesser degree, the `staking-async` parachain runtime), the list omits `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm` (where present), `PolkadotXcm`, `Revive`, and `Indices::transfer`/`force_transfer`. This is structurally identical to the CVE-2024-23336 pattern: a security-relevant blocklist that is incomplete, so anything not explicitly enumerated is implicitly allowed ("fails open"), letting a supposedly-restricted delegate reach unintended sensitive operations.

### Finding Description
`InstanceFilter<RuntimeCall>::filter` for `ProxyType::NonTransfer` in `asset-hub-rococo` negates a `matches!` deny-list covering only `Balances`, `Assets`, `NftFractionalization`, `Nfts`, `Uniques` [7](#0-6) . Any pallet call not in that list — including `ForeignAssets::transfer`, `PoolAssets::transfer`, `AssetConversion::swap_exact_tokens_for_tokens`, `PolkadotXcm::transfer_assets`, `Revive::call` (with `value`), and `Indices::transfer`/`force_transfer` — passes the filter and is dispatchable by a `NonTransfer` delegate. This is precisely the class of bug that was already identified and fixed for the near-identical Asset Hub Westend runtime in issue #12466 and `pr_12771.prdoc` [8](#0-7) , whose corrected list is visible in `asset-hub-westend/src/lib.rs` [9](#0-8) . The fix's `prdoc` only bumped `asset-hub-westend-runtime`, so the parallel, structurally identical Rococo runtime was left with the pre-fix deny-list. The `staking-async` parachain runtime received a narrower fix (`pr_12922.prdoc`, only `ForeignAssets`/`PoolAssets`) [5](#0-4)  but its current filter [6](#0-5)  still omits `AssetConversion`, `PolkadotXcm`, `Revive`, and `Indices::transfer`/`force_transfer`, matching the remaining gaps fixed on Westend.

### Impact Explanation
A user who grants a `ProxyType::NonTransfer` delegation — expecting the delegate to be unable to move their funds or assets, per the documented semantics and the `pallet_proxy` `add_proxy` flow — can have that delegate execute `ForeignAssets`/`PoolAssets` transfers, swap/burn assets via `AssetConversion`, move assets cross-chain via `PolkadotXcm::transfer_assets`/`teleport_assets`, call `Revive` contracts carrying value, or repatriate reserved deposits via `Indices::transfer`/`force_transfer`, all fully attacker-controlled given only a `NonTransfer` delegation (no privileged role required). This is a proxy authorization bypass leading to unauthorized asset movement — a direct theft/loss-of-funds vector, matching or exceeding the severity class of the reference CVE.

### Likelihood Explanation
Exploitation requires only: (1) a victim to add a `NonTransfer` proxy for their account via `pallet_proxy::add_proxy` (a normal, encouraged usage pattern for "safe" delegation), and (2) the delegate account to submit any of the un-denied calls via `Proxy::proxy`. No governance, no stolen keys, and no privileged origin are needed — this matches the required "no privileged role" attacker model exactly, and the identical bug class was already confirmed exploitable and fixed on the sibling Westend runtime.

### Recommendation
Mirror the `pr_12771` fix onto `asset-hub-rococo` (and complete the `pr_12922` fix onto `pallet-staking-async-parachain-runtime`): extend the `ProxyType::NonTransfer` deny-list to also deny `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm` (where applicable), `PolkadotXcm`, `Revive`, and `Indices::transfer`/`force_transfer`. More durably, consider replacing deny-list semantics with an explicit allow-list (or a shared, tested constant) so newly added pallets do not silently become reachable by a "NonTransfer" delegate by default — precisely the "fails open" pattern flagged in the CVE analogy.
