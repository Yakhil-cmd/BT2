### Title
Webhook signature check keys off `repository.owner.login` while handlers act on `repository.full_name`, letting a no-secret org's forged `pull_request` payload mutate a different repository's PR record - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` resolves the signing `GitHubApp` using `repository.owner.login` (falling back to `organization.login`) from the raw JSON body, but `Shipit::Webhooks::Handlers::PullRequest::AssignedHandler` (and its siblings) locate the target `Repository`/`PullRequest` using the independent `repository.full_name` field from the same body. Because the two fields are never checked for consistency, and `GitHubApp#verify_webhook_signature` trivially returns `true` when the resolved org's `webhook_secret` is blank, an attacker can set `repository.owner.login` to any configured no-secret org while pointing `repository.full_name` at a victim repository, bypassing signature verification entirely and mutating the victim's PR/stack state.

### Finding Description
The broken binding is: the org that `verify_signature` authenticates against must equal the org that owns the repository the handler subsequently mutates, i.e. `Shipit.github(organization: params.dig('repository','owner','login'))` == `Shipit::Repository.from_github_repo_name(params.repository.full_name).owner`. This is never enforced.

Path:
- `Shipit::WebhooksController#verify_signature` computes `repository_owner` purely from attacker-controlled JSON: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) , then calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [2](#0-1) .
- `GitHubApp#verify_webhook_signature` short-circuits to `true` when the resolved org's `webhook_secret` is blank: `return true unless webhook_secret` [3](#0-2) . Multiple orgs can be configured under `secrets.github`, each with its own (optionally blank) `webhook_secret`, resolved via `Shipit.github_app_config(organization)` [4](#0-3) .
- Once past `verify_signature`, `Shipit::Webhooks.for_event('pull_request')` fans the parsed body out to all PR handlers, including `AssignedHandler` [5](#0-4) , [6](#0-5) .
- `AssignedHandler#repository` resolves the target repo from `params.repository.full_name` — a wholly separate field from the one used for signature verification: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [7](#0-6) . It then finds and updates the matching `PullRequest` row for that repository/stack: `Shipit::PullRequest.joins(...).find_by(number: params.number, stacks: { repositories: { id: repository.id } })` followed by `pull_request.update(github_pull_request: params.pull_request)` [8](#0-7) .

Exploit: attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature` (or any junk value), and a JSON body where `repository.owner.login` = `"no-secret-org"` (an org configured in Shipit's `secrets.github` map but with `webhook_secret` unset/blank) while `repository.full_name` = `"victim-org/victim-repo"` (the real target). `verify_signature` authenticates against `no-secret-org`'s (secret-less) `GitHubApp`, which returns `true` unconditionally, so the request passes with `head(422)` never triggered. The handler then updates the `PullRequest` belonging to `victim-org/victim-repo`'s stack using entirely attacker-supplied `github_pull_request` data (title, labels, additions/deletions, head sha/ref, assignees), because `action: "assigned"` satisfies `respond_to_assignee_change?`.

Existing guards fail: `drop_unhandled_event` only checks whether handlers are registered for the event type, not the payload's internal consistency [9](#0-8) . `GithubOrganizationUnknown` is only raised for orgs absent from config, not for known orgs with a blank secret [10](#0-9) . No code path re-derives or checks that the org used for signing matches the org owning `repository.full_name`.

### Impact Explanation
A payload authenticated under one (secret-less) organization's identity is used to write state (`PullRequest#github_pull_request`) belonging to a completely different, victim repository/stack, satisfying the "payload for one repository mutating another's stack" Critical category. This is repeatable against any repository configured in Shipit as long as at least one other configured org has no `webhook_secret` set — a configuration weakness that is plausible in multi-org GitHub App setups where some orgs are onboarded without webhook secrets configured. The blast radius spans every repository/stack Shipit tracks, since any repo can be targeted via `repository.full_name` regardless of which org's key is used to pass signature verification. Similar reasoning extends to the other `PullRequest` handlers (`Opened`, `Closed`, `Reopened`, `Labeled`, etc.), which use the same `full_name`-based repository resolution pattern, broadening the blast radius (e.g. closing/merging state transitions, label-driven automation) beyond just the `assigned` case named in the question.

### Likelihood Explanation
Preconditions: Shipit must be configured with multiple GitHub orgs under `secrets.github` (the multi-org schema, detected via `github_default_organization`), and at least one configured org must have a blank/absent `webhook_secret`. No Shipit session, API token, or GitHub secret is required by the attacker — only knowledge (or a guess) of a configured org name with no secret, which is discoverable via repeated probing (each org attempt returns 422 for wrong/unknown orgs vs 200 for accepted ones, providing an oracle). Attacker cost is a single unauthenticated HTTP POST; the attack is fully repeatable.

### Recommendation
Do not derive the signature-verification org independently from the record-mutation target. Either (a) require every configured org to have a non-blank `webhook_secret` and reject/refuse startup or webhook delivery otherwise, or (b) after signature verification, derive `repository_owner` used for verification and re-validate that it equals the owner segment of `params.repository.full_name` (and of `params.organization.login` when present) before dispatching to handlers, rejecting the request with `422` on mismatch.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb` (or an equivalent handler test), simulating multi-org config with one no-secret org:

1. Configure `Shipit.stub(:github_app_config)` (or stub `Rails.application.credentials.github`) so that `Shipit.github(organization: 'no-secret-org')` returns a `GitHubApp` whose `webhook_secret` is blank, and separately create a real `Shipit::Stack`/`Shipit::Repository` for `"victim-org/victim-repo"` with an existing `Shipit::PullRequest` (number: 42, some known `github_pull_request` state).
2. Assert binding before: `pull_request.github_pull_request['title']` == original title.
3. POST `/webhooks` with header `X-Github-Event: pull_request`, an invalid/empty `X-Hub-Signature`, and body:
```json
{
  "action": "assigned",
  "number": 42,
  "pull_request": { "id": 1, "number": 42, "url": "...", "title": "ATTACKER TITLE",
    "state": "open", "additions": 1, "deletions": 1,
    "head": { "sha": "deadbeef", "ref": "attacker-branch" },
    "user": { "login": "attacker" }, "assignees": [{"login": "attacker"}], "labels": [] },
  "repository": { "owner": { "login": "no-secret-org" }, "full_name": "victim-org/victim-repo" },
  "sender": { "login": "attacker" }
}
```
4. Assert response is `200`, not `422`.
5. Reload `pull_request` and assert `pull_request.github_pull_request['title'] == 'ATTACKER TITLE'`, proving the equality `signing_org == owning_org` was violated and a victim record was mutated by a payload authenticated under a different org's (secret-less) identity.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
