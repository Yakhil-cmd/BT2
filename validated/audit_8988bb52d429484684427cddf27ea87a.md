### Title
Cross-organization webhook forgery: signature verified against attacker's org, but repository acted upon comes from an unrelated payload field - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate a webhook against using `repository_owner`, which is read straight from the untrusted JSON body (`repository.owner.login`, falling back to `organization.login`). Once the HMAC check passes, the whole raw payload is handed unmodified to the event handlers, which determine the actual `Repository`/`Stack` to mutate from a *different* field of the same body: `repository.full_name`. Because these two fields are never cross-checked against each other, an attacker who controls a legitimately configured GitHub organization on a multi-tenant Shipit instance can sign a webhook with their own `webhook_secret` while pointing `repository.full_name` at a victim organization's repository, causing Shipit to act on that victim's stack.

### Finding Description
- `Shipit.github(organization:)` looks up a `GitHubApp` (and its `webhook_secret`) per organization, supporting the documented multi-org config shown in `config/secrets.development.shopify.yml` and `docs/setup.md`. [1](#0-0) 

- `WebhooksController#verify_signature` derives `repository_owner` purely from the attacker-controlled body and uses it to pick which org's secret to verify the `X-Hub-Signature` HMAC against: [2](#0-1) 

- After verification succeeds, `create` dispatches the *entire raw payload* to the registered handlers for the event, without re-deriving or constraining which repository they may touch to the one implied by `repository_owner`: [3](#0-2) 

- Every handler (base `Handler`, `PushHandler`, `StatusHandler` via `Commit.where(sha:)`, the `PullRequest::*Handler`s) resolves the target repository from `payload.dig('repository', 'full_name')` — a field entirely independent from `repository.owner.login` used for signature selection: [4](#0-3) [5](#0-4) [6](#0-5) 

- `Repository.from_github_repo_name` parses that unchecked string directly into an `owner`/`name` DB lookup with no relation to the org that was cryptographically verified: [7](#0-6) 

**Equality broken:** `organization authenticated` (`repository.owner.login` used to select `webhook_secret`) ≠ `repository written` (`repository.full_name` used to select the `Repository`/`Stack` mutated). Before the attack, these two fields are supposed to describe the same GitHub repository (as in a genuine GitHub-originated webhook); after the attack, they can name two unrelated organizations, and the code performs no equality check between them.

This is a structural analog of the `https-proxy-agent` bug: a security check (TLS upgrade / signature verification) is performed on one channel/attribute, while the subsequent privileged action (forwarding request data / mutating a repository's stack) is keyed off a different, unverified attribute of the same transaction.

### Impact Explanation
On a multi-tenant Shipit deployment (the officially supported configuration, cf. `config/secrets.development.shopify.yml`), any organization that has its own `webhook_secret` configured can forge webhooks that act on **any other organization's repositories/stacks** registered on the same instance:
- `PushHandler` can force `stack.sync_github(expected_head_sha: <attacker chosen sha>)` on a victim stack.
- `StatusHandler` can inject arbitrary commit statuses (`create_status_from_github!`) for any commit whose `sha` the attacker knows, potentially satisfying deployability/CI checks that gate deploys.
- `PullRequest::*Handler`s can create, archive, or unarchive review stacks belonging to a victim repository.

This is a cross-repository/cross-organization write that bypasses the intended per-org isolation of the webhook signing scheme, matching the "cross-repository writes" / "unauthorized deploy" impact tier. I was not able to fully trace whether forged commit statuses alone can flip `continuous_deployment` gating to trigger an actual unauthorized deploy end-to-end (that requires deeper review of `Stack#sync_github` and `ContinuousDeliveryJob`, which I could not fully verify in the time available), but the cross-repository/cross-stack write itself is concretely demonstrated.

### Likelihood Explanation
Requires the instance to run with multiple organizations configured (documented, supported feature) and requires the attacker to control one of those organizations (i.e., possess/derive a legitimate `webhook_secret` for their own org via their own installed GitHub App) — no privileged access to the victim org, no `ApiClient` token, and no GitHub credentials of the victim are needed. This is a realistic scenario for any Shipit instance shared across multiple GitHub orgs (e.g., an internal platform team hosting deploys for many teams/orgs).

### Recommendation
In `WebhooksController#verify_signature`, after signature verification succeeds, assert that the organization implied by `params.dig('repository','full_name')` (or `params.dig('organization','login')`) matches the `repository_owner` whose `webhook_secret` was used to verify the signature, and reject the request (422) if they diverge. Equivalently, have each `Handler` receive/validate the already-verified `repository_owner` rather than independently trusting `repository.full_name` from the raw, only-partially-verified payload.

### Proof of Concept
1. Configure a multi-org Shipit instance with organizations `attacker-org` and `victim-org`, each with its own GitHub App / `webhook_secret` (per `config/secrets.development.shopify.yml` schema).
2. Attacker legitimately owns `attacker-org` and knows its `webhook_secret` (e.g., set it themselves in their own GitHub App settings).
3. Attacker POSTs to the Shipit webhooks endpoint:
   ```
   POST /github_hooks
   X-Github-Event: push
   X-Hub-Signature: sha1=<HMAC-SHA1 of body using attacker-org's webhook_secret>

   {
     "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" },
     "ref": "refs/heads/master",
     "after": "<attacker chosen sha>"
   }
   ```
4. `verify_signature` computes `repository_owner = "attacker-org"`, fetches `attacker-org`'s `GitHubApp`, and the HMAC check passes (signed correctly with attacker's own secret).
5. `PushHandler.process` runs `Repository.from_github_repo_name("victim-org/victim-repo")`, finds the real victim `Stack`, and calls `stack.sync_github(expected_head_sha: "<attacker chosen sha>")` — a write against a repository the attacker was never authenticated for.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
```
