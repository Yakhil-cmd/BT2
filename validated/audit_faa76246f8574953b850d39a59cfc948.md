The Palmera report describes a hardcoded, manually-computed `PALMERA_TX_TYPEHASH` constant that doesn't match `keccak256` of its own EIP-712 type string — a copy/paste-style miscalculation that breaks EIP-712 signature verification. Searching the polkadot-sdk codebase for an analogous pattern (EIP-712/EIP-2612 typehash or domain-separator constants), the only real usage is in the new `pallet_assets` precompile permit implementation.

There, `DOMAIN_TYPEHASH` and `PERMIT_TYPEHASH` are not hardcoded hex literals — they are computed at compile time directly from the canonical EIP-712 type strings via `const_crypto::sha3::Keccak256`, which structurally eliminates the exact bug class reported (a manually-computed/copy-pasted incorrect hash constant) [1](#0-0) . The domain separator and struct hash are then assembled by concatenating the typehash with ABI-encoded fields, matching the standard EIP-712/EIP-2612 layout [2](#0-1) . There is also an explicit regression test asserting `PERMIT_TYPEHASH` equals `keccak256` of the exact canonical string [3](#0-2) , and further tests verifying the domain separator is deterministic and varies correctly per verifying contract and token name [4](#0-3) .

No other hardcoded typehash/domain-separator constants exist elsewhere in the codebase (e.g., EIP-7702 authorization signing in `pallet_revive` uses direct RLP/signature recovery rather than an EIP-712 typehash) [5](#0-4) . Since the compile-time hash derivation removes the possibility of a manually miscalculated constant, there is no demonstrable Polkadot SDK analog to this specific bug class.

		/// Compute the EIP-712 domain separator for a given verifying contract.
		///
		/// DOMAIN_SEPARATOR = keccak256(abi.encode(
		///   keccak256("EIP712Domain(string name,string version,uint256 chainId,address
		/// verifyingContract)"),
		///   keccak256(name),
		///   keccak256("1"),
		///   chainId,
		///   verifyingContract
		/// ))
		///
		/// The `name` parameter should be the token name per EIP-2612 specification.
		pub fn compute_domain_separator(verifying_contract: &H160, name: &[u8]) -> H256 {
			let name_hash = keccak_256(name);
			let version_hash = keccak_256(b"1");
			let chain_id = T::ChainId::get();

			// Encode: typehash || name_hash || version_hash || chainId || verifyingContract
			let mut data = Vec::with_capacity(DOMAIN_SEPARATOR_ENCODED_LEN);
			data.extend_from_slice(&DOMAIN_TYPEHASH);
			data.extend_from_slice(&name_hash);
			data.extend_from_slice(&version_hash);
			// Pad chain_id to 32 bytes (big-endian)
			data.extend_from_slice(&[0u8; 24]);
			data.extend_from_slice(&chain_id.to_be_bytes());
			// Pad address to 32 bytes
			data.extend_from_slice(&[0u8; 12]);
			data.extend_from_slice(verifying_contract.as_bytes());

			H256(keccak_256(&data))
		}

		/// Compute the EIP-712 struct hash for a permit.
		///
		/// structHash = keccak256(abi.encode(
		///   PERMIT_TYPEHASH,
		///   owner,
		///   spender,
		///   value,
		///   nonce,
		///   deadline
		/// ))
		pub fn permit_struct_hash(
			owner: &H160,
			spender: &H160,
			value: &[u8; 32], // U256 as bytes (big-endian)
			nonce: &U256,
			deadline: &[u8; 32], // U256 as bytes (big-endian)
		) -> H256 {
			let mut data = Vec::with_capacity(PERMIT_STRUCT_ENCODED_LEN);
			data.extend_from_slice(&PERMIT_TYPEHASH);
			// owner (padded to 32 bytes)
			data.extend_from_slice(&[0u8; 12]);
			data.extend_from_slice(owner.as_bytes());
			// spender (padded to 32 bytes)
			data.extend_from_slice(&[0u8; 12]);
			data.extend_from_slice(spender.as_bytes());
			// value (already 32 bytes)
			data.extend_from_slice(value);
			// nonce (convert U256 to 32 bytes big-endian)
			data.extend_from_slice(&nonce.to_big_endian());
			// deadline (already 32 bytes)
			data.extend_from_slice(deadline);

			H256(keccak_256(&data))
		}
