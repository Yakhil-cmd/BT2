The s3-proxy report concerns a Go HTTP proxy's URL path routing: mismatched handling between `net/http`'s decoded `r.URL.Path` and encoded `r.URL.RequestURI()`/`RawPath`, combined with a `glob.Compile` call missing a `/` separator, allowing `*` to cross path segments and enabling auth bypass via `%2F` encoding and `..` traversal.

Polkadot SDK has no analogous surface. XCM location/asset matching (e.g., `StartsWith`, `MatchedConvertedConcreteId` in [1](#0-0)  and [2](#0-1) ) operates on structurally-typed `Location`/`Junction` values compared via SCALE-encoded equality and prefix checks — there is no string-based glob compilation, no percent-encoding/decoding step, and no dual-representation ambiguity (encoded vs. decoded) analogous to `RawPath` vs. `Path`. Extrinsic dispatch, XCM barriers, and pallet call filtering do not route based on textual path patterns; they match on strongly-typed enums and origins, so the root cause (two different string representations of the same resource being matched by different layers) has no equivalent code path here.
