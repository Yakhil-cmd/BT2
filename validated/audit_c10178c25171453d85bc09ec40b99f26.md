### Title
Deterministic assert_eq! panic when a stake account's delegation is modified between epoch-rewards calculation and distribution, before `relax_post_exec_min_balance_check` activates - ([File: runtime/src/bank/partitioned_epoch_rewards/distribution.rs])

### Summary
`Bank::build_updated_stake_reward` recomputes a stake account's post-reward state at distribution time by re-loading the *live* stake account from `stakes_cache` and comparing it against a value that was computed and "frozen" during the earlier calculation phase. If the feature `relax_post_exec_min_balance_check` (`adjust_delegations_for_rent`) is not active, the code falls back to a hard `assert_eq!` that any unprivileged staker can cause to fail simply by issuing an ordinary stake-program instruction (e.g. `Split`, `Merge`, or `DelegateStake` on a top-up) on their own stake account during the multi-block window between reward calculation and reward distribution.

### Finding Description
Partitioned epoch rewards work in two phases:
1. **Calculation** (single slot, epoch boundary): rewards for every delegated stake account are computed from a snapshot of `stakes_cache` and stored as `PartitionedStakeReward` entries, each carrying a pre-computed `inflation.stake` (the expected new delegation value) [1](#0-0) .
2. **Distribution** (spread over many subsequent blocks/partitions, up to `slots_per_epoch/10`): `distribute_partitioned_epoch_rewards` calls `distribute_epoch_rewards_in_partition` → `store_stake_accounts_in_partition` → `build_updated_stake_reward` once per stake account, for each partition [2](#0-1) .

`build_updated_stake_reward` re-fetches the account from the **current** `stakes_cache` (not the frozen calculation-time snapshot):

```
let stake_account = stakes_cache_accounts.get(&partitioned_stake_reward.stake_pubkey)...
...
let expected_delegation = stake.delegation.stake.saturating_add(partitioned_stake_reward.inflation.stake_reward);
assert_eq!(expected_delegation, new_stake.delegation.stake, "stake reward delegation must be consistent with the updated stake account lamport balance");
``` [3](#0-2) 

This assert only executes when `adjust_delegations_for_rent` (i.e. `feature_snapshot.relax_post_exec_min_balance_check`) is `false`; when the feature is active, `adjust_delegation_for_rent` is called instead and no panic path exists [4](#0-3) [5](#0-4) .

Because there can be many blocks between the calculation slot and the block that finally processes a given stake account's partition, a stake account's live `delegation.stake` can legitimately diverge from the value captured at calculation time. Any staker who owns a stake account included in the current epoch's reward set can, in the intervening blocks, submit an ordinary `Split`, `Merge`, or `DelegateStake` transaction that changes `delegation.stake` on their own account. When that account's partition is later processed, `stake.delegation.stake + stake_reward` will no longer equal the `new_stake.delegation.stake` value frozen during calculation, and the `assert_eq!` panics.

This is directly analogous to the OpenQ bug class described in the source report: a stale "receipt" (the calculation-time `PartitionedStakeReward.inflation.stake`) is later used against live/mutated state (the current stake account) without reconciliation, and the mismatch breaks the shared payout process — except here the failure mode is a hard Rust panic inside `Bank` execution rather than a revert, and it hits *every* replaying validator identically because Bank processing is deterministic.

The code comment at `store_stake_accounts_in_partition` even states the assumption that "there should never be rewards burned... because ... further state mutation [is] prevent[ed] by stake-program restrictions" [6](#0-5) , but no such restriction is visible in the reachable code path (no check gating `Split`/`Merge`/`DelegateStake` while an account has a pending, undistributed partitioned reward), so the assumption appears unenforced for the non-`relax_post_exec_min_balance_check` code path.

### Impact Explanation
A panic inside `Bank::build_updated_stake_reward`, invoked from block-processing code (`distribute_partitioned_epoch_rewards`), is not a transaction-level error that can simply be dropped — it aborts bank/replay processing. Because all validators execute this same deterministic logic on the same ledger state, the panic would occur identically on every node reaching that slot, producing a cluster-wide halt at an epoch boundary — one of the explicitly in-scope impact categories (epoch-boundary halt).

### Likelihood Explanation
This requires the `relax_post_exec_min_balance_check` feature to *not* be active on the cluster in question (it is listed among not-yet-universally-activated features in `feature-set/src/lib.rs`'s `FeatureSnapshot`, i.e. it is feature-gated and not guaranteed to be enabled on all clusters/at all times) [7](#0-6) . On any cluster/testnet or during the period before this feature activates on mainnet, the vulnerable branch is live, and the trigger (ordinary `Split`/`Merge`/`DelegateStake` by the stake authority during the reward-distribution window) requires no special privilege — only that the attacker own a stake account that received a nonzero calculated reward for the epoch and act on it during the several-block distribution window. I was not able to fully confirm the exact current activation status of `relax_post_exec_min_balance_check` on Solana mainnet-beta from the code alone; this should be verified before treating the issue as live on mainnet, but it is a legitimate reachable code path.

### Recommendation
- Remove the hard `assert_eq!` panic in `build_updated_stake_reward` and replace it with the same graceful `Err(DistributionError::...)` handling used elsewhere in this function (as already done for `AccountNotFound`, `ArithmeticOverflow`, `UnableToSetState`), so a legitimate delegation change between calculation and distribution burns/skips that individual reward instead of panicking the whole bank.
- Alternatively/additionally, gate stake-program instructions that mutate `delegation.stake` (`Split`, `Merge`, `DelegateStake`/redelegate, `Deactivate` interactions) on accounts that have a pending, uncredited partitioned stake reward for the current epoch, consistent with the comment's stated assumption that "further state mutation [is] prevent[ed] by stake-program restrictions."
- Ensure the fix is not conditioned solely on the `relax_post_exec_min_balance_check` feature flag, since panics in the non-adjusted path remain reachable on any cluster where that feature has not yet activated.

### Proof of Concept
Conceptual reproduction (cannot be executed without a live cluster/test harness, but derivable from the code):
1. Run a bank/cluster with `relax_post_exec_min_balance_check` feature **not** activated.
2. Delegate a stake account and let it earn nonzero epoch rewards; at the epoch boundary, `calculate_rewards_for_partitioning` computes `PartitionedStakeReward.inflation.stake` for this account and freezes it into `all_stake_rewards` [8](#0-7) .
3. Before this stake account's partition is processed (there are multiple partitions distributed over multiple blocks, see `get_reward_distribution_num_blocks` [9](#0-8) ), the stake authority submits a `Split` (or `Merge`/redelegate) transaction that changes the account's live `delegation.stake`.
4. When `distribute_partitioned_epoch_rewards` reaches the block/partition containing this stake account, `store_stake_accounts_in_partition` → `build_updated_stake_reward` loads the now-mutated account, computes `expected_delegation = stake.delegation.stake (mutated) + stake_reward`, compares against the frozen `new_stake.delegation.stake` computed pre-mutation, finds them unequal, and triggers `assert_eq!` panic, aborting bank processing on every node that replays this block.

        }

    pub(in crate::bank) fn distribute_partitioned_epoch_rewards(&mut self) {
        let EpochRewardStatus::Active(status) = &self.epoch_reward_status else {
            return;
        };

        let distribution_starting_block_height = match &status {
            EpochRewardPhase::Calculation(status) => status.distribution_starting_block_height,
            EpochRewardPhase::Distribution(status) => status.distribution_starting_block_height,
        };

        let height = self.block_height();
        if height < distribution_starting_block_height {
            return;
        }

        if let EpochRewardPhase::Calculation(status) = &status {
            // epoch rewards have not been partitioned yet, so partition them now
            // This should happen only once immediately on the first rewards distribution block, after reward calculation block.
            let epoch_rewards_sysvar = self.get_epoch_rewards_sysvar();
            let (partition_indices, partition_us) = measure_us!({
                epoch_rewards_hasher::hash_rewards_into_partitions(
                    &status.all_stake_rewards,
                    &epoch_rewards_sysvar.parent_blockhash,
                    epoch_rewards_sysvar.num_partitions as usize,
                )
            });

            // update epoch reward status to distribution phase
            self.set_epoch_reward_status_distribution(
                distribution_starting_block_height,
                Arc::clone(&status.all_stake_rewards),
                partition_indices,
            );

            datapoint_info!(
                "epoch-rewards-status-update",
                ("slot", self.slot(), i64),
                ("block_height", height, i64),
                ("partition_us", partition_us, i64),
                (
                    "distribution_starting_block_height",
                    distribution_starting_block_height,
                    i64
                ),
            );
        }

        let EpochRewardStatus::Active(EpochRewardPhase::Distribution(partition_rewards)) =
            &self.epoch_reward_status
        else {
            // We should never get here.
            unreachable!(
                "epoch rewards status is not in distribution phase, but we are trying to \
                 distribute rewards"
            );
        };

        let distribution_end_exclusive =
            distribution_starting_block_height + partition_rewards.partition_indices.len() as u64;

            self.epoch_schedule.get_slots_in_epoch(self.epoch)
                > partition_rewards.partition_indices.len() as u64
        );

        if height >= distribution_starting_block_height && height < distribution_end_exclusive {
            let partition_index = height - distribution_starting_block_height;

            self.distribute_epoch_rewards_in_partition(partition_rewards, partition_index);

    fn build_updated_stake_reward(
        distribution_epoch: u64,
        stake_history: &StakeHistory,
        new_warmup_cooldown_rate_epoch: Option<Epoch>,
        stakes_cache_accounts: &imbl::HashMap<Pubkey, StakeAccount<Delegation>>,
        partitioned_stake_reward: &PartitionedStakeReward,
        rent: &Rent,
        adjust_delegations_for_rent: bool,
        use_fixed_point_stake_math: bool,
    ) -> Result<StakeReward, DistributionError> {
        let stake_account = stakes_cache_accounts
            .get(&partitioned_stake_reward.stake_pubkey)
            .ok_or(DistributionError::AccountNotFound)?
            .clone();

        let (mut account, stake_state): (AccountSharedData, StakeStateV2) = stake_account.into();
        let StakeStateV2::Stake(meta, stake, flags) = stake_state else {
            // StakesCache only stores accounts where StakeStateV2::delegation().is_some()
            unreachable!(
                "StakesCache entry {:?} failed StakeStateV2 deserialization",
                partitioned_stake_reward.stake_pubkey
            )
        };
        account
            .checked_add_lamports(partitioned_stake_reward.inflation.stake_reward)
            .map_err(|_| DistributionError::ArithmeticOverflow)?;
        account
            .checked_add_lamports(partitioned_stake_reward.block_reward)
            .map_err(|_| DistributionError::ArithmeticOverflow)?;

        let mut new_stake = partitioned_stake_reward.inflation.stake;
        if adjust_delegations_for_rent {
            let minimum_balance = rent.minimum_balance(account.data().len());
            // The rewarded epoch is right before the distribution epoch
            let rewarded_epoch = distribution_epoch.saturating_sub(1);
            // The entry in `partitioned_stake_reward` contains the rewards,
            // calculated during the calculation phase
            let delegation_with_rewards = new_stake.delegation.stake;
            adjust_delegation_for_rent(
                &mut new_stake.delegation,
                rewarded_epoch,
                delegation_with_rewards,
                account.lamports(),
                minimum_balance,
            );
        } else {
            let expected_delegation = stake
                .delegation
                .stake
                .saturating_add(partitioned_stake_reward.inflation.stake_reward);
            assert_eq!(
                expected_delegation, new_stake.delegation.stake,
                "stake reward delegation must be consistent with the updated stake account \
                 lamport balance"
            );
        }
        account
            .set_state(&StakeStateV2::Stake(meta, new_stake, flags))
            .map_err(|_| DistributionError::UnableToSetState)?;

        let stake_at_distribution_epoch = delegation_effective_stake(
            &new_stake.delegation,
            distribution_epoch,
            stake_history,
            new_warmup_cooldown_rate_epoch,
            use_fixed_point_stake_math,
        );
        let reward_type = if stake_at_distribution_epoch == 0 {
            RewardType::DeactivatedStake
        } else {
            RewardType::Staking
        };
        Ok(StakeReward {
            stake_pubkey: partitioned_stake_reward.stake_pubkey,
            stake_reward_info: StakeRewardInfo {
                reward_type,
                lamports: i64::try_from(
                    partitioned_stake_reward.inflation.stake_reward
                        + partitioned_stake_reward.block_reward,
                )
                .unwrap(),
                post_balance: account.lamports(),
                commission_bps: partitioned_stake_reward.inflation.commission_bps,
            },
            stake_account: account,
        })
    }

    /// Calculate rewards from previous epoch to prepare for partitioned distribution.
    pub(super) fn calculate_rewards_for_partitioning<'a>(
        &self,
        stake_history: &StakeHistory,
        stake_delegations: Vec<(&'a Pubkey, &'a StakeAccount<Delegation>)>,
        cached_vote_accounts: CachedVoteAccounts<'_>,
        rewarded_epoch: Epoch,
        reward_epoch_delegated_stakes: RewardEpochDelegatedStakes,
        reward_calc_tracer: Option<impl Fn(&RewardCalculationEvent) + Send + Sync>,
        thread_pool: &ThreadPool,
        metrics: &mut RewardsMetrics,
    ) -> PartitionedRewardsCalculation {
        let capitalization = self.capitalization();
        let epoch_inflation_rewards =
            if AlpenglowEpochType::is_alpenglow_or_migration_epoch(self, rewarded_epoch) {
                EpochInflationAccountState::new_from_bank(self)
                    .and_then(|state| state.inflation_rewards_for_epoch(rewarded_epoch))
                    .unwrap_or_else(|| {
                        panic!(
                            "Missing epoch inflation state for non-Tower reward epoch \
                             {rewarded_epoch}"
                        )
                    })
            } else {
                self.calculate_epoch_inflation_rewards(capitalization, rewarded_epoch)
            };
        // `distribution_epoch_vote_accounts` is the post-VAT-filter snapshot
        // produced upstream of this call, so its length is the right value for
        // the `epoch_rewards` metric.
        let num_filtered_vote_accounts =
            cached_vote_accounts.distribution_epoch_vote_accounts.len();

        let CalculateValidatorRewardsResult {
            reward_commissions,
            stake_reward_calculation: stake_rewards,
            point_value,
        } = self
            .calculate_validator_rewards(
                stake_history,
                stake_delegations,
                cached_vote_accounts,
                rewarded_epoch,
                epoch_inflation_rewards,
                reward_epoch_delegated_stakes,
                reward_calc_tracer,
                thread_pool,
                metrics,
            )
            .unwrap_or_default();
