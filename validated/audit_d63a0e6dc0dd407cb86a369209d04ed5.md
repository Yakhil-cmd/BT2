### Title
`creator` field in `initialize_with_permission` is an unvalidated `UncheckedAccount` and can be set to a null/uncontrollable address, permanently freezing accrued creator fees - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
`InitializeWithPermission` accepts `creator` as a bare `UncheckedAccount<'info>` with no constraint that it differ from the zero/default `Pubkey` or otherwise be a valid, key-controlled address. This value is written directly into `pool_state.pool_creator` and later becomes the sole authorized recipient of accumulated creator swap fees, mirroring the reported "merchant address can be null" bug class (an actor-identity field accepted without a sanity check, later relied upon for critical control-flow).

### Finding Description
In `InitializeWithPermission`, the `creator` account is declared with no ownership/signer/`!= default()` checks: [1](#0-0) 

It is stored verbatim into the pool state during pool creation: [2](#0-1) 

The only gate on this instruction is that `payer` must hold a `Permission` PDA created by an admin (`permission_authority`), which authorizes *who may create a pool*, but it does not constrain the *value of the `creator` field* the payer supplies: [3](#0-2) 

Once the pool exists, `pool_creator` is the only address permitted to withdraw accrued creator fees. `collect_creator_fee` requires `creator` to be a `Signer` whose address matches `pool_state.pool_creator`: [4](#0-3) 

`collect_creator_fee_permissionless` relaxes the signer requirement but still routes all collected fees to an ATA whose *authority* is set to `pool_creator`: [5](#0-4) [6](#0-5) 

If `creator` is set to `Pubkey::default()` (all-zero) or any other address for which no private key exists, no one can ever produce a valid signature to satisfy `CollectCreatorFee`'s `Signer` constraint, and `collect_creator_fee_permissionless` will happily fund an ATA whose authority nobody controls. Fees keep accruing in `pool_state.creator_fees_token_0/1` via `update_fees`: [7](#0-6) 
but can never be moved out of the resulting token accounts once transferred, since the ATA's authority key cannot sign further transfers.

### Impact Explanation
This causes a concrete, permanent freezing of pool-generated creator fee funds. Every swap that routes through the pool (when `enable_creator_fee` is on) increments `creator_fees_token_0/1`; once collected into an ATA owned by an uncontrollable authority, those SPL tokens are locked forever, an irreversible loss of funds for the intended fee recipient/creator ecosystem. This matches the accepted impact class of "permanent freezing of user or LP funds."

### Likelihood Explanation
Any payer who has been granted a `Permission` PDA (a routine, non-privileged capability intended just to let approved integrators create pools) can supply an arbitrary `creator` account in the single `initialize_with_permission` transaction — the account is never validated to be a signer, to equal `payer`, or to differ from the default `Pubkey`. No special privilege beyond normal pool-creation permission is needed to trigger the freeze, and it can happen accidentally (e.g., a client bug passing an uninitialized/zeroed pubkey) as much as maliciously.

### Recommendation
Add an explicit constraint in `InitializeWithPermission` requiring `creator.key() != Pubkey::default()` (and ideally requiring `creator` to be a `Signer` or otherwise attestable/controllable address), failing the instruction early rather than allowing an uncollectable pool creator to be recorded.

### Proof of Concept
1. Admin grants `payer` a `Permission` PDA via `create_permission_pda`.
2. `payer` calls `initialize_with_permission`, supplying `creator = Pubkey::default()` (or any other address with no corresponding keypair) while all other accounts are valid.
3. The instruction succeeds; `pool_state.pool_creator` is now the zero address, as written in `pool_state.initialize(...)`.
4. Swaps occur against the pool; `creator_fees_token_0/1` accumulate per `update_fees` in `programs/cp-swap/src/states/pool.rs`.
5. Any attempt to call `collect_creator_fee` fails because no signer can match `address = pool_state.load()?.pool_creator = Pubkey::default()`.
6. Calling `collect_creator_fee_permissionless` succeeds in transferring the fees into a newly created ATA whose authority is the zero address — funds are now permanently unrecoverable since no private key exists for that authority.

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();
                if is_creator_fee_on_input {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                }
            }
        };
        Ok(())
    }
