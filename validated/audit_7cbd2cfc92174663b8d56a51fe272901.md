### Title
Untrusted swap route can inject token transfers under the caller's authorization - (File: contracts/controller/src/strategies/swap.rs)

### Summary
`swap_collateral`, `swap_debt`, `multiply`, and `repay_debt_with_collateral` accept an opaque `StrategySwap` byte payload and pass it to the configured router. [1](#0-0) [2](#0-1)  A malicious route can select attacker-controlled venue addresses that execute arbitrary contract code while the transaction is authorized by the caller. [3](#0-2)  That injected code can add an unrelated token `transfer` beneath the caller's signed authorization tree, draining wallet assets while still returning enough swap output to satisfy the controller. [4](#0-3) [5](#0-4) 

### Finding Description
`process_swap_collateral` authorizes `caller`, verifies account ownership or delegation, withdraws the selected collateral to the controller, and forwards the caller-supplied `swap` bytes to `withdraw_and_swap_from_supply`. [6](#0-5) [7](#0-6)  The same untrusted payload is used by debt refinancing, collateral repayment, and multiply strategies. [8](#0-7) [9](#0-8) [10](#0-9)  `swap_tokens` treats the payload as opaque data, invokes `execute_strategy(controller, amount_in, swap)`, and only records controller balances for the declared input and output tokens before and after the call. [11](#0-10)  It rejects router overspending of the routed input and requires a positive output balance delta, but it performs no semantic validation of venue addresses or nested calls selected by the route. [12](#0-11) [5](#0-4)  The controller's own contract authorization is limited to one exact input-token transfer to the router, but that restriction protects only the controller's grant and not additional invocations executed under the user's root authorization. [13](#0-12) 

### Impact Explanation
An attacker can craft a route whose venue contract both provides enough `token_out` to pass the controller's measured-output check and calls an unrelated token's `transfer(victim, attacker, amount)` during the swap. [5](#0-4)  If a wallet signs the simulated authorization tree containing that child transfer, the victim loses arbitrary approved wallet-token balances in addition to the collateral intentionally routed through the strategy. [6](#0-5) [4](#0-3)  The resulting theft is permanent and is not bounded by `amount`, minimum output, final health checks, or the exact controller-to-router transfer authorization. [12](#0-11) [14](#0-13) 

### Likelihood Explanation
The attacker needs no privileged role because all strategy entrypoints expose caller-provided `swap` bytes and the intended caller can be any account owner or delegate. [15](#0-14) [16](#0-15)  Exploitation requires the victim to submit an attacker-provided route and sign the authorization tree produced by simulation, which is consistent with the user-interaction command-injection pattern rather than a protocol-privilege requirement. [6](#0-5) [2](#0-1)  Because the malicious venue can return a legitimate-looking output, the route can remain economically valid while performing the unauthorized wallet transfer. [5](#0-4) 

### Recommendation
Do not allow opaque strategy payloads to select arbitrary executable venue addresses for calls made under a lending user's authorization. [2](#0-1) [4](#0-3)  Constrain routes to a governance-approved venue contract registry, or require a decoded route manifest to be checked before `execute_strategy` is invoked. [3](#0-2)  Wallets and strategy builders should also reject any signed authorization tree containing children other than the single expected strategy input transfer. [13](#0-12) 

### Proof of Concept
1. Victim owns account `A` and holds an unrelated wallet token `W` in addition to the collateral being swapped. [17](#0-16) 
2. Attacker supplies `swap` bytes for `swap_collateral(A, current, amount, new, swap)` whose address registry contains an attacker-controlled venue contract and whose output token remains `new.asset`. [1](#0-0) [2](#0-1) 
3. The victim's transaction reaches `swap_tokens`, authorizes the controller's exact input transfer, and invokes the router with the supplied payload. [18](#0-17) 
4. During route execution, the malicious venue transfers the victim's entire `W` balance to the attacker and returns a positive `new.asset` output to the controller. [5](#0-4) 
5. The controller observes a valid input spend and positive output, deposits the swapped collateral, and finalizes the account while the unrelated `W` transfer remains permanently paid to the attacker. [19](#0-18) [12](#0-11)

```rust
/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`
/// call on `token_addr` made deeper in the next contract call (for example by
/// the pool). The entry allows no further sub-invocations.
pub fn authorize_transfer_as_current(
    env: &Env,
    token_addr: &Address,
    from: &Address,
    to: &Address,
    amount: i128,
) {
    let entry = InvokerContractAuthEntry::Contract(SubContractInvocation {
        context: ContractContext {
            contract: token_addr.clone(),
            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);
```

```rust
/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
```
