### Title
`checkConsistency` validates `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` votes individually but not their combined epoch effect, enabling `LowerBoundBaseFee > UpperBoundBaseFee` and incorrect KAIA fee burns - (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` cross-validates each KIP-71 base-fee bound vote against the **current** parameter set in isolation. Two votes cast in the same epoch — one raising `LowerBoundBaseFee` above the current upper bound, one lowering `UpperBoundBaseFee` below the current lower bound — each pass the per-vote check, but their combined application at the epoch boundary produces `LowerBoundBaseFee > UpperBoundBaseFee`. `NextMagmaBlockBaseFee` then oscillates the base fee between the two inverted bounds, causing every block to charge users either above the intended maximum or below the intended minimum, corrupting the KAIA fee-burn amount permanently until governance corrects it.

---

### Finding Description

`VerifyVote` calls `checkConsistency` for every incoming vote:

```go
// kaiax/gov/headergov/impl/header.go:179-192
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    } else {
        return nil
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    } else {
        return nil
    }
``` [1](#0-0) 

Each check reads `h.GetParamSet(blockNum)` — the **currently active** parameter set — not the other pending vote in the same epoch. With the default values `Lower=25 Gwei, Upper=750 Gwei`:

1. Vote A: `LowerBoundBaseFee = 100 Gwei` → `100 ≤ 750` → **passes**
2. Vote B: `UpperBoundBaseFee = 50 Gwei` → `50 ≥ 25` → **passes**

At the epoch boundary `getExpectedGovernance` collects both votes and writes them into `header.Governance` without any cross-parameter check:

```go
// kaiax/gov/headergov/impl/header.go:218-233
for _, voteBlock := range sortedVoteBlocks {
    vote := prevEpochVotes[voteBlock]
    govs.Add(string(vote.Name()), vote.Value())
}
return headergov.NewGovData(govs)
``` [2](#0-1) 

After the epoch block is accepted, `GetParamSet` returns `Lower=100, Upper=50`. `NextMagmaBlockBaseFee` then behaves as follows:

```go
// params/kip71_config.go:82-128
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {   // any fee ≥ 50 → clamp to 50
    parentBaseFee = upperBoundBaseFee
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
    parentBaseFee = lowerBoundBaseFee
}
// parentBaseFee = 50 (below the lower bound of 100)
// low-traffic path:
nextBaseFee = parentBaseFee - delta   // < 50 < 100
if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
    return makeEvenByFloor(lowerBoundBaseFee)  // returns 100 — ABOVE upper bound
}
``` [3](#0-2) 

The base fee permanently oscillates: low-traffic blocks produce `100 Gwei` (above the upper bound), high-traffic blocks produce `50 Gwei` (below the lower bound). `VerifyMagmaHeader` accepts both because it only checks that the header's base fee equals `NextMagmaBlockBaseFee`'s output — it does not re-validate the bounds relationship. [4](#0-3) 

---

### Impact Explanation

The base fee is the primary component of every transaction's effective gas price. Under Magma/Kore rules, `F/2` of every block's fees is burnt. With the inverted bounds:

- Low-traffic epochs: base fee locked at `lowerBoundBaseFee` (100 Gwei) — **above** the intended maximum (50 Gwei). Every user overpays; excess KAIA is burnt beyond the protocol's intended rate.
- High-traffic epochs: base fee locked at `upperBoundBaseFee` (50 Gwei) — **below** the intended minimum (100 Gwei). Users underpay; the burn rate drops below the protocol floor.

This is a persistent, per-block incorrect KAIA fee-burn and fee-charge affecting all network participants until governance issues a corrective vote.

---

### Likelihood Explanation

In `governance.governancemode = "none"` (any non-Mainnet chain), **any single validator** may cast both votes within the same epoch. The last vote for each parameter name wins (`getExpectedGovernance` takes the last entry per key in block-number order), so the attacker simply ensures their two votes are the last for each parameter before the epoch closes. No coordination with other validators is required. [5](#0-4) 

On Mainnet (`governancemode = "single"`), only the governing node can vote, making this a privileged-actor scenario.

---

### Recommendation

Replace the per-vote individual checks with a combined check that accounts for all pending votes in the current epoch. Specifically, when a `Kip71LowerBoundBaseFee` or `Kip71UpperBoundBaseFee` vote arrives, resolve the **effective** value of the other bound by merging the current parameter set with any already-cast votes for that bound in the same epoch, then validate the pair:

```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    effectiveUpper := resolveEffectiveUpper(blockNum, params) // check pending votes
    if vote.Value().(uint64) > effectiveUpper {
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    effectiveLower := resolveEffectiveLower(blockNum, params)
    if vote.Value().(uint64) < effectiveLower {
        return ErrUpperBoundBaseFee
    }
```

Additionally, add a final cross-parameter sanity check inside `getExpectedGovernance` before writing `header.Governance`, rejecting the epoch governance data if the resulting `LowerBoundBaseFee ≥ UpperBoundBaseFee`.

---

### Proof of Concept

Assume `governance.governancemode = "none"`, epoch = 1000, current `Lower=25 Gwei`, `Upper=750 Gwei`.

1. At block 800, validator V casts vote `(kip71.lowerboundbasefee, 100 Gwei)`.  
   `checkConsistency`: `100 ≤ 750` → accepted, written to `header.Vote`.

2. At block 900, validator V casts vote `(kip71.upperboundbasefee, 50 Gwei)`.  
   `checkConsistency`: `50 ≥ 25` → accepted, written to `header.Vote`.

3. At block 1000 (epoch boundary), `getExpectedGovernance` collects both votes. `header.Governance = {"kip71.lowerboundbasefee": 100, "kip71.upperboundbasefee": 50}`. `VerifyGov` accepts it (it only checks that the governance matches the locally derived map — which it does).

4. From block 1001 onward, `GetParamSet` returns `Lower=100, Upper=50`.

5. Block 1001 proposer calls `NextMagmaBlockBaseFee(parentBaseFee=200, parentGasUsed=10M < gasTarget=30M)`:
   - Clamp: `parentBaseFee = min(200, 50) = 50`
   - Low-traffic: `nextBaseFee = 50 - delta < 100` → return `lowerBoundBaseFee = 100`
   - Block 1001 `header.BaseFee = 100 Gwei` (above the upper bound of 50 Gwei).

6. `VerifyMagmaHeader` on block 1001: `expectedBaseFee = 100`, `headerBaseFee = 100` → **accepted**.

7. Every subsequent low-traffic block charges 100 Gwei base fee, burning KAIA at a rate above the protocol's intended maximum. [6](#0-5) [7](#0-6)

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}

```markdown
The ratification condition is determined by the `governance.governancemode` parameter. Mainnet and Kairos both operate in `single` mode. There are two governance modes:

- `none` mode: all members of the GC can vote. For each governance parameter, the last vote in the epoch will be ratified.
- `single` mode: only one member of the GC, stipulated in the parameter `governance.governingnode`, can vote. All valid votes from the governing node in the epoch are ratified in block order. For each governance parameter, the last vote in the epoch will be ratified.
