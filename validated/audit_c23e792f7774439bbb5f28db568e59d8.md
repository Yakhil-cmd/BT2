## Title
Unbounded recursion in `replaceInTemplate`/`replaceInVar` when resolving a `definition_template` message can crash validating nodes - (File: `definition.js`)

## Summary
The `definition_template` message app lets any unit poster store an arbitrary array-of-two payload that is later resolved by `['definition template', [unit, params]]` inside an address or asset-condition definition. Resolution calls `replaceInTemplate()` → `replaceInVar()`, which walks the stored template recursively with **no depth or complexity limit at all**, unlike the sibling `evaluate()` walkers in the same file that bump `complexity`/`count_ops` and abort at `MAX_COMPLEXITY`/`MAX_OPS`. A template payload nested to a large, attacker-chosen depth can drive `replaceInVar` into a stack overflow, mirroring the CVE-2019-11026 pattern of unbounded recursion on attacker-controlled tree-shaped input.

## Finding Description
`replaceInTemplate`/`replaceInVar` recurse over every array element and object key of the stored template with plain recursive calls and no depth counter: [1](#0-0) 

The two validation entry points for `definition_template` messages perform only shallow structural checks (`isArrayOfLength(payload, 2)`), never checking nesting depth or node count of the payload before it is written to the DB: [2](#0-1) [3](#0-2) 

Once the unit carrying this message is stable, anyone can define/reference an address whose definition contains `['definition template', [unit, params]]`. When such a definition is evaluated (e.g., during `validateDefinition` or `validateAuthentifiers`), the code fetches the stored payload, `JSON.parse`s it, and calls `replaceInTemplate` **before** any of the complexity/depth accounting that guards the rest of `evaluate()`: [4](#0-3) [5](#0-4) 

By contrast, every other recursive walker in `definition.js` (`evaluate()` in `validateDefinition`) increments `complexity`/`count_ops` on every call and bails out once `constants.MAX_COMPLEXITY`/`MAX_OPS` is exceeded: [6](#0-5) 
`replaceInVar` has none of these guards, so its recursion depth is bounded only by the depth of the JSON structure the attacker chose to store in the `definition_template` payload, which is essentially unbounded (subject only to overall unit/message size limits, not nesting depth).

## Impact Explanation
Any node (full node, hub, or light-vendor-serving node) that needs to validate a unit/authentifier referencing the malicious `['definition template', ...]` will call `replaceInTemplate` and can crash with a JavaScript "Maximum call stack size exceeded" `RangeError`. Because address/asset-condition validation is mandatory for any unit that spends from, or is co-signed by, an address using this op, a node that cannot get past this recursive call cannot validate/confirm the affected unit(s). This is a network-wide denial-of-service on consensus/validation for any peer that encounters the crafted definition template — consistent with "a network unable to confirm new units."

## Likelihood Explanation
The primitive is reachable purely from data any unprivileged unit poster controls:
1. Post a unit with a `definition_template` message whose payload is a deeply nested array/object (only bounded by overall unit size limits, not nesting depth).
2. Define (or have an existing) address whose definition includes `['definition template', [that_unit, params]]`, then post a unit using that address (as author or referenced address) so that `validateDefinition`/`validateAuthentifiers` is invoked and resolves the template.
No special network position, hub cooperation, or leaked keys are required — both steps are ordinary, permissionless actions any user can perform.

## Recommendation
Add depth/complexity accounting to `replaceInTemplate`/`replaceInVar`, mirroring the `complexity`/`count_ops`/`MAX_COMPLEXITY` guard used in `evaluate()`, or enforce a hard nesting-depth limit (similar to `aa_validation.js`'s `MAX_DEPTH` or `string_utils.isTooDeeplyNestedOrHasTooManyNodes`) on `definition_template` payloads at message-validation time (`validation.js` and `aa_validation.js`), rejecting templates that exceed the limit before they can ever be stored or resolved.

## Proof of Concept
1. Construct and post a unit containing a message:
   ```
   { app: 'definition_template', payload: ['and', [ /* nested thousands of levels deep, e.g. repeated ['and', [X]] or nested arrays */ ]] }
   ```
   Validation of this message only checks `isArrayOfLength(payload, 2)` (`aa_validation.js:425-429`, `validation.js:2003-2009`), so arbitrarily deep nesting passes.
2. Once stable, create/use an address whose definition is `['definition template', [unit_of_step_1, {param1: 'value1'}]]`.
3. Post any unit authored by (or referencing) that address. Validating nodes call `definition.js`'s `evaluate()` → `replaceInTemplate(arrTemplate, params)` → `replaceInVar` (`definition.js:1468-1495`), recursing over the full nested payload with no depth check, causing a stack overflow crash on the validating node.

function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
