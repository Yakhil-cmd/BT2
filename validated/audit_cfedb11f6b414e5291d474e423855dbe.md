### Title
Unauthenticated `ServiceChainParentChainInfoResponseMsg` Allows Any Bridge Peer to Corrupt Parent Operator Nonce, Halting Bridge Value Transfers - (File: node/sc/sub_bridge_handler.go)

### Summary
Any peer that can establish a bridge P2P connection to a SubBridge node can send a crafted `ServiceChainParentChainInfoResponseMsg` containing an arbitrary nonce value. `handleParentChainInfoResponseMsg` accepts this message from any registered bridge peer without verifying the sender is the legitimate MainBridge, and unconditionally overwrites the parent operator's nonce used to sequence all bridge value-transfer transactions. Setting the nonce to `math.MaxUint64` permanently stalls the bridge: every subsequent KAIA/ERC-20/ERC-721 handle transaction is rejected by the parent chain with "nonce too high."

### Finding Description
`SubBridge.handleMsg` reads every inbound P2P message and dispatches it to `SubBridgeHandler.HandleMainMsg` with no sender-identity check beyond the initial bridge handshake. [1](#0-0) 

`HandleMainMsg` routes `ServiceChainParentChainInfoResponseMsg` directly to `handleParentChainInfoResponseMsg`: [2](#0-1) 

`handleParentChainInfoResponseMsg` decodes the peer-supplied `parentChainInfo` struct and, in every branch of its logic, calls `sbh.setParentOperatorNonce(pcInfo.Nonce)` with the attacker-controlled value: [3](#0-2) 

The `parentChainInfo` struct carries a plain `uint64` nonce with no signature, timestamp, or chain-of-custody field: [4](#0-3) 

The bridge handshake only checks `networkId`, `chainID`, total-difficulty, and current block hash — all publicly observable values — so any node on the internet can complete it and become a registered bridge peer: [5](#0-4) 

Once registered, the attacker sends one `ServiceChainParentChainInfoResponseMsg` with `Nonce = math.MaxUint64`. The SubBridge sets `mainChainAccountNonce` to that value and marks `nonceSynced = true`, unblocking the bridge tx loop. Every bridge transaction subsequently built with `GenerateTransactOpts` carries nonce `math.MaxUint64` and is rejected by the parent chain mempool.

The corrupted nonce also propagates into `setRemoteChainValues`, overwriting `remoteGasPrice` and the KIP-71 config with attacker-supplied values, further disrupting fee estimation for all pending bridge transactions: [6](#0-5) 

### Impact Explanation
The parent operator nonce governs every `HandleKLAYTransfer`, `HandleERC20Transfer`, and `HandleERC721Transfer` transaction the SubBridge submits to the parent chain bridge contract. Corrupting it to `math.MaxUint64` causes all such transactions to be permanently rejected, freezing all cross-chain value transfers. Locked KAIA and bridged tokens remain stranded in the bridge contract until the SubBridge operator manually restarts the node and re-syncs the nonce. This constitutes unauthorized nonce consumption affecting KAIA and bridged assets held by the system-managed bridge account. [7](#0-6) 

### Likelihood Explanation
The SubBridge's bridge P2P port is reachable by any peer that knows the network ID and chain ID (both public). No secret credential, validator key, or privileged role is required. A single UDP/TCP connection and one crafted message suffice. The attack is repeatable: even after a restart the attacker can reconnect and re-corrupt the nonce before the legitimate MainBridge peer responds.

```go
func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil
```
