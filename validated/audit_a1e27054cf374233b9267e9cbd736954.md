### Title
Webhook signature verification keyed off `organization.login` fallback while handlers trust `repository.full_name` from the same unverified body, enabling cross-org stack mutation - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#repository_owner` picks the signing organization by first checking `repository.owner.login`, falling back to `organization.login` only if the former is absent. Since the request body is fully attacker-controlled, an attacker can omit `repository.owner.login` while still supplying `repository.full_name`, forcing verification to be keyed on an org of their choosing (one with no `webhook_secret` configured) while the payload's `repository.full_name` targets a victim's stack.

### Finding Description
The broken binding: the code implicitly assumes `repository_owner used for verification == owner(repository.full_name) used for stack lookup`. In fact:

- `repository_owner` is computed as `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) .
- `verify_signature` calls `Shipit.github(organization: repository_owner)` and then `github_app.verify_webhook_signature(...)`, rejecting with 422 only if `verified` is falsy [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when `@webhook_secret` is blank: `return true unless webhook_secret` [3](#0-2) .
- Handlers (e.g. `Handler#stacks`/`repository_name`, and `OpenedHandler#repository`/`ClosedHandler#repository`) resolve the target stack purely from `payload.dig('repository', 'full_name')`, independent of whatever value was used for signature verification [4](#0-3) [5](#0-4) .

Because the JSON body is raw attacker input (not a real GitHub-signed payload structurally guaranteed to be self-consistent), the attacker can send a body where `repository.full_name` = `"victim-org/victim-repo"` but `repository.owner.login` is omitted, and `organization.login` = `"attacker-org"` (an org with no `webhook_secret` in `Shipit.github_apps`). `repository_owner` then resolves to `attacker-org`, `Shipit.github(organization: "attacker-org")` returns a `GitHubApp` with `webhook_secret` nil, and `verify_webhook_signature` returns `true` regardless of the (missing/garbage) `X-Hub-Signature` header. The request passes `verify_signature` and reaches `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`, where the handler resolves the real target stack from `repository.full_name` and executes its side effects (e.g., archiving/creating review stacks, enqueuing `GithubSyncJob`, creating commit statuses) against the victim repository/stack — none of which was ever authenticated by a secret belonging to that victim organization.

Existing guards do not stop this: `drop_unhandled_event` only filters by event name, not payload consistency; `ExplicitParameters` schemas on handlers require `repository.full_name` but never require `repository.owner.login` to be present or consistent with `organization.login`; there is no cross-check anywhere that the org used for signing matches the owner implied by `repository.full_name`.

### Impact Explanation
An attacker who controls (or merely names) any GitHub organization slug that happens to be configured in `Shipit.github_apps` without a `webhook_secret` can forge unauthenticated webhook events that mutate stacks belonging to a completely different, secret-protected organization/repository. Depending on the event/handler this can enqueue sync jobs, create/archive review stacks, or write commit statuses for the victim stack — a payload for one repository mutating another repository's stack/task, matching the Critical "authentication bypass" / "payload for one repository mutating another's stack" category. The attack is repeatable against any stack in the installation and is not limited to a single victim.

### Likelihood Explanation
Preconditions: the Shipit instance must be configured with at least one organization in `Shipit.github_apps` that has no `webhook_secret` set (a real, if avoidable, misconfiguration many multi-org GitHub App setups can have for lower-risk/staging orgs). No Shipit credentials, sessions, or GitHub secrets are required — only knowledge of (a) that unconfigured org's login and (b) the victim's `owner/repo` full name, both public information. The attacker sends a single unauthenticated `POST /webhooks` request with a crafted JSON body and an arbitrary/missing `X-Hub-Signature` header.

### Recommendation
Do not fall back to `organization.login` for signature verification when `repository` is present in the payload; instead derive `repository_owner` strictly from `repository.full_name`'s owner segment (or require `repository.owner.login` to match the owner portion of `repository.full_name`) so the org used to select the `webhook_secret` cannot be decoupled from the org whose stack the handler will mutate. Additionally, treat a blank/misconfigured `webhook_secret` for an organization as a hard failure (reject with 422) rather than "unconditionally trust," at minimum for any organization referenced in a payload that also asserts a `repository.full_name` in a different namespace.

### Proof of Concept
Minitest plan (two tests):

1. Unit test on `GitHubApp#verify_webhook_signature` (`test/lib` or wherever GitHubApp is tested):
```ruby
app = Shipit::GitHubApp.new('attacker-org', {}) # no webhook_secret
assert_not app.verify_webhook_signature('sha1=deadbeef', '{"any":"payload"}'),
```

```ruby
# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class Handler
        class << self
          attr_reader :param_parser

          def params(&block)
            @param_parser = ExplicitParameters::Parameters.define(&block)
          end
        end

        def self.call(params)
          new(params).process
        end

        attr_reader :params, :payload

        def initialize(payload)
          @payload = payload
          @params = self.class.param_parser.parse!(payload)
        end

        def process
          raise NotImplementedError
        end

        private

        def stacks
          @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
        end

        def repository_name
          payload.dig('repository', 'full_name')
        end
      end
    end
  end
end
```
