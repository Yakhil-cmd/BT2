## Title
Cross-tenant Review Stack creation via webhook `repository.owner.login`/`repository.full_name` divergence — ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb])

## Summary
`WebhooksController#verify_signature` authenticates a `pull_request` webhook using the GitHub App/secret for the organization named in `params.repository.owner.login`, but `OpenedHandler#repository` (and all sibling PR handlers) loads the target `Shipit::Repository` row using `params.repository.full_name` instead. These two payload fields are never cross-checked, so an attacker who names an org with no configured `webhook_secret` in `repository.owner.login` can still forge a `full_name` that resolves to a real `Shipit::Repository` belonging to a completely different, victim organization, causing an unauthenticated cross-tenant `ReviewStack`/`Stack`/`PullRequest` to be created.

## Finding Description
Binding claimed: `repository_owner` (the org whose GitHub App secret authenticates the request) == owner of the `Shipit::Repository` row that `from_github_repo_name` loads and mutates.

- `WebhooksController#repository_owner` reads `params.dig('repository', 'owner', 'login')` and uses it purely to select which `GitHubApp`/secret verifies the HMAC signature: `Shipit.github(organization: repository_owner)` → `verify_webhook_signature`. [1](#0-0) [2](#0-1) 

- `GitHubApp#verify_webhook_signature` trivially returns `true` when no `webhook_secret` is configured for that organization: `return true unless webhook_secret`. [3](#0-2) 

- `Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#repository` (and `ClosedHandler`, `ReopenedHandler`, `LabeledHandler`, `UnlabeledHandler`, `EditedHandler`, `LabelCapturingHandler`) all instead resolve the acted-upon repository from `params.repository.full_name` via `Shipit::Repository.from_github_repo_name`, completely independent of `repository.owner.login`. [4](#0-3) [5](#0-4) 

- `Repository.from_github_repo_name` simply splits `owner/repo` from whatever string is supplied in `full_name` and does a `find_by`, with no comparison to the `owner.login` field used for authentication. [5](#0-4) 

- `provision?`/`find_or_create!` then act on this "resolved-by-full_name" repository's `review_stacks` association, creating a `ReviewStack` scoped to that repository's own `repository_id`, using attacker-controlled `pull_request.head.ref` (branch) and `params.sender.login` (user), all inside `ReviewStackAdapter#create!`. [6](#0-5) [7](#0-6) 

Exploit flow: the target host is configured with multiple GitHub Apps keyed by organization (a documented, supported configuration, see `github_app_config`/`github_organizations`). [8](#0-7) 
Suppose org `victim-org` has an existing `Shipit::Repository` (`victim-org/victim-repo`) with `review_stacks_enabled` and `provisioning_behavior_allow_all`, and some other configured org `attacker-org` happens to have no `webhook_secret` set (common misconfiguration, and the exact scenario the setup docs show as an empty field). [9](#0-8) 
The attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request` and a body where `repository.owner.login = "attacker-org"` (so signature verification looks up `attacker-org`'s blank secret and auto-passes) but `repository.full_name = "victim-org/victim-repo"`. No valid `X-Hub-Signature` is required at all. `OpenedHandler` then resolves the real `victim-org/victim-repo` `Repository` row via `full_name`, evaluates `provision?` using *victim's* configuration, and creates a `ReviewStack`/`PullRequest` under victim's `repository_id` — entirely unauthenticated by victim's own webhook secret.

None of the existing guards catch this: `verify_signature` only checks HMAC validity for whichever org `repository.owner.login` names, `drop_unhandled_event` only filters by event type, the `ExplicitParameters` schema only requires `full_name` to be a `String` (any value), and no model validation or handler code compares `owner.login` to the resolved repository's `owner`.

## Impact Explanation
An unauthenticated attacker can create arbitrary `Shipit::ReviewStack`/`Stack` and `PullRequest` records against any tracked repository whose owning org's identity they can spoof via a *different, weakly-configured* org's `webhook_secret`. This is a cross-tenant write: a payload nominally authenticated for org A mutates org B's stack state, matching the Critical impact category ("a payload for one repository mutating another's stack ... or an unauthorized deploy"). Repeatable against any repository resolvable by `full_name`, for every PR handler that shares this same `repository` resolution pattern (`OpenedHandler`, `ClosedHandler`, `ReopenedHandler`, `LabeledHandler`, `UnlabeledHandler`, `EditedHandler`, `LabelCapturingHandler`).

## Likelihood Explanation
Requires: (1) a multi-organization GitHub App configuration (documented, supported feature) with at least one configured org lacking a `webhook_secret`, and (2) a target `Shipit::Repository` with review-stack provisioning enabled belonging to a different org. Given (1), the attack costs a single crafted HTTP POST with no secrets, tokens, or GitHub session — well within the unprivileged attacker capability described. Feasibility depends entirely on deployment configuration (an org with a blank `webhook_secret` existing alongside a victim org), which is a realistic misconfiguration since `webhook_secret` is commented as optional/nil in every documented secrets template.

## Recommendation
Bind the authenticated organization to the repository actually mutated: after loading `repository` in each PR handler, verify `repository.owner.casecmp?(params.repository.owner.login)` (or equivalent) and abort/no-op if they differ; alternatively, have `WebhooksController` derive `repository_owner` strictly from `full_name.split('/').first` so the same value used for HMAC selection is the value used for record resolution, closing the divergence entirely.

## Proof of Concept
minitest plan (`test/models/shipit/webhooks/handlers/pull_request/opened_handler_test.rb` style, no live GitHub):
1. Create `victim_repository = Shipit::Repository.create!(owner: "victim-org", name: "victim-repo", review_stacks_enabled: true, provisioning_behavior: "allow_all")`.
2. Build `payload = payload_parsed(:pull_request_opened)`; set `payload["repository"]["full_name"] = "victim-org/victim-repo"` and `payload["repository"]["owner"] = { "login" => "attacker-org" }`.
3. Stub `Shipit.github(organization: "attacker-org")` to return a `GitHubApp` whose `webhook_secret` is blank (simulate the double-org config in `test/dummy/config/secrets_double_github_app.yml` with one org's `webhook_secret` unset), so `WebhooksController#verify_signature` passes without any valid `X-Hub-Signature`.
4. POST this payload to `WebhooksController#create` with `X-Github-Event: pull_request`.
5. Assert: `assert_response :ok`; `assert_equal victim_repository.id, Shipit::ReviewStack.last.repository_id` — proving the stack was created against `victim-org`'s repository even though the authenticated org (via signature) was `attacker-org`.
6. Equality check per the binding: assert `Shipit::ReviewStack.last.repository.owner == "victim-org"` while the request's authenticated `repository_owner` was `"attacker-org"` — showing the two values do **not** match, breaking the claimed binding.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
