### Title
Duplicate crediting of the same L1 Bitcoin lockup output across separate calls to `verify-l1-lockups` inflates sats staked without corresponding BTC being locked - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
### Finding Description
`validate-l1-lockup`, folded via `verify-l1-lockups`, is meant to ensure every Bitcoin lockup output that is credited toward a bond/staker's `amount-sats` corresponds to a real, distinct on-chain UTXO. Duplicate protection is implemented purely with a `seen-outpoints` accumulator that is freshly initialized to `(list)` at the start of every call to `verify-l1-lockups`: [1](#0-0) 

and the actual de-duplication assertion only checks against this call-scoped list: [2](#0-1) 

Because `seen-outpoints` is not backed by a persistent map (e.g., a `define-map` recording previously-credited `{txid, output-index}` pairs across all past calls/bonds/stakers), nothing in this function prevents the exact same Bitcoin outpoint (same `tx`, same `output-index`, same `header`, same merkle proof) from being submitted again in a *separate* invocation of `verify-l1-lockups` — whether for the same bond/staker on a later transaction, or for a different bond/staker altogether. Each independent call re-verifies the merkle proof and script match (which will succeed identically every time, since the underlying Bitcoin transaction never changes) and adds `(get amount output)` to that call's `sum`, which the caller then treats as real, newly locked sats.

### Impact Explanation
This breaks the equality "sats credited to a staker/bond == sats actually locked on the corresponding Bitcoin timelock output." An attacker (or even an honest staker replaying the same proof) can present a single real BTC lockup multiple times across multiple `verify-l1-lockups` calls (e.g., across multiple bond registrations, or repeated calls tied to `roll-sbtc`/reward-share bookkeeping) to have the same locked sats counted more than once toward `amount-sats`, `total-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, and `staker-shares-staked-for-cycle`. This directly double-counts a commitment that was only locked once on Bitcoin — inflating a staker's/signer's effective stake and reward-weight without a matching increase in real locked BTC, which is one of the explicitly in-scope Critical impacts ("sats credited by an L1 proof that were never locked on Bitcoin" / "double-counting a commitment"). It can be used to claim disproportionate sBTC/STX rewards relative to actual collateral, or to inflate signer weight beyond what is backed by locked value.

### Likelihood Explanation
Likelihood is high given the reachable path requires no privileged role: any unprivileged staker who controls a valid L1 lockup output can construct the exact same `lockups` tuple (same `tx`, `header`, `leaf-hashes`, etc.) and submit it in more than one contract call. The per-call `(list)` reset is a direct, structural implementation gap (not an edge case), analogous to the referenced bug class where an initialization-style function assumes zero prior committed state on every invocation. The only mitigating factor is uncertainty over how the caller of `verify-l1-lockups` gates repeat calls for the *same* bond (I could not fully trace all call sites of `verify-l1-lockups` within the available context to rule out an additional persistent guard at a higher layer); however, no such persistent record of previously consumed outpoints was found within `pox-5.clar`.

### Recommendation
Introduce a persistent `define-map` (e.g., `consumed-lockup-outpoints`) keyed by `{txid, output-index}` (or a hash of the full outpoint) that is checked and updated globally — not merely within the transient per-call `seen-outpoints` accumulator — before any lockup's amount is added to `sum`. Reject with `ERR_DUPLICATE_LOCKUP_OUTPOINT` if the outpoint has ever been consumed by any prior call, and mark it consumed as part of the same transaction that credits `amount-sats`.

### Proof of Concept
1. A staker locks BTC in a valid timelock output matching `expected-script-hash` for their bond, producing a valid lockup proof tuple (`tx`, `header`, `leaf-hashes`, `tx-count`, `tx-index`, `amount`, `unlock-burn-height`).
2. The staker calls the public function that invokes `verify-l1-lockups` with this proof, crediting `amount-sats` to their bond/stake — increasing `total-shares-staked-for-cycle` / `signer-shares-staked-for-cycle` accordingly.
3. The staker calls the same (or a related) public function again with the identical proof tuple. Because `verify-l1-lockups` re-initializes `seen-outpoints` to `(list)` on every call, `validate-l1-lockup` re-validates the same outpoint successfully and returns the same `amount` again, since no persistent record blocks reuse.
4. The staker's/bond's `amount-sats`/stake weight is now double the actual BTC locked, without any additional Bitcoin ever being locked. [3](#0-2)

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
