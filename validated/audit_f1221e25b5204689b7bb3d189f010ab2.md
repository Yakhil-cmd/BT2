### Title
Bad-debt write-down clamps supply index to `SUPPLY_INDEX_FLOOR_RAW`, leaving wiped-out suppliers a residual claim that drains future deposits - (File: contracts/pool/src/interest.rs)

### Summary
When a borrow position is seized with unpaid debt, `apply_bad_debt_to_supply_index` reduces the supply index pro-rata but clamps the result at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`). The clamp is an unconditional write to the index that does not burn the corresponding supply shares, so wiped-out suppliers retain shares whose `unscale_supply_floor` value is still positive. Once new cash enters the market, that residual claim is withdrawable, transferring fresh depositors' funds to the wiped-out position — the storage-level analog of a corrupt-input write that corrupts adjacent data.

### Finding Description [1](#0-0)  `apply_bad_debt_to_supply_index` computes `reduction_factor = (total_supplied_value - capped_debt) / total_supplied_value` and multiplies the supply index by it. When `bad_debt >= total_supplied_value`, `remaining = 0`, so the mathematically correct index is 0 — but line 88 writes `new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))`, storing `RAY/1000` while every supplier's scaled share balance remains intact. The index is a global accumulator over all shares; writing a nonzero floor is effectively a write beyond the intended domain: share balances that should have been zeroed keep a floor-priced redemption value.

The corrupt write lands via `seize::apply` on the `AccountPositionType::Borrow` leg, which unscales the position debt, calls `apply_bad_debt_to_supply_index`, and burns the debt shares. [2](#0-1) 

The in-repo test `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` demonstrates the full exploit chain on this code: after a wipeout seizure clamps the index, the victim's `unscale_supply_floor` is still positive, a fresh deposit is credited, and the victim's `resolve_withdrawal(i128::MAX, ...)` pays out real cash exactly equal to the fresh deposit, leaving the honest depositor undercollateralized. [3](#0-2) 

### Impact Explanation
Theft of user funds / protocol insolvency. A wiped-out supplier (or anyone holding stranded supply shares after a full bad-debt event) can withdraw a positive floor-valued balance against cash they have no legitimate claim to. In the demonstrated scenario the attacker extracts exactly a subsequent depositor's principal, leaving `cash < honest_claim` — a direct transfer of new deposits to the residual claimant.

### Likelihood Explanation
Reachable by an unprivileged address through the controller's liquidation/`clean_bad_debt` path, which emits `PoolSeizeEntry` records into the pool's seize op. The trigger requires the market's total supplied value to be fully covered by the bad debt (a wipeout where `remaining == 0`), which occurs when collateral is exhausted and debt is socialized — precisely the condition `clean_bad_debt` exists for. After that, any attacker holding stranded shares profits whenever fresh liquidity enters the market, which they can even facilitate themselves by depositing. The clamp is deterministic and does not depend on oracle honesty or privileged action.

### Recommendation
When the write-down factor is zero, burn or flag all outstanding supply shares instead of leaving them with a floored index — e.g., set the index to the floor only if `supplied` is simultaneously zeroed, or track residual shares as explicitly unclaimable. Alternatively, gate withdrawals behind a solvency check so that a market whose `supplied_value_at_floor > cash` from a clamped index cannot pay out against fresh deposits until `recapitalize` restores backing.

### Proof of Concept
1. Attacker opens an over-leveraged borrow (or an existing position goes under water) in market M so that a liquidation/`clean_bad_debt` seizes a borrow whose `bad_debt >= total_supplied_value` — `seize::apply` calls `apply_bad_debt_to_supply_index`, writing `supply_index = SUPPLY_INDEX_FLOOR_RAW` while Alice's supply shares are unburned.
2. Alice's `unscale_supply_floor(alice_scaled)` returns a positive residual (shares × RAY/1000).
3. Attacker (or Bob) supplies `deposit` to M; `mint_supply` + `credit_cash` make `total_owed > cash`.
4. Alice calls `withdraw` with `amount = i128::MAX`; `resolve_withdrawal` burns her shares and `debit_cash(gross)` pays out the fresh deposit, leaving Bob's claim unfunded.

This mirrors `contracts/pool/tests/interest.rs:430-494`, which asserts `gross == deposit` and `cash < bob_claim`.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
