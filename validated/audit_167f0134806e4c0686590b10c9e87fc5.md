### Title
Unsanitized in-toto Subject.Name from a release attestation is written to the terminal via `table.AddField`, allowing ANSI/terminal escape sequence injection - ([File: pkg/cmd/release/verify/verify.go])

### Summary
`printVerifiedSubjects` reads `Subject[].Name` (and digest map values) straight out of the DSSE-signed in-toto `Statement` and passes them unmodified into `tableprinter.AddField`, with no call to the sanitization helper the CLI already uses elsewhere for other externally-sourced display strings. Because `Subject.Name` is derived from the release asset filename that the (unprivileged) repository owner chooses when publishing the release, an attacker can embed ANSI/terminal control sequences that get written verbatim to `io.Out` when a victim runs `gh release verify`.

### Finding Description
`verifyRun` fetches the release attestation via `AttClient.GetByDigest`, filters it with `shared.FilterAttestationsByTag`, and verifies it with `AttVerifier.VerifyAttestation`, then calls `printVerifiedSubjects`: [1](#0-0) 

Inside `printVerifiedSubjects`, the DSSE payload is unmarshalled into an in-toto `v1.Statement`, and for each subject the `Name` and a `digest` map entry are written directly to the table with no escaping/sanitization: [2](#0-1) 

The underlying `internal/tableprinter.TablePrinter` is a thin wrapper over `github.com/cli/go-gh/v2/pkg/tableprinter`; it only handles column padding/truncation/coloring, it performs no terminal-escape stripping: [3](#0-2) 

The CLI codebase demonstrably recognizes this class of risk and has a dedicated sanitization mechanism (`pkg/iostreams/untrusted.go`) that is deliberately applied at other call sites that render externally-controlled strings, e.g. `pkg/cmd/repo/view/http.go`, `pkg/cmd/run/view/view.go`, `pkg/cmd/workflow/shared/shared.go`, `pkg/cmd/pr/diff/diff.go`, and — most tellingly — a purpose-built `sanitizeForTerminal` wrapper (using `asciisanitizer`) added specifically in `pkg/cmd/skills/list/list.go` to strip control characters from untrusted skill metadata before `table.AddField`: [4](#0-3) 

`printVerifiedSubjects` has no equivalent guard. `Subject.Name` originates from the filename of the release asset the repo owner (attacker) uploaded — GitHub's release-attestation generation attests to whatever filename was supplied, it does not restrict the byte content of that name to a safe printable subset. There is no host allowlist, safepath, or output-sanitization check anywhere on this path that would prevent control bytes from reaching the terminal.

### Impact Explanation
An unprivileged attacker who owns any public repository can create a release, upload an asset with a filename containing ANSI/terminal escape sequences, and rely on GitHub's own release attestation to sign that filename into the DSSE payload. When a victim runs `gh release verify` against that release/tag, the escape sequences are echoed to the victim's terminal, allowing terminal-escape injection: this can be used to overwrite/spoof preceding trusted output (e.g. the "Release verified!" success line printed just above the table), hide or rewrite terminal content, or (depending on terminal emulator) manipulate window title / clipboard / cursor position. This maps to GitHub's "terminal escape sequence injection" bounty impact class rather than remote code execution.

### Likelihood Explanation
High feasibility and full repeatability: the attacker needs only an ordinary public repository, the ability to publish a release with a custom-named asset, and GitHub's normal automatic release attestation — no elevated privileges, no token leak, and no interaction beyond the victim running `gh release verify` on the attacker's tag/repo (a normal, expected usage pattern for supply-chain verification).

### Recommendation
Sanitize `name` and `digestStr` (and generally any field derived from `Subject.Name`/`Subject.Digest`) with the same control-character/ANSI-escape sanitization used elsewhere in the codebase (e.g. reuse the `asciisanitizer`-based `sanitizeForTerminal` helper from `pkg/cmd/skills/list/list.go`, or the existing `pkg/iostreams/untrusted.go` mechanism) before calling `table.AddField` in `printVerifiedSubjects`.

func printVerifiedSubjects(io *iostreams.IOStreams, att *verification.AttestationProcessingResult) error {
	cs := io.ColorScheme()
	w := io.Out

	statement := att.Attestation.Bundle.GetDsseEnvelope().Payload
	var statementData v1.Statement

	err := protojson.Unmarshal([]byte(statement), &statementData)
	if err != nil {
		return err
	}

	// If there aren't at least two subjects, there are no assets to display
	if len(statementData.Subject) < 2 {
		return nil
	}

	fmt.Fprintln(w, cs.Bold("Assets"))
	table := tableprinter.New(io, tableprinter.WithHeader("Name", "Digest"))

	for _, s := range statementData.Subject {
		name := s.Name
		digest := s.Digest

		if name != "" {
			digestStr := ""
			for key, value := range digest {
				digestStr = key + ":" + value
			}

			table.AddField(name)
			table.AddField(digestStr)
			table.EndRow()
		}
	}

type TablePrinter struct {
	tableprinter.TablePrinter
	isTTY bool
	cs    *iostreams.ColorScheme

// IsTTY gets whether the TablePrinter will render to a terminal.
func (t *TablePrinter) IsTTY() bool {
	return t.isTTY
}

// AddTimeField in TTY mode displays the fuzzy time difference between now and t.
// In non-TTY mode it just displays t with the time.RFC3339 format.
func (tp *TablePrinter) AddTimeField(now, t time.Time, c func(string) string) {
	var tf string
	if tp.isTTY {
		tf = text.FuzzyAgo(now, t)
	} else {
		tf = t.Format(time.RFC3339)
	}
	tp.AddField(tf, WithColor(c))
}

func renderTable(io *iostreams.IOStreams, skills []listedSkill) error {
	table := tableprinter.New(io, tableprinter.WithHeader("Name", "Agent", "Scope", "Source"))

	for _, skill := range skills {
		table.AddField(sanitizeForTerminal(skill.skillName))
		table.AddField(formatAgentHosts(skill.agentHostIDs))
		table.AddField(displayOrDash(skill.scope))
		table.AddField(displayOrDash(sanitizeForTerminal(skill.source)))
		table.EndRow()
	}

	return table.Render()
}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}
