CVE-2021-35939 concerns an incomplete ownership check across *all* ancestor directories of a locally-created file, allowing a local unprivileged OS user with control of a directory ancestor to escalate to root during a setuid utility's file creation — a classic multi-user filesystem TOCTOU/ownership-race bug class specific to privileged local tools like RPM.

This bug class requires: (1) a local unprivileged OS user distinct from the process owner, (2) a privileged (setuid/root) process creating files while walking up parent directories, and (3) a missing ownership check on some ancestor beyond the immediate parent.

I searched the codebase for directory-creation and file-creation code paths that could be reached with attacker control (`fs::create_dir_all`, `File::create`, keystore/key file writes, PVF worker/artifact directory setup, wasm-builder output paths, network secret-key files) [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) . All of these are host/node-operator-controlled filesystem operations performed by the same OS user/process that runs the node — they are not exposed to any signed extrinsic, contract call, XCM message, or public proof-submission entry point, and they don't involve a privileged process creating files on behalf of a separate, lower-privileged local OS user walking through directories owned by that untrusted user.

The task's required attacker model is a real runtime user entry (signed extrinsic, enabled contract deploy/call, permitted XCM execute/send, or public proof submission) with no privileged role and no local/OS-level access. CVE-2021-35939's root cause is inherently about local multi-user OS filesystem trust boundaries in a setuid utility, which has no meaningful analog in FRAME/XCM/contracts runtime dispatch logic — there is no on-chain "directory ownership" concept, and the closest off-chain analogs (keystore, PVF worker security, wasm-builder) are single-operator, non-multi-tenant processes not reachable through any permitted runtime entry point. No demonstrable Polkadot SDK analog satisfying the attacker model exists.
