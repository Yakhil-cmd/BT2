### Title
Webhook signature verification is bound to the wrong field, allowing cross-organization commit-status/stack forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/secret to validate a webhook against using `repository.owner.login` (or `organization.login`) taken from the *unverified* JSON body, but the handlers that actually act on the payload (`PushHandler`, `StatusHandler`, `PullRequest::*Handler`) resolve the target `Repository`/`Stack`/`Commit` from a *different* field of the same body (`repository.full_name`, or no repository scoping at all). Because Shipit supports multiple GitHub organizations, each with an independently and optionally configured `webhook_secret`, and `GitHubApp#verify_webhook_signature` short-circuits to `true` when that secret is blank, an attacker can pick any configured organization that has no webhook secret to pass verification, while pointing the rest of the payload at a completely different, secured, tracked repository/stack.

### Finding Description
The binding that should hold is:

`organization used to select/verify the HMAC secret == owner of the repository/commit the handler subsequently mutates`

This equality is never enforced.

1. Verification keys off attacker-controlled JSON, not the entity acted upon: [1](#0-0) [2](#0-1) 

2. `verify_webhook_signature` is a no-op whenever the selected organization has no secret configured — an explicitly documented, optional setting: [3](#0-2) [4](#0-3) 

3. Handlers resolve the *real* target repository/stack from a **different payload field**, with no cross-check against the field used for signature selection: [5](#0-4) [6](#0-5) 

4. `StatusHandler` is even weaker: it does not scope by repository at all, matching any commit with the given SHA across the entire install: [7](#0-6) 

Because `Shipit.github(organization:)` picks a completely independent `GitHubApp` instance/secret per organization key: [8](#0-7) 

an attacker can send a raw, unsigned POST to `/webhooks` with `X-Github-Event: status` (or `push`) and a body where `repository.owner.login` (or `organization.login`) is set to any org key configured with `webhook_secret: nil` — trivially passing `verify_signature` — while `sha` matches a commit belonging to a totally unrelated, secured stack/organization. The handler then forges a commit status (`Commit#create_status_from_github!`) or triggers a `GithubSyncJob` (`Stack#sync_github`) for that unrelated stack, even though its organization's real webhook secret was never presented.

### Impact Explanation
Forged commit statuses feed directly into Shipit's deployable-status/merge-status logic, which gates whether a commit is considered safe to deploy or merge. An unauthenticated attacker who only needs to know (a) the name of one configured GitHub org that has no webhook secret (visible in Shipit's own documented multi-app config pattern) and (b) the SHA of a target commit, can inject fabricated "success" statuses for arbitrary tracked repositories/stacks, or trigger sync jobs against arbitrary stacks — a cross-repository write and a path to an unauthorized deploy/merge decision, matching the Critical/High impact classes (unauthorized deploy, cross-repository writes).

### Likelihood Explanation
The attack requires no credentials, no Shipit session, and no GitHub App secret — only knowledge of one org name lacking a webhook secret (an explicitly supported, documented configuration) and a target commit SHA (visible on GitHub or via Shipit's public UI/API for tracked repos). It is a straightforward, single unauthenticated HTTP request.

### Recommendation
- Derive both the verification key **and** the repository resolution from the same canonical identifier, and reject the request if `repository.full_name`'s owner segment does not match the organization used to select/verify the signature.
- Do not allow `verify_webhook_signature` to return `true` unconditionally when `webhook_secret` is blank in multi-organization mode; require a secret per configured org, or scope handlers strictly by the same verified organization.
- Scope `StatusHandler` (and any other handler) queries by the repository resolved from the verified payload, not merely by `sha`, to prevent cross-repository commit/status collisions.

### Proof of Concept
1. Configure Shipit with two GitHub orgs, e.g. `OrgUnsecured` (no `webhook_secret`) and `OrgSecured` (has `webhook_secret`), both with tracked stacks, per `docs/setup.md`'s multi-app example.
2. Find a commit SHA belonging to a stack in `OrgSecured`.
3. POST to `/webhooks` with header `X-Github-Event: status`, no `X-Hub-Signature`, and body:
```json
{
  "sha": "<OrgSecured commit sha>",
  "state": "success",
  "context": "ci/forged",
  "repository": { "owner": { "login": "OrgUnsecured" }, "full_name": "OrgUnsecured/whatever" }
}
```
4. `verify_signature` resolves `Shipit.github(organization: "OrgUnsecured")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (absent) signature.
5. `StatusHandler#process` runs `Commit.where(sha: params.sha)`, finds the `OrgSecured` commit (no repository scoping), and calls `create_status_from_github!`, forging a "success" status on a commit the attacker never authenticated against.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
