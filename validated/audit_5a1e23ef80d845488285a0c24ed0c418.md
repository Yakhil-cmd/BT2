### Title
Webhook signature verified against `repository.owner.login`-selected app while `ClosedHandler` trusts unrelated `repository.full_name` for stack resolution, allowing cross-org review-stack archival - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/organization used for HMAC verification from `params.dig('repository', 'owner', 'login')`, but `ClosedHandler#repository` resolves the mutated `Repository` record from the unrelated `params.repository.full_name` field in the very same JSON body. Since nothing enforces that these two fields agree, a webhook validly signed under an attacker-controlled org's `webhook_secret` can carry a `repository.full_name` pointing at a victim org/repo, causing `review_stack.archive!` to run against the victim's `ReviewStack`.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't: `organization_verifying_signature (params.repository.owner.login)` must equal `organization_owning_the_mutated_repository (owner segment of params.repository.full_name)`.

Trace:
- `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(signature, raw_body)`, per [1](#0-0) , with `repository_owner` defined at [2](#0-1) .
- `Shipit.github(organization:)` looks up the per-organization config (and thus `webhook_secret`) purely by that organization name string, from operator-configured `secrets.github`, at [3](#0-2) .
- After signature verification passes, `WebhooksController#create` dispatches the raw parsed JSON `params` unchanged to the handler chain: [4](#0-3) .
- `ClosedHandler#repository` resolves the `Repository` (and thus which `review_stacks` scope is mutated) from `params.repository.full_name`, a completely separate JSON field from `repository.owner.login`: [5](#0-4) .
- `ClosedHandler#process` then calls `review_stack.archive!` unconditionally once `action == "closed"`: [6](#0-5) , and `ReviewStackAdapter#archive!` deprovisions and archives whatever stack is found by `pr#{number}` environment in that scope: [7](#0-6) .

Root cause: no code anywhere compares `params.dig('repository','owner','login')` (used for HMAC org selection) against the owner segment of `params.repository.full_name` (used for the actual DB write). The `ExplicitParameters` schema on `ClosedHandler` only requires `repository.full_name` to be present; it never requires or checks `repository.owner.login` at all: [8](#0-7) .

Exploit flow: attacker owns `attacker/repo`, which is validly configured in Shipit as its own onboarded organization `attacker` with its own `webhook_secret` known to the attacker (since GitHub webhook secrets for self-service organizations are configured by the org's own operator/owner when wiring up the webhook). Attacker crafts a POST to `/webhooks` with `X-Github-Event: pull_request`, HMAC-signed with `attacker`'s real `webhook_secret`, but with a JSON body where `repository.owner.login == "attacker"` (so `verify_signature` selects and validates against the attacker's own app) while `repository.full_name == "victim-org/victim-repo"` and `number` equal to the PR number of a pre-existing `ReviewStack` for `victim-org/victim-repo`. `verify_signature` succeeds because it authenticates against `attacker`'s config, not the org named in `full_name`. `ClosedHandler` then resolves `Repository.from_github_repo_name("victim-org/victim-repo")` (the real victim `Repository`) and archives the matching `ReviewStack` — a stack the attacker's app installation has no legitimate authority over.

Existing guards do not catch this: `verify_signature` only checks that *some* configured organization's secret validated the raw bytes — it doesn't check that the winning organization matches the repository referenced elsewhere in the same payload. `drop_unhandled_event` only checks the event type is registered. The `ExplicitParameters` schema on `ClosedHandler` never requires or reads `repository.owner.login`, so no cross-check happens downstream either.

### Impact Explanation
An attacker with a valid webhook secret for their own onboarded organization can cause `Shipit::ReviewStack#archive!` — including `stack.remove_from_provisioning_queue` and `stack.deprovision` — to run against any other tenant's review stack, by simply naming `repository.full_name` for the victim while keeping `repository.owner.login` (and thus the HMAC) tied to their own org. This is a cross-tenant mutation: a payload authenticated for one organization mutates another organization's stack, matching the Critical category "a payload for one repository mutating another's stack." It is repeatable against any repository/PR number combination for which a `ReviewStack` exists, across the whole multi-tenant Shipit install.

### Likelihood Explanation
Requires: (1) Shipit configured in multi-organization mode (`secrets.github` keyed by org, per `Shipit.github_default_organization`/`github_app_config`), (2) attacker's own org onboarded with a `webhook_secret` known to the attacker, and (3) a victim `ReviewStack` already existing for the targeted repo/PR-number pair. All three are realistic in a shared, self-service Shipit deployment onboarding multiple GitHub organizations, and the attacker's cost is a single crafted HTTP POST with a valid signature computed over their own crafted body — no secrets belonging to the victim are needed.

### Recommendation
In `WebhooksController#verify_signature` (or in the shared `Handler` base class), after determining the verifying organization, require that it matches the owner segment of every `repository.full_name` referenced in the payload before dispatching to handlers — e.g., reject with 422 if `repository_owner.downcase != params.dig('repository','full_name').to_s.split('/').first`. Alternatively, thread the verified organization through to each handler and have `Repository.from_github_repo_name` (or a new scoped lookup) reject repositories whose owner doesn't match the verified organization.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style):
1. Configure two orgs in test credentials: `attacker` (webhook_secret `"attacker-secret"`) and `victim-org` (webhook_secret `"victim-secret"`).
2. Create `victim_repo = Repository.create!(owner: "victim-org", name: "victim-repo", review_stacks_enabled: true)` and a `ReviewStack` for PR number `42` (`environment: "pr42"`).
3. Build a `pull_request` `closed` payload with `repository: { full_name: "victim-org/victim-repo", owner: { login: "attacker" } }`, `number: 42`, `action: "closed"`.
4. Compute `signature = "sha1=" + OpenSSL::HMAC.hexdigest('sha1', "attacker-secret", body)`.
5. POST to `/webhooks` with `X-Github-Event: pull_request` and that signature.
6. Assert response is NOT `:ok` with the stack archived — i.e. assert `victim_repo.review_stacks.find_by(environment: "pr42").archived? == false` after the request (current buggy behavior would make this assertion fail, proving `archive!` was wrongly invoked); the fix should either return `422` or leave the victim stack untouched.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
