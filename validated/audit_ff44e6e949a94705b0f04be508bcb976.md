## Analysis

The reported bug class is a **binding break where an unprivileged actor uses one properly-issued credential/value to reach a target broader than what the credential was intended to authorize** (WETH input token bypasses the ETH-only path, so `msg.value` sent for the ETH case leaks through unchecked for the non-ETH case). The closest analog in this engine is the `read:stack`-scoped `ApiClient` minted for the CCMenu ("CI dashboard") integration: the token is generated for exactly one requested stack, but the `ApiClient` record backing it is never actually scoped to that stack, so the equality "token authorizes stack X" silently becomes "token authorizes every stack." [1](#0-0) 

The `fetch` action builds a per-stack CCMenu URL, but `client` is looked up/created via `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')` — `stack:` is never part of either the creation attributes or the lookup key. [2](#0-1) 

`ApiClient#stack` is `optional: true`, and nothing in `CCMenuUrlController` sets it, so the resulting record has `stack_id = nil`. [3](#0-2) 

`BaseController#stacks`/`#stack` is the only place scope is enforced: `current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all`. Because the CCMenu client's `stack_id` is `nil`, `stack_id?` is false and the client is treated as **unscoped over `Stack.all`**, so `stacks.from_param!(params[:stack_id])` will resolve *any* stack the token holder asks for. [4](#0-3) 

`Api::CCMenuController` only checks `require_permission :read, :stack` (an operation/scope check, not a specific-stack check) before rendering `stack.deploys_and_rollbacks.last`, where `stack` comes from the unscoped `stacks` collection.

### Title
Unscoped `ApiClient` issued for a single-stack CCMenu URL grants `read:stack` access to every stack - (File: `app/controllers/shipit/ccmenu_url_controller.rb`)

### Summary
`CCMenuUrlController#client` mints an `ApiClient` with `read:stack` permission but never assigns `stack:`, so the token meant to expose one stack's CI status is actually valid for every stack in the Shipit instance.

### Finding Description
`GET /ccmenu/*stack_id` builds a CCMenu URL containing an authentication token for the requested stack:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
``` [5](#0-4) 

`stack:` is neither part of `create_with` (creation defaults) nor part of the `find_or_create_by!` lookup key, so the created/reused `ApiClient` always has `stack_id == nil`. The equality that should hold is `client.stack_id == stack.id` (the stack the user requested a CCMenu URL for); instead it is `client.stack_id == nil`, i.e. unscoped.

`Api::BaseController` treats a `nil` `stack_id` as "no scoping restriction":
```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end
``` [6](#0-5) 

`Api::CCMenuController#show`/`#stack` resolves `params[:stack_id]` against this unscoped collection and only enforces the coarse `read:stack` permission, never checking that the token's intended stack matches the requested one: [7](#0-6) 

Additionally, because the lookup key is only `creator` + fixed `name: 'CCMenu Client'`, the very first CCMenu URL a given user ever generates for *any* stack becomes their single, reused, unscoped `ApiClient` for all future CCMenu URLs of any other stack.

### Impact Explanation
CCMenu/CCTray-style URLs are designed to be handed to external, less-trusted consumers (build-status dashboards, IDE plugins, status widgets), often embedded in pages or configs that are less carefully protected than the main Shipit session. Anyone who obtains a single CCMenu URL — generated for one specific, possibly public/low-sensitivity stack — can reuse its `token` query parameter against `GET /api/stacks/:stack_id/ccmenu` for **any other stack_id**, including stacks the URL was never meant to expose. This is an unauthenticated read of stack build/deploy state for repositories outside the scope the token was created for, matching the High-severity criterion "unauthenticated read of stack state, task streams or deploy output."

### Likelihood Explanation
No special privileges are required beyond obtaining one legitimately-issued CCMenu URL (e.g., from a shared dashboard, log, browser history, or a semi-public status page where such CI-badge URLs are commonly embedded). The exploitation itself is a single unauthenticated HTTP GET to a different `stack_id` with the same token — no signature forgery, no additional credential needed.

### Recommendation
Scope the CCMenu `ApiClient` to the specific stack at creation and in the lookup key, e.g.:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, stack: stack, name: 'CCMenu Client')
end
```
and additionally have `Api::BaseController`/`Api::CCMenuController` assert `current_api_client.stack_id == stack.id` (or absence of `stack_id` be disallowed for CCMenu-purpose clients) so a `nil`-scoped token can never satisfy a stack-specific request implicitly.

### Proof of Concept
1. As an authenticated Shipit user, request `GET /ccmenu/*stack-a` → receive `{"ccmenu_url": ".../api/stacks/stack-a/ccmenu?token=T"}`.
2. Share/leak URL from step 1 (as intended, e.g. embed in an external CI dashboard).
3. An attacker who only has this leaked `token=T` sends `GET /api/stacks/*stack-b/ccmenu?token=T` for a different, unrelated stack `stack-b`.
4. Because the `ApiClient` behind `T` has `stack_id == nil`, `Api::BaseController#stacks` resolves to `Stack.all`, `stack-b` is found, `read:stack` permission check passes, and the attacker receives `stack-b`'s build/deploy status — a stack never referenced when the token was minted.

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack

    end
  end

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
