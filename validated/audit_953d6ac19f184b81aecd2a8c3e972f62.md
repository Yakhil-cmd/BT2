### Title
Webhook signature verification is keyed on `repository.owner.login`/`organization.login` but the acted-upon repository is looked up from the unauthenticated `repository.full_name` field, breaking the "organization authenticated == repository written" binding - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
In multi-GitHub-App deployments, `WebhooksController#verify_signature` selects which organization's webhook secret to HMAC-verify against based solely on `params.dig('repository','owner','login')` (falling back to `params.dig('organization','login')`), while the handler that actually acts on the payload (`Shipit::Webhooks::Handlers::Handler#repository_name`, used by `PushHandler`) resolves the target `Repository`/`Stack` from the separate, unauthenticated `repository.full_name` field. Nothing ties these two fields together, so the field the signature covers is not the field the engine acts on.

### Finding Description
`WebhooksController#verify_signature` computes the signing organization purely from attacker-controlled JSON: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` then looks up per-organization secrets from `secrets.github` (as seen in the multi-app fixture where an organization can have `webhook_secret: # nil`): [3](#0-2) [4](#0-3) 

And `GitHubApp#verify_webhook_signature` trivially returns `true` when no `webhook_secret` is configured for that organization: [5](#0-4) 

Meanwhile, the event handlers resolve the *actual* repository/stack to act on from a completely different, independently-attacker-controlled field of the same JSON body: [6](#0-5) [7](#0-6) 

There is no code anywhere that checks `repository.full_name.split('/').first == repository_owner` (or `== organization.login`). The binding the controller implicitly assumes — "the organization whose secret verified this signature is the organization whose repository gets acted on" — is never enforced.

### Impact Explanation
If an operator has configured multiple GitHub Apps/organizations in `secrets.github` (a documented, supported configuration — see `test/dummy/config/secrets_double_github_app.yml` and `Shipit.github_organizations`), and any one of those organizations either has no `webhook_secret` set (explicitly optional per `docs/setup.md`) or an attacker otherwise possesses/derives that organization's own webhook secret, the attacker can forge a POST to `/webhooks` with:
- `repository.owner.login` (or `organization.login`) = the weakly/unsecured organization (satisfies `verify_signature`),
- `repository.full_name` = `<victim-org>/<victim-repo>` (drives `PushHandler#process` via `stacks`/`Repository.from_github_repo_name`).

This forges a `push` (or other) event against a stack belonging to an organization whose credentials the attacker never proved. For a `push` event this triggers `Stack#sync_github` for the victim's stack — an unauthorized action reachable purely by an unprivileged network attacker (no `ApiClient` token, no session, no GitHub write access needed), matching the "cross-repository" trust-boundary break called out in the rules (organization authenticated vs. repository written).

### Likelihood Explanation
Requires: (1) the operator has configured more than one organization/App in `secrets.github` (a supported, documented feature, not a misconfiguration of "not mounting the engine as documented"), and (2) at least one configured organization has no `webhook_secret` (explicitly documented as "optional") or its secret is otherwise known to the attacker. Given `webhook_secret` is optional and per-org, this is a plausible real-world state, especially for orgs added for OAuth/API-only use without webhook delivery. No privileged credentials of the target org are needed.

### Recommendation
In `Handler#repository_name` (or centrally before dispatch), require that the organization segment of `repository.full_name` matches the organization used to select/verify the webhook signature (`repository.owner.login` / `organization.login`), and reject the request otherwise. Additionally, do not allow `verify_webhook_signature` to silently return `true` for organizations with a blank secret when multiple organizations are configured — require an explicit secret for every configured organization app, or fail closed.

### Proof of Concept
Given `secrets.github` configured with two orgs, `AttackerOrg` (no `webhook_secret`) and `VictimOrg` (has a stack tracked in Shipit):

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # irrelevant, AttackerOrg has no secret

{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "AttackerOrg" },
    "full_name": "VictimOrg/victim-repo"
  }
}
```

- `WebhooksController#verify_signature` sets `repository_owner = "AttackerOrg"`, calls `Shipit.github(organization: "AttackerOrg")`, whose `verify_webhook_signature` returns `true` immediately (`return true unless webhook_secret` at `lib/shipit/github_app.rb:77`).
- `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, whose `repository_name` reads `payload.dig('repository','full_name')` = `"VictimOrg/victim-repo"` (`app/models/shipit/webhooks/handlers/handler.rb:36-38`), resolving and calling `sync_github` on the victim's real stack — despite the request never being authenticated for `VictimOrg`.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
