### Title
Shared-address definitions accepted from a paired device without verifying that the local co-signer is actually required, letting a malicious peer solely drain "shared" funds - (File: wallet_defined_by_addresses.js)

### Summary
The Merlin DEX rug worked because a "Feeto" address was silently granted unlimited, unilateral control over funds that users believed were safe in a jointly-controlled liquidity pool — the trust assumption of shared custody was a facade. `ocore`'s wallet-defined-by-addresses module has an analogous trust gap: when a paired device sends a `new_shared_address` message proposing a definition for what the victim believes is a co-signed (e.g. 2-of-2) shared address, the code never checks that the local user's key is actually *required* by the definition topology — only that it appears *somewhere* in the tree.

### Finding Description
`handleNewSharedAddress()` in `wallet_defined_by_addresses.js` processes an incoming `new_shared_address` device message (`body.address`, `body.definition`, `body.signers`) sent by any paired device/correspondent: [1](#0-0) 

It validates that:
1. `body.definition` hashes to `body.address` (structural integrity),
2. every declared signer address matches an `["address", ...]` leaf extracted by `extractAddressPathsFromDefinition()`,
3. `determineIfIncludesMeAndRewriteDeviceAddress()` confirms one of my known addresses is present *somewhere* in the signer map: [2](#0-1) 
4. `validateAddressDefinition()` only checks that the raw boolean-expression definition is syntactically valid and that "each branch must have a signature" (enforced generically inside `Definition.validateDefinition`): [3](#0-2) 

None of these checks verify that the *topology* actually requires the local address's signature for spending. The `Definition.validateDefinition` "each branch must have a signature" rule is satisfied even by a definition like `["or", [["address","VICTIM"], ["address","ATTACKER"]]]`, because every branch (`VICTIM` alone, and `ATTACKER` alone) independently has a signature. The victim's address is present in the tree — satisfying step 3 — yet the attacker's own address alone fully satisfies the definition and can authorize spends without the victim's cooperation.

The code even carries a self-documented gap acknowledging this:
```
// fix:
// 1. check that my address is referenced in the definition
function validateAddressDefinition(arrDefinition, handleResult){
``` [4](#0-3) 
That comment (and the corresponding check that's missing) is about verifying *presence*, but the deeper, unaddressed problem is that presence alone (rather than being on every OR-branch / being an AND-mandatory party) doesn't guarantee joint control — exactly the "looks decentralized, isn't" pattern that let Merlin's Feeto address silently override the multisig promise.

Once `addNewSharedAddress()` records the address as `shared_addresses` and `shared_address_signing_paths`, the victim's wallet (and UI) will treat it as their own controlled/co-signed address and may direct funds to it (e.g. via `sendToPeerAllSharedAddressesHavingUnspentOutputs`, arbiter contracts, or manual deposits) under the belief that the attacker cannot move funds unilaterally: [5](#0-4) 

### Impact Explanation
Funds sent to an address that the wallet displays/tracks as a jointly-controlled "shared address" can in fact be spent unilaterally by the malicious paired device that proposed the definition, because the local co-signer's signature is not actually required by the accepted definition's boolean structure. This is concrete unauthorized spending / fund loss enabled purely by a message from a paired device counterparty — one of the explicitly in-scope reachable actors.

### Likelihood Explanation
Any correspondent device the user has paired with (a common, low-trust interaction in this wallet-to-wallet protocol, e.g. for arbiter contracts or joint wallets) can trigger this by sending a single `new_shared_address` message with a crafted `or`-based definition that includes the victim's real address as one alternative and the attacker's own address as another. No special privileges beyond being a paired correspondent are needed, and the flaw is deterministic (not race- or timing-dependent).

### Recommendation
In `validateAddressDefinition()` (and/or `handleNewSharedAddress()`), after generic structural validation, additionally verify that the local user's address(es) are structurally indispensable to every satisfying assignment of the definition — e.g., require that the top-level operator enclosing the local signer is `and` (or `r of set`/`weighted and` with a threshold that cannot be met without the local signer), rejecting definitions where the local address sits in an `or` branch that can be independently satisfied by other parties. At minimum, warn/require explicit user confirmation showing the full spending topology (not just address labels) before persisting a peer-proposed shared address as trusted.

### Proof of Concept
1. Attacker pairs their device with the victim's wallet (a normal correspondent relationship).
2. Attacker computes `arrDefinition = ["or", [["address", VICTIM_ADDRESS], ["address", ATTACKER_ADDRESS]]]`, `address = chash160(arrDefinition)`, and sends a `new_shared_address` message: `{address, definition: arrDefinition, signers: {"r.0": {address: VICTIM_ADDRESS, ...}, "r.1": {address: ATTACKER_ADDRESS, ...}}}`.
3. `handleNewSharedAddress()` accepts it: the hash matches, every signer address matches a definition leaf, `determineIfIncludesMeAndRewriteDeviceAddress` finds the victim's own address present, and `validateAddressDefinition` accepts the definition because both `or` branches have a valid signature.
4. The wallet stores this as a `shared_addresses` entry and treats it as a jointly-controlled address in the UI/APIs.
5. The victim (or a third party trusting the "shared"/multisig appearance) sends funds to `address`.
6. The attacker alone signs and posts a payment unit satisfying only the `["address", ATTACKER_ADDRESS]` branch, spending all funds without any cooperation from the victim — replicating the Merlin-style outcome where a supposedly safe custody arrangement was in fact unilaterally controllable by one party.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
