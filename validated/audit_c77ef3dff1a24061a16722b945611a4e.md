### Title
Webhook signature verification org is derived from a different attacker-controlled payload field than the Repository lookup, allowing a payload verified under one org to create a review Stack under another org's Repository - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/org config (and therefore which `webhook_secret`) to validate the request against using `params.dig('repository', 'owner', 'login')`, while `OpenedHandler#repository` (and `ClosedHandler`, `ReopenedHandler`, etc.) looks up the target `Shipit::Repository` using `params.repository.full_name` [1](#0-0) [2](#0-1) . Both values are independent, attacker-controlled fields inside the same JSON body, and nothing cross-validates that `repository.owner.login` matches the owner segment of `repository.full_name`.

### Finding Description
The binding the code implicitly assumes is:
`params['repository']['owner']['login'] == owner_segment(params['repository']['full_name'])`

This is never enforced. `verify_signature` computes `repository_owner` purely from `params.dig('repository', 'owner', 'login')` and asks `Shipit.github(organization: repository_owner)` for a `GitHubApp`, then checks `verify_webhook_signature` against that org's `webhook_secret` [3](#0-2) . If that org's config has no `webhook_secret` set, `GitHubApp#verify_webhook_signature` unconditionally returns `true`: `return true unless webhook_secret` [4](#0-3) .

Separately, `Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#repository` resolves the actual target `Repository` model with `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, which splits `full_name` on `/` and does `find_by(owner:, name:)` [5](#0-4) . This value comes from `params['repository']['full_name']`, a field the controller never uses and never checks against `repository_owner`.

Attack: an attacker crafts a raw JSON `pull_request` webhook where:
- `repository.owner.login` = `"org-x"` (any org configured in `secrets.github` that has no `webhook_secret` set, e.g. a legacy/test org with `webhook_secret: nil` — several example configs in this codebase show orgs configured this way [6](#0-5) [7](#0-6) )
- `repository.full_name` = `"org-y/victim-repo"` (a real tracked repository belonging to a different, victim organization)
- `pull_request.head.ref`, `pull_request.head.sha`, `pull_request.user.login`, `labels`, `sender.login` are all fully attacker-chosen.

`verify_signature` computes `repository_owner = "org-x"`, calls `Shipit.github(organization: "org-x")`, and since org-x has no `webhook_secret`, `verify_webhook_signature` returns `true` regardless of the actual `X-Hub-Signature` header (even if absent or garbage) [8](#0-7) . The request passes signature verification without the attacker knowing any secret belonging to org-x or org-y.

The controller then dispatches to `OpenedHandler.call(params)` [9](#0-8) . `OpenedHandler#process` computes `repository` via `params.repository.full_name` = `"org-y/victim-repo"`, resolving to the real victim `Repository` row (owned by org-y) [10](#0-9) . If that repository has `review_stacks_enabled` and a matching `provisioning_behavior`, `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` creates a brand-new `Shipit::Stack`/`ReviewStack` row scoped to org-y's `Repository`, with `branch: params.pull_request.head.ref` (attacker-named) and `environment: "pr#{params.number}"` [11](#0-10) .

No existing guard closes this gap:
- `drop_unhandled_event` only checks the event type is registered, not repository consistency [12](#0-11) .
- The `ExplicitParameters` schema in `OpenedHandler` only requires `repository.full_name` to be a `String`; it never requires or checks `repository.owner.login` [13](#0-12) .
- `Repository.from_github_repo_name` performs no cross-check against the verifying org — it trusts `full_name` verbatim [5](#0-4) .
- `Stack`/`ReviewStack` model validations do not verify that the creating request was authenticated for that specific repository's org.

### Impact Explanation
This is a payload for one repository (verified under org-x's, possibly secret-less, config) mutating another repository's state (creating a Stack owned by org-y) — matching the Critical category "a payload for one repository mutating another's stack." The attacker fully controls the created Stack's `branch` and `environment` name, and the attached `PullRequest` record's metadata (`head.sha`, `user.login`, labels), planting a deployable Stack under the victim org's Repository ahead of any real PR review. This blast radius extends to any org configured in `secrets.github` without a `webhook_secret` (a supported, documented configuration in this codebase), which the attacker can pair with any other tracked repository in the same Shipit install, regardless of which org that repository belongs to.

### Likelihood Explanation
Preconditions: (1) at least one org configured in `secrets.github` with `webhook_secret` unset (a legitimate, non-privileged operational configuration — the repo's own example secrets files ship with `webhook_secret: nil`), and (2) a target victim repository tracked by Shipit with `review_stacks_enabled` and a `provisioning_behavior` (`allow_all`, or label-based with attacker satisfying the label). Given these, the attacker needs no session, token, or secret — only the ability to POST an arbitrary JSON body to `/webhooks` with a spoofed `X-Github-Event: pull_request` header. This is repeatable per PR number/environment and against any tracked repository in the install.

### Recommendation
Bind `verify_signature`'s org resolution and the handler's `Repository` resolution to the *same* source of truth, and require they match. Concretely: derive `repository_owner` from `params.dig('repository', 'full_name')`'s owner segment (not from `repository.owner.login`) so the same field drives both authentication and target lookup, or explicitly assert `params.dig('repository','owner','login') == full_name.split('/').first` before signature verification and reject on mismatch (422). Additionally, do not treat an absent `webhook_secret` as an implicit bypass across multi-org configs — require every configured org to define a `webhook_secret` when `github_organizations.size > 1`, or fail closed.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb

test "pull_request payload verified under org-x (no secret) creates a Stack under org-y's Repository" do
  # Binding under test:
  # repository_owner_used_for_signature == owner_segment(repository.full_name)_used_for_lookup
  victim_repo = shipit_repositories(:shipit) # owner: "shopify" per fixtures
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :allow_all)

  attacker_org = "org-x-no-secret" # configured in secrets.github with webhook_secret: nil
  Shipit.stubs(:github).with(organization: attacker_org)
        .returns(Shipit::GitHubApp.new(attacker_org, { webhook_secret: nil }))

  payload = JSON.parse(payload(:pull_request_opened))
  payload["repository"]["owner"] = { "login" => attacker_org }   # used ONLY for signature org lookup
  payload["repository"]["full_name"] = victim_repo.github_repo_name # used for actual Stack creation
  payload["pull_request"]["head"]["ref"] = "attacker-planted-branch"

  @request.headers['X-Github-Event'] = 'pull_request'
  # No valid X-Hub-Signature required, since attacker_org has no webhook_secret

  assert_difference -> { victim_repo.stacks.count }, 1 do
    post :create, body: payload.to_json, as: :json
  end

  assert_response :ok
  stack = victim_repo.stacks.last
  assert_equal "attacker-planted-branch", stack.branch
  assert_equal victim_repo.id, stack.repository_id
  # This proves: repository_owner ("org-x-no-secret") used to pick the verifying GitHubApp
  # != owner("shopify") of the Repository actually mutated -- the binding is broken.
end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
