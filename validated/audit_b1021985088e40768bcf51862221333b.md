### Title
RAY-value overflow in `accrue_step` permanently freezes an overgrown market - ([File: common/src/rates/simulate.rs])

### Summary
**Severity: Medium.** `accrue_step` converts aggregate scaled debt and supply into RAY values before calculating utilization, while `scaled_to_original` performs the multiplication in the `i128` RAY domain and panics when the result exceeds `i128::MAX`. [1](#0-0) [2](#0-1) 

Every pool mutation synchronizes interest before accounting, so once either aggregate crosses the representable RAY-value limit, repayment, withdrawal, and liquidation legs for that market revert before changing state. [3](#0-2) [4](#0-3) 

### Finding Description
`accrue_step` computes `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original`, and `Ray::mul` then calls `mul_div_half_up`. [5](#0-4) [6](#0-5) 

`mul_div_half_up` uses an exact `I256` fallback for the intermediate product, but still converts the final quotient back to `i128`; an unrepresentable result returns `None` and is converted into `GenericError::MathOverflow` by the caller. [7](#0-6) [8](#0-7) 

The pool’s `synced_market` helper calls `interest::global_sync`, which runs `accrue_step` before any leg-specific operation and only marks the market accrued afterward. [9](#0-8) 

Repayment and withdrawal reach that synchronization through `ops::load_leg` before resolving shares, so they cannot reduce the oversized scaled balances once accrual starts panicking. [10](#0-9) [11](#0-10) 

### Impact Explanation
This permanently freezes the affected `(hub_id, asset)` market absent a code upgrade: supplier cash cannot be withdrawn, borrower debt cannot be repaid, and liquidation settlement cannot proceed because those paths all attempt the same accrual first. [12](#0-11) 

The existing regression test demonstrates `update_indexes` reverting with `MATH_OVERFLOW`, followed by withdrawal and repayment reverting with the same error. [13](#0-12) [12](#0-11) 

### Likelihood Explanation
Triggering the condition requires a very large listed market and enough index growth that a scaled balance times its index exceeds `i128::MAX`; the documented domain explicitly notes that value overflow can occur before the index ceiling and block repayment or withdrawal. [14](#0-13) 

The condition is nevertheless reachable through ordinary `supply` and `borrow` flows within admitted decimal and cap bounds, and any authorized caller can later invoke controller `update_indexes(caller, assets)`, which forwards the affected `HubAssetKey` to the owner-gated pool entrypoint. [15](#0-14) [16](#0-15) 

### Recommendation
Keep the protocol out of the unrepresentable state by enforcing `scaled * index / RAY <= i128::MAX` before minting shares and before persisting an index increase, or derive utilization and accrued rewards with `I256` arithmetic without materializing the oversized aggregate as `i128`. [17](#0-16) 

If a market is already at the boundary, accrual should clamp the index to the maximum representable value for its current scaled totals rather than panic, preserving repayment, withdrawal, and liquidation paths. [18](#0-17) 

### Proof of Concept
1. On an active 18-decimal market with a cap allowing at least `1_000_000_000 * 10^18` base units, Bob calls controller `supply(caller=BOB, account_id=0, spoke_id=<spoke_id>, assets=[(hub_asset, 1_000_000_000 * 10^18)])`. [19](#0-18) 
2. Alice supplies sufficient collateral on another listed market and calls `borrow(caller=ALICE, account_id=<alice_id>, borrows=[(hub_asset, 980_000_000 * 10^18)], to=None)`. [20](#0-19) 
3. Once index growth makes `borrowed * borrow_index / RAY` exceed `i128::MAX`, any address calls `update_indexes(caller=<any_address>, assets=[hub_asset])`; the controller only requires that caller’s authorization and then calls `pool.update_indexes`. [15](#0-14) 
4. The call reaches `accrue_step`, panics with `MathOverflow`, and leaves the market unaccrued; later `withdraw` and `repay` calls for even minimal amounts repeat the same accrual and revert, as asserted by the regression test. [21](#0-20)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
