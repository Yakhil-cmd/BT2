The report describes an application-level vulnerability in DataEase (a Java BI tool) where a REST endpoint (`/de2api/datasetData/previewSql`) accepts attacker-controlled raw SQL text and executes it via `prepareStatement(...).executeQuery()` against arbitrary configured datasources. This is a SQL-preview feature vulnerability specific to a data-visualization web application with a "datasource" concept and user-supplied SQL strings — a bug class that has no structural analog in the Polkadot SDK.

I searched for SQL usage across the codebase. The only SQL-executing code found is in the `pallet-revive` Ethereum RPC receipt/indexer component, which uses a local SQLite database purely for internal indexing of block hashes, transaction hashes, and logs — not for querying arbitrary user-configured external datasources: [1](#0-0) . All queries there use bound parameters (`$1`, `$2`, etc.) via `sqlx::query!` macros, and even the dynamically-built `DELETE ... WHERE ... in (...)` statements use `?` placeholders bound via `.bind()` rather than concatenating user-controlled SQL text [2](#0-1) . There is no RPC/extrinsic entry point in this codebase that accepts a raw SQL string from an external, unprivileged caller and forwards it for execution against a queryable datasource, as DataEase's `previewSql` endpoint does.

Polkadot SDK's runtime/FRAME architecture has no concept of "datasources" or a "preview SQL" feature — storage access is through typed pallet storage APIs, not free-form SQL, so the described bug class (arbitrary SQL execution via unsanitized preview endpoint) does not map onto any signed extrinsic, XCM message, or contract call surface in this repository.

	async fn remove(&self, block_mappings: &[BlockHashMap]) -> Result<(), ClientError> {
		if block_mappings.is_empty() {
			return Ok(());
		}
		log::debug!(target: LOG_TARGET, "Removing block hashes: {block_mappings:?}");

		let mut db_tx = self.db_ctx.pool.begin().await?;

		for chunk in block_mappings.chunks(self.db_ctx.max_variable_number) {
			let placeholders = vec!["?"; chunk.len()].join(", ");
			let sql_tx =
				format!("DELETE FROM transaction_hashes WHERE block_hash in ({placeholders})");
			let sql_logs = format!("DELETE FROM logs WHERE block_hash in ({placeholders})");
			let sql_mappings = format!(
				"DELETE FROM eth_to_substrate_blocks WHERE substrate_block_hash in ({placeholders})"
			);

			let mut delete_tx_query = sqlx::query(&sql_tx);
			let mut delete_logs_query = sqlx::query(&sql_logs);
			let mut delete_mappings_query = sqlx::query(&sql_mappings);

			for block_map in chunk {
				delete_tx_query = delete_tx_query.bind(block_map.substrate_hash.as_ref());
				delete_logs_query = delete_logs_query.bind(block_map.ethereum_hash.as_ref());
				delete_mappings_query =
					delete_mappings_query.bind(block_map.substrate_hash.as_ref());
			}

			delete_tx_query.execute(&mut *db_tx).await?;
			delete_logs_query.execute(&mut *db_tx).await?;
			delete_mappings_query.execute(&mut *db_tx).await?;
		}

		db_tx.commit().await?;
		Ok(())
	}
