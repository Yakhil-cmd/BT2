### Title
TPS-fee rate calculation can be deflated by choosing a stale `last_ball_unit` to widen the `elapsed` divisor - ([File: storage.js])

### Summary
The `computationUnitsAvailable` bug class (a rate = amount / duration where the duration can be freely minimized by the caller) has an analog in `ocore`'s TPS-fee anti-spam mechanism. `storage.getLocalTps()` / `getLocalTpsFee()` and `getFinalTps()` compute `tps = count / elapsed`, where `elapsed = unit.timestamp - last_ball_unit.timestamp`. Both `timestamp` and, more importantly, which stable ball is referenced as `last_ball_unit` are chosen by the unit's author, and validation never enforces that `last_ball_unit` be the most recent stable ball. By deliberately referencing an older (but still valid, stable, on-MC) `last_ball_unit`, an author can artificially inflate `elapsed`, which deflates the computed `tps` and, in turn, the `min_tps_fee` required by `validateTpsFee()` in `validation.js`.

### Finding Description
`getLocalTps()` computes:
```
const elapsed = (objUnitProps.timestamp - objLastBallUnitProps.timestamp) || elapsedTimeWhenZero;
...
return count / elapsed;
``` [1](#0-0) 

`getLocalTpsFee()` then turns this `tps` into the minimum fee the unit must pay:
```
const tps_fee_per_unit = Math.round(tps_fee_multiplier * base_tps_fee * (exp(tps / tps_interval) - 1));
return count_units * tps_fee_per_unit;
``` [2](#0-1) 

This is the exact same "rate = amount / duration, duration chosen by the caller" pattern flagged in the external report: `computationUnitsAvailable` divides `computationUnits` by an attacker-chosen `lockEnd - lockStart`, and here `count` is divided by an author-chosen `elapsed = timestamp - last_ball_timestamp`.

`validateTpsFee()` uses exactly this function to compute the minimum acceptable fee for the newly posted unit:
```
const min_tps_fee = await storage.getLocalTpsFee(conn, objUnitProps, count_units);
...
if (tps_fees_balance + objUnit.tps_fee * share < min_tps_fee * share)
    return callback(...);
``` [3](#0-2) 

The two inputs to `elapsed` are both attacker-influenced:
- `objUnit.timestamp` is set by the composer/author and is only constrained to be `>= parent timestamp` and `<= now + 5s`; there is no lower bound tying it close to real time or to `last_ball_timestamp`. [4](#0-3) [5](#0-4) 
- `last_ball_unit` merely has to be a stable, on-main-chain ball that is included in the unit's parents (`max_parent_limci >= last_ball_mci`); nothing requires it to be the most recently stabilized ball. [6](#0-5) [7](#0-6) 

Because a well-connected DAG allows referencing an older, but still-valid, stable MC ball as `last_ball_unit` while keeping a fresh `timestamp`, an author can maximize `elapsed` and thereby minimize the computed local `tps`, hence minimize `min_tps_fee`. This directly parallels the `GatewayRegistry` bug: instead of shrinking a "duration" denominator to inflate a rate, here the "duration" (`elapsed`) is enlarged to deflate a rate (`tps`)—the same root cause of trusting a party-controlled duration in a rate formula that feeds an economic/anti-spam control.

### Impact Explanation
`tps_fee` is `ocore`'s post-v4 mechanism for pricing DAG throughput and discouraging spam bursts (an economic control analogous to a resource/quota system). If the required minimum fee can be systematically underpaid by choosing a stale `last_ball_unit`, an author can pay less than the protocol-intended price for the throughput they consume. Because `tps_fees_balance` (used across many later units and shared among earned-headers-commission recipients) is accounted against this deflated `min_tps_fee`, this also skews the fee-balance bookkeping (`tps_fees_balances`) used by `getPaidTpsFee()` and the fee redistribution logic in `updateTpsFees()`, which downstream nodes rely on for consensus on unit validity via `validateTpsFee`. Divergent interpretations of the "correct" `min_tps_fee` for a unit (if some nodes' local computation of `elapsed` differs, e.g., due to different `last_ball_unit` selection paths) could, in edge cases, produce disagreement about whether a given `tps_fee` field is sufficient, i.e., a validity dispute among nodes for the same objective.

### Likelihood Explanation
Medium. Exploiting this requires no special privilege — any unit author who composes their own unit (bypassing the default composer's freshest-parent behavior) can pick a stable ancestor further back as `last_ball_unit`, subject only to needing it to be included via parents (`max_parent_limci >= last_ball_mci`), which is normal DAG topology, not a corner case. The economic incentive (avoiding the tps-fee anti-spam surcharge during congestion) is direct and repeatable.

### Recommendation
Do not let the fee-relevant `elapsed` be a value freely chosen by the unit author. Consider basing `min_tps_fee`/`tps` on the most recent network-wide known stable MC timestamp available at broadcast time (independent of which `last_ball_unit` the author references), or enforce that `last_ball_unit` used for TPS-fee purposes must be the most recent stable ball known to validators, not merely "some stable ball included in the parents." Alternatively, clamp `elapsed` to a value derived from `main_chain_index` progression (e.g., number of stabilized MC indices) rather than raw wall-clock timestamps that the author controls, mirroring the report's recommendation to enforce a minimum "epoch" granularity rather than trusting an attacker-chosen interval.

### Proof of Concept
1. Wait until the network has multiple stable MC balls, e.g. balls at MCI `N` (timestamp `T1`) and a later stable ball at MCI `N+50` (timestamp `T2 >> T1`).
2. Compose a new unit whose `parent_units` still legally include ball `N` in their ancestry (so `max_parent_limci >= N`), and explicitly set `last_ball_unit` to the ball at MCI `N` instead of the freshest stable ball at `N+50`, while setting `objUnit.timestamp` to the current time.
3. `elapsed = timestamp - T1` is now much larger than the "natural" `timestamp - T2` a default composer would have used, so `getLocalTps()` returns a much smaller `tps`, and `getLocalTpsFee()` returns a much smaller `min_tps_fee`.
4. `validateTpsFee()` accepts a `tps_fee` computed from this deflated `min_tps_fee`, letting the unit pass with a fee lower than the value that reflects the actual, current network throughput. [8](#0-7) [9](#0-8)

async function getLocalTps(conn, objUnitProps, count_units = 1) {
	const unit = objUnitProps.unit;
	const objLastBallUnitProps = await readUnitProps(conn, objUnitProps.last_ball_unit);
	const elapsed = (objUnitProps.timestamp - objLastBallUnitProps.timestamp) || elapsedTimeWhenZero;
	const last_ball_mci = objLastBallUnitProps.main_chain_index;
	let count = count_units;
	let visited = {};
	let arrProps = [objUnitProps];

	while (true) {
		let arrParentProps = [];
		for (let props of arrProps) {
			if (!props.best_parent_unit)
				throw Error(`no best parent in props of ${props.unit}`);
			const parent_units = props.unit === unit ? [props.best_parent_unit] : props.parent_units;
			for (let parent_unit of parent_units) {
				if (visited[parent_unit])
					continue;
				const parentProps = await readUnitPropsWithParents(conn, parent_unit);
				if (parentProps.main_chain_index <= last_ball_mci && parentProps.main_chain_index !== null)
					continue;
				if (!parentProps.bAA) // AA responses are counted elsewhere via max_aa_responses of their trigger
					count += getCountUnitsPayingTpsFee(parentProps);
				visited[parent_unit] = true;
				arrParentProps.push(parentProps);
			}
		}
		if (arrParentProps.length === 0)
			break;
		arrProps = arrParentProps;
	}
	if (count === count_units && last_ball_mci > 0 && constants.COUNT_WITNESSES > 1)
		throw Error(`getLocalTps count=${count}, elapsed=${elapsed}, ${JSON.stringify(objUnitProps)}`);
	return count / elapsed;
}

async function getLocalTpsFee(conn, objUnitProps, count_units = 1) {
	const objLastBallUnitProps = await readUnitProps(conn, objUnitProps.last_ball_unit);
	const last_ball_mci = objLastBallUnitProps.main_chain_index;
	const base_tps_fee = getSystemVar('base_tps_fee', last_ball_mci); // unit's mci is not known yet
	const tps_interval = getSystemVar('tps_interval', last_ball_mci);
	const tps_fee_multiplier = getSystemVar('tps_fee_multiplier', last_ball_mci);
	const tps = await getLocalTps(conn, objUnitProps, count_units);
	console.log(`local tps at ${objUnitProps.unit} ${tps}`);
	const tps_fee_per_unit = Math.round(tps_fee_multiplier * base_tps_fee * (exp(tps / tps_interval) - 1));
	return count_units * tps_fee_per_unit;
}

async function validateTpsFee(conn, objJoint, objValidationState, callback) {
	if (objValidationState.last_ball_mci < constants.v4UpgradeMci || !objValidationState.last_ball_mci)
		return callback();
	const objUnit = objJoint.unit;
	if (objValidationState.bAA) {
		if ("tps_fee" in objUnit)
			return callback("tps_fee in AA response");
		return callback();
	}
	if ("content_hash" in objUnit) // tps_fee and other unit fields have been already stripped
		return callback();
	const objUnitProps = {
		unit: objUnit.unit,
		parent_units: objUnit.parent_units,
		best_parent_unit: objValidationState.best_parent_unit,
		last_ball_unit: objUnit.last_ball_unit,
		timestamp: objUnit.timestamp,
		count_primary_aa_triggers: objValidationState.count_primary_aa_triggers,
		max_aa_responses: objUnit.max_aa_responses,
	};
	const count_units = storage.getCountUnitsPayingTpsFee(objUnitProps);
	const min_tps_fee = await storage.getLocalTpsFee(conn, objUnitProps, count_units);
	console.log('validation', {min_tps_fee}, objUnitProps)
	
	// compare against the current tps fee or soft-reject
	const current_tps_fee = objJoint.ball ? 0 : storage.getCurrentTpsFee(0, count_units); // very low while catching up
	const min_acceptable_tps_fee_multiplier = objJoint.ball ? 0 : storage.getMinAcceptableTpsFeeMultiplier();
	const min_acceptable_tps_fee = current_tps_fee * min_acceptable_tps_fee_multiplier * count_units;

	const author_addresses = objUnit.authors.map(a => a.address);
	const bFromOP = isFromOP(author_addresses, objValidationState.last_ball_mci);
	const recipients = storage.getTpsFeeRecipients(objValidationState.last_ball_mci < constants.tpsFeeRecipientsFixMci ? objUnit.earned_headers_commission_recipients : storage.ehcr2assoc(objUnit.earned_headers_commission_recipients), author_addresses);
	for (let address in recipients) {
		const share = recipients[address] / 100;
		if (!share)
			throw Error(`invalid share for address ${address}: ${share}`);
		const [row] = await conn.query("SELECT tps_fees_balance FROM tps_fees_balances WHERE address=? AND mci<=? ORDER BY mci DESC LIMIT 1", [address, objValidationState.last_ball_mci]);
		const tps_fees_balance = row ? row.tps_fees_balance : 0;
		if (tps_fees_balance + objUnit.tps_fee * share < min_tps_fee * share)
			return callback(`tps_fee ${objUnit.tps_fee} + tps fees balance ${tps_fees_balance} less than required ${min_tps_fee} for address ${address} whose share is ${share}`);
		const tps_fee = tps_fees_balance / share + objUnit.tps_fee;
		if (tps_fee < min_acceptable_tps_fee) {
			if (!bFromOP)
				return callback(createTransientError(`tps fee on address ${address} must be at least ${min_acceptable_tps_fee}, found ${tps_fee}`));
			console.log(`unit from OP, hence accepting despite low tps fee on address ${address} which must be at least ${min_acceptable_tps_fee} but found ${tps_fee}`);
		}
	}
	callback();
