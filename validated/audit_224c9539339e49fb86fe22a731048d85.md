## Analysis

The cert-manager advisory (GHSA-gx3x-vq4p-mhhv) describes a DoS caused by untrusted/attacker-influenced data being cached and later triggering an unchecked panic on every subsequent access, bricking the controller until manually recovered. The `raydium-cp-swap` program has an directly analogous unchecked-division panic reachable from the swap entrypoints, which any unprivileged swapper can trigger with a single crafted transaction, permanently DoS'ing the pool's swap path.

### Title
Divide-by-zero panic in `PoolState::token_price_x32` permanently DoSes swaps once net vault liquidity reaches zero - (File: `programs/cp-swap/src/states/pool.rs`)

### Summary
`token_price_x32` performs raw (non-`checked_div`) division that panics whenever the net (fee-excluded) balance of either vault reaches zero. This function is invoked unconditionally from `get_swap_params`, which both `swap_base_input` and `swap_base_output` call on every swap. Any unprivileged user can drive a pool's net vault balance to zero through a routine, fully-permitted `withdraw`, after which every subsequent `swap_base_input`/`swap_base_output` transaction on that pool panics and fails.

### Finding Description
`PoolState::token_price_x32` computes: [1](#0-0) 

using plain `/` operators instead of `checked_div`. The inputs `token_0_amount`/`token_1_amount` come from `vault_amount_without_fee`, which subtracts accumulated protocol/fund/creator fees from the live vault balance: [2](#0-1) 

`token_price_x32` is called from `get_swap_params`, unconditionally, on every swap, using the *current* raw vault balances before any transfer for the instruction occurs: [3](#0-2) 

`get_swap_params` is invoked at the top of both `swap_base_input` and `swap_base_output`, before any other validation of the trade amount: [4](#0-3) [5](#0-4) 

If the net liquidity of either token (vault balance minus that token's accrued fees) is exactly zero — which happens whenever LPs withdraw all pool liquidity via the fully permissionless `withdraw` instruction (which only uses `vault_amount_without_fee`, not `token_price_x32`, so it does not itself panic) — then any subsequent swap attempt computes `x / 0` in `token_price_x32` and panics. `withdraw` itself: [6](#0-5) 

does not have any minimum-remaining-liquidity guard, so an LP holding all (or effectively all) LP tokens can reduce net vault amounts to zero in one ordinary transaction.

### Impact Explanation
Once net liquidity in either token reaches zero, every future `swap_base_input`/`swap_base_output` call on that pool panics and reverts, making the pool's swap functionality permanently unusable until a new `deposit` restores non-zero net liquidity. This is a Denial-of-Service condition triggerable by an unprivileged actor (any LP performing a legitimate, permitted full withdrawal) with no special privileges, mirroring the cert-manager bug class of "crafted/edge-case data causes an unrecoverable panic on every future access, until a manual/administrative recovery action is taken."

### Likelihood Explanation
High reachability: the only precondition is that a pool's net (fee-adjusted) vault balance for one side hits zero, which naturally occurs whenever the LP(s) fully exit a pool (e.g., a newly created pool with a single depositor withdrawing 100% of the position) — a completely ordinary, unprivileged action requiring no attacker-controlled account substitution or malicious data crafting beyond normal instruction parameters.

### Recommendation
Replace the raw division in `token_price_x32` with `checked_div`/`checked_mul` and propagate `None` as an `ErrorCode` (e.g., `ErrorCode::ZeroTradingTokens` or a new error) instead of panicking, consistent with the rest of the fee/curve math in the codebase (`curve/fees.rs`, `curve/constant_product.rs`) which already uses `checked_*` throughout.

### Proof of Concept
1. Create a pool and deposit a small amount of liquidity as the sole LP.
2. Call `withdraw` for the full LP token balance, draining net vault liquidity (`vault_amount_without_fee`) for at least one token to `0` (no minimum-liquidity check exists in `withdraw`).
3. Any subsequent call to `swap_base_input` or `swap_base_output` on this pool now triggers `get_swap_params` → `token_price_x32`, dividing by the zero net amount, causing an unrecoverable panic and reverted transaction. Repeat step 3 to confirm the pool's swap path remains permanently broken until a new `deposit` restores non-zero net liquidity.

    pub fn vault_amount_without_fee(&self, vault_0: u64, vault_1: u64) -> Result<(u64, u64)> {
        let fees_token_0 = self
            .protocol_fees_token_0
            .checked_add(self.fund_fees_token_0)
            .ok_or(ErrorCode::MathOverflow)?
            .checked_add(self.creator_fees_token_0)
            .ok_or(ErrorCode::MathOverflow)?;
        let fees_token_1 = self
            .protocol_fees_token_1
            .checked_add(self.fund_fees_token_1)
            .ok_or(ErrorCode::MathOverflow)?
            .checked_add(self.creator_fees_token_1)
            .ok_or(ErrorCode::MathOverflow)?;
        Ok((
            vault_0
                .checked_sub(fees_token_0)
                .ok_or(ErrorCode::InsufficientVault)?,
            vault_1
                .checked_sub(fees_token_1)
                .ok_or(ErrorCode::InsufficientVault)?,
        ))
    }

    pub fn token_price_x32(&self, vault_0: u64, vault_1: u64) -> Result<(u128, u128)> {
        let (token_0_amount, token_1_amount) = self.vault_amount_without_fee(vault_0, vault_1)?;
        Ok((
            token_1_amount as u128 * Q32 as u128 / token_0_amount as u128,
            token_0_amount as u128 * Q32 as u128 / token_1_amount as u128,
        ))
    }

    pub fn get_swap_params(
        &self,
        input_vault_key: Pubkey,
        output_vault_key: Pubkey,
        input_vault_amount: u64,
        output_vault_amount: u64,
    ) -> Result<SwapParams> {
        let (
            trade_direction,
            total_input_token_amount,
            total_output_token_amount,
            token_0_price_x64,
            token_1_price_x64,
            is_creator_fee_on_input,
        ) = if input_vault_key == self.token_0_vault && output_vault_key == self.token_1_vault {
            let (total_input_token_amount, total_output_token_amount) =
                self.vault_amount_without_fee(input_vault_amount, output_vault_amount)?;
            let (token_0_price_x64, token_1_price_x64) =
                self.token_price_x32(input_vault_amount, output_vault_amount)?;

            (
                TradeDirection::ZeroForOne,
                total_input_token_amount,
                total_output_token_amount,
                token_0_price_x64,
                token_1_price_x64,
                self.is_creator_fee_on_input(TradeDirection::ZeroForOne)?,
            )
        } else if input_vault_key == self.token_1_vault && output_vault_key == self.token_0_vault {
            let (total_output_token_amount, total_input_token_amount) =
                self.vault_amount_without_fee(output_vault_amount, input_vault_amount)?;
            let (token_0_price_x64, token_1_price_x64) =
                self.token_price_x32(output_vault_amount, input_vault_amount)?;

            (
                TradeDirection::OneForZero,
                total_input_token_amount,
                total_output_token_amount,
                token_0_price_x64,
                token_1_price_x64,
                self.is_creator_fee_on_input(TradeDirection::OneForZero)?,
            )
        } else {
            return err!(ErrorCode::InvalidVault);
        };
        Ok(SwapParams {
            trade_direction,
            total_input_token_amount,
            total_output_token_amount,
            token_0_price_x64,
            token_1_price_x64,
            is_creator_fee_on_input,
        })
    }
