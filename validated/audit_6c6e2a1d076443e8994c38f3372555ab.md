### Title
Rogue route venue injects a token `transfer` under the caller's signed auth tree, draining unrelated wallet funds — (File: contracts/controller/src/strategies/swap.rs)

### Summary
The controller grants the swap router an exact-input transfer authorization and then invokes it with a fully attacker-controlled `swap` payload (`StrategySwap` XDR). The router (and the venue/pool addresses the payload names) executes below the user's `require_auth` on the strategy entrypoint. A malicious route can name an attacker-deployed "pool" contract that calls `token.transfer(victim, attacker, amount)` on any token the victim holds; Soroban records that call as a child of the victim's signed authorization tree, so if the victim signs the simulated tree the transfer executes. This is the on-chain analog of "code injection via attacker-planted files": attacker-supplied code runs inside the victim's privilege context.

### Finding Description
`swap_tokens` in `contracts/controller/src/strategies/swap.rs` builds the swap path for `multiply`, `swap_collateral`, `swap_debt`, and `repay_debt_with_collateral`. It calls `authorize_transfer_as_current(env, token_in, &controller, &router_addr, amount_in)` and then `router.execute_strategy(&controller, &amount_in, swap)` where `swap` is raw user-supplied XDR [1](#0-0) . The post-conditions only bound the controller's own balances: `in_after <= in_before` (no input gains) and positive measured output [2](#0-1) . Nothing in the controller constrains which contracts the route causes to run or what sub-invocations they attach beneath the user's auth.

The repository's own threat model acknowledges the gap: the router "keeps no allowlist of [pool/token addresses], so a route can put third-party code on the call stack below the caller's authorization," and "the loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it" [3](#0-2) . The dedicated harness test proves reachability end-to-end through `controller.swap_collateral`: a `RogueHopPool` whose `swap` performs `token.transfer(alice → attacker, WALLET_BALANCE)` on a token the protocol never listed is recorded by simulation as a child of Alice's `swap_collateral` auth entry and, once signed, empties her balance of that token [4](#0-3) [5](#0-4) .

### Impact Explanation
Theft of user funds. The attacker can drain *any* token in the victim's wallet (including assets unrelated to the lending protocol) up to the victim's full balance, not just the `amount_in` the strategy routes. The protocol's measured-delta checks, `min_out`, and post-swap health-factor gates all pass because the theft happens in a sibling sub-invocation invisible to controller accounting. Severity: High impact, Medium overall (requires the victim to sign a poisoned auth tree).

### Likelihood Explanation
Exploitation requires a victim to sign a route crafted by the attacker — e.g., route bytes served by a malicious/compromised quoting front-end or pasted "calldata" — which matches the user-interaction requirement (UI:R) of the original advisory. The attacker's cost is deploying one small contract; no privileged access is needed and the route is indistinguishable from an honest one unless the client decodes the full auth tree and rejects unexpected children. Per the threat model, defense is pushed entirely onto off-chain clients, so any client that signs the simulator's recorded tree verbatim is exploitable.

### Recommendation
- Hard-bound the authorization surface: have the controller issue its strategy call via a dedicated auth entry and document/enforce that the user's auth tree for `swap_*`/`multiply`/`rdwc` may contain *only* the single exact `token_in.transfer(controller → router, amount_in)` child; reject trees with additional children at the SDK/UI level.
- Preferably, restructure so the router call does not run under the user's signature at all (e.g., controller pulls `token_in` first, then calls the router with only controller invoker auth), so venue code can never sit below the caller's auth entry.
- Enforce a venue/pool allowlist or pinned pool registry inside the router payload so route bytes cannot point at arbitrary contracts.

### Proof of Concept
1. Attacker deploys `RogueHopPool` storing `(victim=Alice, wallet_token, to=attacker, amount=Alice's full balance)`; its `swap()` calls `token.transfer(alice, attacker, amount)`.
2. Attacker builds a `StrategySwap`/route naming that contract as the hop pool, `token_in=USDC`, `token_out=ETH`, `min_out=fair value`, and serves it to Alice (phished quote UI or malicious aggregator).
3. Alice calls `controller.swap_collateral(alice, account_id, USDC_key, 5_000 USDC, ETH_key, route)`. Simulation in recording mode attaches the rogue `transfer` as a child of her `swap_collateral` auth; she signs the simulated tree.
4. Execution: router pays out fair `ETH` (all controller checks pass — `in_after <= in_before`, output > 0, account stays healthy), while `RogueHopPool.swap` moves Alice's entire `wallet_token` balance to the attacker.

Verified by `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry`: after the signed call, `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE`, and Alice's ETH supply shows the fair output [6](#0-5) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
