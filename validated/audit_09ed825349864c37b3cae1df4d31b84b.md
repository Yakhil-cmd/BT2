### Title
Recipient-Controlled Revert in `handleKLAYTransfer` Permanently Locks Bridged KLAY — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

`handleKLAYTransfer` in `BridgeTransferKLAY.sol` delivers KLAY to the destination address via a low-level `.call.value()`. If the destination `_to` is a contract whose fallback function reverts, the delivery always fails. Because the vote key is bound to the full calldata (including `_to`), operators cannot substitute a different destination for the same nonce. The bridged KLAY is permanently undeliverable and locked inside the bridge contract.

---

### Finding Description

In `handleKLAYTransfer`, the execution order is:

1. Nonce check (`_lowerHandleNonceCheck`)
2. Vote threshold check (`_voteValueTransfer` — sets `closedValueTransferVotes[nonce] = true`)
3. Mark request tx hash handled (`_setHandledRequestTxHash`)
4. Record block number (`handleNoncesToBlockNums[nonce] = blockNum`)
5. Advance nonce window (`_updateHandleNonce`)
6. Emit `HandleValueTransfer`
7. **`(bool ok, ) = _to.call.value(_value)("")`**
8. **`require(ok, "handleKLAYTransfer: transfer failed")`** [1](#0-0) 

When step 8 fails, the entire transaction reverts — including all state mutations in steps 2–5. This means `closedValueTransferVotes[nonce]` is reset to `false` and `handleNoncesToBlockNums[nonce]` is never written. Operators can retry, but the vote key is computed as:

```solidity
bytes32 voteKey = keccak256(msg.data);
``` [2](#0-1) 

`msg.data` encodes all parameters including `_to`. Operators cannot change `_to` for the same `_requestedNonce` without producing a different vote key, which would never reach threshold for the original nonce. There is no mechanism to skip or override a stuck nonce.

The `lowerHandleNonce` advances only when consecutive nonces starting from `lowerHandleNonce` have been written into `handleNoncesToBlockNums`:

```solidity
for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
``` [3](#0-2) 

Once all nonces below the stuck one are handled, `lowerHandleNonce` advances to the stuck nonce and halts there permanently. The `recoveryBlockNumber` stops advancing, degrading the VT recovery mechanism's ability to detect missed transfers.

---

### Impact Explanation

- **Unauthorized asset lock**: KLAY locked on the source chain (burned or escrowed) is never delivered on the destination chain. The bridge contract holds the KLAY indefinitely with no recovery path.
- **Bridge nonce stall**: `lowerHandleNonce` and `recoveryBlockNumber` freeze at the stuck nonce, impairing the value-transfer recovery subsystem for all subsequent transfers.
- This matches the allowed impact gate: *unauthorized lock of bridged assets* and *persistent corruption of bridge settlement state*.

---

### Likelihood Explanation

Any user who initiates a KLAY bridge transfer on the source chain controls the `_to` field. They can set `_to` to a contract address whose fallback unconditionally reverts. No special privilege is required — this is a standard user-facing bridge operation. The attacker sacrifices only the gas cost of the source-chain request transaction.

---

### Recommendation

1. **Use a pull-payment pattern**: Instead of pushing KLAY to `_to` inside `handleKLAYTransfer`, credit the amount to a claimable balance mapping. The recipient calls a separate `claim()` function. A failed claim does not block the bridge nonce.

2. **Alternatively, cap gas forwarded to `_to`**: Use a fixed gas stipend (e.g., `_to.call{value: _value, gas: 2300}("")`) so that complex fallback logic cannot consume enough gas to revert, while still delivering to plain EOAs. Note this does not fully protect against contracts that revert within 2300 gas.

3. **Add a nonce-skip / rescue mechanism**: Allow the bridge owner to mark a nonce as permanently failed and advance `lowerHandleNonce` past it, releasing the stuck KLAY to a recovery address.

---

### Proof of Concept

1. Alice deploys a contract `MaliciousReceiver` on the destination chain:
   ```solidity
   contract MaliciousReceiver {
       fallback() external payable { revert("no KLAY"); }
   }
   ```
2. Alice calls `requestKLAYTransfer(address(MaliciousReceiver), value, extraData)` on the source bridge, locking `value` KLAY.
3. Operators observe the `RequestValueTransfer` event and call `handleKLAYTransfer(..., address(MaliciousReceiver), value, nonce, ...)` on the destination bridge.
4. Step 7 executes `address(MaliciousReceiver).call.value(value)("")` → `MaliciousReceiver.fallback()` reverts.
5. `require(ok, ...)` fails; the entire transaction reverts. All state changes (vote, nonce, tx hash) are rolled back.
6. Operators retry — same calldata, same `_to`, same revert. The nonce is never settled.
7. After nonces 0…N-1 are handled, `lowerHandleNonce` advances to N and stalls. `recoveryBlockNumber` freezes. The `value` KLAY is permanently locked in the destination bridge contract. [4](#0-3) [5](#0-4) [6](#0-5)

    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }

    // _updateHandleNonce increases lower and upper handle nonce after the _requestedNonce is handled.
    function _updateHandleNonce(uint64 _requestedNonce) internal {
        if (_requestedNonce > upperHandleNonce) {
            upperHandleNonce = _requestedNonce;
        }

        uint64 limit = lowerHandleNonce + 200;
        if (limit > upperHandleNonce) {
            limit = upperHandleNonce;
        }

        uint64 i;
        for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
            recoveryBlockNumber = handleNoncesToBlockNums[i];
            delete handleNoncesToBlockNums[i];
            delete closedValueTransferVotes[i];
        }
        lowerHandleNonce = i;
    }
