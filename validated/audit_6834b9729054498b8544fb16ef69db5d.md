### Title
NonTransfer proxy escalates to Auction proxy to bypass the explicitly-denied Registrar `swap` call - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
On Westend (and identically on Rococo and the `staking-async` relay-chain runtime), `ProxyType::NonTransfer` is defined to explicitly *deny* `paras_registrar::Call::swap` while allowing `register`, `deregister`, `reserve` and — critically — the entire `Proxy` pallet. Separately, `ProxyType::is_superset` for `NonTransfer` is a wildcard: `(ProxyType::NonTransfer, _) => true`, i.e. it claims to be a superset of *every* other proxy type, including `ProxyType::Auction`, whose filter admits `RuntimeCall::Registrar(..)` unrestricted (including `swap`). `pallet_proxy::do_proxy` only gates nested `add_proxy`/`remove_proxy` calls on `is_superset`, not on the actual call filter. A delegate holding only a `NonTransfer` proxy can therefore use that proxy to add itself an `Auction` sub-proxy, and then use the `Auction` proxy to invoke `Registrar::swap` on behalf of the delegator — a call the `NonTransfer` filter explicitly forbids.

### Finding Description
`ProxyType::filter` for `NonTransfer` explicitly comments and enforces "Specifically omitting Registrar `swap`": [1](#0-0) 

`ProxyType::Auction`'s filter, by contrast, admits the entire `Registrar` pallet without restriction: [2](#0-1) 

`is_superset` claims `NonTransfer` is a superset of every other type (including `Auction`), with no per-call check that the claimed superset actually dominates the subset's filter: [3](#0-2) 

`pallet_proxy::do_proxy` relies solely on `is_superset` to gate nested `add_proxy`/`remove_proxy`, not on a full filter-set comparison: [4](#0-3) 

Because `RuntimeCall::Proxy(..)` is itself admitted by `NonTransfer`'s filter, a `NonTransfer` delegate can dispatch `Proxy::add_proxy { delegate: <attacker>, proxy_type: Auction, delay: 0 }` as the real account. The `is_superset` guard passes (since `NonTransfer.is_superset(Auction) == true`), and the outer filter also passes since `Proxy(..)` is allowed — so the nested `add_proxy` succeeds, granting the attacker an `Auction` proxy over the real account. The attacker then dispatches `Proxy::proxy(real, None, Registrar::swap { id, other })`, which the `Auction` filter admits (`RuntimeCall::Registrar { .. }` unrestricted). `Registrar::swap`'s origin check `ensure_root_para_or_owner` accepts the real account if it is the registered owner of the para (a state reachable by any ordinary user via `reserve`/`register`): [5](#0-4) 

This is the exact same bug class as the reported Keycloak issue: a policy/type is asserted to be a superset/equivalent of another type without re-validating that the actual permitted operation set is dominated, letting an entity register (or swap in) a less-restricted type to obtain a capability the original, narrower type explicitly excluded. This project's own regression test suite and prdoc for asset-hub-westend confirm the general bug class is known and was fixed there for `NonTransfer` vs `Governance`: [6](#0-5) 
but the same `NonTransfer`-is-superset-of-everything pattern (with the equivalent `Auction`/`Registrar::swap` gap) remains present, unpatched, in `polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`.

### Impact Explanation
A para owner (any ordinary signed account that registered a parachain via `reserve`/`register`) who grants a `NonTransfer` proxy to a lower-trust automation/ops account — expecting `Registrar::swap` to remain unreachable, as the code comment states — can have that delegate silently escalate to full `Registrar::swap` authority by self-granting an `Auction` sub-proxy. `swap` moves a para's lease/on-demand status and associated deposit/auction state between two `ParaId`s, which is a security- and economically-sensitive operation the owner explicitly did not authorize for that delegate. This is an unauthorized-dispatch / privilege-escalation bug within a live, deployed proxy filter design (Westend and Rococo relay runtimes, and the `staking-async` rc runtime template).

### Likelihood Explanation
No privileged role, governance action, or stolen keys are required. The only precondition is that a real user (para owner) has granted a `NonTransfer` proxy to another account — a common, intended pattern for delegating "non-transfer" operational calls. The escalation path uses only calls each account already has an entry point to (`add_proxy` via proxy, then `proxy` again), matching normal fee-paying signed extrinsic flows.

### Recommendation
Fix `ProxyType::is_superset` so it is not an unconditional wildcard for `NonTransfer`; either enumerate exactly which types are true subsets of `NonTransfer`'s actual filter (as apparently intended, mirroring the AssetHub fix), or replace the ad hoc `is_superset` relation with a systematic check (as the new `proxy_type_superset_relation_matches_call_filters` test does for asset-hub-westend) applied to every runtime defining `ProxyType`, including `polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`.

### Proof of Concept
I was not able to execute a live integration test against this repository within this session (no test harness run was performed); this is a static-analysis-derived finding based on directly reading the guard logic in `pallet_proxy::do_proxy` [4](#0-3)  combined with the `NonTransfer`/`Auction` filter and `is_superset` definitions in `polkadot/runtime/westend/src/lib.rs` [7](#0-6) . A concrete reproduction would require a FRAME integration test constructing: (1) account `A` registers a para via `Registrar::reserve`/`register`; (2) `A` calls `Proxy::add_proxy(delegate=B, proxy_type=NonTransfer, delay=0)`; (3) `B` calls `Proxy::proxy(A, None, Proxy::add_proxy{delegate=B, proxy_type=Auction, delay=0})` and observes it succeed (no `CallFiltered`); (4) `B` calls `Proxy::proxy(A, None, Registrar::swap{id, other})` and observes it dispatches (bypassing the `NonTransfer` filter's explicit `swap` denial). This mirrors the existing `proxy_type_superset_relation_matches_call_filters`/`non_transfer_proxy_is_not_a_superset_of_governance` regression tests already present for asset-hub-westend [8](#0-7) , which should be replicated for the relay-chain runtimes to confirm and close this gap.

title: 'asset-hub-westend: fix `NonTransfer` proxy falsely claiming `Governance` containment'
doc:
- audience: Runtime User
  description: |-
    On Asset Hub Westend, the `NonTransfer` proxy type declared itself a superset of the
    `Governance` proxy type while its call filter denied the `Treasury`, `ConvictionVoting`,
    `Referenda` and `Whitelist` calls that `Governance` admits.

    Because `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `is_superset`, a
    `NonTransfer` proxy could add a `Governance` proxy for its delegator and thereby reach calls
    that its own filter denies. `NonTransfer` no longer declares `Governance` as a subset, so this
    is rejected.

    Existing `Governance` proxies are unaffected; only the ability of a `NonTransfer` proxy to
    create or remove one changes. The `Collator`, `Staking`, `NominationPools` and
    `StakingOperator` subsets of `NonTransfer` are unchanged.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}
