## Multi-Organization Webhook Signature Bypass Cross-Repository Trigger - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In multi-organization Shipit deployments, `WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate against based on `repository.owner.login` (or `organization.login`) taken directly from the **unauthenticated** webhook payload, but the handlers that actually act on the webhook (e.g. `PushHandler`) resolve the target `Stack`/`Repository` using `repository.full_name`, a **separate, unverified** field from the same payload. [1](#0-0) [2](#0-1)  This breaks the binding "organization authenticated == repository written," because the signature check authenticates only that the request came from *some* organization's webhook secret, while a different field entirely determines which tracked repository/stack gets acted upon.

### Finding Description
`GitHubApp#verify_webhook_signature` returns `true` unconditionally when no `webhook_secret` is configured for the organization being checked: [3](#0-2)  `return true unless webhook_secret`.

`Shipit.github(organization:)` picks the app config per organization via `github_app_config(organization)` from `secrets.github`, keyed by organization name: [4](#0-3) . In a multi-org configuration (as documented and tested in `test/dummy/config/secrets_double_github_app.yml`), each organization can have its own (optional) `webhook_secret`.

`WebhooksController#verify_signature` derives the organization to check against purely from the attacker-supplied payload: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, with **no cryptographic tie** between that value and the rest of the payload beyond the HMAC itself. [5](#0-4) 

Handlers (e.g. `PushHandler`, and the base `Handler#repository_name`/`#stacks`) resolve the actual repository/stack to operate on from a *different* payload field, `repository.full_name`: [6](#0-5) [7](#0-6) .

If any organization configured in `Shipit.github_organizations` has no `webhook_secret` set (blank/omitted — an allowed, non-error configuration per `verify_webhook_signature`'s `return true unless webhook_secret`), an attacker can:
1. Submit a webhook with `X-Github-Event: push`, `repository.owner.login` (or `organization.login`) set to that secret-less organization, so `verify_signature` short-circuits to `true` regardless of the (even absent/garbage) `X-Hub-Signature` header.
2. Set `repository.full_name` in the same payload to `<victim-org>/<victim-repo>`, an entirely different, secret-protected organization's repository that is tracked by Shipit.
3. `PushHandler#process` (or `status`, `check_suite`, `pull_request` handlers, etc.) resolves stacks via `Repository.from_github_repo_name(repository_name)` using the attacker-controlled `full_name`, and triggers `stack.sync_github(expected_head_sha: params.after)` — i.e. `GithubSyncJob` — for the victim's stack, entirely bypassing the victim organization's webhook secret.

### Impact Explanation
This allows an unauthenticated external attacker to forge GitHub events (push, status, check_suite, pull_request, membership, etc.) targeting any repository/stack tracked by Shipit, as long as at least one other organization onboarded to the same Shipit instance has no webhook secret configured. Triggering `sync_github`/`GithubSyncJob` for an arbitrary stack causes Shipit to fetch and ingest attacker-influenced commit history and can advance deploy state/merge queue behavior (`MergeRequest.request_merge!`, `PullRequest` label/state handling) without ever proving possession of the target organization's webhook secret — an authentication bypass across the multi-tenant organization boundary and a path to unauthorized deploy-affecting state changes.

### Likelihood Explanation
Requires a multi-organization Shipit deployment where at least one onboarded organization's `webhook_secret` is left blank (explicitly supported by the code — `return true unless webhook_secret` is not an error path, just a permissive default) while other organizations are properly secured. This is a plausible operational misconfiguration in a webhook endpoint that is by design internet-reachable and unauthenticated prior to signature verification.

### Recommendation
Bind the field used to select the signing secret to the field used to resolve the target repository — verify the signature using the secret for the organization/repository that the handler will actually act on (i.e., derive both from `repository.full_name`, not two independent lookups), and treat a missing `webhook_secret` for a configured organization as a hard failure (`head(422)`) rather than an automatic pass, so that no organization can act as an "open door" for spoofing events against other organizations' repositories.

### Proof of Concept
```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # ignored because org below has no webhook_secret

{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "org-with-no-webhook-secret" },
    "full_name": "victim-org/victim-repo"
  }
}
```
`verify_signature` looks up `Shipit.github(organization: "org-with-no-webhook-secret")`; since that org has no `webhook_secret`, `verify_webhook_signature` returns `true` unconditionally. `PushHandler` then resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and enqueues `GithubSyncJob` for the victim's stack, having bypassed victim-org's webhook secret entirely.       github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
