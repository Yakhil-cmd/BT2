### Title
ANSI/OSC escape sequence passthrough in `printTreeDir` when rendering attacker-controlled skill filenames - (File: pkg/cmd/skills/install/install.go)

### Summary
`printTreeDir` in `pkg/cmd/skills/install/install.go` renders a directory listing of just-installed skill files by calling `entry.Name()` directly into `fmt.Fprintf`, with no stripping of ANSI/OSC/C0 control sequences. Because the on-disk filenames originate from a remote skill's git tree paths (or local archive/walk names) which are only checked for path traversal—not for control bytes—an attacker who publishes a skill can name a file to smuggle terminal escape sequences into the `gh skills install` output.

### Finding Description
`printTreeDir` reads directory entries and prints each name verbatim: [1](#0-0) 

The color helpers `cs.Muted(...)` / `cs.Bold(...)` only wrap the connector/box-drawing characters and directory names in SGR color codes; they perform no sanitization of the file/directory `name` itself, which is written straight to `w` (the command's stdout, via `printFileTree`, called from the install command's success/summary output path).

The filenames come from two install code paths:
- `installSkill` in `internal/skills/installer/installer.go`, which takes `file.Path` from a GitHub API tree response (`discovery.DiscoverSkillFiles`) — fully attacker-controlled since a repo owner can name a blob path with embedded ANSI/OSC bytes (git only forbids `/` and NUL in path components) — and writes it to disk via `safeSkillDir.Join(relPath)` + `os.WriteFile`, which only guards against path traversal, not control characters. [2](#0-1) 
- `installLocalSkill`, which walks a locally cloned/extracted source tree and copies files preserving their original names. [3](#0-2) 

Neither `safepaths.Join` nor `zip.ExtractZip`/`extractTarGz` (used elsewhere in the codebase for similar archive handling) strip control bytes from filenames — they only reject `..`-style traversal. [4](#0-3) 

The codebase does have a purpose-built defense for exactly this class of issue: the `iostreams.Untrusted` type, whose `String()` method sanitizes ANSI escape sequences via `asciisanitizer` before any `fmt` print path renders it. [5](#0-4) 

However, `printTreeDir` does not wrap `entry.Name()` in `iostreams.Untrusted` before printing — it passes the raw `string` directly to `fmt.Fprintf`. This is the root cause: attacker-controlled text (the skill's file names, ultimately derived from repo/tree content) reaches the terminal without going through the sanitization mechanism the project already provides for untrusted content elsewhere.

### Impact Explanation
An attacker who publishes a skill (via a public repo, fork, or registry entry) can name a file inside the skill directory with embedded OSC sequences (e.g., OSC 52 clipboard write, OSC 7/8 hyperlink/cwd spoofing, or cursor-repositioning C0/C1 sequences). When the victim runs `gh skills install <repo>` and the tool prints the installed file tree via `printFileTree`/`printTreeDir`, those bytes are emitted to the victim's terminal unfiltered. Depending on the victim's terminal emulator, this can be used for terminal/prompt spoofing, hiding or altering the perceived directory listing, or triggering clipboard writes (OSC 52) if the terminal honors it — matching the "Terminal output/prompt spoofing" impact class described in the question. This does not achieve direct code execution but can support social-engineering-adjacent attacks such as making the printed review hint or subsequent prompt appear different from what happens on confirmation.

### Likelihood Explanation
Fully attacker-controlled and requires no special privilege: publishing a skill repo/tree with a maliciously-named file is a normal, unprivileged GitHub action. Any victim running `gh skills install` against that repo triggers the vulnerable print path automatically as part of normal, successful output (no destructive-confirmation flag needed) — high feasibility and repeatability.

### Recommendation
Wrap `entry.Name()` (and any other remotely-derived string printed in `printTreeDir`, `printFileTree`, `printReviewHint`, `printHostHints`) in `iostreams.Untrusted` before formatting, e.g. `fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), iostreams.NewUntrusted(name))`, so the existing `asciisanitizer`-based sanitization strips ANSI/OSC/C0/C1 sequences before the text reaches the terminal. Alternatively, sanitize filenames at extraction time (in `installSkill`/`installLocalSkill`) before writing them to disk, though sanitizing at the print boundary is safer since it also protects any other future consumer of these names.

### Proof of Concept
Golden test plan:
1. In `pkg/cmd/skills/install/install_test.go` (or a new test), simulate an installed skill directory containing a file named with an embedded OSC 52 sequence, e.g. `"file\x1b]52;c;<base64>\x07.txt"` created via `os.WriteFile` in a temp dir (bypassing the network layer, since the goal is to test the print function directly).
2. Call `printFileTree(&buf, cs, tmpDir, []string{"skill-name"})` (or `printTreeDir` directly) with a `bytes.Buffer` as `w`.
3. Assert `!strings.Contains(buf.String(), "\x1b]52;")` and `!strings.Contains(buf.String(), "\x07")` — currently this assertion fails because the raw escape bytes pass through unchanged.
4. For an end-to-end variant, use `httpmock` to stub a git tree response (`repos/.../git/trees/...`) from `TestInstallSkill`-style tests with a `path` field containing the same escape sequence, run through `installSkill`, then invoke `printFileTree` on the resulting directory and assert the same absence of raw escape bytes in the terminal-bound output.

func printTreeDir(w io.Writer, cs *iostreams.ColorScheme, dir, indent string) {
	entries, err := os.ReadDir(dir)
	if err != nil {
		fmt.Fprintf(w, "%s%s\n", indent, cs.Muted("(could not read directory)"))
		return
	}
	for i, entry := range entries {
		isLast := i == len(entries)-1
		connector := "├── "
		childIndent := "│   "
		if isLast {
			connector = "└── "
			childIndent = "    "
		}
		name := entry.Name()
		if entry.IsDir() {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), cs.Bold(name+"/"))
			printTreeDir(w, cs, filepath.Join(dir, name), indent+cs.Muted(childIndent))
		} else {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), name)
		}
	}
}

func ExtractZip(zr *zip.Reader, destDir safepaths.Absolute) error {
	for _, zf := range zr.File {
		fpath, err := destDir.Join(zf.Name)
		if err != nil {
			var pathTraversalError safepaths.PathTraversalError

			}

		}

		if err := extractZipFile(zf, fpath); err != nil {

	}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
