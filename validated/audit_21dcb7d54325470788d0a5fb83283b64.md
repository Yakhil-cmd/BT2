### Title
Bridge Fallback Function Fetches Mutable `feeOfKLAY` Without User-Supplied Maximum — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

The `BridgeTransferKLAY` fallback function passes the live `feeOfKLAY` storage variable as both the fee **and** the `_feeLimit` ceiling. Because the two values are always equal, the `require(_feeLimit >= fee)` guard in `_payKLAYFeeAndRefundChange` is trivially satisfied regardless of how high the fee has been raised. A single bridge operator (default threshold = 1) can front-run any pending fallback call by raising `feeOfKLAY` to just below `msg.value`, causing the user to pay an arbitrarily large fee and receive a near-zero cross-chain transfer value.

---

### Finding Description

**Fallback function — no user-supplied fee ceiling** [1](#0-0) 

```solidity
function () external payable {
    _requestKLAYTransfer(msg.sender, feeOfKLAY, new bytes(0));
}
```

`feeOfKLAY` is a mutable storage variable. It is passed directly as `_feeLimit`, so the user never commits to a maximum fee at signing time.

**`_requestKLAYTransfer` — value transferred equals `msg.value − _feeLimit`** [2](#0-1) 

The cross-chain value emitted in `RequestValueTransfer` is `msg.value.sub(_feeLimit)`. If `_feeLimit` (= `feeOfKLAY`) is raised from 0.4 KLAY to 1.3 KLAY, the transferred value shrinks from 1.0 KLAY to 0.1 KLAY.

**`_payKLAYFeeAndRefundChange` — guard is always satisfied** [3](#0-2) 

```solidity
uint256 fee = feeOfKLAY;
require(_feeLimit >= fee, "insufficient feeLimit");   // _feeLimit == fee, always true
```

Because `_feeLimit` was set to `feeOfKLAY` in the fallback, and `fee` is re-read as `feeOfKLAY` inside this function, the check `_feeLimit >= fee` is an identity comparison that can never revert.

**Default operator threshold is 1 — single operator can change the fee** [4](#0-3) 

```solidity
constructor() internal {
    for (uint8 i = 0; i < uint8(VoteType.Max); i++) {
        operatorThresholds[uint8(i)] = 1;   // single-operator threshold by default
    }
    operators[msg.sender] = true;
    operatorList.push(msg.sender);
}
```

`setKLAYFee` is gated by `onlyOperators` and calls `_voteConfiguration`, which passes immediately when `operatorThresholds[Configuration] == 1`. [5](#0-4) 

**Contrast: `requestKLAYTransfer` is protected** [6](#0-5) 

```solidity
function requestKLAYTransfer(address _to, uint256 _value, bytes calldata _extraData) external payable {
    uint256 feeLimit = msg.value.sub(_value);   // user-controlled ceiling
    _requestKLAYTransfer(_to, feeLimit, _extraData);
}
```

Here `feeLimit = msg.value − _value` is set by the user. If the operator raises `feeOfKLAY` above this ceiling, `require(_feeLimit >= fee)` reverts and the user loses nothing. The fallback function has no equivalent protection.

---

### Impact Explanation

A malicious operator front-runs a user's fallback call by submitting `setKLAYFee(msg.value − ε, configNonce)` in the same block with higher priority. When the fallback executes:

- `require(msg.value > _feeLimit)` passes because `msg.value > msg.value − ε`.
- The fee paid to `feeReceiver` is `msg.value − ε`.
- The cross-chain value emitted is `ε` (near zero).

The user's KAIA is drained to the `feeReceiver`. This is an **unauthorized fee charge affecting KAIA** — a direct match to the allowed-impact gate.

---

### Likelihood Explanation

- The default `operatorThresholds[Configuration]` is **1**, so no collusion is required; a single operator can execute the attack atomically in one transaction.
- The fallback function is the natural entry point for users who simply send KLAY to the bridge address (e.g., from a wallet UI).
- The operator can observe the mempool, identify pending fallback calls, and front-run them by submitting the fee-change transaction with a higher gas price.

---

### Recommendation

Remove the no-argument fallback or require users to supply an explicit maximum fee. The simplest fix mirrors the `requestKLAYTransfer` pattern: accept a `_maxFee` parameter and revert if `feeOfKLAY > _maxFee`.

```solidity
// Replace the current fallback with a guarded version:
function () external payable {
    // Users must use requestKLAYTransfer to specify a fee ceiling.
    revert("use requestKLAYTransfer");
}
```

Or, if the fallback must be kept, add a user-supplied slippage guard analogous to the MechMarketplace fix:

```solidity
function requestKLAYTransferWithFeeLimit(
    address _to,
    uint256 _maxFee,
    bytes calldata _extraData
) external payable {
    require(feeOfKLAY <= _maxFee, "fee exceeds maxFee");
    _requestKLAYTransfer(_to, _maxFee, _extraData);
}
```

---

### Proof of Concept

1. Bridge is deployed with default `operatorThresholds[Configuration] = 1`. Operator is `op`.
2. `feeOfKLAY = 0.4 KLAY`, `feeReceiver` is set.
3. User broadcasts a fallback call: `bridge.call{value: 1.4 ether}("")`.
4. `op` observes the pending transaction and broadcasts `bridge.setKLAYFee(1.39 ether, configNonce)` with higher gas price.
5. `setKLAYFee` executes first (threshold = 1, passes immediately). `feeOfKLAY` is now `1.39 KLAY`.
6. User's fallback executes:
   - `_feeLimit = feeOfKLAY = 1.39 KLAY`
   - `require(1.4 > 1.39)` → passes
   - `_payKLAYFeeAndRefundChange(1.39)`: `fee = 1.39`, `require(1.39 >= 1.39)` → passes, pays `1.39 KLAY` to `feeReceiver`
   - `RequestValueTransfer` emits value = `1.4 − 1.39 = 0.01 KLAY`
7. User paid `1.39 KLAY` in fees instead of `0.4 KLAY`. Net loss: **0.99 KLAY** drained to `feeReceiver`.

```text
    function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }
```
