### Title
Missing `receipt.Status` Check Allows Malicious Bridge Peer to Falsely Advance Anchored Block Number and Evict Anchoring Tx — (`node/sc/sub_bridge_handler.go`)

---

### Summary

`writeServiceChainTxReceipts` processes `ReceiptForStorage` messages received over the bridge P2P layer without checking `receipt.Status`. Any peer that can connect to the SubBridge P2P port and pass the chainID handshake can send a crafted `ServiceChainReceiptResponseMsg` with `Status=0` (failed) for a known pooled anchoring tx, causing the child chain to falsely record the block as anchored, store a failed receipt in the chainDB, and permanently evict the anchoring tx from the pool.

---

### Finding Description

`handleParentChainReceiptResponseMsg` decodes an inbound `ServiceChainReceiptResponseMsg` and passes the receipts directly to `writeServiceChainTxReceipts`: [1](#0-0) 

Inside `writeServiceChainTxReceipts`, for every receipt whose `TxHash` matches a pooled anchoring tx, the code unconditionally calls `WriteReceiptFromParentChain`, `WriteAnchoredBlockNumber`, and `RemoveTx` — with no check on `receipt.Status`: [2](#0-1) 

The bridge P2P handshake (`readStatus`) only validates `networkId` and `protocolVersion`: [3](#0-2) 

The only additional gate is `RegisterNewPeer`, which checks that the peer's chainID matches the parent chain ID — a value that is public: [4](#0-3) 

The SubBridge actively broadcasts all pending anchoring tx hashes to every connected peer via `broadcastServiceChainReceiptRequest`, so an attacker learns the exact `TxHash` values to spoof: [5](#0-4) 

---

### Impact Explanation

Three persistent state mutations occur for a single crafted receipt with `Status=0`:

1. **`WriteAnchoredBlockNumber`** advances the on-disk anchored block number to the block number embedded in the anchoring tx's payload, even though the parent-chain tx failed. The child chain now permanently believes that block is anchored. [6](#0-5) 

2. **`WriteReceiptFromParentChain`** stores the failed receipt in `bridgeServiceDB` keyed by the child-chain block hash, corrupting the receipt store. [7](#0-6) 

3. **`RemoveTx`** permanently evicts the anchoring tx from the `bridgeTxPool`, preventing any retry. There is no automatic re-anchoring mechanism for anchoring txs. [8](#0-7) 

The net effect is a durable false anchoring confirmation: the child chain reports blocks as anchored on the parent chain when the parent-chain transaction actually failed, breaking the cross-chain security guarantee.

---

### Likelihood Explanation

- The SubBridge P2P port is network-accessible.
- The only admission check is a matching `networkId` + `protocolVersion` (handshake) and a matching parent `chainID` (both public values).
- The SubBridge itself leaks the target `TxHash` values by broadcasting them to all connected peers.
- No cryptographic proof-of-execution or signature over the receipt is required.

An attacker on the same network as the SubBridge node can execute this with a single crafted P2P message.

---

### Recommendation

Add a `receipt.Status` guard before processing any anchoring receipt:

```go
// In writeServiceChainTxReceipts, after retrieving the tx:
if receipt.Status != types.ReceiptStatusSuccessful {
    logger.Warn("skipping failed anchoring receipt", "txHash", txHash, "status", receipt.Status)
    continue  // do NOT RemoveTx; allow retry
}
```

The `RemoveTx` call should also be moved inside the `Status == successful` branch so that failed receipts do not evict the tx from the pool.

---

### Proof of Concept

1. Attacker node connects to the SubBridge P2P port, passes handshake with correct `networkId` and parent `chainID`.
2. SubBridge sends `ServiceChainReceiptRequestMsg` containing the hashes of pending anchoring txs.
3. Attacker constructs a `[]*types.ReceiptForStorage` with one entry: `{TxHash: <observed hash>, Status: 0}`.
4. Attacker sends `ServiceChainReceiptResponseMsg` containing that receipt.
5. `handleParentChainReceiptResponseMsg` → `writeServiceChainTxReceipts` processes it.
6. Assert: `chainDB.ReadAnchoredBlockNumber()` returns the block number from the anchoring tx payload (advanced), `chainDB.ReadReceiptFromParentChain(blockHash).Status == 0`, and `bridgeTxPool.Get(txHash) == nil` (tx evicted).
7. The child chain now incorrectly reports the block as anchored; the anchoring tx will never be retried.

func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
	for _, receipt := range receipts {
		txHash := receipt.TxHash
		if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
			if tx.Type().IsChainDataAnchoring() {
				data, err := tx.AnchoredData()
				if err != nil {
					logger.Error("failed to get anchoring data", "txHash", txHash.String(), "err", err)
					continue
				}
				decodedData, err := types.DecodeAnchoringData(data)
				if err != nil {
					logger.Warn("failed to decode anchoring tx", "txHash", txHash.String(), "err", err)
					continue
				}
				sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
				sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
			}
			// TODO-Kaia-ServiceChain: support other tx types if needed.
			sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
		} else {
			logger.Trace("received service chain transaction receipt does not exist in sentServiceChainTxs", "txHash", txHash.String())
		}
		logger.Trace("received service chain transaction receipt", "anchoring txHash", txHash.String())
	}
}

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}
