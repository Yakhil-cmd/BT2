### Title
Market permanently freezes when accrued debt value overflows the RAY ceiling before the borrow-index cap engages - (File: `common/src/rates/simulate.rs`)

### Summary
Like CVE-2021-35638 (a reachable crash/DoS in the optimizer), the pool's accrual engine can be driven into a state where every subsequent accrual panics with `MathOverflow`. Because every state-changing verb calls `global_sync` first, one sustained high-utilization market freezes permanently: no supply, borrow, withdraw, repay, liquidation, bad-debt cleanup, or revenue claim on that `(hub, token)` book ever succeeds again.

### Finding Description
Interest accrual in `contracts/pool/src/interest.rs::global_sync` runs `accrue_step` in chunks of at most `MAX_COMPOUND_DELTA_MS` for every mutating entrypoint, and `common/src/rates/simulate.rs::simulate_update_indexes_body` does the same for projections. Inside the step, debt is valued as `borrowed_scaled * borrow_index / RAY` (`scaled_to_original`). Both factors are unbounded user-influenced quantities: `borrowed` grows with whale-scale supply, and `borrow_index` compounds upward at high utilization. The borrow-index cap (`MAX_BORROW_INDEX_RAY = 10^36`) limits the index itself, but not the product — a market with ~10^29 scaled debt at ~1.7e27 index already exceeds `i128` range, and accrual panics inside the multiply before the cap can ever engage.

Once the panic threshold is crossed, `last_timestamp` can never advance (accrual always recomputes the overflowing product), so the state is absorbing. `update_indexes`, `repay`, `withdraw`, `liquidate` (which accrues the debt market), `clean_bad_debt`, and `claim_revenue` all revert on that market forever.

### Impact Explanation
Permanent freezing of all user funds in the affected market — suppliers cannot withdraw, borrowers cannot repay, liquidators cannot clear insolvent positions, and bad debt can never be socialized. This is theft-equivalent loss of every supplied token in that book. It matches the CVE class: an attacker-reachable condition that converts a normal code path into a repeatable crash with availability impact, here with permanent rather than restartable effect.

### Likelihood Explanation
Fully reachable by a single unprivileged address using only `supply` + `borrow` on a listed market: supply a large principal, borrow to ~98% utilization, then let ledger time advance. The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the cliff deterministically on the XLM rate curve — the borrow index stays below its cap when accrual dies (`assert_contract_error(... MATH_OVERFLOW)` and frozen `try_withdraw_raw`/`try_repay`). The capital requirement is whale-scale (a billion 18-decimal tokens in the test), so the attack requires either a genuinely large market or a low-priced/high-decimal asset where such scaled values are realistic — which is the normal state of a successful lending market over time. No privileged action, oracle manipulation, or off-chain precondition is needed; ledger timestamps advance on their own.

### Recommendation
Guard the debt-value multiplication in `accrue_step`/`scaled_to_original` with a saturating or capped computation, or cap the borrow index dynamically at `i128::MAX / borrowed` so accrual can never panic on value overflow. At minimum, let `global_sync` clamp and stamp `last_timestamp` when the product would overflow (freezing index growth, like the existing `MAX_BORROW_INDEX_RAY` sticky-cap behavior) so exits and repayments remain possible.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub(crate) fn simulate_update_indexes_body(
    env: &Env,
    current_timestamp: u64,
    sync: &PoolSyncData,
) -> MarketIndex {
    let state = PoolState::from(&sync.state);
    let total_delta_ms = current_timestamp.saturating_sub(state.last_timestamp);

    if total_delta_ms == 0 {
        return MarketIndex {
            supply_index: state.supply_index,
            borrow_index: state.borrow_index,
        };
    }

    let params = MarketParams::from(&sync.params);

    let mut supplied = state.supplied;
    let mut borrow_index = state.borrow_index;
    let mut supply_index = state.supply_index;

    let mut remaining = total_delta_ms;
    while remaining > 0 {
        let chunk = remaining.min(MAX_COMPOUND_DELTA_MS);
        let step = accrue_step(
            env,
            &params,
            state.borrowed,
            supplied,
            borrow_index,
            supply_index,
            chunk,
        );

        borrow_index = step.borrow_index;
        supply_index = step.supply_index;
        supplied = supplied.checked_add(env, step.revenue_shares);

        remaining -= chunk;
    }

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
