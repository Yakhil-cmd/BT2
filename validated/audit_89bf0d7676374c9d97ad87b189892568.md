### Title
Frontmatter `---` split can truncate/silently drop `action`, `enabled`, or `conditions` keys, downgrading a `block` rule to default `warn` - ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter` uses `content.split('---', 2)` to locate the frontmatter fence, but this naive split matches *any* literal `---` substring, including one embedded inside a quoted `pattern` value. An attacker who controls the `pattern` (or a condition's `pattern`) field can insert `---` inside the value to make the split cut the frontmatter short before later keys like `action: block`, causing `Rule.from_dict` to silently fall back to the default `action='warn'`.

### Finding Description
`extract_frontmatter` splits the whole file content on the literal `---` delimiter with `maxsplit=2`: [1](#0-0) 
This split is delimiter-unaware — it does not respect YAML quoting or fence semantics, and simply finds the first two `---` occurrences anywhere in the string. If a `pattern` value (which is attacker-controlled content of a `hookify.*.local.md` rule file) contains the substring `---`, e.g. `pattern: "a---rf"`, that embedded `---` is counted as the *second* delimiter occurrence instead of the real closing fence. As a result, `parts[1]` (the frontmatter text actually parsed) is truncated mid-value, and everything after it — including subsequent keys such as `action: block`, `enabled: false`, or a `conditions:` block — is pushed into `parts[2]`, which is treated as the markdown message body and never parsed as YAML.

Downstream, `Rule.from_dict` reads keys with permissive defaults: [2](#0-1) 
Because `action` defaults to `'warn'` and `enabled` defaults to `True`, a rule author's `action: block` intent is silently replaced by `warn` when the field is dropped by the truncated split — with no error, warning, or exception raised anywhere in `load_rule_file`/`load_rules`.

The call chain `load_rules -> load_rule_file -> extract_frontmatter -> Rule.from_dict` performs no re-validation that all expected keys were actually captured, so this parser differential (`extract_frontmatter`'s ad-hoc splitting vs. a spec-compliant YAML parser like `yaml.safe_load`) goes undetected.

### Impact Explanation
This is a security-control weakening bug: a hookify rule file intended to `block` a dangerous action (e.g., blocking `rm -rf` bash commands) can be crafted (or unintentionally exist, but here we assume attacker-crafted) such that the loaded `Rule` object ends up with `action='warn'` instead of `'block'`, or other trailing fields dropped, silently degrading the enforcement rule without any error being surfaced to the user or logged in a way that flags the semantic change. Any consumer relying on the `enabled`/`action`/`conditions` values loaded via `load_rules()` acts on the parser's silently altered rule.

### Likelihood Explanation
No special privileges are required — only the ability to author/merge a `.claude/hookify.*.local.md` file containing a `pattern` (or condition `pattern`) value that includes the literal three-dash sequence, which is plausible in a legitimate-looking regex/pattern (e.g., matching `a---rf`, `rm---rf`, or any pattern using `---` as a separator/range marker). The bug is deterministic and 100% reproducible for any such input.

### Recommendation
Replace the ad-hoc `content.split('---', 2)` fence detection with a regex that only matches `---` at the start of a line (e.g. `^---\s*$` in MULTILINE mode) to delimit the frontmatter block, and parse the frontmatter body with a real YAML parser (`yaml.safe_load`) instead of the hand-rolled line-based parser, eliminating this entire class of parser differential.

### Proof of Concept
Unit/differential test in `plugins/hookify/core/config_loader.py`'s test module (or a new test file):
```python
import yaml
from config_loader import extract_frontmatter, Rule

content = (
    "---\n"
    "name: test-rule\n"
    "enabled: true\n"
    "event: bash\n"
    'pattern: "a---rf"\n'
    "action: block\n"
    "---\n\n"
    "Dangerous command detected!\n"
)

fm, msg = extract_frontmatter(content)
rule = Rule.from_dict(fm, msg)

# Reference parse using the real closing fence (last '---' at line start)
ref_fm = yaml.safe_load(content.split('\n---\n', 1)[0].lstrip('-\n'))

assert 'action' in fm, "action key silently dropped by extract_frontmatter"
assert fm.get('action') == ref_fm.get('action') == 'block'
assert rule.action == 'block', f"Expected block, got {rule.action} (security downgrade to warn)"
```
Expected (buggy) result: `fm` lacks the `action` key, `rule.action == 'warn'`, diverging from the reference YAML parse where `action == 'block'` — confirming the silent downgrade.
