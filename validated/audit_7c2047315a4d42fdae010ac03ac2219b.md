### Title
Creator fees permanently frozen if `pool_creator` is blacklisted by token_0/token_1 (e.g. USDC) - ([File: programs/cp-swap/src/instructions/collect_creator_fee.rs])

### Summary
`collect_creator_fee` and `collect_creator_fee_permissionless` are the only instructions that can withdraw accumulated `creator_fees_token_0`/`creator_fees_token_1` from the pool vaults. Both instructions hard-bind the destination token accounts to the immutable `pool_creator` address stored in `PoolState`, with no mechanism to change that address or redirect the funds. If the mint of token_0 or token_1 is a token with a blacklist feature (e.g. USDC) and the `pool_creator` address gets blacklisted, the creator fee will be permanently unrecoverable.

### Finding Description
`PoolState.pool_creator` is set once at pool creation and is never updated anywhere in the program — there is no admin or user instruction that mutates it. [1](#0-0) [2](#0-1) 

Both fee-collection instructions constrain the `creator` account to `pool_state.load()?.pool_creator` and derive the receiving token accounts as ATAs whose authority is fixed to that same `creator` address: [3](#0-2) [4](#0-3) 

Unlike `withdraw`/`swap_base_input`, where the user-supplied destination token accounts (`token_0_account`, `token_1_account`, `output_token_account`) are only mint-checked and not tied to the owner's authority — allowing the depositor/swapper to redirect proceeds to any account they control if their own account were ever blacklisted — [5](#0-4) [6](#0-5) 
the creator-fee flow offers no such flexibility: `creator_token_0`/`creator_token_1` must be ATAs owned by the pool creator, and the fee transfer is executed via `transfer_from_pool_vault_to_user` → `transfer_checked` CPI, which will revert if the token program blacklists the destination owner. [7](#0-6) [8](#0-7) 

Because the `creator` field is immutable and the fee accounts are pinned to it with no fallback, once the token blacklists the `pool_creator`, both the permissioned and the "permissionless" collection paths become permanently uncallable for the affected mint.

### Impact Explanation
`creator_fees_token_0`/`creator_fees_token_1` accumulate in the pool vaults on every swap that routes through this pool and are excluded from the tradable vault balance via `vault_amount_without_fee`: [9](#0-8) 
If the creator can never collect them (due to blacklisting), those funds remain locked inside the vault forever — a permanent freezing of legitimately-earned funds, matching the accepted impact class (permanent freezing of user funds / fee-ledger accounting that can never be settled). This is a protocol-level bug reachable by an ordinary blacklist event on the underlying token (e.g., USDC/Tether-style compliance action against the creator's wallet), not a privileged or off-chain-only scenario, and it is triggered purely through the normal, unprivileged `collect_creator_fee`/`collect_creator_fee_permissionless` instructions.

### Likelihood Explanation
Any pool created with a blacklist-capable token (USDC is explicitly cited in the source report and is a common quote asset for this class of pool) is at risk if the pool creator's wallet is ever blacklisted for any reason unrelated to the pool itself. Since `pool_creator` can never be changed and the destination ATA is derivable and fixed, this is a deterministic, guaranteed loss once the precondition (blacklisting) occurs — no attacker action is even required beyond the token issuer's blacklist action, making it a realistic Medium-severity issue analogous to the reported one.

### Recommendation
Add an admin- or creator-signed instruction to update `pool_creator` (subject to appropriate authorization, e.g., signed by the current creator or a permissioned party) so a blacklisted creator can reassign the fee-recipient address, or allow the creator to specify an arbitrary destination token account (mint-checked only, as already done for `withdraw`/`swap`) instead of forcing the ATA of the immutable `pool_creator`.

### Proof of Concept
1. Create a pool where token_0 (or token_1) is a mint with blacklist authority (e.g., USDC), with `creator` = wallet `C`.
2. Perform swaps that accrue `creator_fees_token_0` in `PoolState`.
3. Token issuer blacklists wallet `C` (an event entirely outside program control).
4. Call `collect_creator_fee` or `collect_creator_fee_permissionless`: `creator_token_0`, the ATA owned by `C`, is blacklisted, so `transfer_checked` in `transfer_from_pool_vault_to_user` reverts every time. [10](#0-9) 
5. Because `pool_creator` cannot be reassigned anywhere in the program, `creator_fees_token_0` remains stuck in the vault permanently, with no instruction able to extract it.

```rust
    pub fn vault_amount_without_fee(&self, vault_0: u64, vault_1: u64) -> Result<(u64, u64)> {
        let fees_token_0 = self
            .protocol_fees_token_0
            .checked_add(self.fund_fees_token_0)
            .ok_or(ErrorCode::MathOverflow)?
            .checked_add(self.creator_fees_token_0)
            .ok_or(ErrorCode::MathOverflow)?;
        let fees_token_1 = self
            .protocol_fees_token_1
            .checked_add(self.fund_fees_token_1)
            .ok_or(ErrorCode::MathOverflow)?
            .checked_add(self.creator_fees_token_1)
            .ok_or(ErrorCode::MathOverflow)?;
        Ok((
            vault_0
                .checked_sub(fees_token_0)
                .ok_or(ErrorCode::InsufficientVault)?,
            vault_1
                .checked_sub(fees_token_1)
                .ok_or(ErrorCode::InsufficientVault)?,
        ))
```

```rust
pub struct CollectCreatorFee<'info> {
    /// Only pool creator can collect fee
    #[account(mut, address = pool_state.load()?.pool_creator)]
    pub creator: Signer<'info>,

    /// CHECK: pool vault and lp mint authority
    #[account(
        seeds = [
            crate::AUTH_SEED.as_bytes(),
        ],
        bump,
    )]
    pub authority: UncheckedAccount<'info>,

    /// Pool state stores accumulated protocol fee amount
    #[account(mut)]
    pub pool_state: AccountLoader<'info, PoolState>,

    /// Amm config account stores fund_owner
    #[account(address = pool_state.load()?.amm_config)]
    pub amm_config: Account<'info, AmmConfig>,

    /// The address that holds pool tokens for token_0
    #[account(
        mut,
        constraint = token_0_vault.key() == pool_state.load()?.token_0_vault
    )]
    pub token_0_vault: Box<InterfaceAccount<'info, TokenAccount>>,

    /// The address that holds pool tokens for token_1
    #[account(
        mut,
        constraint = token_1_vault.key() == pool_state.load()?.token_1_vault
```

```rust
pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
```

```rust
pub fn transfer_from_pool_vault_to_user<'a>(
    authority: AccountInfo<'a>,
    from_vault: AccountInfo<'a>,
    to: AccountInfo<'a>,
    mint: AccountInfo<'a>,
    token_program: AccountInfo<'a>,
    amount: u64,
    mint_decimals: u8,
    signer_seeds: &[&[&[u8]]],
) -> Result<()> {
    if amount == 0 {
        return Ok(());
    }
    token_2022::transfer_checked(
        CpiContext::new_with_signer(
            *token_program.key,
            token_2022::TransferChecked {
                from: from_vault,
                to,
                authority,
                mint,
            },
            signer_seeds,
        ),
        amount,
        mint_decimals,
    )
}
```
