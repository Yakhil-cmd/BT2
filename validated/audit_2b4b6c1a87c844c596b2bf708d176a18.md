### Title
Webhook signature verification authenticates the organization but the payload's `repository.full_name` (used to select the target Stack) is never bound to that organization - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` looks up the GitHub App/webhook secret to check using `repository_owner`, which is read straight from the attacker-controlled JSON body (`repository.owner.login` or `organization.login`). Once the HMAC is valid, the event handlers (e.g. `PushHandler`) resolve *which* `Repository`/`Stack` to act on using a completely different field of the same body: `repository.full_name`. Nothing cross-checks that the repository named in `full_name` actually belongs to the organization whose secret was used to sign the request.

### Finding Description
`verify_signature` derives the signing identity purely from the payload: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` yields a `GithubApp` instance holding a per-organization `webhook_secret`, and `verify_webhook_signature` just does an HMAC-SHA1 compare of the raw body against that secret: [3](#0-2) 

Because the whole request body (including `repository.full_name`) is under attacker control before it is signed, an actor who legitimately knows the `webhook_secret` for *any one* onboarded GitHub organization in this Shipit instance can craft an arbitrary JSON body: set `repository.owner.login`/`organization.login` to their own org (so the secret lookup and HMAC succeed), but set `repository.full_name` to `victim-org/victim-repo`. The signature check never verifies that `full_name`'s owner matches `repository_owner`.

Handlers then resolve the target purely from `full_name`: [4](#0-3) 
`Repository.from_github_repo_name` does a straight DB lookup with no ownership cross-check against the authenticated organization: [5](#0-4) 

`PushHandler` then syncs the resolved stacks to an attacker-chosen `after` SHA: [6](#0-5) 

**The broken binding, stated as an equality that should hold but doesn't:**
`organization authenticated by webhook_secret (repository_owner) == owner(repository.full_name resolved to a Stack that gets acted upon)`

Before the fix (current code): the left side is checked by `verify_signature`; the right side is read from an independent, unchecked field of the same attacker-controlled body — they are never compared.

### Impact Explanation
This lets an attacker who controls the `webhook_secret` for one organization onboarded to the Shipit instance forge webhook events (`push`, `check_suite`, `status`, `pull_request`, `membership`, etc.) that are dispatched against **any other organization's Stack** in the same instance, because the identity check (org secret) and the target-selection field (`repository.full_name`) are decoupled. Concretely this enables triggering `GithubSyncJob`/`sync_github` (and other handler side effects such as archiving/unarchiving review stacks, creating teams/users via `membership`) on a victim's stack without any credential belonging to that victim — an unauthorized cross-repository action driven purely by a payload field that was never covered by the identity check that authorized the request. This satisfies the "cross-repository writes" / "unauthorized deploy" impact bar.

### Likelihood Explanation
Likelihood depends on whether the deployment is multi-tenant (multiple organizations, each with a distinct `webhook_secret`, hosted by the same Shipit instance) — which is exactly the model `Shipit.github(organization:)` and `secrets.yml`'s `github:` block support. Any organization admin/webhook holder in such a deployment is, with respect to *other* organizations' repositories, an unprivileged attacker, and can reach this with a single crafted HTTP POST to `/webhooks` with a valid signature for their own org. No repository write access, session, or API client token is required — only knowledge of one's own legitimately-provisioned webhook secret.

### Recommendation
In `WebhooksController#verify_signature` (or immediately after, before dispatch), require that `repository.owner.login` (or `organization.login`) equals the owner segment of `repository.full_name`, and reject (422) any payload where they diverge. Alternatively, resolve the target `Repository`/`Stack` from the authenticated `repository_owner` rather than trusting an independent `full_name` field for repository selection.

### Proof of Concept
1. Attacker legitimately controls org `attacker-org`, onboarded in this Shipit instance, and thus knows its `webhook_secret`.
2. Attacker crafts a POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Attacker computes `X-Hub-Signature: sha1=<hmac(webhook_secret_of_attacker-org, body)>` using their own known secret and sends the request.
4. `verify_signature` calls `Shipit.github(organization: "attacker-org")` and successfully verifies the HMAC against the body — passes.
5. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` [7](#0-6)  and calls `stack.sync_github(expected_head_sha: params.after)` on the victim's stack [8](#0-7) , causing Shipit to act on `victim-org/victim-repo` using a signature that only ever proved knowledge of `attacker-org`'s secret.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
```
