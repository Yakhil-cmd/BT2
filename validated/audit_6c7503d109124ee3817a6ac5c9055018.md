The vm2 CVE-2023-32314 stems from JavaScript's dynamic `Proxy` object trapping mechanism creating an unexpected host object that escapes the sandbox — this is a JS engine/language-specific bug class with no structural analog in Rust/FRAME, which has no dynamic proxy/trap object model at the type-system level.

My search into the codebase's `pallet-proxy` (a different "proxy" concept — delegated dispatch authorization, not object proxying) found the closest semantically-related bug class: `InstanceFilter::is_superset` mismatches vs `filter` that could let a `ProxyType` privilege-escalate via `add_proxy`. However, the one concrete instance of this bug class in this codebase (`NonTransfer` on Asset Hub Westend falsely claiming superset of `Governance`) is already fixed, as documented in [1](#0-0) , and is now guarded by a regression test asserting the fix and a lattice-wide invariant test across all `ProxyType`s [2](#0-1) [3](#0-2) .

I checked the other live runtimes' `ProxyType::is_superset` implementations (`polkadot/runtime/westend`, `polkadot/runtime/rococo`, `substrate/frame/staking-async/runtimes/rc`) and all of them collapse to the simple `NonTransfer` implies superset of everything except `Any`, with no per-pallet claims that could be inconsistent with `filter` [4](#0-3) [5](#0-4) [6](#0-5) . The `add_proxy`/`remove_proxy` gating logic in `pallet_proxy::do_proxy` correctly checks `is_superset` before allowing a delegate to escalate [7](#0-6) .

I also examined `pallet-contracts`/`pallet-revive` Wasm/PolkaVM sandboxing (`LoadedModule::new`, `validate`, PVM limits enforcement) since these are the closest "code sandbox" analogs in this codebase, but found no unchecked host-object-creation-equivalent gap — module validation, import/export scanning, and blob limits are enforced consistently before execution [8](#0-7) [9](#0-8) .

No unpatched, reachable, attacker-triggerable analog matching the vm2 bug class exists in the inspected scope.

fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));

		#[cfg(feature = "std")]

		let program = polkavm::ProgramBlob::parse(pvm_blob.as_slice().into()).map_err(|err| {
