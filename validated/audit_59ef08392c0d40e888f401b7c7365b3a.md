### Title
Silently Swallowed VRank Errors in `fetchVRankCtx` Produce Fail-Open Validator-Set Transitions, Bypassing PFS/CFS Penalties and Corrupting On-Chain Validator State — (`File: kaiax/valset/impl/transition.go`)

### Summary

`fetchVRankCtx` in `kaiax/valset/impl/transition.go` catches all errors from `VRankModule.GetCFS`, `VRankModule.GetPfReport`, and `VRankModule.GetPFS`, logs them, and returns `nil`/empty values to the caller instead of propagating the error. The caller (`newTransitionContext` → `applyTransition` → `writeTransitionToABv2`) proceeds with empty VRank context and writes the resulting — incorrectly computed — validator-state diff to AddressBookV2 (on-chain state). This means that whenever VRank data is unavailable, validators that should be penalised for proposal failures (PFS) or candidate-failure scores (CFS) are silently exempted, and the wrong validator set is committed to chain state.

### Finding Description

`fetchVRankCtx` is explicitly documented as "fail-open": [1](#0-0) 

Three independent error paths are swallowed:

1. **`GetCFS` failure** (epoch blocks only): `cfs` is returned as `nil`. `isPassVrankTest` then treats every `CandTesting` validator as having no score recorded and returns `true` (pass): [2](#0-1) 

   Transition T2 (`CandTesting → Registered`) is therefore never applied at the epoch boundary, and high-CFS candidates compete for `ValActive` slots they should have been barred from.

2. **`GetPfReport` failure**: `pfReport` is `nil`. `applyViolationTransition` short-circuits immediately: [3](#0-2) 

   No PFS violation check fires for that block, regardless of how many proposal failures actually occurred.

3. **`GetPFS` failure** (even when `GetPfReport` succeeds): `pfs` map is `nil`. Inside the PFS loop, `ctx.PFS[addr]` returns `0, false`, so `!ok` causes every validator to be skipped: [4](#0-3) 

   Validators with accumulated PFS scores above the threshold escape both `ValPaused` (minor) and `ValExiting` (severe) demotions.

The corrupted `TransitionResult` is then written to AddressBookV2 via `writeTransitionToABv2`: [5](#0-4) 

The test suite explicitly names and validates this behaviour as "errors fail open": [6](#0-5) 

### Impact Explanation

**Validator-set state corruption (on-chain):** The wrong node states are written to AddressBookV2. Validators that should be in `ValExiting` or `ValPaused` remain `ValActive`; candidates that should be `Registered` remain `CandTesting` and then win `ValActive` slots at the next epoch. This is a persistent, on-chain invalid state transition.

**Unauthorized reward distribution:** `ValActive` validators receive block rewards every block. Validators that should have been demoted continue to receive KAIA block rewards they are no longer entitled to under the protocol rules. Candidates that should have failed the VRank test and been barred from the active set receive proposer and staker rewards they should not receive.

**Consensus set divergence risk:** If VRank errors are non-deterministic across nodes (e.g., one node's checkpoint database is stale while another's is current), different nodes compute different `TransitionResult`s and write different diffs to ABv2, producing divergent on-chain validator sets and potential consensus failure.

### Likelihood Explanation

`GetPfReport` reads `header.VRank` and calls `RoundReader.Round(header)`: [7](#0-6) 

`GetCFS` and `GetPFS` replay block history from checkpoints stored in the chain key-value store. Any of the following non-privileged conditions trigger the fail-open path:

- A node restarts mid-epoch before the VRank warm-up (`Init` calls `GetPFS(head)` and `getCPMatrix(head)`) completes and a block is processed before the cache is populated.
- The VRank checkpoint database entry for the current epoch is missing or corrupted (e.g., after a non-clean shutdown).
- A software bug in the VRank scoring path (e.g., in `applyBlocksForCPMatrix` or `applyBlocksForPFS`) returns an error for a specific block pattern.
- `RoundReader.Round` fails to decode the Istanbul extra data for a header.

None of these require privileged access. The first two are reachable by any node operator running standard software under adverse conditions (crash, disk pressure, sync interruption).

### Recommendation

**Short term:** Propagate VRank errors from `fetchVRankCtx` to `applyTransition` and return them as block-processing errors, consistent with how all other errors in `applyTransition` are handled. If the design intent is to tolerate transient VRank unavailability, the fallback should be to **skip the block** (return an error that causes the caller to retry) rather than to silently apply an incorrect transition.

**Long term:** Separate the "VRank data unavailable" case (which should stall or retry) from the "VRank data available but empty" case (which is a legitimate no-op). Introduce a typed sentinel error (e.g., `ErrVRankUnavailable`) so callers can distinguish transient failures from authoritative empty results, and ensure the validator-set transition pipeline never commits state derived from missing inputs.

### Proof of Concept

1. Start a Kaia node with the permissionless fork enabled.
2. Corrupt or delete the VRank checkpoint entry for the current epoch from the chain key-value store (key prefix `vrankCheckpoint || Uint64BE(epochStart)`).
3. Trigger a block at an epoch boundary (block number divisible by `VRankEpoch`).
4. `fetchVRankCtx` calls `GetCFS(epochEnd)`, which calls `getCPMatrix` → `lookupCFSSeed` → `loadCPMatrixCheckpointInEpoch` (returns nothing) → `newCPMatrix` → `applyBlocksForCPMatrix`. If the checkpoint is missing and the replay fails, `GetCFS` returns an error.
5. `fetchVRankCtx` logs the error and returns `cfs = nil`.
6. `isPassVrankTest` returns `true` for every `CandTesting` validator regardless of their actual failure score.
7. `applyEpochTransition` promotes all `CandTesting` validators (including those with CFS above threshold) to compete for `ValActive` slots via T3a instead of demoting them to `Registered` via T2.
8. `writeTransitionToABv2` commits this incorrect state to AddressBookV2 on-chain.
9. The promoted validators receive block rewards in subsequent blocks despite having failed the VRank reliability test. [8](#0-7) [9](#0-8) [10](#0-9)

// fetchVRankCtx pulls the three vrank scores transitions need at block num.
// Errors are swallowed here so the orchestrator stays robust to transient vrank failures.
func (v *ValsetModule) fetchVRankCtx(num uint64) (cfs, pfs map[common.Address]uint64, pfReport []common.Address) {
	if v.VRankModule == nil {
		logger.Error("VRankModule is nil")
		return nil, nil, nil
	}
	// Pre-HF blocks have no VRank evidence. Keep applyTr(HF-1) as a no-op
	// for VRank-dependent transitions by returning an empty VRank context.
	if !v.Chain.Config().IsPermissionlessForkEnabled(new(big.Int).SetUint64(num)) {
		return nil, nil, nil
	}
	if nextNum := num + 1; v.isVrankEpoch(nextNum) {
		c, err := v.VRankModule.GetCFS(num)
		if err != nil {
			logger.Error("fetchVRankCtx: GetCFS failed", "num", num, "err", err)
		} else {
			cfs = c
		}
	}
	r, err := v.VRankModule.GetPfReport(num)
	if err != nil {
		logger.Error("fetchVRankCtx: GetPfReport failed", "num", num, "err", err)
	} else {
		pfReport = r
	}
	if len(pfReport) > 0 {
		p, err := v.VRankModule.GetPFS(num)
		if err != nil {
			logger.Error("fetchVRankCtx: GetPFS failed", "num", num, "err", err)
		} else {
			pfs = p
		}
	}
	return cfs, pfs, pfReport
}

func (v *ValsetModule) writeTransitionToABv2(
	vmenv *vm.EVM,
	header *types.Header,
	statedb *state.StateDB,
) error {
	num := header.Number.Uint64()
	tr, err := v.getTransitionResult(num, statedb)
	if err != nil {
		return err
	}

	// Compute diff against committed ABv2(N-1) to get only applyTr(N-1) changes.
	parentHeader := v.Chain.GetHeaderByNumber(num - 1)
	if parentHeader == nil {
		return errParentHeaderNotFound(num)
	}
	parentRes, err := system.ReadABv2Snapshot(statedb, v.Chain, parentHeader)
	if err != nil {
		return fmt.Errorf("failed to read ABv2(N-1): %w", err)
	}
	diff := diffNodeStates(parentRes.Nodes, tr.Nodes)

	// Skip the call if no changes and not an epoch block (epoch blocks need
	// the epochVACount snapshot update regardless)
	if len(diff) == 0 && !v.isVrankEpoch(num) {
		return nil
	}

	config := v.Chain.Config()
	from, msg, err := system.EncodeProcessSystemTransition(config.Rules(header.Number), diff, tr.epochVACountForWrite)
	if err != nil {
		logger.Error("Failed to encode processSystemTransition", "number", header.Number.Uint64(), "err", err.Error(), "nodes", diff.String())
		return err
	}
	if ret, err := blockchain.SystemTxCall(msg, from, header, vmenv, statedb, config.Rules(header.Number)); err != nil {
		return fmt.Errorf("processSystemTransition failed: %w (ret=%s)", err, common.Bytes2Hex(ret))
	}
	return nil
}

func (ctx *TransitionContext) ApplyAllTransitions(nodes valset.NodeMap) *TransitionResult {
	epochVACountForWrite := uint64(0)

	if ctx.IsEpoch {
		nodes = ctx.applyEpochTransition(nodes)
		// After the epoch transition the active-validator count changes, so
		// slot limits must be recomputed before violation runs.
		epochVACountForWrite = nodes.CountByState(valset.ValActive)
		ctx.SetSlotsCtx(slotLimitsFor(epochVACountForWrite))
	}
	nodes = ctx.applyViolationTransition(nodes)
	nodes = ctx.applyTimeoutTransition(nodes)

	return &TransitionResult{
		Nodes:                nodes,
		epochVACountForWrite: epochVACountForWrite,
	}
}
