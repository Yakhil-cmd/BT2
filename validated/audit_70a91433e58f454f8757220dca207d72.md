### Title
Unsanitized release asset filenames enable path traversal / arbitrary file write via `filepath.Join` in `destinationWriter.makePath` - (File: pkg/cmd/release/download/download.go)

### Summary
`gh release download` writes each release asset to `filepath.Join(w.dir, name)` where `name` is the `Name` field taken directly from the GitHub Releases API response, with no path-separator or `..`-traversal validation applied in this codebase. Unlike the archive-extraction path (`internal/zip/zip.go`, which uses the traversal-safe `safepaths.Absolute.Join`), the asset-download path has no equivalent defense, so an attacker-controlled asset name such as `.git/hooks/pre-commit` or `../../.github/workflows/evil.yml` is written verbatim relative to the destination directory.

### Finding Description
In `downloadRun`, assets come straight from `release.Assets` (an API response) and are converted into `downloadTarget{url, name: a.Name}` without any sanitization: [1](#0-0) [2](#0-1) 

The filename is later used unchanged as the write target: [3](#0-2) [4](#0-3) 

`filepath.Join(w.dir, name)` performs no check that the resulting path stays within `w.dir`; a name containing `/` (e.g. `.git/hooks/pre-commit`) resolves directly into the repository's `.git` directory when `gh release download` is run from the repo root (the default `--dir` is `.`), and a name containing `../` can escape the directory entirely. `os.MkdirAll(filepath.Dir(fp), 0755)` at line 435-439 will happily create any needed subdirectories, and `os.OpenFile(..., O_CREATE|O_TRUNC, 0644)` overwrites/creates the target file.

This is notably inconsistent with the rest of the codebase: for zip-archive extraction the project already has a dedicated `safepaths.Absolute.Join` primitive that detects and rejects/​skips path-traversal (`internal/zip/zip.go:24-40`), and it is used by `pkg/cmd/copilot/copilot.go`'s `extractZip`. The asset-name-based `destinationWriter.makePath` in `download.go` does not use this or any equivalent guard.

The only sanitization of asset names that exists in the codebase is in `pkg/cmd/release/upload/upload.go`'s `sanitizeFileName`, which strips slashes/special characters — but that function only runs client-side during `gh release upload` via the CLI. It is explicitly described as an attempt to "mimic" server-side behavior, not a guarantee, and it has no bearing on assets created through other means (e.g., direct API calls, or any other client) that place arbitrary bytes in the `name` field of an asset object returned by the Releases API. `download.go` performs no defense-in-depth validation of the name it receives, so if the server ever returns (or an attacker manages to get set) a `/`- or `..`-containing asset name, `gh release download` will write outside the intended destination.

### Impact Explanation
If an attacker can get a release asset with a crafted name (e.g. `.git/hooks/post-checkout`, `.github/workflows/ci.yml`) associated with a release the victim downloads, running `gh release download` writes attacker bytes into a git-hook or CI workflow location, leading to code execution the next time git runs a hook or CI/Actions process the workflow file — a Critical, RCE-class impact on the developer's machine, matching the GitHub Bug Bounty "RCE in gh" impact class.

### Likelihood Explanation
Exploitability depends entirely on whether the GitHub Releases API can be made to return an asset `Name` containing `/` or `..` sequences. The codebase gives no evidence this is enforced server-side beyond a client-side sanitizer in the unrelated `upload` command; there is no test or guard confirming that traversal-y names are rejected on the download path itself, unlike the parallel `internal/zip` code which explicitly defends against exactly this class of issue for zip contents. Because the write-path code (`destinationWriter.makePath`/`Copy`) contains zero validation, any asset name that does contain a separator will be exploited without further conditions once the victim runs `gh release download` in the affected repository.

### Recommendation
Validate/sanitize `a.Name` (and any archive `Content-Disposition` filename) before use in `makePath`: reject or strip path separators and `..` components, or better, route the final path through the existing `safepaths.Absolute.Join` helper (as already used in `internal/zip/zip.go`) so any traversal attempt is rejected/skipped rather than silently honored.

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
}
