### Title
Griefing top-up of an insolvent account's existing supply leg permanently blocks permissionless bad-debt cleanup - (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
`clean_bad_debt` is permissionless but only admits an account when `total_collateral <= BAD_DEBT_USD_THRESHOLD`. Because `supply` lets any third party top up an asset slot an account already holds, an attacker can donate just over the dust threshold of collateral to an insolvent account and shut the permissionless cleanup gate. The uncapped gate, `force_socialize_bad_debt`, is owner-only, so the bad debt then persists in the market's books unless governance acts — a reachable "unauthorized state change + partial denial of service" analog to CVE-2023-21986.

### Finding Description
The dust gate for permissionless socialization is value-based and checked against live totals: [1](#0-0) 

`process_clean_bad_debt` is callable by any address (`caller.require_auth()` only) and reaches `socialize_bad_debt` with `BadDebtGate::DustCapped`, which reverts with `CannotCleanBadDebt` when `total_collateral` exceeds the threshold: [2](#0-1) 

Meanwhile `controller::supply` permits anyone to top up a foreign account as long as the asset is already one of the account's supply positions ("only for hub assets it already holds a supply position in"), per the declared permissionless surface: [3](#0-2) 

The Certora boundary rule confirms the exact straddle: one raw unit above `BAD_DEBT_USD_THRESHOLD` keeps the account insolvent yet blocks the dust gate: [4](#0-3) 

The threat model acknowledges that above the permissionless threshold an insolvent account "may require the governed force-socialize runbook," so this is partially documented as residual risk, but no control prevents a third party from manufacturing that state on someone else's account. [5](#0-4) 

### Impact Explanation
Protocol insolvency / persistent bad debt (Medium). While `total_collateral` stays above the threshold, every `clean_bad_debt(account_id)` call reverts, so the insolvent account's debt is never socialized and its collateral is never converted to revenue. The market's measured backing shortfall persists; suppliers' claims remain impaired and the index write-down needed to reflect the loss is deferred indefinitely absent an owner-run `force_socialize_bad_debt` runbook. Attack cost is a donation of ~`BAD_DEBT_USD_THRESHOLD` USD of collateral — trivially cheap and permanent for as long as the attacker tops up faster than price drift erodes it.

### Likelihood Explanation
Fully reachable by a single unprivileged address:
1. `supply(attacker, 0, hub, [(asset, amt)])` creates an attacker-owned account, then `borrow` draws debt against it; wait for, or contribute to, a price move that makes it insolvent (HF < 1, debt > collateral).
2. Let liquidators seize most collateral, or simply structure the account so remaining collateral sits below the dust cap — the normal path to `clean_bad_debt`.
3. `supply(attacker, victim_id, hub, [(existing_collateral_asset, dust_topup)])` pushes `total_collateral` to `BAD_DEBT_USD_THRESHOLD + ε`. Because it uses an existing supply slot, `INV-AUTH-03` does not block it.
4. Every subsequent `clean_bad_debt` reverts at the `is_socializable_bad_debt` assertion. If price drift pushes collateral back under the cap, repeat step 3 — the straddle is renewable.

The attacker can also front-run observed `clean_bad_debt` calls on any insolvent account that already has a supply leg, applying the same blockade to third-party bad debt.

### Recommendation
Make the dust gate resistant to donation griefing. Options: (a) exempt unsolicited third-party supply from counting toward the cleanup threshold (e.g., snapshot a per-account "cleanup eligibility" stamp, or track self-funded vs. donated supply); (b) let `clean_bad_debt` ignore collateral donated by addresses other than the account owner/delegate, which requires tagging deposits by payer; or (c) allow `clean_bad_debt` to first seize-and-convert remaining collateral up to the threshold rather than gating on its USD value. Alternatively, accept the residual risk explicitly but lower `BAD_DEBT_USD_THRESHOLD` and add monitoring, since the current gate makes the griefing cost equal to the cleanup bound.

### Proof of Concept
Conceptual harness PoC (mirroring `tests/test-harness` style):

```rust
// Attacker opens an account, supplies collateral, borrows against it.
let id = ctrl.supply(&attacker, &0u64, &hub, &vec![&env, (collat.clone(), c_amt)]);
ctrl.borrow(&attacker, &id, &hub, &debt_asset, &d_amt);

// Price moves → account insolvent, collateral < BAD_DEBT_USD_THRESHOLD.
oracle.set_price(&collat.asset, &crashed_price);

// Grief: top up the victim's existing collateral leg just above the cap.
let topup = dust_amount_above_threshold();
ctrl.supply(&attacker, &id, &hub, &vec![&env, (collat.clone(), topup)]);

// Permissionless cleanup now reverts permanently.
assert_contract_error!(
    ctrl.try_clean_bad_debt(&keeper, &id),
    CollateralError::CannotCleanBadDebt
);
// Only owner-gated force_socialize_bad_debt can still clear it.
```

Root cause: `BadDebtGate::DustCapped` evaluates `total_collateral` on live, attacker-influenceable state, while the only countermeasure (`supply` requiring owner/delegate for existing slots) is deliberately absent to support `INV-AUTH-03` top-ups.

```rust
/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}
```

```rust
/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));

    // Explicit +1 witness: one raw WAD unit above the cap blocks it.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(BAD_DEBT_USD_THRESHOLD + 2),
        Wad::from(BAD_DEBT_USD_THRESHOLD + 1)
    ));
```
