### Title
Truncated integer exponent in graduated liquidation curve causes incorrect liquidation percentage, over/under-seizing borrower collateral - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`calc-liq-factor-exp` (mainnet/contracts/market/v0-4-market.clar:708-713) implements `liq-factor^alpha` for the graduated liquidation curve. When `exp > BPS` (i.e., alpha > 1), it computes the integer exponent by first truncating `(/ exp BPS)` and then raising `factor` to that truncated power, instead of computing the true fractional power before any truncation — the same order-of-operations rounding-bias class as Fei's `Roots.twoThirdsRoot`/`threeHalfsRoot` bug cited in the report. [1](#0-0) 

### Finding Description
`calc-liq-factor-exp` branches on `exp` (the curve exponent, scaled in BPS, e.g. `15000` = 1.5×):
```
(define-private (calc-liq-factor-exp (factor uint) (exp uint))
  (if (is-eq exp BPS) 
    factor
    (if (> exp BPS) 
        (/ (pow factor (/ exp BPS)) (pow BPS (- (/ exp BPS) u1)))
        (sqrti (* factor BPS)))))
``` [2](#0-1) 

For any `exp` strictly between `BPS` and `2*BPS` (i.e., a fractional exponent alpha in `(1, 2)`, such as `alpha = 1.5`), `(/ exp BPS)` performs integer division and truncates to `1`. The function then evaluates `factor^1 / BPS^0 = factor`, completely discarding the curve exponent and falling back to the *linear* liquidation factor regardless of how far above 1.0 alpha actually is. This is structurally identical to the reported bug: the truncating step (dividing the exponent) is performed *before* the exponentiation, rather than after, producing a severe downward/upward bias depending on branch, instead of the small bias in the original Fei case.

This `liq-pct-scaled` value directly drives:
- `calc-liq-factor-bound` → `liq-penalty` (bonus paid to liquidator) [3](#0-2) 
- `calc-liq-debt-repay` → `max-debt-usd`, the cap on how much debt/collateral can be liquidated in one call [4](#0-3) 
- `calc-liquidation-params`, which returns `{liq-pct-scaled, liq-penalty, max-debt-usd}` consumed by `process-debt-asset`/`process-collateral-asset` to compute how much collateral is seized from the borrower and paid to the liquidator [5](#0-4) 

Because the truncation collapses any alpha in `(1,2)` down to alpha=1 (linear), a DAO-configured graduated (convex, alpha>1) liquidation curve intended to liquidate a smaller percentage near the partial-liquidation threshold ends up liquidating a strictly larger percentage than designed at every LTV level in that threshold's early range. The liquidator (an unprivileged caller invoking the public liquidate entrypoint) then legitimately seizes more of the borrower's collateral and receives a larger `liq-penalty` bonus than the curve-exponent parameter was set to allow, at the borrower's direct expense.

### Impact Explanation
This is a direct-theft-of-user-funds scenario between two unprivileged principals: the liquidator (attacker/caller) receives more seized collateral (`coll-actual`) and a higher penalty bonus than the intended curve dictates, while the borrower (victim) loses more collateral than the configured liquidation curve should allow for their current LTV. Since `max-debt-usd = calc-liq-debt-repay(total-debt-usd, liq-pct-scaled)` is inflated whenever the true intended `liq-pct-scaled` for alpha in `(1,2)` should be smaller than the linear factor but instead equals the full linear factor, borrowers at LTVs just past `ltv-liq-partial` are exposed to a larger liquidation than the DAO's graduated curve was designed to apply — this is a permanent, direct loss of borrower collateral to the liquidator, not merely a temporary freeze.

### Likelihood Explanation
Any market whose graduated liquidation curve is configured with a `curve-exponent` (alpha) between `BPS` (1.0×) and `2*BPS` (2.0×) — the entire practical range typically used for graduated/convex liquidation curves (e.g., 1.2×, 1.5×, 1.8×) — triggers this bug on every partial liquidation that occurs while `current-ltv` is inside the partial band. No special attacker action beyond calling the ordinary, permissionless `liquidate` entrypoint is required; the mis-computation happens automatically whenever this configuration is live, making this a persistent, easily and repeatedly triggerable defect rather than an edge case.

### Recommendation
Rework `calc-liq-factor-exp` to compute the fractional power without truncating the exponent before exponentiation. Either use a fixed-point power function that operates on `exp` as a rational exponent directly (e.g., decompose alpha into integer and fractional parts and combine an integer power with a `sqrti`/root-based correction for the fractional remainder), or restrict configurable `curve-exponent` values to those exactly representable as `k * BPS` (whole multiples) and reject/round others explicitly with clear documentation, and add regression tests comparing against the true `factor^(exp/BPS)` for the full range of alpha the DAO intends to support (not just alpha=BPS, 2*BPS, or BPS/2).

### Proof of Concept
1. DAO configures a market with a graduated liquidation curve using `curve-exponent = 15000` (alpha = 1.5×, i.e., between BPS=10000 and 2·BPS=20000), intending liquidations near the partial threshold to seize noticeably less than the fully linear amount.
2. Borrower's position reaches `current-ltv` such that `calc-liq-factor` yields, e.g., `liq-pct-linear = 4000` (40%).
3. Intended (undiscovered/true) `liq-pct-scaled = 4000^1.5 / 10000^0.5 ≈ 2530` (≈25.3%), a smaller liquidatable fraction than linear, per the graduated-curve design.
4. Actual on-chain computation: `exp=15000 > BPS=10000` → `(/ exp BPS) = 1` (truncated) → `(/ (pow 4000 1) (pow 10000 0)) = 4000` — i.e., `liq-pct-scaled` returned is `4000` (the full linear factor), roughly 58% larger than the intended `2530`.
5. `calc-liq-debt-repay(total-debt-usd, 4000)` and downstream `process-collateral-asset`/`process-debt-asset` therefore let the liquidator repay and seize ~58% more debt/collateral than the DAO's configured curve intended, directly at the borrower's expense, with no way for the borrower to prevent it since liquidation is a normal permissionless market operation. ;; Apply curve exponent for graduated liquidation
;; liq-factor = liq-factor^alpha
(define-private (calc-liq-factor-exp (factor uint) (exp uint))
  (if (is-eq exp BPS) 
    factor
    (if (> exp BPS) 
        (/ (pow factor (/ exp BPS)) (pow BPS (- (/ exp BPS) u1)))
        (sqrti (* factor BPS))))) ;; assume factor^0.5

;; Scale penalty between min and max using liquidation factor
;; liq-penalty = liq-penalty-min + (liq-factor * (liq-penalty-max - liq-penalty-min) / BPS)
;; Capped at bound-max to handle cases where liq-factor > BPS
(define-private (calc-liq-factor-bound (liq-factor uint) (bound-min uint) (bound-max uint))
  (min bound-max (+ bound-min (mul-bps-down liq-factor (- bound-max bound-min)))))

;; Calculate debt to repay based on liquidation factor
;; debt-repay = liq-factor * debt / BPS
(define-private (calc-liq-debt-repay (debt uint) (liq-factor uint)) 
  (mul-bps-down liq-factor debt))

;; Calculate collateral to seize (includes liquidator bonus)
;; collateral-repay = debt-repay * (BPS + liq-penalty) / BPS
(define-private (calc-liq-collateral-repay (debt-repay uint) (liq-penalty uint)) 
  (mul-bps-down debt-repay (+ BPS liq-penalty)))

;; Calculate actual debt repayment when collateral is capped
;; debt-repay-real = (collateral-amount-usd * BPS) / (BPS + liq-penalty)
(define-private (calc-liq-debt-repay-real (collateral-amount-usd uint) (liq-penalty uint)) 
  (div-bps-down collateral-amount-usd (+ BPS liq-penalty)))

;; Graduated liquidation parameter calculation
;; Combines the 4-step liquidation factor calculation into a single helper
;; Returns: { liq-pct-scaled: uint, liq-penalty: uint, max-debt-usd: uint }
(define-private (calc-liquidation-params
  (current-ltv uint)
  (ltv-liq-partial uint)
  (ltv-liq-full uint)
  (liq-penalty-min uint)
  (liq-penalty-max uint)
  (curve-exponent uint)
  (total-debt-usd uint))
  
  (let ((liq-pct-linear (calc-liq-factor current-ltv ltv-liq-partial ltv-liq-full))
        (liq-pct-scaled (calc-liq-factor-exp liq-pct-linear curve-exponent))
        (liq-penalty (calc-liq-factor-bound liq-pct-scaled liq-penalty-min liq-penalty-max))
        (max-debt-usd (calc-liq-debt-repay total-debt-usd liq-pct-scaled)))
    {
      liq-pct-scaled: liq-pct-scaled,
      liq-penalty: liq-penalty,
      max-debt-usd: max-debt-usd
    }))
```
