### Title
Governance vote `checkConsistency` checks each KIP-71 bound vote in isolation, allowing two same-epoch votes to ratify an inverted `LowerBoundBaseFee > UpperBoundBaseFee` state that corrupts every subsequent block's base-fee and KAIA fee-burn accounting — (`File: kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` validates each governance vote individually against the **current effective** parameter set. It does not validate the combined effect of multiple votes cast within the same epoch. A council member (in `none` governance mode) can cast two votes in the same epoch — one raising `LowerBoundBaseFee` above the current `UpperBoundBaseFee` value, and one lowering `UpperBoundBaseFee` below the current `LowerBoundBaseFee` value — each of which passes the per-vote check in isolation. When both are ratified at the epoch boundary, the effective parameter set has `LowerBoundBaseFee > UpperBoundBaseFee`, permanently inverting the KIP-71 base-fee adjustment mechanism and corrupting KAIA fee-burn and reward-distribution accounting for every subsequent block.

---

### Finding Description

`checkConsistency` enforces two one-sided guards:

```go
// kaiax/gov/headergov/impl/header.go  lines 179-192
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {   // checked against CURRENT upper
        return ErrLowerBoundBaseFee
    }
    return nil
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {   // checked against CURRENT lower
        return ErrUpperBoundBaseFee
    }
    return nil
``` [1](#0-0) 

Each vote is validated against `GetParamSet(blockNum)`, which returns the **currently effective** parameters — not the pending votes already accumulated in the same epoch. The ratification path (`getExpectedGovernance`) simply merges all votes from the previous epoch without any cross-parameter consistency check:

```go
// kaiax/gov/headergov/impl/header.go  lines 218-233
func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
    prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
    govs := make(gov.PartialParamSet)
    for _, voteBlock := range sortedVoteBlocks {
        vote := prevEpochVotes[voteBlock]
        govs.Add(string(vote.Name()), vote.Value())   // no cross-param validation
    }
    return headergov.NewGovData(govs)
}
``` [2](#0-1) 

**Attack sequence (none-mode, two council members):**

| Block | Vote | Per-vote check | Current effective params |
|-------|------|----------------|--------------------------|
| 100 (epoch k) | `LowerBoundBaseFee = 600 Gkei` | 600 ≤ 750 ✓ | Lower=25, Upper=750 |
| 200 (epoch k) | `UpperBoundBaseFee = 50 Gkei` | 50 ≥ 25 ✓ | Lower=25, Upper=750 |
| k·epoch | ratification | — | **Lower=600, Upper=50** ← inverted |

Both votes pass `checkConsistency` individually. After ratification, `LowerBoundBaseFee (600) > UpperBoundBaseFee (50)`.

The corrupted parameters are then consumed by `NextMagmaBlockBaseFee` in every subsequent block:

```go
// params/kip71_config.go  lines 80-86
parentBaseFee := parentHeaderBaseFee
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {   // parentBaseFee >= 50 → almost always true
    parentBaseFee = upperBoundBaseFee             // clamp to 50
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
    parentBaseFee = lowerBoundBaseFee             // clamp to 600
}
``` [3](#0-2) 

With the bounds inverted:
- **High gas usage (above target):** `nextBaseFee` is capped at `UpperBoundBaseFee` (50 Gkei) — the fee is forced to the *lower* value during congestion.
- **Low gas usage (below target):** `nextBaseFee` is floored at `LowerBoundBaseFee` (600 Gkei) — the fee is forced to the *higher* value during idle periods.

This is the exact opposite of the EIP-1559 design intent.

---

### Impact Explanation

Every block's `header.BaseFee` is computed from the corrupted `KIP71Config`. Because `baseFee` is part of the block header and is verified by all nodes via `VerifyMagmaHeader` → `NextMagmaBlockBaseFee`, all nodes agree on the same (wrong) base fee — there is no consensus split, but the fee accounting is permanently wrong:

1. **Fee burning:** Post-Kaia, a portion of `baseFee × gasUsed` is burned. With inverted bounds, KAIA is burned at the wrong rate on every block — under-burned during congestion, over-burned during idle periods.
2. **Reward distribution:** Proposer and staking rewards are computed from the remaining fee after burning. The wrong base fee propagates into every reward calculation.
3. **Transaction filtering:** `FilterTransactionWithBaseFee` in `worker.go` uses `nextBaseFee` to drop transactions below the base fee. With inverted bounds, valid transactions are dropped during idle periods (base fee = 600 Gkei) and spam is admitted during congestion (base fee = 50 Gkei). [4](#0-3) [5](#0-4) 

---

### Likelihood Explanation

In `none` governance mode, any council member (validator) can cast a vote. Two council members acting independently — or a single council member casting two votes in different blocks within the same epoch — can produce the inverted state without any coordination. Neither vote is individually invalid; the flaw is purely in the absence of a cross-vote consistency check at ratification time. On Mainnet and Kairos, governance mode is `single`, so the governing node would need to be the trigger; however, the code path is identical and the missing check is present in all modes.

---

### Recommendation

Add a cross-parameter consistency check at ratification time in `getExpectedGovernance` (or equivalently in `VerifyGov`) after merging all epoch votes into the candidate `PartialParamSet`:

```go
// After building govs from epoch votes:
if lower, lok := govs[gov.Kip71LowerBoundBaseFee]; lok {
    if upper, uok := govs[gov.Kip71UpperBoundBaseFee]; uok {
        if lower.(uint64) > upper.(uint64) {
            return headergov.GovData{}, ErrInvertedBaseFee
        }
    }
}
```

Alternatively, extend `checkConsistency` to look up pending votes already accumulated in the current epoch and validate the new vote against the *pending* value of the counterpart parameter, not just the currently effective one. [6](#0-5) 

---

### Proof of Concept

Assume `none` governance mode, epoch = 604800, current params: `LowerBoundBaseFee = 25 Gkei, UpperBoundBaseFee = 750 Gkei`.

1. Council member A proposes block N (epoch k, block 100): `header.Vote = encode("kip71.lowerboundbasefee", 600_000_000_000)`.  
   `checkConsistency`: `600e9 > 750e9`? No → accepted. ✓

2. Council member B proposes block N+100 (epoch k, block 200): `header.Vote = encode("kip71.upperboundbasefee", 50_000_000_000)`.  
   `checkConsistency`: `50e9 < 25e9`? No → accepted. ✓

3. At block `k * epoch`, `getExpectedGovernance` merges both votes → `{LowerBoundBaseFee: 600e9, UpperBoundBaseFee: 50e9}`. No cross-check is performed. `VerifyGov` accepts the header.

4. From block `(k+1) * epoch` onward, `NextMagmaBlockBaseFee` uses `lower=600e9, upper=50e9`. With any non-zero `parentGasUsed`, `parentBaseFee` is clamped to 50 Gkei (the "upper" bound). Every block's base fee is now 50 Gkei regardless of congestion, and fee-burn accounting is permanently corrupted. [1](#0-0) [2](#0-1) [4](#0-3)

		council, err := h.ValSet.GetCouncil(blockNum - 1)

			return nil
		}

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}
