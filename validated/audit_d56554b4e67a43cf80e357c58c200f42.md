### Title
Path traversal via malicious release asset filename in `gh release download` - (File: pkg/cmd/release/download/download.go)

### Summary
The HackerOne report describes `http_server` serving a file through a symlink to escape the web root. The applicable analog in this codebase is not symlink-following, but the structurally identical bug class of **path traversal through untrusted, attacker-supplied filenames written to disk without sanitization**. `gh release download` writes each release asset to a path built directly from the asset's `Name` field returned by the GitHub API, with no traversal check, unlike the sibling `gh run download` artifact-download code path which explicitly guards against this exact issue.

### Finding Description
In `pkg/cmd/release/download/download.go`, `destinationWriter.makePath` builds the destination path with a plain `filepath.Join(w.dir, name)`: [1](#0-0) 

That `name` comes straight from `shared.ReleaseAsset.Name`/`toDownload`, which is populated from the release's asset list fetched from the GitHub API (attacker-controlled if the attacker owns or can publish to the repository being downloaded from): [2](#0-1) [3](#0-2) 

`Copy` then opens the file with `O_CREATE|O_WRONLY|O_TRUNC` at that unsanitized path and writes the downloaded bytes: [4](#0-3) 

`filepath.Join` normalizes `..` segments but does not prevent the joined path from escaping `w.dir` — e.g. an asset named `../../.bashrc` or `../../.ssh/authorized_keys` will resolve outside the intended download directory. Only a Windows-reserved-filename check is performed on the asset name; no traversal check exists: [5](#0-4) 

This is a clear regression relative to the project's own established pattern: the analogous `gh run download` artifact path explicitly wraps destination construction in `safepaths.Absolute.Join`, which detects and rejects any traversal attempt: [6](#0-5) [7](#0-6) 

The `gh release download` code path was never updated to use this shared `safepaths` protection, leaving it as the one asset-writing flow in the CLI without traversal defense.

### Impact Explanation
A malicious or compromised repository owner can publish a release with an asset whose `name` contains path traversal sequences. Any user who runs `gh release download` (or `gh release download --pattern`) against that repository will have the asset content written to an attacker-chosen location outside the intended download directory, up to whatever permissions the invoking user process has — i.e. arbitrary file write/overwrite on the victim's machine (e.g. overwriting `~/.bashrc`, `~/.ssh/authorized_keys`, or shell profile files), which can lead to code execution on next shell/login.

### Likelihood Explanation
Moderate. It requires the victim to run `gh release download` against a repository controlled (or compromised) by the attacker — a normal, unprivileged interaction that gh explicitly supports and that users routinely perform to fetch release binaries from third-party projects. No MITM, no admin privileges, and no leaked token are required; the only prerequisite is that the GitHub API/asset-upload flow permits asset names containing `../` segments (asset `name` is largely attacker-controlled metadata associated with the release, independent of the actual uploaded file content).

### Recommendation
Route asset destination-path construction in `pkg/cmd/release/download/download.go` (`destinationWriter.makePath`/`Copy`) through the same `internal/safepaths.Absolute.Join` mechanism already used by `pkg/cmd/run/download/download.go`, rejecting any asset whose name would resolve outside `opts.Destination`, and surfacing a clear error (mirroring the `"would result in path traversal"` behavior already implemented for artifact downloads).

### Proof of Concept
1. As the owner of a public repository (or via a compromised account), create a release and upload/rename an asset so that its recorded `name` is `../../evil.sh` (or equivalent traversal sequence), while keeping the actual asset content whatever payload is desired.
2. A victim runs `gh release download <tag> -R attacker/repo` in some project directory.
3. `downloadRun` → `downloadAssets` → `downloadAsset` → `dest.Copy("../../evil.sh", body)` computes `fp := filepath.Join(w.dir, "../../evil.sh")`, which resolves outside the intended `w.dir`, and `os.OpenFile(fp, O_CREATE|O_WRONLY|O_TRUNC, 0644)` writes attacker content there — demonstrating a write outside the intended destination directory.

// Copy writes the data from r into a file specified by name.
func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)

// Join an absolute path with elements to create a new Absolute path, or error.
// A PathTraversalError will be returned if the joined path would traverse outside of
// the base Absolute path. Note that this does not handle symlinks.
func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}
