### Title
Webhook signature verification is bound to `repository.owner.login`/`organization.login` while the event is executed against `repository.full_name` — an org with no `webhook_secret` lets an attacker forge events for any other org's stacks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and therefore which `webhook_secret`) to validate the HMAC signature against using `repository_owner`, a value read straight out of the untrusted JSON body (`repository.owner.login`, falling back to `organization.login`). The event handlers that actually mutate state, however, resolve the target `Stack`/`Repository` from a *different* field of the same untrusted body: `repository.full_name`. These two fields are never checked for consistency, so the "organization that authenticated" and the "repository that is written" are not the same binding.

### Finding Description
`verify_signature` does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
``` [1](#0-0) 
where
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

`Shipit.github(organization:)` resolves a distinct `GitHubApp` config (and thus a distinct `webhook_secret`) per organization key in a multi-org deployment. [3](#0-2)  and `verify_webhook_signature` explicitly trusts the payload unconditionally when that organization's `webhook_secret` is blank/unset:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [4](#0-3) 

`webhook_secret` is documented as optional (`nil`) per-organization. [5](#0-4) 

Once the request passes (or trivially bypasses) `verify_signature`, the actual event dispatch and stack resolution use an entirely different field:
```ruby
def process
  stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [6](#0-5) 
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [7](#0-6) 

Because `repository.owner.login` (used to pick the signature-verifying `GitHubApp`) and `repository.full_name` (used to pick the acted-upon `Repository`/`Stack`) are two independent, attacker-controlled keys of the same JSON body, an attacker can set them to point at different organizations. This is exactly the "organization that authenticated versus the repository that is written" binding break called out in the exploit class.

### Impact Explanation
In a multi-organization Shipit deployment (explicitly supported and documented) [5](#0-4) , if any single configured organization has `webhook_secret` left unset, an unauthenticated internet attacker can:
1. Set `repository.owner.login` (or `organization.login`) to the org with no configured secret — `verify_webhook_signature` will return `true` unconditionally for this request. [8](#0-7) 
2. Set `repository.full_name` to `"<victim-org>/<victim-repo>"` — an org/repo whose stacks the attacker has no access to at all.
3. The request passes `verify_signature` fully (no signature is required at all since the secret is blank), and the dispatched handler (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, etc.) resolves and acts on the victim organization's `Repository`/`Stack` via `repository_name`/`repository.full_name`.

This lets an attacker forge push/status/check_suite events for repositories belonging to organizations they have no relationship with, causing cross-organization writes — e.g. triggering `GithubSyncJob`, injecting forged commit statuses via `StatusHandler#process` (`Commit#create_status_from_github!`), or forging check-run refresh jobs that feed the merge/deploy gating logic — none of which requires knowledge of any secret. This matches the "cross-repository writes" / unauthorized-action impact category.

### Likelihood Explanation
Requires only that a multi-organization Shipit deployment exist and that at least one configured organization leaves `webhook_secret` unset — a state the setup docs present as a normal, supported configuration option, not a misconfiguration. No credentials, sessions, or tokens of any kind are needed by the attacker; only network access to `POST /webhooks` with a crafted JSON body and the `X-Github-Event` header.

### Recommendation
Do not select the verifying `GitHubApp`/secret from the same untrusted payload field that is decoupled from the field used to resolve the acted-upon repository. Either:
- require `repository.owner.login` and `repository.full_name`'s owner segment to match before dispatching, rejecting mismatches with `422`, and/or
- disallow (or fail closed on) an organization having no `webhook_secret` configured when running in multi-organization mode, since a blank secret currently means "accept any payload, for any repository, from anyone."

### Proof of Concept
Given a multi-org `secrets.github` config where `OrgWithoutSecret.webhook_secret` is `nil` and `VictimOrg.webhook_secret` is set:
```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything-or-omitted

{
  "repository": {
    "owner": { "login": "OrgWithoutSecret" },
    "full_name": "VictimOrg/victim-repo"
  },
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>"
}
```
`verify_signature` looks up `Shipit.github(organization: "OrgWithoutSecret")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally regardless of the (or a missing) `X-Hub-Signature` header. [4](#0-3)  The request then reaches `PushHandler#process`, which resolves `VictimOrg/victim-repo`'s stacks via `repository_name` = `payload.dig('repository', 'full_name')` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")`, entirely bypassing any authentication tied to `VictimOrg`.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
