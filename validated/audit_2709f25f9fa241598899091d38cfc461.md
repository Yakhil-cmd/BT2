### Title
`flash_position` prices callback-supplied collateral with a stale pre-manipulation oracle value - (`contracts/controller/src/strategies/flash_position.rs`)

### Summary

`process_flash_position` caches collateral and debt prices before minting debt and invoking an attacker-controlled receiver. [1](#0-0)  The receiver can then move an Aquarius-sourced collateral price downward, return collateral to the controller, and have the final solvency check value that collateral at the stale higher price. [2](#0-1)  `Context::fetch_prices` retains the first fetched `PriceFeedRaw`, and `cached_price` later returns that unchanged value. [3](#0-2) 

### Finding Description

The vulnerable ordering is:

1. `prefetch_strategy_prices` loads the collateral and debt feeds before external control is transferred. [4](#0-3) 
2. `mint_and_forward` creates the debt position and transfers the borrowed tokens to the receiver. [5](#0-4) 
3. The receiver callback executes before collateral balances are measured. [6](#0-5) 
4. Callback-supplied collateral is deposited and `strategy_finalize` performs the risk check. [7](#0-6) 
5. The risk calculation uses `feed.price` already stored in the invocation-local context, rather than the post-callback price. [8](#0-7) 
6. Debt is also valued from the cached feed, so neither side reflects a price change caused by the callback. [9](#0-8) 

This is equivalent to using a stale order price when collateral is sourced later: debt is created first, the attacker gains an opportunity to change the economic state, and only then is the collateral priced with the obsolete value. [10](#0-9) 

### Impact Explanation

An attacker can keep the forwarded debt tokens, supply collateral whose real current value is below the stale valuation, and leave an account that would fail the LTV or health-factor checks under the post-callback price. [11](#0-10) 

If the collateral decline is large enough that its unweighted current value is below the debt value, the position is economically insolvent and subsequent liquidation leaves residual bad debt for suppliers. [12](#0-11)  If the manipulated feed is outside the accepted bands, the stale cached value also bypasses the normal post-move validity check, potentially leaving a temporarily unliquidatable position until a valid price is restored. [13](#0-12) 

### Likelihood Explanation

The path requires only an authenticated caller, a flash-loanable debt market, a listed collateral market, and an attacker-owned Wasm receiver implementing `execute_flash_position`. [14](#0-13)  A new Multiply, Long, or Short account can be used, so no pre-existing victim position is required. [15](#0-14) 

The receiver must be able to move the collateral asset's accepted pricing source, such as an Aquarius pool, by enough to cross the configured LTV or liquidation threshold. [16](#0-15)  The required relative move is `P_current / P_cached < LTV` for actual collateral value below debt, or `< liquidation_threshold` for a post-action health factor below one.

### Recommendation

Invalidate and refetch token prices after the receiver callback and before collateral deposit valuation and `strategy_finalize`. [17](#0-16)  The refreshed feeds must again pass freshness, validity, and dual-source tolerance checks; merely recording minimum token amounts is insufficient because the exploit concerns USD valuation, not receipt measurement. [18](#0-17)  If the same context must remain for indexes or spoke usage, add an explicit `refresh_prices` operation that replaces rather than retains entries in `token_prices`. [3](#0-2) 

### Proof of Concept

Assume:

- Debt asset `A` has a stable price of `$1`.
- Collateral asset `B` initially has a valid cached price `P0 = $100`.
- `B` has `LTV = 80%` and `liquidation_threshold = 90%`.
- The attacker controls a deployed receiver contract.

Attack:

1. Call:

   ```text
   flash_position(
       caller = attacker,
       account_id = 0,
       spoke_id = spoke,
       mode = Long,
       debt = A,
       amount = 800,
       receiver = attacker_receiver,
       collaterals = [(B, 1000)],
       refund_assets = []
   )
   ```

2. The controller caches `B = $100`, mints `800 A` of debt, and transfers `800 A` to the receiver. [19](#0-18) 
3. In `execute_flash_position`, the receiver keeps the `800 A`, uses its own `B` inventory to move `B`'s Aquarius-derived price to `P1 = $75`, and transfers `1000 B` to the controller.
4. The controller measures and deposits `1000 B`. [20](#0-19) 
5. The stale valuation gives:

   ```text
   ltv_collateral = 1000 * 100 * 0.80 = $800
   weighted_collateral = 1000 * 100 * 0.90 = $900
   debt = 800 * 1 = $800
   HF = 900 / 800 = 1.125
   ```

   The final gate therefore succeeds. [21](#0-20) 
6. At the post-callback valuation, the account has `$750` of collateral against `$800` of debt and is already below one dollar of collateral per dollar of debt:

   ```text
   actual_collateral = 1000 * 75 = $750
   actual_HF = 750 * 0.90 / 800 = 0.84375
   ```

The attacker retains the borrowed `A`, while subsequent fresh-price liquidation cannot recover the full `$800` debt from the `$750` collateral balance. [22](#0-21)

/// Requires debt coverage by LTV-weighted collateral, health factor >= 1, and
/// the configured collateral floor. Debt-free accounts skip all three checks.
pub(crate) fn require_post_pool_risk_gates(env: &Env, cache: &mut Context, account: &Account) {
    if account.debt_free() {
        return;
    }

    let totals = risk::calculate_account_risk_totals(
        env,
        cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    assert_with_error!(
        env,
        totals.ltv_collateral >= totals.total_debt,
        CollateralError::InsufficientCollateral
    );

    spec_hooks::solvency_gate_checked(account);

    assert_with_error!(
        env,
        totals.health_factor >= Wad::ONE,
        CollateralError::InsufficientCollateral
    );

    let floor = storage::get_min_borrow_collateral_usd_wad(env);
    if floor != 0 && totals.ltv_collateral.raw() < floor {
        panic_with_error!(env, CollateralError::MinBorrowCollateralNotMet);
    }

    require_whole_unit_collateral_floor(env, cache, account);
}
