### Title
Webhook signature verification uses an attacker-controlled organization field while handlers act on a different, unverified `repository.full_name` field, allowing cross-organization forged events - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate against using `repository_owner`, a value read straight out of the untrusted, unsigned JSON body (`params.dig('repository','owner','login')` or `organization.login`). Every downstream `Webhooks::Handlers::Handler` (push, pull_request, etc.), however, resolves the actual `Repository`/`Stack` to act on using a *different* unsigned field, `repository.full_name`. Because signature verification and target-resolution key off two independent, both attacker-supplied, fields, the "organization that authenticated" and the "repository that is written" are never proven to be the same entity.

### Finding Description
The verification flow is: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` resolves a per-organization `GithubApp` config, and `verify_webhook_signature` checks the `X-Hub-Signature` against that org's `webhook_secret`: [3](#0-2) 

Critically, `return true unless webhook_secret` — if the organization selected via the unauthenticated `repository.owner.login` payload field has no `webhook_secret` configured, verification is bypassed entirely and *any* signature (or none) is accepted. Shipit's own setup docs and shipped config templates document `webhook_secret` as **optional**: [4](#0-3) [5](#0-4) 

Once `verify_signature` passes (either because the secret genuinely matches, or because the attacker-chosen org has no secret configured), `WebhooksController#create` dispatches the raw, unverified params to the event handler: [6](#0-5) 

All handlers derive the *acted-upon* repository from `payload.dig('repository', 'full_name')` — a completely separate field from the one used for signature-organization selection: [7](#0-6) [8](#0-7) [9](#0-8) 

**Equality that should hold but doesn't:** `organization used to select/verify the webhook_secret == organization owning the repository the handler mutates`. Before the request: an attacker crafts `{"repository":{"owner":{"login":"OrgWithNoSecret"},"full_name":"VictimOrg/victim-repo"},"ref":"refs/heads/main","after":"<attacker-sha>"}` with header `X-Github-Event: push`. After the request: `verify_signature` resolves `Shipit.github(organization: "OrgWithNoSecret")`, finds no `webhook_secret`, and returns `true` unconditionally — no HMAC needed at all. `PushHandler#process` then looks up stacks for `VictimOrg/victim-repo` (an org the attacker never authenticated as) and calls `stack.sync_github(expected_head_sha: params.after)`, enqueuing `Shipit::GithubSyncJob` for that stack with an attacker-chosen `expected_head_sha`: [10](#0-9) 

This root cause is proven purely from in-scope engine code (`app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/handler.rb`, `app/models/shipit/webhooks/handlers/push_handler.rb`, `app/models/shipit/repository.rb`, `lib/shipit/github_app.rb`) with no reliance on `test/**`.

### Impact Explanation
An unauthenticated internet client, with no Shipit session, no `ApiClient` token, and no knowledge of any org's real `webhook_secret`, can trigger webhook-driven side effects (`GithubSyncJob`, pull-request review-stack creation/archival, membership team/user creation, status writes) against a stack/repository belonging to an organization other than the one whose (absent) secret satisfied `verify_signature`. Because `GithubSyncJob` fetches commits via `stack.github_commits`/`stack.github_api` using the *real* configured GitHub App credentials for the victim org, and merges them (`stack.commits.create_from_github!`) potentially unlocking deploy/rollback/merge flows keyed to `expected_head_sha`, this crosses the "cross-repository writes / unauthorized deploy" impact bar for any Shipit deployment that has at least one organization configured without a `webhook_secret` — a state the project itself documents and ships as an example (`config/secrets.development.shopify.yml`, `docs/setup.md`).

### Likelihood Explanation
Likelihood is High only in the specific, documented-as-supported configuration where at least one onboarded GitHub organization has no `webhook_secret` set (explicitly called "optional" in `docs/setup.md`). In that state, exploitation requires zero credentials and a single crafted HTTP POST to `/webhooks`. If every organization has a webhook secret configured, exploitation additionally requires knowledge of at least one org's real `webhook_secret`, which falls outside this engine's own trust boundary. The vulnerability is a genuine engine-level design flaw (verification target and action target are decoupled) rather than a pure operator-misconfiguration issue, since the "optional secret" behavior is intentional and documented.

### Recommendation
Bind signature verification to the same repository identity the handler will act on: verify the signature using the organization/owner derived from `repository.full_name` (not a separate `owner.login`/`organization.login` field), and reject (rather than silently pass) events for organizations with no configured `webhook_secret`, or require that `webhook_secret` be mandatory for any organization onboarded into `Shipit.github_teams`/multi-org config. At minimum, `verify_webhook_signature` should not treat a missing secret as an automatic pass when the payload asserts a `repository.full_name` outside the resolved organization.

### Proof of Concept
```
POST /webhooks HTTP/1.1
X-Github-Event: push
Content-Type: application/json

{
  "repository": {
    "owner": { "login": "org-without-webhook-secret" },
    "full_name": "victim-org/victim-repo"
  },
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef"
}
```
1. `verify_signature` calls `Shipit.github(organization: "org-without-webhook-secret")` and, finding `webhook_secret` blank, returns `true` regardless of `X-Hub-Signature` (`lib/shipit/github_app.rb:76-83`).
2. `PushHandler#process` resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and, for every non-archived stack on branch `main`, calls `stack.sync_github(expected_head_sha: "deadbeef...")`, enqueuing `GithubSyncJob` against a stack the requester never authenticated for (`app/models/shipit/webhooks/handlers/push_handler.rb:12-17`, `app/models/shipit/repository.rb:53-56`).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
