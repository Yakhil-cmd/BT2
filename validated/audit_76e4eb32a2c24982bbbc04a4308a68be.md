### Title
Path Traversal in `gh release download` via Malicious Asset Name — Arbitrary File Write Outside `--dir` - (File: pkg/cmd/release/download/download.go)

### Summary
`destinationWriter.makePath` builds the output file path with `filepath.Join(w.dir, name)`, where `name` is the release asset's `name` field taken verbatim from the GitHub API response. Because `filepath.Join` does not confine the result to `w.dir` (it only lexically cleans `..` segments, it does not reject them), an attacker who publishes a release with an asset named with traversal sequences (e.g. `../../.ssh/authorized_keys`) can cause `gh release download` to write the downloaded content outside the user-selected `--dir` destination.

### Finding Description
The download flow is: `downloadRun` (pkg/cmd/release/download/download.go:142) builds `downloadTarget{name: a.Name}` directly from the release asset name returned by the GitHub API [1](#0-0) , then calls `downloadAssets` → `downloadAsset`, which calls `dest.Check(fileName)` and, after downloading, `dest.Copy(fileName, resp.Body)` [2](#0-1) .

Both `Check` and `Copy` derive the on-disk path via `makePath`:
```go
func (w destinationWriter) makePath(name string) string {
	if w.file == "" {
		return filepath.Join(w.dir, name)
	}
	return w.file
}
``` [3](#0-2) 

`filepath.Join` lexically cleans the resulting path (collapsing `..` against preceding segments) but does not stop it from escaping `w.dir` when the `name` component contains enough `../` segments — e.g. `filepath.Join("/home/victim/downloads", "../../.ssh/authorized_keys")` resolves to `/home/victim/.ssh/authorized_keys`. There is no use of `internal/safepaths.Absolute.Join` or any equivalent confinement check anywhere in this file, unlike other subsystems in the CLI that use `safepaths` to keep extracted/downloaded content inside a target root.

`Copy` then unconditionally creates the parent directories with `os.MkdirAll(dir, 0755)` and opens/writes the file with `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` [4](#0-3) , so a traversal path will actually be created and written to, not merely rejected.

The only validation applied to `a.Name` before reaching `makePath` is the Windows reserved-filename check and glob-pattern filtering in `downloadRun` [5](#0-4) ; neither of these rejects `..` path segments or absolute paths. No `safepaths`-style confinement exists between the asset's `name` field and the filesystem write.

### Impact Explanation
An attacker who publishes a public release with a malicious asset name can cause the victim's `gh release download` invocation to write attacker-controlled file content to an arbitrary path reachable via relative traversal from the victim's chosen `--dir` (or current directory by default), subject to OS filesystem permissions of the running user. This is a file write outside the intended output directory, which can be used to overwrite configuration files, shell profiles, SSH `authorized_keys`, or other files under the victim's write permissions — a concrete path to persistence/compromise on the victim host. This matches GitHub bounty's "file write/overwrite outside intended path" impact class.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to publish (or have merged) a public GitHub release with a crafted asset `name` — something any repo owner/collaborator with release permissions can do without special privileges relative to the victim. The victim just needs to run `gh release download` (with no `--pattern`/`--output`, or with a pattern that still matches the crafted asset name) against that repo. This is a normal, expected usage pattern (downloading release assets from third-party repos), making the attack highly feasible and repeatable.

### Recommendation
Sanitize/validate `a.Name` before using it to build a filesystem path, or better, use the `internal/safepaths.Absolute.Join` confinement (as used elsewhere in the codebase) inside `makePath` to ensure the resolved path stays within `w.dir`, rejecting or stripping any asset name that would resolve outside of it (e.g., reject names containing `..` path segments after `filepath.Clean`, or verify `strings.HasPrefix(resolvedAbsPath, absDir+string(os.PathSeparator))`).

### Proof of Concept
```go
func TestDownloadRun_AssetNamePathTraversal(t *testing.T) {
    tmpDownloadDir := t.TempDir()
    // sibling target the traversal name should try to escape into
    reg := &httpmock.Registry{}
    defer reg.Verify(t)
    reg.Register(
        httpmock.REST("GET", "repos/OWNER/REPO/releases/latest"),
        httpmock.JSONResponse(map[string]interface{}{
            "assets": []map[string]interface{}{
                {
                    "name": "../../evil.sh",
                    "url":  "https://api.github.com/assets/1234",
                },
            },
        }),
    )
    reg.Register(
        httpmock.REST("GET", "assets/1234"),
        httpmock.StringResponse("malicious content"),
    )

    opts := &DownloadOptions{
        HttpClient: func() (*http.Client, error) { return &http.Client{Transport: reg}, nil },
        IO:         iostreams.Test(),
        BaseRepo:   func() (ghrepo.Interface, error) { return ghrepo.New("OWNER", "REPO"), nil },
        Destination: filepath.Join(tmpDownloadDir, "downloads"),
        Concurrency: 1,
    }

    err := downloadRun(opts)
    require.NoError(t, err)

    // Assert the file was NOT written outside Destination
    escapedPath := filepath.Join(tmpDownloadDir, "evil.sh")
    _, statErr := os.Stat(escapedPath)
    require.NoError(t, statErr, "expected traversal write to escape Destination, confirming vulnerability")

    // Assert it was not properly confined to Destination
    confinedPath := filepath.Join(opts.Destination, "../../evil.sh")
    require.Equal(t, escapedPath, filepath.Clean(confinedPath))
}
```
Expected (vulnerable) result: the file lands at `tmpDownloadDir/evil.sh`, outside `opts.Destination` (`tmpDownloadDir/downloads`), demonstrating the path-confinement bypass. After a fix using `safepaths.Absolute.Join`, this test should instead assert that `downloadRun` returns an error (or that the file remains within `Destination`).
