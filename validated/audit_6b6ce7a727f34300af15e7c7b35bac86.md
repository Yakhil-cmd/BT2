### Title
Webhook signature is verified against the organization derived from `repository.owner.login`/`organization.login`, while the handler acts on the independent `repository.full_name` field — allowing cross-organization webhook forgery in multi-app deployments - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which `GitHubApp` (and therefore which `webhook_secret`) to validate the incoming HMAC signature against, by reading `repository.owner.login` (falling back to `organization.login`) straight out of the *same untrusted payload* being verified. [1](#0-0) [2](#0-1) 

Once the signature passes, every event handler determines *which repository/stack to act on* using a completely different field, `repository.full_name`, via `Shipit::Webhooks::Handlers::Handler#repository_name`/`#stacks` and `Repository.from_github_repo_name`, with no re-check that `full_name`'s organization matches the organization that was used to select/verify the signature. [3](#0-2) [4](#0-3) 

This engine explicitly supports and documents hosting multiple independent GitHub Apps/organizations from a single Shipit instance, each with its own `webhook_secret`. [5](#0-4) 

### Finding Description
`verify_signature` computes `repository_owner` from the payload and looks up the corresponding `GitHubApp`:

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [6](#0-5) 

`GitHubApp#verify_webhook_signature` explicitly no-ops when the org's `webhook_secret` is not configured:

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [7](#0-6) 

An unset `webhook_secret` is a documented, first-class configuration state for multi-org deployments — every shipped example config (`config/secrets.development.example.yml`, `config/secrets.development.shopify.yml`, `template.rb`, `docs/setup.md`) shows `webhook_secret:` left blank as the default, and `docs/setup.md` explicitly documents the multi-organization schema where each org gets its own top-level key/secret. [8](#0-7) [9](#0-8) 

Once `verify_signature` passes, the *actual* repository the request writes to is picked independently from a different field of the same untrusted JSON body:

```ruby
def repository_name
  payload.dig('repository', 'full_name')
end

def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end
``` [3](#0-2) 

`PushHandler#process` (and analogously `status`, `check_suite`, `pull_request`, etc.) then acts directly on those stacks (`stack.sync_github(expected_head_sha: params.after)`), with no verification that the org embedded in `full_name` matches the org used to validate the signature. [10](#0-9) 

**Binding broken:** `organization authenticated (repository.owner.login / organization.login, used to pick the webhook_secret) != repository written (repository.full_name, used to pick the Stack/Repository acted upon)`. The webhook signature covers the raw HTTP body bytes, but the trust decision ("which org's secret validates this request") and the effect decision ("which repo/stack gets mutated") are read from two independently-attacker-controllable JSON keys within that same body, with no cross-check binding them together.

### Impact Explanation
In a Shipit instance configured for multiple GitHub organizations (a documented, supported topology), if **any** one configured organization is left without a `webhook_secret` — the shipped default in every example/template file — an unauthenticated internet attacker can POST directly to `/webhooks` with:
- `X-Github-Event: push` (or `status`, `check_suite`, `pull_request`, etc.)
- payload `repository.owner.login` (or `organization.login`) set to the unsecured org name — which makes `verify_webhook_signature` return `true` unconditionally, regardless of the `X-Hub-Signature` header contents
- payload `repository.full_name` set to `SecuredOrg/critical-repo` — a repository belonging to a *different*, properly-secured organization tracked by the same Shipit instance

The `PushHandler` will locate the real `Repository`/`Stack` for `SecuredOrg/critical-repo` via `Repository.from_github_repo_name` and trigger `stack.sync_github`, which pulls the (attacker-chosen) `after` SHA and can lead to unauthorized deploys/merges of arbitrary commits against a stack the attacker has no GitHub-level access to, entirely bypassing that organization's configured webhook protection. This crosses the required impact bar: unauthorized deploy/rollback triggering and cross-repository/cross-organization writes, achieved by a fully unprivileged, unauthenticated external attacker.

### Likelihood Explanation
Likelihood is conditioned on at least one organization in a multi-org Shipit deployment being configured without a `webhook_secret` — which is the shipped default in `config/secrets.development.example.yml`, `config/secrets.development.shopify.yml`, and `template.rb`, and is explicitly presented as a supported configuration in `docs/setup.md`'s multi-org section. Given that condition, exploitation requires no credentials, no GitHub App private key, no Shipit session, and no API token — only a raw HTTP POST with a crafted JSON body, making it trivially exploitable once the precondition holds.

### Recommendation
Bind the authentication and effect decisions to the same value: after selecting the `GitHubApp`/secret via `repository.owner.login`/`organization.login`, verify that `repository.full_name`'s owner segment matches that same organization before dispatching to handlers (or, simpler, derive the app/secret lookup from `repository.full_name`'s owner instead of a separately-read field). Additionally, consider refusing silent signature-bypass (`return true unless webhook_secret`) for any organization once more than one GitHub App/org is configured, since a single unsecured org currently downgrades the security of every other org sharing the instance.

### Proof of Concept
1. Deploy Shipit configured for two organizations, per the documented multi-org schema in `docs/setup.md`:
   - `SecuredOrg`: real `webhook_secret`, has a tracked `Repository`/`Stack` (e.g. `SecuredOrg/critical-repo`).
   - `OpenOrg`: `webhook_secret` left blank (the shipped default in every example config in this repo).
2. As an unauthenticated attacker, send:
```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything-invalid
Content-Type: application/json

{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "OpenOrg" },
    "full_name": "SecuredOrg/critical-repo"
  }
}
```
3. `verify_signature` computes `repository_owner => "OpenOrg"`, looks up `Shipit.github(organization: "OpenOrg")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally regardless of the bogus `X-Hub-Signature`. [7](#0-6) 
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("SecuredOrg/critical-repo")` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")`, mutating `SecuredOrg`'s stack despite `SecuredOrg` having a properly configured, unbroken `webhook_secret`. [10](#0-9)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
