This confirms a genuine multi-tenant trust-binding break: `Shipit.github(organization:)` supports a per-organization config map (`secrets.github`) each with its own optional `webhook_secret` [1](#0-0) , and `GitHubApp#verify_webhook_signature` trivially returns `true` when that organization's `webhook_secret` is blank [2](#0-1) .

### Title
Webhook signature verified against `repository.owner.login`'s GitHub App while payload processing acts on `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's GitHub App secret to check the HMAC signature against using `repository.owner.login` (falling back to `organization.login`), but every downstream event handler resolves the repository/stack to actually operate on using the completely separate `repository.full_name` field from the same unauthenticated JSON body.

### Finding Description
`verify_signature` computes `repository_owner` from `params.dig('repository','owner','login') || params.dig('organization','login')` and uses it to fetch the GitHub App config via `Shipit.github(organization: repository_owner)`, then calls `verify_webhook_signature` [3](#0-2) . That method returns `true` unconditionally when `webhook_secret` is blank for that org's config [2](#0-1) , and `webhook_secret` is an optional per-org setting (`@webhook_secret = @config[:webhook_secret].presence`) [4](#0-3) .

Every handler, however, resolves the target repository from `payload.dig('repository','full_name')` (the base `Handler#repository_name`) or `params.repository.full_name` in the pull-request handlers — a field never used, and never bound, in the signature check. For example `Handler#stacks` [5](#0-4) , `OpenedHandler#repository` (which creates review stacks) [6](#0-5) , `ClosedHandler#repository`/`review_stack.archive!` [7](#0-6) , and `PushHandler#process` which triggers `stack.sync_github` on the resolved stacks [8](#0-7) .

This breaks exactly the trust binding called out by the report's bug class: **the organization that authenticated the request (`repository.owner.login`) ≠ the repository that gets written to (`repository.full_name`)**. Because the two fields are read independently from the same fully attacker-controlled JSON body (`request.raw_post`, no authentication required to reach `WebhooksController#create`), an attacker only needs to find *any* organization configured in `secrets.github` with a blank/unset `webhook_secret` to satisfy `verify_signature`, then forge `repository.full_name` to point at a victim org/repository that has real Shipit stacks configured with a properly-set secret.

### Impact Explanation
A successful forgery lets an unauthenticated attacker submit fabricated GitHub events against a victim repository's stacks without ever possessing that repository's real webhook secret: triggering `GithubSyncJob` deploiement syncs, creating/archiving review stacks via `ReviewStackAdapter`, injecting fake commit `Status`, or affecting `PullRequest` records tied to the victim's stacks — i.e., cross-repository/cross-organization writes into stack state that should be isolated per-organization. This matches the "cross-repository writes" / "unauthorized deploy" high-impact category, since it can influence which commits are considered deployable and can archive/unarchive review app stacks tied to a victim repository.

### Likelihood Explanation
Requires at least one configured organization in `secrets.github` to have no `webhook_secret` set (or a per-organization config the attacker can otherwise satisfy), which is an explicitly supported configuration by `GitHubApp#initialize`/`verify_webhook_signature` rather than a hardening requirement enforced by the code. Given multi-organization deployments are the very use case `github_app_config`/`github_organizations` exist for [9](#0-8) , an operator who forgets to set `webhook_secret` on any one tenant compromises the write-path integrity of every other tenant's repositories through this endpoint.

### Recommendation
Bind the signature-verifying organization to the same repository field the handlers use to select the target stack: verify that `repository.owner.login` matches the owner segment of `repository.full_name` before dispatching to handlers, or better, derive `repository_owner` from `repository.full_name` itself so a single field governs both authentication and the write target. Additionally, consider rejecting webhook processing entirely when the resolved organization's `webhook_secret` is blank rather than treating it as an implicit bypass.

### Proof of Concept
1. Shipit is configured with two GitHub orgs in `secrets.github`: `victim-org` (has `webhook_secret` set, owns a repo with active Shipit stacks) and `test-org` (misconfigured with no `webhook_secret`).
2. Attacker POSTs to `/github/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "repository": { "owner": { "login": "test-org" }, "full_name": "victim-org/victim-repo" },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>"
}
```
3. `verify_signature` resolves `repository_owner` = `"test-org"`, calls `Shipit.github(organization: "test-org").verify_webhook_signature(...)`, which returns `true` immediately because `test-org`'s `webhook_secret` is blank [10](#0-9) , regardless of the (missing/arbitrary) `X-Hub-Signature` header.
4. `PushHandler#process` then resolves stacks via `Repository.from_github_repo_name("victim-org/victim-repo")` [11](#0-10)  and enqueues `GithubSyncJob` for the victim's real stacks, all without ever knowing `victim-org`'s webhook secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
