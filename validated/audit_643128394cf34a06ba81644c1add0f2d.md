### Title
Sybil signer-key splitting lets a staker capture voting/reward weight exceeding their proportional locked-STX share in the PoX-5 largest-remainder apportionment - (File: `stackslib/src/chainstate/nakamoto/signer_set.rs`)

### Summary
`pox_5_make_signer_set` (used to build the PoX-5 signer/reward set) allocates `reward_slots` of signing weight using a Hare/largest-remainder quota: each `signer_key`'s base weight is `floor(stacked_amt / threshold)`, and any leftover slots (`reward_slots - sum(base weights)`) are handed out one-per-`signer_key` in descending order of `stacked_amt % threshold`. Because apportionment happens per distinct `signer_key` rather than per staking principal, a single staker who splits an identical amount of locked STX across multiple `signer_key`s can win multiple leftover-slot awards that a single, unsplit key could not, thereby capturing more total signing weight (reward slots) than is proportional to the STX they actually locked. This is the same rounding/division-based value-loss class as the referenced Proteus finding, but here the rounding artifact is exploitable to *gain* unearned weight rather than merely lose it.

### Finding Description
`stackslib/src/chainstate/nakamoto/signer_set.rs` implements `pox_5_make_signer_set`: [1](#0-0) 

The threshold is `max(1, total_ustx_locked.div_ceil(reward_slots))`, each signer's base weight is `stacked_amt / threshold` (floor division), and the remainder `stacked_amt % threshold` determines who gets one of the leftover slots (`reward_slots - sum(base weights)`), sorted by descending remainder with ties broken by `signing_key`: [2](#0-1) 

Because the aggregation key is `signer_key` (a distinct pubkey), and the leftover round assigns at most one slot per distinct key, a staker who spreads a fixed amount of locked STX across `k` different `signer_key`s participates in the leftover round `k` times instead of once. If each of the `k` slices is engineered to have a large remainder just under `threshold` (`stacked_amt % threshold` close to `threshold - 1`), the staker can win up to `k` leftover slots — weight that would not be reachable by keeping the same total stake under one key (where they could win at most one extra slot beyond their floor-division base weight). This directly breaks the intended equality that a signer's total assigned voting weight is bounded by `⌊(their locked STX)/threshold⌋ + 1`; splitting turns that bound into `k` extra units for the same amount of locked STX, at the expense of the honest signers who lose from the shared leftover pool.

The regression test in `stackslib/src/chainstate/nakamoto/tests/signer_set.rs` (`equal_stakes_exceeding_reward_slots_are_not_all_zeroed`) documents that the largest-remainder scheme was deliberately introduced to replace a prior "floor-and-drop" scheme, but the property tests only verify system-wide invariants (`total_weight <= reward_slots`, per-entry `weight in {base, base+1}`) — they do not check per-*staker* (as opposed to per-key) proportionality, so the sybil-splitting gap is not covered: [3](#0-2) [4](#0-3) 

The same `weight`/`stacked_amt` per-`signing_key` division pattern (`floor(stacked_amt/threshold)`) also exists in the PoX-4 `make_signer_set` in `boot/mod.rs`: [5](#0-4) 

### Impact Explanation
This falls into the "High" bucket explicitly listed in scope: signing weight exceeding locked value. A staker who registers multiple `signer_key`s (this is unprivileged — any staker/delegator can choose an arbitrary `signer-key` per stacking action in PoX-5) can obtain more `weight` (i.e., more reward slots and more signer-vote weight in `.signers`/`signers-voting.clar` aggregate-key voting) than the amount of STX they have locked would otherwise entitle them to under a single key. Excess signing weight directly translates into disproportionate control over signature thresholds for Nakamoto blocks and aggregate-key voting, which is a threshold/consensus-security-relevant asset, not merely the attacker's own stake being at risk.

### Likelihood Explanation
Likelihood is constrained by the difficulty of engineering `stacked_amt % threshold` to be large for each split slice, since `threshold` is a chain/consensus-wide value computed from the sum of everyone's stacked amounts for the cycle and is not known with certainty in advance (though it can be estimated/predicted with reasonable accuracy since stacking commitments for the next cycle are visible on-chain during the current cycle before the prepare-phase computation). An attacker with enough capital to be a significant staker already has a strong incentive to maximize signing weight, and splitting a stake across several `signer_key`s costs nothing beyond running multiple signer processes. This makes the attack plausible for any large/whale staker but requires some care in timing/sizing to land favorable remainders, so likelihood is moderate rather than trivial.

### Recommendation
Aggregate `stacked_amt` per staking *principal* (not per `signer_key`) before running the largest-remainder leftover round, or otherwise cap the number of leftover slots any single principal (across all controlled `signer_key`s) may win, mirroring the per-address aggregation already performed by `make_reward_set`/`make_signer_set` for PoX addresses. Alternatively, restrict each stacking principal to a single active `signer_key` per reward cycle. Add a property test that verifies total weight granted to a *single staker* who splits an identical total stake across `N` `signer_key`s never exceeds the weight they would receive by keeping it under one key (i.e., prove `k`-way splitting is not weight-increasing).

### Proof of Concept
Given `threshold = T` and `reward_slots = R`:
1. Staker Alice locks `3T - 3` uSTX under a single `signer_key` A. Base weight = `floor((3T-3)/T) = 2`, remainder = `T-3` (large but only one entry contends for the leftover round). Best-case outcome if she wins the leftover slot: weight = 3.
2. Instead, Alice locks `T-1` uSTX under three separate `signer_key`s (A1, A2, A3) — same total `3T-3` uSTX overall. Each entry independently has base weight `floor((T-1)/T) = 0` and remainder `T-1` (the maximum possible remainder short of `T`), guaranteeing each of the three entries ranks at or near the top of the leftover ordering in `pox_5_make_signer_set` (`signer_set.rs:896-911`). If the leftover pool has ≥3 slots available, all three entries win, giving Alice a combined weight of 3 — matching or, in scenarios where other honest signers have smaller remainders than `T-1`, virtually guaranteeing she captures the leftover slots that a single unsplit key would have had to compete for probabilistically. As the number of splits `k` grows (for the same total locked STX, spread thinner per key but each still crafted to have remainder close to `T-1`), Alice's realized weight approaches `k` while her base (floor) contribution across all keys is driven to `0`, systematically extracting more of the shared leftover pool than her aggregate stake share justifies, at other signers' expense. This is directly reproducible against `NakamotoSigners::pox_5_make_signer_set` in `stackslib/src/chainstate/nakamoto/signer_set.rs:822-937` by constructing `RawPox5Entry` vectors with one aggregated key vs. several split keys carrying the same total `amount_ustx` and comparing resulting `weight` sums.

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}
