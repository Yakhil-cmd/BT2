### Title
Unauthenticated `light/dry_run_aa` network command allows unlimited, unmetered execution of arbitrarily deep/recursive AA logic — Denial of Service - (File: network.js)

### Summary
`light/dry_run_aa` in `network.js` lets any connected peer (no unit posted, no fee paid, no signature required) trigger a full `handleTrigger` evaluation of an arbitrary existing AA with attacker-chosen trigger data/outputs, repeatedly and without any rate limit or resource cap, other than the generic `MAX_COMPLEXITY`/`MAX_OPS` limits enforced once at AA-definition time. This mirrors CVE-2023-25171 (Kiwi TCMS): an unauthenticated, cheap request triggers unbounded backend resource consumption (DB connections, CPU-heavy oscript evaluation, disk I/O) with no throttling in place.

### Finding Description
The handler is: [1](#0-0) 

It only validates that `params.address` is a syntactically valid address and that `params.trigger` passes `validateAATriggerObject` (structural checks only — sizes, address validity, asset existence) via: [2](#0-1) 

It then calls `aa_composer.dryRunPrimaryAATrigger`, which takes a DB connection from the pool, begins a transaction, reads the full AA definition, inserts fake outputs, and runs the complete `handleTrigger` pipeline exactly as if this were a real, stable trigger — including all secondary/chained AA triggers, oscript/formula evaluation, state-variable reads/writes, and database queries — before rolling everything back: [3](#0-2) 

`handleTrigger` recursively calls itself for secondary triggers whenever the AA's response sends funds to another AA address, with no additional per-request throttling beyond the existing `MAX_RESPONSES_PER_PRIMARY_TRIGGER` cap that already exists for genuine on-chain triggers: [4](#0-3) [5](#0-4) 

Crucially, none of this requires:
- Posting a real unit (no headers/payload commission, no PoW-like cost, no fee).
- Any wallet balance, signature, or authentication.
- Any per-connection or per-IP rate limiting — a `grep` across the repository shows no rate-limiting, throttling, or "too many requests" logic anywhere in `network.js` or elsewhere.

Any peer that opens a websocket connection to a full node (this is the standard light-client protocol, reachable by an "unprivileged unit poster" analog — here, an unprivileged light client / paired device / any node peer) can send unlimited `light/dry_run_aa` requests in a tight loop, each one:
1. Taking a DB connection from the pool (`db.takeConnectionFromPool`),
2. Opening a transaction (`BEGIN`),
3. Reading arbitrarily complex, attacker-selected AA definitions (which can be a long chain of interlinked AAs, each with `MAX_OPS`=2000 operations and `MAX_COMPLEXITY`-bounded formulas, and up to `MAX_RESPONSES_PER_PRIMARY_TRIGGER`=10 chained secondary triggers per invocation),
4. Fully evaluating oscript/formula logic (`formula/evaluation.js`), state var reads, and nested `handleTrigger` calls,
5. Rolling back.

Because there exists no cost (bytes fee, TPS fee, PoW) to gate this operation — unlike posting a real unit, which must pay `headers_commission`/`payload_commission`/`tps_fee` — an attacker can flood many full nodes concurrently with concurrent `light/dry_run_aa` calls against the heaviest AA definitions that exist on the DAG (chains of AAs calling remote functions across multiple AAs, as shown to be supported in `test/aa_composer.test.js` for "chain of AAs" and "calling a remote function" tests), exhausting the DB connection pool and CPU, denying service to legitimate light clients and slowing full-node validation/relay of real units.

### Impact Explanation
This does not directly enable theft, double-spend, or inflation, but it satisfies the "network unable to confirm new units" bar from the validation criteria: the attack consumes the shared DB connection pool and CPU that the node also needs for validating and relaying real, fee-paying units and for computing AA triggers for genuinely posted units (`validateAATrigger`, `writer.saveJoint`, `handleAATriggers`). Exhausting connections/CPU on full nodes serving light clients degrades their ability to process the network's actual unit stream, a network-wide availability impact analogous to the CVE's SMTP/service exhaustion.

### Likelihood Explanation
High likelihood: the attack requires no special privileges, no keys, no fees, and no crafted malicious unit — just a normal light-client websocket connection and a loop sending `light/dry_run_aa` requests referencing existing, complex AAs (attacker can even define their own maximally-complex AA chain beforehand and then dry-run-trigger it repeatedly for free). There is no rate limiting anywhere in the message-handling path to mitigate this.

### Recommendation
- Add per-connection/per-IP rate limiting (e.g., token bucket) specifically for `light/dry_run_aa` (and other DB/CPU-heavy light commands) in `network.js`'s `handleRequest`.
- Require the caller to pay a nominal cost or use a lightweight cached/estimated evaluation instead of the full `handleTrigger` pipeline for dry runs, or cap the number of dry-run requests per connection per time window.
- Track and cap concurrent `dryRunPrimaryAATrigger` executions server-wide so a burst of requests cannot exhaust `db.takeConnectionFromPool`.

### Proof of Concept
1. Publish or reuse existing AA definitions forming a chain of AAs that call each other (as in the "chain of AAs" / "calling a remote function" test scenarios), maximizing `MAX_OPS`/`MAX_COMPLEXITY` and `MAX_RESPONSES_PER_PRIMARY_TRIGGER` (10 chained secondary triggers) per dry run.
2. Open a websocket connection to a full node using the standard light-client protocol.
3. Continuously send:
```json
{"command":"light/dry_run_aa","params":{"address":"<heavy_AA_address>","trigger":{"address":"<any_valid_address>","outputs":{"base":10000},"data":{...}}}}
```
4. Repeat concurrently from multiple connections/IPs with no delay — since there is no fee and no rate limit, each request forces the node to take a DB connection, evaluate the full (possibly deeply chained) AA logic, and roll back, exhausting the node's DB pool/CPU and degrading its ability to serve/validate real traffic.

function validateAATriggerObject(trigger, handle) {
	if (!ValidationUtils.isNonemptyObject(trigger))
		return handle("no trigger");
	if (!ValidationUtils.isNonemptyObject(trigger.outputs))
		return handle("no trigger outputs");
	if (!ValidationUtils.isValidAddress(trigger.address))
		return handle("bad trigger address");
	if ("max_aa_responses" in trigger && (!ValidationUtils.isNonnegativeInteger(trigger.max_aa_responses) || trigger.max_aa_responses > constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER))
		return handle("bad trigger max_aa_responses");
	if (ValidationUtils.hasFieldsExcept(trigger, ["address", "data", "outputs", "max_aa_responses"])) // initial_address and initial_unit cannot be separately set in a primary trigger
		return handle("unexpected trigger fields");
	if (string_utils.isTooBigObj(trigger, { lengthLimit: 10e3 }))
		return handle("trigger data is too big");
	try {
		if (trigger.data)
			string_utils.getJsonSourceString(trigger.data);
	}
	catch (e) {
		return handle("invalid trigger data: " + e);
	}
	var arrAssets = Object.keys(trigger.outputs).filter(function(asset) {return asset !== 'base'});
	if (arrAssets.length >= constants.MAX_MESSAGES_PER_UNIT)
		return handle("too many assets");
	if (!ValidationUtils.isPositiveInteger(trigger.outputs.base))
		return handle("no base payment");
	if (!arrAssets.every(function(asset){return ValidationUtils.isPositiveInteger(trigger.outputs[asset])}))
		return handle("invalid output amount")

	function checkAddressIsNotAA() {
		db.query("SELECT 1 FROM aa_addresses WHERE address=?", [trigger.address], rows => {
			if (rows.length)
				return handle("trigger address must not be an AA");
			else
				return handle();
		});
	}

	if (arrAssets.length === 0)
		return checkAddressIsNotAA();
	// we have to check that assets exist otherwise foreign key constraint would fail when inserting fake outputs
	db.query("SELECT 1 FROM assets WHERE unit IN (?)", [arrAssets], function(rows) {
		if (rows.length !== arrAssets.length)
			return handle("unknown asset");
		else
			checkAddressIsNotAA();
	});
}
