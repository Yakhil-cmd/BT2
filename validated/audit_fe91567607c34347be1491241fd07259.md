### Title
Plaintext Logging of Decrypted Device-Message Payloads Exposes Private-Payment Secrets and Textcoin Mnemonics - (File: device.js)

### Summary
`decryptPackage()` in `device.js` unconditionally writes the full plaintext of every successfully decrypted device message to the console/log with `console.log("decrypted: "+decrypted_message)`, before any inspection of its contents. [1](#0-0)  Device messages routinely carry highly sensitive material — private-payment chains (spend proofs/blinding factors), textcoin mnemonics forwarded between a user's own wallets, arbiter-contract pairing codes, and wallet-setup secrets — because any paired correspondent can freely choose the JSON payload it sends. This mirrors the Jenkins Mask Passwords bug class (CWE-319/CWE-532): sensitive secrets that should stay confidential are written out in cleartext to a persistent, commonly-monitored artifact (here, application logs instead of a config form).

### Finding Description
`decryptPackage()` is invoked whenever a device message addressed to the local node is received and successfully decrypted (via `handleMessage`/`hub/deliver` processing in `network.js`, which is directly reachable by any paired device sending `hub/deliver`). [2](#0-1)  After AES-GCM decryption, the function logs the entire decrypted JSON string unconditionally, then parses it: `console.log("decrypted: "+decrypted_message);` [3](#0-2) 

Because the message content is fully controlled by whichever device is paired with the recipient (an "unprivileged" paired correspondent per the pairing flow in `handlePairingMessage`) [4](#0-3) , any data forwarded through this channel — including chains of private elements for private-asset payments and textcoin mnemonics exchanged as part of `storePrivateAssetPayload`/`handlePrivatePaymentFile`/`forwardPrivateChainsToOtherMembersOfOutputAddresses` flows — ends up in plaintext in the recipient's logs. [5](#0-4)  A concrete companion instance of the same bug class is `claimBackOldTextcoins()`, which logs the plaintext mnemonic (the private key material controlling a textcoin address) directly to the console on both success and failure: `console.log("failed claiming back old textcoin "+row.mnemonic+...)` and `console.log("claimed back mnemonic "+row.mnemonic+...)`. [6](#0-5) 

### Impact Explanation
A textcoin mnemonic is equivalent to a bearer private key for the funds sitting at that address; a private-payment chain's blinding factors/spend proofs are the secrets required to prove ownership and later spend private-asset outputs. [7](#0-6)  Persisting either of these in plaintext application logs means that anyone who later obtains read access to those logs (log aggregation services, crash reporters, shared hosting, backups) can directly steal funds or double-spend/claim private assets without needing to compromise the wallet's key storage at all. This satisfies the required "concrete unauthorized spending" impact bar.

### Likelihood Explanation
No special privilege is needed to trigger the logging: pairing with a victim device (a normal, user-initiated but attacker-reachable action) and then sending it any well-formed encrypted device message is enough to make the recipient log the decrypted plaintext. [8](#0-7)  For the textcoin case, simply sending a textcoin (which is an ordinary wallet feature) results in the mnemonic being logged automatically by the periodic `claimBackOldTextcoins` sweep. [9](#0-8)  Exploitation only requires log access, which is a common secondary compromise vector (shared servers, log shipping, support-ticket log pastes), making this a realistic likelihood scenario for a "Medium" severity, consistent with the source advisory's Medium rating.

### Recommendation
Remove or heavily redact the `console.log("decrypted: "+decrypted_message)` statement in `decryptPackage()` — at most log message type/length, never full content. [10](#0-9)  Similarly, redact the mnemonic value in the `claimBackOldTextcoins` log statements, logging only the unit/address instead of the raw mnemonic. [6](#0-5)  Audit other `console.log` call sites flagged in `network.js`, `divisible_asset.js`, `indivisible_asset.js`, and `private_payment.js` for the same pattern of dumping private/secret-bearing variables.

### Proof of Concept
1. Pair a throwaway device with the victim wallet using a normal pairing code (`startWaitingForPairing`/`handlePairingMessage`). [11](#0-10) 
2. From the attacker device, send the victim any encrypted device message (e.g., a chat message) via `hub/deliver`; the victim's client calls `decryptPackage`, which logs the full decrypted body regardless of content. [12](#0-11) 
3. Separately, have the victim send a textcoin via `sendMultiPayment`; when `claimBackOldTextcoins` runs on the configured interval, it prints the plaintext mnemonic for that textcoin to the console/log. [9](#0-8) 
4. Anyone with subsequent read access to the victim's log output can extract the mnemonic (i.e., private key) or private-payment secrets and use them to spend the associated funds/assets.

function handlePairingMessage(json, device_pubkey, callbacks){
	var body = json.body;
	var from_address = objectHash.getDeviceAddress(device_pubkey);
	if (!ValidationUtils.isNonemptyString(body.pairing_secret))
		return callbacks.ifError("correspondent not known and no pairing secret");
	if (!ValidationUtils.isNonemptyString(json.device_hub)) // home hub of the sender
		return callbacks.ifError("no device_hub when pairing");
	if (json.device_hub.length > 200)
		return callbacks.ifError("device_hub too long");
	if (!network.isValidWsUrl(conf.WS_PROTOCOL + json.device_hub))
		return callbacks.ifError("invalid device_hub URL");
	if (!ValidationUtils.isNonemptyString(body.device_name))
		return callbacks.ifError("no device_name when pairing");
	if (body.device_name.length > 100)
		return callbacks.ifError("device_name too long");
	if ("reverse_pairing_secret" in body && !ValidationUtils.isNonemptyString(body.reverse_pairing_secret))
		return callbacks.ifError("bad reverse pairing secret");
	eventBus.emit("pairing_attempt", from_address, body.pairing_secret);
	db.query(
		"SELECT is_permanent FROM pairing_secrets WHERE pairing_secret IN(?,'*') AND expiry_date>"+db.getNow()+" ORDER BY (pairing_secret=?) DESC LIMIT 1", 
		[body.pairing_secret, body.pairing_secret], 
		function(pairing_rows){
			if (pairing_rows.length === 0)
				return callbacks.ifError("pairing secret not found or expired");
			// add new correspondent and delete pending pairing
			var safe_device_name = body.device_name.replace(/<[^>]*>?/g, '');
			db.query(
				"INSERT "+db.getIgnore()+" INTO correspondent_devices (device_address, pubkey, hub, name, is_confirmed) VALUES (?,?,?,?,1)", 
				[from_address, device_pubkey, json.device_hub, safe_device_name],
				function(){
					db.query( // don't update name if already confirmed
						"UPDATE correspondent_devices SET is_confirmed=1, name=? WHERE device_address=? AND is_confirmed=0", 
						[safe_device_name, from_address],
						function(){
							db.query("UPDATE correspondent_devices SET is_blackhole=0 WHERE device_address=?", [from_address], function(){
								eventBus.emit("paired", from_address, body.pairing_secret);
								if (pairing_rows[0].is_permanent === 0){ // multiple peers can pair through permanent secret
									db.query("DELETE FROM pairing_secrets WHERE pairing_secret=?", [body.pairing_secret], function(){});
									eventBus.emit('paired_by_secret-'+body.pairing_secret, from_address);
								}
								if (body.reverse_pairing_secret)
									sendPairingMessage(json.device_hub, device_pubkey, body.reverse_pairing_secret, null);
								callbacks.ifOk();
							});
						}
					);
				}
			);
		}
	);
}

function expandMnemonic(mnemonic) {
	var addrInfo = {};
	mnemonic = mnemonic.toLowerCase().split('-').join(' ');
	if ((mnemonic.split(' ').length % 3 !== 0) || !Mnemonic.isValid(mnemonic)) {
		throw new Error("invalid mnemonic: "+mnemonic);
	}
	mnemonic = new Mnemonic(mnemonic);
	addrInfo.xPrivKey = mnemonic.toHDPrivateKey().derive("m/44'/0'/0'/0/0");
	addrInfo.pubkey = addrInfo.xPrivKey.publicKey.toBuffer().toString("base64");
	addrInfo.definition = ["sig", {"pubkey": addrInfo.pubkey}];
	addrInfo.address = objectHash.getChash160(addrInfo.definition);
	return addrInfo;
}

// if a textcoin was not claimed for 'days' days, claims it back
function claimBackOldTextcoins(to_address, days){
	if (typeof days !== 'number')
		throw Error("bad days: " + days);
	db.query(
		"SELECT mnemonic FROM sent_mnemonics LEFT JOIN unit_authors USING(address) \n\
		WHERE mnemonic!='' AND unit_authors.address IS NULL AND creation_date<"+db.addTime("-"+days+" DAY"),
		function(rows){
			async.eachSeries(
				rows,
				function(row, cb){
					receiveTextCoin(row.mnemonic, to_address, function(err, unit, asset){
						if (err)
							console.log("failed claiming back old textcoin "+row.mnemonic+": "+err);
						else
							console.log("claimed back mnemonic "+row.mnemonic+", unit "+unit+", asset "+asset);
						cb();
					});
				}
			);
		}
	);
}
