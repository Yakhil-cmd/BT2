### Title
Liquidator can seize a borrower's entire remaining collateral balance beyond the graduated liquidation bound via the "dust-sweep" rounding path in `liquidate` - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
In `v0-4-market.clar liquidate`, after the bonus-adjusted collateral seizure (`coll-final-raw`) is computed from the graduated liquidation factor, the function checks whether the borrower's *remaining* collateral for that asset converts (at the liquidation-bonus rate) to a repayable debt amount of exactly `u0`. If so, it discards the bounded seizure amount and instead seizes the borrower's **full** collateral balance for that asset (`coll-final = user-coll-balance`), while the debt actually removed from the borrower's ledger (`scaled-to-remove`/`debt-to-repay`) is still only the smaller, bound-respecting amount computed earlier. A liquidator who chooses `debt-amount` so that the leftover collateral rounds to zero repayable debt captures collateral in excess of what the graduated liquidation curve and penalty bounds allow, at the borrower's expense.

### Finding Description
The liquidation flow computes a graduated, bounded seizure: [1](#0-0) 

`coll-actual`/`coll-final-raw` are capped by `user-coll-balance` and by the debt-driven bound (`calc-liq-collateral-repay`, which folds in `liq-penalty`): [2](#0-1) 

After the bound-respecting `coll-final-raw` is computed via `scale-debt-for-liquidation`, the contract inspects the leftover collateral (`coll-remaining = user-coll-balance - coll-final-raw`). It converts this remainder to a hypothetical “debt repayable” amount using the same bonus-adjusted rate, and if that rounds down to `u0`, it overrides the bounded amount and instead sweeps the borrower's **entire** balance of that collateral asset: [3](#0-2) 

Critically, this override only changes `coll-final` (what gets seized) — it does **not** increase `debt-to-repay`/`scaled-to-remove`, which were already fixed from the earlier, smaller `coll-actual`-based calculation: [4](#0-3) 

So the liquidator repays only the bound-respecting debt amount but can receive the borrower's full remaining collateral of that asset, once the "remainder" is engineered (via the chosen `debt-amount` parameter, which the liquidator fully controls) to fall under the rounding threshold of `mul-div-down`/`mul-div-up` in: [5](#0-4) 

The rounding threshold size depends on `debt-price`/`debt-decimals`/`liq-penalty-max`, and since `debt-amount` is attacker-supplied, a liquidator can iteratively probe/select a `debt-amount` that lands the remainder just below the "repayable" rounding floor, converting a small, bound-respecting partial liquidation into a full collateral sweep for that asset — without repaying debt proportional to the extra collateral taken.

### Impact Explanation
The victim is the borrower being liquidated: they lose collateral beyond what the graduated liquidation curve/penalty (`ltv-liq-partial/full`, `liq-penalty-min/max`, `curve-exponent`) entitles the liquidator to seize for the debt actually repaid. The attacker is the liquidator (an unprivileged, permissionless caller of `liquidate`), and the shared state harmed is the borrower's collateral balance tracked in `market-vault`'s `collateral` map. This is a direct theft of a user's collateral at rest, exceeding the intended liquidation bound, i.e. Critical impact under "direct theft of user funds at rest."

### Likelihood Explanation
`liquidate` is a fully permissionless, public entry point, and `debt-amount` is attacker-controlled, so an attacker can select values that deterministically trigger the rounding branch. The threshold window is a function of price/decimals and is computable off-chain before submitting the transaction, making this reliably repeatable rather than a rare accident.

### Recommendation
When the "remainder rounds to zero" branch sweeps `coll-final` up to `user-coll-balance`, also increase `debt-to-repay`/`scaled-to-remove` proportionally (i.e., treat the swept dust as additional debt repaid at the same bonus rate), or alternatively only sweep dust that is below a protocol-defined absolute minimum (independent of the liquidator's chosen `debt-amount`) rather than a value derived from attacker-controlled inputs.

### Proof of Concept
1. Attacker identifies a borrower whose position is liquidatable (`current-ltv >= ltv-liq-partial`) with a single collateral asset.
2. Attacker computes the graduated liquidation parameters (`liq-pct-scaled`, `liq-penalty`, `max-debt-usd`) for the position, then selects `debt-amount` such that the resulting `coll-actual`/`coll-final-raw` leaves a `coll-remaining` whose USD value, converted at `(BPS + liq-penalty-max)`, produces `rem-debt-usd * 10^debt-decimals < debt-price` (i.e., `mul-div-down` rounds to `u0`).
3. Attacker calls `liquidate(borrower, collateral-ft, debt-ft, debt-amount, min-collateral-expected, none, none)`.
4. `remaining-debt-to-repay` evaluates to `u0`, so `coll-final` is set to `user-coll-balance` (full sweep) at line 1486, while `debt-to-repay`/`scaled-to-remove` remain based on the smaller, bound-respecting `coll-actual`.
5. Attacker receives the borrower's entire collateral balance for that asset while repaying debt equivalent to only the smaller, bound-respecting amount — extracting extra collateral beyond the graduated liquidation bound.

;; Graduated liquidation parameter calculation
;; Combines the 4-step liquidation factor calculation into a single helper
;; Returns: { liq-pct-scaled: uint, liq-penalty: uint, max-debt-usd: uint }
(define-private (calc-liquidation-params
  (current-ltv uint)
  (ltv-liq-partial uint)
  (ltv-liq-full uint)
  (liq-penalty-min uint)
  (liq-penalty-max uint)
  (curve-exponent uint)
  (total-debt-usd uint))
  
  (let ((liq-pct-linear (calc-liq-factor current-ltv ltv-liq-partial ltv-liq-full))
        (liq-pct-scaled (calc-liq-factor-exp liq-pct-linear curve-exponent))
        (liq-penalty (calc-liq-factor-bound liq-pct-scaled liq-penalty-min liq-penalty-max))
        (max-debt-usd (calc-liq-debt-repay total-debt-usd liq-pct-scaled)))
    {
      liq-pct-scaled: liq-pct-scaled,
      liq-penalty: liq-penalty,
      max-debt-usd: max-debt-usd
    }))

;; Process collateral asset for liquidation
;; Handles both enabled and disabled collateral assets
;; Calculates expected collateral, caps at user balance
;; Returns: { coll-actual: uint, coll-expected: uint, coll-price: uint, coll-decimals: uint }
(define-private (process-collateral-asset
  (coll-aid uint)
  (debt-actual-usd uint)
  (liq-penalty uint)
  (user-coll-balance uint)
  (assets (list 64 {
    id: uint, addr: principal, decimals: uint,
    oracle: { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint },
    collateral: bool, debt: bool, price: uint
  }))
  (coll-asset {
    id: uint, addr: principal, decimals: uint,
    oracle: { type: (buff 1), ident: (buff 32), callcode: (optional (buff 1)), max-staleness: uint },
    collateral: bool, debt: bool
  }))
  
  (let (;; Calculate expected collateral in USD (with penalty bonus for liquidator)
        (coll-usd-expected (calc-liq-collateral-repay debt-actual-usd liq-penalty))
        
        ;; Handle disabled collaterals by resolving price if not in enabled assets
        (coll-asset-info (match (find-asset coll-aid assets)
                           ;; Found in enabled list: use it (already has price)
                           found found
                           ;; Not found (disabled): resolve price on demand
                           (let ((oracle-data (get oracle coll-asset))
                                 (price (unwrap-panic (price-resolve oracle-data))))
                             (merge coll-asset { price: price }))))
        (coll-price (get price coll-asset-info))
        (coll-decimals (get decimals coll-asset-info))
        (coll-expected (mul-div-down coll-usd-expected (pow u10 coll-decimals) coll-price))
        
        ;; cap at available collateral (user may not have enough)
        (coll-actual (if (> coll-expected user-coll-balance)
                         user-coll-balance
                         coll-expected)))
    {
      coll-actual: coll-actual,
      coll-expected: coll-expected,
      coll-price: coll-price,
      coll-decimals: coll-decimals
    }))
