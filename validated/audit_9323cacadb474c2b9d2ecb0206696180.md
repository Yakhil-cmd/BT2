### Title
Webhook Signature Verification Bypass via Query-String / Body Parameter Divergence in `repository_owner` Selection - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App (and therefore which `webhook_secret`) to validate a webhook against by reading `repository_owner` out of Rails' merged `params` hash, while `#create` re-derives the actual event payload by parsing `request.raw_post` directly. These two reads of "the organization/repository" are not guaranteed to refer to the same data, because Rails `params` merges query-string parameters over body-parsed parameters. An attacker can therefore make signature verification run against a different (and possibly secret-less) GitHub App configuration than the one whose payload is actually processed, breaking the binding "organization authenticated == repository that is written."

### Finding Description
`verify_signature` computes:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

`params` here is Rails' merged parameter hash (`ActionDispatch::Http::Parameters#parameters`), which shallow-merges `request_parameters` (JSON body) with `query_parameters` (query string), with the query string winning on key collisions. Because `repository` is a single top-level key, an attacker can supply `?repository[owner][login]=<org>` in the query string and have it *completely replace* the body-derived `repository` hash for the purposes of `repository_owner`, without altering `request.raw_post` at all (the HMAC is still computed over the real, unmodified raw body, and, more importantly, only over the raw body, not the query string).

Meanwhile `#create` explicitly parses the raw body again:
```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [2](#0-1) 

So the org used to pick the verification secret (`repository_owner`, influenced by the query string) and the org/repo whose data is actually acted upon by the handlers (parsed straight from `request.raw_post`, unaffected by the query string) can diverge.

In multi-org deployments — explicitly documented and supported (`config/secrets.development.example.yml`, `docs/setup.md` "Using Multiple Github Applications") — each organization can have its own, independently configured `webhook_secret`, and that value is explicitly allowed to be blank/nil:
```yaml
github:
  somegithuborg:
    webhook_secret: # nil
``` [3](#0-2) 

`GitHubApp#verify_webhook_signature` treats an absent secret as "always verified":
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [4](#0-3) 

Combining these: if any org configured in the Shipit instance has no `webhook_secret` set (a documented, legitimate configuration state), an attacker who knows that org's name can send a POST to `/github/webhooks` with:
- Query string: `?repository[owner][login]=<org-without-secret>`
- Body: an arbitrary, unsigned (or wrongly signed) JSON payload referencing the real victim org/repo/stack, e.g. a `push` event, or a `membership` event that adds an arbitrary GitHub login to a `Team` used for `Shipit.github_teams` authorization.

`verify_signature` will resolve `Shipit.github(organization: 'org-without-secret')`, whose `verify_webhook_signature` unconditionally returns `true`, so the request passes signature verification even though it was never signed by GitHub for the targeted victim repository/organization. `#create` then dispatches the untouched, attacker-controlled body to the relevant handler (`PushHandler`, `MembershipHandler`, etc.), which acts on the real target data.

### Impact Explanation
This breaks the intended equality "GitHub organization whose signature was verified == organization/repository whose webhook data is processed." Concretely reachable impacts:
- `Handlers::MembershipHandler#process` calls `team.add_member(member)` for arbitrary GitHub logins [5](#0-4) , which is exactly the "escalation into `Shipit.github_teams` authorization" High-severity impact category, since `User#authorized?` gates access based on team membership [6](#0-5) .
- `Handlers::PushHandler#process` triggers `stack.sync_github(expected_head_sha: params.after)` for arbitrary stacks/branches [7](#0-6) , letting an attacker inject a forged `after` SHA into the sync/deploy pipeline of a real target stack without a valid GitHub signature.

### Likelihood Explanation
Requires: (1) a Shipit deployment configured with more than one GitHub App/organization (a documented, supported configuration), and (2) at least one configured org having no `webhook_secret` (also an explicitly documented, legitimate option) — or, more generally, any two orgs where the attacker knows one org's secret/behavior but not the other's. No authentication, session, or API token is required; only network access to the public `/github/webhooks` endpoint (`skip_before_action :verify_authenticity_token`) is needed [8](#0-7) . The org name used in the query string is typically public information (GitHub org handles), so the main precondition is that the deployment actually uses the multi-org config path with a secret-less entry — plausible but not guaranteed in every deployment.

### Recommendation
- Derive `repository_owner` (and any other value used to select the verification secret) exclusively from the same parsed raw body that is later dispatched to handlers — i.e., parse `request.raw_post` once, store it, and use that single hash for both `repository_owner` and the event payload, never `ActionController`'s merged `params`.
- Disable/ignore query-string parameters entirely for this endpoint route, or strip `query_parameters` before computing `repository_owner`.
- Consider disallowing a configured `webhook_secret: nil` for any GitHub App used in production, or requiring a secret for every registered organization so that `verify_webhook_signature` cannot silently short-circuit to `true`.

### Proof of Concept
1. Configure Shipit with two orgs, e.g. `OrgA` (`webhook_secret: some-secret`) and `OrgB` (`webhook_secret: nil`), matching the documented multi-org config.
2. As an unauthenticated attacker, POST to `/github/webhooks` with:
   - Header: `X-Github-Event: push`
   - Query string: `?repository[owner][login]=OrgB`
   - Body (raw JSON, unsigned/garbage `X-Hub-Signature`):
     ```json
     {"ref":"refs/heads/master","after":"<attacker-chosen-sha>","repository":{"full_name":"OrgA/victim-repo","owner":{"login":"OrgA"}}}
     ```
3. `verify_signature` computes `repository_owner => "OrgB"` (from the query string, overriding the body's `OrgA` for that lookup) via `params.dig('repository', 'owner', 'login')`, resolves `Shipit.github(organization: "OrgB")`, and since `OrgB` has no `webhook_secret`, `verify_webhook_signature` returns `true` unconditionally [9](#0-8) .
4. `create` re-parses `request.raw_post` (unaffected by the query string) and dispatches the forged `push` event for `OrgA/victim-repo` to `PushHandler`, causing `stack.sync_github` to run with the attacker's chosen `after` SHA — despite the request never being validly signed for `OrgA`.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    end

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
