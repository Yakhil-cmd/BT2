### Title
Zero Address Can Be Voted Into the Validator Council Without Validation, Causing Periodic Consensus Delays — (File: `kaiax/gov/param.go`, `kaiax/gov/headergov/impl/header.go`, `kaiax/valset/impl/getter_council.go`)

### Summary

The `governance.addvalidator` vote path accepts zero address (`0x0000...0000`) as a valid validator address because the `FormatChecker` for `AddValidator` is `noopFormatChecker` (always returns `true`) and `checkConsistency` only guards against including the governing node — not against zero address. Once zero address is written into the council, it is treated as a permanently qualified validator in RoundRobin or Sticky proposer-policy chains. When the round-robin schedule selects zero address as proposer, no block can be produced; honest validators time out and advance the round, introducing a forced delay every `len(council)` blocks.

---

### Finding Description

**Step 1 — No zero-address guard in `FormatChecker`**

`ValidatorParams` in `kaiax/gov/param.go` registers `AddValidator` with `noopFormatChecker`, which unconditionally returns `true` for any canonicalized value:

```go
var ValidatorParams = map[ParamName]*Param{
    AddValidator: {
        Canonicalizer: validatorAddressListCanonicalizer,
        FormatChecker: noopFormatChecker,   // ← always true
        DefaultValue:  []common.Address{},
    },
    ...
}
``` [1](#0-0) 

The `validatorAddressListCanonicalizer` accepts a 20-byte slice of all zeros and returns `[]common.Address{common.Address{}}` (zero address) without error:

```go
// Type1
if len(v) == common.AddressLength {
    return []common.Address{common.BytesToAddress(v)}, nil
}
``` [2](#0-1) 

**Step 2 — `checkConsistency` does not reject zero address**

`VerifyVote` calls `checkConsistency`, which for `AddValidator`/`RemoveValidator` only checks that the vote value does not contain the current governing node:

```go
case gov.AddValidator, gov.RemoveValidator:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    if slices.Contains(vote.Value().([]common.Address), params.GoverningNode) {
        return ErrGovNodeInValSetVoteValue
    }
    return nil
``` [3](#0-2) 

Zero address passes this check as long as it is not the current governing node.

**Step 3 — `applyVote` writes zero address into the council**

`applyVote` in the valset module iterates the vote addresses and adds any address that is not the governing node and not already in the council:

```go
for _, address := range addresses {
    if address == governingNode {
        continue
    }
    switch voteKey {
    case gov.AddValidator:
        if !council.Contains(address) {
            council.Add(address)
        }
    }
}
``` [4](#0-3) 

No zero-address guard exists here. Zero address is written to the persistent council DB.

**Step 4 — Zero address becomes a permanently qualified validator in RoundRobin/Sticky mode**

In RoundRobin (policy 0) and Sticky (policy 1) modes, all council members are qualified regardless of staking. Zero address, having no private key, can never sign or propose a block. When the round-robin schedule reaches zero address's slot (`blockNum % len(council) == 0`, since `0x000...000` sorts first lexicographically), no block is produced. Honest validators time out and advance the round, introducing a forced delay every `len(council)` blocks for the lifetime of the chain.

---

### Impact Explanation

Every `len(council)` blocks, the chain stalls for one full round-timeout (typically several seconds) because the selected proposer (zero address) can never produce a block. This constitutes **consensus divergence on honest nodes**: all honest validators agree on the same proposer but none can advance without timing out. On a small council (e.g., 4 validators), 25 % of all block slots are permanently wasted. The effect is permanent and cannot be undone without a hard fork, because `IstanbulPolicy` is in `AlwaysDeprecated` and cannot be changed via governance. [5](#0-4) 

---

### Likelihood Explanation

The trigger requires the governing node to cast a `governance.addvalidator` vote containing zero address. This is a semi-trusted privileged action — analogous to the seed report where governance whitelisting zero address was rated Medium. The scenario is reachable on any permissioned chain using RoundRobin or Sticky proposer policy (policy 0 or 1), which are valid genesis configurations. The absence of a zero-address guard is a missing invariant that the system should enforce regardless of the caller's trust level.

---

### Recommendation

Add a zero-address check in the `FormatChecker` for `AddValidator` (and `RemoveValidator`) in `kaiax/gov/param.go`:

```go
AddValidator: {
    Canonicalizer: validatorAddressListCanonicalizer,
    FormatChecker: func(cv any) bool {
        addrs, ok := cv.([]common.Address)
        if !ok {
            return false
        }
        for _, addr := range addrs {
            if common.EmptyAddress(addr) {
                return false
            }
        }
        return true
    },
    DefaultValue: []common.Address{},
},
```

Alternatively, add the same guard inside `checkConsistency` for `AddValidator`/`RemoveValidator` in `kaiax/gov/headergov/impl/header.go`, or inside `applyVote` in `kaiax/valset/impl/getter_council.go`.

---

### Proof of Concept

1. Deploy a chain with `istanbul.policy = 0` (RoundRobin) and 4 validators `[A, B, C, D]`.
2. Governing node `A` calls `governance_vote("governance.addvalidator", "0x0000000000000000000000000000000000000000")`.
3. `NewVoteData` succeeds: `noopFormatChecker` returns `true`.
4. `VerifyVote` → `checkConsistency` succeeds: zero address ≠ governing node `A`.
5. At the next epoch boundary, `applyVote` writes `0x000...000` into the council DB. Council is now `[0x000...000, A, B, C, D]` (sorted).
6. At block `N` where `N % 5 == 0`, zero address is the scheduled proposer. No block arrives. All validators time out and advance to round 1, where `A` proposes.
7. This repeats every 5 blocks, permanently degrading throughput by ~20 %. [1](#0-0) [3](#0-2) [6](#0-5)

func applyVote(header *types.Header, council *valset.AddressSet, governingNode common.Address) bool {
	voteKey, addresses, ok := parseValidatorVote(header)
	if !ok {
		return false
	}

	originalSize := council.Len()
	for _, address := range addresses {
		if address == governingNode {
			continue
		}
		switch voteKey {
		case gov.AddValidator:
			if !council.Contains(address) {
				council.Add(address)
			}
		case gov.RemoveValidator:
			if council.Contains(address) {
				council.Remove(address)
			}
		}
	}
	return originalSize != council.Len()
}
