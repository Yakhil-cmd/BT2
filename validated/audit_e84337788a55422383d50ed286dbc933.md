### Title
Session fixation in `GithubAuthenticationController#callback` lets an attacker mint the victim's persistent CCMenu `ApiClient` token via `CCMenuUrlController#fetch` - (File: app/controllers/shipit/github_authentication_controller.rb, app/controllers/shipit/ccmenu_url_controller.rb)

### Summary
`GithubAuthenticationController#callback` writes `session[:user_id]` into the existing session without calling `reset_session`, so an attacker who fixes a victim's session id can, after the victim logs in, reuse that same session id to act as the victim. Hitting `GET /:stack_id` on `CCMenuUrlController#fetch` while impersonating that session mints (or reuses) an `ApiClient` bound to the victim and returns its `authentication_token` in the JSON response, directly to the attacker.

### Finding Description
The broken binding: `client.authentication_token` returned by `CCMenuUrlController#fetch` should be equal to *a token requested by the GitHub identity acting through a session it legitimately controls*. Instead it equals *a token requested by whatever `User` row `session[:user_id]` happens to reference*, and that value is attacker-controllable because the session id itself is never rotated on login.

- `GithubAuthenticationController#callback` sets `session[:user_id] = sign_in_github(auth)` and `session[:authenticated] = true` but never calls `reset_session` or regenerates the session id: [1](#0-0) . Rails does not rotate the session id automatically on writes to the session hash, so a session id fixed by the attacker before login remains valid and now maps to the victim's `user_id` after `callback` runs. `logout` does call `reset_session`, but that's irrelevant to the login path: [2](#0-1) .
- `current_user` is derived purely from `session[:user_id]` with no additional binding to the browser/session origin: [3](#0-2) .
- `CCMenuUrlController#fetch` calls `client`, which does `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')` and embeds `client.authentication_token` directly into the JSON response body: [4](#0-3) .
- The existing test suite confirms the response literally contains the plaintext token: `assert_equal client.authentication_token, query['token']` [5](#0-4) .

Exploit flow:
1. Attacker obtains/fixes a session id (e.g., via a shared/predictable session cookie, or any mechanism that lets them force a victim to use a chosen `_session_id`).
2. Victim completes GitHub OAuth; `callback` sets `session[:user_id]` for that same fixed session id without rotating it.
3. Attacker, presenting the same session id, issues `GET /:stack_id` (routed to `CCMenuUrlController#fetch`) for any stack.
4. `current_user` resolves to the victim inside the attacker's request; a persistent `ApiClient` is created/found for the victim and its `authentication_token` is returned in the JSON body to the attacker.

`force_github_authentication` only checks `current_user.logged_in?` and team authorization — it does not, and cannot, distinguish a legitimately-authenticated session from a fixated one, so it does not block this. There is no `require_permission!`/per-stack ownership check gating `CCMenuUrlController#fetch` beyond generic login/team-authorization.

### Impact Explanation
The attacker obtains a real, persistent API token (`ApiClient#authentication_token`) scoped `read:stack`, bound to the victim's `User` record, without ever knowing the victim's credentials. This token can be replayed against the API (e.g., stack/task read endpoints) as the victim indefinitely, and is a durable credential leak surviving the fixed session — it is an authentication-bypass/credential-exfiltration primitive matching the Critical category ("exfiltration of ... a user's ... deploy-time secrets" / "authentication bypass ... session ... accepted"). Blast radius is scoped to whichever victim's session the attacker fixed and whichever stacks that victim can access; it is repeatable against any victim susceptible to the session-fixation precondition.

### Likelihood Explanation
This requires the pre-existing session-fixation flaw in `callback` (no `reset_session`) as a strict precondition — the attacker must be able to fix/known a session id used by the victim's browser and cause the victim to authenticate through it, and know a valid `stack_id` the victim can view. Given that precondition, the follow-up `GET /:stack_id` request is a single unauthenticated-cost HTTP call with no secrets required, making the token exfiltration step trivial and fully reliable once fixation succeeds.

### Recommendation
Call `reset_session` (or otherwise rotate the session id) inside `GithubAuthenticationController#callback` immediately before/when setting `session[:user_id]`, so any pre-existing (potentially attacker-fixed) session id is invalidated on login. Additionally, consider not returning raw `authentication_token` values in `CCMenuUrlController#fetch` to arbitrary repeat requesters, or scoping/rotating the CCMenu client token per authenticated session.

### Proof of Concept
```ruby
# test/controllers/ccmenu_url_session_fixation_test.rb
require 'test_helper'

module Shipit
  class CCMenuUrlSessionFixationTest < ActionDispatch::IntegrationTest
    test "attacker with fixed session id obtains victim's CCMenu API token" do
      stack = shipit_stacks(:shipit)
      victim = shipit_users(:walrus)

      # 1. Attacker "fixes" a session id by visiting the app first (gets cookie jar A)
      get shipit.root_path
      fixed_cookie = cookies['_session_id'] # simulate attacker capturing this and forcing victim to use it

      # 2. Victim authenticates using the SAME fixed session id (simulating callback without reset_session)
      # (simulate directly: since callback doesn't reset_session, session[:user_id] is set on the fixed session)
      post '/auth/github/callback' # with mocked omniauth.auth for `victim`, using cookie = fixed_cookie

      # 3. Attacker, still holding the same fixed session cookie, requests the CCMenu URL
      get "/#{stack.to_param}", headers: { 'Cookie' => fixed_cookie }
      assert_response :ok
      data = JSON.parse(response.body)
      token = Rack::Utils.parse_nested_query(URI(data['ccmenu_url']).query)['token']

      # Broken binding assertion: token belongs to victim's ApiClient, now known to attacker
      client = ApiClient.find_by(creator: victim, name: 'CCMenu Client')
      assert_equal client.authentication_token, token
    end
  end
end
```

    def callback
      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']

      return render('failed', layout: false) if auth.blank?

      session[:user_id] = sign_in_github(auth)

      # We need to set this so that the /events and /sidekiq endpoint
      # which leverage `UserRequiredMiddleware` will recognize the user
      # is authenticated.
      session[:authenticated] = true

      redirect_to(return_url)
    end
