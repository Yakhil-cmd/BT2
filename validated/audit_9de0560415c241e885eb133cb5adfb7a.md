### Title
Accrual overflow permanently freezes an oversized debt market - ([File: common/src/rates/simulate.rs])

### Summary
A large borrowed position can grow until `borrowed * borrow_index` no longer fits in `i128`. Because interest accrual runs before every market mutation, once that threshold is crossed the market cannot be repaid, withdrawn, liquidated, recapitalized, or synchronized again. [1](#0-0) [2](#0-1) 

### Finding Description
Each accrual first converts scaled debt to its current underlying value with `scaled_to_original(env, borrowed, borrow_index)`, which performs a checked RAY multiplication. [3](#0-2) [4](#0-3) 

Although `update_borrow_index` caps the index at `10^36`, the cap is applied only after debt-value conversion and supplier-reward calculations have already multiplied the scaled debt by the new index. [5](#0-4) [6](#0-5) 

`synced_market` runs `interest::global_sync` before market mutations, while the public `update_indexes` path loads each market and invokes the same accrual routine. [7](#0-6) [8](#0-7) 

The integration test demonstrates the reachable cliff: a one-billion-token, 18-decimal market at 98% utilization eventually causes `update_indexes`, `withdraw`, and `repay` to revert with `MathOverflow`, before the borrow-index cap engages. [9](#0-8) 

### Impact Explanation
This permanently freezes every position and pool operation that touches the affected `(hub, asset)` market because the failed accrual occurs before the operation-specific state change. [7](#0-6) 

Suppliers cannot withdraw collateral, borrowers cannot reduce debt, liquidators cannot liquidate accounts whose plans touch the market, and `recapitalize` cannot repair backing because it also loads an interest-synced market. [10](#0-9) [11](#0-10) [12](#0-11) 

The stored `last_timestamp` is only advanced after the accrual loop completes, so a failed call does not make partial progress; every later call retries the overflowing calculation. [13](#0-12) 

### Likelihood Explanation
An unprivileged caller can create the prerequisite state through normal `supply` and `borrow` calls and later trigger the overflow through permissionless controller `update_indexes(caller, assets)`; no privileged call is needed at trigger time. [14](#0-13) [15](#0-14) 

The likelihood is bounded by market scale, caps, token supply, collateral requirements, and sustained high utilization, so it is not universally available on every listing. [16](#0-15) 

Once a market approaches the RAY-value ceiling, any keeper or user can trigger the failure by submitting the market's `HubAssetKey` to `update_indexes`; afterward the freeze cannot be removed by ordinary protocol actions. [17](#0-16) [18](#0-17) 

### Recommendation
Make accrual saturation safe instead of reverting on debt-value overflow. In particular:

- Bound or saturate `scaled_to_original` where it is used only for utilization/reward calculations.
- Apply the borrow-index ceiling before calculating `new_total_debt`.
- When the calculated debt value would exceed `i128::MAX`, clamp the effective debt/index state to the protocol ceiling and continue with capped interest rather than returning `MathOverflow`.
- Add a regression test proving that `update_indexes`, `repay`, `withdraw`, liquidation, `clean_bad_debt`, and `recapitalize` remain callable after the oversized market reaches the ceiling.
- Add market-level accounting limits that ensure `supplied * supply_index` and `borrowed * borrow_index` remain representable for all admitted caps, decimals, and index growth.

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index

#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);

    assert_contract_error(failed, errors::MATH_OVERFLOW);

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);

        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();

/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
