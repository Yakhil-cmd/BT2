### Title
Deregistered Bridge Operator's Votes Persist and Can Still Execute Value Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`deregisterOperator` removes an operator from the `operators` mapping and `operatorList`, but does **not** clear that operator's already-cast votes from the `votes` storage mapping. A deregistered (compromised/rogue) operator's vote count remains in `votes[VoteType][nonce][voteKey]` and can still contribute to reaching the `operatorThresholds` required to execute a bridge value transfer (KLAY/ERC20/ERC721 mint or transfer).

### Finding Description

`BridgeOperator.deregisterOperator` performs:

```solidity
delete operators[_operator];
// removes from operatorList array
``` [1](#0-0) 

It does **not** touch the `votes` mapping:

```solidity
mapping(uint8 => mapping (uint64 => VotesData)) private votes;
``` [2](#0-1) 

`_voteCommon` accumulates vote counts keyed by `keccak256(msg.data)` per `(voteType, nonce)`. When operator A votes before deregistration, `votes[ValueTransfer][N][voteKey].voteCounts` is incremented to 1. After A is deregistered, that count is never decremented. When any subsequent operator B calls `handleERC20Transfer` with the **same** parameters (same nonce N, same `_to`, same `_value`), `_voteCommon` increments the same `voteKey`'s count to 2, reaching the threshold, and the transfer executes — counting A's stale vote. [3](#0-2) 

The contract itself documents this as a known limitation:

> "Note that outstanding votes by the deregistered operator are not revoked. … The Owner shall recognize this issue and expect that operator deregistration takes some time to be fully effective." [4](#0-3) 

The `handleERC20Transfer` (and `handleKLAYTransfer`, `handleERC721Transfer`) functions are gated by `onlyOperators`, which only checks `operators[msg.sender]` at call time — not whether any prior voter has since been deregistered. [5](#0-4) 

### Impact Explanation

A deregistered operator's vote persists and can be combined with a subsequent legitimate or compromised operator's vote to execute an unauthorized bridge value transfer: minting ERC20/ERC721 tokens or transferring KLAY/ERC20/ERC721 out of the bridge contract to an arbitrary `_to` address. This directly affects bridged assets.

The owner's act of deregistering a compromised operator provides a false sense of security — the compromised operator's influence over pending nonces is not neutralized.

### Likelihood Explanation

Requires: (1) a compromised operator A votes for a malicious transfer on nonce N; (2) the owner deregisters A; (3) a second operator B (also compromised, or tricked) votes for the same malicious parameters on nonce N. With threshold=2 and two operators, this is a realistic attack path. The contract's own comment acknowledges the scenario explicitly.

### Recommendation

In `deregisterOperator`, iterate over all open (non-closed) nonces and decrement the deregistered operator's vote count for any nonce where `vote.voted[_operator] != bytes32(0)`, then zero out `vote.voted[_operator]`. Alternatively, add a per-operator vote-invalidation epoch counter so that votes cast before the current epoch are ignored when computing thresholds.

### Proof of Concept

Setup: threshold = 2, operators = {Owner, A, B}.

1. Operator A (compromised) calls `handleERC20Transfer(txHash, from, attacker, token, 1000e18, nonce=5, blockNum, "")`. `votes[ValueTransfer][5][voteKey].voteCounts[voteKey]` = 1. Transfer not yet executed.
2. Owner calls `deregisterOperator(A)`. `operators[A]` = false. `votes[ValueTransfer][5]` is **untouched**.
3. Operator B (also compromised) calls `handleERC20Transfer` with identical parameters. `_voteCommon` increments `voteCounts[voteKey]` from 1 → 2 ≥ threshold. `closedValueTransferVotes[5]` = true. `handleERC20Transfer` mints/transfers 1000e18 tokens to `attacker`. [6](#0-5) [7](#0-6) [5](#0-4)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
```

    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
```
