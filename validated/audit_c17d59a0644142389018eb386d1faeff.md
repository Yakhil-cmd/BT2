Looking at the `consolidateNodes()` function and the CLStakingInfo assignment, I can see a clear analog to the Ajna bug. Let me verify the exact mechanics.

### Title
Silent CLStakingInfo Overwrite for Consolidated Validators Causes Wrong KAIA Staking Reward Distribution — (`kaiax/staking/staking_info.go`)

### Summary

`consolidateNodes()` in `kaiax/staking/staking_info.go` silently overwrites the `CLStakingInfo` of a consolidated validator when two NodeIds sharing the same `RewardAddr` are both registered in the CLRegistry. The second CL entry unconditionally replaces the first with `cmap[r].CLStakingInfo = clsi`. This causes the first CL pool to receive zero staking rewards every block, and corrupts the staking-weight denominator used to distribute KAIA rewards to all validators.

### Finding Description

The AddressBook explicitly supports multiple NodeIds mapping to the same `RewardAddr` — this is the "consolidated node" design. `consolidateNodes()` correctly sums their `StakingAmount` values, but when it attaches `CLStakingInfo` it does so with a bare assignment:

```go
// One CLStakingInfo per validator is guaranteed by CLRegistry.
cmap[r].CLStakingInfo = clsi   // line 157
```

The comment's guarantee is per-NodeId, not per-RewardAddr. If NodeId N1 and NodeId N3 both map to RewardAddr R1 in AddressBook, and both N1 and N3 are independently registered in CLRegistry (each with its own CL pool and staking amount), the loop processes N1 first, sets `cmap[R1].CLStakingInfo = clsi_N1`, then processes N3 and overwrites: `cmap[R1].CLStakingInfo = clsi_N3`. `clsi_N1` is permanently lost.

The test suite already encodes this exact scenario and acknowledges the silent drop:

```
// CL1 will be ignored when being consolidated since it has duplicate CL (not feasible in real)
```

The "not feasible in real" assumption is the only guard — there is no on-chain enforcement.

Downstream, `assignStakingRewards` / `assignStakingRewardsFlex` call `cn.Split(reward)`, which computes the CN/CL split using:

```go
cnAmountBig = big.NewInt(int64(c.StakingAmount))      // A1+A3 (correct)
clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))  // only CL3 amount (wrong)
totalAmount = cnAmountBig + clAmountBig               // missing CL1 amount
```

Three concrete errors result:
1. `clPool1` (N1's CL pool) receives `0` KAIA instead of `CL1_amount / (A1+A3+CL1+CL3) * reward`.
2. `clPool2` (N3's CL pool) receives `CL3/(A1+A3+CL3)` instead of `CL3/(A1+A3+CL1+CL3)` — inflated.
3. The `totalExcessInt` denominator used to allocate rewards across all validators is understated by `CL1_amount`, shifting every other validator's share.

### Impact Explanation

Every block after Prague HF in which the affected `StakingInfo` is active:
- `clPool1` receives **zero** KAIA staking rewards (unauthorized denial of reward distribution).
- `clPool2` receives **excess** KAIA staking rewards (unauthorized over-distribution).
- All other validators' staking reward shares are **distorted** because the global denominator `totalExcessInt` is wrong.

These are direct, per-block corruptions of KAIA reward distribution written to chain state via `state.AddBalance` in `FinalizeState`.

### Likelihood Explanation

**Permissioned path (legacy AddressBook + Prague CLRegistry):** A GC member who already has two NodeIds with the same RewardAddr (a governance-approved configuration) registers both NodeIds in CLRegistry. No additional governance vote is needed for the CLRegistry step. The AddressBook multi-NodeId pattern is explicitly documented and tested.

**Permissionless path (AddressBookV2 + CLRegistry):** Two validators who independently choose the same `RewardAddress` in AddressBookV2 and both register in CLRegistry trigger the bug without any governance involvement. `parsePermissionlessCallResult` performs no deduplication of `RewardAddrs`.

The developers themselves tested this scenario (labeled "not feasible in real") but provided no enforcement. The assumption is fragile.

### Recommendation

Replace the bare assignment with an accumulation that handles multiple CLStakingInfos per consolidated node:

```go
// Instead of a single *CLStakingInfo field, use a slice or accumulate amounts.
if existing := cmap[r].CLStakingInfo; existing != nil {
    // Accumulate: add CL staking amount to existing entry, or track all pools.
    existing.CLStakingAmount += clsi.CLStakingAmount
    // Also track clsi.CLPoolAddr separately for reward splitting.
} else {
    cmap[r].CLStakingInfo = clsi
}
```

A more complete fix changes `consolidatedNode.CLStakingInfo` from a single pointer to a slice `[]*CLStakingInfo`, updates `Split()` to distribute proportionally across all CL pools, and updates `assignStakingRewards`/`assignStakingRewardsFlex` to iterate over all CL pools when emitting `alloc` entries. Additionally, add an on-chain or off-chain check that rejects CLRegistry registrations for NodeIds whose RewardAddr already has a registered CL.

### Proof of Concept

**Setup (permissioned path):**
- AddressBook: `NodeIds=[N1,N3]`, `RewardAddrs=[R1,R1]`, `StakingAmounts=[6M,6M]` (both above minStake 5M)
- CLRegistry: `N1 → clPool1 (CL amount = 4M)`, `N3 → clPool2 (CL amount = 4M)`

**Expected reward split (1e18 kei staking budget, minStake=5M):**
- Total staking = (6M+6M CN) + (4M+4M CL) = 20M; excess = 20M - 5M = 15M
- clPool1 share = 4M/20M × reward; clPool2 share = 4M/20M × reward; R1 share = 12M/20M × reward

**Actual reward split after bug:**
- `consolidateNodes()` sets `cmap[R1].CLStakingInfo = clsi_N3` (clPool2, 4M), dropping clsi_N1
- `cnTotalStakingAmount` = 12M (CN) + 4M (only CL3) = 16M; excess = 16M - 5M = 11M
- `Split(reward)` ratio = 12M : 4M → clPool2 gets `4/16 × reward`, R1 gets `12/16 × reward`
- **clPool1 receives 0** (should receive ~`4/20 × reward` ≈ 0.2e18 kei per block)
- **clPool2 receives `4/16 × reward` ≈ 0.25e18 kei** (should receive `4/20 × reward` ≈ 0.2e18 kei)
- **All other validators' shares are distorted** because the global denominator used 11M excess instead of 15M

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
}

// assignStakingRewardsFlex assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewardsFlex(config *reward.RewardConfig, budget *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		minStake  = config.MinimumStake.Uint64()
		threshold = config.StakingRewardThreshold.Uint64()
		isPrague  = config.Rules.IsPrague

		cns            = si.ConsolidatedNodes()
		excessInt      = make(map[common.Address]uint64)
		totalExcessInt = uint64(0)
	)

	// Calculate the excess stakes (the amount over the threshold) for each CN.
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it. Even if (CNStaking + CLStaking) could be more than minStake,
		// the CNStaking alone must be at least minStake to be eligible.
		if cn.StakingAmount < minStake {
			continue
		}

		amount := cn.StakingAmount
		if isPrague && cn.CLStakingInfo != nil {
			amount += cn.CLStakingInfo.CLStakingAmount
		}

		// Excess is the amount over the threshold (not over minStake).
		if amount > threshold {
			excessInt[cn.RewardAddr] = amount - threshold
			totalExcessInt += excessInt[cn.RewardAddr]
		}
	}

	// Distribute the budget to the CNs based on the excess stakes.
	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(budget)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		if excessInt[cn.RewardAddr] <= 0 {
			continue
		}
		excess := new(big.Int).SetUint64(excessInt[cn.RewardAddr])

		// The KAIA unit will cancel out:
		// reward (kei) = excess (KAIA) * budget (kei) / totalExcess (KAIA)
		reward := new(big.Int).Div(new(big.Int).Mul(excess, budget), totalExcess)
		if reward.Sign() <= 0 {
			continue
		}

		// If Prague and CL is configured for this CN, split the reward between CN and CL.
		if isPrague && cn.CLStakingInfo != nil {
			cnAmount, clAmount := cn.Split(reward)
			alloc[cn.RewardAddr] = cnAmount
			alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
		} else {
			alloc[cn.RewardAddr] = reward
		}
		remaining.Sub(remaining, reward)
	}
	return alloc, remaining
}

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}
