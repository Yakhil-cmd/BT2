### Title
Webhook signature verification authenticates the payload's `repository.owner`/`organization` while handlers act on the unverified `repository.full_name` field, enabling cross-repository forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate an incoming webhook's HMAC against using `repository_owner`, a value taken straight from the untrusted JSON body (`repository.owner.login`, falling back to `organization.login`). Once that check passes, `Shipit::Webhooks::Handlers::Handler#repository_name` (used by `PushHandler` and other handlers) determines *which repository/stack to mutate* using a **different** body field, `repository.full_name`. Nothing ties these two fields together, so a signature that is valid for organization A's webhook secret can be replayed with `repository.full_name` pointing at organization B's repository.

### Finding Description
The signature check:
```ruby
# app/controllers/shipit/webhooks_controller.rb
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

selects a per-organization `webhook_secret` purely from attacker-controlled JSON (`repository.owner.login`), then HMACs the *raw request body* against it [2](#0-1) . It never checks that this organization actually owns the repository the handlers subsequently act on.

That subsequent repository resolution comes from a sibling, independent field:
```ruby
# app/models/shipit/webhooks/handlers/handler.rb
def repository_name
  payload.dig('repository', 'full_name')
end
``` [3](#0-2) 

`PushHandler#process` uses that name to find real stacks and enqueue a sync using Shipit's own GitHub credentials for that stack:
```ruby
def process
  stacks
    .not_archived
    .where(branch:)
    .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [4](#0-3) 

Since Shipit is explicitly multi-tenant (multiple GitHub organizations/apps configured side by side, each with its own `webhook_secret`, per `config/secrets.development.shopify.yml`) [5](#0-4) , the binding that should hold is:

`organization authenticated by X-Hub-Signature == owner(repository.full_name)`

but the code enforces only "some configured org's secret validates the raw body," and separately trusts `repository.full_name` unchecked. Any party that legitimately administers **one** organization's GitHub App in this Shipit instance (and therefore knows/controls that org's `webhook_secret`) can sign a payload with `repository.owner.login` set to their own org, while setting `repository.full_name` to an arbitrary victim repository tracked by the same Shipit instance. The same disconnect applies to the `status`/`check_suite` handlers, which likewise resolve the acted-upon repository from `repository.full_name` [6](#0-5) .

### Impact Explanation
An attacker who administers any single organization onboarded to the shared Shipit instance can forge webhook events (`push`, `status`, `check_suite`, `pull_request`) that are attributed to a victim organization's repository, without ever knowing the victim's `webhook_secret`. This is a cross-repository write: the attacker can inject fabricated commit-status ("success"/CI-passing) records or trigger `GithubSyncJob`/`sync_github` against a stack that belongs to a repository their credentials have no relationship to, using Shipit's own GitHub App credentials for that target stack. Fabricated CI-success statuses undermine `ci.require` deploy gating for a repository the attacker does not control, and forged `push` events can force premature/incorrect sync and, on stacks with continuous deployment enabled, contribute to an unintended deploy of a legitimate-but-attacker-chosen commit sha.

### Likelihood Explanation
Requires the attacker to be a legitimate administrator of at least one GitHub organization/app registered in the same Shipit deployment (a realistic scenario in any shared/multi-tenant Shipit installation, and trivial if any configured org has no `webhook_secret` set, in which case `verify_webhook_signature` returns `true` unconditionally regardless of signature) [7](#0-6) . No Shipit session, `ApiClient` token, or GitHub App private key for the *victim* org is needed — only a POST to the public `/webhooks` endpoint.

### Recommendation
Cross-validate `repository.owner.login`/`organization.login` (the field used to select the verifying secret) against the owner encoded in `repository.full_name` before dispatching to handlers, rejecting the webhook if they diverge. Alternatively, derive the verifying organization directly from the resolved `Repository`/`Stack` record (looked up via `full_name`) rather than from a second, independently-controlled body field.

### Proof of Concept
1. Attacker administers `attacker-org`, a GitHub organization configured in the shared Shipit instance with its own known `webhook_secret` (or one with no `webhook_secret` set at all).
2. Attacker computes `sha1=HMAC(attacker-org-secret, body)` (or omits the need entirely if no secret configured) over:
```json
{
  "ref": "refs/heads/master",
  "after": "<some real sha from victim repo history>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. POST to `/webhooks` with header `X-Github-Event: push` and the computed `X-Hub-Signature`.
4. `verify_signature` resolves `repository_owner` → `"attacker-org"`, verifies the signature against `attacker-org`'s secret, and passes. [8](#0-7) 
5. `PushHandler#process` resolves `repository_name` → `"victim-org/victim-repo"` and enqueues `stack.sync_github` for every matching stack under that repository, even though the signature never proved any relationship to `victim-org`. [4](#0-3)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
