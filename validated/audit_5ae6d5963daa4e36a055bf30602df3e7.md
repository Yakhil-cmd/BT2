### Title
Cross-repository signature bypass via `repository.owner.login` / `repository.full_name` divergence in webhook processing - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App configuration (and therefore which `webhook_secret`) to use for HMAC verification based on `repository_owner`, a value read from the untrusted, unauthenticated JSON body (`repository.owner.login`, falling back to `organization.login`). [1](#0-0) [2](#0-1)  The handler that actually performs the write, `PushHandler`/`Handler#stacks`, resolves the target `Repository`/`Stack` from a completely different field in the same untrusted body: `repository.full_name`. [3](#0-2)  These two fields are never required to match, and `verify_webhook_signature` returns `true` unconditionally whenever the selected organization's `webhook_secret` is blank/unset. [4](#0-3) 

### Finding Description
The engine supports multi-organization GitHub App configuration, keyed by organization login, each with its own optional `webhook_secret`. [5](#0-4)  The sample configuration explicitly documents organizations that can be configured with a `nil` `webhook_secret`. [6](#0-5) 

The trust binding that should hold is: *the organization whose secret authenticates the request* == *the repository/organization whose Stack is written to*. The code breaks this binding:

1. `verify_signature` picks the `github_app` used for HMAC verification using `repository_owner`, taken directly from the attacker-controlled body via `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. [2](#0-1) 
2. If that organization's `github_app.webhook_secret` is blank (a supported, documented configuration state), `verify_webhook_signature` short-circuits and returns `true` without checking the `X-Hub-Signature` header at all. [7](#0-6) 
3. Once past `verify_signature`, `WebhooksController#create` parses the same attacker-controlled body and dispatches it to registered handlers for the declared `X-Github-Event`. [8](#0-7) 
4. `PushHandler`/`Handler#stacks` resolves the `Repository` to act on using `payload.dig('repository', 'full_name')` — a separate field from `repository.owner.login` used in step 1. [3](#0-2)  `PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack on the target branch. [9](#0-8) 

Because nothing ties `repository.owner.login` to `repository.full_name`, an attacker can submit a single crafted JSON body where `repository.owner.login` names an organization configured with no `webhook_secret` (satisfying the free-pass in step 2) while `repository.full_name` names an entirely different, victim organization's repository (the one actually written to in step 4). This is the "organization that authenticated versus the repository that is written" binding failure called out in scope.

### Impact Explanation
This allows an unauthenticated, external attacker to forge push/status/pull_request/check_suite webhook events that get routed to and processed against a victim repository's `Stack`, without ever having a valid signature for that victim organization. For the `push` event this can force `Stack#sync_github` to run with an attacker-chosen `expected_head_sha`, effectively an unauthorized trigger on the victim's deploy pipeline (sync to arbitrary/attacker-controlled SHA), and other handlers (`status`, `check_suite`, `pull_request`) can similarly be triggered against a victim stack that the attacker has no legitimate authorization over. This is a cross-repository write / unauthorized-action impact.

### Likelihood Explanation
Likelihood depends entirely on operator configuration: the attack requires that at least one organization in the multi-tenant `github:` config has no `webhook_secret` set. This is an explicitly supported, documented configuration (shown as `webhook_secret: # nil` in the sample config), not a misuse of the engine, so it is squarely a defect in the engine's own trust-binding logic rather than a deployment error. Any Shipit instance serving more than one GitHub organization, where even one org is configured without a secret (e.g., during initial onboarding, matching the documented sample), is exploitable against every other configured organization's stacks.

### Recommendation
Bind signature verification to the same repository identity that handlers act on. Concretely:
- Verify the signature using the organization/repository derived consistently with `Handler#repository_name` (`repository.full_name`), not a separately-read `repository.owner.login`/`organization.login` field.
- Do not allow an organization with a missing `webhook_secret` to implicitly authenticate events for repositories belonging to a different, secured organization; either require a secret for all configured organizations or scope the "no secret" bypass strictly to that organization's own repositories, cross-checked against `repository.full_name`.
- Reject events where `repository.owner.login` does not match the owner portion of `repository.full_name`.

### Proof of Concept
1. Shipit is configured for two organizations: `unsecured-org` (no `webhook_secret` set) and `victim-org` (has a `webhook_secret` and an active `Stack` tracking `victim-org/victim-repo`).
2. Attacker POSTs to `/webhooks` with header `X-Github-Event: push` and no valid `X-Hub-Signature`, and body:
```json
{
  "ref": "refs/heads/master",
  "after": "attacker-chosen-sha",
  "repository": {
    "owner": { "login": "unsecured-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. `verify_signature` computes `repository_owner` = `"unsecured-org"`, loads that org's `github_app`, and since its `webhook_secret` is blank, `verify_webhook_signature` returns `true` regardless of the (missing/invalid) signature header. [1](#0-0) [7](#0-6) 
4. `create` dispatches the same body to `Handlers::PushHandler`, which resolves the target repository via `repository.full_name` = `"victim-org/victim-repo"` and calls `stack.sync_github(expected_head_sha: "attacker-chosen-sha")` on the victim's stack. [3](#0-2) [9](#0-8)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
