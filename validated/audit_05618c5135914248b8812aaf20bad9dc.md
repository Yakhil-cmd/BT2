### Title
Baseline-shift review-window bypass via Bash-only edits and non-linear commits (git amend) hides dangerous changes from Stop-hook diff - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
The Stop-hook review window is derived from `baseline_sha` (loaded via `load_baseline_sha`) and `head_at_capture`, refreshed every `UserPromptSubmit` by `capture_git_baseline`. The intersection logic in `compute_v2_review_set` only re-includes committed changes when the old HEAD is a linear ancestor of the new HEAD, and the baseline-preservation guard in `handle_user_prompt_submit` only fires when `touched_paths` is non-empty — but `touched_paths` is populated only for Edit/Write/MultiEdit tool calls, not Bash-driven file writes. This lets a dangerous change made via Bash (or via `git commit --amend`) be silently absorbed into a fresh baseline on the next turn, causing `compute_v2_review_set` to compute an empty or incomplete review set even though the dangerous content is present in the working tree/HEAD.

### Finding Description
`load_baseline_sha` simply returns `state["baseline_sha"]` [1](#0-0) , which is written by `handle_user_prompt_submit` on every user turn via `capture_git_baseline` [2](#0-1) . The Stop hook computes its review set with `compute_v2_review_set`, whose window logic is: `review_set = dirty_now ∩ changed_since(baseline_sha)`, where `dirty_now` includes committed changes only when `head_at_capture` is an ancestor of the current HEAD [3](#0-2) .

Two attacker-reachable git sequences shift the review window so a dangerous change is excluded:
1. **Bash-only edit**: `record_touched_path` is invoked only from the Edit/Write/MultiEdit PostToolUse path (not from Bash tool calls). If Claude (driven by prompt-injected repo content) writes the dangerous change via `Bash` (`cat >`, `sed -i`, etc.) instead of `Edit`/`Write`, `touched_paths` stays empty for that file. The docstring of `compute_v2_review_set` explicitly documents this as a "known limitation": *"a Bash-only turn that's interrupted before Stop fires leaves touched_paths empty, so the next UPS re-baselines past those edits"* [4](#0-3) . Because `touched_paths` is empty, the UPS preservation guard `if state.get("touched_paths") and state.get("baseline_sha")` never activates [5](#0-4) , so the next UPS overwrites `baseline_sha` with a fresh `git stash create` snapshot that already contains the dangerous, unreviewed edit — permanently placing it outside the diff window.
2. **`git commit --amend`**: amending replaces HEAD with a new, non-descendant commit object, so `_is_ancestor(repo, head_at_capture, current_head)` returns `False`, and the committed-range term (`_git_name_only(repo, f"{head_at_capture}..HEAD")`) is never unioned into `dirty_now` [6](#0-5) . With a clean working tree after the amend, `tracked_dirty` and `new_untracked` are both empty, so `dirty_now` is empty and `review_set` is empty regardless of `changed_since`, silently dropping the amended dangerous change from Stop-hook review.

In both cases, `load_baseline_sha`/`capture_git_baseline` produce a baseline state that reflects a git history/worktree the attacker fully controls through ordinary git commands run in the cloned repo (Bash tool or `git commit --amend`), and the invariant that "an attacker must not hide a dangerous change by shifting it outside the computed review window" is violated.

### Impact Explanation
A dangerous, security-relevant local command or file change (e.g., a backdoored script, a malicious build step, or an unreviewed command-execution primitive) introduced through the agent's own Bash tool or an amended commit is never surfaced to the Stop-hook's LLM security review. Since this review is the mechanism gating Claude Code's approval/deny feedback loop for code changes, bypassing it results in unauthorized local command execution content passing through unreviewed — matching the target's "Unauthorized local command execution that bypasses Claude Code approval or deny controls" impact class.

### Likelihood Explanation
The preconditions are entirely within the normal operating envelope of the plugin: an attacker who can influence the agent's actions in a cloned repo (e.g., via prompt injection in repository content, issue text, or automation instructions) only needs to get the agent to (a) write/modify a file via `Bash` instead of `Edit`/`Write`, or (b) run `git commit --amend`. Both are extremely common, unremarkable operations that require no special privilege beyond normal repo interaction, and the docstring in the code itself acknowledges the Bash-only gap as a known limitation, indicating the condition is easily and repeatably triggered.

### Recommendation
- Record touched paths (or otherwise mark the session as having unreviewed changes) for Bash-tool file mutations as well, not only Edit/Write/MultiEdit, e.g. by diffing the worktree against the last baseline before allowing UPS to advance `baseline_sha`.
- In `compute_v2_review_set`, when `_is_ancestor` fails (non-linear HEAD move, e.g. amend/rebase), fall back to including the diff between `head_at_capture` and current HEAD via symmetric or content comparison rather than dropping the committed-range term entirely.
- Treat `capture_git_baseline`/UPS baseline advancement as fenced by "no unreviewed dirty content exists," rather than solely gating on `touched_paths` being non-empty.

### Proof of Concept
Integration test plan for `plugins/security-guidance/hooks/diffstate.py::compute_v2_review_set` and `handle_user_prompt_submit`:
1. **Bash-only bypass**: In a temp git repo with one commit, call `capture_git_baseline(cwd)` to get `baseline_sha1`. Write a dangerous file via a raw `open()`/shell write (simulating Bash tool, not Edit/Write) — do NOT call `record_touched_path`. Simulate a second UPS: call `capture_git_baseline(cwd)` again to get `baseline_sha2` and save it as the new `baseline_sha` (since `touched_paths` is empty, the preservation guard does not fire). Call `compute_v2_review_set(cwd, baseline_sha2, head_at_capture2)`. Assert the dangerous file is **absent** from the returned review set even though it was never reviewed — demonstrating the bypass.
2. **Amend bypass**: Commit a dangerous file, capture `head_at_capture = HEAD`. Run `git commit --amend --no-edit` (no content change, or trivial unrelated change) so HEAD is a new SHA that is not a descendant of `head_at_capture`. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture)` with a clean working tree. Assert `dirty_now_count == 0` and the dangerous file is excluded from `review_set`, confirming the invariant "review set must still contain the dangerous file" is violated.
