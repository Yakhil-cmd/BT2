The reported bug class—miscalculating LP rewards by applying an *average* rate across multiple epochs of unequal length instead of weighting each epoch individually—does not map onto any reachable code path in this codebase. Raydium CP Swap has no epoch-based reward-accrual module analogous to `RewardsMath.sol`; LPs earn no time-weighted "rewards" stream, only constant-product fee splits realized at swap/deposit/withdraw time [1](#0-0) .

The only time-weighted accumulator in the program is the price oracle in `ObservationState::update`, which is a standard TWAP-style cumulative-price accumulator (each call multiplies the *current* price by the elapsed time since the last update and adds it to a running cumulative sum), not an averaged-rate-across-epochs calculation [2](#0-1) . This accumulator correctly weights each interval by its own elapsed time (`time_since_last_update`) rather than assuming uniform epoch lengths, so it does not reproduce the root cause described in the external report (using an average rate applied to the *total* elapsed time across variable-length epochs). It also has no bearing on user/LP fund custody, minting, or fee-ledger solvency—it only feeds price observations.

No other in-scope surface (deposit, withdraw, swap_base_input/output, collect_creator_fee(_permissionless), the constant-product curve/fee split, or token CPIs in utils/token.rs) performs any epoch-averaged reward distribution that could inherit this bug class.
