### Title
Pre-publish gate (`--pre-publish-exechook-command`) does not block symlink publication, allowing the publish check to be bypassed - (File: main.go, pkg/hook/hook.go)

### Summary
`git-sync`'s `--pre-publish-exechook-command` is documented and designed as a gate that must run "before publishing the symlink" [1](#0-0) . In `SyncRepo`, the intended flow is: run the pre-publish check, then only if it passes, publish the symlink [2](#0-1) . However, the check is invoked asynchronously and its result is never awaited or checked, so the symlink swap proceeds unconditionally, exactly mirroring the `NumaPrinter.mintNuAsset()` bug class where a guarding check does not actually gate the guarded action.

### Finding Description
The `beforePublish` hook closure only enqueues work onto a background goroutine and immediately returns `nil`, regardless of whether the exechook has run or succeeded: [3](#0-2) 

`HookRunner.Send` performs a non-blocking channel write and returns instantly: [4](#0-3) [5](#0-4) 

The actual exechook execution and retry-on-failure logic happens later, in a separate goroutine (`HookRunner.Run`), completely decoupled from the caller that invoked `Send`: [6](#0-5) 

Back in `SyncRepo`, because `syncHooks.beforePublish(...)` always returns `nil` immediately, execution falls through unconditionally to `git.publishSymlink(newWorktree)`: [7](#0-6) 

This is structurally identical to the reported bug class: a validation/guard (`notInWarningCF` / here, the pre-publish exechook) is supposed to prevent an action (minting / here, publishing the symlink) from completing when a condition is not satisfied, but the guard's result is not actually consulted before the action executes. In the audited contract, the check ran too early relative to state changes; in `git-sync`, the check runs "too late" relative to the return path — its outcome is discarded before the gated action (`publishSymlink`) executes.

The only place the pre-publish hook's result is actually awaited is `WaitForCompletion`, which is exclusively used in `--one-time` mode after the symlink has already been published, purely to determine the process exit code — it does not block or reverse `publishSymlink`: [8](#0-7) 

### Impact Explanation
Users configure `--pre-publish-exechook-command` explicitly to run validation, sanitization, security scanning, or approval logic against the newly-fetched worktree before it becomes visible to consumers via the published symlink (per the documented contract: "executed after syncing a new hash ... but before publishing the symlink"). Because the check does not gate publication:
- A failing (non-zero exit) pre-publish check does not prevent an unvetted/unapproved commit from becoming visible at `--link`.
- This is a persistent, silent violation of the documented safety contract, potentially resulting in publishing wrong or unvalidated content to consumers, which downstream application containers in Kubernetes sidecar deployments will read and treat as trusted/verified.
- Because failure only affects `--one-time` exit code (not streaming/daemon mode, which is the primary use case), the vast majority of `git-sync` deployments (non `--one-time`, i.e., continuous sidecars) get zero enforcement of the configured pre-publish gate.

### Likelihood Explanation
This triggers on every normal sync cycle whenever `--pre-publish-exechook-command` is configured and running in the default (non `--one-time`) mode, which is the common Kubernetes sidecar deployment pattern . No attacker interaction is required beyond pushing a new commit/ref that would normally fail the configured pre-publish check (e.g., a malicious or unreviewed commit reachable via the synced `--repo`). This is a deterministic logic bug, not a race condition, so likelihood is high whenever the feature is used outside `--one-time`.

### Recommendation
In `SyncRepo`, `beforePublish` must block until the pre-publish exechook actually completes and must propagate a failure so that `publishSymlink` is not called:
- Change `prePubExechookRunner.Send(hash)` to a synchronous call (or add a dedicated blocking `RunOnce`/`WaitForCompletion`-style API used unconditionally, not just under `--one-time`) so `beforePublish` returns an error on hook failure.
- Ensure `SyncRepo` treats a non-nil error from `beforePublish` as a reason to skip `git.publishSymlink` and retry the exechook (respecting `--pre-publish-exechook-backoff`) before ever swapping the symlink.

### Proof of Concept
1. Start `git-sync` in normal (non `--one-time`) mode with `--pre-publish-exechook-command` pointing to a script that always exits non-zero (e.g., the `EXECHOOK_COMMAND_FAIL` test fixture referenced in `test_e2e.sh`) [9](#0-8) .
2. Push a new commit to the synced `--repo`.
3. Observe that `--link` is updated to point at the new worktree/hash on the very first sync attempt, even though the pre-publish exechook is failing and retrying in the background — i.e., the guard fails but the guarded action (publish) still happens. The existing e2e test `e2e::pre_publish_exechook_fail_retry` only asserts that the hook *retries* (`assert_file_lines_ge "$RUNLOG" 2`); it never asserts that `$ROOT/link` was *not* updated while the hook was failing, which would be the correct behavior if the gate worked as documented.

```go
func (r *HookRunner) Run(ctx context.Context) {
	var lastHash string

	// Wait for trigger from hookData.Send
	for range r.data.events() {
		// Retry in case of error
		for {
			// Always get the latest value, in case we fail-and-retry and the
			// value changed in the meantime.  This means that we might not send
			// every single hash.
			hash := r.data.get()
			if hash == lastHash {
				break
			}

			if err := r.hook.Do(ctx, hash); err != nil {
				r.log.Error(err, "hook failed", "hash", hash, "retry", r.backoff)
				updateHookRunCountMetric(r.hook.Name(), "error")
				// don't want to sleep unnecessarily terminating anyways
				r.sendOneTimeResultAndTerminate(false)
				time.Sleep(r.backoff)
			} else {
				updateHookRunCountMetric(r.hook.Name(), "success")
				lastHash = hash
				r.sendOneTimeResultAndTerminate(true)
				break
			}
		}
	}
}
```

```shellscript
function e2e::pre_publish_exechook_fail_retry() {
    cat /dev/null > "$RUNLOG"

    # First sync - return a failure to ensure that we try again
    GIT_SYNC \
        --period=100ms \
        --repo="file://$REPO" \
        --root="$ROOT" \
        --link="link" \
        --pre-publish-exechook-command="/$EXECHOOK_COMMAND_FAIL" \
        --pre-publish-exechook-backoff=1s \
        &
    sleep 3 # give it time to retry

    # Check that exechook was called
    assert_file_lines_ge "$RUNLOG" 2
}
```
