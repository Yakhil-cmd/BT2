### Title
Deregistered Bridge Operator's Vote Persists and Can Satisfy Threshold — (`contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`BridgeOperator.deregisterOperator()` removes an operator from the `operators` mapping and `operatorList`, but does **not** revoke or delete any votes that operator has already cast in `votes[voteType][nonce]`. A subsequently-cast vote by any remaining valid operator can then combine with the stale deregistered-operator vote to meet the threshold, causing `handleKLAYTransfer`, `handleERC20Transfer`, or `handleERC721Transfer` to execute and release bridged assets — even though the deregistered operator's authorization was revoked before the threshold was reached.

### Finding Description

`BridgeOperator` stores per-nonce vote state in:

```solidity
mapping(uint8 => mapping(uint64 => VotesData)) private votes;
```

where `VotesData.voteCounts[voteKey]` accumulates one count per operator call. [1](#0-0) 

When `_voteCommon` is called it increments `voteCounts[voteKey]` and immediately checks whether the count meets `operatorThresholds[voteType]`:

```solidity
vote.voteCounts[_voteKey]++;
if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
    return true;
}
``` [2](#0-1) 

`deregisterOperator` only clears `operators[_operator]` and removes the address from `operatorList`. It explicitly does **not** touch the `votes` mapping:

```solidity
// Note that outstanding votes by the deregistered operator are not revoked.
``` [3](#0-2) 

Because `_voteValueTransfer` calls `_voteCommon` which checks `operators[msg.sender]` only via the `onlyOperators` modifier on the outer `handleKLAYTransfer` function — not inside `_voteCommon` itself — the stale vote count from the deregistered operator remains in storage and is counted toward the threshold when any still-valid operator votes next. [4](#0-3) 

The asset-release path in `handleKLAYTransfer` executes unconditionally once `_voteValueTransfer` returns `true`:

```solidity
if (!_voteValueTransfer(_requestedNonce)) { return; }
...
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
``` [5](#0-4) 

The same pattern applies to `handleERC20Transfer` (mint or `safeTransfer`) and `handleERC721Transfer`. [6](#0-5) 

### Impact Explanation

A deregistered operator's vote persists in `votes[ValueTransfer][nonce].voteCounts[voteKey]`. When any remaining valid operator submits the same `handleKLAYTransfer` / `handleERC20Transfer` / `handleERC721Transfer` call for that nonce, the accumulated count (stale + new) can meet `operatorThresholds[ValueTransfer]`, causing the bridge to release KAIA or bridged ERC-20/ERC-721 tokens to an arbitrary `_to` address without the intended quorum of currently-authorized operators. This is an **unauthorized asset transfer** of bridged funds.

### Likelihood Explanation

The code comment at line 148 explicitly acknowledges this behavior as a known design choice, calling it a "subtle counterintuitive scenario." The owner is expected to "recognize this issue." However, from a security standpoint, any window between an operator's deregistration and the expiry of their outstanding votes is exploitable by any remaining operator who can call `handleKLAYTransfer` with the same parameters. The trigger requires only one valid operator call after deregistration — no privileged access beyond being a registered operator is needed. The owner's `deregisterOperator` call is the semi-trusted trigger that opens the window.

### Recommendation

In `deregisterOperator`, iterate over all open (non-closed) nonces for which the deregistered operator has cast a vote and decrement `voteCounts` for that operator's `voteKey`, effectively revoking the stale vote:

```solidity
function deregisterOperator(address _operator) external onlyOwner {
    require(operators[_operator]);
    // Revoke outstanding ValueTransfer votes by this operator
    // (iterate known open nonces or require operators to explicitly cancel)
    delete operators[_operator];
    ...
}
```

Alternatively, record the block number at which each operator was deregistered and reject votes cast before that block number when checking the threshold.

### Proof of Concept

Setup: threshold = 2, operators = {A, B, C}.

1. Operator A calls `handleKLAYTransfer(txHash, from, to, 100, nonce=5, ...)`. `voteCounts[voteKey]` becomes 1. Transfer not yet executed.
2. Owner calls `deregisterOperator(A)`. `operators[A]` is deleted. `voteCounts[voteKey]` for nonce 5 remains 1.
3. Operator B calls `handleKLAYTransfer(txHash, from, to, 100, nonce=5, ...)`. `onlyOperators` passes (B is still registered). `_voteCommon` increments `voteCounts[voteKey]` to 2. `2 >= threshold(2)` → returns `true`. `closedValueTransferVotes[5]` set to `true`. Bridge sends 100 KAIA to `to`.

The transfer executed with one vote from a deregistered operator and one from a current operator — the intended 2-of-3 quorum of *current* operators was never satisfied. [7](#0-6) [3](#0-2) [8](#0-7)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    // deregisterOperator deregisters the operator.
    //
    // Note that outstanding votes by the deregistered operator are not revoked.
    // This enables a subtle counterintuitive scenario.
    //
    // Suppose there are two operators A, B and C with threshold 2.
    // 1. Operator A votes on nonce N
    // 2. Owner deregisters A
    // 3. Operator B votes on nonce N, thereby executing the request N.
    // In this case the request was executed with A's vote after A is deregistered.
    //
    // The Owner shall recognize this issue and expect that operator deregistration
    // takes some time to be fully effective.
    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
