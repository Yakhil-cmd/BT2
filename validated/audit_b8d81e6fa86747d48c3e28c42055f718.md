### Title
`ProxyType::NonTransfer` fails open on Asset Hub Rococo: swaps, XCM transfers and contract calls with value are reachable despite the "no funds transfer" guarantee - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
Asset Hub Rococo's `ProxyType::NonTransfer` filter is implemented as a deny-list that only blocks `Balances`, `Assets`, `NftFractionalization`, `Nfts` and `Uniques`. It does not deny `AssetConversion`, `PolkadotXcm`, `Revive`, `ForeignAssets`, or `PoolAssets` calls, all of which are wired into the same runtime. A delegate holding only a `NonTransfer` proxy can therefore move the delegator's funds/assets through these unlisted pallets, even though the type is documented (and relied upon by users) as "can execute any call that does not transfer funds or assets."

### Finding Description
`pallet_proxy` gates every proxied call through `InstanceFilter::filter` before dispatch. On Asset Hub Rococo the filter for `NonTransfer` is: [1](#0-0) 

This is a deny-list, so any pallet call not explicitly named is implicitly allowed ("fails open"). The filter omits several call families that are known to move a delegator's assets:
- `AssetConversion` (swaps/liquidity operations move the caller's assets)
- `PolkadotXcm` (`transfer_assets`/`teleport_assets` move assets off-chain; `send`/`execute` can express arbitrary XCM including asset moves)
- `Revive` (contract calls/instantiations that carry a `value`)
- `ForeignAssets`/`PoolAssets` (other `pallet-assets` instances that transfer value exactly like `Assets`)

This is the exact same class of bug as the external report: a whitelist/denylist check blocks the "obvious" dangerous target (`Balances`/`Assets`/NFTs, analogous to blocking `_DODO_APPROVE_PROXY_`) but fails to block an equally privileged alternate path that reaches the same asset-moving effect (`AssetConversion`/`PolkadotXcm`/`Revive`, analogous to `DODOApprove.sol`'s `claimTokens`). The attacker input is fully user-controlled: any account that has been granted a `NonTransfer` proxy by another signed account (a completely ordinary, non-privileged relationship — the delegator opts in via `Proxy::add_proxy`) can submit `Proxy::proxy(real, None, call)` with `call` set to one of the unlisted pallets, and `pallet_proxy::do_proxy` will dispatch it as the `real` account, moving `real`'s funds.

This exact bug class was already identified and fixed for two sibling runtimes in this same repository: [2](#0-1) [3](#0-2) 

And the patched, corrected version (on Asset Hub Westend) explicitly documents the fail-open risk and lists the pallets that must be denied: [4](#0-3) 

Asset Hub Rococo, however, still ships the pre-fix deny-list and was never patched — confirmed by grepping the file for the pallets that Westend's fix denies (`AssetConversion`, `PolkadotXcm`, `Revive`, `ForeignAssets`, `PoolAssets`), none of which appear anywhere in `asset-hub-rococo/src/lib.rs`'s `InstanceFilter` implementation.

### Impact Explanation
Any account that is granted a `NonTransfer` proxy (a normal, low-trust delegation intended to prevent the delegate from moving the delegator's funds) can instead:
- Call `AssetConversion::swap_exact_tokens_for_tokens` / `add_liquidity` / `remove_liquidity` on behalf of the delegator, moving the delegator's pooled assets to an attacker-chosen recipient via unfavorable swaps or liquidity withdrawal.
- Call `PolkadotXcm::transfer_assets`/`teleport_assets`/`send`/`execute`, moving the delegator's assets off-chain to an attacker-controlled account on another chain.
- Call `Revive` contract calls with a nonzero `value`, transferring the delegator's balance into an attacker-deployed contract.
- Transfer `ForeignAssets`/`PoolAssets` balances directly.

This breaks the documented security guarantee of the `NonTransfer` proxy type and allows theft/misappropriation of the delegator's funds by a party that was only meant to perform non-transfer operations on their behalf. This matches a High-severity theft-of-funds pattern, analogous to the original DODO finding (a check meant to prevent asset drain misses an equally capable alternate path).

### Likelihood Explanation
Likelihood is contingent entirely on a delegator granting a `NonTransfer` proxy — a normal, expected, unprivileged action supported by the runtime's documented proxy model (`Proxy::add_proxy(delegate, ProxyType::NonTransfer, delay)`), not a privileged prerequisite or attacker-controlled configuration. Given that many users grant `NonTransfer` proxies specifically believing their funds cannot be moved, and that `AssetConversion`/`PolkadotXcm`/`Revive` are present and callable in the exact same runtime, exploitation requires only the delegate submitting a single `Proxy::proxy` extrinsic wrapping one of the unlisted calls. This is a straightforward, deterministic, and repeatable dispatch — not a race condition, front-running or unbounded-resource issue.

### Recommendation
Apply the same fix already merged for Asset Hub Westend (pr_12771) and staking-async parachain (pr_12922) to Asset Hub Rococo: extend the `NonTransfer` deny-list in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs` to explicitly deny `RuntimeCall::ForeignAssets`, `RuntimeCall::PoolAssets`, `RuntimeCall::AssetConversion`, `RuntimeCall::PolkadotXcm`, `RuntimeCall::Revive`, and value-moving `Vesting`/`Indices` calls, matching the Westend implementation exactly. More robustly, consider converting `NonTransfer` from a deny-list to an allow-list (or adding a regression test, as Westend now has) so that newly added pallets do not silently become reachable by a `NonTransfer` proxy.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
