### Title
`flash_position` mints the same leveraged debt as `multiply` but skips the strategy origination fee, letting any user bypass protocol revenue - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
`multiply` and `flash_position` are two permissionless, caller-authorized entrypoints that open the same leveraged position: both mint strategy debt on a `Multiply`/`Long`/`Short` account, convert it into collateral, and finalize with identical solvency gates. `multiply` routes the debt mint through `pool.create_strategy` with `charge_fee = true`, so the pool withholds `flashloan_fee` bps and books it as protocol revenue. `flash_position` mints the identical debt with `charge_fee = false`. Any unprivileged address that deploys a Wasm receiver implementing `execute_flash_position` can therefore take the same leveraged position and pay zero protocol fee, exactly the fee-control bug class: the fee the protocol intends to collect on leveraged opens is optional at the caller's choice.

### Finding Description
- `multiply` calls `borrow_into_controller(env, &mut account, debt, debt_to_flash_loan, true, PositionAction::Multiply, &mut cache)` — the `true` is `charge_fee` — which reaches `pool_create_strategy_call(..., charge_fee)` and `LiquidityPoolClient::create_strategy(receiver, &action, &charge_fee)` [1](#0-0) [2](#0-1) 
- In the pool, `compute_fee` returns `0` whenever `charge_fee` is false; otherwise it charges `flashloan_fee` bps and books it via `interest::add_protocol_revenue` [3](#0-2) 
- `flash_position` is permissionless (`require_authorized_caller` + account-owner check only), requires merely a Wasm `receiver` and `is_flashloanable` on the debt market, and is explicitly documented as minting debt "with no flash fee" [4](#0-3) [5](#0-4) 
- The dedicated parity test proves the substitution: "flash_position opens the same leveraged position as multiply without the strategy origination fee", asserting `multiply` books the expected fee while `flash_position` books `fp_revenue == 0` and ends with *more* collateral for the same debt [6](#0-5) 

### Impact Explanation
Every leveraged open routed through `flash_position` deprives the protocol of the `flashloan_fee`-bps origination fee it collects on `multiply`. Fee revenue that would accrue as supply-index-bearing protocol revenue is never minted, so this is a direct loss of unclaimed protocol yield proportional to strategy volume — unbounded and repeatable on every open/extend.

### Likelihood Explanation
High for any user with a deployed receiver contract: `flash_position` needs no listing, no approval, and no privileged role — only a Wasm contract implementing `execute_flash_position` that swaps and pushes collateral to the controller (a documented integration pattern in `skills/xoxno-lending-contracts/flash-loans.md`). Rational users always prefer the fee-free route, so `multiply`'s fee is effectively voluntary. The only mitigation is off-chain (UI steering), mirroring the external report's "enforce through the frontend" weakness.

### Recommendation
Charge the same origination fee in `flash_position` (call `create_strategy` with `charge_fee = true` for debt mints that open leveraged exposure), or — if the fee-free contract path is an intentional design decision — remove the fee from `multiply` as well so revenue does not depend on which door the user walks through. A middle option is a governance-set strategy fee applied uniformly in `strategy_finalize` regardless of entrypoint.

### Proof of Concept
1. Governance lists USDC/ETH markets with `flashloan_fee = 9` bps and `is_flashloanable = true` on the debt market.
2. Attacker deploys a receiver implementing `execute_flash_position` that swaps the received debt tokens and transfers the bought collateral to the controller.
3. Attacker calls `controller.flash_position(caller, 0, spoke_id, PositionMode::Multiply, debt=ETH, amount, receiver, data, collaterals=[(USDC, min)], refund_assets=[ETH])`.
4. Result: a new solvent Multiply account holding USDC collateral and ETH debt identical to what `multiply` would produce — but `get_revenue(ETH)` is unchanged and the attacker keeps the `amount * 9 / 10_000` that `multiply` would have withheld. Confirmed by `strategy_origination_fee_parity.rs`, where `fp_revenue == 0` while `mul_revenue == expected_fee` for the same debt.

Note: the README documents the fee-free mint deliberately ("with no flash fee"), so the sponsor may classify this as an intended integrator path rather than a bug — the same "documented choice" caveat the external report's judge raised about likelihood.

/// Computes the strategy fee from `flashloan_fee` bps when `charge_fee` is true;
/// returns 0 otherwise (does not consult the market flash-loan enable flag).
///
/// Panics if the fee would exceed principal when charging.
fn compute_fee(env: &Env, cache: &Cache, amount: i128, charge_fee: bool) -> i128 {
    if !charge_fee {
        return 0;
    }
    let fee = Bps::from(i128::from(cache.params().flashloan_fee)).flash_loan_fee_on(env, amount);
    assert_with_error!(env, fee <= amount, FlashLoanError::StrategyFeeExceeds);
    fee
}

#[test]
fn flash_position_substitutes_multiply_without_origination_fee() {
    let (mul_collateral, mul_debt, mul_revenue) = open_via_multiply();
    let (fp_collateral, fp_debt, fp_revenue) = open_via_flash_position();

    std::println!("multiply       : collateral={mul_collateral:.4} USDC  debt={mul_debt:.6} ETH  revenue={mul_revenue}");
    std::println!("flash_position : collateral={fp_collateral:.4} USDC  debt={fp_debt:.6} ETH  revenue={fp_revenue}");

    // Same debt taken on both routes.
    assert!(
        (mul_debt - fp_debt).abs() < 0.01,
        "routes should take comparable debt: multiply={mul_debt} flash_position={fp_debt}"
    );

    // `multiply` books exactly the fee on 1.0 ETH of strategy debt at
    // `DEFAULT_FLASHLOAN_FEE_BPS`; `flash_position` books nothing.
    let strategy_debt_raw = 10_000_000i128;
    let expected_fee = strategy_debt_raw - apply_flash_fee(strategy_debt_raw);
    assert_eq!(
        mul_revenue, expected_fee,
        "multiply must book exactly the origination fee on {strategy_debt_raw} \
         raw ETH of debt: expected {expected_fee}, got {mul_revenue}"
    );
    assert_eq!(
        fp_revenue, 0,
        "flash_position books no protocol revenue, got {fp_revenue}"
    );

    // The fee-free route ends with more collateral for the same debt.
    assert!(
        fp_collateral > mul_collateral,
        "flash_position should yield more collateral for the same debt: \
         multiply={mul_collateral} flash_position={fp_collateral}"
    );
}
