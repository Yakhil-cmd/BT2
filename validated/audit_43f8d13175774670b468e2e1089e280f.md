### Title
Webhook signature verification key is selected from an unverified payload field decoupled from the repository field handlers actually act on, enabling cross-tenant/cross-repository webhook forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks the `GitHubApp` (and therefore the `webhook_secret` used to validate `X-Hub-Signature`) using `repository_owner`, a value read straight out of the still-unverified JSON body. Every webhook `Handler`, however, resolves the repository/stack to act on using a different field of the same body: `payload.dig('repository', 'full_name')`. Because the field used to choose *which secret verifies the request* is not the same field used to choose *which repository the request acts on*, and both are attacker-supplied before verification, an attacker who can produce a valid signature for **any** org configured on a multi-tenant Shipit instance can make the payload's action target a **different** org/repository's stack.

### Finding Description
`verify_signature` does: [1](#0-0) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
```

`repository_owner` is derived from the request body itself, before signature verification happens: [2](#0-1) 

`Shipit.github(organization:)` uses this attacker-chosen value to select which per-organization config (and thus which `webhook_secret`) validates the signature in multi-org deployments: [3](#0-2) 

If that organization's `webhook_secret` is blank (an explicitly documented, optional setting), verification is bypassed entirely: [4](#0-3) 

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
```

Meanwhile, every `Handler` that actually performs an action resolves the target repository/stack from a **different** field of the same payload: [5](#0-4) 

e.g. `PushHandler#process` calls `stack.sync_github(...)` for whichever stacks match `repository.full_name`: [6](#0-5) 

So the field the signature-selection logic trusts (`repository.owner.login` / `organization.login`) and the field the business logic trusts (`repository.full_name`) are never checked for consistency with each other. The setup docs explicitly say the per-org `webhook_secret` is optional: [7](#0-6) 

### Impact Explanation
In a multi-organization Shipit deployment (the schema documented for "configuring multiple Github applications for different Github organizations" in `config/secrets.development.example.yml`), if any one configured organization has no `webhook_secret` set (a supported/documented configuration), `verify_webhook_signature` unconditionally returns `true` for any payload whose `repository.owner.login`/`organization.login` names that org — regardless of the `repository.full_name` inside the same payload. An attacker can therefore submit an unsigned POST to `/webhooks` naming the unsecured org as owner while setting `repository.full_name` to a real repository belonging to a *different*, protected organization on the same instance. The relevant handler (e.g. `PushHandler`) will then act on the victim repository's `Stack` (triggering `GithubSyncJob`, commit/status ingestion, PR/label-driven review-stack archiving, etc.) with no authentication at all. This is a cross-repository/cross-tenant write, breaking the trust boundary between tenants on a shared Shipit instance.

### Likelihood Explanation
This requires: (1) the target Shipit instance to be configured for multiple GitHub organizations (a documented, supported configuration), and (2) at least one of those organizations to have left `webhook_secret` blank (explicitly documented as optional). Given that combination, exploitation needs no credentials, tokens, or secrets whatsoever — a single crafted HTTP POST is sufficient.

### Recommendation
Bind signature verification to the same repository identity the handlers act on: after verifying the signature with the org-selected secret, re-derive the organization from `repository.full_name` (the value the handler actually consumes) and reject the request if it disagrees with the `repository_owner`/`organization` field used to select the verification key. Alternatively, verify the signature against the secret belonging to the org that owns the *acted-upon* repository (looked up in Shipit's `Repository`/`Stack` records) rather than trusting an unverified field from the payload to pick the verification key. Do not allow a per-organization `webhook_secret` to be omitted when the instance hosts more than one organization.

### Proof of Concept
Given a multi-org `secrets.yml` such as:
```yaml
github:
  attacker-org:
    webhook_secret: # left blank/optional
  victim-org:
    webhook_secret: some-secret
```
An attacker (no credentials) sends:
```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything

{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
- `repository_owner` resolves to `attacker-org`.
- `Shipit.github(organization: "attacker-org")` loads `attacker-org`'s config, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (arbitrary) `X-Hub-Signature` header.
- `WebhooksController#create` then dispatches to `PushHandler`, which resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` and triggers `sync_github` on `victim-org`'s stack — with zero authentication. [8](#0-7) [4](#0-3) [5](#0-4) [9](#0-8)

# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
