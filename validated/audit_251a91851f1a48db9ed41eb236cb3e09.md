### Title
Crafted swap route can hide an attacker-chosen token transfer inside the caller’s authorization tree - ([File: contracts/controller/src/strategies/swap.rs])

### Summary

Controller strategy entrypoints accept caller-supplied route XDR and execute it through the configured swap aggregator while only constraining the controller’s own exact input transfer. Because the route can name an arbitrary hop-pool contract, that contract can add an unrelated `token.transfer(caller, attacker, amount)` beneath the caller’s root authorization; simulation records it, and enforcing mode executes it if the caller signs the poisoned authorization tree. [1](#0-0) [2](#0-1) 

### Finding Description

`swap_collateral` is permissionlessly reachable by the account owner or delegate and accepts an opaque `swap: Bytes` argument. [3](#0-2) [4](#0-3) 

The withdrawn collateral reaches `swap_tokens`, which loads the configured router, authorizes only the controller-to-router transfer of the exact input amount, and calls `router.execute_strategy(&controller, &amount_in, swap)`. [5](#0-4) [6](#0-5) 

The route program resolves `hop.pool` from caller-controlled `assets` and dispatches that address as a venue hop; there is no venue/pool allowlist at this boundary. [7](#0-6) [8](#0-7) 

The controller’s post-route checks measure only the controller’s input spend and output receipt, so they do not detect an unrelated transfer from the caller’s wallet added by route-selected code. [9](#0-8) 

### Impact Explanation

An attacker can steal tokens unrelated to the lending position from a user who signs a crafted strategy authorization tree. [10](#0-9) 

The loss is not bounded by the swap input, minimum output, controller balance checks, or final account risk checks. [11](#0-10) 

The same authorization-tree exposure applies to the other user-supplied route paths, including `swap_debt`, `repay_debt_with_collateral`, and route-bearing `multiply`/`flash_position` flows. [12](#0-11) [13](#0-12) 

### Likelihood Explanation

Exploitation requires the victim to submit and sign the crafted route, because `require_authorized_caller` and account owner/delegate checks prevent the attacker from directly naming the victim as `caller`. [4](#0-3) 

A malicious quote or route builder can nevertheless make simulation attach the rogue token transfer as a child of the victim’s ordinary `swap_collateral` authorization; if the wallet or client does not decode and reject that extra child, the signed transaction succeeds. [14](#0-13) 

The repository’s enforcing-auth test demonstrates that the rogue transfer succeeds when the simulated poisoned tree is signed, while an honest tree without that child fails. [15](#0-14) 

### Recommendation

Constrain route execution to an explicit registry of approved venue/pool contracts or immutable venue adapters, rather than allowing payload-supplied contract addresses. [7](#0-6) 

Clients should simulate every strategy transaction, decode the returned authorization tree, and reject any child invocation other than the expected input-token transfer. [16](#0-15) 

Wallets should clearly display nested token transfers separately from the top-level lending action and require explicit confirmation of their token, recipient, and amount. [14](#0-13) 

### Proof of Concept

1. Alice supplies USDC and owns an unrelated wallet token `WLT`; the attacker deploys a hop-pool contract configured to execute `WLT.transfer(Alice, attacker, Alice_balance)`. [17](#0-16) 

2. The attacker creates a route whose hop-pool address is the malicious contract while still returning a fair amount of the requested output asset. [18](#0-17) 

3. Alice calls `swap_collateral(Alice, account_id, usdc_hub_asset, amount, eth_hub_asset, route)`. [19](#0-18) 

4. The controller authorizes only its own USDC transfer to the router and invokes `execute_strategy` with Alice’s route bytes. [1](#0-0) 

5. The malicious pool runs inside the route and calls `WLT.transfer(Alice, attacker, Alice_balance)`; simulation records that transfer as a child under Alice’s `swap_collateral` authorization. [14](#0-13) 

6. If Alice signs that returned tree, the unrelated wallet-token transfer executes, while the controller still observes positive output and completes the collateral swap. [20](#0-19)

            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);

    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");

        sub_invocations: std::vec![stolen_transfer],
    };

fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
