### Title
Webhook signature verification is keyed off `repository.owner.login`, but event handlers act on the independent `repository.full_name` field, letting any onboarded organization forge cross-tenant `push` events - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate the HMAC signature against using `repository_owner`, derived from `params.dig('repository', 'owner', 'login')` (with an `organization.login` fallback). Once the signature check for *that* organization passes, `create` re-parses the raw body and dispatches it to `Shipit::Webhooks.for_event(event)` handlers, which resolve the target `Stack`/`Repository` using a completely different, unauthenticated field: `payload.dig('repository', 'full_name')`. Nothing binds these two fields together, so a payload can be signed as organization A but claim to belong to organization B's repository.

### Finding Description
`verify_signature` in [1](#0-0)  picks the webhook secret via `repository_owner`: [2](#0-1) 

`Shipit.github(organization: repository_owner)` loads a distinct `GithubApp`/secret per configured organization, as seen in `config/secrets.development.shopify.yml` where each org (`somegithuborg`, `someothergithuborg`) has its own `webhook_secret`, `app_id`, and `private_key` [3](#0-2) . `GithubApp#verify_webhook_signature` performs a straightforward HMAC comparison against that org's secret only [4](#0-3) .

Once verification passes, `Handler#stacks` and `Handler#repository_name` resolve the target repository from an entirely separate JSON path that was never checked against the verified organization: [5](#0-4) 

`PushHandler#process` then looks up stacks for that repository/branch and calls `stack.sync_github(expected_head_sha: params.after)`: [6](#0-5) 

Because `repository.owner.login` (used to pick the signing secret) and `repository.full_name` (used to pick the acted-upon stack) are independent, unrelated JSON keys in the same attacker-controlled request body, an organization that legitimately owns a GitHub App integration in this Shipit instance (and therefore knows its own `webhook_secret`, since App creation/secret-setting is performed by whoever configures the org's integration per the setup docs) can craft a POST directly to `/github/webhooks` with:
```json
{
  "repository": {
    "owner": { "login": "org-attacker" },
    "full_name": "victim-org/victim-repo"
  },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>"
}
```
signed with `org-attacker`'s own secret. `verify_signature` resolves and validates against `org-attacker`'s secret and passes; `PushHandler` then acts on `victim-org/victim-repo`, a stack belonging to a different tenant that `org-attacker` has no authorization over. This exactly mirrors the report's bug class: a value the code trusts for one purpose (secret/org selection = "authentication") and a different value used for the actual privileged action ("repository written"), with no equality enforced between them.

The binding that should hold is:
`organization authenticated by verify_signature == organization owning the repository acted on by the handler`
but the code only enforces the left side is internally self-consistent (secret matches org string in body) — it never checks that side against the right side (`full_name`'s owner segment).

### Impact Explanation
This allows a low-privileged, unprivileged-relative-to-the-victim tenant (any organization onboarded to this multi-tenant Shipit instance) to trigger `GithubSyncJob`/`sync_github` on a victim stack it does not own, using a spoofed `ref`/`after` SHA. Depending on continuous-deployment configuration (`Stack.schedule_continuous_delivery`, `continuous_deployment: true`) this can lead to an unauthorized deploy being queued against the victim's commit history, and can desynchronize the victim stack's recorded head. This matches the "unauthorized deploy" / cross-tenant-write impact class called out in scope.

### Likelihood Explanation
Exploitability requires the attacker to control at least one organization already configured with its own GitHub App/webhook secret in this Shipit deployment (a normal, unprivileged tenant in a multi-org Shipit install — not a Shipit admin, GitHub org admin of the victim, or holder of any Shipit `ApiClient`/session credential). No interaction with GitHub's own webhook delivery is required since the endpoint is a plain unauthenticated HTTP POST once a valid HMAC for any onboarded org can be computed.

### Recommendation
Bind the two fields: after resolving the signing organization via `repository_owner`, require that the `repository.full_name`'s owner segment (or, more robustly, the `Repository` record itself and its stored `owner`) matches the same organization the signature was verified against, and reject (422) any request where they diverge. Alternatively, verify the signature using the secret associated with the repository resolved from `full_name`, not from the separate, unauthenticated `owner.login` field.

### Proof of Concept
1. Configure two organizations in Shipit, `org-attacker` and `victim-org` (as in `config/secrets.development.shopify.yml`), each with its own `webhook_secret`.
2. As `org-attacker`, compute `sha1=HMAC-SHA1(org-attacker_webhook_secret, body)` for body:
   ```json
   {"repository":{"owner":{"login":"org-attacker"},"full_name":"victim-org/victim-repo"},"ref":"refs/heads/master","after":"<attacker sha>"}
   ```
3. POST to `/github/webhooks` with header `X-Github-Event: push` and `X-Hub-Signature: sha1=<computed>`.
4. `verify_signature` in [2](#0-1)  resolves `repository_owner` = `org-attacker`, verification succeeds against `org-attacker`'s secret.
5. `PushHandler#process` in [6](#0-5)  resolves stacks via `full_name` = `victim-org/victim-repo` and calls `sync_github(expected_head_sha: "<attacker sha>")` on the victim's stack, despite the request never being authenticated as belonging to `victim-org`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
