## Analysis

The Hive CVE describes a credentials file being created with default (insecure) permissions (644) in a shared/temp directory, allowing any local user to read sensitive material. The matching pattern in `ocore` is in the private-payment/textcoin flow, where `storePrivateAssetPayload()` writes the mnemonic (a spending credential) and private-chain history to a file on disk using Node's `fs.writeFile()` without ever specifying an explicit file mode. [1](#0-0) 

The `fullPath` used here comes from the caller-supplied `getPrivateAssetPayloadSavePath` callback, invoked from `sendMultiPayment`'s private-asset commit path when the sender doesn't have a `recipient_device_address` and is instead creating a textcoin for someone by mnemonic: [2](#0-1) 

Node's `fs.writeFile(path, data, cb)` with no `options.mode` defaults to mode `0o666`, which after the process umask (commonly `022`) results in world/group-readable `0644` permissions — exactly the CWE-732 class described in the advisory (credentials file written with `644` permissions in a directory other local users/processes can access).

### Title
Private Textcoin Payload (Mnemonic/Private Chains) Written to Disk With Default World-Readable Permissions - (File: wallet.js)

### Summary
`storePrivateAssetPayload()` in `wallet.js` persists a zipped JSON blob containing the textcoin `mnemonic` (the spending credential for the private-payment address) and the full private-chain payloads to a file via `fs.writeFile(fullPath, zipFile, cb)` without specifying restrictive file permissions. On multi-user systems (or any shared filesystem/backup/sync context) the resulting file inherits the default umask-derived mode (typically `0644`), making it world-readable.

### Finding Description
When a full or light wallet built on `ocore` sends a private payment/asset to a recipient without a paired device address (the "textcoin" flow), `sendMultiPayment` invokes the `getPrivateAssetPayloadSavePath` callback supplied by the host application, then calls `storePrivateAssetPayload(fullPath, cordovaPathObj, mnemonic, chains, cb)`. [3](#0-2) 
That function serializes `{ mnemonic, chains }` into a zip and writes it to `fullPath` with no explicit `mode` argument: [4](#0-3) 
The `mnemonic` here is not incidental metadata — `expandMnemonic()` derives an HD private key and address directly from it, meaning possession of the mnemonic is equivalent to possession of the private key controlling all funds sent to that textcoin address: [5](#0-4) 
Because the file is created with the process default mode (`0666` masked by umask, commonly `0644`), any other unprivileged local user/process on the same host — or anything with read access to the storage/sync path the app writes into — can read the mnemonic before the intended recipient claims the textcoin, exactly mirroring the Hive advisory's root cause (sensitive credential file left world-readable in a shared location).

### Impact Explanation
Reading this file yields the mnemonic, which is a full spending credential for the pending private payment. An unauthorized local reader can immediately call the equivalent of `receiveTextCoin()` and claim/spend the funds before the legitimate recipient does, resulting in concrete unauthorized spending / theft of the private payment's balance. This satisfies the "concrete unauthorized spending" acceptance bar.

### Likelihood Explanation
Exploitation requires only that another local unprivileged actor (or a process with read access to the destination path, e.g., a synced folder, shared machine, or misconfigured mobile storage) reads the file before the recipient imports it — no cryptographic break or privileged access needed, since the mode is left at the OS default. Any deployment where `getPrivateAssetPayloadSavePath` points to a shared or synced directory (a supported/expected usage pattern for exporting textcoin payloads) is directly affected.

### Recommendation
Explicitly set a restrictive mode (e.g., `0600`) when writing the private asset payload file, e.g. `fs.writeFile(fullPath, zipFile, { mode: 0o600 }, cb)`, and consider verifying/tightening permissions on the containing directory as well.

### Proof of Concept
1. Sender uses `sendMultiPayment` to pay a private asset to a recipient by mnemonic (no `recipient_device_address`), supplying `getPrivateAssetPayloadSavePath` pointing to a directory that other local users can read (e.g., default temp dir on a shared host, or an auto-synced folder on mobile).
2. `storePrivateAssetPayload()` writes the zip file containing `{mnemonic, chains}` via `fs.writeFile(fullPath, zipFile, cb)` — file lands with mode `0644` (default umask).
3. Any other local user runs `cat fullPath`, unzips it, extracts `mnemonic`, and calls `expandMnemonic(mnemonic)` / `receiveTextCoin(mnemonic, attacker_address, cb)` to claim the funds before the intended recipient does.

function expandMnemonic(mnemonic) {
	var addrInfo = {};
	mnemonic = mnemonic.toLowerCase().split('-').join(' ');
	if ((mnemonic.split(' ').length % 3 !== 0) || !Mnemonic.isValid(mnemonic)) {
		throw new Error("invalid mnemonic: "+mnemonic);
	}
	mnemonic = new Mnemonic(mnemonic);
	addrInfo.xPrivKey = mnemonic.toHDPrivateKey().derive("m/44'/0'/0'/0/0");
	addrInfo.pubkey = addrInfo.xPrivKey.publicKey.toBuffer().toString("base64");
	addrInfo.definition = ["sig", {"pubkey": addrInfo.pubkey}];
	addrInfo.address = objectHash.getChash160(addrInfo.definition);
	return addrInfo;
}

function storePrivateAssetPayload(fullPath, cordovaPathObj, mnemonic, chains, cb) {
	var storedObj = {
		mnemonic: mnemonic,
		chains: chains
	};
	var bCordova = (typeof window === 'object' && window.cordova);
	var JSZip = require("jszip");
	var zip = new JSZip();
	zip.file('private_textcoin', JSON.stringify(storedObj));
	var zipParams = {type: "nodebuffer", compression: 'DEFLATE', compressionOptions: {level: 9}};
	zip.generateAsync(zipParams).then(function(zipFile) {
		if (!bCordova) {
			var fs = require('fs');
			fs.writeFile(fullPath, zipFile, cb);
		} else {
			window.requestFileSystem(LocalFileSystem.TEMPORARY, 0, function(fs) {
				window.resolveLocalFileSystemURL(cordovaPathObj.root, function(dirEntry) {
					dirEntry.getDirectory(cordovaPathObj.path, {create: true, exclusive: false}, function(dirEntry1) {
						dirEntry1.getFile(cordovaPathObj.fileName, {create: true, exclusive: false}, function(file) {
							file.createWriter(function(writer) {
								writer.onwriteend = function() {
									cb(null); 
								};
								writer.write(zipFile.buffer);
							}, cb);
						}, cb);
					}, cb);
				}, cb);
			}, cb);
		}
	}, cb);
}
