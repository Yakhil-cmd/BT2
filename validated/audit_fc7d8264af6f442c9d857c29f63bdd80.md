### Title
Permanent market freeze from RAY-value overflow before the borrow-index cap - (File: `common/src/rates/scaling.rs`)

### Summary

A sufficiently large high-utilization market can reach a state where converting its scaled debt back into a RAY-denominated value overflows `i128` before the configured borrow-index ceiling is reached. `scaled_to_original` multiplies scaled debt by the current borrow index and panics on overflow, while the index is only capped after `update_borrow_index` multiplies it by the next interest factor. [1](#0-0) [2](#0-1) 

### Finding Description

Every accrual step starts by reconstructing `borrowed_original` with `scaled_to_original(env, borrowed, borrow_index)`. [3](#0-2)  Once `borrowed * borrow_index / RAY` exceeds `i128::MAX`, this conversion panics even if `borrow_index` is still below `MAX_BORROW_INDEX_RAY`. [1](#0-0) [4](#0-3) 

All pool mutation legs load a synchronized market, so `interest::global_sync` runs before supply, borrow, withdraw, repay, liquidation/seizure, or other market operations. [5](#0-4)  `global_sync` calls `accrue_chunk`, and `accrue_chunk` invokes the vulnerable `accrue_step` calculation. [6](#0-5)  The permissionless controller `update_indexes` path reaches the pool's `update_indexes` call, which runs the same accrual for each selected market. [7](#0-6) [8](#0-7) 

The repository already contains a regression-style proof for this cliff: a market holding one billion 18-decimal tokens at 98% utilization overflows inside `scaled_to_original` after the index grows, while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [9](#0-8) 

### Impact Explanation

After the cliff is reached, every mutation for that market re-enters accrual and re-panics, so suppliers cannot withdraw and borrowers cannot repay. [5](#0-4) [10](#0-9)  Because liquidation legs also synchronize their markets, the debt cannot be cleared through the normal liquidation route, permanently freezing supplier cash and protocol revenue associated with the affected market. [5](#0-4) 

### Likelihood Explanation

An unprivileged user can create the prerequisite state through normal `supply` and `borrow` calls by providing enough collateral and creating sustained high utilization; no governance call, leaked key, malformed storage, or privileged pool invocation is needed. [11](#0-10)  The condition requires an exceptionally large position and prolonged high-utilization accrual rather than a single crafted small input, so the practical likelihood is low and the impact is best treated as High rather than Critical. [12](#0-11) 

### Recommendation

Bound the market's scaled debt against the maximum index before admitting debt, for example by enforcing `borrowed_scaled <= i128::MAX / MAX_BORROW_INDEX_RAY` in the same units used by `Ray::mul`, rather than relying only on the index cap. [2](#0-1) [4](#0-3) 

Also make accrual's utilization and reward calculations avoid materializing an unrepresentable `borrowed * index` value: use widened multiplication/division throughout `scaled_to_original`, `calculate_supplier_rewards`, and related accrual paths, or cap the represented debt value before conversion. [13](#0-12) [14](#0-13)  Add a regression test asserting that borrow-index saturation occurs before the RAY-value overflow for every allowed market size. [15](#0-14) 

### Proof of Concept

1. Through the public controller `supply`, deposit enough collateral and supply a very large 18-decimal asset position to the target market.
2. Through public `borrow`, borrow approximately 98% of that market, producing a very large fixed scaled-debt total.
3. Allow the market to remain at sustained high utilization while periodically calling public `update_indexes` for that `HubAssetKey`.
4. `accrue_step` eventually evaluates `scaled_to_original(borrowed, borrow_index)` while `borrow_index < MAX_BORROW_INDEX_RAY`; the product no longer fits `i128`, so the call reverts with `MathOverflow`.
5. Subsequent `withdraw`, `repay`, `liquidate`, and `update_indexes` calls all synchronize the same market first and revert on the same multiplication.

The repository's test demonstrates this sequence with a one-billion-token 18-decimal market, a 98% borrow, repeated yearly `update_indexes` calls, and subsequent failed withdraw and repay calls. [15](#0-14)

```rust
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,

    delta_ms: u64,

    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);

        supplied,

        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
