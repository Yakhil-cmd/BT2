### Title
Textcoin Mnemonic (Bearer Private Key) Written in Plaintext to Application Logs - (File: wallet.js)

### Summary
`ocore`'s "textcoin" feature lets a wallet send bytes/assets to a randomly-generated BIP39 `mnemonic` that acts as a bearer private key: anyone who possesses the mnemonic can derive the spending key and claim the funds. The background job `claimBackOldTextcoins()` in `wallet.js` logs this bearer secret in cleartext via `console.log` whenever it retries claiming an unclaimed/expired textcoin. This is directly analogous to CVE-2020-14330 (ansible `uri` module exposing sensitive keys in logs/output): a secret that is equivalent to a private key is written unredacted into log output that is often collected, rotated, shipped to log-aggregation systems, or attached to bug/crash reports, exposing it to anyone with log access and enabling unauthorized spending of the underlying funds.

### Finding Description
`expandMnemonic()` derives the actual signing key from the mnemonic phrase: [1](#0-0) 

`receiveTextCoin()` then uses that derived `xPrivKey` to sign and spend the funds held at the mnemonic-derived address — i.e. the mnemonic *is* the private key for that on-chain address: [2](#0-1) 

The periodic background job `claimBackOldTextcoins()`, which iterates over `sent_mnemonics` (textcoins the wallet itself created and sent) and retries reclaiming stale/unclaimed ones, prints the raw mnemonic value to the process log on both the success and failure path: [3](#0-2) 

Because the mnemonic is the sole credential needed to spend the corresponding textcoin address (no other authentication is required — `expandMnemonic` + `ecdsaSig.sign` is sufficient, as seen in `receiveTextCoin`), writing it to `console.log` places a full bearer private key into application/process logs. Node.js log output from wallets/services is routinely captured to disk, forwarded to centralized logging, rotated into support tickets, or included in crash/bug reports (`network.js` already forwards similarly-shaped diagnostic text via `mail.sendBugEmail`), so any process, log-shipping agent, support engineer, or third party with read access to those logs — a much lower trust level than "wallet owner" — obtains the ability to spend the funds. This mirrors the ansible finding precisely: a secret value that should remain confidential is emitted into logs/console output reachable by less-privileged consumers.

### Impact Explanation
Any entity with access to the node's stdout/log files (log aggregation services, monitoring agents, support/ops staff, or an attacker who compromises log storage) can read the plaintext mnemonic and immediately derive the private key to claim/spend the still-unclaimed textcoin funds — a concrete case of unauthorized spending of the wallet owner's funds. Because `claimBackOldTextcoins` runs automatically and repeatedly for every stale textcoin, the mnemonic (and thus the spending key) for every outstanding textcoin created by the wallet is periodically re-exposed in the logs until it is claimed.

### Likelihood Explanation
The logging occurs unconditionally on every invocation of the automatic reclaim job for stale textcoins — no attacker interaction is required to trigger the log write; it happens purely as part of normal wallet operation whenever a sent textcoin remains unclaimed past the configured number of days. The only precondition is that some party other than the wallet operator gains read access to the node's logs, which is a common occurrence in hosted, containerized, or centrally-logged deployments.

### Recommendation
Remove the raw `mnemonic` from the `console.log` calls in `claimBackOldTextcoins` (and anywhere else it may be logged), logging only non-sensitive identifiers such as the resulting `unit`/`address`/error message. Treat the mnemonic with the same handling discipline as a private key (never logged, never persisted outside of the encrypted store) throughout its lifecycle.

### Proof of Concept
1. Wallet A sends a textcoin (creates a bearer mnemonic-secured address) to an email address that never claims it, per `sendTextcoinEmail`/`replaceInTextcoinTemplate` (`wallet.js:2605-2641`).
2. After the configured number of days, the scheduled job calls `claimBackOldTextcoins(to_address, days)` (`wallet.js:2818`), which selects the row from `sent_mnemonics` and invokes `receiveTextCoin(row.mnemonic, ...)`.
3. On either branch of the callback, the exact plaintext mnemonic is written to the process log:
```
console.log("failed claiming back old textcoin "+row.mnemonic+": "+err);
console.log("claimed back mnemonic "+row.mnemonic+", unit "+unit+", asset "+asset);
```
4. Any party who can read these logs (log shipping/aggregation, ops/support access, crash-report attachments) extracts `row.mnemonic`, calls the same `expandMnemonic`/HD-derivation logic used by `receiveTextCoin`, and signs a spend from the derived address — claiming the funds before (or instead of) the legitimate recipient/operator, resulting in unauthorized spending.

function expandMnemonic(mnemonic) {
	var addrInfo = {};
	mnemonic = mnemonic.toLowerCase().split('-').join(' ');
	if ((mnemonic.split(' ').length % 3 !== 0) || !Mnemonic.isValid(mnemonic)) {
		throw new Error("invalid mnemonic: "+mnemonic);
	}
	mnemonic = new Mnemonic(mnemonic);
	addrInfo.xPrivKey = mnemonic.toHDPrivateKey().derive("m/44'/0'/0'/0/0");
	addrInfo.pubkey = addrInfo.xPrivKey.publicKey.toBuffer().toString("base64");
	addrInfo.definition = ["sig", {"pubkey": addrInfo.pubkey}];
	addrInfo.address = objectHash.getChash160(addrInfo.definition);
	return addrInfo;
}
```

function claimBackOldTextcoins(to_address, days){
	if (typeof days !== 'number')
		throw Error("bad days: " + days);
	db.query(
		"SELECT mnemonic FROM sent_mnemonics LEFT JOIN unit_authors USING(address) \n\
		WHERE mnemonic!='' AND unit_authors.address IS NULL AND creation_date<"+db.addTime("-"+days+" DAY"),
		function(rows){
			async.eachSeries(
				rows,
				function(row, cb){
					receiveTextCoin(row.mnemonic, to_address, function(err, unit, asset){
						if (err)
							console.log("failed claiming back old textcoin "+row.mnemonic+": "+err);
						else
							console.log("claimed back mnemonic "+row.mnemonic+", unit "+unit+", asset "+asset);
						cb();
					});
				}
			);
		}
	);
}
```
