### Title
Unauthenticated `push` webhooks are fully trusted for any GitHub org with no configured `webhook_secret`, letting a forged event drive `Stack#sync_github` — (File: `lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when no `webhook_secret` is configured for the organization derived from the payload, so `Shipit::WebhooksController#verify_signature` never rejects a forged `push` event for such an org. `PushHandler` then resolves stacks strictly from the attacker-supplied `repository.full_name`/branch and calls `stack.sync_github(expected_head_sha: params.after)` for every matching non-archived stack, including auto-provisioned review stacks that execute `shipit.yml`.

### Finding Description
The broken binding: the intended invariant is `signature_valid(request) == (X-Hub-Signature verifies against organization's real webhook_secret using HMAC-SHA1)`. In practice, for an org whose `Shipit.github(organization:)` config has no `webhook_secret`, `verify_webhook_signature` evaluates to `true` regardless of the (attacker-supplied or absent) `X-Hub-Signature` header: [1](#0-0) 

`WebhooksController#verify_signature` relies entirely on this method and does not perform any additional authentication (no session, no API client, no team check): [2](#0-1) 

Once the request passes, `Shipit::Webhooks.for_event('push')` invokes `PushHandler#process`, which resolves the target stacks purely from the JSON body's `repository.full_name` (via `Handler#stacks`/`#repository_name`) and the `ref`, then syncs every matching non-archived stack to the attacker-chosen `after` SHA: [3](#0-2) [4](#0-3) 

Root cause: signature verification is a no-op ("trust by default") whenever `webhook_secret` is absent from the org's GitHub App configuration, rather than failing closed. This is a genuine authentication-bypass path in the engine's own code — the controller and handler correctly bind the sync target to the payload's `repository_owner`/`full_name`, but they never validate that the request actually originated from GitHub for orgs with no secret configured.

Exploit flow: attacker sends `POST /webhooks` with `X-Github-Event: push`, a body whose `repository.owner.login`/`repository.full_name` match the victim org/repo (public information), `ref` matching a branch tracked by a review-stack-enabled (`allow_all`) stack, and any `after` SHA. `verify_signature` passes trivially (no secret configured for that org), `drop_unhandled_event`/`check_if_ping` do not block `push`, and `PushHandler` calls `stack.sync_github(expected_head_sha: <attacker value>)` on every matching stack, including auto-provisioned review stacks that run `shipit.yml` on sync/deploy.

### Impact Explanation
For any organization onboarded without a `webhook_secret`, an unauthenticated attacker can force the corresponding Shipit install to treat arbitrary forged `push` events as legitimate GitHub traffic. This lets the attacker drive `Stack#sync_github` (and, transitively, `GithubSyncJob`) for every non-archived stack on the targeted branch, without holding any Shipit session, API token, or GitHub secret — matching the "authentication bypass (forged webhook … accepted)" Critical category. Combined with `review_stacks_enabled: true, allow_all` stacks that auto-provision from external PRs and execute `shipit.yml` on sync/deploy, this can drive execution of tasks on the deploy host for that org. The blast radius is scoped to organizations that have not configured `webhook_secret` (repository binding via `full_name` prevents cross-tenant writes to unrelated orgs' repositories), but it is fully repeatable against every such org/stack.

### Likelihood Explanation
Preconditions: the target organization's GitHub App config in Shipit must have no `webhook_secret` set (this is the scenario's stated precondition), and a stack must exist for the pushed branch with `review_stacks_enabled: true, allow_all` to obtain the amplified review-stack/`shipit.yml` execution effect. Attacker cost is a single unauthenticated HTTP POST; no credentials, sessions, or GitHub write access are required. This is fully repeatable and requires no interaction from a maintainer or victim.

### Recommendation
Make signature verification fail closed: if no `webhook_secret` is configured for an organization, `GitHubApp#verify_webhook_signature` should reject the request (return `false`/log and `head(422)`) rather than defaulting to `true`. Require `webhook_secret` to be present for every org configured via `Shipit.github`, and add a startup/config check that surfaces orgs missing a secret. Additionally, consider binding `PushHandler`'s stack resolution to a signed/authenticated repository identity rather than the raw JSON payload alone, as defense in depth.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure a test `Shipit.github` organization config with `webhook_secret` omitted/nil.
2. Create a `Repository` with `full_name` matching that org, and a `Stack` with `review_stacks_enabled: true`, `allow_all_pull_requests` semantics, tracking branch `main`.
3. Assert baseline: `stack.sync_github` has not been called (spy/mock `Stack#sync_github`).
4. POST `/webhooks` with header `X-Github-Event: push`, no/garbage `X-Hub-Signature`, and body `{ "ref": "refs/heads/main", "after": "<attacker_sha>", "repository": { "full_name": "<org>/<repo>", "owner": { "login": "<org>" } } }`.
5. Assert response is `200`/`:ok` (not `422`) and that `Stack#sync_github` was invoked with `expected_head_sha: "<attacker_sha>"` on the stack — i.e., assert `verified == true` even though no real GitHub secret produced the signature, proving `signature_valid(request) != (request actually signed by GitHub)`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
