### Title
Overbroad `AllMatchingCredentialsPattern` credential-helper scope during PR checkout submodule/fetch operations on attacker-controlled content - (File: `pkg/cmd/pr/checkout/checkout.go`, `git/client.go`)

### Summary
`git.AllMatchingCredentialsPattern` configures `gh` as the `credential.helper` for **all** hosts (`credential.helper=`) rather than scoping it to a single host pattern (as `CredentialPatternFromGitURL`/`CredentialPatternFromHost` do). In `pkg/cmd/pr/checkout/checkout.go`'s `executeCmds`, this all-matching pattern is unconditionally used for `submodule` and `fetch` git subcommands, even though the content driving those operations (a PR branch's `.gitmodules` file, submodule URLs, or the ref being fetched) can originate from an attacker-controlled fork/branch. This mirrors the ENS `wrapETH2LD` finding: an approval/trust relationship granted for one legitimate scope (the credential helper trusted for the specific remote host you intend to operate on) is extended broadly (to any host git happens to contact during that command), and that broadening is triggered by data the attacker controls (the PR's checked-out content).

### Finding Description
`git/client.go` defines two ways to scope the `gh auth git-credential` helper:
- `CredentialPatternFromGitURL`/`CredentialPatternFromHost`, which install the helper only for `credential.<scheme>://<host>.helper`.
- `AllMatchingCredentialsPattern`, documented as "less secure" and meant for narrow backwards-compatibility, which installs the helper as the global `credential.helper` matching every host. [1](#0-0) 

`Fetch`, `Pull`, and `Push` on `git.Client` unconditionally use `AllMatchingCredentialsPattern`: [2](#0-1) 

In `pkg/cmd/pr/checkout/checkout.go`, `executeCmds` dispatches on the subcommand and explicitly forces `git.AllMatchingCredentialsPattern` for both `submodule` and `fetch` operations that occur while operating on a checked-out PR: [3](#0-2) 

Because a checked-out PR branch (from an untrusted fork) can contain an arbitrary `.gitmodules` file with attacker-chosen submodule URLs/hosts, `git submodule update`/`sync` invoked with the all-matching credential pattern will consult `gh auth git-credential` for *whatever host the attacker specified*, not just the intended repository host. This is the same class of bug as the ENS finding: the credential-helper "approval" that a user reasonably expects to apply only to their intended target (their authenticated GitHub/GHES host) is instead extended to cover any host reachable through content that is not under the user's control.

### Impact Explanation
The actual credential leak is bounded by `pkg/cmd/auth/gitcredential/helper.go`'s `helperRun`, which only returns a token when `cfg.ActiveToken(lookupHost)` succeeds for the exact host git requests: [4](#0-3) 

This means a completely unrelated attacker-chosen host will not receive a real token. However, the impact is realized in more nuanced setups: a user authenticated to multiple hosts (e.g., both `github.com` and a GitHub Enterprise Server instance, or multiple accounts) who checks out a hostile PR whose `.gitmodules` references one of the user's *other* authenticated hosts (not the one the PR/checkout is scoped to) will have `gh` silently hand credentials for that other host to a submodule fetch driven entirely by attacker-supplied content. This is a credential-scope confusion: the trust relationship the user granted for "checking out this PR/repo" is broadened to "any host I have a `gh` token for," triggered by content the attacker controls.

### Likelihood Explanation
This is reachable through a completely normal, unprivileged workflow: `gh pr checkout <PR-from-a-fork>` followed by a submodule sync/update step that `gh` itself drives via `executeCmds`. No admin/operator privileges, MITM, or local access are required — only that the victim runs `gh pr checkout` against a PR whose branch content (attacker-published) includes a `.gitmodules` referencing a host the victim also has `gh` credentials for. This satisfies "attacker-published content ... during a normal `gh` command."

### Recommendation
- Do not use `AllMatchingCredentialsPattern` for `submodule` operations (and ideally `fetch`) that are driven by content originating from an untrusted PR/fork. Instead, derive the credential pattern per-URL the same way `Clone` does via `CredentialPatternFromGitURL`, scoping the helper to only the intended host(s) for that specific submodule/remote URL.
- Where a single command touches multiple remotes (as `git submodule update --init --recursive` can), enumerate the actual submodule URLs first and only enable the credential helper for hosts that match the trusted repository's host (or that the user explicitly consents to), rejecting/skipping helper registration for arbitrary third-party hosts.
- Continue to treat `AllMatchingCredentialsPattern` as the exception it's documented to be, and audit remaining call sites (`Fetch`, `Pull`, `Push`) for whether they can also be driven by attacker-influenced remote configuration (e.g., prior `AddRemote` calls sourced from repository metadata).

### Proof of Concept
1. Authenticate `gh` to two hosts: `gh auth login` for `github.com` and for a second host `ghes.example.com` (both now have tokens resolvable by `cfg.ActiveToken`).
2. Attacker creates a PR against a repository on `github.com` from a fork whose branch adds a `.gitmodules` file with:
   ```
   [submodule "x"]
       path = x
       url = https://ghes.example.com/attacker/malicious-path
   ```
   (choosing a host the victim is known/likely to have credentials for, e.g. discovered via public info or social engineering).
3. Victim runs `gh pr checkout <PR-number>` and then a submodule sync/update flow that reaches `executeCmds` in `pkg/cmd/pr/checkout/checkout.go`, which routes the `submodule` subcommand through `git.AllMatchingCredentialsPattern`. [5](#0-4) 
4. `git`, per the global `credential.helper` set for all hosts, contacts `gh auth git-credential get` when fetching `https://ghes.example.com/attacker/malicious-path`.
5. `gh`'s helper looks up `cfg.ActiveToken("ghes.example.com")` — which succeeds because the victim is legitimately authenticated to that host — and returns that host's real token to satisfy the attacker-directed submodule fetch, exfiltrating the victim's second-host credential to a URL/path chosen entirely by the attacker's PR content. [6](#0-5)

// However, we should endeavour to remove it as it's less secure.
var AllMatchingCredentialsPattern = CredentialPattern{allMatching: true, pattern: ""}
var disallowedCredentialPattern = CredentialPattern{allMatching: false, pattern: ""}

// CredentialPatternFromGitURL takes a git remote URL e.g. "https://github.com/cli/cli.git" or
// "git@github.com:cli/cli.git" and returns the credential pattern that should be used for it.
func CredentialPatternFromGitURL(gitURL string) (CredentialPattern, error) {
	normalizedURL, err := ParseURL(gitURL)
	if err != nil {
		return CredentialPattern{}, fmt.Errorf("failed to parse remote URL: %w", err)
	}
	return CredentialPatternFromHost(normalizedURL.Host), nil
}

// CredentialPatternFromHost expects host to be in the form "github.com" and returns
// the credential pattern that should be used for it.
// It does not perform any canonicalisation e.g. "api.github.com" will not work as expected.
func CredentialPatternFromHost(host string) CredentialPattern {
	return CredentialPattern{
		pattern: strings.TrimSuffix(ghinstance.HostPrefix(host), "/"),
	}
}

func executeCmds(client *git.Client, credentialPattern git.CredentialPattern, cmdQueue [][]string) error {
	for _, args := range cmdQueue {
		// Determine the git sub-command, skipping any -C <path> prefix.
		subCmd := args[0]
		if len(args) >= 3 && args[0] == "-C" {
			subCmd = args[2]
		}

		var err error
		var cmd *git.Command
		switch subCmd {
		case "submodule":
			cmd, err = authenticatedCommand(client, credentialPattern, args)
		case "fetch":
			cmd, err = authenticatedCommand(client, git.AllMatchingCredentialsPattern, args)
		default:
			cmd, err = client.Command(context.Background(), args...)
		}
		if err != nil {
			return err
		}
		if err := cmd.Run(); err != nil {
			return err
		}
	}
	return nil
}
