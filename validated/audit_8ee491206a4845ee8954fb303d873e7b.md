## Analog Found: `pallet-psm` (Peg Stability Module)

The `StoneBTCVault` report's root cause — a shared reserve backing multiple third-party tokens under an assumed fixed 1:1 exchange rate, with no delay between deposit and withdrawal — has a direct analog in `substrate/frame/psm/src/lib.rs`, newly integrated into Asset Hub Westend per `prdoc/stable2606/pr_11529.prdoc`.

### Title
PSM cross-asset arbitrage during depeg drains higher-value external collateral from the shared reserve - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet-psm` lets a single internal asset be backed by multiple approved external assets held in one shared, derived reserve account, and swaps between internal and any approved external asset are computed purely from decimal scaling (a fixed 1:1 peg), never from market price. `mint` and `redeem` are permissionless, single-block, signed extrinsics with only a fixed ~0.5% fee on each side and no delay between them, so an attacker can mint internal asset with a depegged (cheap) external asset and immediately redeem it for a different, still fully-valued external asset from the same reserve — draining the more valuable collateral, exactly as described for `StoneBTCVault`.

### Finding Description
Per the pallet doc, "A PSM strengthens its internal asset's peg by providing arbitrage opportunities" and "A PSM may approve multiple externals, each identified by `external_asset`", all held in one reserve account: `blake2_256((PalletId::TYPE_ID, PalletId, internal_asset).encode())` [1](#0-0) .

`mint` converts `external_amount` to `internal_equivalent` using only decimal scaling (`external_to_internal`/`internal_to_external`), never a price oracle, then transfers the external asset into the shared reserve and mints internal asset to the caller minus a `MintingFee` (default 0.5%, `DefaultFee`) [2](#0-1) [3](#0-2) .

`redeem` lets the caller choose *any* approved `external_asset` to receive, independent of which external asset was used to mint the internal tokens being burned. The only gate is `PsmDebt::<T>::get(&internal_asset, &external_asset) >= effective_internal_net` [4](#0-3) . `PsmDebt` is a per-`(internal, external)` bucket populated by *any* user's prior mint of that external asset, not the caller's own mints [5](#0-4) . Since the internal asset is fully fungible, an attacker's internally-minted tokens (sourced from a cheap, depegged external asset) are indistinguishable from tokens backed by a different, non-depegged external asset once minted — the only requirement to redeem into the more valuable asset is that its debt bucket has non-zero balance, which normal user activity on any multi-external PSM instance will produce.

This reproduces the exploit scenario from the original report almost verbatim: instead of two vault tokens xBTC/yBTC, this is two PSM externals (e.g. USDT/USDC) sharing one internal stablecoin and one physical reserve account; instead of `deposit()`/`withdraw()` it is `mint()`/`redeem()`; the "no delay between staking and unstaking" maps directly to `mint` and `redeem` both being ordinary same-block signed extrinsics with no lock-up.

### Impact Explanation
If any approved external asset depegs downward relative to another external asset approved on the same PSM instance by more than the combined mint+redeem fee (default 1% total), an attacker can:
1. Acquire the depegged external asset cheaply on the open market.
2. Call `mint` to convert it into internal asset at the pallet's fixed decimal-only rate.
3. Call `redeem`, selecting the non-depegged external asset, extracting full-value collateral from the shared reserve.

This directly drains the reserve of its most valuable collateral, leaving remaining internal-asset holders backed disproportionately by the depegged asset — an unbacked-issuance/loss-of-collateral condition for the PSM's users, analogous to draining `StoneBTCVault` of its valuable wrapped BTC.

### Likelihood Explanation
Reachable by any permissionless, signed account — no privileged role or governance action is needed to call `mint`/`redeem`. The precondition (a PSM instance with 2+ approved externals) is an explicitly documented, intended usage pattern of the pallet ("A PSM may approve multiple externals"), not a misconfiguration. On Westend today, only one external (USDT) has reportedly been added per `prdoc/stable2606/pr_11529.prdoc`, so exploitation there currently requires governance to add a second external asset — an ordinary, expected pallet operation rather than a compromise. Once a second external is approved (as the pallet design anticipates), the attack requires no special privilege and is bounded only by the size of the opposing debt bucket and the size/duration of the market depeg, both of which are realistic (stablecoin depegs of several percent have occurred, e.g., USDC during the March 2023 SVB event, far exceeding the pallet's ~1% round-trip fee).

### Recommendation
- Do not allow redemption into an external asset different from a price-consistent basket without an oracle-based, real-time valuation check, or restrict `redeem` to return the same external asset that was deposited per debt bucket only when there is a live depeg.
- Introduce a withdrawal delay or per-account cooldown between `mint` and `redeem` (mirroring the original report's recommendation) so that a same-block or short-window arbitrage across a transient depeg is not profitable.
- Consider dynamic, oracle-informed fees or circuit-breaker triggers tied to external asset price deviation, not just governance-configured static fees.

### Proof of Concept
No local Rust/FRAME integration test was executed; this is a code-level structural analog derived from reading `substrate/frame/psm/src/lib.rs` (storage layout, `mint`, `redeem`) and `prdoc/stable2606/pr_11529.prdoc`. The reasoning is grounded directly in the pallet's own mint/redeem dispatchables and `PsmDebt` storage definition cited above; I did not run a reproduction harness, and I could not verify from the index whether any deployed runtime currently has 2+ external assets approved on the same PSM instance (Asset Hub Westend's prdoc mentions only USDT as of this migration). Confirming live exploitability under the actual Snowbridge/Parity bounty program would require inspecting current on-chain `ExternalAssets`/`PsmDebt` storage for Asset Hub Westend and constructing a signed `mint`→`redeem` integration test using the existing `substrate/frame/psm/src/tests.rs` harness with two externals and a simulated price divergence — this was not run due to lack of further tool access in this session.

		pub fn mint(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			external_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_minting(), Error::<T>::MintingStopped);

			let ext_decimals = external.decimals;
			let internal_decimals = info.internal_decimals;

			let internal_equivalent =
				Self::external_to_internal(external_amount, ext_decimals, internal_decimals)?;
			ensure!(!internal_equivalent.is_zero(), Error::<T>::AmountTooSmallAfterConversion);
			ensure!(internal_equivalent >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let effective_external =
				Self::internal_to_external(internal_equivalent, ext_decimals, internal_decimals)?;

			let fee_rate = MintingFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_equivalent);
			let internal_to_user = internal_equivalent.saturating_sub(fee);

			let current_total_psm_debt = Self::total_psm_debt(&internal_asset);
			ensure!(
				current_total_psm_debt.saturating_add(internal_equivalent) <= info.max_debt,
				Error::<T>::ExceedsMaxPsmDebt
			);

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			let max_debt = Self::max_asset_debt(&internal_asset, &external_asset, &info);
			let new_debt = current_debt.saturating_add(internal_equivalent);
			ensure!(new_debt <= max_debt, Error::<T>::ExceedsMaxPsmDebt);

			let psm_account = Self::psm_account(&internal_asset);

			if !fee.is_zero() {

			}

		pub fn redeem(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			internal_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_redemption(), Error::<T>::AllSwapsStopped);

			let ext_decimals = external.decimals;
			let internal_decimals = info.internal_decimals;

			ensure!(internal_amount >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let fee_rate = RedemptionFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_amount);
			let internal_net = internal_amount.saturating_sub(fee);

			let external_out =
				Self::internal_to_external(internal_net, ext_decimals, internal_decimals)?;
			ensure!(
				internal_net.is_zero() || !external_out.is_zero(),
				Error::<T>::AmountTooSmallAfterConversion
			);
			// `effective_internal_net` is the internal value that round-trips to `external_out`;
			// it is what we actually burn and what the tracked debt decreases by. Any truncation
			// dust stays in the caller's internal balance, symmetric with `mint`, which takes
			// only the round-tripped share of the external amount.
			let effective_internal_net =
				Self::external_to_internal(external_out, ext_decimals, internal_decimals)?;

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			ensure!(current_debt >= effective_internal_net, Error::<T>::InsufficientReserve);

			let reserve = Self::get_reserve(&internal_asset, &external_asset);
			if reserve < external_out {
				defensive!("PSM reserve is less than expected output amount");
				return Err(Error::<T>::Unexpected.into());
			}
