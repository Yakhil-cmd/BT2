### Title
Governance vote of `kip71.gastarget = 0` causes division-by-zero panic in `NextMagmaBlockBaseFee`, halting all block processing - (File: `params/kip71_config.go`)

---

### Summary

The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, which accepts any `uint64` value including `0`. When `GasTarget = 0` is ratified via a governance vote and takes effect, every subsequent call to `NextMagmaBlockBaseFee` panics with a division-by-zero in Go's `big.Int.Div`, because `gasTarget` is used as a divisor without a zero-guard. This is called on every block during header validation, txpool updates, and block production, permanently halting the chain.

---

### Finding Description

The `Kip71GasTarget` parameter's `FormatChecker` is `noopFormatChecker`, which unconditionally returns `true` for any canonicalized `uint64` value: [1](#0-0) 

This means a governance vote of `kip71.gastarget = 0` passes all format and consistency checks and is ratified normally.

Once effective, `NextMagmaBlockBaseFee` is called every block. When `parentGasUsed > 0` (the normal case on a live network), execution enters the `parentGasUsed > gasTarget` branch (since any positive gas used exceeds 0). It then reaches:

```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // gasTarget == 0 → panic
``` [2](#0-1) 

Go's `(*big.Int).Div` panics on a zero divisor. There is an explicit zero-guard for `BaseFeeDenominator` (lines 71–76), but **no equivalent guard for `GasTarget`**: [3](#0-2) 

`NextMagmaBlockBaseFee` is called in at least two production paths:

1. **Block header validation** via `VerifyMagmaHeader` → `NextMagmaBlockBaseFee`: [4](#0-3) 

2. **Transaction pool reset** on every new head: [5](#0-4) 

---

### Impact Explanation

After the governance change takes effect (at the next epoch boundary), every node panics when processing any block where `parentGasUsed > 0`. Since virtually all blocks on a live network consume gas, this permanently halts block processing on all honest nodes. No new blocks can be validated or produced. This is an invalid state transition / consensus halt affecting the entire network.

---

### Likelihood Explanation

Low. The trigger requires the governing node (in `single` governance mode) to cast a vote of `kip71.gastarget = 0`, either maliciously or by operator error. The governing node is a semi-trusted party, not an unprivileged attacker. However, the vote passes all existing validation silently, with no warning or rejection.

---

### Recommendation

Add a non-zero check to the `FormatChecker` for `Kip71GasTarget`, mirroring the existing check for `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0  // GasTarget == 0 causes division-by-zero in NextMagmaBlockBaseFee
    },
    ...
},
``` [6](#0-5) 

Additionally, add a defensive zero-check inside `NextMagmaBlockBaseFee` itself (analogous to the existing `BaseFeeDenominator` guard) as defense-in-depth.

---

### Proof of Concept

1. Chain is running post-Magma with `governance.governancemode = "single"`.
2. The governing node calls `governance_vote("kip71.gastarget", uint64(0))`.
3. The vote passes `NewVoteData` (type check only), `FormatChecker` (`noopFormatChecker` → `true`), and `checkConsistency` (falls through to `return nil` at line 207).
4. At the next epoch block, the vote is ratified and written to `header.Governance`.
5. Starting from `(epoch+1)*epoch`, `GetParamSet` returns `GasTarget = 0`.
6. On the next block where `parentGasUsed > 0`, `NextMagmaBlockBaseFee` is called with `gasTarget = 0`. Execution enters the `parentGasUsed > gasTarget` branch and panics at `x.Div(x, new(big.Int).SetUint64(0))`.
7. All nodes crash. The chain halts. [7](#0-6) [8](#0-7)

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
