### Title
`add_tip`/`register_token` swap tip/fee assets to Ether with no slippage protection - ([File: bridges/snowbridge/pallets/system-frontend/src/lib.rs])

### Summary
`pallet-snowbridge-system-frontend`'s `add_tip` (and `register_token`) extrinsics let any signed user swap an arbitrary fee/tip asset into Ether via `pallet-asset-conversion`, but the swap is hardcoded to pass `None` for the minimum-output parameter, i.e. slippage protection is explicitly disabled by the pallet itself, not merely omitted by the caller.

### Finding Description
`add_tip` is a plain signed extrinsic — any account can call it with no privileged role: [1](#0-0) 

It calls `swap_fee_asset_and_burn`, which for any tip asset other than Ether calls `swap_and_burn`: [2](#0-1) 

`swap_and_burn` invokes the generic `Swap` trait's `swap_exact_tokens_for_tokens` (backed by `pallet_asset_conversion::do_swap_exact_tokens_for_tokens`) with the min-out argument hardcoded to `None`: [3](#0-2) 

In `pallet-asset-conversion`, when `amount_out_min` is `None`, the minimum-received check is skipped entirely: [4](#0-3) 

Contrast this with the pallet's own public `swap_exact_tokens_for_tokens` extrinsic, which always requires and enforces an explicit `amount_out_min`: [5](#0-4) 

This mirrors exactly the Kyber report's root cause: one code path (the AMM's own public entry point / position-manager-equivalent, here `AssetConversion::swap_exact_tokens_for_tokens`) enforces a minimum-received guard, while another path that performs the same underlying value-extracting operation (here, `swap_and_burn` used by `add_tip`/`register_token`) bypasses that guard entirely and has no parameter for the caller to express an acceptable minimum. The `ether_gained` returned from the unprotected swap is exactly what gets burned/teleported and reported to BridgeHub as the tip/fee amount credited to the relayer/registration — so any adverse price impact (thin liquidity, large tip relative to pool depth, or unfavorable pool state at execution time) directly and irreversibly reduces the value the user intended to spend, with the shortfall lost with no recourse.

### Impact Explanation
The caller cannot bound the amount of tip-asset value lost to price impact when it is converted to Ether for the Ethereum-side reward. In a thin or freshly-created pool, or when swap size is a non-trivial fraction of pool reserves, this can cause a large fraction of the tip to be wasted, while the full `fee_amount` is unconditionally withdrawn from the caller. This is a Medium-severity value-loss issue affecting individual users transacting through the bridge fee/tip mechanism (analogous in class and severity to the referenced Kyber finding), not a critical fund-theft or consensus-safety bug.

### Likelihood Explanation
Likelihood is limited by the precondition that the tip/fee asset differs from Ether and that the relevant AMM pool has non-trivial slippage at the requested swap size (thin liquidity, dust reserves, or normal price movement between submission and execution). No privileged role, governance action, or malicious peer is required — a normal user simply calling `add_tip` or `register_token` with a non-Ether fee asset in a real, unremarkable market condition is sufficient to trigger unbounded slippage exposure, since the pallet gives the caller no way to specify or verify an acceptable minimum.

### Recommendation
Add a caller-supplied minimum-ether-out (or minimum-tip-value) parameter to `add_tip` and `register_token`, and thread it through `swap_fee_asset_and_burn`/`swap_and_burn` into `T::Swap::swap_exact_tokens_for_tokens` instead of hardcoding `None`, so the swap fails (and can be retried) rather than silently completing at an unfavorable price.

### Proof of Concept
Not executed. This is a static-analysis analog derived from code inspection (no test harness run). Evidence supporting the finding:
- `swap_and_burn` explicitly comments "No minimum amount required" and passes `None` [6](#0-5) .
- `do_swap_exact_tokens_for_tokens` only performs the `amount_out >= amount_out_min` check when `Some` is supplied [4](#0-3) .
- `add_tip` is reachable by any `ensure_signed` origin with no additional authorization [7](#0-6) .

A concrete reproduction would require constructing a `pallet-asset-conversion` pool with low liquidity relative to the tip amount in the `system-frontend` pallet's mock/test runtime, calling `add_tip` with a tip asset that triggers meaningful price impact, and asserting `ether_gained` is materially below the amount obtainable at the pool's pre-trade spot price — this was not executed in this session, so failure/pass status is not asserted; it is provided as the concrete next verification step.

		/// teleportation. Returns the amount of Ether gained if successful, or a DispatchError if
		/// any step fails.
		fn swap_and_burn(
			origin: Location,
			tip_asset_location: Location,
			ether_location: Location,
			tip_amount: u128,
		) -> Result<u128, DispatchError> {
			// Swap tip asset to ether
			let swap_path = vec![tip_asset_location.clone(), ether_location.clone()];
			let who = T::AccountIdConverter::convert_location(&origin)
				.ok_or(Error::<T>::LocationConversionFailed)?;

			let ether_gained = T::Swap::swap_exact_tokens_for_tokens(
				who.clone(),
				swap_path,
				tip_amount,
				None, // No minimum amount required
				who,
				true,
			)?;

			// Burn the ether
			let ether_asset = Asset::from((ether_location.clone(), ether_gained));

			burn_for_teleport::<T::AssetTransactor>(&origin, &ether_asset)
				.map_err(|_| Error::<T>::BurnError)?;

			Ok(ether_gained)
		}

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}
