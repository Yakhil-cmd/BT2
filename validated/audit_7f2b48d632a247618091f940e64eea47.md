### Title
Aquarius LP oracle reads live, caller-malleable pool reserves — donation inflates LP collateral price inside the same transaction - (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
The `AquariusLp` price source resolves an LP share's USD value from the pool's *current* `get_reserves` and `total_shares` at the moment `prices` is invoked (`aquarius::read`, `aquarius.rs:90-114`). Analogous to the wasmd `module_query_safe` bug — where a query consumed non-deterministic, execution-context-dependent state — this oracle leg is a non-deterministic read: the same `PriceKey` returns different prices depending on transient reserves that the querying caller (or any unprivileged address) can shift inside the same transaction via direct token transfers to the pool contract. The fair-value formula `2 * sqrt(value_a * value_b) / total_shares` (`common/src/oracle/lp.rs:75-84`) is resistant to swaps (reserves and the share-free product move together), but not to donations, which raise both reserves while `total_shares` stays fixed.

### Finding Description
`aquarius::read` fetches `aquarius_pool_reserves_call` and `aquarius_total_shares_call` live from the pool and computes `fair_lp_price_wad` (`aquarius.rs:90-114`). Because the geometric-mean fair price scales with `sqrt(reserve_a * reserve_b)` while the denominator `total_shares` is unchanged by a donation, transferring extra tokens directly to the Aquarius pool inflates the reported LP share price by `sqrt(1 + donation/pool_value)` per leg — up to `sqrt(k)` for a `k`-multiple donation. There is no staleness, timestamp, or snapshot check on reserves; the only guards are `pool_value_wad >= min_pool_value_wad` (`aquarius.rs:118-122`, which a donation only *helps* satisfy) and the configured `[min_sanity_price_wad, max_sanity_price_wad]` band — which on the live mainnet config spans roughly 10x (`5356670329052813` to `53566703290528136`, `configs/ops/mainnet/1c352e...json`). For a single-source `AquariusLp` configuration the donated price flows straight into the controller's `Context.token_prices` (`context.rs:141-160`) and drives health factor / borrow-limit checks in `calculate_account_risk_totals`.

### Impact Explanation
An attacker who supplies LP shares as collateral can execute, in one transaction: (1) direct token transfers of both reserve assets to the Aquarius pool (in-scope per the rules), (2) `controller.borrow` against the now-inflated LP collateral valuation, then (3) unwind a swap to recover part of the donation, or redeem their existing LP position which now embeds the donated value. If the attacker is a large LP holder, most of the donation is recaptured through their own shares, making net cost small while borrowed proceeds are kept. This is theft of pool funds via over-borrowing; residual bad debt can also force `clean_bad_debt`/index write-down on honest suppliers.

### Likelihood Explanation
Reachable by any unprivileged address holding LP collateral, using only token transfers plus `borrow`. Magnitude is bounded by the sanity band and by the sqrt cost curve (2x price requires ~3x pool value donated), and by the attacker's ability to recapture the donation — real but capital-dependent, consistent with Medium severity.

### Recommendation
Snapshot or bound the mutable inputs: read reserves through a committed/TWAP-style interface if Aquarius exposes one, or track a protocol-side rolling observation; additionally enforce a per-leg deviation bound between successive reads and tighten `min_sanity/max_sanity` for LP keys, and reject reserve/supply readings whose implied pool value jumps materially within a short window.

### Proof of Concept
1. Attacker acquires Aquarius LP shares for a pool listed as `AquariusLp` collateral and supplies them via `controller.supply`.
2. In one transaction, an attacker contract: (a) `TokenClient::transfer` large amounts of `token_a` and `token_b` directly to `lp.pool` (no shares minted, `total_shares` unchanged); (b) calls `controller.borrow` — `Context::fetch_prices` → `PriceAggregator::prices` → `aquarius::read` reads the inflated reserves, reporting an LP price up to `sqrt(k)`× fair, still inside the 10x sanity band; borrow proceeds are paid out; (c) swaps back through the pool and/or redeems pre-held LP shares to recover most of the donation, leaving the lending pool with under-collateralized debt.
