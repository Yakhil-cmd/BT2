### Title
RAY value overflow during interest accrual permanently freezes a high-balance market - (File: common/src/rates/simulate.rs)

### Summary
XOXNO Lending stores market supply and debt as index-scaled RAY shares. Every accrual step first reconstructs the unscaled totals with `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)` [1](#0-0) . Those products are bounded by `i128`, while the borrow-index ceiling is a separate bound applied only after calculating the new index [2](#0-1) . A sufficiently large market can therefore cross the RAY-value ceiling before the index cap is reached.

Once that happens, `scaled_to_original` panics with `MathOverflow` through `Ray::mul` [3](#0-2) . Because accrual runs before market mutations, the affected market can no longer repay, withdraw, liquidate, or process another index update. The permissionless `update_indexes` entrypoint reaches this state directly after enough time has elapsed [4](#0-3) .

### Finding Description
The pool’s mutating accrual path calls `accrue_step` for each elapsed interval chunk [5](#0-4) . The step calculates:

```rust
let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
let supplied_original = scaled_to_original(env, supplied, supply_index);
``` [6](#0-5) 

`scaled_to_original` multiplies scaled RAY shares by the RAY index [3](#0-2) . For example, one billion whole units of an 18-decimal token is `1e9 * 10^18 = 1e27` token units, or `1e36` RAY. A borrow index above approximately `170x` makes `borrowed * borrow_index / RAY` exceed `i128::MAX`.

The index cap does not prevent this condition. `update_borrow_index` computes `old_index.mul(interest_factor)` and only then clamps the resulting index to `MAX_BORROW_INDEX_RAY` [2](#0-1) . It does not bound `borrowed * borrow_index`; the earlier valuation overflows before the capped index can restore a safe state.

The public call chain is:

```text
Controller.update_indexes(caller, [hub_asset])
  -> markets::update_indexes
  -> LiquidityPool.update_indexes
  -> ops::market::accrue
  -> interest::global_sync
  -> accrue_step
  -> scaled_to_original
  -> MathOverflow
```

The controller method is permissionless apart from caller authorization [4](#0-3) , forwards the supplied `HubAssetKey` list to the pool [7](#0-6) , and the pool applies accrual to each requested market [8](#0-7) .

### Impact Explanation
This is a permanent freezing-of-funds condition for the affected market. After `borrowed * borrow_index` or `supplied * supply_index` exceeds the `i128` result domain, the next accrual reverts. Since repayment, withdrawal, liquidation, and further index updates all depend on accrual first, suppliers cannot exit, borrowers cannot reduce debt, and liquidators cannot clear the position through the normal pool paths.

The condition is not merely a transient arithmetic rejection that can be bypassed with a smaller amount. The overflowing value is the market total, not an attacker-controlled per-call amount, so splitting withdrawals or repayments does not avoid it. Even a dust repayment requires `global_sync` before the debt burn and reaches the same panic [9](#0-8) .

### Likelihood Explanation
Triggering the condition requires a very large listed market and enough collateral for a large borrow, followed by sustained high-utilization accrual. It is therefore capital-intensive, but no privileged call, oracle manipulation, leaked key, malformed token, or off-chain service is required once a market configuration permits the balances.

A whale can create the state using ordinary `supply` and `borrow` calls, and any authorized account can later call `update_indexes(caller, vec![hub_asset])`. The repository’s long-horizon test demonstrates this exact sequence: one billion whole 18-decimal tokens supplied, approximately 98% borrowed, then repeated yearly index updates until `update_indexes`, `withdraw`, and `repay` all fail with `MATH_OVERFLOW` while the borrow index remains below `MAX_BORROW_INDEX_RAY` [10](#0-9) .

### Recommendation
Bound market totals by their accrued RAY value rather than only bounding the indexes. In particular:

- Enforce a per-market `borrowed` and `supplied` scaled-share ceiling that guarantees `scaled * MAX_INDEX / RAY` remains representable.
- Alternatively, make accrual use widened value arithmetic for `borrowed * borrow_index` and `supplied * supply_index`, while preserving explicit caps on stored values.
- Check the value ceiling before admitting a borrow or supply that can leave no representable accrued value under the configured index ceiling.
- Add a fail-safe recovery path for a market already at the cliff that does not require evaluating the overflowing total before allowing repayment or socialized wind-down.

The market caps must account for both indexes and token decimals; the representable token-unit maximum alone is insufficient because index growth later multiplies the scaled total [11](#0-10) .

### Proof of Concept
Conceptual transaction sequence for an 18-decimal market configured with a steep high-utilization rate curve and sufficiently high caps:

```rust
// 1. Supplier provides approximately 1e9 whole tokens:
supply(bob, account_id, spoke_id, vec![
    (big18_key, 1_000_000_000 * 10i128.pow(18))
]);

// 2. Borrower supplies enough collateral and borrows ~98% utilization:
supply(alice, account_id, spoke_id, vec![
    (collateral_key, sufficient_collateral)
]);
borrow(alice, account_id, vec![
    (big18_key, 980_000_000 * 10i128.pow(18))
], None);

// 3. Wait for index growth and call the permissionless entrypoint:
update_indexes(anyone, vec![big18_key]);
```

When `borrowed * borrow_index` exceeds `i128::MAX`, `accrue_step` reverts inside `scaled_to_original` before the borrow-index cap can take effect. Subsequent calls such as:

```rust
update_indexes(anyone, vec![big18_key]);
repay(anyone, borrower_account, vec![(big18_key, 1)]);
withdraw(bob, supplier_account, vec![(big18_key, 1)], None);
```

all perform market accrual first and hit the same `MathOverflow`. The repository’s `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` test encodes this scenario and asserts that index update, withdrawal, and repayment all fail after the cliff [12](#0-11) .

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
