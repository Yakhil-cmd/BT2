### Title
Webhook signature verification is scoped to `repository.owner.login`, but repository/stack targeting is scoped to `repository.full_name` — allows unauthenticated cross-organization webhook forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App/organization secret to validate the incoming `X-Hub-Signature` against by reading `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`). Every downstream webhook handler, however, resolves the actual `Repository`/`Stack` to act on from a *different* JSON field: `params.dig('repository', 'full_name')`. Because these two fields are never cross-validated, an attacker can pick an organization that is configured without a `webhook_secret` (an explicitly documented, optional setting) to satisfy signature verification, while setting `repository.full_name` to point at a repository belonging to an entirely different, properly-secured organization.

### Finding Description
`verify_signature` uses `repository_owner` only to select the `GitHubApp` instance used for HMAC verification: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` trivially passes when that organization's `webhook_secret` is blank/absent: [3](#0-2) 

This is a supported, documented configuration — the setup guide and multi-org fixture both show `webhook_secret` as optional/nil per-organization: [4](#0-3) [5](#0-4) 

Meanwhile, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches the **entire** raw payload to handlers, unfiltered by which organization was used for verification: [6](#0-5) 

Every handler's target repository/stack lookup is keyed off `repository.full_name`, not `repository.owner.login`: [7](#0-6) [8](#0-7) [9](#0-8) 

`Shipit.github(organization:)` resolves per-org config strictly by name lookup, with no relation whatsoever enforced between the organization used for auth and the organization embedded in `full_name`: [10](#0-9) 

**Binding broken:** organization that authenticated (`repository.owner.login`, used to pick the verifying `webhook_secret`) ≠ repository that is written (`repository.full_name`, used by `Repository.from_github_repo_name` and every handler to resolve the `Stack` acted upon). The payload carries two independent identifiers, only one of which is covered by the signature-selection logic, and the raw signature — when it exists — covers the full raw body, but when the selected org has *no* secret configured, no signature coverage exists at all for that request, regardless of what `full_name` claims.

### Impact Explanation
In a documented multi-organization Shipit deployment (`secrets.github` keyed by org name, as shown in `secrets_double_github_app.yml`), if any single organization is configured without a `webhook_secret` (explicitly optional per `docs/setup.md`), an unprivileged network attacker can:
1. Craft a webhook payload with `repository.owner.login` set to the secret-less organization (so `verify_webhook_signature` returns `true` unconditionally).
2. Set `repository.full_name` to `"<protected-org>/<repo>"`, targeting a stack belonging to a different, properly secured organization.
3. POST this to `/webhooks` with the `push` event header (or `pull_request`, `status`, `check_suite`) — no valid `X-Hub-Signature` is required.

This triggers `Handlers::PushHandler#process`, which calls `stack.sync_github(expected_head_sha: params.after)` on the targeted stack of the *protected* organization, forcing an unauthorized deploy-relevant repository sync, or manipulates pull-request/review-stack state and commit statuses cross-organization. This is a cross-repository, cross-organization action triggered without ever possessing the target organization's actual webhook secret — an unauthorized write/sync spanning trust boundaries the app is supposed to enforce.

### Likelihood Explanation
Requires only network access to the public `/webhooks` endpoint and knowledge that the deployment hosts multiple GitHub orgs where at least one has no `webhook_secret` configured (a state explicitly permitted by Shipit's own setup documentation and test fixtures, not an application misconfiguration outside the documented design). No authentication, session, or API token is needed.

### Recommendation
Enforce that the field used to select the verifying GitHub App (`repository.owner.login` / `organization.login`) equals the organization embedded in `repository.full_name` before dispatching to handlers; reject the request otherwise. Additionally, consider requiring a non-empty `webhook_secret` for every configured organization, or making `verify_webhook_signature` fail closed instead of returning `true` when no secret is configured, so signature-less orgs cannot be used as a bypass anchor for payloads targeting other orgs' repositories.

### Proof of Concept
```
POST /webhooks
X-Github-Event: push
(no valid X-Hub-Signature required)

{
  "ref": "refs/heads/master",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "owner": { "login": "org-without-secret" },
    "full_name": "protected-org/protected-repo"
  }
}
```
`verify_signature` resolves `Shipit.github(organization: "org-without-secret")`, whose `webhook_secret` is nil, so `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-83`). `PushHandler` then resolves `Repository.from_github_repo_name("protected-org/protected-repo")` and calls `stack.sync_github` on that stack, entirely bypassing `protected-org`'s actual webhook secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
