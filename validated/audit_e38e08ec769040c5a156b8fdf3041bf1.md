### Title
Webhook signature check binds to `repository.owner.login`, but repository resolution/write binds to `repository.full_name` — cross-organization webhook forgery when any configured org lacks a `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
In multi-organization Shipit deployments, the webhook authenticity check is keyed on `repository.owner.login` (or `organization.login`), while the actual state-mutating action (finding the `Repository`/`Stack` to sync) is keyed on the independent `repository.full_name` field of the same attacker-supplied JSON body. Because `GitHubApp#verify_webhook_signature` treats a missing/blank `webhook_secret` as "always verified", any org configured without a webhook secret becomes a skeleton key: an attacker can submit an unsigned/forged payload claiming to be from that org while pointing `repository.full_name` at a totally different, victim organization's repository, and Shipit will act on it.

### Finding Description
`WebhooksController#verify_signature` selects which GitHub App config (and therefore which HMAC secret) is used to authenticate the request based on a value pulled from the attacker-controlled JSON body: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` resolves the org-specific `GitHubApp`, and signature verification is delegated to it: [3](#0-2) 

Critically, `verify_webhook_signature` returns `true` unconditionally when that org's `webhook_secret` is blank/unset (`return true unless webhook_secret`). The setup docs and multi-org config templates explicitly allow `webhook_secret` to be `nil` per organization: [4](#0-3) [5](#0-4) 

Once the request clears `verify_signature` (i.e., the request is treated as authenticated because the *claimed* org has no secret), the full raw JSON is dispatched to handlers unmodified: [6](#0-5) 

But the handlers never re-check that `repository.owner.login` (used for authentication) matches the repository they act on. Instead, they resolve the target `Repository`/`Stack` purely from `repository.full_name`: [7](#0-6) [8](#0-7) 

This is the broken binding: the engine verifies **"organization referenced by `repository.owner.login`/`organization.login`"** but writes to **"repository referenced by `repository.full_name`"**, with nothing enforcing `repository.full_name.split('/').first == repository.owner.login`.

### Impact Explanation
An attacker who knows (or guesses) that any organization configured in `secrets.yml`'s multi-org `github:` block has a blank `webhook_secret` (a state explicitly supported and documented) can forge a `push` webhook body where:
- `repository.owner.login` / `organization.login` = the unsecured org (bypasses signature check entirely)
- `repository.full_name` = `"victim-org/victim-repo"` (any repository actually tracked by Shipit under a *different*, secured org)

The forged, completely unsigned request is treated as authenticated, and `PushHandler#process` looks up stacks for `victim-org/victim-repo` and calls `stack.sync_github(expected_head_sha: params.after)`, which can trigger `GithubSyncJob` and, for stacks with continuous deployment enabled, an unauthorized deploy of an attacker-chosen commit SHA on a repository the attacker has no access to and no valid signature for. This is a cross-organization/cross-repository write and an unauthorized deploy path, matching the required Critical impact category.

### Likelihood Explanation
This requires only that the Shipit deployment use the multi-organization `github:` config format (explicitly documented and supported) and that at least one configured organization has no `webhook_secret` set — a state the example configs (`config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`) show as normal/default (`webhook_secret: # nil`). No GitHub App credentials, `ApiClient` token, or repository write access are needed; the attacker only needs unauthenticated HTTP access to the public `/webhooks` endpoint. This is a realistic configuration, not a hypothetical misconfiguration outside the engine's own logic, since the engine's own docs recommend/permit an optional webhook secret per org.

### Recommendation
Bind the two checks together: `verify_signature` should be evaluated using the same `GitHubApp` that is authoritative for the repository the payload will actually act on (derived from `repository.full_name`'s owner segment, not a value that may diverge from it), and/or the handlers should reject any payload where `repository.owner.login` does not match the first segment of `repository.full_name`. Additionally, `GitHubApp#verify_webhook_signature` returning `true` for orgs without a configured secret should be reconsidered — at minimum, cross-check that the resolved organization for authentication matches the organization implied by the acted-upon repository.

### Proof of Concept
Preconditions: Shipit configured with multi-org `github:` block containing `OrgWithNoSecret` (no `webhook_secret`) and `VictimOrg` (has a repo tracked as a Shipit stack, e.g. `VictimOrg/prod-app`, with `continuous_deployment: true`).

```
POST /webhooks HTTP/1.1
X-Github-Event: push
Content-Type: application/json

{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha-that-exists-in-victim-repo>",
  "repository": {
    "full_name": "VictimOrg/prod-app",
    "owner": { "login": "OrgWithNoSecret" }
  }
}
```

- No `X-Hub-Signature` header (or any garbage value) is required.
- `repository_owner` resolves to `OrgWithNoSecret`; `Shipit.github(organization: 'OrgWithNoSecret').verify_webhook_signature` returns `true` because `webhook_secret` is blank.
- `PushHandler` resolves `Repository.from_github_repo_name('VictimOrg/prod-app')` and calls `stack.sync_github(expected_head_sha: ...)`, triggering a sync/deploy job for `VictimOrg`'s stack despite the request never being signed by `VictimOrg`'s GitHub App.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
