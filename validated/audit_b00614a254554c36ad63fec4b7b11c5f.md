### Title
Webhook signature check is keyed on `repository.owner.login`/`organization.login` while dispatch acts on the unauthenticated `repository.full_name`, allowing unsigned/forged events to be replayed against any trusted stack - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks the GitHub App/organization used for HMAC verification from `params.dig('repository', 'owner', 'login')` (or `organization.login`), but `Handler#stacks` later resolves the actual target repository from the completely independent `repository.full_name` field of the same payload. If any configured organization in `Shipit.github` lacks a `webhook_secret` (which the docs explicitly list as optional — `github.webhook_secret` "optional"), `verify_webhook_signature` returns `true` unconditionally for that organization, regardless of the actual `X-Hub-Signature` header supplied.

### Finding Description
- Verification binding: `organization authenticated == organization.login used for HMAC lookup`, but the binding actually enforced by the rest of the pipeline is `organization authenticated == repository the handler acts on`. These are two different payload fields never cross-checked.
- `verify_signature` computes `repository_owner` from `repository.owner.login`/`organization.login` [3](#0-2) , fetches `Shipit.github(organization: repository_owner)`, and checks the signature with that org's secret [2](#0-1) .
- `create` then dispatches the **entire raw params** (not scoped to the verified organization) to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [5](#0-4) .
- Handlers resolve the affected `Stack`/`Repository` solely via `repository.full_name`, an entirely separate field never used in the signature check: `Repository.from_github_repo_name(repository_name)` where `repository_name = payload.dig('repository', 'full_name')` [1](#0-0) .
- If any organization configured in `Shipit.github` has no `webhook_secret` set (documented as optional in `docs/setup.md`, and defaulted to `nil` in the sample secrets files such as `config/secrets.development.shopify.yml`), then for a payload whose `repository.owner.login`/`organization.login` names that organization, `verify_webhook_signature` returns `true` unconditionally: `return true unless webhook_secret` [6](#0-5) .
- An unprivileged attacker can therefore submit a POST to `/webhooks` with an arbitrary/garbage `X-Hub-Signature`, set `repository.owner.login` (or `organization.login`) to the no-secret organization's name to bypass verification, while setting `repository.full_name` to the full name of a *different, secret-protected* repository/stack that is actually deployed by Shipit. The handler dispatch never re-checks that the two identities match.

### Impact Explanation
This breaks the deployment-trust binding "organization authenticated" vs "repository the payload acts on." Depending on the event handled, this can trigger unauthorized state changes on a protected stack without possessing its webhook secret: e.g., `PushHandler` calls `stack.sync_github(expected_head_sha: params.after)` on stacks resolved from the attacker-controlled `full_name` [7](#0-6) , and other handlers (status, check_suite, membership, pull_request/closed, merge, etc.) similarly act on the resolved stack/commit without confirming the authenticated organization matches. This can influence merge-queue/deploy state and is best characterized as an authentication-bypass class issue, though the concrete blast radius depends on which handler is targeted (e.g., `check_run`/`status`/`push` can affect mergeability and sync state of a stack the attacker doesn't own).

### Likelihood Explanation
Requires: (a) the Shipit installation to have at least one organization configured under `Shipit.github` without a `webhook_secret` — a state the app's own setup documentation explicitly allows ("Webhook secret (optional)") — and (b) knowledge of that organization's login name, which is not secret. No credentials, tokens, or GitHub App keys are needed; the request is a plain unauthenticated POST to the public `/webhooks` endpoint. This is a realistic misconfiguration in multi-organization deployments (`docs/setup.md` "Using Multiple GitHub Applications" section explicitly shows per-org `webhook_secret` that can be left blank for some orgs while others are protected).

### Recommendation
Bind the verification identity to the same field used for dispatch: verify the signature using the webhook secret associated with `repository.full_name`'s owner (or reject if `repository.full_name` and the authenticated `repository_owner`/`organization.login` disagree), and do not allow a "no secret configured" organization to implicitly authenticate payloads targeting a different, secret-protected organization's repositories. Consider also requiring a webhook secret unconditionally in production rather than defaulting to open verification when unset.

### Proof of Concept
1. Configure `Shipit.github` with two orgs: `trusted-org` (has `webhook_secret` set, owns the protected stack `trusted-org/app`) and `open-org` (no `webhook_secret`, per docs' "optional" setting).
2. POST to `/webhooks` with header `X-Github-Event: push`, an arbitrary/invalid `X-Hub-Signature`, and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker chosen sha>",
  "repository": {
    "owner": { "login": "open-org" },
    "full_name": "trusted-org/app"
  }
}
```
3. `verify_signature` resolves `repository_owner = "open-org"`, fetches its `GithubApp`, and `verify_webhook_signature` returns `true` unconditionally because `open-org` has no `webhook_secret` [6](#0-5) .
4. `create` dispatches full `params` to `PushHandler`, which resolves the stack via `repository.full_name = "trusted-org/app"` [8](#0-7)  and calls `stack.sync_github(expected_head_sha: params.after)` [9](#0-8)  on the protected `trusted-org/app` stack, despite never presenting a valid signature for `trusted-org`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
