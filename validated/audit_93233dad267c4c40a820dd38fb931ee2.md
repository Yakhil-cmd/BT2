## Analog Found: `pallet-asset-rewards` `harvest_rewards` sends reward tokens directly to the staker with no alternate-recipient fallback, permanently trapping rewards (and blocking pool cleanup) if the staker's asset account is `Blocked`

### Title
Unharvestable reward tokens permanently trapped and pool cleanup permanently blocked when a staker's `reward_asset_id` account is `Blocked` in `pallet-asset-rewards::harvest_rewards` - (File: `substrate/frame/asset-rewards/src/lib.rs`)

### Summary
`pallet-asset-rewards` lets a permissioned `CreatePoolOrigin` create an incentive pool using **arbitrary** `pallet-assets` asset IDs for both the staked asset and the reward asset [1](#0-0) . `pallet-assets` natively supports a freezer-controlled `block()` extrinsic that sets an account's `AccountStatus::Blocked`, which makes both incoming and outgoing transfers fail with `Frozen`/`TokenError::Blocked` [2](#0-1) [3](#0-2) .

Unlike the reported Solidity issue, the **staked principal** in `pallet-asset-rewards` is never custodied by a pool-owned transfer: `stake`/`unstake` only place/remove a `Freeze` on the staker's own account via `T::AssetsFreezer` [4](#0-3) [5](#0-4) , so `unstake` always succeeds regardless of the staker's account status for the staked asset. However, **accrued rewards** are held in a separate pool-pot account and only leave it via a direct `T::Assets::transfer(reward_asset_id, pool_account, staker, rewards, Expendable)` inside `harvest_rewards`, always addressed to the `staker`/optional target account with no way to redirect to another recipient [6](#0-5) .

### Finding Description
1. A pool creator (`T::CreatePoolOrigin`, not the staker) creates a reward pool where `reward_asset_id` is a `pallet-assets` asset whose freezer/admin has `block()` capability (e.g., a stablecoin-style asset mirroring the real-world USDC/USDT blacklist pattern referenced in the original report) [1](#0-0) .
2. A normal, unprivileged staker calls `stake` (a permitted signed extrinsic) and begins accruing rewards [7](#0-6) .
3. At some point, the reward asset's freezer calls `Assets::block(origin, reward_asset_id, staker)` — this is an ordinary, already-existing `pallet-assets` capability, not an attack, exactly analogous to a USDC-style blacklist action against the staker's address [2](#0-1) .
4. The staker calls `harvest_rewards`. `T::Assets::transfer` to the now-`Blocked` staker account fails with `TokenError::Blocked` (mirrored by the existing test `transferring_to_blocked_account_should_not_work`) [3](#0-2) , so `harvest_rewards` returns an error and the accrued `rewards` value in `PoolStakers` is never cleared (the `staker_info.rewards = 0` reset only happens after the transfer succeeds) [8](#0-7) .
5. The staker can still call `unstake` (it only decreases the freeze, no transfer to a possibly-blocked account) [9](#0-8) , but because `unstake` only removes the `PoolStakers` entry when **both** `amount` and `rewards` are zero [10](#0-9) , a fully-unstaked-but-still-owed-rewards staker permanently occupies a `PoolStakers` entry.
6. `cleanup_pool` — the only path by which the pool admin can retrieve unused reward tokens and free the pool's storage deposit — explicitly requires `PoolStakers::<T>::iter_key_prefix(pool_id).next()` to be `None`, i.e., **zero remaining stakers** [11](#0-10) . As long as the blocked staker's dangling reward entry exists, `cleanup_pool` returns `Error::<T>::NonEmptyPool` forever, even for the pool admin.

### Impact Explanation
The accrued reward tokens owed to the blocked staker are permanently unreachable by that staker (no alternate-recipient parameter exists on `harvest_rewards`), and — beyond the individual loss analogous to the reported Medium — the entire pool becomes **permanently un-cleanable**: the admin can never reclaim the pool's leftover reward-asset balance or its storage `Consideration` deposit via `cleanup_pool`, since the check is a strict "no stakers at all" gate with no override for stuck/blocked stakers. This is a deterministic, irreversible storage/fund lock triggered without any privileged action by the staker or an attacker — the root cause matches the report's invariant violation (unconditional transfer-to-recipient with no fallback path when the recipient token account is administratively blocked).

### Likelihood Explanation
Likelihood is Medium, matching the accepted-Medium severity in the original report and requiring a legitimate real-world precondition (the reward asset uses `pallet-assets`' `block`/freezer functionality, e.g., a compliance-blacklisted asset used as a reward token) rather than any privileged exploit by the staker. No governance, root, or stolen-key action is needed by the "attacker" side — only the ordinary, documented `Assets::block` capability already exercised in the pallet's own test suite [3](#0-2) .

### Recommendation
- Add a `beneficiary: Option<T::AccountId>` parameter to `harvest_rewards` allowing the staker (or an authorized delegate) to redirect the reward transfer to an unblocked account, analogous to the Hats report's suggested fix of parameterizing the recipient in `unstake`.
- Decouple `PoolStakers` cleanup from successful reward transfer: allow zeroing/dropping the `rewards` field (e.g., via an admin-only "force settle to a designated escrow/burn account" call) so a single unresponsive/blocked staker cannot permanently block `cleanup_pool` for the whole pool.
- Consider relaxing `cleanup_pool`'s `NonEmptyPool` gate to tolerate stakers with `amount == 0` regardless of outstanding, unclaimable `rewards`, with those rewards written off to a defined sink instead of blocking cleanup indefinitely.

### Proof of Concept
Not executed against a live network; based on static code reading and existing repository unit tests establishing each guard's behavior:
- `transferring_to_blocked_account_should_not_work` proves `Assets::transfer` to a `Blocked` account returns `TokenError::Blocked` [3](#0-2) .
- `harvest_rewards`'s only reward-payout path is the unconditional `T::Assets::transfer(... &staker ...)` [6](#0-5) , with no fallback.
- `cleanup_pool`'s `ensure!(stakers.is_none(), Error::<T>::NonEmptyPool)` gate [12](#0-11)  combined with `unstake`'s conditional `PoolStakers::remove` only when `rewards.is_zero()` [10](#0-9)  together establish the permanent-lock chain.
A minimal FRAME integration test to confirm end-to-end (not run here) would: create a pool with a `pallet-assets` reward asset, `stake`, accrue rewards, `Assets::block` the staker for the reward asset, assert `harvest_rewards` returns `Err`, `unstake` fully, then assert `cleanup_pool` by the admin returns `Error::<T>::NonEmptyPool` indefinitely. This was not executed; the guard logic and test precedents above are cited as static evidence rather than a live/mocked run result.

		pub fn stake(origin: OriginFor<T>, pool_id: PoolId, amount: T::Balance) -> DispatchResult {
			let staker = ensure_signed(origin)?;

			// Always start by updating staker and pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			T::AssetsFreezer::increase_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_add_assign(amount)?;

			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_add_assign(amount)?;
			PoolStakers::<T>::insert(pool_id, &staker, staker_info);

			// Emit event.
			Self::deposit_event(Event::Staked { staker, pool_id, amount });

			Ok(())
		}

		/// Unstake tokens from a pool.
		///
		/// Removes the freeze on the staked tokens.
		///
		/// Parameters:
		/// - origin: must be the `staker` if the pool is still active. Otherwise, any account.
		/// - pool_id: the pool to unstake from.
		/// - amount: the amount of tokens to unstake.
		/// - staker: the account to unstake from. If `None`, the caller is used.
		#[pallet::call_index(2)]
		pub fn unstake(
			origin: OriginFor<T>,
			pool_id: PoolId,
			amount: T::Balance,
			staker: Option<T::AccountId>,
		) -> DispatchResult {
			let caller = ensure_signed(origin)?;
			let staker = staker.unwrap_or(caller.clone());

			// Always start by updating the pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let now = T::BlockNumberProvider::current_block_number();
			ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin);

			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			// Check the staker has enough staked tokens.
			ensure!(staker_info.amount >= amount, Error::<T>::NotEnoughTokens);

			// Unfreeze staker assets.
			T::AssetsFreezer::decrease_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_sub_assign(amount)?;
			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_sub_assign(amount)?;

			if staker_info.amount.is_zero() && staker_info.rewards.is_zero() {
				PoolStakers::<T>::remove(&pool_id, &staker);
			} else {
				PoolStakers::<T>::insert(&pool_id, &staker, staker_info);
			}

			// Emit event.
			Self::deposit_event(Event::Unstaked { caller, staker, pool_id, amount });

			Ok(())
		}

		#[pallet::call_index(8)]
		pub fn cleanup_pool(origin: OriginFor<T>, pool_id: PoolId) -> DispatchResult {
			let who = ensure_signed(origin)?;

			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			ensure!(pool_info.admin == who, BadOrigin);

			let stakers = PoolStakers::<T>::iter_key_prefix(pool_id).next();
			ensure!(stakers.is_none(), Error::<T>::NonEmptyPool);

			let pool_balance = T::Assets::reducible_balance(
				pool_info.reward_asset_id.clone(),
				&pool_info.account,
				Preservation::Expendable,
				Fortitude::Polite,
			);
			T::Assets::transfer(
				pool_info.reward_asset_id,
				&pool_info.account,
				&pool_info.admin,
				pool_balance,
				Preservation::Expendable,
			)?;

			if let Some((who, cost)) = PoolCost::<T>::take(pool_id) {
				T::Consideration::drop(cost, &who)?;
			}

			Pools::<T>::remove(pool_id);

			Self::deposit_event(Event::PoolCleanedUp { pool_id });

			Ok(())
		}

		pub fn block(
			origin: OriginFor<T>,
			id: T::AssetIdParameter,
			who: AccountIdLookupOf<T>,
		) -> DispatchResult {
			let origin = ensure_signed(origin)?;
			let id: T::AssetId = id.into();

			let d = Asset::<T, I>::get(&id).ok_or(Error::<T, I>::Unknown)?;
			ensure!(
				d.status == AssetStatus::Live || d.status == AssetStatus::Frozen,
				Error::<T, I>::IncorrectStatus
			);
			ensure!(origin == d.freezer, Error::<T, I>::NoPermission);
			let who = T::Lookup::lookup(who)?;

			Account::<T, I>::try_mutate(&id, &who, |maybe_account| -> DispatchResult {
				maybe_account.as_mut().ok_or(Error::<T, I>::NoAccount)?.status =
					AccountStatus::Blocked;
				Ok(())
			})?;

			Self::deposit_event(Event::<T, I>::Blocked { asset_id: id, who });
			Ok(())
		}
