### Title
Multi-organization `webhook_secret` misconfiguration lets an attacker forge webhooks for any repository via the `X-Github-Event`/`repository.owner.login` vs `repository.full_name` binding mismatch - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which organization's HMAC secret to check against using `repository_owner`, which is read from the payload's `repository.owner.login` (falling back to `organization.login`). The handler code that actually acts on the payload (`Shipit::Webhooks::Handlers::Handler#repository_name`, and all handlers such as `PushHandler`) instead uses a *different* field, `repository.full_name`, to look up the `Repository`/`Stack` that will be mutated. Because both fields are attacker-controlled JSON in the raw POST body and are never cross-validated against each other, the "organization whose secret authenticated the request" and "the repository that is actually written to" are two independently forgeable values.

### Finding Description
`verify_signature` in `app/controllers/shipit/webhooks_controller.rb` does: [1](#0-0) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
```

`repository_owner` is: [2](#0-1) 

i.e. it is derived from `params.dig('repository', 'owner', 'login')` — a field inside the same attacker-supplied JSON body.

`GitHubApp#verify_webhook_signature` in `lib/shipit/github_app.rb` returns `true` unconditionally when no `webhook_secret` is configured for that organization: [3](#0-2) 

This engine explicitly supports multi-organization GitHub App configuration where `webhook_secret` may be unset per-org (see the fixture `test/dummy/config/secrets_double_github_app.yml`, where `OrgOne` and `OrgTwo` both declare `webhook_secret:` with no value), selected via `lib/shipit.rb#github_app_config`.

Meanwhile, every webhook handler resolves the repository/stack to mutate using a completely separate JSON field, `repository.full_name`, not `repository.owner.login`: [4](#0-3) 

and e.g. `PushHandler`: [5](#0-4) 

Because `repository.owner.login` (used only to pick the signing org) and `repository.full_name` (used to pick the affected `Repository`/`Stack`) are independent, attacker-controlled keys in the same unauthenticated request body, an attacker can name an organization with no configured `webhook_secret` in `owner.login`/`organization.login` (to trivially pass `verify_signature`) while setting `repository.full_name` to any other org/repo string that has a real `Stack` provisioned in Shipit.

**Binding broken:** `organization authenticated by verify_signature` **≠** `repository/stack actually written to by the handler`.

### Impact Explanation
If the deployment has *any* GitHub App organization configured without a `webhook_secret` (which the engine's own multi-org fixture demonstrates as a supported configuration shape), an unauthenticated attacker can craft an arbitrary JSON body, set `X-Github-Event: push` (or `check_suite`, `pull_request`, etc.), set `organization.login`/`repository.owner.login` to the secret-less org, and set `repository.full_name` to any tracked repository. `verify_signature` short-circuits to `true` for that request (no secret exists to check against), and the handler then acts on the named repository's stacks: e.g. `PushHandler` enqueues `stack.sync_github(expected_head_sha: ...)`, and PR handlers can archive/unarchive/create review stacks for repositories the attacker does not own and never presented a valid signature for. This is a cross-repository write triggered without any credential for the targeted repository, i.e. an unauthorized action on a stack the attacker has no authority over.

### Likelihood Explanation
This requires the operator to have configured at least one GitHub organization/App without a `webhook_secret` while other organizations' repos are tracked in the same Shipit instance — a configuration explicitly exercised by this engine's own test fixture (`secrets_double_github_app.yml`), so it is a realistic, engine-endorsed configuration shape rather than a purely theoretical one. It requires no privileged access, no `webhook_secret`, and no session — only knowledge of one organization's login string that lacks a secret.

### Recommendation
Verify the webhook signature using the *same* field that the handlers subsequently trust for repository resolution (`repository.full_name`, or better, look up the `Repository`/`Stack`'s configured organization/secret directly rather than trusting an attacker-supplied `owner.login`/`organization.login` field to select which secret to check against). Additionally, disallow (or emit an error for) organization configurations that omit `webhook_secret` when the same Shipit instance also hosts organizations that do define one, since a secret-less config makes `verify_webhook_signature` universally permissive for any payload claiming that org.

### Proof of Concept
1. Configure Shipit with two GitHub orgs: `OrgA` (no `webhook_secret`, as in `test/dummy/config/secrets_double_github_app.yml`) and `OrgB` (has a real, secret webhook and an existing tracked `Stack` for `orgb/target-repo`).
2. As an unauthenticated attacker, POST to `/github/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": { "full_name": "orgb/target-repo", "owner": { "login": "OrgA" } }
}
```
No `X-Hub-Signature` header is required to be correct because `verify_webhook_signature` returns `true` when `OrgA`'s `webhook_secret` is blank.
3. `WebhooksController#verify_signature` resolves `Shipit.github(organization: "OrgA")`, finds no secret, and passes.
4. `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, which resolves `Repository.from_github_repo_name("orgb/target-repo")` and calls `stack.sync_github(expected_head_sha: "deadbeef")` on `OrgB`'s stack — an action triggered without ever presenting a valid credential for `OrgB`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
