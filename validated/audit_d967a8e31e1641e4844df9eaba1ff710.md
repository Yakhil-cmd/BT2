### Title
Unauthenticated P2P Peer Can Forge `ServiceChainInvalidTxResponseMsg` to Evict Legitimate Handle Transactions from `bridgeTxPool`, Causing Permanent Value-Transfer Loss When VTRecovery Is Disabled — (`node/sc/sub_bridge_handler.go`)

### Summary

`handleParentChainInvalidTxResponseMsg` unconditionally removes a transaction from the `bridgeTxPool` upon receiving a `ServiceChainInvalidTxResponseMsg` whose `ErrStr` equals `blockchain.ErrGasPriceBelowBaseFee.Error()`. The SubBridge P2P handshake authenticates only `NetworkId` and `ProtocolVersion`; it does not verify that the sender is a legitimate parent-chain node. Any peer that can reach the SubBridge P2P port and pass the trivial handshake can forge this message, targeting any known handle-tx hash, and cause the bridge operator's pool to silently drop a live value-transfer transaction.

### Finding Description

**Entry point — SubBridge P2P handshake (no peer identity check):**

`subbridge.go:handle` accepts any inbound peer that passes the handshake:

```go
err := p.Handshake(sb.networkId, sb.getChainID(), td, hash)
``` [1](#0-0) 

`readStatus` only validates `NetworkId` and `ProtocolVersion`; there is no cryptographic proof that the peer is the legitimate MainBridge: [2](#0-1) 

**Dispatch — peer identity is discarded before the handler:**

`HandleMainMsg` dispatches `ServiceChainInvalidTxResponseMsg` by calling `handleParentChainInvalidTxResponseMsg(msg)` — the peer argument `p` is **not** forwarded, so the handler has no way to check who sent the message: [3](#0-2) 

**Vulnerable handler — unconditional pool eviction:**

```go
if invalidTx.ErrStr == blockchain.ErrGasPriceBelowBaseFee.Error() {
    ...
    if err := sbh.subbridge.GetBridgeTxPool().RemoveTx(tx); err != nil { ... }
}
``` [4](#0-3) 

The only guard is `txPool.Get(invalidTx.TxHash) != nil` — i.e., the tx must exist in the pool. There is no signature, nonce, or origin check on the message itself.

**VTRecovery — the only safety net, and it is optional:**

The code comment at the eviction site explicitly acknowledges the dependency:

> "For value transfer txs, Value Transfer Recovery will retry if enabled." [5](#0-4) 

`valueTransferRecovery.Start()` returns `ErrVtrDisabled` and does nothing when `config.VTRecovery == false`: [6](#0-5) 

### Impact Explanation

A malicious peer that can reach the SubBridge P2P port:

1. Connects and passes the trivial handshake (public network ID + protocol version).
2. Observes the handle-tx hash from the parent-chain mempool (the SubBridge broadcasts it via `broadcastServiceChainTx`).
3. Sends a forged `ServiceChainInvalidTxResponseMsg{TxHash: <observed hash>, ErrStr: "gas price is below basefee"}`.
4. The handle tx is removed from `bridgeTxPool`.

With `VTRecovery = false` (a supported, documented configuration): the handle transaction is gone, no automatic retry exists, and the corresponding KAIA or ERC20 value transfer is permanently stuck — the user's assets are locked in the child-chain bridge contract and never released on the parent chain.

With `VTRecovery = true`: the attacker can race the recovery interval, repeatedly evicting re-submitted handle txs faster than the recovery goroutine re-queues them, causing a sustained bridge DoS.

### Likelihood Explanation

- The SubBridge P2P port is network-accessible by design (it must accept connections from the MainBridge).
- The handshake requires only public, observable values.
- The target tx hash is visible in the parent-chain mempool.
- No rate-limiting or per-peer message quota exists on `ServiceChainInvalidTxResponseMsg`.

### Recommendation

1. **Authenticate the sender**: record which peer is the confirmed parent-chain peer (e.g., after a successful nonce-sync exchange) and reject `ServiceChainInvalidTxResponseMsg` from any other peer. Pass `p BridgePeer` into `handleParentChainInvalidTxResponseMsg` and gate on peer identity.
2. **Cross-validate before eviction**: before removing a tx, verify that the parent-chain account nonce has actually advanced past the tx's nonce (confirming the tx was processed or superseded), rather than trusting the error string alone.
3. **Harden VTRecovery**: treat VTRecovery as a required safety net and warn loudly (or refuse to start) when it is disabled while bridge value-transfer is active.

### Proof of Concept

```
1. Run a SubBridge node with VTRecovery=false.
2. Initiate a child→parent KAIA transfer; observe the resulting handle-tx hash H
   in the parent-chain mempool.
3. Connect a custom P2P client to the SubBridge port; complete the handshake
   (NetworkId, ProtocolVersion).
4. Send: ServiceChainInvalidTxResponseMsg = [{TxHash: H,
   ErrStr: "gas price is below basefee"}]
5. Observe: bridgeTxPool.Get(H) == nil  (tx evicted).
6. Observe: handle tx never lands on parent chain; user's assets remain locked
   in the child-chain bridge contract indefinitely.
```

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}
