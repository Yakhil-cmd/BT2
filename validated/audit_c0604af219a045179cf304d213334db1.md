### Title
RAY value-ceiling overflow in chunked accrual permanently freezes a whale market — all verbs revert in `scaled_to_original` before the index cap engages - (File: common/src/rates/simulate.rs)

### Summary
CVE-2025-30689 is a crafted-input crash/hang DoS: the victim's own query makes the server compute an expression that crashes it. The Soroban analog is a state-driven arithmetic crash: `accrue_step` (run by `global_sync`/`simulate_update_indexes_body`) recomputes `scaled_to_original(borrowed, borrow_index)` per chunk, which overflows `i128` once a market's scaled debt times index exceeds `i128::MAX`. The `MAX_BORROW_INDEX_RAY = 1e36` cap was intended to bound the index, but the *value* ceiling `borrowed × index > i128::MAX` is hit first on any market holding roughly a billion whole tokens at 18 decimals. Since every pool verb accrues first, the market is permanently frozen — no repay, withdraw, supply, or liquidation ever succeeds again. The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates exactly this freeze and asserts `MATH_OVERFLOW` on `update_indexes`, `withdraw`, and `repay`. [1](#0-0) 

### Finding Description
`global_sync` loops `accrue_chunk` over the elapsed interval, and `accrue_step` converts scaled RAY balances back to original units by multiplying by the borrow index before clamping the index at `MAX_BORROW_INDEX_RAY`. [2](#0-1)  On an 18-decimal market with ~1e9 whole tokens of scaled debt (~1e36 RAY), sustained near-max utilization grows the borrow index past ~170× within a few years on the XLM-style rate curve, at which point `borrowed × borrow_index` exceeds `i128::MAX` and panics with `GenericError::MathOverflow` inside `scaled_to_original` — before the index ever reaches its 1e36 cap. [1](#0-0)  The panic is inside the accrual preamble shared by every mutating entrypoint, so `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `claim_revenue`, `flash_loan`, and `recapitalize` all revert identically. Even `clean_bad_debt`/recapitalization cannot recover the market because they too accrue first. The permissionless `update_indexes` keeper commits the same accrual, so a single unprivileged call crosses the cliff.

### Impact Explanation
Permanent freezing of all funds in the affected market: suppliers' full principal and accrued interest become unrecoverable, borrowers can never repay (so their cross-market collateral on liquidatable accounts is also harder to unwind cleanly), and the pool's `supplied`/`borrowed` books are stuck mid-accrual forever. This matches the "permanent freezing of funds" acceptance criterion, and it is state permanent — no future transaction, parameter change, or governance execution can skip the accrual that panics. `MAX_BORROW_INDEX_RAY` exists precisely to bound index growth, but it is evaluated *after* the multiplications that overflow, so the documented safety bound is unreachable. [3](#0-2) 

### Likelihood Explanation
Requires a very large market (≈1e9 whole tokens at 18 decimals; smaller thresholds for higher-decimal assets, larger for 7-decimal assets) sitting at sustained high utilization for multiple years, plus an unprivileged `update_indexes`/any-verb call to trigger the fatal chunk. Not cheap or quick, but fully reachable by unprivileged supply/borrow/update calls — no governance, upgrade, or oracle manipulation needed — and irreversible once crossed. Consistent with Medium.

### Recommendation
In `accrue_step`/`scaled_to_original` (common/src/rates/scaling.rs, common/src/rates/simulate.rs), clamp the effective index or saturate the product before the `i128` multiply — e.g., early-return `Ray::ZERO` interest and cap `borrow_index` at `MAX_BORROW_INDEX_RAY` (or at `i128::MAX / borrowed` when nonzero) before computing original-value legs, so the index cap engages before the value ceiling. Add the same guard to `simulate_update_indexes_body`'s chunk loop so the view path never panics either. [4](#0-3) 

### Proof of Concept
The checked-in test is the PoC (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-360`):

```rust

t.supply_raw(BOB, "BIG18", principal);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98); // 98% utilization

    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
// => Error MATH_OVERFLOW, borrow_index < MAX_BORROW_INDEX_RAY (cap never engaged)

assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

Root cause chain: `update_indexes`/any verb → `interest::global_sync` → `accrue_step` → `scaled_to_original(borrowed, borrow_index)` overflows `i128` when `borrowed ≈ 1e36` and `index > ~1.7e2 × RAY`, a value the `1e36` index cap cannot preempt because the multiplication happens before the clamp.

```rust
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);

    assert_contract_error(failed, errors::MATH_OVERFLOW);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```markdown
### ADR-0016: Millisecond rates and chunked accrual

Accrual uses a per-millisecond RAY rate derived from the annual rate. It splits
elapsed time into chunks of at most one year (`MAX_COMPOUND_DELTA_MS`). Each
chunk uses the preceding chunk's market state. This bounds individual time
steps without eliminating value overflow, cumulative work, cadence dependence,
or rounding error. The [formula reference](../reference/formulas.md) defines these limits.
```
