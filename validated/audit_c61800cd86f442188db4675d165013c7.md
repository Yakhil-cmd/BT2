Based on the evidence gathered, there is a concrete, already-flagged analog to the reported bug class in `pox-5.clar`'s reward-settlement code, and it is directly proven by an existing regression test in the repo.

### Title
Signer reward snapshot advances rewards-per-token for signers with zero shares in a cycle, letting a below-threshold signer's stakers claim STX-only rewards they never earned - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`settle-rewards` in `pox-5.clar` unconditionally records the global `rewards-per-token` snapshot into the per-signer map `signer-rewards-per-token-for-cycle` only when `shares > 0` at settlement time, but `settle-rewards`/`settle-staker-rewards` are invoked opportunistically (e.g. via a bond co-claim) rather than being gated to the point where the cycle's final vote/stake distribution is fixed. This mirrors the THENA `_notifyRewardAmount`/`_updateFor` bug class: reward accounting is snapshotted against an intermediate/incidental system state (whichever call happens to trigger `settle-rewards` for a given signer/cycle) instead of the cycle's settled state, letting a staker end up credited for STX-only rewards from a cycle/signer pairing that never contributed to the STX-only pool.

### Finding Description
`calculate-rewards` computes a single global `cumulative-rewards-per-ustx` for the cycle and stores it in `rewards-per-token-for-cycle` [1](#0-0) .

Per-signer bookkeeping is done lazily in `settle-rewards`, which reads the signer's *current* shares for the cycle and, if `shares > 0`, copies the current global rate into `signer-rewards-per-token-for-cycle` for that signer [2](#0-1) . Staker-level accounting (`settle-staker-rewards`) then reads that per-signer snapshot to compute what the staker has earned [3](#0-2) .

Because `settle-rewards` is triggered incidentally by unrelated flows (bond reward claims, stake/unstake, registration, etc.) rather than strictly at cycle finalization, the timing of when a signer's `signer-rewards-per-token-for-cycle` snapshot is advanced is not tied to when that signer actually held nonzero shares throughout the cycle. The repo's own regression test demonstrates the exploit: a below-threshold signer (`signer1`) with zero cycle-1 STX-only shares triggers `settle-rewards` via `claimRewards` on an unrelated bond claim; this advances `signer1`'s STX-only snapshot to the global rate even though `signer1` never held STX-only shares in that cycle, letting Alice's staker-level accounting see phantom rewards [4](#0-3) .

The same class of bug is visible from the other direction in `current-cycle rewards accrue to the old signer after a signer update and partial unstake`, which confirms that reward crediting is order/state-dependent on whatever intermediate share snapshot exists at settlement time rather than the cycle's final distribution [5](#0-4) .

### Impact Explanation
This breaks the equality between total sBTC/STX rewards actually earned by a signer's stakers in a cycle and the rewards paid out to them: a signer that contributed zero (or the wrong amount of) shares to the STX-only pool for a cycle can still have its stakers draw from the shared rewards pool, diluting or double-counting against stakers who legitimately earned those rewards. This is a reward-accounting/double-counting defect (temporary freezing/misallocation of staker-earned sBTC), matching the "double-counting a commitment or reward" / "signing weight or reward slots exceeding locked value" impact classes.

### Likelihood Explanation
The `below-threshold signer leaks phantom stx-only rewards via bond co-claim` test in the repo is written specifically to reproduce this exact scenario and asserts it should fail on unfixed code, indicating the maintainers are aware this is a real, reachable path (triggered by an ordinary `claim-rewards`/bond-claim call, requiring no privileged role) [6](#0-5) .

### Recommendation
Gate `settle-rewards`'s write to `signer-rewards-per-token-for-cycle` so it never advances a signer's STX-only snapshot for a cycle in which that signer held zero shares throughout, and ensure settlement is anchored to the cycle's finalized share distribution rather than to whatever call happens to invoke `settle-rewards` first, consistent with the fix pattern that removed the vulnerable `_notifyRewardAmount` in the referenced external report.

### Proof of Concept
The existing test `below-threshold signer leaks phantom stx-only rewards via bond co-claim` is a complete PoC: it sets up `signer1` below the STX-only threshold with zero cycle-1 shares, funds rewards, calls `calculateRewards`, then triggers `testSigner.claimRewards([0n], 1n)` (a bond claim) which internally invokes `settle-rewards` for `signer1`'s STX-only pool at zero shares, corrupting the snapshot such that `getEarnedStakerRewards(alice, 1n, null)` becomes nonzero despite `signer1` never being a cycle-1 STX-only participant [4](#0-3) .

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
