### Title
RAY value overflow in accrual permanently freezes an overlarge market - ([File: common/src/rates/simulate.rs])

### Summary
A market whose scaled supply or debt approaches the `i128` value domain can grow its indexes until the next accrual overflows fixed-point multiplication. Because every market mutation loads the accrued cache before attempting the requested action, the first `MathOverflow` makes subsequent repayments, withdrawals, liquidations, and index updates fail permanently.

### Finding Description
`accrue_step` converts stored RAY shares into asset values with `scaled_to_original`, then computes a new borrow index and immediately multiplies the stored debt by both the old and new indexes in `calculate_supplier_rewards`. [1](#0-0)  `Ray::mul` delegates to `mul_div_half_up`, which raises `MathOverflow` when the result does not fit `i128`. [2](#0-1) [3](#0-2) 

The borrow-index ceiling is applied only after the multiplication, so it does not prevent the debt-value overflow. [4](#0-3)  Every pool leg calls `synced_market`, which runs `global_sync` before the requested accounting or transfer. [5](#0-4)  `global_sync` calls the same `accrue_step` for every elapsed chunk, so the overflow is hit before a risk-reducing mutation can execute. [6](#0-5) [7](#0-6) 

### Impact Explanation
This is permanent freezing of all funds and debt operations in the affected market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot seize debt or collateral, and permissionless `update_indexes` cannot advance the market past the failed accrual. The repository's integration test demonstrates the terminal state: once the overflow is reached, both withdrawal and repayment fail with `MathOverflow`. [8](#0-7) 

### Likelihood Explanation
The trigger requires an extremely large market and sustained interest accrual at high utilization. An unprivileged account can create the state through normal `supply` and `borrow` calls if governance-configured caps and utilization limits admit the position. [9](#0-8)  The reproduced fixture uses one billion 18-decimal tokens supplied and 98% borrowed, then accrues until `update_indexes` overflows. [10](#0-9)  Although capital-intensive and time-dependent, it is not transient: after the state crosses the boundary, every accrual-dependent operation repeats the same panic.

### Recommendation
Bound scaled market totals against the maximum possible index, not only against the token-to-RAY conversion limit. In particular, admission and mint paths should enforce `scaled * MAX_INDEX <= i128::MAX`, or index accrual should clamp the new index to the largest representable index for the current `borrowed` and `supplied` totals before valuing them. The cap must cover debt and supply separately and should be checked before `update_borrow_index`, `calculate_supplier_rewards`, `update_supply_index`, and `supply_index_reward_shortfall`.

Add an invariant proving that stored market totals remain representable through `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`, and extend the existing long-horizon test to assert that the protocol reaches a capped-index state rather than an unrecoverable overflow.

### Proof of Concept
The repository already contains a reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

1. Supply `1_000_000_000 * 10^18` base units of an 18-decimal asset.
2. Supply sufficient collateral in another market.
3. Borrow 98% of the first market through the normal `borrow` path.
4. Advance ledger time and repeatedly call `update_indexes`.
5. The accrual eventually fails with `MathOverflow`; subsequent `withdraw` and `repay` attempts fail with the same error because they accrue first. [11](#0-10)

```rust
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");

        "the index cap did not engage before the value overflow"
```
