The reported issue is specific to Perennial Vault's Solidity margin-trading/liquidation mechanism, where collateral used for leverage and liquidation checks excludes pending keeper/position fees that are otherwise accounted for inside the underlying `Market` contract. I searched the Polkadot SDK for structurally analogous "pending fee/slash excluded from a liquidation-like health check" patterns across `pallet-nomination-pools`, `pallet-delegated-staking`, and `pallet-staking-async`/`pallet-staking` slashing logic, since these are the closest FRAME constructs involving pooled funds, pending deductions, and share-based accounting.

In these pallets, pending deductions are explicitly and correctly tracked and exposed: [1](#0-0)  — `api_pool_pending_slash` and `api_member_pending_slash` expose pending slash amounts for reporting/application, and slashing bookkeeping is verified consistent in tests such as [2](#0-1) . [3](#0-2)  shows slashing is applied proportionally against active/unlocking balances with explicit accounting, not silently excluded from any health/liquidation-style check.

None of these FRAME pallets implement a leverage/margin/liquidation mechanism analogous to Perennial's vault (which computes "effective leverage" from a market's collateral and liquidates positions based on that computed value while excluding pending fees). There is no comparable "vault leverage relative to per-market collateral, where pending fees skew the calculation and enable griefing-driven liquidation" construct in FRAME, XCM, or bridge code. Forcing this DeFi-specific margin-trading bug class onto FRAME's pooled-staking or fee-payment primitives would not be a genuine analog — the closest constructs (`pallet-nomination-pools`, `pallet-delegated-staking`, `pallet-staking-async`) already track pending fees/slashes explicitly and consistently in the same balance domain used for share conversion, unlike Perennial's split between `local.collateral` (excluding fees) and the pending-fee-inclusive health check inside `Market`.

	pub(crate) fn slash(
		&mut self,
		slash_amount: BalanceOf<T>,
		minimum_balance: BalanceOf<T>,
		offence_era: EraIndex,
	) -> BalanceOf<T> {
		if slash_amount.is_zero() {
			return Zero::zero();
		}

		use sp_runtime::PerThing as _;
		let mut remaining_slash = slash_amount;
		let pre_slash_total = self.total;

		// for an `offence_era = x`, any chunk that is scheduled to be unlocked at era `x + 28`
		// (assuming 28 is the bonding duration) onwards should be slashed.
		let slashable_chunks_start = offence_era.saturating_add(T::BondingDuration::get());

		// `Some(ratio)` if this is proportional, with `ratio`, `None` otherwise. In both cases, we
		// slash first the active chunk, and then `slash_chunks_priority`.
		let (maybe_proportional, slash_chunks_priority) = {
			if let Some(first_slashable_index) =
				self.unlocking.iter().position(|c| c.era >= slashable_chunks_start)
			{
				// If there exists a chunk who's after the first_slashable_start, then this is a
				// proportional slash, because we want to slash active and these chunks
				// proportionally.

				// The indices of the first chunk after the slash up through the most recent chunk.
				// (The most recent chunk is at greatest from this era)
				let affected_indices = first_slashable_index..self.unlocking.len();
				let unbonding_affected_balance =
					affected_indices.clone().fold(BalanceOf::<T>::zero(), |sum, i| {
						if let Some(chunk) = self.unlocking.get(i).defensive() {
							sum.saturating_add(chunk.value)
						} else {
							sum
						}
					});
				let affected_balance = self.active.saturating_add(unbonding_affected_balance);
				let ratio = Perquintill::from_rational_with_rounding(
					slash_amount,
					affected_balance,
					Rounding::Up,
				)
				.unwrap_or_else(|_| Perquintill::one());
				(
					Some(ratio),
					affected_indices.chain((0..first_slashable_index).rev()).collect::<Vec<_>>(),
				)
			} else {
				// We just slash from the last chunk to the most recent one, if need be.
				(None, (0..self.unlocking.len()).rev().collect::<Vec<_>>())
			}
		};
