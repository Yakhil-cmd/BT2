### Title
`NonTransfer` proxy escalates to `paras_registrar::swap` (and other unrestricted-Registrar calls) by self-granting an `Auction` proxy - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
Multiple relay-chain-style runtimes (`rococo`, `westend`, and the `staking-async` RC-client runtime) declare `ProxyType::NonTransfer` as a superset of every other `ProxyType` via a catch-all in `is_superset`, while `ProxyType::Auction`'s `filter` admits an *unrestricted* `RuntimeCall::Registrar(..)`. `NonTransfer`'s own filter deliberately omits `paras_registrar::Call::swap` (and other Registrar calls) — the code even comments "Specifically omitting Registrar `swap`". Because `pallet_proxy::do_proxy` only gates `add_proxy`/`remove_proxy` through `is_superset` (not `filter`), a delegate holding only a `NonTransfer` proxy can grant itself an `Auction` proxy and then invoke `Registrar::swap`, a call explicitly excluded from its own permission set.

### Finding Description
`pallet_proxy`'s runtime-added filter in `do_proxy` blocks `add_proxy`/`remove_proxy` only when `!def.proxy_type.is_superset(proxy_type)`: [1](#0-0) 

For `rococo`, `westend`, and the staking-async RC runtime, `ProxyType::is_superset` uses a blanket rule that `NonTransfer` is a superset of *every* other type: [2](#0-1) 

But `ProxyType::Auction`'s `filter` admits the entire `Registrar` call surface with no restriction: [3](#0-2) 

while `NonTransfer`'s own `filter` explicitly excludes `Registrar::swap` (comment: "Specifically omitting Registrar `swap`"), only admitting `register`/`deregister`/`reserve`: [4](#0-3) 

The identical pattern exists in `rococo`: [5](#0-4) [6](#0-5) 

and in the staking-async RC runtime: [7](#0-6) [8](#0-7) 

This is exactly the bug class Parity already fixed once for `asset-hub-westend` (`NonTransfer`/`Governance`), documented in `prdoc/pr_12769.prdoc` and guarded by a regression test and a lattice-wide test that checks `is_superset` implies `filter` containment: [9](#0-8) [10](#0-9) 

That lattice-check test exists only for `asset-hub-westend`; it has not been ported to `rococo`, `westend`, or the staking-async RC runtime, where the same class of mismatch (`NonTransfer` claiming superset of `Auction` without covering `Registrar::swap`) still exists unaddressed.

The `swap` extrinsic itself is gated by `ensure_root_para_or_owner`, which accepts a `Signed` origin equal to the para's recorded `manager`: [11](#0-10) [12](#0-11) 

Because `pallet_proxy::do_proxy` dispatches the proxied call under `RawOrigin::Signed(real)` (the delegator, i.e., the para manager), this check passes when executed via proxy exactly as if the manager called it directly — the delegate merely needs `Registrar::swap` to pass the *proxy* filter, which it should not for a `NonTransfer` delegate.

### Impact Explanation
A user who grants only a `NonTransfer` proxy (explicitly meant to exclude parachain-slot manipulation via `Registrar::swap`) to a delegate unintentionally allows that delegate to:
1. Call `Proxy::add_proxy { delegate: <self>, proxy_type: Auction }` on behalf of the real account — permitted because `NonTransfer.is_superset(Auction) == true` and `NonTransfer.filter` admits `RuntimeCall::Proxy(..)`.
2. Then call `Proxy::proxy` with `force_proxy_type: Auction` and inner call `Registrar::swap`, which `Auction.filter` unconditionally admits.

This lets an untrusted `NonTransfer` delegate perform parachain lease/lifecycle swaps on behalf of the delegator's owned para(s) — an action the delegator's own filter design explicitly intended to withhold ("Specifically omitting Registrar `swap`"). This breaks the confidentiality/integrity guarantee of the proxy delegation model: the delegate exceeds its granted permission envelope, mirroring the Spark CVE's pattern of a restricted (`proxy-user`) execution context escaping its intended privilege boundary through an unchecked path (custom classpath vs. `is_superset` catch-all). Concrete on-chain damage is bounded by `swap`'s cooperative two-sided `PendingSwap` protocol and requires the delegator to actually own a registered para, which narrows severity relative to a full privilege takeover.

### Likelihood Explanation
Requires only: (a) a signed extrinsic granting a `NonTransfer` proxy (a common, ordinary user action, no privileged role needed), and (b) the delegator owning/managing at least one registered para. No governance, no validator/collator collusion, no forged inherent. The attacker (proxy delegate) is an ordinary account with no special role. Reachability of `Auction`/`Registrar` pallets and `pallet_proxy` is standard relay-chain runtime wiring on `rococo`/`westend`.

### Recommendation
Apply the same fix used for `asset-hub-westend` (`pr_12769`) to `rococo`, `westend`, and the staking-async RC runtime: either restrict `Auction`'s filter to the same subset of `Registrar` calls that `NonTransfer` admits (`register`/`deregister`/`reserve`, omitting `swap`), or remove the blanket `(ProxyType::NonTransfer, _) => true` rule from `is_superset` and instead enumerate only the pairs verified to have full filter containment. Port the `proxy_type_superset_relation_matches_call_filters`-style lattice test to these runtimes to catch regressions.

### Proof of Concept
Not executed against a live/public network. A minimal FRAME integration-test reproduction (analogous to `pure_proxy_stash_can_delegate_to_staking_operator` in `asset-hub-westend`'s test suite) would:
1. Fund account `ALICE` (para manager) and `BOB` (delegate).
2. `Registrar::reserve`/`register` a para as `ALICE`, so `ALICE` is `para_info.manager`.
3. `Proxy::add_proxy(ALICE, BOB, ProxyType::NonTransfer, 0)`.
4. As `BOB`, call `Proxy::proxy(ALICE, force_proxy_type: NonTransfer, call: Proxy::add_proxy{delegate: BOB, proxy_type: Auction})` — expect `Ok`, verified via `ProxyExecuted{result: Ok(())}` event, confirming `is_superset` did not block it.
5. As `BOB`, call `Proxy::proxy(ALICE, force_proxy_type: Auction, call: Registrar::swap{id, other})` — expect `Ok` per `Auction.filter`, demonstrating `BOB` executed a Registrar call that `NonTransfer.filter` explicitly denies.
I was unable to actually run this test in this environment (no code-execution access here); this describes the exact repro steps mirroring the already-existing `asset-hub-westend` regression tests (`non_transfer_proxy_is_not_a_superset_of_governance`, `pure_proxy_stash_can_delegate_to_staking_operator`) that a Devin agent with repo/test access could execute to confirm `Ok` results and the `ProxyExecuted` events described above.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

		#[pallet::call_index(3)]
		#[pallet::weight(<T as Config>::WeightInfo::swap())]
		pub fn swap(origin: OriginFor<T>, id: ParaId, other: ParaId) -> DispatchResult {
			Self::ensure_root_para_or_owner(origin, id)?;

			// If `id` and `other` is the same id, we treat this as a "clear" function, and exit
			// early, since swapping the same id would otherwise be a noop.
			if id == other {
				PendingSwap::<T>::remove(id);
				return Ok(());
			}

			// Sanity check that `id` is even a para.
			let id_lifecycle =
				paras::Pallet::<T>::lifecycle(id).ok_or(Error::<T>::NotRegistered)?;

			if PendingSwap::<T>::get(other) == Some(id) {
				let other_lifecycle =
					paras::Pallet::<T>::lifecycle(other).ok_or(Error::<T>::NotRegistered)?;
				// identify which is a lease holding parachain and which is a parathread (on-demand
				// parachain)
				if id_lifecycle == ParaLifecycle::Parachain &&
					other_lifecycle == ParaLifecycle::Parathread
				{
					Self::do_thread_and_chain_swap(id, other);
				} else if id_lifecycle == ParaLifecycle::Parathread &&
					other_lifecycle == ParaLifecycle::Parachain
				{
					Self::do_thread_and_chain_swap(other, id);
				} else if id_lifecycle == ParaLifecycle::Parachain &&
					other_lifecycle == ParaLifecycle::Parachain
				{
					// If both chains are currently parachains, there is nothing funny we
					// need to do for their lifecycle management, just swap the underlying
					// data.
					T::OnSwap::on_swap(id, other);
				} else {
					return Err(Error::<T>::CannotSwap.into());
				}
				Self::deposit_event(Event::<T>::Swapped { para_id: id, other_id: other });
				PendingSwap::<T>::remove(other);
			} else {
				PendingSwap::<T>::insert(id, other);
			}

			Ok(())
		}

	fn ensure_root_para_or_owner(
		origin: <T as frame_system::Config>::RuntimeOrigin,

			let para_info = Paras::<T>::get(id).ok_or(Error::<T>::NotRegistered)?;

			if para_info.manager == who {
				ensure!(!para_info.is_locked(), Error::<T>::ParaLocked);
				return Ok(());
			}
		}
