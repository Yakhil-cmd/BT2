### Title
Unsanitized release asset `name` field from REST response enables path traversal file write in `gh release download` - ([File: pkg/cmd/release/download/download.go])

### Summary
`api.Client.REST` (api/client.go) performs zero validation of the `data` it unmarshals from a server response, and the release-download flow feeds the resulting asset `Name` field directly into a filesystem path with no traversal check, unlike the sibling `gh run download` command which explicitly guards against this with `safepaths`. A malicious or attacker-controlled host that the victim points `gh` at (custom `--hostname`/GHES, or a compromised GH Enterprise endpoint) can return a release JSON body with an asset `"name"` containing `../` sequences, causing `gh release download` to write the downloaded content outside the intended destination directory.

### Finding Description
`Client.REST` simply forwards to `ghAPI.RESTClient.Do(method, p, body, data)` and wraps only HTTP error handling; it performs no field-level sanitization of the response body before unmarshaling into the caller-supplied struct: [1](#0-0) .

`pkg/cmd/release/shared.FetchRelease`/`FetchLatestRelease` populate `shared.Release.Assets[].Name` from this unsanitized REST response. In `downloadRun`, each asset's `Name` is passed straight through as the download `fileName` with no `filepath.Base` or path-confinement applied: [2](#0-1) [3](#0-2) .

The download worker then uses this raw name to check for existing files and to write the asset content: [4](#0-3) [5](#0-4) [6](#0-5) 

`makePath` does `filepath.Join(w.dir, name)` with no traversal check — `filepath.Join` cleans `..` segments, so a name like `../../../.ssh/authorized_keys` resolves outside `w.dir`, and `Copy` will `os.MkdirAll` the resulting parent directories and write the file there with `os.OpenFile(..., os.O_CREATE|os.O_TRUNC, 0644)`. The only sanitization present (`filepath.Base(serverFileName)`) applies solely to the archive/Content-Disposition fallback path when `fileName` is empty, not to the common named-asset path: [7](#0-6) .

This is in stark contrast to the equivalent `gh run download` flow, which explicitly builds destination paths through `safepaths.Absolute.Join`, rejecting any artifact name that would traverse outside the destination directory, and has a dedicated regression test for exactly this attack: [8](#0-7) [9](#0-8) . No equivalent protection or test exists for `gh release download`.

### Impact Explanation
An attacker who controls (or has compromised) a GitHub-API-compatible host that a victim points `gh` at — a realistic and in-scope scenario given custom `--hostname`/GHES support — can serve a release JSON response with an asset name such as `../../../.ssh/authorized_keys` or `../.bashrc`. When the victim runs `gh release download` (with a matching `--pattern` or default download), the tool will write the fetched content to that traversed path, overwriting or creating files outside the intended destination directory. This is an arbitrary file write outside the intended path, which can escalate to code execution (e.g., overwriting `~/.bashrc`, `~/.ssh/authorized_keys`, or shell/profile startup files) — matching the "arbitrary file write" / "downstream code execution" bounty impact classes.

### Likelihood Explanation
Requires the victim to run `gh release download` against a repository/host the attacker controls (self-hosted/custom hostname, or any REST endpoint the CLI is pointed at). No token, MITM, or elevated privileges are needed — only that the attacker's server returns a crafted release JSON body. The exploit is deterministic and repeatable: any asset whose `name` matches the victim's `--pattern`/download selection (or all assets if no pattern) will attempt the traversal.

### Recommendation
In `pkg/cmd/release/download/download.go`, route the asset `Name` (and Content-Disposition-derived filename) through the same `internal/safepaths.Absolute.Join` path-confinement mechanism already used by `pkg/cmd/run/download`, rejecting or sanitizing any name that would escape `opts.Destination`/`w.dir`. At minimum, apply `filepath.Base` (as already done for the archive fallback) to every asset name before calling `makePath`, and add a path-traversal error path analogous to `safepaths.PathTraversalError` with test coverage mirroring `pkg/cmd/run/download/download_test.go`'s "handling artifact name with path traversal exploit" case.

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
}
