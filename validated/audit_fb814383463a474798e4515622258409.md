### Title
Unauthenticated cross-repository status forgery via nil `webhook_secret` bypass in `WebhooksController` / `StatusHandler` - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/status_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` instance (and thus the HMAC secret to validate against) using an attacker-supplied field of the same JSON body it is about to trust, and unconditionally treats the request as verified when that org has no `webhook_secret` configured. `StatusHandler` then applies the payload's `sha`/`state` to any `Commit` row in the database with zero scoping to the repository or organization that was "verified." This breaks the binding: *organization that authenticated == repository whose commit status is written*.

### Finding Description
`WebhooksController#verify_signature` picks the org/app config from the untrusted payload itself: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` returns `true` unconditionally when no `webhook_secret` is configured for that org: [3](#0-2) 

`webhook_secret` is explicitly documented and templated as optional (`webhook_secret: # nil`), so a real multi-organization Shipit deployment (as shown in `test/dummy/config/secrets_double_github_app.yml`) can legitimately have one configured org with a secret and another without one.

Once past `verify_signature`, `StatusHandler#process` writes the commit status using only `sha` from the payload, with no repository or organization scoping at all: [4](#0-3) 

Compare this to `Handler#stacks`/`#repository_name`, which at least scope by `repository.full_name` for other handlers (e.g. `PushHandler`): [5](#0-4) [6](#0-5) 

`StatusHandler` never calls `repository_name`/`stacks`; it globally queries `Commit.where(sha: params.sha)` across the whole instance.

Binding broken (equality that should hold but doesn't):
`organization authenticated by verify_signature (repository.owner.login / organization.login of the request)` ⇔ `repository whose Commit rows are mutated by StatusHandler`.

Before the attack: only GitHub, holding each org's real `webhook_secret`, can produce signed events for that org, and status writes are implicitly trusted to originate from the GitHub App installed on the corresponding repository.
After the attack: an unauthenticated internet client can POST an unsigned/self-signed `X-Github-Event: status` request naming any org that happens to have no `webhook_secret` set on this instance (`repository.owner.login` = that org, satisfying `verify_signature` trivially), while the actual `sha`/`state` in the body targets a commit that belongs to a *different*, secured organization's repository tracked by the same Shipit instance. `StatusHandler` has no code path that checks the org used for signature verification against the repository owning the targeted commit.

### Impact Explanation
This is an unauthenticated write of arbitrary CI/status state onto commits belonging to any repository/organization configured on the Shipit instance, not just the (potentially secret-less) org named in the payload. Since Shipit's status/check state is used to determine whether a commit is "green" and eligible for continuous deployment (`continuous_delivery_schedule` feature is present, see `config/routes.rb` resource `continuous_delivery_schedule`), an attacker who can mark an arbitrary commit as `success` can influence deploy readiness decisions on a repository they have no access to, satisfying the High-impact bar of "escalation ... unauthorized deploy" through a credential/authorization boundary that was supposed to be enforced by per-org webhook signatures. [7](#0-6) 

### Likelihood Explanation
Requires: (1) the target Shipit instance to run in multi-organization mode with at least one configured org lacking a `webhook_secret` (an explicitly supported, documented configuration — not a deviation from documented mounting), and (2) the attacker knowing/guessing a real commit SHA in the victim repository (SHAs are often publicly visible via the GitHub UI/API for public repos, PRs, etc.). No credentials, sessions, or tokens are needed to reach `/webhooks`, satisfying the "unprivileged attacker" requirement.

### Recommendation
- Scope `StatusHandler` (and any other handler that doesn't already do so) to the repository named in the payload via `Handler#stacks`/`#repository_name`, and reject/ignore the event if that repository does not belong to the organization that was actually verified by `verify_signature`.
- In `WebhooksController#verify_signature`, after resolving `github_app` from the payload's claimed `repository_owner`, cross-check that the resolved organization actually owns the `repository.full_name` in the same payload before dispatching to handlers.
- Treat a missing `webhook_secret` as "reject all events for this org" rather than "accept unconditionally," or require `webhook_secret` to be mandatory for any organization once more than one GitHub App is configured.

### Proof of Concept
1. Configure Shipit with two orgs per `test/dummy/config/secrets_double_github_app.yml`: `OrgOne` (no `webhook_secret`), `OrgTwo` (has a `webhook_secret`, tracked repo `OrgTwo/victim`).
2. Attacker (no session, no token, no secret) sends:
```
POST /webhooks
X-Github-Event: status
X-Hub-Signature: sha1=anything   (or omit; unused because OrgOne's secret is nil)
{
  "repository": { "owner": { "login": "OrgOne" }, "full_name": "OrgOne/whatever" },
  "sha": "<real sha of a commit in OrgTwo/victim>",
  "state": "success"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "OrgOne")`, whose `verify_webhook_signature` returns `true` unconditionally (no secret configured), so the request passes.
4. `StatusHandler#process` runs `Commit.where(sha: params.sha)`, finds the commit belonging to `OrgTwo/victim`, and calls `commit.create_status_from_github!(params)`, writing a forged `success` status onto a commit in a repository never associated with `OrgOne`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
