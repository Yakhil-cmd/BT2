### Title
Webhook signature verification is bound to `repository.owner.login` while handlers act on `repository.full_name`, enabling forged webhooks against any tracked repository if any configured GitHub org lacks a `webhook_secret` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to validate against using an **attacker-controlled** field of the JSON body (`repository.owner.login`, falling back to `organization.login`), but every webhook handler resolves the target `Stack`/`Repository` using a **different** field of the same body (`repository.full_name`). Combined with the fact that `GitHubApp#verify_webhook_signature` fails open when no `webhook_secret` is configured for the selected organization, this breaks the binding "the organization whose secret authenticated the request" == "the repository the request is allowed to act on."

### Finding Description
`WebhooksController` picks the signing organization purely from the untrusted payload: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` is fail-open: if the selected organization's config has no `webhook_secret`, the signature check always returns `true`, regardless of what is sent in `X-Hub-Signature`: [3](#0-2) 

This is not a hypothetical config: Shipit natively supports multiple GitHub App configurations per Shipit instance keyed by organization (`Shipit.github_app_config`, `TOP_LEVEL_GH_KEYS`), and `webhook_secret` is explicitly optional (`@config[:webhook_secret].presence`): [4](#0-3) [5](#0-4) 

The test fixture used for multi-org setups shows this is a supported, real operating mode — both demo orgs have `webhook_secret: # nil`: [6](#0-5) 

Once the signature check passes (trivially, for the org with no secret), every handler determines which repository/stack to mutate from the **independent** `repository.full_name` field of the same attacker-supplied JSON body: [7](#0-6) [8](#0-7) 

So `repository.owner.login` (used only to pick which secret authenticates the request) and `repository.full_name` (used to decide what gets written) are never checked for consistency. An attacker can set `repository.owner.login` to any organization configured in Shipit without a `webhook_secret`, sail through `verify_signature` with a garbage/absent signature, and set `repository.full_name` to any other tracked repository (owned by a fully-secured organization) to have the handler act on it.

### Impact Explanation
Depending on which event is spoofed, this allows an unauthenticated attacker to:
- Forge `status`/`check_suite` events for a targeted repository's commits, faking passing CI statuses that `ci.require` gates rely on to allow deploys — an unauthorized-deploy-enabling bypass of the CI safety gate documented in the `ci.require` feature.
- Forge `push` events to trigger `stack.sync_github(expected_head_sha: ...)` against an arbitrary tracked stack.
- Forge `pull_request` events to force-provision or deprovision review stacks on a targeted repository.
- Forge `membership`/`team` events, creating `Team`/`User` records that intersect with `Shipit.github_teams` authorization on the fly.

This crosses the required boundary: an unprivileged external actor obtains control over a repository/stack's webhook-driven state without any credential, session, or repository-write access — matching the High-impact category "escalation into `Shipit.github_teams` authorization" and bordering on "unauthorized deploy" via forged CI status.

### Likelihood Explanation
Exploitability is conditioned on the deployment having at least one organization configured under `Shipit.github` without a `webhook_secret`. This is an explicitly supported, non-default-rejected configuration in the codebase (optional field, dedicated multi-org fixture demonstrating it), so it is a realistic operational state rather than a theoretical one, but it does depend on host configuration choices outside this engine's enforced defaults — the engine itself never requires or validates that all configured organizations set a `webhook_secret`.

### Recommendation
- Derive the authenticating organization independently of the JSON body (e.g., resolve the target `Repository`/`Stack` first from a `full_name` that has already been matched against a known, configured organization, and require that the same organization's secret validated the signature) rather than trusting `repository.owner.login`/`organization.login` from the payload before verification.
- Make `verify_webhook_signature` fail closed: if no `webhook_secret` is configured for an organization, reject the webhook (or require an explicit "unauthenticated webhooks allowed" opt-in) instead of silently returning `true`.
- Cross-validate that `repository.owner.login` and `repository.full_name`'s owner segment refer to the same organization before dispatching to handlers.

### Proof of Concept
1. Shipit is configured with `Shipit.github` containing at least two organizations, e.g. `OrgOne` (no `webhook_secret`) and `OrgTwo` (real `webhook_secret`, tracks `OrgTwo/target-repo`), as in `test/dummy/config/secrets_double_github_app.yml`.
2. Attacker POSTs to `/webhooks` with header `X-Github-Event: status` and an arbitrary/garbage `X-Hub-Signature`, and body:
```json
{
  "repository": { "owner": { "login": "OrgOne" }, "full_name": "OrgTwo/target-repo" },
  "sha": "<victim commit sha>",
  "state": "success",
  "context": "ci/required-check",
  "target_url": "http://attacker.example/fake"
}
```
3. `verify_signature` calls `Shipit.github(organization: "OrgOne")`, whose `webhook_secret` is `nil`, so `verify_webhook_signature` returns `true` unconditionally.
4. The `status` handler resolves the target repository via `full_name` = `"OrgTwo/target-repo"`, and writes a fabricated successful `Status` on `target commit`, satisfying `ci.require` for a stack it has no legitimate access to.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
