### Title
Interrupted Bash-only turns cause `capture_git_baseline` to re-baseline past unreviewed commits, permanently skipping security review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`capture_git_baseline`, invoked from `handle_user_prompt_submit` on every `UserPromptSubmit`, snapshots the current git worktree state (via `git stash create`, falling back to `HEAD`) as the new review baseline. When a turn makes a dangerous change purely through `Bash` (not `Edit`/`Write`, which is what populates `touched_paths` via `record_touched_path`) and that turn is interrupted before the `Stop` hook fires, the next `UserPromptSubmit` sees an empty `touched_paths` list, skips the baseline-preservation guard, and re-captures a baseline that already includes the dangerous commit — permanently removing it from any future `git diff <baseline>` comparison used by `compute_v2_review_set`.

### Finding Description
`handle_user_prompt_submit` in `plugins/security-guidance/hooks/security_reminder_hook.py` (lines 486-503) decides whether to overwrite the stored `baseline_sha`/`head_at_capture` or preserve the prior ones: [1](#0-0) 

The preservation branch only fires `if state.get("touched_paths") and state.get("baseline_sha")`. `touched_paths` is populated by `record_touched_path`, which is called from the pattern-rule `PostToolUse` handler for `Edit`/`Write`/`MultiEdit`. A dangerous change made purely via the `Bash` tool (e.g. `sed -i`, `cat >>`, or a direct `git commit` of attacker-influenced content) does not go through that code path, so `touched_paths` can remain empty even though the working tree/HEAD has moved.

If the turn is then interrupted before `Stop` fires (`consume_stop_state` never runs, so `touched_paths` is never populated from that turn either), the next `UserPromptSubmit` calls `capture_git_baseline` and, seeing no `touched_paths`, overwrites `baseline_sha` with a fresh snapshot of the *current* (already-dangerous) tree: [2](#0-1) 

This is explicitly called out as a known limitation in `compute_v2_review_set`'s docstring: [3](#0-2) 

Once the baseline has shifted past the dangerous commit, `compute_v2_review_set` computes `changed_since = git diff --name-only <new baseline>`, which no longer contains the dangerous file, and `dirty_now` (from `git status`) also won't contain it if the tree is otherwise clean: [4](#0-3) 

The `head_at_capture`/`_is_ancestor` linear-commit-inclusion logic only compensates for commits made *within the same turn* before `Stop` fires; it does nothing once the baseline itself has been recaptured on a subsequent `UserPromptSubmit`. The dangerous code is thus permanently excluded from both the Stop-hook LLM review and the commit/push review paths that rely on the same baseline/touched-path bookkeeping.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths." A dangerous change that should have been surfaced by the Stop-hook security review is silently and permanently dropped because the baseline shifts to include it before any diff is computed against it. This is a logic-level bypass of a required security guard (the LLM-based vulnerability scan), matching "Logic-level service disruption caused by bypassing a required guard or misbinding security state" — dangerous/injected code can land in the repository without ever being flagged by the plugin meant to catch it.

### Likelihood Explanation
Requires no elevated privilege: any workflow where Claude executes a `Bash`-only edit/commit sequence (e.g., driven by prompt-injected instructions in repository content, an issue, or a tool response) and the turn is interrupted (user Ctrl-C, session drop, tool-reject, crash, `maxTurns`) before `Stop` runs will reproduce this. The condition is explicitly acknowledged by the plugin authors as a known limitation, indicating it is a real, reachable, and repeatable gap rather than a hypothetical edge case.

### Recommendation
Do not gate baseline preservation solely on `touched_paths`. Also preserve (or merge) the baseline whenever the previous turn's `Stop` state was never consumed (e.g., track a `pending_review` flag set at `UserPromptSubmit`/`PreToolUse[Bash]` time and cleared only by `consume_stop_state`), or compare `head_at_capture` against the git reflog to detect any HEAD movement or worktree mutation that occurred without a corresponding `Stop` consumption, and preserve the old baseline in that case regardless of `touched_paths` contents.

### Proof of Concept
Unit/integration test plan in a temp git repo:
1. Init repo, commit an initial file, start a session (`session_id`), call `handle_user_prompt_submit` to capture baseline A (`head_at_capture=H0`).
2. Simulate a Bash-only dangerous edit: write a vulnerable pattern into a tracked file and `git commit` it directly (bypassing `record_touched_path`/`Edit`/`Write`), producing `H1`. Do **not** call `consume_stop_state` (simulating an interrupted turn) — `touched_paths` remains `[]`.
3. Call `handle_user_prompt_submit` again (next turn). Assert `state["baseline_sha"]` and `state["head_at_capture"]` have been overwritten to reflect `H1` (the tree containing the dangerous commit), instead of being preserved as baseline A/`H0`.
4. Call `compute_v2_review_set(cwd, new_baseline_sha, new_head_at_capture, untracked_at_baseline)` and assert the dangerous file's path is **absent** from the returned `review_paths`, proving the change is no longer reviewable — violating the expectation that "the computed review set still contains the dangerous file."

```python
def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None
```
