### Title
Attacker-controlled default branch name beginning with `-` can be parsed as a git option in `merge-base --is-ancestor`, bypassing the fast-forward/diverging-changes check - ([File: pkg/cmd/repo/sync/git.go])

### Summary
`gitExecuter.IsAncestor` builds `git merge-base --is-ancestor <ancestor> <progeny>` by directly splicing the caller-supplied `ancestor` string into the argv without a `--` separator to force revision parsing. [1](#0-0)  In `syncLocalRepo`/`executeLocalRepoSync`, the `ancestor` value is `opts.Branch`, which defaults to the *attacker's* repo default branch name fetched via `api.RepoDefaultBranch(apiClient, srcRepo)` whenever the victim doesn't pass `--branch`. [2](#0-1) [3](#0-2)  If this branch name begins with `-`, it can be interpreted by git as an option rather than a revision.

### Finding Description
The call chain is: `syncLocalRepo` → `api.RepoDefaultBranch` (attacker-controlled) → `executeLocalRepoSync(srcRepo, remote, opts)` → `git.HasLocalBranch(branch)` (true precondition given) → `git.IsAncestor(branch, "FETCH_HEAD")` → `gitExecuter.IsAncestor`, which does:
```go
args := []string{"merge-base", "--is-ancestor", ancestor, progeny}
```
with no `--` separating options from revisions. [4](#0-3) 

The codebase's own maintainers are already aware of this exact injection class: `pkg/cmd/pr/checkout/checkout.go` explicitly rejects any `pr.HeadRefName` starting with `-` before using it in git argv construction (`if strings.HasPrefix(pr.HeadRefName, "-") { return fmt.Errorf(...) }`). [5](#0-4)  No equivalent guard exists for `opts.Branch`/the default branch value flowing through `pkg/cmd/repo/sync/sync.go` and `pkg/cmd/repo/sync/git.go`, and none of the other exec sites in `git.go` (`UpdateBranch`, `CreateBranch`, `MergeFastForward`, `ResetHard`) insert a `--` separator either. [6](#0-5) 

`IsAncestor`'s return semantics compound the risk: any failure of the underlying git invocation (including a parse/usage error caused by option injection) is swallowed and reported simply as `false, nil` — i.e., "not a fast-forward" — rather than surfacing the parse error:
```go
_, err = cmd.Output()
return err == nil, nil
```
This means the function can never itself signal that the check was subverted; callers only see a boolean. [7](#0-6) 

### Impact Explanation
`executeLocalRepoSync` relies entirely on `IsAncestor`'s boolean to gate the diverging-changes protection:
```go
fastForward, err := git.IsAncestor(branch, "FETCH_HEAD")
...
if !fastForward && !useForce {
    return divergingError
}
``` [8](#0-7) 
If this boolean were spoofed to falsely report `true` (ancestor), the code would proceed to `git.UpdateBranch(branch, "FETCH_HEAD")` — an unconditional `update-ref` that overwrites the local branch ref regardless of the `--force` flag — potentially discarding unpushed local commits without the diverging-changes safeguard the design intends. [9](#0-8) [10](#0-9) 

However, I could not construct or confirm a concrete `merge-base --is-ancestor` option-injection payload that reliably forces git to *exit 0* (falsely reporting "is ancestor") for an unrelated commit. `git merge-base --is-ancestor` only recognizes a small, fixed set of long options (`--all`, `--octopus`, `--independent`, `--fork-point`), and injecting any of them alongside the already-fixed `--is-ancestor` argument produces a usage error and a non-zero exit in ordinary git behavior, which `IsAncestor` maps to `false` — the *safe* (fail-closed) outcome, not a bypass. I was not able to identify a git option that both (a) is accepted in this exact argv shape and (b) causes a spurious success exit code, so I cannot confirm the specific "hard reset / data loss" outcome described in the question is achievable through this particular call site with currently known git option semantics. This is a real gap in argument hygiene (missing `--` separator, unlike the explicit dash-prefix rejection already present in `checkout.go`), but the scoped, concrete "bypass causing data loss" impact could not be reproduced or verified with the tools available here.

### Likelihood Explanation
Preconditions require the victim to run `gh repo sync` without `--branch` against an attacker's repo, with a local branch already present matching the attacker's default branch name (`hasLocalBranch=true`), and require GitHub to actually permit setting a repository's default branch to a ref name beginning with `-`. Whether GitHub's ref-naming/default-branch API enforces such a restriction was not verified in this codebase and is a git/platform-level question outside `pkg/cmd/repo/sync`.

### Recommendation
Regardless of exploitability confirmation, harden `gitExecuter.IsAncestor` (and the other exec sites in `pkg/cmd/repo/sync/git.go`) to separate options from revision arguments with `--`, e.g. `[]string{"merge-base", "--is-ancestor", "--", ancestor, progeny}`, and/or reject branch names beginning with `-` in `syncLocalRepo`/`executeLocalRepoSync` the same way `pkg/cmd/pr/checkout/checkout.go` does for `pr.HeadRefName`.

### Proof of Concept
Not able to provide a verified reproducible PoC demonstrating the claimed bypass outcome (spurious `true`/exit-0 from `git merge-base --is-ancestor <dash-prefixed-arg> FETCH_HEAD`) within the scope of this analysis; a `git-stub`/integration test would be needed against real `git` to confirm actual exit-code behavior for candidate crafted branch names (`--all`, `--fork-point`, `-q`, etc.), which was not executable here.

func executeLocalRepoSync(srcRepo ghrepo.Interface, remote string, opts *SyncOptions) error {
	git := opts.Git
	branch := opts.Branch
	useForce := opts.Force

	hasLocalBranch := git.HasLocalBranch(branch)
	if hasLocalBranch {
		fastForward, err := git.IsAncestor(branch, "FETCH_HEAD")
		if err != nil {
			return err
		}
		if !fastForward && !useForce {
			return divergingError
		}
		if fastForward && useForce {
			useForce = false
		}
	}
