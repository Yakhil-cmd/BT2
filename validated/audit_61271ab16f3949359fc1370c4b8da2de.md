## Confirmed root cause

`WebhooksController#verify_signature` selects which GitHub App/organization config to use for HMAC verification purely from the attacker-supplied JSON body, then verifies the *entire* raw body against that organization's `webhook_secret`: [1](#0-0) [2](#0-1) 

The signature check itself is a no-op whenever that organization's `webhook_secret` is blank: [3](#0-2) 

`webhook_secret` is explicitly documented/shipped as optional and nil by default: [4](#0-3) 

Once the request passes `verify_signature` (trivially true when the org keyed by `repository.owner.login` has no secret), the handlers act on a *different, independently-controlled* JSON field — `repository.full_name` — to resolve the actual `Repository`/`Stack` to mutate, via `Repository.from_github_repo_name`: [5](#0-4) [6](#0-5) [7](#0-6) 

`repository.owner.login` (used only to pick the app config for the trivial/absent signature check) and `repository.full_name` (used to pick the repo/stack that is actually written to) are two independent, unrelated fields in the same JSON body — nothing ties them together. An attacker who knows any organization in the Shipit config that has no `webhook_secret` set can set `repository.owner.login` to that unsecured org (so `verify_signature` passes unconditionally) while setting `repository.full_name` to the full name of any *other* repository/stack tracked by the instance (including ones belonging to organizations that do have a real secret configured), and the push/status/check_suite/pull_request handlers will act on that unrelated stack.

### Title
Webhook organization used for signature selection is decoupled from the repository actually mutated by handlers, allowing forgery of events for any tracked stack when any configured org has no `webhook_secret` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks the GitHub App config (and thus whether/what secret to check) using `params.dig('repository','owner','login')`, but the event handlers (`Shipit::Webhooks::Handlers::Handler#stacks`, `PushHandler`, `StatusHandler`, etc.) resolve the target `Repository`/`Stack` using the unrelated `params.dig('repository','full_name')` field. Because `GithubApp#verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank (the documented default), an attacker can pick any organization configured without a secret to satisfy the "authenticated organization" check while pointing `repository.full_name` at a completely different, secured stack, causing the handler to act on that stack.

### Finding Description
The binding that should hold is: *the organization whose signature authenticated the request* == *the repository/stack the handler writes to*. `verify_signature` computes `repository_owner` and fetches the matching `Shipit.github(organization: repository_owner)` config, then calls `verify_webhook_signature`, which short-circuits to `true` when that org's `webhook_secret` is absent. No part of this check ties the verified organization to the `repository.full_name` value used downstream by every handler to look up the actual `Repository` record via `Repository.from_github_repo_name`. Since both `repository.owner.login` and `repository.full_name` are ordinary, independently-settable JSON fields in the same unsigned (or trivially-"verified") request body, an attacker can decouple them.

### Impact Explanation
This allows forged webhook events (`push`, `status`, `check_suite`, `pull_request`, `membership`, etc.) to be delivered against any stack tracked by the Shipit instance, as long as at least one configured GitHub organization lacks a `webhook_secret`. Concretely this can trigger `GithubSyncJob`/`sync_github` on arbitrary stacks, forge commit statuses, spoof `check_suite` results that feed into merge-queue decisions, or manipulate pull-request derived review-stack/merge state for repositories that belong to a *different*, properly-secured organization — effectively an unauthorized cross-repository/cross-organization write reachable without any session, token, or the target organization's actual webhook secret.

### Likelihood Explanation
Requires only that the Shipit deployment has multiple configured GitHub organizations and that at least one of them was set up without a `webhook_secret` — which the shipped sample config (`config/secrets.development.shopify.yml`) and setup docs treat as an explicitly supported/optional configuration, not a misconfiguration outside the engine's control. No credentials, sessions, or tokens are needed by the attacker; the request is a plain unauthenticated POST to `/webhooks`.

### Recommendation
Bind the two identities together: derive the target repository/stack lookup from the same organization value that was cryptographically verified (or reject the payload if `repository.owner.login` used for signature selection doesn't match `repository.full_name`'s owner segment). Additionally, consider making `webhook_secret` mandatory for every configured organization rather than silently disabling verification when absent.

### Proof of Concept
Given a Shipit instance configured with two orgs, `unsecured-org` (no `webhook_secret`) and `secured-org` (real stacks, real secret):

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything

{
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "owner": { "login": "unsecured-org" },
    "full_name": "secured-org/victim-repo"
  }
}
```

`verify_signature` computes `repository_owner = "unsecured-org"`, loads that org's (secret-less) `GithubApp`, and `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:77`). The request proceeds to `PushHandler`, which resolves the target via `Repository.from_github_repo_name("secured-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: ...)` on the real, secured-org stack — despite the request never being validated against `secured-org`'s webhook secret.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
