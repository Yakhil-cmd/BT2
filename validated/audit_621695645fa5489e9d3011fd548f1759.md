Based on my investigation, `git commit --amend` does have a real, separately-tracked review pathway (`_resolve_amend_pre_sha`, `is_amend` delta review in `handle_commit_review_posttooluse`), which is a strong signal that the plugin authors specifically considered amend-based baseline confusion — but that mitigation lives in the **commit-review** hook, not in the **Stop-hook** review-set path (`compute_v2_review_set` in `diffstate.py`), which relies purely on `_is_ancestor(head_at_capture, current_head)` to decide whether to union in committed-this-turn changes.

### Title
Stop-hook review set silently drops amended commits when pre-amend HEAD is not an ancestor of post-amend HEAD - (File: plugins/security-guidance/hooks/diffstate.py)

### Summary
`compute_v2_review_set` only unions committed changes into `dirty_now` when `_is_ancestor(head_at_capture, current_head)` is true, but `git commit --amend` produces a commit that is a sibling of the original, not a descendant of `head_at_capture` when the amend happens after `head_at_capture` was already advanced to the pre-amend commit. In that case the working tree is clean (nothing "dirty" per `git status`), so `dirty_now` is empty, and `review_set = dirty_now & changed_since` collapses to the empty set even though `changed_since` (diff against the older `baseline_sha`) does contain the dangerous file.

### Finding Description
`compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) computes:
```
dirty_now = tracked_dirty | new_untracked                     # from `git status`
if head_at_capture != current_head and _is_ancestor(head_at_capture, current_head):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD")
changed_since = _git_name_only(repo, baseline_sha)             # diff vs stash-baseline
review_set = dirty_now & changed_since   # <-- AND, not OR
``` [1](#0-0) 

Consider a two-turn sequence:
1. Turn 1: `git commit` creates commit `C` from parent `P`. `head_at_capture=P`, `_is_ancestor(P,C)` is true, so the committed diff is correctly included and reviewed. At UPS for turn 2, baseline is re-captured: since the tree is clean, `baseline_sha = C` and `head_at_capture = C`.
2. Turn 2: Claude (or repo-controlled automation) edits a dangerous file, stages it, and runs `git commit --amend --no-edit`, producing `C'` — a new commit with the *same parent* `P` as `C`, not a descendant of `C`.
3. At Stop for turn 2: `current_head = C'`, `head_at_capture = C`. `_is_ancestor(C, C')` is **false** (amend rewrites, it does not extend history), so the amend's diff is never unioned into `dirty_now`. The working tree is now clean (amend committed everything), so `tracked_dirty` and `new_untracked` are also empty → `dirty_now = ∅`.
4. `changed_since = _git_name_only(repo, baseline_sha=C)` (i.e., `git diff C`, comparing `C` against the current worktree state which is `C'`) correctly contains the dangerous file, since `C'` differs from `C`.
5. `review_set = ∅ ∩ {dangerous_file, ...} = ∅`. The dangerous file is silently excluded from the Stop-hook's review set even though it was genuinely changed and committed this turn.

`load_baseline_sha` itself (`diffstate.py:50-54`) is a thin state getter with no validation logic — it is simply the source of `baseline_sha` fed into this computation; the actual break of the "review set bound to right baseline" invariant happens in the AND-based intersection combined with the ancestor-only detection of "committed this turn," which does not account for non-fast-forward rewrites (amend/rebase-style history changes). [2](#0-1) [3](#0-2) 

Notably, the authors were aware amend needs special handling — but only implemented it for the separate commit-review PostToolUse hook (`_resolve_amend_pre_sha`, `is_amend`/`pre_amend_sha` delta review in `handle_commit_review_posttooluse`), which independently reviews `git commit`/`--amend` invocations via reflog-derived pre-amend SHAs. [4](#0-3) [5](#0-4) 
That parallel mechanism can act as a compensating control if `ENABLE_COMMIT_REVIEW` is on and `_GIT_COMMIT_RE` matches the amend command, but it is a distinct code path with distinct kill switches (`ENABLE_COMMIT_REVIEW`), gates, and rate limits (`MAX_COMMIT_REVIEWS_PER_HOUR`), so its coverage is not guaranteed identical to the Stop-hook's, and does not fix the underlying logic flaw in `compute_v2_review_set`.

### Impact Explanation
If the compensating commit-review hook is disabled (`ENABLE_COMMIT_REVIEW=0`), rate-limited out, or otherwise skipped (e.g., `ENABLE_STOP_REVIEW` relied on alone, per the documented use case for multi-agent/shared-worktree deployments at `security_reminder_hook.py:154-161`), a dangerous change introduced via `git commit --amend` on a previously-captured commit is never surfaced by the Stop-hook's LLM security review, because the review set computed by `compute_v2_review_set` is empty for that file. This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths," letting a dangerous change slip through the automated review gate — consistent with unauthorized/unreviewed file changes reaching the workspace without the intended review-based backstop. [6](#0-5) 

### Likelihood Explanation
This requires: (1) a session spanning at least two turns/UPS captures so `head_at_capture` for the amend turn is the pre-amend commit rather than the original grandparent, (2) a `git commit --amend` that folds new dangerous content into that commit, and (3) a clean working tree afterward (no other uncommitted dirt to keep `dirty_now` non-empty). These are all achievable via ordinary git operations, no privileged access needed, and amend is a very common workflow ("fix the last commit"). It is not a contrived edge case — it can happen incidentally during normal review-and-fix iteration loops the plugin itself encourages (Stop → fix → amend → Stop again).

### Recommendation
In `compute_v2_review_set`, do not require `_is_ancestor(head_at_capture, current_head)` to include committed-but-clean changes. Instead, when `current_head != head_at_capture`, always include `_git_name_only(repo, f"{head_at_capture}..HEAD")` where resolvable, and treat a failure to compute that diff (e.g. because history was rewritten) as cause for the `changed_since`-alone fallback (union, not intersection) rather than silently zeroing the set. More robustly, compute `review_set = dirty_now | (changed_since if head advanced OR was rewritten)` rather than intersecting an ancestor-conditioned `dirty_now` with `changed_since`, or explicitly detect amend/rebase via reflog (mirroring `_resolve_amend_pre_sha`) in the Stop-hook path itself so it doesn't rely solely on the separate commit-review hook for coverage.

### Proof of Concept
Integration test in a temp git repo:
1. Init repo, commit `file_a.py` (dummy content) → `P`.
2. Simulate UPS turn 1: call `capture_git_baseline`/set `baseline_sha=P`, `head_at_capture=P`.
3. Edit `dangerous.py` with a clearly vulnerable pattern, `git add`, `git commit -m wip` → `C`.
4. Simulate Stop for turn 1 via `compute_v2_review_set(cwd, P, P)`; assert `dangerous.py` is in the returned review set (sanity check that normal commit flow works).
5. Simulate UPS turn 2: baseline becomes `C` (clean tree) → `baseline_sha=C`, `head_at_capture=C`.
6. Edit `dangerous.py` further to inject a second, distinct dangerous change, `git add`, `git commit --amend --no-edit` → `C'` (sibling of `C`, same parent `P`).
7. Call `compute_v2_review_set(cwd, baseline_sha=C, head_at_capture=C)`.
8. **Expected (bug) result**: `dangerous.py` is **absent** from the returned review set, and `metrics["review_set_count"] == 0`, despite `git diff C` showing real differences — demonstrating the invariant break.
9. Assert this fails the security expectation: `assert os.path.join(repo, "dangerous.py") in review_paths` should fail on current code, proving the gap.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```

def _resolve_amend_pre_sha(repo_root, expected_post_sha=None):
    """For a `git commit --amend` we just ran, return the pre-amend SHA via
    reflog, or None if it can't be safely determined.

    expected_post_sha: the post-amend SHA the caller parsed from bash stdout
    (or reflog). If provided, HEAD@{0} of `repo_root` must match it (prefix
    compare — bash stdout SHAs are abbreviated, reflog %H is 40 chars) before
    we trust the reflog-derived pre-amend SHA. This guards against the
    cross-repo case (`cd ../other && git commit --amend && cd -`) where
    `repo_root` happens to have its own recent amend that's unrelated to
    the bash command we're reviewing.

    We require HEAD@{0}'s reflog subject to start with `commit (amend)` —
    otherwise our `--amend` regex matched something that didn't actually
    perform an amend (e.g., `git commit --amend --dry-run`, aliased commands,
    aborted amends), and HEAD@{1} would be the wrong commit. Also requires
    HEAD@{1} to NOT itself be an amend, since back-to-back amends would have
    HEAD@{1} as the previous-amend's post state — the original commit we
    want to compare against is then HEAD@{2}, but at that point we're
    reaching and fall back to a full review.

    Bytes + decode('utf-8', errors='replace'): reflog subjects embed commit
    subjects, which git stores as raw bytes (commit messages may be latin-1
    / cp1252 / etc.). text=True would raise UnicodeDecodeError (a
    ValueError, not OSError) on non-UTF8 bytes and crash the hook.
    """
    if not repo_root:
        return None
    try:
        r = subprocess.run(
            [*GIT_CMD, "log", "-g", "-2", "--format=%H|%gs", "HEAD"],
            cwd=repo_root, capture_output=True, timeout=5,
        )
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
    if r.returncode != 0:
        return None
    stdout_text = r.stdout.decode("utf-8", errors="replace")
    lines = [ln for ln in stdout_text.splitlines() if "|" in ln]
    if len(lines) < 2:
        return None
    head0_sha, _, head0_subj = lines[0].partition("|")
    head1_sha, _, head1_subj = lines[1].partition("|")
    if not head0_subj.startswith("commit (amend)"):
        return None
    if head1_subj.startswith("commit (amend)"):
        return None
    # Cross-repo guard: the post-amend SHA the caller is about to review must
    # match HEAD@{0} of repo_root. Otherwise the bash command was likely run
    # in a different repo than repo_root, and the reflog we just read is
    # unrelated. Prefix-compare: expected_post_sha is typically the 7-char
    # abbreviated SHA captured from bash stdout by _COMMIT_SHA_RE (git's
    # default core.abbrev floor), while head0_sha is the full 40-char %H —
    # strict equality would always fail and silently disable the delta path.
    if expected_post_sha and not head0_sha.startswith(expected_post_sha):
        return None
    return head1_sha or None
```
