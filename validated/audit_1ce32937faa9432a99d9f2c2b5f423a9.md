### Title
Webhook signature verification is keyed to an attacker-controlled organization field that is decoupled from the repository the event actually acts on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate the inbound HMAC signature against using `repository_owner`, a value read directly from the untrusted JSON body (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). Once verification "passes," the actual event handlers (`Shipit::Webhooks::Handlers::Handler#repository_name`, used by `PushHandler`, `PullRequest::*Handler`, etc.) act on a completely independent field of the same body: `payload.dig('repository', 'full_name')`. Nothing binds these two fields together, so the "organization that authenticated" and the "repository that is written" can be made to diverge.

### Finding Description
In a multi-organization Shipit deployment (`config/secrets.yml` with multiple top-level GitHub org keys, as documented in `docs/setup.md`), each organization has its own independently configured `webhook_secret`, which per `secrets.development.example.yml`/`secrets.development.shopify.yml` may legitimately be left `nil` ("# nil").

`WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) does:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
```
`repository_owner` is taken from the attacker-supplied JSON body itself, before any authentication occurs. `Shipit.github(organization:)` (`lib/shipit.rb:170-181,196-200`) resolves this string, case-insensitively, to whichever org's config block exists in `secrets.github`.

`GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`):
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```
returns `true` unconditionally when that organization's `webhook_secret` is blank/unset.

Meanwhile, the actual side effects use a different field entirely — `Handler#repository_name` (`app/models/shipit/webhooks/handlers/handler.rb:36-38`):
```ruby
def repository_name
  payload.dig('repository', 'full_name')
end
```
which drives `Repository.from_github_repo_name(repository_name)` and, through it, which `Stack` receives `sync_github`, review-stack archiving/unarchiving, commit-status writes, etc. (`PushHandler`, `PullRequest::OpenedHandler`, `ClosedHandler`, `LabeledHandler`, etc. all resolve their target repository this way).

Because `repository.owner.login`/`organization.login` and `repository.full_name` are two independent, attacker-controlled JSON fields in the same unauthenticated POST body, an attacker can craft a payload where:
- `organization.login` (or `repository.owner.login`) = an org configured in `secrets.github` **without** a `webhook_secret` (a legitimate, documented configuration state), causing `verify_webhook_signature` to short-circuit to `true` with no cryptographic check at all, and
- `repository.full_name` = the full name of a *different*, protected organization's repository/stack that Shipit tracks.

The request sails through `verify_signature` unauthenticated, and the event handler then acts on the protected repository's stack (triggering `sync_github`, archiving/unarchiving review stacks, writing commit statuses, etc.) using data the attacker fully controls.

### Impact Explanation
This breaks the trust binding "organization the webhook was authenticated for == repository the event is applied to." It allows an unauthenticated, unprivileged network attacker to forge GitHub webhook events (push, pull_request, status, check_suite, membership, etc.) for stacks belonging to an organization whose webhook secret is configured and unknown to the attacker, simply by routing signature verification through a sibling organization that has no secret configured. Consequences include:
- Forged `push` events causing `GithubSyncJob`/`sync_github` to run against arbitrary shas for a real stack, corrupting commit/deploy state used to gate deploys.
- Forged `pull_request` events causing review stacks to be created, archived, or unarchived (provisioning/deprovisioning infrastructure) without any legitimate GitHub activity.
- Forged `membership`/`status`/`check_suite` events manipulating team membership, CI/commit status data that feeds into deploy safety checks (`Commit#deployable?`), potentially contributing to an unauthorized deploy pathway.

This aligns with the "High" category: unauthenticated manipulation of stack/task state via a webhook signature bypass, without needing any session, API token, or secret.

### Likelihood Explanation
Requires a multi-organization Shipit deployment, which is an explicitly documented and supported configuration (`docs/setup.md`, `secrets.development.shopify.yml`), and requires at least one configured organization to have `webhook_secret` left blank — also explicitly shown as a valid, common configuration (`webhook_secret: # nil`) in the example secrets files. No credentials, tokens, or write access are required from the attacker; only network access to the `/webhooks` (or engine-mounted webhook) endpoint is needed. This makes exploitation realistic wherever this common, documented setup exists.

### Recommendation
Bind signature verification to the same repository field the handlers act on, not an independently attacker-controlled organization field:
- Derive the verifying organization from `repository.full_name`'s owner segment (the same value used by `Repository.from_github_repo_name`) rather than trusting `repository.owner.login`/`organization.login` directly, or
- Cross-check that `repository.owner.login` matches the owner segment of `repository.full_name` before using it to select a `webhook_secret`, and
- Do not allow `verify_webhook_signature` to auto-pass (`return true unless webhook_secret`) for any organization that also has other organizations configured with a secret in the same install — require every organization in a multi-org install to configure a `webhook_secret`, or reject events whose claimed organization has no secret while other organizations do.

### Proof of Concept
Given `secrets.github` configured with two orgs, `OrgA` (has a real `webhook_secret`) and `OrgB` (no `webhook_secret`, `# nil`), and Shipit tracking a stack for `OrgA/protected-repo`:

```
POST /webhooks HTTP/1.1
X-Github-Event: push
Content-Type: application/json

{
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "organization": { "login": "OrgB" },
  "repository": {
    "owner": { "login": "OrgB" },
    "full_name": "OrgA/protected-repo"
  }
}
```
- `verify_signature` calls `Shipit.github(organization: 'OrgB')`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of (or absent) `X-Hub-Signature`.
- `PushHandler#process` then resolves `stacks` via `Repository.from_github_repo_name('OrgA/protected-repo')` and invokes `stack.sync_github(expected_head_sha: 'deadbeef...')` on the real, protected stack — with no valid signature ever presented for `OrgA`.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
