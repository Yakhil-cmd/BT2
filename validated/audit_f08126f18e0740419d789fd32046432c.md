### Title
Stale owner-stamped delegate grants survive NFT transfer and regain authority on return - (`contracts/controller/src/storage/account.rs`)

### Summary
A `DelegateGrant` persists under the account ID and is only filtered by `granted_by`; an NFT ownership change hides the grant but does not clear it. [1](#0-0) 
When the position NFT later returns to the original owner, the stale `granted_by` matches again and the old delegate silently regains account-control authority. [2](#0-1) 

### Finding Description
Account ownership is resolved dynamically from the position NFT rather than being stored in account metadata. [3](#0-2) 
`get_delegates` reads the single `Delegates(account_id)` entry and returns its list only when `grant.granted_by` equals the current NFT owner. [4](#0-3) 
The position NFT uses the stock enumerable token implementation for `transfer`, so ownership changes do not notify the controller or delete the controller-side delegate entry. [5](#0-4) 
A subsequent owner can purge a stale grant only by explicitly invoking `remove_delegate`, which deletes a mismatched grant. [6](#0-5) 
If that owner performs no delegate write before transferring the NFT back, the original grant remains stored and becomes active for the original owner again. [2](#0-1) 

### Impact Explanation
A resurrected delegate can call owner-gated operations such as `borrow`, which may pay proceeds to an arbitrary `to` address. [7](#0-6) 
The same delegate can call `withdraw`, including a zero-amount full-position withdrawal, and direct collateral to itself through `to`. [8](#0-7) 
This permits theft of the returning owner's collateral and borrowed assets without any authorization granted after that owner reacquired the account. [8](#0-7) 

### Likelihood Explanation
The exploit requires an account that previously granted an active delegate, an NFT transfer to another owner, and a later transfer back without an intervening delegate write or purge. [2](#0-1) 
That sequence is reachable through ordinary position-NFT transfers, such as temporary custody, marketplace sale and repurchase, or a malicious manager returning an account to the victim. [5](#0-4) 
Because an ownership change makes the old grant read as empty, the intermediate owner has no normal indication that a dormant grant still needs to be purged. [4](#0-3) 

### Recommendation
Invalidate delegate grants on every NFT ownership change rather than filtering them by owner address. [4](#0-3) 
For example, store an ownership epoch or NFT transfer counter inside `DelegateGrant`, have the NFT notify the controller during `transfer`, or remove `Delegates(account_id)` in the transfer path. [9](#0-8) 
At minimum, treat any mismatched stored grant as permanently revoked for both future owners and the original owner unless the current owner explicitly re-grants the delegate. [10](#0-9) 

### Proof of Concept
```rust
// Alice owns account_id and has collateral deposited.
controller.add_delegate(alice, account_id, mallory_delegate);
// Stored grant: DelegateGrant { granted_by: alice, delegates: [mallory_delegate] }.

position_nft.transfer(alice, bob, account_id_as_u32);
// The grant now reads as empty for Bob, but remains stored.

position_nft.transfer(bob, alice, account_id_as_u32);
// No delegate entry was overwritten or removed, so granted_by == alice again.

controller.withdraw(
    mallory_delegate,
    account_id,
    vec![(collateral_hub_asset, 0)], // full collateral position
    Some(mallory_delegate),
);
```

The final withdrawal succeeds because owner or delegate authorization is sufficient and zero requests the full position. [8](#0-7) 
The dormant grant survives because the transfer path does not clear controller-side `Delegates(account_id)` and the account is not being deleted. [11](#0-10)

/// Stores delegates stamped by the granting owner and renews user TTL;
/// deletes the entry when the list is empty.
fn set_delegates(env: &Env, account_id: u64, owner: &Address, delegates: &Vec<Address>) {
    let key = ControllerKey::Delegates(account_id);
    if delegates.is_empty() {
        env.storage().persistent().remove(&key);
    } else {
        set_user(
            env,
            &key,
            &DelegateGrant {
                granted_by: owner.clone(),
                delegates: delegates.clone(),
            },
        );
    }
