### Title
Cross-tenant HMAC/repository binding gap lets a forged `pull_request` `closed` event archive an unrelated victim `ReviewStack` - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/secret used to authenticate a webhook from `params.dig('repository','owner','login')` [1](#0-0)  and `GitHubApp#verify_webhook_signature` trivially returns `true` when that organization has no configured `webhook_secret` [2](#0-1) . `ClosedHandler`, however, resolves the repository/stack it mutates from the independent `params.repository.full_name` field [3](#0-2) , with no check that this repository belongs to the organization that authenticated the request. This lets an attacker authenticate via a "no-secret" org and archive a `ReviewStack` belonging to an entirely different, victim organization's repository.

### Finding Description
The broken binding, stated as an equality that the code never enforces:

`org_used_for_HMAC(params.repository.owner.login) == org_that_owns(params.repository.full_name)`

Trace:
1. `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository','owner','login')` and calls `Shipit.github(organization: repository_owner)` then `verify_webhook_signature` [4](#0-3) .
2. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected org's config has no `webhook_secret` set: `return true unless webhook_secret` [2](#0-1) . If the org is unknown, a `GithubOrganizationUnknown` is raised and the request is rejected with 422 [5](#0-4) , so the attacker must pick an org that IS configured in `Shipit.github_teams`/multi-org config but simply lacks a `webhook_secret`.
3. Once verification passes, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches the full, attacker-controlled JSON body — including `repository.full_name` — to `ClosedHandler` [6](#0-5) .
4. `ClosedHandler#repository` resolves the target repository purely from `params.repository.full_name`, entirely decoupled from the org used in step 1 [3](#0-2) .
5. `ClosedHandler#process` then calls `review_stack.archive!` scoped to `repository.review_stacks` and matched only by `environment`/`pr_number` [7](#0-6) , and `ReviewStackAdapter#archive!` removes the stack from the provisioning queue, deprovisions it, and archives it [8](#0-7) .

Attacker request: a forged `pull_request` webhook, `action=closed`, `X-Github-Event: pull_request`, any `X-Hub-Signature` (ignored since no secret is configured for the chosen org), body with `repository.owner.login = "no-secret-org"` and `repository.full_name = "victim-org/victim-repo"`, `number` set to the target review-stack's PR number.

No existing guard closes this gap: `drop_unhandled_event` only checks the event type exists [9](#0-8) ; there is no cross-check between `repository_owner` (used for auth) and `repository.full_name` (used for mutation) anywhere in the controller or handler; `ExplicitParameters` in `ClosedHandler.params` only validates shape/types, not cross-field consistency [10](#0-9) .

Note on the `ignore_ci`/`Commit#deployable?` amplification claimed in the question: `ClosedHandler` never calls `deployable?` or triggers a deploy — it only calls `archive!`, which deprovisions/archives the review stack [7](#0-6) . `Commit#deployable?` short-circuiting on `stack.ignore_ci?` [11](#0-10)  is unrelated to this code path and does not amplify this specific handler's impact — the `ignore_ci true` precondition in the question is not load-bearing here.

### Impact Explanation
An unprivileged attacker who knows (a) any org configured on the Shipit instance that lacks a `webhook_secret`, and (b) a victim org/repo/PR number, can forge a `pull_request` `closed` event that authenticates using the no-secret org's (non-)secret but archives/deprovisions a `ReviewStack` belonging to a completely different, victim repository. This is a payload for one repository/tenant mutating another repository's stack state, matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." It is repeatable against any PR number/environment of any repository reachable via `Repository.from_github_repo_name`, and blast radius spans all tenants sharing the Shipit instance if any configured org omits a `webhook_secret`.

### Likelihood Explanation
Preconditions: the Shipit instance must be configured in multi-organization mode (`Shipit.github_organizations`) with at least one organization lacking a `webhook_secret` (a real-world misconfiguration, not a secret the attacker needs to know), and review stacks (PR-based stacks) must be enabled for the victim repository. Given those, the attacker's cost is trivial — a single unauthenticated HTTP POST with a crafted JSON body and no valid signature needed. This is fully repeatable and requires no privileged role, session, or token.

### Recommendation
Cross-validate that the organization used to authenticate the webhook (`repository.owner.login` / `organization.login`) matches the organization embedded in `repository.full_name` before dispatching to handlers, and reject/422 on mismatch. Additionally, do not treat an org lacking a `webhook_secret` as automatically verified — either require a hard secret for all configured organizations or refuse to process events for the always-verified path when signature is absent/empty.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
```ruby
test "pull_request closed forged via no-secret org archives victim repo's review stack" do
  # Precondition: configure two orgs, "no-secret-org" (no webhook_secret) and "victim-org" (has webhook_secret)
  victim_stack = shipit_stacks(:review_stack) # belongs to victim-org/victim-repo, environment matches PR number

  binding_before_owner = "no-secret-org"
  binding_before_full_name = victim_stack.github_repo_name # "victim-org/victim-repo"
  assert_not_equal binding_before_owner, binding_before_full_name.split('/').first

  payload = {
    action: "closed",
    number: victim_stack.pull_request_number,
    pull_request: { ... head: { sha: "...", ref: "..." }, user: { login: "attacker" }, assignees: [], labels: [] },
    repository: { owner: { login: binding_before_owner }, full_name: binding_before_full_name },
    sender: { login: "attacker" }
  }.to_json

  assert_not victim_stack.reload.archived?

  post :create, body: payload, params: {}, headers: {
    'X-Github-Event' => 'pull_request',
    'X-Hub-Signature' => 'sha1=deadbeef' # invalid, but org has no secret so verify_webhook_signature returns true
  }

  assert_response :ok
  assert victim_stack.reload.archived?, "victim-org's stack was archived by a request authenticated as no-secret-org"
end
```
This demonstrates the equality `org_used_for_HMAC != org_that_owns_mutated_repo` holds both before and after the request, and the mutation still succeeds against the victim stack.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
