Based on my investigation, I found a concrete analog in the `security-guidance` plugin's Stop-hook review pipeline that mirrors the TraderJoe bug's core pattern: a "freshness" reference gets advanced unconditionally while the enforcement/decay state that should gate it only updates conditionally, letting a cheap, repeatable trigger permanently defeat the protection.

### Title
Security-review coverage can be permanently and cheaply defeated by exhausting Stop-hook fire budget, then having the baseline silently absorb the unreviewed edits - (File: plugins/security-guidance/hooks/security_reminder_hook.py, plugins/security-guidance/hooks/diffstate.py)

### Summary
The `security-guidance` plugin's `Stop` hook (`handle_stop_hook`) reviews code changes for vulnerabilities by diffing the working tree against a `baseline_sha` captured at `UserPromptSubmit` (`handle_user_prompt_submit`). If the hook is skipped for almost any reason other than `skip_reason=10` (unreachable API), `baseline_sha` is **not** rolled forward and `touched_paths` has already been cleared by `consume_stop_state`. The next `UserPromptSubmit` then unconditionally overwrites `baseline_sha` with a fresh snapshot of the *current* (already-edited) tree, because its "preserve old baseline" guard only fires when `touched_paths` is non-empty [1](#0-0) .

### Finding Description
`consume_stop_state` atomically snapshots and clears `touched_paths` at the start of every `Stop` fire, regardless of whether the review actually completes [2](#0-1) .

`handle_stop_hook` has many early-exit paths (`_skip(...)`) that do **not** call `restore_unreviewed_stop_state` and do **not** advance `baseline_sha`:
- `skip_reason=2`: `fire_count >= MAX_STOP_HOOK_FIRINGS` [3](#0-2) 
- `skip_reason=3`: review disabled / no API credentials
- `skip_reason=4,6,7,8,9,35,50`: no cwd, empty diff, no source files, pathological diff, all findings already deduped, `ENABLE_STOP_REVIEW=0`

Only `skip_reason=10` (`api.anthropic.com` unreachable) calls `restore_unreviewed_stop_state(session_id, touched_paths, snap_baseline)` to re-arm the preservation guard [4](#0-3) .

`baseline_sha` is only advanced forward when `concrete_guidance` (i.e., vulnerabilities were actually found and reported) is non-empty [5](#0-4) . When the Stop hook skips for any of the reasons above, the diff between the un-advanced `baseline_sha` and the new edits is never generated during that Stop fire, and `touched_paths` (which is what protects the stale baseline from being overwritten) is already empty.

Consequently, on the very next `UserPromptSubmit`, the `_save` closure's guard `if state.get("touched_paths") and state.get("baseline_sha")` evaluates false, so it unconditionally recaptures `baseline_sha` to the *current* tree state — silently folding the never-reviewed edits into the new "clean" baseline [6](#0-5) . Those edits will never be diffed or flagged, exactly as the TraderJoe bug lets `_fp.time` keep advancing while `volatilityReference` never resets — here the "review baseline" (the state that should gate/decay malicious code exposure) keeps sliding forward even though the underlying protective condition (`touched_paths` recorded + review completed) never fired.

`MAX_STOP_HOOK_FIRINGS` is the cheapest lever: `Stop` hooks are asyncRewake and CC re-fires them each time the hook exits with code 2 to force continuation; the plugin caps re-fires per loop and, once exceeded, exits via `skip_reason=2` with no restore [3](#0-2) .

### Impact Explanation
An attacker who can influence a Claude Code session (e.g., via prompt injection controlling what the agent does within a turn, or a malicious skill/plugin instructing repeated edits) can cause the `Stop` hook's fire budget to be exhausted, or exploit any of the other no-restore skip paths, in the same turn as a malicious code change. The malicious edit is then silently absorbed into the next baseline and permanently escapes the LLM-based security review (`analyze_code_security`) for the rest of the session — at essentially zero cost (no extra API calls, no extra permission prompts), analogous to how the TraderJoe attacker cheaply kept fees maxed by exploiting a timestamp-refresh/decay-reference disconnect. This weakens (but does not eliminate — pattern-based `check_patterns` reminders still fire independently) the security-guidance plugin's defense-in-depth for that project.

### Likelihood Explanation
This requires (a) the `security-guidance` plugin to be installed/enabled, and (b) some ability to trigger multiple quick Stop-hook re-fires or one of the other no-restore skip conditions within a single turn immediately after (or including) the malicious edit — realistic via prompt injection that causes Claude to keep producing exit-code-2-triggering output, or simply relying on normal skip conditions (rate limiting, API unreachability without hitting reason 10 specifically, disabled flags) that occur in ordinary usage. It does not require any privilege escalation or bypass of Claude Code's core permission system itself — it only defeats this optional security-guidance plugin's review coverage.

### Recommendation
Make baseline preservation the default, not opt-in via `touched_paths` non-emptiness:
1. Have every `_skip(...)` path in `handle_stop_hook` that has not confirmed a clean, fully-reviewed diff call `restore_unreviewed_stop_state` (or an equivalent "mark baseline stale, do not advance" flag), not just `skip_reason=10`.
2. In `handle_user_prompt_submit`'s `_save`, do not overwrite `baseline_sha` based solely on `touched_paths` being non-empty; instead track an explicit "last Stop fully reviewed and cleared" boolean that is only set true when `handle_stop_hook` completes (found findings and rebaselined, or found a clean diff — `skip_reason=6/7/9`) rather than skipped for capacity/availability/config reasons.
3. Add telemetry/logging when a baseline is overwritten while `stop_hook_fire_count` hit its cap, so operators can detect this coverage gap.

### Proof of Concept
Not executed (this is a plugin hook running in the developer's own environment, not something I can execute here). Conceptually:
1. Enable the `security-guidance` plugin with a low `MAX_STOP_HOOK_FIRINGS` (or rely on the default).
2. Within one turn, have Claude make a malicious edit (e.g., introduce a `subprocess.run(shell=True, ...)` with attacker-controlled input) and then perform several additional trivial edits/turns that each cause the Stop hook to re-fire (exit code 2) until `fire_count >= MAX_STOP_HOOK_FIRINGS` is reached, hitting `skip_reason=2` with no baseline restore.
3. Submit the next prompt — `handle_user_prompt_submit` finds `touched_paths` empty (cleared by the exhausted `consume_stop_state`) and unconditionally recaptures `baseline_sha` to the current (already-malicious) tree state [7](#0-6) .
4. Confirm via debug logs / `previous_findings` state that the malicious diff is never analyzed by `analyze_code_security` in any subsequent Stop or commit-review fire, since it now predates every future baseline.

def handle_user_prompt_submit(input_data):
    """
    Handle UserPromptSubmit — capture git baseline SHA.
    Called on every user prompt. Updates the baseline so the stop hook
    only reviews changes made since the last prompt.

    Does NOT reset touched_paths/fire_count/previous_findings — those are
    consumed by Stop (consume_stop_state) and time-expired respectively.
    UPS racing the asyncRewake Stop hook caused a meaningful share of reviews
    to be lost when the wipe landed before Stop's state read.

    """
    cwd = input_data.get("cwd", "")
    if not cwd:
        debug_log("UPS: no cwd, skipping baseline capture")
        sys.exit(0)

    session_id = input_data.get("session_id", "default")
    # stash-create and ls-files both walk the worktree (~2-5s each in a very
    # large repo). Run them concurrently so UPS latency stays ≈ max(both).
    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
        # Always capture the untracked snapshot. `git stash create` returns
        # empty when there are no TRACKED changes, but pre-existing untracked
        # files still need to be excluded from the next Stop's review_set —
        # otherwise an untracked-only working tree gets every untracked file
        # reviewed on every turn until something tracked is dirtied.
        untracked_now = _f_ut.result() or {}
    head = _git_rev_parse_head(cwd)

    # If the previous turn's Stop hook never ran (user interrupt, follow-up
    # during work, tool-reject, model crash, maxTurns, PostToolUse block…),
    # touched_paths is still populated because consume_stop_state is the only
    # consumer and it runs under the state lock. Overwriting baseline_sha now
    # would re-baseline *past* those unreviewed edits, making them permanently
    # invisible to the next Stop. Preserve the old baseline so the next Stop
    # diffs the aborted turn's edits plus the new turn's edits together.
    preserved = {"value": False}

    def _save(state):
        # Only preserve if there's actually an old baseline to preserve.
        # First UPS of a session can have touched_paths if PostToolUse
        # somehow ran first (print mode, odd harnesses) — in that case
        # we still need to capture a baseline.
        if state.get("touched_paths") and state.get("baseline_sha"):
            preserved["value"] = True
            return
        if sha:
            state["baseline_sha"] = sha
            state["head_at_capture"] = head
        # untracked_at_baseline is independent of whether the stash produced
        # a SHA — write it unconditionally so compute_v2_review_set's
        # preexisting-untracked exclusion works in untracked-only trees.
        state["untracked_at_baseline"] = untracked_now
    with_locked_state(session_id, _save)

def consume_stop_state(session_id):
    """Atomically snapshot all state the Stop hook needs and clear touched_paths.

    The Stop hook is asyncRewake — it runs in the background after Claude's
    turn ends. The user can submit a new prompt before this hook finishes its
    initial state read. Telemetry showed a meaningful share of would-be reviews lost when
    the next turn's UPS wiped touched_paths before Stop read it.

    Single locked read-then-clear closes that window: PostToolUse appends
    after this clear go into the next snapshot; UPS overwrites of baseline_sha
    after this snapshot are invisible to this Stop fire.
    """
    import time as _time
    now = _time.time()

    def _snap(state):
        fire_ts = state.get("stop_hook_fire_count_ts", 0)
        expired = (now - fire_ts) > STOP_LOOP_STATE_TTL_SEC
        findings_ts = state.get("previous_findings_ts", fire_ts)
        findings_expired = (now - findings_ts) > PREVIOUS_FINDINGS_TTL_SEC
        snap = {
            "touched_paths": list(state.get("touched_paths", [])),
            "baseline_sha": state.get("baseline_sha"),
            "head_at_capture": state.get("head_at_capture"),
            "untracked_at_baseline": (
                dict(state["untracked_at_baseline"])
                if isinstance(state.get("untracked_at_baseline"), dict) else {}
            ),
            "fire_count": 0 if expired else state.get("stop_hook_fire_count", 0),
            "fire_count_expired": expired and state.get("stop_hook_fire_count", 0) > 0,
            "previous_findings": [] if findings_expired else list(state.get("previous_findings", [])),
        }
        state["touched_paths"] = []
        return snap
