### Title
Unbounded read of attacker-influenced attestation bundle response can exhaust memory (return-bomb-style DoS) - (File: pkg/cmd/attestation/api/client.go)

### Summary
`gh attestation verify` fetches a Sigstore bundle from a `bundle_url` returned by the Attestations API and reads the entire HTTP response body into memory with no size cap, mirroring the "return bomb" bug class from the report: an untrusted response body of unbounded size is fully buffered before any validation occurs, which can cause an out-of-memory/DoS condition for the caller.

### Finding Description
`LiveClient.getBundle` performs a GET request against a bundle URL taken directly from attestation metadata and reads the whole body with `io.ReadAll(resp.Body)` before any length check or streaming decode: [1](#0-0) 

The `bundle_url` value comes from the `AttestationsResponse` returned by `getAttestations`/`fetchBundleFromAttestations`, which is populated from the GitHub Attestations API response for the digest/repo being verified: [2](#0-1) 

A test even shows the `bundle_url` field is taken verbatim from the JSON attestation payload (`"bundle_url": "https://example.com/bundle"`), confirming it is untrusted, publisher-controlled data rather than a hardcoded/GitHub-only endpoint: [3](#0-2) 

Nowhere in the repository is `io.LimitReader` or `http.MaxBytesReader` used to bound response bodies before buffering (confirmed absent across the codebase), so this unbounded-read pattern is systemic rather than isolated to one call site.

### Impact Explanation
An attacker who publishes an artifact and its own attestation (a normal, permitted workflow for `gh attestation verify`) can set `bundle_url` to point at a host that returns an extremely large or slow-to-terminate body. Because the CLI fully buffers the response with `io.ReadAll` before any size or content validation, this can exhaust the memory of the machine running `gh attestation verify`, causing the process (or system) to crash — a denial-of-service against a security verification workflow. This is analogous to the reported return-bomb issue: unbounded data returned by an untrusted party is trusted to be well-behaved and fully materialized in memory before any check happens.

### Likelihood Explanation
`gh attestation verify` is specifically designed to validate artifacts whose provenance is not yet trusted (that is the point of the command), so the attacker-controlled data path is reachable by design during normal use, not merely stub/mocked usage. No authentication or privilege beyond publishing an attestation/artifact is required, satisfying the "unpriviledged remote-attacker" scope for attestation verification.

### Recommendation
Wrap `resp.Body` with `io.LimitReader` (or `http.MaxBytesReader`) capped to a sane maximum bundle size before calling `io.ReadAll`/`snappy.Decode`, and reject/abort with a clear error if the limit is exceeded, rather than buffering an unbounded response into memory.

### Proof of Concept
1. Publish an artifact and attestation whose Attestations API entry has `bundle_url` pointing to an attacker-controlled HTTP endpoint (as accepted by `fetchBundleFromAttestations`/`getBundle`).
2. Configure that endpoint to stream a very large (e.g., multi-GB) or effectively infinite response body.
3. Run `gh attestation verify` against that artifact/digest.
4. `getBundle` calls `io.ReadAll(resp.Body)` unconditionally, causing the `gh` process to consume unbounded memory and eventually be OOM-killed or hang, denying the verification workflow. [4](#0-3)

func (c *LiveClient) fetchBundleFromAttestations(attestations []*Attestation) ([]*Attestation, error) {
	fetched := make([]*Attestation, len(attestations))
	g := errgroup.Group{}
	for i, a := range attestations {
		g.Go(func() error {
			if a.Bundle == nil && a.BundleURL == "" {
				return fmt.Errorf("attestation has no bundle or bundle URL")
			}

			// for now, we fall back to the bundle field if the bundle URL is empty
			if a.BundleURL == "" {
				c.logger.VerbosePrintf("Bundle URL is empty. Falling back to bundle field\n\n")
				fetched[i] = &Attestation{
					Bundle: a.Bundle,
				}
				return nil
			}

			// otherwise fetch the bundle with the provided URL
			b, err := c.getBundle(safeurl.NewImmutableSafeURL(a.BundleURL))
			if err != nil {
				return fmt.Errorf("failed to fetch bundle with URL: %w", err)
			}
			fetched[i] = &Attestation{
				Bundle: b,
			}

			return nil
		})
	}

	if err := g.Wait(); err != nil {
		return nil, err
	}

	return fetched, nil
}
