### Title
Stale decimals snapshot in `pallet-psm` used indefinitely for mint/redeem conversion despite documented "drift guard" - ([File: substrate/frame/psm/src/lib.rs])

### Summary
`pallet-psm` snapshots each asset's `decimals` at registration time (`PsmInfo::internal_decimals`, `ExternalAssetInfo::decimals`) and uses only that snapshot for the `external_to_internal`/`internal_to_external` conversion math on every `mint`/`redeem` call. The pallet's own documentation and changelog (`prdoc/stable2606/pr_11819.prdoc`, `substrate/frame/psm/README.md`) claim a "Runtime drift guard": `mint`/`redeem` should return `Error::DecimalsMismatch` if the live on-chain decimals metadata diverges from the snapshot, halting that asset until governance intervenes. That guard is not actually implemented — `DecimalsMismatch` is declared once in the `Error` enum and explicitly commented as `"Reserved legacy error; retained to preserve error variant indices"` [1](#0-0) , and it is never referenced anywhere in `mint` or `redeem`. This is the same bug class as the Cooler.sol report: a fixed/stale decimals assumption is baked into the collateral/interest (here, mint/redeem) conversion ratio and is never revalidated against the live, authoritative decimals value, so the peg conversion silently becomes wrong once decimals drift.

### Finding Description
`create_psm` snapshots the internal asset's decimals once, at PSM creation time: [2](#0-1) 

`add_external_asset` snapshots the external asset's decimals once, at approval time (see `ExternalAssetInfo::decimals`, populated when an external is added) [3](#0-2) .

Both `mint` and `redeem` then pull `ext_decimals`/`internal_decimals` exclusively from these stored snapshots, never from the live `T::Fungibles` metadata: [4](#0-3) [5](#0-4) 

This is intentional and tested — `redeem_uses_snapshot_when_internal_decimals_drift` explicitly asserts the pallet keeps using the stale snapshot after `Assets::set_metadata` changes the internal asset's decimals from 6 to 8, with no error and no adjustment to the conversion ratio: [6](#0-5) 

However, the pallet's changelog and README advertise this as a *safety* feature that halts trading rather than silently mispricing it: "Runtime drift guard: mint/redeem return DecimalsMismatch if live metadata diverges from the registration snapshot; that asset halts until governance intervenes" [7](#0-6) . No such check exists in `mint`/`redeem`; the only `DecimalsMismatch` variant in the whole crate is dead code [1](#0-0) .

The conversion arithmetic itself (`external_to_internal`/`internal_to_external`, scaling by `10^diff`) is correct given whatever decimals values it is handed [8](#0-7) ; the flaw is entirely that the decimals values it is handed can become stale relative to the token's real precision without any on-chain mechanism to detect or halt on that divergence, contrary to the documented behavior.

### Impact Explanation
Any unprivileged, signed user calling `mint`/`redeem` (the pallet's normal, permissionless entry points — `#[pallet::call_index(0)]`/`(1)]`, both only `ensure_signed`) is affected once a decimals drift occurs on either the internal or an approved external asset, because the peg ratio computed from the stale snapshot no longer reflects the token's actual precision: [9](#0-8) [10](#0-9) 

Since the internal asset's decimals can be legitimately changed post-creation by its owner via `pallet_assets::set_metadata` (a routine, non-privileged-with-respect-to-PSM operation for the asset team) and the PSM never re-validates or halts, the 1:1 peg the PSM is meant to guarantee breaks: every subsequent `mint`/`redeem` by ordinary users is executed at a wrong scaling factor (off by `10^|old_decimals - new_decimals|`), producing under- or over-collateralized swaps versus the token's true value — the same "increase/decrease in exchange amount due to wrong decimals" impact class as the referenced Cooler.sol report, applied to PSM's mint/redeem instead of Cooler's collateral/interest.

### Likelihood Explanation
The prerequisite (decimals metadata drift after PSM/external registration) is a documented, expected, test-covered scenario in this pallet — not a hypothetical edge case; the pallet's own test suite exercises it, and the changelog explicitly calls out drift as something the pallet needs to defend against. Reaching the vulnerable path requires no attacker privilege at all: any signed account can call `mint`/`redeem`; the only actor needed to trigger the divergence is the (non-PSM) asset owner performing a normal metadata update. This makes the missing halt a real, low-cost-to-trigger correctness gap rather than a purely theoretical one, though it needs a metadata change event to occur (it is not exploitable purely by an attacker with no dependency on any third-party action).

### Recommendation
Implement the drift check the documentation already promises: in `mint`/`redeem`, read live decimals via `T::Fungibles::decimals` for both the internal and external asset and compare against the stored snapshot (`PsmInfo::internal_decimals` / `ExternalAssetInfo::decimals`); if they differ, return `Error::DecimalsMismatch` and require governance (e.g. via a dedicated `resync_decimals`/re-approval call) to update the snapshot before further swaps are allowed. Alternatively, if snapshot-only behavior is the intended design (accepting the drift), remove the misleading "halts until governance intervenes" language from `prdoc/stable2606/pr_11819.prdoc` and `substrate/frame/psm/README.md` and remove the now-provably-dead `Error::DecimalsMismatch` variant, so operators and integrators do not rely on a safety guarantee that does not exist.

### Proof of Concept
- Failed/missing guard evidence: `Error::DecimalsMismatch` is defined but never constructed/returned anywhere in `mint`, `redeem`, or any other dispatchable in `substrate/frame/psm/src/lib.rs` — confirmed by a repo-wide search showing its only two non-error-definition references are in `README.md` and `prdoc/stable2606/pr_11819.prdoc` (documentation only), not in code.
- Deployment/behavior evidence: the existing unit test `redeem_uses_snapshot_when_internal_decimals_drift` in `substrate/frame/psm/src/tests.rs` already runs this exact scenario (mint at decimals=6, then `Assets::set_metadata` changes internal asset decimals to 8, then `redeem` succeeds using the old snapshot ratio with no error), directly demonstrating that the documented halt never fires and swaps continue with a stale conversion ratio [6](#0-5) . I did not execute this test myself (no build/test execution tools available in this session); the analysis is based on static code/test inspection confirming the discrepancy between documented and implemented behavior. A background engineering session with repo access would be needed to actually run `cargo test -p pallet-psm redeem_uses_snapshot_when_internal_decimals_drift` and confirm runtime pass/fail status.

		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}

	#[test]
	fn redeem_uses_snapshot_when_internal_decimals_drift() {
		new_test_ext().execute_with(|| {
			// Seed ALICE's internal balance and PSM reserve with a prior mint, then
			// drift the internal asset's decimals.
			assert_ok!(Psm::mint(
				RuntimeOrigin::signed(ALICE),
				INTERNAL_ASSET_ID,
				USDC_ASSET_ID,
				1000 * INTERNAL_UNIT,
				Permill::from_percent(1)
			));
			assert_ok!(Assets::set_metadata(
				RuntimeOrigin::signed(ALICE),
				INTERNAL_ASSET_ID,
				b"INTERNAL".to_vec(),
				b"INTERNAL".to_vec(),
				8
			));

			let alice_usdc_before = get_asset_balance(USDC_ASSET_ID, ALICE);
			let alice_internal_before = get_asset_balance(INTERNAL_ASSET_ID, ALICE);
			let insurance_internal_before = get_asset_balance(INTERNAL_ASSET_ID, INSURANCE_FUND);
			let debt_before = PsmDebt::<Test>::get(INTERNAL_ASSET_ID, USDC_ASSET_ID);
			let redeem = 100 * INTERNAL_UNIT;
			let fee = Permill::from_percent(1).mul_ceil(redeem);
			let external_out = redeem - fee;

			assert_ok!(Psm::redeem(
				RuntimeOrigin::signed(ALICE),
				INTERNAL_ASSET_ID,
				USDC_ASSET_ID,
				redeem,
				Permill::from_percent(1)
			));

			assert_eq!(get_asset_balance(USDC_ASSET_ID, ALICE), alice_usdc_before + external_out);
			assert_eq!(get_asset_balance(INTERNAL_ASSET_ID, ALICE), alice_internal_before - redeem);
			assert_eq!(
				get_asset_balance(INTERNAL_ASSET_ID, INSURANCE_FUND),
				insurance_internal_before + fee
			);
			assert_eq!(
				PsmDebt::<Test>::get(INTERNAL_ASSET_ID, USDC_ASSET_ID),
				debt_before - external_out
			);
		});
