### Title
Unbounded EventEmitter Listener & Row Leak in Private Payment Chain Handling - (File: wallet.js, network.js)

### Summary
`handlePrivatePaymentChains()` in `wallet.js` registers a one-time `eventBus` listener for every private-payment chain element that gets queued (`ifQueued` branch), keyed by `'private_payment_validated-'+unit+'-'+json_payload_hash+'-'+output_index`. This listener, along with its closure (holding `arrChains`, `ws`, `assocValidatedByKey`, etc.), is only released when `network.js`'s background job `handleSavedPrivatePayments()` eventually emits that same key via `ifOk`/`ifError`. If the private-payment chain instead falls into the `ifWaitingForChain` branch (light client waiting for past units it never receives), the key is never emitted, the row is never deleted, and the listener is never removed — leaking memory indefinitely for every distinct chain an attacker sends, analogous to the un-freed allocation in `parseSWF_FREECHARACTER` from CVE-2024-24148 that leaks memory per crafted-but-never-fully-processed record.

### Finding Description
A paired device or private-payment counterparty sends a `private_payment_chains` message that is handled by `handlePrivatePaymentChains` [1](#0-0) . For each chain element, a unique key is computed and an entry is created in `assocValidatedByKey`, then `network.handleOnlinePrivatePayment` is invoked [2](#0-1) . When the result is `ifQueued` (the normal path for light clients or units not yet locally known), `wallet.js` registers `eventBus.once(key, ...)` [3](#0-2)  and moves on without any timeout or independent cleanup — the listener is only removed either when the key event fires, or when `cancelAllKeys()` is triggered by a *different* chain element in the same batch failing [4](#0-3) [5](#0-4) .

`handleOnlinePrivatePayment` persists the unresolved chain to the `unhandled_private_payments` table and calls `ifQueued` [6](#0-5) . The periodic job `handleSavedPrivatePayments`, run every 5 seconds for both full and light nodes [7](#0-6) , re-processes each pending row via `validateAndSave` [8](#0-7) . Crucially, when `privatePayment.validateAndSavePrivatePaymentChain` reports `ifWaitingForChain` (light client still missing past units of the chain), the handler simply calls `cb()` and returns — it neither emits the `private_payment_validated-...` key nor deletes the row [9](#0-8) , unlike the `ifOk`/`ifError` branches which both emit the key and delete the row [10](#0-9) .

An attacker (any device correspondent or chat/private-payment counterparty) can craft private-payment chains whose head unit intentionally references parent/ancestor units that are permanently withheld (never sent), so `findUnfinishedPastUnitsOfPrivateChains` keeps returning a non-empty `arrUnfinishedUnits` forever [11](#0-10) . Each such crafted chain, sent with a unique unit/hash, produces:
- a permanent row in `unhandled_private_payments` that is only garbage-collected by `cleanBadSavedPrivatePayments`, which is explicitly full-node-only and skipped entirely on light wallets [12](#0-11) ;
- a permanent `eventBus.once` listener plus its closure state in `wallet.js`, never removed.

Since the key is derived from attacker-controlled `unit`/`payload_hash`/`output_index`, an attacker can generate unlimited unique keys, so this is not deduplicated by any cache, and each message costs the victim an unremovable listener and DB row.

### Impact Explanation
This is a persistent, unbounded memory/resource leak reachable by any unauthenticated paired-device correspondent or private-payment counterparty, requiring no privileged access. Repeated exploitation causes continuous growth of `eventBus` listeners and `unhandled_private_payments` rows in the victim's (typically light-wallet) node, eventually exhausting memory and crashing the process — a denial of service that prevents the node from confirming or processing further private payments/units, matching the "network unable to confirm new units" / node-DoS impact class this scan accepts.

### Likelihood Explanation
Likelihood is high: any device paired with the victim, or any counterparty the victim exchanges private payments/chat with, can trigger this by simply sending crafted chains with unresolvable parent-unit references — no race condition, no privileged position, and it can be automated to send an unbounded stream of distinct chains.

### Recommendation
- Add a cap/limit and periodic sweep for `unhandled_private_payments` entries (including light clients), independent of `cleanBadSavedPrivatePayments`'s full-node restriction.
- In `wallet.js`'s `handlePrivatePaymentChains`, apply a timeout to the `eventBus.once(key, ...)` registration so that if the corresponding validation event never fires, the listener is removed and the pending chain is treated as failed/timed out.
- In `network.js`'s `handleSavedPrivatePayments`, when `ifWaitingForChain` persists beyond a bound (e.g., max retries or max age), emit the key with a failure and purge the row so waiting listeners are released.

### Proof of Concept
1. As a paired device or chat/private-payment correspondent, construct a private-payment chain whose head element references a valid-looking but permanently-unavailable ancestor unit (i.e., never actually broadcast/available), and send it via the `private_payment_chains` wallet message so it reaches `handlePrivatePaymentChains` [1](#0-0) .
2. The chain is queued (`ifQueued`), registering an `eventBus.once(key, ...)` listener in `wallet.js` [3](#0-2)  and a row in `unhandled_private_payments` [13](#0-12) .
3. `handleSavedPrivatePayments` repeatedly hits `ifWaitingForChain` every 5 seconds forever since the referenced ancestor unit never arrives [9](#0-8) , so the key is never emitted and the row/listener are never cleaned up.
4. Repeat step 1 with a fresh unique unit/hash combination many times (scriptable, no rate limiting observed on this path) to accumulate unbounded listeners and rows, driving the victim node's memory usage up until it degrades or crashes.

function handlePrivatePaymentChains(ws, body, from_address, callbacks){
	var arrChains = body.chains;
	if (!ValidationUtils.isNonemptyArray(arrChains))
		return callbacks.ifError("no chains found");
	if (!arrChains.every(c =>
		isNonemptyArray(c) &&
		c.every(e =>
			isNonemptyObject(e) &&
			isNonemptyString(e.unit) &&
			isNonemptyObject(e.payload) &&
			isNonemptyString(e.payload.asset) &&
			isNonemptyArray(e.payload.inputs) &&
			isNonemptyArray(e.payload.outputs) &&
			e.payload.inputs.every(isNonemptyObject) &&
			e.payload.outputs.every(isNonemptyObject)
		)
	))
		return callbacks.ifError("malformed private chain");
	try {
		var cache_key = objectHash.getBase64Hash(arrChains);
	}
	catch (e) {
		return callbacks.ifError("chains hash failed: " + e.toString());		
	}
	if (handledChainsCache[cache_key]) {
		eventBus.emit('all_private_payments_handled', from_address);
		eventBus.emit('all_private_payments_handled-' + arrChains[0][0].unit);
		return callbacks.ifOk();
	}
