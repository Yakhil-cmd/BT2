### Title
Argument injection via attacker-controlled skill path lets `gh skill search` install flow overwrite/redirect files outside the intended install directory - ([File: pkg/cmd/skills/search/search.go])

### Summary
`promptInstall` builds the `installArg` passed to a `gh skills install` subprocess directly from the GitHub Code Search API's `path` field, which an attacker fully controls by choosing the directory structure of their published repository. Because this value is passed as a bare positional `exec.Command` argument without a `--` terminator, an attacker can craft a path whose "prefix" segment is itself a recognized flag such as `--dir=<path>`, causing `pflag` (used by the child `gh` process) to parse it as a flag rather than a positional skill argument.

### Finding Description
In `pkg/cmd/skills/search/search.go`, `deduplicateResults` builds `skillResult.Path` directly from `codeSearchItem.Path` (the attacker-supplied file path from the GitHub Code Search API, `item.Path`) at [1](#0-0) . The only content validated in this path is the leaf skill `name` and `namespace` components via `validateName`/`discovery.MatchSkillPath` [2](#0-1)  — the arbitrary "prefix" segments that precede `skills/<namespace>/<name>/SKILL.md` in the deeply-nested convention are matched with no character restrictions at all (only `path.Base(grandparentDir) == "skills"` is checked) [3](#0-2) .

In `promptInstall`, for namespaced results this unvalidated path is used to build `installArg`: [4](#0-3) 

`installArg` (and `s.Repo`) are then passed as bare positional arguments to `exec.Command(opts.ExecutablePath, "skills", "install", s.Repo, installArg, "--agent", host.ID, "--scope", scope)` with no `--` separator to stop flag parsing.

Because the child process is another invocation of `gh`, its `skills install` subcommand parses `installArg` with Cobra/pflag, which recognizes flags anywhere in the argument list (interspersed flags) and splits `--flag=value` tokens on the first `=`. If an attacker publishes a `SKILL.md` at a path like:

```
--dir=/tmp/pwned-XX/skills/attacker-ns/attacker-skill/SKILL.md
```

then `s.Path` = `"--dir=/tmp/pwned-XX/skills/attacker-ns/attacker-skill/SKILL.md"`, and after `TrimSuffix(..., "/SKILL.md")`, `installArg` = `"--dir=/tmp/pwned-XX/skills/attacker-ns/attacker-skill"`. When this becomes an argv token to the `gh skills install` subprocess, pflag parses it as the recognized `--dir` flag [5](#0-4) , which "overrides `--agent` and `--scope`" and controls the install destination directory [6](#0-5) , causing installed skill files to be written under an attacker-chosen directory prefix instead of the intended per-agent project/user scope directory.

None of `safeurl`, `ghrepo`, or `git` argument sanitization applies here since this is a purely local `exec.Command` invocation of the `gh` binary itself, and the `//nolint:gosec` comment on the line explicitly (and incorrectly) assumes the values are safe because they come from "user-selected search results."

### Impact Explanation
This is an argument-injection issue enabling **file write/overwrite outside the intended path**: a victim who runs `gh skill search <query>` interactively and selects an attacker-published skill can have their `gh skills install` invocation silently redirected to write files to an attacker-influenced directory path (via injected `--dir`), or have other install-behavior flags injected (e.g. `--force` to suppress overwrite prompts, `--all`, `--from-local`, `--pin`). This matches the GitHub bounty impact class "file write or overwrite outside the intended path." It does not achieve direct remote code execution since the injected process is still `gh` itself (not a shell), but it can be leveraged to overwrite or place skill files at unexpected filesystem locations under attacker-partial control.

### Likelihood Explanation
Exploitation requires only that the attacker publish a public GitHub repository with a `SKILL.md` file placed at a crafted nested path (fully within GitHub's normal repo-content constraints — path segments in a git tree accept almost any non-slash characters, including a leading `--` and `=`), and that a victim run `gh skill search <matching query>` interactively and select that result for installation. No elevated privileges, tokens, or MITM are required — this is a standard "attacker publishes a repo, victim searches/installs via gh" flow described in the threat model.

### Recommendation
- Insert a `--` argument terminator before positional arguments in the `exec.Command` call in `promptInstall`, e.g. `exec.Command(opts.ExecutablePath, "skills", "install", "--", s.Repo, installArg, "--agent", host.ID, "--scope", scope)`, and make sure `pkg/cmd/skills/install` treats `--` as a proper terminator (Cobra/pflag support this by default).
- Additionally validate that `s.Repo` and `installArg` do not start with `-` before using them, rejecting/skipping such search results defensively.
- Consider validating that no path segment in `s.Path` (including "prefix" segments before `skills/`) contains disallowed leading characters, tightening `matchSkillConventions`'s deep-nesting branches to also call `validateName`-style checks on intermediate segments.

### Proof of Concept
Go test outline using `search.go`'s existing internal test hooks (add near existing search tests):

```go
func TestPromptInstall_ArgumentInjectionViaPath(t *testing.T) {
    skills := []skillResult{
        {
            Repo:      "attacker/evil-repo",
            SkillName: "attacker-skill",
            Namespace: "attacker-ns",
            // Attacker-controlled path with an unvalidated "prefix" segment
            // before "skills/", crafted to be parsed as a --dir flag.
            Path: "--dir=/tmp/pwned-poc/skills/attacker-ns/attacker-skill/SKILL.md",
        },
    }

    installArg := skills[0].SkillName
    if skills[0].Namespace != "" {
        installArg = strings.TrimSuffix(skills[0].Path, "/SKILL.md")
    }

    // Assert the computed installArg is flag-shaped, demonstrating that it
    // will be parsed by pflag as --dir=<value> rather than a positional arg.
    if !strings.HasPrefix(installArg, "--dir=") {
        t.Fatalf("expected flag-shaped installArg, got %q", installArg)
    }
}
```
