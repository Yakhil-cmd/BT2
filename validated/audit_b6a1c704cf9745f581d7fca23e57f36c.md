### Title
No Rate Limiting on Bridge Handle Calls Allows a Compromised Operator to Drain the Bridge — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `BridgeTransferERC20.sol`, `BridgeTransferERC721.sol`)

---

### Summary

The Kaia service-chain bridge contracts allow registered operators to execute cross-chain value transfers by calling `handleKLAYTransfer`, `handleERC20Transfer`, and `handleERC721Transfer`. The only per-call guard against re-execution is `closedValueTransferVotes[_requestNonce]`, which prevents the same nonce from being handled twice. There is no rate limiting on how many **distinct** nonces an operator can handle per block or time window, and there is no on-chain verification that a supplied `_requestTxHash` or `_value` corresponds to a real `RequestValueTransfer` event on the counterpart chain. A compromised operator with `operatorThresholds[ValueTransfer] == 1` (the default) can therefore call the handle function with fabricated nonces and arbitrary values in rapid succession, draining the bridge in a single block.

---

### Finding Description

`BridgeTransferKLAY.handleKLAYTransfer` (and its ERC20/ERC721 siblings) is gated by `onlyOperators` and internally calls `_voteValueTransfer(_requestedNonce)`:

```solidity
function _voteValueTransfer(uint64 _requestNonce) internal returns(bool) {
    require(!closedValueTransferVotes[_requestNonce], "closed vote");
    bytes32 voteKey = keccak256(msg.data);
    if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
        closedValueTransferVotes[_requestNonce] = true;
        return true;
    }
    return false;
}
``` [1](#0-0) 

Once `_voteCommon` returns `true` (threshold met), the transfer executes immediately:

```solidity
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
``` [2](#0-1) 

The `_requestTxHash` is recorded in `handledRequestTx` but is never verified against any counterpart-chain state:

```solidity
function _setHandledRequestTxHash(bytes32 _requestTxHash) internal {
    handledRequestTx[_requestTxHash] = true;
}
``` [3](#0-2) 

The `_lowerHandleNonceCheck` only enforces a lower bound:

```solidity
function _lowerHandleNonceCheck(uint64 _requestedNonce) internal {
    require(lowerHandleNonce <= _requestedNonce, "removed vote");
}
``` [4](#0-3) 

There is no upper-bound check, no per-block call count limit, and no per-time-window transfer volume limit. The default `operatorThresholds[ValueTransfer]` is `1`:

```solidity
for (uint8 i = 0; i < uint8(VoteType.Max); i++) {
    operatorThresholds[uint8(i)] = 1;
}
``` [5](#0-4) 

The `deregisterOperator` function explicitly acknowledges that outstanding votes by a deregistered operator are not revoked, meaning the window for a compromised operator to act cannot be closed atomically: [6](#0-5) 

---

### Impact Explanation

A compromised bridge operator with `threshold == 1` can call `handleKLAYTransfer` (or `handleERC20Transfer`) in a tight loop within a single block, supplying:
- A fresh fabricated `_requestTxHash` (any unique `bytes32`) per call
- An incrementing `_requestedNonce` (0, 1, 2, …)
- An arbitrary `_value` and attacker-controlled `_to`

Each call passes all guards (`lowerHandleNonce` check, `closedValueTransferVotes` check, threshold check) and immediately transfers KAIA or ERC20 tokens out of the bridge. The entire bridge balance can be drained in one block. This is an unauthorized transfer of KAIA and bridged assets — a direct match to the Kaia Allowed Impact Gate.

---

### Likelihood Explanation

The default `operatorThresholds[ValueTransfer]` is `1`, meaning a single operator key compromise is sufficient. The bridge is deployed with the deployer as the sole initial operator. If the operator key is compromised (e.g., via infrastructure breach), the attacker can drain the bridge before the owner can call `deregisterOperator` — and even after deregistration, any votes already cast by the deregistered operator remain valid. With `threshold > 1`, the attack requires collusion among threshold-many operators, which raises the bar but does not eliminate the risk.

---

### Recommendation

1. **Enforce a per-block or per-time-window transfer volume cap** in `handleKLAYTransfer`/`handleERC20Transfer`/`handleERC721Transfer`. Track cumulative transferred value per block and revert if it exceeds a configurable limit.
2. **Require on-chain proof** (e.g., a Merkle proof against an anchored counterpart-chain state root) that `_requestTxHash` and `_value` correspond to a real `RequestValueTransfer` event, removing the ability to fabricate requests entirely.
3. **Enforce a minimum time delay** between consecutive handle executions (analogous to a cooldown), giving the owner time to react to anomalous activity.

---

### Proof of Concept

```
Setup:
  - Bridge deployed with threshold = 1 (default), operator = attacker
  - Bridge holds 10,000 KAIA

Attack (single block):
  attacker.handleKLAYTransfer(0xdead...0001, from, attacker, 1000e18, nonce=0, blockNum, "")
    → closedValueTransferVotes[0] = false → vote passes → 1000 KAIA sent to attacker
  attacker.handleKLAYTransfer(0xdead...0002, from, attacker, 1000e18, nonce=1, blockNum, "")
    → closedValueTransferVotes[1] = false → vote passes → 1000 KAIA sent to attacker
  ...repeat 10 times...
  Bridge balance: 0 KAIA
```

Each call uses a distinct fabricated `_requestTxHash` and an incrementing `_requestedNonce`. The `closedValueTransferVotes` guard only prevents re-use of the same nonce; it does not limit the total number of distinct nonces that can be handled. No existing guard preserves the invariant that bridge funds are only released for legitimate counterpart-chain requests. [7](#0-6) [8](#0-7) [9](#0-8)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }
