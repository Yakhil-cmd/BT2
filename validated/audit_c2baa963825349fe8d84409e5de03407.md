### Title
Unbounded per-block reward-distribution work via mass low-stake delegation creation - ([File: runtime/src/bank/partitioned_epoch_rewards/mod.rs])

### Summary
`Bank::get_reward_distribution_num_blocks` caps the number of reward-distribution blocks (`num_chunks`) at `slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH`, but does not cap the number of stake accounts (`total_stake_accounts`) that must be spread across those blocks. Because `hash_rewards_into_partitions` divides `total_stake_accounts` roughly evenly across the (now-fixed) number of partitions, an attacker who creates an arbitrarily large number of minimum-stake delegations can make each of the fixed number of distribution blocks process an arbitrarily large, unbounded slice of stake accounts, defeating the intended fixed per-block cost design of `partitioned_rewards_stake_account_stores_per_block`.

### Finding Description
`get_reward_distribution_num_blocks` computes: [1](#0-0) 

`num_chunks = total_stake_accounts.div_ceil(stores_per_block)` is clamped to `[1, slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH]`. This clamp is meant to bound the *number of blocks* used for distribution, under the implicit assumption that `total_stake_accounts` stays proportional to `stores_per_block * num_chunks`. That assumption is not enforced anywhere: an unprivileged attacker can permissionlessly submit `CreateAccount` + `Initialize` + `DelegateStake` instructions (subject only to the stake program's per-account minimum delegation and rent-exempt reserve) to create an unbounded number `N` of low-stake `StakeStateV2::Stake` delegations before an epoch boundary.

At the epoch boundary, `total_stake_accounts` in the resulting `PartitionedStakeRewards` reflects `N`. Once `N` grows past `stores_per_block * (slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH)`, `num_chunks` saturates at the fixed cap `slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH` and no longer grows with `N`. The partitioning of rewards into that fixed number of partitions is done by `hash_rewards_into_partitions`, called from `distribute_partitioned_epoch_rewards`: [2](#0-1) 

which distributes `N` stake rewards roughly evenly across `epoch_rewards_sysvar.num_partitions` buckets — i.e., average partition size becomes `N / num_partitions_capped`, growing without bound as `N` grows. Each block then processes its full assigned partition unconditionally in `distribute_epoch_rewards_in_partition` → `store_stake_accounts_in_partition`, which iterates over every index in the partition and performs stake-account rebuild/store work per entry with no per-block work limit: [3](#0-2) 

No guard exists between `get_reward_distribution_num_blocks` and `hash_rewards_into_partitions` that re-caps per-partition size once the block-count clamp is hit; the only per-block sizing knob (`partitioned_rewards_stake_account_stores_per_block`) is used purely to *compute* the (capped) block count, not to bound the actual partition size delivered to each block. This breaks the intended invariant that each epoch-boundary distribution block performs bounded, fixed-cost work.

### Impact Explanation
This falls under an epoch-boundary halt / network-wide liveness degradation: once the block-count clamp saturates, every validator, when landing the block corresponding to an over-large partition, must synchronously deserialize, mutate, and re-store an unbounded number of stake accounts within a single slot's time budget. This directly stalls block production for that slot across the whole cluster (every validator processes the same partition indices deterministically from the hashed rewards), matching the "epoch-boundary halt / cross-node degraded availability" bounty category rather than lamport theft.

### Likelihood Explanation
The attack requires no special privilege — only the ability to fund and submit ordinary `CreateAccount` + stake `Initialize` + `DelegateStake` transactions for `N` accounts, each needing only the rent-exempt reserve plus the stake program's minimum delegation amount. The larger the desired blow-up factor, the more capital/transactions required, so the attack is directly proportional to attacker capital and transaction throughput, not blocked by any protocol-level cap on total stake-account count. This is fully reproducible in a deterministic unit test using the existing test harness (`create_reward_bank_with_specific_stakes`, `get_reward_distribution_num_blocks`).

### Recommendation
Bound the per-block/per-partition work independently of the block-count clamp — e.g., compute `num_chunks` so that `total_stake_accounts / num_chunks <= stores_per_block` always holds (removing or raising the `MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH` cap, or extending distribution across additional blocks/epochs when `total_stake_accounts` exceeds `stores_per_block * (slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH)`), and/or enforce a protocol-level ceiling on the total number of active stake delegations counted for reward distribution purposes.

### Proof of Concept
Extend the existing `test_get_reward_distribution_num_blocks_cap` test pattern in `runtime/src/bank/partitioned_epoch_rewards/mod.rs`:
```rust
#[test]
fn test_reward_distribution_partition_size_unbounded() {
    // configure small epoch (slots_per_epoch = 432000) and stores_per_block = 100
    // MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH = 10 => max_chunks = 43200
    for num_stakes in [100usize, 1_000_000, 10_000_000] {
        let stake_rewards = (0..num_stakes)
            .map(|_| Some(PartitionedStakeReward::new_random()))
            .collect::<PartitionedStakeRewards>();
        let num_blocks = bank.get_reward_distribution_num_blocks(&stake_rewards);
        let avg_partition_size = num_stakes as u64 / num_blocks;
        // Assert this stays bounded: FAILS once num_stakes exceeds
        // stores_per_block * max_chunks, proving unbounded per-block work.
        assert!(avg_partition_size <= stores_per_block,
            "avg_partition_size {} exceeds configured stores_per_block {}",
            avg_partition_size, stores_per_block);
    }
}
```
Expected result: the assertion passes for `num_stakes = 100` but fails for `1_000_000`/`10_000_000`, demonstrating that `avg_partition_size` (and thus per-block work in `store_stake_accounts_in_partition`) grows unboundedly with attacker-controlled `N` once the `num_chunks` clamp saturates.

    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );
