### Title
Cache Pointer Aliasing in `postInsertBlockPermissioned` Corrupts `councilCache[N]` During Incomplete Migration, Causing Double-Vote Application and Consensus Divergence — (`kaiax/valset/impl/execution.go`, `kaiax/valset/impl/getter_council.go`)

---

### Summary

During the incomplete-migration state, `postInsertBlockPermissioned` retrieves a `*valset.AddressSet` pointer that is **the same pointer stored in `councilCache` at key N**. It then calls `applyVote` which mutates that pointer in-place. The cache entry at N now represents Council(N+1) instead of Council(N). The next call to `getCouncilFromIstanbulSnapshot(N+1, false)` hits the corrupted cache entry at N, copies it, and applies the vote at N **a second time**, producing a doubly-wrong validator set for block N+1 and all subsequent blocks that chain off it.

---

### Finding Description

**Step 1 — `getCouncilFromIstanbulSnapshot(N, false)` stores and returns the same pointer.** [1](#0-0) 

Line 169 stores `council` in the LRU cache at key `N`. Line 171 returns the **same pointer** — no copy is made before returning.

**Step 2 — `getCouncilPermissioned(N)` propagates the raw pointer upward.** [2](#0-1) 

In the incomplete-migration branch (lines 40–43), the pointer returned by `getCouncilFromIstanbulSnapshot` is returned directly without copying.

**Step 3 — `postInsertBlockPermissioned` mutates the pointer in-place.** [3](#0-2) 

Line 58 calls `applyVote(header, council, governingNode)` on the pointer that is simultaneously stored in `councilCache[N]`. `applyVote` calls `council.Add` or `council.Remove`: [4](#0-3) 

Both `Add` and `Remove` mutate `as.list` in-place under a write lock. After this call, `councilCache[N]` holds Council(N+1) — the validator set **after** the vote at block N — instead of Council(N).

**Step 4 — The next call to `getCouncilFromIstanbulSnapshot(N+1, false)` hits the corrupted entry.** [5](#0-4) 

`targetNum = N+1`, so the cache lookup is at `targetNum - 1 = N`. It finds the corrupted entry, copies it (already containing the vote at N), then calls `applyBlock(council, N, write)` at line 144 — applying the vote at N **a second time**. The resulting council for block N+1 has the validator change applied twice.

---

### Impact Explanation

- **Incorrect validator set for block N+1 and all subsequent blocks** computed via the cache chain. A validator add/remove vote is applied twice: the added validator appears duplicated (or the removed validator is absent when it should still be present, or vice versa).
- **Consensus divergence between nodes with warm vs. cold cache.** A node whose `councilCache[N]` was populated before `postInsertBlockPermissioned` ran (warm) computes a different qualified-validator set and proposer sequence for block N+1 than a node that recomputes from scratch (cold). This is a chain split condition.
- The corruption is **self-inflicted by normal block processing**: `postInsertBlockPermissioned` itself warms the cache at N (via `getCouncilPermissioned`) and then immediately corrupts it.

---

### Likelihood Explanation

The incomplete-migration state is the **normal operational state** for any node that has just upgraded. Per the code comments, migration of a chain at block 180,000,000 takes at least 3.2 hours. [6](#0-5) 

During this window, every block that carries a validator vote (`AddValidator` or `RemoveValidator`) triggers the corruption. No special attacker capability is required — the trigger is a standard governance vote embedded in a block header, which is a normal permissioned-governance operation already present in the chain.

---

### Recommendation

In `postInsertBlockPermissioned`, work on a copy of the council rather than the raw pointer returned by `getCouncilPermissioned`:

```go
// execution.go – postInsertBlockPermissioned
council, err := v.getCouncilPermissioned(num)
if err != nil {
    return err
}
councilCopy := council.Copy()   // <-- add this
governingNode := v.GovModule.GetParamSet(num).GoverningNode
if applyVote(header, councilCopy, governingNode) {
    insertValidatorVoteBlockNums(v.ChainKv, num)
    writeCouncil(v.ChainKv, num, councilCopy.List())
    v.validatorVoteBlockNumsCache = nil
}
```

Alternatively, `getCouncilFromIstanbulSnapshot` should return `council.Copy()` at line 171 so callers always receive an independent copy, consistent with the defensive copy already made on the cache-hit path at line 143. [7](#0-6) 

Note the asymmetry: the cache-hit path at line 143 already calls `.Copy()` before mutating, but the return value at line 171 does not.

### Proof of Concept

```
1. Set up ValsetModule in incomplete-migration state
   (getCouncilDB returns ok=false for block N).

2. Construct block N whose header encodes an AddValidator vote for address X.

3. Call postInsertBlockPermissioned(blockN).
   Internally this calls getCouncilFromIstanbulSnapshot(N, false),
   which stores councilPtr at councilCache[N] and returns councilPtr.
   Then applyVote mutates councilPtr.Add(X) in-place.
   councilCache[N] now contains {original validators} ∪ {X}.

4. Call getCouncilFromIstanbulSnapshot(N+1, false).
   Cache hit at N: copies {original validators} ∪ {X}.
   applyBlock(council, N, false) applies the AddValidator(X) vote again.
   Result: council for N+1 = {original validators} ∪ {X} (X already present,
   so Add is a no-op due to the duplicate check — but if the vote were
   RemoveValidator(X), X would be removed twice, leaving a council missing X
   when it should still contain X, or vice versa for a node with cold cache).

5. On a cold-cache node, getCouncilFromIstanbulSnapshot(N+1, false) computes
   the correct council without the double-application.

6. The two nodes now disagree on the qualified-validator set for block N+1,
   producing different proposer selections → chain split.
```

func (as *AddressSet) Add(addr common.Address) {
	as.mu.Lock()
	defer as.mu.Unlock()

	if slices.Contains(as.list, addr) {
		return
	}
	as.list = append(as.list, addr)
	sort.Sort(as.list)
}

func (as *AddressSet) Remove(addr common.Address) bool {
	as.mu.Lock()
	defer as.mu.Unlock()
	for i, a := range as.list {
		if a == addr {
			as.list = append(as.list[:i], as.list[i+1:]...)
			return true
		}
	}
	return false
}
