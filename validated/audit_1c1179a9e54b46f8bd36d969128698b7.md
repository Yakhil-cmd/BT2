### Title
Webhook signature verified against attacker-controlled `repository.owner.login` instead of the target repository owner, allowing cross-repository webhook forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the `webhook_secret`) used to authenticate an incoming webhook based on `repository_owner`, which is read straight from the untrusted JSON body (`params.dig('repository','owner','login')`), while the actual handler that mutates state (`PushHandler`) resolves the target stack from `repository.full_name` in that same body. An attacker who owns any GitHub org configured in Shipit can sign a payload with their own `webhook_secret` while setting `repository.full_name` to any other tenant's repository, causing `PushHandler#process` to call `stack.sync_github` for a stack they do not own.

### Finding Description
The broken binding is: `organization_that_signed_the_request` (derived in `verify_signature` from `repository_owner`) should equal `organization_owning_repository.full_name` (used later to select the stack in `PushHandler`). In this code path they are never actually checked against each other — both are read independently from the same attacker-supplied JSON body.

`verify_signature` reads: [1](#0-0) 

and `repository_owner`: [2](#0-1) 

`github_app = Shipit.github(organization: repository_owner)` looks up the `GitHubApp` for `attacker-org`, and `github_app.verify_webhook_signature` HMAC-verifies the raw body against **attacker-org's own** `webhook_secret`: [3](#0-2) 

Since the attacker computed the signature using their own org's secret over the exact bytes they are sending, verification succeeds. Nothing in `verify_signature` cross-checks `repository_owner` against `repository.full_name`.

`#create` then re-parses the same raw body and dispatches to handlers with no re-validation: [4](#0-3) 

`PushHandler#process` resolves stacks purely from the handler's `stacks` scope (inherited from the base `Handler`, tied to `repository.full_name` in the payload) and the branch/ref, and calls `stack.sync_github`: [5](#0-4) 

There is no code anywhere in this chain that requires `repository_owner` (the org whose secret validated the signature) to match the owner portion of `repository.full_name` (the org whose stack gets synced). I was unable to locate/read the base `Handler` class's `stacks` method in this pass (file not found via the searches performed), but the `PushHandler` implementation confirms stack resolution is driven solely by `repository.full_name`/`ref` from the payload with no dependency on `repository_owner`.

### Impact Explanation
An attacker who controls any single GitHub organization with a Shipit GitHub App/`webhook_secret` configured can sign arbitrary webhook payloads that appear to originate from that org, but whose `repository.full_name` field targets a completely unrelated victim organization's repository. This causes `PushHandler` to enqueue `stack.sync_github` (a `GithubSyncJob`) for the victim's stack — a cross-tenant write triggered by a party who never authenticated against the victim's secret. This matches the "Critical" impact category: a payload for one repository (attacker-org) mutating another's stack (victim-org). The same technique likely extends to any other webhook handler dispatched through this controller (e.g., pull_request/status handlers), since none of them re-validate `repository_owner` against the payload they act on. This is repeatable at will and works against any victim stack whose full name the attacker can guess/know (which is public GitHub information).

### Likelihood Explanation
Preconditions are modest: the attacker needs to control at least one GitHub organization that has been onboarded into Shipit with its own GitHub App and `webhook_secret` (i.e., they are a legitimate but unprivileged Shipit tenant/org owner, not a Shipit operator). No Shipit session, API token, or victim secret is required. The attacker only needs to know the victim's `full_name` (public) and craft a POST body plus a correctly computed HMAC using their own secret — trivial and fully repeatable.

### Recommendation
In `verify_signature`, do not use attacker-controlled `repository.owner.login` alone to select the verifying `GitHubApp`. Instead, derive the expected owner from the same field the handler will act upon (`repository.full_name`'s owner segment) and require it to match `repository_owner` before proceeding, or better, verify the signature using the `GitHubApp` associated with the actual target repository/stack (looked up from `Repository`/`Stack` records) rather than trusting any owner field embedded in the unauthenticated payload.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`):
1. Configure `Shipit.github(organization: 'attacker-org')` and `Shipit.github(organization: 'victim-org')` with distinct `webhook_secret` values (e.g. via `Shipit.github_apps`/config stub).
2. Create `victim-org/victim-repo` `Repository` and an associated `Stack` with branch `master`.
3. Build payload: `{'repository' => {'owner' => {'login' => 'attacker-org'}, 'full_name' => 'victim-org/victim-repo'}, 'ref' => 'refs/heads/master', 'after' => '<sha>'}`.
4. Compute `X-Hub-Signature` as `"sha1=" + OpenSSL::HMAC.hexdigest('sha1', attacker_org_secret, body)`.
5. POST to `/webhooks` with header `X-Github-Event: push` and the above signature.
6. Assert response is `200 OK` (signature accepted) — i.e. `repository_owner` resolved to `attacker-org` and verification against `attacker-org`'s secret returned true.
7. Assert `Shipit::GithubSyncJob` was enqueued for the victim stack (`assert_enqueued_with(job: Shipit::GithubSyncJob, args: [stack_id: victim_stack.id, ...])`), proving `PushHandler` mutated `victim-org`'s stack despite the request only being authenticated against `attacker-org`'s secret.
8. Contrast: assert that if `attacker_org_secret` and `victim_org_secret` differ, no code path checks `repository_owner == 'victim-org'`, confirming the binding is broken both before and after the request.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
