### Title
Webhook signature verification keys on `organization.login`/`repository.owner.login` while `EditedHandler` targets `repository.full_name` — org-without-secret bypass lets forged `pull_request.edited` events mutate PRs on any repository - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb, app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the verifying `GitHubApp` using `repository_owner`, which falls back from `repository.owner.login` to `organization.login` when the former is absent. `EditedHandler`, however, resolves the target repository independently from `params.repository.full_name`. Because these are separate JSON fields under attacker control, an attacker can supply a `repository.full_name` pointing at a victim repo while omitting `repository.owner.login` and supplying `organization.login` for an org that has no `webhook_secret` configured, causing `GitHubApp#verify_webhook_signature` to accept the payload unconditionally.

### Finding Description
The broken binding: the code implicitly assumes `repository_owner == owner(repository.full_name)`, i.e. that the GitHub organization used to select/verify the webhook signature is the same organization that owns the repository the handler will act on. In reality:

- `WebhooksController#repository_owner` (app/controllers/shipit/webhooks_controller.rb:59-62): `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`.
- `Shipit.github(organization: repository_owner)` selects a `GitHubApp` config for that org, and `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) does `return true unless webhook_secret` — i.e., if the selected org has no `webhook_secret` configured, **any** signature (or none) is accepted.
- `EditedHandler#repository` (app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb:63-65) independently derives the target repository from `params.repository.full_name`, which is a required parameter of the handler's `ExplicitParameters` schema but is a *different sub-field* than `repository.owner.login` used above.

Exploit flow: attacker POSTs to `/webhooks` with `X-Github-Event: pull_request`, a body with `action: "edited"`, a `repository: { full_name: "victim-org/victim-repo" }` (deliberately omitting `repository.owner.login`), and a top-level `organization: { login: "org-without-secret" }`. `repository_owner` resolves to `"org-without-secret"` (an org configured in `Shipit.github_teams`/app config without a `webhook_secret`), so `verify_signature` passes unconditionally regardless of the actual `X-Hub-Signature` header. The request then reaches `EditedHandler#process`, which looks up `Shipit::PullRequest` by `number` and `repository.id` derived from `victim-org/victim-repo` and calls `pull_request.update(github_pull_request: params.pull_request)`, mutating the persisted `PullRequest` record for a repository whose secret never authenticated the request.

Existing guards don't stop this: `drop_unhandled_event` only checks the event type exists; the `ExplicitParameters` schema on `EditedHandler` requires `repository.full_name` but does not require `repository.owner.login`, so a payload can satisfy the handler schema while still triggering the owner fallback in the controller. There is no code that cross-checks that `repository_owner` matches the owner implied by `repository.full_name`.

### Impact Explanation
An attacker can forge a `pull_request` `edited` webhook that mutates the `PullRequest` record (title, state, additions/deletions, head SHA/ref, assignees, labels, etc.) for **any** repository/stack tracked by Shipit, as long as some org configured in the Shipit instance lacks a `webhook_secret`. This is a cross-tenant write: a payload "authenticated" via one org (the one without a secret) mutates state belonging to a completely different, unrelated repository named in `repository.full_name`. This matches the Critical category: "a payload for one repository mutating another's stack, commit, task, or team" / forged webhook accepted as trusted.

### Likelihood Explanation
Preconditions: at least one org must be configured in the Shipit instance without a `webhook_secret` (the scenario stipulated in the question). Given that, the attack requires zero authentication — a single unauthenticated POST to `/webhooks` with a crafted JSON body and the `X-Github-Event: pull_request` header. It's trivially repeatable against any repository name known to the attacker (repository names are typically public). No GitHub App private key, no Shipit session, and no valid HMAC signature are needed.

### Recommendation
Use a single, consistent source of truth for the organization/repository binding used both for signature verification and handler targeting — derive `repository_owner` strictly from `repository.full_name`'s owner segment (or require `repository.owner.login` to be present and match `repository.full_name`'s prefix) rather than falling back to a separate `organization.login` field. Additionally, require `webhook_secret` to be configured for every org in production and fail closed (reject, not accept) when it is absent, instead of `verify_webhook_signature` returning `true` unconditionally when no secret is set.

### Proof of Concept
minitest (test/controllers/webhooks_controller_test.rb style — not enumerating file changes, but the assertion structure):

```ruby
test "pull_request edited forged via organization fallback mutates an unrelated repository's PR" do
  # victim stack/repo exists with a real webhook_secret configured for its own org
  victim_repo = shipit_repositories(:shipit)
  victim_stack = victim_repo.stacks.first
  pr = victim_stack.pull_requests.create!(number: 42, github_pull_request: {...})

  # attacker-controlled org configured WITHOUT webhook_secret
  Shipit.github_apps # ensure "org-without-secret" has no webhook_secret

  payload = {
    action: "edited",
    number: pr.number,
    pull_request: { id: 1, number: pr.number, url: "...", title: "PWNED",
      state: "open", additions: 1, deletions: 1,
      head: { sha: "a"*40, ref: "x" },
      user: { login: "attacker" }, assignees: [], labels: [] },
    repository: { full_name: "#{victim_repo.owner}/#{victim_repo.name}" }, # no owner.login
    organization: { login: "org-without-secret" },
    sender: { login: "attacker" }
  }.to_json

  post "/webhooks", params: payload, headers: {
    "X-Github-Event" => "pull_request",
    "X-Hub-Signature" => "sha1=deadbeef", # invalid/unrelated signature
    "Content-Type" => "application/json"
  }

  assert_response :ok
  pr.reload
  assert_equal "PWNED", pr.title  # write succeeded despite invalid signature for victim's real secret
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
