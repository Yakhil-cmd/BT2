### Title
Unbounded recursion in `replaceInTemplate`/`replaceInVar` when expanding a `definition_template` message allows stack-overflow DoS during address/AA definition validation - (File: definition.js)

### Summary
`fig2dev`'s `read_objects()` bug is a stack overflow from unbounded recursion while parsing an attacker-supplied, deeply-nested input structure. `ocore` has an analogous unguarded recursive structure walk in `replaceInTemplate`/`replaceInVar` in `definition.js`, which is invoked while resolving the `definition template` opcode during address- and asset-definition validation, and during AA-nested-address evaluation. The template payload itself is only checked to be "an array of length 2" when posted, with no depth or node-count limit, so a malicious template can be arbitrarily deeply nested and will overflow the JS call stack when expanded.

### Finding Description
Any unprivileged unit poster can post a `definition_template` message. Its payload validation is trivial: [1](#0-0) [2](#0-1) 

Neither check enforces a depth or node-count limit on the template array, unlike other structures in the codebase that explicitly guard against deep nesting (e.g. `isTooDeeplyNestedOrHasTooManyNodes` in `string_utils.js`): [3](#0-2) 

Later, when any address definition (or asset condition, or nested-address evaluation) references this template via the `definition template` opcode, the stored payload is loaded and expanded with `replaceInTemplate`: [4](#0-3) [5](#0-4) 

`replaceInTemplate`'s inner `replaceInVar` recurses over the entire template structure with **no depth counter, no iteration-count guard, and no `setImmediate` call-stack interruption** — unlike the sibling `evaluate()`/`validate()` walkers in the same file and in `aa_validation.js`, which explicitly track `depth` against `MAX_DEPTH` and periodically yield via `setImmediate`: [6](#0-5) 
Compare to the guarded recursive walker pattern used elsewhere in the same file: [7](#0-6) 

Because `replaceInVar` recurses once per array/object nesting level with no bound, a template consisting of, e.g., thousands of nested single-element arrays/objects (`['and',[['and',[...]]]]`) will drive the recursion deep enough to exhaust the V8 call stack, throwing an uncatchable `RangeError: Maximum call stack size exceeded` (or crashing the process) inside the `conn.query` callback of `evaluate()`. This code path executes during consensus-critical validation (`validateDefinition`/`validateAuthentifiers`), so a crash here can be triggered by any node that processes a unit referencing the malicious template through an `address`/`definition template` condition.

### Impact Explanation
A single crafted `definition_template` message, later referenced from any address definition (own or another party's, since address definitions can be evaluated for template resolution during validation regardless of whether it's the "attacker's" own address), can crash the validating node's process while validating a unit — a network-wide validity/stability disagreement or an availability failure (nodes unable to confirm new units) if reproduced widely, matching this scan's accepted impact categories (node disagreement on validity/stability / network unable to confirm new units).

### Likelihood Explanation
Reachable by any unprivileged unit poster: posting a `definition_template` message requires no special privilege, and referencing it via `['definition template', [unit, params]]` in an address definition is a normal, permitted construct. The only requirement is constructing a sufficiently deeply nested array/object template, which is trivial to generate programmatically and passes the existing shallow "array of length 2" check.

### Recommendation
Add an explicit depth (and/or total node count) limit to `replaceInTemplate`/`replaceInVar` (mirroring `MAX_DEPTH`/`isTooDeeplyNestedOrHasTooManyNodes` usage elsewhere), and/or enforce the same depth/size limit on `definition_template` payloads at message-validation time (`validation.js` case `"definition_template"`, `aa_validation.js` case `'definition_template'`) before they are ever stored or expanded.

### Proof of Concept
1. Post a unit with a `definition_template` message whose payload is a very deeply nested array, e.g. programmatically build `['and', [['and', [['and', [ ... ['sig', {pubkey: 'X'}] ... ]]]]]]` nested ~50,000+ levels deep (well within message-size limits since each level only adds a few bytes) — this passes validation because only `isArrayOfLength(payload, 2)` is checked.
2. Have any address definition (yours or one you control) reference it: `['definition template', [<template_unit_hash>, {}]]`.
3. Trigger validation of a unit that exercises this address definition (e.g. via `validateAuthentifiers`/`validateDefinition` for spending from that address, or via nested-address resolution in `evaluate()`'s `'address'`/`'definition template'` cases).
4. During validation, `replaceInTemplate(arrTemplate, params)` recurses once per nesting level with no depth guard, exhausting the call stack and crashing/throwing inside the node process handling validation — unlike `evaluate()`/`validate()` walkers elsewhere that check `depth > MAX_DEPTH` and yield via `setImmediate`.

function isTooDeeplyNestedOrHasTooManyNodes(obj, depthLimit = 100, nodesLimit = 10000) {
	let nodeCount = 0;

	function check(variable, depth){
		if (depth > depthLimit || nodeCount > nodesLimit)
			return true;
		if (variable === null || typeof variable !== "object")
			return false;
		if (Array.isArray(variable)) {
			nodeCount += variable.length;
			for (let v of variable)
				if (check(v, depth + 1))
					return true;
		}
		else {
			nodeCount += Object.keys(variable).length;
			for (let key in variable)
				if (check(variable[key], depth + 1))
					return true;
		}
		return false;
	}

	return check(obj, 1);
}

function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
