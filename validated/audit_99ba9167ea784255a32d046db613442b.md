### Title
Cross-organization webhook forgery via authentication/repository binding mismatch in `WebhooksController` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate a webhook against using an attacker-controlled field from the payload (`repository.owner.login`/`organization.login`), while the actual event handlers act on a *different* field of the same payload (`repository.full_name`) to decide which tracked `Repository`/`Stack` to mutate. Because these two fields are never checked for consistency, and because per-organization `webhook_secret` is optional (and can be blank for one configured org while set for another), an attacker can "authenticate" as an org with no secret and have the payload's real target point at a completely different, properly-secured organization's repository.

### Finding Description
Shipit supports multiple GitHub App configurations keyed by organization [1](#0-0) . Each org's `GitHubApp` instance carries its own `webhook_secret`, which is optional — if blank/nil, `verify_webhook_signature` unconditionally returns `true`: [2](#0-1) . The test fixtures even ship a second org (`OrgTwo`) explicitly configured with `webhook_secret: # nil` [3](#0-2) , and the setup docs describe the webhook secret as "(optional)" [4](#0-3) , so a multi-org install with one unsecured org is a documented, supported configuration.

`WebhooksController#verify_signature` picks the `GitHubApp` (and thus the secret) to verify against using `repository_owner`, which is read directly out of the untrusted payload before any signature check: [5](#0-4) .

The `create` action then re-parses the raw body independently and dispatches it to event handlers: [6](#0-5) . Every handler resolves the *actual* target repository/stack using a different payload field, `repository.full_name`, via `Handler#repository_name`/`#stacks`: [7](#0-6) , e.g. `PushHandler#process` calling `stack.sync_github` for every matching stack: [8](#0-7) .

Nothing binds `repository.owner.login` (used to choose/bypass the signature) to `repository.full_name` (used to pick the repository actually acted upon). This breaks the equality: **organization that authenticated == repository that is written**. An attacker can therefore craft a payload where `repository.owner.login` (or `organization.login`) names an org with no `webhook_secret` configured — bypassing signature verification entirely and requiring zero secrets or credentials — while `repository.full_name` names any other tracked repository belonging to a different, fully-secured organization.

### Impact Explanation
This lets an unauthenticated, unprivileged internet attacker inject GitHub webhook events (`push`, `status`, `check_suite`, `pull_request`, `membership`, etc.) that are processed as if legitimately delivered by GitHub for a repository/org the attacker has no relationship with, as long as any other org on the same Shipit instance has no webhook secret configured. Concretely for `push`: `PushHandler` enqueues `GithubSyncJob` for the victim stack [9](#0-8) , which mutates the victim stack's commit history (`append_commit`, `lock_reverted_commits!`) and re-caches its deploy spec [10](#0-9) . For continuously-deployed stacks, forcing a resync can trigger an unauthorized deploy pipeline for a repository the attacker does not control. This matches the required Critical bucket ("an unauthorized deploy, rollback or merge") since the trust boundary between "who signed this webhook" and "what repository state it mutates" is not enforced.

### Likelihood Explanation
Exploitation requires: (1) the target Shipit instance to be configured for more than one GitHub organization with at least one having no `webhook_secret` — a supported, documented, and even test-fixtured configuration — and (2) sending a single unauthenticated HTTP POST to the public `/webhooks` endpoint with a crafted JSON body. No GitHub App credentials, session, `ApiClient` token, or repository access are needed, making this readily reachable by any internet attacker against affected multi-org deployments.

### Recommendation
In `WebhooksController#verify_signature`, require that the field used to select the verifying organization also be validated against (or derived consistently with) the field the handlers use to resolve the target repository (`repository.full_name`'s owner segment), and/or require a non-blank `webhook_secret` for every configured organization so that `verify_webhook_signature` can never trivially return `true`. Additionally, `Handler#repository_name`/`#stacks` should cross-check that the resolved repository's owner matches the organization whose secret validated the request.

### Proof of Concept
1. Configure Shipit with two orgs: `Shopify` (has `webhook_secret` set, owns tracked repo `Shopify/victim-repo`) and `OrgTwo` (no `webhook_secret`, per the shipped `secrets_double_github_app.yml` pattern) [3](#0-2) .
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<any sha>",
  "repository": { "full_name": "Shopify/victim-repo", "owner": { "login": "OrgTwo" } }
}
```
Any (or no) `X-Hub-Signature` value is accepted since `Shipit.github(organization: "OrgTwo")` has a blank secret [11](#0-10) , [2](#0-1) .
3. `create` re-parses the body and dispatches to `PushHandler`, which resolves the stack via `repository.full_name = "Shopify/victim-repo"` [12](#0-11)  and enqueues `GithubSyncJob` against the real `Shopify/victim-repo` stack [9](#0-8) , despite the request never having been signed by `Shopify`'s secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
