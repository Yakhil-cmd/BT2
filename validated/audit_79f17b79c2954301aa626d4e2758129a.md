### Title
Webhook signature verification is keyed to an attacker-controlled `repository.owner.login`, decoupled from the repository the event actually mutates - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and thus which `webhook_secret`) to validate the request against using a field taken from the unauthenticated JSON body itself (`repository.owner.login`, with a fallback to `organization.login`), not from any authenticated channel. In a multi-organization deployment (`Shipit.github_app_config`, documented in `docs/setup.md`), the org used to select the signing secret is completely independent from the `repository.full_name` value the downstream event handlers use to pick the actual `Repository`/`Stack`/`Commit` to mutate.

### Finding Description
`verify_signature` computes:
```
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
``` [1](#0-0) 

`repository_owner` is read straight out of the untrusted payload:
```
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

`GitHubApp#verify_webhook_signature` treats a missing `webhook_secret` as automatically verified:
```
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [3](#0-2) 

`webhook_secret` is documented as optional per organization in the multi-app configuration ("If you've set a webhook secret during the App creation, you should copy it here"), and the test fixtures explicitly demonstrate an org configured with `webhook_secret: # nil`: [4](#0-3) [5](#0-4) 

Once `verify_signature` passes (because the org named by `repository.owner.login` has no `webhook_secret`), `create` re-parses the same body and dispatches it to event handlers by a *different* field:
```
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [6](#0-5) 

Handlers resolve the target repository from `repository.full_name`, e.g. the base `Handler`:
```
def repository_name
  payload.dig('repository', 'full_name')
end
``` [7](#0-6) 

Nothing anywhere cross-checks that `repository.owner.login` (used to pick the verifying secret) equals the owner encoded in `repository.full_name` (used to pick the mutated repository). Worse, `StatusHandler#process` does not scope by repository at all — it looks up commits globally by SHA:
```
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [8](#0-7) 

This breaks the intended binding: `organization authenticated == repository/commit written`. An attacker only needs to know (or guess) the name of any single organization in the Shipit installation's multi-org config that has no `webhook_secret` set (a state explicitly supported and demonstrated in the fixtures/docs), then craft a payload whose `repository.owner.login`/`organization.login` names that unsecured org while `repository.full_name` or `sha` targets a completely different, "secured" repository/commit.

### Impact Explanation
This allows an unauthenticated attacker to forge GitHub events (`push`, `status`, `check_suite`, `membership`, `pull_request`, etc.) against any repository/commit tracked by the Shipit instance, as long as one org in the multi-org config lacks a webhook secret. Concretely:
- Forged `status` events can set arbitrary commit statuses (`create_status_from_github!`) on any commit in the database regardless of which repository it belongs to, potentially marking CI checks green and enabling an unauthorized merge/deploy decision downstream.
- Forged `push` events can trigger `GithubSyncJob` for stacks unrelated to the "authenticating" (secret-less) organization.
This crosses the "unauthorized deploy/merge" and "authentication bypass" impact bar called out in scope.

### Likelihood Explanation
Requires only that the Shipit installation use the documented multi-organization GitHub App configuration with at least one org lacking a `webhook_secret` — a supported and exampled configuration, not a misconfiguration outside the engine's control. No credentials, tokens, or session are required; the request is a plain unauthenticated HTTP POST to `/webhooks`.

### Recommendation
- Require `webhook_secret` to be present for every configured organization, or refuse verification (return `false`, not `true`) when `webhook_secret` is blank.
- Cross-validate that the organization used to select the verifying secret matches the owner encoded in `repository.full_name` (and any other repository-identifying field) before dispatching to handlers.
- Scope `StatusHandler` (and any other handler that resolves objects by global attributes such as `sha`) to the repository asserted in the payload rather than looking up commits/stacks instance-wide.

### Proof of Concept
1. Deploy Shipit with the documented multi-org config where `OrgWithoutSecret` has no `webhook_secret` and `OrgWithSecret` does [4](#0-3) .
2. POST to `/webhooks` with header `X-Github-Event: status` and no valid `X-Hub-Signature`, body:
```json
{
  "repository": { "owner": { "login": "OrgWithoutSecret" }, "full_name": "OrgWithoutSecret/decoy" },
  "sha": "<real-sha-of-target-repo-commit>",
  "state": "success",
  "context": "ci/tests"
}
```
3. `verify_signature` looks up `Shipit.github(organization: "OrgWithoutSecret")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally [3](#0-2) .
4. `StatusHandler#process` runs unfiltered by repository, marking the targeted commit's status as `success` [8](#0-7) , regardless of which org actually owns that commit.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
