### Title
Overflowing accrued debt value permanently freezes market withdrawals and repayments - (File: contracts/pool/src/interest.rs)

### Summary
A large outstanding debt can push `borrowed * borrow_index` beyond the `i128` RAY domain before the borrow-index ceiling is reached. Because every market mutation and `update_indexes` calls `interest::global_sync` before changing state, the first overflow traps the accrual and prevents the timestamp from advancing. [1](#0-0) [2](#0-1) 

### Finding Description
The accrual path computes the market’s new scaled debt value inside `accrue_step`, which uses checked `i128` fixed-point arithmetic through `Ray`. A market can legally accumulate enough scaled debt that the product `borrowed × new_borrow_index` overflows even though `new_borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [3](#0-2) 

`global_sync` does not catch or bound that overflow; the panic rolls back the entire invocation before `mark_accrued` executes. [4](#0-3)  Since every subsequent operation starts from the same stale timestamp and now has an even larger elapsed interval, the same arithmetic fails again. [5](#0-4) 

The repository’s stress test demonstrates the reachable state: an 18-decimal market holding one billion supplied units and 980 million borrowed units eventually fails `try_update_indexes_for` with `MATH_OVERFLOW`, while the stored borrow index is still below the cap. [6](#0-5) 

### Impact Explanation
Once this state is reached, suppliers cannot withdraw and borrowers cannot repay because both paths accrue interest before mutating the market. [7](#0-6)  Parameter replacement also cannot rescue the market because `update_params` accrues on the old model before writing new parameters. [8](#0-7) 

This permanently freezes the funds tracked by the affected market absent a contract upgrade or another privileged recovery mechanism.

### Likelihood Explanation
The attack requires a market whose configured caps and collateral support extremely large positions, on the order used by the stress fixture. [9](#0-8)  An attacker with sufficient collateral can borrow near the admitted limit and leave the debt untouched; ordinary time passage then raises the index until accrual crosses the RAY-value ceiling. [10](#0-9) 

The cost and required market size substantially limit practical likelihood, but no privileged action is needed to create the borrowing position or invoke the accrual path through `update_indexes`. [11](#0-10) 

### Recommendation
Constrain each market’s admitted scaled supply and debt so `scaled_amount * MAX_*_INDEX` cannot overflow, or make accrual clamp the effective borrow index before multiplying when the next index would exceed the representable value domain. At minimum, derive spoke supply/borrow caps from the worst-case index bound rather than only the token-native domain, and add an explicit market-level guard that rejects a borrow whose committed scaled debt can later make `borrowed * borrow_index` unrepresentable.

### Proof of Concept
The existing stress test provides the concrete sequence:

1. Configure an 18-decimal asset with the steep test curve and lifted market caps.
2. Supplier BOB deposits `1_000_000_000 * 10^18` atomic units.
3. Attacker ALICE posts the required separate collateral and borrows `980_000_000 * 10^18` atomic units.
4. Advance ledger time until the next public `update_indexes` call accrues the market.
5. `accrue_step` overflows `i128` while computing accrued debt value, the update reverts, and `last_timestamp` remains unchanged.
6. Subsequent `withdraw` and `repay` calls hit the same unchecked recoverability condition and revert with `MATH_OVERFLOW`.

The test asserts that the borrow-index cap has not engaged and that both withdrawal and repayment are already frozen. [12](#0-11)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
