### Title
Stop-hook review set silently drops security-relevant changes across `git commit --amend` - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` computes the Stop-hook's review set as `dirty_now ∩ changed_since`, where `dirty_now` is derived from `git status` against the *current* HEAD and only gets commit-authored files unioned in when `head_at_capture` is a **linear ancestor** of the current HEAD. A `git commit --amend` (a completely normal git operation) replaces HEAD with a sibling commit rather than a descendant of `head_at_capture`, so `_is_ancestor` returns `False`, the amended file drops out of `dirty_now`, and the intersection with `changed_since` becomes empty — even though the dangerous change is present in the amended commit and would show up in `changed_since` alone.

### Finding Description
`compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) builds the review set as:

```
dirty_now = tracked_dirty | new_untracked            # from `git status` vs CURRENT HEAD
if head_at_capture is ancestor of current_head:       # only true for plain, linear commits
    dirty_now |= files changed in head_at_capture..HEAD
    diff_base = head_at_capture
changed_since = files differing from baseline_sha (the pre-turn stash)
review_set = dirty_now ∩ changed_since
``` [1](#0-0) 

The ancestor check is done with `_is_ancestor`, which uses `git merge-base --is-ancestor head_at_capture current_head` — true only when HEAD moved forward via a normal commit/merge: [2](#0-1) 

`git commit --amend` creates a brand-new commit object that shares the same parent as the pre-amend HEAD; the old `head_at_capture` SHA is not reachable by walking parents from the new HEAD, so `_is_ancestor` returns `False`. Consequently:
- `diff_base` stays `"HEAD"`, and `dirty_now` is computed purely from `git status` against the amended (now-current) HEAD — after the amend the working tree is clean relative to the new HEAD, so the dangerous file is **not** in `dirty_now`.
- `changed_since` (from `_git_name_only(repo, baseline_sha)`, comparing the pre-turn stash baseline against the current worktree) still correctly lists the file as changed.
- `review_set = dirty_now ∩ changed_since` intersects an empty (or file-missing) `dirty_now` with a non-empty `changed_since`, so the dangerous file silently disappears from the set reviewed by the Stop hook's LLM analysis and by `get_git_diff`, which is invoked with the resulting `review_set`/`diff_base`.

No other gate compensates: per the module's own docstring, "v2 diff strategy: derive the review set from git state alone," i.e. the review set is not independently cross-checked against `touched_paths` before being handed to the diff/LLM pipeline (touched_paths is used elsewhere for dedup/restore bookkeeping, not as a floor on the review set). This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": a normal, attacker-reachable git operation (amend) desynchronizes the baseline-vs-HEAD-derived `dirty_now` term from the baseline-vs-worktree `changed_since` term, and the AND-of-two-imperfect-signals design fails closed (excludes) instead of failing open, silently skipping review of a dangerous change that was made and then amended in the same session.

Because `security_reminder_hook.py` is 2192 lines and truncated during this review, I was not able to fully confirm the exact call site that consumes `compute_v2_review_set`'s output inside the Stop handler, but the function's contract (its return values feed `get_git_diff`/LLM review per its own docstring) and the module's re-export list confirm it is the sole review-set source for the v2 Stop-hook diff strategy.

### Impact Explanation
This matches "Cross-repo, cross-session, or wrong-target mutation with real security impact" in scope: a session that makes a dangerous edit, commits it, and then amends that commit (a completely ordinary developer/agent workflow — e.g., fixing a commit message, `git commit --amend --no-edit` after a lint-staged hook modifies a file) causes the security-guidance Stop hook to compute an empty or incomplete review set for that turn. The dangerous change is treated as already-reviewed/old and is never sent to the LLM security reviewer or flagged via `exit(2)`, defeating the plugin's core security-review guarantee without needing any privilege beyond running `git commit --amend` in the working repo.

### Likelihood Explanation
High feasibility and full repeatability: the trigger is nothing more than `git commit -m "x" && git commit --amend --no-edit` (or any amend) performed within a single Claude Code turn/session after a security-relevant edit, which is unprivileged, common, and requires no special repo configuration. It reproduces deterministically because `_is_ancestor` is a straightforward git ancestry check that is provably false for sibling amend commits.

### Recommendation
When `head_at_capture != current_head` but `_is_ancestor` is false (HEAD moved sideways — amend, rebase, cherry-pick, reset), do not silently fall back to a pure `dirty_now`-vs-current-HEAD computation. Instead, union in the files changed between `baseline_sha` and current HEAD directly (i.e., treat `changed_since` as authoritative in this branch, or set `dirty_now` to `changed_since` when a non-ancestor HEAD move is detected) so an amended/rewritten commit's changes are never excluded from the review set. Additionally, consider retaining `touched_paths` as a floor that is unioned into (not just cross-checked against) the git-derived review set, so PostToolUse-recorded edits are reviewed even if the git-state heuristic degrades on non-linear HEAD movement.

### Proof of Concept
Integration test plan (pytest, mirroring existing diffstate tests):
1. Create a temp git repo with an initial commit.
2. Capture baseline: `baseline_sha = capture_git_baseline(repo)`, `head_at_capture = _git_rev_parse_head(repo)`.
3. Write a dangerous change to `app.py` (e.g., `os.system(user_input)`), `git add -A && git commit -m "wip"`.
4. Run `git commit --amend --no-edit` (simulating a normal amend, e.g. after a pre-commit formatter).
5. Call `review_paths, diff_base, repo_root, untracked, metrics = compute_v2_review_set(repo, baseline_sha, head_at_capture, {})`.
6. Assert: `os.path.join(repo, "app.py") in review_paths` — **expected to fail**, demonstrating the dangerous file is dropped from the review set (`metrics["review_set_count"] == 0` while `metrics["changed_since_count"] >= 1`).
7. Follow-up assertion for the fix: after applying the recommended change, re-run step 5/6 and assert the file **is** present in `review_paths`.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
