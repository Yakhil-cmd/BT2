### Title
Signature verification org selection is decoupled from the repository field handlers actually act on, allowing forged webhooks for a *different* (secured) org/repo - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub App/`webhook_secret` used to validate `X-Hub-Signature` based on `repository_owner`, taken from `payload.dig('repository', 'owner', 'login')` (falling back to `payload.dig('organization', 'login')`). Once the signature check passes, `Webhooks.for_event` handlers act on a *different* field of the very same attacker-controlled JSON body — `payload.dig('repository', 'full_name')` — to resolve which `Stack`/`Repository`/`Commit` to mutate. Nothing binds these two fields together, so in a multi-GitHub-App deployment (`docs/setup.md` "Using Multiple Github Applications"), an attacker who can satisfy verification for one configured organization (in particular one whose `webhook_secret` is left blank, which is explicitly documented as optional) can supply a mismatched `repository.full_name` pointing at a repository belonging to a *different*, properly-secured organization.

### Finding Description [1](#0-0) 
selects the app/secret via `Shipit.github(organization: repository_owner)` where [2](#0-1)  derives `repository_owner` purely from the JSON body.

`verify_webhook_signature` trivially returns `true` when the resolved org's `webhook_secret` is blank: [3](#0-2) 

Multi-org configuration is a documented, supported setup where each org has its own independent `webhook_secret`, and the secret is explicitly optional per org: [4](#0-3) [5](#0-4) 

Once the signature gate passes, `Handler#stacks`/`repository_name` and every push/pull_request handler resolve the target purely from `repository.full_name` in the same JSON body — a field never covered by the org used to pick the signing secret: [6](#0-5) [7](#0-6) 

Worse, `StatusHandler` doesn't even scope by repository at all — it matches by raw commit `sha` across the entire instance: [8](#0-7) 

The broken binding, stated as an equality that must hold but doesn't:
`organization authenticated by verify_signature (repository.owner.login / organization.login)` ≠ `repository the handler writes to (repository.full_name, or unscoped sha lookup for status)`.

### Impact Explanation
An attacker who knows (or controls) an organization configured in the same Shipit instance with a blank/unset `webhook_secret` can pass signature verification while forging events (`push`, `status`, `pull_request`, `check_suite`) whose `repository.full_name`/commit `sha` targets a stack belonging to a *different*, properly secret-protected organization. Concretely:
- Forge `status` events to post an arbitrary CI status (e.g. `success`) on any commit `sha` in the system (`StatusHandler` has zero repository scoping), which can influence deploy-safety gating derived from commit status checks.
- Forge `push` events to trigger `GithubSyncJob`/`sync_github` on stacks outside the attacker's own org.
- Forge `pull_request`/`check_suite` events to manipulate label capture or check-run refresh state for repositories in other organizations.

This crosses the "organization that authenticated vs. repository that is written" trust boundary and can contribute to unauthorized deploy decisions (falsified CI/status state), qualifying as at least High severity per the engine's own webhook-authentication boundary.

### Likelihood Explanation
Requires the deployment to run in multi-GitHub-App mode with at least one configured organization lacking a `webhook_secret` (explicitly documented as optional/nil-able), and requires network reachability to `/webhooks` (publicly exposed endpoint, unauthenticated by design apart from HMAC). No GitHub App private key, `ApiClient` token, or Shipit session is needed — only knowledge of one org's (weakly configured) name and the target repo's `full_name`, both discoverable information. This is a realistic misconfiguration given the docs present the webhook secret as optional per-org.

### Recommendation
Bind repository-owner used for signature-secret selection to the same field(s) actually used by handlers, and reject requests where they diverge. Specifically: after resolving `github_app` for `repository_owner`, verify that `payload.dig('repository', 'full_name')`'s owner segment equals the verified `repository_owner` before dispatching to handlers; additionally scope `StatusHandler#process` to commits belonging to the repository named in the payload (not a global `sha` lookup), and disallow/alert when a configured org's `webhook_secret` is blank in multi-org mode.

### Proof of Concept
Preconditions: Shipit configured with two orgs, `OrgOne` (no `webhook_secret` set) and `OrgTwo` (secret configured, hosting the victim stack), as in `test/dummy/config/secrets_double_github_app.yml`.

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # ignored because OrgOne has no webhook_secret

{
  "repository": { "owner": { "login": "OrgOne" }, "full_name": "OrgTwo/victim-repo" },
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>"
}
```
`verify_signature` resolves `repository_owner` = `"OrgOne"` → `Shipit.github(organization: "OrgOne")` → `verify_webhook_signature` returns `true` unconditionally (blank secret). `PushHandler` then resolves `repository_name = "OrgTwo/victim-repo"` and calls `sync_github` on the victim's stack, even though the request was never authenticated against `OrgTwo`'s secret.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",

      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
