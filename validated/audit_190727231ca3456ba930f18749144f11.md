### Title
Git pathspec magic in `_diff_pathspec`/`get_git_diff` lets an attacker-named repo file neutralize path restriction, turning a scoped diff into an unrestricted repo-wide diff sent to the LLM reviewer - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`get_git_diff` restricts the reviewed diff to Claude-touched files by appending repo-relative paths after `--` to `git diff` [1](#0-0) . `_diff_pathspec` correctly hardens against symlink/`..`-based escapes with `realpath` + `..`-prefix rejection [2](#0-1) , but git's pathspecs are never made literal (no `--literal-pathspecs` flag or `core.literalPathspecs=true` config anywhere in `GIT_CMD`/`get_git_diff`) [3](#0-2) [4](#0-3) , so a repo-controlled file whose name begins with git pathspec magic (e.g. `:(exclude)`, `:!`) is parsed by git as a magic pathspec rather than a literal filename.

### Finding Description
`get_git_diff(cwd, baseline_sha, paths=...)` builds the diff command as `[*GIT_CMD, "diff", ..., baseline_sha, ...] + pathspec` where `pathspec = _diff_pathspec(cwd, paths)` [1](#0-0) . `_diff_pathspec` converts each touched absolute path into a repo-root-relative string and returns `["--"] + rel` [2](#0-1) . These relative strings are passed straight into `git diff -- <rel...>` without `--literal-pathspecs`/`core.literalPathspecs`, so git's own pathspec-magic parser (triggered when a pathspec literally starts with `:`) is active.

An attacker who controls the content of a cloned repository can commit a file whose name is a valid Unix filename that is *also* a git pathspec-magic string, e.g. `:(exclude)x` or the short form `:!x`. If the normal Claude workflow (Edit/Write tool use, tracked via `record_touched_path`) ever touches that file, its relative path becomes one of the `--` arguments fed to `git diff`. Because that argument is exclude-magic with no accompanying positive pathspec, git's actual pathspec semantics change from "restrict diff to this file" to "diff everything except this file" — i.e. the restriction the code explicitly tries to enforce (see the comment: *"an empty pathspec would mean an UNRESTRICTED diff — the bug this whole change exists to fix"*, [5](#0-4) ) is silently defeated by an in-repo filename rather than an empty list. The resulting diff is no longer scoped to Claude's touched files but to the entire (or a much broader) working tree, and that oversized diff is what gets sent for LLM security review — including via networked calls to the configured Claude/Anthropic API (`llm.py`'s `_call_claude` / `analyze_code_security` / `agentic_review`, reached from `security_reminder_hook.py`'s Stop-hook and commit-review paths).

The existing hardening (`os.path.realpath` + `..`-prefix rejection) only defends against paths resolving outside `cwd` via symlinks or `../` traversal; it does nothing to neutralize git's own pathspec-magic parsing of the resulting relative string, so this specific escape class is unaddressed.

### Impact Explanation
The invariant "git path scoping must never escape the intended repo target" is broken at the pathspec-semantics level: a single attacker-crafted repo filename converts a path-restricted diff into an unrestricted (or much broader than intended) diff of the working tree. Since that diff content is the payload forwarded to the LLM review pipeline (a networked, potentially external sink), this results in disclosure of unrelated source files, comments, embedded secrets/tokens, or other sensitive repo content that the intended scoping was designed to exclude from the review payload — matching the "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink" impact category.

### Likelihood Explanation
Requires only: (1) an unprivileged attacker able to place arbitrary files/names into a repository that will later be cloned and worked on (a normal, low-bar precondition — pushing a PR branch or a public repo file is sufficient), and (2) the ordinary workflow of Claude editing/writing that specific file (or the attacker crafting the repo so the natural task touches it, e.g. via prompt-injected instructions in repo content directing edits to that path). No admin/maintainer privilege, key leakage, or social engineering beyond normal untrusted-repo content is needed. Filenames starting with `:` are valid on Linux/macOS filesystems (the common Claude Code host environments), making this concretely reproducible.

### Recommendation
Pass `-c core.literalPathspecs=true` in `GIT_CMD` (or add `--literal-pathspecs` to every `git diff`/`git add`/`git status` invocation in `gitutil.py` that consumes repo-controlled filenames), so pathspec magic parsing is disabled and all path arguments are treated as literal strings. Apply this uniformly to `_diff_pathspec`'s consumers (`get_git_diff`, `_temp_index`'s `git add`, `_git_name_only`) since they all splice repo-derived relative paths into pathspec argument positions.

### Proof of Concept
Unit/integration test plan (pytest, extending the existing `gitutil`/`security_reminder_hook` test suite):
1. Initialize a temp git repo with an initial commit containing `secret.txt` with content `TOP-SECRET-TOKEN`.
2. Create a file literally named `:(exclude)touched.py` (or `:!touched.py`) and commit it, then modify it (or leave it untracked) so it appears as a Claude-touched path.
3. Call `get_git_diff(cwd, baseline_sha, paths=[os.path.join(cwd, ":(exclude)touched.py")])`.
4. Assert (expected failing today): the returned diff text contains hunks for `secret.txt` (or other files outside the touched set) — i.e. the pathspec restriction did not confine the diff to `:(exclude)touched.py`.
5. Fix validation: after adding `core.literalPathspecs=true` to `GIT_CMD`, re-run the same test and assert the diff contains only `:(exclude)touched.py`'s own changes and `secret.txt` is absent.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
