### Title
Webhook signature verification keyed on an attacker-controlled `repository.owner.login` field allows spoofed events against a different organization's repositories - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App configuration (and thus which `webhook_secret`) to verify the HMAC signature against by reading `repository_owner`, itself derived from the **unauthenticated** request body (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`), before the signature has been validated. The downstream event handlers, however, act on a *different* field of the same body — `repository.full_name` — to decide which `Stack`/`Repository` to mutate. Because these two fields are independent JSON keys in the same unsigned/unverified payload, an attacker can supply an `owner.login` that maps to an organization with no `webhook_secret` configured (or one they know), while setting `repository.full_name` to point at a *different*, secured organization's repository.

### Finding Description [1](#0-0) 

`verify_signature` computes the signing key to check against using `repository_owner`: [2](#0-1) 

```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
```

This value is passed to `Shipit.github(organization: repository_owner)`, which resolves per-organization config via `github_app_config`: [3](#0-2) 

If that organization's config lacks a `webhook_secret`, `verify_webhook_signature` unconditionally returns `true`: [4](#0-3) 

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```

Once the check "passes" (bypassed), `create` dispatches the *entire* raw payload to the event handler: [5](#0-4) 

Handlers such as `PushHandler` resolve the target `Stack` using `repository.full_name`, not `repository.owner.login`: [6](#0-5) [7](#0-6) 

Equality broken: **organization authenticated (`repository.owner.login`, used to select `webhook_secret`) ≠ repository actually written (`repository.full_name`, used to select the `Stack`)**. Before the fix, these two fields are assumed to describe the same repository; an attacker can decouple them since neither is cryptographically bound together before signature verification occurs, and if the attacker-chosen owner has no `webhook_secret` (or one the attacker knows), the signature check is trivially satisfied for a forged event describing an entirely different, secured repository.

### Impact Explanation
This is exactly the class of binding violation described in scope: "an organization that authenticated versus the repository that is written." A successful forgery lets an unauthenticated network attacker trigger `GithubSyncJob` (forcing a resync of a stack's HEAD to an attacker-chosen `expected_head_sha`), toggle commit `Status` records, archive/unarchive/provision review stacks via `PullRequest` handlers, or manipulate `Membership`/`Team` records — all against a repository/organization the attacker does not control, without ever presenting a valid signature for that organization's secret. This can lead to unauthorized deploys/rollbacks (an explicitly listed Critical impact) if `sync_github`/subsequent auto-deploy logic acts on the attacker-influenced SHA.

### Likelihood Explanation
Requires that the Shipit instance be configured for multiple GitHub organizations (per `config/secrets.development.example.yml` multi-org schema) where at least one configured organization has no `webhook_secret` set, or the attacker can obtain/guess one organization's secret. Given this is a documented supported configuration schema (not an edge case), and Shipit exposes `/webhooks` publicly (no authentication required, per `docs/setup.md`), the precondition is realistic for any multi-org deployment.

### Recommendation
Bind signature verification to the same repository/organization actually acted upon: verify the signature using the config resolved from a value that cannot be spoofed independently of the entity being mutated (e.g., require that `repository.full_name`'s organization component matches `repository_owner`, or better, require a valid signature under **every** configured organization's secret set, or attribute signature validity to the specific `Repository` record's own stored install/org — not a value pulled fresh from the same untrusted body used for routing).

### Proof of Concept
1. Configure Shipit in multi-org mode with two organizations: `victim-org` (has `webhook_secret: strongsecret`) and `attacker-org` (misconfigured with no `webhook_secret`, or attacker otherwise knows `attacker-org`'s secret).
2. Attacker crafts a `push` webhook POST to `/webhooks` with:
   - `X-Github-Event: push`
   - Body: `{"repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"}, "ref": "refs/heads/master", "after": "<attacker-chosen-sha>"}`
   - `X-Hub-Signature` set to any value (or a validly-computed sha1 using `attacker-org`'s known/absent secret).
3. `WebhooksController#verify_signature` resolves `repository_owner` as `attacker-org`, loads that org's (absent/known) secret, and passes verification.
4. `PushHandler` resolves the `Stack` for `victim-org/victim-repo` via `Repository.from_github_repo_name` and enqueues `GithubSyncJob` with the attacker-supplied `expected_head_sha`, forcing a sync against `victim-org`'s stack despite never presenting a signature valid for `victim-org`'s secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations

  end

  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
