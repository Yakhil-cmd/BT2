### Title
Missing zero-address (System Program ID) validation on `creator` in `initialize_with_permission` permanently freezes creator fees - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`initialize_with_permission` accepts a `creator` account that is only declared `UncheckedAccount<'info>` with a `/// CHECK: creator of pool` comment and no `constraint` at all, unlike the `initialize` handler where `creator` is a `Signer`. The unchecked `creator` pubkey is written directly into `pool_state.pool_creator` via `pool_state.initialize(...)`, with no check that it is non-zero (i.e., not `Pubkey::default()` / the System Program ID `11111111111111111111111111111111`).

### Finding Description
In `initialize_with_permission.rs`, `creator` is declared as: [1](#0-0) 
and is stored unchecked as `pool_creator` when the pool is created: [2](#0-1) 

Unlike `initialize.rs`, where `creator` is a `Signer<'info>` (so it can never realistically be the zero/System-Program address because that address has no controllable private key) [3](#0-2) , `initialize_with_permission`'s `creator` is a plain `UncheckedAccount` decoupled from the transaction's signer (`payer`), and the instruction performs no `require!`, `constraint`, or `address` check to reject `Pubkey::default()`.

Once `pool_creator` is set to the zero address, every subsequent swap accrues creator fees into `pool_state.creator_fees_token_0/1` via `update_fees`: [4](#0-3) 

But collection of those fees is permanently blocked:
- `collect_creator_fee` requires `creator: Signer<'info>` constrained by `address = pool_state.load()?.pool_creator` [5](#0-4) . No keypair exists for the System Program address, so this signer constraint can never be satisfied.
- `collect_creator_fee_permissionless` allows anyone to trigger collection, but the destination ATA is created with `associated_token::authority = creator` [6](#0-5) . If `creator` is the zero/System-Program address, the tokens are moved into an ATA whose authority is that same uncontrollable address, permanently locking the funds instead of merely leaving them in `pool_state`.

### Impact Explanation
Any (permissioned) pool creator invoking `initialize_with_permission` with `creator` set to `Pubkey::default()` causes all creator-fee revenue generated by every swap against that pool to be irrecoverably locked forever — first unreachable in `pool_state`, and if "collected" permissionlessly, moved into a token account with no controlling private key. This is a permanent freezing of funds accruing over the pool's lifetime, satisfying the "permanent freezing of user/LP funds" impact bar. It does not affect LP principal or the constant-product invariant directly, but does permanently strand real, transferred token value (the creator-fee portion of every trade) with no recovery path.

### Likelihood Explanation
Reaching this requires calling `initialize_with_permission`, which is gated by a pre-existing `Permission` PDA for the `payer` (created by an admin-designated `create_permission_pda_owner`) [7](#0-6) [8](#0-7) . Any account holding a valid Permission PDA (a normal, non-privileged pool creator once granted permission — this instruction is explicitly in the reachable surface per the assignment scope) can set `creator` to the zero address in a single transaction with fully attacker-chosen accounts/data; no admin or protocol-privileged signature is needed for the exploit itself. This can happen either from a malicious permissioned creator intentionally griefing fee accrual, or accidentally from tooling that fails to populate the `creator` field.

### Recommendation
Add an explicit non-zero check on `creator` in `InitializeWithPermission`, e.g. `require_keys_neq!(creator.key(), Pubkey::default())`, or better, constrain `creator` more strongly (e.g., require it match `payer` or another accountable/whitelisted identity) before writing it into `pool_state.pool_creator`. Additionally, consider adding the same defensive check inside `PoolState::initialize` so all initialization paths are protected uniformly, and consider validating `pool_creator != Pubkey::default()` inside `collect_creator_fee_permissionless` before creating the destination ATA, as a defense-in-depth measure.

### Proof of Concept
1. Attacker/permissioned account `P` already holds a valid `Permission` PDA (created previously by `create_permission_pda_owner`).
2. `P` calls `initialize_with_permission` as `payer`, passing `creator = Pubkey::default()` (System Program ID) along with two valid mints and initial liquidity amounts.
3. The instruction succeeds; `pool_state.pool_creator` is now `11111111111111111111111111111111` [2](#0-1) .
4. Any user swaps against the pool via `swap_base_input`/`swap_base_output`; `update_fees` accrues nonzero `creator_fees_token_0/1` [4](#0-3) .
5. `collect_creator_fee` can never be called (no signer exists for the zero address) [5](#0-4) .
6. Anyone calling `collect_creator_fee_permissionless` moves the accrued fees into an ATA owned by the zero address [6](#0-5) , permanently freezing them since no private key can ever authorize a transfer out of that ATA.

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();
                if is_creator_fee_on_input {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                }
            }
        };
        Ok(())
    }

#[derive(Accounts)]
pub struct CreatePermissionPda<'info> {
    #[account(
        mut,
        constraint = (owner.key() == crate::admin::ID || owner.key() == crate::create_permission_pda_owner::ID) @ ErrorCode::InvalidOwner
    )]
    pub owner: Signer<'info>,

    /// CHECK: permission account authority
    pub permission_authority: UncheckedAccount<'info>,

    /// Initialize config state account to store protocol owner address and fee rates.
    #[account(
        init,
        seeds = [
            PERMISSION_SEED.as_bytes(),
            permission_authority.key().as_ref()
        ],
        bump,
        payer = owner,
        space = Permission::LEN
    )]
    pub permission: Account<'info, Permission>,

    pub system_program: Program<'info, System>,
}

pub fn create_permission_pda(ctx: Context<CreatePermissionPda>) -> Result<()> {
    let permission = ctx.accounts.permission.deref_mut();
    permission.authority = ctx.accounts.permission_authority.key();
    Ok(())
}
