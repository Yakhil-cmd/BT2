### Title
`ProxyType::NonTransfer` falsely claims superset of `ProxyType::Auction`, allowing proxy escalation to bypass the `Registrar::swap` denial - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
On the Westend relay chain runtime, `ProxyType::is_superset` unconditionally returns `true` for `(NonTransfer, _)` (any other type except `Any`), while `ProxyType::filter` explicitly *excludes* `paras_registrar::Call::swap` from what a `NonTransfer` proxy may execute. `ProxyType::Auction`'s filter admits the *entire* `Registrar` pallet, including `swap`. Because `pallet_proxy::add_proxy`/`remove_proxy` are authorized purely via `is_superset` (not `filter`), a `NonTransfer` proxy can add itself (or its delegate) an `Auction` sub-proxy and then dispatch `Registrar::swap`, a call its own filter was explicitly written to deny.

### Finding Description
`pallet_proxy` gates the ability of a delegated proxy to create/remove another proxy solely through `InstanceFilter::is_superset`, not through `filter`: [1](#0-0) 

The invariant the pallet relies on (and which is called out explicitly in comments and a regression test elsewhere in this same repository, for the `NonTransfer`/`Governance` pair on Asset Hub Westend — see PR `prdoc/pr_12769.prdoc` and `non_transfer_proxy_is_not_a_superset_of_governance` in `asset-hub-westend/tests/tests.rs`) is:

> If `A.is_superset(B) == true`, then every call that `B.filter` admits must also be admitted by `A.filter`. Otherwise the declared "subset" `B` is reachable as an escalation path from `A`. [2](#0-1) [3](#0-2) 

This exact invariant is violated on the Westend **relay chain** runtime for the `NonTransfer` / `Auction` pair:

```rust
// filter():
ProxyType::NonTransfer => matches!(
    c,
    ...
    RuntimeCall::Registrar(paras_registrar::Call::register{..}) |
    RuntimeCall::Registrar(paras_registrar::Call::deregister{..}) |
    // Specifically omitting Registrar `swap`
    RuntimeCall::Registrar(paras_registrar::Call::reserve{..}) |
    ...
),
...
ProxyType::Auction => matches!(
    c,
    RuntimeCall::Auctions(..) |
        RuntimeCall::Crowdloan(..) |
        RuntimeCall::Registrar(..) |   // <-- admits ALL Registrar calls, including `swap`
        RuntimeCall::Slots(..)
),
...
fn is_superset(&self, o: &Self) -> bool {
    match (self, o) {
        (x, y) if x == y => true,
        (ProxyType::Any, _) => true,
        (_, ProxyType::Any) => false,
        (ProxyType::NonTransfer, _) => true,   // <-- claims superset of Auction too
        _ => false,
    }
}
``` [4](#0-3) 

`NonTransfer`'s call filter deliberately omits `Registrar::swap` (the comment "Specifically omitting Registrar `swap`" makes the intent explicit), but `is_superset` declares `NonTransfer` a superset of `Auction`, whose filter admits the entire `Registrar` pallet including `swap`. This is structurally identical to the already-recognized and fixed bug class in this same repository for `NonTransfer`/`Governance` on Asset Hub Westend (`prdoc/pr_12769.prdoc`, fixing GH issue paritytech/polkadot-sdk#12724): a "restrictive" proxy type declares itself a superset of a type whose filter is broader on at least one call the restrictive type explicitly denies.

### Impact Explanation
An account holding a `NonTransfer` proxy for a delegator can:
1. Use the `NonTransfer` proxy to call `Proxy::add_proxy(delegate, ProxyType::Auction, delay)` on behalf of the delegator — permitted because `NonTransfer`'s filter admits `RuntimeCall::Proxy(..)` generically and `is_superset(NonTransfer, Auction)` returns `true`.
2. Use the newly created `Auction` proxy to call `Registrar::swap(..)` on behalf of the delegator — a call the original `NonTransfer` proxy grant was explicitly designed to deny.

This breaks the confinement guarantee that a `NonTransfer` proxy delegation was supposed to provide: the delegate was never authorized to swap the delegator's parachain registration/lease slot, yet can reach it through proxy-type escalation. The severity depends on what `swap` allows an attacker to do to the delegator's registered para (potential lease/deposit/slot manipulation for the delegator's parachain), which is an unauthorized-dispatch/integrity-break class of issue on the relay chain, analogous to the Tomcat "broader rule evaluated before/instead of the narrower restrictive one" bypass.

### Likelihood Explanation
The precondition is only that some account already granted a `NonTransfer` proxy to a delegate — a completely ordinary, permissionless configuration (`Proxy::add_proxy` is a normal signed extrinsic available to any account). No privileged role, governance action, or stolen keys are required beyond the delegator having voluntarily created a `NonTransfer` proxy, which is a common/expected proxy type for exactly this kind of "trusted for most things but not fund/registration moves" use case. This is a Medium/High-likelihood, "silently reachable" logic bug, not a probabilistic or resource-based one.

### Recommendation
Fix `ProxyType::is_superset` on the Westend (and audit Polkadot/Rococo/Kusama analogues) relay-chain runtime the same way it was fixed for Asset Hub Westend's `NonTransfer`/`Governance` pair: either
- remove the blanket `(ProxyType::NonTransfer, _) => true` and enumerate only the pairs that are genuinely correct supersets (mirroring the explicit per-pair lattice used in `asset-hub-westend`'s `is_superset`), or
- extend `Auction`'s filter to only admit the specific `Registrar` calls that `NonTransfer` already permits (`register`, `deregister`, `reserve`), consistent with the "Specifically omitting Registrar `swap`" comment's intent.

Add a lattice regression test analogous to `proxy_type_superset_relation_matches_call_filters` (already present for `asset-hub-westend`) to the Westend/Polkadot/Rococo relay-chain test suites to prevent recurrence.

### Proof of Concept
Verified statically by comparing the two match arms in the same file:
- `ProxyType::filter` for `NonTransfer` excludes `paras_registrar::Call::swap` (explicit comment + omission), while `ProxyType::filter` for `Auction` matches `RuntimeCall::Registrar(..)` unconditionally (includes `swap`).
- `ProxyType::is_superset` returns `true` for `(NonTransfer, Auction)` via the catch-all `(ProxyType::NonTransfer, _) => true` arm.
- `pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` purely via `def.proxy_type.is_superset(proxy_type)` [1](#0-0) , so the mismatch is directly reachable through a normal signed `Proxy::add_proxy` extrinsic, then a normal `Proxy::proxy` dispatch of `Registrar::swap` through the newly added `Auction` proxy.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
