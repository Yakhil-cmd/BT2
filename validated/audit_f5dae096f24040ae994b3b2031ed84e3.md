## Title
NULL Pointer Dereference (Node Crash) via crafted `definition` message with non-inline payload - (File: network.js)

### Summary
`network.js`'s `getAllAuthorsAndOutputAddresses()` dereferences `message.payload.definition` without checking that `payload` exists, mirroring the libming `outputSWF_TEXT_RECORD` NULL-pointer-dereference class (CVE-2017-16883): a specially crafted, otherwise fully valid record/unit reaches a code path that assumes a field is always present and crashes the process when it is missing.

### Finding Description
`validation.js` explicitly allows any message (including `app: "definition"`) to omit its `payload` entirely when `payload_location` is `"none"` or `"uri"`. The relevant validation loop performs no further checks in that case and simply `continue`s: [1](#0-0) 

Because of this, an unprivileged unit poster can submit a unit containing a message with `app: "definition"` and `payload_location: "none"` (no `payload` field at all), which passes `validate()` as long as the unit also carries a valid base payment message and correct hashes.

Once such a unit is accepted (`ifOk`) by `handleJoint()`, every full node calls `notifyWatchers(objJoint, ...)`, which in turn calls `getAllAuthorsAndOutputAddresses(objUnit)`: [2](#0-1) 

In this function, for `app === "payment"` messages the code correctly checks `payload` truthiness (`message.app === "payment" && payload`), but for `app === 'definition'` it dereferences `payload.definition[1].base_aa` with **no null check**: [3](#0-2) 

If `payload` is `undefined` (as allowed by validation for non-inline payload_location), this line throws an uncaught `TypeError: Cannot read properties of undefined (reading 'definition')`. `notifyWatchers` is invoked synchronously inside the `ifOk` handler for every accepted joint on every node, without a surrounding try/catch: [4](#0-3) 

### Impact Explanation
The dereference throws an uncaught exception in the main unit-acceptance code path (`handleJoint` → `ifOk` → `notifyWatchers`), which is executed by **every** full node (light nodes skip it via `if (conf.bLight) return;` further down, but the crash happens before that check). Since the crafted unit is a normally valid unit that is durably saved to storage before the crash occurs, every full node that processes/replays this unit (freshly received, from catch-up, or replayed on restart) will crash on the same statement. This can be used to repeatedly crash full nodes across the network as they process/re-process the unit, preventing the network from making progress in validating and confirming subsequent units — matching the "network unable to confirm new units" impact class.

### Likelihood Explanation
Any unprivileged party can post a unit with a `definition` message using `payload_location: "none"` (or `"uri"`) and omitting the `payload` field. No special privileges, keys, or trust relationships are required — only a validly signed unit with a normal base payment message elsewhere to satisfy `bHasBasePayment`. The vulnerable code executes unconditionally for every accepted unit, so exploitation is deterministic and repeatable.

### Recommendation
Add a null/type check on `payload` before accessing `payload.definition` in `getAllAuthorsAndOutputAddresses()`, e.g.:
```js
else if (message.app === 'definition' && payload && payload.definition && payload.definition[1] && payload.definition[1].base_aa)
```
Additionally, review other `switch`/`if` branches keyed on `message.app` throughout `network.js`, `writer.js`, and `aa_composer.js` for similar unchecked `payload` accesses whenever `payload_location` can legally be `"none"`/`"uri"`.

### Proof of Concept
1. Construct a unit with:
   - A base `payment` message (to satisfy `bHasBasePayment`).
   - A second message: `{ app: "definition", payload_location: "none", payload_hash: <valid 44-char base64 hash> }` (no `payload` field).
2. Sign and post the unit; it passes `validate()` because the payload-absence path for non-inline `payload_location` is accepted unconditionally (`validation.js` lines 227-231).
3. Once the unit is accepted (`ifOk`), `notifyWatchers(objJoint, ...)` is called, which calls `getAllAuthorsAndOutputAddresses(objUnit)`.
4. In the loop, `message.app === 'definition'` is true, `payload` is `undefined`, and `payload.definition[1].base_aa` throws `TypeError: Cannot read properties of undefined (reading 'definition')`, crashing the node process (assuming no top-level `uncaughtException` handler recovers cleanly and the process exits/restarts).

function getAllAuthorsAndOutputAddresses(objUnit){
	var arrAuthorAddresses = objUnit.authors.map(function(author){ return author.address; });
	if (!objUnit.messages) // voided unit
		return null;
	var arrOutputAddresses = [];
	var arrBaseAAAddresses = [];
	for (var i=0; i<objUnit.messages.length; i++){
		var message = objUnit.messages[i];
		var payload = message.payload;
		if (message.app === "payment" && payload) {
			for (var j = 0; j < payload.outputs.length; j++) {
				var address = payload.outputs[j].address;
				if (arrOutputAddresses.indexOf(address) === -1)
					arrOutputAddresses.push(address);
			}
		}
		else if (message.app === 'definition' && payload.definition[1].base_aa)
			arrBaseAAAddresses.push(payload.definition[1].base_aa);
	}
	var arrAddresses = _.union(arrAuthorAddresses, arrOutputAddresses, arrBaseAAAddresses);
	return {
		author_addresses: arrAuthorAddresses,
		output_addresses: arrOutputAddresses,
		base_aa_addresses: arrBaseAAAddresses,
		addresses: arrAddresses,
	};
}
