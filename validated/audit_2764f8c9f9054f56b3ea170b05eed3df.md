### Title
L1 BTC lockup proofs in `register-for-bond` can be replayed to credit unlocked sats to a new bond - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`pox-5.clar`'s `register-for-bond` accepts an L1 Bitcoin lockup proof (historical merkle proof + block header) as evidence that a staker's sats are locked, and credits `sats-total` (derived from that proof) as the bond's `amount-sats`. The only anti-duplication check, `ERR_DUPLICATE_LOCKUP_OUTPOINT`, dedups outpoints only *within a single call's fold* — there is no persistent, contract-level map of outpoints that have already been used to back a bond. Because the check is purely historical (a merkle/header proof that a UTXO existed at some past block) and never verifies the UTXO is still unspent, the same real BTC lockup transaction can be replayed across multiple, non-overlapping `register-for-bond` calls to credit sats that are no longer actually locked on Bitcoin.

### Finding Description
`register-for-bond` computes `sats-total` via `verify-l1-lockups`, which folds `validate-l1-lockup` over the caller-supplied `outputs` list: [1](#0-0) 

`validate-l1-lockup` checks (a) the output script matches the staker's expected timelock script for the *new* bond's requested `unlock-burn-height`, (b) the amount matches, (c) the outpoint hasn't been seen earlier **in this same fold**, (d) the block header is valid, and (e) the merkle proof is valid: [2](#0-1) 

Critically, `seen-outpoints` is a fresh, per-call accumulator seeded as `(list)` inside `verify-l1-lockups` — it exists only for the duration of one contract-call's `fold` and is never persisted to contract storage: [3](#0-2) 

There is no map such as `l1-lockup-used` or `claimed-outpoints` anywhere in the contract (confirmed by search) that would record "this Bitcoin outpoint has already backed a bond." The only cross-call defenses that exist are: `ERR_ALREADY_REGISTERED` (rejects overlapping bond memberships for the *same principal*) and the bond-rollover-window check. Neither of these prevents:
1. Staker A registers for bond 0 using L1 proof for outpoint X, locking BTC on-chain until height H.
2. Bond 0 ends (its membership becomes inactive/non-overlapping).
3. Staker A calls `register-for-bond` again for a *new*, non-overlapping bond N, submitting the *same* historical proof for outpoint X (same tx, same merkle proof, same header) — as long as the encoded `unlock-burn-height` in the constructed script satisfies `>= minimum-unlock-height` of the new bond, `validate-l1-lockup` re-validates successfully because all its checks (script match, amount match, header validity, merkle validity) are static facts about a historical block; none of them assert that outpoint X is still unspent on the current Bitcoin chain.
4. `sats-total` is credited again to the new bond's `amount-sats`, and `is-l1-lock: true` is stored, `protocol-bonds-total-staked` and `add-staker-to-bond-cycles`/`add-staker-to-signer-cycles` are updated as if fresh, still-locked BTC backs this — even if the staker has since spent/unlocked the real BTC.

This breaks the equality "L1 BTC locked ↔ pox-5 bond sats credited": sats can be credited to a bond without any BTC currently locked on L1, directly matching the excluded/target bug class "sats credited by an L1 proof that were never locked on Bitcoin" (here: no longer locked, credited again).

### Impact Explanation
This is a Critical-severity issue matching the rubric's "unbacked minting… of locked STX or sBTC rewards" / "unlocking value never locked" category, in its pox-5 L1-lockup analog: an attacker can accrue signer-set weight, reward shares, and share of protocol rewards for a bond whose sats collateral does not exist anymore. Since bond rewards (sBTC payouts and signer-set eligibility) are calculated from `amount-sats`/shares, credited-but-unbacked sats let an attacker dilute honest bond participants' rewards and/or artificially inflate a signer's qualifying stake without real economic backing, degrading the security assumption that signer weight/rewards are proportional to actually-locked BTC or STX.

### Likelihood Explanation
Exploitation requires only: (1) performing one legitimate real BTC lockup once, (2) waiting for it to mature and optionally spending/unlocking the real BTC, and (3) resubmitting the exact same historical proof bytes (tx, header, merkle path) in a subsequent `register-for-bond` call for a later, non-overlapping bond period with a compatible `unlock-burn-height`. No admin, miner, or other-user key is needed — the caller only needs their own valid, previously-used proof, which is by construction always self-consistent (their own past transaction). This is a fully reachable path for any unprivileged staker who has ever done an L1 lockup.

### Recommendation
Persist a durable map (e.g. `l1-outpoint-used: {txid, output-index} -> bool`) that is checked and set on every successful `validate-l1-lockup`/`register-for-bond` call (not reset per call), so that once an outpoint has backed a bond, it can never be credited again regardless of whether the bond has since ended. Alternatively/additionally, require proof that the outpoint is still unspent at call time (e.g., via a more recent SPV proof anchored close to `tx-sender`'s call, or an oracle attesting current UTXO status) rather than relying solely on a possibly stale historical merkle proof.

### Proof of Concept
Conceptual reproduction (cannot be executed without full integration harness, but follows directly from the code path):
1. Staker locks real BTC to the pox-5 timelock P2WSH script for bond 0 (`unlock-burn-height = U0`), submits `register-for-bond(bond_index=0, ..., btc-lockup = ok {outputs: [output_X], ...})`. `validate-l1-lockup` passes, `sats-total` credited, bond 0 membership created with `is-l1-lock: true`.
2. Bond 0 matures; staker's `unlock-burn-height U0` passes; the staker spends the BTC on L1 (funds now unlocked/moved out of the P2WSH).
3. A new bond N (non-overlapping with bond 0) is set up. Staker calls `register-for-bond(bond_index=N, ..., btc-lockup = ok {outputs: [output_X] (same tx/proof as step 1, with an `unlock-burn-height` chosen ≥ bond N's minimum-unlock-height})`.
4. `verify-l1-lockups` → `validate-l1-lockup` re-validates output_X successfully (script/amount/header/merkle all check out because they are facts about the same historical block); `seen-outpoints` dedup only guards against repeats *within this one list*, so it does not block reuse across the two separate transactions in steps 1 and 3.
5. Bond N's membership is created with the same `sats-total`, `is-l1-lock: true`, and full share/reward eligibility — despite the underlying BTC no longer being locked. [4](#0-3) [5](#0-4)

(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
