### Title
Pre-permissionless quorum collapses to 1 for N=3 validators via `F(3,3)=0` — (`blockchain/block_validator.go`)

### Summary

`IstanbulSealer.F` computes `ceil(N/3)-1`, which equals the standard PBFT `f = floor((N-1)/3)`. For N=3 this yields f=0, so `2f+1=1`. The pre-permissionless branch of `verifySeals` uses `2*sealer.F(...)+1` as its quorum threshold, meaning a block carrying exactly **one** valid committed seal from any council member passes the seal-count check. The permissionless branch correctly calls `sealer.Quorum`, which special-cases `n<4` and returns `n` (i.e., 3), but that guard is absent from the pre-permissionless path.

### Finding Description

In `blockchain/block_validator.go`, `verifySeals` splits on `rules.IsPermissionless`:

- **Permissionless path** (line 279): `validSeal < v.sealer.Quorum(blockNum, len(committee), len(committee))` — for N=3 this threshold is 3.
- **Pre-permissionless path** (line 314): `validSeal < 2*v.sealer.F(blockNum, qualifiedLen, committeeSize)+1` — for qualifiedLen=3, committeeSize=3 this threshold is **1**.

A block header whose `CommittedSeal` slice contains a single valid ECDSA signature from any council member satisfies `validSeal >= 1` and passes `verifySeals` unconditionally. The `countValidCommittedSeals` helper only checks that each signer is in the council set and is not duplicated; it does not enforce a minimum count beyond what the outer comparison requires. ### Impact Explanation

A single Byzantine council member on a pre-permissionless network with exactly 3 qualified validators can:

1. Act as block proposer for some height H.
2. Craft a block at H containing only their own committed seal (1 seal).
3. Serve this block to any node performing block import or header-chain sync.
4. `verifySeals` accepts it (`validSeal=1 >= 1`), so the block is inserted as canonical.

Honest nodes that participated in live consensus committed a different block at H (with proper quorum). Syncing nodes that receive only the crafted block diverge from the canonical chain. This constitutes **invalid block acceptance** and **consensus divergence** — both are in-scope impacts under the allowed impact gate.

### Likelihood Explanation

- Requires a pre-permissionless network (historical but still active for chains that have not yet crossed the permissionless fork block).
- Requires exactly qualifiedLen ≤ 3 (or any N where `ceil(N/3)-1 = 0`, i.e., N ∈ {1,2,3}).
- Requires one malicious council member — not a majority, not compromised keys, just a single Byzantine participant, which BFT is explicitly supposed to tolerate.
- The attack surface is the standard block-import path reachable from P2P sync peers.

### Recommendation

Replace the pre-permissionless quorum expression with `v.sealer.Quorum(...)`, which already contains the correct `n<4` guard:

```go
// Before (broken for N ≤ 3):
if validSeal < 2*v.sealer.F(blockNum, qualifiedLen, committeeSize)+1 {

// After:
if validSeal < v.sealer.Quorum(blockNum, qualifiedLen, committeeSize) {
```

Alternatively, add the same `n<4 → return n` guard inside `F` so that `2*F+1` is never less than `ceil(2N/3)`.

func countValidCommittedSeals(committers []common.Address, signerSet *valset.AddressSet) (int, error) {
