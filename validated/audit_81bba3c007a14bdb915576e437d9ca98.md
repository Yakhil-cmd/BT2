### Title
CCMenu token issued by `CCMenuUrlController#fetch` is unscoped and grants read access to every stack via `Api::CCMenuController#show` - (File: app/controllers/shipit/ccmenu_url_controller.rb)

### Summary
`CCMenuUrlController#client` creates (or reuses) an `ApiClient` with permission `read:stack` but never sets `stack:`, so the resulting `authentication_token` is not bound to the requesting stack. Because `Api::CCMenuController#stack` also bypasses the stack-scoping helper entirely, that token can be replayed against `Api::CCMenuController#show` for any stack in the system, and once returned to the browser as a plain URL query parameter it can leak (public CI badge, git remote, third-party status page) to an unauthenticated internet party.

### Finding Description
The expected binding is `client.stack_id == stack.id` for the `ApiClient` returned to a given user for a given stack. In `app/controllers/shipit/ccmenu_url_controller.rb`:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
```
`stack:` is never passed, so `ApiClient#stack_id` remains `nil` (`app/models/shipit/api_client.rb:8` — `belongs_to :stack, optional: true`). The equality `client.stack_id == stack.id` is false; instead `client.stack_id == nil` regardless of which stack the URL was requested for.

`find_or_create_by!(creator: current_user, name: 'CCMenu Client')` also means every CCMenu URL a given user requests, for any stack, resolves to the *same* `ApiClient` row and the *same* `authentication_token` — a single reusable global read token per user.

On the consuming side, `Api::BaseController#stacks` (app/controllers/shipit/api/base_controller.rb:74-76) is designed to scope by `current_api_client.stack_id` when present, falling back to `Stack.all` otherwise:
```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end
```
However `Api::CCMenuController` (app/controllers/shipit/api/ccmenu_controller.rb:29-31) overrides `stack` and does not use `stacks` at all:
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```
So even independent of the `stack_id` omission in `CCMenuUrlController`, the CCMenu endpoint never enforces per-stack scoping — it only checks `require_permission :read, :stack`, which is satisfied by the `read:stack` permission string regardless of which stack the client's `stack_id` points to (`ApiClient#check_permissions!` in app/models/shipit/api_client.rb:38-45 only checks membership in the `permissions` array, never `stack_id`).

Attacker/exploit flow:
1. Any authenticated Shipit user U (who has access to at least one stack, e.g. stack A) visits the CCMenu URL feature for stack A, hitting `CCMenuUrlController#fetch`.
2. This creates/looks up an `ApiClient` with `permissions: ['read:stack']`, `stack_id: nil`, and returns `token = client.authentication_token` embedded in the returned URL.
3. That URL/token, if pasted into a public CI dashboard, git remote comment, or third-party status page, is now visible to unauthenticated internet parties.
4. Any holder of the token can call `GET /api/stacks/:any_stack_id/ccmenu.xml?token=<token>` for **any** stack B, C, ... in the Shipit instance. `ApiClient.authenticate(token)` succeeds (signature valid), `require_permission!(:read, :stack)` passes (permission array contains `read:stack`), and `Api::CCMenuController#stack` resolves stack B without any ownership check, returning stack B's deploy/task XML.

No existing guard prevents this: `authenticate_api_client` only verifies the token's cryptographic validity, not scope; `require_permission!` checks only permission strings, not `stack_id`; and the `stack` method in this specific controller doesn't even consult the `stacks` scoping helper that other API controllers may rely on.

### Impact Explanation
Any authenticated Shipit user's action of requesting a CCMenu URL creates a durable, reusable token that discloses deploy/task state (latest deploy/rollback status) of **every stack in the Shipit instance**, not just the stack the user requested it for. If the URL is leaked outside the trust boundary (e.g., a public CI badge or shared dashboard), an unauthenticated internet attacker gains persistent, repeatable read access to all stacks' deploy state. This matches "High - unauthenticated read of stack state" in the given severity rubric; it is a genuine tenant-isolation break across all stacks (global blast radius), not confined to the stack the URL was intended for.

### Likelihood Explanation
Preconditions are minimal: the attacker needs no Shipit credentials, no GitHub team membership, and no secrets. They only need to obtain a previously-generated CCMenu URL/token, which by design is meant to be pasted into external tools (CI status badges, IDE plugins) — a use case that inherently risks exposure outside the trusted boundary. No special repository/stack configuration is required, and the bug is deterministic and 100% reproducible once a token from any stack is obtained.

### Recommendation
Bind the `ApiClient` created by `CCMenuUrlController#client` to the specific stack: `ApiClient.create_with(permissions: %w[read:stack], stack:).find_or_create_by!(creator: current_user, stack:, name: 'CCMenu Client')` (or a per-stack unique name/lookup), and fix `Api::CCMenuController#stack` to use the inherited `stacks` scoping helper (`stacks.from_param!(params[:stack_id])`) instead of unscoped `Stack.from_param!`, so a stack-scoped `ApiClient` cannot read stacks outside its `stack_id`.

### Proof of Concept
Minitest plan (e.g. `test/controllers/ccmenu_url_controller_test.rb` + `test/controllers/api/ccmenu_controller_test.rb`, conceptually combined):
```ruby
test "CCMenu token for stack A also grants read access to unrelated stack B" do
  user = shipit_users(:walrus)
  stack_a = shipit_stacks(:shipit)
  stack_b = shipit_stacks(:cyclimse) # unrelated stack

  session[:user_id] = user.id
  get :fetch, params: { stack_id: stack_a.to_param } # CCMenuUrlController#fetch
  body = JSON.parse(response.body)
  token = URI(body['ccmenu_url']).query.split('token=').last

  client = Shipit::ApiClient.find_by(creator: user, name: 'CCMenu Client')
  assert_nil client.stack_id
  # binding violated: client.stack_id (nil) != stack_a.id

  get :show, params: { stack_id: stack_b.to_param, token: token } # Api::CCMenuController#show
  assert_response :success
  assert_match stack_b.to_param, response.body
end
```
This demonstrates the token minted for stack A is accepted and returns stack B's CCMenu XML with a 200 response, confirming the unscoped/global-read vulnerability. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)
