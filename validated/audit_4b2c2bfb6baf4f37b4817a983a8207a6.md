### Title
Missing Cross-Parameter Ordering Check in `checkConsistency` Allows `LowerBoundBaseFee > UpperBoundBaseFee` via Same-Epoch Governance Votes, Inverting Base Fee Dynamics — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

The `checkConsistency` function validates each KIP-71 base-fee bound vote independently against the *current* parameter set. It does not check whether a new lower-bound vote and a new upper-bound vote cast in the **same epoch** will together violate the invariant `LowerBoundBaseFee ≤ UpperBoundBaseFee`. When both votes are ratified at the epoch boundary, the resulting inverted state causes `NextMagmaBlockBaseFee` to produce completely reversed base-fee dynamics: the base fee decreases under high gas usage and increases under low gas usage, corrupting every subsequent block's base fee, fee-burn amount, and transaction-filtering threshold.

---

### Finding Description

**Root cause — `kaiax/gov/headergov/impl/header.go`, `checkConsistency`:** [1](#0-0) 

```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {   // strict >
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {   // strict <
        return ErrUpperBoundBaseFee
    }
```

Each vote is validated against `h.GetParamSet(blockNum)` — the parameter set **before** any pending votes in the current epoch take effect. Two votes cast in the same epoch are never cross-checked against each other.

**Attack in `none` governance mode** (any GC member may vote):

| Step | Action | Check performed | Result |
|---|---|---|---|
| Current state | `lower=25 gwei`, `upper=750 gwei` | — | — |
| Block N (epoch k) | Vote: `LowerBoundBaseFee = 600` | `600 > 750`? No | Accepted |
| Block N+k (epoch k) | Vote: `UpperBoundBaseFee = 200` | `200 < 25`? No | Accepted |
| Epoch boundary | Both ratified | No cross-check | `lower=600 > upper=200` |

Both votes pass individually. No validation occurs at ratification time. The resulting state has `LowerBoundBaseFee (600) > UpperBoundBaseFee (200)`.

**Effect on `NextMagmaBlockBaseFee` — `params/kip71_config.go`:** [2](#0-1) 

With `lower=600`, `upper=200`, for any `parentBaseFee ≥ 200` (virtually always true):

```
parentBaseFee = upperBoundBaseFee = 200   // clamped to the smaller value
```

Then:
- **High gas usage** (`parentGasUsed > gasTarget`): shortcut fires because `parentBaseFee == upperBoundBaseFee` → returns `200`. Base fee stays low despite congestion.
- **Low gas usage** (`parentGasUsed < gasTarget`): `nextBaseFee = 200 − delta < lowerBoundBaseFee (600)` → returns `600`. Base fee spikes high despite low demand.

This is the exact inverse of the intended EIP-1559-style adjustment.

**`VerifyMagmaHeader` propagates the corruption:** [3](#0-2) 

Every block proposer and every verifying node calls `VerifyMagmaHeader` → `NextMagmaBlockBaseFee` with the same inverted parameters. All honest nodes agree on the wrong base fee, so the chain continues without a fork — but with permanently corrupted fee semantics.

---

### Impact Explanation

1. **Incorrect KAIA fee burning**: Kore-fork burns half the base fee. With inverted dynamics, during high-congestion periods the base fee is artificially suppressed (200 gwei instead of ~750 gwei), burning far less KAIA than the protocol intends. During low-congestion periods the base fee is artificially inflated (600 gwei), burning more KAIA than intended. This is an unauthorized alteration of the KAIA burn/supply schedule.

2. **Transaction filtering corruption**: `FilterTransactionWithBaseFee` in the worker uses `NextMagmaBlockBaseFee` to filter the pending pool before block production. [4](#0-3) 
With an inverted base fee, valid transactions are excluded during low-usage periods (base fee = 600 gwei) and transactions that should be excluded are included during high-usage periods (base fee = 200 gwei).

3. **Persistent state corruption**: The invalid `LowerBoundBaseFee > UpperBoundBaseFee` state is written to the governance DB at the epoch boundary and persists until another governance vote corrects it. Every block produced in the interim carries a wrong base fee.

---

### Likelihood Explanation

- **`none` governance mode** is a valid production configuration (used in private/consortium deployments and test networks). Any single GC member can cast both votes within one epoch — no collusion required.
- The two votes are individually indistinguishable from legitimate governance activity; no anomaly detection fires.
- The window is one full epoch (default 604,800 blocks on mainnet, configurable to much shorter intervals).
- On mainnet (`single` mode), the governing node alone can execute this, making it a privileged-actor scenario there. On `none`-mode networks the trigger is semi-trusted (any council member).

---

### Recommendation

Add a cross-parameter consistency check at two points:

1. **In `checkConsistency`** — when validating a `Kip71LowerBoundBaseFee` vote, also check it against any pending `Kip71UpperBoundBaseFee` vote already recorded in the current epoch (and vice versa).

2. **At epoch ratification** — in `getExpectedGovernance` / `HandleGov`, after assembling the ratified parameter set, validate that `ratified.LowerBoundBaseFee ≤ ratified.UpperBoundBaseFee` before committing. If violated, reject the governance update or drop the offending vote.

Minimal fix in `checkConsistency`:

```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    newLower := vote.Value().(uint64)
    if newLower > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    }
    // NEW: also reject if equal, to preserve strict lower < upper
    if newLower >= params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    }
```

And symmetrically for `Kip71UpperBoundBaseFee`. Additionally, add a final cross-check at ratification time in `getExpectedGovernance`.

---

### Proof of Concept

Precondition: network running in `none` governance mode with default KIP-71 parameters (`lower=25 gwei`, `upper=750 gwei`).

```
Epoch k, block B1:
  GC member casts vote: governance_vote("kip71.lowerboundbasefee", 600_000_000_000)
  checkConsistency: 600e9 > 750e9? No → accepted, written to header.Vote

Epoch k, block B2 (same epoch, later block):
  Same (or different) GC member casts vote: governance_vote("kip71.upperboundbasefee", 200_000_000_000)
  checkConsistency: 200e9 < 25e9? No → accepted, written to header.Vote

Epoch boundary block (k+1)*epoch:
  getExpectedGovernance collects both votes, ratifies both.
  header.Governance = {"kip71.lowerboundbasefee": 600e9, "kip71.upperboundbasefee": 200e9}
  No cross-check performed.

Block (k+1)*epoch + 1 onward:
  NextMagmaBlockBaseFee(lower=600e9, upper=200e9, parentGasUsed=60_000_000 > gasTarget=30_000_000):
    parentBaseFee clamped to upper=200e9
    shortcut: parentBaseFee == upperBoundBaseFee → return 200e9
  // Base fee = 200 gwei despite maximum congestion. Half burned = 100 gwei/gas instead of ~375 gwei/gas.

  NextMagmaBlockBaseFee(lower=600e9, upper=200e9, parentGasUsed=1_000_000 < gasTarget):
    parentBaseFee clamped to upper=200e9
    nextBaseFee = 200e9 - delta ≈ 199e9 < lowerBoundBaseFee=600e9 → return 600e9
  // Base fee = 600 gwei despite near-zero congestion. Half burned = 300 gwei/gas.
```

The base fee is inverted: high congestion → low fee, low congestion → high fee. KAIA burn amounts are wrong in both directions, and transaction filtering is corrupted for every block until governance is corrected. [5](#0-4) [6](#0-5) [7](#0-6)

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}
