### Title
Webhook signature validated with a webhook_secret selected from an unauthenticated payload field, decoupled from the repository the event actually writes to - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks *which* `webhook_secret` to HMAC-verify a delivery against by reading `repository_owner` straight out of the still-unauthenticated JSON body, then validates the whole raw body against that org's secret. [1](#0-0)  Nothing in this check ties the chosen "authenticating organization" to the repository/commit that the corresponding webhook handler subsequently writes to, because handlers resolve their target purely from `payload.dig('repository', 'full_name')`. [2](#0-1)  This is the exact class of bug from the report: a value (`voterPercent_`/here, the "authenticating org") is validated in isolation and trusted for a downstream effect (finalizing the vote / writing to a resource) without checking it actually corresponds to the resource being acted on.

### Finding Description
Shipit supports hosting multiple GitHub organizations, each with its own `webhook_secret` in `secrets.yml`. [3](#0-2)  `Shipit.github(organization:)` looks up the `GitHubApp`/secret for whatever organization string is passed in. [4](#0-3) 

`verify_signature` determines that organization from the payload itself, before the signature has been checked:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [5](#0-4) 

The equality that should hold is:
`organization whose secret authenticated the delivery == organization that owns the repository the handler subsequently mutates`

But `repository.owner.login` (used to pick the secret) and `repository.full_name` (used by every handler to resolve the target `Stack`/`Commit`) are two independent, attacker-controlled fields of the same unsigned JSON body. An attacker who legitimately possesses a valid `webhook_secret` for *any one* onboarded organization (e.g. because they administer their own org/app installation that Shipit is also configured for) can craft a payload where:
- `repository.owner.login = "attacker-org"` (so `Shipit.github(organization: "attacker-org")` resolves to the secret the attacker knows), and
- `repository.full_name = "victim-org/victim-repo"` (so the handler acts on the victim repository/stack).

Because the HMAC covers the *entire* raw body, and the attacker knows the secret selected by `repository.owner.login`, they can compute a signature that passes `verify_webhook_signature` even though the payload's `full_name` points at a completely different, un-owned repository. `StatusHandler`, for example, takes `sha`/`state`/`description`/`target_url`/`context` directly from this unauthenticated payload and writes a `Status` on any `Commit` in the datastore matching that `sha`, regardless of which organization was used to authenticate:
```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [6](#0-5)  Other handlers (`PushHandler`, `pull_request/*Handler`, `membership_handler`, `check_suite_handler`) similarly resolve their target purely via `Repository.from_github_repo_name(payload.dig('repository','full_name'))`, with no cross-check against the org whose secret validated the request. [2](#0-1)  `PushHandler` can thus enqueue `GithubSyncJob`/continuous-delivery-relevant syncs for a victim stack that the attacker never controls. [7](#0-6) 

### Impact Explanation
This breaks the "organization that authenticated versus the repository that is written" binding. An attacker with legitimate webhook credentials for one onboarded organization can forge cross-organization writes: fabricating commit statuses (`Status` records) for arbitrary commits/stacks in other organizations hosted on the same Shipit instance, and/or triggering `PushHandler`-driven syncs/continuous-delivery activity against a victim's stack, unauthenticated read/write of stack state that they have no legitimate access to. This is a cross-repository write achieved without needing a Shipit session, `ApiClient` token, or GitHub write access to the victim repo — only requiring possession of one organization's `webhook_secret`, which is the intended trust boundary the signature check is supposed to enforce per-repository.

### Likelihood Explanation
This only affects deployments configured with the multi-organization `github:` schema (`docs/setup.md`), which is documented and supported. [3](#0-2)  Any actor who is an org owner/admin for one of the organizations onboarded to the same shared Shipit instance (a low, plausible bar — e.g. a legitimate but lower-trust tenant org in a shared internal deploy tool) can obtain that org's `webhook_secret` and mount this attack against any other tenant.

### Recommendation
`verify_signature` should not decide the verification key from unauthenticated payload data alone. At minimum, after selecting `github_app` by `repository_owner` and validating the signature, the controller (or `Handler` base class) must additionally verify that `payload.dig('repository', 'full_name')`'s owner segment matches the same `repository_owner`/organization used to select the signing secret, rejecting the delivery otherwise. More robust: authenticate solely against the specific `Repository`'s stored owner/organization derived from the DB record identified by `full_name`, not from a value read out of the unsigned body prior to verification.

### Proof of Concept
1. Shipit is configured with two organizations, `attacker-org` and `victim-org`, each with its own GitHub App installation and `webhook_secret` (per `docs/setup.md`'s multi-org config).
2. Attacker knows `attacker-org`'s `webhook_secret` (legitimately, as the org/app owner).
3. Attacker crafts a `status` webhook JSON body:
```json
{
  "sha": "<victim commit sha>",
  "state": "success",
  "context": "ci/forced",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" }
}
```
4. Attacker computes `X-Hub-Signature: sha1=HMAC-SHA1(attacker-org's webhook_secret, raw_body)` and POSTs to `/github/webhooks` with `X-Github-Event: status`.
5. `WebhooksController#verify_signature` computes `repository_owner = "attacker-org"`, fetches `attacker-org`'s `GitHubApp`, and the signature verifies successfully. [8](#0-7) 
6. `StatusHandler#process` runs with the attacker-supplied `sha`/`state`/`context`, writing a forged `Status` onto the victim's commit, entirely independent of the organization that authenticated the request. [6](#0-5)

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event

    end

    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
