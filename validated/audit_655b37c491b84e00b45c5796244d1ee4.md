### Title
`NonTransfer` proxy can self-escalate to reach `Registrar::swap` by exploiting an incorrect `is_superset(NonTransfer, Auction)` claim - ([File: polkadot/runtime/rococo/src/lib.rs])

### Summary
Rococo's (and Westend relay chain's) `ProxyType::is_superset` implementation declares `NonTransfer` a superset of *every* other `ProxyType`, including `Auction`, via the catch-all arm `(ProxyType::NonTransfer, _) => true`. However `NonTransfer`'s own `filter` deliberately *excludes* `Registrar::swap` (explicitly commented "Specifically omitting Registrar `swap`"), while `ProxyType::Auction`'s filter admits the entire `Registrar { .. }` call family, including `swap`. Because `pallet_proxy` uses `is_superset` (not `filter`) to authorize `add_proxy`/`remove_proxy` performed through an existing proxy (`substrate/frame/proxy/src/lib.rs` `do_proxy`, lines 994-1026), a delegate holding only a `NonTransfer` proxy can add an `Auction` proxy for the same delegator and thereby reach `Registrar::swap`, a call its own `NonTransfer` grant was designed to deny. This is the exact bug class already identified and fixed for `NonTransfer`/`Governance` on Asset Hub Westend in [PR #12769](https://github.com/paritytech/polkadot-sdk/commit/) (see `prdoc/pr_12769.prdoc` and the regression test `non_transfer_proxy_is_not_a_superset_of_governance` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2518-2559`), but the analogous `NonTransfer`⊃`Auction` relationship in the relay-chain runtimes was not covered by that fix.

### Finding Description
`pallet_proxy::do_proxy` (`substrate/frame/proxy/src/lib.rs:994-1026`) installs a call filter on the inner origin used for proxied calls:
```rust
Some(Call::add_proxy { ref proxy_type, .. }) |
Some(Call::remove_proxy { ref proxy_type, .. })
    if !def.proxy_type.is_superset(proxy_type) => { false },
```
This means a proxy is only prevented from widening its own delegated permission set if `is_superset` correctly reflects the actual `filter` containment relationship between two `ProxyType`s. In `polkadot/runtime/rococo/src/lib.rs:1000-1008` (and equivalently in `polkadot/runtime/westend/src/lib.rs:1022-1030`):
```rust
fn is_superset(&self, o: &Self) -> bool {
    match (self, o) {
        (x, y) if x == y => true,
        (ProxyType::Any, _) => true,
        (_, ProxyType::Any) => false,
        (ProxyType::NonTransfer, _) => true,
        _ => false,
    }
}
```
`NonTransfer` is claimed as a superset of *all* other types, but its `filter` (lines 922-967) explicitly denies `Registrar::swap` while `ProxyType::Auction`'s `filter` (lines 988-995) admits `RuntimeCall::Registrar { .. }` unconditionally, which includes `swap`. The invariant required by `do_proxy` — "if A is a superset of B, then every call B's filter admits, A's filter also admits" — is broken for this pair, mirroring exactly the previously-patched `NonTransfer`/`Governance` case on Asset Hub Westend.

### Impact Explanation
A signed account holding only a `NonTransfer` proxy over a delegator is not supposed to be able to invoke `Registrar::swap` on the delegator's behalf (it is explicitly denied in `NonTransfer`'s filter). Using the broken `is_superset` check, the delegate can call `Proxy::add_proxy(real, Auction, delay)` through the existing `NonTransfer` proxy (since `is_superset(NonTransfer, Auction)` incorrectly returns `true`), then call `Proxy::proxy(real, Some(Auction), Registrar::swap{..})`. This grants the delegate a capability it was never authorized for, violating the confinement guarantee the proxy system is supposed to enforce for `NonTransfer` delegates — the same integrity break as CVE-2021-43835 (self-granted permission expansion) and the already-acknowledged Asset Hub Westend issue (#12724/PR 12769).

Note: `Registrar::swap` itself still requires `ensure_root_para_or_owner(origin, id)` (`polkadot/runtime/common/src/paras_registrar/mod.rs:330-331`), so the *delegator* (`real`) must already be the para's manager/owner for the call to succeed. The escalation therefore does not create new authority for the real account, but it does let an under-privileged *delegate* (holding only `NonTransfer`) exercise an operation on the delegator's registered parachain that was explicitly and deliberately withheld from it — an authorization-model violation of the same class as the reported CVE, though of lesser severity than the Asset Hub Westend `Governance` case, since `swap` cannot move funds directly and is gated by the para-owner check.

### Likelihood Explanation
Likelihood is Medium: it requires (1) an account has already granted a `NonTransfer` proxy to another account (a normal, common configuration), and (2) that delegator account is itself a parachain manager/owner. Both conditions are realistic for parachain teams that use proxies for day-to-day operations while keeping sensitive powers ("Auction"-class operations) behind stronger proxy types. No privileged role, governance action, or validator/collator compromise is needed — only ordinary signed extrinsics (`add_proxy`, `proxy`) from the delegate account, exactly matching the reachable-entry-point requirement.

### Recommendation
Add an explicit non-superset arm for `(ProxyType::NonTransfer, ProxyType::Auction)` (and audit any other `ProxyType` pairs matched by the `(ProxyType::NonTransfer, _) => true` catch-all) in `polkadot/runtime/rococo/src/lib.rs` and `polkadot/runtime/westend/src/lib.rs`, mirroring the fix applied in `prdoc/pr_12769.prdoc` for Asset Hub Westend's `NonTransfer`/`Governance` pair, and add a regression test analogous to `non_transfer_proxy_is_not_a_superset_of_governance` asserting that every call admitted by `Auction`'s filter is also admitted by `NonTransfer`'s filter before allowing `is_superset` to return `true` for that pair.

### Proof of Concept
No executable PoC was run against a live chain or local node (per policy, no execution against public networks and no unverified "test ran" claims are made). The escalation path is derived purely from static code inspection and is deterministic given the cited source:
1. `filter` mismatch evidence: `polkadot/runtime/rococo/src/lib.rs:922-967` (`NonTransfer` filter, comment "Specifically omitting Registrar `swap`") vs. `polkadot/runtime/rococo/src/lib.rs:988-995` (`Auction` filter, unconditional `RuntimeCall::Registrar { .. }`).
2. `is_superset` over-claim: `polkadot/runtime/rococo/src/lib.rs:1000-1008`, catch-all `(ProxyType::NonTransfer, _) => true`.
3. Authorization gate relying on `is_superset`: `substrate/frame/proxy/src/lib.rs:994-1026` (`do_proxy`), specifically lines 1005-1013.
4. `swap`'s origin check requiring para owner/root: `polkadot/runtime/common/src/paras_registrar/mod.rs:328-331`.

A concrete integration reproduction would require: creating a `NonTransfer` proxy for a delegator that already owns/manages a registered `ParaId`, then, as the delegate, dispatching `Proxy::add_proxy(real, ProxyType::Auction, 0)` (expected to succeed under current code due to the broken `is_superset`), followed by `Proxy::proxy(real, Some(ProxyType::Auction), RuntimeCall::Registrar(paras_registrar::Call::swap{id, other}))` and observing it dispatch successfully despite `NonTransfer`'s filter denying `swap` directly. This reproduction was not executed as part of this analysis; the finding is supported entirely by the cited source excerpts and the already-merged analogous fix (`prdoc/pr_12769.prdoc`) demonstrating that Parity itself treats this exact `is_superset`-vs-`filter` mismatch pattern as a confirmed, fixable vulnerability class.
