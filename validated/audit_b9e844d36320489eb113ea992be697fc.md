### Title
`in merkle` address-definition condition validates against any historical merkle root ever posted by the oracle, not just the current one - ([File: definition.js])

### Summary
The `in merkle` authentifier condition is meant to let an address restrict spending/AA-trigger authorization to members of a merkle-tree whitelist published by an oracle via a data feed. However, the check does not bind the proof to the *current* (latest) root — it accepts any root the oracle ever posted for that `feed_name` within `[min_mci, last_ball_mci]`. This mirrors the `changeMaxGenerationId` bug class: a validity check that should be scoped to "the current generation/epoch" instead accepts anything valid in *any* past epoch, as long as an unrelated range parameter (`min_mci` / `maxGenerationId`) doesn't happen to exclude it.

### Finding Description
When evaluating an `in merkle` clause, `definition.js` deserializes the caller-supplied merkle proof, verifies it structurally with `merkle.verifyMerkleProof`, and then checks whether the proof's `root` was ever recorded as a value of `feed_name` posted by one of `arrAddresses`, using `dataFeeds.dataFeedExists(arrAddresses, feed_name, '=', proof.root, min_mci, objValidationState.last_ball_mci, false, cb2)`: [1](#0-0) 

`dataFeedExists` (via `dataFeedByAddressExists`) implements the `'='` relation as "does a record with this exact value exist anywhere in the key range `[min_mci, max_mci]`", not "is this the most recent/current value": [2](#0-1) 

`min_mci` is an optional 4th argument in the definition (`args[3]`), defaulting to `0` if omitted both at validation time and evaluation time: [3](#0-2) [4](#0-3) 

Consequently, if an oracle rotates its whitelist by posting a new merkle root under the same `feed_name` (e.g. to remove a compromised or expired member, analogous to advancing to a new "generation"/"season"), any address that was a member of an **older** root can still satisfy the `in merkle` condition, because `dataFeedExists` finds the old root among the oracle's historical postings — exactly like `changeMaxGenerationId`'s Merkle proof not being scoped to the current generation/season, so old-generation proofs remain valid.

### Impact Explanation
An `in merkle` clause is typically embedded in an address definition (shared/managed wallet) or an asset/AA condition to gate spending or AA-trigger authorization to "current members of list X, as maintained by oracle O." Because the check accepts membership from any historical root the oracle ever published (unless the address author deliberately sets a tight `min_mci`, which is optional and not enforced), a previously-listed but since-revoked address can still author units that pass the definition, authorizing spends from the shared address or triggering AA logic that should only be reachable by current whitelist members. This is unauthorized spending / unauthorized authorization analogous to unintended minting from old generations.

### Likelihood Explanation
Any unprivileged unit poster who once possessed a valid merkle proof against a stale root retains the ability to reuse it indefinitely (bounded only by `last_ball_mci`), since nothing forces `min_mci` to track the oracle's latest root update. Address definitions using `in merkle` without an aggressively maintained `min_mci` are realistic given `min_mci` is optional, making this reachable by design, not requiring any privileged or malicious-node behavior — the affected unit author is a normal, previously-whitelisted party.

### Recommendation
Change `in merkle` validation to require matching the **latest** posted root for `feed_name` (e.g., use a `readDataFeedValue`-style "last" lookup restricted to the newest MCI ≤ `last_ball_mci`) rather than `dataFeedExists` with an open-ended historical range, or mandate that address definitions using `in merkle` explicitly track the oracle's root-update MCI as `min_mci` and document/enforce that this must be refreshed on every rotation.

### Proof of Concept
1. Oracle address `O` posts merkle root `R1` (whitelist v1) under `feed_name = "wl"`, including address `A`'s value `e_A` in the tree.
2. `A`'s (or a shared) address definition includes `['in merkle', [[O], 'wl', e_A]]` (no `min_mci`, defaulting to 0).
3. `A` posts a unit satisfying the condition with a merkle proof for `e_A` against `R1` — accepted because `dataFeedExists([O], 'wl', '=', R1, 0, last_ball_mci, ...)` finds `R1` among `O`'s postings.
4. Oracle later posts a new root `R2` (whitelist v2) that excludes `A`.
5. `A` posts a new unit reusing the *old* proof (still valid against `R1`) with the *same* `['in merkle', [[O], 'wl', e_A]]` condition (still `min_mci=0`). `dataFeedExists` still finds `R1` in `O`'s history within `[0, last_ball_mci]`, so the condition is satisfied even though `A` is no longer in the current whitelist `R2`. function dataFeedExists(arrAddresses, feed_name, relation, value, min_mci, max_mci, bAA, handleResult){
	var start_time = Date.now();
	var bLimitedPrecision = (max_mci < constants.aa2UpgradeMci);
	if (bAA) {
		var bFound = false;
		function relationSatisfied(v1, v2) {
			switch (relation) {
				case '<': return (v1 < v2);
				case '<=': return (v1 <= v2);
				case '>': return (v1 > v2);
				case '>=': return (v1 >= v2);
				default: throw Error("unknown relation: " + relation);
			}
		}
		function valueIsNumber() {
			if (typeof value === 'string') {
				const float = string_utils.toNumber(value, bLimitedPrecision);
				return float !== null;
			}
			return true;
		}
		for (var unit in storage.assocUnstableMessages) {
			var objUnit = storage.assocUnstableUnits[unit] || storage.assocStableUnits[unit];
			if (!objUnit)
				throw Error("unstable unit " + unit + " not in assoc");
			if (!objUnit.bAA)
				continue;
			if (objUnit.latest_included_mc_index < min_mci || objUnit.latest_included_mc_index > max_mci)
				continue;
			if (_.intersection(arrAddresses, objUnit.author_addresses).length === 0)
				continue;
			storage.assocUnstableMessages[unit].forEach(function (message) {
				if (message.app !== 'data_feed')
					return;
				var payload = message.payload;
				if (!ValidationUtils.hasOwnProperty(payload, feed_name))
					return;
				var feed_value = payload[feed_name];
				if (relation === '=') {
					if (value === feed_value || value.toString() === feed_value.toString())
						bFound = true;
					return;
				}
				if (relation === '!=') {
					// search only within the same type, otherwise 'abc' != 123 but we don't want to say that they are not equal, because they are incomparable
					if (valueIsNumber()) {
						if (value.toString() !== feed_value.toString())
							bFound = true;
					}
					else {
						if (value !== feed_value)
							bFound = true;
					}
					return;
				}
				if (typeof value === 'number' && typeof feed_value === 'number') {
					if (relationSatisfied(feed_value, value))
						bFound = true;
					return;
				}
				var f_value = (typeof value === 'string') ? string_utils.toNumber(value, bLimitedPrecision) : value;
				var f_feed_value = (typeof feed_value === 'string') ? string_utils.toNumber(feed_value, bLimitedPrecision) : feed_value;
				if (f_value === null && f_feed_value === null) { // both are strings that don't look like numbers
					if (relationSatisfied(feed_value, value))
						bFound = true;
					return;
				}
				if (f_value !== null && f_feed_value !== null) { // both are either numbers or strings that look like numbers
					if (relationSatisfied(f_feed_value, f_value))
						bFound = true;
					return;
				}
				if (typeof value === 'string' && typeof feed_value === 'string') { // only one string looks like a number
					if (relationSatisfied(feed_value, value))
						bFound = true;
					return;
				}
				// else they are incomparable e.g. 'abc' > 123
			});
			if (bFound)
				break;
		}
		if (bFound)
			return handleResult(true);
	}
	async.eachSeries(
		arrAddresses,
		function(address, cb){
			dataFeedByAddressExists(address, feed_name, relation, value, min_mci, max_mci, cb);
		},
		function(bFound){
			console.log('data feed by '+arrAddresses+' '+feed_name+relation+value+': '+bFound+', df took '+(Date.now()-start_time)+'ms');
			handleResult(!!bFound);
		}
	);
