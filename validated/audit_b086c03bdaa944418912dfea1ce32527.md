**Reasoning:** The reported CVE concerns an MCP tool server that blindly fetches an attacker-supplied URL without validating against private/internal IP ranges — the vulnerable pattern requires (1) attacker-controlled URL input reaching (2) an outbound fetch call with (3) no address/scope validation.

In `polkadot-sdk`, the only outbound-HTTP-fetch capability is the Offchain Worker HTTP API: [1](#0-0)  and its high-level wrapper in `sp_runtime::offchain::http::Request` [2](#0-1) . This API is exposed only to offchain worker code that runs **locally on the node**, driven by `Externalities::http_request_start` [3](#0-2) , not by any signed extrinsic, XCM message, or contract call dispatched by an external, unprivileged attacker. The URL passed to `http_request_start` is chosen by the runtime/pallet author's own offchain-worker logic (e.g. a hardcoded oracle endpoint), not by arbitrary user-submitted extrinsic payload data processed generically by the SDK.

Because there is no core-SDK entry point where an unprivileged external actor supplies a URL/target that framework code then fetches server-side without validation, the required "real user entry" (signed extrinsic, contract call, or permitted XCM message) reaching an unguarded outbound-fetch primitive does not exist in this codebase. The vulnerability class is specific to the npm `mcp-fetch-server` tool and does not have a demonstrable structural analog in the Polkadot SDK's production Rust code.

	pub fn send(self) -> Result<PendingRequest, HttpError> {
		let meta = &[];

		// start an http request.
		let id = sp_io::offchain::http_request_start(self.method.as_ref(), self.url, meta)
			.map_err(|_| HttpError::IoError)?;

		// add custom headers
		for header in &self.headers {
			sp_io::offchain::http_request_add_header(id, header.name(), header.value())
				.map_err(|_| HttpError::IoError)?
		}

		// write body
		for chunk in self.body {
			sp_io::offchain::http_request_write_body(id, chunk.as_ref(), self.deadline)?;
		}

		// finalize the request
		sp_io::offchain::http_request_write_body(id, &[], self.deadline)?;

		Ok(PendingRequest { id })
	}
