### Title
Owner/full_name signature-org split lets a no-secret org forge `pull_request:edited` events that mutate another org's stack's `PullRequest`/`Commit` records - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb, app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to verify with using `repository.owner.login`, while `EditedHandler` resolves the repository/stack to mutate using `repository.full_name`. Because these two fields are never checked for consistency, an attacker who controls a GitHub org configured in Shipit without a `webhook_secret` can point `full_name` at a completely different, secret-protected repository and have `EditedHandler` write attacker-controlled data into that victim stack's `PullRequest` (and, via commit lookup, `Commit`) records. This holds independent of the target stack's `review_stacks_enabled` setting, since `EditedHandler` contains no provisioning logic at all.

### Finding Description
The broken invariant, stated as an equality that should hold but doesn't:
`Shipit.github(organization: params.repository.owner.login)` (the org whose secret authenticates the request) **should equal** `Shipit::Repository.from_github_repo_name(params.repository.full_name).owner` (the org whose data is mutated). These are two independently attacker-supplied strings with no cross-check.

Path:
- `Shipit::WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository','owner','login')` [1](#0-0)  and fetches `Shipit.github(organization: repository_owner)` to verify the signature [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected org has no configured `webhook_secret` [3](#0-2) . So naming a Shipit-known org that has no secret set makes signature verification a no-op for the whole payload.
- Once verification passes, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches the raw, attacker-controlled JSON to `EditedHandler` [4](#0-3) .
- `EditedHandler#repository` resolves the target repository from `params.repository.full_name` only, with no relation to the org used to verify the signature: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) .
- `EditedHandler#pull_request` looks up an existing `Shipit::PullRequest` scoped to that resolved repository's stacks by PR `number` [6](#0-5) .
- `EditedHandler#process` then calls `pull_request.update(github_pull_request: params.pull_request)` if a matching record is found [7](#0-6) .
- `PullRequest#github_pull_request=` overwrites `title`, `state`, `additions`, `deletions`, `user`, `assignees`, `labels`, and resolves `head` via `find_or_create_commit_from_github_by_sha!`, which — if the SHA is not already known locally — calls `stack.github_api.commit(stack.github_repo_name, sha)` and `stack.commits.create_from_github!(github_commit)`, writing a new `Shipit::Commit` row into the **victim's** stack using an attacker-chosen SHA [8](#0-7) .

Why guards fail: `verify_signature` only checks that *some* organization's HMAC matches; it never checks that the verifying organization equals the organization actually referenced by `repository.full_name`. `drop_unhandled_event`/`ExplicitParameters` schema only validate shape, not cross-field consistency (they require `repository.full_name` as a plain `String` [9](#0-8) ). `GithubOrganizationUnknown` only blocks completely unregistered orgs, not ones that are registered but secret-less [10](#0-9) .

Note on the "review_stacks_enabled" framing in the question: `EditedHandler` contains no reference to `review_stacks_enabled` or any provisioning behavior at all (unlike `OpenedHandler`/`LabeledHandler`), so the claimed "provisioning precedence bug amplifies the effect" does not apply here — `EditedHandler` never creates a stack or `PullRequest`; it only mutates a record that must already exist for that PR number under the resolved repository's stack. The core cross-org authentication bypass is real and independent of `review_stacks_enabled`.

### Impact Explanation
An attacker who knows of any Shipit-configured GitHub org without a `webhook_secret` can forge `pull_request` `edited` webhooks that overwrite `title`, `state`, `additions`, `deletions`, `user`, `assignees`, and `labels` on an existing `PullRequest` record belonging to an unrelated victim stack, and can force creation of a new `Shipit::Commit` record in that victim stack for an attacker-chosen (but real, publicly known) SHA via the victim stack's own GitHub API client. This matches the "a payload for one repository mutating another's stack, commit, task or team" Critical impact category. It does not, by itself, execute `Command`/`PTY.spawn`, trigger deploys, or leak secrets — the blast radius is data-integrity corruption of PR/commit bookkeeping for any stack whose repository owner is known to the attacker, repeatable per PR number that already has a matching record.

### Likelihood Explanation
Requires: (1) at least one GitHub org configured in Shipit's `github` app config lacking a `webhook_secret` (a plausible, common misconfiguration since the secret is optional per `verify_webhook_signature`'s `return true unless webhook_secret`), and (2) a pre-existing `PullRequest` row in the victim stack matching the forged PR `number` (created earlier through a legitimately authenticated `opened` event). No Shipit session, API token, or GitHub credentials are needed — only knowledge of a secret-less org name and the target repo's `full_name`/PR number, both discoverable via public GitHub data or Shipit's own UI. Attacker cost is a single crafted HTTP POST to `/webhooks`, fully repeatable.

### Recommendation
In `Shipit::WebhooksController#verify_signature`, derive `repository_owner` and the repository used by handlers from the same, single source of truth, and reject the payload if `params.dig('repository','owner','login')` does not match the owner segment of `params.dig('repository','full_name')`. Additionally, do not treat a missing `webhook_secret` as an automatic pass — require an explicitly configured secret per org, or fail closed when repository/organization identity is ambiguous.

### Proof of Concept
Minitest plan under `test/controllers/webhooks_controller_test.rb` (no live GitHub):
1. Configure two orgs in the test `Shipit.github` config: `"attacker-org"` with no `webhook_secret`, and `"victim-org"` with a `webhook_secret` set.
2. Seed `Shipit::Repository` for `victim-org/victim-repo`, a `Shipit::Stack` on it, and a `Shipit::PullRequest` with `number: 42` and known baseline `title`/`labels`.
3. POST to `/webhooks` with `X-Github-Event: pull_request`, body: `action: "edited"`, `number: 42`, `pull_request: {... title: "PWNED", labels: [{name:"malicious"}], head: {sha: "<victim commit sha>", ref:"x"}, ...}`, `repository: {owner: {login: "attacker-org"}, full_name: "victim-org/victim-repo"}`, and `X-Hub-Signature` computed with any bogus value (irrelevant since `attacker-org` has no secret).
4. Assert response is `200 OK` (bypassing what should be a signature failure against `victim-org`'s secret).
5. Reload the `PullRequest` record and assert `title == "PWNED"` and `labels == ["malicious"]`, proving a payload that was never authenticated by `victim-org`'s secret mutated `victim-org`'s stack data — violating the invariant "a `pull_request` event only affects the repository/stack whose secret authenticated it."

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def github_pull_request=(github_pull_request)
      self.github_id = github_pull_request.id
      self.number = github_pull_request.number
      self.api_url = github_pull_request.url
      self.title = github_pull_request.title
      self.state = github_pull_request.state
      self.additions = github_pull_request.additions
      self.deletions = github_pull_request.deletions
      self.user = User.find_or_create_by_login!(github_pull_request.user.login)
      self.assignees = github_pull_request.assignees.map do |github_user|
        User.find_or_create_by_login!(github_user.login)
      end
      self.labels = github_pull_request.labels.map(&:name)
      self.head = find_or_create_commit_from_github_by_sha!(github_pull_request.head.sha)
    end

    def find_or_create_commit_from_github_by_sha!(sha)
      if commit = stack.commits.by_sha(sha)
        commit
      else
        github_commit = stack.github_api.commit(stack.github_repo_name, sha)
        stack.commits.create_from_github!(github_commit)
      end
    rescue ActiveRecord::RecordNotUnique
      retry
    end
```
