### Title
Bridge Event Loop Permanently Halts on Subscription Error, Causing Irreversible Loss of Cross-Chain Value Transfer Events — (File: `node/sc/bridge_manager.go`)

### Summary

`BridgeManager.loop()` in `node/sc/bridge_manager.go` terminates permanently when any of its three event subscriptions (`reqVTevSub`, `reqVTencodedEvSub`, `handleEventSub`) signals an error. After the loop exits, all subsequent on-chain `RequestValueTransfer` and `HandleValueTransfer` events are silently dropped. Users whose assets were already locked or burned on the source chain receive nothing on the destination chain. The only partial mitigation — `valueTransferRecovery` — is **disabled by default** and does not cover `HandleValueTransfer` events even when enabled.

### Finding Description

`BridgeManager.subscribeEvent()` starts three `WatchLogs`-backed subscriptions and launches a single goroutine, `BridgeManager.loop()`, to consume them: [1](#0-0) 

Inside `loop()`, any subscription error causes an unconditional `return`: [2](#0-1) 

There is no restart, no re-subscription, and no buffering of events that arrive after the goroutine exits. The three subscriptions are backed by `event.NewSubscription`, which wraps a `WatchLogs` call: [3](#0-2) 

A transient backend error (e.g., a dropped WebSocket connection to the parent-chain RPC, a context cancellation, or a log-filter backend failure) causes the inner `sub.Err()` channel to fire, which propagates to `reqVTevSub.Err()` / `reqVTencodedEvSub.Err()` / `handleEventSub.Err()` in `loop()`, terminating it.

The same structural defect exists in `SubBridge.loop()`, which also returns permanently on any of five subscription errors: [4](#0-3) 

### Impact Explanation

When `BridgeManager.loop()` exits:

- **`RequestValueTransfer` / `RequestValueTransferEncoded` events** emitted on-chain are never forwarded to `reqVTevFeeder` / `reqVTevEncodedFeeder`, so `SubBridge.loop()` never calls `ProcessRequestEvent()`, and the counterpart bridge never calls `HandleKLAYTransfer` / `HandleERC20Transfer` / `HandleERC721Transfer`. Assets already locked or burned on the source chain are permanently stranded. [5](#0-4) 

- **`HandleValueTransfer` events** are never forwarded to `handleEventFeeder`, so `ProcessHandleEvent()` is never called. `MarkHandledNonce` and `UpdateLowerHandleNonce` are never updated, corrupting the bridge's internal nonce accounting: [6](#0-5) 

The `valueTransferRecovery` subsystem is the intended mitigation, but:

1. It is **disabled by default** (`VTRecovery: false`): [7](#0-6) [8](#0-7) 

2. Even when enabled, it only recovers `RequestValueTransfer` events by re-scanning historical logs; it has **no mechanism to recover `HandleValueTransfer` events**: [9](#0-8) 

3. It requires **two consecutive recovery intervals** before acting (the `candidate` flag mechanism), introducing a mandatory delay: [10](#0-9) 

### Likelihood Explanation

The trigger is a subscription error on any of the three `WatchLogs`-backed subscriptions. These subscriptions communicate over the local Ethereum client's internal event system. A transient RPC backend error, a context cancellation during node shutdown/restart, or a log-filter backend failure is sufficient. No privileged access or attacker control is required; the condition arises from ordinary operational events. Any service-chain operator running without `--vtrecovery` (the default) is exposed.

### Recommendation

1. Replace the bare `return` on subscription error with an automatic re-subscription loop (analogous to `event.Resubscribe`) so `BridgeManager.loop()` restarts after a backoff period without losing events.
2. Enable `VTRecovery` by default, or make the node refuse to start a subscribed bridge without it.
3. Extend `valueTransferRecovery` to also re-scan and re-process missed `HandleValueTransfer` events, not only `RequestValueTransfer` events.
4. Apply the same fix to `SubBridge.loop()`, which has the identical structural defect.

### Proof of Concept

1. Deploy a service-chain bridge pair with `--subbridge` and without `--vtrecovery` (default).
2. Subscribe the bridge (`bm.SubscribeEvent(addr)`), which starts `BridgeManager.loop()`.
3. Inject a subscription error by closing the underlying backend connection or triggering a `WatchLogs` failure (e.g., restart the parent-chain RPC node momentarily).
4. `reqVTevSub.Err()` fires; `BridgeManager.loop()` logs `"Contract Event Loop Running Stop by receivedSub.Err()"` and exits.
5. Submit a `RequestValueTransfer` transaction on the child-chain bridge contract. The `RequestValueTransfer` event is emitted on-chain but `chanReqVT` has no reader; the event is never forwarded to `reqVTevFeeder`; `ProcessRequestEvent` is never called; `HandleKLAYTransfer` / `HandleERC20Transfer` is never submitted on the parent chain.
6. The user's KAIA/ERC20/ERC721 remains locked or burned on the child chain with no corresponding release on the parent chain — permanent asset loss without manual operator intervention. [11](#0-10) [5](#0-4)

func (bm *BridgeManager) subscribeEvent(addr common.Address, bridge *bridgecontract.Bridge) error {
	bm.tokenEventMu.Lock()
	defer bm.tokenEventMu.Unlock()

	chanReqVT := make(chan *bridgecontract.BridgeRequestValueTransfer, TokenEventChanSize)
	chanReqVTencoded := make(chan *bridgecontract.BridgeRequestValueTransferEncoded, TokenEventChanSize)
	chanHandleVT := make(chan *bridgecontract.BridgeHandleValueTransfer, TokenEventChanSize)

	vtEv, err := bridge.WatchRequestValueTransfer(nil, chanReqVT, nil, nil, nil)
	if err != nil {
		logger.Error("Failed to watch RequestValueTransfer event", "err", err)
		return err
	}
	bm.receivedEvents[addr] = append(bm.receivedEvents[addr], vtEv)

	vtEncodedev, err := bridge.WatchRequestValueTransferEncoded(nil, chanReqVTencoded, nil, nil, nil)
	if err != nil {
		logger.Error("Failed to watch RequestValueTransferEncoded event", "err", err)
		return err
	}
	bm.receivedEvents[addr] = append(bm.receivedEvents[addr], vtEncodedev)

	withdrawnSub, err := bridge.WatchHandleValueTransfer(nil, chanHandleVT, nil, nil, nil)
	if err != nil {
		logger.Error("Failed to watch HandleValueTransfer event", "err", err)
		vtEv.Unsubscribe()
		vtEncodedev.Unsubscribe()
		delete(bm.receivedEvents, addr)
		return err
	}
	bm.withdrawEvents[addr] = withdrawnSub

	bridgeInfo, ok := bm.GetBridgeInfo(addr)
	if !ok {
		vtEv.Unsubscribe()
		vtEncodedev.Unsubscribe()
		withdrawnSub.Unsubscribe()
		delete(bm.receivedEvents, addr)
		delete(bm.withdrawEvents, addr)
		return ErrNoBridgeInfo
	}
	bridgeInfo.subscribed = true

	go bm.loop(addr, chanReqVT, chanReqVTencoded, chanHandleVT, vtEv, vtEncodedev, withdrawnSub)

func (cce *ChildChainEventHandler) ProcessHandleEvent(ev *HandleValueTransferEvent) error {
	handleBridgeInfo, ok := cce.subbridge.bridgeManager.GetBridgeInfo(ev.Raw.Address)
	if !ok {
		return errors.New("there is no bridge")
	}

	handleBridgeInfo.MarkHandledNonce(ev.HandleNonce)
	handleBridgeInfo.UpdateLowerHandleNonce(ev.LowerHandleNonce)

	logger.Trace("RequestValueTransfer Event",
		"bridgeAddr", ev.Raw.Address.String(),
		"handleNonce", ev.HandleNonce,
		"to", ev.To.String(),
		"valueType", ev.TokenType,
		"token/NFT contract", ev.TokenAddress,
		"value", ev.ValueOrTokenId.String())
	return nil
}

func retrievePendingEventsFrom(hint *valueTransferHint, from, to *BridgeInfo) ([]IRequestValueTransferEvent, error) {
	if from.bridge == nil {
		return nil, errors.New("from bridge is nil")
	}
	if to.bridge == nil {
		return nil, errors.New("to bridge is nil")
	}
	if hint.requestNonce == hint.handleNonce {
		return nil, nil
	}
	if !checkRecoveryCondition(hint) {
		return nil, nil
	}

	var pendingEvents []IRequestValueTransferEvent

	curBlkNum, err := from.GetCurrentBlockNumber()
	if err != nil {
		return nil, err
	}

	startBlkNum := hint.blockNumber
	endBlkNum := startBlkNum + filterLogsStride

pendingTxLoop:
	for startBlkNum <= curBlkNum {
		if endBlkNum > curBlkNum {
			endBlkNum = curBlkNum
		}
		opts := &bind.FilterOpts{Start: startBlkNum, End: &endBlkNum}
		reqVTevIt, err := from.bridge.FilterRequestValueTransfer(opts, nil, nil, nil)
		if err != nil {
			return nil, err
		}
		reqVTencodedDataIt, err := from.bridge.FilterRequestValueTransferEncoded(opts, nil, nil, nil)
		if err != nil {
			return nil, err
		}

		// TODO: The same logic with two types are verbose and can be neat with Go1.18 which supports generic.
		// For the FilterRequestValueTransfer type
		for reqVTevIt.Next() {
			logger.Trace("pending nonce in the RequestValueTransfer event", "requestNonce", reqVTevIt.Event.RequestNonce)
			if reqVTevIt.Event.RequestNonce >= hint.handleNonce {
				// Check if the event is already handled in target bridge contract
				if isHandledEvent(to, RequestValueTransferEvent{reqVTevIt.Event}) {
					continue
				}
				logger.Trace("filtered pending nonce", "requestNonce", reqVTevIt.Event.RequestNonce, "handledNonce", hint.handleNonce)
				pendingEvents = append(pendingEvents, RequestValueTransferEvent{reqVTevIt.Event})
				if len(pendingEvents) >= maxPendingTxs {
					reqVTevIt.Close()
					break pendingTxLoop
				}
			}
		}
		// For the FilterRequestValueTransferEncoded type
		for reqVTencodedDataIt.Next() {
			logger.Trace("pending nonce in the RequestValueTransferEncoded event", "requestNonce", reqVTencodedDataIt.Event.RequestNonce)
			if reqVTencodedDataIt.Event.RequestNonce >= hint.handleNonce {
				// Check if the event is already handled in target bridge contract
				if isHandledEvent(to, RequestValueTransferEncodedEvent{reqVTencodedDataIt.Event}) {
					continue
				}
				logger.Trace("filtered pending nonce", "requestNonce", reqVTencodedDataIt.Event.RequestNonce, "handledNonce", hint.handleNonce)
				pendingEvents = append(pendingEvents, RequestValueTransferEncodedEvent{reqVTencodedDataIt.Event})
				if len(pendingEvents) >= maxPendingTxs {
					reqVTencodedDataIt.Close()
					break pendingTxLoop
				}
			}
		}
		startBlkNum = endBlkNum + 1
		endBlkNum = startBlkNum + filterLogsStride
		reqVTevIt.Close()
		reqVTencodedDataIt.Close()
	}

	if len(pendingEvents) > 0 {
		logger.Info("retrieved pending events", "bridge", from.address.String(),
			"len(pendingEvents)", len(pendingEvents), "1st nonce", pendingEvents[0].Nonce())
	}
	return pendingEvents, nil

func checkRecoveryCandidateCondition(hint *valueTransferHint) bool {
	return hint.requestNonce != hint.handleNonce && hint.prevHandleNonce == hint.handleNonce
}

// checkRecoveryCondition checks if recovery for the handle value transfers is needed or not.
func checkRecoveryCondition(hint *valueTransferHint) bool {
	if checkRecoveryCandidateCondition(hint) && hint.candidate {
		hint.candidate = false
		return true
	}
	if checkRecoveryCandidateCondition(hint) && !hint.candidate {
		hint.candidate = true
		return false
	}
	hint.candidate = false
	return false
}
