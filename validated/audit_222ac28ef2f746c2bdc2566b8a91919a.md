The audit report describes an Ethereum/EVM-style gas exhaustion DoS from an unbounded loop appending to storage in `registerPool`. Searching the reachable Solana instructions in this repo (`initialize`, `initialize_with_permission`, `deposit`, `withdraw`, `swap_base_input`, `swap_base_output`, `collect_creator_fee`, `collect_creator_fee_permissionless`) turns up no analogous unbounded loop that grows with attacker-supplied data:

- The oracle observation buffer is a fixed-size array (`OBSERVATION_NUM = 100`) written to with a single indexed update, not an appended/growing loop [1](#0-0) [2](#0-1) .
- `support_mint_associated_is_initialized` and `is_supported_mint` in `utils/token.rs` contain the only loops in the reachable code paths, iterating over `remaining_accounts` or a mint's extension list, both of which are bounded by Solana's transaction size/account-count limits rather than an unbounded on-chain array [3](#0-2) [4](#0-3) .
- All PoolState fee/vault fields are fixed-size fields with `checked_add`/`checked_sub` arithmetic, not loop-driven accumulation [5](#0-4) .

Solana's compute model is also fundamentally different from EVM gas accounting: each instruction has a fixed compute-unit budget (not attacker-inflatable via storage growth), and remaining-account lists are inherently capped by the ~1232-byte transaction size limit, so there is no reachable path where a single transaction from an unprivileged swapper/LP/pool creator can force unbounded iteration analogous to the reported `registerPool` issue. Per the validation rules, this would at best be a compute-only concern, not concrete theft/freezing/insolvency impact, so it is excluded.

    remaining_accounts: &[AccountInfo],
    token_mint: &InterfaceAccount<Mint>,
) -> Result<bool> {
    if remaining_accounts.len() == 0 {
        return Ok(false);
    }
    let (expect_mint_associated, __bump) = Pubkey::find_program_address(
        &[SUPPORT_MINT_SEED.as_bytes(), token_mint.key().as_ref()],
        &crate::id(),
    );
    let mut mint_associated_is_initialized = false;
    for mint_associated_info in remaining_accounts.into_iter() {
        if *mint_associated_info.owner != crate::id()
            || mint_associated_info.key() != expect_mint_associated
        {
            continue;
        }

            &mut mint_associated_info.data.borrow().as_ref(),
        )?;
        if mint_associated.mint == token_mint.key() {
            mint_associated_is_initialized = true;
            break;
        }
    }

pub fn is_supported_mint(

    mint_associated_is_initialized: bool,

    let mint_info = mint_account.to_account_info();
    if *mint_info.owner == Token::id() {
        return Ok(true);
    }
    if mint_associated_is_initialized {
        return Ok(true);
    }
    let mint_data = mint_info.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
    let extensions = mint.get_extension_types()?;
    for e in extensions {
        if e != ExtensionType::TransferFeeConfig
            && e != ExtensionType::MetadataPointer
            && e != ExtensionType::TokenMetadata
            && e != ExtensionType::InterestBearingConfig
            && e != ExtensionType::ScaledUiAmount

            return Ok(false);

    }
    Ok(true)
