### Title
Skill update trusts owner/repo string identity with no anchor to the original repository, enabling repojacking-based content substitution - (File: internal/skills/discovery/discovery.go)

### Summary
`DiscoverSkills`/`DiscoverSkillsWithOptions` in [1](#0-0)  fetches a repository's git tree purely by `host`, `owner`, `repo`, and a freshly resolved `commitSHA`, with no check that this repository is the same entity the lockfile/frontmatter originally recorded. The update flow in `pkg/cmd/skills/update/update.go` re-resolves the ref and re-discovers skills every run using only the stored `owner`/`repo` strings, so if the underlying GitHub repository is transferred away and the `owner/repo` name is later reclaimed (repojacking) or a tag is force-moved, the tool downloads and installs the attacker's content as a "legitimate update".

### Finding Description
Installed-skill metadata records only `owner`, `repo`, `treeSHA`, and an optional `pinned` ref/tag string — see `parseInstalledSkill` at [2](#0-1)  and the corresponding lockfile entry written by `RecordInstall`, which stores `Source = owner + "/" + repo` and `SourceURL` built from those same strings with no persisted repository ID: [3](#0-2) .

During `gh skill update`, for each installed skill the code resolves the ref and calls `DiscoverSkills` keyed only by `owner`/`repo`/`host`: [4](#0-3) . `DiscoverSkillsWithOptions` blindly issues `GET /repos/{owner}/{repo}/git/trees/{commitSHA}` and treats whatever tree it gets back as authoritative: [5](#0-4) . There is no verification of the GitHub repository's node ID, creation date, or any other identity anchor between the recorded pin and the currently resolved repository at that owner/repo path.

The update decision solely compares tree SHAs of matched skill paths: `matched && (remote.TreeSHA != s.treeSHA || opts.Force)` — [6](#0-5) . Any content served from the resolved `owner/repo` at the resolved ref is accepted as a legitimate update and installed in place via `updateSkillInPlace` → `installer.Install`, which writes files onto the victim's disk: [7](#0-6) .

Exploit flow: an attacker publishes `attacker/skills-repo`, a victim installs a skill from it (lockfile/frontmatter records `owner=attacker, repo=skills-repo`). The attacker later transfers/renames the repo away, then re-creates a new repository at the same `attacker/skills-repo` path (GitHub permits name reuse once the original name is vacated) or, for pinned installs, force-moves the recorded tag (`github-pinned`) to point at a different commit. On `gh skill update`, `ResolveRef` and `DiscoverSkills` resolve against whatever repository now occupies that owner/repo slug and whatever commit the tag currently points to, with no cross-check against the original repo's identity or a content digest independent of the mutable tag. The victim's tool overwrites the local skill (potentially containing agent/LLM-executable instructions or scripts) with attacker content, and reports this as a normal "Updated" event.

### Impact Explanation
This allows a remote, unprivileged attacker (who only needs to control a GitHub repo/tag that a victim previously installed a skill from) to substitute arbitrary attacker-controlled files into a path the victim's tools/agents trust and act upon, without any warning that the source identity changed. Since skills are consumed by AI agent runtimes (Copilot, Claude, Cursor, etc.) as instructions, this is a realistic vector for remote code execution or high-impact prompt/tooling compromise on the developer's machine, matching a Critical RCE-class impact.

### Likelihood Explanation
Preconditions are attacker-feasible without any special privilege: publish a public repo, get a victim to install from it once, then transfer/rename the repo away and recreate the same owner/repo name (a known "repojacking" technique), or simply force-move a release tag the pin references. `gh skill update` is a normal, expected command victims run repeatedly, and the described condition (`remote.TreeSHA != s.treeSHA`) will trivially trigger on the substituted content, making exploitation reliable and repeatable.

### Recommendation
Anchor pins to an immutable identity rather than mutable owner/repo strings and tag names:
- Record and re-verify the GitHub repository's immutable `id`/`node_id` (from the API tree/repo response) at install time, and fail/warn loudly on update if the currently resolved repository's ID differs from the recorded one.
- For pinned installs, resolve and store an immutable commit SHA at pin time rather than trusting a tag name; if `--unpin`/re-resolution follows a tag, detect and warn when the tag now points to a commit that is not a fast-forward descendant of the previously recorded commit.
- Add an explicit test asserting that `updateRun`/`DiscoverSkills` refuses to apply an update when the resolved repository identity does not match the lockfile's recorded identity.

### Proof of Concept
Go test plan using `httpmock`:
1. Seed an installed skill's `SKILL.md` frontmatter with `github-repo: https://github.com/attacker/skills-repo`, `github-tree-sha: origsha`, `github-path: skills/demo` (as in `parseInstalledSkill` tests, e.g. [8](#0-7) ).
2. Stub `GET repos/attacker/skills-repo/git/ref/...`, `.../git/trees/{sha}` to return a *different* repository's tree contents (simulating repojacking) — same owner/repo path, unrelated `id`, unrelated tree/blob SHAs.
3. Run `updateRun` with `--all` and assert:
   - Current behavior: update proceeds, `remote.TreeSHA != s.treeSHA` is true, `installer.Install` overwrites `skills/demo/SKILL.md` with attacker content, and `wantStdout` shows `"Updated demo"` — demonstrating unauthorized content substitution.
   - Desired behavior (post-fix): update should fail or warn because repository identity verification fails, and the local file should remain unchanged.

func DiscoverSkillsWithOptions(client *api.Client, host, owner, repo, commitSHA string, opts DiscoverOptions) ([]Skill, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "trees", commitSHA)
	if err != nil {
		return nil, err
	}
	apiPath.SetQuery("recursive", "true")
	var tree treeResponse
	if err := client.REST(host, "GET", apiPath.String(), nil, &tree); err != nil {
		return nil, fmt.Errorf("could not fetch repository tree: %w", err)
	}

	if tree.Truncated {
		return nil, &TreeTooLargeError{Owner: owner, Repo: repo}
	}

	treeSHAs := make(map[string]string)
	for _, entry := range tree.Tree {
		if entry.Type == "tree" {
			treeSHAs[entry.Path] = entry.SHA
		}
	}

func updateSkillInPlace(opts *UpdateOptions, u pendingUpdate, apiClient *api.Client, gitRoot, homeDir string) error {
	if u.local.dir == "" {
		return fmt.Errorf("cannot update %s: no install location recorded", u.local.name)
	}

	parent := filepath.Dir(u.local.dir)
	if err := os.MkdirAll(parent, 0o755); err != nil {
		return fmt.Errorf("could not ensure parent directory %s: %w", parent, err)
	}

	// Stage as a sibling of the existing skill directory so the swap stays
	// on the same filesystem and every rename is atomic.
	staging, err := os.MkdirTemp(parent, "."+u.skill.Name+".gh-skill-update-")
	if err != nil {
		return fmt.Errorf("could not create staging directory: %w", err)
	}
	defer os.RemoveAll(staging)

	installOpts := &installer.Options{
		Host:    u.local.repoHost,
		Owner:   u.local.owner,
		Repo:    u.local.repo,
		Ref:     u.resolved.Ref,
		SHA:     u.resolved.SHA,
		Skills:  []discovery.Skill{u.skill},
		Dir:     staging,
		GitRoot: gitRoot,
		HomeDir: homeDir,
		Client:  apiClient,
	}
	if _, err := installer.Install(installOpts); err != nil {
		return err
	}
