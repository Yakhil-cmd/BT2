### Title
Accrual math overflow panic permanently freezes a whale market — no repay, withdraw, or liquidation possible (File: common/src/rates/index.rs)

### Summary
The apko bug class is "unchecked conversion of external-shaped data → panic → crash/DoS." In XOXNO Lending every panic is a revert, but one panic site is reachable persistently: `update_supply_index` (and `scaled_to_original`/`accrue_step`) compute `supplied.mul(old_index)` in `i128`, so once `supplied * index / RAY` exceeds `i128::MAX`, **every** subsequent accrual panics with `MathOverflow`. Because every pool verb accrues first (`interest::global_sync` runs on `Cache::load` for supply/borrow/withdraw/repay/seize/claim), the market freezes permanently — an outcome strictly worse than a transient revert.

### Finding Description
`update_supply_index` at `common/src/rates/index.rs:34` multiplies `supplied` by `old_index` via `Ray::mul`, which is checked `i128` arithmetic that panics with `GenericError::MathOverflow` on overflow (`common/src/math/fp.rs:12-16`, `common/src/math/fp_core.rs:298-303`). The borrow-side value product in `accrue_step` (`scaled_to_original`, `common/src/rates/scaling.rs:14-16`) has the same bound. The index clamps (`MAX_BORROW_INDEX_RAY`, `MAX_SUPPLY_INDEX_RAY`) engage *after* the multiplication, so they never fire before the value overflow — confirmed by `test_borrow_index_at_the_ceiling_multiplies_without_overflow` relying on headroom that does not exist once `supplied` is large. `interest::global_sync` (`contracts/pool/src/interest.rs:20-33`) runs this loop before every mutation, so once the product overflows there is no state transition that skips it. The project's own regression test demonstrates the cliff: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-360`) shows `update_indexes`, `withdraw`, and `repay` all reverting with `MATH_OVERFLOW` once `borrowed/supplied × index` leaves `i128`, with `borrow_index < MAX_BORROW_INDEX_RAY` (cap never engaged).

### Impact Explanation
Permanent freezing of funds: supplier principal, borrower collateral backing the debt, and accrued revenue in that market become unrecoverable — `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `claim_revenue`, and `recapitalize` all route through `global_sync` and trap on the same multiplication. There is no governance escape hatch that bypasses accrual. This matches the accepted impact "permanent freezing of funds / contract unable to operate," not a fail-closed revert (which would be out of scope).

### Likelihood Explanation
A single unprivileged address can drive this with only permissionless entrypoints: `controller::supply` a large position in a high-decimals listed asset (supply/borrow caps are governance-set, and the test lifts them to show the path is mechanical, not privileged), `controller::borrow` to push utilization onto the steep segment of the rate curve, then permissionless `controller::update_indexes` (or simply time) advances the index until the product overflows. The ceiling is `i128::MAX / RAY ≈ 1.7e11` whole-token value units, so it requires a genuinely whale-scale market (≈10^11 whole tokens supplied at ~98% utilization on a steep curve for a few years of accrual). That is capital- and time-intensive but not impossible for an asset with a large supply or a market that grows organically; once crossed the freeze is irreversible. `docs/reference/invariants.md` (INV-IDX-01) already acknowledges "Debt-value overflow can still revert accrual before that ceiling is reached," so this is partially a documented bound — severity is Medium at best given the extreme capital requirement.

### Recommendation
Make accrual saturate instead of panic: use the existing `mul_div_floor_saturating`/`mul_div_half_up_saturating` style already used for `calculate_scaled_cap` and supply-index growth (`common/src/rates/index.rs:41`), or short-circuit `accrue_step` when `borrowed`/`supplied` is zero or when the index is already at its cap. Alternatively clamp `borrowed`/`supplied` values entering the product, or add a governance `pause_market`-style path that writes `last_timestamp` without accruing so frozen markets can be unwound.

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```

```markdown
### INV-IDX-01 — Borrow index is monotone and bounded

Both indexes start at one RAY. Successful accrual with validated rate parameters
cannot lower the borrow index and caps it at the protocol constant 10^36 raw

Debt-value overflow can still revert accrual before that ceiling is reached.
```
