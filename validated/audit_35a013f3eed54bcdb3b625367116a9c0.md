### Title
`Shipit::GitHubApp#verify_webhook_signature` accepts unsigned webhooks for any organization configured without a `webhook_secret`, allowing forged `Team`/`Membership` records - ([File: lib/shipit/github_app.rb])

### Summary
`verify_webhook_signature` returns `true` unconditionally when the organization's `webhook_secret` is blank, and `WebhooksController#verify_signature` selects the organization/app to verify against purely from attacker-controlled payload fields (`repository.owner.login` or `organization.login`). If any configured org in a multi-org Shipit deployment has no `webhook_secret` set, an attacker can send a completely unsigned `membership` webhook naming that org and have `MembershipHandler#process` run unauthenticated, creating arbitrary `Team` and `Membership` rows.

### Finding Description
The broken binding is: **"a webhook body was verified by organization O's shared secret" should imply "organization O actually sent this request."** For any org where `webhook_secret` is nil, this equality is false — no secret exists, so no verification occurs, yet the code proceeds as if it did.

Code path:
- `WebhooksController#verify_signature` picks the app via `Shipit.github(organization: repository_owner)`, where `repository_owner` is read straight from the untrusted JSON body: `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0) .
- `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) does `return true unless webhook_secret` before checking any signature [2](#0-1) .
- `@webhook_secret = @config[:webhook_secret].presence` in the initializer, so a missing/blank `webhook_secret` in that org's config yields `nil`, triggering the bypass [3](#0-2) .
- If verification passes (trivially, here), `WebhooksController#create` dispatches to `Shipit::Webhooks.for_event(event)` handlers with the raw parsed JSON, unauthenticated [4](#0-3) .
- `MembershipHandler#process` creates/updates a `Team` keyed off `params.team.id` with `team.organization = params.organization.login`, and adds/removes a `member` User to/from it — all fields taken directly from the forged payload [5](#0-4) .

Attacker's exact request: `POST /webhooks` with header `X-Github-Event: membership`, no `X-Hub-Signature` (or a garbage one), and a JSON body containing `organization.login` set to the org whose config lacks `webhook_secret`, plus attacker-chosen `team` and `member` fields. No other guard intervenes: `check_if_ping` only special-cases the `ping` event; `drop_unhandled_event` only rejects events with no registered handler (membership has one); `ExplicitParameters` schema in `MembershipHandler` only validates shape/types, not provenance.

### Impact Explanation
This is a full authentication-bypass / forgery of `Membership` and `Team` records for the misconfigured org — matching the "authentication bypass (forged webhook ... accepted)" Critical category. The blast radius is scoped to whichever org(s) lack `webhook_secret`, but is fully repeatable: every `membership` webhook request to that org is unauthenticated and can add/remove arbitrary users from arbitrary teams. Whether this further elevates to `User#authorized?`/`Shipit.github_teams` depends on `Shipit.github_teams`, which is derived from the *default* GitHub app's `oauth_teams` (`Shipit.github.oauth_teams`, i.e., the app with no `organization:` argument) [6](#0-5) [7](#0-6) . If the misconfigured org happens to be (or match) the org backing one of the configured `oauth_teams`, a forged `Team`/`Membership` there directly grants `authorized?` to arbitrary GitHub logins claimed as `member.login`, escalating into full Shipit authorization — this is the scenario the question's precondition targets.

### Likelihood Explanation
Preconditions: a multi-org Shipit deployment (i.e., `secrets.github` keyed by organization, not the single-app legacy schema) where at least one organization entry omits `webhook_secret`. Given that precondition, the attacker cost is trivial: no secrets, no session, no GitHub App access — just an HTTP POST to a public `/webhooks` endpoint with attacker-chosen JSON. This is fully repeatable and requires no interaction with GitHub at all. The likelihood is entirely gated on the operator misconfiguration described (an org present in config without a `webhook_secret`), which the question itself states as its precondition.

### Recommendation
`verify_webhook_signature` (lib/shipit/github_app.rb:76-83) should not treat a blank `webhook_secret` as an automatic pass. Instead, either require every configured organization to have a non-blank `webhook_secret` (fail closed / raise at boot or reject the webhook with 422 when the target org has no secret configured), or reserve the "unsigned webhook" bypass exclusively for the legacy single-app config path where `Shipit.github_default_organization` is nil, not for any resolvable multi-org entry.

### Proof of Concept
minitest plan (no live GitHub required):
1. Configure `Shipit.secrets.github` (via test credentials/stub) with two orgs: `"secured-org"` with a `webhook_secret`, and `"unsecured-org"` with `webhook_secret` omitted/nil.
2. `POST /webhooks` with `X-Github-Event: membership`, no `X-Hub-Signature` header, body:
   ```json
   {"action":"added","team":{"id":999,"name":"Evil","slug":"evil","url":"https://x"},
    "organization":{"login":"unsecured-org"},"member":{"login":"attacker"}}
   ```
3. Assert response status is `200` (not `422`).
4. Assert `Shipit::Team.find_by(github_id: 999)` exists with `organization == "unsecured-org"`.
5. Assert `Shipit::User.find_by(login: "attacker")` is a member of that team via `Membership`.
6. Contrast: repeat with `organization.login` set to `"secured-org"` and no valid signature — assert response is `422` and no `Team`/`Membership` is created, confirming the divergence is specific to the org missing `webhook_secret`.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
