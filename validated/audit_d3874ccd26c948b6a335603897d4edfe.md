### Title
Passing `address(0)` (or any unwitnessable address) as `creator` in `initialize_with_permission` permanently freezes accrued creator fees - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
`initialize_with_permission` lets the caller (`payer`, an unprivileged signer) supply an arbitrary `creator` account that becomes `pool_state.pool_creator`. Unlike `initialize.rs`, which derives `pool_creator` from the actual transaction `Signer`, `initialize_with_permission.rs` accepts `creator` as an `UncheckedAccount`, with no constraint that it be non-zero, be a signer, or be controlled by anyone. This mirrors the reported bug class: an unset/attacker-chosen "counterpart" address (there, `mirrorConnector`; here, `pool_creator`) is written once and later used to gate a privileged, otherwise-unprotected code path, permanently breaking that path if the value is degenerate.

### Finding Description
In `initialize_with_permission.rs`, the `creator` account is declared as:
```rust
/// CHECK: creator of pool
pub creator: UncheckedAccount<'info>,
``` [1](#0-0) 

It is never required to be a signer, never checked against `Pubkey::default()`, and is written verbatim into `PoolState.pool_creator` via `pool_state.initialize(...)` (mirroring the pattern used in `initialize.rs` at [2](#0-1) , but using `creator.key()` instead of a signer's key for this permissioned variant).

`pool_creator` subsequently gates both fee-collection code paths:
- `CollectCreatorFee` requires the caller to literally be `pool_creator`: `#[account(mut, address = pool_state.load()?.pool_creator)] pub creator: Signer<'info>` [3](#0-2) 
- `CollectCreatorFeePermissionless` sends fees to an ATA whose authority is forced to equal `pool_creator`: `associated_token::authority = creator` where `creator` is constrained via `#[account(address = pool_state.load()?.pool_creator)]` [4](#0-3)  and [5](#0-4) .

If `payer` supplies `creator = Pubkey::default()` (or any address with no discoverable private key) when calling `initialize_with_permission`, `pool_creator` becomes permanently fixed to that unwitnessable address:
1. `CollectCreatorFee` can never succeed, because no `Signer` can ever match `address(0)` (there is no corresponding private key).
2. `CollectCreatorFeePermissionless` will still execute and create/mint into an ATA owned by `address(0)`/the unwitnessable address, but the tokens deposited there can never be withdrawn by anyone, since no one can sign as that authority.

Since `creator_fee_on`/`enable_creator_fee` accrue fees on every subsequent `swap_base_input`/`swap_base_output` call for that pool as tracked in `PoolState.creator_fees_token_0/1` [6](#0-5) , all creator-fee revenue generated by the pool for its entire lifetime becomes permanently and irrecoverably locked in the vaults/ATA.

### Impact Explanation
This is a permanent freezing of funds: all creator fees accrued over the pool's lifetime (a portion of every swap's trade fee) become unrecoverable once `pool_creator` is set to a degenerate address, with no owner/admin override available to fix `pool_creator` after pool creation (there is no `set_pool_creator`/admin instruction found in the codebase). This satisfies the "Medium/High" bar under "permanent freezing of user or LP funds."

### Likelihood Explanation
`initialize_with_permission` is reachable by any account holding a valid `Permission` PDA (an unprivileged pool creator, per the scope's allowed entry points), and the `creator` field is entirely attacker-controlled with zero validation. The attack requires a single transaction with a chosen `creator` account and does not require any elevated privilege beyond what is already granted to call this pool-creation instruction — this is a strict single-tx, attacker-chosen-account/data path, matching the reported bug class exactly (mis-set "counterpart" field that is later relied upon for privileged gating, without a zero-address / signer check).

### Recommendation
Add a constraint on `creator` in `InitializeWithPermission` requiring `creator.key() != Pubkey::default()` (and consider requiring it be a signer, matching `initialize.rs`'s pattern of using the actual transacting party as `pool_creator`), so a degenerate/unwitnessable `pool_creator` can never be written into `PoolState`.

### Proof of Concept
1. Attacker (or any holder of a valid `Permission` PDA) calls `initialize_with_permission` with `creator = Pubkey::default()` (system_program's zero-value pubkey) as the `creator` account, funding the pool normally with `payer_token_0`/`payer_token_1`.
2. `pool_state.pool_creator` is set to `Pubkey::default()` via `pool_state.initialize(...)` [7](#0-6) .
3. Users swap against the pool; `creator_fees_token_0/1` accumulate in `PoolState` as normal.
4. `CollectCreatorFee` can never be called successfully because no keypair can sign as `address(0)` to satisfy `#[account(mut, address = pool_state.load()?.pool_creator)] pub creator: Signer<'info>` [3](#0-2) .
5. Calling `CollectCreatorFeePermissionless` moves the fees into an ATA owned by `address(0)`, which no one can ever control or withdraw from [8](#0-7) , permanently freezing all accrued creator fees.

pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
```
