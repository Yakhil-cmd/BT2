### Title
Forged `pull_request` reopened webhook: signature verified against `repository.owner.login` org while handler mutates a stack keyed off a different `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub org (and thus the `webhook_secret` used to validate `X-Hub-Signature`) using `params.dig('repository', 'owner', 'login')`, while `Shipit::Webhooks::Handlers::PullRequest::ReopenedHandler` resolves the repository to mutate using `params.repository.full_name`. These are two independent, attacker-controlled fields in the same JSON body, so an attacker can make them point at different organizations.

### Finding Description
The broken binding is: *the org whose `webhook_secret` verified the request* MUST equal *the org that owns the repository the handler writes to*. That is:
`repository_owner` (used in `verify_signature`) == owner parsed from `params.repository.full_name` (used in `ReopenedHandler#repository`).

Trace:
- `verify_signature` in `app/controllers/shipit/webhooks_controller.rb` (lines 24-30) computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` (lines 59-62) reads only `params.dig('repository', 'owner', 'login')`.
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb` lines 76-83) returns `true` unconditionally `unless webhook_secret` — i.e., if the selected org has no `webhook_secret` configured, ANY signature (or none) passes.
- `ReopenedHandler#repository` (`app/models/shipit/webhooks/handlers/pull_request/reopened_handler.rb` lines 49-53) resolves the target repo via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, which splits `full_name` on `/` (`app/models/shipit/repository.rb` lines 53-56) — a completely different payload field than `repository.owner.login`.
- The handler then calls `stack.unarchive!` (line 44), which via `ReviewStackAdapter#unarchive!` either unarchives an existing `ReviewStack` or creates a new one (`create!`, lines 72-85) scoped to `repository.review_stacks` — i.e., scoped to whatever repository was resolved from `full_name`.

Exploit: An attacker sets `repository.owner.login` = "attacker-org" (a GitHub org configured in Shipit with no `webhook_secret`), while setting `repository.full_name` = "victim-org/victim-repo" (a real, secret-protected repo tracked by Shipit with review stacks enabled). Because "attacker-org" has no secret, `verify_webhook_signature` returns `true` regardless of the `X-Hub-Signature` header content. The controller proceeds to dispatch the event to `ReopenedHandler`, which resolves `repository` from `full_name` = "victim-org/victim-repo", and unarchives/creates a `ReviewStack` for that PR — despite the fact that no secret belonging to `victim-org` was ever checked.

Existing guards fail because:
- `drop_unhandled_event` and `check_if_ping` don't validate ownership consistency.
- `verify_signature` never cross-checks `repository.owner.login` against `repository.full_name`'s owner segment.
- `ExplicitParameters` schema on `ReopenedHandler` only requires `repository.full_name` to be present as a String; it does not require or validate `repository.owner.login` at all, so there's no schema-level tie between the two fields.
- `GithubOrganizationUnknown` only triggers if the org name given in `repository.owner.login` isn't configured at all — it does nothing to catch the case where a *valid, but unrelated, no-secret* org is named.

### Impact Explanation
An attacker with no Shipit credentials and no knowledge of any `webhook_secret` can trigger state changes (unarchiving/creating `ReviewStack` records, which are tied to CI/deploy provisioning) for a repository/org they do not own or control, as long as some other org configured in the same Shipit instance has no `webhook_secret` set. This is cross-tenant state manipulation: one repository's/org's authentication weakness is used to forge writes against a different repository's records. This matches the Critical category "a payload for one repository mutating another's stack, commit, task or team." The blast radius includes any tracked repository with review stacks enabled, and the attack is repeatable per PR/organization at will.

### Likelihood Explanation
Preconditions: the Shipit deployment must have at least one configured GitHub organization without a `webhook_secret` (common in multi-org Shipit setups where not every org's webhook is secured), and the target org/repo must have review stacks configured. Given that, the attacker cost is minimal — a single crafted HTTP POST to `/webhooks` with a `pull_request`/`reopened` payload, no valid signature needed. This is trivially repeatable and requires no privileged access, session, or token.

### Recommendation
In `WebhooksController#verify_signature`, ensure the org used to verify the signature is the same org that the handler will actually operate on. Concretely: derive `repository_owner` consistently from `repository.full_name` (not from `repository.owner.login`) or validate that both fields' owner values match before proceeding; additionally, consider rejecting webhook events for organizations that have no `webhook_secret` configured (fail closed rather than fail open) instead of returning `true` in `GitHubApp#verify_webhook_signature` when `webhook_secret` is blank.

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

      Rails.logger.info([

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
