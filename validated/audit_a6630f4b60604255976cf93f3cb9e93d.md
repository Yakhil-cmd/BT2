### Title
Reachable assertion (`throw Error`) in AA trigger/formula handling crashes the whole node - ([File: aa_composer.js])

### Summary
CVE-2023-37022 is a reachable assertion in Open5GS MME's `UE Context Release Request` handler: a peer-supplied packet with an invalid field reaches an `assert()`/uncaught fault and kills the process (DoS). ocore has an analogous class of bugs: several code paths that process attacker/AA-author supplied data use `throw Error(...)` instead of returning a soft validation error, and any such throw that escapes the call stack is caught by the global handler that **deliberately re-throws to kill the process**.

### Finding Description
The global exception handler in `network.js` is explicit about this behavior: [1](#0-0) 
Any synchronous `throw Error(...)` reached while processing a unit, AA trigger, or formula evaluation that is not wrapped by a callback-based error path will bubble up as an uncaught exception and crash the daemon for every node that processes it — not just the sender.

The most directly reachable instance is `getTrigger()` in `aa_composer.js`, which builds the AA trigger from a posted unit's messages and throws synchronously if the computed outputs map ends up empty: [2](#0-1) 

This function is invoked from `handleJoint()`'s `ifOk` callback path when `conf.bDryRunNewTriggers` is enabled, using addresses extracted directly from the **just-validated but not otherwise pre-filtered** payment outputs of an incoming unit: [3](#0-2) 

`validateAATrigger()` in `validation.js`, which runs during normal unit validation, only checks that *some* output address is an AA address and that there is at most one primary trigger — it does not guarantee that `getTrigger()`'s internal invariant (non-empty `trigger.outputs`) can never be violated for every code path that later calls `getTrigger()` with a different receiving address (e.g. secondary/derived processing, or future dry-run integrations), since the guard logic lives in two independently-maintained places (`validateAATrigger` in `validation.js` vs. `getTrigger`/`handleTrigger` in `aa_composer.js`): [4](#0-3) 

A second, more directly externally reachable throw sits in the `light/dry_run_aa` network command, which takes a raw JSON `trigger` object and `address` from **any connected peer (including unauthenticated light clients)** and pipes it into `aa_composer.dryRunPrimaryAATrigger` → `handleTrigger`: [5](#0-4) 
`validateAATriggerObject` performs field-shape checks but is not exhaustive with respect to every `throw Error(...)` reachable deeper in `handleTrigger`/formula evaluation (e.g. `throw Error("bad AA definition " + arrDefinition)`, `throw Error("unexpected params")`, `throw Error("base AA not found: " + template.base_aa)`): [6](#0-5) [7](#0-6) 

This mirrors the CVE-2023-37022 bug class exactly: a boundary/validation function (analogous to Open5GS's S1AP field checker) fails to fully constrain a downstream function that enforces its invariant via a hard `assert`/`throw` rather than a recoverable error return, and that downstream function is reachable from attacker-controlled network input.

### Impact Explanation
Because the process-level `uncaughtException` handler explicitly re-throws (`throw err; // crash the process to avoid ending up in an inconsistent state`), any of these reachable `throw Error(...)` calls, if triggered through a code path not wrapped in a try/catch that converts it into a graceful validation error, crashes the entire hub/full node process. Given the node's role in relaying, validating, and stabilizing units for the whole network, a repeatable process crash on many/most full nodes constitutes a "network unable to confirm new units" scenario per the validation criteria.

### Likelihood Explanation
Reaching `getTrigger()`'s throw via `handleJoint` requires `conf.bDryRunNewTriggers` to be enabled and requires constructing a unit whose payment output to an AA address becomes empty by the time `getTrigger` is called for that address — this is a narrower, configuration-dependent path. Reaching the `light/dry_run_aa` command is trivially available to any connected peer without needing a valid unit to be posted or confirmed, since it is a stateless RPC-style query; however I could not fully trace whether every deeper `throw` in `handleTrigger`/formula evaluation is actually reachable with a value that passes `validateAATriggerObject`'s current checks (this needs runtime verification, e.g., by crafting `trigger.data` structures that survive `string_utils.getJsonSourceString` size checks but trip an internal invariant assumption).

### Recommendation
- Audit all `throw Error(...)` statements reachable from `handleJoint`, `handleTrigger`, `evaluateAA`/`evaluate()` in `formula/evaluation.js`, and `validateAATriggerObject`/`dryRunPrimaryAATrigger` in `aa_composer.js`, and convert those reachable with attacker/AA-author-controlled input into recoverable errors (`setFatalError`, `bounce(...)`, or callback errors) instead of hard throws.
- Add defense-in-depth checks in `getTrigger()` so that an empty `trigger.outputs` results in a caller-visible error return rather than a thrown exception when invoked from network-triggered code paths (e.g. the `light/dry_run_aa` dry-run integration in `handleJoint`).
- Consider making the `light/dry_run_aa` handler wrap `dryRunPrimaryAATrigger` in a try/catch that converts any thrown error into `sendErrorResponse` rather than letting it propagate to the global `uncaughtException` handler.
- Add fuzz/property tests that feed adversarial `trigger` objects and AA definitions through `light/dry_run_aa` and `handleTrigger` to find any remaining reachable `throw` statements.

function validateAATriggerObject(trigger, handle) {
	if (!ValidationUtils.isNonemptyObject(trigger))
		return handle("no trigger");
	if (!ValidationUtils.isNonemptyObject(trigger.outputs))
		return handle("no trigger outputs");
	if (!ValidationUtils.isValidAddress(trigger.address))
		return handle("bad trigger address");
	if ("max_aa_responses" in trigger && (!ValidationUtils.isNonnegativeInteger(trigger.max_aa_responses) || trigger.max_aa_responses > constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER))
		return handle("bad trigger max_aa_responses");
	if (ValidationUtils.hasFieldsExcept(trigger, ["address", "data", "outputs", "max_aa_responses"])) // initial_address and initial_unit cannot be separately set in a primary trigger
		return handle("unexpected trigger fields");
	if (string_utils.isTooBigObj(trigger, { lengthLimit: 10e3 }))
		return handle("trigger data is too big");
	try {
		if (trigger.data)
			string_utils.getJsonSourceString(trigger.data);
	}
	catch (e) {
		return handle("invalid trigger data: " + e);
	}
	var arrAssets = Object.keys(trigger.outputs).filter(function(asset) {return asset !== 'base'});
	if (arrAssets.length >= constants.MAX_MESSAGES_PER_UNIT)
		return handle("too many assets");
	if (!ValidationUtils.isPositiveInteger(trigger.outputs.base))
		return handle("no base payment");
	if (!arrAssets.every(function(asset){return ValidationUtils.isPositiveInteger(trigger.outputs[asset])}))
		return handle("invalid output amount")

	function checkAddressIsNotAA() {
		db.query("SELECT 1 FROM aa_addresses WHERE address=?", [trigger.address], rows => {
			if (rows.length)
				return handle("trigger address must not be an AA");
			else
				return handle();
		});
	}

	if (arrAssets.length === 0)
		return checkAddressIsNotAA();
	// we have to check that assets exist otherwise foreign key constraint would fail when inserting fake outputs
	db.query("SELECT 1 FROM assets WHERE unit IN (?)", [arrAssets], function(rows) {
		if (rows.length !== arrAssets.length)
			return handle("unknown asset");
		else
			checkAddressIsNotAA();
	});
}

function getTrigger(objUnit, receiving_address) {
	var trigger = { address: objUnit.authors[0].address, unit: objUnit.unit, outputs: {} };
	if ("max_aa_responses" in objUnit)
		trigger.max_aa_responses = objUnit.max_aa_responses;
	objUnit.messages.forEach(function (message) {
		if (message.app === 'data' && !trigger.data) // use the first data message, ignore the subsequent ones
			trigger.data = message.payload;
		else if (message.app === 'payment' && message.payload) {
			var payload = message.payload;
			var asset = payload.asset || 'base';
			payload.outputs.forEach(function (output) {
				if (output.address === receiving_address) {
					if (!trigger.outputs[asset])
						trigger.outputs[asset] = 0;
					trigger.outputs[asset] += output.amount; // in case there are several outputs
				}
			});
		}
	});
	if (Object.keys(trigger.outputs).length === 0)
		throw Error("no outputs to " + receiving_address);
	return trigger;
}

async function validateAATrigger(conn, objUnit, objValidationState, callback) {
	if (objValidationState.last_ball_mci < constants.v4UpgradeMci || objValidationState.bAA || !objValidationState.last_ball_mci) {
		if ("max_aa_responses" in objUnit)
			return callback(`max_aa_responses should not be there`);
		if (objValidationState.bAA || !objValidationState.last_ball_mci)
			return callback();
	}
	if ("content_hash" in objUnit) { // messages already stripped off
		objValidationState.count_primary_aa_triggers = 0;
		return callback();
	}
	if (objUnit.max_aa_responses === 0 && (objValidationState.last_ball_mci >= constants.pemCurvesFixMci || !objValidationState.hasBall && storage.getMinRetrievableMci() >= constants.pemCurvesFixMci))
		return callback(`max_aa_responses=0 is not allowed`);
	let outputCounts = {};
	for (let m of objUnit.messages) {
		if (m.app === 'payment' && m.payload) {
			const asset = m.payload.asset || 'base';
			for (let o of m.payload.outputs) {
				if (!outputCounts[o.address])
					outputCounts[o.address] = {};
				if (!outputCounts[o.address][asset])
					outputCounts[o.address][asset] = 0;
				outputCounts[o.address][asset]++;
			}
		}
	}
	const arrOutputAddresses = Object.keys(outputCounts);
	if (arrOutputAddresses.length === 0)
		return callback("no output addresses found in payment messages");

	// Look for AA triggers
	// There might be actually more triggers due to AAs defined between last_ball_mci and our unit, so our validation of tps fee might require a smaller fee than the fee actually charged when the trigger executes
	const rows = await conn.query("SELECT address FROM aa_addresses WHERE address IN (?) AND mci<=?", [arrOutputAddresses, objValidationState.last_ball_mci]);
	if (rows.length === 0) {
		if ("max_aa_responses" in objUnit)
			return callback(`no outputs to AAs, max_aa_responses should not be there`);
		return callback();
	}
	objValidationState.count_primary_aa_triggers = rows.length;
	if (objValidationState.count_primary_aa_triggers > 1) {
		if (objValidationState.last_ball_mci >= constants.pemCurvesFixMci)
			return callback(`more than 1 primary AA trigger (${objValidationState.count_primary_aa_triggers})`);
		if (storage.getMinRetrievableMci() > constants.pemCurvesFixMci)
			return callback(createTransientError(`more than 1 primary AA trigger (${objValidationState.count_primary_aa_triggers})`));
	}
	if ((objValidationState.last_ball_mci >= constants.pemCurvesFixMci || !objValidationState.hasBall && storage.getMinRetrievableMci() >= constants.pemCurvesFixMci) && objValidationState.count_primary_aa_triggers === 1) {
		const address = rows[0].address;
		for (let asset in outputCounts[address]) {
			if (outputCounts[address][asset] > 1)
				return callback(`more than 1 output to the same AA ${address} for asset ${asset}`);
		}
	}
	callback();
}
