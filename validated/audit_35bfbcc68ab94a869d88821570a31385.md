### Title
Unbounded response body read in `GetCurrentLogin` allows memory-exhaustion DoS from a malicious `--hostname` endpoint - (File: pkg/cmd/auth/shared/login_flow.go)

### Summary
`GetCurrentLogin` performs an authenticated GraphQL request and decodes the HTTP response body directly with `json.NewDecoder(res.Body).Decode(&result)` without ever bounding the number of bytes read. [1](#0-0)  A server controlling the response for the configured `hostname` (e.g. a GitHub Enterprise-style host the victim runs `gh auth login --hostname <host>` against) can return an arbitrarily large JSON body (or a single huge string field such as `login`) to force the client to buffer unbounded data in memory.

### Finding Description
`GetCurrentLogin(httpClient, hostname, authToken)` builds a GraphQL POST request to `ghinstance.GraphQLEndpoint(hostname)` and reads the response with a plain `json.Decoder` over `res.Body`, with no `io.LimitReader`, `http.MaxBytesReader`, or explicit size cap anywhere in the read path. [2](#0-1)  The `hostname` value is attacker-influenceable in the "host victim points gh at" sense described by the rules — when a user authenticates against a non-github.com host (common for GHES/custom endpoints), that host's responses are fully attacker-controlled. Because `json.Decoder.Decode` must buffer complete JSON string tokens to parse them, a multi-gigabyte string value in the JSON response (e.g. an oversized `login` field or padding elsewhere in the payload) will be read entirely into memory before decoding fails or succeeds, with no safeguard to abort early. A grep across the repository confirms there is no `LimitReader`/`MaxBytesReader` usage anywhere, so this lack of bounding is systemic rather than unique to this function. [3](#0-2) 

### Impact Explanation
If exploited, a malicious/compromised host that the victim points `gh auth login` at can cause unbounded memory consumption on the victim's machine, potentially crashing the `gh` process or degrading the host (resource-exhaustion DoS). This matches a "High - unbounded resource consumption" class, but is scoped strictly to the case where the victim explicitly configures `gh` to authenticate against an attacker-controlled/malicious hostname — it does not affect default `github.com` usage.

### Likelihood Explanation
Exploitability requires the victim to run `gh auth login --hostname <attacker-controlled-host>` (or otherwise have `gh` configured to reach a non-github.com endpoint controlled by the attacker) and for that attacker endpoint to have valid enough TLS/response handling to reach the JSON decode step. This is a real but narrower precondition than a passive git/GitHub-content-only attack path; it depends on victim-initiated configuration of a custom host, which is a scenario `gh` implicitly trusts for enterprise use. Given this precondition, the exploit is fully repeatable and deterministic once triggered.

### Recommendation
Wrap `res.Body` in `io.LimitReader(res.Body, maxBytes)` (or use `http.MaxBytesReader`) before constructing the `json.Decoder` in `GetCurrentLogin`, and apply the same fix consistently across other unbounded body-read sites in the codebase (e.g. `api.HandleHTTPError` and other response-decoding call sites), returning a clear bounded error when the limit is exceeded.

func GetCurrentLogin(httpClient httpClient, hostname, authToken string) (string, error) {
	query := `query UserCurrent{viewer{login}}`
	reqBody, err := json.Marshal(map[string]interface{}{"query": query})
	if err != nil {
		return "", err
	}
	result := struct {
		Data struct{ Viewer struct{ Login string } }
	}{}
	apiEndpoint, err := safeurl.JoinPathWithHostPrefix(ghinstance.GraphQLEndpoint(hostname))
	if err != nil {
		return "", err
	}
	req, err := http.NewRequest("POST", apiEndpoint.String(), bytes.NewBuffer(reqBody))
	if err != nil {
		return "", err
	}
	req.Header.Set("Authorization", "token "+authToken)
	res, err := httpClient.Do(req)
	if err != nil {
		return "", err
	}
	defer res.Body.Close()
	if res.StatusCode > 299 {
		return "", api.HandleHTTPError(res)
	}
	decoder := json.NewDecoder(res.Body)
	err = decoder.Decode(&result)
	if err != nil {
		return "", err
	}
	return result.Data.Viewer.Login, nil
