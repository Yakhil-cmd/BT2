## Title
Uncaught `TypeError`/`Error` in oscript `map`/`filter`/`reduce`/`foreach` on `null` array/object elements crashes the validating node — (File: `formula/evaluation.js`)

### Summary
The CVE-2021-45267 bug class is an unhandled invalid-memory dereference in gpac's `svg_node_start` when it encounters a malformed node it doesn't expect, causing an unchecked crash. The analogous bug class in `ocore` is code that assumes a value coming from attacker-controlled data (AA trigger `data`, state vars, or params) always matches one of a few expected JS types, and falls through to an unconditional `throw Error(...)` when it doesn't — instead of returning a formula-evaluation error through the `cb`/`setFatalError` path. Because `network.js` installs a global `process.on('uncaughtException', ...)` handler that explicitly re-throws to crash the whole node process, any such uncaught exception reachable from validating an untrusted unit terminates the node.

### Finding Description
`toOscriptType` in `formula/evaluation.js` converts a raw JS value taken from `trigger.data`/local vars/state vars into the oscript-internal representation: [1](#0-0) 

It handles `string`, `boolean`, `wrappedObject`, `number`, `Decimal`, and non-null `object`, but it has no branch for `null`. Any other value falls through to `throw Error("unknown type in toOscriptType:" + x)` — this is a hard JS exception, not the formula error/callback convention (`setFatalError`) used everywhere else in this file.

`toOscriptType` is called on data coming directly out of a trigger-supplied array/object during `map`/`filter`/`reduce`/`foreach`: [2](#0-1) 

`res` here is `evaluate(expr, ...)`'s result — a `wrappedObject` that can wrap any JSON-decoded structure taken from the AA trigger's `data` field (`trigger.data...`), which is fully attacker-controlled JSON posted by an ordinary unit author invoking an AA. If any array element or referenced object key equals JSON `null`, `toOscriptType(null)` throws `Error("unknown type in toOscriptType:null")`, and there is no `try/catch` around the `evaluate`/`async.eachOfSeries` call chain in this function to convert this into a formula validation failure.

The AA trigger data is validated only for basic JSON structure/size/depth (see `aa_validation.js`), not for absence of `null` inside nested arrays/objects, so a unit author can freely include `null` values in `trigger.data`: [3](#0-2) 

Because oscript evaluation runs during normal unit/AA-trigger validation (both when the trigger unit is validated and when the AA response formula executes it via `map`/`filter`/`reduce`/`foreach`), the exception propagates up through the async callback chain outside of any `try/catch`, becoming an uncaught exception in the node process. `network.js` deliberately treats such uncaught exceptions as fatal: [4](#0-3) 

This is the direct structural analog of the GPAC bug: a value that should have been explicitly checked/rejected during parsing/validation instead reaches a code path that unconditionally dereferences/consumes it assuming a valid shape, causing a crash instead of a graceful validation error.

### Impact Explanation
Any node (full node or light-vendor) that receives and validates a unit invoking an AA whose oscript formula performs `map`/`filter`/`reduce`/`foreach` over an object/array taken from `trigger.data` (or any state derived from it) containing a `null` element/value will crash with an uncaught exception. Given `process.on('uncaughtException')` in `network.js` intentionally re-throws to terminate the process, this converts a single crafted unit into a full node crash. Because every node that receives, relays, or validates the triggering unit is affected identically, this can be broadcast network-wide, potentially causing widespread node crashes and inability of affected nodes to process/confirm subsequent units until restarted — satisfying "a network unable to confirm new units."

### Likelihood Explanation
- The attacker only needs to author and post an ordinary unit that triggers an AA containing (or is combined with) an oscript formula using `map`, `filter`, `reduce`, or `foreach` over trigger-derived data, and set a `null` value inside the array/object being iterated in `trigger.data`.
- No special privileges are required — any unprivileged AA trigger sender can supply `trigger.data` with arbitrary nested JSON including `null`.
- The relevant AA formula code (using `map`/`filter`/`reduce`/`foreach` on trigger data) is a normal and expected oscript pattern that any third-party AA author can legitimately deploy, so the attack surface (an AA of this shape existing on-chain) is realistic and not contrived.
- The only uncertainty is whether some earlier validation layer (e.g., a length/type check performed before the array reaches `toOscriptType`) filters out `null` before it reaches this branch; based on the code reviewed, `aa_validation.js`'s payload/data-feed validation and `isTooDeeplyNestedOrHasTooManyNodes` only check depth/size/string content, not for the absence of `null`, so this path appears reachable. Full confirmation would require running the exact formula through the test AA harness, which was not available in this read-only review.

### Recommendation
- Add an explicit `null` branch to `toOscriptType` (and any other similar "fallthrough `throw`" conversion helpers used on trigger/state-derived data) that returns a defined oscript value (e.g., `false`) instead of throwing.
- More generally, audit `formula/evaluation.js` for other `throw Error(...)` statements reachable from attacker-controlled AA trigger data or local/state variables (e.g., `toJsType`, and any "unknown type"/"unknown op" throws inside `evaluate`) and convert them to `setFatalError(...)` calls so a malformed value produces a formula-evaluation failure (rejecting the unit) rather than an uncaught process-crashing exception.
- Add regression tests exercising `map`/`filter`/`reduce`/`foreach` over trigger data containing `null` values at various nesting levels.

### Proof of Concept
Conceptual PoC (would need to be run against the AA test harness / `evalFormulaWithVars` used in `test/formula.test.js`):
```
trigger.data = { arr: [1, null, 3] }
formula:
  $r = map(trigger.data.arr, 3, $x => $x);
  $r
```
Evaluating this formula (e.g., via `evalFormulaWithVars`, or by posting a unit that triggers a deployed AA with this code) causes `map` to iterate `arr`, call `toOscriptType(null)` on the second element, and throw `Error("unknown type in toOscriptType:null")`, which is not caught anywhere in the evaluation call chain and — per `network.js`'s `process.on('uncaughtException')` handler — crashes the entire node process when this formula executes during unit/AA validation.

```javascript
function toOscriptType(x) {
	if (typeof x === 'string' || typeof x === 'boolean' || x instanceof wrappedObject)
		return x;
	if (typeof x === 'number')
		return createDecimal(x);
	if (Decimal.isDecimal(x))
		return toDoubleRange(x);
	if (typeof x === 'object' && x !== null)
		return new wrappedObject(x);
	throw Error("unknown type in toOscriptType:" + x);
}
```

```javascript
function isTooDeeplyNestedOrHasTooManyNodes(obj, depthLimit = 100, nodesLimit = 10000) {
	let nodeCount = 0;

	function check(variable, depth){
		if (depth > depthLimit || nodeCount > nodesLimit)
			return true;
		if (variable === null || typeof variable !== "object")
			return false;
		if (Array.isArray(variable)) {
			nodeCount += variable.length;
			for (let v of variable)
				if (check(v, depth + 1))
					return true;
		}
		else {
			nodeCount += Object.keys(variable).length;
			for (let key in variable)
				if (check(variable[key], depth + 1))
					return true;
		}
		return false;
	}

	return check(obj, 1);
}
```
