### Title
`BridgeOperator.deregisterOperator()` Does Not Revoke Outstanding Votes, Allowing Deregistered Operators' Votes to Execute Bridge Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`BridgeOperator.deregisterOperator()` removes an operator from the `operators` mapping and `operatorList`, but does **not** clear that operator's accumulated vote counts from the `votes` storage mapping. Because `_voteCommon()` checks only `voteCounts[voteKey] >= operatorThresholds[voteType]` — with no check that all contributing voters are still active operators — a deregistered operator's prior vote permanently remains counted. A single subsequent vote from any remaining active operator can then push the tally to threshold, executing a bridge value transfer that the owner intended to prevent by deregistering the operator.

---

### Finding Description

`deregisterOperator()` performs two actions:

```solidity
delete operators[_operator];          // prevents future votes
operatorList[i] = operatorList[...];  // shrinks the list
operatorList.length--;
``` [1](#0-0) 

It does **not** touch `votes[VoteType.ValueTransfer][nonce].voteCounts[voteKey]` for any pending nonce. The threshold check in `_voteCommon()` reads the raw counter:

```solidity
if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
    return true;
}
``` [2](#0-1) 

The contract itself documents the consequence in a comment:

> *"Note that outstanding votes by the deregistered operator are not revoked. This enables a subtle counterintuitive scenario… In this case the request was executed with A's vote after A is deregistered."* [3](#0-2) 

The downstream transfer functions (`handleKLAYTransfer`, `handleERC20Transfer`, `handleERC721Transfer`) all call `_voteValueTransfer()` which calls `_voteCommon()`, and execute the asset transfer unconditionally once the threshold is met:

```solidity
if (!_voteValueTransfer(_requestNonce)) { return; }
...
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
``` [4](#0-3) 

```solidity
if (!_voteValueTransfer(_requestedNonce)) { return; }
...
IERC20(_tokenAddress).safeTransfer(_to, _value);
``` [5](#0-4) 

---

### Impact Explanation

The broken invariant is: *after an operator is deregistered, their authority over pending bridge requests must be fully revoked.* Because `votes` state is never cleaned up, a deregistered operator's vote permanently contributes to the threshold counter for every nonce they voted on. Any remaining active operator can then complete the quorum and trigger an irreversible KLAY/ERC20/ERC721 transfer out of the bridge contract — directly violating the owner's intent when they called `deregisterOperator()`.

The corrupted value is `votes[VoteType.ValueTransfer][N].voteCounts[voteKey]`, which retains a count contribution from an address that is no longer in `operators`.

---

### Likelihood Explanation

The scenario requires: (1) threshold ≥ 2, (2) a deregistered operator having already voted on a pending nonce, and (3) a remaining active operator voting on the same nonce after the deregistration. This is a realistic operational sequence — the owner deregisters a compromised or departing operator precisely to stop a pending transfer, but the transfer executes anyway. The code comment acknowledges this is a known reachable path.

---

### Recommendation

In `deregisterOperator()`, iterate over all open (non-closed) nonces and decrement or zero out `votes[vt][nonce].voteCounts[vote.voted[_operator]]` for the deregistered operator across both `VoteType.ValueTransfer` and `VoteType.Configuration`. Alternatively, store a per-nonce "active-operator snapshot" and validate voters against it at execution time rather than at vote time.

---

### Proof of Concept

```
Setup: operators = [A, B, C], threshold = 2

1. Operator A calls handleKLAYTransfer(nonce=5, to=attacker, value=1000 KLAY)
   → _voteCommon: voteCounts[voteKey] = 1  (threshold not met, returns false)

2. Owner calls deregisterOperator(A)
   → operators[A] = false, operatorList shrinks
   → votes[0][5].voteCounts[voteKey] still = 1  ← stale

3. Operator B calls handleKLAYTransfer(nonce=5, to=attacker, value=1000 KLAY)
   → _voteCommon: voteCounts[voteKey]++ = 2 >= threshold(2) → returns true
   → closedValueTransferVotes[5] = true
   → 1000 KLAY transferred to attacker

Owner's deregistration of A had no effect on the pending vote.
``` [6](#0-5) [1](#0-0)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }
```

    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
