### Title
RAY-scaled debt valuation overflows during accrual and permanently freezes a market - (File: common/src/rates/scaling.rs)

### Summary

Medium. An overlarge borrowed position can make `scaled_to_original` overflow `i128` when the accrued borrow index is applied. Because every market operation loads and accrues the market before mutating it, this single arithmetic failure makes repayment, withdrawal, liquidation, recapitalization, and even `update_indexes` revert permanently once the boundary is crossed. The in-repo regression test reproduces the condition at 98% utilization on an accepted 175%-APR stress curve and confirms that both withdrawal and repayment fail with `MathOverflow`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description

Positions and market totals are represented as RAY-scaled shares, while `scaled_to_original` computes `scaled * index / RAY` using checked fixed-point multiplication. The borrow index is allowed to grow as high as `MAX_BORROW_INDEX_RAY`, but there is no separate cap ensuring that `borrowed * borrow_index` remains representable in `i128`. [1](#0-0) [4](#0-3) 

`update_indexes` calls the pool's `accrue` implementation, which loads every listed market and invokes `interest::global_sync`. The same `global_sync` call is made by `synced_market`, which supply, borrow, repay, withdraw, and related pool legs all use before accounting. Consequently, once the debt-value multiplication overflows, every state-changing path for that market reverts before it can reduce the debt or otherwise recover. [5](#0-4) [2](#0-1) [6](#0-5) 

The repository's test creates a one-billion-token, 18-decimal market, borrows 98% of it under the XLM stress curve, advances time, and observes `MathOverflow` from `update_indexes` before `MAX_BORROW_INDEX_RAY` is reached. Subsequent calls to withdraw one unit and repay one token also fail with `MathOverflow`, proving that the state is not merely a rejected input but a persistent market halt. [7](#0-6) 

### Impact Explanation

All funds associated with the affected market become permanently inaccessible: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot execute repayment or collateral seizure through the normal paths, revenue cannot be claimed, and recapitalization cannot restore backing. Since the failed accrual does not commit a bounded index, later calls recompute the same or an even larger product and fail again. [8](#0-7) [9](#0-8) [10](#0-9) 

### Likelihood Explanation

An unprivileged caller can invoke `update_indexes(caller, assets)`, and an account owner can create the required exposure through ordinary `supply` and `borrow` calls. The attack requires an admitted market with sufficiently high decimal-based caps and enough liquidity to create a debt whose RAY value approaches `i128::MAX / borrow_index`, followed by sustained high utilization until interest pushes the product over the boundary. [11](#0-10) [12](#0-11) 

This is not an immediate one-transaction failure: it requires a very large book and accrued interest. However, the test demonstrates that the configured curve and caps admit the state before the borrow-index ceiling protects it, and the resulting failure is unrecoverable through ordinary user or keeper entrypoints. [13](#0-12) [14](#0-13) 

### Recommendation

Add an explicit representable-value bound before every scaled-total multiplication used by accrual. In particular, cap accrual when `borrowed > i128::MAX / borrow_index` or perform the debt and supply valuations with widened arithmetic and clamp only after the widened result is known. Apply the same protection to revenue-share growth and supply-value calculations so accrual cannot introduce a second overflow cliff. Enforce market caps tightly enough that listed `decimals`, cap, and maximum index combinations cannot cross the representable-value boundary.

### Proof of Concept

The repository already contains a deterministic reproduction. Conceptually, through public controller calls:

```text
supply(
    caller = attacker,
    account_id = 0,
    spoke_id = admitted_spoke,
    assets = [(hub_id, BIG18, 1_000_000_000 * 10^18)]
)

supply(
    caller = attacker,
    account_id = second_account,
    spoke_id = admitted_spoke,
    assets = [(hub_id, collateral_asset, sufficient_collateral)]
)

borrow(
    caller = attacker,
    account_id = second_account,
    assets = [(hub_id, BIG18, 98% of supplied BIG18)],
    to = attacker
)

# After enough elapsed ledger time:
update_indexes(
    caller = attacker,
    assets = [(hub_id, BIG18)]
)
```

The actual regression test uses `principal = BILLION * 10^18`, `debt = principal * 98 / 100`, repeatedly advances one year, and stops when `try_update_indexes_for(&["BIG18"])` returns `MathOverflow`; it then verifies that `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` fail with the same error. /// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
```
