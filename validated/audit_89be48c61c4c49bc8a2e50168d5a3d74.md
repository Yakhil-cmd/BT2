### Title
Unauthorized registration of shared addresses via unauthenticated `new_shared_address` device message - (File: wallet_defined_by_addresses.js)

### Summary
The Mjolnir CVE was caused by a message-processing entry point that acted on commands without verifying that the sender was authorized to issue them. The analogous flaw in `ocore` is in the device-message handler for the `new_shared_address` subject: `wallet.js` dispatches this subject straight to `wallet_defined_by_addresses.handleNewSharedAddress()` for any correspondent device (any paired device, i.e., the p2p equivalent of "any room"), and that function never verifies that the sending device is actually one of the parties named in the shared-address definition it is registering.

### Finding Description
In `wallet.js`, the `new_shared_address` message from any known/paired device is handled unconditionally: [1](#0-0) 

It is routed to `handleNewSharedAddress`, defined in `wallet_defined_by_addresses.js`: [2](#0-1) 

This function checks:
- that `body.definition` hashes to `body.address` (internal consistency),
- that signer addresses referenced in `body.signers` match the definition,
- that the local wallet is one of the members (`determineIfIncludesMeAndRewriteDeviceAddress`),

but it never checks that `from_address` (the actual sender of the device message, passed by `wallet.js`'s `handleMessageFromHub` as `from_address = objectHash.getDeviceAddress(device_pubkey)`) is one of the `device_address` values named in `body.signers`, nor that the sender initiated this via the normal handshake (`createNewSharedAddressByTemplate` → `approvePendingSharedAddress` → `sendNewSharedAddress`). In the legitimate flow, a shared address is only created after all members explicitly approve a definition template via `approvePendingSharedAddress` (unused/legacy path) or `createNewSharedAddress` (used path), which does check `includesMyDeviceAddress`: [3](#0-2) [4](#0-3) 

However, `handleNewSharedAddress` is exposed directly as a network-message handler (case `"new_shared_address"` in `wallet.js`) and is reachable by ANY paired correspondent device without going through that consent flow, and without validating that the message sender is one of the parties in the definition. This mirrors the Mjolnir bug class: a privileged registration operation is accepted from any authenticated-but-unauthorized source, because the code checks "is this message well-formed and internally consistent" but not "is the sender entitled to submit this command."

Once accepted, `addNewSharedAddress` persists the shared address, adds it to `shared_address_signing_paths`, and — critically — forwards it onward to cosigners of the victim's own addresses that are referenced in the definition: [5](#0-4) [6](#0-5) 

An attacker (any correspondent device already paired with the victim, e.g. via normal pairing, not requiring any hub compromise) can construct a definition such as `["or", [["address", "<attacker_fully_controlled_address>"], ["address", "<victim_address>"]]]`, sign it as `new_shared_address`, and have the victim's wallet silently register it as a shared address it is a "member" of, and propagate it to the victim's other cosigner devices — all without the victim's consent or the normal approval dialog.

### Impact Explanation
The registered shared address is functionally spendable unilaterally by the attacker (the `"or"` branch containing the attacker's own address is fully satisfied by the attacker alone), while it is silently added to the victim's wallet's list of shared/controlled addresses and propagated to the victim's other devices/cosigners as though it were a jointly-approved multisig address. This can be used to trick the victim (or automated tooling built on `readAllControlAddresses`/wallet UI) into funding what appears to be a jointly-controlled address, which the attacker can then unilaterally drain — i.e., unauthorized spending of funds sent to the address. It also pollutes wallet state and cosigner records without any confirmation step, undermining node/wallet agreement about which addresses are validly "shared."

### Likelihood Explanation
The attacker needs only to be a paired correspondent device of the target wallet (a normal, low-privilege relationship established via pairing codes, not requiring any special access or hub compromise) and to send a single `new_shared_address` justsaying message — reachable exactly like the report's "any room" analog (any authenticated-but-unprivileged peer can issue the command). No race conditions or additional prerequisites are required beyond pairing, which is routinely done between wallet users and services.

### Recommendation
In `handleNewSharedAddress` (and the `new_shared_address` case in `wallet.js`), require that `from_address` be present among the `device_address` values in `body.signers`/the resolved definition, or otherwise verify that the address registration was preceded by an authorized approval step (i.e., only accept `new_shared_address` from a device that legitimately participated in creating/approving that definition, analogous to how `createNewSharedAddress` calls `includesMyDeviceAddress`). Reject the message if the sender is not a party to the definition it is asserting.

### Proof of Concept
1. Device B pairs with victim's wallet device A (normal pairing flow).
2. B constructs `arrDefinition = ["or", [["address", B_address], ["address", A_existing_address]]]` where `B_address` is fully controlled by B and `A_existing_address` is any address already known/owned by A.
3. B computes `address = objectHash.getChash160(arrDefinition)` and sends device message `new_shared_address` with `{address, definition: arrDefinition, signers: {"r.0": {device_address: B, address: B_address}, "r.1": {device_address: A, address: A_existing_address}}}`.
4. A's wallet, on receipt in `wallet.js` (`case "new_shared_address"`), calls `walletDefinedByAddresses.handleNewSharedAddress(body, callbacks)` with no check that B is authorized to register this definition; `determineIfIncludesMeAndRewriteDeviceAddress` succeeds because `A_existing_address` is genuinely A's, so the whole message passes.
5. `addNewSharedAddress` persists the shared address and forwards it to A's other cosigner devices via `forwardNewSharedAddressToCosignersOfMyMemberAddresses`, presenting it as a legitimate shared address.
6. Anyone funding this "shared" address (believing both parties are needed) allows B to spend unilaterally via the `"or"` branch, with no signature from A ever required.

*(Note: I could not fully verify `Definition.validateDefinition`'s exact constraints on `"or"`/mixed-address definitions within the available index — this should be confirmed in a full checkout, e.g. via `definition.js`, to make sure `"or"` with a pure attacker-controlled branch is indeed accepted as valid; I am reasonably confident based on the `"or"`/`"and"`/`"r of set"` operators visible in `extractAddressPathsFromDefinition` and `getMemberDeviceAddressesBySigningPaths`, but the full semantic validation logic in `definition.js` was not retrievable in this session.)*

		var signerInfo = assocSignersByPath[signing_path];

			assocMyMemberAddresses[signerInfo.address] = true;

	var arrMyMemberAddresses = Object.keys(assocMyMemberAddresses);

		"SELECT DISTINCT device_address FROM my_addresses JOIN wallet_signing_paths USING(wallet) WHERE address IN(?) AND device_address!=?", 
		[arrMyMemberAddresses, device.getMyDeviceAddress()],
		function(rows){
			rows.forEach(function(row){
				sendNewSharedAddress(row.device_address, address, arrDefinition, assocSignersByPath, true);
			});
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

function createNewSharedAddress(arrDefinition, assocSignersByPath, callbacks){
	if (!includesMyDeviceAddress(assocSignersByPath))
		return callbacks.ifError("my device address not mentioned");
	var address = objectHash.getChash160(arrDefinition);
	handleNewSharedAddress({address: address, definition: arrDefinition, signers: assocSignersByPath}, {
		ifError: callbacks.ifError,
		ifOk: function(){
			// share the new address with all cosigners
			var arrDeviceAddresses = [];
			for (var signing_path in assocSignersByPath){
				var signerInfo = assocSignersByPath[signing_path];
				if (signerInfo.device_address !== device.getMyDeviceAddress() && arrDeviceAddresses.indexOf(signerInfo.device_address) === -1)
					arrDeviceAddresses.push(signerInfo.device_address);
			}
			arrDeviceAddresses.forEach(function(device_address){
				sendNewSharedAddress(device_address, address, arrDefinition, assocSignersByPath);
			});
			callbacks.ifOk(address);
		}
	});
}
