### Title
Attacker-controlled route XDR injects arbitrary contract calls into the caller's authorization tree, enabling wallet theft — (`File: contracts/controller/src/strategies/swap.rs`)

### Summary
The bug class of the external report is injection: attacker-supplied data is interpreted as executable instructions. The analog here is the controller's strategy swap path: every strategy verb (`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`) accepts a caller-supplied `StrategySwap` XDR payload and hands it verbatim to the swap router, which invokes whatever pool/token addresses the payload names — with no venue or contract allowlist. Third-party code thus executes inside a call tree rooted at the victim's own `require_auth`, and any `transfer` it performs from the victim is recorded as a child of the victim's authorization entry and succeeds if the victim signs the simulated tree.

### Finding Description
`process_swap_collateral` takes `swap: &StrategySwap` directly from the caller's arguments and forwards it through `withdraw_and_swap_from_supply` into `swap_tokens`, which calls `router.execute_strategy(&controller, &amount_in, swap)` with the raw payload [1](#0-0) [2](#0-1) . The router dispatches to venue/pool addresses named inside the payload and keeps no allowlist, so arbitrary contract code runs on the call stack below the caller's authorization, and a token transfer it makes from the caller joins the caller's recorded auth tree [3](#0-2) . The same applies to `swap_debt`, `repay_debt_with_collateral`, and `multiply`, which all take a `StrategySwap` argument.

### Impact Explanation
Theft of user funds: the injected transfer moves arbitrary wallet tokens to the attacker, bounded by the victim's wallet balance rather than the routed amount — "the loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it" [4](#0-3) . The contract-side defenses (measured balance deltas, `RouterOverspend`, min-out, post-swap risk check in `strategy_finalize`) all pass because the stolen transfer is an unrelated call riding the same signature [5](#0-4) .

### Likelihood Explanation
Reachable by any unprivileged address that can cause a victim to sign a strategy invocation — a malicious route/quote source, a phishing-crafted `swap` argument, or an account delegate calling `swap_collateral` (delegates pass `require_owner_or_delegate`) [6](#0-5) . The only mitigation is client-side: the docs state "a client must decode the route it signs and refuse an authorization tree with any other child," which is outside the protocol's control [7](#0-6) .

### Recommendation
Constrain the attack surface the payload can reach: require venues/pools referenced by strategy swaps to come from a governance-registered allowlist, or have the controller reject `StrategySwap` payloads naming non-whitelisted pool addresses before authorizing the router transfer. At minimum, document and enforce that integrators must simulate and verify the auth tree contains exactly one input-transfer child before signing.

### Proof of Concept
The harness test `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` demonstrates the exploit: `RogueHopPool` is an attacker-deployed contract whose `swap` executes `token::Client::transfer(&victim, &to, &amount)` against the caller's wallet [8](#0-7) . A `swap_collateral` call carrying a route through that pool records the stolen transfer as a sub-invocation of the victim's `swap_collateral` auth entry; once signed, the victim's full wallet balance moves to the attacker while the collateral swap still completes normally [9](#0-8) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
