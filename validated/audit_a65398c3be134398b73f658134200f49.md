### Title
Signature verification keyed on `repository.owner.login` while stack routing uses `repository.full_name` allows unsigned webhooks for an unsecured org to write to another org's Stack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and thus which `webhook_secret`) to check against using `repository_owner`, read from `params.dig('repository','owner','login')`. The actual write target is chosen later by `Handler#stacks`, using a *different* field, `payload.dig('repository','full_name')`. Because these are two independent, attacker-controlled fields in the same JSON body, an attacker can point `owner.login` at an organization configured with no `webhook_secret` (which makes `verify_webhook_signature` return `true` unconditionally) while pointing `full_name` at a different, secret-protected organization's real repository, causing `PushHandler#process` to call `stack.sync_github` on that victim's Stack with a completely unauthenticated request.

### Finding Description
The broken binding, stated as an equality that should hold but does not:
`organization whose webhook_secret verified request bytes (derived from repository_owner)` == `organization owning the repository/stack actually mutated (derived from repository.full_name)`.

Code path:
1. `before_action :check_if_ping, :drop_unhandled_event, :verify_signature` (app/controllers/shipit/webhooks_controller.rb:6).
2. `verify_signature` calls `Shipit.github(organization: repository_owner)` where `repository_owner` reads `params.dig('repository', 'owner', 'login')` [1](#0-0) [2](#0-1) .
3. `Shipit.github` looks up config keyed by that organization name and constructs a `GitHubApp` from it [3](#0-2) .
4. `GitHubApp#verify_webhook_signature` unconditionally returns `true` when the resolved organization's `webhook_secret` is blank: `return true unless webhook_secret` [4](#0-3) .
5. On success, `#create` dispatches to `PushHandler`, whose `process` queries `stacks` scoped to the parsed `branch` [5](#0-4) .
6. `Handler#stacks` resolves the target repository via `Repository.from_github_repo_name(repository_name)`, where `repository_name` is `payload.dig('repository', 'full_name')` — a **separate** field from the one used for signature verification [6](#0-5) .

Attacker request: POST `/webhooks` with `X-Github-Event: push`, no valid (or any) `X-Hub-Signature`, and body:
```json
{"repository":{"owner":{"login":"org-with-no-secret"},"full_name":"victim-org/victim-repo"},"ref":"refs/heads/master","after":"<sha>"}
```
Since `org-with-no-secret` is a configured GitHub App organization in `Shipit.github_organizations` with `webhook_secret` blank, step 4 returns `true` regardless of the actual header. Step 6 then looks up `victim-org/victim-repo` (a real, secret-protected tenant's repository) and, if a Stack tracks `master` for that repository, calls `stack.sync_github(expected_head_sha: params.after)`.

Why existing guards fail: `verify_signature`'s only check is whether the bytes match the secret for `repository_owner`'s org; it never confirms that `repository_owner` corresponds to the org embedded in `repository.full_name`. The only test covering signature failure (`"verifies webhook signature"`) mocks `verify_webhook_signature` to return `false` directly and does not exercise the "no configured secret" branch or the owner/full_name mismatch [7](#0-6) . The `GithubOrganizationUnknown` rescue only protects against organizations absent from config, not against organizations present but misconfigured with no secret [8](#0-7) . `Repository.from_github_repo_name` performs no cross-check against the verified organization; it blindly trusts `full_name` [9](#0-8) .

### Impact Explanation
An attacker who controls (or registers) any organization in the multi-org `github:` config with a blank `webhook_secret` — or who targets a Shipit deployment using the single-org schema with no `webhook_secret` set (the documented default, `webhook_secret: # nil`, shown in the example secrets files) — can forge a `push` payload naming any other tenant's `repository.full_name`. This triggers `stack.sync_github` for that victim Stack, an unauthenticated write causing the target Stack to sync against attacker-chosen `ref`/`after` values. This matches the Critical category "a payload for one repository mutating another's stack." The attack is fully repeatable against any Stack whose `full_name`/branch is known or guessable, and generalizes to other events dispatched through the same `verify_signature` gate (e.g. `status`, `check_suite`, `membership`) wherever those handlers key their target lookup off a field independent of `repository_owner`.

### Likelihood Explanation
Preconditions: (a) at least one organization entry in Shipit's GitHub config has no `webhook_secret` configured — the shipped example configs (`config/secrets.development.example.yml`, `test/dummy/config/secrets.yml`) both default `webhook_secret` to nil, so this is a realistic real-world misconfiguration, not a contrived edge case; (b) a victim Stack exists tracking a repository/branch the attacker can name. No GitHub secrets, sessions, or tokens are needed — cost is a single crafted HTTP POST. This is highly feasible and trivially repeatable for any deployment with even one loosely-secured organization.

### Recommendation
Bind signature verification to the same organization/repository actually used for routing: derive both `repository_owner` and the write target from the same trusted, single source of truth (e.g., resolve the `Repository` record first via `full_name`, then verify the signature using that repository's `owner`, rejecting when `owner.login` in the payload disagrees with the resolved repository's actual owner). Additionally, require `webhook_secret` to be present for every configured organization (fail closed instead of `return true unless webhook_secret`), and add a check that the signature-verifying organization matches the organization portion of `repository.full_name` before dispatching to any handler.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb`):
```ruby
test "push webhook signed for an org with no secret cannot mutate a stack owned by a different org" do
  # Arrange: stub Shipit.github so that organization "org-with-no-secret" resolves
  # to a GitHubApp instance with webhook_secret = nil (verify_webhook_signature -> true unconditionally),
  # and organization "shopify" (victim) is the owner of an existing tracked Stack (@stack) for branch "master".
  no_secret_app = Shipit::GitHubApp.new('org-with-no-secret', webhook_secret: nil)
  Shipit.stubs(:github).with(organization: 'org-with-no-secret').returns(no_secret_app)

  payload = {
    'repository' => { 'owner' => { 'login' => 'org-with-no-secret' }, 'full_name' => @stack.repository.full_name },
    'ref' => 'refs/heads/master',
    'after' => 'deadbeef'
  }.to_json

  request.headers['X-Github-Event'] = 'push'
  # No X-Hub-Signature header sent at all -- fully unauthenticated for this repository.

  # Assert: the equality "signing org == owning org" should hold (organization named in owner.login
  # should equal the organization portion of full_name) -- here it does NOT (org-with-no-secret != shopify),
  # yet sync_github is still invoked on the victim stack.
  @stack.expects(:sync_github).with(expected_head_sha: 'deadbeef')
  Stack.any_instance.stubs(:sync_github) # for any other stacks matched by branch scope
  post :create, body: payload, as: :json
  assert_response :ok
end
```
This demonstrates that `repository_owner` (used to select the verifying `webhook_secret`) and `repository.full_name` (used to select the mutated Stack) are independently attacker-controlled and can diverge, breaking the required binding and producing an unauthenticated write to a stack for a repository/org that never validated the request.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
