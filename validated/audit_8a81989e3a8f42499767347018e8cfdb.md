### Title
Repository sync authorization uses a different field than the repository actually mutated, enabling cross-tenant stack writes via a secret-less org - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` authenticates a webhook based on `repository_owner` (`params.dig('repository','owner','login')` or the `organization.login` fallback), while `Handler#repository_name` used by `PushHandler#process` to select the target stack reads the independent `payload.dig('repository','full_name')` field. Combined with `GitHubApp#verify_webhook_signature` trivially accepting any signature when no `webhook_secret` is configured for that org, an attacker who merely knows the name of a secret-less org configured in `Shipit.github_apps` can forge a webhook that is "verified" as that org but whose payload targets an arbitrary victim repository's stack.

### Finding Description
The broken binding is: the login used to authorize the request (`repository_owner`) is assumed to equal the owner of the repository being mutated (`repository_name`'s owner), but the code never enforces this equality.

- `repository_owner` is computed from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) , and is used solely to pick which `GitHubApp` config to verify the signature against: `Shipit.github(organization: repository_owner)` [2](#0-1) .
- `Handler#repository_name`, used by every handler (including `PushHandler`) to select the affected `Repository`/`Stack`, reads a completely separate field: `payload.dig('repository', 'full_name')` [3](#0-2) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the target org has no `webhook_secret` configured: `return true unless webhook_secret` [4](#0-3) .

Exploit flow: given a secret-less org `attacker-org` present in `Shipit.github_apps`, the attacker POSTs to `/webhooks` with header `X-Github-Event: push` and a body such as:
```json
{
  "organization": {"login": "attacker-org"},
  "repository": {"full_name": "victim-org/victim-repo"},
  "ref": "refs/heads/main",
  "after": "deadbeef"
}
```
Because `repository.owner.login` is absent, `repository_owner` falls back to `organization.login` = `"attacker-org"` [1](#0-0) . `verify_signature` resolves `Shipit.github(organization: "attacker-org")`, and since that org has no `webhook_secret`, `verify_webhook_signature` returns `true` regardless of the (even absent or garbage) `X-Hub-Signature` header. The request passes `before_action` checks and reaches `create`, which dispatches to `PushHandler.call(params)` [5](#0-4) . `PushHandler#process` then resolves `stacks` via `Repository.from_github_repo_name(repository_name)`, where `repository_name` reads `payload.dig('repository','full_name')` = `"victim-org/victim-repo"` — a field never checked against the authenticated org — and triggers `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack on the matched `branch` [6](#0-5) .

No existing guard closes this gap: `drop_unhandled_event` and `check_if_ping` do not inspect repository identity [7](#0-6) ; `ExplicitParameters` only validates that `ref`/`after` are present, not repository/organization consistency [8](#0-7) ; and there is no code anywhere that compares `repository_owner` to the owner portion of `repository_name`.

### Impact Explanation
Any org with no `webhook_secret` configured in `Shipit.github_apps` becomes a skeleton key: an attacker who merely knows that org's login (organization names are public on GitHub) can send a completely unsigned/forged webhook that is treated as verified, then direct its payload at any other tenant's repository (`victim-org/victim-repo`) to trigger `Stack#sync_github` for that stack. This is a payload from one (unauthenticated) party mutating another org's stack state — the "Critical" category explicitly listed ("a payload for one repository mutating another's stack, commit, task or team"). The blast radius spans every repository/stack hosted on the same Shipit instance, and the attack is trivially repeatable per request/per victim repo.

### Likelihood Explanation
Requires the operator to have configured at least one org in `Shipit.github_apps` without a `webhook_secret`. This is a realistic and explicitly named precondition (e.g., a placeholder/test org, or an org onboarded before secrets were set). Given that precondition, exploitation costs the attacker nothing beyond knowledge of that org's login and the target repo's `owner/name` — no secrets, sessions, or GitHub write access are needed, and the request is a single unauthenticated `POST /webhooks`.

### Recommendation
Bind the authenticated identity to the mutated resource: derive `repository_owner` and the handler's `repository_name` from the same source field (prefer `repository.full_name`'s owner segment, and require the `repository` key to be present), and reject requests where `repository.owner.login` disagrees with the org used for signature verification. Additionally, treat a missing/blank `webhook_secret` as a configuration error rather than an automatic-accept path in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
Minitest under `test/controllers/webhooks_controller_test.rb` (illustrative; not executed):
```ruby
test "push webhook authenticated as secret-less org can mutate another org's stack" do
  Shipit.github_apps # ensure "attacker-org" configured with no webhook_secret in test config
  victim_stack = shipit_stacks(:shipit) # owner/name resolves to a real Repository/Stack

  body = {
    organization: { login: "attacker-org" },
    repository: { full_name: "#{victim_stack.repository.owner}/#{victim_stack.repository.name}" },
    ref: "refs/heads/#{victim_stack.branch}",
    after: "deadbeef"
  }.to_json

  assert_enqueued_with(job: Shipit::GithubSyncJob) do
    post shipit.github_webhooks_path, params: body,
      headers: { 'X-Github-Event' => 'push', 'X-Hub-Signature' => 'sha1=bogus', 'Content-Type' => 'application/json' }
  end

  assert_response :ok
  # Assert the equality claimed broken:
  owner_used_for_auth = "attacker-org"
  owner_of_mutated_repo = victim_stack.repository.owner
  refute_equal owner_used_for_auth, owner_of_mutated_repo
end
```
This demonstrates `repository_owner` (`"attacker-org"`, secret-less, verification bypassed) diverging from the actual owner of the repository whose stack (`victim_stack`) is synced via `repository_name`, with no code path preventing the mismatch.

      return true unless webhook_secret
