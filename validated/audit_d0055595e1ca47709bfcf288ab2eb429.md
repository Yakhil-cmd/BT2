### Title
Attacker-controlled issue title/body reach the terminal unsanitized via `printRawIssuePreview` - ([File: pkg/cmd/issue/view/view.go])

### Finding Description
`printRawIssuePreview` writes `issue.Title` and `issue.Body` directly with `fmt.Fprintf`/`fmt.Fprintln` [1](#0-0) [2](#0-1) . These fields originate from the GraphQL API response and are attacker-controlled (any GitHub user who authors an issue/PR title or body). Unlike the codebase's general pattern for handling remote text, this path does not use the `iostreams.Untrusted` wrapper that the project introduced specifically to neutralize ANSI/control sequences before they reach a writer: `Untrusted.String()` runs the content through `asciisanitizer.Sanitizer` so any `fmt` print path is safe by default [3](#0-2) . Several other view/read paths in the codebase (gist view, pr diff, run logs, repo read-file, workflow shared, release upload) reference this sanitize/Untrusted mechanism, but `issue/view/view.go`'s raw preview path does not, based on the grep results and field types found in `api/queries_issue.go`.

`printRawIssuePreview` is reached whenever `opts.IO.IsStdoutTTY()` is false [4](#0-3) , which is the normal branch taken when a user pipes `gh issue view` output into another program (e.g. `gh issue view 123 | cat`, `| less -R`, `| tee`). In that scenario gh's own stdout is a pipe (non-TTY), so `IsStdoutTTY()` correctly returns false and no pager/tty protections in gh apply, but the downstream consumer (`cat`, `less`, etc.) writes gh's raw bytes straight to the victim's real controlling terminal. Because `issue.Title`/`issue.Body` are not passed through sanitization, any terminal escape sequences embedded by the attacker (e.g. `\x1b[?1049h` alt-screen, `\x1b[?1000h` mouse reporting, `\x1b[?25l` cursor hide) survive intact and are interpreted by that terminal, with no complementary reset issued by gh, since gh's own process never coordinates terminal restoration for content it treats as "not going to a TTY."

### Impact Explanation
This maps to the described impact: "Terminal output/prompt spoofing." An attacker who authors an issue/PR title or body can leave the victim's terminal in an altered state (hidden cursor, alt-screen buffer, mouse capture, or echo suppression) that persists after the piped command exits, enabling spoofed prompts or hidden output that could facilitate credential capture on a subsequent unrelated command, or the appearance that the terminal is unresponsive/different.

### Likelihood Explanation
Requires no special privilege beyond publishing normal issue content, and the vulnerable path is exercised whenever a user runs `gh issue view <n>` with stdout not attached to a TTY, which is a common and unremarkable pattern for filtering (`grep`), paging (`less`), logging (`tee`), or simple redirection into `cat` inside a terminal multiplexer/session. It is fully repeatable and requires no interaction beyond the victim viewing the issue.

### Recommendation
Wrap `issue.Title` and `issue.Body` (and any other remotely-sourced fields printed in `printRawIssuePreview`) in `iostreams.NewUntrusted(...)` before printing so `Fprintf`/`Fprintln` invoke `Untrusted.String()` and route through `asciisanitizer`, consistent with how other remote-content view paths in the repo already handle this. Confirm `api.Issue.Title`/`Body` types in `api/queries_issue.go` and update either the struct fields or the call sites in `printRawIssuePreview` accordingly.

### Proof of Concept
Go test sketch for `pkg/cmd/issue/view/view_test.go`:
```go
func TestPrintRawIssuePreview_StripsEscapeSequences(t *testing.T) {
    issue := &api.Issue{
        Title: "innocuous title\x1b[?1049h\x1b[?1000h", // alt-screen + mouse reporting
        Body:  "body\x1b[?25l", // hide cursor, never restored
    }
    buf := &bytes.Buffer{}
    err := printRawIssuePreview(buf, issue)
    require.NoError(t, err)
    out := buf.String()
    assert.NotContains(t, out, "\x1b[?1049h")
    assert.NotContains(t, out, "\x1b[?1000h")
    assert.NotContains(t, out, "\x1b[?25l")
}
```
Manual validation: create/author an issue with a title containing `\x1b[?1049h` and body containing `\x1b[8m` (conceal) or `\x1b[?1000h`, then run `gh issue view <n> | cat` in a real terminal and observe the terminal enter alt-screen/mouse-report mode without automatic restoration on exit.

Note: I was not able to directly open `api/queries_issue.go` to confirm the exact declared type of `Issue.Title`/`Issue.Body` (plain `string` vs `iostreams.Untrusted`) before the tool budget ran out; this was inferred from grep matches and the absence of `Untrusted`/sanitize references in `pkg/cmd/issue/view/view.go`. If those fields are already typed as `iostreams.Untrusted`, the raw-string `%s` formatting would still invoke `String()` and be sanitized, which would invalidate this finding — this should be verified directly in the repository (e.g., via a Devin session) before treating it as confirmed.

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
