### Title
Accrued RAY-value overflow permanently freezes an oversized market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
`calculate_supplier_rewards` computes `borrowed.mul(new_borrow_index)` before the borrow-index cap can be applied safely to market totals. Once `borrowed * new_borrow_index / RAY` exceeds `i128::MAX`, every pool operation that loads the market panics during mandatory accrual, including withdrawal, repayment, liquidation settlement, recapitalization, and `update_indexes`. [1](#0-0) [2](#0-1) 

### Finding Description
`Ray::mul` returns `mul_div_half_up(scaled, index, RAY)`, which panics with `GenericError::MathOverflow` when the representable quotient exceeds `i128::MAX`. [3](#0-2) [4](#0-3) 

During accrual, `accrue_step` receives the pool's scaled `borrowed` total and calls `calculate_supplier_rewards`; that function separately computes `borrowed * old_borrow_index` and `borrowed * new_borrow_index`. [5](#0-4) [1](#0-0) 

Although `update_borrow_index` caps the index itself at `MAX_BORROW_INDEX_RAY`, the cap is applied only after multiplying the old index by the interest factor and does not bound the resulting total-debt value. [6](#0-5) 

Every market-mutating pool leg calls `synced_market`, which invokes `interest::global_sync`; consequently, once the total-debt multiplication no longer fits, even operations that would reduce debt or supply cannot execute. [2](#0-1) [7](#0-6) 

The controller exposes the reachable user-facing operations `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `update_indexes`, and `recapitalize`; pool mutations then perform the same accrual-first path. [8](#0-7) [9](#0-8) 

### Impact Explanation
The market becomes permanently unusable absent a code upgrade: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot process the affected debt leg, and permissionless `update_indexes` cannot advance state. [2](#0-1) [10](#0-9) 

The overflow occurs before the operation's reduction logic runs, so a repayment or withdrawal cannot make the representable total smaller first. [11](#0-10) [12](#0-11) 

### Likelihood Explanation
The trigger requires a very large market whose scaled debt approaches the protocol's RAY-value domain and enough accrual to push `scaled_debt * borrow_index / RAY` past `i128::MAX`; valid token balances and caps do not by themselves prevent the accrued value from crossing that boundary. [13](#0-12) 

An unprivileged participant can drive the state through ordinary `supply` and `borrow` calls, provided sufficient real liquidity and collateral exist; after that, the overflow is reached by normal index accrual rather than by supplying malicious indexes or privileged parameters. [14](#0-13) [1](#0-0) 

The repository's regression test demonstrates that the borrow index can still be below `MAX_BORROW_INDEX_RAY` when accrual fails, after which both `withdraw` and `repay` fail with `MathOverflow`. [15](#0-14) 

### Recommendation
Bound market exposure by projected future value rather than only current asset amount, or make accrual handle unrepresentable totals without trapping. [16](#0-15) 

At minimum, detect `borrowed * new_borrow_index / RAY > i128::MAX` inside `calculate_supplier_rewards`, cap or split the calculation before the fallible `Ray::mul`, and preserve a recovery path that permits debt reduction and withdrawals after the ceiling is reached. [1](#0-0) 

Cap admission using the worst-case `amount_at_entry * MAX_BORROW_INDEX_RAY / RAY` domain, and enforce the same bound on aggregate scaled debt across all spokes for the hub asset. [17](#0-16) [6](#0-5) 

### Proof of Concept
1. Create or use an 18-decimal listed market whose caps permit a very large book.
2. Through `Controller::supply`, deposit enough of the asset that its RAY-normalized value is close to the representable `i128` boundary.
3. Through `Controller::borrow`, borrow a high-utilization fraction of that market from collateral in another listed market.
4. Call permissionless `Controller::update_indexes(caller, vec![hub_asset])` as ledger time advances.
5. Once `borrowed_scaled * new_borrow_index / RAY` exceeds `i128::MAX`, `calculate_supplier_rewards` panics in `Ray::mul`.
6. Subsequent `update_indexes`, `repay`, `withdraw`, `liquidate`, and `recapitalize` calls for that market all fail before mutation because they load an interest-synced cache.

The deterministic regression `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` exercises this sequence with `BIG18`, observes `MathOverflow` from `update_indexes`, confirms the borrow-index cap had not engaged, and verifies both withdrawal and repayment fail afterward. [15](#0-14)

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
```

```rust
pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
```

```rust
/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```markdown
| Bound | Consequence |

| Asset decimals 0..=18 | Exact token-to-RAY upscaling. Below 3: collateral only, no flash loans, no liquidation fee, its account's only supply position, at least 2 whole units while in debt |

| Supply-index floor 10^24 | At most 1,000 times the shares minted at index one for the same deposit |
| Borrow APR maximum 2 RAY | 200% annual rate; not a bound on balance growth alone |
| Token-to-RAY input maximum `i128::MAX / 10^(27-d)` | About 170.14 billion whole tokens, before other limits |
| Deposit conversion at the supply-index floor | About 170.14 million whole tokens before scaled-share overflow |

The token-to-RAY maximum is also the admitted cap maximum. Accrued position
values and market totals must independently fit the RAY domain; valid caps and
bounded indexes do not guarantee that future accrual fits. Value overflow can
occur before the index ceiling and block repayment/withdrawal because those
operations accrue first. At the borrow-index ceiling, further accrual produces
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
