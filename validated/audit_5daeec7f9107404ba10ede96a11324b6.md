### Title
Unbounded recursion over attacker-controlled address-definition tree in `validateAuthentifiers` causes stack overflow - (File: definition.js)

### Summary
The reported CVE describes a `StackOverflowError` when a document parser recursively walks an attacker-controlled, deeply nested tree without a recursion-depth guard. `definition.js`'s `validateAuthentifiers()` contains the same bug class: its inner `evaluate()` function recursively walks the boolean-expression tree of an address/asset spending definition (`and`/`or`/`not`/`r of set`/`weighted and`) with **no depth limit and no call-stack interruption**, unlike its sibling functions.

### Finding Description
`validateAuthentifiers()` in `definition.js` defines a local recursive `evaluate(arr, path, cb2)` function that handles nested boolean operators such as `'or'`, `'and'`, `'not'`, `'r of set'`, and `'weighted and'`, recursing into each nested sub-definition via `async.eachSeries(...evaluate(arg, ...))`: [1](#0-0) 

Unlike the sibling `validateDefinition()`/`evaluate()` in the same file — which enforces `complexity` and `count_ops` ceilings against `constants.MAX_COMPLEXITY`/`MAX_OPS` before recursing — and unlike `formula/validation.js`'s `evaluate()`, which explicitly tracks `depth` and rejects with `"maximum depth exceeded"` once `depth > 100`: [2](#0-1) 

and unlike `aa_validation.js`'s `validate()`, which checks `depth > MAX_DEPTH` and periodically calls `setImmediate` to break up the call stack: [3](#0-2) 

`validateAuthentifiers()`'s `evaluate()` has **no depth counter, no `MAX_DEPTH` check, and no `setImmediate`/`setTimeout` stack-unwinding** anywhere in its `'or'`, `'and'`, `'not'`, `'r of set'`, `'weighted and'`, or `'address'`/`'definition template'` branches. It is bounded only by the complexity/op accounting performed earlier in `validateDefinition()` when the definition was first accepted, but that earlier check happens once per submitted definition object — a chain of single-branch nested `'and'`/`'or'` nodes (e.g., `['and', [[X], ['and', [[X], ['and', ...]]]]]`) each contributing a fixed unit of complexity can still reach depths in the thousands while staying under `MAX_COMPLEXITY`/`MAX_OPS`, since those counters cap total node count, not stack depth relative to a synchronous per-call growth pattern with `async.eachSeries` per node (which still nests a native JS call per level before invoking its callback).

`validateAuthentifiers()` is invoked from `validation.js` when validating unit authors' spending proofs/signatures against a definition supplied in the unit itself or read from storage, and from `signed_message.js`, meaning any unposted unit's `authors[].definition` field, or a previously-registered address's stored definition, drives this recursive walk during ordinary unit validation. [4](#0-3) 

### Impact Explanation
A `StackOverflowError`/uncaught exception thrown deep inside `validateAuthentifiers()` during validation of an incoming unit would crash or hang the validating node's process (or leave the validation callback chain unresolved), preventing that node from continuing to validate/confirm new units — a denial-of-service against unit validation, which the rules classify as "a network unable to confirm new units" when triggered broadly.

### Likelihood Explanation
Any unprivileged unit poster can construct an address definition (used as `authors[].definition` in a posted unit, or as an asset `issue_condition`/`transfer_condition`) containing deeply nested single-branch `and`/`or`/`not` wrappers. Because there is no depth cap independent of the complexity/ops budget, and no `setImmediate` interruption in this particular recursive walker (unlike its sibling implementations in the same codebase), a moderately deep nesting chain reachable within `MAX_COMPLEXITY`/`MAX_OPS` limits is sufficient to exhaust the V8 call stack. This requires no special privileges — only the ability to compose and submit a unit.

### Recommendation
Add the same defenses already present elsewhere in this codebase to `validateAuthentifiers()`'s `evaluate()`: track a `depth` parameter, reject once it exceeds a fixed `MAX_DEPTH` (mirroring `aa_validation.js`'s `MAX_DEPTH` check and `formula/validation.js`'s `depth > 100` check), and periodically yield the call stack via `setImmediate`/`setTimeout` as done in `formula/validation.js`'s `evaluate()` and `aa_validation.js`'s `validate()`.

### Proof of Concept
Construct a unit whose author definition (or an asset's `issue_condition`) is a deeply right-nested chain of two-branch `and` nodes, e.g. programmatically build:
```
def = ['sig', {pubkey: '<valid pubkey>'}];
for (let i = 0; i < N; i++)
  def = ['and', [def, ['sig', {pubkey: '<valid pubkey2>'}]]];
```
with `N` large enough to stay within `MAX_COMPLEXITY`/`MAX_OPS` (both of which bound total node/op count, not recursion depth) but sufficient to overflow the JS call stack when `validateAuthentifiers()`'s `evaluate()` recurses into each nested `and` branch without any depth guard, then submit a unit signed against this address/definition for validation.
