### Title
Overflow during time-based interest accrual permanently freezes a large market - (File: common/src/rates/simulate.rs)

### Summary
Every pool mutation first calls `interest::global_sync`, which accrues elapsed time through `accrue_step`. [1](#0-0)  `accrue_step` converts scaled debt and supply to RAY-denominated balances before updating the indexes, but does not cap the resulting `i128` value. [2](#0-1)  On a sufficiently large market, index growth can make `borrowed * borrow_index` exceed `i128::MAX` before `update_borrow_index` reaches its `1e36` cap. [3](#0-2)  The resulting `MathOverflow` aborts `supply`, `borrow`, `withdraw`, `repay`, liquidation paths, and even `update_indexes`, leaving the market permanently frozen absent a contract upgrade. [4](#0-3) 

### Finding Description
`global_sync` divides long inactivity into chunks, but each chunk still computes the full scaled debt value at the new borrow index. [4](#0-3)  The configured borrow rate is capped at `2 * RAY`, while `update_borrow_index` separately caps the index at `1e36`. [5](#0-4)  Those bounds do not protect the earlier fixed-point balance multiplication: for example, approximately `0.98e36` scaled debt shares overflow once the borrow index exceeds roughly `173 * RAY`, well below the index cap. [6](#0-5)  Because `checked_sub` only runs after both total-debt multiplications have succeeded, the transaction panics before index capping or fee accounting can occur. [3](#0-2) 

### Impact Explanation
This permanently freezes all funds and debt operations for the affected `(hub_id, asset)` market once the threshold is crossed. [7](#0-6)  The repository’s long-horizon test demonstrates that `update_indexes`, `withdraw`, and `repay` all fail with `MATH_OVERFLOW` after the market reaches the condition. [8](#0-7)  `update_params` cannot safely lower the rate afterward because it also accrues interest under the old model before writing new parameters. [9](#0-8) 

### Likelihood Explanation
Triggering the condition requires an unusually large scaled balance and enough inactivity for the borrow index to grow beyond the value ceiling; it is not reachable through an arbitrarily short interval or a small market. [10](#0-9)  Nevertheless, an unprivileged caller can directly invoke controller `update_indexes(caller, assets)` once the state exists, and the same overflow is automatically reached by ordinary repayments, withdrawals, and liquidations. [11](#0-10) 

### Recommendation
Bound or saturate the RAY-valued `borrowed * index` and `supplied * index` calculations before calling `Ray::mul`, or redesign accrual so index growth is capped based on the maximum representable scaled book value. [12](#0-11)  At minimum, clamp `new_borrow_index` to `min(MAX_BORROW_INDEX_RAY, i128::MAX / borrowed)` before calculating total debt, while preserving conservative rounding and the existing share-accounting invariant. [13](#0-12) 

### Proof of Concept
1. On a high-decimal market with sufficient configured caps, a supplier calls `supply(caller, supplier_account, spoke_id, [(hub_asset, 1_000_000_000 * 10^18)])`. [14](#0-13) 
2. A borrower with adequate collateral calls `borrow(caller, borrower_account, [(hub_asset, principal * 98 / 100)], None)`, leaving utilization near 98%. [15](#0-14) 
3. Advance ledger time until the projected `borrowed * borrow_index` exceeds `i128::MAX`; the checked test reaches this before the `1e36` index cap. [16](#0-15) 
4. Any address calls `update_indexes(caller, [hub_asset])`; controller authorization succeeds, but the pool call panics with `MathOverflow`. [11](#0-10) 
5. Subsequent `withdraw` and `repay` calls panic identically because `load_leg` accrues interest before resolving the requested action. [1](#0-0)

pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);
