### Title
Cross-org webhook forgery via attacker-controlled `repository.owner.login` decoupled from `repository.full_name` — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the HMAC key/organization used to validate a webhook from `params.dig('repository','owner','login')` (falling back to `params.dig('organization','login')`), a field taken directly from the unauthenticated JSON body. `ClosedHandler`/`Handler#stacks` instead resolve the *target* repository/review stack from `params.repository.full_name`, an entirely different, independently-forgeable field in the same body. Nothing enforces that these two fields refer to the same organization, so the org whose secret is checked can differ from the org whose stack gets mutated.

### Finding Description
The claimed binding is: `organization_used_to_verify_signature == organization_owning(repository.full_name)`. Tracing the code shows this is **false by construction**:

- `verify_signature` computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` and calls `Shipit.github(organization: repository_owner)` to fetch the `GitHubApp` (and its `webhook_secret`) used for HMAC verification. [1](#0-0) 
- `Shipit.github` resolves `github_app_config(organization)` from `secrets.github[organization]` in multi-org deployments; each org can have an independently-set (and, per docs, *optional*) `webhook_secret`. [2](#0-1) 
- `GitHubApp#verify_webhook_signature` explicitly bypasses verification when no secret is configured: `return true unless webhook_secret`. [3](#0-2) 
- Once past `verify_signature`, `ClosedHandler#repository` resolves the actual target via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a field never checked against `repository_owner`. [4](#0-3) 
- `ClosedHandler#process` unconditionally archives the resolved review stack on any `action == "closed"`, without inspecting `pull_request.merged` at all. [5](#0-4) 

Exploit: on a multi-org Shipit deployment (top-level `github:` keys per org, as shown in the repo's own example configs, e.g. both orgs ship with `webhook_secret: # nil`) [6](#0-5) , an attacker with zero secrets sends:
```json
{
  "action": "closed",
  "number": <victim PR number>,
  "pull_request": {"merged": true, "head": {"sha": "<attacker-chosen sha>", ...}, ...},
  "repository": {"full_name": "victim-org/repo", "owner": {"login": "org-with-no-secret"}},
  "sender": {"login": "attacker"}
}
```
`verify_signature` looks up `org-with-no-secret`, finds no `webhook_secret`, and returns `true` unconditionally — no valid `X-Hub-Signature` is even required. The request then reaches `ClosedHandler`, which resolves and archives/tears down `victim-org/repo`'s review stack purely from the forged `repository.full_name`. This is a genuine cross-tenant write with no dependency on any secret the attacker is disallowed from holding.

Existing guards do not stop this: `drop_unhandled_event` only checks event type, `ExplicitParameters` only validates shape/types (not cross-field consistency), and there is no `require_permission!`/`current_user` check on webhook ingestion by design (webhooks are meant to be machine-to-machine, gated solely by `verify_signature`). The single point of trust — signature verification — is keyed off attacker-supplied data disjoint from the data it's supposed to protect.

### Impact Explanation
An unauthenticated internet attacker can force `Shipit::Repository.from_github_repo_name`-resolved review stacks belonging to **any repository/org tracked by the same Shipit instance** to archive/deprovision, purely by naming a different, secret-less (or misconfigured) org in `repository.owner.login` while pointing `repository.full_name` at the victim. This is a cross-tenant write triggered by a payload that never authenticated for the victim org — matching the Critical category "a payload for one repository mutating another's stack." The same decoupling affects every other webhook handler that reads `repository.full_name`/`payload.dig('repository','full_name')` independently of `repository_owner` (push, status, pull_request handlers generally), so blast radius spans the whole multi-org install, not just `ClosedHandler`.

### Likelihood Explanation
Requires: (1) this Shipit instance configured for multiple GitHub orgs (`github:` keyed by org name) — a supported, documented deployment mode, not a hypothetical, and (2) at least one configured org left with no `webhook_secret` — which the setup docs describe as optional and the repo's own example multi-org secrets files ship with unset. Given that, the attacker needs no secret, no session, no API token, and no repository permissions on the victim — only knowledge of the victim's `full_name` and PR number, both public. This is fully repeatable against arbitrary repos/orgs served by the same instance for as long as any one org lacks a webhook secret.

### Recommendation
Derive the organization used for signature verification and the organization used for repository/stack resolution from the *same* trusted, single field (e.g., always require `repository.full_name`'s owner segment to match `repository.owner.login`/`organization.login`, and reject the request otherwise). Do not permit signature verification to fall back to "no secret configured" as an implicit pass in multi-org mode; require every configured org to have a non-blank `webhook_secret`, or fail closed if it's missing. Additionally, after locating the target `Repository` via `full_name`, re-validate that its owner matches the organization whose secret validated the request before performing any mutation.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (illustrative)
test "cross-org forged closed event archives victim stack when payload org has no webhook secret" do
  Shipit.stubs(:github_default_organization).returns("org-with-no-secret")
  Shipit.stubs(:github_app_config).with("org-with-no-secret").returns({ webhook_secret: nil })
  Shipit.stubs(:github).with(organization: "org-with-no-secret").returns(
    Shipit::GitHubApp.new("org-with-no-secret", { webhook_secret: nil })
  )

  victim_stack = shipit_stacks(:shipit) # tracked repo "shopify/shipit-engine"

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=garbage'

  body = {
    action: 'closed',
    number: victim_stack.pull_request.number,
    pull_request: { id: 1, number: victim_stack.pull_request.number, url: 'x', title: 't',
                     state: 'closed', additions: 1, deletions: 1,
                     head: { sha: 'attackersha', ref: 'attacker-ref' },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { full_name: 'shopify/shipit-engine', owner: { login: 'org-with-no-secret' } },
    sender: { login: 'attacker' }
  }.to_json

  assert_not victim_stack.reload.archived?
  post :create, body:, as: :json
  assert_response :ok
  assert victim_stack.reload.archived?, "victim stack archived by attacker-org-signed forged payload"
end
```
This demonstrates `organization_used_to_verify == "org-with-no-secret"` while `organization_owning(repository.full_name) == "shopify"`, and shows the victim stack state changes despite the mismatch — proving the claimed binding is false.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
