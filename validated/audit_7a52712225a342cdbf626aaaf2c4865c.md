### Title
Webhook Signature Selected by `repository.owner.login` / `organization.login` Is Never Bound to the `repository.full_name` the Handlers Act On - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks *which* organization's webhook secret to validate the HMAC signature against using `repository.owner.login` (or `organization.login`), while every webhook handler resolves the repository/stack it actually mutates using the independent `repository.full_name` field from the same payload. ` [1](#0-0) ` Nothing cross-checks that the owner segment of `full_name` matches `repository.owner.login`/`organization.login`.

### Finding Description
Shipit supports hosting multiple GitHub organizations from a single instance, each with its own `webhook_secret`, selected via `Shipit.github(organization:)` / `github_app_config(organization)`. ` [2](#0-1) ` ` [3](#0-2) `

`verify_signature` computes `repository_owner` from the payload and uses it purely to choose which secret to verify the raw body against: ` [1](#0-0) `

Once verification passes, every handler (`Handler#stacks`, and each `PullRequest::*Handler`) resolves the target `Repository`/`Stack` using `Repository.from_github_repo_name(payload.dig('repository', 'full_name'))`, splitting `owner/name` straight out of `full_name` — a field that is never compared to `repository.owner.login`: ` [4](#0-3) ` ` [5](#0-4) ` ` [6](#0-5) `

Because HMAC verification only proves "whoever signed this body knows *some* configured org's secret," and that org is self-declared by the attacker via `repository.owner.login`/`organization.login`, an operator who legitimately owns/administers **their own** GitHub organization "org-attacker" (with its own Shipit-configured GitHub App and `webhook_secret`) can forge an arbitrary webhook body where:
- `repository.owner.login` (or `organization.login`) = `"org-attacker"` → selects and passes signature verification with their own known secret.
- `repository.full_name` = `"victim-org/victim-repo"` → is the field every handler actually uses to locate the `Repository`/`Stack` to mutate.

This breaks the equality **organization authenticated (`repository.owner.login`) == repository written (`repository.full_name`)** that the code implicitly (and incorrectly) assumes holds.

### Impact Explanation
With a forged, correctly-signed-for-org-attacker payload targeting `victim-org/victim-repo`:
- `PushHandler` will call `stack.sync_github(expected_head_sha: params.after)` on the victim's non-archived matching-branch stacks, letting the attacker pick an arbitrary "expected head sha" to drive victim stack sync state. ` [7](#0-6) `
- `PullRequest::OpenedHandler` and `LabeledHandler` will provision/archive/unarchive review stacks for the victim's repository/PR based on attacker-supplied `pull_request` fields and labels, bypassing the label-based provisioning gate (`provisioning_behavior_allow_with_label?` / `prevent_with_label?`) since the "approved" label state is taken from the attacker-controlled payload, not a re-fetch from GitHub. ` [8](#0-7) ` ` [9](#0-8) `

This lets an unprivileged operator of one tenant organization trigger cross-repository stack actions (sync, provisioning gate bypass) against a different, unrelated organization's repositories hosted on the same Shipit instance — a cross-repository write / unauthorized provisioning action, matching the required Critical/High impact bucket (cross-repository writes / unauthorized deploy-adjacent action).

### Likelihood Explanation
Requires: (a) the Shipit instance to be configured with the multi-org `secrets.github` schema (explicitly documented/supported), and (b) the attacker to legitimately control at least one configured org's webhook secret (i.e., they are a real, if low-privileged, tenant of the multi-org deployment) — this is an unprivileged-attacker path relative to the victim org, requiring no GitHub write access, no Shipit session, and no compromise of the victim's own secret. Given multi-tenant Shipit deployments are an explicit supported configuration, likelihood is realistic wherever multiple independently-controlled orgs share one instance.

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler`), after selecting the org via `repository_owner`/`organization.login` and verifying the signature, additionally assert that the owner segment of `payload.dig('repository','full_name')` matches `repository_owner` (case-insensitively) before dispatching to handlers; reject (422) on mismatch.

### Proof of Concept
1. Configure Shipit with two orgs, `org-attacker` (attacker-administered) and `victim-org` (unrelated tenant), each with distinct `webhook_secret`s, both hosting repositories/stacks on the same Shipit instance.
2. Attacker crafts a `push` event JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": { "owner": { "login": "org-attacker" }, "full_name": "victim-org/victim-repo" }
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC(webhook_secret_for_org-attacker, body)` — a secret they legitimately possess.
4. POST to `/webhooks` with `X-Github-Event: push`. `verify_signature` calls `Shipit.github(organization: "org-attacker")` and succeeds. ` [10](#0-9) `
5. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` and invokes `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on victim stacks, despite the payload never being signed with `victim-org`'s secret. ` [4](#0-3) `

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
