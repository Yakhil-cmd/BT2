### Title
Unvalidated `parentChainInfo` from Malicious Parent Chain Node Enables Gas Price Manipulation and Nonce Corruption in ServiceChain Bridge — (File: `node/sc/sub_bridge_handler.go`)

---

### Summary

The SubBridge handler accepts `parentChainInfo` (nonce, gas price, KIP71Config) from a P2P-connected parent chain node without any bounds validation. A malicious or compromised parent chain node can send crafted values that cause the child chain to construct and sign anchoring transactions with an inflated gas price, draining the parent operator's KAIA balance. The nonce field is also accepted without validation, corrupting the bridge's transaction sequencing.

---

### Finding Description

When the child chain (SubBridge) needs to sync its nonce and gas price, it calls `SyncNonceAndGasPrice()`, which broadcasts a `ServiceChainParentChainInfoRequestMsg` to all connected parent chain peers. [1](#0-0) 

The parent chain node responds with a `parentChainInfo` struct containing `Nonce`, `GasPrice`, `KIP71Config`, and `IsMagmaEnabled`. [2](#0-1) 

In `handleParentChainInfoResponseMsg`, the child chain decodes this P2P message and directly applies the received values with no bounds validation: [3](#0-2) 

`setRemoteChainValues` then unconditionally sets `remoteGasPrice` to `pcInfo.KIP71Config.UpperBoundBaseFee` when `IsMagmaEnabled` is true — a value fully controlled by the remote peer: [4](#0-3) 

This `remoteGasPrice` is then embedded directly into the unsigned anchoring transaction: [5](#0-4) 

The transaction is then signed with the parent operator's key and submitted to the parent chain: [6](#0-5) 

The parent chain's txpool has no upper-bound gas price check — it only enforces `tx.GasPrice() >= baseFee`: [7](#0-6) 

The only peer authentication is a chain ID comparison, meaning any node advertising the correct chain ID can connect and send crafted `parentChainInfo`: [8](#0-7) 

---

### Impact Explanation

A malicious parent chain node sets `IsMagmaEnabled = true` and `KIP71Config.UpperBoundBaseFee` to an arbitrarily large `uint64` value. The child chain stores this as `remoteGasPrice` and uses it as `TxValueKeyGasPrice` in every subsequent anchoring transaction. Each anchoring transaction is signed by the parent operator's key and submitted to the parent chain with the inflated gas price. If the gas price is set to a value within the parent operator's balance (e.g., enough to drain the account in tens of transactions), the parent chain txpool accepts the transaction, it is included in a block, and the parent operator's KAIA balance is drained through excessive fee charges.

Additionally, when `poolNonce == 0` (no pending bridge transactions), the nonce is set unconditionally to `pcInfo.Nonce`: [9](#0-8) 

A malicious node can set this to an arbitrarily high value, causing all subsequent anchoring transactions to carry an unreachable nonce, permanently stalling the bridge's anchoring functionality and consuming the parent operator's nonce space.

**Corrupted values:**
- `sbh.remoteGasPrice` (uint64): set to attacker-controlled `UpperBoundBaseFee`
- `pAccount.nonce` (uint64): set to attacker-controlled `pcInfo.Nonce`
- `TxValueKeyGasPrice` in signed anchoring transactions: inflated to drain parent operator KAIA

---

### Likelihood Explanation

The attack requires a malicious or compromised parent chain node that the service chain connects to. The only authentication guard is chain ID matching. A network-level attacker (e.g., BGP hijack, DNS spoofing, or a compromised EN on the parent chain) who can intercept or impersonate the parent chain P2P peer can trigger this. The child chain automatically re-syncs nonce and gas price on every new peer connection and every `SyncRequestInterval` blocks, so the attack window is recurring.

---

### Recommendation

**Short term:**
- In `handleParentChainInfoResponseMsg`, validate `pcInfo.Nonce` against the locally tracked nonce — reject values that deviate by more than a configurable threshold.
- In `setRemoteChainValues`, validate `pcInfo.KIP71Config.UpperBoundBaseFee` and `pcInfo.GasPrice` against a locally known or configurable maximum (e.g., reject values exceeding `N × localBaseFee`).

**Long term:**
- Fetch nonce and gas price directly from the parent chain via an authenticated RPC call (using `remoteBackend`) rather than trusting P2P messages from a peer.
- Implement cryptographic peer authentication beyond chain ID matching for the bridge P2P protocol.

---

### Proof of Concept

1. Set up a ServiceChain (SubBridge) configured to connect to a parent chain.
2. Run a malicious parent chain node that advertises the correct parent chain ID.
3. When the SubBridge connects and sends `ServiceChainParentChainInfoRequestMsg`, the malicious node responds with:
   ```go
   parentChainInfo{
       Nonce:          999999999,          // far above actual nonce
       GasPrice:       1e15,               // 1 milli-KAIA per gas unit
       KIP71Config:    params.KIP71Config{
           UpperBoundBaseFee: 1e15,        // 1 milli-KAIA per gas unit
       },
       IsMagmaEnabled: true,
   }
   ```
4. `handleParentChainInfoResponseMsg` sets `remoteGasPrice = 1e15` and `pAccount.nonce = 999999999` with no validation.
5. `genUnsignedChainDataAnchoringTx` constructs an anchoring transaction with `GasPrice = 1e15` and `Nonce = 999999999`.
6. The transaction is signed by `pAccount.SignTx` and submitted to the parent chain.
7. With `GasLimit = 100000` and `GasPrice = 1e15`, each anchoring transaction costs `100000 × 1e15 = 1e20 wei = 100 KAIA`. A parent operator with 1000 KAIA is drained in 10 anchoring cycles.
8. The nonce `999999999` causes all anchoring transactions to be permanently queued but never executed on the parent chain (nonce too high), stalling the bridge.

func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil
