### Title
`NonTransfer` proxy declares itself a superset of `Auction`/`SudoBalances` while its call filter denies calls those types admit, enabling privilege escalation via self-granted proxies - ([File: substrate/frame/staking-async/runtimes/rc/src/lib.rs])

### Summary
In the Westend-relay "rc" runtime built for `pallet-staking-async` (`substrate/frame/staking-async/runtimes/rc/src/lib.rs`), `ProxyType::is_superset` uses a catch-all `(ProxyType::NonTransfer, _) => true` [1](#0-0) , claiming `NonTransfer` is a superset of every other proxy type except `Any`. But `NonTransfer`'s own `filter` explicitly omits the entire `Sudo` pallet and only admits `Registrar::register/deregister/reserve` (excluding `swap`) [2](#0-1) , while `ProxyType::Auction`'s filter admits *any* `Registrar` call (including `swap`) [3](#0-2)  and `ProxyType::SudoBalances` admits `Sudo::sudo{Balances}` [4](#0-3) . This is precisely the bug class described in the Zulip CVE-2024-21630 report: a party is permitted to grant a capability (here, a proxy relationship) that they cannot exercise directly themselves through their own permission set.

This exact bug class was already found and fixed in `asset-hub-westend`'s `ProxyType` for the `NonTransfer`/`Governance` pair (see PR fixing issue #12724) [5](#0-4) , with regression tests added there [6](#0-5) . The `rc` staking-async runtime was not covered by that fix and still contains the unguarded catch-all.

### Finding Description
`pallet_proxy::add_proxy`/`remove_proxy`, when dispatched *through* an existing proxy relationship (`Proxy::proxy`), are gated only by `T::ProxyType::is_superset`, not by `filter`: [7](#0-6) 

Concretely: if `def.proxy_type.is_superset(new_proxy_type)` is true, the proxy is allowed to call `add_proxy`/`remove_proxy` for `new_proxy_type` regardless of what `def.proxy_type.filter()` itself permits. This is exactly the same invariant Zulip's advisory covers: an operation that grants a new relationship/permission (inviting a user; adding a proxy) must not exceed what the granter is already allowed to do directly (adding an existing user to a stream; dispatching the same call the new proxy type would allow).

In `substrate/frame/staking-async/runtimes/rc/src/lib.rs`:
- `NonTransfer.filter()` excludes `RuntimeCall::Sudo(..)` entirely and only allows three specific `Registrar` calls (`register`, `deregister`, `reserve`), explicitly excluding `swap`.
- `Auction.filter()` allows unrestricted `RuntimeCall::Registrar(..)`, which includes `swap`.
- `SudoBalances.filter()` allows `Sudo::sudo { call: Balances(..) }`.
- `is_superset` nonetheless declares `NonTransfer ⊇ Auction` and `NonTransfer ⊇ SudoBalances` via the blanket `(ProxyType::NonTransfer, _) => true` arm.

Because `NonTransfer.filter()` permits `RuntimeCall::Proxy(..)` unconditionally [8](#0-7) , a delegate holding only a `NonTransfer` proxy can dispatch `Proxy::add_proxy { delegate: <self>, proxy_type: Auction, .. }` on behalf of the real account. `pallet_proxy::add_proxy` checks `def.proxy_type.is_superset(&Auction)`, which returns `true`, so the escalation succeeds. The delegate can then directly call `Proxy::proxy(real, Some(Auction), Registrar::swap { .. })`, which `Auction.filter()` admits — even though the delegate's originally granted `NonTransfer` proxy explicitly forbids `swap`.

### Impact Explanation
`Registrar::swap` lets a parachain manager swap para IDs/lease deposits between two parachain slots — a capability deliberately withheld from `NonTransfer` proxies (per the inline comment "Specifically omitting Registrar `swap`"), presumably because it can be used to move/rearrange locked deposits and slot ownership in ways functionally similar to a value transfer. A `NonTransfer` delegate escalating to reach `swap` breaks the intended separation of that proxy type and can manipulate parachain slot/lease state the delegator never intended to expose. The `SudoBalances` escalation is less directly exploitable in practice because `pallet_sudo::sudo` further requires the dispatching account to equal the on-chain sudo key, so simply holding an `is_superset`-approved `SudoBalances` proxy relationship does not by itself grant sudo key control — but it is still a violation of the declared proxy-type lattice and a defense-in-depth failure identical in kind to the already-patched `NonTransfer`/`Governance` bug.

### Likelihood Explanation
Reachability requires only: (1) an account granting someone a `NonTransfer` proxy — a common, low-privilege delegation pattern — and (2) that delegate issuing two ordinary signed extrinsics (`add_proxy` then `proxy`). No governance, root, or validator/collator privilege is needed. This mirrors the "no privileged prerequisite" bar in the report's scoping and the exact fix pattern already applied to `asset-hub-westend`, confirming the bug class is realistic and has previously been assessed by the project as worth a patch (bumped to `patch` on `asset-hub-westend-runtime`).

### Recommendation
Apply the same fix pattern used in `asset-hub-westend` (`prdoc/pr_12769.prdoc`): remove the blanket `(ProxyType::NonTransfer, _) => true` arm in `substrate/frame/staking-async/runtimes/rc/src/lib.rs` and instead explicitly enumerate only the proxy types whose `filter` calls are fully contained within `NonTransfer`'s filter (e.g., `Governance`, `IdentityJudgement`, `CancelProxy`, `ParaRegistration`, `Staking`, `NominationPools` if their calls are indeed subsets — each needs re-verification), explicitly excluding `Auction` and `SudoBalances`. Additionally, port the lattice-consistency regression test (`proxy_type_superset_relation_matches_call_filters`) from `asset-hub-westend`'s test suite [9](#0-8)  to this runtime (and ideally to all other runtimes sharing this `ProxyType` boilerplate, e.g. `polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs`, `substrate/frame/staking-async/runtimes/parachain/src/lib.rs`) to prevent regressions.

### Proof of Concept
Not executed against a live network. Based on static analysis of the `filter`/`is_superset` implementations in `substrate/frame/staking-async/runtimes/rc/src/lib.rs` (lines 1323–1419) and the shared `pallet_proxy::do_proxy` authorization logic (`substrate/frame/proxy/src/lib.rs` lines 994–1023), the escalation path is:
1. `RealAcct` calls `Proxy::add_proxy(delegate: Attacker, proxy_type: NonTransfer, delay: 0)`.
2. `Attacker` calls `Proxy::proxy(real: RealAcct, force_proxy_type: None, call: Proxy::add_proxy { delegate: Attacker, proxy_type: Auction, delay: 0 })`. This passes `do_proxy`'s filter because `Call::add_proxy { proxy_type: Auction, .. }` requires `NonTransfer.is_superset(&Auction)`, which the catch-all arm returns `true` for.
3. `Attacker` calls `Proxy::proxy(real: RealAcct, force_proxy_type: Some(Auction), call: Registrar::swap { .. })`. `Auction.filter()` admits any `Registrar` call, so this dispatches successfully as `RealAcct`, despite `NonTransfer.filter()` explicitly excluding `swap`.

This mirrors the already-fixed and test-verified `asset-hub-westend` case [10](#0-9) , confirming the logic is a genuine reachable escalation rather than a theoretical construct — I was not able to run an actual integration test in this environment to observe the resulting state transition; a background Devin session with build/test tooling would be needed to execute a concrete `#[test]` reproduction and confirm the dispatched `Registrar::swap` succeeds end-to-end in this runtime's mock/test harness.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});
