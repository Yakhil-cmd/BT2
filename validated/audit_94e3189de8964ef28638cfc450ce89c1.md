### Title
`ProxyType::NonTransfer` falsely declares itself a superset of `ProxyType::Auction`, letting a `NonTransfer` proxy self-escalate to `Registrar::swap` - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
On the Westend and Rococo relay-chain runtimes, `ProxyType::is_superset` declares `NonTransfer` a superset of *every* other `ProxyType` (`(ProxyType::NonTransfer, _) => true`), including `ProxyType::Auction`. However, `ProxyType::Auction::filter` admits the entire `Registrar` pallet (`RuntimeCall::Registrar(..)`), while `ProxyType::NonTransfer::filter` explicitly excludes `Registrar::swap` (the code comment reads "Specifically omitting Registrar `swap`"). Because `pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` purely through `is_superset`, a delegate holding only a `NonTransfer` proxy can add themselves an `Auction` proxy for the same delegator and then invoke `Registrar::swap` on the delegator's behalf — a call the `NonTransfer` grant was deliberately designed to withhold. This mirrors the exact bug class of CVE-2021-32725 (a "reshare"/re-delegation not respecting the original grant's restricted permission set).

### Finding Description
`pallet_proxy::Pallet::do_proxy` gates `add_proxy`/`remove_proxy` sub-calls solely by `def.proxy_type.is_superset(proxy_type)`, then falls through to `def.proxy_type.filter(c)` for the outer `add_proxy` call itself: [1](#0-0) 

On Westend (and Rococo) relay-chain runtime, `ProxyType::NonTransfer` filter admits the entire `Proxy` pallet and omits only specific value-moving calls, explicitly `Registrar::swap`: [2](#0-1) 

`ProxyType::Auction` filter admits the *entire* `Registrar` pallet, i.e. including `swap`: [3](#0-2) 

Yet `is_superset` declares `NonTransfer` a superset of every other type unconditionally: [4](#0-3) 

Because `Auction.filter` admits a call (`Registrar::swap`) that `NonTransfer.filter` denies, `is_superset` violates the lattice invariant that a declared superset must admit every call its declared subset admits — the same invariant this codebase already had to fix once, for `NonTransfer`/`Governance` on asset-hub-westend: [5](#0-4) [6](#0-5) 

The identical rococo relay-chain code shows the same pattern (`NonTransfer` filter with "Specifically omitting Registrar `swap`" plus `Auction` admitting full `Registrar`, plus the blanket `is_superset` rule): [7](#0-6) [8](#0-7) 

`Registrar::swap` itself requires only that the origin be root, the para's manager, or the para itself — a normal, permissionless-to-the-owner extrinsic, reachable by any account that owns a registered `ParaId`: [9](#0-8) [10](#0-9) 

### Impact Explanation
A delegator who grants a `NonTransfer` proxy explicitly withholds `Registrar::swap` (grouped by the code's own comments alongside `Balances`, `vested_transfer`, and `Indices::transfer` as "transfer-like" actions). Because of the superset bug, any `NonTransfer` delegate can nonetheless reach `swap` by first self-granting an `Auction` proxy through the delegator's account (permitted since `NonTransfer.filter` admits the whole `Proxy` pallet and `is_superset(Auction)` wrongly returns `true`). `swap` reassigns a para's on-demand/lease-holding lifecycle status and its associated auction/crowdloan bookkeeping (`T::OnSwap::on_swap`) between two `ParaId`s. If the delegator manages more than one `ParaId` (e.g., a funded lease-holding parachain and a cheap on-demand para id), the delegate can rearrange which id carries the crowdloan-raised funds/lease, entirely bypassing an access restriction the delegator relied on. This is a genuine authorization-boundary bypass (privilege escalation within `pallet_proxy`), matching the CVE's root cause ("permissions not respected across delegation"), though the blast radius is limited to the delegator's own para management rather than direct theft of third-party funds — consistent with a Medium rating.

### Likelihood Explanation
No privileged role, governance, or stolen keys are required. The only precondition is a delegator granting a `NonTransfer` proxy (a normal, common, unprivileged operation) and owning at least one registered `ParaId`. The attacker is the proxy delegate — an account the delegator itself chose but restricted via `NonTransfer` specifically to prevent value-moving/ownership-shifting actions. The escalation path (`add_proxy(Auction)` → `proxy(force_proxy_type=Auction, Registrar::swap)`) requires only two signed extrinsics dispatched by the delegate, with normal transaction fees.

### Recommendation
Correct `ProxyType::is_superset` for the Westend and Rococo relay-chain runtimes (and any other runtime sharing this pattern, e.g. `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, which also contains the "Specifically omitting Registrar `swap`" comment and should be checked for the same `Auction` relationship) so it only declares `NonTransfer` a superset of proxy types whose filters are fully contained in `NonTransfer`'s filter — i.e., remove `Auction` (and any other type admitting `Registrar::swap` or other calls `NonTransfer` excludes) from the blanket `(ProxyType::NonTransfer, _) => true` rule, mirroring the fix already applied for `Governance` on asset-hub-westend in PR #(pr_12769). Add a lattice-consistency regression test (as already exists for asset-hub-westend) to the relay-chain runtime test suites so this class of bug cannot silently reappear on another edge.

### Proof of Concept
Verified statically via source inspection; not executed against a live network. A minimal FRAME integration reproduction (to be run against `polkadot/runtime/westend` or `rococo` test harness) would:
1. Fund account `ALICE`, have her `Registrar::reserve` + `register` two `ParaId`s (`P1`, `P2`), and elevate `P1` to lease-holding status with crowdloan funds attached (mirroring `polkadot/runtime/common/src/paras_registrar/tests.rs::swap_works`, lines 298-421, and `polkadot/runtime/common/src/integration_tests.rs::parachain_swap_works`, lines 1034+).
2. `Proxy::add_proxy(origin=ALICE, delegate=BOB, proxy_type=NonTransfer, delay=0)`.
3. As `BOB`: `Proxy::proxy(origin=BOB, real=ALICE, force_proxy_type=None, call=Proxy::add_proxy{delegate: BOB, proxy_type: Auction, delay: 0})` — expect this to succeed (asserting the bug) because `NonTransfer.is_superset(&Auction) == true` and `NonTransfer.filter` admits `Proxy::add_proxy`.
4. As `BOB`: `Proxy::proxy(origin=BOB, real=ALICE, force_proxy_type=Some(Auction), call=Registrar::swap{id: P1, other: P2})` (plus the confirming counter-swap from `P2`'s owner or via a second self-granted proxy if `ALICE` owns both) — expect it to succeed, demonstrating that a `NonTransfer`-only delegate reached a call (`Registrar::swap`) that `NonTransfer`'s own filter explicitly denies.

I did not execute this reproduction in a sandbox; the guard-bypass logic (`is_superset` vs. `filter` mismatch) and the reachability of `swap` under only owner/root/para origin are established directly from the cited source, matching exactly the pattern the repository's own `prdoc/pr_12769.prdoc` and asset-hub-westend regression tests already document and fix for a different `ProxyType` pair — confirming this is a real, previously-known bug *class* in this codebase that remains unpatched on the Westend/Rococo relay-chain runtimes. I could not locate Polkadot/Kusama mainnet runtime source in this repository snapshot to confirm or rule out the same defect there; that should be checked separately before assuming production-network impact.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

impl<T: Config> Pallet<T> {
	/// Ensure the origin is one of Root, the `para` owner, or the `para` itself.
	/// If the origin is the `para` owner, the `para` must be unlocked.
	fn ensure_root_para_or_owner(
		origin: <T as frame_system::Config>::RuntimeOrigin,
		id: ParaId,
	) -> DispatchResult {
		if let Ok(who) = ensure_signed(origin.clone()) {
			let para_info = Paras::<T>::get(id).ok_or(Error::<T>::NotRegistered)?;

			if para_info.manager == who {
				ensure!(!para_info.is_locked(), Error::<T>::ParaLocked);
				return Ok(());
			}
		}

		Self::ensure_root_or_para(origin, id)
	}
