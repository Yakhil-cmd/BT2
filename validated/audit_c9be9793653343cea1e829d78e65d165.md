### Title
Asset definer can permanently freeze all holders of a `spender_attested` asset by replacing the attestor list with non-cooperative addresses - ([File: validation.js])

### Summary
For assets that require `spender_attested`, only the definer (issuer) is authorized to update the attestor list via an `asset_attestors` message, and the only validation applied to the new list is format-level (non-empty, sorted, valid addresses, under the max count). Nothing prevents the definer from swapping the entire attestor list to addresses that will never publish attestations for any existing holder, which retroactively makes every future payment message referencing that asset fail validation, freezing all previously issued coins for everyone except the definer.

### Finding Description
`validateAttestorListUpdate` only checks that the caller is the asset's definer and that the new array passes `checkAttestorList`, which merely enforces that the list is a non-empty, sorted array of valid addresses within `MAX_ATTESTORS_PER_ASSET`: [1](#0-0) [2](#0-1) 

There is no check that the new attestors overlap with the previous attestor set, that they are reachable/known trusted entities, or that already-attested addresses remain attested going forward. This is structurally identical to the Union Finance `setWithdrawSequence()` bug: a privileged party (there, AssetManager admin; here, the asset definer) can post an unvalidated ordered/list update that renders a core downstream function ("withdraw" there, "payment"/transfer validation here) unusable for legitimate users.

The impact of an attestor-list swap is enforced at every subsequent payment validation and composition path:
- `loadAssetWithListOfAttestedAuthors` / `filterAttestedAddresses` compute `arrAttestedAddresses` strictly from the current (post-update) attestor list, and any payment whose authors/output addresses are not attested by that new list is rejected: [3](#0-2) [4](#0-3) [5](#0-4) 
- The wallet-side composer (`divisible_asset.js`) performs the same check before even attempting to compose a spend, so wallets simply fail to build a valid transaction once the definer swaps the attestor list: [6](#0-5) 

Because the attestor list update is a normal, single-message unit that any account holding the definer address can post (no special "admin" mechanism — just being the `definer_address` of the asset), and it is retroactively binding on all coins of that asset already in circulation, the definer can unilaterally and permanently disable transfers/payments of the asset for every holder by pointing `attestors` to addresses that will simply never publish `attestation` messages for those holders.

### Impact Explanation
All existing holders of a `spender_attested` asset can have their funds frozen indefinitely: any `payment` message spending or receiving that asset will fail `validateInlinePayment`/`validatePaymentInputsAndOutputs` once `arrAttestedAddresses` no longer covers their addresses. This matches the "AA fund loss or freezing" / freezing-of-user-funds impact category, since holders cannot move their asset balance at all until (if ever) the newly designated attestors choose to attest them — a decision entirely outside their control.

### Likelihood Explanation
Any account that is the `definer_address` of a `spender_attested` asset can trigger this at will by posting a single `asset_attestors` message; there is no additional signature, timelock, or validation of attestor legitimacy beyond format checks. This requires no special network position, hub cooperation, or race condition — a single privileged (but otherwise ordinary and code-reachable) unit poster action is sufficient.

### Recommendation
When processing an `asset_attestors` update, require that the new attestor list preserve backward compatibility for already-attested addresses (e.g., disallow removing all previously-active attestors in one step, or require a timelocked/multi-step transition), or expose a mechanism for holders to keep spending coins attested under a prior, still-valid attestor list for some grace period. At minimum, document/require that `spender_attested` assets are non-transferrable-safe only when the definer is trusted, and consider adding a validation rule in `checkAttestorList` (validation.js) / `validateAttestorListUpdate` that flags or restricts attestor-list replacements that would immediately invalidate 100% of the previous attestor set.

### Proof of Concept
1. Definer `D` issues asset `A` with `spender_attested: true` and initial `attestors: [X]`, where `X` regularly attests holders (e.g., via KYC).
2. Users obtain coins of asset `A` and are attested by `X` (recorded via `attestation` messages, checked in `storage.filterAttestedAddresses`).
3. `D` posts an `asset_attestors` message for asset `A` setting `attestors: [Y]`, where `Y` is an address controlled by `D` that will never issue attestations. `checkAttestorList` accepts this because `[Y]` is non-empty, sorted, and a valid address.
4. From this point on, `loadAssetWithListOfAttestedAuthors`/`filterAttestedAddresses` compute attested addresses solely against `[Y]`'s attestations (validation.js:2634-2641, storage.js:1959-1991). No existing holder is attested by `Y`, so every `payment` message for asset `A` fails with `"none of the authors is attested"` / `"some output addresses are not attested"`, permanently freezing all previously issued coins of `A`.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

function checkAttestorList(arrAttestors){
	if (!isNonemptyArray(arrAttestors))
		return "attestors not defined";
	if (arrAttestors.length > constants.MAX_ATTESTORS_PER_ASSET)
		return "too many attestors";
	var prev="";
	for (var i=0; i<arrAttestors.length; i++){
		if (!isValidAddress(arrAttestors[i]))
			return "invalid attestor address: "+JSON.stringify(arrAttestors[i]);
		if (arrAttestors[i] <= prev)
			return "attestors not sorted";
		prev = arrAttestors[i];
	}
	return null;
}

// filter only those addresses that are attested (doesn't work for light clients)
function filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAddresses, handleAttestedAddresses){
	conn.query(
		"SELECT DISTINCT address FROM attestations CROSS JOIN units USING(unit) \n\
		WHERE attestor_address IN(?) AND address IN(?) AND main_chain_index<=? AND is_stable=1 AND sequence='good' \n\
			AND main_chain_index>IFNULL( \n\
				(SELECT main_chain_index FROM address_definition_changes JOIN units USING(unit) \n\
				WHERE address_definition_changes.address=attestations.address AND main_chain_index<=? AND is_stable=1 AND sequence='good' ORDER BY main_chain_index DESC LIMIT 1), \n\
			0)",
		[objAsset.arrAttestorAddresses, arrAddresses, last_ball_mci, last_ball_mci],
		function(addr_rows){
			var arrAttestedAddresses = addr_rows.map(function(addr_row){ return addr_row.address; });
			handleAttestedAddresses(arrAttestedAddresses);
		}
	);
}

// note that light clients cannot check attestations
function loadAssetWithListOfAttestedAuthors(conn, asset, last_ball_mci, arrAuthorAddresses, bAcceptUnconfirmedAA, handleAsset){
	if (arguments.length === 5) {
		handleAsset = bAcceptUnconfirmedAA;
		bAcceptUnconfirmedAA = false;
	}
	readAsset(conn, asset, last_ball_mci, bAcceptUnconfirmedAA, function(err, objAsset){
		if (err)
			return handleAsset(err);
		if (!objAsset.spender_attested)
			return handleAsset(null, objAsset);
		filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAuthorAddresses, function(arrAttestedAddresses){
			objAsset.arrAttestedAddresses = arrAttestedAddresses;
			handleAsset(null, objAsset);
		});
	});
