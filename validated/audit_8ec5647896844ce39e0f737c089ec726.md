### Title
Webhook organization used for signature verification is never bound to the repository the handlers act on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App / webhook secret to validate a signature against using `repository_owner`, which is read from `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`). Every event handler (`Shipit::Webhooks::Handlers::Handler#repository_name` and the duplicated logic in the `PullRequest::*` handlers) instead resolves the repository to mutate using a *different* field of the same JSON body: `payload.dig('repository', 'full_name')`. Because these two fields are never compared to each other, an attacker who can produce a validly-signed payload for one configured GitHub organization can put an arbitrary `repository.full_name` belonging to a different, victim organization/stack in the same request and have the corresponding handler act on it.

### Finding Description
`Shipit.github(organization:)` in `lib/shipit.rb` supports per-organization app configuration (see `docs/setup.md`'s "Using Multiple Github Applications" section, and `test/dummy/config/secrets_double_github_app.yml`), each with its own `webhook_secret`. [1](#0-0) 

`verify_signature` picks which of these secrets to check the HMAC against solely based on `repository_owner`: [2](#0-1) 

Once the signature is accepted, `create` dispatches the raw, attacker-suppliable `params` hash to every registered handler for the event, unmodified: [3](#0-2) 

Handlers resolve the target repository from a **separate** JSON key, `repository.full_name`, with no cross-check against the `repository.owner.login`/`organization.login` value that was used to select the verifying secret: [4](#0-3) [5](#0-4) 

This is the same class of bug as the referenced governance patch: a value used to authorize/validate a request (there, `np.id`; here, the organization tied to the verified signature) is not actually bound to the value the code subsequently acts on (there, the node provider being compared; here, `repository.full_name`). The equality that should hold and is never enforced is:

`organization used to select/verify the webhook secret` == `organization embedded in the repository.full_name that the handler mutates`

Before an attacker's crafted request: for legitimate GitHub-originated webhooks, `repository.owner.login` and the owner segment of `repository.full_name` are always the same value, so the binding coincidentally holds.
After: because `WebhooksController#create` forwards the raw parsed JSON directly to handlers with no re-derivation, an attacker who legitimately controls a webhook secret for Organization B (e.g., because they are an admin of an org that this Shipit instance trusts and is configured in `secrets.github`) can send a POST to `/github/webhooks` with:
- `repository.owner.login = "OrgB"` / `organization.login = "OrgB"` (so `Shipit.github(organization: "OrgB")`'s `webhook_secret` is what verify_signature checks, and the attacker can compute a valid HMAC for it),
- `repository.full_name = "OrgA/victim-repo"` (a repository/stack belonging to a completely different, unrelated organization).

The signature check passes because it is scoped to `OrgB`, yet `Handler#stacks`/`PullRequest::*#repository` will resolve and mutate `OrgA/victim-repo`'s `Stack`/`ReviewStack` records.

### Impact Explanation
Handlers acting on the wrongly-resolved repository can archive/unarchive review stacks, trigger `sync_github`/deploy-relevant state changes (`PushHandler`), or forge commit statuses (`StatusHandler`, which doesn't even scope by repository, compounding the issue) for a stack that belongs to an organization the attacker never authenticated against. This crosses the "cross-repository writes" / "unauthorized deploy or rollback" impact bar because state mutations that should be exclusively controllable by GitHub events from `OrgA` can be triggered by anyone possessing valid webhook credentials for `OrgB` only.

### Likelihood Explanation
Exploitation requires the attacker to control (or know the webhook secret for) at least one organization configured in this Shipit instance's multi-org `secrets.github` map — a realistic scenario for any Shipit deployment that serves multiple organizations, since each org's admins/CI infra know their own `webhook_secret` but should have no authority over other tenants' repositories. No GitHub App private key, `ApiClient` token, or Shipit session is required, only the ability to POST directly to the public `/github/webhooks` endpoint with a self-computed HMAC.

### Recommendation
In `WebhooksController#verify_signature` and/or `Shipit::Webhooks::Handlers::Handler`, enforce that the organization used to select/verify the webhook signature is the same organization embedded in every repository field the handler subsequently reads (`repository.full_name`'s owner segment and, where present, `organization.login`). Reject the request (422) if they diverge, rather than trusting `repository.full_name` unconditionally once any org's signature has verified.

### Proof of Concept
1. Deploy this engine with two organizations configured, `OrgA` and `OrgB`, each with its own `webhook_secret` (as in `test/dummy/config/secrets_double_github_app.yml`).
2. As an attacker who is an admin of `OrgB` (and thus knows `OrgB`'s `webhook_secret`, e.g., because they configured the GitHub App/webhook themselves), craft a `pull_request` (or `push`) payload body:
```json
{
  "action": "closed",
  "number": 1,
  "pull_request": { ... valid stub fields ... },
  "repository": { "owner": { "login": "OrgB" }, "full_name": "OrgA/victim-repo" },
  "sender": { "login": "attacker" }
}
```
3. Compute `X-Hub-Signature: sha1=<hmac-sha1(OrgB_webhook_secret, body)>` and set `X-Github-Event: pull_request`.
4. POST to `/github/webhooks`. `verify_signature` resolves `Shipit.github(organization: "OrgB")` and accepts the signature.
5. `ClosedHandler#repository` resolves `Repository.from_github_repo_name("OrgA/victim-repo")`, and `review_stack.archive!` is invoked on `OrgA`'s stack — a write the attacker was never authorized to trigger. [6](#0-5)

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
```
