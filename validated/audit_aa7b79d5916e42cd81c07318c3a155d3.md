### Title
Webhook signature verification is bound to the payload's `repository.owner.login`, but event handlers act on the payload's `repository.full_name` — an unauthenticated organization can forge events for any other repository's stack ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App / HMAC secret to check the request against using `repository_owner`, taken from the attacker-controlled JSON field `repository.owner.login` (or `organization.login`) [1](#0-0) [2](#0-1) . Once that check passes, `create` dispatches the *entire raw payload* to every registered handler for the event [3](#0-2) , and every handler resolves the target repository/stack independently from `payload.dig('repository', 'full_name')` [4](#0-3) . Nothing enforces that `repository.owner.login` and `repository.full_name` refer to the same repository — they are two independent, attacker-supplied strings in the same JSON body.

### Finding Description
Shipit supports multiple GitHub Apps, one per organization, each with its own `webhook_secret` [5](#0-4) . Crucially, `verify_webhook_signature` treats an organization with **no configured `webhook_secret`** as automatically verified:

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
``` [6](#0-5) 

The binding that should hold is: `organization used to select/verify the HMAC signature == organization that owns the repository the handlers act on`. In practice these are two separately-read JSON fields from the *same unauthenticated request*:
- Verification side: `repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [2](#0-1) 
- Execution side: `repository_name = payload.dig('repository', 'full_name')`, used to resolve `Repository.from_github_repo_name(repository_name)` and its stacks [4](#0-3) [7](#0-6) 

Because the controller only checks the signature against the organization named in `repository.owner.login`, an attacker who controls (or is granted) an organization entry in `secrets.github` that has no `webhook_secret` set can submit a forged webhook whose `repository.owner.login` is that unprotected organization (satisfying `verify_signature` trivially, since `webhook_secret` is blank) while setting `repository.full_name` to any other organization/repository actually tracked by Shipit. The handler layer never re-checks that the two fields agree — it blindly trusts `full_name` to select the stack(s) to act on.

This is the same binding-break pattern as the SwapPool flashloan report: a value the verification step covers (`repository.owner.login`) is not the value the execution step acts on (`repository.full_name`), letting an attacker satisfy the "cheap" side of the check while causing effects on the "expensive"/protected side.

### Impact Explanation
Handlers triggered by forged events perform state-changing actions on stacks belonging to repositories the attacker does not control, without any GitHub App private key, webhook secret, session, or API token. For example, `PushHandler#process` calls `stack.sync_github(expected_head_sha: params.after)` for every non-archived stack of the victim repository matching the forged branch [8](#0-7) , and other handlers (status, merge, pull_request, membership) act similarly on `stacks` resolved the same insecure way [4](#0-3) . Depending on which handlers are registered/enabled (push syncing revision state, commit status updates gating continuous deployment, merge-request handlers), this can desynchronize deployed-revision tracking or unblock/trigger automated deploys — an authentication bypass on the webhook trust boundary that leads to an unauthorized deploy path.

### Likelihood Explanation
Requires an operator to have configured at least one organization in `secrets.github` without a `webhook_secret` (or an attacker being able to get such an org registered) while other organizations/repositories in the same instance are properly protected. This is a plausible misconfiguration in multi-tenant/multi-org Shipit deployments (e.g., a test or staging org added without a secret), but it depends on that specific configuration state rather than being universally exploitable against any correctly-configured single-secret Shipit instance.

### Recommendation
Bind signature verification to the exact repository being acted upon, not merely its claimed owner: derive `repository_owner` from `repository.full_name` split, or better, re-validate that `repository.owner.login` matches the owner segment of `repository.full_name` before dispatching to handlers. Additionally, disallow (or fail closed on) organizations configured without a `webhook_secret` — never treat a blank secret as an implicit "verified" signature; require every configured organization to have a non-blank secret, and reject events for organizations that don't.

### Proof of Concept
1. Shipit instance has orgs `victim-org` (webhook_secret set) and `unsecured-org` (no `webhook_secret`) both present in `secrets.github`, with `unsecured-org` mapped to no HMAC secret.
2. Attacker POSTs to `/github_webhooks` (or engine-mounted webhook path) with header `X-Github-Event: push` and no valid `X-Hub-Signature`, body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "unsecured-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. `verify_signature` computes `repository_owner = "unsecured-org"`, fetches its `GitHubApp` (no `webhook_secret`), and `verify_webhook_signature` returns `true` unconditionally [9](#0-8) .
4. `create` dispatches the payload to `PushHandler`, which resolves `repository_name = "victim-org/victim-repo"`, finds the real `Repository`/stacks, and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` [8](#0-7)  — all without ever presenting a valid signature for `victim-org`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
