The OpenClaw advisory describes a stateful, session-based authorization bug: a WebSocket gateway server updates a credential store (revoking a device token) but does not proactively terminate an already-established, long-lived connection that was authenticated under the old credential — so the session keeps working until it naturally reconnects.

This bug class does not have a structural analog in Polkadot SDK's runtime/FRAME architecture, for several reasons:

- FRAME extrinsic dispatch is stateless per-call: authorization for privileged operations like `pallet_proxy` is re-checked against current on-chain storage on every single call via `Self::find_proxy(&real, &who, force_proxy_type)`, which reads live `Proxies::<T>` storage. [1](#0-0) 
There is no "already-authenticated session" that persists independently of storage the way a WebSocket connection does — removing a proxy via `remove_proxy_delegate` mutates `Proxies::<T>` immediately, and the very next `proxy` call will fail because `find_proxy` no longer finds the entry, with no intervening window of stale authorization. [2](#0-1) 

- Node networking layers (libp2p notifications behaviour, connection lifecycle) do model connection/session state machines, but these govern peer-to-peer gossip/consensus traffic, not user-authenticated privileged dispatch, and disconnection there is driven by the `ProtocolController`/peerset rather than any credential-revocation semantics analogous to a device token. [3](#0-2) 

- The closest "session" abstraction in the codebase is the RPC `SubscriptionManagement`/`RpcConnections` used by `chainHead_follow`, which does track per-connection subscription state and unregisters on drop. [4](#0-3) 
However, this is client-side JSON-RPC infrastructure, not a signed extrinsic, contract call, or XCM message — it has no on-chain wiring, no fee/authorization boundary reachable by an unprivileged attacker in the sense required by the scan method (no runtime state mutation, no theft/issuance/dispatch impact), so it falls outside the scope of a Polkadot SDK runtime security finding.

There is no real user-facing FRAME/XCM entry point where authorization is cached in a long-lived out-of-band session that persists past an on-chain revocation of that authorization — every dispatch path re-validates against current storage. This makes the OpenClaw bug class fundamentally inapplicable to the FRAME/XCM runtime model as instructed ("do not force an EVM/unrelated analogy").

	pub fn remove_proxy_delegate(
		delegator: &T::AccountId,
		delegatee: T::AccountId,
		proxy_type: T::ProxyType,
		delay: BlockNumberFor<T>,
	) -> DispatchResult {
		Proxies::<T>::try_mutate_exists(delegator, |x| {
			let (mut proxies, old_deposit) = x.take().ok_or(Error::<T>::NotFound)?;
			let proxy_def = ProxyDefinition {
				delegate: delegatee.clone(),
				proxy_type: proxy_type.clone(),
				delay,
			};
			let i = proxies.binary_search(&proxy_def).ok().ok_or(Error::<T>::NotFound)?;
			proxies.remove(i);
			let new_deposit = Self::deposit(proxies.len() as u32);
			if new_deposit > old_deposit {
				T::Currency::reserve(delegator, new_deposit - old_deposit)?;
			} else if new_deposit < old_deposit {
				T::Currency::unreserve(delegator, old_deposit - new_deposit);
			}
			if !proxies.is_empty() {
				*x = Some((proxies, new_deposit))
			}
			Self::deposit_event(Event::<T>::ProxyRemoved {
				delegator: delegator.clone(),
				delegatee,
				proxy_type,
				delay,
			});
			Ok(())
		})
	}
