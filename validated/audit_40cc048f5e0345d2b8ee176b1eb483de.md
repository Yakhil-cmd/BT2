### Title
Webhook Signature Verification Selects Auth Org From `repository.owner.login` While Handlers Act On `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
Shipit's multi-tenant webhook signature verification looks up the HMAC secret to use for a webhook based on `repository.owner.login` (or `organization.login`) taken directly from the unverified JSON body, but the handlers that actually mutate Shipit state look up the target `Stack`/`Repository` using a *different* field from the same unverified body: `repository.full_name`. Nothing binds these two attacker-controlled fields together, and any org configured without a `webhook_secret` makes signature verification a no-op for that org, so an attacker can "authenticate" as a low-value/secret-less org while writing to any repository tracked by Shipit.

### Finding Description
`WebhooksController#verify_signature` selects which GitHub App/secret to verify against using a value pulled straight out of the still-unverified raw POST body: [1](#0-0) [2](#0-1) 

`GithubApp#verify_webhook_signature` trivially returns `true` whenever the selected org has no `webhook_secret` configured: [3](#0-2) 

This "no secret configured" state is an explicitly supported/shipped configuration, not an edge case — the example multi-org config leaves `webhook_secret` blank for orgs: [4](#0-3) 

Once `verify_signature` passes (or is skipped for a secret-less org), `WebhooksController#create` dispatches to handlers using the *same unverified body*: [5](#0-4) 

Handlers do not re-check the org used for authentication; they independently resolve the target repository from `repository.full_name`: [6](#0-5) 

`PushHandler` then forces every matching `Stack` on the resolved branch to sync against an attacker-chosen `after` SHA: [7](#0-6) 

The binding that should hold is: `organization authenticated (repository.owner.login used to pick webhook_secret) == organization that owns the repository actually written (repository.full_name used by Handler#stacks)`. Because both values are independent, attacker-controlled fields inside the same unverified JSON payload, this equality is never enforced by the code, only assumed.

### Impact Explanation
An attacker who knows (or controls) any org configured in the Shipit instance with a blank/absent `webhook_secret` can craft a payload where `repository.owner.login` (or `organization.login`) names that secret-less org, while `repository.full_name` names a *different*, fully protected, victim repository tracked by Shipit. The request passes `verify_signature` unconditionally (`return true unless webhook_secret`), and the `PushHandler` then walks `Repository.from_github_repo_name(victim_full_name)` and calls `stack.sync_github(expected_head_sha: params.after)` on the victim stack — an unauthenticated write to state (and indirectly commit-tracking) of a repository the attacker was never authorized to touch. Depending on stack configuration (e.g., continuous deployment enabled), this can drive the sync/merge pipeline toward attacker-chosen commits, i.e., an effectively unauthorized state mutation of a stack the attacker has no credentials for — matching the High-impact class "escalation into authorization boundaries / unauthenticated write to stack state."

### Likelihood Explanation
Exploitation requires no privileged account, no `ApiClient` token, and no valid webhook secret for the victim repo — only knowledge that some org in the Shipit install has no `webhook_secret` configured (a common, documented configuration state, as shown in the example secrets file) and the target's `full_name`, which is public information for any GitHub repo. This is a realistic no-privilege attacker precondition, consistent with the class of "authenticated organization vs. repository actually written" bindings called out as in-scope.

### Recommendation
Bind the verified organization to the repository being acted upon: after selecting `github_app` for `repository_owner`, require that `repository.full_name`'s owner matches `repository_owner` (or, better, resolve the target `Repository`/`Stack` first and verify the signature using *that* repository's owning organization's secret, rejecting the request if they diverge). Additionally, disallow orgs with no `webhook_secret` from being treated as "always verified" — require an explicit secret for every configured organization, or restrict processing to events whose declared repository owner matches an org with a real secret.

### Proof of Concept
1. Shipit is configured with two orgs: `secretless-org` (no `webhook_secret` set) and `victim-org` (tracks `victim-org/victim-repo` as a Shipit stack, protected by a real secret unknown to the attacker).
2. Attacker sends a `push` webhook to `/webhooks`:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "secretless-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
with header `X-Github-Event: push` and an arbitrary/garbage `X-Hub-Signature`.
3. `verify_signature` calls `Shipit.github(organization: "secretless-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the signature header.
4. `Shipit::Webhooks.for_event('push')` invokes `PushHandler`, which resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on the victim stack — a state-mutating action on a repository the attacker never had signature-verified access to.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
```
