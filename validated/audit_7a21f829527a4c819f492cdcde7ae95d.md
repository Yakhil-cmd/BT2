### Title
Webhook signature verified against the organization named in the payload, not the repository the event actually mutates - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary

### Finding Description
`WebhooksController#verify_signature` selects which GitHub App/organization webhook secret to HMAC-verify the request against using a field pulled straight out of the untrusted, attacker-suppliable JSON body: [1](#0-0) 

```
repository_owner (used to pick the secret) = params.dig('repository','owner','login') || params.dig('organization','login')
``` [2](#0-1) 

But the actual handlers that mutate state pick the target `Stack`/`Repository` using a *different* field of the same untrusted body — `repository.full_name`: [3](#0-2) [4](#0-3) 

`Repository.from_github_repo_name` splits this string on `/` and does a straight `find_by(owner:, name:)` lookup with no cross-check against `repository.owner.login`: [5](#0-4) 

`Shipit.github(organization:)` resolves the webhook secret purely from the `organization` key looked up in `config/secrets.yml`, one secret per configured GitHub App/org: [6](#0-5) [7](#0-6) 

The equality that should hold, but is never enforced, is:
`organization whose secret authenticated the request == owner of the repository the handler writes to`.

An attacker who controls (or has compromised) a GitHub App installed on **organization A** (i.e., knows org A's `webhook_secret`) can build an arbitrary JSON body where `repository.owner.login = "org-a"` (so `verify_signature` validates the HMAC against org A's secret) while `repository.full_name = "org-b/target-repo"` (an entirely different, unrelated repository/stack hosted under organization B in the same Shipit instance). Because the HMAC only proves "this body was signed with org A's secret," not "this body's `full_name` belongs to org A," the forged, validly-signed webhook is processed by handlers (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, `MembershipHandler`, etc.) against `org-b/target-repo`'s stacks.

### Impact Explanation
This breaks the binding "GitHub organization that authenticated the webhook" vs. "repository the engine actually writes to" — the exact class of trust-binding violation called out in the rules (organization authenticated vs. repository written). Concretely:
- `PushHandler` would trigger `stack.sync_github(expected_head_sha:)` for a stack belonging to an unrelated org/repo, based entirely on forged data, causing unsynchronized/incorrect deploy state, which can feed into unauthorized deploy/rollback flows since Shipit trusts synced SHAs as legitimate GitHub state.
- `MembershipHandler` mutates `Team`/`Membership` records scoped by the `organization` field, and since only the secret-selection field is checked against org A while the same payload's other org-scoped identifiers can be independently crafted, team membership for org B could be manipulated by someone only holding org A's secret.
This qualifies under the "escalation into `Shipit.github_teams` authorization" / cross-repository-write High-impact bucket.

### Likelihood Explanation
Requires the attacker to control/know one organization's `webhook_secret` (e.g., via a compromised or intentionally malicious GitHub App the operator installed on any one of the multiple orgs configured in a multi-org Shipit deployment) but crucially does **not** require credentials for the target organization/repo being attacked. Multi-org GitHub App configuration is a documented, supported configuration (`config/secrets.yml` with multiple orgs, `github_default_organization`), and the test suite even demonstrates constructing payloads with independently settable `repository.owner.login` vs. other fields (see `webhooks_controller_test.rb` `repository_params`), showing the two fields are treated as decoupled by the code path.

### Recommendation
In `WebhooksController`, after signature verification, assert that `repository_owner` (used to select the secret) equals the owner segment parsed from `repository.full_name` (and from `organization.login` for membership events) before dispatching to handlers; reject with 422 on mismatch. Alternatively, derive the repository/stack lookup exclusively from the same field used for secret selection.

### Proof of Concept
1. Configure Shipit with two GitHub Apps/orgs, `org-a` and `org-b`, each with its own `webhook_secret` (multi-org config supported by `lib/shipit.rb#github_organizations`).
2. As the holder of `org-a`'s `webhook_secret` (e.g., a malicious GitHub App owner installed innocuously on org-a), construct a push payload:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "org-a" },
    "full_name": "org-b/target-repo"
  }
}
```
3. Compute `X-Hub-Signature` as `sha1=` + `HMAC-SHA1(org-a's webhook_secret, raw_body)`.
4. POST to `/webhooks` with `X-Github-Event: push`.
5. `verify_signature` resolves `Shipit.github(organization: "org-a")` and validates successfully.
6. `PushHandler#stacks` resolves `Repository.from_github_repo_name("org-b/target-repo")` and calls `sync_github` on org-b's stacks — despite the request never being signed by org-b's secret.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
