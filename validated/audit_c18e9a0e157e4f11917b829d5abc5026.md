This confirms the enforcement path: `RuleEngine.evaluate_rules` in `plugins/hookify/core/rule_engine.py` decides blocking vs. warning strictly by checking `rule.action == 'block'` [1](#0-0) , and only emits `permissionDecision: deny` (or `decision: block` for Stop) if the rule landed in `blocking_rules` [2](#0-1) . So whatever `Rule.action` ends up being after parsing directly controls whether "Deny means deny" holds.

### Title
Ambiguous-indentation frontmatter causes `extract_frontmatter` to silently drop `action`/`enabled`, downgrading `block` rules to `warn` - (File: plugins/hookify/core/config_loader.py)

### Summary
`extract_frontmatter` in `plugins/hookify/core/config_loader.py` is a hand-rolled, non-YAML-compliant parser that only recognizes keys at `indent == 0` (top-level) or `indent > 2` (dict-item continuation inside a list). Any frontmatter line whose leading whitespace is 1 or 2 spaces (e.g. `action: block` accidentally indented by one or two spaces, or written directly at the boundary of a list-item continuation) matches none of the parser's branches and is silently discarded, so `Rule.from_dict` falls back to its default `action="warn"` (or `enabled=True`), turning an intended block rule into a no-op/warn-only rule with no error or warning emitted anywhere in the load path.

### Finding Description
The call chain is `load_rules()` → `load_rule_file()` → `extract_frontmatter()` → `Rule.from_dict()`, all in [3](#0-2) .

`extract_frontmatter` classifies every non-empty frontmatter line into exactly three buckets:
1. `indent == 0 and ':' in line and not line.strip().startswith('-')` → top-level key [4](#0-3) 
2. `stripped.startswith('-') and in_list` → list item [5](#0-4) 
3. `indent > 2 and in_dict_item and ':' in line` → continuation of a multi-line dict item under a list [6](#0-5) 

There is no `else` branch — any line falling in the gap `1 <= indent <= 2` (or any line with `indent > 2` while `in_dict_item` is `False`) is silently ignored; the loop just moves to the next line without recording the key anywhere and without raising any error. Because `Rule.from_dict` uses defaults (`frontmatter.get('action', 'warn')`, `frontmatter.get('enabled', True)`) [7](#0-6) , a dropped `action: block` key silently becomes `action == "warn"`, and a dropped `enabled: false` key silently becomes `enabled == True`.

An attacker who can commit a `.claude/hookify.{name}.local.md` file into a repository the victim clones can therefore write frontmatter like:
```
---
name: block-rm
enabled: true
event: bash
pattern: "rm -rf"
 action: block
---
```
where `action: block` has a single leading space. `indent` for that line is `1`, which satisfies none of the three branches, so `action` is never stored in the `frontmatter` dict. `Rule.action` then defaults to `"warn"`. `load_rule_file` reports no warning because `frontmatter` is non-empty (the check at [8](#0-7)  only checks for an empty dict), and the rule loads "successfully" — just silently downgraded. `RuleEngine.evaluate_rules` then routes the match into `warning_rules` instead of `blocking_rules`, so the dangerous `Bash`/`Edit` operation is allowed with only a `systemMessage`, never a `permissionDecision: deny` [9](#0-8) .

No schema validation, comparison against a real YAML parser, or strict-mode check exists anywhere in this path to catch the divergence — `load_rules`'s exception handling in [10](#0-9)  only guards against I/O and type errors, not semantic parsing drift, and none of these branches raise for unrecognized indentation.

### Impact Explanation
A rule author (or, more concerningly, an attacker seeding a `.claude/hookify.*.local.md` file into a shared/cloned repo) can craft a rule that appears to declare `action: block` for a dangerous `Bash rm -rf` or credential-file `Edit` pattern, but which the loader silently treats as `warn`-only. Anyone relying on the rule (e.g. a maintainer who reviewed the `.md` file and believed it enforced a hard block, as referenced by `plugins/pr-review-toolkit/agents/silent-failure-hunter.md`) gets a false sense of protection: the dangerous Bash/Edit operation is allowed to execute with only a cosmetic warning message instead of being denied. This is a violation of the "deny means deny" invariant for hookify's block enforcement.

### Likelihood Explanation
The precondition is narrow but realistic: the attacker needs write access to files under a repo's `.claude/` directory that the victim will subsequently load rules from (e.g. via a malicious PR adding/modifying a `hookify.*.local.md` file, or a typo/formatting slip by a legitimate rule author that goes unnoticed because there is no validation or lint step). Because the bug is purely whitespace-driven and requires no special crafting beyond off-by-one/two space indentation, it is trivially reproducible and easy to miss in code review since the frontmatter still "looks like" valid YAML to a human reader.

### Recommendation
Replace the hand-rolled line-based parser in `extract_frontmatter` with a real YAML parser (e.g. `yaml.safe_load` on the frontmatter block) for correctness, or, if the custom parser must be kept, add an explicit `else` branch that raises/logs a hard error (and fails closed, i.e. treats the rule as unparseable rather than defaulting to `warn`) whenever a non-empty line does not match any recognized indentation pattern. Additionally, `Rule.from_dict` should not silently default `action` to `"warn"` when frontmatter parsing encountered any unrecognized line — the loader should surface a fatal warning and skip loading the rule (fail closed) instead of silently downgrading it.

def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules


def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule

    except (IOError, OSError, PermissionError) as e:
        print(f"Error: Cannot read {file_path}: {e}", file=sys.stderr)
        return None
    except (ValueError, KeyError, AttributeError, TypeError) as e:
        print(f"Error: Malformed rule file {file_path}: {e}", file=sys.stderr)
        return None
    except UnicodeDecodeError as e:
        print(f"Error: Invalid encoding in {file_path}: {e}", file=sys.stderr)
        return None
    except Exception as e:
        print(f"Error: Unexpected error parsing {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
        return None
