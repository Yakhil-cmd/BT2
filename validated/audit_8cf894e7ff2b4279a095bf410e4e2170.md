### Title
Webhook signature verification can be bypassed by spoofing the payload's organization to select an unconfigured `webhook_secret`, allowing unauthenticated cross-organization webhook forgery - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`)

### Summary
`WebhooksController#verify_signature` picks *which* `GitHubApp`/`webhook_secret` to verify a webhook against using a field taken from the **same untrusted request body** it is about to verify, and `GitHubApp#verify_webhook_signature` silently treats a missing `webhook_secret` as "verification passed." An attacker can therefore choose which organization's key material is used for verification independently of which repository/stack the webhook payload actually mutates, breaking the binding between "the organization that authenticated the request" and "the repository that is written by the handlers."

### Finding Description
`WebhooksController` runs `verify_signature` as a `before_action`: [1](#0-0) 

```
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
``` [1](#0-0) 

`repository_owner` is derived purely from the JSON body the attacker sends: [2](#0-1) 

That value selects which `GitHubApp` instance (and thus which `webhook_secret`) is used to check the HMAC. In `GitHubApp#verify_webhook_signature`: [3](#0-2) 

```
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [3](#0-2) 

If **any** configured organization has no `webhook_secret` set (an explicitly supported/optional setting per the setup docs and the example secrets file, which lists `webhook_secret: # nil` for multiple orgs), then choosing that organization's name as `repository.owner.login` makes verification trivially return `true`, regardless of the actual signature header sent.

After this check passes, `create` re-parses the raw body and dispatches it to the registered handlers using whatever `repository`/`full_name` is embedded in the payload — completely decoupled from the `repository_owner` value used to select the (unsecured) verification key: [4](#0-3) 

This breaks the equality that should hold: `organization used to verify signature == organization whose repository/stack is mutated by the handler`. An attacker can spoof `repository.owner.login` to point at a no-secret-configured org while setting `repository.full_name` (and other fields such as `sha`, `state`, `context`, `ref`, `after`) to target a stack belonging to a different, properly-configured (secret-protected) organization. Handlers such as `PushHandler` (queues `GithubSyncJob`/sync of arbitrary branch state) and the status handler (creates arbitrary commit `Status` records) then act on forged, unauthenticated data for that unrelated stack.

### Impact Explanation
This is an authentication-boundary break: the HMAC signature check that is supposed to gate all webhook processing can be routed to a non-existent/blank secret by an unauthenticated attacker, letting them submit arbitrary, unsigned payloads that are processed as if they came from GitHub. Depending on which stacks/organizations exist:
- Forged `status` events can inject fabricated CI success statuses for arbitrary commits. If a stack has `continuous_deployment` enabled and `ci.require` matching the forged context, this can result in an **unauthorized deploy** of a commit that never actually passed CI — the highest impact tier (unauthorized deploy).
- Forged `push`/`check_suite`/`membership` events can pollute stack sync state, commit history tracking, and team/user membership records for repositories the attacker does not control.

### Likelihood Explanation
The primary precondition is that at least one configured GitHub organization in `secrets.yml`/`credentials` has a blank `webhook_secret` — a state the documentation explicitly calls "optional" and the shipped example config demonstrates (`webhook_secret: # nil`). In any Shipit deployment serving multiple GitHub orgs where even one org's secret was left unset (e.g., a lower-priority or newly-added org), this becomes exploitable by any unauthenticated party who can reach `/webhooks`.

### Recommendation
- Do not select the verification key from attacker-controlled payload content; verify against the specific stack/repository being targeted, or require a `webhook_secret` for every configured organization (fail closed, not open, when a secret is missing).
- Change `verify_webhook_signature` to fail (return `false`) rather than `true` when `webhook_secret` is blank, or make `webhook_secret` mandatory and reject configuration without it.
- After signature verification, ensure the organization used for verification is checked to actually match `repository.owner.login`/`full_name` acted upon by the handlers before dispatching.

### Proof of Concept
1. Configure Shipit with two organizations in `secrets.yml`: `victim-org` (has `webhook_secret` set) and `attacker-org` (no `webhook_secret`, i.e., blank/nil — a documented "optional" state).
2. POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" },
  "sha": "<victim-commit-sha>",
  "state": "success",
  "context": "ci/required-check",
  "branches": [{ "name": "main" }]
}
```
No valid `X-Hub-Signature` is required, because `Shipit.github(organization: "attacker-org")` resolves to a `GitHubApp` whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally (`app/controllers/shipit/webhooks_controller.rb:25-30`, `lib/shipit/github_app.rb:76-83`).
3. The request passes `verify_signature`, and `create` dispatches the raw payload (targeting `victim-org/victim-repo`) to the status handler, injecting a forged commit status for the victim repository — with no valid signature ever presented for `victim-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
