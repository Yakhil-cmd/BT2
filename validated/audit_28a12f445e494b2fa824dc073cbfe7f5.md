**Reasoning:**

The premise requires that WebAuthn/secp256r1/multisig authenticator identity be determined by comparing `type_name`/`to_canonical_string()` output strings. That is not how admission-path authenticator identification works in this codebase.

1. **Authenticator/signature-scheme identity is resolved via Rust enum pattern matching, not string comparison.** `AnySignature` and `AnyPublicKey` are native Rust enums, and dispatch (e.g., in `AnySignature::verify`) matches directly on enum variants such as `Self::WebAuthn { signature }` vs `AnyPublicKey::Secp256r1Ecdsa`, never on a canonical-string representation of a Move `TypeTag`. [1](#0-0) [2](#0-1) 

2. **`native_type_name`/`to_canonical_string()` is a Move-level reflection utility**, exposed through `aptos-move/framework/natives/src/type_info.rs`'s `native_type_name`, and used by Move framework/library code (e.g. `coin.move`, `aggregator_v2.move`, `config_buffer.move`) for on-chain type reflection — not for authenticator, WebAuthn, multisig, or approval-set identification anywhere in the transaction-admission path. [3](#0-2) 

3. **The canonical string function carries an explicit uniqueness invariant that is enforced by property-based testing.** `TypeTag::to_canonical_string` is documented with "INVARIANT: If two type tags are different, they must have different canonical strings," and this is asserted directly by a `proptest` (`test_to_canonical_string_is_unique`) that fuzzes up to 100 random `TypeTag`s and fails the build if any two distinct tags produce the same canonical string. [4](#0-3) [5](#0-4) 

Because (a) the actual authenticator/approval-set checks never key off `type_name` strings, and (b) the canonical string format is structurally injective by construction (fully-qualified address::module::name plus recursively canonical, delimiter-safe type arguments) and is verified against collisions in tests, an unprivileged attacker cannot construct a distinct `StructTag`/`TypeTag` that collides with a trusted authenticator type string in a way that corrupts sender/signer/approval-set binding at transaction admission. The scenario described does not have a real code path in this repository's admission stack.

impl TypeTag {
    /// Returns a canonical string representation of the type tag.
    ///
    /// INVARIANT: If two type tags are different, they must have different canonical strings.
    pub fn to_canonical_string(&self) -> String {
        use TypeTag::*;

        match self {
            Bool => "bool".to_owned(),
            U8 => "u8".to_owned(),
            U16 => "u16".to_owned(),
            U32 => "u32".to_owned(),
            U64 => "u64".to_owned(),
            U128 => "u128".to_owned(),
            U256 => "u256".to_owned(),
            I8 => "i8".to_owned(),
            I16 => "i16".to_owned(),
            I32 => "i32".to_owned(),
            I64 => "i64".to_owned(),
            I128 => "i128".to_owned(),
            I256 => "i256".to_owned(),
            Address => "address".to_owned(),
            Signer => "signer".to_owned(),
            Vector(t) => format!("vector<{}>", t.to_canonical_string()),
            Struct(s) => s.to_canonical_string(),
            Function(f) => f.to_canonical_string(),
        }
    }
