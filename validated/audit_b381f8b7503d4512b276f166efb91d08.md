### Title
Largest-remainder ("Hare") signer-weight rounding is exploitable by fragmenting locked STX across multiple signer keys, letting an attacker capture more reward-slot weight than a single lock of the same total would receive - ([File: stackslib/src/chainstate/nakamoto/signer_set.rs])

### Summary
`pox_5_make_signer_set` aggregates stacked amounts only by `signer_key` [1](#0-0) , then apportions `reward_slots` of weight using floor division plus a largest-remainder ("Hare") top-up that grants at most one extra weight unit per *entry* in the map, not per underlying beneficial owner [2](#0-1) . Because `protocol-bond-memberships` is keyed by `principal` (one membership per principal) [3](#0-2) , an attacker who controls several of their own Stacks principals and assigns each principal a distinct `signer_key` can split one economic stake into N sub-threshold entries, each of which independently competes for — and can win — a leftover Hare slot, yielding total weight greater than `floor(total_ustx_locked/threshold)+1`.

### Finding Description
The intended invariant is: for a single beneficial staker with total locked amount `A` under threshold `T`, their credited weight should be bounded by `floor(A/T) + 1` (one base allotment plus at most one "fairness" rounding slot, per the code's own comment and the property test `check_make_signer_set` assertion `weight in {base, base+1}` per entry) [4](#0-3) .

The apportionment logic:
1. Sums `amount_ustx` per `signer_key` into a `HashMap`, with no aggregation across different keys belonging to the same real owner [5](#0-4) .
2. Computes `base_weight = stacked_amt / threshold` and `remainder = stacked_amt % threshold` per signer_key [6](#0-5) .
3. Distributes `leftover = reward_slots - sum(base_weight)` slots one-per-entry, sorted by descending remainder [7](#0-6) .

**Exploit path**: Suppose threshold `T = 1000` and an attacker's true total locked stake is `1999` uSTX (as verified in the single-entry case, this alone can already win at most `weight=2`, i.e., `base 1 + 1 leftover`, per the code's documented degenerate-avoidance design). If instead the attacker locks that `1999` through 3 separate principals/`stack-stx` calls (each principal has its own single `protocol-bond-memberships` entry, satisfiable because that map is keyed by principal, not a global identity check), and assigns each a *distinct* `signer_key`, with per-key amounts `700`, `700`, `599`:
- Each entry's `base_weight = amount/1000 = 0` (all three floor to 0, contributing `0` to global `base`, versus `1` if kept as a single lock).
- Each entry's `remainder` equals its full amount (`700`, `700`, `599`) — all large fractions of `T`.
- If these remainders outrank other honest signers' remainders, the attacker wins **up to 3 separate leftover slots** (one per split key) instead of the single leftover slot a non-split lock could win, netting total weight `3` for a true locked value of `1999`, versus the `2`-slot cap that applies to a single signer_key holding the same amount.

This directly breaks the equality "weight assigned == STX locked" (scaled by threshold) for the attacker's combined position, because the Hare round's "one extra slot" fairness guarantee is enforced **per map entry (signer_key)**, not per beneficial owner. Splitting stake below `threshold` across many self-controlled signer keys converts what would be counted toward the entry's `base_weight` into zero, shifting that share into the global `leftover` pool and simultaneously creating additional independent lottery tickets (one remainder-slot competition per split key) for the same attacker to win, at the expense of honest signers since total weight is capped by `reward_slots` globally [8](#0-7) .

**Why existing guards don't stop it**: There is no aggregation of `amount_ustx` across different `signer_key`s belonging to the same STX principal, and no aggregation across different principals belonging to the same real-world attacker (which is inherently unenforceable on-chain). `protocol-bond-memberships` limits one lock per principal [3](#0-2) , but an attacker trivially controls multiple principals with their own STX, satisfying the "unprivileged attacker with own STX" threat model. No `<=` guard, reentrancy check, or prepare-phase gate in `pox_5_compute_and_update_signers` / `pox_5_make_signer_set` constrains per-owner weight; the function only sees disjoint `signer_key`s and has no notion of "true owner."

### Impact Explanation
The attacker gains signing weight (i.e., reward-slot / block-signing power in the `.signers` contract) that is not fully backed by their locked STX, matching the "High - signing weight or reward slots exceeding locked value" category. Because total weight across all signers is capped at `reward_slots`, the extra weight the attacker wins is taken directly from the pool that would otherwise be distributed to honest signers with genuinely larger remainders — i.e. this is a direct redistribution of signing power away from honest stakers to the attacker without a corresponding increase in the attacker's locked STX. This is repeatable every reward-cycle recomputation, as long as the attacker re-splits their lock across sufficiently many principals/keys each cycle.

### Likelihood Explanation
Preconditions: the attacker needs (a) multiple Stacks principals they control (trivial, unprivileged), (b) the ability to choose an arbitrary `signer_key` per principal when locking via pox-5 (a normal, permitted stacking parameter), and (c) their split amounts' remainders to outrank other signers' remainders in that cycle (achievable by choosing amounts close to, but under, `threshold`, maximizing remainder to near-100%). No special cycle phase or membership state is required beyond normal stacking. Cost is limited to the STX being locked (which the attacker already intends to lock) plus transaction fees for additional stacking calls — feasible and repeatable every cycle.

### Recommendation
Aggregate `amount_ustx` for Hare-round remainder purposes by the true beneficial owner where determinable (e.g., aggregate by the stacking principal / bond membership before mapping to `signer_key`, and only sum by `signer_key` after that aggregation), or cap the number of leftover slots any single principal-controlled set of signer keys can win in one cycle. Alternatively, disallow splitting a bond membership's locked amount across more than one `signer_key` per principal, and require any additional bonds from the same underlying source of funds (e.g., same L1 lockup UTXO owner) to reuse the same `signer_key`.

### Proof of Concept
Extend `check_make_signer_set` / add a targeted unit test in `stackslib/src/chainstate/nakamoto/tests/signer_set.rs`:
1. Set `pox_constants` so `reward_slots() = R` and pick `threshold = T` (e.g., via `test_pox_constants` to fix `T=1000`).
2. Case A (no split): one `RawPox5Entry { signer_key: k, amount_ustx: 1999 }`. Run `pox_5_make_signer_set`; record `weight_A = signer_set[0].weight`. Assert `weight_A <= 1999/1000 + 1 = 2`.
3. Case B (split): three entries `{k1,700}, {k2,700}, {k3,599}` (summing to the same `1999`), constructed so their remainders dominate other filler signers' remainders (add enough dummy signers with small remainders to consume the rest of `reward_slots` without outranking the split entries). Run `pox_5_make_signer_set`; compute `weight_B = sum of weight over {k1,k2,k3}`.
4. Assert the violation: `weight_B > 1999/1000 + 1` (i.e., `weight_B == 3 > 2`), demonstrating that splitting the identical locked total across signer keys increases total credited weight beyond the single-entry bound, while `total_ustx_locked` and `threshold` are unchanged — breaking the weight-to-locked-STX equality for the attacker's combined position.
