### Title
Liveness/readiness endpoint never reverts to "not ready," causing consumers to trust stale data indefinitely - (File: main.go)

### Summary
`git-sync`'s HTTP liveness endpoint reports "ready" (HTTP 200) purely based on a one-shot, monotonic boolean flag (`repoReady`) that is set to `true` after the first successful sync and is never reset to `false`, even when all subsequent sync attempts fail. This is directly analogous to the reported Nabla bug: a "freshness" signal (price feed staleness / repo readiness) is trusted by downstream consumers without any mechanism enforcing that the underlying data is actually current, allowing stale data to be treated as valid indefinitely.

### Finding Description
The main sync loop calls `setRepoReady()` once `git.SyncRepo` succeeds for the first time [3](#0-2) . `setRepoReady()` unconditionally flips the package-level `repoReady` boolean to `true` and there is no corresponding "un-ready" call anywhere in the codebase [1](#0-0) .

When a sync fails, the loop only increments `failCount`, logs the error, and — only if `failCount` reaches `--max-failures`/`--init-max-failures` — calls `os.Exit(1)` [4](#0-3) . If `--max-failures` is left at its default (or set to a large/negative "retry forever" value, which is an explicitly documented and supported configuration [5](#0-4) ), the process keeps retrying forever without exiting and without ever un-setting `repoReady`.

Meanwhile, the HTTP handler serves 200 for any request as long as `getRepoReady()` returns `true`, and only returns 503 when it is `false` [6](#0-5) . Once the first sync succeeds, this handler will report "ready" for the remainder of the process's life, regardless of how long or how badly subsequent syncs have been failing (e.g., due to a remote-side change such as force-pushed history that breaks `fsck`/connectivity checks in `sanityCheckWorktree` [7](#0-6) , transient network partitions to the git remote, or credential/auth failures).

This is structurally the same bug class as the Nabla report: a "freshness/currency" guarantee that downstream consumers rely on (price data being fresh vs. repo/link content being current) is actually enforced by a stale, one-way flag rather than a live check tied to the most recent sync outcome.

### Impact Explanation
Kubernetes readiness/liveness probes and other consumers commonly gate traffic routing or app startup decisions on this endpoint. If it always reports "ready" after the first successful sync, an application container relying on this signal will keep serving from a directory (`--link`) whose content has stopped updating — potentially for an unbounded period — without any external signal indicating the sidecar has degraded. This can result in the application silently operating on stale/outdated configuration or code (published wrong/partial or outdated content being trusted as current), which was explicitly listed as an acceptable impact category (publishing wrong or partial content / persistent sync denial masked as healthy).

### Likelihood Explanation
Likelihood is moderate-to-low: it requires either (a) an operator/consumer configuration where `--max-failures` is negative or high ("retry forever" is a documented, legitimate use case) combined with (b) a subsequent failure condition. That failure condition can be triggered from attacker-controlled repo content, e.g. a history rewrite or a poisoned commit that causes `git fsck --connectivity-only` to start failing in `sanityCheckWorktree`/`sanityCheckRepo` [8](#0-7) , or any push that breaks subsequent fetch/checkout while a previous good sync already flipped `repoReady` to `true`.

### Recommendation
Track readiness as a function of the current sync loop's health, not a monotonic latch: reset `repoReady` to `false` when a sync attempt fails (or after N consecutive failures / after exceeding some staleness age), and expose the last-successful-sync timestamp so the liveness endpoint can enforce a max-age freshness check analogous to `priceMaxAge` in the original report, rather than relying on a "sync ever succeeded once" flag.

### Proof of Concept
1. Start `git-sync` with `--max-failures=-1` (retry forever) against a valid repo; wait for the first successful sync — `repoReady` becomes `true` and `curl http://<bind>/` returns `200`.
2. Make the upstream repo/ref subsequently unfetchable/unusable for `git-sync` (e.g., force-push a history rewrite that fails `git fsck --connectivity-only`, or block network access to the remote), causing every following `SyncRepo` call to return an error.
3. Continue polling `curl http://<bind>/` — it keeps returning `200 OK` indefinitely (`getRepoReady()` still `true`), even though `--link` has not advanced and the sync loop has been failing continuously, confirmed by `assert_metric_eq "${METRIC_GOOD_SYNC_COUNT}"` staying flat and `METRIC_SYNC_COUNT{key=error}` climbing (metrics wiring in `updateSyncMetrics` [9](#0-8) ) — while the liveness check gives no indication of the outage.

// repoReady indicates that the repo has been synced.
var readyLock sync.Mutex
var repoReady = false

func getRepoReady() bool {
	readyLock.Lock()
	defer readyLock.Unlock()
	return repoReady
}

func setRepoReady() {
	readyLock.Lock()
	defer readyLock.Unlock()
	repoReady = true
}

// sanityCheckRepo tries to make sure that the repo dir is a valid git repository.
func (git *repoSync) sanityCheckRepo(ctx context.Context) bool {
	git.log.V(3).Info("sanity-checking git repo", "repo", git.root)
	// If it is empty, we are done.
	if empty, err := dirIsEmpty(git.root); err != nil {
		git.log.Error(err, "can't list repo directory", "path", git.root)
		return false
	} else if empty {
		git.log.V(3).Info("repo directory is empty", "path", git.root)
		return false
	}

	// Check that this is actually the root of the repo.
	if root, _, err := git.Run(ctx, git.root, "rev-parse", "--show-toplevel"); err != nil {
		git.log.Error(err, "can't get repo toplevel", "path", git.root)
		return false
	} else {
		root = strings.TrimSpace(root)
		if root != git.root.String() {
			git.log.Error(nil, "repo directory is under another repo", "path", git.root, "parent", root)
			return false
		}
	}

	// Consistency-check the repo.  Don't use --verbose because it can be
	// REALLY verbose.
	if _, _, err := git.Run(ctx, git.root, "fsck", "--no-progress", "--connectivity-only"); err != nil {
		git.log.Error(err, "repo fsck failed", "path", git.root)
		return false
	}

	// Check if the repository contains an unreleased lock file. This can happen if
	// a previous git invocation crashed.
	if lockFile, err := hasGitLockFile(git.root); err != nil {
		git.log.Error(err, "error calling stat on file", "path", lockFile)
		return false
	} else if len(lockFile) > 0 {
		git.log.Error(nil, "repo contains lock file", "path", lockFile)
		return false
	}

	return true
}

// sanityCheckWorktree tries to make sure that the dir is a valid git
// repository.  Note that this does not guarantee that the worktree has all the
// files checked out - git could have died halfway through and the repo will
// still pass this check.
func (git *repoSync) sanityCheckWorktree(ctx context.Context, worktree worktree) bool {
	git.log.V(3).Info("sanity-checking worktree", "repo", git.root, "worktree", worktree)

	// If it is empty, we are done.
	if empty, err := dirIsEmpty(worktree.Path()); err != nil {
		git.log.Error(err, "can't list worktree directory", "path", worktree.Path())
		return false
	} else if empty {
		git.log.V(0).Info("worktree is empty", "path", worktree.Path())
		return false
	}

	// Make sure it is synced to the right commmit.
	stdout, _, err := git.Run(ctx, worktree.Path(), "rev-parse", "HEAD")
	if err != nil {
		git.log.Error(err, "can't get worktree HEAD", "path", worktree.Path())
		return false
	}
	if stdout != worktree.Hash() {
		git.log.V(0).Info("worktree HEAD does not match worktree", "path", worktree.Path(), "head", stdout)
		return false
	}

	// Consistency-check the worktree.  Don't use --verbose because it can be
	// REALLY verbose.
	if _, _, err := git.Run(ctx, worktree.Path(), "fsck", "--no-progress", "--connectivity-only"); err != nil {
		git.log.Error(err, "worktree fsck failed", "path", worktree.Path())
		return false
	}

	return true
}
