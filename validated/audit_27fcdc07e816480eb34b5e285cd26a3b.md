### Title
Webhook signature verification uses a different organization key than the repository the handlers act on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and therefore which `webhook_secret`) to authenticate the request against based on `repository_owner`, computed as `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. Every downstream `Webhooks::Handlers::Handler` instead resolves the repository/stack to mutate using `payload.dig('repository', 'full_name')` [1](#0-0) . These two fields of the same untrusted JSON body are never checked for consistency, so the "organization that authenticated" is not bound to equal "the repository that is written."

### Finding Description
`verify_signature` reads `repository_owner` straight out of the unauthenticated request body and uses it to pick the `GitHubApp` config, hence the `webhook_secret` used for HMAC verification: [2](#0-1) [3](#0-2) 

Shipit explicitly supports multiple GitHub organizations, each with an independent `webhook_secret` in `secrets.yml` [4](#0-3) , and the shipped example configs leave `webhook_secret` blank/nil by default [5](#0-4) . When `webhook_secret` is blank for a given org, `verify_webhook_signature` short-circuits to `true` unconditionally, so no signature is required at all for that organization: [6](#0-5) 

Once `verify_signature` passes (because the org picked via `repository.owner.login` happens to have no secret configured), the actual event handler resolves the target repository independently, from `repository.full_name`: [7](#0-6) [8](#0-7) 

Because `repository.owner.login` (used to select the authenticating org) and `repository.full_name` (used to select the repository/stack that is written) are independent fields of the same attacker-supplied JSON body, an attacker can set `repository.owner.login` to an org with no `webhook_secret` configured while setting `repository.full_name` to any other, fully-secured org/repo tracked by the same Shipit instance. Verification passes trivially (no secret to check against), yet the handler acts on the unrelated, protected repository's stack.

### Impact Explanation
This breaks the deployment-trust binding "an organization that authenticated versus the repository that is written," as called out explicitly in-scope. Concretely, for the `push` event, `PushHandler#process` enqueues `GithubSyncJob` for the victim stack with an attacker-chosen `expected_head_sha` [8](#0-7) , and `GithubSyncJob#perform` fetches commits via the victim org's real GitHub App credentials and appends them to the stack, unlocking reverted commits and re-triggering `CacheDeploySpecJob` [9](#0-8) . On stacks with continuous delivery/deployment enabled, syncing new commits from an attacker-controlled trigger can cause an unauthorized deploy to fire without any legitimate GitHub webhook from the affected org/repo, and without the attacker possessing any `webhook_secret`, `ApiClient` token, or GitHub credentials for the targeted org.

### Likelihood Explanation
Exploitability depends entirely on the deployment configuration: it requires a multi-organization Shipit install (explicitly documented and supported) where at least one configured organization has no `webhook_secret` set — which is the out-of-the-box default in every shipped example config. This is not a hypothetical edge case; it is the default state unless an operator explicitly sets a secret for every org, and Shipit ships multi-org examples that leave the field blank. An unauthenticated network attacker who knows (a) that a target Shipit instance tracks a given org/repo and (b) any second configured org name (which may be discoverable via error messages, e.g. the "unknown organization" logging path) can exploit it without holding any credential.

### Recommendation
Bind the two checks together: derive the repository/stack that handlers act on from the *same* field that was authenticated, or verify that `repository.owner.login` (or `organization.login`) matches the owner segment of `repository.full_name` before dispatching to handlers. Additionally, treat a missing `webhook_secret` as "reject the request" rather than "skip verification," or require an explicit opt-in flag to run without webhook signature verification, so a misconfigured/unconfigured organization cannot be used as an authentication bypass for unrelated, properly-secured organizations sharing the same Shipit instance.

### Proof of Concept
1. Configure Shipit with two organizations in `secrets.yml`: `Victim` (has `webhook_secret` set) and `Attacker-visible-org` (no `webhook_secret`, e.g. left as the shipped default `# nil`) [5](#0-4) .
2. Shipit tracks a `Victim/private-repo` stack with continuous delivery enabled.
3. Attacker (no token, no secret) sends:
   ```
   POST /webhooks
   X-Github-Event: push
   {
     "ref": "refs/heads/main",
     "after": "<attacker-chosen-sha-that-exists-upstream>",
     "repository": {
       "owner": { "login": "Attacker-visible-org" },
       "full_name": "Victim/private-repo"
     }
   }
   ```
4. `verify_signature` resolves `Shipit.github(organization: "Attacker-visible-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` with no signature check [6](#0-5) .
5. `PushHandler#process` resolves `stacks` via `payload.dig('repository','full_name')` = `Victim/private-repo`, finds the matching stack, and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")`, enqueuing a real sync/potential deploy trigger for the `Victim` repository the attacker never authenticated against [7](#0-6) [8](#0-7) .

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
```
