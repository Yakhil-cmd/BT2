### Title
`kip71.gastarget` Governance Parameter Accepts Zero — Division-by-Zero Panic in `NextMagmaBlockBaseFee` Halts Block Production - (File: `params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter uses `noopFormatChecker`, which accepts any `uint64` value including `0`. When `GasTarget == 0` is ratified and takes effect, every subsequent call to `NextMagmaBlockBaseFee()` panics with a division-by-zero, crashing all nodes that attempt to produce or verify a Magma-era block. This halts the chain entirely.

---

### Finding Description

In `kaiax/gov/param.go`, the `Kip71GasTarget` parameter definition uses `noopFormatChecker`, which unconditionally returns `true` for any canonical value:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // ← accepts 0
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

This contrasts with `Kip71BaseFeeDenominator`, which explicitly rejects `0`:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // ← zero rejected
    },
``` [2](#0-1) 

In `params/kip71_config.go`, `NextMagmaBlockBaseFee()` uses `gasTarget` as a divisor in two places with no zero-guard:

```go
gasTarget := kc.GasTarget   // could be 0 after governance vote
...
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // L102: panics if gasTarget==0
...
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // L120: panics if gasTarget==0
``` [3](#0-2) 

The `BaseFeeDenominator` zero-case is explicitly handled with a fallback to `64` (lines 71–76), but no equivalent guard exists for `GasTarget`. The `big.Int.Div` method panics on a zero divisor in Go.

The `checkConsistency` function in `kaiax/gov/headergov/impl/header.go` places `gov.Kip71GasTarget` in the default no-op branch, performing no additional validation: [4](#0-3) 

---

### Impact Explanation

`NextMagmaBlockBaseFee()` is called in three critical production paths:

1. **Block mining** — `work/worker.go` line 382: `pset.ToKip71Config().NextMagmaBlockBaseFee(...)` — the miner panics before producing any block.
2. **Block header verification** — `params/kip71_config.go` line 50 via `VerifyMagmaHeader()` — every importing node panics when verifying any new block.
3. **Tx pool reset** — `blockchain/tx_pool.go` line 576 — the tx pool update panics on every new head. [5](#0-4) [6](#0-5) [7](#0-6) 

Once the governance change takes effect (at the next epoch boundary), all honest validators crash on every block attempt. The chain halts: no KAIA transfers, no reward distributions, no state transitions are possible until the parameter is corrected via a new governance vote — which itself requires block production to proceed.

---

### Likelihood Explanation

- In **`none` governance mode** (any validator can vote), any single validator can cast a vote for `kip71.gastarget = 0`. In a network with `none` mode, this is a low-privilege trigger.
- In **`single` governance mode** (Mainnet), only the governing node can vote, making this a semi-trusted trigger. However, the code vulnerability is present regardless of governance mode.
- The vote passes `NewVoteData` format checks (since `noopFormatChecker` accepts 0) and `checkConsistency` (no cross-parameter check for `GasTarget`), so it is ratified without any on-chain rejection.

---

### Recommendation

Add a non-zero check to the `FormatChecker` for `Kip71GasTarget`, mirroring the existing check for `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v > 0   // reject zero
    },
    ...
},
```

Additionally, add a defensive zero-guard in `NextMagmaBlockBaseFee()` analogous to the existing `BaseFeeDenominator` guard (lines 71–76):

```go
if kc.GasTarget == 0 {
    // fallback to avoid panic; base fee stays at current level
    return makeEvenByFloor(parentBaseFee)
}
gasTarget := kc.GasTarget
```

---

### Proof of Concept

1. On a Magma-enabled network in `none` governance mode, any validator calls `governance_vote("kip71.gastarget", 0)`.
2. The vote is accepted by `NewVoteData` (passes `noopFormatChecker`) and ratified at the next epoch block.
3. Starting from `(epoch+1)*epoch` block, `GetParamSet()` returns `GasTarget = 0`.
4. The miner calls `pset.ToKip71Config().NextMagmaBlockBaseFee(parent.Number(), parent.Header().BaseFee, parent.GasUsed())`.
5. Inside `NextMagmaBlockBaseFee`: `gasTarget = 0`, `parentGasUsed > 0` (any non-empty block), so the `parentGasUsed > gasTarget` branch is taken.
6. `x.Div(x, new(big.Int).SetUint64(0))` → **panic: division by zero**.
7. All validators crash. Chain halts.

	}
