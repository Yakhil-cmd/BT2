**Analysis:** The `on_new_epoch` function in `epoch_timeout_config.move` is declared `public(friend)`, restricting its callers exclusively to `aptos_framework::reconfiguration_with_dkg`, and it further asserts the passed-in signer via `system_addresses::assert_aptos_framework(framework)` before doing anything else. [1](#0-0)  The `friend` declaration limits the module's callable surface to that one trusted module. [2](#0-1) 

There is no public API in this file, or reachable from it, that lets an unprivileged account obtain a `&signer` for `@aptos_framework` via any "capability-store read." The only entry points that take a signer for governance/config updates (`initialize`, `set_for_next_epoch`) themselves call `system_addresses::assert_aptos_framework`, which aborts unless the signer's address is literally `@aptos_framework`. [3](#0-2)  This is confirmed by the existing unit test `non_framework_signer_cannot_set`, which shows that any non-framework signer attempting to call these APIs aborts with `system_addresses`'s permission-denied error. [4](#0-3) 

Additionally, `on_new_epoch` is invoked only from the trusted reconfiguration path (`reconfiguration_with_dkg.move`), which runs as part of validator/system-driven block prologue reconfiguration logic, not as a result of any unprivileged user transaction, REST/BCS input, or authenticator flow. There is no capability, resource, or store in this file whose leakage or misuse could substitute a capability-derived `@aptos_framework` signer for a directly authenticated sender in the transaction-admission path (mempool, vm-validator, authenticator, multisig, sponsor, or secondary-signer handling). The exploit hypothesis presupposes a "leaked-but-unprivileged capability-store read" API that does not exist in this module or its friend chain.

Since the finding requires either a privileged signer (which this module already strictly gates) or an unprivileged capability-derivation path that isn't present, and since this module plays no role in transaction admission (mempool/vm-validator/authenticator/multisig/sponsor binding), it does not meet the Admission Impact Gate criteria.
