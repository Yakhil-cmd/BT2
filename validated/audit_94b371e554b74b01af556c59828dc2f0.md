### Title
Liquidation with penalty bonus can increase (worsen) a borrower's LTV instead of improving it - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The `liquidate` flow in `v0-4-market.clar` computes the debt to repay and collateral to seize using a linear formula that always adds a liquidator bonus (`liq-penalty`) on top of the repaid debt value, without ever verifying that the resulting post-liquidation LTV is lower than the pre-liquidation LTV. This mirrors the root cause of the referenced Inverse Finance finding (`[M-10]`): liquidation is not guaranteed to make the borrower healthier, and at high enough LTV it provably makes the position *unhealthier*, letting an unprivileged liquidator worsen a stranger's position and push additional bad debt onto the lender pool through `socialize-debt-asset`.

### Finding Description
`liquidate` computes:
- `liq-penalty` via `calc-liquidation-params` → `calc-liq-factor-bound`, scaled between `LIQ-PENALTY-MIN` and `LIQ-PENALTY-MAX` (`mainnet/contracts/market/v0-4-market.clar:739-756`).
- `coll-usd-expected = debt-actual-usd * (BPS + liq-penalty) / BPS` in `calc-liq-collateral-repay` (`mainnet/contracts/market/v0-4-market.clar:726-729`), i.e. the liquidator always seizes `debt_repay * (1 + penalty)` in collateral value.
- If the borrower has enough collateral, `coll-actual == coll-expected` and `debt-final == debt-actual` (no proportional shrink) in `calc-final-liquidation-amounts` (`mainnet/contracts/market/v0-4-market.clar:834-853`).

Let `D` = total debt USD, `C` = total collateral USD, `p` = `liq-penalty` (bps), `r` = `debt_repay/D` = `liq-pct-scaled` (the fraction of debt liquidated). After liquidation:
- `D' = D(1-r)`
- `C' = C - D*r*(1+p)`

New LTV `D'/C'` is lower than old LTV `D/C` **only if** `C > D*(1+p)`, i.e. only if `current_ltv < 1/(1+p)`. When `current_ltv >= 1/(1+p)` (which is reachable well below 100% LTV — e.g. with a 10% max penalty this threshold is ~90.9%, and the code explicitly allows `LTV-LIQ-FULL` egroup thresholds and graduated liquidation up to and beyond that boundary, `mainnet/contracts/market/v0-4-market.clar:701-719` `calc-liq-factor`/`calc-liq-factor-bound`), the liquidation strictly *increases* LTV: the borrower is left with proportionally less collateral relative to remaining debt than before. No check anywhere in `liquidate` (`mainnet/contracts/market/v0-4-market.clar:1382-1585`) compares pre- and post-liquidation LTV/health, unlike the recommended fix adopted by Inverse Finance.

This is not solely a self-harm situation: the borrower (victim) does not choose to be liquidated — any unprivileged third party (the liquidator) can call `liquidate` on the borrower's position (`(borrower principal)` is an arbitrary address argument, `mainnet/contracts/market/v0-4-market.clar:1383`) and drive their LTV higher, setting up the position for repeat liquidations that erode collateral faster than debt, ultimately exhausting collateral and triggering `no-collateral-left` → `socialize-debt-asset` (`mainnet/contracts/market/v0-4-market.clar:879-901`, invoked at `local-testing/contracts/market/market.clar:1567-1571`), which writes down the debt across the lending pool — harming lenders who did not participate in the transaction.

### Impact Explanation
This lands on **temporary/permanent freezing and loss of funds** for two distinct unprivileged parties beyond the caller:
1. The borrower's collateral is depleted disproportionately fast relative to debt reduction, accelerating them into insolvency faster than a correctly-designed liquidation curve would, directly caused by a third-party (liquidator) call.
2. The resulting bad debt is socialized onto all suppliers of the debt asset via `vault-socialize-debt`/`socialize-debt-asset`, a loss imposed on lenders who did not cause and could not prevent the triggering liquidation.

This matches the Impact criteria for **Critical (protocol insolvency / theft of funds at rest)** since cascading unhealthy liquidations increase realized bad debt beyond what sound liquidation math would produce, directly reducing pooled lender funds.

### Likelihood Explanation
Likelihood depends on the deployed egroup parameters for `LTV-LIQ-PARTIAL`, `LTV-LIQ-FULL`, `LIQ-PENALTY-MIN`, `LIQ-PENALTY-MAX` (defined per-egroup in `v0-egroup.clar` / set via `v0-init.clar`). I was not able to confirm the exact production values before running out of tool calls, so I cannot state with certainty how close `LTV-LIQ-FULL` sits to the `1/(1+liq_penalty_max)` unsafe boundary in the live deployment. However, the vulnerability is structural — it exists in the math for *any* nonzero `liq-penalty` once LTV crosses `1/(1+p)`, and the graduated curve (`curve-exponent`, `calc-liq-factor-exp`) explicitly targets exactly the region near `LTV-LIQ-FULL`, which is the highest-LTV (most dangerous) region where this effect is strongest. Given typical liquidation bonuses (5–10%) and full-liquidation thresholds often set at 90–98% in comparable protocols, this boundary is very plausibly within the normal liquidatable range.

### Recommendation
In `liquidate` (`mainnet/contracts/market/v0-4-market.clar:1382-1585`), compute LTV (or health factor) both before and after the collateral/debt mutation and assert the post-liquidation LTV is not worse than the pre-liquidation LTV (mirroring the Inverse Finance fix: revert when the combination of collateral factor / LTV thresholds and liquidation penalty would make debt unhealthier or permit profitable self-liquidation). Concretely, enforce at egroup-configuration time (in `v0-egroup.clar`) that `LTV-LIQ-FULL <= BPS*BPS/(BPS+LIQ-PENALTY-MAX)` so that `1+liq-penalty` never exceeds `1/current_ltv` for any liquidatable position, and/or add an explicit runtime assertion comparing `current-ltv` computed before and after mutation inside `liquidate`.

### Proof of Concept
Numeric example: `liq-penalty = 1000` bps (10%), `D = 100`, `C = 105` (LTV = 95.2%, within a plausible `LTV-LIQ-FULL` band). Full liquidation (`r=1`, per `calc-liq-factor` capped at BPS when at/above `LTV-LIQ-FULL`):
- `debt_repay = 100`
- `coll_seized = 100 * 1.10 = 110 > C(105)` → capped at `coll-actual = 105` (`process-collateral-asset`, `mainnet/contracts/market/v0-4-market.clar:820-823`)
- `calc-final-liquidation-amounts` recalculates `debt-final-usd = coll-actual-usd * BPS/(BPS+p) = 105/1.10 = 95.45`
- Result: `D' = 100 - 95.45 = 4.55`, `C' = 0`. Borrower left with debt and zero collateral → immediately triggers bad-debt socialization.

Even before full depletion, intermediate partial liquidations at `LTV ∈ (1/(1+p), LTV-LIQ-FULL)` strictly raise `D'/C'` above `D/C` per the derivation above, since `debt_repay*(1+p) > debt_repay/current_ltv` in that region — each liquidator call worsens, rather than improves, the borrower's health, exactly the "unhealthier after liquidation" pattern from the cited report. ;; Calculate liquidation factor: ((ltv-curr - ltv-liq-partial) * BPS) / (ltv-liq-full - ltv-liq-partial)
;; Capped at BPS (100%) to prevent over-liquidation
(define-private (calc-liq-factor (ltv-curr uint) (ltv-liq-partial uint) (ltv-liq-full uint))
  (min BPS (div-bps-down (- ltv-curr ltv-liq-partial) (- ltv-liq-full ltv-liq-partial))))

;; Apply curve exponent for graduated liquidation
;; liq-factor = liq-factor^alpha
(define-private (calc-liq-factor-exp (factor uint) (exp uint))
  (if (is-eq exp BPS) 
    factor
    (if (> exp BPS) 
        (/ (pow factor (/ exp BPS)) (pow BPS (- (/ exp BPS) u1)))
        (sqrti (* factor BPS))))) ;; assume factor^0.5

;; Scale penalty between min and max using liquidation factor
;; liq-penalty = liq-penalty-min + (liq-factor * (liq-penalty-max - liq-penalty-min) / BPS)
;; Capped at bound-max to handle cases where liq-factor > BPS
(define-private (calc-liq-factor-bound (liq-factor uint) (bound-min uint) (bound-max uint))
  (min bound-max (+ bound-min (mul-bps-down liq-factor (- bound-max bound-min)))))

;; Calculate debt to repay based on liquidation factor
;; debt-repay = liq-factor * debt / BPS
(define-private (calc-liq-debt-repay (debt uint) (liq-factor uint)) 
  (mul-bps-down liq-factor debt))

;; Calculate collateral to seize (includes liquidator bonus)
;; collateral-repay = debt-repay * (BPS + liq-penalty) / BPS
(define-private (calc-liq-collateral-repay (debt-repay uint) (liq-penalty uint)) 
  (mul-bps-down debt-repay (+ BPS liq-penalty)))

;; Calculate actual debt repayment when collateral is capped
;; debt-repay-real = (collateral-amount-usd * BPS) / (BPS + liq-penalty)
(define-private (calc-liq-debt-repay-real (collateral-amount-usd uint) (liq-penalty uint)) 
  (div-bps-down collateral-amount-usd (+ BPS liq-penalty)))

  (debt-actual-usd uint)
  (liq-penalty uint)

    id: uint, addr: principal, decimals: uint,

    collateral: bool, debt: bool, price: uint
  }))

    id: uint, addr: principal, decimals: uint,

    collateral: bool, debt: bool
  }))

        (coll-asset-info (match (find-asset coll-aid assets)
                           ;; Found in enabled list: use it (already has price)
                           found found

        (coll-expected (mul-div-down coll-usd-expected (pow u10 coll-decimals) coll-price))

        (coll-actual (if (> coll-expected user-coll-balance)
                         user-coll-balance
                         coll-expected)))
    {
      coll-actual: coll-actual,
      coll-expected: coll-expected,
      coll-price: coll-price,
      coll-decimals: coll-decimals
    }))

  (debt-actual-usd uint)
  (coll-actual uint)
  (coll-expected uint)

  (coll-decimals uint)
  (debt-price uint)
  (debt-decimals uint)

      debt-final-usd: debt-final-usd,

                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc

            (scaled-debt (get scaled debt-entry)))

                                      debt-remove-scaled

(define-public (liquidate
                (borrower principal)
                (collateral-ft <ft-trait>)
                (debt-ft <ft-trait>)
                (debt-amount uint)
                (min-collateral-expected uint)
                (collateral-receiver (optional principal))
                (price-feeds (optional (list 3 (buff 8192)))))
  (let (
    (feeds-check (try! (write-feeds price-feeds)))
    (liquidator contract-caller)
    (position (try! (get-liquidation-position borrower)))
    (pos-full (try! (get-full-position borrower)))
    (mask (get mask position))
    (group (try! (get-egroup mask)))

    (coll-address (contract-of collateral-ft))
    (debt-address (contract-of debt-ft))
    (coll-asset (try! (get-asset coll-address)))
    (debt-asset (try! (get-asset debt-address)))
    (coll-aid (get id coll-asset))
    (debt-aid (get id debt-asset))

    ;; accrue FIRST - populates cache for zToken price resolution
    (u-debt (accrue-user-debts (get debt pos-full)))
    (u-coll (accrue-user-collateral (get collateral pos-full)))

    ;; NOW safe to resolve prices (cache is populated)
    (assets (get-assets mask))
    (notional-valued-assets (get-notional-evaluation { position: position, assets: assets }))
    (total-collateral-usd (get collateral notional-valued-assets))
    (total-debt-usd (get debt notional-valued-assets))

    ;; LTC thresholds, liq params, health
    (ltv-liq-partial (buff-to-uint-be (get LTV-LIQ-PARTIAL group)))
    (ltv-liq-full (buff-to-uint-be (get LTV-LIQ-FULL group)))
    (liq-penalty-min (buff-to-uint-be (get LIQ-PENALTY-MIN group)))
    (liq-penalty-max (buff-to-uint-be (get LIQ-PENALTY-MAX group)))
    (curve-exponent (buff-to-uint-be (get LIQ-CURVE-EXP group)))

    ;; LTV = (debt x 10,000) / collateral
    ;; handle edge case: If collateral = 0, return max LTV (BPS) or 0 if debt also 0
    (current-ltv   (if (is-eq total-collateral-usd u0)
                       (if (is-eq total-debt-usd u0) u0 BPS)
                       (mul-div-down total-debt-usd BPS total-collateral-usd)))
    
    ;; Oracle frontrunning protection: prevent same-block liquidation
    ;; This blocks flash-loan based attacks where user borrows + gets liquidated in same block
    (last-borrow-block (get last-borrow-block position))
    (same-block-check (asserts! (not (is-eq last-borrow-block stacks-block-height)) ERR-LIQUIDATION-BORROW-SAME-BLOCK))

    ;; health check (FAIL-FAST) 
    ;; Check position is liquidatable BEFORE calling calc-liq-factor
    (health-check  (asserts! (>= current-ltv ltv-liq-partial) ERR-HEALTHY))
