### Title

Supply-index floor resurrects wiped supplier claims after bad-debt cleanup - (File: `contracts/pool/src/interest.rs`)

### Summary

`apply_bad_debt_to_supply_index` correctly caps bad debt at the market’s total supplied value, but then clamps the resulting supply index upward to `SUPPLY_INDEX_FLOOR_RAW`. A total loss therefore leaves every supplier share with `0.1%` of its original claim instead of zero. After a permissionless `clean_bad_debt`, a wiped-out supplier can wait for fresh liquidity and withdraw this phantom claim, draining assets belonging to later suppliers.

### Finding Description

Bad-debt cleanup is permissionless through `Controller::clean_bad_debt(caller, account_id)` when an insolvent account’s remaining collateral is at or below the dust threshold. [1](#0-0)  The cleanup submits each borrow position as a `PoolSeizeEntry`, and the pool converts the scaled debt to a RAY asset value, applies it to the supply index, and burns the debt. [2](#0-1) 

The vulnerable sequence is:

```rust
let capped = bad_debt.min(total_supplied_value);
let remaining = total_supplied_value.checked_sub(cache.env(), capped);
let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
let new_supply_index = cache.supply_index().mul_floor(cache.env(), reduction_factor);
cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
``` [3](#0-2) 

When `bad_debt >= total_supplied_value`, `capped` equals the supplied value and `new_supply_index` is zero. The `.max(SUPPLY_INDEX_FLOOR_RAW)` operation then raises it to `RAY / 1000`, preserving a claim equal to approximately `scaled_amount * 0.001`. This is the same class as the reported issue: a computed entitlement that should be capped at zero/total entitlement is instead allowed to retain value because an upper bound on the final claim is missing. [4](#0-3) 

Withdrawal unscales the stored supply shares using this inflated floor index and pays the floored asset amount. [5](#0-4)  The production test demonstrates that an old position receives a positive withdrawal after a complete bad-debt write-down and can drain exactly a later supplier’s deposit. [6](#0-5) 

### Impact Explanation

The old supplier can extract tokens that should have been socialized away entirely. If `P` is the phantom floor-index value of the wiped position, the first `P` units deposited into the market can be withdrawn by that wiped supplier. The new supplier’s account still records an economically valid claim, but the pool has insufficient cash to pay it, producing direct theft of user funds or protocol insolvency.

The affected path is reachable without privileges:

1. A market contains an old supplier position and an insolvent borrower.
2. Any authorized caller invokes `clean_bad_debt(caller, borrower_account_id)` once the borrower satisfies the dust-capped insolvency gate. [7](#0-6) 
3. Cleanup socializes debt equal to or greater than the market’s supplied value.
4. Any later `supply` adds cash to the same market.
5. The old supplier invokes `withdraw(caller, supplier_account_id, [(hub_asset, 0)], Some(caller))`, where zero requests a full withdrawal, and receives the phantom claim from the new cash. [8](#0-7) 

### Likelihood Explanation

The exploit requires a severe bad-debt event whose value is at least the market’s total supplied value and whose account collateral satisfies the cleanup dust gate. That is a significant market precondition, but no privileged call, leaked key, upgrade, oracle manipulation, or helper service is required to trigger it once such an account exists. [9](#0-8)  The later deposit need not come from the attacker; any subsequent supplier creates the cash that the stale position can claim.

The bug is deterministic after that market state occurs. There is no timing race, rounding requirement beyond the total-loss condition, or special token behavior.

### Recommendation

Do not apply `SUPPLY_INDEX_FLOOR_RAW` after a complete write-down. When `bad_debt >= total_supplied_value`, treat the market as a wipeout rather than resurrecting all share claims at `0.1%`.

A safe fix needs an explicit wiped-market state, because merely setting the index to zero would make future supply-share divisions invalid while stale controller positions remain. Suitable approaches include:

- Reset the market accounting to zero supplied and zero revenue, mark a new market/accounting epoch, and make pre-reset scaled positions withdraw zero.
- Alternatively freeze supply and withdrawals after a total write-down until governance performs an explicit market reset; this prevents phantom payouts but is less user-friendly.
- If partial-loss handling is retained, apply the floor only when `remaining > 0`; when `remaining == 0`, the resulting entitlement must remain zero and the stale shares must be invalidated by an epoch or equivalent mechanism.

Add an end-to-end regression test covering `borrow → collateral deterioration → clean_bad_debt → new supply → old supplier withdraw`, asserting that the old supplier receives zero and the new supplier retains a fully backed claim.

### Proof of Concept

The repository already contains a minimal production-code demonstration in `contracts/pool/tests/interest.rs`. A market begins with `1_000_000 * RAY` supplied shares at index `RAY`; bad debt of `2_000_000 * RAY` should erase the position. Instead, the index becomes `SUPPLY_INDEX_FLOOR_RAW`, the stale position retains `stranded > 0`, and it withdraws the entire later deposit `c`. [10](#0-9) 

The essential reproduction is:

```rust
// contracts/pool/tests/interest.rs
let scaled_a = Ray::from(1_000_000 * RAY);

// Total wipeout: debt exceeds supplied value.
apply_bad_debt_to_supply_index(&mut cache, Ray::from(2_000_000 * RAY));

// Expected: zero. Actual: RAY / 1000.
assert_eq!(cache.supply_index().raw(), SUPPLY_INDEX_FLOOR_RAW);

let stranded = cache.unscale_supply_floor(scaled_a);
assert!(stranded > 0);

// A later supplier contributes exactly enough cash to cover the stale claim.
let scaled_b = cache.calculate_scaled_supply(stranded);
cache.mint_supply(scaled_b);
cache.credit_cash(stranded);

// The wiped supplier's old scaled position drains the fresh cash.
let (_, gross) = cache.resolve_withdrawal(i128::MAX, scaled_a);
cache.require_reserves(gross);
cache.burn_supply(scaled_a);
cache.debit_cash(gross);

assert_eq!(gross, stranded);
assert_eq!(cache.cash(), 0);
```

Through the public controller API, the corresponding sequence is `clean_bad_debt(caller, insolvent_account_id)`, followed by any user’s `supply(...)`, followed by the stale supplier’s `withdraw(..., [(hub_asset, 0)], ...)`.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

            "wipeout must clamp supply index UP to the floor, not reset the base"
        );

        let stranded = cache.unscale_supply_floor(scaled_a);
        assert!(stranded > 0, "floor clamp leaves userA a phantom claim");

        let scaled_b = cache.calculate_scaled_supply(c);
        cache.mint_supply(scaled_b);
        cache.credit_cash(c);

        let b_claim = cache.unscale_supply_floor(scaled_b);

        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}
