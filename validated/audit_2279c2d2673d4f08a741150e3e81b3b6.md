# No vulnerability found for this question.

**Analysis supporting this conclusion:**

The claimed collision mechanism does not exist in the code. `deduplicate_commitments` in `src/eip7594/eip7594.c` builds `commitment_indices[i]` purely by byte-equality comparison (`commitments_equal`, using `memcmp`) between `commitments_bytes[i]` and previously seen unique commitments — it has no dependency whatsoever on `cell_indices[i]` or the numeric value of the cell column index (e.g., 127). [1](#0-0) 

The two arrays that matter for correctness are:
- `cell_indices[i]` — the column each cell belongs to, used in `compute_commitment_to_aggregated_interpolation_poly` to place/interpolate cell data into the right column. [2](#0-1) 
- `commitment_indices[i]` — the row/commitment index for cell `i`, used in `compute_weighted_sum_of_commitments` to weight the correct unique commitment. [3](#0-2) 

Both arrays are indexed by the *same* loop variable `i` (the per-cell position in the caller-supplied arrays), and both are derived once and passed consistently to every helper (`compute_verify_cell_kzg_proof_batch_challenge`, `compute_weighted_sum_of_commitments`, `compute_commitment_to_aggregated_interpolation_poly`, `computed_weighted_sum_of_proofs`) in `verify_cell_kzg_proof_batch`. [4](#0-3) [5](#0-4) 

There is no code path where `cell_index == 127` (or `CELLS_PER_EXT_BLOB - 1`) causes `commitment_indices` to be computed differently, wraps around, or aliases with another row. The bound check `cell_indices[i] >= CELLS_PER_EXT_BLOB` rejects any out-of-range column before deduplication even runs. [6](#0-5) 

The equality the question posits — "cell `i` checked against commitment `i`'s polynomial, never a remapped one" — holds for all `i` including `i` where `cell_indices[i] == 127`, because `commitment_indices[i]` is derived solely from the content of `commitments_bytes[i]`, independent of `cell_indices[i]`'s value. No divergence is introduced by the last-column case; the premise of a "commitment-index map collision via cell_index 127" is not supported by the code.

```c
static void deduplicate_commitments(
    Bytes48 *commitments_out, uint64_t *indices_out, size_t *count_out
) {
    /* Bail early if there are no commitments */
    if (*count_out == 0) return;

    /* The first commitment is always new */
    indices_out[0] = 0;
    size_t new_count = 1;

    /* Create list of unique commitments & indices to them */
    for (size_t i = 1; i < *count_out; i++) {
        bool exist = false;
        for (size_t j = 0; j < new_count; j++) {
            if (commitments_equal(&commitments_out[i], &commitments_out[j])) {
                /* This commitment already exists */
                indices_out[i] = j;
                exist = true;
                break;
            }
        }
        if (!exist) {
            /* This is a new commitment */
            commitments_copy(&commitments_out[new_count], &commitments_out[i]);
            indices_out[i] = new_count;
            new_count++;
        }
    }

    /* Update the count */
    *count_out = new_count;
}
```
