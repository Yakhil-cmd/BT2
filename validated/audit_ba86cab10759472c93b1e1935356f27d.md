### Title
Permanent market freeze: `i128` overflow in `scaled_to_original` during interest accrual bricks all exit paths on a high-decimals market - (File: contracts/pool/src/interest.rs)

### Summary
The analog of CVE-2018-4122 (crafted input → memory corruption → crash/DoS) is a crafted position size that pushes `borrowed_scaled * borrow_index` past `i128::MAX` inside the fixed-point accrual path. `global_sync` runs before every verb, so once the product overflows, `scaled_to_original` panics with `MathOverflow` on every subsequent `update_indexes`, `withdraw`, `repay`, and `liquidate` — permanently freezing supplier funds. The protocol's own `MAX_BORROW_INDEX_RAY` cap never engages because the value ceiling is hit first; the documented bound in `docs/reference/formulas.md` is wrong per the codebase's own harness test.

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs:20-33` is invoked unconditionally before state-changing ops and calls `accrue_step` each chunk. Debt/supply valuation uses `scaled_to_original(scaled, index)` (`contracts/pool/src/cache/scale.rs:23-24`, `common::rates`), which computes `scaled * index / RAY`. With an 18-decimals asset and a large book, the RAY-scaled intermediate product overflows `i128` long before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`. The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the cliff: at ~98% utilization on the steep segment of the XLM rate curve, accrual panics with `MATH_OVERFLOW`, and `withdraw`/`repay` fail identically because every verb accrues first [1](#0-0) . `accrue_step` and `scaled_to_original` have no saturating or capped fallback on this path [2](#0-1) .

### Impact Explanation
Permanent freezing of funds. Once the market crosses the ray-value ceiling, every entrypoint that touches that market (`supply`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`) reverts in accrual before any state transition. Suppliers can never exit; the panic is deterministic and unrecoverable because no verb skips accrual and the index is monotonically non-decreasing [3](#0-2) .

### Likelihood Explanation
Medium. Reachable by a single unprivileged address: supply a large amount of a high-decimals asset (`supply`), borrow near max utilization (`borrow`), then let time accrue — no privileged action required. It does require a whale-scale position (the test uses 10^27 raw units) and sustained high utilization on the steep part of the rate curve over a long horizon, plus caps lifted or a market configured without tight supply/borrow caps. Not a documented design choice — the repo's own test asserts the formulas doc is wrong and the index cap does not protect the path [4](#0-3) .

### Recommendation
Make the accrual/valuation path saturate or degrade gracefully instead of panicking: use a saturating `scaled_to_original` (or I256-widened valuation) inside `accrue_step` and utilization math, and enforce an effective borrow-index cap that triggers at the value ceiling rather than at `MAX_BORROW_INDEX_RAY`. Alternatively, enforce supply/borrow caps bounded per `asset_decimals` so `scaled * index` provably fits `i128`.

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`: build a market with an 18-decimals asset on the XLM curve, supply `BILLION * 10^18`, borrow 98% of it, advance time year-by-year until `try_update_indexes_for` returns `MATH_OVERFLOW`; then `try_withdraw_raw` and `try_repay` also fail with `MATH_OVERFLOW`, with `borrow_index < MAX_BORROW_INDEX_RAY` [5](#0-4) .

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
