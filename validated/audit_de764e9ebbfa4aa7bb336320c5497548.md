### Title
Cross-tenant webhook forgery via secret-less organization allows `UnlabeledHandler` to archive/unarchive a victim's review stack without any valid signature - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/unlabeled_handler.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects which `GitHubApp`/secret to check against using `params.dig('repository','owner','login')`, but the `pull_request` handlers (including `UnlabeledHandler`) resolve the *target* repository/stack independently, from `params.repository.full_name`. Because `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected org's `webhook_secret` is blank, an attacker who can name any configured no-secret organization as `repository.owner.login` bypasses signature verification entirely, while pointing `repository.full_name` at an arbitrary victim repository/stack that the handler will actually mutate.

### Finding Description
The invariant the code should guarantee is:
`org_used_to_verify_signature == org_that_owns_the_mutated_repository`

In practice these are two independent reads of the same attacker-controlled JSON body:

- `repository_owner` (used for signature verification) = `params.dig('repository','owner','login')` [1](#0-0)  feeding `Shipit.github(organization: repository_owner)` and `github_app.verify_webhook_signature(...)` [2](#0-1) .
- The repository actually mutated by `UnlabeledHandler` is looked up via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [3](#0-2) , which parses `owner/name` straight out of `full_name` and does a DB lookup independent of the value that authenticated the request [4](#0-3) .

`verify_webhook_signature` short-circuits to `true` when the selected organization's config has no `webhook_secret` set: `return true unless webhook_secret` [5](#0-4) . Multi-org Shipit deployments are explicitly supported and documented, with each org independently configuring (or omitting) a `webhook_secret` [6](#0-5) ; the dummy config even ships two orgs with `webhook_secret: # nil` [7](#0-6) .

Exploit flow: attacker crafts a `pull_request`/`action=unlabeled` payload with `repository.owner.login = "no-secret-org"` (a real org configured in Shipit but with no `webhook_secret`) and `repository.full_name = "victim-org/victim-repo"` (a different, properly-secured org's repository with review stacks enabled). No `X-Hub-Signature` header, or any arbitrary value, is required — `verify_signature` passes because `Shipit.github(organization: "no-secret-org").verify_webhook_signature` always returns `true`. `Shipit::Webhooks.for_event('pull_request')` then dispatches to `UnlabeledHandler`, which resolves `repository` from `victim-org/victim-repo` and, depending on the victim's provisioning label and `provisioning_behavior`, calls `stack.archive!` (deprovisions and archives the review stack) or `stack.unarchive!` (re-queues it via `Shipit::ReviewStackProvisioningQueue.add(stack)`, which re-triggers provisioning/deploy activity) [8](#0-7) [9](#0-8) .

Existing guards do not stop this: `drop_unhandled_event` only checks the event type exists a handler for it [10](#0-9) ; `GithubOrganizationUnknown` only fires if the owner name isn't configured at all, not if it's configured without a secret [11](#0-10) ; the `ExplicitParameters` schema on `UnlabeledHandler` validates shape, not cross-consistency between `repository.owner.login` and `repository.full_name` (that field isn't even part of the schema) [12](#0-11) .

### Impact Explanation
An unprivileged internet user can force the archive (deprovision) or unarchive (re-provision/re-deploy) of any review stack belonging to any repository configured in the target Shipit instance, as long as *any* other organization in the same Shipit installation has a blank `webhook_secret` — regardless of whether the victim organization itself has a properly configured, secret webhook. This is a "payload for one repository mutating another's stack," matching the Critical impact category (unauthorized deploy/rollback triggered via re-provisioning, or unauthorized deprovisioning/archival of a stack). The blast radius spans every tenant/repository configured on the shared Shipit instance, and the attack is trivially repeatable per request, requiring no valid credentials, sessions, or secrets.

### Likelihood Explanation
Preconditions: the Shipit instance must be configured with the multi-org `github:` schema (documented, supported feature) where at least one configured organization omits `webhook_secret`, and the target victim repository must have `review_stacks_enabled`. Given multi-org Shipit installs commonly onboard new orgs before wiring up their webhook secret (or intentionally leave a low-risk sandbox org unsecured), this is a realistic misconfiguration. The attacker's cost is a single unauthenticated HTTP POST with a crafted JSON body and correct `X-Github-Event: pull_request` header — no GitHub App or repository access is needed for the forged org name, and the exploit is fully repeatable.

### Recommendation
Bind the signature-verifying organization to the actual mutated resource: derive the organization used both for `Shipit.github(organization: ...)` verification and for repository resolution from a single, already-authenticated source (e.g., look up the `Shipit::Repository` first by `full_name`, then verify the signature using that repository's own owner's `GitHubApp`, rejecting the request if `repository.owner.login` does not match the resolved repository's owner). Additionally, disallow (or explicitly opt-in with a warning) organizations configured without a `webhook_secret` from being treated as "verified" — never treat a missing secret as an implicit bypass.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb` (or a new `unlabeled_handler_test.rb`), using `test/dummy/config/secrets_double_github_app.yml`-style config where `OrgOne` has no `webhook_secret` and `OrgTwo` (or a distinct secured org) has one, with a `Shipit::Repository` and archived-eligible `Shipit::ReviewStack` under the secured org:

```ruby
test "pull_request unlabeled forged with a no-secret organization mutates a different, secured org's stack" do
  victim_repo   = shipit_repositories(:shipit) # owner has webhook_secret configured
  victim_stack  = shipit_review_stacks(:some_review_stack_under_victim_repo)

  payload = {
    action: "unlabeled",
    number: victim_stack.pull_request.number,
    pull_request: {
      id: 1, number: victim_stack.pull_request.number, url: "https://api.github.com/...",
      title: "x", state: "open", additions: 1, deletions: 1,
      head: { sha: "a" * 40, ref: victim_stack.branch },
      user: { login: "attacker" },
      assignees: [],
      labels: [] # no provisioning label -> triggers archive per victim's provisioning_behavior
    },
    repository: {
      full_name: victim_repo.github_repo_name, # points at the VICTIM repo/stack
      owner: { login: "no-secret-org" }        # org with blank webhook_secret used for signature check
    },
    sender: { login: "attacker" }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  # no X-Hub-Signature header sent at all

  assert_changes -> { victim_stack.reload.archived? }, from: false, to: true do
    post :create, body: payload, as: :json
  end

  assert_response :ok
end
```

Binding checked on both sides: before the request, `victim_stack.archived? == false` and the request carries `repository.owner.login = "no-secret-org" != victim_repo.owner`; after the request, `victim_stack.reload.archived? == true` despite no valid signature for `victim_repo.owner`'s secret ever being presented — demonstrating the equality `org_used_to_verify_signature == org_that_owns_the_mutated_repository` is violated.

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end
