### Title
Unscoped `Commit.where(sha:)` lookup in `StatusHandler` lets an attacker with a signed webhook from *any* configured organization forge CI status on commits belonging to a *different* stack/repository - ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` authenticates a webhook against the GitHub App/organization derived from the payload's `repository.owner.login` (or `organization.login`) fallback, then calls `Shipit.github(organization: repository_owner).verify_webhook_signature`. Signature validity therefore proves only "this event genuinely originated from GitHub App/organization X's webhook secret" - it says nothing about which `Stack`/`Repository` the event's *content* is allowed to affect. `StatusHandler#process`, however, resolves the target purely by commit SHA, globally, with no scoping to the repository/organization that was actually authenticated: [1](#0-0) 

This breaks the binding: `organization that authenticated (repository_owner used to pick the webhook secret)` ≠ `repository/stack whose Commit record is written`.

### Finding Description
`verify_signature` picks the webhook secret using a value taken from the same JSON payload it is about to verify: [2](#0-1) 

In a multi-organization deployment (explicitly supported, see `Shipit.github_app_config` and `docs/setup.md`'s "Using Multiple Github Applications" section), each organization has its own `webhook_secret`: [3](#0-2) 

Once the signature check passes for organization X (using X's own legitimate secret - obtainable by anyone who legitimately configures/administers a GitHub App/repo under organization X, which is an unprivileged, non-Shipit-credentialed actor relative to organization Y), the raw payload is handed to `Shipit::Webhooks.for_event('status')`, i.e. `StatusHandler`:

```
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
```

There is no check that the `Commit` found belongs to a stack/repository under the organization that was actually authenticated. `Commit#sha` is a git SHA1 that is fully attacker-reproducible for any **public** repository (cloning/forking a public repo yields byte-identical commits and therefore identical SHAs). An attacker who controls (or forks into) their own organization/repository - one they can legitimately trigger real, correctly-signed `status` webhooks from (e.g., their own CI, or by using GitHub's API to set a commit status on a repo they administer) - can pick `sha` equal to a known public commit that Shipit is tracking for an unrelated stack belonging to a different organization/team, and the resulting signed-but-cross-tenant webhook will be applied to that unrelated `Commit` record via `Commit#create_status_from_github!`.

### Impact Explanation
Commit statuses directly gate Shipit's deploy/merge-readiness logic: `Commit#deployable?`, `MergeRequest#all_status_checks_passed?` / `any_status_checks_failed?` / `any_status_checks_missing?`, and `ProcessMergeRequestsJob` consult exactly the statuses attached to a `Commit` (`StatusChecker`, `deploy_spec.required_statuses`, `merge_request_required_statuses`) to decide whether a commit can be deployed or a pull request auto-merged: [4](#0-3) [5](#0-4) 

By forging a `success` status (with an arbitrary `context`, `description`, `target_url`) on a commit that is not in the attacker's own organization, an attacker can satisfy `required_statuses`/`merge_request_required_statuses` for another team's stack and cause the merge queue to auto-merge a pull request or unblock a deploy that never actually passed CI - matching the "unauthorized deploy/merge" impact class. This crosses an organizational trust boundary using no Shipit credentials, `ApiClient` token, or repository write access to the victim org - only a legitimately signed webhook from the attacker's own, unrelated organization/app installation.

### Likelihood Explanation
Reachable by any party who can trigger a genuine `status` webhook from an organization configured in Shipit's multi-org `github` config (a documented, supported deployment mode) - e.g. an outside contributor who administers their own small repo/CI in that org. No access to the victim stack, its repository, or its GitHub App secret is required; only knowledge of a target commit's SHA, which is public information for any public repository Shipit tracks. This is a config-supported, low-effort exploit path once a multi-org setup is used.

### Recommendation
Scope `StatusHandler#process` (and any other handler relying solely on payload-derived identifiers) to the authenticated organization/repository, not just the SHA:
```ruby
def process
  Commit.joins(stack: :repository)
        .merge(Repository.from_github_repo_name(repository_name))
        .where(sha: params.sha)
        .each { |commit| commit.create_status_from_github!(params) }
end
```
i.e., require that `repository_name` (which is itself covered by the verified HMAC of the *same organization's* webhook secret) matches the stack's repository before writing a status, rather than trusting a bare, globally-unscoped SHA match. More generally, `WebhooksController#verify_signature` should thread the verified `repository_owner`/`repository_name` through to every handler and each handler should enforce that its writes are confined to that repository.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgVictim` and `OrgAttacker`, each with its own `webhook_secret` (supported multi-app config, see `test/dummy/config/secrets_double_github_app.yml`).
2. `OrgVictim` has a public repo/stack tracking commit `abc123...`, currently `pending` (no status), blocking a merge request that requires `ci/tests` to be `success`.
3. Attacker forks `OrgVictim`'s public repository into their own `OrgAttacker`-owned repo (fork preserves the exact same commit SHA `abc123...`).
4. Attacker uses the GitHub API on their own fork (which they administer) to set a commit status `ci/tests: success` on `abc123...`. GitHub sends a `status` webhook to Shipit, correctly signed with `OrgAttacker`'s legitimate `webhook_secret`.
5. `WebhooksController#verify_signature` resolves `repository_owner` = `OrgAttacker` from the payload, fetches `OrgAttacker`'s app, and the HMAC verifies successfully (it's a real, correctly-signed webhook from `OrgAttacker`).
6. `StatusHandler#process` runs `Commit.where(sha: 'abc123...')`, finds the `OrgVictim` commit (SHA collision by design via fork), and calls `create_status_from_github!`, writing `ci/tests: success` onto it.
7. `MergeRequest#all_status_checks_passed?` for the pending PR in `OrgVictim`'s stack now returns true, and `ProcessMergeRequestsJob` merges/deploys code that never actually passed `OrgVictim`'s real CI.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
