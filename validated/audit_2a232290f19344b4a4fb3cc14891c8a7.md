## Title
CCMenu API endpoint bypasses per-stack authorization scoping of `ApiClient` tokens - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::CCMenuController` overrides the `stack` accessor that `Shipit::Api::BaseController` uses to enforce that an `ApiClient` token can only touch the stack it was scoped to. The override resolves the stack straight from the request parameter via `Stack.from_param!(params[:stack_id])` instead of going through the client-scoped `stacks` relation, breaking the binding between "the stack a token authorizes" and "the stack the endpoint actually touches."

### Finding Description
`ApiClient` records can be scoped to a single stack via `belongs_to :stack, optional: true` and `stack_id` [1](#0-0) . `Shipit::Api::BaseController` enforces this scoping centrally: any endpoint resolving `stack` goes through `stacks`, which restricts the queryable set to `Stack.where(id: current_api_client.stack_id)` when the client is scoped: [2](#0-1) 

This is exactly the authorization primitive tested in `test/controllers/api/stacks_controller_test.rb` ("an api client scoped to a stack will only see that one stack") using the `here_come_the_walrus` fixture, which is scoped to the `shipit` stack: [3](#0-2) , verified in `test/controllers/api/stacks_controller_test.rb#L217-223`.

`CCMenuController`, however, defines its own `stack` method that ignores the `stacks` scoping entirely and resolves any stack by param: [4](#0-3) 

The `require_permission :read, :stack` before_action only checks that the token carries the `read:stack` permission string (`ApiClient#check_permissions!`) — it does not check which stack the permission applies to: [5](#0-4) 

So the equality that should hold — "stack authorized for token == stack touched by request" — is broken specifically in this controller: any token carrying `read:stack` (even one legitimately scoped to stack A via `stack_id`) can be used to fetch CCMenu XML status (`deploys_and_rollbacks.last`, branch/build status) for any other stack B by simply passing `stack_id=B` in the URL.

### Impact Explanation
This matches the "High - unauthenticated/unauthorized read of stack state" category: it lets an attacker in possession of a stack-scoped CCMenu/API token (which is routinely embedded in unauthenticated URLs — see `CCMenuUrlController#fetch`, which builds a plain query-string URL for CI dashboard tools: [6](#0-5) ) read the deploy/build status of stacks that token was never meant to access, i.e. cross-stack disclosure of deploy state.

### Likelihood Explanation
Any holder of a valid `read:stack`-permissioned token (which is deliberately handed out in bare query strings for CI status widgets, per `CCMenuUrlController`) can immediately exploit this by changing the `stack_id` route/query parameter — no additional privilege, session, or secret is required beyond the token itself.

### Recommendation
Remove the `stack` override in `CCMenuController` (or reimplement it to delegate to the inherited, client-scoped `stacks` relation, e.g. `stacks.from_param!(params[:stack_id])`), so that stack-scoped `ApiClient` tokens are enforced consistently across all API controllers.

### Proof of Concept
1. An operator calls `GET /ccmenu_url?stack_id=stack-a` while authenticated in the browser; `CCMenuUrlController#fetch` creates/finds an `ApiClient` named "CCMenu Client" with `permissions: %w[read:stack]` and returns a URL such as `https://shipit.example.com/api/stack-a/ccmenu.xml?token=<signed-token>`.
2. This URL is placed, unauthenticated, into a CI status dashboard/CCMenu client.
3. Anyone who obtains that URL (e.g., from a shared dashboard config, browser history, or network log) can request `GET /api/stack-b/ccmenu.xml?token=<same-token>` for an arbitrary stack `stack-b`.
4. Because `CCMenuController#stack` calls `Stack.from_param!(params[:stack_id])` directly rather than `stacks.from_param!(...)`, the request succeeds and returns `stack-b`'s deploy/build status, even though the token was never scoped or intended for `stack-b`.

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])

    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
