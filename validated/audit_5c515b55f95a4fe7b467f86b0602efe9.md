### Title
Unsanitized attacker-controlled comment content written to pager/stdout via `formatRawComment` - (File: pkg/cmd/pr/shared/comments.go)

### Summary
`formatRawComment` writes `comment.Content()` — fully attacker-controlled text from a PR/issue comment, review, or check — directly into the raw comment stream with no ANSI/escape-sequence sanitization, unlike the dedicated `ContentOut` sanitizing writer that `IOStreams` provides for exactly this class of "external content." This raw text is fed straight to `fmt.Fprintln`/`fmt.Fprint` and ultimately to stdout/pager, so any terminal escape sequence embedded in a comment body is passed through unmodified.

### Finding Description
`formatRawComment` builds output purely with `fmt.Fprintf`/`fmt.Fprintln`, writing `comment.Content()` verbatim between `--` delimiters with no escaping, stripping, or use of the codebase's `asciisanitizer`/`ContentOut` mechanism: [1](#0-0) 

`RawCommentList` simply concatenates the output of `formatRawComment` for every sorted comment/review and returns the string as-is: [2](#0-1) 

`Comment.Content()` returns the raw GitHub API field (issue/PR/review comment body), which is fully attacker-controlled — any GitHub user with comment permissions on a public repo can embed arbitrary bytes, including ANSI/OSC/DCS terminal escape sequences, cursor movement codes, or terminal title/clipboard manipulation sequences.

`IOStreams` explicitly documents and implements a separate `ContentOut` writer specifically to sanitize this class of external content before it reaches the terminal/pager: [3](#0-2) 

This shows gh's own security model treats comment/API-body text as requiring sanitization at the output boundary regardless of sink (pager vs. direct stdout). However, `formatRawComment`'s output path (used for the raw/plaintext comment listing consumed by `gh pr view`/`gh issue view` in non-interactive or `--comments` raw mode) does not route through `ContentOut` or any sanitizer — it is built with plain `strings.Builder`/`fmt.Fprint` calls and returned as a string for the caller to print. If that string is subsequently written to `io.Out` (or piped into the configured pager via `StartPager`) instead of through `ContentOut`, none of the sanitization applied elsewhere in gh (e.g., the color-scheme/markdown-rendered `formatComment` path) is applied here.

### Impact Explanation
An attacker who can post an issue/PR comment, review, or check output can embed terminal escape sequences (e.g., ANSI cursor repositioning, OSC 8 hyperlink spoofing, terminal title changes, or sequences that clear/overwrite prior lines) that are rendered verbatim by the victim's pager or terminal emulator when they run `gh pr view`/`gh issue view`. Because pagers (e.g., `less`) and terminal emulators may interpret raw/control sequences differently than gh's own color-scheme-aware rendering path (`formatComment`), this can be used for terminal output spoofing — e.g., faking prompts, hiding malicious content, or overwriting visible command output — potentially tricking a victim into approving a destructive action or revealing credentials typed in response to a spoofed prompt. This matches the "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" impact class.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to be able to comment on or review a PR/issue that the victim later views with `gh pr view --comments`/`gh issue view` (or any code path invoking `RawCommentList`), which is achievable by any unprivileged GitHub user on a public repository. No token leakage, MITM, or admin access is required, making this readily repeatable.

### Recommendation
Route the output of `RawCommentList`/`formatRawComment` through the same sanitizing mechanism used for other external content (`IOStreams.ContentOut` / `asciisanitizer`), or explicitly strip/escape ANSI and other control sequences from `comment.Content()` before formatting, so that sanitization is guaranteed at the point the bytes are produced rather than depending on the caller choosing the correct writer.

### Proof of Concept

Expected (current) result: the test fails because `formatRawComment` writes `comment.Content()` unmodified, i.e., the escape bytes `\x1b]0;PWNED\x07\x1b[2J` are present verbatim in the output, confirming the sink receives unsanitized bytes.

```go
func formatRawComment(comment Comment) string {
	if comment.IsHidden() {
		return ""
	}
	var b strings.Builder
	fmt.Fprintf(&b, "author:\t%s\n", comment.AuthorLogin())
	fmt.Fprintf(&b, "association:\t%s\n", strings.ToLower(comment.Association()))
	fmt.Fprintf(&b, "edited:\t%t\n", comment.IsEdited())
	fmt.Fprintf(&b, "status:\t%s\n", formatRawCommentStatus(comment.Status()))
	fmt.Fprintln(&b, "--")
	fmt.Fprintln(&b, comment.Content())
	fmt.Fprintln(&b, "--")
	return b.String()
}
```
