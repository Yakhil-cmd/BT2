### Title
i128 value overflow in accrual permanently freezes a market before the borrow-index cap can engage — (`File: common/src/rates/index.rs`)

### Summary
The bug class of ALPINE-CVE-2022-39244 is a size/overflow of an unchecked arithmetic domain (buffer overflow in a C parser). The analog in XOXNO Lending is an `i128` numeric-domain overflow inside the interest-accrual path: `scaled_to_original` / `calculate_supplier_rewards` compute `borrowed × borrow_index` in Ray units, and this product overflows `i128` well before `borrow_index` reaches its `MAX_BORROW_INDEX_RAY` clamp. Since every mutating pool entrypoint runs `interest::global_sync` first, once a market crosses this RAY-value ceiling it reverts with `MathOverflow` on every call — permanently freezing all supplied, borrowed, and revenue funds in that market.

### Finding Description
- `update_borrow_index` multiplies the old index by the compound factor and only then clamps to `MAX_BORROW_INDEX_RAY` (`common/src/rates/index.rs:13-19`). The cap bounds the *index*, not the *value* `borrowed × index`.
- `accrue_step` (`common/src/rates/simulate.rs:60-69`) calls `scaled_to_original(env, borrowed, borrow_index)` and `calculate_supplier_rewards`, which computes `borrowed.mul(env, new_borrow_index)` (`common/src/rates/index.rs:80-83`). With a large scaled `borrowed` (e.g., ~1e9 whole tokens of an 18-decimal asset) this product overflows `i128` at an index around ~170× — far below `MAX_BORROW_INDEX_RAY`.
- `global_sync` (`contracts/pool/src/interest.rs:20-33`) runs this accrual inside every market mutation (`Cache::load → global_sync → mutate`, per `contracts/pool/README.md:159-168`), so the panic bricks `withdraw`, `repay`, `borrow`, `supply`, `seize_positions`/`liquidate`, `claim_revenue`, and `recapitalize` for that market. Even the permissionless `controller.update_indexes` (`contracts/controller/src/lib.rs:367-372`) reverts, so the accrual can never be advanced past the overflowing chunk.

This is not a documented design choice: `docs/reference/formulas.md` asserts a numeric bound implying the index cap protects the accrual, and the harness test explicitly notes "the bound in docs/reference/formulas.md is wrong" and "the index cap never engages" before the value overflow.

### Impact Explanation
Permanent freezing of funds — an accepted impact class. Once the market's `borrowed × index` crosses the `i128` ceiling, no supplier can withdraw, no borrower can repay, no liquidator can seize, and protocol revenue cannot be claimed. All token funds held by that pool market are frozen forever; there is no recovery entrypoint that bypasses accrual (even `recapitalize` accrues first).

### Likelihood Explanation
Medium. Every step is reachable by an unprivileged address via `supply`, `borrow`, and `update_indexes` — no privileged input is needed. The cost is the barrier: the attacker (or organic whale activity) must push a market to roughly a billion whole tokens supplied at ~98% utilization and sustain high borrow rates for multiple years so the index grows to the ~170× cliff before utilization drops. On a steep-segment curve at sustained near-max utilization this is deterministic; it is not gated by the index cap, the supply-index floor, or any liveness guard. The test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-362`) demonstrates the full freeze end-to-end, including failing `withdraw` and `repay` afterwards.

### Recommendation
Bound the *value* domain, not just the index. Options: (a) in `update_borrow_index`, clamp the pre-clamp product through a saturating/checked path and also cap `borrowed` scaled shares so `borrowed × MAX_BORROW_INDEX_RAY` stays inside `i128` — enforce this in `create_market`/supply caps via `max_cap_for_decimals`; (b) make `global_sync` degrade gracefully at the ceiling (clamp index and skip further accrual) rather than panicking, so exits remain possible; (c) fix the `formulas.md` numeric-limits bound to reflect the real value ceiling.

### Proof of Concept
Existing harness test, `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`:

1. Create an 18-decimal market with the XLM-style curve; attacker supplies `principal = 1e9 × 10^18` base units and borrows 98% of it (both permissionless).
2. Advance ledger time in 1-year steps and call the permissionless `controller.update_indexes`.
3. After the index reaches ~170× (before `MAX_BORROW_INDEX_RAY`), `accrue_step` panics with `MathOverflow` inside `scaled_to_original`/`calculate_supplier_rewards`.
4. Verify freeze: `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` both revert with `MATH_OVERFLOW` — asserted in the test at lines 355-356. The market can never accrue again, so all verbs revert permanently. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };

    AccrualStep {
        borrow_index: new_borrow_index,
        supply_index: new_supply_index,
        revenue_shares,
    }
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
