### Title
Unprivileged pool creation can assign creator-fee entitlement to an arbitrary, non-consenting/unspendable address, permanently freezing accrued creator fees - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`initialize_with_permission` lets any payer holding a valid `Permission` PDA create a pool while declaring the `creator` field as an `UncheckedAccount` that is never required to sign. `pool_state.pool_creator` is then set directly from that unchecked pubkey, and this pool_creator becomes the sole party permanently entitled to the pool's accumulated `creator_fees_token_0/1`.

### Finding Description
Compare `initialize.rs`, where `creator` is a `Signer<'info>` [1](#0-0) , to `initialize_with_permission.rs`, where `creator` is only declared as `/// CHECK: creator of pool` `UncheckedAccount<'info>` with no signature or ownership constraint [2](#0-1) . The only signer-gated account in this instruction is `payer`, and the `permission` PDA is derived and checked against `payer.key()`, not `creator.key()` [3](#0-2) . The handler then writes the attacker-supplied `creator` pubkey straight into `PoolState.pool_creator` via `pool_state.initialize(..., ctx.accounts.creator.key(), ...)` with no validation that the address is capable of ever signing a transaction [4](#0-3) .

Downstream, fee withdrawal is split into two paths:
- `collect_creator_fee` strictly requires `creator` to be the transaction signer and to match `pool_state.pool_creator` (`#[account(mut, address = pool_state.load()?.pool_creator)] pub creator: Signer<'info>`) [5](#0-4) .
- `collect_creator_fee_permissionless` allows anyone to push the accrued fees into an ATA owned by `pool_creator`, without requiring `creator` to sign [6](#0-5) , [7](#0-6) .

Because a payer with an authorized `Permission` PDA can set `pool_creator` to any pubkey of their choosing (including a program-derived address or any account with no known private key), the creator-fee stream accrued from ordinary, permissionless swap activity (`swap_base_input`/`swap_base_output`) can be permanently routed to an address nobody controls. `collect_creator_fee_permissionless` will happily create the ATA and push the tokens there, but once inside that ATA, the funds are unrecoverable because the owning pubkey can never sign a transfer instruction, and `collect_creator_fee` cannot be used either since it requires that same unsignable key as `Signer`.

### Impact Explanation
This results in permanent freezing of protocol/creator-fee funds that are skimmed from real swap volume across the pool's lifetime. Anyone who swaps through such a pool unknowingly contributes to fees that become permanently locked with no recovery mechanism in the program (no admin override exists to reassign `pool_creator` or reroute stuck creator fees). This matches "permanent freezing of user or LP funds" in the validation criteria, reachable purely from an unprivileged, permission-holding pool-creation transaction plus ordinary swap transactions from unrelated unprivileged swappers.

### Likelihood Explanation
Reaching this requires the caller to already hold a `Permission` PDA granted by the admin (`create_permission_pda` is gated to `crate::admin::ID` or `create_permission_pda_owner::ID`) [8](#0-7) . This lowers likelihood relative to a fully open-to-anyone bug: it is only exploitable by, or requires cooperation of, an entity that has been granted launch permission (e.g. a launchpad/partner), not by an arbitrary anonymous swapper. It could occur accidentally (a partner integration bug passing a wrong/derived address as `creator`) or intentionally (a permitted launcher misconfiguring or maliciously bricking creator-fee distribution for a token they don't control, or to grief a project).

### Recommendation
Require `creator` in `InitializeWithPermission` to either be a `Signer` (consistent with `Initialize`) or otherwise assert on-chain that the supplied `creator` pubkey is a valid, non-PDA, ed25519-derivable account (e.g., by checking it is not equal to any of the program's own PDAs and, ideally, requiring a signature or an explicit opt-in signature message from that key) before writing it into `pool_state.pool_creator`. At minimum, add a system-owned/non-PDA sanity check and/or an admin-recoverable path for creator fees whose declared `pool_creator` proves unable to sign.

### Proof of Concept
1. Admin grants a `Permission` PDA to `payer_key` via `create_permission_pda`.
2. `payer_key` calls `initialize_with_permission` with `creator` set to an arbitrary pubkey `X` for which no private key exists (e.g., a PDA of an unrelated program, or a burn-style address with only a 0-lamport system account, or a mint/vault address already in use by the program) — no signature from `X` is required because `creator` is `UncheckedAccount`.
3. `pool_state.pool_creator` is set to `X` [4](#0-3) .
4. Unrelated, unprivileged users swap through the pool via `swap_base_input`/`swap_base_output`, accruing `creator_fees_token_0/1` in `PoolState`.
5. Anyone calls `collect_creator_fee_permissionless`, which creates an ATA owned by `X` and transfers the accrued fees into it [9](#0-8) .
6. Because `X` cannot sign any transaction, the tokens in that ATA can never be moved out; `collect_creator_fee` (the only other withdrawal path) also requires `X` as `Signer`, so it is unusable — the fees are permanently frozen.

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
```
