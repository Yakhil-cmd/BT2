### Title
Quorum Mismatch Between Live Consensus and Block Validation Allows Single-Validator Block Acceptance in Small Validator Sets — (File: `blockchain/block_validator.go`)

### Summary

In pre-permissionless mode, `verifySeals` enforces a quorum of `2*F+1` committed seals, where `F = ceil(qualifiedLen/3) - 1`. For `qualifiedLen ≤ 3`, `F = 0`, so only **1 committed seal** is required to pass block validation. However, the live consensus engine (`calcQuorumSize`) requires **all** `qualifiedLen` commits for the same small validator sets. A malicious proposer in a 2–3 validator network can produce a block with only their own committed seal; syncing nodes accept it via `verifySeals` while honest live-consensus nodes would never produce such a block, causing consensus divergence.

---

### Finding Description

**Live consensus quorum** (`consensus/istanbul/core/core.go`):

```go
func calcQuorumSize(qualifiedLen int, committeeSize uint64) int {
    size := min(qualifiedLen, int(committeeSize))
    if size < 4 {
        return size   // everyone must agree for N < 4
    }
    return int(math.Ceil(float64(2*size) / 3))
}
```

For `qualifiedLen = 3`, `calcQuorumSize` returns **3** — unanimous agreement required. [1](#0-0) 

**Block validation quorum** (`blockchain/block_validator.go`):

```go
if validSeal < 2*v.sealer.F(blockNum, qualifiedLen, committeeSize)+1 {
    return istanbul.ErrInvalidCommittedSeals
}
```

`sealer.F` for `qualifiedLen = 3`: `ceil(3/3) - 1 = 0`, so the check becomes `validSeal < 1` — only **1 seal** required. [2](#0-1) [3](#0-2) 

The concrete mismatch table:

| `qualifiedLen` | Live consensus quorum | `verifySeals` quorum (`2F+1`) |
|---|---|---|
| 1 | 1 | 1 |
| 2 | 2 | **1** |
| 3 | 3 | **1** |
| 4 | 3 | 3 |

For `qualifiedLen = 2` or `3`, `verifySeals` accepts blocks that live consensus would never commit.

The `signerSet` used in `countValidCommittedSeals` for pre-permissionless is the full **council** (not just qualified validators), so a council member's single committed seal passes the membership check: [4](#0-3) 

The committed seal format is `Sign(Keccak256(PrepareCommittedSeal(blockHash)), privateKey)`, which a proposer can self-produce for their own key without any other validator's cooperation. [5](#0-4) 

---

### Impact Explanation

A malicious proposer in a 2–3 qualified-validator pre-permissionless network can:

1. Produce a block with only their own committed seal (1 seal).
2. Broadcast it to syncing peers.
3. Syncing peers call `BlockValidator.verifySeals` → `validSeal = 1 ≥ 2*0+1 = 1` → **accepted**.
4. Honest live-consensus nodes never commit such a block (they require `qualifiedLen` commits), so they remain on a different chain head.

Result: **consensus divergence** — syncing nodes import a chain that honest validators reject. In a 2-validator network where the malicious proposer withholds COMMIT messages, the honest validator's live consensus stalls (cannot reach quorum of 2), while the malicious chain grows and becomes canonical for syncing nodes. Any transactions on the malicious chain (transfers, reward distributions, governance votes) are accepted by syncing nodes but not by the honest validator, breaking settlement finality.

---

### Likelihood Explanation

- Requires a malicious validator who is the current proposer in a network with `qualifiedLen ≤ 3`.
- Small validator sets occur during network bootstrapping or when validators are demoted below minimum staking (`reward.minstake`), leaving only 1–3 qualified validators.
- The malicious validator uses their own legitimate key — no key compromise required.
- A single malicious validator suffices; no majority collusion needed.
- The pre-permissionless code path is active on any Kaia network that has not yet enabled `PermissionlessCompatibleBlock`.

---

### Recommendation

Align `verifySeals` quorum with `calcQuorumSize` for pre-permissionless blocks. Replace:

```go
if validSeal < 2*v.sealer.F(blockNum, qualifiedLen, committeeSize)+1 {
```

with a call that uses the same formula as `calcQuorumSize`:

```go
effectiveSize := min(qualifiedLen, committeeSize)
var required int
if effectiveSize < 4 {
    required = effectiveSize
} else {
    required = int(math.Ceil(float64(2*effectiveSize) / 3))
}
if validSeal < required {
    return istanbul.ErrInvalidCommittedSeals
}
```

This preserves the `ceil(2N/3)` formula for large sets (matching historical behavior) while closing the gap for small sets where `2F+1 < N`.

### Proof of Concept

**Setup**: Pre-permissionless Kaia network, `qualifiedLen = 2` (validators A and B).

**Computed values**:
- `calcQuorumSize(2, 2) = 2` → live consensus requires both A and B to COMMIT
- `sealer.F(_, 2, 2) = ceil(2/3) - 1 = 0` → `verifySeals` requires `2*0+1 = 1` seal

**Attack**:
1. A is the proposer for block N. A sends PREPREPARE.
2. B sends PREPARE and COMMIT. A does **not** relay B's COMMIT to itself.
3. A constructs a block with only A's own committed seal: `Sign(Keccak256(PrepareCommittedSeal(blockHash_N)), keyA)`.
4. A writes this 1-seal block to disk and broadcasts it to syncing node C.
5. C calls `verifySeals`:
   - `committers = [A]`, `signerSet = council = {A, B}`
   - `countValidCommittedSeals([A], {A,B})` → removes A → `validSeal = 1`
   - `1 < 2*0+1 = 1` → **false** → no error → block accepted
6. C imports block N with only A's seal as canonical.
7. B's live consensus is stuck: it has only B's own COMMIT, needs 2, never commits block N.

**Divergence**: C's canonical chain includes block N (A's unilateral block); B's node has no block N. Any state changes in block N (KAIA transfers, reward payouts, governance parameter changes) are applied on C but not on B. [6](#0-5) [7](#0-6) [8](#0-7)

func (m *IstanbulSealer) F(_ uint64, qualifiedLen, committeeSize int) int {
	if qualifiedLen > int(committeeSize) {
		return int(math.Ceil(float64(committeeSize)/3)) - 1
	}
	return int(math.Ceil(float64(qualifiedLen)/3)) - 1
}

// Quorum returns the quorum: ceil(2N/3) over the effective size
// N = min(qualifiedlen, committeeSize), or N for tiny committees. This matches
// calcQuorumSize used by the consensus core.
// Pre-permissionless sealer quorum: 2f+1
func (m *IstanbulSealer) Quorum(_ uint64, qualifiedlen, committeeSize int) int {
	n := min(qualifiedlen, committeeSize)
	if n < 4 {
		return n
	}
	return int(math.Ceil(float64(2*n) / 3))
}
