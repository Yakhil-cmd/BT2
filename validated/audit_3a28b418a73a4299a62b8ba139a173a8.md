### Title
Webhook signature verified against the payload's `repository.owner.login` while events are dispatched to the repository named by `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
Multi-tenant Shipit installations configure one GitHub App/webhook secret per organization key under `secrets.github` [1](#0-0) . `WebhooksController#verify_signature` picks which organization's secret to verify the HMAC against purely from `params.dig('repository', 'owner', 'login')` (or `organization.login`) inside the JSON body [2](#0-1) . Nothing cross-checks that this `owner.login` value is consistent with the `repository.full_name` value that the event handlers (`PushHandler`, `StatusHandler`, etc.) actually use to select which `Stack`/`Commit` gets mutated [3](#0-2) [4](#0-3) .

### Finding Description
The binding that should hold is: **organization whose secret authenticated the request == organization that owns the repository being written to**. The code breaks this equality:

- `verify_signature` computes `repository_owner` from `repository.owner.login`/`organization.login` and fetches `Shipit.github(organization: repository_owner)` to get that org's `webhook_secret`, then verifies the raw body HMAC against it [5](#0-4) .
- The HMAC signature does cover the raw JSON body byte-for-byte (so an attacker can't tamper with an already-signed payload from a *legitimate* GitHub delivery). However, the attacker doesn't need to tamper with a legitimate payload — they can **originate** their own payload and sign it themselves with a secret they legitimately possess for their own org's Shipit-configured secret, deliberately putting a different value in `repository.full_name` than in `repository.owner.login`.
- `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` then dispatches the full, self-authored `params` to handlers that resolve the target `Stack`/`Repository` from `repository.full_name` (e.g. `PushHandler#process` matches `stacks.where(branch:)` scoped through `Repository.from_github_repo_name(params.repository.full_name)` used across handlers, and `StatusHandler` matches purely on `Commit.where(sha: params.sha)` with no owner check at all) [6](#0-5) [7](#0-6) .
- Because `repository.owner.login` (used only to select the verification secret) and `repository.full_name` (used to select the write target) are two independently-attacker-controlled fields in the same signed body, an attacker who legitimately controls a GitHub App installation configured under Shipit for `attacker-org` (and therefore knows/possesses that org's `webhook_secret`) can craft `{"repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"}, ...}`, sign it with the `attacker-org` secret, and Shipit will accept it as valid and dispatch a `push`/`status`/`check_suite`/`membership` event as if it legitimately originated from `victim-org/victim-repo`.

This is the "organization that authenticated versus the repository that is written" binding named in scope: the equality `verifying_org == writing_repo.owner` is never enforced.

### Impact Explanation
This is a cross-repository/cross-tenant integrity break, not merely benign noise:
- `PushHandler` triggers `stack.sync_github(expected_head_sha:)` for any stack whose branch matches, on a repository/stack the attacker doesn't own [3](#0-2) .
- `StatusHandler` writes forged CI/commit statuses onto arbitrary commits found solely by `sha`, with no repository/owner check at all — an attacker can inject a fake "success" status for any known SHA in any stack, which can unblock CI-gated deploys/merges in `MergeRequest#reject_unless_mergeable!` and `StatusChecker` [4](#0-3) [8](#0-7) .
- `PullRequest`/`OpenedHandler` and friends resolve `Repository.from_github_repo_name(params.repository.full_name)` to create/attach review stacks and pull request state for a victim repository from a payload authenticated under a different org [9](#0-8) .

Given this can force fake CI-success statuses and trigger unintended stack syncs on a victim repository/stack that the attacker was never granted, it satisfies the "High: escalation ... unauthorized deploy/merge-adjacent state manipulation" bar, and in combination with CI-gated auto-merge configurations it can escalate to an unauthorized merge.

### Likelihood Explanation
Requires the deployment to run a **multi-tenant** Shipit instance (multiple orgs configured under `secrets.github` with distinct per-org webhook secrets) where the attacker legitimately administers at least one of the configured organizations/GitHub App installations — a realistic setup for shared internal Shipit deployments serving many teams/orgs. No repository write access, session, or `ApiClient` token is needed; only the ability to know one's own org's configured webhook secret and to send an arbitrary POST to `/webhooks`.

### Recommendation
After selecting the verification secret from `repository.owner.login`/`organization.login`, verify that this same value is the owner-prefix of `repository.full_name` (and of `organization.login` when both are present) before dispatching to handlers; reject the request (422) on mismatch. Alternatively, resolve the target `Stack`/`Repository` strictly by `(owner, name)` pairs taken from the same field that was authenticated, rather than trusting `full_name` independently in each handler.

### Proof of Concept
1. Shipit configured with `secrets.github: { "attacker-org" => {webhook_secret: S_A, ...}, "victim-org" => {webhook_secret: S_V, ...} }`, with `Stack` for `victim-org/victim-repo` existing.
2. Attacker (who legitimately administers `attacker-org`'s GitHub App/knows `S_A`) crafts:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha already known to exist in victim stack>",
  "repository": { "owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo" }
}
```
3. POST to `/webhooks` with header `X-Github-Event: push` and `X-Hub-Signature: sha1=<HMAC-SHA1(S_A, body)>`.
4. `WebhooksController#verify_signature` computes `repository_owner = "attacker-org"`, fetches `attacker-org`'s secret, verifies successfully [5](#0-4) .
5. `create` dispatches to `PushHandler`, which finds `victim-org/victim-repo`'s stack by branch and calls `stack.sync_github` — an action the attacker was never authorized to trigger on that stack [3](#0-2) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
