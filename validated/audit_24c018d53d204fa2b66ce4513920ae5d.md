## Analog Found

### Title
Permanent unresolvable dependency from TTL-limited in-memory pruned-joint cache races network-wide pruning, stalling confirmation of units spending old final-bad outputs - (File: `archiving.js`, `validation.js`, `network.js`)

### Summary
The CVE describes a use-after-free caused by a race between two code paths that share mutable state without a durable, always-valid handle to that state (`af_unix.c`'s `unix_scm_to_skb`). The ocore analog is the "pruned content recovery" subsystem that lets validation temporarily depend on an in-memory cache (`archiving.js` `assocCachedPrunedJoints`) that is torn down on both a TTL and network-wide pruning cadence. Validation logic (`validation.js`) that spends an already-pruned `final-bad` output relies on this transient cache or on a best-effort network-wide recovery race (`network.js` `tryRecoverPrunedContentOfFinalBadUnit`) that has no guaranteed positive outcome, leaving the dependent unit's disposition undefined/stuck rather than deterministically resolved.

### Finding Description
When an output's source unit is `final-bad` and has already been stripped locally (`main_chain_index < storage.getMinRetrievableMci()`), `validatePaymentInputsAndOutputs` in [1](#0-0)  tries `archiving.getCachedOutput()`. If the data isn't in the short-lived, process-local cache, it returns `{error_code: "unresolved_dependency", ..., bRequestPrunedContent: true}`, which `network.js` turns into a one-shot peer request and a bookkeeping entry in `assocUnitsWaitingForPrunedContent` [2](#0-1) .

The recovery path is inherently racy against the very pruning it's trying to work around:
- The cache that services this dependency, `assocCachedPrunedJoints`, is populated either when *this* node prunes the unit (`archiving.cachePrunedJoint(objJoint)` in [3](#0-2) ) or when a peer sends back recovered content ( [4](#0-3) ), and expires unconditionally after `PRUNED_JOINT_CACHE_TTL_ms` (1 hour) via `purgeExpiredCachedPrunedJoints` [5](#0-4) .
- Because pruning of `final-bad` units happens deterministically off the globally-agreed `min_retrievable_mci` ( [6](#0-5) ), essentially every full node prunes the same unit within a similar window and starts (and ends) its 1-hour cache TTL at roughly the same time.
- The waiting-side bookkeeping (`assocUnitsWaitingForPrunedContent`) is also purged after 1 hour, deleting the withheld joint from rocksdb (`kvstore.del('wj\n' + o.unit)`), [7](#0-6) , with no alternative resolution (e.g., explicit rejection/ifUnitError) — the unit is simply forgotten from `assocUnitsWaitingForPrunedContent`/rocksdb while `assocUnitsInWork[unit]` was already cleared at request time ( [8](#0-7) ), so it is neither accepted, rejected, nor retried again.

If a unit that spends such a stale, pruned `final-bad` output is (re-)submitted or replayed (e.g., during catch-up, hash-tree processing, or simply because it arrives from a slow/delayed peer) after this common network-wide TTL window has elapsed on all reachable full nodes, no peer can supply `getCachedOutput`/`cachePrunedJoint` data any more, and the request-response race in `tryRecoverPrunedContentOfFinalBadUnit` can never succeed. The unit's validation state is now undecidable by the intended mechanism: it cannot be proven to spend a `final-bad` output (which would normally be a hard rejection [9](#0-8) ) nor can it be validated as good, and it is dropped from tracking after the 1‑hour housekeeping purge — a torn-down/evicted-state race directly analogous to the referenced UAF: code assumes a handle to shared state remains valid across an asynchronous boundary, but a concurrent cleanup path removes it first.

### Impact Explanation
Units (and anything chained on them, e.g., dependent payments or AA triggers) that reference an already-pruned `final-bad` output and lose the recovery race become permanently unconfirmable on any full node that has already expired its `assocCachedPrunedJoints`/`assocUnitsWaitingForPrunedContent` entries — this is the "network unable to confirm new units" condition. Because the cache/bookkeeping state is per-process and time-based rather than derived from durable, agreed-upon on-chain state, different nodes can also transiently diverge on whether a given input is "known-recoverable" versus "unresolved," producing inconsistent validation-state views (`ifOk`/`ifNeedParentUnits`) for the same submitted joint across the network until/unless the discrepancy self-heals — a node-disagreement risk in a subsystem explicitly introduced to fix "spends that raced the pruning locally" (per the code comment in [10](#0-9) ), i.e., the fix's own race window is not fully closed.

### Likelihood Explanation
Triggering the underlying data shape (spending a final-bad, already-pruned output near/after the shared 1-hour cache window) requires only posting an ordinary unit referencing an old input — no privileged access, hub role, or peer-manipulation is needed, matching the "unprivileged unit poster" reachability requirement. However, actually landing squarely inside the narrow post-TTL/pre-any-recovery window on a broad set of nodes, and having the recovery race genuinely fail everywhere, requires specific timing (long-delayed replay/catch-up scenarios), so likelihood is moderate rather than trivially reproducible on demand.

### Recommendation
Persist recovered/about-to-be-pruned final-bad output data (address/amount/denomination/asset) in a durable store keyed by unit/message_index/output_index instead of, or in addition to, the volatile TTL-based `assocCachedPrunedJoints`/`assocUnitsWaitingForPrunedContent` in-memory maps, or extend the TTL to be tied to protocol-level guarantees (e.g., never purge before all interested waiting joints are resolved) rather than a fixed wall-clock timeout. Additionally, when `assocUnitsWaitingForPrunedContent` entries expire, explicitly fail the withheld joint (invoke an error callback / re-surface `ifUnitError`) instead of silently dropping it from rocksdb and all tracking maps, so nodes converge on a definite, network-wide decision rather than leaving the unit in limbo.

### Proof of Concept
1. Node A creates output `O` in unit `U1`, and unit `U2` spends `O`; a conflicting unit causes `U1`/`O` to resolve `final-bad`.
2. Once `main_chain_index(U1) < min_retrievable_mci` network-wide, every full node prunes `U1`'s content (`updateMinRetrievableMciAfterStabilizingMci`, [11](#0-10) ) and starts its independent 1‑hour `assocCachedPrunedJoints` TTL.
3. Wait more than 1 hour (or force cache eviction) so that no full node in the reachable network still holds `U1` in `assocCachedPrunedJoints`.
4. Re-submit/replay a unit `U3` (e.g., during catch-up) that spends `O` from `U1` while presenting an old `last_ball` so `bStableInParents` is false, hitting the `!src_output.address` branch in [1](#0-0) .
5. Observe: `getCachedOutput` returns `null` everywhere, `ifNeedParentUnits({..., bRequestPrunedContent:true})` fires on every node, `tryRecoverPrunedContentOfFinalBadUnit` never succeeds (no peer has `U1`'s content), and after another hour `assocUnitsWaitingForPrunedContent`/`wj\n`+unit records are purged ( [7](#0-6) ), leaving `U3` permanently unresolved/unconfirmed across the network with no explicit rejection ever issued.

const PRUNED_JOINT_CACHE_TTL_ms = 60 * 60 * 1000;
let assocCachedPrunedJoints = {};

function cachePrunedJoint(objJoint){
	assocCachedPrunedJoints[objJoint.unit.unit] = { objJoint: objJoint, expiry_ts: Date.now() + PRUNED_JOINT_CACHE_TTL_ms };
}

function getCachedPrunedJoint(unit){
	const cached = assocCachedPrunedJoints[unit];
	if (!cached)
		return null;
	return cached.objJoint;
}

// looks up a specific output within a cached pruned joint, in the same shape as the outputs table columns we lost to stripping
function getCachedOutput(unit, message_index, output_index){
	const objJoint = getCachedPrunedJoint(unit);
	if (!objJoint)
		return null;
	const message = objJoint.unit.messages && objJoint.unit.messages[message_index];
	if (!message || message.app !== 'payment' || !message.payload)
		return null;
	const output = message.payload.outputs && message.payload.outputs[output_index];
	if (!output)
		return null;
	return {
		address: output.address,
		amount: output.amount,
		denomination: message.payload.denomination || 1,
		asset: message.payload.asset || null
	};
}

function purgeExpiredCachedPrunedJoints(){
	const now = Date.now();
	for (let unit in assocCachedPrunedJoints)
		if (assocCachedPrunedJoints[unit].expiry_ts < now)
			delete assocCachedPrunedJoints[unit];
}
setInterval(purgeExpiredCachedPrunedJoints, PRUNED_JOINT_CACHE_TTL_ms);
