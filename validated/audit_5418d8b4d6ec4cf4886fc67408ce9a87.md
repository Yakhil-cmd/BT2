## Title
Webhook signature verification keys off `repository.owner.login`/`organization.login` while every handler resolves its target stack from the independent `repository.full_name` field, letting a forged payload write to a repository never covered by the verifying secret - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `Shipit::GitHubApp` (and thus which `webhook_secret`) to check a request against using `repository_owner`, computed from `params.dig('repository','owner','login')` (falling back to `organization.login`). All the actual event handlers (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, `PullRequest::*Handler`) resolve the `Stack`/`Repository` they act on from a *different* field of the same unauthenticated JSON body: `repository.full_name`, via `Handler#repository_name` / `Repository.from_github_repo_name`. Because GitHub's HMAC signature is only meaningful when a `webhook_secret` is actually configured, and the engine's own shipped/documented configuration examples leave `webhook_secret` blank (`nil`) by default, `GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever the selected org has no secret configured. This decouples "which organization/app authenticated the request" from "which repository's Stack the webhook payload is written to."

Both `repository.owner.login` (used to pick the verifying secret) and `repository.full_name` (used to pick the target `Stack`/`Repository`) live in the same attacker-supplied JSON payload and are never cross-checked against each other. Shipit's own documented/shipped configuration examples for multi-org setups leave `webhook_secret` blank by default (`config/secrets.development.example.yml`, `config/secrets.development.shopify.yml`, `docs/setup.md`'s multi-org example), so `verify_webhook_signature` returns `true` unconditionally for any org whose secret is unset: [5](#0-4) [6](#0-5) 

The binding that should hold is:
`organization/app whose secret authenticated the request == organization owning the repository the handler writes to`

Instead, only `repository.owner.login` is used to pick the authenticating secret, while `repository.full_name` (a separate, independently-forgeable field) is used to pick the `Repository`/`Stack` acted upon. An attacker able to satisfy verification for *any one* configured organization (trivially, one whose `webhook_secret` is unset - the documented default) can set `repository.owner.login`/`organization.login` to that unsecured org while setting `repository.full_name` to the full name of a Stack belonging to any other, properly-secured organization in the same Shipit instance.

### Impact Explanation
This is an unauthenticated write into Stack/Commit state for a repository outside the org that "authenticated" the webhook, satisfying the required "unauthorized deploy" impact class:
- `StatusHandler` lets the attacker fabricate a `success` `Status` (with attacker-chosen `context`) on any commit for a targeted Stack. If that Stack has `continuous_deployment` enabled and that context is the required CI context, `Status#schedule_continuous_delivery` → `ContinuousDeliveryJob` → `Stack#trigger_continuous_delivery` triggers an actual automated deploy that was never legitimately blessed by real CI/checks. [7](#0-6) [8](#0-7) 
- `PushHandler`/`CheckSuiteHandler` can force `GithubSyncJob`/`RefreshCheckRunsJob` to run against arbitrary Stacks in a different org, causing the engine to make GitHub API calls using the wrong org's credentials/authorization boundary and mutate commit/check state for repositories the "authenticating" org has no relation to. [9](#0-8) 

### Likelihood Explanation
The precondition is realistic and low-effort: multi-org Shipit deployments only need *one* configured organization with `webhook_secret` unset (which is the value shown blank/`nil` in every shipped example config and the setup docs) to make signature verification a no-op for that org - after which the attacker fully controls `repository.owner.login`/`organization.login` and `repository.full_name` independently in the same POST body, with no other authentication required (`WebhooksController` skips CSRF and requires no session/API token).

### Recommendation
Cross-validate that the organization used to select/verify the webhook secret (`repository.owner.login`/`organization.login`) matches the organization actually owning the `Repository`/`Stack` resolved by each handler's `repository.full_name` before processing; reject the request otherwise. Additionally, require `webhook_secret` to be present for every configured organization (fail closed rather than returning `true` when unset) so `verify_webhook_signature` cannot silently no-op for any org in a multi-org configuration.

### Proof of Concept
1. Deploy Shipit with two configured organizations in `config/secrets.yml`: `TrustedOrg` (no `webhook_secret` set, matching the documented default) and `SecureOrg` (has a Stack for `SecureOrg/prod-app` with `continuous_deployment: true` and a required CI context `ci/build`).
2. POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "sha": "<head sha of SecureOrg/prod-app>",
  "state": "success",
  "context": "ci/build",
  "repository": { "owner": { "login": "TrustedOrg" }, "full_name": "SecureOrg/prod-app" }
}
```
No `X-Hub-Signature` header is required to be valid because `repository_owner` resolves to `TrustedOrg`, whose `verify_webhook_signature` returns `true` unconditionally (no secret configured).
3. `WebhooksController` dispatches to `StatusHandler`, which finds the commit via `sha` (independent of `repository.full_name`/owner) and creates a `success` `Status` for `ci/build` on `SecureOrg/prod-app`'s Stack.
4. If this satisfies the Stack's continuous-deployment condition, `ContinuousDeliveryJob` triggers an unauthorized deploy of `SecureOrg/prod-app`, despite the attacker never having credentials for `SecureOrg`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
