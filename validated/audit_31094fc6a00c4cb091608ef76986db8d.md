### Title
Cross-Organization Repository Write via Webhook Signature/Target Binding Confusion - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to validate a request against using the `repository.owner.login` (or `organization.login`) field of the *unverified* JSON body, but the webhook handlers that actually mutate state (sync stacks, run jobs, merge/label PRs, etc.) select their target `Repository`/`Stack` using a *different* field from the same body: `repository.full_name`. Nothing ties these two fields together, so the "organization whose secret authenticated the request" and "the repository that is actually acted upon" are never proven to be the same tenant.

### Finding Description
`WebhooksController#verify_signature` computes `repository_owner` from the payload and fetches the app for that org, then checks the signature against that org's secret: [1](#0-0) [2](#0-1) 

Crucially, `GitHubApp#verify_webhook_signature` treats an org with **no configured secret** as automatically verified: [3](#0-2) 

`config/secrets.development.example.yml` documents `webhook_secret: # nil` as a supported per-organization configuration in multi-org setups, i.e. it is normal/documented for some configured organizations to have no secret at all. [4](#0-3) 

Once `verify_signature` passes, the full raw payload is dispatched unchanged to handlers: [5](#0-4) 

Every handler resolves its target `Stack`/`Repository` from `payload.dig('repository', 'full_name')`, an entirely independent field from the one used for signature/org selection: [6](#0-5) [7](#0-6) 

`PushHandler#process` then acts directly on any stacks matching that repository's branch: [8](#0-7) 

This is the same bug class as the report: `enableConcreteLite` trusted a `loanId_Owner` value without validating it belonged to the acting party before sending state-changing messages. Here, Shipit trusts `repository.owner.login` to pick the *authentication* key, but trusts the sibling, unchecked field `repository.full_name` to pick the *authorization target* — the two are never validated as referring to the same tenant.

**Binding broken (as an equality):**
`organization_that_authenticated (payload.repository.owner.login → secret used in verify_webhook_signature)` **must equal** `organization_that_is_written (payload.repository.full_name.split('/').first → Repository.from_github_repo_name → Stack acted on)`, but the engine never enforces this equality.

- Before the attack: both fields normally point to the same real GitHub repository because GitHub itself populates the payload honestly.
- After a crafted delivery: an unauthenticated caller sets `repository.owner.login` (or `organization.login` for org-scoped events) to any organization configured in Shipit **without** a `webhook_secret` — signature check auto-passes per `return true unless webhook_secret` — while setting `repository.full_name` to `victim-org/victim-repo`, a completely different, secured tenant. `verify_signature` succeeds, and the handler mutates `victim-org`'s stack.

### Impact Explanation
An unauthenticated attacker who knows (or guesses) that any organization configured on the Shipit instance lacks a `webhook_secret` (a documented, supported configuration state) can forge webhook deliveries that are treated as fully verified, and then point `repository.full_name` at any other configured tenant's repository. Depending on which handler fires this enables triggering `GithubSyncJob`/`RefreshCheckRunsJob` on stacks not owned by the "authenticating" org, or manipulating pull-request/label/status/membership state cross-tenant — an unauthorized action against a repository the request was never actually authenticated for. This matches the High-impact criterion of "unauthenticated read of stack state, task streams or deploy output" and can extend toward unauthorized deploy triggers depending on which handlers are registered.

### Likelihood Explanation
Requires only that the Shipit instance be configured with more than one GitHub organization/app and that at least one configured organization have no `webhook_secret` set — a state the shipped example config treats as normal (`webhook_secret: # nil`). No credentials, session, or GitHub write access are needed; only network access to the `webhooks_controller` endpoint and knowledge of one unsecured org's login name.

### Recommendation
Bind the field used for signature verification and the field used to select the mutation target to the same value, and reject the request if they diverge. Concretely, `WebhooksController#verify_signature` should re-derive the organization from `repository.full_name` (or whatever field the dispatched handler will use) rather than a separately-controlled `repository.owner.login`/`organization.login`, and/or `Handler#repository_name` should assert that the resolved repository's owner matches the organization whose secret verified the request. Additionally, do not treat an organization with a blank `webhook_secret` as automatically verified; require an explicit secret for any organization capable of authorizing webhook-driven actions.

### Proof of Concept
1. Configure Shipit with two organizations: `decoy-org` (no `webhook_secret`) and `victim-org` (has repos/stacks configured with a secret).
2. Send an unauthenticated `POST /webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "decoy-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. `verify_signature` resolves `Shipit.github(organization: 'decoy-org')`, whose `verify_webhook_signature` returns `true` unconditionally because `decoy-org` has no `webhook_secret`.
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name('victim-org/victim-repo')` and enqueues `sync_github` on `victim-org`'s real stack — despite the request never being authenticated for `victim-org`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
