Confirmed finding: `pkg/cmd/skills/list/list.go` has an explicit `sanitizeForTerminal` helper (using `asciisanitizer.Sanitizer`) that is applied to skill names/sources before rendering the `skills list` table [1](#0-0) , but `printFileTree`/`printTreeDir` in `pkg/cmd/skills/install/install.go` has no equivalent sanitization — it writes `entry.Name()` straight to `w` via `fmt.Fprintf`, only wrapping it in `cs.Bold`/`cs.Muted` (which just add SGR color codes around the string, not strip control bytes) [2](#0-1) .

### Title
Unsanitized attacker-controlled filenames printed to terminal in `printFileTree` allow terminal escape-sequence injection - (File: pkg/cmd/skills/install/install.go)

### Summary
`printFileTree`/`printTreeDir` renders the names of files extracted from an attacker-published skill directly to the terminal without any control-character or ANSI/OSC sanitization, unlike the sibling `skills list` command which explicitly sanitizes such strings with `asciisanitizer.Sanitizer`. Since skill file paths originate from GitHub tree entries in an attacker's repository, an attacker can name a file with embedded OSC 8 hyperlink, title-set, or bracketed-paste sequences that get echoed to the victim's terminal on `gh skill install`.

### Finding Description
`printFileTree` is called after `gh skills install` downloads a skill and prints its resulting on-disk layout to help the user review what was installed [3](#0-2) . `printTreeDir` recursively walks the extracted directory with `os.ReadDir` and prints each `entry.Name()` verbatim: `fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), name)` for files, and `cs.Bold(name+"/")` for directories [4](#0-3) . These names come from `discovery.DiscoverSkillFiles`/`FetchBlob`, which resolve the attacker's repository tree/blob paths, and are written to disk as-is in `installSkill` via `safepaths` (which only guards against path traversal, not disallowed byte content) — file names are otherwise passed through unmodified as `relPath`/`destPath` and then `os.WriteFile` [5](#0-4) . Unix filesystems permit arbitrary bytes in filenames except `/` and NUL, so an attacker can name a file (or an entry under `SKILL.md`'s associated skill directory) with embedded ANSI/OSC control sequences, e.g. an OSC 8 hyperlink escape with a non-http URI, or a title-set/report sequence. `cs.Bold`/`cs.Muted` only wrap the string in additional SGR codes; they do not strip or escape existing control bytes already present in `name`. Since the wiki's exploit note ("Embed the payload in a PR title/body/check output the victim displays") is not directly applicable here (the reachable path is the extracted filename itself, not PR text), the actual concrete reachable vector is the archive/blob filename rendered by `printFileTree`, which is directly comparable to the sanitization gap that `sanitizeForTerminal` in `pkg/cmd/skills/list/list.go` was added to close for the `list` command, confirming the maintainers recognize this class of risk for skill-derived strings but did not apply the same protection to `install`'s tree printer.

### Impact Explanation
A malicious skill published to a repository can cause the victim's terminal, upon running `gh skill install`, to render escape sequences from the printed file tree. Depending on the victim's terminal emulator, this can enable OSC 8 hyperlink spoofing to a non-http URI (e.g., `file://`), window-title manipulation, or bracketed-paste-disabling sequences that make subsequent attacker text auto-execute if echoed back to a shell. This matches GitHub's bounty class for terminal-escape/command-injection style issues, with worst-case impact scoped to terminal manipulation/spoofing rather than direct RCE (RCE claims via OSC sequences require terminal-emulator-specific vulnerabilities, which are outside the `gh` codebase itself).

### Likelihood Explanation
An attacker only needs to publish a public repo with a skill whose file/directory has a crafted name; no privileges beyond publishing a repo are required, and any user running `gh skill install <attacker-repo>` triggers the vulnerable print path. The precondition is that the destination filesystem accepts the crafted byte sequence in the filename (true on Linux/macOS ext4/APFS; NTFS on Windows is more restrictive of certain bytes but many control bytes are still permitted).

### Recommendation
Apply the same control-character sanitization used in `pkg/cmd/skills/list/list.go`'s `sanitizeForTerminal` (built on `github.com/cli/go-gh/v2/pkg/asciisanitizer`) to `name` before printing it in `printTreeDir`/`printFileTree`, and consider centralizing this sanitizer so all skill-name/file-name rendering paths (`install`, `list`, `preview`, etc.) use it consistently.

### Proof of Concept
```go
func TestPrintFileTree_SanitizesControlSequences(t *testing.T) {
    dir := t.TempDir()
    skillDir := filepath.Join(dir, "evil-skill")
    require.NoError(t, os.MkdirAll(skillDir, 0o755))

    // Filename containing an OSC 8 hyperlink escape sequence with a non-http URI.
    maliciousName := "safe\x1b]8;;file:///etc/passwd\x07CLICK\x1b]8;;\x07.txt"
    require.NoError(t, os.WriteFile(filepath.Join(skillDir, maliciousName), []byte("x"), 0o644))

    var buf bytes.Buffer
    cs := iostreams.NewColorScheme(true, true, true)
    printFileTree(&buf, cs, dir, []string{"evil-skill"})

    out := buf.String()
    require.NotContains(t, out, "\x1b]8;;file://", "OSC 8 hyperlink escape sequence must be stripped/sanitized before printing")
}
```
Expected (current) result: the test fails because `out` contains the raw `\x1b]8;;file:///etc/passwd\x07` sequence, confirming the sanitization gap relative to `sanitizeForTerminal` used elsewhere in the skills codebase [1](#0-0) .

// sanitizeForTerminal replaces ASCII control characters in s with inert

func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}

// printFileTree renders a text tree of the on-disk contents of each skill directory.
func printFileTree(w io.Writer, cs *iostreams.ColorScheme, dir string, skillNames []string) {
	if len(skillNames) == 0 {
		return
	}
	fmt.Fprintln(w)
	for _, name := range skillNames {
		skillDir := filepath.Join(dir, filepath.FromSlash(name))
		fmt.Fprintf(w, "  %s\n", cs.Bold(name+"/"))
		printTreeDir(w, cs, skillDir, "  ")
	}
}

func printTreeDir(w io.Writer, cs *iostreams.ColorScheme, dir, indent string) {
	entries, err := os.ReadDir(dir)
	if err != nil {
		fmt.Fprintf(w, "%s%s\n", indent, cs.Muted("(could not read directory)"))
		return
	}
	for i, entry := range entries {
		isLast := i == len(entries)-1
		connector := "├── "
		childIndent := "│   "
		if isLast {
			connector = "└── "
			childIndent = "    "
		}
		name := entry.Name()
		if entry.IsDir() {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), cs.Bold(name+"/"))
			printTreeDir(w, cs, filepath.Join(dir, name), indent+cs.Muted(childIndent))
		} else {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), name)
		}
	}
}
