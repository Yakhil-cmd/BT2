### Title
Unbounded `io.ReadAll` + snappy decompression bomb in `getBundle` allows memory-exhaustion DoS via attacker-controlled `bundle_url` payload - ([File: pkg/cmd/attestation/api/client.go])

### Summary
`(*LiveClient).getBundle` reads the entire HTTP response body from an attestation's `bundle_url` into memory with `io.ReadAll` and then decompresses it with `snappy.Decode(nil, body)` without any size limits at either stage. Since the `bundle_url` response body ultimately reflects an attestation bundle that an attacker can control (by publishing an attestation on a repository/artifact they control), a crafted response can trigger an unbounded read and/or a snappy decompression bomb, exhausting memory on the victim's machine when they run `gh attestation verify`/`inspect`/`download`.

### Finding Description
The relevant call sequence is: [1](#0-0) 

1. `fetchBundleFromAttestations` calls `c.getBundle(safeurl.NewImmutableSafeURL(a.BundleURL))` where `a.BundleURL` originates from the GitHub attestations API response for the digest being verified [2](#0-1) .
2. Inside `getBundle`, the response body is fully buffered via `io.ReadAll(resp.Body)` with no `http.MaxBytesReader` or length cap [3](#0-2) .
3. The raw bytes are then passed straight to `snappy.Decode(out, body)` with `out` being `nil`, meaning the decoder allocates a buffer sized according to the length field embedded in the attacker-supplied snappy stream header before validating the remaining content [4](#0-3) .
4. No existing check in this file (or in `safeurl`) restricts the size of the response body or the claimed decompressed length; `safeurl` only validates/normalizes the URL host/scheme, not response size, and there is no cap comparable to `maxLimitForFetch`/`maxLimitForFlag` used for pagination limits elsewhere in the file [5](#0-4) .

Because `bundle_url` content is effectively the attestation bundle payload previously uploaded/associated by the artifact owner, an attacker who controls the repository/artifact under verification (or otherwise controls the endpoint content served for `bundle_url`, per the question's stated precondition) can supply a small compressed body whose snappy header declares an extremely large uncompressed length (the snappy block format's length varint permits values up to about 4 GiB), forcing a large single allocation, or can supply a very large raw body to be read into memory before decompression is even attempted.

### Impact Explanation
This is a denial-of-service / resource-exhaustion issue on the machine running `gh attestation verify`/`inspect`/`download` — worst case a large allocation attempt can crash the CLI process or, on constrained systems, exhaust the host memory. It does not lead to code execution, credential exfiltration, file write outside intended paths, or verification bypass; the resulting decompressed bytes would still need to pass `protojson.Unmarshal` into a `v1.Bundle` and subsequent sigstore bundle validation, so no signature/attestation bypass results from this path alone. This maps to a DoS-class impact, not a memory-safety/RCE-class impact.

### Likelihood Explanation
Preconditions: the attacker must be able to make the CLI fetch a `bundle_url` whose content they control — this is plausible for an attacker who publishes their own repository/artifact and associated attestation, since a victim who runs `gh attestation verify` against attacker-supplied artifacts/repos will have the CLI fetch `bundle_url` from GitHub's attestation storage populated with attacker-supplied bundle bytes. The exploit requires no privilege beyond publishing content and is fully repeatable/deterministic (crafting a snappy header with a large declared length is trivial). No network position or credential theft is required.

### Recommendation
- Wrap `resp.Body` with `http.MaxBytesReader`/`io.LimitReader` before `io.ReadAll` to cap the number of bytes read from the network response (e.g., a few MB, consistent with expected sigstore bundle sizes).
- Use `snappy.DecodedLen` (or equivalent) to check the claimed decompressed size against a sane maximum before calling `snappy.Decode`, rejecting the response early if the declared length is implausible.
- Consider adding a request timeout / context deadline on `externalHttpClient.Get` calls to bound total time spent regardless of response size.

### Proof of Concept
```go
func FuzzGetBundleSnappyBomb(f *testing.F) {
    f.Add([]byte{0xff, 0xff, 0xff, 0xff, 0x0f}) // varint declaring ~4GiB decoded length, no payload
    f.Fuzz(func(t *testing.T, body []byte) {
        var out []byte
        start := time.Now()
        var mstart, mend runtime.MemStats
        runtime.ReadMemStats(&mstart)

        decompressed, err := snappy.Decode(out, body)
        _ = decompressed

        runtime.ReadMemStats(&mend)
        elapsed := time.Since(start)

        // Assert bounded time and bounded allocation growth even on malformed/adversarial input.
        if elapsed > 2*time.Second {
            t.Fatalf("snappy.Decode took too long: %v", elapsed)
        }
        if mend.TotalAlloc-mstart.TotalAlloc > 200*1024*1024 { // 200MB threshold
            t.Fatalf("snappy.Decode allocated too much memory: %d bytes (err=%v)", mend.TotalAlloc-mstart.TotalAlloc, err)
        }
    })
}
```
Additionally, an httpmock-based integration test can register a `bundle_url` responder that streams a small crafted snappy header claiming a multi-GB decoded length and assert that `LiveClient.getBundle` returns an error (post-fix, after adding size caps) rather than attempting a large allocation, exercising the exact `getBundle` → `io.ReadAll` → `snappy.Decode` path shown at [6](#0-5) .

func (c *LiveClient) getBundle(url safeurl.SafeURL) (*bundle.Bundle, error) {
	c.logger.VerbosePrintf("Fetching attestation bundle with bundle URL\n\n")

	var sgBundle *bundle.Bundle
	bo := backoff.NewConstantBackOff(getAttestationRetryInterval)
	err := backoff.Retry(func() error {
		resp, err := c.externalHttpClient.Get(url.String())
		if err != nil {
			return fmt.Errorf("request to fetch bundle from URL failed: %w", err)
		}

		if resp.StatusCode >= 500 && resp.StatusCode <= 599 {
			return fmt.Errorf("attestation bundle with URL %s returned status code %d", url.String(), resp.StatusCode)
		}

		defer resp.Body.Close()
		body, err := io.ReadAll(resp.Body)
		if err != nil {
			return fmt.Errorf("failed to read blob storage response body: %w", err)
		}

		var out []byte
		decompressed, err := snappy.Decode(out, body)
		if err != nil {
			return backoff.Permanent(fmt.Errorf("failed to decompress with snappy: %w", err))
		}

		var pbBundle v1.Bundle
		if err = protojson.Unmarshal(decompressed, &pbBundle); err != nil {
			return backoff.Permanent(fmt.Errorf("failed to unmarshal to bundle: %w", err))
		}
