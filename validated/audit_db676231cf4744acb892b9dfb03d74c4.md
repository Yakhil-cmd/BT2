### Title

Unvalidated route pool contracts can execute attacker-chosen calls under the caller’s authorization - (File: contracts/swap-aggregator/src/execute/mod.rs)

### Summary

The swap router treats every address in the user-supplied `assets` registry as a callable pool address and invokes it through the selected venue adapter without verifying that it is a known or authentic pool contract. Because route execution occurs below the caller’s `require_auth` authorization, malicious pool code can add unrelated token transfers to the authorization tree recorded by simulation. A victim who signs that tree can lose tokens entirely unrelated to the swap.

### Finding Description

`execute_strategy` authenticates only `sender`, decodes the supplied strategy, and executes each decoded hop using `pool = assets[idx_a]`. [1](#0-0) [2](#0-1)  `Program::validate` checks opcode bytes, registry bounds, token-chain structure, amount modes, and split weights, but does not authenticate `idx_a` as a legitimate venue contract. [3](#0-2)  For an Aquarius-labelled hop, the router queries the payload-selected address and invokes its `swap` function, meaning the pool contract itself is attacker-controlled if the attacker supplies the route. [4](#0-3)  The router’s measured input/output checks constrain the routed token deltas, but they do not constrain additional calls that the malicious pool performs against contracts requiring the caller’s authorization. [5](#0-4)  The repository’s dedicated test demonstrates that a rogue pool’s `token.transfer(victim, attacker, amount)` is recorded under the caller’s `swap_collateral` authorization and succeeds when that poisoned tree is signed. [6](#0-5) [7](#0-6) 

### Impact Explanation

An unprivileged attacker can steal arbitrary SEP-41 token balances from a victim’s wallet by convincing the victim to use a malicious route and sign the authorization tree produced by simulation. The stolen asset need not be a lending market asset or otherwise participate in the swap, and the amount is bounded only by the victim’s balance and the authorization the victim signs. The same authorization-tree abuse is reachable through direct `execute_strategy` calls and controller strategy calls such as `swap_collateral`, since the controller authenticates the caller and passes the caller-provided route to the configured router. [8](#0-7) [9](#0-8) 

### Likelihood Explanation

The attacker needs to deploy a contract implementing the called venue interface, place its address in a route, and have a victim submit/sign that route. The malicious pool can still return a valid output so the router’s positive-output, input-spend, and minimum-output checks pass. [10](#0-9) [11](#0-10)  The exploit therefore does not require privileged access, leaked keys, malformed token behavior, or failure of another contract; it relies on the opaque authorization tree containing an extra legitimate-looking child invocation.

### Recommendation

Authenticate route executors instead of accepting arbitrary `pool` addresses. Maintain a governance-controlled registry or allowlist of valid pool contracts per venue, verify each hop’s `pool` before invocation, and bind any trusted quote/router metadata to the expected venue contract. At minimum, reject routes whose pool addresses are not registered and surface a canonical authorization-tree check so clients can reject any child invocation beyond the expected input-token transfer.

### Proof of Concept

1. Attacker deploys a fake Aquarius-compatible pool whose `get_tokens` returns the victim’s input and output tokens and whose `swap` calls `token.transfer(victim, attacker, victim_wallet_balance)` on an unrelated token.
2. Attacker funds the fake pool or an accomplice contract with enough `token_out` to make the swap appear successful.
3. Attacker supplies the victim a route whose `assets` registry contains that fake pool address; `Program::decode` accepts it because address-registry entries are not validated as authentic pools. [12](#0-11) 
4. Victim calls `swap_collateral(caller=victim, account_id, current, amount, new, malicious_route)` or direct `execute_strategy(sender=victim, total_in, malicious_route)`.
5. During execution, the router calls the fake pool, which performs the unrelated victim-to-attacker token transfer while also producing the measured `token_out` increase.
6. Simulation records that extra transfer under the victim’s authorization entry; if the victim signs the returned tree, the unrelated wallet tokens are stolen and the swap still completes. [13](#0-12) [6](#0-5)

    fn validate(&self, env: &Env, assets_len: u32, amounts_len: u32, weight_count: u32) {
        for i in 0..self.op_count {
            let record = self.raw(i);
            let Some(opcode) = Opcode::from_u8(record[field::OPCODE]) else {
                panic_with_error!(env, Error::InvalidRouteXdr);
            };
            let mode = Mode::from_u8(record[field::MODE]);
            let (idx_a, idx_b, idx_c) = (
                record[field::POOL] as u32,
                record[field::TOKEN_IN] as u32,
                record[field::TOKEN_OUT] as u32,
            );

            // `Prev` is a purely structural link: the predecessor must exist,
            // must have a single output, and that output must be this
            // instruction's input.
            if mode == Mode::Prev {
                if i == 0 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
                let previous = self.raw(i - 1);
                let produced = match Opcode::from_u8(previous[field::OPCODE]) {
                    // A swap produces its `token_out`, a mint its share token.
                    Some(Opcode::Swap(_)) => previous[field::TOKEN_OUT],
                    Some(Opcode::Mint) => previous[field::TOKEN_IN],
                    // A burn releases every constituent at once.
                    _ => panic_with_error!(env, Error::BrokenTokenChain),
                };
                if idx_b != produced as u32 {
                    panic_with_error!(env, Error::BrokenTokenChain);
                }
            }
            match mode {
                Mode::Fixed(idx) if idx as u32 >= amounts_len => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                Mode::Ppm(idx) if idx as u32 >= weight_count => {
                    panic_with_error!(env, Error::InvalidRouteXdr)
                }
                _ => {}
            }

            if idx_a >= assets_len || idx_b >= assets_len {
                panic_with_error!(env, Error::InvalidRouteXdr);
            }
            match opcode {
                Opcode::Swap(_) => {
                    if idx_c >= assets_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_b == idx_c {
                        panic_with_error!(env, Error::SameToken);
                    }
                }
                // Liquidity legs spend the full vault balance, so only `Mode::All` is valid.
                Opcode::Burn | Opcode::Mint => {
                    if mode != Mode::All {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                    if idx_c >= amounts_len {
                        panic_with_error!(env, Error::InvalidRouteXdr);
                    }
                }
            }
        }

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
