### Title
Stale delegate grants regain account control after NFT ownership returns - ([File: contracts/controller/src/storage/account.rs])

### Summary
High severity. Delegate grants are stamped with the NFT owner at grant time, but transferring the position NFT does not delete the stored grant. If ownership later returns to the granting address, the stale grant again satisfies `require_owner_or_delegate`, allowing the former delegate to withdraw the account’s collateral or borrow against it.

### Finding Description
`is_owner_or_delegate` accepts a caller when they are the current account owner or when they are an active manager present in `get_delegates(env, account_id, owner)`. [1](#0-0)  `get_delegates` does not record an ownership epoch or generation; it returns the stored `DelegateGrant` whenever `grant.granted_by` equals the currently resolved NFT owner. [2](#0-1)  The grant therefore becomes inactive while a different owner holds the NFT, but it is not disconnected or removed, and it automatically becomes authoritative again if the NFT returns to `granted_by`. [2](#0-1)  Although `remove_delegate` deletes a mismatched grant when called, deletion is only a manual cleanup path and does not occur when the NFT is transferred. [3](#0-2) 

This is analogous to the kernel bug: an object remains present but lacks the metadata needed to keep it permanently unreachable after its parent changes. Here, the delegate grant remains stored without an ownership-generation binding, so moving back to the old owner resurrects it.

### Impact Explanation
After the NFT returns to the original owner, the former delegate can pass `require_owner_or_delegate` without fresh authorization from that owner. [4](#0-3)  The revived delegate can call `withdraw`; a zero withdrawal amount is translated into the withdraw-all sentinel and the proceeds may be sent to a caller-selected external recipient. [5](#0-4) [6](#0-5)  For an account with collateral, this permits theft of withdrawable user funds; for a leveraged account, the revived delegate can also borrow within the account’s risk limits and take the proceeds, leaving the owner with the debt.

### Likelihood Explanation
The attack requires three preconditions: the original owner previously granted an active manager, the NFT is transferred to another address, and it later returns to the original owner. Those are all reachable through the allowed position-NFT transfer and controller delegation paths. The former delegate needs no new signature from the victim after the return transfer and can act before the victim manually removes the stale grant.

### Recommendation
Bind delegate grants to an ownership generation that changes on every NFT transfer, or store both the granting owner and an NFT transfer epoch/version and reject grants stamped under an older epoch. Alternatively, have the controller maintain a transfer-aware authorization epoch indexed by `account_id`, increment it before ownership changes become effective, and include that epoch in `DelegateGrant`. Simply deleting stale grants during `remove_delegate` is insufficient because authority revives before that cleanup runs. [3](#0-2) 

### Proof of Concept
1. Alice creates controller account `account_id`, supplies collateral, and calls `add_delegate(account_id, mallory_manager)` while the manager is active. This stores a grant whose `granted_by` is Alice. [7](#0-6) 
2. Alice calls `position-nft::transfer(account_id, alice, bob)`. Controller storage still contains the Alice-stamped grant; it only fails while Bob is the owner because `get_delegates` filters on the current owner. [2](#0-1) 
3. Bob calls `position-nft::transfer(account_id, bob, alice)`. `account_owner(account_id)` again resolves to Alice through the NFT. [8](#0-7) 
4. The stale grant’s `granted_by == alice`, so `get_delegates(account_id, alice)` returns `mallory_manager`; `is_owner_or_delegate` accepts it if the manager is still active. [1](#0-0) 
5. Mallory calls `controller::withdraw(account_id, [(collateral_hub_asset, 0)], Some(mallory))`. The zero amount requests the full position, and the recipient can be Mallory’s external address. [6](#0-5) 
6. The pool withdraw leg transfers the collateral to Mallory, even though Alice never reauthorized Mallory after regaining the NFT. [9](#0-8)

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Authenticates the NFT owner and updates delegates; grants require an active
/// manager. Emits an event only when the current owner's delegate list changes.
fn set_account_delegate(
    env: &Env,
    caller: &Address,
    account_id: u64,
    delegate: &Address,
    add: bool,
) {
    caller.require_auth();
    require_account_owner(env, account_id, caller);
    if add {
        // Reject dormant grants that could gain authority on later manager activation.
        assert_with_error!(
            env,
            storage::get_position_manager(env, delegate).is_some_and(|c| c.is_active),
            GenericError::NotAuthorized
        );
    }

    let changed = if add {
        storage::add_delegate(env, account_id, caller, delegate)
    } else {
        storage::remove_delegate(env, account_id, caller, delegate)
    };

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
}

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }

/// Withdraws in normal or liquidation mode and merges the pool mutations.
pub(crate) fn apply_withdraw_batch(
    env: &Env,
    account: &mut Account,
    recipient: &Address,
    kind: WithdrawKind,
    action: events::PositionAction,
    entries: &Vec<PoolWithdrawEntry>,
    cache: &mut Context,
) -> Vec<PoolPositionMutation> {
    let is_liquidation = kind == WithdrawKind::Liquidation;
    let pool_addr = cache.cached_pool_address();
    let results = pool_withdraw_call(env, &pool_addr, recipient, is_liquidation, entries);
    for_each_leg(env, entries, &results, |entry, result| {
        let hub_asset = entry.action.hub_asset;
        let outcome = LegOutcome::from(&result);
        merge_withdraw_leg(env, account, action, &hub_asset, kind, &outcome, cache);
    });
