### Title
Unbounded recursion in `definition template` expansion causes uncaught stack-overflow crash - ([File: definition.js])

### Summary
`definition.js`'s `evaluate()` handler for the `'definition template'` address-definition operator loads an attacker-stored `definition_template` payload and expands it with `replaceInTemplate()`, which recurses over the template's array/object structure with **no depth limit**. Any exception other than the expected `NoVarException` is deliberately re-thrown, uncaught, out of the `conn.query` callback. A crafted, deeply-nested `definition_template` payload can drive `replaceInTemplate`/`replaceInVar` past V8's call-stack limit, producing an uncaught `RangeError: Maximum call stack size exceeded` that propagates out of the async DB callback and crashes the node process — the same bug class as the FFmpeg AMF field parser in ALPINE-CVE-2017-11665 (crafted input causes an unchecked recursive/parsing routine to crash the process).

### Finding Description
1. Any unprivileged unit poster can post a message with `app: "definition_template"`. Validation only checks that the payload is an array of two elements: [1](#0-0) 
No limit is placed on the nesting depth or size of the template array/object itself, only on overall unit byte size via commission fees.

2. Later, when any address (in any unit, potentially posted by the same or a different party) uses a `'definition template'` operator referencing that stored template, `definition.js`'s `evaluate()` loads it and expands it: [2](#0-1) 
`params` is restricted to string/number values, but `arrTemplate` itself (the JSON-parsed stored template) is not depth-limited before being passed into `replaceInTemplate`.

3. `replaceInTemplate`/`replaceInVar` recurse into every array element and object key with no depth check: [3](#0-2) 

4. The `catch` block in `evaluate()`'s `'definition template'` case only swallows `NoVarException`; any other exception — including a `RangeError` from stack exhaustion — is explicitly re-thrown: [4](#0-3) 
This re-throw happens inside a SQLite/MySQL query callback (not wrapped by any outer `try/catch` in the calling chain, e.g. `validateAuthentifiers`/`validateDefinition` in `definition.js:1454-1465`), so the exception is unhandled and terminates the Node.js process.

This mirrors the FFmpeg bug: a parsing/expansion routine that walks attacker-supplied structured data (`ff_amf_get_field_value` walking AMF fields; `replaceInTemplate` walking template arrays) without adequate bounds/depth validation, letting a single crafted input crash the process that processes it.

### Impact Explanation
A crash of the full node process is a denial of service: the affected witness/relay/hub node stops validating and relaying units until manually restarted, which can halt confirmation of new units network-wide if enough witnesses/nodes are affected — matching the "network unable to confirm new units" impact bar. Unlike the CVSS 7.5 network-DoS framing of the original FFmpeg bug, here the trigger is a legitimately-formed but maliciously deep template payload that any unprivileged user can post and any user (attacker themselves, to guarantee triggering) can reference from an address definition, satisfying the "unprivileged unit poster reachable" requirement.

### Likelihood Explanation
Likelihood is high for a knowledgeable attacker: posting a `definition_template` message with deeply nested arrays is straightforward and inexpensive (bytes cost commission but a few tens of KB of nested `[[[...]]]` brackets is cheap and can already exceed V8's default stack depth, typically triggered well under 15,000 levels of nesting, i.e. well under typical unit size limits). Triggering the crash only requires referencing that template from a `'definition template'` op in an address definition and having any node validate/evaluate that definition (e.g., via signature verification, AA trigger processing, or private-payment/wallet address resolution), which is a normal, frequently-executed code path.

### Recommendation
- Add an explicit recursion/depth limit (and/or a size limit) to `replaceInTemplate`/`replaceInVar` in `definition.js`, similar to `MAX_DEPTH` already used in `aa_validation.js`'s definition `validate()` function.
- Validate the depth/complexity of the `definition_template` payload at message-validation time (`validation.js` `case "definition_template"`), not only its top-level array length.
- Wrap the `replaceInTemplate` call (and generally the whole `'definition template'` evaluation path) in a `try/catch` that converts *all* exceptions — not just `NoVarException` — into a validation error (`cb(...)`) instead of re-throwing, so a malformed/oversized template fails validation gracefully rather than crashing the process.

### Proof of Concept
1. Attacker posts unit A containing a message:
   `{ app: "definition_template", payload: ["definition_template_name", <deeply nested array, e.g. 20000 levels of `[[[...]]]`>] }`
   This passes validation because only `isArrayOfLength(payload, 2)` is checked.
2. Once unit A is stable, attacker (or anyone) posts unit B whose address definition (or asset spending condition) includes:
   `['definition template', [unit_A, {param1: 'value1'}]]`
3. When any node evaluates/validates the definition of unit B's address (e.g., during signature verification of a subsequent transaction from that address, or when an AA/light wallet resolves the address definition), `definition.js` executes `evaluate()` → `'definition template'` case → `JSON.parse(template)` → `replaceInTemplate(arrTemplate, params)`.
4. `replaceInVar` recurses through the deeply nested array without a depth cap, exhausts the call stack, throws `RangeError: Maximum call stack size exceeded`, which is not an instance of `NoVarException` and is therefore re-thrown uncaught inside the `conn.query` callback, crashing the Node.js process.

function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
