### Title
Webhook `push`/`membership`/etc. handlers resolve the target repository from an unverified field, decoupling the organization whose secret authenticated the request from the repository that gets written - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/handler.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate the HMAC signature against using `repository_owner`, derived from `params.dig('repository', 'owner', 'login')` (or `organization.login`). However, once the signature check passes, every `Webhooks::Handlers::Handler` subclass (e.g. `PushHandler`) resolves the actual `Stack`/`Repository` to act on using a *different* field from the same attacker-supplied JSON body: `payload.dig('repository', 'full_name')`. Nothing ties the two together, so the org whose secret validated the request is not the org whose repository is mutated.

### Finding Description [1](#0-0) 

`verify_signature` computes `repository_owner` from the JSON body and fetches that organization's `Shipit.github(organization: repository_owner)` app config to validate `X-Hub-Signature`: [2](#0-1) 

Critically, `verify_webhook_signature` short-circuits to `true` whenever that organization has no `webhook_secret` configured: [3](#0-2) 

After the (possibly vacuous) signature check, `create` re-parses the same raw body and dispatches to handlers: [4](#0-3) 

Every handler resolves its target repository/stack from `payload.dig('repository', 'full_name')` — not from the `repository_owner`/organization value that gated the signature check: [5](#0-4) [6](#0-5) 

Because the field used to select "whose secret must sign this" (`repository.owner.login`) and the field used to select "which stack gets acted on" (`repository.full_name`) are two independent, attacker-controlled keys in the same unsigned-until-verified JSON blob, an attacker who controls (or has push access to) *any* organization/repository registered in this Shipit instance — particularly one whose `webhook_secret` is unset, which is the documented default seen in the test/dummy config — can submit a `push` (or `membership`, etc.) payload where `repository.owner.login`/`organization.login` names their own, unprotected org (satisfying `verify_signature`) while `repository.full_name` names an entirely different, victim stack's repository. The handler then performs `stack.sync_github(...)` (or team/membership mutations) against the victim stack using the application's own GitHub credentials, with no relationship to the organization that was actually authenticated.

This is exactly the class of binding break called out in scope: "an organization that authenticated versus the repository that is written." The signature verification and the repository-resolution logic operate on disjoint trust anchors within the same payload.

### Impact Explanation
This breaks the equality that should hold for every webhook: `organization_whose_secret_validated_request == owner(repository_acted_upon)`. Exploiting the gap lets an attacker who only controls one (possibly secret-less) org's webhook registration cause the application to process push/sync/membership events against a stack/repository belonging to a completely different organization, using Shipit's own GitHub App credentials to fetch/act on that repository's data and state — this is a cross-repository write from an org boundary the attacker does not control, matching the Critical impact category "cross-repository writes."

### Likelihood Explanation
Likelihood is high in any multi-organization Shipit deployment: `webhook_secret` is optional per-org config (defaulting to unset in the shipped test config), and even where secrets are configured, nothing prevents a legitimately-authenticated org's payload from naming an arbitrary `repository.full_name` belonging to another org tracked by the same Shipit instance. No Shipit session, ApiClient token, or GitHub App private key is required — only the ability to deliver a POST to the `/webhooks` endpoint claiming to originate from an org that either has no secret configured or whose secret the attacker legitimately possesses for their own repository.

### Recommendation
Bind signature verification and repository resolution to the same value: verify the signature using the organization derived from `repository.full_name`'s owner (the same field handlers use to resolve `Repository`/`Stack`), and reject any payload where `repository.owner.login`/`organization.login` does not match the owner segment of `repository.full_name`. Additionally, treat a missing `webhook_secret` as "reject the request" rather than "skip verification," or restrict unsigned webhook processing to organizations explicitly marked as not requiring verification.

### Proof of Concept
1. Register two organizations with the Shipit instance: `org-attacker` (no `webhook_secret` configured, or one the attacker controls) and `org-victim` (has a tracked `Stack` for `org-victim/app`).
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "org-attacker" },
    "full_name": "org-victim/app"
  }
}
```
3. `verify_signature` computes `repository_owner = "org-attacker"`, loads `Shipit.github(organization: "org-attacker")`, and — because that org's `webhook_secret` is unset — `verify_webhook_signature` returns `true` unconditionally, regardless of (or absent) `X-Hub-Signature`.
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("org-victim/app")` [7](#0-6)  and calls `stack.sync_github(expected_head_sha: params.after)` on the victim's stack — a mutation triggered under the guise of `org-attacker`'s (unauthenticated) webhook.

```ruby
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
