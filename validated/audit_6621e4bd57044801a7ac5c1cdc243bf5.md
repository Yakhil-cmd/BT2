### Title
Signature-verified organization is decoupled from the repository the webhook actually mutates - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate a payload against using `repository_owner`, which is read from the attacker-supplied JSON body itself (`repository.owner.login`, falling back to `organization.login`). The event handlers, however, target a `Stack`/`Repository` using a *different* attacker-supplied field from the same body: `repository.full_name`. Nothing binds these two fields together, so the "organization whose secret authenticated the request" and "the repository that gets written to" are two independently-controlled strings inside one unauthenticated JSON blob.

### Finding Description
`verify_signature` picks the GitHub App config purely from payload content: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that organization's config has no `webhook_secret` configured — a state explicitly supported by the multi-org config schema (`config/secrets.development.example.yml`, `lib/shipit.rb#github_app_config`): [3](#0-2) [4](#0-3) 

Once `verify_signature` passes, `create` hands the *entire raw JSON body* to the event handlers unmodified: [5](#0-4) 

Every handler then resolves its target `Repository`/`Stack` from `repository.full_name` in that same body, independent of whatever value was used for `repository_owner` during signature selection: [6](#0-5) [7](#0-6) 

For `pull_request` events, `OpenedHandler`/`ReviewStackAdapter` provision a review stack using attacker-controlled `pull_request.head.ref` and `pull_request` metadata taken directly from the payload — with no round-trip validation against GitHub's API: [8](#0-7) [9](#0-8) 

So the equality the code implicitly (and wrongly) assumes is: `verified_org(repository.owner.login) == written_repo_owner(repository.full_name)`. An attacker who knows (or can guess/enumerate) any organization in the deployment's multi-org config that has a blank/missing `webhook_secret` can set `repository.owner.login`/`organization.login` to that unsecured org (making `verify_webhook_signature` return `true` unconditionally, regardless of the `X-Hub-Signature` header) while setting `repository.full_name` to `<fully-secured-org>/<repo>`. The signature check authenticates against the unsecured org, but the write lands on the fully-secured org's `Stack`/`ReviewStack`.

### Impact Explanation
This breaks the deployment-trust binding between "the organization whose credential authorized this webhook" and "the repository the engine actually mutates." It allows an unauthenticated request (no valid `X-Hub-Signature` for the target org required) to: (a) force a `GithubSyncJob` re-sync for an arbitrary secured stack, and (b) for `pull_request` events, create/unarchive a `ReviewStack` with attacker-chosen `branch`/`environment`/`pull_request` metadata for a target repo whose own webhook secret was never validated. This crosses a repository/organization boundary that the per-org `webhook_secret` model is meant to enforce.

### Likelihood Explanation
Requires the deployment to run Shipit's documented multi-organization GitHub config with at least one organization lacking a `webhook_secret` (a directly supported, non-default-breaking configuration state shown in `config/secrets.development.example.yml`) — no privileged Shipit session, token, or GitHub write access is needed, only an unauthenticated POST to the public `/webhooks` endpoint.

### Recommendation
Bind signature verification to the same repository/organization the handlers act on: require `repository.full_name`'s owner to match `repository_owner`, and/or refuse to treat a missing `webhook_secret` for one organization as a pass for events whose `repository.full_name` belongs to a different, secured organization. Alternatively, never allow `return true unless webhook_secret` to apply to cross-organization traffic — key the "no secret configured" bypass strictly to the same org that owns the target repository, not merely the org that happens to appear in the (unauthenticated) request body.

### Proof of Concept
1. Configure Shipit with two GitHub Apps: `org-secured` (has `webhook_secret` set, hosts `org-secured/app`) and `org-open` (no `webhook_secret` configured), per `config/secrets.development.example.yml`.
2. POST to `/webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature`, and body:
```json
{
  "action": "opened",
  "number": 999,
  "organization": {"login": "org-open"},
  "repository": {"owner": {"login": "org-open"}, "full_name": "org-secured/app"},
  "pull_request": {"id":1,"number":999,"url":"x","title":"x","state":"open","additions":0,"deletions":0,
    "head": {"sha":"deadbeef","ref":"attacker-branch"},
    "user": {"login":"attacker"}, "assignees": [], "labels": []},
  "sender": {"login":"attacker"}
}
```
3. `WebhooksController#verify_signature` resolves `Shipit.github(organization: "org-open")`, whose `verify_webhook_signature` returns `true` unconditionally because `webhook_secret` is blank.
4. `OpenedHandler` resolves `Repository.from_github_repo_name("org-secured/app")` and creates/provisions a `ReviewStack` on `org-secured/app` using attacker-supplied `branch`/PR data, despite `org-secured` having a correctly configured (and never satisfied) `webhook_secret`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
