Looking at the `kaiax` module registration in `node/cn/backend.go` and the `VRankModule` interface definition, I found a structural analog to the LSP8Burnable inheritance bug.

### Title
`VRankModule` Interface Omits `ExecutionModule` and `RewindableModule`, Leaving Persistent Validator-Performance State Never Written or Rewound — (`node/cn/backend.go`, `kaiax/vrank/interface.go`)

---

### Summary

The `VRankModule` interface declares only `kaiax.BaseModule` and `kaiax.HeaderModule`. The concrete implementation in `kaiax/vrank/impl/` contains `execution.go` and `rewind.go` — files whose names match the kaiax naming convention for `PostInsertBlock` (`ExecutionModule`) and `RewindTo`/`RewindDelete` (`RewindableModule`). Because the interface omits those two sub-interfaces, `mVRank` is never added to the `mExecution` or `mRewindable` registration slices in `SetupKaiaxModules`, so those hooks are never invoked. VRank's persistent CFS/PFS validator-performance database is therefore never updated after block insertion and never cleaned up after a chain rewind.

---

### Finding Description

**Interface declaration — `kaiax/vrank/interface.go`**

```go
type VRankModule interface {
    kaiax.BaseModule
    kaiax.HeaderModule          // VerifyHeader, PrepareHeader only
    // kaiax.ExecutionModule    ← MISSING (PostInsertBlock)
    // kaiax.RewindableModule   ← MISSING (RewindTo, RewindDelete)
    HandleIstanbulPreprepare(...)
    HandleVRankPreprepare(...) error
    HandleVRankCandidate(...) error
    EvaluateCandidates(...) ([]common.Address, error)
    GetPfReport(...) ([]common.Address, error)
    GetPFS(...) (map[common.Address]uint64, error)
    GetCFS(...) (map[common.Address]uint64, error)
    SubscribeVRank(...) event.Subscription
}
```

Compare with `ValsetModule`, which correctly declares all five sub-interfaces it needs:

```go
type ValsetModule interface {
    kaiax.BaseModule
    kaiax.JsonRpcModule
    kaiax.ExecutionModule    // ← present
    kaiax.RewindableModule   // ← present
    kaiax.BlockStateModule
    kaiax.HeaderModule
    ...
}
```

**Registration — `node/cn/backend.go` lines 596–603**

```go
mBase      := []kaiax.BaseModule     {..., mVRank}   // VRank started/stopped
mExecution := []kaiax.ExecutionModule{stakingModule, mSupply, govModule, mValset, mRandao}
                                                      // mVRank ABSENT
mRewindable:= []kaiax.RewindableModule{stakingModule, mSupply, govModule, mValset, mRandao}
                                                      // mVRank ABSENT
mHeader    := []kaiax.HeaderModule   {..., mVRank}   // VerifyHeader/PrepareHeader called
```

The concrete `impl.VRankModule` struct has `execution.go` and `rewind.go` in its implementation directory — the same naming pattern used by every other module that implements `ExecutionModule` (`PostInsertBlock`) and `RewindableModule` (`RewindTo`, `RewindDelete`). Because `VRankModule` interface omits those sub-interfaces, the compiler never enforces them, and `SetupKaiaxModules` never adds `mVRank` to the slices that are passed to `blockchain.RegisterKaiaxModules`.

The downstream call at line 634:

```go
s.blockchain.RegisterKaiaxModules(s.govModule, mValset, mExecution, mRewindable, mHeader, mBlockState)
```

passes `mExecution` and `mRewindable` without VRank, so `PostInsertBlock`, `RewindTo`, and `RewindDelete` on VRank are dead code in production.

---

### Impact Explanation

VRank maintains per-block CFS (Consecutive Failure Score) and PFS (Performance Failure Score) records in a persistent key-value store. These scores are consumed by:

- `EvaluateCandidates` — determines which validators are qualified for the committee at each block.
- `GetCFS` / `GetPFS` — exposed via JSON-RPC and used by the consensus engine to select the active validator set.

Because `PostInsertBlock` is never called, the CFS/PFS database is never written after block insertion. All scores remain at their initial (zero/empty) values. As a result:

1. **Validator set corruption**: Validators that should be demoted due to repeated failures are never penalized in the persistent store. `EvaluateCandidates` returns an incorrect qualified set, allowing underperforming or misbehaving validators to remain in the committee indefinitely.
2. **Rewind corruption**: When `debug_setHead` triggers a chain rewind, `RewindTo`/`RewindDelete` are never called on VRank. Any CFS/PFS entries that were written (e.g., during a prior correct execution path) are not erased, leaving the module with data for blocks that no longer exist on the canonical chain. Subsequent `EvaluateCandidates` calls read stale scores from the orphaned branch, producing an incorrect validator set for the rewound chain.

Both effects corrupt the validator set used by IBFT consensus, which is a protected-state impact under the "validator set… changes protected chain state" criterion.

---

### Likelihood Explanation

The missing registration affects **every block** from the moment the node starts. No special attacker action is required — normal block production is sufficient to trigger the divergence between what VRank's implementation computes and what is actually persisted. The rewind path is reachable via the `debug_setHead` RPC (available to node operators) or via the startup repair path.

---

### Recommendation

1. Add `kaiax.ExecutionModule` and `kaiax.RewindableModule` to the `VRankModule` interface in `kaiax/vrank/interface.go`:

```go
type VRankModule interface {
    kaiax.BaseModule
    kaiax.HeaderModule
+   kaiax.ExecutionModule    // PostInsertBlock
+   kaiax.RewindableModule   // RewindTo, RewindDelete
    ...
}
```

2. Add `mVRank` to the `mExecution` and `mRewindable` slices in `node/cn/backend.go`:

```go
mExecution  := []kaiax.ExecutionModule {stakingModule, mSupply, govModule, mValset, mRandao, mVRank}
mRewindable := []kaiax.RewindableModule{stakingModule, mSupply, govModule, mValset, mRandao, mVRank}
```

3. Ensure the mock in `kaiax/vrank/mock/` is regenerated to include the new interface methods.

---

### Proof of Concept

1. Start a Kaia CN node.
2. Produce N blocks. VRank's `PostInsertBlock` is never called; CFS/PFS DB remains empty.
3. Call `kaia_getCFS(N)` — returns empty map regardless of actual validator behavior.
4. Call `debug_setHead(N-10)` to rewind. VRank's `RewindTo`/`RewindDelete` are never called; any pre-existing VRank DB entries for blocks N-9…N survive the rewind.
5. Produce 10 new blocks on the rewound chain. `EvaluateCandidates` reads the orphaned CFS/PFS entries from the old branch, producing a validator qualified-set that does not match the canonical chain's state, corrupting the IBFT committee selection.
