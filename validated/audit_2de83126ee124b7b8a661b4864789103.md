### Title
Cross-tenant Team-membership injection via global login lookup in `MembershipHandler#process` - (File: app/models/shipit/webhooks/handlers/membership_handler.rb)

### Summary
`MembershipHandler#process` resolves `member` via `User.find_or_create_by_login!(params.member.login)`, a global, org-unscoped lookup, then calls `team.add_member(member)` for a `Team` created from the *attacker's own* organization. Since GitHub webhook signatures only prove control of the signing organization, not control over the named `login`, an attacker who owns an organization wired into Shipit (per-org `GithubHook::Organization` secret, as supported by `Shipit.github(organization:)`) can force any existing, unrelated Shipit `User` row to become a member of a team they control.

### Finding Description
The broken binding is: `verified_org(signature) == organization_that_owns(member.login)`. Only the left side is checked — `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) verifies the HMAC against the secret configured for `repository_owner`/`organization.login`, proving only that the *attacker's own org* signed the request. The right side is never checked.

`MembershipHandler#process` (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-34`) then does:
```ruby
team = find_or_create_team!                                   # scoped to attacker's org (github_id/organization.login)
member = User.find_or_create_by_login!(params.member.login)   # global lookup, no org scoping
team.add_member(member)                                        # writes Membership(team, member)
```
`User.find_or_create_by_login!` (`app/models/shipit/user.rb:22-28`) does `find_or_create_by!(login:)` — `login` is the sole key, and `User` rows are global across the entire Shipit instance (not scoped per organization). `Team.find_or_create_team!` builds/looks up the `Team` keyed by `params.team.id`, tagged with `organization: params.organization.login` — this is the attacker's own org, and `find_or_create_by!` will create a brand-new `Team` row for a fresh `team.id` the attacker mints.

The `ExplicitParameters` schema on `MembershipHandler` only validates shape (`action`, `team.id/name/slug/url`, `organization.login`, `member.login` are present strings/integers) — it enforces no relationship between `organization.login` and `member.login`. No model validation on `Membership`/`Team`/`User` cross-checks organization provenance either.

Attack: attacker owns org `attacker-org` wired into Shipit (a legitimate per-org GitHub App/webhook config, as the `GithubHook::Organization` model and `Shipit.github(organization:)` support multi-tenant orgs). Attacker creates a new team in `attacker-org` (`team.id = X`), then POSTs to `/webhooks` with `X-Github-Event: membership`, a valid signature for `attacker-org`, and body:
```json
{"action":"added","team":{"id":X,"name":"n","slug":"s","url":"u"},"organization":{"login":"attacker-org"},"member":{"login":"real-operator"},"repository":{"owner":{"login":"attacker-org"}}}
```
This creates/fetches `Team(organization: "attacker-org", github_id: X)` and unconditionally attaches the existing `User` with `login == "real-operator"` to it via `Membership`.

### Impact Explanation
The attacker writes a `Membership` record binding a real, unrelated Shipit `User` to a `Team` the attacker fully controls, without that user (or their real GitHub org) ever authenticating or consenting to this — a cross-tenant mutation of a shared resource (`Team`/`Membership`) driven entirely by attacker-controlled organization data. If that attacker-controlled team's handle (`organization/slug`) is ever included in `Shipit.github_teams` (the operator-configured authorization list built via `Shipit.github_teams` / `Team.find_or_create_by_handle`, `lib/shipit.rb:256-258`), `User#authorized?` (`app/models/shipit/user.rb:80-82`) — which checks only `teams.where(id: Shipit.github_teams...).exists?` with no per-org provenance check — would treat the victim as authorized, an escalation into `Shipit.github_teams` authorization (High/Critical per the stated severity bands). Independent of that specific overlap, the injected Membership row is itself an unauthorized write of team/user relationship data attributable to an org that never verified the victim's participation, and is repeatable against any known GitHub login and any number of teams/orgs the attacker controls.

### Likelihood Explanation
Preconditions: the attacker must control (or register) at least one organization that Shipit has wired up with a valid per-org webhook secret (`GithubHook::Organization`) — this is a normal, supported multi-tenant Shipit configuration, not a privileged internal secret. The attacker needs only the victim's public GitHub login (trivially discoverable) and a `team.id` they mint themselves. No Shipit session, API token, or `Shipit.github_teams` membership is required. This is fully repeatable per request against any login and any attacker-owned org/team.

### Recommendation
Scope the `member` lookup/creation in `MembershipHandler#process` to the webhook's own organization: verify the resolved `User`'s GitHub org membership matches `params.organization.login` before creating/attaching the membership (e.g., call the GitHub API to confirm `member.login` belongs to `organization.login`, or restrict `find_or_create_by_login!` usage here to only update an *existing* Team/User pairing when provenance can be established), and avoid globally mutating a `User` record based solely on an org-signed claim about an unrelated identity.

### Proof of Concept
```ruby
# test/models/shipit/webhooks/handlers/membership_handler_test.rb
test "membership webhook from an unrelated org attaches an existing global User to that org's team" do
  victim = Shipit::User.create!(login: 'real-operator', name: 'Real Operator')

  payload = {
    'action' => 'added',
    'team' => { 'id' => 999_001, 'name' => 'Evil Team', 'slug' => 'evil-team', 'url' => 'http://example.com' },
    'organization' => { 'login' => 'attacker-org' },
    'member' => { 'login' => 'real-operator' }
  }

  Shipit::Webhooks::Handlers::MembershipHandler.new(payload).call(payload)

  team = Shipit::Team.find_by(github_id: 999_001)
  assert_equal 'attacker-org', team.organization
  assert_includes team.members, victim   # victim never interacted with attacker-org

  Shipit.stubs(:github_teams).returns([team])
  assert victim.authorized?              # binding broken: attacker-org membership grants authorization
end
```

          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          when 'added'
            team.add_member(member)
          when 'removed'
