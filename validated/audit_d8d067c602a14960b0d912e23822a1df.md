### Title
Panic (slice bounds out of range) in `setSecret` when public-key API response has fewer than 32 bytes - ([File: pkg/cmd/secret/set/set.go])

### Summary
`setSecret` decodes the `pk.Key` field from the public-key API response and immediately slices the decoded bytes with `decodedPubKey[0:32]` without checking length. If the host serving the public-key endpoint returns a `key` value that base64-decodes to fewer than 32 bytes, this causes a runtime panic (index out of range), crashing the `gh` CLI process.

### Finding Description
The call chain is: `setRun` (`pkg/cmd/secret/set/set.go:203`) → `getOrgPublicKey`/`getRepoPubKey`/`getEnvPubKey`/`getUserPublicKey` → `getPubKey` (`pkg/cmd/secret/set/http.go:34-41`), which unmarshals the raw JSON API response directly into the `PubKey` struct via `client.REST`: [1](#0-0) 

The resulting `pk.Key` string is fully attacker-controlled content from whatever host `gh` is pointed at (e.g., `--hostname`/`GH_HOST` pointing to a hostile or compromised server, or a GHE server under attacker influence). In `setSecret`: [2](#0-1) 

`base64.StdEncoding.DecodeString(pk.Key)` succeeds for any validly base64-encoded string regardless of length (e.g., an empty string, or a short string like `"AA=="` decodes to 1 byte). There is no length check on `decodedPubKey` before the fixed-size slice expression `decodedPubKey[0:32]` is evaluated. Slicing a byte slice with an upper bound greater than its length triggers a Go runtime panic (`slice bounds out of range`), which is unrecovered here and will crash the running `gh` process.

No existing check (host allowlist, safeurl, JSON schema validation, or explicit length validation) protects against this — `safeurl` in this file only validates URL paths sent to the server, not response payload shapes coming back.

### Impact Explanation
This is a Denial-of-Service on the victim's local `gh` CLI invocation: any `gh secret set` command that resolves to fetching a public key from an attacker-influenced host (custom `GH_HOST`, malicious/compromised GHE instance, or an HTTP proxy/mock the victim has configured for testing against `gh`) can crash the process with an unhandled panic. It does not lead to code execution, credential theft, or file write outside the intended path — the impact is limited to abrupt process termination, matching a low-severity DoS/crash impact class rather than a compromise-of-account/host bounty tier.

### Likelihood Explanation
Exploitation requires the victim to run `gh secret set` (org, repo, environment, or user secret) against a host under attacker control or influence — e.g., an enterprise/self-hosted GitHub instance operated or compromised by the attacker, or a local HTTP mock/proxy pointed to by `GH_HOST`. This is not exploitable against api.github.com since GitHub's real public-key endpoint always returns a valid 32-byte NaCl box key. The preconditions therefore require the victim to intentionally or unknowingly point `gh` at an untrusted host, making exploitation feasible only in that narrower scenario, and trivially repeatable once that precondition holds.

### Recommendation
Validate `len(decodedPubKey) == 32` (or `>= 32`) immediately after `base64.StdEncoding.DecodeString` in `setSecret` (`pkg/cmd/secret/set/set.go:335`) and return a descriptive error (e.g., `"invalid public key length returned by host"`) instead of proceeding to the fixed-size copy/slice.

### Proof of Concept
```go
func TestSetSecret_ShortPubKeyPanics(t *testing.T) {
    reg := &httpmock.Registry{}
    reg.Register(
        httpmock.REST("GET", "repos/owner/repo/actions/secrets/public-key"),
        httpmock.StringResponse(`{"key_id":"1234","key":"AA=="}`), // decodes to 1 byte
    )
    httpClient := &http.Client{Transport: reg}
    client := api.NewClientFromHTTP(httpClient)

    pk, err := getRepoPubKey(client, ghrepo.New("owner", "repo"), shared.Actions)
    require.NoError(t, err)

    opts := &SetOptions{ /* ... minimal fields ... */ }
    // Expect this call to panic with "runtime error: slice bounds out of range"
    require.Panics(t, func() {
        setSecret(opts, pk, "github.com", client, ghrepo.New("owner", "repo"),
            "MYSECRET", []byte("value"), nil, shared.Actions, shared.DefaultEntity)
    })
}
```
Expected assertion: without a length check, the test panics inside `setSecret` at `copy(peersPubKey[:], decodedPubKey[0:32])`; after adding the recommended length validation, the function should instead return a non-nil `res.err` and the panic should no longer occur.
