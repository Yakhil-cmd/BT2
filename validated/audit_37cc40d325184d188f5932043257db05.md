### Title
Webhook signature check keyed on `repository.owner.login` while handlers dispatch on `repository.full_name` — orgs without `webhook_secret` allow full webhook forgery for any registered repository - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally when the org's config has no `webhook_secret` (line 77), and the org used to select that config, `repository.owner.login`, is completely decoupled from the repository the event is actually processed against, `repository.full_name`. An attacker who knows (or guesses) that any single org configured in `Shipit.github_app_configs` lacks a `webhook_secret` can forge a webhook naming that org as the payload owner while setting `repository.full_name` to any other registered repository, causing the corresponding handler to act on that unrelated repository/stack with no valid signature at all.

### Finding Description
The broken binding: the code implicitly assumes `verified_owner(repository.owner.login) == acted_upon_repository(repository.full_name)`, but no such equality is ever enforced.

- `WebhooksController#verify_signature` selects the GitHub app config solely from the attacker-controlled `repository.owner.login`: `Shipit.github(organization: repository_owner)` [1](#0-0)  and `repository_owner` at [2](#0-1) .
- `GitHubApp#verify_webhook_signature` short-circuits to `true` when `webhook_secret` is nil/blank, i.e. for any org configured without a `webhook_secret` key (a legitimate config for OAuth-only orgs): [3](#0-2) , with `@webhook_secret = @config[:webhook_secret].presence` set at [4](#0-3) .
- Once `verified` is `true`, `#create` dispatches the parsed body to handlers keyed only by `X-Github-Event`: [5](#0-4) .
- Every handler resolves its target `Stack`/`Repository` from `payload.dig('repository', 'full_name')`, entirely independent of the owner used for signature verification: [6](#0-5) . For example `PushHandler#process` triggers `stack.sync_github` for any non-archived stack matching the branch of that resolved repository: [7](#0-6) .

Exploit flow: attacker sends `POST /webhooks` with `X-Github-Event: push`, body `{"repository": {"owner": {"login": "<unsecured-org>"}, "full_name": "<victim-org>/<victim-repo>"}, "ref": "refs/heads/main", "after": "<attacker sha>"}`, and an arbitrary/absent `X-Hub-Signature`. `repository_owner` resolves to `<unsecured-org>`, `Shipit.github(organization: "<unsecured-org>")` returns a `GitHubApp` with `webhook_secret == nil`, `verify_webhook_signature` returns `true` regardless of the signature, and `PushHandler` is invoked against the victim repository's registered stacks, triggering `sync_github` (and, for other event types, `status`/`pull_request`/`membership` side effects) on a repository that never authenticated the request.

No other guard intervenes: `drop_unhandled_event` only checks the event name is registered, not the payload's authenticity [8](#0-7) ; there is no cross-check that the resolved `Repository`/`Stack`'s org matches the `repository_owner` used for signature selection anywhere in the controller or `Handler` base class.

### Impact Explanation
Any single Shipit deployment that configures one org without a `webhook_secret` (a documented, legitimate configuration for OAuth-only orgs) loses webhook authentication entirely for every other registered repository/stack, since dispatch target selection (`repository.full_name`) is decoupled from the org used to pick the verifier. This lets an unauthenticated attacker inject forged `push`, `status`, `pull_request`, `check_suite`, and `membership` events against arbitrary victim repositories/stacks — e.g. driving `PushHandler`/`StatusHandler` state transitions used to gate deploys, or `membership`/`pull_request` handlers that affect review-stack provisioning and team membership caches. This is a cross-tenant authentication bypass: Critical.

### Likelihood Explanation
Preconditions: the Shipit instance must have at least one entry in `Shipit.github_app_configs` without a `webhook_secret`. This is presented in the question as a legitimate, supported configuration (OAuth-only org), and nothing in the codebase prevents or warns against it. Given that precondition, the attack requires only a single unauthenticated HTTP POST with a guessed/known unsecured org login and the target's `full_name` — no secrets, sessions, or GitHub credentials are needed. Feasibility is high and the attack is trivially repeatable against any registered repository.

### Recommendation
Do not allow signature verification to succeed for an event whose `repository.owner.login` does not correspond to the org that actually owns `repository.full_name`, and/or require every configured org to define a `webhook_secret` (fail closed, e.g. raise/reject webhooks instead of returning `true`) when no secret is present. At minimum, `verify_webhook_signature`/`verify_signature` should validate that `repository.owner.login` is a prefix/owner of `repository.full_name` before selecting the app config, and treat a missing `webhook_secret` as "verification impossible" (422) rather than "verification not required".

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`):
1. Configure `Shipit.github_app_configs` with two orgs: `"unsecured-org"` (no `webhook_secret` key) and `"victim-org"` (has a `webhook_secret`).
2. Create a `Shipit::Stack` for `victim-org/victim-repo` on branch `main`.
3. POST to `/webhooks` with headers `X-Github-Event: push`, an arbitrary/garbage `X-Hub-Signature`, and body:
   ```json
   {"repository": {"owner": {"login": "unsecured-org"}, "full_name": "victim-org/victim-repo"}, "ref": "refs/heads/main", "after": "deadbeef"}
   ```
4. Assert the response is `200 OK` (not `422`), i.e. `Shipit.github(organization: "unsecured-org").verify_webhook_signature(garbage_signature, raw_post) == true` while `Shipit.github(organization: "victim-org").verify_webhook_signature(garbage_signature, raw_post) == false`.
5. Assert `Stack#sync_github` was invoked on the `victim-org/victim-repo` stack (e.g. stub/mock and assert it was called), proving the equality `verified_owner("unsecured-org") == acted_upon_repository("victim-org/victim-repo")` does not hold yet the action was still performed.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
