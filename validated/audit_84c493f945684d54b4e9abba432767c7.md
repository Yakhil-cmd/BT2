### Title
Silent Error Suppression in `fillAllocated` Causes Total Zeroed-Balance Burn Instead of Treasury Distribution — (`File: blockchain/system/rebalance.go`)

### Summary

`fillAllocated` returns `nil` instead of `err` when `GetAllocatedCount` fails. This causes `RebalanceTreasury` to proceed with an empty allocated-address map, silently zeroing all treasury addresses and burning the entire zeroed balance rather than distributing it to the intended recipients.

### Finding Description

In `blockchain/system/rebalance.go`, the `fillAllocated` function contains an asymmetric error-return bug relative to its sibling `fillZeroed`:

```go
// fillZeroed — correct
func (result *rebalanceResult) fillZeroed(contract RebalanceCaller, state *state.StateDB) error {
    numRetiredBigInt, err := contract.GetZeroedCount(nil)
    if err != nil {
        logger.Error("Failed to get ZeroedCount from TreasuryRebalance contract", "err", err)
        return err   // ← propagates the error
    }
    ...
}

// fillAllocated — buggy
func (result *rebalanceResult) fillAllocated(contract RebalanceCaller, state *state.StateDB) error {
    numNewbieBigInt, err := contract.GetAllocatedCount(nil)
    if err != nil {
        logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
        return nil   // ← swallows the error; should be `return err`
    }
    ...
}
``` [1](#0-0) 

When `GetAllocatedCount` fails, `fillAllocated` returns `nil`, leaving `result.After.Allocated` as an empty map. The caller `RebalanceTreasury` sees no error and continues: [2](#0-1) 

The downstream execution path then:
1. `totalAllocatedAmount = result.totalAllocatedBalance() = 0` (empty map)
2. KIP-103 guard `totalZeroedAmount.Cmp(totalAllocatedAmount) < 0` evaluates to `false` (zeroed > 0), so it passes
3. **Execution 1**: All zeroed addresses have their balances set to `0` via `state.SetBalance(addr, big.NewInt(0))`
4. **Execution 2**: No allocated addresses → nothing distributed
5. `remainder = totalZeroedAmount − 0 = totalZeroedAmount` → entire zeroed balance is added to `result.Burnt`
6. `result.Success = true`

The entire treasury zeroed balance is burned rather than distributed to the intended allocated recipients.

### Impact Explanation

The `RebalanceTreasury` function is invoked during block finalization at the KIP-103 or KIP-160 hard-fork block number: [3](#0-2) 

If `GetAllocatedCount` fails (e.g., the KIP-160 `TreasuryRebalanceV2` contract is misconfigured, the contract address is wrong, or the EVM call reverts), the silent `nil` return causes:

- **Unauthorized burn of KAIA**: All balances of zeroed addresses are destroyed with zero KAIA reaching the allocated recipients. This is an incorrect state transition that permanently destroys system-managed funds.
- **Corrupted treasury state**: `result.Success = true` is written to the memo, masking the failure from any post-hoc audit.
- The impact is irreversible because the hard-fork rebalance executes exactly once at the designated block.

### Likelihood Explanation

The trigger requires `GetAllocatedCount` to return an error during the hard-fork block's state transition. Conditions that can cause this include:

- `Kip160ContractAddress` pointing to an address with no deployed contract or a contract that does not implement `getAllocatedCount()`
- An EVM revert inside the contract call (e.g., contract in wrong state)
- For KIP-103: the in-state contract caller encountering a missing trie node

The asymmetry with `fillZeroed` (which correctly returns `err`) strongly suggests this is a copy-paste defect rather than intentional design. The probability of the error path being hit is low in a correctly configured mainnet deployment, but the consequence when it is hit is total loss of the allocated distribution.

### Recommendation

Change line 219 from `return nil` to `return err`:

```go
func (result *rebalanceResult) fillAllocated(contract RebalanceCaller, state *state.StateDB) error {
    numNewbieBigInt, err := contract.GetAllocatedCount(nil)
    if err != nil {
        logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
        return err   // propagate; do not silently succeed
    }
    ...
}
``` [4](#0-3) 

This makes `fillAllocated` consistent with `fillZeroed` and ensures `RebalanceTreasury` aborts with an error rather than proceeding with an empty allocation map.

### Proof of Concept

Execution trace when `GetAllocatedCount` returns an error:

1. `RebalanceTreasury` is called at the KIP-160 fork block.
2. `fillZeroed` succeeds; `result.Before.Zeroed` is populated with, e.g., `{0xAA: 7_000_000 KAIA}`.
3. `fillAllocated` calls `contract.GetAllocatedCount(nil)` → returns `(nil, someError)`.
4. Bug: `return nil` → caller sees no error; `result.After.Allocated = {}`.
5. `totalAllocatedAmount = 0`.
6. KIP-103 guard: `7_000_000 < 0` → false → passes.
7. `state.SetBalance(0xAA, 0)` → 7,000,000 KAIA destroyed.
8. No `state.SetBalance` calls for allocated addresses.
9. `result.Burnt = 7_000_000 KAIA`, `result.Success = true`.
10. Block is finalized with 7,000,000 KAIA permanently burned and zero KAIA distributed to intended recipients.

func RebalanceTreasury(state *state.StateDB, chain backends.BlockChainForCaller, header *types.Header) (*rebalanceResult, error) {
	var (
		err    error
		caller RebalanceCaller

		result   = newRebalanceReceipt()
		isKIP160 = chain.Config().IsKIP160ForkBlock(header.Number)
		isKIP103 = chain.Config().IsKIP103ForkBlock(header.Number)
	)

	if isKIP160 {
		caller, err = rebalance.NewTreasuryRebalanceV2Caller(chain.Config().Kip160ContractAddress, backends.NewBlockchainContractBackend(chain, nil, nil))
	} else if isKIP103 {
		caller, err = NewKip103ContractCaller(state, chain, header)
	} else {
		return nil, errors.New("rebalancing shouldn't be executed unless the block number is kip103 or kip160 hard fork")
	}
	if err != nil {
		return nil, err
	}

	// Retrieve 1) Get Zeroed
	if err = result.fillZeroed(caller, state); err != nil {
		return result, err
	}

	// Retrieve 2) Get Allocated
	if err = result.fillAllocated(caller, state); err != nil {
		return result, err
	}

	// Validation 1) Check the target block number
	if blockNum, err := caller.RebalanceBlockNumber(nil); err != nil || blockNum.Cmp(header.Number) != 0 {
		return result, ErrRebalanceIncorrectBlock
	}

	// Validation 2) Check whether status is approved. It should be 2 meaning approved
	if status, err := caller.Status(nil); err != nil || status != 2 {
		return result, ErrRebalanceBadStatus
	}

	// Validation 3) Check approvals from zeroeds
	if err = caller.CheckZeroedsApproved(nil); err != nil {
		return result, err
	}

	// Validation 4) Check the total balance of zeroeds are bigger than the distributing amount
	totalZeroedAmount := result.totalZeroedBalance()
	totalAllocatedAmount := result.totalAllocatedBalance()
	if isKIP103 && totalZeroedAmount.Cmp(totalAllocatedAmount) < 0 {
		return result, ErrRebalanceNotEnoughBalance
	}

	// Execution 1) Clear all balances of zeroeds
	for addr := range result.Before.Zeroed {
		state.SetBalance(addr, big.NewInt(0))
		result.After.Zeroed[addr] = big.NewInt(0)
	}
	// Execution 2) Distribute KAIA to all allocateds
	for addr, balance := range result.After.Allocated {
		// if an allocated has KAIA before the allocation, it will be burnt
		currentBalance := state.GetBalance(addr)
		result.Burnt.Add(result.Burnt, currentBalance)

		state.SetBalance(addr, balance)
	}

	// Fill the remaining fields of the result
	remainder := new(big.Int).Sub(totalZeroedAmount, totalAllocatedAmount)
	result.Burnt.Add(result.Burnt, remainder)
	result.Success = true
	return result, nil
