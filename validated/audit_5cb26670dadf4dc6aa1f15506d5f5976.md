Confirmed: `transfer_from_pool_vault_to_user` uses `token_2022::transfer_checked` with no fallback if the destination account is frozen/blacklisted [1](#0-0) . This validates the analog.

### Title
Fixed creator-fee recipient in `collect_creator_fee`/`collect_creator_fee_permissionless` permanently freezes both tokens' creator fees if creator becomes blacklisted on one token - ([File: programs/cp-swap/src/instructions/collect_creator_fee.rs, programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs])

### Summary
Both `collect_creator_fee` and `collect_creator_fee_permissionless` hard-code the fee recipient to the pool creator's own associated token accounts (`creator_token_0`/`creator_token_1`, constrained via `associated_token::authority = creator`), with no way to specify an alternate recipient [2](#0-1) [3](#0-2) . This is the exact analog of the reported `collectLiquidity()` issue: the recipient is unconditionally the position/fee owner.

### Finding Description
In `collect_creator_fee`, both token transfers to the creator's ATAs happen atomically within a single instruction using `transfer_from_pool_vault_to_user`, which is a straight `token_2022::transfer_checked` CPI with no error handling for a frozen/blacklisted destination account [4](#0-3) [1](#0-0) . The same pattern exists in `collect_creator_fee_permissionless`, which anyone can trigger, but the recipient is still fixed to the pool creator's ATA (`associated_token::authority = creator`) [5](#0-4) .

If the pool creator's token account for either mint becomes frozen (e.g., the mint's freeze authority freezes it, or a Token-2022 mint uses the `DefaultAccountState` extension so newly `init_if_needed` ATAs are created already frozen), the `transfer_checked` CPI for that token will fail. Since both transfers occur in the same instruction and the whole instruction must succeed atomically, the failure of one transfer reverts the entire instruction — meaning creator fees for the *other, non-blacklisted* token also cannot be collected, ever, since there is no code path to collect them separately or to a different recipient.

This mirrors the original report precisely: `collectLiquidity()` only allowed `msg.sender` as recipient, so blacklisting on one token froze both. Here, `collect_creator_fee`/`collect_creator_fee_permissionless` only allow the pool creator's own ATA as recipient, so freezing/blacklisting on one token's mint freezes collection of both tokens' accumulated creator fees.

### Impact Explanation
`creator_fees_token_0` and `creator_fees_token_1` accumulate in the pool vaults on every swap via `update_fees` [6](#0-5) . If the creator becomes unable to receive one token (frozen account), these accrued fees for both tokens become permanently unretrievable — the funds are stuck in the pool vaults indefinitely, since there is no admin override or alternate-recipient path for creator fees. This is a permanent freezing of LP/creator funds.

### Likelihood Explanation
Likelihood is moderate: it requires the creator's token account to become frozen, which is possible for any pool paired with a Token-2022 mint that has a freeze authority or uses the `DefaultAccountState` extension (both mint properties an unprivileged pool creator/initializer could encounter or configure when creating a pool with `initialize`/`initialize_with_permission`, since token creation utilities such as `is_supported_mint` allow various Token-2022 extensions) [7](#0-6) . Since `collect_creator_fee_permissionless` can be triggered by any payer, an attacker could also repeatedly attempt collection to confirm the funds are permanently stuck, but the root freezing condition depends on mint-level freeze/blacklist configuration, not on privileged program actions.

### Recommendation
Add an optional/explicit recipient parameter (or decouple the two transfers so a revert on one does not block the other), similar to `collect_fund_fee`, which already allows an arbitrary `recipient_token_0_account`/`recipient_token_1_account` without forcing `associated_token::authority = creator` [8](#0-7) . At minimum, make the two `transfer_from_pool_vault_to_user` calls independently recoverable (e.g., allow partial collection) so a freeze on one token's mint does not lock the other token's accrued fees forever.

### Proof of Concept
1. Pool creator initializes a pool where `token_0` is a Token-2022 mint with a freeze authority (or `DefaultAccountState = Frozen`) and `token_1` is a normal SPL token, enabling creator fees via `initialize_with_permission`.
2. Swaps occur, accruing `creator_fees_token_0` and `creator_fees_token_1` in `pool_state`.
3. The mint's freeze authority freezes the creator's ATA for `token_0` (or the ATA is created already frozen due to `DefaultAccountState`).
4. Creator (or any payer, via `collect_creator_fee_permissionless`) calls `collect_creator_fee`; the `transfer_checked` CPI to `creator_token_0` fails because the account is frozen, causing the whole instruction — including the `token_1` transfer — to revert [4](#0-3) .
5. `creator_fees_token_0` and `creator_fees_token_1` remain permanently stuck in the pool vaults with no way to collect either, since no alternate recipient can be specified.

pub fn transfer_from_pool_vault_to_user<'a>(
    authority: AccountInfo<'a>,
    from_vault: AccountInfo<'a>,
    to: AccountInfo<'a>,
    mint: AccountInfo<'a>,
    token_program: AccountInfo<'a>,
    amount: u64,
    mint_decimals: u8,
    signer_seeds: &[&[&[u8]]],
) -> Result<()> {
    if amount == 0 {
        return Ok(());
    }
    token_2022::transfer_checked(
        CpiContext::new_with_signer(
            *token_program.key,
            token_2022::TransferChecked {
                from: from_vault,
                to,
                authority,
                mint,
            },
            signer_seeds,
        ),
        amount,
        mint_decimals,
    )
}

pub fn is_supported_mint(
    mint_account: &InterfaceAccount<Mint>,
    mint_associated_is_initialized: bool,
) -> Result<bool> {
    let mint_info = mint_account.to_account_info();
    if *mint_info.owner == Token::id() {
        return Ok(true);
    }
    if mint_associated_is_initialized {
        return Ok(true);
    }
    let mint_data = mint_info.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
    let extensions = mint.get_extension_types()?;
    for e in extensions {
        if e != ExtensionType::TransferFeeConfig
            && e != ExtensionType::MetadataPointer
            && e != ExtensionType::TokenMetadata
            && e != ExtensionType::InterestBearingConfig
            && e != ExtensionType::ScaledUiAmount
        {
            return Ok(false);
        }
    }
    Ok(true)
}

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();
                if is_creator_fee_on_input {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                }
            }
        };
        Ok(())
    }
