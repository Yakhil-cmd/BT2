### Title
Signature verification keys off `repository.owner.login`/`organization.login` while handlers act on a different field (`repository.full_name`, `team.id`, `organization.login`) — org authentication is decoupled from the resource acted upon - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to validate the HMAC signature against using `repository_owner`, derived only from `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`). [1](#0-0) [2](#0-1)  However, none of the actual event handlers use that same field to determine what resource they act on: `Handler#repository_name`/`stacks` and every pull-request handler resolve the target repository from `payload.dig('repository', 'full_name')` [3](#0-2) , and `MembershipHandler` grants/revokes `Team` membership using `params.team.id`/`params.organization.login`, independent of `repository.owner.login` [4](#0-3) . Combined with `GitHubApp#verify_webhook_signature` returning `true` unconditionally when an organization has no `webhook_secret` configured [5](#0-4) , this breaks the binding: `organization authenticated (repository.owner.login) == organization/repository actually written (repository.full_name / team / stack)`.

### Finding Description
Shipit supports hosting multiple GitHub organizations in one instance, each with its own `webhook_secret` in `secrets.yml` (`Shipit.github(organization:)` / `github_app_config`) [6](#0-5) . The sample/onboarding secrets files ship with `webhook_secret: # nil` for organizations, i.e. it is an optional, per-org setting [7](#0-6) .

`WebhooksController#verify_signature` picks the `GitHubApp` instance to validate against solely from the attacker-controlled JSON body field `repository.owner.login` (or `organization.login` as fallback) — before any authentication has occurred: 
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  head(422) unless verified
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [8](#0-7) 

If `verify_webhook_signature` finds `webhook_secret` blank for that selected organization, it returns `true` unconditionally, i.e. no signature validation occurs at all for requests attributed to that org [5](#0-4) .

Once past `verify_signature`, `create` dispatches the entire raw JSON `params` to the event handlers, unmodified — `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [9](#0-8) . None of the handlers re-derive or cross-check the organization against the field used for signature selection:
- `Handler#stacks`/`#repository_name` resolve the target `Repository`/`Stack` purely from `payload.dig('repository', 'full_name')` [3](#0-2) , used by `PushHandler` to sync a stack's commits [10](#0-9) , and by all pull-request handlers to look up `Shipit::Repository.from_github_repo_name(params.repository.full_name)` and provision/archive/unarchive `ReviewStack`s [11](#0-10) [12](#0-11) .
- `MembershipHandler#process` creates/updates a `Team` and adds/removes a `User` as a member based solely on `params.team`, `params.organization.login`, and `params.member.login` — completely independent of `repository.owner.login` [13](#0-12) . `Team` membership drives OAuth authorization checks against `Shipit.github_teams`/`oauth_teams` [14](#0-13) .

So the equality that should hold — "the organization whose secret authenticated this request == the organization/repository/team the handler is about to mutate" — does not hold anywhere in the code: the controller authenticates based on one field (`repository.owner.login`), while every handler acts on a different, independently-attacker-controlled field (`repository.full_name`, `team.id`, `organization.login`).

### Impact Explanation
An unauthenticated attacker who can determine (or guess) that at least one configured GitHub organization on the instance has no `webhook_secret` set (an explicitly supported/onboarding configuration, per `config/secrets.development.shopify.yml`) can send a crafted, entirely self-forged webhook body with:
- `repository.owner.login` (or `organization.login`) set to that unsecured organization → `verify_signature` passes trivially (`return true unless webhook_secret`), no signature or GitHub credential of any kind is required.
- `repository.full_name` / `team` / `organization.login` used by the handler set to a *different*, victim organization's repository/team.

This lets the attacker:
- Force `PushHandler`/`GithubSyncJob` to re-sync arbitrary stacks belonging to a victim organization, and drive `PullRequest::*Handler`s to provision, archive, or unarchive review stacks (which trigger real deploy/deprovision commands) for repositories they have no legitimate access to.
- Via `MembershipHandler`, add an arbitrary GitHub login (including their own) as a member of an arbitrary `Team`, which is exactly the authorization data consumed for `Shipit.github_teams` access control — an escalation into `Shipit.github_teams` authorization, one of the explicitly listed High-impact outcomes.

### Likelihood Explanation
Likelihood depends on at least one configured GitHub organization lacking a `webhook_secret`, which the shipped example configs treat as an acceptable/likely (nil-by-default) setting rather than a hardening requirement. In that state, exploitation requires no credentials, no GitHub App access, and no prior session — only knowledge of which org has no secret and the target org/repo/team names, all of which are discoverable via the public UI (`stacks_controller`, team pages) of the same Shipit instance.

### Recommendation
- Tie signature verification to the *same* organization/repository the handler will act on: derive `repository_owner` (or an explicit allowed-organizations list) from a value the handler also uses, and reject requests where `repository.full_name`'s org segment or `organization.login`/`team.organization` doesn't match the organization whose secret validated the signature.
- Require every configured organization to have a non-blank `webhook_secret` in production (fail closed instead of `return true unless webhook_secret`), removing the implicit signature bypass.
- Have `MembershipHandler` and repository-scoped handlers validate that the `organization`/`repository.owner.login` used for authentication matches the organization implied by `team.organization`/`repository.full_name` before mutating state.

### Proof of Concept
1. Configure Shipit with two organizations: `AttackerOrg` (no `webhook_secret` set) and `VictimOrg` (has stacks/teams and a secret configured), as supported by `secrets.yml`.
2. POST to `/webhooks` with header `X-Github-Event: membership` and body:
```json
{
  "action": "added",
  "team": { "id": 999, "name": "victim-team", "slug": "victim-team", "url": "https://example.com" },
  "organization": { "login": "AttackerOrg" },
  "member": { "login": "attacker-github-login" },
  "repository": { "owner": { "login": "AttackerOrg" } }
}
```
No `X-Hub-Signature` header (or any garbage value) is required because `Shipit.github(organization: "AttackerOrg").verify_webhook_signature` returns `true` unconditionally (blank `webhook_secret`) — see `app/controllers/shipit/webhooks_controller.rb:24-30` and `lib/shipit/github_app.rb:76-83`.
3. `MembershipHandler#process` (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-43`) executes unauthenticated, creating/associating `team.github_id == 999` with organization `AttackerOrg` string but adding the attacker's login as a member — if `team.id` collides with (or is later reused for) a real Shipit-recognized team backing `Shipit.github_teams`, the attacker gains recorded team membership without any GitHub credential.

module Shipit
  module Webhooks
    module Handlers
      class MembershipHandler < Handler
        params do
          requires :action, String
          requires :team do
            requires :id, Integer
            requires :name, String
            requires :slug, String
            requires :url, String
          end
          requires :organization do
            requires :login, String
          end
          requires :member do
            requires :login, String
          end
        end
        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
      end
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
