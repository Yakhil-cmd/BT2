### Title
Cross-tenant Status write via unscoped `Commit.where(sha:)` in StatusHandler#process - (File: app/models/shipit/webhooks/handlers/status_handler.rb)

### Summary
`StatusHandler#process` looks up commits purely by `sha` across the entire database, with no filter on the repository named in the webhook payload. Since webhook signature verification (`WebhooksController#verify_signature`) only proves the payload came from the GitHub org owning the *named* repository, but the base `Handler` class exposes a `stacks`/`repository_name` scoping mechanism that `StatusHandler` deliberately does not use, a valid signature from any org can create a `Status` row on a `Commit` belonging to a completely different tenant's `Stack`, provided the sha happens to coincide.

### Finding Description
The broken binding, stated explicitly:

`repository.full_name` in the verified webhook payload (`fork-org/victim-clone`) MUST equal the `Repository`/`Stack` that owns the `Commit` row(s) being mutated — but `StatusHandler#process` never checks this, so in practice `payload.repository.full_name != commit.stack.repository.full_name` for any commit not belonging to the attacker's own stack, and the code proceeds anyway.

Code path:
- `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository','owner','login')` and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [1](#0-0) [2](#0-1) . This only proves the request is genuinely from `fork-org` (using fork-org's own `webhook_secret`); it says nothing about which `Commit`/`Stack` rows may be touched.
- `StatusHandler#process` then runs: `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` [3](#0-2) . This is a global, unscoped query against the `commits` table — it does not join or filter on `stack_id`, `repository_name`, or anything derived from `payload['repository']`.
- Compare with the base `Handler` class, which explicitly provides a `stacks` helper scoped by `repository_name = payload.dig('repository', 'full_name')` via `Repository.from_github_repo_name(repository_name)&.stacks` [4](#0-3) , and `PushHandler#process` correctly uses this scoping (`stacks.not_archived.where(branch:)`) [5](#0-4) . `StatusHandler` bypasses this pattern entirely and queries `Commit` directly by `sha` only.
- `create_status_from_github!` writes a `Status` row scoped to the commit's own `stack_id` (`statuses.replicate_from_github!(stack_id, github_status)` in `app/models/shipit/commit.rb:165-169`), and `Status#replicate_from_github!` creates the row and fires `enable_ci_on_stack`/`schedule_continuous_delivery` callbacks on that commit's stack — i.e., on whichever stack happens to own a `Commit` with the matching sha, regardless of which org's webhook secret signed the request.

Attacker flow: attacker owns `fork-org/victim-clone`, pushes/cherry-picks a commit whose sha matches (or is copied to be byte-identical with) a commit sha already present in some victim `Stack`'s `commits` table (trivial for empty/no-diff commits since git sha is content-addressed and independent of remote/org). Attacker's own CI (which they fully control) reports a `status` event for that sha to GitHub; GitHub relays it to Shipit signed with `fork-org`'s own `webhook_secret`. `verify_signature` passes because it's genuinely from `fork-org`. `StatusHandler.call` then finds the victim's pre-existing `Commit` row purely by sha match and writes a `Status`/state transition into the victim's stack.

No other guard intervenes: `drop_unhandled_event` and `check_if_ping` don't scope by repository either [6](#0-5) , and there is no `ExplicitParameters` validation of `repository.full_name` against the found commit's stack in `StatusHandler`'s params block [7](#0-6) .

### Impact Explanation
This is a cross-repository write: a `Status` row (and derived CI/deploy state, e.g. `enable_ci_on_stack`, `schedule_continuous_delivery`, `ProcessMergeRequestsJob` enqueue per `test/models/commits_test.rb:763-777`) is written into a victim tenant's `Stack`/`Commit` by an attacker who only controls an unrelated repository and its own webhook secret. This can flip a victim commit's CI state to `success`, potentially unblocking merges/deploys that depend on commit status, without the victim org's webhook secret ever being used. This matches the "payload for one repository mutating another's stack/commit" Critical category. The attack is repeatable against any Shipit deployment that tracks more than one Stack, and its blast radius is bounded only by shared sha collisions across tenants (guaranteed for empty commits, and achievable for identical content commits mirrored from a public repo).

### Likelihood Explanation
Preconditions are modest: the attacker needs (a) their own GitHub repo with a configured Shipit org/webhook_secret (attacker-controlled, trivial to set up if Shipit is multi-tenant and self-serve, or the attacker just needs any repo already onboarded that they can push to), and (b) a commit sha that also exists in some victim `Commit` row — achievable deterministically via empty commits (sha is a function of tree+parent+metadata, so two orgs authoring bit-identical empty commits from identical parents/timestamps could collide, though this requires matching parent commit and timestamps) or, more realistically, by mirroring a public commit byte-for-byte into their own repo history so the identical sha appears in both the victim's and the attacker's git history, then triggering their own CI to post a status for that sha. This is fully within reach of an unprivileged attacker who owns a fork/mirror repo, requires no secrets belonging to the victim, and can be repeated for any known target sha.

### Recommendation
Scope `StatusHandler#process` to only operate on commits belonging to stacks whose repository matches `payload['repository']['full_name']`, mirroring the `Handler#stacks` pattern already used by `PushHandler`. E.g., replace `Commit.where(sha: params.sha)` with a query joined through `stacks` (derived from `repository_name`), such as `Commit.where(sha: params.sha, stack_id: stacks.select(:id))`, and only call `create_status_from_github!` on commits within that scoped set.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`):
1. Create `stack_a` for repo `org-a/repo-a` with `webhook_secret_a`, and `stack_b` for repo `org-b/repo-b` with `webhook_secret_b`. Create `commit_b` under `stack_b` with a known `sha` (e.g. `"deadbeef...".freeze`).
2. Build a `status` webhook payload with `repository.full_name = "org-a/repo-a"`, `repository.owner.login = "org-a"`, `sha = commit_b.sha`, `state = "success"`.
3. Sign the payload using `webhook_secret_a` (org A's own secret) and set `X-Hub-Signature`/`X-Github-Event: status`.
4. Assert on both sides of the binding:
   - Before: `assert_equal "org-a/repo-a", payload_repo_full_name` and `assert_equal "org-b/repo-b", commit_b.stack.repository.full_name` — confirm they differ.
   - `assert_difference('commit_b.statuses.count', 1) { post :create, body: payload, as: :json }` and `assert_equal 'success', commit_b.reload.state`.
5. This demonstrates that a signature verified only against `org-a`'s secret produced a write on `stack_b`/`commit_b`, which belongs to `org-b`, proving the cross-tenant mutation. [8](#0-7) [9](#0-8) [10](#0-9)

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
    end
  end
end

module Shipit
  module Webhooks
    module Handlers
      class Handler
        class << self
          attr_reader :param_parser

          def params(&block)
            @param_parser = ExplicitParameters::Parameters.define(&block)
          end
        end

        def self.call(params)
          new(params).process
        end

        attr_reader :params, :payload

        def initialize(payload)
          @payload = payload
          @params = self.class.param_parser.parse!(payload)
        end

        def process
          raise NotImplementedError
        end

        private

        def stacks
          @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
        end

        def repository_name
          payload.dig('repository', 'full_name')
        end
      end
    end
  end
end
