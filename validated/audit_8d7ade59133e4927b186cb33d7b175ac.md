### Title
Large sustained-utilization markets can permanently freeze through RAY-value overflow during accrual - (File: `common/src/rates/simulate.rs`)

### Summary
Pool accrual converts the market’s scaled borrow and supply shares back to RAY values before applying the bounded index update. For a sufficiently large market, ordinary interest growth can make either multiplication exceed `i128::MAX` before the borrow index reaches `MAX_BORROW_INDEX_RAY`. The resulting `MathOverflow` panic prevents accrual from completing. Because every market operation accrues first, subsequent repayments, withdrawals, liquidations, and explicit `update_indexes` calls all fail, permanently freezing the affected market.

### Finding Description
`Controller::update_indexes` is permissionless after caller authorization and forwards the requested `HubAssetKey` vector to the pool. [1](#0-0)  Pool `global_sync` processes all elapsed time in bounded chunks and runs `accrue_step` for each chunk. [2](#0-1) 

The vulnerable ordering is in `accrue_step`: it calculates `borrowed_original` and `supplied_original` before updating or capping the next index. [3](#0-2)  Both calculations call `scaled_to_original`, which performs `scaled.mul(env, index)`; the fixed-point multiply reverts on overflow. [4](#0-3)  Consequently, the index ceiling does not protect the multiplication involving the already-grown index.

A production regression test demonstrates the reachable state: a market holding one billion 18-decimal tokens at 98% utilization eventually fails `update_indexes` with `MathOverflow`, while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`; afterward both withdrawal and repayment fail with the same error. [5](#0-4) 

### Impact Explanation
This permanently freezes all user funds in the affected pool market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot execute repayments against that debt market, and keepers cannot repair the condition through `update_indexes` because each path first hits the same overflowing accrual. Any protocol revenue or collateral represented by the market’s scaled shares is likewise inaccessible.

This is not merely an oversized-input or transaction-budget failure. Once the stored scaled balances and elapsed index growth cross the representable RAY-value boundary, every later state transition hits arithmetic overflow even for a one-unit repayment or withdrawal.

### Likelihood Explanation
Likelihood is constrained by market scale and time, but an unprivileged attacker can construct the required position. The attacker supplies a very large amount of an admitted high-decimal asset, supplies separate collateral, borrows most of that liquidity, and waits for the borrow index to grow under sustained high utilization. Other users can independently create the same condition through normal usage without coordinating with the original borrower.

Governance-selected supply caps, borrow caps, utilization limits, and the interest-rate curve determine whether a listed market can reach the required scale. The tested configuration uses admitted market parameters with disabled maximum-utilization protection and reaches the failure below the intended index ceiling. Once reached, no user action is required to trigger it—the next accrual fails.

### Recommendation
Cap market state by representable accrued value, not only by nominal index bounds:

- Before minting supply or debt shares, validate that `scaled_amount * index` remains below the `i128` RAY-value domain under the configured caps.
- Derive conservative market caps from the admitted token decimals, index ceiling, and expected interest-rate curve.
- In `accrue_step`, use saturating or explicitly bounded value conversion when calculating utilization, then clamp the indexes before any multiplication that can exceed the domain.
- Add fail-safe market handling that permits repayments and withdrawals when the debt or supply index has reached its ceiling without requiring another overflowing value conversion.
- Add deployment checks so configured caps cannot admit a market whose accrued total can exceed `i128::MAX` before `MAX_BORROW_INDEX_RAY`.

### Proof of Concept
The repository already contains a deterministic reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

1. Create an 18-decimal market using the steep `xlm_curve`.
2. Supply `principal = 1_000_000_000 * 10^18` units.
3. Supply collateral and borrow `98%` of that market.
4. Advance time in yearly intervals and call permissionless `update_indexes` for the market.
5. The call eventually returns `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`.
6. Subsequent one-unit `withdraw` and one-unit `repay` calls also return `MathOverflow`. [6](#0-5)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
