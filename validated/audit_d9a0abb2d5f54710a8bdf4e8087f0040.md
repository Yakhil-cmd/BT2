## Analysis

I could not find a literal "balance not decremented" bug in this codebase — this is a Go CLI (`gh`), not a smart contract, so there is no reward-pool state to drain. However, the underlying bug *class* from the Mochi report is a **failure to gate a sensitive action on the correct state check before performing it** (claiming a reward without verifying/clearing the balance first). The closest reachable analog in `gh` is a similarly missing state check that causes a **sensitive credential to be attached to a request without verifying the destination host**, in the CAPI (Copilot API) HTTP transport.

### Title
Bearer token unconditionally attached to every request regardless of destination host, enabling credential leak on redirect - (File: `pkg/cmd/agent-task/capi/client.go`)

### Summary
`capiTransport.RoundTrip` in `pkg/cmd/agent-task/capi/client.go` sets the `Authorization: Bearer <token>` header on **every** outgoing request unconditionally, without checking whether the request's destination host is the expected CAPI/GitHub host. This is the opposite of the pattern used elsewhere in the same codebase (`api/http_client.go`'s `AddAuthTokenHeader`), which explicitly detects a host change across a redirect and withholds the token in that case.

### Finding Description [1](#0-0) 

```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}
```

The `Authorization` header is set for `req.URL.Host` unconditionally — there is no equivalent of the `redirectHostnameChange` guard found in the general-purpose GitHub API client transport: [2](#0-1) 

```go
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				...
				req.Header.Set(authorization, fmt.Sprintf("token %s", token))
			}
		}
		return rt.RoundTrip(req)
	}}
}
```

That intentional check — and its accompanying test, `TestHTTPClientRedirectAuthenticationHeaderHandling` — demonstrates the project explicitly considers "auth header sent across a host change during a redirect" to be a real risk to defend against: [3](#0-2) 

`capiTransport`, used to talk both to the GitHub API and to the Copilot API endpoint (per its own comment), does not apply this same defense. Since `NewCAPIClient` wraps an `*http.Client` whose `RoundTrip` is invoked again on every hop of a standard Go HTTP redirect (Go's default client follows redirects by calling the same `Transport.RoundTrip` for each hop unless `CheckRedirect` blocks it, and no `CheckRedirect` override is set here), a redirect response returned by the CAPI/GitHub host to an attacker-controlled host would cause the Bearer token to be sent to that host.

### Impact Explanation
If the Copilot API (or GitHub API) endpoint used by `gh agent-task` (via `pkg/cmd/agent-task/shared/capi.go` → `NewCAPIClient`) is coerced into issuing an HTTP redirect to an attacker-controlled URL — e.g., through a compromised/misconfigured server response, a man-in-the-middle on a non-TLS-pinned hop, or a malicious enterprise/proxy endpoint — the user's Copilot/GitHub bearer token would be transmitted to that attacker host in the `Authorization` header. This is a credential-exfiltration primitive analogous in root cause to the referenced bug: a sensitive resource (reward balance / auth token) is granted/attached without the necessary conditional check that should have gated it.

### Likelihood Explanation
Exploitation requires the CAPI/GitHub endpoint to actually issue (or be tricked into issuing) a same-request 3xx redirect to a different host — this is not attacker-controlled purely from client input, so it depends on server-side behavior or a network-position attacker. This narrows likelihood relative to a fully client-triggerable bug, but the missing host check is a genuine defense-in-depth gap that the rest of the codebase treats as a real threat (as shown by the parallel, deliberately-guarded code path in `api/http_client.go`).

### Recommendation
Add the same host-verification guard used in `AddAuthTokenHeader` to `capiTransport.RoundTrip`: only set the `Authorization: Bearer` header when `req.URL.Host` matches the expected CAPI host (or the original GitHub host), and skip attaching it (or set an explicit `CheckRedirect` that refuses cross-host redirects) otherwise.

### Proof of Concept
1. `gh agent-task create` (or similar) constructs a `CAPIClient` via `NewCAPIClient`, wrapping the caller's HTTP client transport with `capiTransport`.
2. A request is sent to the Copilot API host with the `Authorization: Bearer <token>` header set by `RoundTrip`.
3. If the server response is a 3xx redirect to `https://attacker.example/collect`, Go's default `http.Client` (no `CheckRedirect` override present) follows the redirect and re-invokes `capiTransport.RoundTrip` for the new request.
4. Because the header-setting logic in `RoundTrip` is unconditional (`req.Header.Set("Authorization", ...)` before any host check), the same Bearer token is attached to the request now going to `attacker.example`, leaking the credential.

**Uncertainty note:** I was unable to fully trace how `pkg/cmd/agent-task/shared/capi.go` constructs the underlying `*http.Client` (e.g., whether any `CheckRedirect` policy is already applied upstream that would block cross-host redirects) because tool access ended before I could inspect that file's full contents. If such a `CheckRedirect` restriction already exists upstream, likelihood would be significantly reduced. Confirming this requires reading `pkg/cmd/agent-task/shared/capi.go` in full.

// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}

func TestHTTPClientRedirectAuthenticationHeaderHandling(t *testing.T) {
	var request *http.Request
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		request = r
		w.WriteHeader(http.StatusNoContent)
	}))
	defer server.Close()

	var redirectRequest *http.Request
	redirectServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		redirectRequest = r
		http.Redirect(w, r, server.URL, http.StatusFound)
	}))
	defer redirectServer.Close()

	client, err := NewHTTPClient(HTTPClientOptions{
		Config: tinyConfig{
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(redirectServer.URL, "http://")): "REDIRECT-TOKEN",
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(server.URL, "http://")):         "TOKEN",
		},
	})
	require.NoError(t, err)

	req, err := http.NewRequest("GET", redirectServer.URL, nil)
	require.NoError(t, err)

	res, err := client.Do(req)
	require.NoError(t, err)

	assert.Equal(t, "token REDIRECT-TOKEN", redirectRequest.Header.Get(authorization))
	assert.Equal(t, "", request.Header.Get(authorization))
	assert.Equal(t, 204, res.StatusCode)
}
