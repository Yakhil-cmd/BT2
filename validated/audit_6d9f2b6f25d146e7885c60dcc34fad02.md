### Title
Permanent market freeze: `i128` overflow in interest accrual panics before the borrow-index cap engages, permanently locking all supplied and borrowed funds — (File: `common/src/rates/index.rs`)

### Summary
An unprivileged caller can permanently freeze any sufficiently large, highly-utilized market. Interest accrual computes a RAY-denominated value (`supplied_shares × index`) inside `scaled_to_original`, which panics with `MathOverflow` when the product exceeds `i128::MAX`. Because every state-changing verb (`supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `recapitalize`) runs `interest::global_sync` accrual before its accounting, once the product crosses the `i128` ceiling — which occurs well before the `MAX_BORROW_INDEX_RAY` cap can clamp the index — every entrypoint on that market reverts forever.

### Finding Description
The OpenLDAP report is a "crash-on-invalid-free → denial of service" class bug. The analog here is a crash-on-overflow → permanent freeze, already demonstrated by the in-repo harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:315-361`. It shows a market holding ~1e36 raw RAY of supplied shares (1 billion 18-decimal tokens) at 98% utilization on the XLM rate curve: the borrow index grows past ~170× within a few years, the next accrual panics inside `scaled_to_original`, and `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`.

Root cause: accrual multiplies scaled shares by the index at full RAY precision (`common/src/math/fp.rs` `checked_add_raw`/`checked_sub_nonneg` panic paths; `common/src/rates/scaling.rs` `unscale_borrow_ceil`/`resolve_repay` all funnel through checked `i128` math). There is no clamp of the *value* product, only of the index — and the value product overflows first for any market whose `supplied × index` can reach `i128::MAX ≈ 1.7e38` raw units. The chunked accrual (`MAX_COMPOUND_DELTA_MS`) does not help: each chunk still recomputes the same overflowing value.

### Impact Explanation
Permanent freezing of funds. Once the cliff is crossed, no user can withdraw supply, repay debt, be liquidated, or clean bad debt on that (hub, token) book — every call accrues first and panics. Supplier principal, accrued yield, and borrower collateral are all permanently locked in the pool contract. Because hub/spoke books share physical pools, an affected market's stranded `cash` bookkeeping also distorts `require_reserves` and utilization accounting for other books.

### Likelihood Explanation
Reachable by any unprivileged address but only at extreme scale: the attacker must bootstrap or ride a market to ~`i128::MAX` raw RAY of supplied value (e.g., 1 billion 18-decimal tokens) and sustain ~98% utilization until the index exceeds ~170× — several years on the steepest curve segment with max-utilization disabled, or a token with very high supply/decimals. Cost is locked capital rather than consumable funds. The harness test itself notes this contradicts the bound documented in `docs/reference/formulas.md`, i.e., it is an acknowledged but unfixed cliff rather than a designed limit.

### Recommendation
Clamp or saturate inside accrual before the value multiply overflows: apply `MAX_BORROW_INDEX_RAY`/`MAX_SUPPLY_INDEX_RAY` caps prior to `scaled_to_original`, use `I256`/`u256` intermediates for `shares × index` products and saturate at `i128::MAX`, or add a kill-switch accrual path (e.g., freeze rate accrual once a value bound is reached but still permit repay/withdraw with the last committed index) so exits remain possible.

### Proof of Concept
The repo already contains an executable PoC: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`.

```rust
let principal = BILLION * 10i128.pow(18);        // whale market, 18 decimals
t.supply_raw(BOB, "BIG18", principal);
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98); // 98% utilization
// advance years until accrual panics:
assert_contract_error(t.try_update_indexes_for(&["BIG18"]), errors::MATH_OVERFLOW);
assert!(book(&t, "BIG18").borrow_index < MAX_BORROW_INDEX_RAY); // cap never engaged
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

All subsequent verbs fail identically: the market, and all funds in it, are permanently frozen.
