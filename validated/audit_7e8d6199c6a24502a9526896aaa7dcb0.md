### Title

Unbounded scaled debt valuation overflows `i128` and permanently freezes a market - (File: common/src/rates/index.rs)

### Summary

A very large borrowed or supplied position can make `scaled_amount * index / RAY` exceed `i128::MAX` before the configured index ceiling is reached. Because every pool mutation first runs `global_sync`, the resulting `MathOverflow` permanently prevents repayment, withdrawal, liquidation, index updates, and recapitalization for that market.

### Finding Description

`accrue_step` converts both market totals to RAY-valued originals before calculating utilization and interest. [1](#0-0)  It then calculates interest by multiplying `borrowed` by both the old and new borrow indexes. [2](#0-1) 

`Ray::mul` delegates to `mul_div_half_up`, which returns `MathOverflow` whenever the resulting RAY value does not fit into `i128`. [3](#0-2)  Although `update_borrow_index` caps the index, the cap is applied only after `old_index * interest_factor` succeeds and does not account for the size of `borrowed`. [4](#0-3) 

Every pool leg loads through `synced_market`, which invokes `interest::global_sync` before the operation. [5](#0-4)  `global_sync` calls `accrue_step` for every elapsed chunk. [6](#0-5)  Consequently, once the stored scaled totals and grown index make the valuation unrepresentable, all later calls revert during accrual and never reach their operation-specific logic.

### Impact Explanation

This permanently freezes the affected hub-asset market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate positions involving that market, and `update_indexes` cannot commit a later timestamp because the accrual transaction panics before writing state. [7](#0-6)  Repayment and withdrawal both go through `load_leg`, so they necessarily perform the same overflowing accrual first. [8](#0-7) [9](#0-8) 

The repository's regression test demonstrates this exact state: after sustained high utilization, `update_indexes` fails with `MATH_OVERFLOW` while the borrow index remains below its cap, and subsequent withdrawal and repayment calls fail identically. [10](#0-9) 

### Likelihood Explanation

Triggering the condition requires an exceptionally large market. The test uses one billion whole 18-decimal tokens supplied and 98% borrowed, plus enough separate collateral to satisfy account risk checks. [11](#0-10)  A single unprivileged attacker can create the supply and borrowing account when the admitted caps, collateral value, token liquidity, and utilization configuration permit that exposure.

The condition is still practical to recognize as a protocol-boundary arithmetic issue rather than an input-validation failure: valid cap-sized positions and bounded indexes can jointly produce an unrepresentable accrued value. Once reached, no ordinary user call can move the market past the panic.

### Recommendation

Represent accrued market values in `I256` throughout `accrue_step`, or enforce a dynamic scaled-share bound derived from the current index before minting supply or debt and before increasing an index.

At minimum, calculate the next index only if both:

```text
borrowed * new_borrow_index / RAY <= i128::MAX
supplied * new_supply_index / RAY <= i128::MAX
```

The bound should be enforced in `accrue_step`, not merely documented as a cap consequence. If value overflow is intentionally terminal, stop accrual at the largest representable index and preserve repayment and withdrawal paths instead of allowing every operation to fail during accrual.

### Proof of Concept

Using a listed 18-decimal asset `A` whose caps admit the exposure:

1. Call `supply(caller, 0, spoke_id, [(A, 1_000_000_000 * 10^18)])` to create an account and supply the principal.
2. Supply sufficient collateral in another listed market to satisfy LTV and minimum-collateral checks.
3. Call `borrow(caller, account_id, [(A, 980_000_000 * 10^18)], None)` to reach 98% utilization.
4. Repeatedly call `update_indexes(caller, [A])` as ledger time advances until `borrowed * new_borrow_index / RAY > i128::MAX`.
5. The call fails with `MathOverflow` inside `accrue_step`.
6. Subsequent calls such as `repay(caller, debt_account_id, [(A, 1)])`, `withdraw(caller, supply_account_id, [(A, 1)], None)`, `liquidate`, and another `update_indexes` all fail with the same error because `load_leg` performs `global_sync` first. [12](#0-11) 

The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` implements this sequence and confirms both the overflow and the frozen repayment and withdrawal paths. [10](#0-9)

```rust
/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);

    t.supply_raw(BOB, "BIG18", principal);

    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"

    let failed: Result<(), soroban_sdk::Error> = Err(failure);
```
