### Title
Accrual value-overflow panics before the borrow-index cap engages, permanently freezing the market - ([File: common/src/rates/index.rs])

### Summary
`accrue_step` computes the new borrow index in `update_borrow_index`, which clamps the *index* to `MAX_BORROW_INDEX_RAY` — but the subsequent `calculate_supplier_rewards` multiplies the scaled `borrowed` total by that index to obtain total debt value. For a sufficiently large market, `borrowed * new_borrow_index` overflows `i128` and panics with `GenericError::MathOverflow` at an index far below the cap. Since every state-changing entrypoint runs `interest::global_sync` first, the market freezes permanently once this threshold is crossed: no supply, withdraw, borrow, repay, liquidation, or bad-debt cleanup can ever execute again.

### Finding Description
The analog to CVE-2017-12800 (a crash on a dereference reachable via crafted input) is a fail-forever panic reachable by unprivileged users in the accrual path.

- `contracts/pool/src/interest.rs:20-53` — `global_sync` runs unconditionally before every pool op and calls `accrue_chunk`, which invokes `accrue_step`. [1](#0-0) 
- `common/src/rates/index.rs:13-19` — `update_borrow_index` multiplies `old_index * interest_factor` and only then clamps to `MAX_BORROW_INDEX_RAY` (1e36 raw, `common/src/constants/pool.rs:19`). The cap guards the index value, not the total-debt value. [2](#0-1) 
- `common/src/rates/index.rs:80-86` — `calculate_supplier_rewards` then computes `borrowed.mul(env, new_borrow_index)` and `borrowed.mul(env, old_borrow_index)`. `Ray::mul` routes through `fp_core` which panics with `MathOverflow` when `scaled * index` exceeds `i128`. [3](#0-2) 

Scaled shares are `amount * RAY / index` (`common/src/rates/scaling.rs:54-56`), so `borrowed * borrow_index ≈ debt_value * RAY`. For an 18-decimals market holding ~1e27 asset units of debt, the total-debt Ray value is ~1e63-scale intermediates; in raw terms `borrowed ≈ 1e36` and the product overflows `i128::MAX (~1.7e38)` once the index passes roughly 170× RAY — vastly below the 1e9× RAY cap. The cap therefore never protects the value domain.

The repository's own harness test confirms this is a live hole, not a hypothetical: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` drives a whale 18-decimals market to ~98% utilization, advances time until `try_update_indexes` panics with `MATH_OVERFLOW`, and asserts `borrow_index < MAX_BORROW_INDEX_RAY` plus that `withdraw` and `repay` both panic identically afterward. [4](#0-3) 

### Impact Explanation
**Permanent freezing of funds.** Once the accrual overflows, every subsequent call to `update_indexes`, `supply`, `withdraw`, `borrow`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, or `recapitalize` re-enters `global_sync` → `accrue_step` → `calculate_supplier_rewards` and panics before any state mutates. All supplier cash in that (hub, token) book is locked forever; borrower collateral backing that debt cannot be released through the affected market's settlement paths. There is no recovery path in-scope — `recapitalize` itself accrues first.

### Likelihood Explanation
Reaching the cliff requires a large debt base in a high-decimals market sustained at high utilization for an extended period. An unprivileged attacker cannot force it instantly, but can materially contribute: hold a large borrow open (`borrow`), keep utilization pinned in the steep segment of the curve, and permissionlessly poke `update_indexes`. No governance action, leaked key, or bad parameter is needed — the arithmetic ceiling is intrinsic to `borrowed * index` growing unboundedly while the cap only bounds `index`. Severity Medium: real permanent freeze, but gated by market scale and accrual horizon rather than a single crafted call.

### Recommendation
Bound accrual in the *value* domain, not only the index domain:

- In `calculate_supplier_rewards` (or `accrue_step`), use a saturating/checked multiply for `borrowed * new_borrow_index`; on overflow, clamp `new_borrow_index` to `i128::MAX / borrowed` (the largest index whose total-debt value still fits) instead of panicking. This makes `MAX_BORROW_INDEX_RAY` an effective dynamic cap of `min(MAX_BORROW_INDEX_RAY, i128::MAX / borrowed)`.
- Alternatively, halt index growth gracefully when `old_index.mul(interest_factor)` or the debt-value product saturates — write the capped index, zero the accrued rewards for that chunk, and continue, so the market remains operable for exits and repayments.
- Add the same guard on the supply side: `update_supply_index` already computes `supplied * old_index` at `common/src/rates/index.rs:34`, which can overflow identically for whale-scale `supplied`.

### Proof of Concept
The in-repo test is the PoC (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`):

```rust
// 18-decimals market on the XLM rate curve, caps lifted, max-utilization disabled.
let principal = BILLION * 10i128.pow(18);          // ~1e27 units supplied
t.supply_raw(BOB, "BIG18", principal);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98); // ~98% utilization

// Advance time; each year calls try_update_indexes_for(&["BIG18"]).
// Within <= 40 simulated years the call fails with GenericError::MathOverflow,
// while borrow_index is still < MAX_BORROW_INDEX_RAY.
assert_contract_error(failure, errors::MATH_OVERFLOW);
assert!(book(&t, "BIG18").borrow_index < MAX_BORROW_INDEX_RAY);

// Permanent freeze: every verb accrues first and hits the same panic.
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

Mechanism: `borrow` mints scaled debt shares `≈ 1e36` raw; accrual pushes `borrow_index` past ~170×RAY; `accrue_step` → `calculate_supplier_rewards` computes `borrowed * new_borrow_index > i128::MAX` and panics inside `scaled_to_original`/`Ray::mul`. Because `global_sync` precedes all state changes, the panic is sticky — every later interaction re-triggers it before doing any work.

Note on uncertainty: I did not read `accrue_step`'s body directly (it lives in `common/src/rates/compound.rs`/`simulate.rs`); the overflow site is confirmed by the test comment ("the index grows past 170x … and the next accrual panics inside `scaled_to_original`") and by `calculate_supplier_rewards` being the only value-domain multiply in the accrual path.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:

#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {

    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);

    );
