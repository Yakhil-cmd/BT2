### Title
Webhook signature verification is bound to `repository.owner.login`, but event handlers act on the unverified `repository.full_name` — cross-organization webhook forgery ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/secret to use for HMAC verification based on `repository.owner.login` (or `organization.login`) taken directly from the *unverified* JSON body [1](#0-0) , and derives that value from the payload itself [2](#0-1) . Once "verified", every downstream handler resolves the target `Repository`/`Stack` using a *different* field from the same payload, `repository.full_name`, without ever checking that its owner matches the org whose secret authenticated the request [3](#0-2) .

### Finding Description
Shipit explicitly supports hosting multiple independent GitHub Apps/organizations in one instance, each with its own `webhook_secret` [4](#0-3) , as documented for "Using Multiple GitHub Applications" (`docs/setup.md`). The equality the system implicitly relies on is:

`org_that_authenticated_the_request == owner_of_the_repository_the_handler_writes_to`

but this is never enforced. `verify_signature` computes `repository_owner` from `params.dig('repository','owner','login')` and uses it purely to pick which app config's secret verifies the raw body [1](#0-0) . The HMAC only proves the request was signed with *that org's* secret — it does not prove anything about `repository.full_name`, which is the field every handler actually trusts to find the `Repository`/`Stack` to mutate, e.g. `PushHandler` and the base `Handler#stacks` [3](#0-2)  and `PushHandler#process` [5](#0-4) .

This is worsened by `GitHubApp#verify_webhook_signature` bypassing verification entirely when the selected org has no configured secret: `return true unless webhook_secret` [6](#0-5) . Because `repository.owner.login` is attacker-controlled (it's just JSON in the raw body, read before verification), an attacker can:
1. Set `repository.owner.login` (or `organization.login`) to any organization configured in this Shipit instance for which they know the `webhook_secret`, or which has no secret configured at all (bypassing the check).
2. Set `repository.full_name` to any *other* tracked repository/stack in the instance (a different org entirely).

The signature check passes (bound only to field 1), but every handler acts on field 2 — breaking the "org that authenticated" vs. "repository that is written" binding called out in scope.

### Impact Explanation
An unauthenticated party who knows (or exploits the absence of) one configured org's `webhook_secret` can forge GitHub events — `push`, `status`, `check_suite`, `pull_request` — against an entirely unrelated tracked stack:
- `push` forges `GithubSyncJob` runs against a victim stack via `stacks.find_each { |stack| stack.sync_github(...) }` [5](#0-4) .
- `status`/`check_suite`/`deployable_status`-related events can inject forged CI/commit statuses against a victim's commits, which the merge queue and deploy readiness checks rely on, potentially enabling an unauthorized merge/deploy decision.

This is a cross-repository write across an organization trust boundary that the engine is documented to isolate per-org, meeting the "cross-repository writes / unauthorized deploy, rollback or merge" bar.

### Likelihood Explanation
The `/webhooks` endpoint is unauthenticated by design (it only relies on `X-Hub-Signature`) [7](#0-6) . Any deployment running the documented multi-org configuration is affected the moment one organization either has no `webhook_secret` set (explicitly supported as optional in `docs/setup.md` — "Webhook secret (optional)") or the attacker is a legitimate GitHub App owner/administrator of one of the other configured orgs and thus knows that org's own secret. No privileged Shipit account, API token, or GitHub write access is required.

### Recommendation
After signature verification succeeds for the org derived from `repository.owner.login`, re-validate that `repository.full_name`'s owner segment matches that same verified org (or, better, resolve the target `Repository` by owner+name and confirm its configured GitHub App/org matches the one whose secret validated the signature) before dispatching to any `Shipit::Webhooks` handler.

### Proof of Concept
Given a multi-org config where `attacker-org` has no `webhook_secret` (or a secret known to the attacker) and `victim-org/victim-repo` is a real tracked stack under a different org:

```
POST /webhooks HTTP/1.1
X-Github-Event: push
X-Hub-Signature: sha1=<hmac using attacker-org secret, or omitted if attacker-org has no secret>

{
  "ref": "refs/heads/master",
  "after": "<sha>",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "attacker-org" }
  }
}
```

`verify_signature` resolves `Shipit.github(organization: "attacker-org")` and verifies (or auto-passes) using `attacker-org`'s secret [1](#0-0) . `PushHandler` then looks up the stack via `payload.dig('repository','full_name')` = `"victim-org/victim-repo"` [3](#0-2)  and triggers `stack.sync_github` on the victim's stack, despite the request never having been authenticated for `victim-org`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
