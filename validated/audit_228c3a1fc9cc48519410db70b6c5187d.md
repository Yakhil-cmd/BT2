### Title
Validator Can Instantly Raise Commission Rate While Delegator Stakes Are Locked — (`File: contracts/bindings/publicdelegation/PublicDelegation.go`)

### Summary

Kaia's `PublicDelegation` contract exposes an `updateCommissionRate(uint256 _commissionRate)` function callable immediately by the validator (contract owner) with no timelock or delay. At the same time, delegators who have staked KAIA through `PublicDelegation` → `CnStakingV4` are subject to a `STAKE_LOCKUP` withdrawal delay. This asymmetry allows a malicious validator to raise the commission to `MAX_COMMISSION_RATE` at any time, extracting maximum commission from all block rewards during the entire lockup window while delegators cannot exit.

### Finding Description

The `PublicDelegation` contract (KIP-226 permissionless delegation) is deployed per-validator and accepts KAIA from public delegators. The validator (owner) sets a `commissionRate` at deployment and can update it at any time via `updateCommissionRate`. The ABI embedded in the Go binding confirms the function signature is:

```
function updateCommissionRate(uint256 _commissionRate) returns()
```

There are no pending-rate fields, no timelock parameters, and no delay enforced before the new rate takes effect. The event emitted is `UpdateCommissionRate(prevCommissionRate, commissionRate)` — a direct, immediate state change.

Meanwhile, `CnStakingV4` (the underlying staking contract used by `PublicDelegation`) enforces a `STAKE_LOCKUP` withdrawal delay. Delegators who call `approveStakingWithdrawal` receive a `withdrawableFrom` timestamp in the future; they cannot recover their KAIA until that period elapses.

The broken invariant: **commission rate changes take effect immediately, but delegator exits are time-locked**, creating a window during which the validator can extract arbitrarily high commission from locked delegator funds.

### Impact Explanation

Every block reward distributed through `FinalizeState` → `getDeferredRewardFull` → `assignStakingRewards` computes the staker's share of KAIA. The commission is deducted from delegator rewards before distribution. If the validator raises `commissionRate` to `MAX_COMMISSION_RATE` (the protocol ceiling), all staking rewards attributable to delegated KAIA flow to the validator's `commissionTo` address instead of delegators. This is a direct, quantifiable transfer of KAIA reward assets from delegators to the validator, sustained for the full duration of the stake lockup period.

**Corrupted value**: `commissionRate` storage slot in `PublicDelegation` — set to `MAX_COMMISSION_RATE` immediately, causing all subsequent reward distributions to route delegator KAIA to the validator.

### Likelihood Explanation

- Any registered validator who has deployed a `PublicDelegation` contract can trigger this.
- The only precondition is being the `owner` of the contract — a normal operational state for every validator using the permissionless delegation system.
- The financial incentive is direct and proportional to total delegated KAIA and the lockup duration.
- No on-chain signal warns delegators before the change takes effect; the `UpdateCommissionRate` event is emitted only after the fact.

### Recommendation

Introduce a commission rate change delay at least equal to `STAKE_LOCKUP`. A two-step pattern is standard:

1. `proposeCommissionRate(uint256 _newRate)` — records the proposed rate and a `effectiveAt = block.timestamp + STAKE_LOCKUP`.
2. `applyCommissionRate()` — callable only after `effectiveAt`, finalizes the change.

This gives delegators the same window to exit that they have for stake withdrawals, preserving the symmetry between the two lockup periods.

### Proof of Concept

1. Validator deploys `PublicDelegation` with `commissionRate = 1%` and `MAX_COMMISSION_RATE = 100%`.
2. Delegators deposit KAIA; their withdrawal requests are subject to `STAKE_LOCKUP` (e.g., 7 days).
3. Validator calls `updateCommissionRate(MAX_COMMISSION_RATE)` — takes effect in the same block.
4. For every block during the lockup window, `FinalizeState` distributes rewards. The commission deduction routes delegator KAIA to the validator's `commissionTo` address.
5. Delegators cannot exit until `STAKE_LOCKUP` expires; they absorb the full commission increase for the entire period.
6. After the lockup, delegators withdraw their principal but have lost all staking rewards above the original commission rate.

func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {
		qualified, err := r.ValsetModule.GetQualifiedValidators(header.Number.Uint64())
		if err != nil {
			return err
		}
		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

		if rewardAddr := r.GetRewardAddress(header.Number.Uint64(), r.NodeAddress); useRewardAddress && rewardAddr != (common.Address{}) {
			header.Rewardbase = rewardAddr
			logger.Trace("Use reward address for nodeValidator", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		} else {
			logger.Trace("No reward address for nodeValidator. Use node's rewardbase.", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		}
	}

	spec, err := r.GetDeferredReward(header, txs, receipts)
	if err != nil {
		return err
	}
	if err := spec.Validate(); err != nil {
		return err
	}
	for addr, amount := range spec.Rewards {
		state.AddBalance(addr, amount)
	}
	return nil
