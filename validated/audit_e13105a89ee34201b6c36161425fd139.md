### Title
Pathspec wildcard/magic injection via unescaped filenames in `_diff_pathspec` causes `get_git_diff` diff scope to escape the intended repo target - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` builds the `git diff -- <paths>` pathspec by splicing repo-relative filenames verbatim after `--`, and `get_git_diff` invokes `git` via `GIT_CMD` without `--literal-pathspecs` or `core.literalPathspecs=true`. Git's default pathspec matcher treats unescaped `*`, `?`, `[...]` and leading `:` as glob/magic syntax rather than literal characters, so a repo-controlled file whose name contains any of these (all legal on POSIX filesystems and valid in git trees) causes `get_git_diff` to match or exclude files outside the caller's intended `review_paths`/`touched_paths` set.

### Finding Description
`_diff_pathspec` (`plugins/security-guidance/hooks/gitutil.py:70-88`) converts each absolute path to a repo-relative string and returns `["--"] + rel` with no quoting/escaping of git pathspec metacharacters: [1](#0-0) 

`get_git_diff` then runs `git diff ... <pathspec>` using `GIT_CMD`, which only sets `core.fsmonitor=false` and `core.hooksPath=/dev/null` — never `core.literalPathspecs` or `--literal-pathspecs`: [2](#0-1) [3](#0-2) 

Git's pathspec syntax (documented under `gitglossary(7)`/`git help glob`) is *not* literal by default: a bare `*`, `?`, `[...]` in a pathspec is matched as an `fnmatch`-style glob, and a pathspec beginning with `:` is parsed as a magic signature (e.g. `:(exclude)`, `:(glob)`, `:(icase)`, `:!`). Both are valid characters in a POSIX/git filename (e.g. `src/*.env`, `:(exclude)notes.md`), so a file with such a name can exist in a normal git repository (introduced via `git clone` of an untrusted remote, a malicious PR checkout, an archive extraction, or even a file the agent itself is asked to create with an attacker-supplied name).

The `paths`/`review_paths` fed into `get_git_diff` originate from git state that already enumerates *actual on-disk filenames* — `compute_v2_review_set` → `_git_status_porcelain`/`_git_name_only` (`plugins/security-guidance/hooks/diffstate.py:353-439`, `gitutil.py:303-328`) and the Stop-hook caller (`plugins/security-guidance/hooks/security_reminder_hook.py:1795-1813`). None of these code paths sanitize or escape pathspec metacharacters before they reach `_diff_pathspec`. Consequently:
- A crafted filename with `*`/`?`/`[]` causes the resulting `git diff -- <name>` invocation to glob-match sibling files (including files never touched this turn, secrets, `.env`, or other WIP), and their diff content is included in `diff_output`, which flows into `parse_diff_into_files` and ultimately into the LLM review prompt (`llm.py:1139-1148`) — an out-of-network sink receiving content the caller never intended to include.
- A crafted filename beginning with `:` (magic signature) can instead be parsed as pathspec magic (e.g. `:(exclude)…`) rather than a literal path, silently dropping the intended file from the diff — the opposite failure, defeating the security review for that file while the hook believes it reviewed it.

The existing `_diff_pathspec` symlink/realpath handling only guards against the macOS `/var`↔`/private/var` case and paths resolving outside `cwd`; it does nothing to prevent metacharacter reinterpretation of in-scope, legitimately-named files, so this is a genuine invariant break: "git path scoping must never escape the intended repo target."

### Impact Explanation
This breaks the repo-diff scoping invariant enforced by `_diff_pathspec`/`get_git_diff`. Depending on the crafted name, the effect is either (a) disclosure of the *content* of files outside the intended review set to the LLM review call (a networked sink, `agentic_review`/single-shot fallback in `llm.py`), leaking sensitive local file content, tokens, or unrelated diffs that were never supposed to leave the intended scope, or (b) silent exclusion of the crafted file from review, letting malicious code changes bypass the security reviewer entirely. Both map to the stated Immunefi impact category: "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink."

### Likelihood Explanation
Feasible without any elevated privilege: an attacker only needs to get a file with such a name into the repository the victim's Claude Code session operates in (a cloned/forked repository, a malicious PR branch checked out locally, or an archive/dependency extracted into the workspace). Because `*`, `?`, `[`, `]`, and leading `:` are all legal in POSIX filenames and in git blob/tree entries, this requires no filesystem-level tricks — a normal `git add`/`git commit` of such a filename is sufficient. Every Stop-hook run and commit-review diff collection that includes such a file in `review_paths`/`touched_paths` triggers the bug deterministically and repeatably.

### Recommendation
Force literal pathspec semantics everywhere `get_git_diff`/`_diff_pathspec`-derived pathspecs are used: add `-c core.literalPathspecs=true` to `GIT_CMD` (or pass `--literal-pathspecs` explicitly on every `git diff`/`git add`/`git status` invocation that consumes untrusted, repo-derived filenames). This makes `*`, `?`, `[]`, and leading `:` matched literally instead of as glob/magic, closing the scope-escape without needing per-path escaping logic.

### Proof of Concept
Unit test plan for `plugins/security-guidance/hooks/gitutil.py`:
1. Create a temp git repo; add and commit two files: `secret.env` (should stay out of scope) and a crafted file literally named `*.env` (or `src/*` directory containing multiple files) plus a normal tracked file `app.py`.
2. Modify `app.py` and the crafted `*.env`-named file; call `get_git_diff(repo_root, "HEAD", paths=[<abs path to the crafted file only>])`.
3. Assert the returned diff text contains ONLY the crafted file's diff and does NOT contain `secret.env`'s diff — currently this assertion fails because git glob-expands `*.env` and includes `secret.env`.
4. Symmetric test: create a file named `:(exclude)app.py`, pass it in `paths`, and assert the diff for that file IS present — currently this assertion fails because git parses the leading `:` as pathspec magic and excludes/misinterprets the path.
5. Re-run both tests after adding `-c core.literalPathspecs=true` to `GIT_CMD` and confirm both assertions pass, demonstrating the fix closes the scope escape.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```

```python
def get_git_diff(cwd, baseline_sha, full_context=False, paths=None, untracked_paths=None):
    """
    Get the git diff between the baseline SHA and the current working tree,
    including untracked (new) files.

    Uses a temporary copy of the git index (GIT_INDEX_FILE) so the user's
    real index is never modified. The temp index gets intent-to-add entries
    for untracked files, making them visible in the diff output. Cleanup
    is just deleting the temp file in a finally block.

    If `paths` is given, the diff is restricted to those paths (relative to
    cwd; absolute paths are converted, paths outside cwd are dropped).
    `untracked_paths` (repo-root-relative) is forwarded to _temp_index so it
    can add only those files instead of scanning the whole worktree.
    """
    pathspec = _diff_pathspec(cwd, paths)
    if paths and not pathspec:
        # Caller restricted to specific paths but none are inside this repo
        # (e.g. only ~/.claude/... edits). Returning "" flows to skip(6); an
        # empty pathspec would mean an UNRESTRICTED diff — the bug this whole
        # change exists to fix.
        return ""

    cmd = [*GIT_CMD, "diff", "--no-color", "--no-ext-diff", baseline_sha] + (["--unified=99999"] if full_context else []) + pathspec
    try:
        with _temp_index(cwd, untracked_paths) as env:
            # env is None when no index could be found (bare repo / not a
            # repo) — diff still runs, just without untracked-file support.
            result = subprocess.run(cmd, cwd=cwd, capture_output=True, timeout=30, env=env)
```
